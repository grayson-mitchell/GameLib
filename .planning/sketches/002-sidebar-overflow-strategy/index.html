Sketch 002 · Overflow strategy

A — Five tabs + a "More" menu

Promote the five destinations people use daily; everything else lives behind ⋯. Simplest to build and the tab bar stays honest at five items. The cost is that nine destinations become invisible — discoverability drops hard for things like Wine Manager and Humble Keys.

+ Simplest build · tab bar never overflows − 9 destinations hidden behind one glyph

B — Two-level bar (primary tabs + contextual sub-bar)

Four broad sections up top, each revealing its own second row. Every one of the 14 destinations stays visible without a hidden menu, and it maps cleanly onto the submenus SidebarLinks already has. The cost is 84px of permanent vertical chrome and a sub-bar that shifts under you as you switch sections.

+ Nothing hidden · matches existing submenu structure − 84px vertical chrome · second row changes on every switch

C — Icon rail + top tabs (hybrid)

Splits the problem by kind rather than by frequency. Content destinations become top tabs; utilities become a 52px icon rail — persistent, always one click away, no hidden menu. It keeps a vertical strip, so it's the least radical departure from today's sidebar, which cuts migration risk.
