## Resolution

root_cause: "TWO independent, compounding gaps, not one: (1) decompressWorker.ts's import chain (./decompress -> backend/logger -> ... -> constants/paths.ts) needs `require('electron')` resolved to a headless stub, because constants/paths.ts calls `app.getPath('appData')` at MODULE SCOPE -- but in dev mode this file was built by electron-vite's shared 'main' Rollup block (alongside main.js) with `externalizeDepsPlugin` leaving 'electron' external/unresolved, and no runtime Module._load hook (installElectronHook.ts, which DOES exist and correctly serves this exact need for the main sidecar thread) is ever installed inside a worker_threads.Worker's own isolate -- worker isolates get a fresh, independent Node module registry that does not inherit a parent thread's Module._load patch. (2) A first-import-based runtime-hook fix (the natural first attempt, mirroring bootstrap.ts's own documented convention) does NOT work for this specific bundler output shape: Rollup's CJS output for a multi-entry build (main.js + decompressWorker.js sharing one Rollup config block) hoists ALL requires -- including a shared chunk containing the offending backend/logger/constants/paths.ts chain, extracted because main.js's own import graph ALSO reaches it via eager store-manager construction -- into a single leading `const ...=require(...)` statement at the top of the generated file, executing before ANY of the importing module's own body code, regardless of that code's original static-import source order."
