## Resolution

root_cause: Humble moved www to Next.js (and commerce to commercetools). (1) The legacy REST API (/api/v1/user/order, /api/v1/order/<gamekey>) is gone, so getGamekeys threw a 404 on every sync. (2) The replacement data source is the Library page's Next.js server action `filterUserLibrary` (paginated, 5 per page, id scraped from the site's JS chunks); items carry entitlements.keys[] with keyIntegrationId and, for revealed keys, redemptionData.keyFormatted. (3) Calling that action from the backend only works if the request mirrors React's reply encoding exactly: FormData entries named `_1_<field>`, args part `[prevState,"$K1"]` with prevState = previous result (initial state on page 1), POST URL /home/library?page=N, and - the decisive difference - root part "0" appended AFTER the `_1_*` parts. With "0" first the server ignored every field and re-served page 1.
fix: adapter.ts: new getLibraryOrders (scrape + per-process cache of the action id with one re-discovery on a stale id; per-page POST with 300 ms gaps, 200-page cap; guards: reported page != requested / no new ids / fewer ids than totalDocs -> schema_error, never a partial library) + libraryItemToOrderDetail (item -> legacy order shape so classify/dedup are unchanged; revealed key value from redemptionData.keyFormatted, never logged). getGamekeys/getOrderDetail/humbleRequest/buildHeaders/HUMBLE_REQUIRED_HEADERS retired. library.ts: one all-or-nothing fetch then local classify+commit, prune of cache entries absent from a COMPLETE library, removal of the per-order network failure modes and the missing-expiration log noise. validation.ts retargeted. Tests rewritten (adapter, library, library.realstore).
