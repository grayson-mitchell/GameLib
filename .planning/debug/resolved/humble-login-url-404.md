## Resolution

root_cause: Humble moved www to Next.js and sign-in to Ory Kratos (auth.humblebundle.com). (1) www /login 404s, so HUMBLE_LOGIN_URL and the WebView/index.tsx copy pointed at a dead page. (2) The session cookie is now ory_session_<slug> on .humblebundle.com; _simpleauth_sess is never set, so watchForLogin never found a candidate. (3) The Ory cookie exists after the FIRST factor (AAL1), and the old validator, GET /api/v1/user/order, 404s even for a fully authenticated aal2 session (legacy API gone), so it could neither confirm nor reject a login.
fix: Login URL -> https://auth.humblebundle.com/login (both copies). Detection matches ory_session_ by prefix (poll host www, apex suffix match; _simpleauth_sess kept as fallback) and carries the credential as the full name=value pair (adapter.buildHeaders sends it as-is). Login validation, and probeSession (startup/reconnect/health), now use www GET /api/auth/session-status == authenticated (adapter.getSessionStatus); an AAL1 cookie reads anonymous and never completes login; unknown/transient never signs the user out. DIAG probe removed. Library sync left calling getGamekeys; its 404 is already handled as a logged transient.
verification: Live, macOS, one run (2026-11-13), operator: Disconnect OK; after first factor the window stayed open at the 2FA prompt; after 2FA it closed by itself and Humble showed connected; Cmd+Q + relaunch -> still connected, no re-login. Library sync logged 'getGamekeys threw (transient), cache untouched: ... 404' at 18:17:40, no sign-out, no loop (expected). Jest src/backend/humble 702/702, prettier clean, tsc clean apart from the pre-existing rustInstall.test.ts error.
files_changed: src/backend/humble/constants.ts, src/backend/humble/user.ts, src/backend/humble/adapter.ts, src/frontend/screens/WebView/index.tsx, src/backend/humble/__tests__/user.test.ts, src/backend/humble/__tests__/probeSession.test.ts

Not fixed (no todos opened; orchestrator to raise with the user):
- Library sync data source: /api/v1/user/order is gone (404 even at aal2), so Humble library sync fails (handled gracefully) until a new data source is found.
- Reveal/redeem csrf: csrf_cookie is absent from the new jar (csrf_token_<hash> instead), so the optional csrf capture is a no-op and reveal/redeem csrf handling needs a change.
- The unexplained mid-2FA window close in the first failed run (likely Esc / sheet Cancel; shell route log unavailable); not reproduced in the later hands-off run.
