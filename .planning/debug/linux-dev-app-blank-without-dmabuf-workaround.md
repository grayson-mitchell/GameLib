## Resolution

root_cause: The debug-only `#[cfg(debug_assertions)]` `window.open_devtools()` at src-tauri/src/main.rs:11911 (wry `webkit_web_inspector_show`) opens the docked Web Inspector during startup, racing the page's still-running entry module (`src/frontend/index.tsx` suspends on a top-level `await hydrateStoreSnapshot()` from ~0.24s to ~0.5s, then runs synchronous boot code). If the inspector attaches inside that window, the page's WebKitWebProcess (WebKitGTK 2.50.4 / JSC 0.9.9, host libs, Ubuntu 22.04 build) aborts with SIGABRT from a JavaScriptCore internal assertion reached from JIT code, ~4ms after the `after-hydrate` mark and before `before-root-render`. The window then shows an empty white page; the Inspector's own separate WebKitWebProcess stays alive and keeps its stale DOM tree, which is what looked like "WebProcess alive at 1% CPU, #root empty". WEBKIT_DISABLE_DMABUF_RENDERER is not the crash site: with the DMABUF renderer left enabled the natural inspector-attach time lands in the crash window 6/6, with `=1` it usually lands just before it (0/6 natural, but 2 crashes in 8 launches once the attach is deliberately delayed by 100-150ms). The packaged AppImage never calls open_devtools, so it is not exposed.
fix: (none applied; goal find_root_cause_only). Candidate directions for the caller: (a) do not auto-open the inspector on Linux (the code comment justifies it only for macOS, "no right-click inspect"); keep it for macOS, or make it opt-in via an env var/flag; (b) if it must auto-open on Linux, defer it until the renderer has reported `frontendReady`/after-root-render instead of calling it in `.setup()`, and apply the same to the Humble login window at main.rs:7264; (c) for the blh live gate, launch the dev binary with the auto-open suppressed rather than with `WEBKIT_DISABLE_DMABUF_RENDERER=1`, because `=1` only hides the race, it does not remove it.
verification: not a fix, a diagnosis. Falsification tests run and passing: (1) same dev binary, unset, inspector show no-op'd via LD_PRELOAD: 3/3 then 6/6 render; (2) natural inspector, unset: 6/6 WebProcess abort (plus r1, s1, s2 straced/sampled); (3) inspector delayed >=400ms (unset): 0/8 crash (D=400,700,1000,1500,4000,10000); (4) the sitting-12 AppImage under the same harness: 2/2 render. Residual: the exact JSC assertion (which RELEASE_ASSERT) is unidentified; Ubuntu's debuginfod has no debuginfo for libjavascriptcoregtk-4.1 2.50.4 build-id 4deaa998..., so symbols are unavailable. Whether it is a JSC bug or an app-side trigger reachable only with the debugger attached is not established.
