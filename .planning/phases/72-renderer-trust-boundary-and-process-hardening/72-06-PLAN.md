<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer (and remote content in main) -> sidecar_send | `openExternalUrl` / `openFolder` / `showConfigFileInFolder` arguments are untrusted |
| sidecar -> Rust shell | sidecar forwards validated values; Rust re-checks |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-72-19 | Elevation of Privilege | openExternalUrl falling through to openPath | mitigate | URL-only `assertOpenableExternalUrl`; `openUrlOrFile` deleted; test asserts no platform call for `file:///x` |
| T-72-20 | Elevation of Privilege | openFolder opening an executable or .app | mitigate | `classifyFolderTarget` returns 'reveal' for files and bundles; Rust open_path rejects them anyway |
| T-72-21 | Tampering | showConfigFileInFolder path traversal via appName | mitigate | `assertContainedPath(gamesConfigPath, `${appName}.json`)`; test with `../evil` |
| T-72-22 | Information Disclosure | logging renderer-supplied paths/URLs | mitigate | category-only `logWarning`; fixed-literal error messages |
| T-72-23 | Denial of Service | relative folder_name / missing savesPath now rejected | accept | documented behaviour change; previously resolved against the sidecar cwd, which was wrong |
</threat_model>
