    Per-target algorithm in check_removal (items in request order; overall = Kleene AND of items; zero targets -> overall yes, no items):
    1. Lexical (identical on every OS): empty or NUL -> No/nul-byte (empty -> not-absolute); not absolute on the host OS -> No/not-absolute (so `.\\x`, `C:\\x` and `\\\\server\\share\\x` are relative on Unix and refused there); any `.` or `..` segment split on `/` and `\\` -> No/dot-segment.
    2. symlink_metadata(target): NotFound -> canonicalise the parent and append the name, mark absent = true, and continue the containment, protected-root and known-install checks on that location (absent + all checks pass = Yes/ok, nothing to delete). Other error -> Unknown/canonicalize-failed.
    3. Links (D-15): is_link = file_type().is_symlink() OR (Windows) the FILE_ATTRIBUTE_REPARSE_POINT bit 0x400 from MetadataExt::file_attributes. For a link the location is canonical(parent) + the link's own name; the referent is never canonicalised or inspected.
    4. Otherwise location = dunce::canonicalize(target); for comparison keys strip `\\\\?\\` and map `\\\\?\\UNC\\` to `\\\\` (port the contain.rs vectors as unit tests).
    5. Protected roots: always protect filesystem roots, drive roots and UNC share roots (a location with no Normal components after the prefix/root). For each non-empty caller protected root (canonical, or lexical-absolute when it does not exist; a non-absolute one -> Unknown/not-absolute): location equal to it or an ancestor of it -> No/is-protected-root.

None -> allowed only for kinds game-install, prefix and sideload-folder when protected_roots is non-empty; otherwise (and always for bottle, game-support, app-data) -> Unknown/no-trust-root. The trust root is never derived from the target, a manifest or a library entry (D-08 rule) — it only ever arrives as a parameter.
    7. Known installs (D-16) as in Task 1, comparing against the link location for links.

Kind rules: prefix — a non-link, non-empty directory with neither drive_c nor pfx at its top level -> No/not-a-prefix (moves today's TS heuristic into the one implementation, D-06). sideload-folder (D-22) — if the top level holds any entry other than the game's own executable (the executable's first path segment under the folder, so its own .app bundle counts as its own) that is an app bundle (.app directory) or an executable-looking file (case-insensitive extensions .exe .bat .cmd .com .msi .lnk .sh .command .appimage .x86 .x86_64, or on Unix any regular file with an execute bit) -> No/folder-looks-shared.
