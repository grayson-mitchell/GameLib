## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest 29.x (`ts-jest` preset), 5 projects (`backend` / `common` / `frontend` / `preload` / `meta`) |
| **Config file** | `jest.config.js` (root) — `testEnvironment: 'node'` project-wide |
| **Quick run command** | `npx jest <path-to-file> --silent` |
| **Full suite command** | `pnpm test:ci` (`jest --runInBand --silent`) |
| **Estimated runtime** | Full suite ~several minutes (4400+ tests); single file ~5–20s |

**HARD CONSTRAINT — no jsdom, no react-test-renderer anywhere in this repo.**
Confirmed by `SideloadDialog/__tests__/index.test.tsx`'s own doc-comment. A test that imports a
`.tsx` dialog directly fails at `import './index.scss'` before any assertion runs. Therefore **no
test in this phase may prove a behavior by rendering a component and simulating a click.** Every
frontend deliverable must be proven either at the pure-function / zustand-store level (the
`SteamBottleSetup.test.ts` and `SideloadDialog/filters.ts` precedent — logic extracted OUT of the
`.tsx` specifically so it is testable) or at the manual UAT gate below.

## Sampling Rate

- **After every task commit:** Run `npx jest <the task's test file> --silent`
- **After every plan wave:** Run `pnpm test:ci`
- **Before `/gsd-verify-work`:** Full suite green **AND** the manual gate below executed
- **Max feedback latency:** ~20s (single file), full suite per wave

⚠ **A green Jest suite alone does NOT satisfy this phase's gate.** The primary deliverable — the
form actually opening and its choice actually reaching the bottle store — is structurally
unprovable in Jest here. The manual gate is load-bearing, not a formality.

## Named Vacuous-Assertion Risks (must be designed against, not discovered later)

1. **Store-flip ≠ dialog renders.** A test asserting `useInstallGameModal.setState({isOpen: true})`
   proves the store flipped, not that `InstallModal/index.tsx` renders a Steam branch. A green
   store test and a broken dialog are indistinguishable to Jest here. Mitigation is the manual
   gate — not a cleverer unit test.
2. **Write ≠ read.** Asserting `persistBottleWineVersion` was called proves the write. It is not
   evidence `SteamBottleSetup` reads it — two independent paths, two independent tests.
3. **Registration ≠ wired.** Asserting the handler is registered in both files proves
   registration, not that the preload seam exposes it. Verify `src/preload/` exposure in the *same*
   task, not a follow-up.
4. **One click-through ≠ coverage.** See the Manual-Only table — enumerate D-10's trigger rows
   crossed with native-install ON/OFF.
