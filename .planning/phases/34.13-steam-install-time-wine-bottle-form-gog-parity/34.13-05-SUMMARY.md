## Final Exported Contract (for 34.13-10, 34.13-11, 34.13-12)

`src/frontend/screens/Library/components/InstallModal/steamSectionGating.ts` — **zero runtime imports**, its only import is `import type { InstallPlatform } from 'common/types'`.

```ts
export type SteamPlatformRowMode =
  | 'absent'
  | 'readonly-windows'
  | 'readonly-macos'
  | 'selectable'

export interface SteamSectionGatingInput {
  hostPlatform: string        // ContextProvider's `platform`: 'darwin' | 'win32' | 'linux' (anything else, including 'unknown', folds into the Linux-family bucket)
  bottleRequired: boolean     // D-09: isSteamBottleEligible() verdict.eligible, mapped by the caller. OPAQUE INPUT -- never re-derived here.
  nativeInstallOn: boolean    // Settings > Steam > "Enable Steam native install"
  libraryCount: number        // listSteamLibraryTargets() result length (already gate-adjusted to 0 when nativeInstallOn is false)
  hasWindowsDepot: boolean    // caller's `gameInfo.is_windows_native === true` comparison -- ONLY `=== true` permits offering Windows
  selectedPlatform: InstallPlatform  // live `platformToInstall` state value
}

export interface SteamSectionGatingVerdict {
  platformRow: SteamPlatformRowMode
  libraryDropdown: boolean
  wineSection: boolean
  freeSpaceLine: boolean
  contentLightNotice: boolean
  forceWindowsViaBottle: boolean
}

export function resolveSteamSectionGating(
  input: SteamSectionGatingInput
): SteamSectionGatingVerdict
```

**Exactly six verdict fields. None is named `opens`.** No `steamInstallFormOpens()` function and no `alwaysShowOn` input exist anywhere in the module (proven by a comment-stripped source gate, not by inspection — see below). No `SteamInstallTriggerInput` type exists.

**Platform literals:** `selectedPlatform` and the platform-selection reasoning use the SAME `InstallPlatform` literals `InstallModal/index.tsx` already uses (`'Mac'` for macOS, `'Windows'`), so 34.13-12 can feed `platformToInstall` straight in with no mapping layer.

## 'unknown' Host-Platform Discretion Call

The UI-SPEC's Section-Gating Matrix table only names `macOS`, `Windows (host)` and `Linux (host)` — it does not enumerate ContextProvider's `'unknown'` fallback value (`src/frontend/types.ts:43`, `NodeJS.Platform | 'unknown'`). This module folds `'unknown'` into the Linux-family bucket (`platformRow: 'absent'`), on the reasoning that a host we cannot positively identify should get NO platform control rather than a possibly-wrong one — the conservative reading of D-18. This is a discretion call made by this plan's execution, not a UI-SPEC-stated rule; it is documented in the module's step-1 comment and pinned by a dedicated defensive test (`hostPlatform 'unknown' behaves as the Linux-family bucket`).
