<objective>
Give the Steam install two explicit doors and make every real entry point walk through one of them.

Today a Steam install has no door at all: `openInstallGameModal` short-circuits into
`startSteamInstall`, which opens a bespoke `SteamInstallLocationPicker` when there is more than one
library — and the game page's Install button does not even reach that code, firing its own hardcoded
`window.api.install({...})` instead. After this plan there are exactly two exported entry points:

- **`startSteamQuickInstall(appName, gameInfo)`** — D-23's one-click default. Resolves Steam's
  primary library, runs D-24's cheap LOCAL validity check, and either installs with no friction at
  all (Phase 21 D-09, unchanged) or degrades into the options dialog carrying the problem.
- **`openSteamInstallOptions(appName, gameInfo, degrade?)`** — D-25's instant dialog. Synchronous,
  no IPC, no eligibility probe. The user already asked for it.

Purpose:
- **D-22** — the auto-open triggers retire. This plan is where they die: no predicate, no eligibility
  await, no always-show read on any path.
- **D-27 / RESEARCH Q4** — the six-row call-site map is right about line numbers and wrong about
  reachability. Four of six do not fire for Steam, and a seventh, uncounted site bypasses the
  chokepoint entirely. This plan makes the map real by routing rather than by relabelling.
- **D-21** — `MainButton` gains the true split: unchanged Install button plus a `Dropdown`-composed
  caret whose single panel item opens the options dialog.
- **D-04** — `SteamInstallLocationPicker` retires. Its job moves into 34.13-10's dropdown; its store,
  its component and its `App.tsx` mount are deleted outright.

Output: one rewritten store module, one new store test (a `34.13-VALIDATION.md` Wave-0 gap — no test
