<objective>
Rewrite the single Steam install chokepoint so it decides — instead of unconditionally
short-circuiting — and retire the surface it replaces.

`startSteamInstall` currently does one thing: fetch `listSteamLibraryTargets()`, and if there is
more than one library open a bespoke `SteamInstallLocationPicker`, else install silently. After this
plan it gathers the three facts 34.13-05's predicate needs (backend bottle verdict, library list,
the two global settings), asks `steamInstallFormOpens()` for the verdict, and then EITHER installs
with zero friction (Phase 21 D-09, unchanged) OR opens `useInstallGameModal` carrying everything the
Wave-5 `SteamDialog` needs so it never has to repeat a 15-second round-trip.

Purpose:
- **D-10** — the dual trigger must be expressed once, in 34.13-05's module. This plan is the caller
  that makes it load-bearing. `34.13-05-PLAN.md`'s own `<verification>` records a review obligation
  against *this* file: "a reviewer on those three plans must grep for a local
  `availablePlatforms.length > 1`, a second `libraryCount > 1`, or a `platformToInstall === 'Windows'`
  section condition." This plan closes that with a mocked-predicate discriminator, not a promise.
- **D-12** — the eligibility check runs BEFORE the dialog exists, so the busy state must be armed
  before the await and the `isOpen` flip must happen strictly after the verdict resolves. A
  same-tick snapshot cannot tell those two orderings apart; an ordered event log can.
- **D-11** — Windows/Linux always-show needs the library dropdown and the platform row without a
  wine section. That gating is 34.13-05's; this plan's obligation is to supply `nativeInstallOn`
  and `alwaysShowOn` from the one settings read 34.13-04 designated.
- **D-04** — `SteamInstallLocationPicker` retires. Its job (choose among registered libraries) moves
  into 34.13-10's dropdown; its store, its component and its `App.tsx` mount are deleted outright.

Output: one rewritten store module, one new test file (a `34.13-VALIDATION.md` Wave-0 gap — no test
covers this store today), two deleted files, one `App.tsx` edit, and one backend doc-comment repair.

**Scope fences (all hard):**

   (Wave 5) and 34.13-12 (Wave 6) import from it and must compile against the signatures landed
   here — so `installSteamGame`'s parameter list and `SteamInstallFormContext`'s field names are

   the D-12 spinner copy belongs to 34.13-11 and the catalog belongs to 34.13-13.
