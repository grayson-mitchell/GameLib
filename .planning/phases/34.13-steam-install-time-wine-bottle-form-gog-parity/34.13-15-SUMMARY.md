## D-29 Resolution, As Implemented

Console Mode's Steam effect now calls `probeSteamQuickInstallTarget()` before firing `install()`. On an ok verdict, behavior is byte-identical to before: the same `install({...})` call fires, followed by the 1500ms auto-dismiss timer — the timer is now armed inside the `.then()` ok branch rather than unconditionally at effect top level, so it can never race a failure that hasn't been decided yet. On a not-ok verdict, `setSteamBlocked(verdict.degrade)` is called and the function returns without installing and without arming any timer. The render swaps the transient "Opening Steam to install…" card for a terminal, non-dismissing failure card built entirely from classes already in the file: a `.consoleModalTitle.blocked` title (`--status-danger`), the unchanged `.consoleModalGameTitle`, one static `.consoleModalReason` line selected by `steamBlocked.reason`, and a single focused `consoleChip` Dismiss button. No platform row, no wine row, no library picker, no new `FocusKey` — structurally not an options surface. Both `BTN_ACTION` and the Enter/Space keydown branch route through `resolveConsoleActionIntent`, which returns `'dismiss'` unconditionally for `runner === 'steam'` (covering both the transient state and the failure state), so an A press can no longer fire the install the check just refused, and — as an intentional consequence, not scope creep — can no longer fire a second concurrent install during the transient "Opening Steam…" window either (a pre-existing latent defect this plan's fix incidentally closes, per the plan's own `<handoffs>` item 5).
