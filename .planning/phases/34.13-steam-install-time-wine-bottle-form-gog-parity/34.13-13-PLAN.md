1. **`pnpm lint-translations:gamelib` NEVER exits non-zero, and it is noisy today.** Measured:
   exit code `0`, **856 lines** of output, of which **53 are `Error: ENOENT`** stack traces. Cause:
   `meta/lintTranslations.ts` has no `process.exit` anywhere, and its `readFile()` catches every
   error and `console.log`s it (`lintTranslations.ts:58-67`). `gamelib.json` exists in **exactly one

   **Consequence: the gate as briefed ("`pnpm lint-translations:gamelib` green") is vacuous if

   a deliberately corrupt catalog.** Task 1 therefore gates on a **before/after output diff**, not
   on the exit code. This repo already carries multiple ledgered instances of a passing check that
   guarded nothing; do not add another.

   `en` (`lintTranslations.ts:177`) and iterates the *translation* file's keys, so with no non-`en`
   `gamelib.json` in the tree there is no file for it to check. Measured: **0** `Empty translation`
   lines and **0** `Missing content in translation` lines. The D-14 "one flat string, no `<Trans>`
   indexed tag" decision (34.13-10) is therefore **future-proofing, not a live failure** — it stays
   binding (it is frozen by 34.13-10 and this plan must not renegotiate it), but do not cite it in
   the SUMMARY as a measured avoided failure.
3. **Handoff 6 confirmed exactly.** In `public/locales/en/gamepage.json`: `button.install` =
   `"Install"`, `install.disk-space-left` = `"Space Available"`, `game.platform` = `"Select
   Platform Version to Install"` all already exist; `install.steam-location.title` and
   `install.steam-location.primary` are **`undefined`** — inline-default-only, reused as-is. None of
