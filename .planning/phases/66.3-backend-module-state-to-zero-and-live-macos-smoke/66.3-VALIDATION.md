## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | jest 29 + ts-jest; projects Backend, Common, Frontend, Preload, Meta, relay |
| **Config file** | `jest.config.js` (Meta project: `meta/jest.config.js`) |
| **Quick run command** | `pnpm jest <touched paths> --maxWorkers=2` |
| **Full suite command** | `pnpm test:ci` |
| **Estimated runtime** | quick ~5–60 s per task; census gates ~1.5 s; full suite several minutes |
| **Known baseline** | 66.2 recorded 10 failing tests in 8 suites at the pre-66 commit. Plan 01 re-measures it, and later plans compare against that list. |

---

## Sampling Rate

- **After every task commit:** touched suites (`pnpm jest <paths> --maxWorkers=2`); `node meta/backendDiCeilings.cjs --shard <shard>` for each edited shard; `npx prettier --file-info <path>` then `npx prettier --check <exact paths>` (never `.`); `pnpm codecheck` when types change.
- **Tasks touching boot order, processGuards, the shim or config (D-66.3-10, D-66.3-01..03):** also `pnpm build:sidecar && pnpm smoke:sidecar`.
- **After every plan wave:** `pnpm jest src/backend --maxWorkers=2`, `pnpm backend-di-ceilings`, `pnpm boundaries`, `pnpm lint`, `pnpm find-deadcode`, `pnpm steam-line-ceiling` (Steam waves), `pnpm planning-gates`, `pnpm build:sidecar && pnpm smoke:sidecar`.
- **Before `/gsd-verify-work`:** full battery green except the recorded baseline.
- **Max feedback latency:** ~60 s per task (quick run).
