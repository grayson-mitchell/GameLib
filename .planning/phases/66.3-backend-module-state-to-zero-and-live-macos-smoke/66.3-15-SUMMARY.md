# Phase 66.3 Plan 15: Steam bottle helpers and DXMT listeners off static holders Summary

Two boot-bound static holders are deleted, not moved: `bindBottleStores` / `BottleStores` (steam/bottle.ts) and `bindDxmtStores` / `DxmtStores` (tools/dxmt.ts). moduleState goes 157 -> 155 (102 -> 100 files); jestMock 2213 -> 2210.

## Tasks

- Task 1, f69ba9163: `createSteamBottle({ stores, config })`, new boot step, 21 importers plus the engine/tools/launcher/download-queue cascade on slices.
- Task 2, 00bf7cb36: `registerDxmtListeners(deps)` called by the 'secret-stores' boot step.

## Contracts

- `createSteamBottle({ stores: { steam: Pick<Stores['steam'],'steamBottleConfigStore'> }, config: Pick<GlobalConfigSlice,'getSettings'> })` returns `{ configStore(), persistedWineBins(), isCrossoverInstalled(deps), isSteamBottleProvisioned(), isBottleReady(name?), getSteamBottleSettings(), persistBottleWineVersion(v), resolveCrossoverWine(label) }`. Construction reads nothing (the store is resolved per call), writes nothing, no I/O (tested: no store/config read at construction, two instances never share state, no default for the required deps). The pure path helpers (`getBottleSteamappsDir`, `getBottleSteamExePath`, `bottleWineArch`, constants, `cxbottleIn`...) stay free exports. `getSteamBottleSettings` now reads the injected config slice, not `GlobalConfig.get()`.
- Slice types exported from bottle.ts: `SteamBottle`, `SteamBottleDeps`, `BottleSettingsDeps` (settings + resolveCrossoverWine), `BottleReadyDeps`, `SteamEngineBottle` (persistedWineBins + resolveCrossoverWine).
- `registerDxmtListeners({ stores, runner, onlineMonitor, dialogs, appState, events })` attaches exactly the three listeners (`wineVersionInstalled`, `wineVersionUninstalled`, `releasesInfoReady`) to `events` and returns an unregister function. Every dep is required, so the "runner not bound" / "wine-manager stores not bound" skip paths are impossible by construction. Importing `tools/dxmt.ts` registers nothing (tested in an isolated registry).
