## HumbleServices contract

```ts
createHumbleServices(deps: {
  stores: Pick<Stores, 'humble' | 'steam'>
  secretStore: HumbleSecretStore            // required: the boot's keyring or dev-vault store
  steamUser: Pick<SteamUser, 'isLoggedIn'>
  signInOutcomes: ManagerDeps['signIn']['outcomes']
  appInfo: Pick<AppInfo, 'userAgentFallback'>
}): { user: HumbleUser, library: HumbleLibrary, syncFence, loginWindowSeam, secretStore, appInfo }
```

The user and the library share the one sync fence and the one seam slot. Consumers take slices: `registerHumbleFlows({ ipc, humble: Pick<..,'user'|'library'>, config, notifications })`, `registerHumbleLoginFlows({ ipc, humble: Pick<..,'user'|'library'|'loginWindowSeam'|'appInfo'> })`, `registerOAuthLoginFlows`/`registerDevEpicCookieSweepFlow` get `loginWindowSeam`, the runner-auth registration and gog/legendary/nile user modules get `loginWindowSeam` through `ManagerDeps`, `signInProbe/pass` gets `humbleUser`, `steamFlowRegistration` gets `humble.library`, `runHumbleValidation({ user })`, `adapter.revealKey(deps, ...)` with `{ loginWindowSeam, appInfo }`.

## Boot path chosen: early construction, not the accessor

The plan allowed either early construction or a `getHumble` call-time accessor. Early construction was possible, so it was taken. The blocker the plan anticipated (the secret store is chosen after `rpc-server`) is only a blocker for the keyring touch, not for the choice:

- `'secret-vault'` (after `'config'`): `createDevSecretVault()` decides dev-vault vs keyring once. It does local file I/O only, no RPC.
- `'steamgrid-secrets'` and `'humble-services'` (after `'steam-user'`, before `'store-managers'` and `'register-handlers'`): build the owners over the chosen store. The keyring stores' construction does no I/O.
- `'secret-stores'` (unchanged position, after `rpc-server`): installs the Steam token store (vault or keyring), then in the keyring arm runs `startSidecarHumbleSecretStore` / `startSidecarSteamGridDbSecretStore`: the receipt line plus the one-time plaintext migration. T-28-10 placement preserved; bootSourceShape anchors pin the order. No storage format, keyring slot name, or fail-closed behaviour changed.
- `createDevSecretVault()` replaces `installDevSecretVault()` (returns `{ tokenStore, humbleSecretStore, steamGridDbSecretStore } | null`). The `[dev-secret-vault] INSTALLED` log now fires in `'secret-vault'`, earlier than before; the `[bootstrap] secret stores: dev-vault|keyring` receipt line is still logged by `'secret-stores'`.
