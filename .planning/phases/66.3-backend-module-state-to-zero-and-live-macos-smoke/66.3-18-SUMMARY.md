## Deviations from Plan

**1. [Rule 3 - Blocking] Delegate-only suites deleted.** `dialogStub`, `lifecycleStub` and `netStub` tested only the deleted shim (logged no-op members, the Electron-shaped `Notification`, `net`). Their real behaviour is covered by `host/__tests__/{dialogs,notifications,openExternal,appState}.test.ts`; the only unique assertions (Rust channel allowlist membership) moved to `host/__tests__/rustChannelAllowlist.test.ts`. Their `testContainment.test.ts` entries and ceiling lines were removed. `wakeLock`/`clipboardFlows` were kept, rebuilt over `host.appState`.

**2. [Rule 3] Test registry views.** About 12 sidecar suites read the shim's `handlerRegistry`/`listenerRegistry`. They now read `helpers/registryViews.ts` (Map-like views over an `IpcRegistry`), and `sidecarHarness.ts` exports views over the most recent boot's `host.ipc`.

**3. [Rule 3] `process.getSystemVersion` / `getSystemMemoryInfo`.** The deleted platform file carried the polyfill and the global type augmentation. Two call sites now use `os.release()` (behaviour identical: the polyfill was `os.release()`); the win32 memory probe reads `os.totalmem()/freemem()` (see Latent bugs).

**4. [Rule 3] Gate pins moved, with reasons.** (a) `gameDetailsImportGate` Gate 8 digest of `electronUntouched.test.ts` re-pinned: its last by-construction gate read the deleted `platform/index.ts` `safeStorage` stub (the file and member are gone, so the gate was removed, not weakened); Gate 6's git-less fallback regex for the same string dropped. (b) `seam-parity-sweep-gate.py` (planning gate) parsed the deleted stub: it now accepts the stub's absence (plan 17 had already emptied the importer pin) and fails hard if a `safeStorage` importer ever reappears without a stub to classify against.

**5. [Rule 1] `SteamGridDbSecretDeps` gained `config`.** `migrateSteamGridDbApiKey` and the Electron-shaped secret store still read `GlobalConfig.get()` (not in the plan's file list). They now take the boot's config slice (`config` joins `{ stores }` in the `secret-stores` step).

**6. OWNED_66_3 count.** The list holds 28 entries (plan 17 removed `humbleStores.ts`), not the 29 the plan text says; `platform/index.ts` stays on the list as the one file that must not exist.

**7. Test doubles keep the removed API's name in a few mocks** (`GameConfig: { get: jest.fn() }` in factories of games/steamStartupKeyring/dismissed tests). They are never called as a static getter, no production module imports either class by value, and the gate scans non-test code for calls. Left as-is, not rewritten.

## Latent bugs found

1. `SteamUser.logout()` never calls `resetSteamAuthTrigger()` (open from plans 13/16; recorded, not fixed). — **Fixed 2026-11-12 by quick 261112-7wv** (logout now resets the auth trigger via deps.steamSession).
2. The win32 memory probe called `process.getSystemMemoryInfo()`, an Electron main-process method that does not exist in the plain-Node sidecar: it would have thrown on Windows. Replaced with `os.totalmem()/freemem()` (bytes) while touching the file; no test covered it.
3. `isMacSonomaOrHigher()` (`utils.ts`) reads `os.release()` (the Darwin kernel major) and compares it with 14 (macOS Sonoma's major). Darwin 14 is OS X 10.10, so the check is true on any macOS the app supports. Pre-existing (the polyfill used `os.release()` too); behaviour unchanged, recorded.
4. `ElectronSteamGridDbSecretStore` is test-only dead code (plan 17); it now reads the injected config.
