# Phase 66.3 Plan 16: SteamUser as a boot-built instance Summary

The static `SteamUser` class is gone. One `SteamUser` is built per boot by `createSteamUser(deps)` in a new `'steam-user'` boot step; its 11 static fields and `boundStores` holder are instance fields, `bindStores` and the throw-if-unbound accessors are deleted, and `steam/user.ts`'s moduleState entry is deleted. moduleState goes 155 -> 144 (99 files); jestMock 2210 -> 2175.

## Tasks

- Task 1, d0fe5d352: instance class, `createSteamUser`, `'steam-user'` boot step, EOF release through an injected member, test doubles. Interim `@66.3-compat` static delegates (census 11 -> 1).
- Task 2, 08a56810f: every production consumer takes `Pick` slices from deps.
- Task 3, 131da1fbb: tests onto fresh instances; compat layer, binder call and census entry deleted; ceilings lowered.

## Contracts

`SteamUserDeps = SteamStoresDeps & { macSteamOffline, signIn: Pick<ManagerDeps['signIn'],'epochs'|'outcomes'>, steamSession: Pick<SteamSessionServices,'authTrigger'|'signIn'>, anonymousClient: Pick<AnonymousClient,'close'>, clock: Clock, config: Pick<GlobalConfigSlice,'getSettings'> }`, all required at construction (the carry-over from plan 14: `anonymousClient` is now a proper constructor dep, not the interim `bindStores` field). The Windows Steam-client probe reads `deps.config.getSettings()` instead of lazily requiring `backend/config`. The idle-close timer is `deps.clock.setTimeout` (unref'd by default, no `keepAlive`). The CM logon-bound timer (35 s) stays a raw unref'd `setTimeout`, unchanged.

## Boot step position and EOF wiring

`... config, steam-bottle, command-runner, steam-user, online-monitor-owner, engine-state, winetricks-queue, store-managers ...` ('steam-user' is also before 'i18n', so `requireServices` finds the field). `releaseOnStdinEof` deps gained `steamUser: Pick<SteamUser,'releaseForShutdown'>` and call `void deps.steamUser.releaseForShutdown()` in the same position, after the anonymous client release; the module no longer imports `SteamUser` as a value. The quit handler's `releaseSteam` keeps the order (anonymous first) and now runs the session release in a `finally`, so it still runs if the anonymous release throws. `build:sidecar` and `smoke:sidecar` pass (exit 0 on stdin EOF).

## Deviations from Plan

1. **[Rule 3 - ordering] Task 1 and Task 2 commits are not individually jest-green.** The plan expected the Task 1 verify (`jest steam/__tests__ ...`) and Task 2's `steam-line-ceiling` to pass on the compat layer. The suites drove state through the static class (resetting private fields, `bindStores`), so they could only be made green by the Task 3 rewrite; `steam-line-ceiling` failed at 1080 lines until the compat block (about 110 lines) was deleted in Task 3 (user.ts is 914 lines now). `codecheck`, `build:sidecar` and `smoke:sidecar` were green at each commit; the full jest check and every gate are green at the end.
2. **[Rule 2] Quit handler hardened.** `releaseSteam` now uses `try/finally` so the session release runs even when the anonymous release throws (the carry-over from plan 14 asked for exactly this).
3. **[Rule 3] `humbleStores` gained `steamUser`** (cascade edit only) because `humble/library.ts` called the static; the plan's file list already named those files.
4. `signInProbe/pass.ts` takes the session through `SignInProbeDeps` (not constructor deps): the pass is built in an earlier boot step than 'steam-user', so it reads the instance when `start()` runs.

## Latent bugs found

- `resetSteamAuthTrigger()` is documented for Steam logout but `SteamUser.logout()` still never calls it (it calls `steamSession.signIn.resetSignInState()` only). Carried over from plan 14 and deliberately not fixed here; the auth-unlock latch survives a sign-out.
- `SteamUser.getLogonFailure()` and the lease `release` helpers are safe to call unbound only because they are called as methods; the `Pick` slices keep that true, but a future consumer that destructures `acquireAuthenticated` loses `this`. Documented rather than guarded.
