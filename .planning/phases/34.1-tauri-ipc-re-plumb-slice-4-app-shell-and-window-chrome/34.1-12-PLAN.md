<the_i18n_constraint_that_decides_the_approach>
READ THIS FIRST. It determines what the fix actually is.

The gap report says "Drop '(requires restart)' from the description string" and warns that the
string is in the BASE `en` catalog, not the `gamelib:` namespace, so the blocking i18n gate applies
— regenerate, never hand-edit. Both halves are correct, and TOGETHER they mean the string cannot
stay where it is:

`meta/i18nCatalogChurnGuard.ts` classifies every changed path under `public/locales/` into
`gamelib` (allowed: `gamelib.json`, `gamelib.mt.json`) or `upstream` (FORBIDDEN: everything else,
including `translation.json`) and throws `UpstreamChurnError` on any upstream change. Its own error
text says: *"Do NOT hand-edit the catalog to paper over this -- revert with
`git checkout -- public/locales/` and fix the call site."* That guard runs under `pnpm test:ci` as
a live-working-tree assertion, and `.husky/pre-push` runs `pnpm i18n --fail-on-update`.

So editing `translation.json` — by hand OR by regeneration — is blocked by design. **The fix is to
move the string into the fork-owned namespace**, which is exactly D-06's split-brain design: fork
content lives in `gamelib.json`, upstream content stays in `translation.json`. GameLib's live-apply
frameless toggle IS fork content — the corrected copy describes fork behaviour that upstream does
not have.

`i18next-parser.config.js` sets `keepRemoved: true` (D-03), so retiring the three old
`setting.frameless-window.*` keys from the code does NOT delete them from `translation.json` —
they simply stop being referenced. That means ZERO upstream churn. This is what makes the approach
work.

<interfaces>
The project's `gamelib:` call-site idiom (17 files, and the reason `i18next-parser.config.js`'s
lexers list `functions: ['t', 'tGamelib']`):

  const { t: tGamelib } = useTranslation('gamelib')
  ...
  tGamelib('gamelib:settings.wineDefaultLabel', 'Wine Default')

The `gamelib:` prefix inside the key is REQUIRED and safe. The incompatible form is the TUPLE
idiom (`t(['key', 'fallback'])`) — do not use it.

`public/locales/en/gamelib.json` top-level keys: `app`, `consoleMode`, `discounts`,
`downloadManager`, `gamepage`, `humble`, `library`, `login`, `redeemKey`, `settings`, `sideload`,
`themeSelector`. The `settings` object is FLAT (`gamescopeFsr`, `gamescopeUpscaleMethod`,
`gamescopeWindowType`, `wineDefaultLabel`, `wineFlatpakPath`) — so the new key is
`settings.framelessWindowDescription`, not a nested `settings.framelessWindow.description`.

`UseFramelessWindow.tsx` as it stands today — 59 lines, three `t()` call sites plus two
upstream button labels inside the dialog:

All five become unreferenced. All five stay in `translation.json` because of `keepRemoved: true`.

`src/frontend/screens/Settings/components/UseFramelessWindow.tsx` is NOT in
