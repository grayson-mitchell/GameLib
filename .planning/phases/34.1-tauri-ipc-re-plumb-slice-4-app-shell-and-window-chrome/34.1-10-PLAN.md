<objective>
Close the mechanism half of gap G4 (UAT test 9, DECISION REVERSAL, major): `.setDecorations(false)`
is NOT the Tauri translation of Electron's `titleBarStyle: 'hidden'`. On macOS the Electron variant
hides chrome but KEEPS the traffic lights; the Tauri call strips every decoration. Tauri's actual
equivalent — the window config key `titleBarStyle: "Overlay"` — was never set.

Purpose: a cross-shell port that swaps the MECHANISM silently changed the PRODUCT decision. Setting
the config key restores the traffic lights; reconciling `setDecorations` stops the runtime from
immediately taking them away again. Leaving both mechanisms competing would restore the lights at
window creation and strip them on the first `applyFramelessDecorations()` call — a worse, flickering
version of the same bug.

Output: `"titleBarStyle": "Overlay"` on the `main` window; a shared `isMacWebview()` predicate;
`applyFramelessDecorations` as a declared, logged macOS no-op; a config gate; retuned frameless
runtime tests.

**Scope boundary — the frontend half of G4 lives in plan 34.1-11** (the 78px reserve, the macOS
`WindowControls` gate, the `shellTokens.test.ts` retune). This plan touches nothing under
`src/frontend/`.
</objective>

<forced_consequence>
READ THIS BEFORE WRITING ANY CODE. It is the one non-obvious constraint in this plan.

`titleBarStyle` is a **static window-creation config key**. Tauri v2 exposes NO JavaScript API to
change it at runtime (`@tauri-apps/api/window` has `setDecorations`, not `setTitleBarStyle`; the
macOS-only Rust extension trait is not surfaced to the webview either). Therefore:

**On macOS the overlaid titlebar + native traffic lights become the window's PERMANENT appearance,
whether `settings.framelessWindow` is on or off.** This is a forced consequence of the D-06
reversal, not an additional product choice — there is no mechanism that would let the setting
toggle it.

The direct corollary: **`settings.framelessWindow` becomes decoration-inert on macOS.** The setting
still persists, still drives `.frameless` class application in the frontend, and still governs
Windows/Linux decorations — it simply no longer changes macOS window decorations, because doing so
would strip the traffic lights this decision exists to restore.

How the toggle should be PRESENTED to a macOS user given this is a genuine product question. It is
NOT decided here. It is routed to a `checkpoint:decision` in plan 34.1-14's live gate, where the
user is looking at the running window. Do not hide, relabel, or platform-branch the toggle in this
plan.
</forced_consequence>

| Boundary | Description |
|----------|-------------|
| renderer -> Tauri core (main window) | `tauri.conf.json` defines the main window; `capabilities/default.json` defines what the renderer may invoke on it. This plan edits the former. |
| remote content -> main window chrome | The main window renders remote/store content in the `content` grid row. `titleBarStyle: "Overlay"` extends the webview's drawing area under the titlebar region on macOS. |
