# Phase 34.1 Plan 06: Real Tauri Tray (D-11) Summary

**A bounded Tauri `TrayIcon` (tooltip, left-click show/focus, two-item Show/Quit menu) built non-fatally at `.setup()`, driven by a new `tray_set_icon` rustInvoke arm -- the slice's only new Rust arm -- with `changeTrayColor` wired to it via a 500ms collapsing settle timer.**

## Performance

- **Duration:** ~45 min
- **Completed:** 2026-07-25
- **Tasks:** 3/3
- **Files modified:** 7 (3 implementation, 3 test, Cargo.lock as a dependency-resolution side effect)

## Accomplishments
- Real `TrayIcon` construction at Tauri `.setup()`: `tray-icon` Cargo feature enabled, both icon variants (`public/icon-dark.png`/`icon-light.png`) embedded via `include_bytes!` (sidestepping this repo's recurring publicDir/getAppPath runtime path-resolution failure family), a `tray_image()` helper with an infallible three-step fallback chain (requested variant -> light variant -> blank 1x1 pixel) so a bad asset can never panic `.setup()`.
- `tray_set_icon` -- the ONE new `dispatch_rust_channel` arm across the entire 34.1 slice -- parses `{ dark }` (default `false` on bad payload), looks up the tray via `tray_by_id`, and resolves `Value::Null` whether or not a tray currently exists (a missing tray is not an error condition).
- `changeTrayColor` sidecar registration (`appShellFlowRegistration.ts`) mirrors `tray_icon.ts:51` exactly: logs immediately, then after a 500ms settle delay reads `darkTrayIcon` from `GlobalConfig` and forwards it through `requestRustInvoke(RUST_TRAY_SET_ICON, ...)`. A module-level timer handle collapses repeated sends within the window to a single invoke (T-34.1-23). `registerAppShellFlows()` also performs one guarded, `setImmediate`-deferred initial sync so the tray's startup light-variant default gets corrected without waiting on a user toggle.
- Every failure path -- menu-item build, menu build, tray build, `GlobalConfig` read, `requestRustInvoke` rejection -- is logged and non-fatal; nothing panics `.setup()` and nothing crashes the sidecar (T-34.1-22).
- Automated gates pin the tray's bounded scope: a negative source-gate test proves `main.rs` contains none of the declared out-of-scope menu depth (`recent`/`dock`/`Reload`/`Debug`/`openDevTools`), and a dispatch-arm-count test proves `tray_set_icon` is the only new arm added.

## Decisions Made
- Added `image-png` alongside `tray-icon` in Cargo.toml (Rule 3): `Image::from_bytes` (used by `tray_image()`) is gated behind the `image-ico`/`image-png` features and is not implied by `tray-icon` alone -- confirmed by a real `cargo check` failure (`E0599: no function ... from_bytes`) before the fix, and a clean `cargo check` after. This means Task 1's literal acceptance-criterion grep for the exact string `features = ["tray-icon"]` no longer matches (the line is now `features = ["tray-icon", "image-png"]`); the underlying intent -- tray-icon enabled, no unrelated features -- is verified instead via `cargoFeatures.test.ts`'s parsed feature-list assertion, which is robust to this addition.
- `changeTrayColor`'s initial sync (correcting the tray's startup light-variant default) is deferred via `setImmediate` rather than run synchronously at `registerAppShellFlows()`'s own top-level call. `registerAppShellFlows()` executes at `handlers.ts`'s synchronous module-scope import, which happens BEFORE `bootstrap.ts`'s `initLogger()` step -- and `GlobalConfig.get()`'s first-ever call in the process can itself synchronously call `logInfo`/`logError` on the config-version-upgrade path (`config.ts:145/152`), which would throw before the sidecar ever reaches READY if not deferred. This mirrors the exact precedent already established in `downloadQueueFlowRegistration.ts` (D-05) for the same class of hazard.
- Left `linux-libxdo` off the `tray-icon` feature set. The plan's own research (34.1-RESEARCH.md Assumption A3) flagged this as unverified for menu-on-click support on some Linux desktops; I did not find authoritative confirmation it's required, so it stays off per the plan's explicit instruction to record this as an open question rather than guess.
- `changeTrayColor`'s jest coverage fires the registered listener directly via `listenerRegistry.get('changeTrayColor')` rather than through the RPC/stream pipe (`writeSend`/`flush`) the rest of the file uses. `registerAppShellFlows()` runs exactly once at file-import time (same precedent already documented for this file's lock/unlock coverage), and `changeTrayColor` has no stream-side effects of its own to exercise -- going through the stream layer would only add real-I/O-vs-fake-timer interleaving risk. The "registerAppShellFlows() performs exactly one initial sync invoke" test uses `jest.isolateModules` (first use of this pattern in the sidecar test suite) specifically because re-invoking the SHARED module's `registerAppShellFlows()` a second time would double-register every other channel's listener too, breaking assumptions in this file's other tests.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added the `image-png` Cargo feature**
- **Found during:** Task 1 (enabling `tray-icon` and building the tray)
- **Issue:** `Image::from_bytes()` (needed by `tray_image()` to decode the embedded PNG bytes) is compiled only under the `image-ico`/`image-png` Tauri crate features. `tray-icon` does not imply either. Compiling with only `features = ["tray-icon"]` failed with `error[E0599]: no function or associated item named 'from_bytes' found for struct 'tauri::image::Image<'a>'`.
- **Fix:** Added `image-png` to the `tauri` dependency's feature list: `features = ["tray-icon", "image-png"]`.
- **Files modified:** `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` (transitively pulls in `image`, `moxcms`, `pxfm`, `byteorder-lite`)
- **Verification:** `cd src-tauri && cargo check` exits 0 with no warnings; `cargoFeatures.test.ts`'s new parsed-feature-list assertion passes.
- **Committed in:** `bb2a9d69` (Task 1 commit)

**2. [Rule 1 - Bug] Fixed the "zero new dispatch arm" test's over-broad match regex**
- **Found during:** Task 3 (writing the dispatch-arm-count negative-bound test)
- **Issue:** An initial `/^\s*"[a-z_]+"\s*=>/gm` regex matched not just `dispatch_rust_channel`'s outer match arms but also nested inner matches elsewhere in the file (`dialog_message`'s `"error"`/`"warning"` `MessageDialogKind` arms) and the tray's own `on_menu_event` closure's `"show"`/`"quit"` `MenuId` matches -- a structurally different match statement at a different indent depth. This produced false positives (`newArms` contained `error`, `warning`, `show`, `quit` in addition to the real `tray_set_icon`).
- **Fix:** Scoped the regex to the outer match arms' exact 8-space indentation (`/^ {8}"[a-z_]+"\s*=>/gm`), verified against every existing pre-34.1-06 arm's actual indentation in the source.
- **Files modified:** `src/backend/__tests__/tauriShellSource.test.ts`
- **Verification:** Test passes with `newArms` equal to exactly `['tray_set_icon']`.
- **Committed in:** `e7d551fd` (Task 3 commit)

**3. [Rule 1 - Bug] Fixed a test-isolation dependency on execution order in appShellFlows.test.ts**
- **Found during:** Task 3, spot-checking the new fake-timer tests in isolation via `-t`
- **Issue:** `fireChangeTrayColor()` (a test helper calling the registered `changeTrayColor` listener directly) triggers `logInfo(...)` synchronously, which requires `heroicLogWriter` to already be assigned via `bootstrap.ts`'s real `initHeadless()`. That only happens inside `startSidecar()`. In a full-suite run, an EARLIER test's `startSidecar()` call happened to initialize the logger first, masking the dependency; running the new describe block in isolation (`-t "REQ-34.1-07 invokes nothing before 500ms"`) crashed with `TypeError: Cannot read properties of undefined (reading 'logInfo')`.
- **Fix:** Added a `startSidecar()` call (result discarded) to this describe block's own `beforeEach`, making it self-sufficient regardless of test execution order or filtering.
- **Files modified:** `src/backend/sidecar/__tests__/appShellFlows.test.ts`
- **Verification:** Re-ran the isolated test via `-t` filter (passes) and the full file (still 27/27 passing).
- **Committed in:** `e7d551fd` (Task 3 commit)
