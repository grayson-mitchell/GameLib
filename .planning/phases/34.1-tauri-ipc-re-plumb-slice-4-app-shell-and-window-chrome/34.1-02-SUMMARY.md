## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corrected `getCustomCSS`'s extracted return type**
- **Found during:** Task 2 (`npx tsc --noEmit` verification after converting `main.ts`'s registrations to delegations)
- **Issue:** The plan's Task 1 prose specified `getCustomCSS(): Promise<string | undefined>`, but `AppSettings.customCSS` is declared `string` (not optional) in `common/types.ts`, and `AsyncIPCFunctions.getCustomCSS` declares `() => Promise<string>`. The `Promise<string | undefined>` annotation compiled fine in isolation but failed `main.ts`'s `addHandler('getCustomCSS', async () => getCustomCSS())` delegation with `TS2322: Type 'Promise<string | undefined>' is not assignable to type 'string | Promise<string>'`. The pre-extraction inline arrow function had no explicit annotation, so TypeScript's contextual typing silently matched it against `Promise<string>` — the mismatch only surfaced once the return type was pulled out and given its own explicit signature.
- **Fix:** Changed `getCustomCSS`'s return type to `Promise<string>` in `src/backend/appshell/themes.ts`. Runtime behavior is unaffected — the function body (`return GlobalConfig.get().getSettings().customCSS`) is unchanged, and can still resolve `undefined` at runtime if settings are malformed (proven by Task 3's own test, which mocks a settings object with no `customCSS` key and asserts `toBeUndefined()`); only the compile-time annotation was corrected.
- **Files modified:** `src/backend/appshell/themes.ts`
- **Verification:** `npx tsc --noEmit -p tsconfig.json` clean; `pnpm jest` 128/128 suites green.
- **Committed in:** `5495962f` (Task 3 commit — the fix was made during Task 2's verification pass but not staged until Task 3's commit; documented here rather than left silent)
