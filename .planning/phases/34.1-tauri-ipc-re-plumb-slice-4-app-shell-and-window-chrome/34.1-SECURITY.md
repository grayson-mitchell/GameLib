# Phase 34.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

Register origin: **plan-time** (`register_authored_at_plan_time: true`) — every threat below was authored in a `<threat_model>` block in one of the eight `34.1-0N-PLAN.md` files. This audit verified that each declared mitigation exists in the shipped code, not merely in plan prose. Mitigations claimed as "asserted by test" were confirmed by opening the test and checking the assertion is real and non-vacuous.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| remote content → Tauri `main` window IPC | The store-search surface (and, from 34.4, the Humble login page) renders inside the `main` window. Tauri has no `<webview>` isolation boundary, so remote script inherits every capability granted to `main`. | Full Rust command surface granted to `main` |
| renderer JS → Rust core commands | Every `core:window:*` / `core:webview:*` grant is a directly-invokable Rust command from any script running in `main`. | Window/webview control calls |
| renderer → sidecar `getThemeCSS(theme)` | A renderer-supplied filename is `path.join`ed onto `customThemesPath` and read from disk. | Arbitrary filename → file contents |
| renderer → sidecar `openWebviewPage(url)` | A renderer-supplied URL reaches `openUrlOrFile` → `shell.openExternal` → the OS handler. | Arbitrary URL/scheme |
| sidecar process → `src/backend/appshell/*` | These modules join the sidecar's import graph; anything they transitively import loads in the sidecar (which must never load `electron`). | Module graph |
| settings snapshot → `setDecorations()` | `framelessWindow` comes from the store snapshot, populated over the sidecar transport. | Config booleans (allow-list gated) |
| document event stream → `startDragging()` / `toggleMaximize()` | Any script can synthesize a `mousedown` in the drag region. | Synthetic UI events (`isTrusted: false`) |
| child window → Tauri command surface | Capabilities resolve per window LABEL. `default.json` names only `main`, so `about` and `external-<n>` match nothing. | Capability inheritance (denied) |
| compile-time tray icon bytes | Tray images are `include_bytes!`-embedded; no runtime path is resolved and no file can be substituted post-build. | None (sealed at build) |
| this slice's declared-channel docs → the Phase 35 cutover reader | `34.1-PORTED-CHANNELS.md` and SEAM.md are what a future agent reads to decide whether the cutover is safe. Their accuracy IS a security control. | Claims of coverage |
| `src-tauri/Cargo.toml` feature flags → the Rust dependency tree | Flipping an optional `tauri` feature can pull new registry crates transitively. | Third-party crate source |

## Accepted Risks Log

| Risk ID | Threat Ref | Rationale | Accepted By | Date |
|---------|------------|-----------|-------------|------|
| AR-34.1-01 | T-34.1-02 | `core:window:allow-close` is reachable by remote content in `main`. `main` is the app's own window and script there can already close its own document context; there is no unsaved state to lose. Routing close through the sidecar would reintroduce the round-trip D-01 rejected. **Re-evaluate in Phase 34.4** when a real remote login page ships. | Grayson Mitchell | 2026-07-25 |
| AR-34.1-02 | T-34.1-05, T-34.1-13 | `getThemeCSS(theme)` uses `path.join` and can be walked out of `customThemesPath`. Pre-existing Electron behavior extracted verbatim under D-07 (byte-equivalent extraction, no "improvements"); the caller is the app's own settings UI, `customThemesPath` is user-chosen, and the read returns to the same renderer that asked. Changing semantics inside a mechanical port would hide a behavior change. **Named target for a later hardening pass** — this repo's containment idiom is `resolve` + `relative`, not `path.join`. | Grayson Mitchell | 2026-07-25 |
| AR-34.1-03 | T-34.1-09 | Synthesized drag / toggle-maximize / close events are window-chrome actions on the app's own window with no data effect and no privilege gain. The underlying commands are directly reachable regardless of the drag-region listener, so the listener widens nothing. Subsumed by AR-34.1-01's grant-set acceptance. | Grayson Mitchell | 2026-07-25 |
| AR-34.1-04 | T-34.1-12 | `openWebviewPage(url)` / `openReleases` reach `shell.openExternal` with no scheme filter (`file://`, `smb://`, registered custom protocols). Ported at parity from `main.ts:719` over the already-shipped `open_external` command reviewed in Phases 30/33. Scheme filtering would be a behavior change smuggled inside a port. **Named target for a later hardening pass covering all `open*` channels at once** — slice 6 owns 20 more of them. | Grayson Mitchell | 2026-07-25 |
| AR-34.1-05 | T-34.1-18 | `window.api.gamepadAction` lets any script in `main` synthesize clicks/keys on GameLib's own UI. The same capability exists today under Electron, where the channel drives `webContents.sendInputEvent` — genuinely *trusted* input, strictly more powerful. The Tauri implementation dispatches `isTrusted: false` events, a net reduction in risk. **Named entry for the Phase 35 `window.api` surface review.** | Grayson Mitchell | 2026-07-25 |
| AR-34.1-06 | T-34.1-30 | `createNewWindow` has no cap on window creation, at parity with Electron's uncapped `new BrowserWindow` per call. The About window — the only case a user can repeatedly trigger — is deduplicated by label. A global cap would be a behavior change smuggled into a port. | Grayson Mitchell | 2026-07-25 |
| AR-34.1-07 | T-34.1-SC | **Corrected disclosure — supersedes plan 34.1-06's inaccurate rationale.** Plan 34.1-06 stated "No new crate and no new npm package… No registry fetch of an unaudited package occurs." That is false. Enabling `features = ["tray-icon", "image-png"]` on the existing `tauri` dependency (`Cargo.toml:15`, commit `bb2a9d69`) pulled **4 crates that were not previously in `Cargo.lock`**: `image` 0.25.10, `moxcms` 0.8.1, `pxfm` 0.1.29, `byteorder-lite` 0.1.0. **Accepted because:** (a) all four are checksum-pinned in `Cargo.lock` against crates.io; (b) they arrive transitively through Tauri's own declared optional feature, not an ad-hoc dependency pick — `image` and `byteorder-lite` are image-rs org crates, `moxcms`/`pxfm` are `image` 0.25.x's color-math deps; (c) they are pure image-decode/color code with no network or process surface; (d) the feature is not droppable — `Image::from_bytes` is gated behind `image-ico`/`image-png` and will not compile without it, and `image-ico` pulls the same `image` crate. **Residual:** no test pins the crate set, so a future feature flip could repeat this silently — see FOLLOW-UP-1. | Grayson Mitchell | 2026-07-25 |

*Accepted risks do not resurface in future audit runs.*
