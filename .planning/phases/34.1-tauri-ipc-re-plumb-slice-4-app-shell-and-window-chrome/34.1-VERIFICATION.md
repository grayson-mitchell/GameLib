### Residual Gap Assessment (from REVIEW-FIX.md's own disclosure)

**Headless i18next init was NOT added to the sidecar bootstrap.** The fixer's chosen remedy for
CR-01 makes the *persist path* independent of i18next (verified above), which restores full
user-visible correctness for the language SETTING (the renderer runs its own i18next instance for
every string it displays). What remains degraded: **backend-side strings** (tray labels,
dialog/notification text built server-side, e.g. `handleExit`'s confirm dialog) render in English
under Tauri regardless of the user's chosen language, because the shared `i18next` singleton is
never `.init()`'d outside `app.whenReady()`.

Judgment: this does **not** leave any of the 12 REQs unmet. REQ-34.1-05 requires the channel to be
registered and functional (it is — the setting persists); REQ-34.1-09's no-op declarations don't
cover this; no requirement text commits to backend-string localization under Tauri. This is
legitimately a tracked follow-up, honestly disclosed in the fix report's own "Residual gaps"
section rather than hidden, and does not block this phase's goal. Recommend it be picked up
whenever a future phase touches sidecar bootstrap ordering (flagged by the fixer as high-risk to
touch blind).
