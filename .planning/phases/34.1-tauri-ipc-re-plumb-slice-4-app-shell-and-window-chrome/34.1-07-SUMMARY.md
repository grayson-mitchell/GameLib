# Phase 34.1 Plan 07: Window Primitive (createNewWindow / showAboutWindow) Summary

**`createNewWindow` and `showAboutWindow` become genuine Tauri `WebviewWindow`s, fail-closed by per-window-label capability scoping, resolving 34.1-RESEARCH.md's Open Question 1 as renderer-side (Tauri JS) with zero new Rust arms.**

## Accomplishments
- `core:webview:allow-create-webview-window` granted, scoped strictly to `windows: ["main"]`; pinned by 5 new tests in `capabilitiesDefault.test.ts` (10/10 total) proving the exact grant, the exact `windows` array, exactly one capability file, the absence of the broader bare `core:webview:allow-create-webview` identifier, and the presence of the fail-closed rationale in `description`.
- `public/about.html`: a fully static, capability-free About page (62 lines) showing the GameLib name, `icon.png` logo, `GPL V3` licence, and the repo URL as plain text, reading its version from `location.search`'s `v` param with an `unknown` fallback, carrying its own CSP meta tag.
- `src/preload/api/tauriChildWindows.ts`: `tauriCreateNewWindow`/`tauriShowAboutWindow` against `@tauri-apps/api/webviewWindow`. Labels are a monotonic counter (`external-<n>`) or the fixed `about` label — never derived from the URL, never `main`. Both exports are total (try/catch + `console.warn`, never throw). `showAboutWindow` dedupes via `WebviewWindow.getByLabel('about')` + `setFocus()` and falls back to `?v=unknown` if `getHeroicVersion()` rejects.
- `helpers.ts`'s `showAboutWindow`/`createNewWindow` now short-circuit on `isTauri()` to the new module, matching `misc.ts`'s existing D-01 window-chrome wrapper shape exactly; the Electron path (`makeListenerCaller`) is untouched and byte-identical.
- 8 new `REQ-34.1-08`-tagged tests in `childWindows.test.ts` prove construction args/dimensions, per-call label uniqueness (including same-URL calls), the about-window dedupe path, the version-rejection fallback, total error handling on constructor throw, and the `isTauri()`-false routing to the untouched Electron IPC path.
- `pnpm jest`: 135 suites / 2456 tests green (up from the pre-plan baseline of 134/2443). `npx tsc --noEmit` clean.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added a `@tauri-apps/api/webviewWindow` mock to `tauriAttach.test.ts`**
- **Found during:** Task 3, running the full preload suite after wiring `helpers.ts` to statically import `tauriChildWindows.ts`
- **Issue:** `tauriAttach.test.ts` imports the real `../tauriAttach` module, which now transitively pulls in `@tauri-apps/api/webviewWindow` (via `./api` → `./api/helpers.ts` → `./tauriChildWindows`). That package's own top-level code calls `applyMixins(WebviewWindow, [Window, Webview])`, reading `Window.prototype`/`Webview.prototype` off the REAL `@tauri-apps/api/window`/`@tauri-apps/api/webview` modules — but this test file's existing mocks for those two packages are plain objects with no `prototype`, so the import chain threw `TypeError: Cannot read properties of undefined (reading 'prototype')` before any of the file's 3 tests could run.
- **Fix:** Added `jest.mock('@tauri-apps/api/webviewWindow', () => ({ WebviewWindow: jest.fn() }))` alongside the file's existing `@tauri-apps/api/window`/`@tauri-apps/api/webview` mocks, with a doc-comment paragraph explaining why (mirroring the file's existing Phase 34.1 Plan 03 doc-comment for the same class of problem).
- **Files modified:** `src/preload/__tests__/tauriAttach.test.ts`
- **Verification:** All 3 previously-failing tests pass; full preload suite (88/88) and full repo suite (135/135, 2456 tests) green; `npx tsc --noEmit` clean.
