## D-06 reversal — decided 2026-08-13

The 2026-07-25 session closed D-06 as "custom buttons on every platform, divergence accepted,
stop investing in frameless." **That decision is REVERSED.** It is preserved above as
`superseded_result` rather than deleted, because the reasoning that produced it was sound on the
information available at the time — what changed is that the information was incomplete.

**The decision:** on macOS, GameLib adopts an overlaid titlebar with **native traffic lights**.

- `src-tauri/tauri.conf.json` — set `"titleBarStyle": "Overlay"` on the `main` window. Its
  window block currently carries ONLY `label`/`title`/`width`/`height`/`resizable` — there is no
  titlebar key of any kind today.
- `--traffic-light-inset` — `0px` → **78px**.
- `WindowControls` — renders on **Windows/Linux only**; hidden on macOS.

**Why the traffic lights disappeared — an unmade decision, not a regression.** Electron and Tauri
were never reconciled:

- Electron sets `windowProps.titleBarStyle = 'hidden'` (`src/backend/main_window.ts:48`), which
  on macOS hides the chrome but **KEEPS the traffic lights**. `main_window.ts:16` also counts
  `titleBarStyle === 'hidden'` as frameless, so `WindowControls` renders too. That is the "both
  sets of buttons" the user remembered — and it IS the duplication D-06 was raised about.
- Tauri only ever calls `.setDecorations(!resolved)`
  (`src/preload/api/tauriWindowChrome.ts:279`). On macOS `setDecorations(false)` strips **all**
  decorations, traffic lights included. Tauri's actual equivalent of Electron's `hidden` is the
  config key `titleBarStyle: "Overlay"`, which was never set.

**The generalisable lesson: a cross-shell port that swaps the MECHANISM silently changes the
PRODUCT decision.** `setDecorations(false)` is not the Tauri translation of
`titleBarStyle: 'hidden'` — it is a different, stricter behaviour. No test failed, no reviewer
flagged it, and the divergence was then formally "accepted" in a UAT session by a user who could
not see what had been lost. Port reviews must ask *what did the old mechanism do that the new one
does not*, not merely *does the new one work*.

**78px is not a guess.** `Skill("sketch-findings-gamelib")` lists it as one of exactly TWO
constraints that **override aesthetics**: *"78px at the window's top-left belongs to the macOS
traffic lights whenever the Tauri titlebar is transparent or overlaid. No top-mounted bar starts
at x=0."* Every sketch's Annotate toggle renders this reserve.

**`--traffic-light-inset: 0px` was never a design position.** `NavShell/index.scss:24-33`
documents it as correct *because nothing overlaid the titlebar*, and explicitly warns: *"Do NOT
set this defensively to the sketches' reserved value: an un-overlaid native title bar makes that
reservation wrong, not merely unnecessary."* Overlay mode is precisely the trigger that flips it.
The same comment anticipated this exact moment: *"This exists as a token so that adopting overlay
mode later is a value change, not a re-layout."*

**`shellTokens.test.ts:54-56` pins the value at exactly `0px` and WILL go red.** It is
correct-as-written for the old mode — retune it with the decision, do not delete it.

**Consequence for the 2026-07-25 "stop investing in frameless" resolution:** that stance is also
superseded on macOS. Overlay mode moves work in the opposite direction — toward the OS providing
the controls rather than GameLib re-implementing them — so it reduces bespoke frameless machinery
on macOS rather than adding polish to it. The "candidate for removal" note still stands for
Windows/Linux, where custom buttons remain the only option.

## The unavoidable gap, restated

Every automated test in this phase proves **wiring**: that the right Tauri API was called with
the right arguments. **None proves the window on screen actually did the thing.** Nobody has run
this build and looked at it. The frameless toggle applying, the titlebar buttons moving the
window, the tray appearing and changing colour, gamepad navigation working, and how macOS traffic
lights versus custom buttons look are all **unobserved**. `cargo check` proves the tray code
compiles; it proves nothing about a tray existing. Do not read "wired and unit-proven" as "seen
working" — that is exactly how G-30-02 was declared fixed twice while the live build hung. Read
this document together with `34.1-PORTED-CHANNELS.md` §6 — neither artifact should be read in
isolation, because either one alone could leave a later reader with the wrong impression.
