<objective>
D-07/D-08: extract the genuinely-portable app-shell handler bodies out of
`src/backend/main.ts` into new Electron-free modules under `src/backend/appshell/`,
leaving `main.ts`'s `addHandler`/`addListener` lines as one-line delegations.

Purpose: one source of truth for behavior. Every prior slice ported a cluster module;
this slice's source is the Electron entry point, which the sidecar can never import
(it calls `app.whenReady()`, constructs `BrowserWindow`, wires `app.on(...)` at module
scope). Extraction is what makes plan 34.1-04's sidecar registration possible without
shipping a second, drifting implementation.

**This is the first slice to modify `src/backend/main.ts` by design.** The
additive/reversible invariant is BEHAVIORAL here, not textual: `npm start` must behave
identically, but `main.ts`'s text legitimately changes.

Output: three Electron-free modules, mechanical one-line delegations in `main.ts`, and a
test suite that calls each extracted function directly.
</objective>

`src/backend/appshell/themes.ts` — export three plain async functions carrying the
bodies verbatim:
  - `getCustomThemes(): Promise<string[]>` — read `customThemesPath` from
    `GlobalConfig.get().getSettings()`; return `[]` if `existsSync` is false; otherwise
    `readdirSync(customThemesPath)` filtered to names ending in `.css`.
  - `getThemeCSS(theme: string): Promise<string>` — read `customThemesPath` (defaulting
    to `''`), `path.join(customThemesPath, theme)`, return `''` if not `existsSync`,
    otherwise `readFileSync(cssPath, 'utf-8')`.
  - `getCustomCSS(): Promise<string | undefined>` — return
    `GlobalConfig.get().getSettings().customCSS`.
  Import `GlobalConfig` from `backend/config` and the fs/path functions from the same
  specifiers `main.ts` uses. Do not "improve" the path handling, add validation, or add
  logging — byte-equivalent behavior is the point.

`src/backend/appshell/releases.ts` — export two plain async functions:
  - `getLatestReleasesForStartup(): Promise<Release[]>` — read
    `checkForUpdatesOnStartup` from `GlobalConfig.get().getSettings()`; if truthy return
    `getLatestReleases()` from `backend/utils`, else return `[]`.
  - `getCurrentChangelogEntry(): Promise<Release | null>` — return
    `getCurrentChangelog()` from `backend/utils`.
  The distinct names avoid shadowing the `backend/utils` exports they wrap; import the
  `Release` type from wherever `main.ts`'s handler signature resolves it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → `getThemeCSS(theme)` | `theme` is a renderer-supplied string that is `path.join`ed onto `customThemesPath` and read from disk. |
| sidecar process → `src/backend/appshell/*` | These modules become part of the sidecar's import graph; anything they transitively import is loaded in the sidecar. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.1-05 | Information Disclosure | `getThemeCSS(theme)` path traversal — `path.join(customThemesPath, '../../.ssh/id_rsa')` escapes the themes directory | accept | Pre-existing Electron behavior, extracted verbatim and unchanged by design (D-07: byte-equivalent extraction, no "improvements"). The caller is the app's own settings UI; `customThemesPath` is user-chosen; the read is returned to the same renderer that asked. Changing the semantics during an extraction would violate the single-source-of-truth intent and hide a behavior change inside a mechanical diff. Recorded here so a later hardening pass has a named target; note this repo's established containment idiom is `resolve` + `relative`, not `path.join`. |
| T-34.1-06 | Elevation of Privilege | An extracted module transitively dragging `electron`, `backend/ipc` or `BrowserWindow` into the sidecar import graph | mitigate | Task 3's comment-stripped by-construction source gate plus Task 1's acceptance criterion forbidding `backend/ipc` / `backend/main_window` imports. |
| T-34.1-07 | Denial of Service | An unresolved `require('./appshell/...')` surviving `electron-vite build` and crashing the Electron main process at runtime | mitigate | Task 2 mandates static top-level imports and its acceptance criteria assert no `require('./appshell` appears in `main.ts`. This is a repeat failure mode in this repo (three occurrences on this branch). |
| T-34.1-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — this plan installs zero packages and changes no manifest. |
</threat_model>
