<objective>
Thread a distinct worker-slot identity from `depot.ts`'s two nested concurrency pools down through `fetchChunk` into `pickHost`'s new `workerSlot` argument, so the Plan 25-01 fan-out mechanism actually receives differing slot values from concurrently-running workers. Without this wiring the fan-out is inert — every caller would pass the default `0`.

Purpose: Attempt-0 convergence happens at BOTH levels (RESEARCH Pitfall 2): across the `FILE_CONCURRENCY=8` file pool AND across the `CHUNK_CONCURRENCY=4` chunk-workers inside a single large file (which dominate total bytes). A cross-file-only fix would leave a big file's 4 chunk workers still converging on one host. This plan captures `Array.from`'s native `(_, i)` index at both pools and threads it through as an optional trailing param following the module's established additive-optional-param convention.
Output: `decompress.ts` fetchChunk forwards `workerSlot` to pickHost; `depot.ts` both pools thread a combined worker slot; `depotPrimitives.test.ts` proves concurrent workers hit >1 host at attempt 0 and that cancel/abort is unregressed.
</objective>
