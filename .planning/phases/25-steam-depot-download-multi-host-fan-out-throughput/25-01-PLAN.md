<objective>
Add worker-slot-aware fan-out to `HostHealthTracker.pickHost` so that concurrent chunk workers' first attempt spreads across the top-N healthy CDN hosts instead of all converging on the single top-scored host. This is the contract-defining plan: it establishes the `pickHost(hosts, seed, attemptIndex, workerSlot?)` signature and the `TOP_N_FANOUT` constant that Plan 25-02's consumers (`fetchChunk`, the two `depot.ts` concurrency pools) will thread into.

Purpose: The diagnosed root cause of Steam native-install slowness (Thread C of resolved debug `steam-install-slow-start`) is that `pickHost` sorts by absolute composite score, erasing seed rotation — every attempt-0 call returns `ordered[0]`, so ~32 concurrent workers hammer one host. This plan fixes attempt-0 selection ONLY, leaving failure-driven rotation, the circuit breaker, and abort semantics untouched.
Output: `hostHealth.ts` with `TOP_N_FANOUT` + the new `workerSlot` param; `hostHealth.test.ts` with fan-out coverage and an explicit no-regression guard.
</objective>
