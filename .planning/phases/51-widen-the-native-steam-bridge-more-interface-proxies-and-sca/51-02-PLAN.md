<objective>
Widen the import scanner and add interface-version capture so eligibility can be scan-derived
honestly. Today `importScan.ts` matches only `SteamAPI_*` under a literal `steam_api.dll` heading,
so Hoard (8 bare accessors) and every 64-bit game pass the coverage check vacuously (ROADMAP hazard
(a), D-UAT-24-09). Planner measurement 2026-10-17 also showed the bare accessors' vtable layout
depends on the interface VERSION baked into the game's original `steam_api.dll` (XCOM's dll names
SteamUser016, SteamFriends011, SteamUtils005, STEAMAPPS_INTERFACE_VERSION004,
STEAMUSERSTATS_INTERFACE_VERSION010, STEAMREMOTESTORAGE_INTERFACE_VERSION005, SteamMatchMaking009,
SteamMatchMakingServers002, SteamNetworking005), so the scan must also capture versions.

Purpose: the scan is the authoritative input to the persisted verdict (D-51-07) and the census (D-51-15).
Output: pure `importParse.ts` + `interfaceVersions.ts`, a widened `scanSteamApiImports`, real-binary fixtures.

Spec-less probe fallback skipped: phase has no requirement IDs to probe (visible skip).
</objective>
