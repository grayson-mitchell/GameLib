<objective>
Ship the Win64 shim (D-51-13 GO) with the modern-SDK lookup family and ELEX's interface set.
`arch` is a generator parameter (51-06 made the C source arch-neutral via the THISCALL macro and
explicit hidden pointers); this plan adds the x64 export table, the second zig target, the
version-string lookup path (SteamInternal_CreateInterface / ISteamClient017), the x64 null-object
fallback, and a disassembly gate proving the register convention.

Important correction to the relayed research rule: 51-RESEARCH disassembled a FREE function
returning a struct by value (sret in RCX, `this_` in RDX). Real games call vtable MEMBER functions,
whose MSVC x64 convention is `this` in RCX and the return buffer in RDX — exactly what Proton's
win64 lsteamclient thunks implement and what the generator's explicit `(self, sretOut, …)` C
signature already produces. Applying the research's "shift this to RDX" rule would corrupt every
CSteamID-returning call. The gate in Task 1 measures the generated code, not a synthetic free
function.

Purpose: D-51-13, D-51-14 (ELEX), ROADMAP hazard (a) closed for real rather than only fail-closed.
Output: x64 generation + build target + ELEX manifests + 64-bit coverage sets.

Spec-less probe fallback skipped: phase has no requirement IDs to probe (visible skip).
</objective>
