Build the boundary validator and the ratchet, with no channel converted yet. Interface-first: the
contract helpers every conversion plan writes against (`schemaTypes.ts`, `channelSchemas.ts`, the
wire marker), then the validator in the dispatch funnel, then the census parser and the
shrink-only coverage ceiling.

Pattern 2 places it in `sidecarRpc.ts` `dispatchInvoke`/`dispatchSend` — not inside
`ipcMain.handle`, which would break ~83 test files that call `handlerRegistry` handlers directly
with loose args. This resolves Claude's Discretion "how a schema is attached": a static
`channelSchemas` map, looked up in the shared dispatch path. The typed error is a marker-prefixed
string with a JSON tail (Discretion resolved: the Rust reader at `sidecar.rs:~400` reads `error`
with `as_str()`, so a structured object would collapse to "sidecar error").

`ipcSchemaCoverage.test.ts` with measured initial ceilings.
