<objective>
Generate the Steamworks flat C API on x64 from the same manifests as the vtable proxies (D-53-01,
D-53-05), with NULL-on-unknown-version flat client lookups (D-53-07) and the vtable path's
null-object fallback untouched (D-53-08). Replace the hand-pinned x64 export list with a generated,
committed one so 400-600 new names stay in sync with the `.def` (RESEARCH Pitfall 5).

Purpose: Unity + Steamworks.NET titles (Vampire's Fall, Planet Crafter, Rogue Waters, Hell Clock)
P/Invoke these names directly; a missing one is `EntryPointNotFoundException`.
Output: flat emitter, regenerated shim, `shimExports.generated.ts`, coverage and compile gates.

Flat-export mechanics (Claude's discretion, recorded here): x64 only. On Win64 a flat cdecl
function and an MSVC member function both take `self` in RCX, so for a non-class return a direct
typed call through `((vfn *)*(void **)self)[slot]` is exact. **Class returns are the exception.**
MSVC member functions return every class type through a hidden pointer passed after `this` (RDX),
even an 8-byte CSteamID, and this repo encodes that in `isSretReturn` (`returnKind === 'class'`):
the committed stub is `vt_SteamUser023_GetSteamID(void *self, void *sretOut)`. The flat C function
instead returns the 8-byte value in RAX (the flat API's `uint64_steamid`). So every isSretReturn
method's flat body declares a zeroed `uint64_t out = 0;`, calls the slot as `(self, &out, args...)`
and returns `out`. A class return with structSize > 8 is refused. RESEARCH Pattern 1's line "no
RCX/RDX sret swap is needed" is wrong for this repo; 53-RESEARCH.md carries a correction note there.

A flat name maps to manifest methods by `<Family>` + method name, with overload suffixes derived
from the out-pointer type and pinned against the measured fixture. When two versions of a family
declare the same flat name with different parameter or return types, every version is still
dispatched (D-53-01): each switch case casts the slot to that version's own signature and casts
each argument to that version's own C type. The export's own prototype takes, per argument
position, the shared type where all versions agree and `uint64_t` where they differ but every
version passes that position in a general-purpose register (integers, enums, bools, pointers,
8-byte by-value classes); positions some versions lack are simply not passed in those cases. The
return is the shared type, or `uint64_t` when all versions return through RAX (a void case returns
0). A position or return where one version uses an XMM register (float/double) and another a GPR,
or float vs double, is not representable in C: the generator throws unless the
`Family.FlatName.Version` triple is listed in `FLAT_UNREPRESENTABLE_CASES` (starts empty), and every
listed case is a deviation in the SUMMARY. Measured 2026-10-25 over the existing x64 manifests:
7 flat names differ across versions (`GetISteamUnifiedMessages` return type; `CreateListenSocket`,
`CreateConnectionSocket`, `GetSocketInfo`, `GetListenSocketInfo`, `GetQuota`,
`GetAuthSessionTicket` parameter types or counts), all GPR-only, so none is unrepresentable. Task 1
re-measures after 53-01's manifests and records the list in the SUMMARY.

Lifecycle no-ops (user decision 2026-10-25, amending D-53-06's timing): the non-interface names
Steamworks.NET imports are exported now as safe no-ops rather than after a live fault.
</objective>
