<objective>
Generate the Steamworks flat C API on x64 from the same manifests as the vtable proxies (D-53-01,
D-53-05), with NULL-on-unknown-version flat client lookups (D-53-07) and the vtable path's
null-object fallback untouched (D-53-08). Replace the hand-pinned x64 export list with a generated,
committed one so 400-600 new names stay in sync with the `.def` (RESEARCH Pitfall 5).

Purpose: Unity + Steamworks.NET titles (Vampire's Fall, Planet Crafter, Rogue Waters, Hell Clock)
P/Invoke these names directly; a missing one is `EntryPointNotFoundException`.
Output: flat emitter, regenerated shim, `shimExports.generated.ts`, coverage and compile gates.

Flat-export mechanics (Claude's discretion, recorded here): x64 only, because on Win64 a flat cdecl
function and an MSVC member function share one calling convention for non-sret returns (`self` in
RCX either way), so a direct typed call through `((vfn *)*(void **)self)[slot]` is exact. A flat
name maps to manifest methods by `<Family>` + method name, with overload suffixes derived from the
out-pointer type and pinned against the measured fixture. When two versions of a family declare
the same flat name with different parameter types, the export takes the highest version's
signature and dispatches only to versions with identical parameter types (the rest fall to the
unknown-self path, with a generated comment naming them).
</objective>
