<objective>
Close the VERIFICATION gap for the Abiotic Factor hang at loading. In 53-UAT item 9, the
bridge-side init is clean (5 CALLs), but UE logs
`LogOnlineIdentity: STEAM: Failed to acquire Steam auth session ticket for 0` twice and then hangs.
GetAuthSessionTicket is a stub in SteamUser021 and SteamUser023 today: it returns 0
(k_HAuthTicketInvalid) and writes no bytes. The hypothesis is that this causes the hang.

The plan first confirms the hypothesis from the log, then forwards the method through
wire-policy.json, per D-06's "not a constant, so forward it" rule, and checks the result live.

Purpose: the method is measured and then fixed, which is the D-53-06 loop. The plan does not
claim the hang is fixed until the operator's live run shows it.
Output: forwarded GetAuthSessionTicket/CancelAuthTicket with pinned tests, a rebuilt bridge, a
scored live re-test of 427410, and a todo if the hang survives.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| game process -> helper (wire) | untrusted game requests an auth ticket via the shim |
| helper -> real Mac Steam | the helper calls the native flat API with the user's real session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-55 | Information Disclosure | auth ticket bytes | accept | the ticket is minted for this game's own appid (the helper is initialised with the game's real AppID, D-51-01), which is exactly what real Steam hands the game; it never leaves the local loopback socket and is never logged (CALL logs the name only) |
| T-53-56 | Tampering | out-buffer overflow | mitigate | the capacity is sent from cbMaxTicket and clamped to WIRE_OUT_BUFFER_MAX_BYTES; the shim writes at most min(len, cbMaxTicket) bytes |
| T-53-57 | Elevation of Privilege | identity pointer across processes | mitigate | the identity pointer is never sent; NULL is passed helper-side (null-in / trailing NULL), so no game address is dereferenced in the helper |
</threat_model>
