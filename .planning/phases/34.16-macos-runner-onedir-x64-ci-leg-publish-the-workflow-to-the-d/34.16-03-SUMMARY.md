# Phase 34.16 Plan 03: Formatter extraction + runId provenance Summary

**`meta/buildRunnersOnedir.ts` now exports pure `formatSha256Sums()`/`buildManifestObject()` formatters, the manifest carries a `runId` from `GITHUB_RUN_ID` (explicit `null` locally), and five new unit tests pin both published artifact formats byte-for-byte.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 2 completed
- **Files modified:** 2

## Sequencing Fact (per plan's `<output>` requirement)

This change **must be on `fix/steam-native-install-stability` before plan 06's dispatch runs**, because
the `workflow_dispatch --ref fix/steam-native-install-stability` invocation executes *that ref's*
copy of `meta/buildRunnersOnedir.ts` — not the copy on `main`. A dispatch that precedes this commit
would produce `BUILD-MANIFEST-{arch}.json` files with no `runId` field at all, leaving plan 05's
`pin:runner-digests` script nothing to record for D-10's "recording the source run id from
`BUILD-MANIFEST-{arch}.json`" requirement. This commit is now on the branch, so that prerequisite is
satisfied for any dispatch from this point forward.

## Accomplishments

- Extracted `writeSha256Sums`/`writeBuildManifest`'s bodies into two new exported pure functions,
  `formatSha256Sums(arch, results): string` and `buildManifestObject(arch, results): Record<string, unknown>`,
  that perform no I/O. Both existing writers are now one-line `writeFileSync` wrappers over them —
  output paths, `archiveName()`, and `RunnerBuildResult` are byte-unchanged.
- Added a top-level `runId` field to the manifest object (sibling to `legendary`/`gogdl`/`nile`), set
  to `process.env.GITHUB_RUN_ID ?? null`. A CI-produced manifest self-describes its provenance; a
  locally-produced one carries explicit `null` — never an absent key — so a future consumer (D-11's
  mismatch error, plan 05's parser) can distinguish "built locally" from "field missing because the
  writer predates this change."
- Added a code comment above `buildManifestObject` flagging `runId` as a top-level sibling so any
  future code iterating the object's keys as "one entry per runner" is warned to exclude it.
- Pinned both published artifact formats with five new unit tests in a new `describe('published audit
  artifact formats (the pin:runner-digests contract)')` block:
  - `formatSha256Sums`: exact `<64-hex>  <archiveName>` line shape per result, in call order
  - `formatSha256Sums`: exactly one trailing newline, no blank interior line
  - `formatSha256Sums`: vacuity guard — a mutated digest produces different output (independently
    verified by temporarily forcing the mutation to never apply; the test failed as expected, then
    the file was restored via `cp` + `shasum` verification, matching the "never `git checkout --`"
    hazard rule)
  - `buildManifestObject`: exact top-level key set `['gogdl','legendary','nile','runId']` via
    `toEqual` (never `toContain`), plus full per-runner field equality including the
    `upstreamWorkingDirectory` `undefined` → `null` collapse
  - `buildManifestObject`: `runId` is the `GITHUB_RUN_ID` value when set, and explicit `null` when
    unset, restored via a captured pre-test value in `afterEach`
