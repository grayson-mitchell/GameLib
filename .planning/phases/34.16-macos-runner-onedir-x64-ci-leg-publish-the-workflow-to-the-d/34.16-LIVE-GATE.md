
Record the value in this document's `session_dir` frontmatter field at run time.

**`$SESSION_DIR` is created FRESH per attempt, never carried over.** Its value is recorded in that
attempt's own `SESSION.DIR` ledger row (§6). The frontmatter `session_dir` field names the MOST
RECENT attempt's directory only and is written by the runner, never by this document's author. A
later attempt that skips this and reuses a prior attempt's directory is the exact process gap
`F-34.16-F` records.

**Exit-status capture uses the redirect form, never `| tee` + `${PIPESTATUS[0]}`.** This is
`34.9-GUARD-PROOF.md` §2.5 CONTRACT AMENDMENT v2 §A2, which is NORMATIVE: the piped idiom silently
no-ops under zsh — the operator's default shell on this hardware — writing a 1-byte bare-newline

```sh
<command> > "$SESSION_DIR/<distinct-name>.log" 2>&1; echo $? > "$SESSION_DIR/<distinct-name>.exit"
```

**Mandatory companion rule: every block gets its OWN filename.** The redirect form reintroduces the
truncation risk `tee -a` existed to prevent, so a re-run never reuses a log or exit filename

**Read every exit file back with `xxd` before scoring it.** `300a` = `0\n`, `310a` = `1\n`. A 1-byte
file is the A2 failure signature. Do not use `cat -A` — macOS BSD `cat` has no `-A`.

## 13. Verdict rule

**No partial pass.** The phase's live-gate portion closes only if **all six** scored items PASS.

A **NOT ATTEMPTED** item is not a PASS and does not count toward the bar; it leaves its requirement
open with a dated, named precondition, in the `deferred-items.md` style this project already uses —
never silently dropped.

Any FAIL routes to a gap cycle per this project's standing discipline. Scored Item 5's BUILD BUG and
GUARD BUG branches are FAIL outcomes with a pre-recorded classification, which is exactly what makes
them useful: the gap cycle starts from a diagnosis rather than from "the x64 guard didn't work".

**Ordering is load-bearing.** Items 2-6 each depend on their predecessors having PASSED. Do not run
Item 4 against sentinels, Item 5 against a tree Item 4 did not produce, or Item 6 before Item 3.

**VOID rule.** Any scored item or criterion whose evidence cites a §6 ledger slot (`P1.HEAD` through
`P9.REF-EQ-HEAD`) is **VOID** — not PASS, not FAIL — if that slot is absent from the current
attempt's ledger row or still reads `TBD`. A VOID item does not close the attempt; the attempt does
not reach a verdict until every cited slot is filled. This is a mechanism, not a courtesy: it exists
because prose alone did not prevent the gap it targets. **Attempt 2 would have been caught by this
rule.** No fresh `$SESSION_DIR` was created and §6 was never re-captured for that attempt (see
`F-34.16-F`), so §7 criterion 2 — which compared against "Precondition 6" — was unsatisfiable as
written; Item 1's PASS had to rest on a direct remote-vs-`HEAD` measurement instead of the criterion
as stated. Under this rule, an attempt in that state would VOID the criterion rather than let the
scorer quietly substitute a different measurement for the one the criterion names.
