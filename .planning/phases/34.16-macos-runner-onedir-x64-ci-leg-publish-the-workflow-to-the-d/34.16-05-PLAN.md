<objective>
Build `pnpm pin:runner-digests` (D-10): fetch `SHA256SUMS-x64`, `SHA256SUMS-arm64`,
`BUILD-MANIFEST-x64.json` and `BUILD-MANIFEST-arm64.json` from the `runners-onedir-macos` rolling
release, validate every line, and rewrite `meta/runnersOnedirDigests.json`'s six digests and `runId`
in one write.

Purpose: hand-transcribing six 64-character hex strings out of a run log is a transcription-risk
ritual that has to be repeated after every re-dispatch, because `gh release upload --clobber`
invalidates all six pins at once. A script makes it repeatable and captures provenance rather than
relying on it being remembered. A bot PR was considered and rejected — this is a developer-initiated
action, not a scheduled one.

Output: the script, its script entry, and a test suite covering the success path and every
refuse-to-write path.
</objective>

The formats this script parses are pinned by plan 03's format-contract tests in
`meta/__tests__/buildRunnersOnedir.test.ts`. Read that block before writing the parser.

`SHA256SUMS-{arch}` — exactly three lines, `<64 lowercase hex><two spaces><filename>`, one trailing
newline, one line per runner. Standard `shasum -a 256`-compatible.

`BUILD-MANIFEST-{arch}.json` — top-level keys are exactly `legendary`, `gogdl`, `nile` and `runId`
(plan 03). Each runner entry carries `repo`, `tag`, `upstreamPyinstallerLine`,
`upstreamWorkingDirectory`, `onedirCommand`, `droppedExpressions`, `python3Version`,
`pyinstallerVersion`, `archiveSha256`, `fileCount`, `machoCount`. `runId` is the CI run id string,
or `null` for a local build.

`meta/runnersOnedirDigests.json` after plan 04 — top-level keys in this exact order:
`_comment`, `layout`, `runId`, `digests`. `digests` has exactly six keys, one per
runner x arch, valued `PENDING-CI-PUBLISH`.

`meta/downloadHelperBinaries.ts:68-69` — the two constants this script must match, and the header
comment at :62-65 explaining why they are hardcoded rather than read from package.json's
`repository` field (which still points at Heroic upstream):

  const RUNNERS_ONEDIR_TAG = 'runners-onedir-macos'

`meta/releaseTags.ts` exports `RELEASE_TAGS` as a plain const object with no side effects — safe to

<constraints>
- **Import nothing from `meta/buildRunnersOnedir.ts` or `meta/downloadHelperBinaries.ts`.** Both carry
  a module-bottom CLI entrypoint guard, and `node meta/runTs.cjs --bundle` co-bundles imports into
  one file, so importing either risks firing another script's `main()` from this one's process.
  `buildRunnersOnedir.ts`'s guard ANDs in `process.argv.some(a => a.startsWith('--arch='))` — which
  means importing `archiveName` and then invoking `pnpm pin:runner-digests --arch=x64` would start a
  real PyInstaller build. Do not create that footgun.
- **Consequently the script derives nothing from `archiveName()`.** It reads the six expected
  filenames from `meta/runnersOnedirDigests.json`'s own `digests` key set. This is a safety property,
  not a shortcut: a script that cannot name a key the file does not already have cannot invent,
  rename or drop one.
- **Never write on a partial or failed read.** Fetch and validate all four remote files first; write
  once, at the end, or not at all.
- **Do not change `layout` or `_comment`'s existing prose**, and do not reorder the four top-level
  keys. `layout` is what forces a global re-download when the archive shape changes; this script
  changes digests, not shape.
- **Do not modify `meta/releaseTags.ts`.** Read it; never write it, never quote its values as
  literals in code, tests, or plan text.
- Direct `writeFile` to the final path, matching every sibling `meta/*.ts` script. Temp-file+rename
  atomicity would be a deviation from the established pattern, not a gap-fill.
- Do not touch `meta/verifyRunnerBundle.ts`.
</constraints>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.16-02 | Tampering | `pin:runner-digests` writing attacker-supplied digests, converting the download gate into a rubber stamp | mitigate | Source URLs are built from hardcoded `GAMELIB_RUNNERS_REPO` / `RUNNERS_ONEDIR_TAG` constants over HTTPS; no env var, argv flag or package.json field can redirect them. Every line is shape-validated against `^[0-9a-f]{64}  \S+$` before use. The write is a diff to a TRACKED file, so a human reviews the six changed values before they are committed — the pin is not self-approving. |
| T-34.16-17 | Spoofing | a digest key invented, renamed or dropped by the pin script | mitigate | The script derives its expected filename set from the existing `digests` keys and refuses any filename outside it, and refuses to write unless all six are covered exactly once. It is structurally incapable of changing the key set. |
| T-34.16-18 | Repudiation | six digests attributed to one run when they came from two | mitigate | Both `BUILD-MANIFEST-{arch}.json` `runId` values must be non-null and equal, or the script throws naming both. A single-leg re-dispatch is therefore a loud failure rather than a silently mis-attributed pin. |
| T-34.16-19 | Tampering | a partial write leaving three real digests and three sentinels | mitigate | All four remote files are fetched and fully validated before any write; the write is a single `writeFile` at the end. Every failure path is covered by a test asserting `writeFile` was never called. |
| T-34.16-20 | Elevation of Privilege | importing a sibling `meta/*.ts` CLI script and firing its `main()` through esbuild co-bundling | mitigate | This script imports neither `buildRunnersOnedir.ts` nor `downloadHelperBinaries.ts`; a grep assertion pins that. | T-34.16-SC | Tampering | npm/pip/cargo installs | n/a | No package installs. The script uses only Node built-ins plus an in-repo import. RESEARCH.md records the Package Legitimacy Gate as skipped because the phase adds no external dependency. |
