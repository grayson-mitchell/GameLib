  <action>
Insert a new first step in the `prepare-release` job, named exactly `Refuse to run from the default
branch`, placed ABOVE the existing `Create or update the rolling release` step. It is a `run:` step
with no `uses:`.

Read both GitHub context values through the step's own `env:` block rather than interpolating them
directly into the shell body — `${{ github.ref_name }}` and
`${{ github.event.repository.default_branch }}` become e.g. `REF_NAME` and `DEFAULT_BRANCH` env
vars, and the shell reads `"$REF_NAME"` / `"$DEFAULT_BRANCH"`. Direct interpolation splices a
branch-controlled string into the script body; env indirection does not. This is the one place this
workflow reads a name-shaped value from the event payload.

Shell logic, in order:
  1. If `"$DEFAULT_BRANCH"` is empty, emit `::error::` saying the default branch could not be
     resolved and that the guard refuses to continue rather than fail open, then `exit 1`.
  2. If `"$REF_NAME"` equals `"$DEFAULT_BRANCH"`, emit `::error::` naming both the observed ref and
     the required one (`fix/steam-native-install-stability`), stating that the default branch carries
     the workflow file only for GitHub's `workflow_dispatch` registration rule and has neither
     `meta/buildRunnersOnedir.ts` nor the `build-runners-onedir` script, then `exit 1`.
  3. Otherwise echo a one-line confirmation naming the ref, and fall through.

Add a short comment above the step explaining D-01/D-02's split (registration on the default branch;
execution on the feature ref). The comment may name the branch; comments are stripped before every
negative assertion in the suite.

The shell body must contain neither the literal `push:` nor `tags:` nor `secrets.` — three existing
committed assertions forbid each of them across the stripped source.
  </action>
