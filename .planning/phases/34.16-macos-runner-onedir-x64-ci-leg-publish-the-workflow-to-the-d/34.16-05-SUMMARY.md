# Phase 34.16 Plan 05: pin:runner-digests script Summary

**`pnpm pin:runner-digests` fetches and validates all four rolling-release artifacts before a single atomic rewrite of `meta/runnersOnedirDigests.json`'s six digests + runId, backed by 17 tests covering the success path and every refuse-to-write path**

## Accomplishments

- `meta/pinRunnerDigests.ts`: fetches `SHA256SUMS-x64`, `SHA256SUMS-arm64`, `BUILD-MANIFEST-x64.json`, `BUILD-MANIFEST-arm64.json` from the `runners-onedir-macos` rolling release; validates SHA256SUMS line shape, filename membership against the tracked digest keys, full coverage of all six keys exactly once, and runId agreement between both manifests; warns (non-fatally) on `RELEASE_TAGS` drift; writes `meta/runnersOnedirDigests.json` exactly once, or never
- `pnpm pin:runner-digests` wired into `package.json` following the existing `runTs.cjs --bundle` convention (same pattern as `download-helper-binaries`)
- 17-test suite covering: 1 success path, 4 non-200 fetch failures (one per URL), 4 malformed-line shapes, 1 unknown filename, 1 missing coverage key, 1 both-null runId, 1 disagreeing runId, 1 RELEASE_TAGS drift (warns + still writes), plus 3 unit tests on the exported pure helpers (`parseSha256Sums`, `assertCoversAllKeys`, `buildPinnedJson`)
- Vacuity guard manually proven: temporarily diverged only the mocked `SHA256SUMS-x64` response text (leaving `EXPECTED_DIGESTS` unchanged) — the success test went RED on a `legendary_macOS_x86_64_onedir.tar.gz` digest mismatch, then GREEN again after reverting

## Decisions Made

- Sequential (not `Promise.all`) fetches inside `main()`, matching the codebase's established convention and making mock call-ordering deterministic in tests.
- `assertAgreedRunId` runs before `warnOnTagDrift` in `main()`, so runId-failure test cases never need to account for warn side effects.
- The digests file's `_comment` and `layout` are carried forward verbatim from the currently-tracked file via `buildPinnedJson`, never regenerated — this script changes digests and `runId` only, not prose or shape.
- `DIGESTS_PATH` is built with `join('meta', 'runnersOnedirDigests.json')`, relative to `process.cwd()`, not `__dirname` — `node meta/runTs.cjs --bundle` compiles the script into a private tmpdir before running it, so `__dirname` at runtime would not point at `meta/`.

- **Observation 1 (red):** re-running only the success-path test (`writes runnersOnedirDigests.json exactly once...`) failed with a Jest deep-equality diff on `parsed.digests`, showing `legendary_macOS_x86_64_onedir.tar.gz` expected `aaaa...` (64 `a`s) but received `9999...` (64 `9`s). This proves the test's `toEqual(EXPECTED_DIGESTS)` assertion is load-bearing, not vacuous.
- **Observation 2 (restored green):** reverting `SHA256SUMS_X64_TEXT` back to `DIGEST_LEGENDARY_X64` and re-running the full file confirmed 17/17 green again, with the whole-project run still confined to the one known baseline failure (`genI18nGateScope.test.ts`).
