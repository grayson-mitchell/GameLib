<objective>
Give `meta/runnersOnedirDigests.json` a run-id provenance slot and make the digest-mismatch throw
name it (D-11), then prove — behaviourally, not by inspection — that the new sibling key leaves
`darwinLayoutMarker()` untouched.

Purpose: `gh release upload --clobber` means every re-dispatch of the runner workflow invalidates
all six pins at once. D-11 keeps the mismatch throw as the drift detector — it is loud and
fail-closed and already refuses to write anything under `public/bin` — but makes the failure say
*which run to re-pin from* instead of leaving the operator to guess. That requires the value to
exist somewhere, and this is where it lives.

The marker question is load-bearing: `computeLayoutMarker(layout, digests)` feeds
`public/bin/.release_tags`'s `__darwin_layout`, and any change to it forces every checkout to
re-download the darwin runners. RESEARCH.md resolves the code answer (the function receives the two
values positionally and can never see a sibling key). This plan is what stops that answer from
silently decaying.

Output: the `runId` slot, the extended error text, and three tests.
</objective>
