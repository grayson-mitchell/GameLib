<objective>
Close UAT gap **G-48-11a** (medium), which is 48-REVIEW.md **WR-01** confirmed live. The 48-12 strip
width sync raises `ResizeObserver loop completed undelivered notifications`. UAT item 11 counted 27
and 25 errors in two launches over a width sweep (1280 to 600 to 1280) and a height sweep (800 to 400
to 800), in 0.15 s steps, with the strip showing. It counted 0 in the identical sweep with
`focusRow` null.

**Cause (WR-01, read in full before starting).** The observer in `FocusRowStrip/index.tsx` watches
`.focusRowTrack` and its list. Its callback calls `syncCardWidth(track)`, which writes
`--focus-row-card-width` inline on the track. Card height follows width through `aspect-ratio`, so a
width-changing write also changes the track's own height. The track sits at the shallowest depth the
observer has just delivered, so its new size cannot be delivered in that frame and the browser
dispatches the loop error. `src/frontend/index.tsx:51` forwards every `ErrorEvent` to
`window.api.logError(ev.error)` with a `null` payload, so each occurrence also costs an IPC log.
48-12's flip-hold (`ae9054a54`) bounds a sustained width flip-flop. It does not move the write out of
the callback, so every real width change still costs one error.

**Fix (WR-01's own suggestion, adopted).** Defer the write to the next animation frame:
- the callback keeps its cheap read (`readMeasurement`) and requests one deferred run;
- that run does the sync and a second read;
- cleanup cancels a pending frame;
- the `useLayoutEffect` write stays exactly as it is, because it is what makes first paint correct.

The deferral lives in `focusRowOverflow.ts` as a small injectable runner. This module's design rule
(its header comment) is that everything is unit-testable in the `node` jest project with stubs. The
Frontend project cannot mount the component, so the wiring is pinned by a comment-stripped source
gate, the idiom `focusRowStripSource.test.ts` already uses.

WR-01's alternative is rejected: observing only an element whose box does not depend on card
height. `.focusRowStrip` and the viewport both grow with card height, and an observer fires on any
size change, so the write would still land inside a delivery.

**Not changed.** The `index.tsx:51` null-payload forwarding is left as it is: removing the cause
removes these events. 48-REVIEW.md IN-01 and WR-02 stay open; they are not this gap. 48-12's
`createStripCardWidthSync` arithmetic, epsilon and flip-hold are untouched.

**Depends on 48-13**: both plans edit `focusRowOverflow.ts`, both strip test files and possibly
`index.tsx`, and this plan extends 48-13's harness generator. Read every file as 48-13 left it.

Purpose: resizing the window with a focus row showing stays silent in the console and in the log.
Output: the runner, the rewired observer, gates that were red first, a WebKit loop-error count, and
WR-01 dispositioned.
