## Accomplishments

- Converted RESEARCH.md Assumption A1 (rated HIGH risk — "no precedent in this codebase or Node's own SEA docs") from an assumption into a measured, VALIDATED fact: a real compiled SEA binary successfully `dlopen()`s a `getRawAsset()`-extracted native addon from inside an eval'd worker, byte-identical decode output, across 10 independent runs

- Obtained an explicit human go/no-go decision (`proceed`) on record before any production code changes begin

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plan's literal binding-shim design (deriving the prebuild path from the `dir` argument `node-gyp-build`'s caller passes) does not work once esbuild bundles the module — fixed with a build-time-resolved generated data module instead**
- **Found during:** Task 3 (building `binding-shim.cjs`)
- **Issue:** The plan's action text described a "Dev branch: compute `<lzma-native package root>/prebuilds/...`" step using the `dir` argument received by the aliased `node-gyp-build` replacement. Empirically confirmed (both via a minimal two-file esbuild repro and directly inside this spike's real bundle) that esbuild flattens `__dirname` for every file merged into one output bundle to that output file's own runtime location — so `dir` arrives as `"."` inside the eval'd worker, not `.../node_modules/lzma-native`. Following the plan literally would have made the dev branch (and any guard checking `dir` ends with `lzma-native`) permanently broken.
- **Fix:** `build-sea.mjs` resolves `lzma-native`'s real package root (and the observed prebuild filename) at build time, before esbuild ever runs, and writes them into a small generated CJS data module (`resolved-paths.generated.cjs`, gitignored, machine-specific) that `binding-shim.cjs` requires directly — a plain data require has no `__dirname` dependency of its own, so it survives bundling intact.
- **Files modified:** `.planning/spikes/023-sea-native-addon-dlopen/binding-shim.cjs`, `.planning/spikes/023-sea-native-addon-dlopen/build-sea.mjs`
- **Verification:** The compiled SEA binary's dev-branch path was not exercised this run (the SEA branch fired since `sea.isSea()` was true), but the finding and fix were verified directly: `binding-shim.cjs`'s own diagnostic line logged `dir="."` at runtime, confirming the `dir` argument is unusable, and the generated-module approach is what actually resolved `lzma_native.node`'s embed path correctly in `sea-config.json`.
- **Committed in:** `24884b2ec` (Task 3 commit)

**2. [Rule 1 - Bug] The plan's literal `<verify>` command for Task 2 (`git status --porcelain ... | wc -l | grep -qx '0'`) fails on this machine's BSD `wc -l` (right-pads its output with leading whitespace, breaking `grep -x`'s exact-line match) even when the underlying invariant (repo manifests untouched) holds**
- **Found during:** Task 2 verification
- **Issue:** Running the plan's exact verify command returned exit 1 despite `git status --porcelain package.json pnpm-lock.yaml pnpm-workspace.yaml` genuinely being empty.
- **Fix:** Verified the underlying invariant with an equivalent, whitespace-safe check (`... | wc -l | tr -d ' '` compared to the string `"0"`), confirmed clean. Did not modify the plan file itself (verification-methodology-only, no code change needed).
- **Files modified:** none (verification approach only)
- **Verification:** `COUNT=$(git status --porcelain package.json pnpm-lock.yaml pnpm-workspace.yaml | wc -l | tr -d ' '); [ "$COUNT" = "0" ]` passes.
- **Committed in:** n/a (no file change)
