Interpretation recorded here (binding, user ruling 2026-11-06): the roadmap says "warn-only"; this
phase instead starts every graph rule at `severity: 'error'` and holds pre-existing violations in
`.dependency-cruiser-known-violations.json`, checked with `--ignore-known`, updated only with
`--baseline --baseline-mode shrink-only` (or the 18.7.2 equivalent the executor confirms in the docs).

Planner decisions recorded here:
- Test files are exempt from `no-cross-store-manager` (`pathNot` on `__tests__`/`__mocks__`/`.test.ts`):
  tests that exercise cross-store interplay (e.g. `gog/__tests__/gogImportGame.test.ts`) are not
  production coupling. Research measured 0 production cross-manager edges, so this rule starts at
  an empty baseline.
- `no-circular` is scoped to the depot subtree only (`src/backend/storeManagers/steam/depot.ts`
  and `steam/depot/**`), NOT all of `steam/`: `games.ts <-> library.ts` is an existing cycle the
  games.ts split cannot remove, and a steam-wide cycle rule with a shrink-only baseline would make
  every lift commit "grow" the baseline as cycle paths change.
- Instead, Pitfall 2 (cycles back into games.ts) is guarded by `games-split-modules-are-leaves`:
  no file matching `^src/backend/storeManagers/steam/game(Constants|SessionState|Requirements|ProtocolUrl|DrmLaunch|Eligibility|Install|Launch|LaunchOverlay|BridgeLaunch|Maintenance|Uninstall)\.ts$`
  may import `steam/games.ts` except type-only (`dependencyTypesNot: ['type-only']`). None of
  those files exists yet, so its baseline is 0.
- `launcher-only-via-store-managers-index` counts static AND dynamic imports: `launcher.ts:256`
  has `await import('backend/storeManagers/steam/bottle')` in addition to the 8 static imports.

Repo facts: `tsconfig.json` has `baseUrl: ./src/` and `moduleResolution: node`, so aliases like
`backend/storeManagers` must resolve via depcruise's `tsConfig` option. Jest project names: `Meta`
(meta/jest.config.js), `Backend`, `Common`, `Frontend`, `Preload`. `tsconfig.meta.json` includes all of
`meta/`, so seeded fixtures must NOT be committed `.ts` files under `meta/` — generate them in a temp
dir at test time.
