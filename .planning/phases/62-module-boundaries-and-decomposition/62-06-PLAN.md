## THE LIFT RECIPE (binding for 62-06, 62-07, 62-08)
L1. A lifted method `M` becomes `export function M(steamGame: SteamGame, <original params>)` with
    the original `async`, generics, parameter types, defaults and return type. Name unchanged. The
    parameter is named `steamGame` (verified: the identifier does not occur in any cluster today;
    `game` and `self` do, so do not use them).
L2. Body bytes are unchanged except every CODE occurrence of the keyword `this` becomes `steamGame`
    (`this.x` and bare `this`, e.g. `fn(this)`). Comments and string/template contents are left
    untouched. Do this with the TypeScript compiler API (a scratch script in the session scratchpad,
    not committed: `ts.createSourceFile`, visit `SyntaxKind.ThisKeyword` nodes inside each lifted
    method, splice replacements from the end backwards), not with sed. Dedenting the body by one
    level and prettier-forced rewrapping are the only other permitted diffs.
L3. In games.ts, `M` keeps its JSDoc, modifiers (minus `private`, L4), name and parameter list; its
    body becomes one statement `return M(this, <param names in order>)`. Destructured parameters
    become `argN: <same type>` in the stub only; parameters with defaults become optional (`?`) in
    the stub only, so the default is evaluated once, in the free function.
L4. Any class member that a lifted body reaches through `steamGame.` loses its `private` keyword
    (that token only), including `private readonly appId` -> `readonly appId`. TS `private` rejects
    outside access; this is a visibility change with no runtime effect. List every member whose
    `private` was removed in the commit message; 62-08 files a todo to re-narrow visibility.
L5. Lifted modules import the class with `import type SteamGame from './games'` only, and do NOT
    import each other: a call to another lifted method stays a call through `steamGame.X(...)`, which
    hits the class stub. This preserves prototype dispatch that tests depend on —
    `SteamGame.prototype` spies on `fetchMetadataIfNeeded`, `installBottleNative`,
    `launchDrmModeGame`, `launchBridgeGameBody`; `(game as any).launchBridgeGame()`; casts reaching
    `fireBridgeWineLaunch` and `prepareTcpOverlay` (games.test.ts lines ~1037, 11548, 13546-13594,
    13663-14614, 15917-16015).
L6. STOP and report (do not lift that method) if a lifted body contains any of: a nested
    `function` declaration/expression or a class that uses its own `this`; an object-literal
    method (`{ m() { ... this ... } }`) or getter/setter (`get`/`set`) whose `this` is the object,
    not the class; any use of `arguments` (the free function's `arguments` gains the leading
    `steamGame` and shifts every index); or a class `get`/`set` accessor being lifted itself
    (accessors cannot be stubbed by L3). Arrow functions are fine. Name collisions: if a lifted
    function's name (e.g. `install`, `launch`, `uninstall`, `repair`, `update`) equals an
    identifier already imported or declared in games.ts or in the target module, import it into
    games.ts with an alias (`import { install as liftedInstall } from './gameInstall'`) and use the
    alias in the stub; the exported name in the module stays unchanged (no rename).
L6b. A lifted body that references a FREE symbol still declared in games.ts (anything other than
    the class itself) would need a runtime import back into games.ts — STOP and report; that symbol
    should have moved in 62-05 (as `buildSteamProtocolUrl` did, to `gameProtocolUrl.ts`).
L7. Imports: the module gets exactly the imports its bodies use (free collaborators keep their
    module paths, so path-based jest mocks still intercept them); games.ts drops imports it no
    longer uses.
L8. No test file changes in a lift commit. `games.test.ts` is the oracle and stays byte-unchanged.
    If a test breaks, the lift was not mechanical: fix the lift, never the test.
L9. Oracle per commit: `pnpm codecheck`; `npx jest --selectProjects Backend src/backend/storeManagers/steam`;
    the sidecar flow tests; `pnpm boundaries`; `pnpm find-deadcode` (path-move baseline edits only);
    `git show --color-moved=zebra --color-moved-ws=allow-indentation-change HEAD` shows bodies as moved.
L10. Commit subject: `refactor(62-NN): lift <cluster> out of SteamGame (mechanical this->steamGame, D-06 ruling)`.
