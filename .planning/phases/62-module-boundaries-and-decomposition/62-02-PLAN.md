Planner decisions (RESEARCH Open Questions 3 and 4, recorded here):
- **Test exemption (OQ3):** `**/__tests__/**`, `**/__mocks__/**`, `**/*.test.ts`, `**/*.test.tsx`,
  `src/backend/jest.setup*.ts` and `**/*.d.ts` are outside the ban. Fixtures legitimately set
  `runner: 'steam'`; comparisons in test code are lower value. The exemption is stated in the
  selector module's header.
- **Humble (OQ4):** `Runner` (`src/common/types.ts:20`) has no `'humble'`, but frontend login code
  compares `runner === 'humble'` (WebView, TauriLoginPanel) and backend compares `store === 'humble'`
  (`signInProbe/verdict.ts`). D-03 says every runner literal, so STORE_LITERALS is
  `steam, gog, legendary, nile, sideload, humble`.
- **Compared-name match (revised 2026-11-06 after plan check, blocker 1):** the compared side is an
  Identifier, or a MemberExpression property, whose name matches
  `RUNNER_NAME = /^(runner|store)$|[a-z0-9]Runner$|[a-z0-9]Store$/` — so `runner`, `store`,
  `removedRunner`, `scopedRunner`, `activeRunner`, `warnLoginForStore` all match. Known real sites
  the narrow `^(runner|store)$` form missed and the test must HIT: `downloadmanager/downloadqueue.ts:344`
  `removedRunner !== 'steam'`; `state/GlobalState.tsx:1255-1257` `scopedRunner === 'legendary'|'gog'|'nile'`;
  `screens/WebView/useTauriOAuthLogin.ts:199,201,341,345` `activeRunner === ...`;
  `screens/Login/components/LoginWarning/index.tsx:34` `warnLoginForStore === 'gog'`.
  A `NAME_DENYLIST` (exported, initially empty plus any false positive found while measuring)
  removes names that end in Runner/Store but are not store identity — each entry carries a one-line
  reason. Names that do not end in Runner/Store at all (e.g. `mountedOverlay`, `openOverlay` in
  `Login/index.tsx`) are UI overlay ids and are not matched. esquery attribute regexes accept this
  pattern (`Identifier[name=/.../]`); the deny-list is applied with `:not(...)`. Build both from
  RUNNER_NAME / NAME_DENYLIST so the pattern and the literal set each have exactly one source.
- **Shapes:** BinaryExpression with operator `===`/`!==`/`==`/`!=` where one side is
  an Identifier or MemberExpression property matching RUNNER_NAME (and not in NAME_DENYLIST)
  (incl. optional chaining) and the other is a string Literal in STORE_LITERALS (either order);
  `SwitchStatement` whose discriminant is such an Identifier/MemberExpression;
  `CallExpression[callee.property.name='includes']` whose object is an ArrayExpression containing
  at least one STORE_LITERALS literal and whose argument is a runner/store Identifier/MemberExpression.
  Not matched: object-literal maps keyed by runner, `runner: 'steam'` property values, type
  annotations, comments, template literals.
- **Sanctioned home:** `src/common/storeCapabilities.ts` (created in 62-13) is outside scope
  because `src/common/**` is not in SCOPE_FILES. No inline `eslint-disable` for this rule anywhere.
- Scopes: `frontend` = `src/frontend/**/*.{ts,tsx}`; `backend` = `src/backend/**/*.ts` minus
  `src/backend/storeManagers/**`. Research prototype measured frontend 122 / backend 63 non-test
  with the narrow name match; a planner grep with the widened names (2026-11-06) gives about
  frontend 127 / backend 61 for `===`/`!==` forms alone (switch and `.includes` add more). Record
  the numbers the ratified selector produces in the SUMMARY — 62-13's classification and the
  62-14..62-19 ceilings work from those measured numbers, not from these estimates.
