<objective>
Close audit S9 (DEBT-01): a SteamStub title launched in DRM mode (steamclient-layer) must never run
the CrossOver clone runner over a bottle whose engine marker says a non-CrossOver engine set it up.
The DRM branch of the bridge launch gains (a) the TCP path's offline up-front refusal with the
override pinned to 'crossover', run before preflightCrossover, and (b) a call to the existing
marker-based engine switch, prepareBottleForEngine, targeting CrossOver after a healthy preflight.
Every refusal shows a clear dialog and sends the terminal 'done' status.

Purpose: the defect lets a DRM launch run over Wine-Staging + DXVK DLLs when the title was
installed while CrossOver was missing. Mirroring the TCP path's switch is the fix the user locked.
Output: two exported helpers in gameLaunch.ts, a 2-call change in gameBridgeLaunch.ts, one new en
string, and unit tests covering every branch (D-08). TDD order: tests first (RED), then code (GREEN).
