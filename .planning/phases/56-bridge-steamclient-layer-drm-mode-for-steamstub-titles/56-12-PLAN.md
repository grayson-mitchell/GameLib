<objective>
Wire the Phase 56 steamclient-layer DRM mode into the Steam bridge launch path in `games.ts`.

1. `launchBridgeGame` reads the launch exe's `.bind` and CEG signals, then calls 56-11's
   `drmLaunchSetup` on every bridge launch, before `placeShimForGame`.
2. A `not-applicable` result continues the existing TCP path unchanged.
3. A step error becomes a D-13 notice (`[bridge-notice] … reason=drm-<step>`, a dialog and a
   notify) with no launch. It never calls `markBridgeFailedThisSession` and never reroutes to
   bottled Steam.
4. An ok result launches the game-process helper `steam.exe <game exe>` under the clone runner.
   The launch carries the 56-01-measured DLL env channels and the `GAMELIB_DRM_TRACE_FILE`,
   `SteamGameId` and `SteamAppId` env, after the `[bridge-drm]` anchor is logged. When the game is
   gone, the trace file is re-logged into the app log.

Purpose: this is the one place DRM mode becomes reachable from Play (D-12). D-13's failure
contract is user-visible here, and the D-15 evidence (anchor plus re-logged trace) reaches the
app log that `pnpm bridge-census` (56-05) reads at the 56-15 live gate.

Output: the `games.ts` changes and new `games.test.ts` cases, the `steam.bridge.drm.*` English
strings, and the regenerated gamelib presence baseline. The Phase 52 forwarder code stays in
place here. In DRM mode it is never reached, and 56-13 removes it.

translations in the 48 other locales fail `lintTranslations`' inverted presence check ("a new key
