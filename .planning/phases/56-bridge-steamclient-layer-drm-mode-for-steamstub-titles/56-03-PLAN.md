<objective>
Port the two GameLib-tree native parts that sit beside `lsteamclient`. Build both with GameLib's own
`meta/` tooling.

1. **The x64 ntdll detour payload.** This is a port of NotProton's GPL-3 `ntdll-patch`
   (`detour.c`, `shim.S`, `link.ld`). It compiles into a per-CrossOver-build `detour-cx<build>.bin`
   whose sha256 is pinned. The dev-only `resolve.py` pattern finder that derives the patch-site
   table is vendored beside it.
2. **The game-process helper `steam.exe`.** This is a port of NotProton's BSD-3 `steam-shim`
   (Proton `steam_helper`): pure Win32, compiled with zig, HKCU-only and with no DIPC thread.

Purpose: 56-10 packages these artifacts into the `steamclient-layer-cx<build>` component (D-18).
56-08 installs the payload into the cloned runner and 56-09 stages the helper into the bottle.
Without them the genuine `steamclient64.dll` exports are never trampolined (D-03). The game process
also never sees the Steam kernel objects and HKCU `ActiveProcess` keys SteamStub checks (D-07).

Output:
- the ported sources and their licence files;
- `meta/buildDrmNativeParts.ts`, which runs compile gates and the payload sha pin;
- its jest suite;
- a local build of `detour-cx26.3.0.39832.bin` and `steam.exe` under a gitignored staging dir.

The built artifacts are never committed.
</objective>
