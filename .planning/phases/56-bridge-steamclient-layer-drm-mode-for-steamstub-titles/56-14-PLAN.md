<objective>
Remove the shim-side support for the Phase 52 SteamStub forwarder (D-20, part of D-14's
"do not keep dormant code"), then fix the stale `.bind` comments and the stale spike-skill
guidance.

1. **Generator.** `meta/gen_vtables.ts` loses three things:
   - the `GameLibBridge_CreateInterface` export and its body;
   - the `g_bridge_steamstub_path_active` flag;
   - the `BRIDGE_CONTROL_SLOT_CREATE_INTERFACE` define.

   The only thing that ever set the flag was `GameLibBridge_CreateInterface`, and it was reached
   only through the forwarder `steamclient64.dll` that 56-13 deletes. So every x64 SteamClient
   stub now compiles to the flag-0 branch: the local answer an ordinary title already got. Then
   run `pnpm gen-vtables`. The computed `SHIM_EXPORT_SET_VERSION` changes on its own, because it
   is derived, never hand-edited (56-PATTERNS).
2. **Helper and protocol.** `bridge_helper.c` loses `CONTROL_SLOT_CREATE_INTERFACE` and its
   handler, the `g_SteamInternal_CreateInterface` dlsym, and the FWD CreateInterface log.
   `protocol.ts` loses `CONTROL_SLOT.createInterface`. The other slot numbers stay as they are.
3. **Docs.** The stale `.bind` comments (RESEARCH F9) in `peSections.ts`, `shimGenerate.ts` and
   `electronStores.ts` are rewritten. The spike-findings skill drops its "don't build lsteamclient"
   guidance.

Purpose: DRM mode (56-12) now carries every `.bind` title, so nothing in the shim may stay
reachable only from the forwarder.

Output: the regenerated shim, the .def files, dispatch and export table, the edited helper and
protocol, and the comment and skill fixes, with their tests.

  without editing the tests breaks the suite.

  198. That comment cites `steamClientSetup.ts`, which 56-13 deletes. The brief lists it as an

- No other wave-5 plan touches any of these four files. 56-13 owns `games.ts`,
  `steamClientSetup.ts`, `paths.ts`, `buildSteamBridgeShims.ts`, `native/steam-bridge/steamclient/`
  and the locales.

**The D-20 "one forced rescan" premise, corrected:** the stamp is persisted for diagnostics only
(the `computeExportSetVersion` doc comment, IN-01). `isScanVerdictNowCovered` uses a per-arch
membership test, and no code compares `shimExportSetVersion` in order to trigger a rescan.
Task 1 pins that real behaviour rather than an invented rescan. The SUMMARY states that the
measured cost is zero forced rescans.

**Out of scope, recorded for the user:** commit `da0103f58` (52-01) declared the
SteamClient017/014 non-callback methods `wire` in `meta/sdk/wire-policy.json`. After this plan,
their x64 stubs never call `bridge_transact`. The x86 shim exports no accessor that hands out an
ISteamClient (`steam_api.def` has no `SteamClient`/`SteamInternal_CreateInterface`). So the
remaining x86 wire branch and the helper-side SteamClient dispatch cases are not reachable from
any game. `meta/sdk/*` is not in this plan's ownership, so this plan does not revert it. The
SUMMARY names it as a follow-up.
