# Phase 08.1: Steam Delisted Games & Library Filters - Context

**Gathered:** 2026-07-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Delisted / no-longer-available Steam games are handled correctly in the **Library** (not
Console — Phase 8 already handled Console), and the Library availability filters work
correctly and gain "only-show" modes.

Delivers three requirements (from Phase 8 UAT):
- **LIB-07** — Wire Steam's `is_delisted` signal (added in Phase 8 Gap B) into the frontend
  availability path so the "show non-available" Library filter works for Steam, with
  "non-available" meaning *delisted*, not merely *not-installed*.
- **LIB-08** — A delisted game renders a greyed "Game no longer available" placeholder with
  its install option disabled (no dead `steam://install` handoff).
- **LIB-09** — Add "only show hidden" and "only show non-available" filter *modes* (today
  `showHidden` / `showNonAvailable` are additive-only — there is no "only" mode).

Scope is Library-side only: frontend Library filters + Steam backend availability + placeholder
UI/messaging. Console-mode delisted handling shipped in Phase 8.
</domain>

<decisions>
## Implementation Decisions

### LIB-07 — "Non-available" semantics (Steam)
- **D-01:** "Non-available" means **`is_delisted === true`**, NOT install-state. An owned Steam
  game that is not installed but still purchasable/installable is **AVAILABLE**. Only a delisted
  game (Steam appdetails `success:false`, persisted in Phase 8) is non-available.
- **D-02:** Reconcile the frontend `nonAvailableGames` availability path so that for Steam,
  not-installed ≠ non-available. Steam's `isGameAvailable()` (`games.ts:507`) currently returns
  false for any not-installed game; the Library's non-available/greying decision for Steam must
  be driven by `is_delisted`, not by install-state. Do NOT break the existing `nonAvailableGames`
  mechanism for the other runners (Epic/GOG/Amazon) — this is a Steam-scoped reconciliation.

### Default visibility of delisted games
- **D-03:** Delisted games are **folded into the "non-available" set**: hidden by default (no
  filters active), consistent with how Console mode hides them and how the existing non-available
  filter works. When revealed via **Show non-available** (or **Only non-available**), they render
  greyed with the placeholder + disabled install. One mechanism drives LIB-07/08/09 coherently —
  no separate "always-visible greyed" path.

### LIB-08 — Delisted tile behavior
- **D-04:** A delisted tile **stays clickable and opens the game details page** (not inert). The
  cover art is greyed with a "Game no longer available" treatment.
- **D-05:** The **install action is disabled/hidden** for delisted games — no `steam://install`
  handoff that cannot succeed.
- **D-06:** An **already-installed** delisted game can still **launch and uninstall** (only the
  install path is dead for delisted; existing installs remain fully actionable).
- **D-07:** Placeholder copy: **"Game no longer available"** (matches ROADMAP wording). Reuse the
  greyed placeholder asset and treatment from Phase 8 where it fits.

### LIB-09 — "Only" filter UX
- **D-08:** Expose "only" modes as a **tri-state on the existing LibraryFilters controls**: each of
  Hidden and Non-available cycles **Off → Show → Only**. No new/separate controls added.
- **D-09:** When BOTH controls are set to "Only", show the **union** (games that are hidden OR
  non-available), not the intersection.

### Claude's Discretion
- Exact greyed styling / opacity / badge placement for the delisted placeholder (reuse Phase 8's
  greyed treatment; planner + executor decide precise CSS via semantic tokens).
- Tri-state control affordance (cycling button vs. segmented control) — implement within the
  existing `LibraryFilters` component conventions.
- How the tri-state cycle persists (localStorage key shape) — follow the existing
  `showHidden`/`showNonAvailable` persistence pattern.
</decisions>
