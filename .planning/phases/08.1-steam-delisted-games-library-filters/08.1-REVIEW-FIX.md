### Notes on two dispositions that were judgement calls

**WR-04's fix is wider than the review asked for.** The review proposed a
`try/catch` around the parse. That catches malformed JSON but not `'"5"'` or
`'{}'`, which parse fine and arrive at `filterEngine` as a value with no
`.includes` — the same crash, one layer downstream. The fix rejects non-arrays
and non-string members too. Worth recording: `frontend/index.tsx:121` does
`storage.removeItem('nonAvailableGames')` at boot, so only an in-session write
could corrupt this key. The real-world risk was therefore lower than the review
implies — the fix stands because a whole-screen unmount is not an acceptable
failure mode for a self-rebuilding cache value, not because the input is likely.

**IN-02 asked a question the review left open** ("if lane consistency is
desired"). Resolved as YES: the lanes render directly above the main grid, so
"only hidden games" in the grid beside an unfiltered recent list is a visible
contradiction, and the two lanes had open-coded the same two-way branch twice.
The rule now lives once in `filterEngine.passesHiddenLaneFilter`, per that
module's single-implementation constraint, and a test asserts the lane and the
grid agree on all three arms.
