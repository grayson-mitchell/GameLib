## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend GameInfo → GameCard render | `is_delisted` and title/art fields cross into the DOM via React |
| user click → steam:// handoff | install action would trigger `steam://install`; delisted must not reach it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08.1-03 | Injection (XSS) | delisted badge text | accept | Badge label is a static i18n string (`library.delisted`), NOT store-derived text; React escapes text nodes; no untrusted store copy injected into the DOM |
| T-08.1-04 | Elevation | steam://install for delisted | mitigate | renderIcon returns null and the context-menu install item is hidden when `isDelisted`, so no unreachable install handoff exists for a delisted AppID |
| T-08.1-05 | DoS / broken UI | not-installed delisted lacking notAvailable class | mitigate | `notAvailable: notAvailable || isDelisted` guarantees the greying CSS applies even when getCardStatus reports `notInstalled` |
| T-08.1-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages; no install tasks |
</threat_model>
