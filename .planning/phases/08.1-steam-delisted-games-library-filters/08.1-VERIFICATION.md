### Human Verification Required

#### 1. Delisted badge rendering and position

**Test:** Run the app with a Steam account that has a delisted game in the library. Observe the game card.
**Expected:** A grey "Game no longer available" badge appears at top-left of the card. Art is desaturated/grayscale (not-installed) or sepia (installed). No install button or "Install" context-menu item. Launch/uninstall present if installed.
**Why human:** Badge visual position, overlap check (IN-03: badge shares `top:5px; left:5px` with `gameCardUpdateBadge` — can overlap if game also has a status label), and art filter rendering require a running UI.

#### 2. Tri-state filter cycle behavior

**Test:** Open Library. Locate the "Show Hidden" filter row. (1) Click the toggle — filter switches to Show. (2) Click "only" link — filter switches to Only. (3) Click "only" again — filter returns to Off. Repeat for "Show non-Available games".
**Expected:** Cycle matches Off→Show via toggle, Show→Only via only-button, Only→Show via toggle-switch re-click, Only→Off via only-button re-click. Behavior consistent with D-08.
**Why human:** Click-cycle interaction requires a running UI.

#### 3. 'only' button visual accent state

**Test:** Set either filter to the Only state. Observe the "only" link.
**Expected:** "only" link is visible and rendered in the accent color (not hidden/grey) while the filter is in Only state. Returns to hidden when filter is Off.
**Why human:** CSS `aria-pressed` selector rendering is visual.

#### 4. Empty-state messages for 'only' modes

**Test:** Set "Show Hidden" to Only mode (with no hidden games in library). Observe the Library content area. Then switch to "Show non-Available" Only mode (with no delisted/non-available games).
**Expected:** First case shows "No hidden games in your library". Second case shows "No non-available games in your library". Other combinations show generic "The current filters produced no results."
**Why human:** Requires a running app with specific filter states.

#### 5. WR-01 advisory — legacy boolean preference loss (QA note, not a gate)

**Test:** In a browser devtools console for the running app, manually set `localStorage.setItem('show_hidden', 'true')` then reload. Check if the Show Hidden filter starts in Show mode or Off mode.
**Expected (current behavior):** Filter initializes to Off — `migrateFilterMode` maps legacy `'true'` to `defaultValue` (`'off'`) since `'true'` is not a valid FilterMode string. A user who had this filter enabled before updating loses their preference.
**Expected (ideal behavior):** Filter initializes to Show — `'true'` should map to `'show'` per WR-01.
**Why human:** Product decision needed on whether this preference data-loss is acceptable for v1.1 or should be fixed before release (requires the one-line fix from WR-01 in the review).
