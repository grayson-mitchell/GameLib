## Summary

Phase 08.1 is a frontend-heavy phase with a small backend touch point. The `is_delisted` signal already exists in `GameInfo` and is persisted by the Phase 8 backend (Gap B). This phase consumes that signal in two places: (1) the Library's non-available filter logic and (2) the GameCard tile rendering. A third independent change upgrades the two boolean filter toggles (showHidden, showNonAvailable) to tri-state values.

The most critical finding is a **two-part gap in the LIB-07 fix**: the existing `nonAvailableGames` localStorage mechanism is only populated for *installed* games (via `hasStatus.ts` → `handleNonAvailableGames`). Non-installed delisted Steam games will never enter that localStorage key on their own. The Library filter must therefore also check `game.runner === 'steam' && game.is_delisted` directly. The backend `isGameAvailable()` fix alone is insufficient for the non-installed case.

A secondary finding is a **pre-existing duplicate filter block**: Library/index.tsx applies the `!showNonAvailable` filter at lines 511–517 and again identically at lines 523–529. The new tri-state implementation should collapse these into one.

**Primary recommendation:** Decompose into five waves: (W0) REQUIREMENTS.md entry; (W1) backend `isGameAvailable()` + test; (W2) TypeScript types + context defaults; (W3) Library filter chain rewrite; (W4) UI (LibraryFilters controls, GameCard badge/install, CSS, i18n).

## Critical Finding: The `nonAvailableGames` Gap for Non-Installed Games

[VERIFIED: codebase grep + direct reading of `src/frontend/hooks/hasStatus.ts` and `src/frontend/hooks/constants.ts`]

The `nonAvailableGames` localStorage key mechanism:
1. Cleared on every app startup: `frontend/index.tsx:34` calls `storage.removeItem('nonAvailableGames')`
2. Rebuilt per-card via `hasStatus` hook
3. **Only for installed games**: `hasStatus.ts:82` — the `handleNonAvailableGames` call is inside `if (is_installed && !thirdPartyManagedApp)` block

**Consequence:** A non-installed Steam game with `is_delisted === true` will NEVER enter `nonAvailableGames` via the existing mechanism, even after the backend `isGameAvailable()` fix. The Library filter reading only from `nonAvailableGames` will not hide it.

**Required fix:** The Library filter non-available test must be:
```typescript
const isNonAvailable = (game: GameInfo): boolean => {
  return nonAvailableGamesArray.includes(game.app_name)
    || (game.runner === 'steam' && !!game.is_delisted)
}
```

This is the correct approach because:
- `nonAvailableGames` covers installed non-available games across all runners (Epic/GOG/Amazon with missing install paths, and installed delisted Steam games after the backend fix)
- The `is_delisted` direct check covers non-installed delisted Steam games that never enter the localStorage key

## Common Pitfalls

### Pitfall 1: Duplicate `!showNonAvailable` filter block

**What goes wrong:** Library/index.tsx has the IDENTICAL `!showNonAvailable` filter at lines 511–517 and again at lines 523–529. If only one block is updated, results will be silently wrong.
**Why it happens:** Likely a copy-paste mistake in the original Heroic code.
**How to avoid:** When rewriting the non-available filter section, replace BOTH blocks with a single tri-state check.
**Warning signs:** Games reappear when `showNonAvailable === 'off'` even after a correct fix.

### Pitfall 2: localStorage migration for tri-state

**What goes wrong:** Existing users have `"true"` or `"false"` (JSON boolean) in `localStorage['show_non_available']` and `localStorage['show_hidden']`. `JSON.parse('true')` returns `true` (a boolean), not `'show'`. The new code expects a string.
**Why it happens:** Type change without backward compatibility handling.
**How to avoid:** In the `useState` initializers, add migration logic:
```typescript
const stored = storage.getItem('show_hidden')
const showHiddenInit: FilterMode = (stored === 'show' || stored === 'only')
  ? stored
  : 'off'  // 'false', 'true', null all default to 'off'
```
**Note:** The old default was `'false'` for show_hidden and `'true'` for show_non_available. After migration, both default to `'off'` (D-03).

### Pitfall 3: `showHidden` boolean cast sites

**What goes wrong:** Two sites in Library/index.tsx use `showHidden` as a boolean:
- Line 343: `if (showHidden)` inside `favouriteGamesList` useMemo
- Line 571: `if (!showHidden)` in the filter chain
- Line 747: `showHidden={showHidden}` prop to `RecentlyPlayed` (typed as `boolean` in that component)

**How to avoid:** Replace each boolean check with the tri-state equivalent:
- `if (showHidden)` → `if (showHidden !== 'off')`
- `if (!showHidden)` → `if (showHidden === 'off')`
- `RecentlyPlayed` prop type needs to change to accept `'off' | 'show' | 'only'` or a derived boolean

### Pitfall 4: `notAvailable` class for non-installed delisted games

**What goes wrong:** `notAvailable` in GameCard comes from `getCardStatus(status, ...)` which checks `status === 'notAvailable'`. For a non-installed delisted game, `status` is `'notInstalled'`, so `notAvailable` is `false`. The card won't get the `.gameCard.notAvailable` wrapper class, meaning the CSS greying won't apply.
**Why it happens:** The `notAvailable` status is only set for installed games by `handleNonAvailableGames`.
**How to avoid:** In GameCard's `wrapperClasses`, derive `isDelisted` from `gameInfoFromProps.is_delisted` and include it in the class condition:
```typescript
const isDelisted = !!gameInfoFromProps.is_delisted
const wrapperClasses = classNames(grid ? 'gameCard' : 'gameListItem', {
  installed: isInstalled,
  hidden: isHiddenGame,
  notAvailable: notAvailable || isDelisted,  // <-- extend here
  ...
})
```

### Pitfall 5: i18n key injection requires `pnpm i18n` run

**What goes wrong:** Adding keys only to `public/locales/en/translation.json` without running `pnpm i18n` causes the pre-push `i18n --fail-on-update` hook to fail (or would, if it weren't already broken by pre-existing drift per STATE.md).
**How to avoid:** After adding the 3 new keys to `en/translation.json`, run `pnpm i18n` to propagate keys to all locale files. This is safe even with existing drift.

### Pitfall 6: `resetFilters()` in LibraryFilters needs to set tri-state values

**What goes wrong:** Current `resetFilters()` calls `setShowHidden(true)` and `setShowNonAvailable(true)`. With tri-state these become `setShowHidden('off')` and `setShowNonAvailable('off')`.
**How to avoid:** Update `resetFilters()` in `LibraryFilters/index.tsx` — the "Reset" button should return all filters to their default off state.

### Pitfall 7: `EmptyLibraryMessage` needs LibraryContext access for "Only" mode empty states

**What goes wrong:** The UI spec defines specific empty state messages for "Only hidden" and "Only non-available" modes with no results. `EmptyLibraryMessage` currently doesn't read `LibraryContext`.
**How to avoid:** Add `useContext(LibraryContext)` to `EmptyLibraryMessage`, check `showHidden === 'only'` and `showNonAvailable === 'only'`, and return the appropriate i18n string. Fall back to the existing generic message for other filter combos.

async isGameAvailable(): Promise<boolean> {
  return new Promise((resolve) => {
    const info = this.getGameInfo()
    // LIB-07: delisted game is non-available regardless of install state
    if (info?.is_delisted) {
      return resolve(false)
    }
    resolve(
      Boolean(
        info?.is_installed &&
        info.install?.install_path &&
        existsSync(info.install.install_path)

  })
}

### Pattern 2: Library filter tri-state logic (LIB-07 + LIB-09)

```typescript
// Replaces lines 511-529 in Library/index.tsx
// Source: direct codebase reading

type FilterMode = 'off' | 'show' | 'only'

const isNonAvailable = (game: GameInfo): boolean => {
  // Installed games across all runners → nonAvailableGames via handleNonAvailableGames
  // Non-installed delisted Steam games → direct is_delisted check (never enters localStorage)
  return nonAvailableGamesArray.includes(game.app_name)
    || (game.runner === 'steam' && !!game.is_delisted)
}

const isHidden = (game: GameInfo): boolean => {
  return hiddenGamesAppNames.includes(game.app_name)
}

// Both 'only' → union (D-09)
if (showHidden === 'only' && showNonAvailable === 'only') {
  library = library.filter(game => isNonAvailable(game) || isHidden(game))
} else if (showHidden === 'only') {
  library = library.filter(isHidden)
} else if (showNonAvailable === 'only') {
  library = library.filter(isNonAvailable)
} else {
  if (showNonAvailable === 'off') {
    library = library.filter(game => !isNonAvailable(game))
  }
  if (showHidden === 'off') {
    library = library.filter(game => !isHidden(game))
  }
}
```

### Pattern 8: localStorage migration for tri-state

```typescript
// src/frontend/screens/Library/index.tsx — existing pattern at lines 141-171

type FilterMode = 'off' | 'show' | 'only'

const migrateFilterMode = (key: string, defaultValue: FilterMode): FilterMode => {
  const stored = storage.getItem(key)
  if (stored === 'show' || stored === 'only' || stored === 'off') return stored
  return defaultValue  // handles 'true', 'false', null (all legacy values)
}

const [showHidden, setShowHidden] = useState<FilterMode>(
  migrateFilterMode('show_hidden', 'off')
)
const handleShowHidden = (value: FilterMode) => {
  storage.setItem('show_hidden', value)
  setShowHidden(value)
}

const [showNonAvailable, setShowNonAvailable] = useState<FilterMode>(
  migrateFilterMode('show_non_available', 'off')
)
const handleShowNonAvailable = (value: FilterMode) => {
  storage.setItem('show_non_available', value)
  setShowNonAvailable(value)
}
```
