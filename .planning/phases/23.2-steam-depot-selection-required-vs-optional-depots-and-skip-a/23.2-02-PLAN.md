Close D-08: stop a native install that downloaded **zero bytes** from clobbering a complete
install's `appmanifest_*.acf` with a `StateFlags 1026` / `buildid 0` / empty-`InstalledDepots`
stub.

because plan 23.2-03 removes the one reproduction we know how to trigger — once EResult 40 stops
aborting the install, the KCD2 path that produced the stub stops producing it. Shipping the skip

to find.

bottle-path regression test that asserts on manifest **content**; and three existing assertions
in `depot.test.ts` deliberately inverted because they encode the defect.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GameLib → on-disk state owned by the Steam client | `appmanifest_*.acf` files are read and trusted by a different application. GameLib writing there is a cross-application write. An unintended overwrite destroys state GameLib did not create and cannot reconstruct — the 989-byte → 402-byte replacement is exactly this. |
| Remote Steam CM → local control flow | The thrown error that reaches the catch block originates at a remote CM. Its shape (including `eresult`) is attacker-influencable in principle and must never be trusted to decide whether a destructive write happens. |
| Depot ids / buildid → VDF serialization | Every value interpolated into the manifest text crosses from remote PICS data into a file another application parses. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23.2-05 | Tampering | `downloadSteamDepots` catch-path `finalize()` → `writeAppManifest` | mitigate | The observed defect IS unintended destruction of another application's on-disk state. Gate the write on `shouldFinalizeAfterThrow({ downloadAttempted })`, which is derived from GameLib's OWN local control flow (a flag set immediately before `downloadDepotFiles`), never from the remote error's contents. A remote CM cannot cause the destructive branch to be taken by shaping its error. |
| T-23.2-06 | Denial of service | Steam's view of a complete install | mitigate | A stub with `StateFlags 1026` and an empty `InstalledDepots` causes Steam to re-verify or re-download a complete 90 GB install — a user-visible availability loss triggered by any plan-build failure. Closed by the same gate. Regression-tested by Task 1's exact-text-equality assertion against a seeded `StateFlags 4` manifest. |
| T-23.2-07 | Tampering | Test assertion shape | mitigate | A presence-only assertion (`existsSync`, or `toMatch(/"InstalledDepots"/)`) passes against the exact stub it should catch, because `buildAppManifestText` emits the key unconditionally. Mitigated by requiring exact-text equality plus a depot-id-entry match, and by an explicit acceptance criterion forbidding the bare-key regex. The red-proof requirement in Task 1 is the enforcement: an assertion that cannot fail against the known-bad specimen is not accepted. |
| T-23.2-08 | Elevation of privilege | Widening the no-write branch | mitigate | The gate is deliberately single-input and returns `true` for every path where `downloadDepotFiles` ran. Task 3's new case B pin fails if a future change makes the no-write branch swallow a legitimate `1026` verify-handoff. |
| T-23.2-09 | Information disclosure | The new `logWarning` on the no-write branch | mitigate | Logs appId only. No decryption key, no manifest GID payload, no SteamID64 — matching `wrapDepotKeyError`'s existing T-23-31 field discipline in the same file. |
| T-23.2-10 | Tampering | VDF interpolation of depot ids / buildid | accept | Unchanged by this plan and already mitigated upstream: `buildInstalledDepotsBlock` runs `assertNumericId` on both `depotId` and `manifest`, and `buildAppManifestText` runs `assertNumericBuildid`. This plan writes strictly fewer manifests than before, so it cannot widen this surface. Accepted with the existing guards as the mitigation. |
| T-23.2-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — this plan installs no packages and adds no dependency. No package-manager command runs. |
</threat_model>
