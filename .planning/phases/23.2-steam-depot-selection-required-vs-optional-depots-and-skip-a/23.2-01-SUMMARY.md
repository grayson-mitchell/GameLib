## Accomplishments

- Read the pre-fix `downloadSteamDepots`/`finalizeToSteam`/`buildAppManifestText` source (before
  plan 23.2-02 changes it) and produced a line-anchored taxonomy naming exactly three
  distinguishable manifest-write outcomes: Case A (plan-build throw — writes a `StateFlags 1026`/
  `buildid 0`/present-but-empty-`InstalledDepots` stub, unconditionally, even over a complete prior
  install — this is the D-08 defect), Case B (post-plan failure/cancel — the legitimate Phase 21
  `1026` verify-handoff, load-bearing and must not regress), Case C (hard process kill — no code
  runs, nothing is written, already correct).
- Corrected the 2026-08-16 todo's false generalisation ("the `.acf` is only written on a successful
  completion") via a dated `## Correction` section that strikes the sentence in place rather than
  deleting it, and narrows the todo's still-open reconciler-invisibility concern to Case C only.
- Adjudicated the 2026-08-19 todo's three candidate explanations for the 2026-07-21-vs-2026-08-19
  contradiction. `git log -S "await finalize().catch" -- depot.ts` shows the catch-block's
  unconditional `finalize()` call has existed unchanged since commit `eacbc7ccf` (2026-07-15) — six
  days before the 2026-07-21 UAT run — ruling out "behaviour changed." "The two failure modes
  differ" is true for Case A vs Case C but does not explain the 2026-07-21 vs 2026-08-19 pair,
  since both were Case A. "Checked the wrong directory" (bottle vs macOS `steamapps`) is therefore
  the most likely unfalsified explanation, but is recorded as unestablished — no artifact from
  2026-07-21 states which directory was inspected.
- Corrected the 2026-08-19 todo's "InstalledDepots ABSENT ENTIRELY" claim to "present but empty" —
  `buildAppManifestText` emits the key unconditionally — flagging that a bare
  `toMatch(/"InstalledDepots"/)` assertion would be vacuous against the exact stub it should catch.
- Amended 23-UAT.md Gate 2 Attempt 1 in place, following the file's own established
  amendment-block precedent (the 2026-08-19 census addendum immediately below it): the
  "before any `.acf` was written" half of the claim is wrong, without touching or weakening the
  EResult 40 / depot 1771304 finding that is this phase's whole premise.
- Closed D-08 sub-item 2: `measureInstalledBytes` (`depot.ts:2439-2457`) is a recursive
  `readdir`/`stat` walk with zero knowledge of `opts.depots`/`plan.depots`. The
  `96,422,090,071` SizeOnDisk match was the official client's own still-present complete install
  being measured, not depot-plan-aware accounting. **No new size accounting is needed for
  skip-and-warn**; `DepotPlan.totalBytes` (the progress denominator) remains plan 23.2-03's
  separate, still-open concern.
