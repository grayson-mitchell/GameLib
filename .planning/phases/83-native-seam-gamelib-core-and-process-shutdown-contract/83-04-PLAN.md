<objective>
Create gamelib-proc (FND-04 criterion 4, D-11, D-13): the process-lifetime implementation crate. It owns how GameLib
spawns a child (SpawnClass::Helper vs SpawnClass::Game, D-15), how it kills a tree (unix process group, Windows Job),
the helper ChildSet the exit path drains, ProcRunner (core's ProcessRunner), and the stand-in harness that proves on
windows, macos and ubuntu that helpers die and a game tree survives. The unix SIGKILL leg needs the reaper (plan 83-07).

Purpose: research Pattern 5 and D-11. Every piece exists today in a narrower form (sidecar.rs kill_process_group and
create_kill_on_close_job, shell_state.rs shutdown_child, steampoll TokioRunner); this plan moves and generalises them
behind one crate so later slices stop re-solving them.

Claude's discretion recorded: Windows uses one kill-on-close Job per Helper spawn (the analogue of one unix process
group per helper) rather than one process-wide Job, so reaping a dead sidecar's Job never kills unrelated helpers. Both
satisfy D-11; research's process-wide variant is not chosen for that reason.
</objective>
