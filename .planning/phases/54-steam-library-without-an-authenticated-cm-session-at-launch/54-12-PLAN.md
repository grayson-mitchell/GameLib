<objective>
Close the core of the 54-UAT.md gap "Mac Steam is never left offline by GameLib": give the
go-offline wrap a persistent record of the goonline it owes, and a restore function the shutdown
and boot paths (plan 54-13) call. Today `withMacSteamOffline` fires `steam://open/gooffline` and
fires `steam://open/goonline` only in `runThenGoOnline`'s `finally`. A process that dies in between
leaves Mac Steam offline, and Mac Steam persists that as the user's choice (`WantsOfflineMode=1` in
`loginusers.vdf`), so it starts offline on every restart.

Purpose: the marker is the only thing that can outlive a `kill -9`. Without it, neither a shutdown
hook nor a boot check can tell "GameLib took Steam offline" from "the user chose offline".
Output: the marker lifecycle and `restoreMacSteamOnlineIfOwed` in `macSteamOffline.ts`, with tests
written first (RED commit, then GREEN commit, as plans 54-01 and 54-03 did).

## Design decisions (settled here; the executor implements them, does not revisit them)

**DD-1. Marker location.** `join(appFolder, 'mac-steam-offline-owed.json')`, which on macOS is
`~/Library/Application Support/GameLib/mac-steam-offline-owed.json`. `appFolder` comes from
`backend/constants/paths`, loaded lazily inside the default dep (same reason `connectionLogPath`
lazily requires `backend/config`; see 54-03 deviation 1). Never Steam's own files: GameLib does not
write `loginusers.vdf` or anything under Steam's directory. Content is
`{"since":"<ISO time>","by":"toggled"|"guided","pid":<deps.selfPid>}`, file mode 0o600, written with `writeFileSync`
after `mkdirSync(dirname, { recursive: true })`. It carries no account name, SteamID or token. `pid` is the owning sidecar's process id (DD-8).
**Presence is the debt.** Content is diagnostic only; an empty or unparseable file still counts
as owed, because a crash during the write must not erase the debt.

**DD-2. Write and clear points.**
- Toggled path: `recordOnlineDebt('toggled')` runs before `watchConnectionLog` starts and before
  `deps.openUrl(STEAM_GO_OFFLINE_URL)`.
- `runThenGoOnline` (both `toggled` and `guided-restore`): records the debt again at entry
  (idempotent), and calls `clearOnlineDebt()` in the `finally`, after `deps.openUrl(STEAM_GO_ONLINE_URL)`.
- `checkGuidedOfflineReady`: when Mac Steam is running and its state is `Logged Off`, record
  `'guided'` before arming. The user went offline because GameLib asked, so GameLib owes the
  goonline from that moment. When Steam is not running, record nothing (Steam is not offline).
- `GuidedOfflineRequiredError('logoff-not-seen')`: the marker is **kept**. gooffline was fired
  and Steam may still act on it. Spike 046a measured goonline on an online Steam as a no-op (0
  connection_log lines over 6 s), so an extra restore costs nothing. Leaving Steam offline is the
  defect being fixed.
- `'running-probe-failed'`: no gooffline was fired and no marker is written.
- A marker write failure logs `go-offline wrap: could not record the owed goonline (<err.code>)`
  via `logWarning` and the wrap proceeds. Refusing the wrap would add a new refusal mode.
  The in-process `finally` still restores in the normal case, and an unwritable config dir
  breaks far more than this.

**DD-3. A Logged Off Steam with the marker present is owed, not the user's choice.** In the
`state === 'Logged Off'` branch, `armed = guidedArmed || debtPresent`. When it is armed only by the
marker, log `go-offline wrap: Mac Steam state=Logged Off (owed from an interrupted wrap), will
restore online afterwards` and run `runThenGoOnline(connect, 'guided-restore', deps)`. Reusing
`guided-restore` is deliberate. The behaviour is identical (Steam is offline because of GameLib, so
log on and then restore), and widening `MacSteamWrapKind` would change the `wrap=` oracle that
Rule K and the live gate score. With no marker and no guided arm, `already-offline` is unchanged, so
gate item 7 still holds.

**DD-4. `restoreMacSteamOnlineIfOwed(trigger, deps)`.** `trigger: 'boot' | 'shutdown'`. It never
rejects, and it is single-flight: a call made while one is in flight returns the same promise.
Steps, in order:
1. `deps.platform !== 'darwin'`: return `'not-darwin'`. No fs or spawn work.
2. Marker absent (`existsSync(deps.onlineDebtPath())` false): return `'not-owed'` with **no** pgrep
   and **no** log line. This is what keeps the user's own offline choice untouched, and it makes
   every test boot and every no-debt boot free.
3. `deps.isSteamRunning()` throws: log `go-offline restore trigger=<t>: running probe failed, marker kept`
   and return `'kept-probe-failed'`. If it returns false: log `go-offline restore trigger=<t>: owed but Mac Steam not running, marker kept`
   and return `'kept-not-running'`. **Decision:** goonline is never fired at a Steam that is not
   running. `open steam://...` would launch Steam, which GameLib must not do on quit or on boot.
   The debt is paid later by the next boot with Steam running, by the next wrapped logon (DD-3), or
   by the next shutdown with Steam running.
4. Log `go-offline restore trigger=<t>: firing goonline`, then fire with
   `deps.openUrlDetached(STEAM_GO_ONLINE_URL)`, never `deps.openUrl` (see DD-5).
5. `trigger === 'shutdown'`: `clearOnlineDebt()` immediately and return `'restored'`. There is no
   wait, because quit must not be held open. At shutdown Mac Steam has been running alongside
   GameLib, and 046a measured goonline completing in about 1.5 s. Keeping the marker for a later
   boot to confirm would undo a deliberate offline choice the user makes between quit and the next
   launch.
6. `trigger === 'boot'`: start `watchConnectionLog(deps.connectionLogPath(), /processing complete/, MAC_STEAM_RESTORE_CONFIRM_MS, deps)`
   BEFORE firing (step 4 runs after the watch is started, same ordering as the wrap). Then:
   - seen: clear, log `go-offline restore trigger=boot: Mac Steam back online, marker cleared`,
     return `'restored'`.
   - not seen, and `readMacSteamCmState(...) === 'Logged On'`: Steam was already online, and
     goonline on an online Steam adds 0 lines (046a). Clear, log the same `back online` line,
     return `'restored'`.
   - otherwise keep the marker, log `go-offline restore trigger=boot: online not confirmed within 10000ms, marker kept`
     and return `'restore-unconfirmed'`. Steam may still be starting up, and the next wrap or boot
     retries.
   **The `Logged On` fallback reads only fresh lines (checker INFO-3).** It uses a new
   `readMacSteamCmStateSince(path, sinceMs)`: the same 64 KiB tail scan as `readMacSteamCmState`,
   but it considers only bracketed lines whose leading `[YYYY-MM-DD HH:MM:SS]` timestamp, parsed as
   local time, is at or after the marker's `since`. A `Logged On` line written before GameLib took
   Steam offline therefore cannot clear the marker. If the marker has no parseable `since`
   (garbage content), the fallback is skipped and only the `processing complete` watch can clear it.
   `MAC_STEAM_RESTORE_CONFIRM_MS = 10000`. The wait is bounded and sleeps on `deps.sleep`, whose
   default `.unref?.()`s its timer (sidecar exit contract halves 1 and 2).

**DD-5. Restore fires through a direct, detached `/usr/bin/open`, not `shell.openExternal`.**
`shell.openExternal` in the sidecar is `transport?.openExternal(url)`. It writes a frame to the Rust
shell over stdout. At stdin EOF the shell is gone, so the frame goes nowhere. On a routed Cmd+Q,
`app.exit()` follows within milliseconds and `shutdown_child()` SIGTERMs the sidecar's whole
process group (`src-tauri/src/main.rs` `shutdown_child`). New dep `openUrlDetached: (url: string) => void`.
Its default is exported as `spawnOpenDetached(url)`:
`spawn('/usr/bin/open', ['-g', url], { detached: true, stdio: 'ignore' })`, then
`child.on('error', ...)` logging via `logWarning` (a spawn failure arrives as an async `'error'`
event, and an unhandled one would crash the sidecar), then `child.unref()`.
- `detached: true` puts `open` in its own process group, so the group SIGTERM/SIGKILL that follows
  a quit cannot kill it before LaunchServices dispatches the URL.
- `-g` keeps Steam in the background, the flag 046a used.
- `unref()` plus `stdio: 'ignore'` keeps the child from holding the sidecar's event loop (exit
  contract half 1). `open` exits by itself in milliseconds.
- **Fake-HOME rule:** this is a production spawn that must inherit the operator's real session,
  because LaunchServices resolves `steam://` per user. So it passes **no** `env` option, which is
  what `fakeHomeIsolation.test.ts` requires (no hand-rolled env literal). Tests never execute it:
  the restore tests inject `openUrlDetached`, and the spawn-shape test mocks `child_process.spawn`.
- The wrap's own gooffline and goonline keep using `deps.openUrl` (`shell.openExternal`). That is
  the path spike 046b proved live, and this gap does not touch it.

**DD-6. `kill -9` cannot be caught.** No in-process hook runs on SIGKILL, so the boot-time restore
(DD-4 with `trigger='boot'`, wired in 54-13) is the **only** cover for a SIGKILL of the sidecar.
The marker is what makes that possible.

**DD-7. A wrap waits for an in-flight boot restore.** At the top of `withMacSteamOffline`, after
the darwin check, `if (restoreInFlight.boot) await restoreInFlight.boot`. Otherwise a Refresh pressed within 10 s
of boot could read a still-`Logged Off` state while the boot goonline is landing, and log on while
Mac Steam reconnects. The wait is bounded by DD-4: pgrep's 2000 ms timeout plus
`MAC_STEAM_RESTORE_CONFIRM_MS`.

**DD-8. The marker has an owner (checker W2).** The UAT evidence shows two GameLib instances
spawned 4 s apart. Without an owner, a second sidecar booting during the first one's live 3-5 s
wrap would read the marker as stale and fire goonline mid-logon, which signs Friends out.
- `recordOnlineDebt` writes `pid: deps.selfPid` (default `process.pid`).
- New dep `isPidAlive: (pid: number) => boolean`. Its default is `process.kill(pid, 0)`: returns
  true, or catches and returns `err.code === 'EPERM'`.
- In `restoreMacSteamOnlineIfOwed`, after the marker-present check and before pgrep: parse the
  marker. If it has a numeric `pid` that is not `deps.selfPid` and `deps.isPidAlive(pid)` is true,
  log `go-offline restore trigger=<t>: marker owned by a live GameLib process, marker kept` and
  return `'kept-owner-alive'`. This applies to both triggers: a shutdown must not break another
  instance's wrap either.
- In the DD-3 branch, a marker owned by another live pid does not arm the owed restore (that
  instance owes it, not this one). The branch falls through to `already-offline` unless guided
  is armed.
- Unparseable content, or no `pid`, means the owner is unknown, which is treated as a dead owner.
  The debt is still owed (DD-1 is unchanged).
- Accepted residual risk: pid reuse can make a stale marker look alive. The result is only that
  the debt is kept, and it is retried at the next boot or wrap. Steam is never wrongly brought
  online.

**DD-9. Flights are per trigger (checker W1).** Use
`const restoreInFlight: { boot: Promise<MacSteamRestoreOutcome> | null; shutdown: Promise<MacSteamRestoreOutcome> | null }`.
A call joins only a flight of the **same** trigger. Why per-trigger rather than racing
`handleExit` against a timeout:
- A `shutdown` call made while a `boot` flight sits in its 10 s confirm window must not wait for
  that window. The shutdown flight runs its own steps: owner check, pgrep, fire, clear.
- The worst-case quit latency is therefore pgrep's 2000 ms, independent of boot.
- A double goonline (boot plus shutdown) is a measured no-op (046a).
- `clearOnlineDebt` uses `force: true`, so whichever flight clears second is a no-op.
- A boot flight that later times out "keeps" the marker by doing nothing, so it cannot re-create a
  marker the shutdown flight already cleared.
- `__resetMacSteamOfflineForTests` resets both slots.
