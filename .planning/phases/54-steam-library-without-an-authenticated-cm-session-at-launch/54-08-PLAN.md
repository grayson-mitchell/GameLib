<objective>
Finish moving `SteamGame` onto the session policy: the game page and Play open nothing; install
paths hold one wrapped lease each (ROADMAP SC2, SC3, SC6).

- `getExtraInfo()`: delete the fire-and-forget `SteamUser.ensureConnected()` (RESEARCH Finding 2
  row 3). The `noteSteamAuthTrigger('game-page')` label call stays (it reads no keyring and opens no
  connection; it only labels later keyring reads).
- Play: already logon-free after plans 05 and 06 (anonymous launch target, shared redists without
  `allowLogon`); this plan pins it with tests and an explicit comment at the call.
- Installs: `runNativeDepotDownload` acquires before `resolveSteamInstallTarget` (so the
  installdir fallback in plan 06 sees an open session for gated apps) and before the crash
  breadcrumb (`markSteamNativeInstallStarted`), so a refused install leaves no residue record.
  `install()`'s bridge pending-scan prescreen acquires its own short lease, so a refusal there
  stops before a second wrap attempt. `installBridgeGame` holds a lease across download, shim
  placement and the shared-redist step, which now runs at install time with `allowLogon: true`
  (decision recorded in plan 05).

Planner decision (Claude's discretion, recorded): a go-offline refusal maps to
`{ status: 'done', deferredToSetup: true }`, the same "a dialog owns the next step, the install did
not fail" contract the bridge route notice uses (games.ts:1296-1305). `installBridgeGame` must
return such a result untouched instead of treating `status: 'done'` as a finished download.
</objective>
