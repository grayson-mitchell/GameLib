<objective>
Wire plan 54-12's `restoreMacSteamOnlineIfOwed` into the three exit and entry paths, so an owed
goonline is paid however GameLib leaves. There are three layers, and each covers what the others
cannot:

1. **Routed quit** (macOS Cmd+Q and Dock Quit are routed to the sidecar's `quit` handler, which
   calls `handleExit()`). The transport is alive and the process has time. `handleExit` awaits
   `SteamUser.releaseForShutdown()`, which logs the CM client off and then restores, before
   `app.exit()`.
2. **Shell killed or crashed** (Force Quit SIGKILLs the shell; the sidecar sees stdin EOF and
   `releaseOnStdinEof` runs). The transport is gone, so the restore uses 54-12's detached
   `/usr/bin/open` (DD-5).
3. **Sidecar SIGKILLed, or SIGTERMed by `shutdown_child()` on a path that skipped `handleExit`**
   (logout, system shutdown, `exit(0)` fallbacks). No JavaScript runs, so the next boot pays the
   debt. This is the only cover for `kill -9` (54-12 DD-6).

Purpose: closes the remaining `missing` items of the 54-UAT.md gap (shutdown-path restore,
boot-time restore). The marker work is done in 54-12.
Output: the wiring, plus tests that pin each call site and its ordering.
</objective>

## Design decisions

**DW-1. Order: logOff first, then restore.** In `releaseForShutdown`, call
`restoreMacSteamOnlineIfOwed('shutdown')` **after** `releaseAnonymousForShutdown()` and after
`client.logOff()`. A GameLib logon still in flight must not land after Mac Steam reconnects; that
is the same invariant as 54-03's "a logon in flight at 35 s is logOff()'d before the wrap returns
(so before goonline)". The current `if (!client) return` early exit must not skip the restore. A
debt from a previous run is owed even when this run never logged on.

**DW-2. `releaseForShutdown` returns the restore promise.** The signature becomes
`static releaseForShutdown(): Promise<MacSteamRestoreOutcome>`. The synchronous side effects
(`shuttingDown = true`, the idle-timer clear, the anonymous release, `logOff`) still happen before
it returns, so existing callers and tests that do not await behave as before. The promise never
rejects (54-12 DD-4). Callers use only `void` or `await`, never `.catch(...)`, because jest's
`resetMocks: true` turns a mocked implementation into one that returns `undefined`.
- `stdinEofRelease.ts`: `void SteamUser.releaseForShutdown()`. This is the exit-contract shape: the
  pending restore is bounded (pgrep 2000 ms; at shutdown there is no confirm wait, DD-4 step 5) and
  the detached child is unref'd, so drain is delayed by at most the pgrep time. That is half 2's
  "bounded", not "unbounded".
- `utils.ts` `handleExit()`: insert `await SteamUser.releaseForShutdown()` immediately after
  `mainWindow?.hide()` and before `await gogPresence.deletePresence()`. It runs only once the user
  has confirmed the quit (after the pending-operations dialog's early `return`). It must finish
  before `app.exit()`, because `app.exit()` leads to `shutdown_child()`'s group SIGTERM within
  milliseconds. The added quit latency is bounded at about 2 s (pgrep timeout) on macOS with a
  marker present. With no marker or not on macOS it is a few microseconds. Import `SteamUser` from
  `./storeManagers/steam/user`. `utils.ts` already imports `./storeManagers` (which loads the steam
  manager), so this adds no new import cycle.

**DW-3. Boot call placement.** In `bootstrap.ts` `init()`, add
`void restoreMacSteamOnlineIfOwed('boot')` right after the
`electronStub.bindTransport({...})` call. Placement reason: `GlobalConfig` (which
`connectionLogPath` needs) is loadable there, and it runs before the READY sentinel, so it is
already in flight before the renderer can press Refresh. 54-12 DD-7 makes any wrap wait for it.
It does not use the transport (DD-5). `init()` runs repeatedly in the sidecar test suites. On a
test profile there is no marker, so the call returns `'not-owed'` with no spawn and no log line
(DD-4 step 2), and no suite changes behaviour. A comment above the call states the three-layer
model in two lines and names `kill -9` as covered only here.

**DW-4. No SIGTERM handler is added.** `shutdown_child()`'s SIGTERM to a sidecar that skipped
`handleExit` is covered by layer 3 (boot). A signal handler would amend the exit contract beyond
its documented stdin-EOF exception. That is a separate decision and is not needed to close this gap.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| quit path -> Rust shell | `app.exit()` triggers a group SIGTERM that bounds what the sidecar can still do |
| boot -> Mac Steam | a stale marker from a previous process drives a URL dispatch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-52 | Denial of service | handleExit | mitigate | the awaited restore is bounded by pgrep's 2000 ms timeout and has no confirm wait at shutdown; with no marker or off macOS it returns immediately |
| T-54-53 | Denial of service | sidecar exit at stdin EOF | mitigate | `void` call; the restore's only referenced work is the bounded pgrep; the detached `open` child is unref'd (54-12 DD-5); `pnpm smoke:sidecar` re-run |
| T-54-54 | Spoofing (Friends) | quit while a logon is in flight | mitigate | `logOff()` precedes the restore inside `releaseForShutdown` (DW-1), asserted by invocation order |
| T-54-55 | Tampering | boot restore vs user intent | mitigate | fires only with a marker (54-12 DD-4 step 2); test profiles and the smoke profile carry none, so behaviour there is unchanged |
</threat_model>
