<objective>
Make the launch deferral deterministic (ROADMAP SC1) and move the Refresh path onto the lease API.

Root cause being removed: `authTrigger.ts`'s gate is sticky and `'boot-probe'` is deliberate, so
whichever of the Phase 49 boot probe and the mount `refresh()` lands first decides whether launch
logs on. The fix separates "may read the keyring" (the existing sticky gate, unchanged) from "this
refresh may open an authenticated logon" (a new one-shot grant armed only by an explicit Refresh or
a sign-in dispatch and consumed synchronously by `refresh()`). No ordering of boot-probe and mount
can arm the grant, so launch cannot log on.

Planner decisions (Claude's discretion, recorded):
- Origins `'game-status'` (fires after every install/Play status change, GlobalState.tsx:1560-1577)
  and `'nav-tabs-games-tab'` (fires when browsing to the Games tab with an empty store) stop being
  `'user-refresh'`: they are Play and browse, which the phase goal says must never log on. They
  fall through to `'startup'`. Origins audited 2026-10-27 (every `origin:` literal under src/frontend): `'steam-sync-notice-retry'`
  (the "Retry Steam sync" button, `Library/components/SteamSyncNotice/index.tsx:96`) is an explicit
  user Refresh but was never in ORIGIN_TO_TRIGGER (it only worked because the gate was sticky); it
  now maps to `'user-refresh'`, else Retry would silently emit idle. `'clear-cache'`
  (`Settings/components/ClearCache.tsx:15`) maps to `'user-refresh'`: it is a deliberate user action
  that may have just cleared cached data, so it must be able to repopulate the list; the logon is
  wrapped like any Refresh. `'login-screen'` (`Login/index.tsx:329`, the Library button on the
  accounts screen) stays unmapped (`'startup'`): it is navigation, and a Steam sign-in already
  granted its own refresh through `'login-success'` / `'steam-login'`. New origin
  `'steam-go-offline-retry'` (plan 07's dialog) maps to
  `'user-refresh'`.
- An ungranted refresh still does useful local work: it reuses an open session if an install or
  Refresh left one in its idle grace (`acquireOpenAuthenticated`, no logon), else it runs the
  existing filesystem-only `refreshInstallState()` (so the post-install/post-Play `game-status`
  resync still reconciles badges) and emits `idle`. The cached list is already on screen from
  `init()` (RESEARCH Finding 9).
- Platform capture follows ROADMAP SC2 (anonymous). To avoid regressing gated apps whose anonymous
  PICS answer is `public_only` (RESEARCH Finding 4), the Refresh runs a second
  `captureOwnedAppPlatforms` pass on the authenticated client it already holds; the function scopes
  to still-uncaptured apps, so that pass covers only the public_only remainder. No extra logon.
- Go-offline refusal on a Refresh emits `idle`, not `failed`: no new failure-reason vocabulary,
  and the guided dialog (pushed by `acquireAuthenticated`) is the user-facing surface.
</objective>
