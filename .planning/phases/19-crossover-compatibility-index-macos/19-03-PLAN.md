<objective>
Build the app-side cache scaffold for the CrossOver compatibility index — the D-19 seam.

This plan delivers three backend files (plus tests) that let the app safely consume a remotely
published index without a running builder or publishing workflow yet:
1. `schema.ts` — a `zod` schema validating the fetched payload (D-09), rejecting malformed,
   truncated, or poisoned payloads.
2. `electronStore.ts` — a `CacheStore` configured with `invalidateCheck: () => false` for a
   24-hour TTL, keep-last-good store (D-08), mirroring the existing `umuStore` precedent.
3. `fetcher.ts` — a generic `loadIndex<T>(descriptor: IndexDescriptor<T>)` layer doing
   fetch → gunzip → `safeParse` → fallback-to-last-good/bundled, reading the bundled snapshot
   via the existing `publicDir` constant and tolerating the file's ABSENCE as a normal
   cold-start.

Purpose: This is the app's trust boundary for the remote index. A bad CI publish must not be
able to inject junk medals or brick badges — schema validation plus keep-last-good is the
mitigation. The seam is deliberately parameterized by index IDENTITY (name/URL/schema) so the
deferred `mac-arch-overrides.json` index drops in without rework — but it is NOT a framework:
one type, one function, no registry, no dynamic dispatch (D-19).

Output: `src/backend/crossover_index/{schema.ts,electronStore.ts,fetcher.ts}` + their tests.
</objective>

CacheStore constructor (src/backend/cache.ts) — already read; key facts:
- `new CacheStore<ValueType, KeyType>(filename, max_value_lifespan_minutes, { invalidateCheck })`
- `get(key)` DELETES the entry on TTL expiry ONLY when `invalidateCheck(value)` returns `true`.
  Default `invalidateCheck` is `() => true` (auto-evict). Passing `() => false` disables
  eviction entirely — the entry is never thrown away, only ever replaced by `set()`.
- `set(key, value)` writes a `__timestamp.<key>` sidecar automatically.
- `get(key, fallback)` returns `fallback` when the key is absent.
This is exactly why keep-last-good (D-09) requires `invalidateCheck: () => false`: the loader,
not CacheStore, decides staleness so an expired-but-valid index is never destroyed before a
refresh attempt succeeds.

Existing instantiation idiom to mirror (src/backend/wiki_game_info/electronStore.ts):
```

  invalidateCheck: (data) => !data
```

```
  version: z.literal(1),
  generatedAt: z.string().datetime(),
  entries: z.array(z.object({
    name: z.string().min(1),
    rating: z.number().int().min(1).max(5),
```

Target D-19 loadIndex skeleton (from RESEARCH.md, copy-ready — reconcile the stored wrapper
with the CacheStore instance so the loader owns staleness):
```
export async function loadIndex<T>(desc: IndexDescriptor<T>): Promise<T | null> {
  const cached = store.get(desc.name)
  if (cached && !isStale(cached, desc.ttlMinutes)) return cached.data
  try {
    const { data } = await axiosClient.get<ArrayBuffer>(desc.url, {
      responseType: 'arraybuffer',
      maxContentLength: 5 * 1024 * 1024
    })
    const json = JSON.parse(gunzipSync(Buffer.from(data)).toString('utf-8'))
    const parsed = desc.schema.safeParse(json)
    if (!parsed.success) {
      logError(['Rejected index payload', desc.name, parsed.error.issues], LogPrefix.Backend)
      return cached?.data ?? loadBundledSnapshot(desc)
    }
    store.set(desc.name, { data: parsed.data, fetchedAt: Date.now() })
    return parsed.data
  } catch (error) {
    logError(['Index refresh failed, keeping last good', desc.name, error], LogPrefix.Backend)
    return cached?.data ?? loadBundledSnapshot(desc)
  }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote GitHub Release asset → app backend | The fetched `crossover-index.json.gz` is untrusted input crossing into the app. It drives a user-facing claim ("this game won't run"), so a bad/poisoned CI publish must not inject junk medals or brick badges. |
| bundled snapshot file → app backend | The `publicDir` snapshot is build-time data but is still parsed and validated like any external payload. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Tampering | `loadIndex` payload parse (fetcher.ts) | mitigate | `desc.schema.safeParse` with `rating.int().min(1).max(5)` rejects poisoned/junk medal values; malformed payloads are rejected and last-good is kept (D-09). safeParse never throws — reject path returns the previous good value. |
| T-19-02 | Denial of Service | `axiosClient.get` (oversized payload) | mitigate | `maxContentLength: 5 * 1024 * 1024` caps the download (mirrors Phase 16's MAX_CONTENT_LENGTH); `entries.min(1000)` upper structure is bounded by the 5 MB cap; a rejected/oversized fetch falls back to last-good/bundled without throwing. |
| T-19-03 | Information Disclosure / Tampering-in-transit | `desc.url` fetch | mitigate | The descriptor `url` MUST be `https://` (TLS integrity + confidentiality). Documented as an IndexDescriptor contract; the CrossOver descriptor URL is the GitHub Releases HTTPS asset endpoint. |
| T-19-04 | Tampering (truncation) | schema validation (schema.ts) | mitigate | `entries.min(1000)` treats a truncated payload as a rejected payload; `version: z.literal(1)` rejects a shape drift; both keep last-good. |
| T-19-05 | Elevation / brick-badges | keep-last-good store (electronStore.ts) | mitigate | `invalidateCheck: () => false` guarantees a validated index is never auto-evicted; a bad publish can only be *ignored*, never *destroy* the working index. An absent bundled snapshot degrades to no-badge cold-start, never a crash. |
| T-19-SC | Tampering (supply chain) | npm installs | accept | No package-manager install in this plan — `zod`, `axios`, and `node:zlib` are all already project dependencies/builtins. No new supply-chain surface introduced; RESEARCH.md Package Legitimacy Gate not triggered. |
</threat_model>
