<objective>
Add a CrossOver compatibility medal badge to every macOS library grid tile: a small colored
dot whose tier is derived IN THE UI from the rating number (5→gold, 4→silver, 3→bronze,
≤2→red/knownnottowork — D-12/D-15), with the full descriptive sentence carried in an
`aria-label`. A neutral grey "unknown" dot appears ONLY on games actually looked up and absent
from the index (rating === null — D-16). When a game was not looked up at all (its app_name is
absent from the `crossoverRatings` map), NO badge element is rendered — "unknown" must always
mean "we searched the index and it isn't there," never "we didn't look."

The badge reads the three-state `crossoverRatings` slice (built by 19-06) synchronously. It
NEVER triggers a scrape or an IPC round-trip to paint itself.

Purpose: Delivers the phase's headline user-visible feature — a scannable library-wide
CrossOver signal — while keeping the badge honest under either D-02 measurement outcome (if the
gate failed and v1 shipped Steam-only, non-Steam tiles simply carry no mark).
Output: A tested `CrossoverBadge` component wired into `GameCard`, plus its CSS and i18n keys.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| index data → grid badge | The `crossoverRatings` slice originates from the fetched/validated CrossOver index (schema-validated in 19-03, resolved to a three-state map in 19-06). The badge is the user-facing surface that turns that data into a compatibility claim. |
| rating value → displayed text | The aria-label sentence is a user-visible assertion ("Known not to work…"). Its wording must come from validated, in-range data, not from raw index strings. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-07-01 | Spoofing (misleading signal) | CrossoverBadge render states | mitigate | Honesty invariant enforced in code + test: `rating === undefined` returns `null` (no element). "Unknown" (`--unknown` dot) renders ONLY for `rating === null` (looked up, absent). An un-looked-up game can never display an "unknown" — or any — mark. Covered by the undefined/null test cases in Task 1. |
| T-19-07-02 | Tampering | aria-label / title text | mitigate | Displayed sentences are derived from the validated rating NUMBER via a fixed tier→copy map and `t(key, default)`; no raw untrusted index string is ever rendered into the label. The index payload itself is bounded upstream (zod `rating.int().min(1).max(5)`, D-09/19-03), so an out-of-range value cannot reach a tier. |
| T-19-07-03 | Information disclosure | badge on non-Steam / non-Mac tiles | accept | If D-02's gate failed and v1 shipped Steam-only, non-Steam app_names are simply absent from the map → no element (T-19-07-01 covers this). No sensitive data is exposed by the badge; it renders only a public compatibility tier. |
| T-19-07-SC | Tampering | pnpm installs | mitigate | This plan adds NO new dependencies (reuses FontAwesome/SCSS + existing react-i18next + zustand). No install task; package-legitimacy checkpoint not applicable. |
</threat_model>
