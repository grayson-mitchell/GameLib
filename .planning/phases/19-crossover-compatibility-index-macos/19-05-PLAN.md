<objective>
On macOS, make `getInfoFromCodeweavers()` **index-first**: `getCodeweaversFromIndex(gameInfo)`
consults the CI-built CrossOver index FIRST and returns a `CodeweaversInfo` on a hit, so the
library grid (19-06) and the game-details panel read one and the same source and can never
disagree (D-11). The medal label (5→gold, 4→silver, 3→bronze, ≤2→knownnottowork) is derived
from the raw rating number **in the UI** (19-07/19-08) — this plan changes **no** `CodeweaversInfo`
type (D-12). The index-first path is gated strictly on `isMac`; on Linux `getInfoFromCodeweavers()`
runs exactly as it does today and the never-rendered Linux fetch is NOT removed (D-10/D-14). An
index miss falls through to the retained Phase-16 lazy scrape on a details-page visit, and a
cached Phase-16 "checked, none found" miss self-heals once the index covers that title (D-13);
the grid must never fire bulk scrapes. Finally, apply the D-20 `slugify()` correction: KEEP the
apostrophe drop (load-bearing), DELETE the roman→arabic conversion (wrong — the site serves the
roman form). The matching key stays in 19-02's `normalize.ts`, distinct from `slugify()`.

Purpose: deliver the single-source-of-truth lookup that every consumer badge in this phase
reads, without regressing Phase 16's Linux ratings or its cacheable-miss behavior.
Output: `crossover_index/index.ts` + its lookup test, the gated wiring in `wiki_game_info.ts`,
and the D-20 `slugify()` fix (+ updated slugify tests).
</objective>
