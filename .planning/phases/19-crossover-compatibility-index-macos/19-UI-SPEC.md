# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope covered by this contract:** the D-15 grid medal badge (`GameCard`), the D-16 "unknown" mark, the D-17 CrossOver-rating library filter, and the D-18 non-blocking install-modal warning. These are the only UI-facing decisions in 19-CONTEXT.md/19-RESEARCH.md — the CI builder, index delivery/fetch/cache layer, and the measurement harness (D-01..D-14, D-19, D-20) are backend/CI-only and out of scope for this document.

## Spacing Scale

This project's real spacing scale is **not** the generic 4px multiples template — it is em-based, defined in `src/frontend/styles/_spacing.scss`. Phase 19 MUST use these existing `var()` tokens exclusively; no new hard-coded px/em values (cross-cutting constraint already established in Phase 1: "All CSS uses semantic tokens from `_colors.scss` / `_spacing.scss` — no hard-coded hex or px").

| Token | Value (em) | ≈px @16px root | Usage in this phase |
|-------|-----------|-----------------|----------------------|
| `--space-3xs` | 0.25em | 4px | Badge glyph internal padding (mirrors `.gameCardDelistedBadge` `padding: var(--space-3xs) var(--space-2xs)`) |
| `--space-2xs` | 0.375em | 6px | Badge padding (paired with 3xs, same pattern) |
| `--space-xs` | 0.5em | 8px | Gap between filter checkbox and its label (existing `ToggleSwitch` spacing — unchanged) |
| `--space-sm` | 0.75em | 12px | Install-modal warning (`infoBox`) vertical padding — `infoBox` already uses `padding: var(--space-sm) var(--space-lg)` |
| `--space-md` | 1em | 16px | Gap between the new "CrossOver rating" filter section and its neighboring `<hr>` dividers in the Filters dropdown (matches existing section spacing) |
| `--space-lg` | 1.5em | 24px | Install-modal warning horizontal padding (same `infoBox` rule as above) |

Exceptions: **none new.** The grid badge's exact pixel footprint (diameter, offsets) is specified in absolute px in Component Notes below because it follows the sibling `macArchBadge`/`gameCardDelistedBadge` precedent, which are themselves specified in absolute px (`top: 5px`, `right: 0.5rem`, `min-width: 1.75rem`) rather than the em spacing scale — this is the established convention for small corner-overlay badges in this codebase, not a new exception introduced here.

## Color

**Deviation from the generic 60/30/10 web-app framework, stated explicitly:** GameLib is a dark, data-dense library grid, not a light marketing-style surface, and this codebase already has an established precedent (Phase 7, `appleRating.ts` `ratingTier()`) of mapping a *multi-tier compatibility rating* onto the existing `--status-*` semantic scale rather than a single "10% accent" color. Phase 19's medal badge follows that exact precedent rather than inventing a gold/silver/bronze hex palette, which `_colors.scss`'s own header comment ("Do not add new colors here") forbids.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--body-background)` | Library grid canvas, InstallModal surface background — unchanged |
| Secondary (30%) | `var(--neutral-02)` / `var(--neutral-03)` + the existing `--gradient-gamecard` overlay | `GameCard` chrome, title-bar gradient, `infoBox` background (`var(--input-background)`) |
| Accent (10%) | The existing 5-token `--status-*` scale, reused as a **medal-tier palette** (see mapping below) — **not** a new hex value | Reserved exclusively for the CrossOver medal badge (D-15) and the D-18 warning icon. Never used for any new button, link, or the filter's "only" chrome (that keeps using the existing generic `--accent` token, unchanged). |
| Destructive | `var(--status-danger)` (`#f97881`) | The `knownnottowork` medal tier (rating ≤2) AND the D-18 install-modal warning icon/left-accent — same token, same semantic ("this is unlikely to run"). This phase has no destructive *action* (no delete/uninstall), only this destructive-adjacent *warning* semantic. |

**Medal-tier → status-token mapping (D-12, this phase's discretion, resolved here):**

| CodeWeavers rating | Medal label (D-12 derivation) | Status token | Hex (for reference — always reference the var, never the hex) |
|---|---|---|---|
| 5 | Gold | `var(--status-success)` | `#0ce396` |
| 4 | Silver | `var(--status-info)` | `#2ceac7` |
| 3 | Bronze | `var(--status-warning)` | `#f8ae79` |
| ≤2 | knownnottowork | `var(--status-danger)` | `#f97881` |
| looked up, no index entry (D-16 "unknown") | — | `var(--status-default)` | `#d2d2d2` |
| not looked up at all | — | *(no element rendered — D-16 hard requirement)* | — |

Accent reserved for: **the CrossOver medal glyph and its `title`/`aria-label` text only** (grid badge + install-modal warning icon). Explicitly NOT reserved for: any new button variant (this phase adds none), the filter dropdown's existing `.toggleWithOnly .only` active-state chrome (unchanged, keeps using `--accent`), or any hover/focus state outside the badge itself.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **N/A — this phase adds no new primary action button.** All three UI surfaces (badge, filter, warning) are passive/informational. The nearest existing interactive element, the CrossOver extra-info row's "Click to open" CodeWeavers link (Phase 16, `AppleWikiInfo.tsx:111`), is unchanged by this phase. |
| Empty state heading | N/A — no dedicated empty-state screen. The closest analog is D-16's "not looked up" case, whose contract is *absence of an element*, not copy (see next row). |
| Empty state body | **"No visual element rendered."** D-16 is explicit: "unknown" must mean *"we searched the index and it isn't there,"* never *"we didn't look."* A game never looked up (index miss on a non-Steam title before/unless D-02's gate passes) gets **no badge at all** on the grid — not a grey placeholder, not an empty circle. This is a hard requirement, not a style choice. |
| Error state | Three distinct "miss" paths exist in this phase — do not conflate them: (1) **Index-fetch/validation failure (D-09, backend-only):** no user-facing copy at all. This is by design — D-09's entire point is invisibility of a bad publish; the app silently keeps the last-good index. Do **not** add a toast/banner for this. (2) **Grid badge, looked-up-but-absent (D-16 "unknown"):** aria-label `"CrossOver compatibility unknown"`, rendered with `var(--status-default)`. (3) **Extra-info panel genuine miss (Phase 16, unchanged):** existing `t('info.unrated', 'Unrated')` text stands as-is. |
| Destructive confirmation | **None.** This phase introduces no destructive or irreversible action. The D-18 install-modal warning is advisory-only and MUST NOT gate, delay, or require an extra confirmation click before Install proceeds — "warns but does not block" (19-CONTEXT.md D-18) is a hard behavioral requirement, not a suggestion. |

### Grid medal badge — `title` / `aria-label` text (D-15)

The visible glyph carries no dense text (see Component Notes); the full sentence lives in `title` + `aria-label`, exactly mirroring the `MacArchBadge` precedent (`GamePage/components/MacArchBadge.tsx:32-38`, visible glyph = `"32"`, full sentence in `title`/`aria-label`).

| Tier | `title` / `aria-label` copy |
|------|------------------------------|
| Gold (5) | `"Runs great on CrossOver (gold rating)"` |
| Silver (4) | `"Runs well on CrossOver (silver rating)"` |
| Bronze (3) | `"Runs with issues on CrossOver (bronze rating)"` |
| knownnottowork (≤2) | `"Known not to work on CrossOver"` |
| Unknown (looked up, no match — D-16) | `"CrossOver compatibility unknown"` |

Suggested i18n keys (new namespace entries under `library` in `translation.json`, mirroring the existing `library.delisted` key at `translation.json:678`): `library.crossover_gold`, `library.crossover_silver`, `library.crossover_bronze`, `library.crossover_wont_run`, `library.crossover_unknown`.

### CrossOver-rating filter (D-17)

New section in the existing `LibraryFilters` dropdown (`src/frontend/components/UI/LibraryFilters/index.tsx`), gated macOS-only exactly like the existing `platform === 'darwin' && platformToggle('mac')` line (`index.tsx:216`) — this filter is meaningless on Windows/Linux since the index only carries Mac medals (same `isMac` gate as D-10).

| Element | Copy |
|---------|------|
| Section label (suggested i18n key `header.show_crossover_rating`, mirrors `header.show_hidden`/`header.show_available_games`) | `"CrossOver rating"` |
| Toggle — Gold | `"Runs great (gold)"` |
| Toggle — Silver | `"Runs well (silver)"` |
| Toggle — Bronze | `"Runs with issues (bronze)"` |
| Toggle — Won't run | `"Known not to work"` |
| Toggle — Unrated | `"Unrated / not yet checked"` |

**Interaction pattern (this phase's discretion, resolved here):** follow the existing multi-checkbox object shape used for `platformsFilters` (`{ win, linux, mac, browser }`, all default `true`, each rendered via `ToggleSwitch` — `LibraryFilters/index.tsx:90-100`), **not** the tri-state off/show/only pattern used for `showHidden`/`showNonAvailable`. A rating filter is inherently multi-select (a user may want "gold OR silver," not a single binary), so the `platformsFilters`-shaped `{ gold, silver, bronze, wontRun, unrated }` object (default all `true` — filter is opt-out, matching every other multi-select filter in this dropdown) is the correct analog, not the tri-state chain. No "only" affordance is required per option (D-17 says "filter only — no sort," not "every option needs its own only-button"); if the planner wants one for parity with `platformToggle`, it MUST reuse the existing generic `toggleWithOnly()` helper — do not invent a second only-button implementation.

### Install-modal warning (D-18)

Non-blocking, advisory-only. Reuse the plain `.infoBox` div pattern already used inline in `WineSelector/index.tsx:157` (NOT the popover `InfoBox` component from `components/UI/InfoBox` — that component is for optional help text behind a click, and this warning must be visible without a click, per D-18's "show a clear warning").

| Element | Copy |
|---------|------|
| Warning body (suggested i18n key `install.warn-crossover-wont-run`, mirrors `setting.warn-use-shared-wine-config`) | `"This game is known not to run well under CrossOver on macOS. Compatibility data is community-sourced and may be wrong for your setup — you can still install it and try for yourself."` |

Visual treatment: `<div className="infoBox">` (existing class, `padding: var(--space-sm) var(--space-lg)`, `background: var(--input-background)`) containing a `FontAwesomeIcon` (`faTriangleExclamation`, already imported in this exact file for the shared-prefix warning) colored `var(--status-danger)` — same token as the `knownnottowork` medal tier, reinforcing the same semantic. Gated on: `is.mac && gameInfo.runner === 'steam' && crossoverRating <= 2` (only for confirmed `knownnottowork` titles, never for `unknown`/not-looked-up games — an absent rating is not evidence of a problem).

## Component Notes (supporting detail for Visuals dimension)

**Grid medal badge placement (D-15, this phase's discretion, resolved here):**

The `GameCard` tile already reserves three corners/bands: `store-icon` (top-right, `right: 0.5rem; top: 0.5rem`), `gameCardStatus`/`gameCardDelistedBadge` (top-left, `top: 5px; left: 5px`), and `gameCardUpdateBadge` (full-width banner, `top: 5px` or `35px` if status is present). The medal badge MUST NOT collide with any of these. Recommended placement: **bottom-right corner, overlaid on the title bar** (`gameTitle` sits at `position: absolute; bottom: 0; width: 100%`), a small **10px solid circular dot** (not an icon — a plain color-filled circle reads fastest at grid-tile scale, and D-15's stated goal is scannability across a whole grid, not detail) using the tier's `--status-*` token as `background-color`, with a `1px solid var(--neutral-01)` outline for contrast against light cover art, `pointer-events: none` (matches every sibling badge), `z-index` above the title bar but below any modal. `title` + `aria-label` carry the full sentence from the Copywriting Contract above. The "unknown" tier renders the same dot shape/size in `var(--status-default)` — same visual language, muted color, so it reads as "checked, nothing found" rather than a different UI element.

**Filter section:** place the new "CrossOver rating" block after the existing `platformToggle('mac')` line and its macOS gate check, before the `<hr />` that currently separates platform toggles from the `showHidden`/`showNonAvailable` block (`LibraryFilters/index.tsx:216-218`) — keeps all macOS-conditional filters adjacent.

**Install-modal warning position:** inline within the Steam-bottle install path of `InstallModal`/`WineSelector` (the same region as the existing shared-prefix warning), appearing only when GameLib is about to route the install through the Phase 17/18 CrossOver bottle flow — never on the native-Mac or Windows/Linux install paths, since the warning is specifically about CrossOver emulation quality.
