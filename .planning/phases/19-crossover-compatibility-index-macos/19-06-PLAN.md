<objective>
Ship the bulk CrossOver-rating pipeline that lets the library grid paint a medal for every macOS game with zero per-card work. The backend resolves each library title → rating once, into a THREE-STATE map (`Record<string, number | null>` keyed by `app_name`: number = matched-with-rating, `null` = looked-up-but-absent, key-absent = never looked up), and ships it to the renderer over a `getCrossoverIndex` pull handler plus a `crossoverIndexChanged` push channel, landing in a `crossoverRatings` zustand slice. This copies the proven `getAllGameOverrides` / `metadataChanged` triple (pull handler + push channel + slice) VERBATIM in shape.

Purpose: The grid must read ratings SYNCHRONOUSLY from zustand and be structurally incapable of triggering a scrape to paint itself (D-11/D-13) — a 200-game library painting itself must not become 200 CodeWeavers round-trips. The three-state distinction is precisely what lets the badge (19-07) honor D-16: "unknown" appears only on games actually looked up, never on games that were never checked. Whether a game was "looked up" is decided by an EXPLICIT eligibility predicate, not inferred from a lookup return value — otherwise a failed D-02 gate would paint grey "unknown" on non-Steam tiles that were never checked.

Output: IPC contract additions, a backend resolver + pull/push registration, the preload bindings, and the frontend slice + push listener.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-06-01 | Tampering | `getCrossoverIndex` IPC input | mitigate | The pull handler accepts NO parameters — there is no renderer-supplied string/appName to inject. `buildCrossoverRatingMap` reads only backend-owned state (`libraryManagerMap`, `isCrossoverIndexEligible`, the validated index from 19-03/19-05); nothing from the caller reaches a filesystem/network path. |
| T-19-06-02 | Tampering | rating values in the map | mitigate | Rating numbers originate solely from the zod-validated index (`rating: int 1..5`, schema from 19-03) or `null` — never from renderer input. The renderer treats `crossoverRatings` as display-only data: no component writes back to the slice and reading it triggers no side effect, so a poisoned map can at worst mis-color a badge, never drive a scrape or an install. |
| T-19-06-03 | Denial of Service | grid render path | mitigate | The map is resolved once in the backend and read synchronously from zustand; painting a card fires zero IPC and zero CodeWeavers round-trips (D-11/D-13), so a large library cannot fan out into per-card network calls. |
| T-19-06-04 | Information Disclosure | resolved map contents | accept | The map is `app_name → rating|null` for the local user's own library, sent only to the app's own renderer over the existing contextIsolated preload bridge — no new external surface, no PII beyond what the library already exposes. |
| T-19-06-SC | Tampering | npm/pip/cargo installs | mitigate | This plan adds NO new package-manager installs (uses in-tree `jest`, existing IPC/zustand plumbing). No `[ASSUMED]`/`[SUS]` package checkpoint required. |
