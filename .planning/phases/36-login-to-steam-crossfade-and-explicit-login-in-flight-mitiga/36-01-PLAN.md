<objective>
Retire `loginweb/steam` as a route and make the Steam sign-in a co-mounted overlay on `/login`,
exactly mirroring the `showSidLogin`/`SIDLogin` shape that already exists in `Login/index.tsx`.

Purpose: the navigation is what unmounts the Login screen. Removing it is the precondition for BOTH
halves of this phase — the crossfade (there is nothing to cross with if one surface is gone) and the
explicit in-flight guard (there are no tiles to guard if they unmounted).

Output: `SteamLogin` dismisses through a callback prop instead of `navigate('/login')`;
`Login/index.tsx` owns the overlay's mount/dismiss lifecycle; the `loginweb/steam` route is deleted.

⚠ INTENTIONAL INTRA-PHASE INTERMEDIATE STATE — READ BEFORE EXECUTING.
At the end of THIS plan the five other login tiles ARE reachable while the Steam flow is open,
because the unmount that incidentally hid them is gone and the explicit guard does not land until
plan 36-02 (wave 2). ROADMAP.md calls the security work "not separable" from the animation; that
constraint is honoured at the PHASE level — both land in phase 36 — and is split across plans only
for context budget. This phase MUST NOT be considered shippable, and MUST NOT be closed, with 36-02
unexecuted. Do not raise this as a defect; do not attempt to close it here.
</objective>

Write `openSteamOverlay()`: clear any pending unmount timer, increment `steamMountKey`, then set both
`steamOverlayMounted` and `steamFlowOpen` true. The key bump is what guarantees a reopen during the
500ms teardown window remounts `SteamLogin` at its first step instead of resurrecting the previous
open's `Step` state — `Dialog` mounts with `open` initialised to `true`, so a remount is the only way
to reopen it.
