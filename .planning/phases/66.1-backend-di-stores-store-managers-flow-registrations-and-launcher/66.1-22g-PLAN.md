System Information move: analysis (checker warning 5, measured 2026-11-10).
- No added work. Today initLogger (the 'logger' step) already starts the one memoized fetch: `getSystemInfo()` runs
  fetchSystemInfo once per process (in-flight + value cache), and that fetch spawns the three runner probes once, after
  its memory/GPU/OS awaits, via the lazy `import('backend/storeManagers')`. After the move the same single fetch starts at
  the end of 'download-queue' instead; settings/clipboard callers still share the cache. Moving the line changes when the
  probes start, not how many run. (getCometVersion's `spawnSync` is pre-existing and unchanged; it already ran inside
  this fetch.)
- Timeouts: the three runner-CLI probes (`legendary --version`, `gogdl --version`, `nile --version`) go through
  `runRunnerCommand` -> the 66.1-05 commandRunner, which runs callRunner with `timeout: { none: true, reason }`
  (commandRunner.ts ~536): they are NOT time-bounded, and CallRunnerOptions has no timeout option. This plan does not add
  one (that would change runRunnerCommand semantics for every caller). The exit contract is still met: the process runner
  unrefs every child and its stdio (process/runner.ts unrefChild, ~104), so a hung probe cannot keep the event loop alive,
  and the probes are tracked (`track: { runner, key: abortId }`), so the quit handler's runner-registry kill reaps them.
  A pending Promise holds no handle. Record this in the SUMMARY; a hung probe leaves only the log line (and the
  memoized in-flight fetch) pending, exactly as today.
- 'download-queue' with `prebuilt.downloadQueue`: the step still assigns the prebuilt queue and then calls
  `logSystemInformation(...)` as a fire-and-forget `void` statement; nothing is awaited, so the step ends as before. The
  managers are reached through a getter only inside fetchSystemInfo (after its awaits), so createTestServices' throwing
  default managers make the fetch reject later, which the default `.catch` turns into 'unavailable': no throw at step time,
  no unhandled rejection.

`bottleConfigStore()` falls back to `require('./stores').steamBottleConfigStore` when unbound. bootstrap.ts binds it in
