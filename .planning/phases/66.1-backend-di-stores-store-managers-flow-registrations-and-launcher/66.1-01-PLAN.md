`ChildProcess` would force throwaway edits in `knownFixesRegistry.ts` and `sharedRedistInstall.ts`
(`unrefWineChild` needs `unref`). Plan 05's command runner declares its own handle-typed options; each consumer
adopts them when it moves to the command-runner slice; plan 24 retypes `common/types.ts` when the legacy
launcher functions are deleted.

Decisions recorded here (Claude's discretion, user chose not to be asked):
- **A1:** the opt-out is `RunOptions.timeout: { none: true; reason: string }`, mirroring
  `TimerOptions.keepAlive` and `RunSyncOptions.reason`. `spawnLongLived` is not used for
  `callRunner`/`spawnAsync` because it registers teardown by id (concurrent same-key calls would
  replace each other) and returns no captured output. D-10's default stays: omitting both fields
  still means `DEFAULT_RUN_TIMEOUT_MS`.
- **A6:** CI is ubuntu-only (`.github/workflows/test.yml:21` `runs-on: ubuntu-latest`), so the win32
  `taskkill` success path cannot be CI-verified. The failure path is tested on every host
  (taskkill is absent on macOS/Linux); the success path is a one-line `code === 0` check, reviewed.
- **WR-02:** the review's splice cannot occur (`outBytes` is incremented even for a dropped chunk).
  Do not invent a different truncation rule; pin today's behaviour and make it explicit.
