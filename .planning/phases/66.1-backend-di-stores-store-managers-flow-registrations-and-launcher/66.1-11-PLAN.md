<objective>
Make the download queue a boot-built service (removing the only indirect import-time store read and the import-time
connectivity subscription found by research) and convert the launch/download-adjacent helpers that reach the managers:
`gamedetails/dispatch`, `protocol`, `save_sync`, `launchSingleFlight`.

Purpose: MH-1 hazard (`downloadqueue.ts:56` reads the store at import) and MH-2 consumers. Ceilings: `downloadmanager`
(moduleState 3 -> 1 for downloadqueue.ts; jestMock for removed mocks), `_root` (protocol/launchSingleFlight entries only if
their counts change), `gamedetails` (jestMock).
Rules: README "Converting a consumer (66.1 rules)" R1-R8.

Boot-order contract (checker blocker 1): the queue needs the managers, so 'download-queue' runs AFTER 'store-managers'.
Anything a manager holds must therefore reach the queue at CALL time, never capture it at construction. This plan
adds `getDownloadQueue: () => DownloadQueue` to `ManagerDeps` (an accessor, not a `downloadQueue` value). Until plan 23
the managers are still built at import by `legacyManagerDeps()`, which cannot see boot state, so the 'download-queue'
step binds the built queue into a transitional holder in downloadqueue.ts (`let legacyBootQueue`, set by
`bindLegacyBootQueue(q)`, read by `getLegacyBootQueue()` which throws `Error('download queue not bound: the
download-queue boot step has not run')` when unset). This is the one `let` left in downloadqueue.ts (ceiling 3 -> 1);
plan 23 deletes the holder, both functions and the ceiling key, and switches the accessor to
`() => requireServices(state).downloadQueue`.
</objective>
