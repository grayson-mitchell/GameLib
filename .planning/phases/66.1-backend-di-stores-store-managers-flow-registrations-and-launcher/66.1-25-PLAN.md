<objective>
The stores contract (A3): every stores module becomes a factory, the store registry becomes per-boot, and the last
facade disappears. All consumers already read stores through slices (plans 04-22), so this plan touches only the store
modules, the registry, the boot step, the two RPC store handlers and tests.

Purpose: MH-1 ("a stores factory replaces the 16 */stores.ts modules and key_value_stores.ts; nothing constructed at
import"). The registry, the 16 modules and the facade must change in one plan: once the registry is per-boot, a store
constructed at import has no registry to join, so a half-converted state would make some stores invisible to the
snapshot/write RPCs.
Ceilings: moduleState -49 across the 17 shards in files_modified (RESEARCH Ceilings map row 15).
Context risk (checker warning 3, accepted): this is the phase's largest plan and its biggest context risk. It stays
atomic for the reason above (a per-boot registry with any store still built at import leaves that store invisible to the
snapshot/write RPCs), so splitting it would leave a broken intermediate commit on main.

Decision (RESEARCH Open Question 2): the static stores outside the 16 (`engine/engineNoticeStore.ts`,
`utils/systeminfo/gpu/pci_ids.ts` x2) are 66.3's. If and only if the pre-change fixture shows they are registered
(RPC-visible) today, add them to createStores in this plan (their modules export factories, their consumers get a slice,
call-site-only edits); otherwise construct them with no registry, which the registry API documents as "not RPC-visible",
matching today. Record which case applied.
</objective>
