<objective>
The contract step for managers and the launcher (A3): construct the five managers and the launcher at boot with real
deps, delete `libraryManagerMap`/`storeLaunchHooks` and the module-level launcher functions, and delete the manager and
launcher facades.

Purpose: D-02 "nothing is constructed at import" and MH-2/MH-4. Every consumer is on a slice (plans 07-22) and the
cleanup plans 22b-22i removed every call-time shim that did not need boot construction (runnerAuth/eosOverlay builders,
storeManagers entry imports, presence/discounts GOG deps, dead utils handleExit, legacySpawnAsync, legacyTools,
the systeminfo lazy import, the bindBottleStores fallback, the call-time stores requires in 22h/22i), so this plan touches owners, the boot step, owner tests,
launcher.ts's own three stand-ins, and one item the checker moved here: `utils.getGame`/`errorHandler` (live, not
dead: launcher.ts:1074 and errorHandler's deleted-folder branch call getGame; errorHandler reaches commandRunner through
the 'command-runner' step), whose library slice is injected here and getGame deleted, so utils.ts stops importing
storeManagers.
Task order: Task 1 builds the factories and injects errorHandler's library slice; Task 2 wires boot and runs the full
gates. Managers and launcher reference each other, so both flip together
(managers need `launcher`; launcher needs the managers map): the late-bound map resolves the cycle at call time.
Two more call-time rules hold in this plan. (1) The download queue is built by the later 'download-queue' step, so
managers get `getDownloadQueue: () => requireServices(state).downloadQueue`, never `state.services.downloadQueue`
(which is undefined at that point and would crash `autoUpdate`). (2) Managers' spawns move to the runner registry here,
so the legendary/nile/sideload stop paths move to `deps.runner.killTracked` in the same commit series (moved forward
from plan 26), otherwise stopping a game between this plan and plan 26 would kill nothing.
The legacy `callRunner`/`runWineCommand`/`runScriptForGame`/`getWinePath` and the gamescope `spawnSync` stay in
launcher.ts until plan 24 (which deletes them with their legacy suites); if knip flags them as unused here, mark them
`@public` with "deleted by plan 24" rather than adding baseline entries.
Ceilings: `__tests__` and `storeManagers.__tests__` jestMock (storeLaunchHooks.test has 12, launcher.engineStep 9,
launchSingleFlight 7, wineLibFolders 2) and `_root` moduleState: `launcher.ts` drops 3 -> 2 when `powerDisplayId` moves into the createLauncher closure; lower it in the same commit (plan 24 removes the other two with the legacy command functions).
