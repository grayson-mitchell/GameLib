## Sidecar exit-contract analysis (System Information move)
- No added work: the single memoized getSystemInfo fetch (in-flight + value cache) starts at the end of 'download-queue' instead of in init(); the three runner probes still run once.
- The runner `--version` probes are unbounded in time (commandRunner passes no timeout) but the process runner unrefs every child and stdio and tracks them for the quit kill, so a hung probe cannot hold the event loop; only the log line stays pending.
- Fire-and-forget; managers resolved via a getter inside the fetch. Default `.catch -> 'unavailable'`, and the call is wrapped in `Promise.resolve().then(...)` so a synchronous throw (or a jest.fn mock returning undefined) is also contained.
- New test: bootstrap.test.ts boots with throwing default managers and asserts no throw and no unhandledRejection. smoke:sidecar PASS on the rebuilt bundle.
