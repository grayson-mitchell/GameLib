<objective>
Build the versioning engine and wire it into `GameLibStore`, the one class every production store
passes through (RESEARCH Finding 1: `FileStore` is dead in production; do not touch
`src/backend/sidecar/fileStore.ts`).

Resolves Claude's Discretion items: migrations run inside `GameLibStore`'s constructor, before
`super()` touches the file (not in `FileStore`, not in today's floated `MigrationSystem` hook); the
version lives inside each file at `__internal__.gamelib.schemaVersion` (atomic with the data, and an
older build can see the file is newer, which D-03 needs); shared-path stores share one path-keyed
state. The Heroic named-migration runner (`src/backend/migration/`, `MigrationSystem`,
`LegendaryGlobalConfigFolderMigration`, `migrationsStore`) is KEPT UNCHANGED for one-off cross-file
moves beside the per-store versioned migrations, which is how this phase builds on it per the
roadmap; the engine reuses its sequential-order and graceful-failure model but never reads or writes
`migrationsStore` (itself a versioned store, so that would be circular). Do not fold the runner in.

Output: the pure migration registry, the engine and its aggregate list, the `GameLibStore` wiring
(including D-13 file modes), and engine + store-level tests.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-68-05 | Denial of service | `prepareStoreFile` at module scope | mitigate | Whole body in try/catch, never rethrows; corrupt or odd-typed files fall through to conf's existing behaviour (Test 7) |
| T-68-06 | Tampering | newer file overwritten by older build | mitigate | Path-keyed read-only state registered before `super()`; setter refuses every write, including conf's constructor merge (Tests 1-2) |
| T-68-07 | Information disclosure | token files at 0o666 (`steam_store`, `humble_store`) | mitigate | `configFileMode: 0o600` on every store; new dirs 0o700; existing token files/dirs tightened on load (D-13, Test 7) |
| T-68-08 | Tampering | RPC-supplied cache name path traversal | mitigate | `translateStoreOptions` containment throw kept ahead of any engine work; dynamic constructions without a declaration never run migrations |
| T-68-09 | Information disclosure | migration failure logs | mitigate | Logs carry store key, versions, `err.message` only (T-28-04) |
| T-68-10 | Tampering | prototype pollution from migrated JSON | mitigate | Migrations operate on `structuredClone` output; result validated as a plain object before the rewrite |
