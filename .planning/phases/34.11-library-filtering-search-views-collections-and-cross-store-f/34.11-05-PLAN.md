<objective>
Rewire `Library`'s `gamesForAlphabetFilter` pipeline onto plan 01's `filterEngine`, and retire the
literal-platform and user-facing CrossOver-rating filter stages.

Purpose: until this lands, the grid runs the old inline pipeline while the counts (plan 04) run
the engine — two implementations, guaranteed to drift. This is the single change that makes the
counts trustworthy. It is also where D-09/D-10's platform→runnability substitution actually takes
effect: `filterByPlatform` (`index.tsx:359-408`) and the macOS `crossoverRatingFilters` block
(`index.tsx:656-676`) both stop running here.

Output: a `useMemo` whose body is store union → search-key precompute → `filterLibrary`, plus a
source gate that stops a second implementation reappearing.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user search text → `Fuse.search()` | A user-controlled string reaches a search library configured with `useExtendedSearch: true`, which gives some characters query-operator meaning. |
| in-memory `GameInfo[]` → grid | All data is the signed-in user's own already-loaded library; no new network or IPC surface is added by this plan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.11-14 | Tampering | `fuse.search(filterText)` with `useExtendedSearch: true` | accept | Extended-search operators let a user alter their own query semantics over their own in-memory library. There is no injection target: the term never reaches a shell, SQL, `eval`, `dangerouslySetInnerHTML` or an IPC call, and the worst outcome is an unexpected result set in the user's own grid. Behaviour is unchanged from what ships today; this plan relocates the call, it does not widen it. |
| T-34.11-15 | Denial of Service | Fuse index rebuilt over the full library on every memo run | mitigate | The index is built inside `gamesForAlphabetFilter`'s existing `useMemo` with a dependency array that includes the store libraries and `filterText`, so it rebuilds only when its inputs change — the same cadence as today. The existing `try/catch` is retained so a Fuse construction failure degrades to "no search constraint" rather than blanking the grid. |
| T-34.11-16 | Repudiation | counts vs. grid divergence | mitigate | Both read the same memoized `FilterEngineState`/`FilterEngineDeps` objects and both go through `filterLibrary`. Task 3's gate asserts exactly one `filterLibrary(` call site, so a duplicated pipeline fails CI rather than shipping counts that quietly disagree with what the user sees. |
| T-34.11-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed; `fuse.js` is already a direct dependency and already imported by this file. If an install appears necessary, STOP — out of scope, blocking human legitimacy checkpoint required. |
</threat_model>
