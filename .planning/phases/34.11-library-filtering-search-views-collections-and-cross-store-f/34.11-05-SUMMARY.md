# Phase 34.11 Plan 05: Rewire the Grid onto filterEngine Summary

**`Library`'s grid now runs `store union -> Fuse search-key precompute -> filterEngine.filterLibrary` against the same memoized `engineState`/`engineDeps` objects the facet counts read, retiring `filterByPlatform` and the macOS CrossOver-rating branch as the two literal-filter stages D-09/D-10 replace with the runnability facet — the change that makes plan 04's counts trustworthy for the first time.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 3 completed
- **Files modified:** 2 (1 created, 1 modified)

## Accomplishments
- `makeLibrary()` is now a pure connected-account union with zero filter logic: it includes each store's library when that store's account is connected (`epic.username`, `gog.username`, `amazon.user_id`, `zoom.enabled && zoom.username`, `steam?.username`) plus `sideloadedLibrary` unconditionally, and no longer applies (or falls back on an empty) `storesFilters` mask.
- `gamesForAlphabetFilter` is the grid's ONLY pipeline: `makeLibrary()` → build the Fuse search index over the full union library → `filterEngine.filterLibrary(library, { ...engineState, searchMatchedKeys }, engineDeps)`. `engineState`/`engineDeps` are the exact objects `countForStore`/`countForRunnability`/`activeFilterDescriptors` already consumed (plan 04) — moved earlier in the component so the grid can read them too, rather than re-assembled a second time.
- `filterByPlatform` (the literal platform facet, D-09) and the macOS `crossoverRatingFilters` filtering branch (the CrossOver-rating gate, D-10) are deleted outright — both are now `filterEngine.passesRunnability`/`deriveRunnabilityTier`. `CrossoverBadge` on the game card is untouched (`git diff --stat` on that directory is empty).
- Fuse.js is unchanged and relocated verbatim: same `{ minMatchCharLength: 1, threshold: 0.4, useExtendedSearch: true, keys: ['title', 'normalizedTitle'] }` options object, same `try/catch` defensive fallback (now falling back to `searchMatchedKeys = null` — "no constraint" — rather than an empty array). The search index is now built over the FULL union library instead of a platform-filtered subset, which is deliberate: it makes search order-independent, the precondition for `filterLibrary`'s `skip` rule to produce correct sibling counts.
- Also deleted from the memo (all now implemented once in `filterEngine`'s per-stage predicates): the `showFavouritesLibrary` branch, the DLC exclusion (now `filterLibrary`'s unconditional `game.install.is_dlc` check), the inline `currentCustomCategories` collection filter, the `showSupportOfflineOnly`/`showThirdPartyManagedOnly`/`showUpdatesOnly`/`showInstalledOnly` toggles, and the hidden/non-available tri-state block.
- `libraryPipeline.test.ts` is a new source-text gate (the `tier2Portal.test.ts` idiom — `readFileSync` + `stripSourceComments`, no jsdom, no render) asserting: exactly one `filterLibrary(` call site; no `filterByPlatform`; no `crossoverRatingTier` derivation and no `crossoverRatingFilters[` indexing (the STATE declaration itself is untouched — it's read by `LibraryFilters` until plan 09); `makeLibrary`'s own brace-counted region contains no `storesFilters` reference; `Fuse` is still imported from `'fuse.js'`; and the options object still carries `threshold: 0.4` and `useExtendedSearch: true`.

## Decisions Made
- Moved the `engineDeps`/`engineState` `useMemo` assembly from its plan-04 location (after `gamesForAlphabetFilter`, `libraryToShow`, and the tier-2-portal effect) to immediately after `favouritesIds`, i.e. ahead of `makeLibrary`/`gamesForAlphabetFilter` — every value those two memos depend on (`hiddenGames`, `favouritesIds`, `recentAppNames`, `customCategories`, `gameUpdates`, `crossoverRatings`, `platform`, `libraryView`, `currentCollection`, `storeFacet`, `runnabilityFacet`, `showHidden`, `showNonAvailable`, `showSupportOfflineOnly`, `showThirdPartyManagedOnly`, `showUpdatesOnly`) was already declared by that point, so no new state needed to move.
- `gamesForAlphabetFilter`'s dependency array is now `[engineState, engineDeps, filterText, epic.library, gog.library, amazon.library, zoom.library, steam?.library, sideloadedLibrary]` rather than listing each individual facet/toggle by name. This is deliberately equivalent to (not a weakening of) the plan's literal list: `engineState`/`engineDeps` are themselves `useMemo`s whose own dependency arrays already include every one of those fields, so they only change identity when one of them changes — listing the composed objects cannot produce a staler render than listing every leaf field individually, and it is the same "read the one shared source" discipline this plan's own objective describes.
- Removed the `currentCustomCategories` destructure from `Library`'s `ContextProvider` read (Rule 1 — a TypeScript/ESLint blocking error: it became unused once the inline collection filter it fed was deleted). `CategoryFilter` (kept, untouched, retired in plan 09) reads `currentCustomCategories`/`setCurrentCustomCategories` directly via its own `useContext(ContextProvider)` call, so this removal changes no runtime behaviour.
