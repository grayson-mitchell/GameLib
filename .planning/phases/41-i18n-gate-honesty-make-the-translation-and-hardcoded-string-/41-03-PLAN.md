## The ENOENT question is ANSWERED, not open — settle it as stated here

REQ-41-02 says "settle whether that exit 0 is deliberate before changing it". It has been settled
by measurement at HEAD (2026-09-06). Do not re-open it; implement the resolution below.

`readFiles()` (`:70-77`) reads all four namespaces for every locale, and the D-15 scope filter
(`namespaceScope.includes(file)`, `:158`) is applied AFTERWARDS. So the ENOENT traces in the
gamelib-scoped run are raised for namespaces that are **out of scope for that run**. The exit 0 is
defensible; the raw stack traces are not.

## The resolution to implement

1. **Read only what is in scope.** Push the namespace scope INTO `readFiles()` so an out-of-scope
   namespace is never opened. This eliminates the spew at its source rather than swallowing an
   error — a swallowed error is the fail-open shape this requirement exists to close.
2. **Classify an absent in-scope catalog by ownership**, reusing the vocabulary
   `meta/i18nCatalogChurnGuard.ts` already establishes for `public/locales/` (D-05/D-06 split-brain:
   `gamelib` is fork-owned; `translation`/`gamepage`/`login` are upstream Weblate-sourced and this
   fork neither owns nor can fix them):
   - fork-owned + absent → **hard failure**, named, counted, exit code 1
   - upstream-owned + absent → **one clean reported line**, no stack trace, no exit contribution
3. **Exit code is derived from a counted failure set**, never from "did anything throw". A gate
   whose exit code is not a counted quantity is a gate whose result cannot be checked.

This keeps D-15's own rationale intact — "a gate with unactionable noise stops being read" — while
making the fork-owned half honest.
