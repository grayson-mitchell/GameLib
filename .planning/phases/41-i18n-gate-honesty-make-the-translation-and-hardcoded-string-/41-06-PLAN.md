<design_notes>
Read this before writing any code. It is the reasoning the executor needs in order not to

## Why GAP-2's fix is a `finding`, not a `hardFailure`

Plan 41-05 originally wired `comparePresenceBaseline()` **unconditionally**. That broke four
fixture tests (R1/R3/R4/R7): those tests build tiny `mkdtempSync` locale trees with a handful of
keys and pass them as `opts.localesPath`, so they were being diffed against the real 794-pair
committed baseline and produced hundreds of spurious `hardFailures`. The `isCanonicalLocalesPath`
gate was added mid-execution as triage — and **that triage is the fail-open now being closed.**

So: emitting a `hardFailure` on the skip path would break those same fixture tests again and you
would be tempted to add a third gate to silence it. **Do not "improve" the finding into a hard
failure.** A `findings` entry is visible in the gate's stdout and in the counted findings total,
without turning every fixture-based test red.

## The rule this plan encodes

**Any skip path in a gate must emit.** A `continue` with no finding, no hard failure and no log
line is indistinguishable from a pass. That is the entire defect class this phase exists to
eliminate, and `:590-597` is currently an instance of it.

**One deliberate exception:** `!isForkOwned(namespace)`. That is a *scope* decision (D-15: the
three upstream Weblate namespaces have no baseline and never will), not a statement about whether
a check was available. Emitting for it would add three noise lines to every full-namespace run.
Keep that one silent, and leave a comment at the branch saying exactly this so the next reviewer
does not read it as a fourth fail-open.

## The second corrupt-`en` crash site the verification did not name

`41-VERIFICATION.md` cites `:569` only. There is a second one. With a corrupt `en/gamelib.json` at
the **canonical** path and the baseline present, the drift block calls
`comparePresenceBaseline()` → `missingPairs()` → `readCatalog(localesPath, 'en', namespace)` at
`:323`, unguarded, which throws. Fixing `:569` alone leaves the real CLI still crashing on exactly
the scenario GAP-1 describes. Both sites are in scope for Task 1.

## Test-safety constraint

The absent-baseline boundary must be provable **without moving, renaming or deleting the committed
`meta/i18nCatalogPresenceBaseline.json`**. This project has a recorded incident of a test suite
clobbering a real artifact, a concurrent Claude session is live on this working tree, and R13/R14/R15
all read that file's real bytes. That is why Task 2 makes the baseline path injectable: the test
points at a nonexistent scratch path instead of disturbing the real one.
</design_notes>
