## Why the baseline exists, and why it is a SET

REQ-41-01 says the check must REPORT. It cannot simply fail: filling 48 locales requires
`pnpm machine-fill-gamelib`, which needs a working API key, has 401'd before, and is **explicitly
out of this phase's unattended scope**. A check that goes red at HEAD with no in-phase remedy is
the "red at head" failure this project has already recorded.

So: report every miss by name, and pin the known set. This is the repo's own established idiom
(`meta/i18nGateAllowlist.json`'s `expectedCount` + `staleExemptions`, and
`genI18nGateScope.test.ts`'s A-17 ratchet asserting SET equality).

**It must be a SET, never a count.** `genI18nGateScope.test.ts` records this project's own lesson
verbatim: *"A count that does not move is not evidence that the SET did not move."* A baseline of
`794` would be satisfied by 794 entirely different misses.

**Set equality must fail in BOTH directions.** Growth = a new blind spot (the exact failure this
requirement exists to prevent: "the next key added will be exactly as invisible as those 80 were").
Shrinkage = someone filled locales without re-recording the baseline, and a baseline that overstates
reality is a baseline that will eventually stop being read.

## Ordering: this plan runs AFTER 41-01, and that is load-bearing

The check is keyed off `en` being non-empty. Before plan 41-01 authors the six English strings,
that filter excludes the 6 `redeemKey.*` keys and the derivation yields **506** pairs. After 41-01,
it yields **794**. Generating the baseline before 41-01 lands would bake in the wrong number.

Keying off `en` non-empty is also what makes an exemption register unnecessary: **do not add one.**
The alternative the todo mentions — exempting the six keys by name — is a list plan 41-01 deletes.

## Scope fence

`meta/` only. No runtime code path. `public/locales/` is READ, never written. **No network.**
`pnpm machine-fill-gamelib` must not be run and must not be planned around. The expected outcome of
this plan is a baseline that still reads 794 — filling the locales is a follow-up needing a key.

The presence check belongs on the fork-owned half only. The three upstream namespaces are
Weblate-sourced data this fork neither owns nor can fix; running an inverted check across them would
surface a wall of unactionable noise, which is precisely what D-15's namespace split exists to
prevent ("a gate with unactionable noise stops being read"). Document that boundary at the code site
so it is a stated decision rather than a silent hole.
