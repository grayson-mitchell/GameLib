## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in this plan's own Task-2 test authoring] E1-RED's known-bad was initially vacuous**
- **Found during:** Task 2, first `npx jest` run of the new Group E block
- **Issue:** The known-bad prefixed the identifier (`'DELETED_resolveDepotAvailability('`) rather than breaking the token being asserted against. Because `String.prototype.split`/`includes` match substrings anywhere, `'DELETED_resolveDepotAvailability('` still contains the exact substring `'resolveDepotAvailability('`, so `countOccurrences(knownBad, 'resolveDepotAvailability(')` returned `1`, not the expected `0` -- the RED proof did not actually exercise a broken state.
- **Fix:** Changed the replacement to insert the marker text between the identifier and its opening paren (`'resolveDepotAvailabilityDELETED('`), which genuinely removes the exact token from the string.
- **Files modified:** `steamEligibilityWiring.test.ts` (this task's own new code, not yet committed at the time of the fix)
- **Verification:** Re-ran the suite; E1-RED now passes, and the fix was proven necessary by observing the original failure output (`Expected: 0, Received: 1`) before correcting.
- **Committed in:** `2802269ed` (Task 2's own commit -- the defect never reached a committed state)

**2. [Rule 1 - stale plan-referenced pattern] E4's boundary token had to be `']'`, not `'],'`**
- **Found during:** Task 2, initial E4 authoring against the real source
- **Issue:** The dependency array's last element (`eligibility.bottleRequired`) has no trailing comma before the closing `]` (prettier's own style), so searching for the literal `'],'` the plan's action text names never matches and the bounded span collapses to an empty string -- E4 would vacuously pass (0 >= 2 is false, so it would actually FAIL closed, not vacuously pass; caught immediately on first run).
- **Fix:** Bound the span to the first `']'` after `resolveSteamSectionGating(` instead of `'],'`. Verified via a standalone node script against the real stripped source before committing to the approach.
- **Files modified:** `steamEligibilityWiring.test.ts` (author-time correction, not a post-hoc patch)
- **Verification:** `countOccurrences(span, 'depotSignalResolved')` returns `2` against real source (object literal + dep array), `1` against the E4-RED known-bad.

**3. [Rule 1 - author-time correction, not a defect that shipped] E3's flattening needed an extra normalisation pass**
- **Found during:** Task 2, initial E3 authoring
- **Issue:** `selectSteamPlatformOptions(platformRowMode, platforms, windowsDepotOffered)` is long enough that `prettier` wraps each argument onto its own line. This file's existing `flat.replace(/\s+/g, ' ')` convention (used by Group B's B7) collapses that to `selectSteamPlatformOptions( platformRowMode, platforms, windowsDepotOffered )` -- with a space after `(` and before `)` -- which does not match the literal no-space form the plan's acceptance criteria specify.
- **Fix:** Added a local `flatten()` helper that also strips whitespace immediately inside parens (`.replace(/\(\s+/g, '(').replace(/\s+\)/g, ')')`), used by E3/E3-RED only; Groups A-D's existing `flat` usages are untouched.
- **Files modified:** `steamEligibilityWiring.test.ts`
- **Verification:** Confirmed via a standalone node script that `flatten(stripped)` contains the exact expected/forbidden strings before writing the jest assertions.
