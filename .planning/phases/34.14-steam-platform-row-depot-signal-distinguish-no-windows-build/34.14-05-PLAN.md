Windows/wine option from games whose Windows-depot signal has not been fetched yet. The gating
layer now distinguishes three states — depot confirmed present, depot confirmed absent, and

  - while the answer is unknown, the platform row is in a new `'pending'` mode and the Install

  - when the probe settles WITHOUT the answer (offline, errored, or the 15-second metadata
    timeout expired), the dialog FAILS OPEN and offers Windows anyway.

  <how-to-verify>
**Before you start**

You will edit one JSON file and (for two of the four runs) block one hostname. Both changes are
reverted at the end. Nothing here touches your game installs.

Terminal commands are given verbatim. The app must be FULLY QUIT before each file edit — a
running app rewrites the file from memory on exit and will undo your edit.

**Step 0 — pick a target game and back up the cache (once)**

1. Launch GameLib normally (`npm start`) and go to your Steam library.
2. Pick one already-synced Steam game whose platform icons already render — write down its name.
   Prefer a well-known game so you can sanity-check whether it really has a Windows build.
3. Find its numeric appId: open the game's page in GameLib; the appId is the numeric identifier
   in the page URL. Write it down.
4. Quit GameLib completely (Cmd-Q; confirm no GameLib process remains).
5. Back up the cache:
   `cp ~/Library/Application\ Support/GameLib/store_cache/steam_metadata.json ~/Desktop/steam_metadata.backup.json`

**Step A — the forcing edit (repeat before EVERY run below)**

6. With GameLib fully quit, open
   `~/Library/Application Support/GameLib/store_cache/steam_metadata.json` in a text editor.
7. Delete the single top-level key whose name is your appId, together with its whole object
   value (e.g. the entire `"570": { … },` entry). Leave everything else untouched — including
   the `"__timestamp"` object, whose stale entry is harmless.
8. Save. Confirm the file is still valid JSON (`python3 -m json.tool ~/Library/Application\ Support/GameLib/store_cache/steam_metadata.json > /dev/null` prints nothing on success).

**Run 1 — Electron, network UP**

9. Ensure normal internet connectivity.
10. Do Step A.
11. `npm start`
12. Navigate to your target game and open the Steam install dialog via **"Install with options…"**
    (NOT the plain Install button — plain Install deliberately short-circuits to quick install
    and never opens this dialog).
13. Watch the dialog from the instant it opens. Record:
    - Does a "Checking install options…" row appear?
    - Is the **Install** button disabled while that row is showing?
    - Within ~20 seconds, does the row disappear and the **Platform** selector become usable?
    - After it settles, does the Platform selector offer **Windows** as well as **macOS**?
      (For a game that genuinely has a Windows build, it should.)
    - Does the Install button become enabled?
14. Close the dialog. Quit the app.

**Run 2 — Electron, `appdetails` BLOCKED**

15. Block Steam's store API (this is the request that captures the depot signal):
    `sudo sh -c 'printf "\n127.0.0.1 store.steampowered.com\n127.0.0.1 api.steampowered.com\n" >> /etc/hosts'`
    then flush DNS:
    `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`
16. Do Step A.
17. `npm start`, open **"Install with options…"** for the same game.
18. Record:
    - Does the "Checking install options…" row appear?
    - Is Install disabled while it shows?
    - Within ~20 seconds (the metadata fetch times out at 15s), does it settle?
    - **THE KEY OBSERVATION:** after it settles, is **Windows** still offered in the Platform
      selector? It MUST be. This is the fail-open behaviour — the whole point of the phase.
      If Windows is absent here, the gate FAILS.
    - Does Install become enabled?
19. Close the dialog, quit the app.
20. **Do not toggle the network back on while the dialog is open and expect it to recover** —
    a single probe fires at dialog-open and reconnecting does not re-probe. That is expected
    behaviour, not a defect.

**Run 3 — Tauri, network UP**

21. Unblock the network: edit `/etc/hosts` (`sudo nano /etc/hosts`) and delete the two lines you
    added, then `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`.
22. Do Step A.
23. `pnpm tauri:dev` (never bare `tauri dev` — it serves a stale static bundle).
24. Repeat observations 12-13.

**Run 4 — Tauri, `appdetails` BLOCKED**

25. Re-apply the `/etc/hosts` block and flush DNS (step 15).
26. Do Step A.
27. `pnpm tauri:dev`, repeat observations 17-18.

**Cleanup (mandatory)**

28. Remove the two `/etc/hosts` lines and flush DNS.
29. Restore the cache: `cp ~/Desktop/steam_metadata.backup.json ~/Library/Application\ Support/GameLib/store_cache/steam_metadata.json` (app quit).
30. Relaunch once and confirm the library still renders normally.

**Also record, for each of the four runs**

31. Whether any DUPLICATE "Checking install options…" row appeared (there should be exactly
    ONE at a time). This is the one visual question `--skip-ui` left unarbitrated — a second row
    would mean the rendered-form decision needs revisiting.
32. Whether the dialog ever asserted, in words, that a game is macOS-only. It must NOT — D-07
    forbids that copy, and per the operator-locked domain constraint it would read as false
