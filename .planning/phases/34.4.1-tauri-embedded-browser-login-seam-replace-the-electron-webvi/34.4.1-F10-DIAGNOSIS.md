### Incidental confirmation of the plan's A3 correction

The top-level Suspense fallback breadcrumb fires **at boot but not during the `/login`
navigation**, while the route-level `lazy` breadcrumbs fire in both. This is direct live evidence
that react-router's route-level `lazy` does not participate in `index.tsx`'s
`<Suspense fallback={<Loading />}>` — the correction plan 25 made to research assumption A3,
previously argued from source alone, is now **observed**.

## Candidate causes for the non-reproduction — all UNVERIFIED

Ordered by strength. None is asserted; each names what would settle it.

1. **Genuine intermittency.** The gate operator's own report says the screen "has intermittently
   rendered blank before." A single clean cold start is weak evidence against an intermittent
   defect. *Settled by:* more cold starts.
2. **Plan 27's `imagecache://` gate.** The Login screen renders account/store artwork through
   `CachedImage`. Before `d40cb20a1`, every one of those requests went to a scheme the Tauri shell
   never registers. *Settled by:* reverting the gate locally and retrying a cold first navigation.
3. **Plan 27's `queryLocalFonts` guard.** Known to throw under WKWebView, and the throw landed in a
   swallowed rejection. *Settled by:* establishing whether any module on the `/login` path reaches
   `getFonts()` — not yet checked.
4. **Plan 26's keyring timeout** — *weakest.* `keyring_get failed: keyring:timeout` fired for
   `humble-session` and `steam-refresh-token` at 19:50:11, 28 s before the navigation, so the path
   was already unblocked by the time the operator navigated. More importantly the gate **refuted
   the keyring link by measurement** (0 backend log lines across a >90 s blank), and a
   mounted-but-loading Login renders a spinner, not a blank. The refutation stands; this is
   recorded only so it is not re-proposed as new.
