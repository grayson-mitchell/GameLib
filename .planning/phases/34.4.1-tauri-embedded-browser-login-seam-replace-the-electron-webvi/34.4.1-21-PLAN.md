<objective>
Restore **D-11** — *"no plan may be written on an unverified API"* — before writing the F-6 fix, and
mint this gap cycle's requirement IDs.

Purpose: `34.4.1-RESEARCH-GAP-CYCLE-2.md`'s single most load-bearing finding is that F-6 and WR-07
are **not a new defect class** — they are the realization of a risk this project already wrote down
and did not close. `IPC-PORT-INVENTORY.md:541` named `delete_cookie()`,
`on_document_title_changed` and `eval_with_callback()` in writing, at planning time, as APIs the
spike never tested. Both named APIs then shipped unspiked and both failed live. This plan does not
repeat that: the F-6 fix's own load-bearing API (`WebviewWindow::with_webview()` + `objc2-web-kit`)
gets spiked **first**, on real hardware, and the result decides plan 22/23's shape rather than being
discovered by them.

Three questions this plan answers with a measurement, not an argument:
1. **Research Open Question 1** — does `with_webview()`'s closure run *synchronously inline* when
   called from inside `dispatch_rust_channel`, or is it dispatched? This decides whether the new
   Rust arm can keep `dispatch_rust_channel`'s synchronous `Result<Value, String>` return contract,
   and whether a `MainThreadMarker` can be obtained there at all.
2. **Research assumption A2** — do the cookie/keyring arms actually run on Tauri's main thread?
   `wait_for_blocking_operation`'s reliance on pumping `NSRunLoop::mainRunLoop()` only works if they
   do, and the whole `with_webview` design rests on that being true rather than working by accident.
3. **The cheap alternative first (research Item 1's own instruction)** — does a
   delete → re-read → retry-with-delay loop change the surviving cookie count at all? If it does,
   the diagnosis is a timing/race problem and the `objc2-web-kit` rewrite is the wrong fix. If it
   does not, an identity-mismatch explanation stands and the rewrite is justified. Answering this
   costs one live run and prevents committing plan 23 to a rewrite on an unverified theory.

**Adjacent already-present code this plan verifies (binding constraint 1).** The probe also counts
the SAME live jar through **both** argument directions of the already-present
`cookie_domain_matches` (`main.rs:489-494`) — the census direction (`host` fixed, cookie domain
varying, as `humble_login_cookies` at `main.rs:1176` uses it) and the clear direction (cookie domain
fixed as `host`, target varying, as `humble_login_clear_cookies` at `main.rs:1250` uses it). Research
Defect A is currently inferred from the gate's arithmetic (`total=25, matched=23, deleted=25`). This
turns it into a direct observation of code that has been shipped and unquestioned since plan 01.

Output: `34.4.1-SPIKE-016-FINDINGS.md`, the minted `REQ-34.4.1-GAP-07..GAP-12`, a corrected
`STATE.md` header, and four direct macOS-only crate dependencies at their already-resolved versions.

proves the removal by grep. It must never reach the gate build.
