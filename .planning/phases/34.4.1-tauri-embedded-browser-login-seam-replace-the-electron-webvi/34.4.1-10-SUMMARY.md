## Decisions Made

- **DECLARED requires a term-level match, not id proximity — enforced on BOTH axes.** The
  classification boundary in the plan's `<interfaces>` states DECLARED needs "an in-source
  comment... AND a threat ID" — this plan's script additionally requires the comment to NAME the
  specific dropped capability (via a category-synonym table for Axis A, an explicit
  alternate-seam term list for Axis B), because F-6's own Tauri branch carries `T-34.4.1-30` and
  still does not mention storage/cache/authCache/hostResolver anywhere. An id-only bar would have
  wrongly classified F-6 DECLARED — and, caught during this plan's own development (see
  Deviations), an id-only bar on the Axis B side would have wrongly cleared F-1 itself
  (`humble/user.ts`'s own module doc comment carries 8 decision ids with no mention of
  storage/keychain/sidecar/bypass at all). Both directions are now proven non-vacuous by dedicated
  self-test cases.
- **Two Axis A sites use narrow, self-testable evidence profiles instead of a generic diff.**
  `watchForLogin`'s UA-delivery setup (no `else`, no `return`) and the env-gated smoke hook don't
  fit any of the three mechanical tiers (wipeSteps / configStore sink / ternary return-shape).
  Rather than force a fragile generic diff onto arbitrary control flow, or silently skip the site,
  each uses a `SITE_PROFILES` entry that asserts specific source substrings are still present —
  self-testable (case 8 proves a missing anchor is detected) and fails loudly on drift, forcing a
  human to re-derive the classification rather than silently reporting stale text.
- **The Axis B `safeStorage` scan is scoped to `safeStorage` specifically, not every `electron`
  member.** ~48 files import something from `'electron'`; most of those members are real forwards
  in `electronStub.ts` (no capability drop). Widening Axis B to all members of all 48 importers was
  judged out of scope for this plan's effort budget and would risk false-positive noise; the
  `<interfaces>` block itself scopes Axis B to "importers whose members the sidecar stub may not
  honour," and `safeStorage` is the concrete example given. This is a stated scope limit, not a
  silent gap — a future plan widening this scan would find it trivial to extend the same
  `parse_electron_stub_safestorage()`-shaped mechanism to another member.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed the sweep's electron/tauri branch-polarity inversion, a multi-line
signature rejection, a nested-bracket array-end truncation, and a decryptString parse gap — all
found and fixed during initial development, before Task 1's commit**
- **Found during:** Task 1, iterating `--self-test` and the real run against the live tree
- **Issue (4 distinct bugs, same root cause — insufficient self-testing before the FIRST attempt):**
  (a) `find_seam_if_else`'s electron/tauri text selection was inverted; (b) the enclosing-function
  finder required a literal `(` on the SAME line as the matched header, which every multi-line
  function signature in this codebase fails; (c) the `wipeSteps` array-end regex stopped at the
  first line-anchored `]`, which for the real Tauri branch is a nested `logWarning([...])` array
  several levels deep, not the outer array's true end; (d) the `safeStorage` block-isolation regex
  consumes the object's own closing `}` as its match terminator, leaving nothing for the LAST
  member's (`decryptString`) own lookahead to terminate against.
- **Fix:** (a) corrected the ternary in all 3 classifier functions; (b) removed the same-line `(`
  requirement; (c) replaced the regex end-matcher with a real depth-counting bracket walk; (d)
  appended a synthetic trailing `\n}` before the per-member search.
- **Files modified:** `seam-parity-sweep.py`
- **Verification:** `--self-test` and the real run both exit 0; every Axis A/B site now classifies
  against real source rather than erroring or silently mis-attributing branches.
- **Committed in:** `a1581b60a` (found and fixed before any commit was made)

**2. [Rule 1 - Bug] Fixed the `steamgrid` reachability evidence missing the real (bare-form)
import, and the return-snippet DECLARED check missing a file-header-level decision id**
- **Found during:** Task 1, reviewing the generated `34.4.1-SEAM-PARITY-SWEEP.md` output before
  committing
- **Issue:** The importer-detection regex only matched `from './steamgrid/ipc_handler'`; the only
  real call site (`main.ts:1557`) is a bare side-effect import with no `from` clause, so the
  document incorrectly reported "(none found)" for a question the plan requires answered with
  evidence. Separately, `oauthLoginCapture.ts:157` was misclassified SILENTLY-DROPPED because its
  `D-04` declaration lives in the file's TOP docstring, separated from `captureOAuthLogin()` by an
  unrelated function in between — too far for a contiguous-comment walk to reach.
- **Fix:** Widened the import-detection regex to tolerate both bare and named-import forms;
  widened the DECLARED check's comment scope to include the file's own leading `/** ... */` header.
- **Files modified:** `seam-parity-sweep.py`
- **Verification:** The document now correctly names `src/backend/main.ts` as the sole importer;
  `oauthLoginCapture.ts:157` classifies DECLARED (`D-04`) as intended.
- **Committed in:** `a1581b60a`

**3. [Rule 1 - Bug] Fixed a vacuous Axis B DECLARED check — an empty-term-set call to
`is_declared_by_terms` is trivially true for ANY doc comment containing an id, silently
threatening to clear the real F-1 finding — found AFTER Task 1's commit, before this SUMMARY**
- **Found during:** writing this SUMMARY's findings table, cross-checking the generated
  document's per-row classifications against the live gate's known-correct answers (F-1 must stay
  SILENTLY-DROPPED for `humble/user.ts`) — the committed run at that point showed `humble/user.ts`
  (S-10) reclassified DECLARED, which is WRONG (F-1 is a real, live-gate-confirmed defect).
- **Issue:** `classify_axis_b`'s fallback path called `is_declared_by_terms(doc_comment, set())` —
  passing an EMPTY required-terms set — as an "id-only fallback." `is_declared_by_terms`'s `for
  term in required_terms` loop never executes against an empty set, so the function *vacuously*
  returns `True` for ANY doc comment containing at least one `D-`/`T-` id, which every module's
  header in this codebase does. This silently reclassified `humble/user.ts` (F-1, a real defect)
  from SILENTLY-DROPPED to DECLARED — exactly the "a finding cannot be quietly reclassified" defect
  T-34.4.1-49 exists to prevent, caught here by the same discipline that IS T-34.4.1-49's own
  point, not by luck.
- **Fix:** Extracted the Axis B declared-check into a standalone `is_axis_b_declared()` function
  that checks for a SPECIFIC alternate-seam term list (`sidecar`/`tauri`/`keyring`/`bypass`)
  directly, never through an empty-set call to the generic term-matcher. Added 2 new self-test
  cases (bringing the total from 9 to 11): one proving an id-only comment (the real
  `humble/user.ts` shape) is correctly rejected, one proving an id-plus-alternate-seam-term comment
  (the real `tokenStore.ts` shape) is correctly accepted.
- **Files modified:** `seam-parity-sweep.py`
- **Verification:** Re-ran `--self-test` (11/11 pass) and the real sweep — `humble/user.ts` (S-10)
  correctly returned to SILENTLY-DROPPED, `storeManagers/steam/tokenStore.ts` (S-12) correctly
  classifies DECLARED (`D-09`) matching the live gate's own "NOT affected" determination for that
  file specifically. `steamgrid/secureKey.ts` (S-11) unaffected (its file has no doc comment at
  all, so it was never at risk from this bug) — stays SILENTLY-DROPPED.
- **Committed in:** `bc90fdc7a` (a NEW commit, per this project's git safety protocol — never
  amended into the already-pushed-to-local-history `a1581b60a`)
