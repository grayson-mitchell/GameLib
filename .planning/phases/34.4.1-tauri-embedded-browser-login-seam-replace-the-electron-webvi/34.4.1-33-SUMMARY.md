# Plan 34.4.1-33 — SUMMARY

**D-29-04 and D-29-05 closed at source level. The live half goes to plan 35.**

## What changed

- **D-29-04** — an empty document title short-circuits **before** the lock and before `set_title`.
  `login_window_title`'s own `!title.is_empty()` guard was already correct; the defect was that the
  callback **called it with a value it should have discarded**, so the composer fell through to the
  bare origin and the bar dropped its document title and got it back (`22 → 0 → 42`). The skip is
  still logged — *"fired and ignored"* and *"never fired"* are different diagnoses.
- **D-29-05** — the visible window is built with `login_window_title(&origin, None)`, so it never
  presents as `Tauri app`. Scoped to `if visible`; hidden windows have no title bar.

The two are causally independent and were fixed as such — D-29-04 was proposed as the cause of
D-29-05 and refuted by ordering.

## The finding worth carrying: an existing gate measured the wrong property

`tauriShellSource.test.ts` asserted `not.toContain('.title(')` — **a blanket ban on the method**.
The D-29-05 fix made it fail, which exposed it: WR-07 prohibits a hard-coded **application** title,
not an origin-derived one, and the ban **could not have distinguished `.title("GameLib")` from
`.title(login_window_title(...))` because it rejected both**.

**The gate was amended; the code was not bent to satisfy it.** The amended version forbids a string
literal in all three Rust forms plus `format!`, **and** requires every surviving `.title(` argument
to contain `login_window_title(` — closing the hole where `.title(some_other_var)` would pass a
literal-only check.

## Four red-proofs

| # | mutation | expected | result |
|---|---|---|---|
| 1 | `.title("GameLib")` | amended WR-07 gate FAILS | **FAILS** ✓ |
| 2 | `.title(some_other_var)` | amended WR-07 gate FAILS | **FAILS** ✓ |
| 3 | remove the provisional title | D-29-05 presence gate FAILS | **FAILS** ✓ |
| 4 | move the guard after `set_title` | D-29-04 order gate FAILS | **FAILS** ✓ |

**Red-proof 1 is the load-bearing one** — it shows the amendment did not weaken WR-07's negative
half. A "fix" to a failing gate that also disarms it would be the worse outcome.

## Explicitly NOT closed

establish presence; the new assertion closes that at source, but whether an operator still **sees**
a `Tauri app` flash is visual and timing-dependent. Plan 35 owns it.
