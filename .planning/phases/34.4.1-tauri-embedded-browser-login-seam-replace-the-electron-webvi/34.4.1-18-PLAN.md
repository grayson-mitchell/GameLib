<objective>
Close the four cheap findings the gate recorded as non-blocking. F-4 is the only one a user feels;
F-2 is the one that made a working login look wedged for two and a half minutes.

Purpose:
- **F-2** — ~37 `Humble login validation rejected candidate session: session_expired` warnings,
  one every ~4.5s, while the operator fetched credentials from a password manager. Functionally
  correct (it rejected a dead session and accepted the live one) but adjacent to the
  "login that keeps trying with a silent log" shape this gate watches for, and a reader cannot
  tell "waiting for the user" from "wedged".
- **F-4** — the login window was **too small for its content** and was **lost behind other
  applications** when the operator switched away. `src-tauri/src/main.rs:956-979` builds it with
  only `.user_agent()` and `.visible()`: no size, no centering, no raise.
- **F-3** — the post-login identity fetch 404s. Correctly handled as best-effort (login was
  already accepted and a subsequent sync returned `gamekeys=27 fetched=7/7`), and the gate
  recorded it as *"unexplained and is recorded, not diagnosed."* This plan does not diagnose it
  either; it makes the next occurrence diagnosable.

Output: quieter, more informative login logging; a specified login window; a named endpoint on
identity failure.

**F-4's title is NOT a missing feature.** The gate lists `.title()` among the unset builder calls,
but WR-07 forbids a hard-coded title on a window displaying remote content — it is a phishing
affordance, and `tauriChildWindows.ts` omits it deliberately for that reason. The correct outcome
is that the remote document's OWN title shows. Verify that; do not "fix" it by setting one.
</objective>

raising must apply only to the visible case, or it will start centering and raising windows that
are supposed to be invisible.

is RE-ARMED on every `notifyLoginNavigated()` relay, so an actively-navigating user is never cut
off — the deadline is not the thing to change.

| T-34.4.1-79 | Spoofing | login window title | mitigate | **WR-07 preserved:** no `.title()` is set, so the remote document's own title shows and the window can never present GameLib's identity while displaying a third-party login form. Enforced by a grep gate, not by intent. |
| T-34.4.1-80 | Information Disclosure | identity-failure logging | mitigate | Path and HTTP status only. Body, cookies and headers stay out, preserving the adapter's existing `see message only, never body/cookie` rule for an uploadable log. |
