<objective>
Wire the four OAuth runners to the login seam this phase builds, so REQ-34.4.1-08's "wired" is a
code path a test can execute rather than a property of the Rust layer's naming.

Purpose: CONTEXT.md's Phase Boundary lists "Wiring the 4 OAuth runners to the new mechanism" as its
own in-scope bullet, and D-04 states the four "get wired **and** declared-blocked" — two actions.
Shipping only the declaration delivers half the decision, and leaves Phase 34.5 inheriting an
unproven claim about navigation observation for three of its four runners instead of a seam already
exercised against their real redirect shapes.

Output: a pure per-runner redirect matcher, a deadline-bounded seam-driven capture driver, one new
handle channel to reach it from the renderer, and a renderer hook that hands the captured code to
the still-unported auth channel and turns its `UNPORTED_CHANNEL_MARKER` rejection into the declared
Phase-34.5 surface.
</objective>

  export interface OAuthRedirectMatch {
    /** The authorization code / token value, or null when the runner consumes the whole url. */
    code: string | null
    /** Always the full redirect url that matched — `zoom` needs this, the others do not. */
    redirectUrl: string

  export type OAuthCaptureOutcome =
    | { status: 'captured'; runner: OAuthRunner; code: string | null; redirectUrl: string }
    | { status: 'cancelled' }        // window closed / seam reported the window gone
    | { status: 'timeout' }          // deadline elapsed with no matching navigation
    | { status: 'unsupported' }      // no seam installed (the Electron build)
    | { status: 'error'; message: string }

  export function captureOAuthLogin(
    runner: OAuthRunner,
    loginUrl: string,
