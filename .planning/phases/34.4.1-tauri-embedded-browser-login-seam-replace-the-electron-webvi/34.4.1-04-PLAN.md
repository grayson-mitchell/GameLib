Give `humbleRevealKey` a real transport under Tauri: a hidden, on-demand child window that issues
the reveal POST from its own JS context and returns the response body through a cancelled
navigation, with an honest declared-degraded outcome if Cloudflare 403s it anyway.

webview's own `fetch()` is the only structurally-new option.

the retirement of a now-stale stub message.

         deliberately — RFC 2606 reserves `.invalid` as non-resolvable, so even a late cancellation

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sidecar → injected JS in an authenticated remote context | The reveal body and csrf token are interpolated into a script executed on humblebundle.com with live session cookies |
| webview → Rust | The response payload returns via a URL the page itself constructs |
| hidden window lifetime | An authenticated browser context exists with no user-visible surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.4.1-20 | Tampering / Elevation of Privilege | `reveal_post_script` interpolation | mitigate | Every interpolated value is embedded via `serde_json::to_string`, producing an escaped JS string literal; unit-asserted against quotes, backslashes and `</script>`. Naive `format!` quoting is grep-asserted absent. |
| T-34.4.1-21 | Information Disclosure | reveal payload (may echo a key value) | mitigate | Never logged in Rust or Node; the exfil URL is never navigated to (cancelled in `on_navigation`) and targets the RFC 2606 non-resolvable `.invalid` TLD, so no DNS resolver can observe it. Only the parsed value crosses the existing stdio channel, which already carries the reveal value today (C4 narrow exposure, unchanged). |
| T-34.4.1-22 | Information Disclosure / Repudiation | orphaned hidden authenticated window | mitigate | Per-reveal open/close (D-08); the arm closes on success, error AND timeout, with each close site named in the summary. No persistent hidden context, matching Phase 34 WR-03's reasoning. |
| T-34.4.1-23 | Denial of Service | a hung fetch inside the webview | mitigate | 20s `recv_timeout` in Rust plus the existing `REQUEST_TIMEOUT_MS` bound on the Node side; both close/settle rather than hang. |
| T-34.4.1-24 | Spoofing | a non-Humble origin used for the reveal window | mitigate | The origin URL is `HUMBLE_BASE_URL` from backend constants and is re-validated https-only by the shared arg helper; it is never renderer-supplied. |
| T-34.4.1-25 | Denial of Service | a rejecting reveal in a fire-and-forget caller | mitigate | `humbleRevealKey` resolves a typed failure outcome, never rejects (`sidecar-dialog-reject-crashes`); `sidecarRejectionGuard.test.ts` stays green. |
| T-34.4.1-SC | Tampering | npm/cargo installs | accept | Zero new packages; `serde_json`, `url` and `tauri` are already in the pinned tree. |
</threat_model>
