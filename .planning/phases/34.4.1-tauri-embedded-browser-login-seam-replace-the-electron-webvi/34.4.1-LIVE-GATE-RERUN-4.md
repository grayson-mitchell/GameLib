# Phase 34.4.1 — FOURTH blocking live gate (gap cycle 3)

---

## Why a fourth run exists — read this before anything else

Run 3 passed 4/4 and closed the phase. **Item 3(b) was the exception, and it was not the operator's
fault.**

`survivingNonHumble=0` was recorded. That number was **arithmetically forced, not passing**:

```
before(total=34, matched=34)   →   every cookie in the jar was Humble's
```

With `total == matched`, **no non-Humble cookie existed for the delete to spare**, so a surviving
count of zero was the only value the census could ever have produced. It measured nothing.

The root cause is **the contract**. Run 3's precondition 6 struck the planted non-Humble cookie as
moot, reasoning that plan 17's jar census *"supplies the evidence without it."* That conflates the
**measuring apparatus** with the **thing measured** — a census cannot report `survivingNonHumble > 0`
against a single-origin jar however correct its counting. Item 1's from-scratch reset then
guaranteed the single-origin condition.

**The contract instructed the operator not to plant a cookie, and then required an outcome only a
planted cookie could produce. No action available during that run could have satisfied it.**

The planted cookie and the census are **complements, not alternatives**. That is what run 3 got
wrong, and it is the single thing this run exists to correct.

## Preconditions

1. **`pnpm tauri:dev` runs from a clean tree.** Use `pnpm tauri:dev` — **not** `tauri dev`, which
   serves a stale static bundle. Note also that `pnpm tauri:dev` **exits 0 without replacing an
   already-running instance**: a whole UAT has previously run against an 8-hour-old build this way.
   Confirm no instance is live first (`pgrep -fl gamelib-shell` — note `pgrep GameLib` misses it).

2. **Operator holds real Humble credentials.** OPERATOR-ATTESTED AT GATE TIME.

3. **Starting credential state — MEASURED 2026-08-23, not attested.**
   `~/Library/Application Support/GameLib/humble_store/config.json` is **`{}` (2 bytes, zero keys)**.
   The state is **(a) ABSENT**. Item 1 is therefore a genuine from-scratch login with no reset step
   required. **If this has changed by gate time, re-measure and record the actual state** — all four
   locations must be clear for (a) to hold: the store file, both Keychain slots, the WKWebView
   cookie jar, and WebKit's WebsiteData store. Run 2's attempt-1 was VOIDED by missing the cookie
   jar alone, which silently auto-restored the session.

4. **At least one UNREVEALED Humble key** in the connected account's library, confirmed on the
   Humble Keys page after item 1's login, before item 4.

5. **Evidence sources — two of them, and they are not interchangeable.**
   - `~/Library/Logs/GameLib/gamelib.log` for anything the **sidecar** logs.
   - The **`pnpm tauri:dev` terminal** for Rust shell `eprintln!` output — the title lines, the
     presentation-configuration line, F-9's timeout message. **These never reach `gamelib.log`,
     because the sidecar's stdout is the RPC pipe and cannot carry them.**

   > **This distinction has already produced one false finding.** F-9 was first recorded "watch
   > CLEAN" on a `gamelib.log` grep that **could not have seen it**. *A clean grep of the wrong
   > source is not evidence of absence.* Take a fresh baseline offset at launch; any offset from
   > preparatory work is VOID once the operator relaunches.

6. ## **A non-Humble cookie of known name and domain, planted before item 3. — UNSTRUCK.**

   **This precondition is RESTORED. It was struck in run 3 and that strike is the defect this run
   corrects. Do NOT skip it. Item 3(b) is unscoreable without it.**

   **Preferred method — use shipped functionality, because it is also the real-world risk:**
   **connect GOG** (Manage Accounts → GOG) before item 3, if not already connected. Measured
   2026-08-23: `gog_store/auth.json` exists and `gog_store/config.json` carries `isLoggedIn` +
   `userData`, so **GOG is currently connected** and its cookies should already be in the shared
   jar. This makes item 3(b) ask the question a user actually cares about: *does disconnecting
   Humble sign me out of GOG?*

   **Record, before item 3 runs:** at least one non-Humble cookie's **name** and **domain**, taken
   from the item-3 "before" census output. Not a count — a **name**. A count cannot be checked for
   survival by identity.

   **Fallback if no second store account is available:** navigate any login window to an https
   origin that sets a deterministic named cookie and record its name and domain. The requirement is
   only that a cookie exists in the shared jar whose name and domain are known and are not
   `humblebundle.com`.

   **If the "before" census shows `total == matched` — STOP.** That is run 3's exact condition
   reproducing. Do not run item 3(b); plant a cookie first and re-take the census. Scoring 3(b)
   against a single-origin jar produces a forced zero, not a pass.
