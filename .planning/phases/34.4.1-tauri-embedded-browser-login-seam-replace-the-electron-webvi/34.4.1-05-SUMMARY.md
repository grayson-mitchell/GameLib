## Decisions Made

- **Combined tasks 1 and 3 into one commit.** Task 1's action explicitly specifies `return <WebviewUnavailablePanel url={startUrl} />` — which only compiles once task 3 has renamed the panel's `runner` prop to `url`. Conversely, task 3's own structural test (Group 2 in the original `WebviewUnavailablePanel.test.tsx`) reads `index.tsx`'s shape, which only reaches its final form once task 1's branch split lands. Splitting these into two separately-verified commits (each required to pass `tsc --noEmit` per its own acceptance criteria) was not possible without one of the two commits temporarily breaking the build. Task 2 (`TauriLoginPanel`) has no such coupling and was committed first, standalone.
- **`window.api.logInfo` called synchronously in `TauriLoginPanel`'s render body, not inside `useEffect`.** This project's frontend Jest config has no jsdom/react-test-renderer installed (see `src/frontend/jest.config.js`'s docstring); every component test in this codebase invokes the component as a plain function outside a React render tree. A real `useEffect` call in that context throws "Invalid hook call" (no dispatcher installed). `WebView/index.tsx` already established the "log directly in the render body" convention for its own Tauri-gap log line — `TauriLoginPanel` follows the same convention rather than introducing an untestable hook.
- **`WebviewUnavailablePanel.test.tsx`'s old two-arm structural gate ("Group 2") was rewritten, not merely extended, into a three-arm gate ("Group 3").** The old gate located the Tauri arm via the literal substring `if (isTauri())`. After the split, that substring's *first* occurrence in the source is inside the login arm's condition text only if written as bare `isTauri()` — but the actual login arm is written `if (isTauri() && isLoginPathname(pathname))`, so the literal substring search actually (and only coincidentally) still lands on the *store* arm. Re-running the old, unmodified test against the new source would have passed — but vacuously, since it never actually inspects the login arm at all. The new gate explicitly locates and asserts on all three arms by name (`isLoginPathname(pathname)` for the login arm, `TauriLoginPanel`/`WebviewUnavailablePanel` for arm identity) so a real regression (e.g. the login arm silently dropped) cannot pass by coincidence.
