## Accomplishments

- Closed WR-07's positive half as far as static analysis can reach: `humble_login_open`'s `if visible` block now chains `.on_document_title_changed(|window, title| { let _ = window.set_title(&title); ... })`, the exact mechanism documented in Tauri's own in-source example (`tauri-2.11.5/src/webview/mod.rs:564-567`). Omitting `.title()` alone does NOT make the OS title track `document.title` -- that assumption was never spiked, and is exactly why two live gate operators (plans 20/23's gate reruns) both reported the title bar reading the Tauri framework default, "Tauri app", despite the grep gate for "no hard-coded title" passing green both times.
- Corrected the arm's own comment block, which previously (falsely) claimed WR-07 was "enforced by the grep gate in this plan's own acceptance criteria, not by intent alone." The corrected text states the measured truth: a grep gate proving `.title(` is never hard-coded can only establish the ABSENCE of the prohibited value, never the PRESENCE of a tracking one -- and explicitly names plan 29 item 1 as the sole owner of the live claim.
- Added a `[shell] humble_login_open: presentation requested visible=true width=900 height=700 center=true focus_once=true persistent_pin=false` `eprintln!`, emitted only on the visible path, giving F-4's one-shot `.focused(true)` raise a machine record for the first time -- the raised half has gone UNOBSERVED across both prior live gates (`34.4.1-LIVE-GATE-RERUN.md` Item 3), and a one-shot event with no persistent state has nothing else to check an operator's memory against.
- Added 5 new static assertions to `tauriShellSource.test.ts` (36 -> 41 tests): `on_document_title_changed` present; `always_on_top` absent from non-comment code; no `WebviewWindowBuilder` chain in the file hard-codes `.title(`; the four presentation calls (`.inner_size(`, `.center()`, `.focused(true)`, `on_document_title_changed`) appear ONLY inside `humble_login_open`'s `if visible` block; and the two hidden-window builder chains (`humble_reveal_post`, `humble_login_clear_storage`) gained neither the title hook nor any presentation call. Every test's own title states what it proves and names plan 29 item 1 as the owner of what it cannot -- research Pitfall 3's own prescribed countermeasure.
- Proved the visible-only gating assertion load-bearing with a REAL temporary edit (not a synthetic snippet): moved `.center()` out of the `if visible` block onto the unconditional builder chain, ran `npx jest tauriShellSource.test.ts -t "if-visible"`, observed the expected failure (`Expected substring: ".center()"` absent from the now-narrower `visibleBlock`), and restored `main.rs` byte-identical (`diff -q` confirmed).
