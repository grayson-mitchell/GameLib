# Phase 34.4.1 Plan 17: Jar census (F-5) + reveal transport label (F-8) Summary

**`disconnect()`'s Tauri cookie-clear step now takes a paired before/after cookie-jar census from inside itself (same still-open window label, empty name filter, `classifyCookieRead`-routed) and emits one greppable log line proving the clear was domain-scoped -- with a distinct, named discrepancy warning if the arithmetic ever fails -- while the reveal-POST log line now derives its transport label from `getLoginWindowSeam()` at log time instead of a stale hardcoded `"electron-net transport"` literal.**

## Accomplishments

- `humble/user.ts`'s `disconnect()` Tauri `'clearHumbleCookies'` wipeStep now takes a paired before/after cookie-jar census, INSIDE the step, against the SAME still-open window label the clear itself uses (F-7's process lesson applied a second time: a measurement scheduled around an operation cannot be reconstructed after the next operation destroys its "after"). The name filter passed to `seam.cookies()` is empty, so `matched` counts every `humblebundle.com` cookie, not just `_simpleauth_sess`.
- **The exact census log line format** (recorded verbatim per this plan's own `<output>` instruction, for plan 20's gate to grep):
  ```
  Humble disconnect: cookie census before(total=T0, matched=M0, verdict=V0) after(total=T1, matched=M1, verdict=V1) deleted=D survivingNonHumble=S
  ```
  where `V0`/`V1` are one of `classifyCookieRead`'s four verdicts (`SUPPORTED_NONEMPTY` / `SUPPORTED_BUT_EMPTY` / `UNSUPPORTED_OR_ERROR` / `UNDECIDABLE`), and `total`/`matched` read `unavailable` instead of a number on the side whose census read structurally failed. Example: `Humble disconnect: cookie census before(total=5, matched=3, verdict=SUPPORTED_NONEMPTY) after(total=2, matched=0, verdict=SUPPORTED_BUT_EMPTY) deleted=3 survivingNonHumble=2`.
- The arithmetic in `<interfaces>` (`matched-after==0` AND `jar-delta==matched-before` AND `deleted==matched-before`) is evaluated as three independent checks. Any failure logs a distinct, separately-greppable warning naming exactly which equality broke:
  ```
  Humble disconnect: cookie census discrepancy — clear may not have been domain-scoped: <failure 1>; <failure 2>; ...
  ```
  A blanket wipe (e.g. `clear_all_browsing_data()`-shaped behavior) fails the middle equality immediately (the jar shrinks by more than the Humble-matched count) and is now loud, never silently absent from the log.
- Both census reads route through the existing `classifyCookieRead` classifier (shared with the login-watch poll path), with a fresh `everProvedLive` flag scoped to this one disconnect call. A read that never sees `total > 0` within the census is reported `UNDECIDABLE`, never collapsed to a false-clean zero. A structurally-rejecting census read is caught, logged (`'Humble disconnect: cookie census read failed (non-fatal, evidence unavailable for this side)'`), and reported as `total=unavailable` rather than blocking the clear or throwing out of `disconnect()`. When either side is unavailable, a distinct `'Humble disconnect: cookie census incomplete — domain-scope arithmetic cannot be verified (a census read was unavailable)'` warning fires instead of attempting (and potentially faking) the arithmetic.
- The window still closes exactly once, in the pre-existing `finally`, on every path -- success, a rejecting census read, a rejecting `clearCookies`, or a rejecting `close()` itself. The census reads live entirely inside the existing `try`, ahead of `finally`, per the plan's explicit constraint that the window must never be kept open to "fix" observability.
- `humble/library.ts`'s reveal calling-adapter log line no longer stamps the literal `"electron-net transport"` unconditionally. A new `revealTransportLabel` local is computed from `getLoginWindowSeam() !== null` at the moment of logging -- the exact same condition `humblePostRequest` (`adapter.ts`) branches its dispatch on -- so the log names `'login-window seam transport'` under Tauri and `'electron-net transport'` under Electron, and the two can never again disagree. `csrfTokenPresent=`/`gamekey`/`machineName` fields, `humblePostRequest`'s branching, both transports, and the reveal response contract are all unchanged -- this is a diagnostics-only fix. The comment history is preserved (round-6 rationale kept) with a new dated paragraph recording F-8: the literal was correct when written and became false the moment Plan 04's seam landed.
- **Precondition 6 (plant a non-Humble control cookie for plan 20's gate) is now genuinely MOOT**, for a better reason than the gate's original one recorded it: the domain-scope evidence no longer requires it (the census reads `total`/`matched` on the Humble jar itself, never another origin's cookie), rather than being merely unavailable without it.
