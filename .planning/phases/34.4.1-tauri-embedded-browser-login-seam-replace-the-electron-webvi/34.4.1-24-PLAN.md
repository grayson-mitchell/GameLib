Purpose (WR-07): the live gate operator reported, verbatim, *"title of window was Tauri app"*. The
login window's title bar shows the Tauri framework default — neither Humble's own document title
(what WR-07 requires) nor `GameLib` (what WR-07 was written to prohibit). `humble_login_open`
(`main.rs:1117-1144`) deliberately omits `.title()` on the builder, on the assumption that omitting
it makes the OS title track `document.title`. It does not. Tauri requires an explicit
`on_document_title_changed` hook, documented with an in-source example at
`tauri-2.11.5/src/webview/mod.rs:564-567`.

**This is research Pitfall 3 in the flesh, and it is why this plan's acceptance criteria are shaped
the way they are.** The comment at `main.rs:1114-1116` asserts *"WR-07 stays intact, enforced by the
grep gate in this plan's own acceptance criteria, not by intent alone."* A grep gate proving
`.title()` is never hard-coded can only establish the **absence of the prohibited value**. It
structurally cannot establish the **presence of the required one**. The gate said green; the title
bar said `Tauri app`. Every static gate this plan writes is therefore explicitly paired with a live
claim that plan 29's item 1 must observe — the static half never closes WR-07 on its own.

Purpose (F-4): sizing and centring are confirmed fixed across both gate runs. The raised/focused
half has been **UNOBSERVED in both**. `.focused(true)` is a one-shot raise-and-focus on creation,
deliberately not `.always_on_top(true)` — and research confirms there is no middle state in the
underlying `tao`/`NSWindow` surface, so this is a platform binary, not an implementation gap. There
is nothing to fix. What is missing is observation, and observation of a one-shot event is easy to
miss or misremember. This plan emits a log line recording exactly which presentation options were
applied when a visible login window was built, so plan 29's operator report has something to be
checked against rather than being the only record.

**Adjacent already-present code this plan verifies (binding constraint 1).** The same
`humble_login_open` arm builds the **hidden** reveal and clear windows, and `main.rs` has two
further `WebviewWindowBuilder` sites (`:1277` for `humble_reveal_post`, `:1344`). The visible-only
gating of `.inner_size()`/`.center()`/`.focused(true)` (plan 18's F-4 fix) has never been asserted
by anything — it is present, and unquestioned. This plan pins it: the new hook must be gated the
same way, and a test must fail if any of the four presentation calls escapes the `if visible` block
or appears on the hidden-window builders.

Output: a title that tracks the page, a presentation-configuration log line, and paired

<interfaces>
**The documented fix, from Tauri's own in-source example (`tauri-2.11.5/src/webview/mod.rs:564-567`):**
```
.on_document_title_changed(|window, title| {
    let _ = window.set_title(&title);   // never .unwrap() on a live user-facing path
})
```
`WebviewBuilder::on_document_title_changed` fires whenever the loaded page's `document.title`
changes, handing back a `Webview<R>` and the new title string. It is core `tauri` API — no new
dependency.

**The builder chain to amend (`main.rs:1126-1132`), current shape:**
```
let mut builder = WebviewWindowBuilder::new(app, &label, WebviewUrl::External(url))
    .user_agent(user_agent)
    .visible(visible);
if visible {
    builder = builder.inner_size(900.0, 700.0).center().focused(true);
}
```
`.user_agent()` is MANDATORY, not reinforcement (spike 013: Tauri's default macOS UA carries no
browser product token). `.on_page_load` is the relay; `.on_navigation` must NEVER be used for it
(spike 013 measured 5 of 8 `on_navigation` events as third-party iframes).

**REQ-34.4.1-09, fail-closed labelling, which this plan must not weaken.** The window label comes
from `next_login_window_label()`'s generated-never-derived scheme, matches no capability, and
therefore receives zero Tauri command access. `on_document_title_changed` sets ONLY the OS window
title — it grants nothing. Say so in-source; do not let a reader infer otherwise.

**What the operator saw and what the log must be able to corroborate.** The gate records
(`34.4.1-LIVE-GATE-RERUN.md` § Item 3 WR-07) only the operator's sentence. There is no machine
record of what presentation options were actually applied to the window they were looking at, so a
disagreement between the code's intent and the operator's report cannot currently be adjudicated.

**Privacy note on titles.** A page title is not a secret in the way a cookie value is, but it is
remote-controlled content on a page the user is authenticating against. Log the fact of a title
change and its LENGTH, never the string — consistent with T-34.4.1-39's register and with never
letting remote content choose what lands in an uploadable log.
