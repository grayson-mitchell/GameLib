# Phase 34.4.1 Plan 22: F-6 Defect A fix — correctly-directed cookie census Summary

**Added a second, purpose-built Rust cookie-read arm (`humble_login_cookies_for_domain`) so the Humble disconnect census counts leading-dot and subdomain-scoped cookies correctly, while the login-watch poll's proven-correct direction is left untouched and pinned by test on both the TS and Rust sides.**

## Performance

- **Duration:** ~30 min
- **Completed:** 2026-07-31T05:27:48Z
- **Tasks:** 3
- **Files modified:** 11

## Accomplishments

- Closed F-6 Defect A: the disconnect census (`humble/user.ts`) previously called `seam.cookies()` — the SAME page-host-first `cookie_domain_matches` direction `watchForLogin()`'s poll correctly uses. With a FIXED apex (`'humblebundle.com'`) passed as the "host" argument, the suffix branch can never fire, so the census only ever matched cookies whose domain attribute was the bare apex string, silently undercounting every leading-dot- and subdomain-scoped Humble cookie. Spike 016 measured this live: `total=33`, that direction's count=`29`, the correct direction's count=`33`.
- Added `humble_login_cookies_for_domain`, a new Rust `dispatch_rust_channel` arm whose filter mirrors `humble_login_clear_cookies`'s (unedited) direction — the cookie's OWN domain first, the fixed target second — and returns the same `{ total, matched }` liveness-proof shape `humble_login_cookies` already returns.
- Exposed `cookiesForDomain(label, domain, names)` on `LoginWindowSeam`, registered it in `createRustLoginWindowSeam()` with the same never-coerce-a-missing-total-to-0 guard `cookies()` already enforces, and updated every existing test double that implements the interface as a full object literal so `tsc` stays clean without widening the interface to optional.
- Routed the disconnect census's before/after reads through `cookiesForDomain()`. The three page-host poll/csrf call sites (`watchForLogin`, `checkHealthAndFlagExpiry`'s csrf backfill, `finishLogin`'s csrf capture) are UNCHANGED and still call `cookies()` with `'www.humblebundle.com'`.
- Added a source-level JS test (`tauriShellSource.test.ts`) that extracts each Rust arm's body from comment-stripped source and asserts the exact `cookie_domain_matches(...)` call shape — pinning the asymmetry from the JS suite, where no TS mock or Rust unit test alone could catch a future "simplification" that collapsed the two arms or swapped one arm's argument order.
- Removed plan 21's `SPIKE 016` throwaway scaffolding in full: the probe arm, its `spike016_wait_for_records` helper, the `objc2_foundation` import, and the `GAMELIB_SPIKE016`-gated trigger block inside `humble_login_open` (the second piece the mandatory-cleanup note in this plan's own prompt flagged, since the plan text only described the first).
