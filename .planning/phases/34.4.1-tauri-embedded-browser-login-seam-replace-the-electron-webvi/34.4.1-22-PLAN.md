<objective>
Close **F-6's Defect A**: the disconnect census reads the cookie jar with `cookie_domain_matches`'s
arguments in the opposite order from the clear, so it silently undercounts every leading-dot or
subdomain-scoped Humble cookie.

Purpose: `cookie_domain_matches` (`main.rs:489-494`) is directional — `host == d || host.ends_with(
".{d}")` only ever fires when `host` is the *narrower* string. `humble_login_cookies`
(`main.rs:1176`) passes the caller's `host` first, which is exactly right for
`watchForLogin()`'s question ("does this cookie's domain cover the page I am on?") and is the
comment-verified fix for wry's `cookies_for_url()` `==` trap. It is exactly **wrong** for the
disconnect census's question ("does this cookie belong to `humblebundle.com` or any of its
subdomains?"), which `user.ts:984` asks by passing the fixed apex as `host`. With a fixed apex, the
suffix branch can never fire, so the census only ever matches cookies whose domain attribute is the
bare string `humblebundle.com`.

**Why this must land before Defect B's fix.** The census's three equalities
(`matched-after == 0`, `T0 - T1 == matched-before`, `deleted == matched-before`) are the only
oracle that will prove or disprove plan 23's rewrite. An undercounting `matched-before` makes a
future "PASS" unreliable — a partial deletion could satisfy all three against wrong numbers.
Research Item 8 #1 states this as an explicit precondition on the gate's item 3.

**Adjacent already-present code this plan verifies (binding constraint 1).** The fix is a NEW arm,
not an edit to the existing one — precisely so the already-present `humble_login_cookies` read
keeps the direction spike 014a proved and `watchForLogin()` depends on. This plan therefore adds a
regression assertion that the poll's call site still passes the page host first and still receives
the liveness `total`, and a source assertion that the existing arm's `cookie_domain_matches(host,
c.domain())` call is unchanged. The last cycle failed because nobody checked the step that was
already there; here the already-there step is checked by name.

Output: a second, correctly-directed cookie read arm; a `cookiesForDomain()` seam method; the
disconnect census routed through it; and the spike scaffolding from plan 21 removed.
</objective>

**The directional function, unchanged by this plan (`main.rs:489-494`):**
```
fn cookie_domain_matches(host: &str, domain: Option<&str>) -> bool
    // true when  host == d  ||  host.ends_with(".{d}")
```

**The two questions, and which direction answers each:**
```
poll  (humble_login_cookies, main.rs:1176)   cookie_domain_matches(page_host, cookie.domain())
      "does this cookie's domain cover the page I am on?"          <- KEEP AS IS

census/clear (humble_login_clear_cookies, main.rs:1250)
                                             cookie_domain_matches(cookie.domain(), Some(target))
      "does this cookie fall under the target domain or its subdomains?"  <- the census needs THIS
```

**The seam contract the new method must mirror (`src/backend/humble/loginWindowSeam.ts:39-42`,
`:106`):**
```
interface LoginWindowCookieRead { total: number; matched: LoginWindowCookie[] }
cookies(label: string, host: string, names: string[]): Promise<LoginWindowCookieRead>
```
`total` is the UNFILTERED jar size and the liveness proof (`classifyCookieRead`'s four-verdict
truth table depends on it). The new `cookiesForDomain(label, domain, names)` must return the same
`LoginWindowCookieRead` shape, with the same "never coerce a missing `total` to 0" rejection the
existing registration enforces at `humbleLoginFlowRegistration.ts:181`.

**The census call site to re-point (`src/backend/humble/user.ts:984`):**
```
const read = await seam.cookies(label, 'humblebundle.com', [])
```
**The poll call sites that must NOT change** (`user.ts:431`, `:651`, `:816`) — all pass
`'www.humblebundle.com'`, the page's own host, which is the correct direction for the existing arm.

**The channel-constant convention** (`src/common/types/sidecarTransport.ts:257`,
`:283`): each Rust channel name is an `as const` export with a doc comment naming the phase, plan,
decision and requirement, the arg tuple and the resolve shape. `ported-channels-gate.py` gates the
seven **IPC** channel names, not the Rust channel constants, so a new Rust constant does not
change that script's expectations — but the script must still be re-run clean.
