<objective>
Close the per-game half of gap G3 (70-REVIEW.md WR-05). `writeConfig` takes the strict
`appSettingsSchema.partial()` and `runWineCommand` takes the strict `gameSettingsSchema.partial()`.
The renderer sends the WHOLE persisted per-game object back
(`{ ...await requestGameSettings(appName), ... }` in DownloadDialog, ThirdPartyDialog,
SideloadDialog and ConsoleMode InstallOverlay). `settings/game` is identity-only, so any value the
strict schema rejects makes the install dialog throw IPC_INVALID_ARGS or silently drop the user's
Wine choice. Values it rejects include a retired key (`useSteamRuntime`), a null, an older build's
`gamescope` without `additionalOptions` (added in 4bb883957 → 4c07157f0), a stale
`lastUsedLaunchOption`, an over-long string or a wrong primitive type. This plan adds a
`settings/game` v1 -> v2 strip step derived from the schema, following the D-12 pattern inside
the Phase 68 engine.

**Data-loss trade-off (orchestrator decision, revision 1, option a):** the strip runs with
`dropInvalidOptional: true`. Under `.partial()` every member is optional, so only a value the strict
schema rejects is dropped, and the default from the global config applies for it. A schema-valid
value is never touched. The user's invalid value is gone from the live file, but the Phase 68
engine writes a 0600 pre-migration backup of the whole file before rewriting it, so the original
can be recovered (T-70-21-03).

The global half is 70-22, which depends on this plan because both edit the version constants, the
version types and two shared test files. Out of scope: awaiting/handling the dialogs' writeConfig
calls, and WR-06's loose wineVersion arm.

Output: the new chain step, the per-game version constant bumped to v2, fixtures and tests.
</objective>
