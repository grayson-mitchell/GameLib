<objective>
Close the global half of gap G3 (70-REVIEW.md WR-05: "settings/global from appSettingsShape").
config.json's `defaultSettings` is read back as the app settings. Every setSetting value is checked
against the strict per-key schema, and a full-config writeConfig (`appName: 'default'`) is checked
against the strict `appSettingsSchema.partial()`. The `settings/global` chain stops at the v0 -> v1
tray/focusRow fold, so a retired key, a rejected null or an invalid value on disk is never cleaned.
This plan adds a `settings/global` v1 -> v2 strip step derived from the schema.

**Data-loss trade-off (orchestrator decision, revision 1, option a):** this is the same policy as
70-21. The strip runs with `dropInvalidOptional: true` under `.partial()`, so only a value the
strict schema rejects is dropped and its factory default applies. Valid values are untouched. The
Phase 68 engine's 0600 pre-migration backup holds the original file.

This plan depends on 70-21 because both edit `constants/others.ts`, `common/types.ts`,
`settingsFiles.test.ts` and `settingsVersioning.test.ts`. As the last plan of the gap closure, its
verify also runs the knip check that 70-18 deferred. Nothing may be pushed before this plan lands,
because pre-push runs `pnpm find-deadcode`.

Output: the new chain step, the global version constant bumped to v2, fixtures and tests, and the knip check.
</objective>
