<objective>
D-12's "stripped at load" half: one Phase 68 chain step per GameInfo-bearing store that deletes
undeclared keys, so objects written by an older build come out clean and the strict IPC schema can
treat an unknown key as a real bug. On this machine's profile the strip is a no-op rewrite except
inside dlcList (RESEARCH), so fixtures SYNTHESIZE the old shape.

Task 1 runs before any migration code exists: it snapshots the operator's real store files for the
D-16 gate (an intermediate `pnpm tauri:dev` after this plan would otherwise migrate the profile
before 70-16 could capture it) and builds redacted real-key fixtures, so a key the schemas forgot
fails a test instead of being deleted from user caches.

Note for the user: the first launch after this lands writes one pre-migration backup per store
(seven more backup files), and an older GameLib build will then open these files read-only with one
notice per launch (Phase 68 D-03). Task 1's snapshot at `~/gamelib-phase70-pregate/` is the pre-phase
copy 70-16 relies on; avoid launching `pnpm tauri:dev` between this plan and 70-16 anyway, so the
gate sees a first-launch migration.

Output: pre-gate snapshot, redacted real-key fixtures, strip chains + registration, synthetic fixtures, chain and engine-level tests.
</objective>
