  <action>
    Write .planning/spikes/092-store-mirror-protocol/sim.mjs (plain Node ESM, no dependencies, run with `node sim.mjs [--runs N] [--seed S]`). Model: one Rust store (map + rev, persists before it emits), a sidecar mirror cell (base, pending ops with seq, view = pending applied over base), an event queue Rust -> sidecar delivered in order, a renderer that writes directly to Rust (renderer-native writes from 85-17) and reads pushes, and a sidecar that writes through frames (FIFO). Ops are state-assigning: set(key, value), delete(key), clear, replace(object). Rust events carry `{rev, op, key, value, originSeq?}`; the mirror applies events to base in rev order, drops the pending op whose seq equals originSeq, recomputes the view. Also model a mirror cell created late (loads the persisted state, then receives events already reflected in what it loaded) and two TS names over one file (one cell).

    First run a fixed trace (renderer set a=1, sidecar set a=2 sent before the renderer's event arrives) and assert final Rust state = mirror view and that the sidecar read its own write at every step. Then run 10,000 seeded random traces (2-20 ops each, random interleaving of sends, applies and deliveries) checking: (a) after quiescence every view equals Rust's state; (b) after each local sidecar write, the next sidecar read returns that write until a later op supersedes it; (c) a renderer applying pushes with `rev <= lastSeenRev` dropped never shows an older value after a newer one. Print counts only. Write README.md (setup, invariants, result, any counterexample trace) and start 85-SPIKES.md with a "## S1 — mirror protocol" section stating the verdict and the protocol rules 85-10 and 85-17 must implement (persist before emit, rev under the lock, one FIFO dispatcher, idempotent ops, per-path cells, originSeq acks, push rev filter).
  </action>
