## Deviations from Plan

**1. [Rule 1 - Bug in the plan's own Task 2 `<verify>` block]** The plan's literal verify
one-liner contains a regex escaping bug: `pat=re.compile(r"\b(makeHandlerInvoker|makeListenerCaller)\s*\(\s*.([^.]+)."...)`
uses a bare `.` where a quote-character class (`['"]`) was clearly intended, and `[^.]+` excludes
literal periods rather than quotes. Run as literally written against the post-bucketing tree, it
extracts giant multi-line blobs (spanning from inside one call's arguments to the next literal `.`
character anywhere downstream) instead of channel names, and exits 1 regardless of whether
bucketing is complete — it cannot pass as written.
- **Found during:** Task 2, running the plan's own verify command after bucketing.
- **Fix:** Ran the corrected form (substituting a real quote-character class) as an independent
  confirmation that bucketing is complete — see "Verification Results" below for both outputs.
  Did NOT edit the plan text. Task 3's `preload-surface-gate.py` is the actual, correctly written,
  self-tested, ships-with-the-repo enforcement of this exact invariant (`unlisted=0` against the
  real documents) and supersedes the broken one-liner as the durable check.
- **Files modified:** none (no source file was touched to fix this — it is a verification-command
  issue, not an application bug).
- **Commit:** documented here; no separate commit, folded into Task 2's `f832e3151`.

**2. [Process note, not a Rule 1-3 auto-fix] Task 3's mandated `U-34.5-14` retirement produces a
git-diff deletion the plan's top-level `<verification>` bullet did not anticipate.** That bullet
reads: "`git diff --numstat -- .planning/phases/34.5-*/34.5-UNTESTED-ITEMS.md` shows 0 deletions,
or exactly 1 identified in the SUMMARY as the preamble row counter." Task 2's own commit satisfied
this cleanly (0 deletions, confirmed before committing). Task 3's commit, however, is explicitly
required by the plan's own Task 3 action text to retire `U-34.5-14`'s row in place (`OPEN` →
`RETIRED ...`), which is a same-line text replacement and therefore shows as `1 1` in
`git diff --numstat` for that commit — **1 deletion, but it is the `U-34.5-14` row's own old text,
not the preamble row counter.** This is the same shape prior plans in this ledger used for their
own row retirements (e.g. `U-34.5-16` by 34.5-44, `U-34.5-19` by 34.5-45) without special-casing
it as an exception to a "0 deletions" rule — retiring a row necessarily edits that row's own line.
Recorded here explicitly, honestly, and by line content, per the acceptance criteria's own
instruction to identify (not silently absorb) any deletion. Cumulative across this plan's three
commits: Task 2 contributed 0 deletions to this file; Task 3 contributed exactly 1, which is the
`U-34.5-14` row.

No other deviations. Tasks 1 and 3 executed exactly as written.
