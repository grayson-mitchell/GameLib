## Root cause (recorded here so the gap cycle does not have to re-derive it)

**Diagnosed 2026-08-01 from `~/Library/Logs/GameLib/gamelib.log` and direct source reads. Every
step below was verified directly, not inferred.**

All three non-Steam runner binaries fail to spawn at sidecar startup, before any login is
attempted — the `spawn ./{legendary,gogdl,nile} ENOENT` lines quoted in items 1-3 above all fire
at `(00:06:26)`, roughly 6 seconds before the first login interaction at `(00:06:32)`.

Confirmed causal chain:

1. `src/backend/constants/paths.ts:73` — `publicDir = resolve(app.getAppPath(), app.isPackaged ||
   CI==='e2e' ? 'build' : 'public')`.
2. `src/backend/sidecar/electronStub.ts:207` — `getAppPath: (): string => process.cwd()`.
3. The Rust shell spawns the sidecar with cwd = `src-tauri/`.
4. Therefore `publicDir` resolves to
   `/Users/graysonmitchell/Projects/GameLib/src-tauri/public`, which **does not exist** (verified
   with `ls`: "No such file or directory").
5. `src/backend/utils.ts:505-513` (`archSpecificBinary`) —
   `existsSync(publicDir/bin/arm64/darwin/legendary)` is false, so it falls back to
   `publicDir/bin/x64/darwin/legendary`, which is **never existence-checked**. This is why the log
   shows `x64` on an arm64 Mac — a SYMPTOM of the wrong `publicDir`, not a separate arch defect.
   (`node -p process.arch` → `arm64`; `uname -m` → `arm64`, both confirmed.)
6. `src/backend/launcher.ts:1728-1733` (`callRunner`) — `fullRunnerPath = join(runner.dir, bin)` is
   what gets LOGGED, but then `if (!isWindows && !isAbsolute(bin) && runner.dir) bin = './' + bin`
   and the spawn uses `./legendary` with `cwd: runner.dir`. A nonexistent `runner.dir` yields
   `spawn ./legendary ENOENT`. This is why the logged command shows an absolute path while the
   error shows a relative one.
7. The real binaries exist at `<repo>/public/bin/arm64/darwin/{legendary,gogdl,nile}` and
   `<repo>/public/bin/x64/darwin/{...}` — verified present with `find`.

**Family:** this is the FOURTH recurrence of this project's `publicdir-getapppath-chunking`
failure family. `src/backend/sidecar/bootstrap.ts:156` ALREADY documents that `app.getAppPath()`
resolves to `process.cwd()` under the sidecar — but it only added a loud `existsSync` warning for
the `locales/` directory and never followed the implication through to `bin/`. The knowledge was
present in the codebase; it was never generalized to every `publicDir`-relative consumer.

**Scope of the blast radius:** this defect blocks items 1, 2, 3 directly (the runner binaries
cannot spawn at all) and item 5 transitively (it requires a successful login from items 1-3). Item
4 is independent of this defect (it depends on `GAMELIB_SHELL_EXE`/`app.getPath('exe')`, a
different `pathShim` branch — see precondition 5 above) but was not attempted this run for
unrelated reasons (developer's choice to re-run the full gate after the fix).
