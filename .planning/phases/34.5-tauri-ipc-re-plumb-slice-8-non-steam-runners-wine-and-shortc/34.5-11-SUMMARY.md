## Decisions Made

- **Byte-identical assertion over file-existence assertion for UNSET/EMPTY:** the plan's own wording ("assert by checking the redirected Steam userdata path is unchanged before and after — file list or mtime") ran into the same reality plan 34.5-08 already found for its own pin: `addNonSteamGame` writes an empty `shortcuts.vdf` via `writeShortcutFile` in the SAME iteration, before the `newEntry.Exe = getPath('exe')` assignment that throws. Starting from a missing file would mean "no file exists" flips to "a file was created" regardless of `GAMELIB_SHELL_EXE`'s state — a false negative waiting to happen. The suite instead pre-seeds a real empty-shortcuts.vdf fixture (the same binary literal `nonesteamgame.test.ts` already asserts against) and proves the bytes are unchanged and no entry was appended — the actual security property (T-34.5-39).
- **Un-mocking `nonesteamgame.ts` in the sidecar test file:** plan 34.5-08's blanket mock of this module was correct for its own suite (never invoked, gated by `addSteamShortcuts: false`) but would make this plan's own pin meaningless — a mocked `addNonSteamGame` can't prove anything about the real VDF write. Removed the mock; added the one real dependency it was shielding against (`wiki_game_info`, now auto-mocked) plus safe stand-ins for `steamhelper.ts`'s own two remaining direct-fs dependencies routed through `backend/shortcuts/utils`.
- **Fixed the TDZ bug rather than working around it in the test:** the crash is a real, pre-existing defect reachable in production whenever `generateImage()`'s renderer round-trip fails for a game with no `steamID` match — exactly the fixture shape this plan's SET case legitimately exercises. Masking it with an extra mock would have hidden a live bug instead of fixing it.
