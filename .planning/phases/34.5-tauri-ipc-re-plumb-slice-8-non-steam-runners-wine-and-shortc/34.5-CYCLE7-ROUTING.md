## Standing rules this cycle inherits

Restated from `34.5-CYCLE6-ROUTING.md`, Rule 1 first, unchanged, and now with two live
demonstrations from THIS gate's own run added to Rule 1's own warning list:

1. **Ledger Rule 1 — a row retires ONLY by the observation named in its own cell**, never by a
   passing test suite and never by inference from a neighbouring row. This gate's own run is a
   fresh demonstration in BOTH directions: `U-34.5-07` retired on its OWN clause (library tiles +
   Manage Accounts) despite item 1's overall FAIL being driven by a completely unrelated clause
   (the title bar) — the item's PASS/FAIL status and a ledger row's own retirement bar are
   different mechanisms, and conflating them in either direction (assuming a row is closed because
   its item passed, or assuming a row stays open because its item failed) is exactly the mistake
   this rule exists to prevent. Conversely, `U-34.5-05` stays open despite years of prior partial
   evidence, because ITS OWN specific bar (an eye-transcription) is what the row names, and no
   amount of adjacent evidence (a log-observed `nav host=` change) substitutes for it.
2. **Ledger Rule 2** — any plan that creates a new untested hole adds its row in the same commit.
   `U-34.5-29`/`U-34.5-30` both followed this discipline this run.
3. **Ledger Rule 3** — the gate contract names every OPEN row its own items would have covered as a
   known hole. The NEXT gate contract (whichever plan authors it) must repeat this discipline
   against the now-30-row ledger.
4. **A green suite is necessary and never sufficient.** This phase's live gate has now beaten a
   green suite FOUR times running (this run's own item 4: a persisted `autoInstallDxvk: true`
   setting and a switch showing ON were both trusted-looking signals that turned out to be a stale
   value from over a week earlier, not evidence of anything this session).
5. **A test/contract citation must exercise the PRODUCTION call shape, not a hand-built one.** This
   run's own item 3 discovery — the real "Add shortcut"/"Add to Steam" buttons are BETTER evidence
   than the DevTools-console reconstruction the original contract prescribed, and the console route
   was independently confirmed unusable on this build (a known, recurring friction, not a one-off)
   — extends this rule to gate-contract AUTHORING, not just test authoring: whichever plan writes
   the next contract should route through real UI by default, not console invocations, for exactly
   this reason.
6. **Weight test design over explanatory fit.** `f10-diagnosis-process-lesson`. This run's own
   `F-34.5-G6-18` discovery is a fresh instance: the contract's own text ASSERTED which log line was
   "definitive... fired regardless of caller," and that assertion was never re-verified against the
   actual code path for the SPECIFIC direction the item's own steps exercise — a plausible,
   unifying, and wrong citation, caught only by reading the real handler chain when the expected
   evidence failed to appear.
