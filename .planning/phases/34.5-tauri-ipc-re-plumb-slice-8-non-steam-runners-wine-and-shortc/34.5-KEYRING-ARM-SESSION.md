### A-1 (BINDING) — the runner is **Humble**, not "Steam or Humble"

**Cause: `21f4f4767` (2026-08-17, quick task 260817-d61) — "defer the Steam keyring read from
startup to first Steam action".**

The body's action list says a cold launch with tokens already stored "is a counted, prompt-bearing
moment". **For Steam that is now false by construction.** `SteamLibraryManager.refresh()` exit path
0 (`src/backend/storeManagers/steam/library.ts:699`) tests `isSteamAuthUnlocked()` and returns
`null` *before any keyring read*, emitting:

```
Steam: library refresh deferred until a deliberate Steam action — no keyring_get issued (trigger=startup)
```

The gate is process-scoped, sticky, and **locked at startup by design**; it unlocks only on one of
six deliberate triggers (Install, Update, Play, game-page open, explicit Refresh, Steam login —
`authTrigger.ts`'s `DELIBERATE_TRIGGERS`, an allowlist, so an unrecognised origin falls through to
the locked `'startup'`). A Steam cold launch therefore yields **zero prompts and zero
`keyring_get`s, and this is CORRECT behaviour, not a failure.**

Scoring consequence, stated so it cannot be misread:

- The session runs on **Humble**. `humbleSecretStore`'s `getToken()` has no `authTrigger` equivalent

- `U-34.5-01`'s condition (4) is satisfiable on a Humble slot alone — the condition names "a real
  slot", and `humble-session`/`humble-csrf` are real slots
  (`keyringTokenStore.ts:27-28`).
