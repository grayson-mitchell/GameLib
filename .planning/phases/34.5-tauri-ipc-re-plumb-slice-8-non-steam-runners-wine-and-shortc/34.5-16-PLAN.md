<objective>
Close the root cause of live-gate items 1, 2, 3 and (transitively) 5: under the sidecar,
`app.getAppPath()` returns `process.cwd()` (`src-tauri/`), so `publicDir` resolves to
`src-tauri/public`, which does not exist, and every bundled asset — including the
`legendary`/`gogdl`/`nile`/`comet` runner binaries — is unreachable.

This plan does NOT patch the `bin/` path. Patching only `bin/` is the exact mistake that produced
this failure: `src/backend/sidecar/bootstrap.ts:156` already documented the
`getAppPath()`/`process.cwd()` equivalence in 2026 and generalised it no further than `locales/`,
which is why this is the FOURTH recurrence of the `publicdir-getapppath-chunking` family. Instead
this plan sweeps every consumer and installs ONE authoritative app-root resolution for the sidecar.

Purpose: make the runner binaries spawnable under `pnpm tauri:dev` so the blocking gate re-run
(plan 34.5-20) is worth a human's time.
Output: a consumer sweep document, a Rust-side `GAMELIB_APP_ROOT` handoff on both spawn paths, an
`electronStub.getAppPath()` that consumes it, and a new classified jest suite.
</objective>

| Rust shell → sidecar child environment | `GAMELIB_APP_ROOT` crosses here; the parent is the authority for its own install location |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.5-G1-01 | Tampering / Elevation | `electronStub.getAppPath()` → `publicDir` → `archSpecificBinary` → spawn | mitigate | The value is accepted ONLY from the process environment set by the parent shell at spawn time — never from renderer IPC, `configStore`, a settings file, or any channel argument. No code path in this plan writes `GAMELIB_APP_ROOT`. An attacker able to set the sidecar's environment already controls the parent process and can spawn arbitrary binaries directly, so this widens no boundary; documented in `34.5-APP-ROOT-SWEEP.md` § 2 |
| T-34.5-G1-02 | Spoofing | Silent fallback to a nonexistent binary path | mitigate | Deferred to plan 34.5-17 by design (`archSpecificBinary` is that plan's file); this plan's `getAppPath()` fallback is deliberately non-throwing because it runs at module import before the logger exists, and plan 34.5-18's boot self-check supplies the loudness |
