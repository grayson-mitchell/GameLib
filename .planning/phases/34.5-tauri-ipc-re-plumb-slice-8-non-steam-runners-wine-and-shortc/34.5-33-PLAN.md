(`Login Successful`, `Saved username to config file`) followed by `No cache found, getting data from
gog...` four times with no completion line — while `Steam: fetched 377 owned games` →
`Steam library sync complete: 377 games` appeared in the same session. Those Steam lines ARE the GOG
refresh calls' actual effect. The handler is a Phase 27 walking-skeleton stub
(`steamFlowRegistration.ts:62`, `ipcMain.handle('refreshLibrary', async () => { await
steamLibraryManager.refresh() })`) that takes no arguments and was never replaced when the runner
libraries were ported.

never print `undefined`.

**Live observable that would prove this — nothing else counts.** In a live `pnpm tauri:dev` session
after a successful GOG login, `~/Library/Logs/GameLib/gamelib.log` must show a completion line naming
`gog` and a game count following `No cache found, getting data from gog...`, and the Library UI must
display GOG games. A passing test suite proves the dispatch wiring only. This phase has failed its
gate twice with 3279, 3387 and 3447 tests green — do NOT record this defect as closed on unit
