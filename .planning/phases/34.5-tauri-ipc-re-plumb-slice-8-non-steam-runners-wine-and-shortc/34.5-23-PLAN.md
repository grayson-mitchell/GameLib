<objective>
Close layer 1 of F-34.5-G6-02: the captured OAuth outcome never reaches the renderer, because
`oauthCaptureLogin`'s round-trip is bounded at 60 seconds by the Rust shell while the sidecar's own
capture deadline is 300 seconds — and the resulting rejection is swallowed as an unhandled promise
rejection by an unprotected `await`.

Purpose: this single mismatch accounts for every observation the 2026-08-01 gate recorded for items
1, 2 and 3 — six backend terminal outcomes (`status=timeout` ×4, `status=captured` ×2) and ZERO
corresponding `[useTauriOAuthLogin]` log lines, with the UI frozen on the pre-capture "Signing in…"
panel. Every real attempt exceeded 60 s: GOG captured at 68 s, Amazon at 91 s, Epic timed out at
300 s ×3.

Output: the channel exempted from the bound, the renderer failure made loud, and a standing guard so
the class cannot recur silently.

**This plan does NOT make a login succeed on its own.** Layer 2 (nothing runs the post-login library
refresh) is plan 34.5-26. Do not attempt it here.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Rust shell → sidecar | Renderer-supplied `channel` name selects the timeout policy; an attacker-influencable channel string could select "wait forever" |
| remote login page → capture outcome → renderer log | A captured OAuth code crosses into a log a user may upload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.5-G6-08 | Denial of service | `timeout_for` / `LONG_RUNNING_CHANNELS` | mitigate | Exempt exactly one named channel; `INVOKE_TIMEOUT` stays 60 s for every other channel, pinned by the existing literal assertion. The exemption list is compile-time and cannot be extended from the renderer |
| T-34.5-G6-09 | Denial of service | never-settling `oauthCaptureLogin` promise | accept | `captureOAuthLogin`'s own 300 000 ms `DEFAULT_DEADLINE_MS` always settles the sidecar side, and a dead sidecar wakes `rx.recv()` with a disconnect error. Documented as the honest failure mode in the existing `LONG_RUNNING_CHANNELS` doc comment |
| T-34.5-G6-10 | Information disclosure | the new `capture-transport-failed` log line | mitigate | The line carries `runner` and the transport error `message` only — never `outcome.code`, `outcome.redirectUrl`, or any URL. Acceptance criteria pin the literal so a future edit that widens it is visible in review |
| T-34.5-G6-SC | Tampering | npm/cargo installs | mitigate | This plan installs no packages. `cargo test`/`cargo check` run against the existing lockfile. Any new dependency requires a `slopcheck` pass and a blocking human checkpoint first |
