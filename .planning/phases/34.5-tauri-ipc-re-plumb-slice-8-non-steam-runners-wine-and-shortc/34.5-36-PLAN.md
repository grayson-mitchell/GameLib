<objective>
Build the developer-scoped item the discriminator's `## Routing` section added to this cycle: a
dev-only local secret vault that removes macOS Keychain prompts as a CONFOUNDER from future gate runs.

Purpose: none of the five blocking-gate items actually touch the keyring. The three login flows are
file-backed (`user.json`, `auth.json`, `nile_*` — see `34.5-CONTEXT.md` D-12), and items 4 and 5 are
`addToSteam` and `runWineCommand`. Keychain dialogs are therefore noise in a gate run, and the
2026-08-01 checkpoint lost time to two of them for a slot no gate item exercises. Injection seams
already exist: `setTokenStore()` for Steam's refresh token and `setHumbleSecretStore()` for Humble's
two secrets.

Output: `devSecretVault.ts`, its bootstrap wiring, and the populated `U-34.5-01` ledger row.

**This is a HIGH-severity surface and its three guardrails are non-negotiable.** This project has
already shipped a credential store that persisted secrets in PLAINTEXT SILENTLY — the `safeStorage`
stub — and that became finding F-1 at a live gate. The guardrails, carried from that lesson, are:
(a) opt-in via environment variable only, never by default; (b) a LOUD warning on install AND on
every read and every write; (c) REFUSED in production builds, failing CLOSED when the build kind
cannot be determined. Each must be verifiable, not assumed.

**Stated cost, tracked not implied.** A gate run against a file vault leaves the real KEYCHAIN PATH
UNPROVEN. That is the exact trap Phase 34.4.1's gate fell into when a struck precondition left
domain-scoping untested and nothing tracked the hole. Task 3 makes the hole a tracked row, not a
footnote.
</objective>
