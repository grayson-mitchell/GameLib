## Evidence-handling rule (T-34.5-G6-02)

Restated and extended from every prior contract's own version, binding on every Result slot and
every pasted excerpt below. This document lives in a public fork's repository.

**Never paste, in any Result slot or excerpt, any of the following six value classes:**
1. an `access_token` value
2. a `refresh_token` value
3. a cookie value
4. a session identifier
5. an OAuth `code=` value
6. a Steam `userdata` account id

Quote only the specific log lines an item or precondition names. If a required line contains one of
these values inline, **redact it in place** (e.g. `access_token=<REDACTED>`, `userdata/<REDACTED>`)
rather than omitting the whole line — the surrounding structure (which field was populated, that a
value was non-empty) is still evidence; the value itself is not needed to prove a PASS.

**Why this is mechanical, not advisory, in this project specifically:** a real Steam account id was
committed unredacted once in this phase's own history, and live PKCE material was committed once
and caught only by a post-commit audit (see the project memory `phase-34-9-gate-failed-packaging-blocked.md`).
Two near-misses in one project is a pattern, not a one-off.

**The mandatory pre-commit sweep.** Before committing the FILLED contract (i.e. before the operator
commits 34.5-51's completed run of this document), run a redaction sweep over the staged diff and
paste its output into the run's own record:

```
git diff --cached -- 34.5-LIVE-GATE-RERUN-3.md | grep -nE "access_token=[A-Za-z0-9._+/=-]{4,}|refresh_token=[A-Za-z0-9._+/=-]{4,}|Cookie: [A-Za-z0-9._+/=-]{4,}|session(id|Cookie)=[A-Za-z0-9._+/=-]{4,}|code=[A-Za-z0-9_-]{6,}|userdata/[0-9]"
```

**Why the value classes require 4+ token-shaped characters rather than "any character but `<`":**
this plan's own Part D specimen validation found that a naive `access_token=[^<]`-style pattern
self-matches its OWN quoted regex source the moment the whole document is staged fresh (the
character immediately following `access_token=` in that pattern's own text is `[`, which is not
`<`) — a false positive with zero credential content, on this document's own first commit. The
value classes above require 4 or more token-alphabet characters (`A-Za-z0-9._+/=-`), which regex
punctuation (`[`, `^`, `<`, `]`, `(`, `)`, `|`) never satisfies in a run of 4, so the sweep's own
documentation cannot trigger it — verified against 11 cases (5 safe, 6 real-leak-shaped) during
this plan's authoring, each behaving as expected. Any match that survives this sweep is a live
credential leak — do not commit until it is redacted in place (e.g. `access_token=<REDACTED>`,
which contains no run of 4 token-alphabet characters after `=` and correctly does not match).

**The published-SteamID64 exception, carried verbatim from `deferred-items.md` item 23.** The 37
already-published files containing the SteamID64 profile-URL number are an **expected, accepted**
sweep match by developer decision (redact-forward, not rewrite-history) — do NOT re-raise a hit
against one of those 37 files as a new finding, and do not spend cycle time on it. Any **NEW**
unredacted account id, token, cookie, session id, or OAuth code — in this document or any other
file this run touches — is still in scope and still blocks the commit.
