## Phase Boundary

Port the inherited non-Steam runner surface onto the Tauri sidecar. The inventory lists **57
channels**; this discussion cut that to **38 ported in 34.5**, with 3 dropped permanently and 16
deferred to a new Phase 34.6. Additive and reversible — the Electron build keeps working unchanged.

**The 38 ported, by cluster:**

| Count | Cluster |
|---:|---|
| 11 | Auth + sign-out — Epic/GOG/Amazon (zoom removed) |
| 9 | Wine versions + DXVK/VKD3D (winetricks removed) |
| 7 | Shortcuts + add-to-Steam |
| 4 | Runner CLI versions (incl. `getCometVersion` — GOG's, see D-04) |

| 2 | Saves sync — `syncSaves`, `syncGOGSaves` |
| 2 | Runtime — `downloadRuntime`, `isRuntimeInstalled` |

**NOT in this phase:** Zoom auth (dropped), EOS overlay / SteamGridDB / winetricks (Phase 34.6).

<decisions>
## Implementation Decisions

### Scope — keep/drop of the 57 (the call the ROADMAP explicitly parked for this phase)

- **D-01:** Keep/drop judged **case-by-case on real usage**, not by a blanket principle (neither
  "Heroic parity — port all 57" nor "trim to core value"). Each cluster was assessed on whether it
  is load-bearing for a working launcher.
- **D-02:** **Zoom (3 channels — `authZoom`, `getZoomUserInfo`, `logoutZoom`) is DROPPED
  permanently.** Never ported; Zoom sign-in dies when Phase 35 deletes the Electron path. Rationale:
  absent from GameLib's stated core value ("Epic, GOG, Amazon, and Steam"), smallest storefront,
  purely inherited from Heroic. **Side benefit: this removes half of `T-34.4.1-44b`'s
  host-anchoring obligation, which covered nile AND zoom — only nile now needs it (see D-11).**
- **D-03:** **EOS overlay (8), SteamGridDB artwork (5) and winetricks (3) are DEFERRED, not
  dropped** — 16 channels total, tracked so they survive the cutover. EOS is Epic (core value) and
  is not needed to install or launch, only for overlay features, so the regression would be real but
  narrow; SteamGridDB is a pure enhancement behind a user-supplied API key; winetricks is
  Linux-centric power-user tooling.
- **D-04 (correction — carry this forward):** **`getCometVersion` is GOG's**, not Zoom's. `comet` is
  the GOG Galaxy Communication replacement, gated on `gameInfo.runner === 'gog'`
  (`src/backend/launcher.ts:973`). An option label during this discussion wrongly bundled it with
  Zoom. **`getCometVersion` IS ported in 34.5** under Runner CLI versions. Zoom is exactly 3
  channels, so the candidate set was 19, not 20.

### Roadmap consequence — a new Phase 34.6 is REQUIRED

- **D-05:** **Insert a new Phase 34.6 before Phase 35** to port the 16 deferred channels. Deferring
  is not free: Phase 35's own roadmap entry requires the IPC re-plumb to be **complete** before
  cutover, so an untracked deferral would silently become accepted loss. Rejected alternatives:
  Phase 35 absorbing them as accepted loss (kills the three clusters for real); folding them into
  Phase 35 (loads the riskiest phase — the one that deliberately breaks the additive/reversible
  invariant — with 16 extra channels); deciding at 34.5 verification (this project's own history
  shows an open obligation is exactly how UAT debt accumulates).
- **ROADMAP ACTION, not yet performed:** 34.6 has not been inserted into `ROADMAP.md`. Do this
  before or during 34.5 planning so Phase 35's precondition stays honest.

### Slice shape

- **D-06:** **Seam-first, single phase.** Wave 1 establishes the cross-cutting seams BEFORE any
  channel porting. Rationale: 34.4 did not split because of channel count (31 was normal for a
  slice) — it split because a cross-cutting seam (the `<webview>`/`session.fromPartition` login
  path) was discovered *inside* it and had to be carved out late into 34.4.1, making its true cost
  38 channels across 19 plans in two phases. **Coupling forces splits, not volume.** Resolving the
  seams up front is the direct lesson. Rejected: one phase split reactively (the carve-out arrives
  late and expensive); pre-splitting into 34.5 + 34.5.1 (two live gates instead of one).
- **D-07:** **The three wave-1 seams are:** (1) extend `pathShim` with the missing path names and
  settle `exe`'s Tauri semantics (D-09/D-10), (2) host-anchor nile's redirect match (D-11),
  (3) establish wine-command execution (D-13).
- **D-08:** **Blocking live gate covering all three logins** (Epic, GOG, Amazon) on macOS — same
  standard as every prior slice, no advisory mode, no pre-authorized override. Rejected: one runner
  live + two declared unit-proven-only; auth-only gating with Wine/shortcuts deferred to UAT.
  Justification for the cost: 34.4.1's gate has just demonstrated that a live gate catches what a
  fully-green 3095-test suite cannot.

### Paths and credential handling

- **D-09 (finding, established by source reading — not yet fixed):** `src/backend/sidecar/pathShim.ts`
  implements only **4** path names (`appData`, `userData`, `temp`, `home`) and **throws loudly** on
  anything else (deliberate — "Unimplemented names throw loudly rather than silently returning
  garbage"). The backend uses **5**, and the three missing ones are all in 34.5's shortcuts cluster:
  - `desktop` — `src/backend/shortcuts/shortcuts/shortcuts.ts:156,161,162` → `addShortcut`,
    `removeShortcut`, `shortcutsExists`
  - `exe` — `src/backend/shortcuts/nonesteamgame/nonesteamgame.ts:258` → `addToSteam`,
    `removeFromSteam`, `isAddedToSteam`
  - `documents` — 1 site, cluster not yet confirmed

  **Consequence: the 7-channel shortcuts cluster throws the moment it is ported, until the shim is
  extended.** This is wave-1 work, not a mid-execution discovery.
- **D-10:** **`app.getPath('exe')` must resolve to the Tauri shell binary.** This is not merely a
  missing stub name — `nonesteamgame.ts:258` writes the value into a **Steam shortcut VDF as the
  launch command**, so a wrong value produces Steam shortcuts that launch the wrong executable. A
  semantic divergence between builds, not a stub gap. **Implementation note for research: the
  sidecar is a node process, so `process.execPath` is node — the Tauri shell must pass its own
  executable path down to the sidecar.** Explicitly rejected: `process.execPath` (would write the
  node interpreter into the VDF).
- **D-11:** **`T-34.4.1-44b`'s host-anchoring fix lands in wave 1, before any credential flow
  exists.** It is the stated precondition inherited from 34.4.1: nile captures via a **host-free
  param match** inherited from the Electron original, harmless today only because the receiving
  channel rejects. Only nile needs it now (zoom dropped per D-02). Rejected: folding it into the
  nile auth plan; a separate hardening plan with its own gate.
- **D-12:** The **plaintext-token fallback is REAL and deliberate**, but it is **not on this
  phase's credential path**. Stated precisely, because an earlier draft of this decision wrongly
  dismissed it:
  - `ElectronTokenStore` (`src/backend/storeManagers/steam/tokenStore.ts:64`) **intentionally
    keeps** a plaintext fallback — warn-then-store-plaintext on `setToken` when
    `safeStorage.isEncryptionAvailable()` is false, plus a legacy non-prefixed plaintext read on
    `getToken`. Per that file's own header (lines 25-32) this is a documented **D-11 divergence**,
    shipped Electron behavior preserved byte-identical per REQ-28-07 — "not a bug".
  - It is the **module default**: `tokenStore.ts:123` sets
    `let activeTokenStore: TokenStore = new ElectronTokenStore()`. The sidecar only escapes it
    because `bootstrap.ts:204` calls `installTokenStore(new SidecarKeyringTokenStore())` at init.
    **No assertion or throw-fast enforces that ordering** — that is the latent risk, and it is
    real.
  - The sidecar implementation has **no fallback at all**
    (`src/backend/sidecar/keyringTokenStore.ts:33`: "No env-var, in-memory, or plaintext fallback
    exists here (D-08/REQ-28-07)").
  - **Why it is nonetheless out of 34.5's scope:** this store is **Steam's refresh-token** path.
    34.5's runners do not use it. Epic/GOG/Amazon persist *profile* data via `configStore`
    (`legendary/user.ts:98 configStore.set('userInfo', …)`,
    `gog/user.ts:105 configStore.set('userData', …)`,
    `nile/user.ts:120 configStore.set('userData', …)`) while their real auth tokens are held by the
    runner CLIs in their own config dirs (`legendaryConfig`, `gogdlConfig`, `gog_store`,
    `nile_store`). `pathShim` resolves `userData` to Electron's own OS convention, so those paths
    already line up.
  - **Therefore: 34.5's credential risk is path resolution, not token encryption.** The
    `ElectronTokenStore` fallback remains a genuine open hardening item for the Steam path — do not
    treat this decision as having cleared it.

  **What the runners actually do:** Epic, GOG and Amazon persist *profile* data via `configStore`
  (electron-store) — `legendary/user.ts:98 configStore.set('userInfo', …)`,
  `gog/user.ts:105 configStore.set('userData', …)`, `nile/user.ts:120 configStore.set('userData', …)`
  — while the real auth tokens are held by the runner CLIs in their own config dirs
  (`legendaryConfig`, `gogdlConfig`, `gog_store`, `nile_store`). `pathShim` resolves `userData` to
  Electron's own OS convention, so those paths already line up. **The credential risk here is path
  resolution, not keyring.**

### Wine tooling

- **D-13:** **Port all 9 Wine channels as-is and trust the existing platform guards.** The platform
  logic is already inherited and correct — `src/backend/tools/index.ts:73`
  (`if (tool.os !== process.platform) return`), `:228` (on macOS only `dxvk` is permitted, **VKD3D
  already excluded**), `:245` (`tool = isMac ? 'dxvk-macOS' : tool`), `:219` (recognizes `-DXMT`
  DirectX→Metal Wine builds), `:807`/`:843` (`if (!isLinux)` early returns), `:642`
  (`isMac ? macEnvs : linuxEnvs`). The sidecar is a real node process on the same OS, so
  `process.platform` behaves identically. Re-deciding platform scope would mean re-implementing
  correct upstream behavior. Explicitly rejected: declaring the cluster macOS-degraded — inaccurate,
  since real macOS support exists (`dxvk-macOS`, DXMT).
- **D-14:** **`runWineCommand` is a wave-1 seam**, not just an early plan in its cluster — its
  consumers span the phase (launcher, tools) and reach beyond the 9 Wine channels.
- **D-15 (inherited gotcha that applies here):** the macOS missing-deps path
  (`tools/index.ts:794`) shows a **dialog**. Under the sidecar a dialog rejection **crashes the
  app** — it must RESOLVE a safe-decline sentinel, never reject, in fire-and-forget paths.

### Claude's Discretion

- Exact wave composition and plan count beyond "wave 1 = the three seams". Healthy prior slices ran
  ~3–4 channels per plan (34.1: 33ch/8 plans, 34.3: 29ch/9, 34.4: 31ch/10), putting 38 channels at
  roughly 10–13 plans. 34.2's 30 plans were the product of four gap cycles, not volume — that is the
  failure mode to avoid, not a size precedent.
- Whether `documents` (D-09) belongs to this phase's surface at all.
- How the Tauri shell hands its executable path to the sidecar (D-10) — mechanism unspecified.

<specifics>
## Specific Ideas

- The keep/drop framing that drove D-02/D-03: **"drop" costs nothing now** because this phase is
  additive and the Electron build keeps working — it bites at Phase 35's cutover. So the real
  question was *"which clusters are you willing to lose at cutover?"*, which is what separated
  DROP (zoom) from DEFER (the other three).
- The upstream-merge tension was weighed explicitly: CLAUDE.md requires staying mergeable with
  Heroic, and every dropped cluster is a future merge-conflict zone. Zoom was accepted as the one
  divergence because it is absent from GameLib's own core value.
