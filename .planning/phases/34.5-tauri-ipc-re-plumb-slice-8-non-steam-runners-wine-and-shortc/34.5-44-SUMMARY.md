# Phase 34.5 Plan 44: Single-Instance Guard + Deep-Link Delivery Summary

**Hand-rolled std-only Unix single-instance guard runs before `tauri::Builder::default()` so a
Steam/desktop shortcut launched while GameLib is already running delivers its `gamelib://` deep
link to the existing instance over a `0700`/`0600` Unix socket instead of spawning a second full
GameLib process — live-verified end to end (accept loop → sidecar `handleProtocolUrl` → real
`gamelib.log` `[ProtocolHandler]: Received` line) on real hardware.**

- **Completed:** 2026-08-11
- **Tasks:** 4 completed
- **Files modified:** 7

## Accomplishments

- `src-tauri/src/main.rs` gained five pure, `AppHandle`-free helpers (`protocol_url_arg`,
  `cli_no_gui`, `sidecar_forward_args`, `single_instance_socket_path`, `single_instance_dir`)
  with 15 new `#[cfg(test)]` cases (`cargo test` **119 → 134**), and a hand-rolled
  `SingleInstanceRole`/`acquire_single_instance` Unix single-instance guard that runs BEFORE
  `tauri::Builder::default()` — a secondary launch's `std::process::exit(0)` fires before
  `.setup()` can ever call `spawn_sidecar`.
- Spawn-time argv forwarding: `spawn_sidecar` computes an allow-listed `forward_args` vector
  ONCE (`--no-gui` + a validated `gamelib://` URL, nothing else — `--no-sandbox` and every
  other Electron-shaped flag is dropped) and hands it to both `spawn_sidecar_dev` and
  `spawn_sidecar_packaged`, neither of which calls `sidecar_forward_args` itself.
- The primary's deep-link accept loop: a spawned thread owns the bound `UnixListener`, reads at
  most one bounded line per connection, and either raises the main window
  (`__GAMELIB_FOCUS__` sentinel) or re-validates the payload through `protocol_url_arg` AGAIN
  (defence in depth, T-34.5-G6-20) before invoking the sidecar's `handleProtocolUrl` channel.
- `--no-gui` now actually suppresses BOTH devtools and the main window (gate 3 recorded both as
  ignored); `RunEvent::Exit` removes the socket file on a clean quit.
- `bootstrap.ts` gained `deliverStartupProtocolUrl` (cold-start, called last in `init()`, after
  `READY_SENTINEL`) and `registerProtocolUrlHandler` (registers `handleProtocolUrl`, called
  right after `startRpcServer` and before `READY_SENTINEL`, so the shell can never race an
  unregistered channel). Neither awaits the launch — `handleProtocolUrl` is deliberately absent
  from `LONG_RUNNING_CHANNELS`, pinned by Task 1's own
  `handle_protocol_url_channel_is_bounded_at_invoke_timeout` Rust test.
- `getInstallInfo` (transferred from plan 34.5-43's ledger row `U-34.5-16`) is now exempt from
  the 60s `INVOKE_TIMEOUT`; the array-iterating Rust test and the JS set-equality gate both stay
  green, unedited beyond the array addition itself.
- **Live-verified on real hardware** (see transcripts below): a cold `pnpm tauri:dev` start
  showed `forward_args=[]`; a second bare launch and a second deep-link launch both stayed at
  exactly ONE `gamelib-shell` process; after Task 3 landed, a full end-to-end second-instance
  deep link produced `[shell] delivered single-instance deep link to sidecar: ok` in the shell's
  own log AND `(HH:MM:SS) [INFO]: [ProtocolHandler]: Received gamelib://launch?appName=…` in the
  REAL `~/Library/Logs/GameLib/gamelib.log` — the exact observable U-34.5-13's own retirement
  bar names, though **U-34.5-13 itself is NOT retired by this plan** (see "Next Phase
  Readiness").
- The Electron build path was live-verified unaffected: `npm start` reaches its normal window
  and actively syncs the real Steam library with zero errors (SEAM Invariant A).
