`SidecarKeyringSlotStore(<slot>).<method>(): ...`:

| Line | Level | Literal shape | What it means |
|---|---|---|---|
| :254 | INFO | `SidecarKeyringSlotStore(<slot>).getToken(): issuing keyring_get (may prompt)` | Emitted before every REAL Keychain round trip. The ONLY read call that can raise a prompt — the count of these lines per slot is the log-side counterpart to the operator's observed prompt count, exactly what `U-34.5-10`'s bar asks to cross-check against. |
| :296 | INFO | `SidecarKeyringSlotStore(<slot>).getToken(): keyring_get ok present=<bool> len=<n>` | Read SUCCEEDED. |
| :261 | WARN | `SidecarKeyringSlotStore(<slot>).getToken(): keyring_get failed: <err>` | Read failed. |
| :277 | WARN | `keyring failure memoized slot=<slot> class=<...> ms=120000` | Memo CREATED. |
| :318 | INFO | `SidecarKeyringSlotStore(<slot>).setToken(): keyring_set ok len=<n>` | Write round trip — also a real round trip, belongs in the same prompt accounting. |
| :344 | INFO | `SidecarKeyringSlotStore(<slot>).clearToken(): keyring_delete ok` | Sign-out delete round trip — sign-out IS a delete, also belongs in the same prompt accounting. |
| :214 | DEBUG | `SidecarKeyringSlotStore(<slot>).getToken(): served from cache, no keyring_get issued` | Warm cache — no round trip, no prompt possible. |
| :221 | DEBUG | `SidecarKeyringSlotStore(<slot>).getToken(): joined in-flight read, no additional keyring_get issued` | Deduped — no round trip, no prompt possible. |

**Known limit, recorded now rather than discovered mid-session:** the memo HIT path
(`keyringTokenStore.ts:232-237`) returns early with **NO log line of any kind**. A prompt
suppressed by an already-active memo is provable only by the **ABSENCE** of an `issuing` line,
never by a positive line. Do not soften this — an operator who expects a "memo hit" line will
misread its absence as a missing round trip.

None of these lines carries a secret: slot name, presence and length only, never a value.
