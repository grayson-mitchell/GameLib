### Process notes (not Rule 1-4 deviations)

**1. Task 1's test harness deviates from the plan's literal `jest.isolateModules` suggestion.**
- **Found during:** Task 1, writing the three behaviour-row tests.
- **Issue:** The plan's action text says "use `jest.isolateModules` so the module-scope
  memoisation... cannot leak between cases." Following that literally, combined with this file's
  existing `jest.mock('electron')` (automock, no factory) and its top-level
  `import * as utils from '../utils'`, produced a fresh module instance whose `app.getPath`
  `jest.fn()` had its `mockImplementation` stripped — `constants/paths.ts`'s module-scope
  `app.getPath('appData')`/`app.getPath('userData')` calls then threw
  `TypeError: The "path" argument must be of type string. Received undefined`. Reproduced
  consistently: any prior call into the `utils` module (even a synchronous, electron-unrelated
  one) before the `isolateModules` block, and even the isolated block being the FIRST test in the
  file, triggered the same failure — narrowed down to Jest's manual-mock resolution for a module
  under a literal `__mocks__/` directory being keyed by module identity, not by which module
  registry (isolated or outer) requested it.
  - Confirmed via direct probing that `jest.requireActual('../__mocks__/electron')` returned an
    `app.getPath` that `isMockFunction()` reported as `true` but whose call returned `undefined`
    — i.e. the SAME already-reset mock function object, not an independent fresh one.
- **Fix:** Instead of forcing a fresh module instance, the suite drives the three behaviour rows
  through THREE DIFFERENT exported getters (`getLegendaryBin`, `getGOGdlBin`, `getCometBin`),
  each of which memoises into its own separate module-scope `let` (`defaultLegendaryPath`,
  `defaultGogdlPath`, `defaultCometPath`). Since each test calls a DIFFERENT getter exactly once,
  no case can observe another case's memoised result — the plan's actual goal (no cross-case
  leakage) is met without needing a fresh module load. `existsSync` was added to the file's
  existing top-level `graceful-fs` mock (alongside `readFileSync`, following the same
  `.mockImplementation()`-per-test pattern already used for `readFileSync` in this file's
  `getCurrentChangelog` tests).
- **Files modified:** `src/backend/__tests__/utils.test.ts`.
- **Verification:** All three tests pass; `npx jest src/backend/__tests__/utils.test.ts
  src/backend/__tests__/launcher_callRunner.test.ts` exits 0 (15/15); full backend suite (2897
  tests) and full `npm run test:ci` (3459 tests) both green.
- **Committed in:** `a79b33163` (Task 1 commit).
- **Impact on plan:** None on scope, correctness, or coverage — all three behaviour rows named in
  the plan's `<behavior>` block are covered, driven through exported getters as the action text
  also explicitly requires ("Drive them through the exported getters... rather than the private
  function"). Documented for transparency since the literal mechanism named in the plan
  (`jest.isolateModules`) was not used for this task.
