# Phase 64 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Reading guide.** Locked inputs: `64-CONTEXT.md` D-01..D-16 and `sketch-findings-gamelib` (treated as
locked, not re-asked). Everything marked **[OD-n]** is an open UI decision from `64-RESEARCH.md` that
the user has not yet answered; the contract adopts the research recommendation provisionally and lists
the alternative in `## Open Decisions` so a single answer can flip it.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not applicable: the app is MUI 5 + hand-written SCSS/CSS on Tauri, no Tailwind, no `components.json`. Introducing shadcn would add a second design system; not proposed) |
| Preset | not applicable |
| Component library | MUI (`@mui/material`) plus in-repo `src/frontend/components/UI/*` |
| Icon library | Font Awesome free (`@fortawesome/react-fontawesome` + `free-solid-svg-icons`), as `NavShell/SettingsPanel` does. MUI icons only where a neighbour already uses them |
| Font | `Rubik` (`--primary-font-family`, headings and buttons) and `Cabin` (`--secondary-font-family`, body), from `styles/_typography.scss`. Both are user-overridable in this same screen; never hardcode a family |

Theming rule for all new chrome: every colour comes from a token on `body` (the **active, saved** theme).
No new colour literals in component CSS, except inside the thumbnail/preview SVG, which paints from the
**draft or stored token map** instead (see `## Thumbnail Anatomy`). This is what satisfies D-05: a draft
can never restyle the editor itself.

## Spacing Scale

Declared values (multiples of 4). Build with the existing `--space-*-fixed` px tokens
(`--space-unit-fixed` = 16px); use `calc(var(--space-unit-fixed) * n)` for 24 / 32 / 48. Use the fixed
(px) tokens, not the `em` tokens, so the editor does not scale with a font-size change.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-button gaps, chip padding, thumbnail-to-name gap |
| sm | 8px | Card inner padding, token-row inner gaps, action-button gaps |
| md | 16px | Grid gap between cards, row padding, pane gutters on narrow layout |
| lg | 24px | Gap between token groups, header-to-body spacing |
| xl | 32px | Gap between the two editor panes, gap between the two gallery groups |
| 2xl | 48px | Gap between the gallery section and the rest of Appearance |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Icon-only buttons are a 32px square hit area (the swatch button is 32px too). 32px is a multiple of 4; the glyph inside is 16px.
- Thumbnail internals are drawn in a 160x100 SVG viewBox and are exempt from this scale (see `## Thumbnail Anatomy`).
- Card minimum width 208px and picker popover width 232px are layout constants, not spacing.

Layout constraint (verified in `Settings/index.css`): `.settingsWrapper` is capped at 513px. The gallery
needs more room, so it renders as a **full-width block above that column**, up to 960px wide, and the existing
controls (zoom, fonts, toggles) stay in the 513px column beneath it with a 48px gap between them.

## Typography

New text in this phase uses 4 sizes from the app's 1.2-ratio scale and 2 weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption (`--text-sm`) | 13.33px | 400 (`--regular`) | 1.5 |
| Body (`--text-md`) | 16px | 400 (`--regular`) | 1.5 |
| Heading (`--text-lg`) | 19.2px | 600 (`--semibold`) | 1.2 |
| Display (`--text-4xl`) | 39.81px | existing `h1` (bold) | 1.2 |

- Caption: token names (`--body-background`), contrast warnings, chips, "Based on", hex values inside inputs, ratio text.
- Body: token labels, card theme names, dialog text, empty-state body.
- Heading: group headings ("Built-in", "Your themes", "Surfaces", ...), the theme name in the editor header, empty-state heading.
- Display: the existing `h1.headerTitle` only ("Appearance", "Edit theme"). Not newly specified.
- Reused existing components keep their own weight (`.button` is 500, headings are 700). Do not add either weight to new text.
- Token names and the gradient textarea use the app monospace stack from `_typography.scss` (the `code` rule) at Caption size.

Layout constraint (verified in `Accessibility/index.css:40-45`): `.Accessibility label, span, select, option` are forced to `--text-xl` with `!important`. Gallery markup inside `.Accessibility` must therefore use `div`, `p`, `h2`, `h3`, `button` and `small`, never bare `span` or `label`, or the sizes above will not apply. The editor is its own route and must not carry the `.Accessibility` class.

## Color

Chrome colours are role tokens of the **active saved theme**, so the table gives the token and the midnightMirage
(default) reference value. The 60/30/10 split is preserved in every theme because it is expressed in tokens.

| Role | Token (midnightMirage value) | Usage |
|------|------------------------------|-------|
| Dominant (60%) | `--body-background` (#070a0b) | Page background, editor background |
| Secondary (30%) | `--background` (#161c1e) and `--navbar-background` (#161c1e) | Gallery cards, token-row surface, picker popover surface |
| Accent (10%) | `--accent` (#8bffff) | See reserved list below |
| Destructive | `--status-danger` (#f97881) | Delete icon hover/focus, "Delete theme" button (`.button.is-danger`) only |

Text: `--text-default` (#caf3fd) for labels and warning text, `--text-secondary` (#b1b1b1) for captions and the
inactive Delete/Rename/Duplicate glyphs. Borders: `--border-color` (gray), which the built-in themes hold at 3:1 or better against body and modal surfaces.

Accent reserved for (and nothing else):
1. The **active** gallery card outline (2px) and its "Active" check
2. The focus ring (existing `--focus-ring-color`, which derives from `--accent`)
3. The Save button in its enabled state (existing `.button.is-primary`)
4. The "Unsaved changes" marker dot in the editor header
5. The Advanced disclosure chevron when expanded

Never accent: card hover, token labels, swatch borders, chips, or warnings.

Warnings: the contrast-warning **text** is `--text-default` (it must stay readable in every theme, including
nord-light, where `--status-warning` text would fail). The leading triangle glyph and a 3px inline-start rule use
`--status-warning`. Warning state is always icon plus text, never colour alone.

Surviving themes: verify the gallery and the editor chrome live on midnightMirage, gruvbox_dark and dracula
(the sketch-findings stress set). Dracula's navbar is lighter than its body, so no chrome here may assume a
surface is darker than another; define selected, hover and warning states relationally (outline, icon, rule), not by tone.

| Active marker | "Active" |

| Contrast summary | "{{count}} contrast warnings" (plural-aware) / "No contrast warnings" |

Validation errors and contrast warnings are not help; they sit under the field they describe.

## Gallery (THEME-01, D-01..D-03, D-07)

Replaces the `SelectField` (`#theme_selector`) in place. The label becomes the heading "Select Theme" (an `h2`, Heading style, no `span`).

**Structure.** Two labelled groups in a vertical stack, 32px apart: **Built-in** (10 cards) then **Your themes**
(custom cards, or the empty state). Built-in first matches D-02 and keeps Duplicate the first thing a new user meets **[OD-7]**.
Each group heading is an `h3`-level landmark: the group is a `role="group"` with `aria-labelledby` its heading.

**Grid.** `grid-template-columns: repeat(auto-fill, minmax(208px, 1fr))`, 16px gap, section max width 960px.
Roughly 3 columns in a typical window, 4 at the cap, and 1 column minimum.

**Card anatomy** (surface `--background`, 1px `--border-color`, radius 10px, padding 8px):
1. Apply control: a single `<button>` wrapping the thumbnail and the name row. This is the whole click target for D-03 "click applies". Thumbnail is 16:10, radius 6px, `aria-hidden` (the button's accessible name is the theme name). `aria-current="true"` on the active card.
2. Name row: theme name (Body, single line, ellipsis, full name in a `title`), then at the inline end either the lock glyph (`faLock`, built-ins) or nothing (custom). The active card shows a check glyph plus "Active" (Caption) here; this is on every active card regardless of group.
3. Action row (outside the apply button, so no interactive nesting): 32px icon buttons, 4px gap, `--text-secondary` glyphs.
   - Built-in card: **Duplicate** (`faClone`).
   - Custom card: **Edit** (`faPen`), **Duplicate**, **Rename** (`faPenToSquare`), **Delete** (`faTrash`, last, glyph turns `--status-danger` on hover and focus only).
   - Each has a visible tooltip on hover and keyboard focus and an `aria-label` from the table above.
4. Each card root carries `data-theme-key="<key>"` (built-ins: the key; custom: `custom:<id>`), because `#theme_selector` no longer exists and operator UAT drives themes by key. `window.setTheme(key)` stays callable from the console.

**States.**

| State | Behaviour |
|-------|-----------|
| Rest | 1px `--border-color` |
| Hover (apply button) | border `--text-secondary`; no scale, no lift |
| Focus-visible | existing focus ring (`--focus-ring-width` / `--focus-ring-color`) |
| Active theme | 2px `--accent` border plus "Active" check; border width change must not shift layout (use `outline` or `box-shadow` inset) |
| Pressed | applies immediately (as the dropdown did); no confirmation |

**Behaviour.**
- Duplicate: creates the copy (flattened, D-10/D-11), then navigates straight to its editor. The copy is **not** applied; the user applies it by clicking its card **[OD-6]**.
- Delete: confirmation dialog first (see Copywriting). Deleting the active theme falls back as described there.
- Rename: opens the Rename dialog from the card **[OD-5]**; the dialog is the same component the editor header uses.
- Transitions: 120ms ease on border-color only. Honour the existing `disableAnimations` setting (no transitions when set).
- RTL: use logical properties (`inline-start`/`inline-end`); the screen already toggles `isRTL`.

`NavItem`, `SearchBar`, `_buttons.scss`, `GameCard`), so **reconcile it against the artifact visually before sign-off**.

A source-text test must pin the table to the `body.nord-light` block.

## Editor (THEME-02, D-04..D-06, D-12..D-15)

**Route.** A flat route under Appearance, `accessibility/themes/:id`, so the Settings tier-2 "Appearance" row stays active
(`navTabs.ts` already matches `/accessibility` by `includes`). A deleted or unknown id renders the "Theme not found" state.

**Layout** (split pane, D-04). Two columns with a 32px gap: token list `minmax(360px, 480px)`, preview `minmax(320px, 1fr)`.
- Preview column is `position: sticky; top: 16px`; the token list scrolls with the page.
- Below about 760px of content width, stack to one column with the preview first, non-sticky, `max-width: 360px`.

**Header.** Row 1: Back button (ghost, arrow + "Appearance") at the inline start. Row 2: `h1.headerTitle` "Edit theme". Row 3: theme name (Heading) with a Rename icon button (`faPenToSquare`) beside it, caption "Based on {{base}}" under it, and at the inline end the "Unsaved changes" marker and the **Save theme** button (`.button.is-primary`, disabled until dirty). The inactive-theme note and the save-state live region sit directly under row 3.

**Token list.**
- Six groups in this order, each an `h2`-level heading (Heading style) with 24px between groups and 8px between rows: Surfaces, Navigation, Text, Buttons, Accent, Status. Then a collapsed **Advanced** disclosure.
- **Row anatomy**: label (Body) with chips and the (i) trigger on the same line; token name under it (Caption, monospace, `--text-secondary`); at the inline end a 32px **swatch button** and a **text input** (width 128px, entered text in Body size). The contrast warning, when present, is a full-width line under the row.
- **Swatch**: square, radius 6px, 1px `--border-color`, a checkerboard under the colour so alpha shows. Click or Enter/Space opens a MUI `Popover` (232px wide) holding `HexAlphaColorPicker`; Escape closes it and returns focus to the swatch. The picker emits `#rrggbb` or `#rrggbbaa`.
- **Text input**: accepts hex (3, 4, 6, 8 digits) and `rgb()` / `rgba()`. On every change it validates; on Enter or blur it commits the canonical `#rrggbb` / `#rrggbbaa` form. While invalid it shows the error under the field and keeps the previous good value in the draft (so the preview never breaks); on blur an invalid entry reverts to the last good value. Must listen to the native `input` event so the on-screen keyboard works.
- **Chips on the label line**: "Derived" (the six `LIVE_DERIVED_TOKENS` **[OD-1]**), "Not in preview", "Set by base theme" **[OD-2]**, each with an (i) where a help text exists. No help text sits under the input.

**Core tokens (27 provisional [OD-4]).** Labels are the human names shown; the token name is the Caption line.

| Group | Label -> token | In preview |
|-------|----------------|-----------|
| Surfaces | Body background -> `--body-background`; Panel and tile surface -> `--background`; Input background -> `--input-background`; Dialog background -> `--modal-background`; Dialog border -> `--modal-border`; Border -> `--border-color` | Body, tile, search-fill fallback yes; dialog x2 and border no |
| Navigation | Sidebar and tab bar -> `--navbar-background`; Active row background -> `--navbar-active-background`; Active label -> `--navbar-active`; Inactive label -> `--navbar-inactive`; Navigation accent -> `--navbar-accent` | yes (accent via fallback) |
| Text | Text -> `--text-default`; Secondary text -> `--text-secondary`; Text on buttons -> `--text-tertiary`; Hover text -> `--text-hover` | all yes except hover text (no) |
| Buttons | Primary button -> `--primary`; Primary hover -> `--primary-hover`; Secondary button -> `--secondary-button`; Success button -> `--success-button`; Danger button -> `--cancel-button`; Danger text and icons -> `--danger` | first, third, fourth, fifth yes; hover and danger text no |
| Accent | Accent -> `--accent`; Accent overlay -> `--accent-overlay`; Search outline -> `--search-bar-border` | yes (accent and overlay via fallbacks) |
| Status | Success -> `--status-success`; Warning -> `--status-warning`; Danger -> `--status-danger` | success and danger via fallbacks; warning no |

Tokens a built-in leaves undeclared (for example `--navbar-inactive` in 8 themes) are seeded on Duplicate with their fallback-resolved value, so every row always has a value.

**Advanced (D-12, D-14).** A disclosure button (`aria-expanded`, chevron `faChevronDown`, rotates, accent when open) that is **collapsed by default** and shows "{{count}} more tokens". When open: a "Filter tokens" input, then one flat list of every other resolved token sorted by name, same row anatomy. **Gradient tokens** (e.g. `--gradient-body-background`) render as a 2-row monospace `textarea` with a 24px gradient strip below it (display only, not a picker); the value is accepted only when `CSS.supports` passes, after rejecting `var(`, `url(`, `;`, `{`, `}`, `@`, `!important`. A non-colour token (for example `--focus-ring-width`) is never listed.

**Contrast warnings (D-15, D-16).** Live as the draft changes. A warning line (triangle + text, `--text-default`, 3px `--status-warning` inline-start rule, 8px padding) appears under **both** rows of a failing pair. Warnings never disable Save and never block navigation. A pair with an unparseable or fully transparent value shows no warning (no throw, no flash). The preview column shows the summary ("{{count}} contrast warnings" / "No contrast warnings", polite live region), and each warned input gets `aria-describedby` pointing at its warning.

Floors shown (three pure token pairs; all 10 built-ins satisfy them) **[OD-3]**:

| Id | Pair | Min | Line shown |
|----|------|-----|-----------|
| border-body | `--border-color` vs `--body-background` | 3:1 | "Border vs body {{ratio}}:1, needs 3:1" |
| border-modal | `--border-color` vs `--modal-background` | 3:1 | "Border vs dialog {{ratio}}:1, needs 3:1" |
| accent-body | `--accent` vs `--body-background` | 3:1 | "Accent vs body {{ratio}}:1, needs 3:1" |

No WCAG 4.5:1 text floor in this phase (D-16).

**Save / leave.**
- Draft values live in component state; the thumbnail and warnings read the draft; the real app is untouched until **Save theme** (D-05).
- Save persists, then re-applies only if the edited theme is the active one. Because the editor's chrome then re-themes, "Saved and applied" confirms what happened.
- Back button and any route change while dirty open the Save / Discard / Cancel dialog (D-06): Save then leaves, Discard leaves, Cancel stays. The in-page Back and `useBlocker` share one dialog.
- Not dirty: Back and route changes leave immediately.

**Keyboard.** Tab order follows the visual order: Back, Rename, Save, then rows (swatch, then input), then Advanced. All dialogs trap focus and return it to the trigger. No pointer-only affordance anywhere.

## Dialogs
