## What is and is not measured here, and why that is written down

D-22 names **exactly two** measurements and D-23 explicitly records two things that were considered
and **not** selected. That asymmetry is deliberate and must survive into the artifact: the point of
D-23 is that no later document gets to claim live coverage this phase does not have.

| Behaviour | Live-gated? | Basis |
|---|---|---|
| Mouse-click install completes with the list mounted through both transitions | **Yes** (D-22.1) | the phase's central claim |
| Installed badge appears in place, no reflow, no scroll jump | **Yes** (D-22.2) | proves the refetch renders as a state change, not a remount |
| Needs-GUI routing for the 8 unattended-incapable verbs | **No** (D-23) | component tests only — plan 44-03's 64-case C-4 parametrisation |
| Pointer-driven browse/search | **No** (D-23) | component tests only — plan 44-04 |
| Theme token survival | gate | the existing undefined-custom-property gate (D-24) |
| Theme contrast | **Yes, spot-check** (D-24) | the gate cannot see a contrast failure; this repo has shipped a 1.46:1 pairing every gate passed |

**Measure, do not eyeball.** Two recorded lessons bind this run. "No layout shift" has been asserted
and been wrong twice on this repo; pixel-measure rather than judging. And a colour contract has
nearly failed correct code when scored by eye; measure the contrast ratio rather than deciding it
looks fine.

**Run the negative control.** A live gate whose instrument was never shown to be capable of
reporting a failure proves nothing. Before scoring D-22.1, confirm the observation method can
actually detect a blanked list — e.g. by watching the same region during a transition known to
unmount something, or by checking that the chosen capture cadence is fast enough to catch a ~4ms
teardown. Record what the control was and what it showed.
</planner_decisions>
