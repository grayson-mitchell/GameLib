<objective>
Build the browse container: a `SearchBar` used for input chrome only, a curated "Commonly needed"
group open by default, one collapsible group per parsed category, and a flat results view that
replaces the grouped structure at ≥2 search characters — plus the four list-level states (loading,
empty, default/browse, zero-result).

Purpose: this is the surface the phase exists to ship. It is also where three of the phase's
hardest constraints meet: the list must never be a focus-conditional overlay (UI-SPEC Interaction
Contract §1), it must survive install without unmounting (C-1, finished in plan 44-05), and it must
carry exactly one inner scroll region (D-06, overriding the UI-SPEC's Layout).

Output: `WinetricksBrowse/index.tsx`, `WinetricksBrowse/index.scss`, and
`__tests__/WinetricksBrowse.test.tsx`.
</objective>

<planner_decisions>
## Three open questions this plan closes, with the reasoning

**1. The grouped region stays MOUNTED during search; it is hidden with CSS, not unmounted.**

`Dropdown` owns its expanded state internally (`src/frontend/components/UI/Dropdown/index.tsx:18` —
`const [isExpanded, setIsExpanded] = useState(false)`) and exposes no controlled prop. UI-SPEC
Interaction Contract §2 requires that clearing the search return to the grouped view **with prior
category expand/collapse state preserved** — "collapsing a category to search and back should not
silently re-collapse a group the user had deliberately opened." If the grouped region is unmounted
while the flat results render, every `Dropdown`'s `useState(false)` re-initialises on remount and
that requirement is structurally impossible to meet.

Two ways out were considered:
- Add an optional controlled `expanded`/`onToggle` prop to `Dropdown`. Rejected: `Dropdown` is a
  shared primitive with two existing consumers (`FilterFacetGroup`, `GamePage`'s `MainButton`), and
  widening a shared primitive to serve one panel is the same class of move D-05 rejects for
  `FilterFacetGroup`'s stylesheet.
- Keep both views mounted and toggle visibility with a class. **Chosen.** It preserves expand state
  for free, needs no change to any shared component, and is consistent with the phase's governing
  principle — this is a phase about *not unmounting things*.

So: render the grouped region and the flat-results region as siblings that are always both mounted,
and give the inactive one a `WinetricksBrowse__pane--hidden` class carrying `display: none`. The
UI-SPEC's "the grouped structure is replaced entirely by the flat results view" is satisfied
visually, which is what that sentence is about.

**2. `Dropdown`'s inherited blur-collapse is accepted, not fixed, and is recorded here so no later
document mistakes it for a Phase 44 regression.**

`Dropdown/index.tsx:41-45` collapses on `onBlur` when focus leaves its container. A user who focuses
a category header and then clicks into the search box may therefore see that category collapse. This
is pre-existing behaviour of the shipped primitive, identical on the Games tier-2 filter panel, and
D-05 directs this phase to build **on** that primitive. It is out of scope to change here and it is
**not** covered by D-22's live gate (D-23 explicitly records that pointer-driven browse/search was
not selected). Do not "fix" it opportunistically; if it proves annoying in use, file a todo with a
measured account.

**3. The category list is derived from the data, not hardcoded to five.**

The UI-SPEC draws five categories and D-09 names five raw values (`apps`, `benchmarks`, `dlls`,
`fonts`, `settings`). But `winetricksListParse.ts` derives categories from whatever
`===== <category> =====` headers the shipped `winetricks list-all` emits. Hardcoding five would
silently drop a sixth if winetricks ever adds one, and would contradict D-14's "parser order, no
sort". Derive the group list from the components array as distinct `category` values in
first-occurrence order.
</planner_decisions>
