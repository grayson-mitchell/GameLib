## Addendum 4 — 2026-08-23, item 1's root cause WITHDRAWN as false

Item 1 was recorded across two re-runs as `blocked` on "this host registers no http/https
handler, so no application can satisfy this criterion". **That is false and is withdrawn.**

Asking LaunchServices directly — `NSWorkspace.urlForApplication(toOpen:)` — returns Safari for
both `http` and `https`. The original claim came from reading
`com.apple.launchservices.secure.plist` and finding no `http` entry, but that file records
OVERRIDES only; a system-default browser correctly has no entry there. The corroborating
"nothing opened" observation was an AppleScript `-1743 Not authorised` permissions failure in
the probe itself. Control with an authorised probe: `/usr/bin/open` on the exact Discord URL
navigates Safari correctly and brings it forward.

**Item 1 is therefore an `issue`, not `blocked`** — a real defect that spent a full session
misfiled as an environment problem. Recount: **4 passed, 1 issue, 0 blocked.**

1. A wrong diagnosis was INHERITED and repeated without re-testing its underlying claim. The
