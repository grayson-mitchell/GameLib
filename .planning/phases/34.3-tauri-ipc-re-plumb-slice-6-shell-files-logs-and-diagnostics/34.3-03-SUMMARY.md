## Accomplishments

- Added `tauri-plugin-clipboard-manager = "2"` to `Cargo.toml`; `Cargo.lock` resolved it to **2.3.2**, matching 34.3-RESEARCH.md's prediction. Re-confirmed at execution time (not just at research time) that `grep -rn "js_init_script" ~/.cargo/registry/src/*/tauri-plugin-clipboard-manager-*/src/lib.rs` returns nothing — the plugin injects no init-time JS, so D-02's zero-grant stance needed no exception (unlike the `tauri-plugin-notification` landmine).
- Registered `.plugin(tauri_plugin_clipboard_manager::init())` and added exactly two new `dispatch_rust_channel` arms: `clipboard_write_text` and `clipboard_read_text`, both calling `app.clipboard()` — the ONLY two new arms this entire 34.3 slice adds. Zero `clipboard-manager:*` entries added to `capabilities/default.json` (confirmed by `git diff --stat` empty on that file).
- Extracted the arms' non-plugin logic into two pure, `AppHandle`-free helpers — `clipboard_text_arg` (ASVS V5 input validation: absent/null/number/bool all rejected, empty string accepted as a valid write, trailing args ignored) and `clipboard_read_value` (shapes an empty successful read to `Value::String("")`, never `Value::Null`) — proven by 10 new `#[cfg(test)]` tests (6 -> 16 total).
- Hand-verified both RED proofs by temporarily applying the stated regressions, confirming the expected failures, and reverting to a byte-identical file (`diff` confirmed clean):
  - `unwrap_or("")` in place of `ok_or_else` in `clipboard_text_arg` flipped exactly the 4 rejection tests (`_rejects_absent_args`, `_rejects_null`, `_rejects_number`, `_rejects_bool`) to failures; all other 12 tests stayed green.
  - `Value::Null` for an empty read in `clipboard_read_value` flipped exactly `clipboard_read_value_empty_string_is_not_null` to a failure (`left: Ok(Null) right: Ok(String(""))`); all other 15 tests stayed green.
- Recorded Q1's verified finding as a `// `-line-comment block above the `app_relaunch` arm: `dispatch_rust_channel` always runs on a `thread::spawn`'d worker thread, so `app.restart()` here is always `restart()`'s background-thread branch, which requests exit through the real event loop and fires `RunEvent::Exit` (the existing WR-03 `shutdown_child()` handler) BEFORE the process re-execs — no orphan-sidecar window, no `state.shutdown_child()` call added. The arm's body is still exactly `app.restart();` (confirmed via `git diff`).
- Minted `RUST_CLIPBOARD_WRITE_TEXT` / `RUST_CLIPBOARD_READ_TEXT` in `sidecarTransport.ts`, both added to the `RUST_INVOKE_CHANNELS` allowlist array.

## Decisions Made

- **D-05's proposed Rust fix is DROPPED, not implemented.** 34.3-RESEARCH.md Q1 traced the exact vendored `tauri = 2.11.5` source and confirmed `AppHandle::restart()`'s background-thread branch (the only branch `dispatch_rust_channel`'s worker-thread calling pattern can ever take) requests exit through the real event loop, which fires `RunEvent::Exit` — and this file's own `.run(...)` closure already calls `state.shutdown_child()` on exactly that event, before the process re-execs. Adding an explicit `shutdown_child()` call inside `app_relaunch` would be dead code. Recorded as a verified finding instead of a fix, per the plan's explicit instruction.
- **Task 1 arms use inline arg-extraction; Task 2 refactors to extract helpers.** This lets Task 1 commit a standalone-compiling change (verified by `cargo check`) before Task 2 extracts the pure `clipboard_text_arg`/`clipboard_read_value` helpers and adds their tests — matching the plan's own task split and its `read_first` note that Task 2 operates on "the two arms added in Task 1."
- **`clipboard_read_value`'s empty-string-is-not-null distinction is load-bearing**, not incidental: the sidecar's `clipboardReadText` handler (owned by a later plan in this phase) coerces a non-string result to `''`, so a regression to `Value::Null` here would be silently masked as an indistinguishable empty clipboard read rather than surfacing as a visibly wrong shape.
