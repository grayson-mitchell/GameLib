# Phase 34.3 — Declared Ported-Channel List

**Purpose:** The enumerated set the next Tauri phase (34.4+) starts from, and the artifact the
Phase 35 cutover gate reads for this slice, mirroring how this phase itself started from
`34.2-PORTED-CHANNELS.md`. It describes what actually shipped in 34.3-01..34.3-07, verified row
by row against all seven plan SUMMARY.md files, not against this phase's original planned intent.

**Read this budget correction first.** 15 of the 29 channels below are near-free — they reduce to
`openUrlOrFile()`/`showItemInFolder()` in `utils.ts`, a module already in the sidecar's import
graph since Phase 34.1, already reaching Rust arms (`open_external`/`shell_open_path`/
`reveal_item_in_dir`) that already existed before this slice started. A reader who budgets this
slice as "29 delegations" has misread it in the opposite direction from 34.2's own warning. The
slice's real content is three things, none of which is "port 29 channels":

1. **A new clipboard platform seam** — the one genuinely missing capability this project had.
2. **A JS-side relaunch/quit ordering fix** — contained entirely inside `electronStub.ts`.
3. **This series' first blocking live gate** — 5 named items, not a 29-channel UAT, and the
   phase does not close until they pass.

## Framing corrections this document owes

**Correction 1 — the clipboard no-op was NOT a latent shipped defect.** Its only backend
consumers are this slice's own three channels (`clipboardWriteText`, `clipboardReadText`,
`copySystemInfoToClipboard`), so nothing has been silently degrading in production — unlike
34.2's i18next finding, which was reachable dead code across many already-shipped call sites.
`electronStub.clipboard` is the direct descendant of Phase 31 D-04, which chose a logged no-op
and explicitly wrote "deferred to Phase 33." Phase 33 never collected it. This slice closes a
two-phase-old promise — completion, not churn. Do not read this as a "34.2-style already broken
in production" narrative; it is not one.

**Correction 2 — `resetHeroic` is narrower than its own UI copy claims.** `resetHeroic` (`utils.ts:466-478`)
deletes exactly two things: `configPath` (`~/…/GameLib/config.json`, global settings) and
`gamesConfigPath` (`~/…/GameLib/GamesConfig/`, per-game settings). It does NOT touch the Steam
refresh token, the Steam library store, any of the 10 Humble stores, the download-manager store,
or the Wine/wiki/CrossOver caches — all ~20 of those `electron-store` files are *siblings* of
`config.json` in `appFolder` and survive a reset untouched. The Settings → Advanced "Reset GameLib"
dialog's "removes all Settings and Caching" copy already overclaims **in Electron** — this is
inherited, out-of-scope UI copy, not a defect this slice introduced or should fix.

**D-05 resolved to NO FIX.** Research verified, at HIGH confidence via a direct read of
`tauri = 2.11.5` (pinned by `Cargo.lock`), that `AppHandle::restart()` fires `RunEvent::Exit` for
this codebase's `dispatch_rust_channel` worker-thread calling pattern — so the existing Phase 33
`shutdown_child()` handler already runs before the process re-execs. The orphan-sidecar scenario
D-05 worried about was an inference from Tauri's API semantics (`restart()`'s signature never
returns), not a measured defect, and plan 34.3-03 recorded the verified finding as a code comment
above the `app_relaunch` arm rather than adding a fix. State that plainly — do not present the
orphan as an established defect that was fixed.

**Why this slice has a live gate when 34.1/34.2 did not.** 34.2 could honestly claim "data in /
data out with assertable return shapes" for its 26 channels — jest genuinely proved most of what
mattered. This slice cannot make that claim for its own headline content: most of these channels'
*entire purpose* is an observable OS side effect (a browser window opening, Finder revealing a
file, a clipboard round-tripping through the real OS clipboard, a process actually exiting). Jest
can assert that `requestRustInvoke` was called with the right arguments; it cannot assert that a
browser opened. This slice also ships two Rust arms CI never compiles (`.github/workflows/*.yml`
runs no cargo step) and one destructive channel (`resetHeroic`) whose failure mode — an orphaned
sidecar process — is only visible in the process table, not in any return value. Assertion-only
evidence is not enough here the way it was for 34.2. This is the gate 34.2 itself named as its
"highest-value optional gate" and deferred.

**Live-gate status as of this document.** The 5-item blocking live gate (D-11/D-12/D-13) is run by
the very next plan in this phase, `34.3-09` — it has **not yet run** as of this document's
authorship. Rows below that name a live-gate item record the item that will supply the
observational half of that row's proof; until `34.3-09` completes and records its results in
`34.3-LIVE-GATE.md`, the LIVE half of any such row is **pending**, not yet observed. See "Automated
vs live proof boundary" below — do not read a `unit + LIVE (item N)` cell as "already observed
working" before `34.3-LIVE-GATE.md` exists and records that item as passed.

## Accepted risks and declared caveats

1. **Humble key-copy silent-failure risk (`clipboardWriteText`).** A `clipboard_write_text` Rust
   failure is logged, never surfaced to the user. `HumbleClaimWizard/index.tsx:120,366` copies a
   *revealed* Humble key through this exact path — a silent failure means the user believes the
   key is on their clipboard when it is not. Accepted at Electron parity (D-03): real Electron's
   `clipboard.writeText` is `void` and cannot surface failure either, so matching it keeps both
   builds behaviorally identical and adds nothing to unwind at the Phase 35 cutover.
2. **`deleteUploadedLogFile`'s both-builds structural deadness.** Cannot delete anything in either
   the Electron or the Tauri build — `uploader.ts:74-77`'s hardcoded `token = '1'`. Ported at
   parity and declared per D-08, not fixed here; distinct from 34.2's D-07 (which *was* a
   port-introduced, in-scope gap).
3. **`clipboard.readText()`'s documented-dead stub.** `electronStub.clipboard.readText()` still
   returns `''` synchronously and is never called by any sidecar-reachable path other than the
   real Rust-backed `clipboardReadText` handler, which bypasses it entirely (D-04). Left in place,
   not deleted, so a future hook-rescued caller gets a degraded-but-safe return instead of a
   `TypeError`.
4. **Log upload's filed-not-audited redaction gap.** `uploadLogFile` sends up to 10 MiB of log
   content to dpaste.com as a public paste with a 2-day expiry, and `src/backend/logger/` has no
   redaction anywhere. GameLib adds Steam refresh tokens and revealed Humble key values upstream
   Heroic never had. **This was filed as a security todo and explicitly NOT audited** — the user
   declined even a bounded audit of whether a real credential can reach a log line (D-09). The
   question is open, not answered; see `.planning/todos/pending/log-upload-has-no-redaction.md`.
5. **`resetHeroic`'s overclaiming dialog copy.** The "Reset GameLib" confirm dialog promises to
   remove "all Settings and Caching"; the real blast radius is `config.json` + `GamesConfig/` only
   (Correction 2 above). Inherited Electron UI copy, not introduced or worsened by this slice.

## Automated vs live proof boundary

**What the jest suites prove:** that each channel dispatches with the right arguments and kind
(`send` vs `invoke`, cross-checked against `main.ts`'s own registration for every ported channel);
that argument shapes round-trip correctly (`removeFolder`'s two-element array, `checkDiskSpace`'s
zod validation); that failure modes are non-fatal where declared (the dialog stub resolving rather
than rejecting, clipboard write failures logging rather than throwing); and, for the two new Rust
arms, that 16 `#[cfg(test)]` cases (10 clipboard-specific, hand-RED-proved) pass under
`cargo test` and are pinned to keep existing by a jest source-existence gate.

**What only the live gate (34.3-09, not yet run as of this document) proves:** that a real browser
window actually opens (item 1); that Finder actually reveals a real item (item 2); that text
written through `clipboardWriteText` can actually be pasted into another application, and that
`clipboardReadText` actually round-trips a real clipboard value (item 3); that a packaged build's
`resetHeroic` leaves **exactly one** sidecar process running with `config.json` genuinely gone,
not two processes racing over a config file (item 4); and that `uploadLogFile` returns a real,
reachable dpaste URL over a real network (item 5).

**No reader may take "wired and unit-proven" for "seen working"** — this is exactly how G-30-02
was declared fixed twice while the live build hung. Read this document together with
`34.3-LIVE-GATE.md` once it exists; neither artifact should be read in isolation.
