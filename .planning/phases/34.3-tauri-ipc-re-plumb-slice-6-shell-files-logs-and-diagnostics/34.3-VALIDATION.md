### Gaps found and filled

Both gaps were created by the **2026-08-23 live-gate remediation** (commit `d15f4bb1e`), i.e.
*after* this document was written — so they were invisible to it by construction. This is the
general hazard: a validation map written at plan time cannot see fixes made during later UAT.

- **G-01 → REQ-34.3-01a.** `send()`'s new rejection `.catch` had zero tests. Its recursion guard
  (the `logError` channel falling back to `console.error`) is load-bearing — an unguarded version
  infinite-loops — and the source docstring says *"DO NOT remove this guard to 'simplify' the
  code"* with nothing enforcing it. Now pinned in `src/preload/__tests__/tauriTransport.test.ts`.
  RED-proved against the real pre-fix revision, which did not merely fail an assertion: it
  **crashed the Node process** on an unhandled rejection, which is the defect itself.
- **G-02 → REQ-34.3-01b.** The zero-arg wrapper stopping React's SyntheticEvent from reaching a
  `send()`-routed IPC call was protected **only by a code comment**. Now pinned by
  `openDiscordCallSiteGuard.test.ts`. Because the component's own comment names `openDiscordLink`,
  `onClick` and `SyntheticEvent` at length, a naive substring gate passes on prose alone — so the
  gate strips comments first and ships four self-tests, including a comment-only specimen and a
  synthetic bare-bind reversion, proving it fails in the RED direction.

*Not a gap:* the `macos_finder_reselect_workaround` fix for live-gate item 2 was initially
suspected uncovered. It is **covered** — `tauriShellSource.test.ts:1749-1880` gates it against the
shipped `main.rs`, including a RED-direction self-test proving a comment merely *naming*
`as alias` fails the gate. That directly answers the history where the fix's first version was
dead code that passed a check measuring a replica rather than the shipped script.

### R-01 — OPEN regression, carried against REQ-34.3-13

**The Preload jest project is currently RED: 8 failures**, all
`TypeError: Cannot read properties of undefined (reading 'catch')` at `tauriTransport.ts:119` —
the line commit `d15f4bb1e` added. Failing tests live in the `change events`, `CR-03` and `WR-03`
describes.

Cause: those tests call `registerStore`/`snapshotSet`, which now reach the new `send()` →
`.catch()`. Under `resetMocks: true` (and the explicit `mockedInvoke.mockReset()` at
`tauriTransport.test.ts:248`) the mock returns `undefined`, not a Promise, so `.catch` throws
synchronously. Before `d15f4bb1e`, `send()` was `void tauriInvoke(...)` with no `.catch`, so an
`undefined` return was harmless.

**This is a test-harness defect, not a production defect** — the real `@tauri-apps/api` `invoke()`
always returns a Promise. Attribution proven by running a single pre-existing test with the new
describe block entirely filtered out (26 skipped): it still fails identically, so the audit's own
additions are not the cause.

Not fixed here: it originates in another workstream's commit on a shared branch, and the audit's
constraints made implementation and pre-existing suites read-only. Recommended fix is one line —
give `mockedInvoke` a resolved default (`mockResolvedValue(undefined)`) everywhere it is reset
ahead of a `send()`-reaching call — which restores green without weakening any assertion.
