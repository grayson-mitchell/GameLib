<objective>
Close CR-01 — the blocking defect that put Phase 21 into `gaps_found`. The in-process
depot engine (`depot.ts`) captures each manifest file's `flags` field but never reads it,
so Steam depot-manifest **directory** entries (`EDepotFileFlag.Directory = 64`) and
**symlink** entries (`EDepotFileFlag.Symlink = 512`) — both `size === 0` with no chunks —
fall into `downloadSingleFile`'s empty-file fast path and are written as empty regular
files. For essentially any real game with subdirectories this produces ENOTDIR/EISDIR
failures depending on file-processing order; symlinks become broken empty files with their
LinkTarget discarded. This is the shared file-writing path used by native installs
(SNI-01), the finalize/adoption flow (SNI-04), and macOS bottle installs (SNI-08), so
fixing it here closes the defect for all three.

While in the exact same code block, also close the two warnings that live in it:
WR-02 (a `size>0` file with zero chunks is silently written empty and reported success)
and WR-03 (progress percent is unclamped and can exceed 100).

Purpose: Make the bytes on disk actually match the structure the manifest describes, which
is the precondition for Steam adopting the `1026` manifest at all.
Output: A corrected `depot.ts` plus regression tests in `depot.test.ts` that exercise
Directory and Symlink flags (the class of defect the currently-green suite never touches).
</objective>

resolveContainedPath(root, filename) (depot.ts:385-394) — ALREADY does the correct
