<objective>
Close UAT gap D-UAT-04 (SNI-03 UX + SNI-06 observability). Three findings from real-hardware UAT (macOS, 2026-07-16):

1. **No "restart Steam to finish" guidance (UAT 1a).** After a native depot download completes, GameLib writes the `1026` manifest and the poller waits for Steam to flip `StateFlags` to bit 4. Steam only re-reads `appmanifest_*.acf` on a FULL restart — focusing the window is not enough. GameLib's Library tile shows a stuck "Steam installing" spinner with no guidance, so users think it hung. Add a passive hint on the surfaces users actually watch (Library grid tile + game detail page). Do NOT auto-manipulate Steam.
2. **Awkward status copy.** The Library tile status reads "Steam installing". Improve to clear copy ("Installing…").
3. **Zero depot-selection logging.** `select.ts` logs nothing about which depots were chosen or why — this observability gap turned a UAT misdiagnosis into an hour-long investigation. Add logInfo of the chosen depot ids + os/arch/oslist/language decisions (no secrets).

NOTE: D-UAT-02 (ETA HH:MM:SS + downSpeed MiB/s) is ALREADY FIXED (commit 6640e8ce) — do NOT re-plan it.

Purpose: make the Steam handoff legible on the grid and the depot selection debuggable.
Output: a poll-time waiting signal surfaced on the Library tile + detail page, cleaner status copy, and depot-selection logging.
</objective>
