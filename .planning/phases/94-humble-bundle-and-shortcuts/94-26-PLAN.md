<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> key actions | requests to reveal, override or record a gift are untrusted |
| crate -> Humble redeem | a reveal consumes a key server-side |
| crate -> shell transport -> hidden Humble webview | crate-built requests become an in-page fetch that carries the user's session cookie |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-94-49 | Elevation of Privilege | override and gift-link actions | high | mitigate | server-side re-validation inside the ops (fuzzy-only; owned-elsewhere and UNREVEALED); goldens pin the refusals |
| T-94-50 | Information Disclosure | revealed key values | high | mitigate | C4: one value-bearing op; an assertion over every log line, event and result; no logging in the reveal path; the transport's types carry the reply body without the formatting trait |
| T-94-51 | Tampering | accidental reveal of an owned-elsewhere key | high | mitigate | C2 block before any transport call, pinned by a golden with zero opens and zero requests |
| T-94-72 | Tampering | crate values reaching the in-page script | medium | mitigate | every crate request goes through the op's own `action_open_args` and `action_post_args` (https Humble pages only, the header allowlist, same-origin paths, size bounds); the op passes them to the page as one JSON value, never spliced into code |
| T-94-73 | Information Disclosure | the humble_action lines now written to the uploadable gamelib.log | low | mitigate | the lines carry status codes, byte counts and fixed text only; engine error text stays on stderr through shell_log_detail; shellLogCategoryOnly.test.ts runs in the verify |
| T-94-74 | Denial of Service | no fallback when the edge also blocks the webview | medium | accept | every non-browser stack is blocked (debug Probes A-G) and the old hidden-window arm cannot send a server action, so no fallback could pass; the live proof is 94-29's dev smoke (library POST) and 94-32 item 2 (the reveal), and a block there routes to /gsd-debug with the user-agent lever named |
| T-94-SC | Tampering | package installs | low | accept | no new dependency |
</threat_model>
