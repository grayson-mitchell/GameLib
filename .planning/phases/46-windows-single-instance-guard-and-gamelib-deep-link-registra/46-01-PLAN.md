<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process token → name/SDDL derivation | The SID string later flows into a kernel-object name and an SDDL string that `ConvertStringSecurityDescriptorToSecurityDescriptorW` parses |
| process environment → guard identity | Env vars are inherited and caller-controlled, so they must not decide the guard's identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-06 | Spoofing | guard identity (`windows_single_instance_key` input) | mitigate | Identity is the token user SID, passed explicitly. The helpers contain no `std::env::var` (acceptance-gated grep = 0). `USERNAME` is not used (planning-time correction 1) |
| T-46-07 | Tampering | `windows_pipe_sddl` | mitigate | Strict `S-1-[0-9-]+` validator with a ≤184 length cap. Injection-shaped inputs `;(A;;GA;;;WD)` / `)(` / `\` are unit-tested as rejected, so no caller can build an SDDL from them |
| T-34.5-G6-20 | Tampering | `single_instance_payload` | mitigate | Delegates to `protocol_url_arg`, the single choke point. A non-allow-listed scheme degrades to the focus sentinel, never forwarded (unit-tested) |
| T-46-SC | Tampering | dependency surface | accept | This plan adds no dependency. windows-sys is added in 46-02 (already in Cargo.lock; slopcheck OK per RESEARCH) |
</threat_model>
