Add the Windows FFI half of the guard and wire it into `main()` ahead of `tauri::Builder::default()`. This plan does NOT start the accept loop. Plan 46-03 spawns it in `.setup()`, which mirrors where the Unix accept loop is spawned.

Purpose: this closes the "second full GameLib instance" half of U-34.5-18 on Windows (REQ-46-01/02/03) and rewrites the guard comments that currently call Windows an accepted gap (REQ-46-11 partial).
Output: a compiling Windows guard. A second launch exits before the sidecar spawns.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| secondary process → named pipe → primary | The payload crosses a process boundary. The pipe namespace is machine-global, so another local user can see and pre-create names |
| network → named pipe | `\\host\pipe\name` is reachable over SMB unless it is rejected |
| primary → child processes (sidecar) | Inheritable handles would extend the mutex lifetime into the sidecar |
