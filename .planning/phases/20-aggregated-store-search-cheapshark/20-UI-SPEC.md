# Phase 20 — UI Design Contract

> Visual and interaction contract for the Aggregated Store Search (CheapShark) screen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is a fork of Heroic Games Launcher with an established SCSS-module + MUI design system.**
Every token below is an EXISTING project variable — nothing here is invented. The new screen
must look like a sibling of `src/frontend/screens/Discounts/`, not a new visual language.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is intentionally **not** introduced |
| Preset | not applicable |
| Component library | MUI (`@mui/material`) for form controls (`Select`, `Checkbox`, `MenuItem`) + hand-rolled semantic-token CSS for cards/badges/layout — the exact mix already used by `Discounts/` |
| Icon library | FontAwesome (`@fortawesome/free-solid-svg-icons` + `free-brands-svg-icons`), used everywhere in `Sidebar/SidebarLinks` |
| Font | Primary (headings): `Rubik` via `var(--primary-font-family)`. Secondary (body/buttons): `Cabin` via `var(--secondary-font-family)`. Both declared once in `src/frontend/styles/_typography.scss`; never redeclare a font-family in phase code. |

**Why no shadcn:** CLAUDE.md locks the stack as "Electron + React + TypeScript to stay
mergeable with Heroic upstream." Heroic's own SCSS-module + CSS-custom-property theme system
(`themes.scss`, `_colors.scss`, `_spacing.scss`, `_typography.scss`) is the actual design system
of record — every existing theme (default dark, "Old School GameLib" light, several community
themes) resolves the SAME semantic variable names to different values. Introducing shadcn would
fork the token system and break every existing theme. This phase reuses the existing tokens
exclusively.

## Spacing Scale

The project's real scale is em-based (root 16px), not the generic 4px-multiple ladder — this is
the existing, in-use convention (`src/frontend/styles/_spacing.scss`) and MUST be reused verbatim,
never re-derived in px.

| Token | Value (at 16px root) | Usage in this phase |
|-------|-----------------------|----------------------|
| `--space-3xs` | 4px | Badge internal padding, tight icon gaps |
| `--space-2xs` | 6px | Gap between stacked badges, row internal gaps |
| `--space-xs` | 8px | Badge/pill padding, icon-to-label gaps |
| `--space-sm` | 12px | Row internal padding (compact), control heights context |
| `--space-md` | 16px | Default gaps, screen padding (matches `.discountsScreen`) |
| `--space-lg` | 24px | Section spacing (row-list to pagination, if added) |
| `--space-xl` | 48px | Empty-state vertical spacing |
| `--space-2xl` | 72px | not used this phase |
| `--space-3xl` | 136px | not used this phase |

Exceptions: none. Do not hardcode any px value — every spacing declaration in new SCSS/CSS
resolves through one of the tokens above (or the matching `-fixed` variant where a non-em pixel
value is required, e.g. `--space-md-fixed: 16px` for the screen's outer padding, mirroring
`.discountsScreen { padding: var(--space-md-fixed); }`).

## Component Inventory & Layout Contract

### Sidebar entry (STORESEARCH-01)
- New `<SidebarItem>` in `SidebarLinks/index.tsx`, placed as a **sibling immediately after** the
  existing `/discounts` "Deals" entry (same indentation level, not inside `SidebarSubmenu`).
- Icon: `faMagnifyingGlassDollar` (FontAwesome free-solid — not yet used elsewhere in the
  sidebar; distinct from `faTags` used by Deals and `faKey` used by Humble Keys).
- Label copy: `t('storeSearch.sidebar', 'Store Search')`.
- `dataTour="sidebar-store-search"` (matches the `data-tour` convention on every existing entry).
- No conditional gate (unlike Humble Keys' `humble?.isLoggedIn` guard) — always visible, exactly
  like Deals; CheapShark requires no account.

### Screen shell
- Root class `.storeSearchScreen`, same shell contract as `.discountsScreen`: `display: flex;
  flex-direction: column; flex-grow: 1; min-width: 20vw; padding: var(--space-md-fixed); color:
  var(--text-default);`
- Header row: `<h2>` at `--text-2xl` reading `t('storeSearch.title', 'Store Search')`, no region
  selector (CheapShark is USD-only — do not copy `discountsScreen__region`, there is nothing to
  select).

### Search input (STORESEARCH-02, D-11)
- Reuse the existing `SearchBar` component (`frontend/components/UI/SearchBar`) verbatim — same
  component `Discounts/components/DiscountFilters` uses for its search row. Do not build a new
  input.
- Placeholder: `t('storeSearch.placeholder', 'Search for a game title…')`.
- **Debounce/loading affordance:** while the 400ms debounce timer is pending OR a request is
  in-flight, render a small inline spinner inside `SearchBar`'s existing `searchButton` slot
  position (same DOM position as the existing search icon — swap icon for spinner, don't add a
  second element). No spinner shows for a query under 3 characters (no request has fired).
- **Minimum-length affordance:** when the trimmed query is 1–2 characters, show no results area
  and no spinner — the screen stays on the initial-empty state (see below). Do not show an error
  or a "type more" nag; the explanatory prompt already covers this (D-14).
- Cancellation is invisible — no UI element represents "a previous request was cancelled."

### Result row (STORESEARCH-03, D-12) — collapsed state
One row per game, NOT a grid of cards (this deliberately departs from `DiscountCard`'s tile
layout — CheapShark's shape is list-like: one cheapest price per title). Class `.storeSearchRow`.

Layout (single flex row, `align-items: center`, `gap: var(--space-md)`, padding
`var(--space-sm) var(--space-md)`, background `var(--gradient-gamecard)`, `border-radius:
var(--space-3xs)`, matches `.discountCard`'s corner radius and shadow: `box-shadow: 0px 0px 12px
4px #00000055`):

1. **Thumb** — CheapShark's `thumb` URL via `CachedImage`, `width: 60px`, `aspect-ratio: 3/4`,
   `object-fit: cover`, fallback to the same `gamelib_card.svg` used by `DiscountCard`.
2. **Title** — `.storeSearchRow__title`, `--text-md` / `--bold`, single line with ellipsis
   overflow (matches `.discountCard__title`).
3. **Badge stack** (STORESEARCH-05/06, D-04/D-06/D-07) — see Badge Contract below. Renders
   between title and price, wraps to its own line on narrow widths.
4. **Cheapest price** — `.storeSearchRow__price`, right-aligned, `--text-md` / `--bold`, rendered
   as **one text node**: `${amount} USD` (see Currency Contract below — never split into a muted
   suffix).
5. **Expand affordance** — a chevron icon-button (`faChevronDown` / rotates 180° when expanded,
   same `.discountFilters__toggleIcon--open` rotate pattern), `aria-expanded`, `aria-label`
   `t('storeSearch.aria.expand', 'Show store breakdown for {{title}}')`.

Hover/focus: `transform: scale(1.02)` (gentler than `DiscountCard`'s `1.05` since this is a row,
not a tile) + `outline: none` on focus-visible, transition `transform 0.1s ease-in`.

### Expanded per-store breakdown (STORESEARCH-03, D-12) — lazy state
On expand, if the per-store deals haven't been fetched yet, fire `GET /games?id=` and show a
**row-scoped** loading state — NOT a full-screen spinner. Render a single inline row: a small
spinner + `t('storeSearch.loadingStores', 'Loading store prices…')`, same treatment as
`UpdateComponent`'s message but sized to fit inside the expanded panel (no full-screen
`UpdateComponent` reuse — that component is screen-level).

Once loaded, each store renders as its own sub-row inside `.storeSearchRow__breakdown`
(`display: flex; flex-direction: column; gap: var(--space-2xs); padding: var(--space-sm)
var(--space-md); border-top: 1px solid var(--divider, rgba(255,255,255,0.12));`):

- Store name — plain text label (`--text-sm` / `--regular`) resolved from CheapShark's numeric
  `storeID` via the `/stores` endpoint lookup (Claude's discretion, per 20-CONTEXT.md). Where the
  resolved store maps to an existing GameLib `Runner` (`steam`, `gog`, `legendary`/Epic,
  `nile`/Amazon), prefix the label with the existing `<StoreLogos runner={...} />` icon (16px) for
  visual consistency with the ownership badge icons below. The other ~26 CheapShark storefronts
  (Fanatical, Green Man Gaming, etc.) render text-only — do not source or fabricate new logo SVGs
  for them this phase.
- Price — same one-text-node `${amount} USD` treatment as the collapsed row, `--text-sm` /
  `--semibold`.
- The whole sub-row is the click target (D-08/D-09): `onClick` → `shell.openExternal()` on
  CheapShark's `redirect?dealID=` URL. Cursor `pointer`, hover background
  `rgba(255,255,255,0.05)` (matches `.discountFilters__toggle:hover`). No `withAffiliate()` call
  (D-09 — that helper is deliberately not imported here).

### Badge contract (STORESEARCH-05/STORESEARCH-06, D-01/D-04/D-06/D-07)

Extends `common/discounts/badges.ts`'s vocabulary (`owned | key-available | null`) — do not fork
a second type. Two badges may render side by side on one row (`display: flex; gap:
var(--space-2xs); flex-wrap: wrap;`), departing from Phase 15's single-badge rule **on this
screen only** — this file is the authoritative record of that intentional departure; do not
"fix" it to match Discounts.

- **`owned` badge copy** (D-04): always **names the store(s)**, never a bare "Owned":
  - Single store: `t('storeSearch.badge.ownedOn', 'Owned on {{store}}', { store })` → e.g.
    `Owned on GOG`.
  - Multiple stores, ≤2 total (D-06 stacking): join with `, ` →
    `t('storeSearch.badge.ownedOnMulti', 'Owned on {{stores}}', { stores: 'Steam, GOG' })`.
  - Multiple stores, >2 total: cap at the first 2 (deterministic order: Steam, GOG, Epic, Amazon
    — the fixed D-05 resolution order) + overflow suffix:
    `t('storeSearch.badge.ownedOnOverflow', 'Owned on {{stores}} +{{count}} more', { stores:
    'Steam, GOG', count: 2 })` → `Owned on Steam, GOG +2 more`. This is the exact cap/overflow
    example from 20-CONTEXT.md D-06 — reuse it verbatim, do not invent a different number.
  - Chrome: reuse `.discountCard__badge--owned` exactly (`background: var(--status-success)`,
    `color: var(--neutral-01)`, `--text-sm` / `--semibold`, `padding: var(--space-3xs)
    var(--space-2xs)`, `border-radius: var(--space-3xs)`).
- **`key-available` badge** (D-07): renders as an independent sibling pill, never suppressed by
  an `owned` badge being present. Copy: `t('storeSearch.badge.keyAvailable', 'Key available')`
  (identical string to the existing Discounts badge — same fact, same words). Chrome: reuse
  `.discountCard__badge--keyAvailable` exactly (`background: var(--status-info)`).
- **`null`** (neither owned nor keyed): no badge element at all — missing beats wrong, same
  principle as `badges.ts`'s header comment.
- Resolution mechanics (informational, for the planner — not a UI concern but constrains what the
  badge can visually claim): Steam badge attribution is **exact ID join only** (CheapShark's
  `steamAppID` against `steam.library`) — never present a Steam "Owned on Steam" badge derived
  from a fuzzy match. GOG/Epic/Amazon attribution may be fuzzy (85% threshold, reused
  `HUMBLE_FUZZY_MATCH_THRESHOLD`) — the UI does not visually distinguish exact vs. fuzzy
  provenance (no "probably owned" treatment — a match is a match, per D-01/D-02).

### Currency contract (STORESEARCH-04, D-13) — CORRECTNESS requirement

Every rendered price — collapsed-row cheapest price AND every expanded per-store price — is a
**single text node** of the exact shape `${amount} USD` (e.g. `$14.99 USD`). Enforcement rules:

1. `USD` is **never** a separate `<span>`, never a smaller font-size, never a reduced-opacity
   suffix, never behind a tooltip/hover-only reveal, and never a dismissible banner. It shares the
   exact `font-size`/`font-weight`/`color` of the number that precedes it, in the same DOM text
   node or an adjacent non-differentiated inline span.
2. This is a deliberate departure from `.discountCard__basePrice`'s dimmed/struck-through
   treatment — that pattern is reserved for the "was" price in a discount, not for a currency
   unit, and must not be reused for `USD`.
3. Rationale (verbatim from 20-CONTEXT.md D-13): the adjacent Deals screen renders localised
   prices via `CatalogLocaleSettings` — a non-US user seeing an unlabelled `$` here would read it
   as their own currency and act on a wrong "cheapest" verdict. The label is a correctness
   mechanism, not decoration; the checker should treat a muted/smaller "USD" as a FAIL, not a
   style nit.

### Three-state contract (STORESEARCH-08, D-14)

Exactly three visually distinct states below the search input. None of them may be confused for
another:

| State | Trigger | Visual treatment | Copy |
|-------|---------|-------------------|------|
| **Initial / explanatory prompt** | No query typed yet, or query <3 characters | Centered block, `var(--space-xl)` vertical margin, `var(--text-md)` `var(--text-secondary)` color, a large muted search icon above the text (reuse `faMagnifyingGlassDollar` at 48px, `opacity: 0.4`) | `t('storeSearch.prompt', 'Search a title to compare prices across every store — GameLib will tell you if you already own it.')` |
| **No results** | Query ≥3 chars, request succeeded, zero matches | Same centered block position as initial prompt, but **no icon** (distinguishes it from the prompt at a glance) and `var(--text-secondary)` — matches `.discountsScreen__message` exactly | `t('storeSearch.noResults', 'No results for "{{query}}". Try a different spelling or a shorter title.')` |
| **Provider failed (retryable)** | Request rejected/errored | An inline **banner**, not a centered block — `background: rgba(249, 120, 129, 0.1)` (status-danger tint), `border-left: 3px solid var(--status-danger)`, `padding: var(--space-sm) var(--space-md)`, `border-radius: var(--space-3xs)`, positioned directly under the search input (search box remains enabled/focusable — fail-soft) | `t('storeSearch.providerError', "Couldn't reach the price provider.")` + inline `t('storeSearch.retry', 'Retry')` link/button in `var(--accent)` color |

The no-results and provider-error states must never share the same visual container — a banner
with a left accent bar (error) vs. a plain centered message (no-results) is the minimum
distinguishing signature; do not implement both as the same `<p className="...__message">` with
only the copy changed.
