actually visible to the engine GameLib runs in.

<dispatch_gate>
`window.api.gamepadAction` is dispatched ONLY from the `navigator.getGamepads()` polling loop -
`src/frontend/helpers/gamepad.ts:559,678`, rAF-driven at `:593,628`, gated on the `gamepadconnected`
event. There is NO keyboard entry point into `src/preload/api/tauriGamepadInput.ts`.

38-C03 is the trap. Phase 34.1's item 7 listed "Tab/Shift+Tab", which reads keyboard-runnable. It is
not: pressing the physical Tab key exercises the webview's native focus traversal and never reaches
the preload module at all. A keyboard run would produce a GREEN result over the largest
never-executed surface in Phase 34.1 - the same class as the recorded lesson that a UAT pass can
cover a surface which cannot render at all.

The Tauri-only predicate that matters for 38-C08: `getFocusableElements()`
(`src/preload/api/tauriGamepadInput.ts:50-62`) builds its OWN focusable list and DROPS any element
failing `hasZeroArea(el.getBoundingClientRect())` (`:57`, defined `:46-48` as
`rect.width <= 0 || rect.height <= 0`), plus `disabled` and `aria-hidden="true"`. Electron's native
traversal applied no such filter, which is why an Electron pass would never have been evidence here
and why the retired 38-C07 was never load-bearing.
</dispatch_gate>

<c08_surface_note>
READ BEFORE RECORDING A FAIL ON 38-C08. The two surfaces do NOT look alike.

- On MainButton the affordance IS a caret: `className="SteamInstallCaret"`,
  `src/frontend/screens/Game/GamePage/components/MainButton.tsx:356`, a real split-button half inside
  a `flex-wrap: wrap` container (`:356-374`) - precisely the shape whose measured box can collapse to
  zero on one runtime and not another, which is what `hasZeroArea` would drop.
- On the GameCard there is NO caret. The entry is a CONTEXT-MENU item labelled
  `gamelib:steam.install.withOptionsLabel` ("Install with options…") at
  `src/frontend/screens/Library/components/GameCard/index.tsx:386-397`. An operator who goes looking
  for a caret on the card will find none and would record a FALSE FAIL against a surface that was
  never specified to have one.
- The caret leaves the tab order by UNMOUNTING, not by `disabled` (`MainButton.tsx:334-339` says so
  in comment form). On a non-Steam or non-installable game the CORRECT observation is that no caret
  element exists at all - not that a present caret refuses focus.

38-C07 (the Electron half) was RETIRED as unscoreable by plan 38-01, so 38-C08 has lost its
comparison arm. Run it against the game the operator would have used for both, and record which game
that was.
