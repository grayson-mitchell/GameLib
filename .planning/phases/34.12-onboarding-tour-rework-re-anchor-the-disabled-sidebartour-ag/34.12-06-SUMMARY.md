# Phase 34.12 Plan 06: Dead-attribute cleanup, the Layer B census gate, and the ROADMAP correction Summary

Removed the last three dead `data-tour` attributes, replaced the transitional `tourDisabled.test.ts`
gate with a RED-proven repo-wide uniqueness census (`navTourAnchorCensus.test.ts`), and corrected
`ROADMAP.md`'s Phase 34.12 section to match what actually shipped instead of what the phase's
opening description assumed still existed.

## What was built

**Task 1 — Three dead `data-tour` attributes removed.** `data-tour="library-header"` was present
on two unrelated elements (`LibraryHeader/index.tsx`'s `<h5>` and `Library/index.tsx`'s
favourites-section `<div>`) and `data-tour="humble-keys"` on `Humble/Keys/index.tsx`'s screen

`library-search`, etc.) and the deliberately-undefined `ActionIcons` passthrough were left
untouched.

**Task 2 — `navTourAnchorCensus.test.ts` landed, `tourDisabled.test.ts` deleted.** The new file is
Layer B of the phase's two-layer Positive Gate Contract: a source-text census proving each of the
twelve `NavShellTour` step ids, the `nav-launcher` id, and the two `LibraryTour` anchor ids is
defined on exactly one element under `src/frontend`, that the four dead ids are defined on zero
elements, and that no `data-tour` value anywhere uses the retired `sidebar-*` prefix — plus a
non-vacuity sanity check on the file walk itself. 22/22 tests pass. All four required RED proofs
were run and reverted (details below) before the deletion. `tourDisabled.test.ts` was confirmed to
have zero remaining references anywhere in the repo (besides this new file's own docstring, which
names it only in the assertion-mapping prose) before `rm`.

**Task 3 — `ROADMAP.md` Phase 34.12 section corrected.** The "34.10 IN-01" bullet named
`CategoryFilter`/`LibraryFilters` as carrying dead `data-tour` props — both components were deleted
outright by phase 34.11, confirmed via `find src/frontend -iname '*CategoryFilter*' -o -iname
'*LibraryFilters*'` returning zero results. Rewrote the bullet to record that the literal item had
nothing left to clean, and that the cleanup which actually survived and was executed here was
`library-header` (x2) plus the previously-uncatalogued `humble-keys`. Also updated the "Gate that
must be retired as part of this phase" paragraph to name `navTourAnchorCensus.test.ts` as the
landed, two-layer replacement.

## RED-proof record (all four required directions, each proven then reverted)

**1. Duplicate detection.** First attempt injected a second `data-tour="nav-downloads"` into
`NavShell/index.tsx` — this unexpectedly stayed green. Root cause: `NavShell/index.tsx` line 46
contains a `// ... routes like \`/gamepage/*\` where ...` line comment; the shared
`stripSourceComments` utility's non-greedy block-comment regex (`/\/\*[\s\S]*?\*\//g`) treats the
bare `/*` inside that line comment as an unclosed block-comment opener and swallows everything
through to the next real `*/` (a JSX comment closer at line 91) — hiding the injected duplicate
from the stripped source the census reads. This is a genuine, pre-existing limitation of a shared
utility, out of scope to fix here (see Deviations). Retried against a comment-clean file instead:
added `data-tour="nav-downloads"` to `HeroicVersion/index.tsx`'s `heroicVersionWrapper` div (a
sibling of the existing `heroicVersionContainer` div carrying `data-tour="nav-version"`). This
correctly failed exactly the `nav-downloads` uniqueness assertion (`Expected length: 1, Received
length: 2` — `DownloadsRing/index.tsx` and `HeroicVersion/index.tsx`) while every other assertion
stayed green. Reverted via `git checkout -- src/frontend/components/UI/NavShell/components/HeroicVersion/index.tsx`.

**2. Dead-id detection.** Re-added `data-tour="library-header"` to
`LibraryHeader/index.tsx`'s `<h5>`. This correctly failed exactly the `library-header` dead-id
assertion (`Expected length: 0, Received length: 1`) while every other assertion stayed green.
Reverted via the Edit tool back to `<h5 className="libraryHeader">`.

**3. Sidebar-prefix detection.** Added `data-tour="sidebar-menu"` to `QuitButton/index.tsx`'s
inner `NavItem__icon` div (a sibling of the button that already carries `data-tour="nav-quit"`).
This correctly failed exactly the sidebar-prefix-absence assertion (`Expected length: 0, Received
length: 1`) while every other assertion stayed green. Reverted via the Edit tool back to
`<div className="NavItem__icon">`. (An earlier, incorrect attempt added an unrelated
`data-red-proof="sidebar-menu"` attribute on the button itself — not a genuine second `data-tour`
value — caught immediately and reverted before being used as evidence.)

**4. Non-vacuity.** Pointed `FRONTEND_DIR` at an empty scratch directory
(`.../scratchpad/empty_frontend_dir`). Result, captured verbatim:
```
✕ scans a non-trivial number of frontend .tsx files (sanity check the walk is not vacuous)
✓ dead tour id library-header is defined on zero elements anywhere in src/frontend
✓ dead tour id humble-keys is defined on zero elements anywhere in src/frontend
✓ dead tour id library-categories is defined on zero elements anywhere in src/frontend
✓ dead tour id library-filters is defined on zero elements anywhere in src/frontend
✓ no data-tour value anywhere under src/frontend uses the retired sidebar-* prefix
```
This is the proof's whole point: against an empty (i.e. broken) walk root, every "exactly 0"
assertion — the four dead-id checks and the sidebar-prefix check — passes vacuously, because an
empty directory trivially contains none of the banned strings. Only the dedicated sanity check
(assertion 1, `expect(walk(...).length).toBeGreaterThan(100)`) catches that the walk itself is
broken; without it, this file's outputs on a silently-broken walk root would be indistinguishable
from a genuinely clean repo on five of its nine assertion groups. Reverted `FRONTEND_DIR` back to
`join(REPO_ROOT, 'src/frontend')`.

Pre-deletion zero-reference grep for `tourDisabled` / `tourDisabled.test.ts` across the repo:
zero matches outside this plan's own new file (which names the deleted file only in its
assertion-mapping docstring, not as an import or path reference).

### Discoveries (documented, not auto-fixed — out of scope)

**1. `stripSourceComments` mis-strips a file whose line comment contains a bare `/*` substring.**
- **Found during:** Task 2, first RED-PROOF #1 attempt.
- **Issue:** `NavShell/index.tsx` line 46's line comment (`// ... /gamepage/* ...`) contains a bare
  `/*`. The shared utility's non-greedy block-comment regex treats it as an unclosed block-comment
  opener and swallows all source through to the next literal `*/` elsewhere in the file, silently
  hiding real code from any source-text gate that uses this utility on that file.
- **Why not fixed:** Pre-existing, shared utility (`src/backend/testUtils/stripSourceComments.ts`)
  used by multiple gates beyond this plan's scope; fixing its regex has a blast radius well outside
  Task 2's three files. Not caused by this plan's changes.
- **Action taken:** Worked around by choosing a comment-clean injection site
  (`HeroicVersion/index.tsx`) for the RED proof instead. No production code affected.

**2. `helperProcess.test.ts` timed out under the full 5-project `pnpm test`, unrelated to this plan.**
- **Found during:** Post-Task-3 full-suite verification (`pnpm test`, all five jest projects, as
  required by this plan's `<verification>` since it is the phase's last autonomous plan).
- **Issue:** `src/backend/storeManagers/steam/bridge/__tests__/helperProcess.test.ts`'s `HEALTH
  answers err on every attempt ... (D-06)` test exceeded its 10000ms timeout; the file self-reported
  744.742s total (vs. 6.2s run alone).
- **Why not fixed:** Re-ran the file in isolation — 9/9 tests passed in 6.2s, including the exact
  test that failed under the full run, confirming CPU/resource contention from the five-project
  parallel run, not a real defect. Nothing in this plan's three tasks touches
  `src/backend/storeManagers/steam/`.
- **Action taken:** Logged to `deferred-items.md` per the scope-boundary rule; not fixed.

**3. Repo-wide `sidebar-` grep necessarily matches the census gate's own implementation.**
- The plan's verification command `grep -rc 'data-tour="sidebar-' src/ | grep -v ':0'` matches
  `navTourAnchorCensus.test.ts` itself (once in its docstring's assertion-mapping prose, once in
  the literal string the assertion searches for). This is expected, not a violation: a gate that
  bans a substring must contain that substring as a string literal to check for it. Re-ran the same
  grep excluding `__tests__` paths — zero matches, confirming the retired prefix is genuinely absent
  from all production code.
