## Decisions this plan resolves (Claude's Discretion, per CONTEXT.md)

**Location: `NavShell/components/NavShellTour/index.tsx`** — CONTEXT.md's recommendation.
`src/frontend/components/UI/Sidebar/` contains ONLY `SidebarTour.tsx`, so moving it empties
that tree and lets 34.10-09's original intent finally land.

**Tour id: `NAV_TOUR_ID = 'nav-tour'`**, mirroring `LIBRARY_TOUR_ID = 'library-tour'`
(`LibraryTour.tsx:7`). Per D-06 the only cost is that anyone who completed `'sidebar-tour'`
is eligible for the new tour — which is correct, it is a different tour.

**The launcher does NOT reuse `TourButton`.** CONTEXT.md suggests reusing it; `TourButton`
renders a MUI `IconButton` inside a `Tooltip`, which is exactly the icon-button shape D-01
rejected. Plan 05 instead ports `TourButton.tsx:22-27`'s three-line `handleStartTour` logic
(`hasTourCompleted` -> `resetTour` -> `startTour`) onto a `NavItem` row. `TourButton` itself
stays untouched and keeps serving `LibraryTour` per D-08.

**Only three steps mint new keys (D-07).** Decision rule, and the trap it avoids: compare the
new English copy against the CATALOG value in `public/locales/en/translation.json`, NOT
against the component's inline `t()` fallback. The two already disagree for several steps and
the catalog is what renders. Under that rule exactly two steps are factually wrong today:
- step 1: catalog `tour.sidebar.welcome.intro` says "This **sidebar** contains all the
  navigation options" and `tour.sidebar.welcome.title` is literally "Sidebar Navigation" —
  there is no sidebar. Both change -> `tour.nav.welcome.intro`, `tour.nav.welcome.title`.
- step 12: catalog `tour.sidebar.version` says "...access this tour from the **help icon**" —
  the help icon was removed in 34.10 and D-01 puts the launcher in a Settings row. Changes ->
  `tour.nav.version`.
Every other step's catalog copy is still accurate for its new anchor and KEEPS its existing
`tour.sidebar.*` key. The mixed namespace is the accepted cost D-07 names explicitly.

**Observed but deliberately NOT changed — TWO instances of the same defect class:**
1. The catalog's `tour.sidebar.accounts` reads "Manage your connected store accounts (Epic,
   GOG, Amazon)..." and omits Steam, GameLib's headline platform.
2. The catalog's `tour.sidebar.stores` reads "Browse and shop for games in different stores
   including Epic, GOG, and Amazon" — the **identical** Steam omission.

Both are copy-accuracy issues, not re-anchoring issues, and changing either would mint keys
for work outside this phase's boundary. Record **both** in the SUMMARY as observations for a
future copy pass; do not fix either here. (Flagging only one of the two would have left an
inconsistent record — the two steps carry the same defect and must be dispositioned the same
way.)
