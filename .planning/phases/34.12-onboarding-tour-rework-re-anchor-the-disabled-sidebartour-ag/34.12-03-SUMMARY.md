## Deviations from Plan

**1. [Rule 1 - Bug] DownloadsRing's in-component uniqueness test needed a populated queue, not an empty one**

- **Found during:** Task 2, while running RED-PROOF #2 for the duplicate-selector check
- **Issue:** The plan's uniqueness assertion, if mounted against the default empty-queue state, never renders the `DownloadsRing__count` badge span at all (`{elements.length > 0 && (...)}`) — so the assertion would pass vacuously against a tree that could never contain the duplicated anchor the historical `sidebar-downloads` defect produced, regardless of whether the source actually had a second `data-tour="nav-downloads"` or not.
- **Fix:** Mounted with a two-element queue (mirroring the file's existing "two-element queue" test pattern: `mount()` → `await Promise.resolve()` x2 → `reinvoke()`) so the badge span is actually present in the tree before asserting uniqueness.
- **Files modified:** `src/frontend/components/UI/NavShell/__tests__/DownloadsRing.test.tsx`
- **Verification:** Re-ran RED-PROOF #2 (adding a second `data-tour="nav-downloads"` on the count span) against the corrected test — it failed with `Received length: 2`, listing both tagged elements including the badge span, confirming the check now actually exercises the case it exists to catch. Restored and confirmed green.
- **Committed in:** `ed3e268b0` (part of Task 2 commit)
