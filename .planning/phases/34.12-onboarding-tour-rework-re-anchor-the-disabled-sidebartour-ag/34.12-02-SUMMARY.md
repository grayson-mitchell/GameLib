# Phase 34.12 Plan 02: Re-anchor LibraryTour's Two Dead Steps Summary

**Wrapped Header's five filter components in two `data-tour`-bearing divs and re-pointed LibraryTour's categories/filters steps onto them, closing the only user-visible defect in the phase that existed at HEAD rather than being introduced by it.**

## Accomplishments

- `Header` now nests `FilterViewList`+`FilterCollectionList` under `data-tour="library-views-collections"` and `FilterStoreFacet`+`FilterRunnabilityFacet`+`FilterMoreGroup` under `data-tour="library-facets"`, with both wrappers restating `.Header`'s `display:flex; flex-direction:column; gap:var(--space-md)` so the tier-2 filter panel's vertical spacing is unchanged
- `LibraryTour`'s two previously-dead steps (`[data-tour="library-categories"]`, `[data-tour="library-filters"]` -- both matched ZERO elements at HEAD, so intro.js silently skipped or mis-highlighted them for every user) now point at the two live anchors above
- Two new i18n keys, `tour.library.viewsCollections` and `tour.library.facets`, mint fresh English copy naming Views/Collections and the store/runnability/more-filters facet groups -- neither reuses "categories" or "platform"/"favorites", both of which 34.11 retired
- Two new structural test files (8 tests total) prove both anchors by child identity, the per-wrapper CSS gate, the absence of the dead selector strings, and the untouched steps' order -- all four required RED proofs recorded below, confirmed to fail for the right reason and restored green

## Decisions Made

- **OQ-1 -> wrap, not representative-element** (per plan): `FilterStoreFacet` renders `null` when `connectedStores.length === 0`, which would leave the facets anchor matching nothing for a fresh install -- exactly the user most likely to run the tour. Wrapping the whole group sidesteps that.
- **New selector strings, not reused ones**: `library-views-collections` / `library-facets` rather than resurrecting `library-categories` / `library-filters`, so a future census can tell "correctly re-anchored" apart from "the old dead string came back".
- **New i18n keys, not edited fallbacks** (D-07): editing the component's inline default string is a silent no-op once a key already exists in the catalog -- the catalog value is what renders, and it disagreed with both retired steps' copy.
- **Catalog-regeneration scope**: `pnpm i18n` is a repo-wide extractor; running it to mint this plan's two keys also surfaced 62 pre-existing missing keys in `translation.json` (plus 4 in `gamepage.json`, 1 in `login.json`) from earlier, already-landed phases that never re-ran the tool. Per the scope-boundary rule, only `translation.json` (this plan's declared file) was kept; the other two catalogs were reverted with `git checkout --`. Confirmed the full frontend suite (121/121, 1950/1950) is unaffected either way. Logged in `deferred-items.md`.
