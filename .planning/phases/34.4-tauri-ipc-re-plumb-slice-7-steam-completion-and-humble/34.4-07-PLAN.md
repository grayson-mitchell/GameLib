<objective>
Replace the silently-blank login screen with an honest "not available on this build" panel (D-04).

Purpose: this is a real, user-visible gap, not a hypothetical. Phase 34.1 D-12 made
`getWebviewPreloadPath` return a declared-empty `''` on the sidecar, and
`src/frontend/screens/WebView/index.tsx:446-448` returns `<></>` when there is no preload path — so
**under Tauri today, clicking "Log in to Humble" renders nothing at all: no error, no log line, no
explanation.** 34.1's own `34.1-PORTED-CHANNELS.md` explicitly parked "the `<webview>` login story"
in this phase.

This slice formally defers the actual fix (the shared `<webview>`/`session.fromPartition` seam moves
to the new Phase 34.4.1 by D-01), which makes it exactly the right slice to stop the gap being
invisible. Leaving the blank screen and merely declaring it is refused — that is the failure shape
34.3 D-01 called out for clipboard, made worse here because Tauri is not yet the shipped build, so
nobody would catch it. Hiding the login entry point under Tauri is also refused: it hides a shipped
feature behind a build check Phase 35 must unwind, and it would make the gap invisible during
34.4.1's own testing.

**The rider is load-bearing: this must not change Electron's behavior at all.** Electron always
resolves a real preload path, so the branch is structurally unreachable there — and D-04 requires
that be **proven in the test, not asserted in prose**.

Output: a small extracted panel component, a one-branch edit in `WebView/index.tsx`, and a test that
proves the Electron path never reaches it.
</objective>

`if (!webviewPreloadPath) { return <></> }`. `webviewPreloadPath` is component state initialised to
`''` at L157 (`const [webviewPreloadPath, setWebviewPreloadPath] = useState('')`) and populated from
the `getWebviewPreloadPath` IPC channel. Immediately below it, L453-455 has a second early return for
`runner === 'humble' && !humbleLoginUserAgent` (the standard-Chrome-UA guard) — leave that one alone.
The `<webview>` element itself is at L467-482, with `partition={persist:...}` serving Humble, Epic,
GOG and Amazon alike. That single element is the shared seam D-01 carves into Phase 34.4.1.

**`isTauri()` import path.** `isTauri` is exported from `src/preload/tauriTransport.ts:52` (it returns
`Boolean(w.isTauri) || typeof w.__TAURI_INTERNALS__ !== 'undefined'` — see L41-57's docstring
explaining why the plain `@tauri-apps/api/core` check is insufficient). Existing frontend consumers:
`src/frontend/index.tsx:36` imports it as `'../preload/tauriTransport'`;
`src/frontend/state/GlobalState.tsx:50` as `'../../preload/tauriTransport'`. From
`src/frontend/screens/WebView/index.tsx` the relative path is three levels up. Confirm the exact
specifier against the project's tsconfig path aliases before writing it.

**Extraction pattern to follow** — `CrossoverBadge.tsx` / `MacArchBadge.tsx`: this project's
convention for a small, independently-testable conditional-render fragment is its own tiny component
file with **no hooks of its own**, so its test can invoke it as a plain function and assert on the
returned element without a jsdom or react-test-renderer harness. Read `src/frontend/jest.config.js`'s
docstring for why the frontend project is set up this way, and `CrossoverBadge.test.tsx` (75 lines)
for the exact test shape, including its `jest.mock('react-i18next', ...)` returning
`t: (_key, defaultValue) => defaultValue`.

**Clipboard constraint.** If the panel offers any copy affordance, it must use
`window.api.clipboardWriteText` / `window.api.clipboardReadText` (ported by Phase 34.3), never
`navigator.clipboard` — under Tauri's WKWebView `navigator.clipboard.writeText` resolves WITHOUT
writing and never rejects, so success paths still run
(`navigator-clipboard-noops-under-tauri`). The simplest compliant choice is to offer no copy
affordance at all.

**`src/backend/sidecar/__tests__/electronUntouched.test.ts`** is the additive/reversible guard,
behavioral since Phase 34.1. This plan touches a frontend file. If that guard flags the change, do
**not** weaken or repurpose it silently — stop and report, per REQ-34.4-15's "if any existing test's
contract must change, it changes openly with a stated reason."
