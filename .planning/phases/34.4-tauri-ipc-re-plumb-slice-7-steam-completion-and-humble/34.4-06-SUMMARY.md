# Phase 34.4 Plan 06: Harden electronStub.net.request (D-06) Summary

**`net.request()` graduated from a total silent dead end to a fail-fast, seam-naming async error, proven end-to-end to reach `humblePostRequest`'s own handler through the real (unmocked) stub — plus one dormant-but-blocking gap (`app.userAgentFallback`) found and worked around along the way.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 2
- **Files modified:** 3 modified, 1 created

## Accomplishments
- `electronStub.ts`'s `net.request()` now records `on()` handlers by event name and asynchronously (`setImmediate`) invokes a registered `'error'` handler with an `Error` naming the stub, Phase 34.4.1, and D-06 — never a synchronous throw, never a rejecting promise a fire-and-forget caller could crash on.
- `humblePostRequest`'s own already-wired `request.on('error', ...)` handler (`adapter.ts:328`) is now provably reachable — verified via `revealKey()` (the exported caller) against the REAL hardened stub, not a fake.
- Added `netStub.test.ts`: Group 1 pins the stub's own contract in isolation; Group 2 is the discriminating integration proof — the rejection carries D-06's seam text, not the pre-fix `"Humble reveal request timed out"` message, and settles without `REQUEST_TIMEOUT_MS`'s `setTimeout` ever being advanced.
- Discovered and worked around a dormant gap: `electronStub.ts`'s `app` object has no `userAgentFallback` member, which `humble/userAgent.ts`'s `standardBrowserUserAgent()` reads — and that call sits INSIDE `humblePostRequest`, before `request.on('error', ...)` is ever reached. Left unfixed in production code (currently unreachable there); patched only inside the test's own `electron` mock factory.
- Discovered (via the hand RED proof) a second, deeper dormant gap: `humblePostRequest`'s timeout branch calls `request.abort()`, which the stub's four-method surface (`on`/`end`/`write`/`setHeader`) has never implemented, pre- or post-D-06 — so the pre-fix code's real failure mode on a genuinely-elapsed timeout is not the "misleading timeout message" the plan's `<objective>` describes, but a masking `TypeError: request.abort is not a function`. Recorded here for Phase 34.4.1; not fixed (out of scope, D-01/D-02).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `lifecycleStub.test.ts`'s stale "request() member is unchanged" assertion no longer typechecked**
- **Found during:** Task 1, running `npx tsc --noEmit` after the `net.request` edit
- **Issue:** A pre-existing test called `req.on()` with zero arguments, asserting the old no-op signature was untouched — TypeScript now requires `on(event: string, cb: ...)`'s two arguments, so the file failed to typecheck as a direct, mechanical consequence of Task 1's change.
- **Fix:** Rewrote the assertion to call `req.on('error', () => {})` and narrowed its scope/name to state that only `end`/`write`/`setHeader` remain unchanged no-ops — full D-06 coverage now lives in `netStub.test.ts`.
- **Files modified:** `src/backend/sidecar/__tests__/lifecycleStub.test.ts`
- **Verification:** `npx tsc --noEmit` exits 0; `npx jest sidecar/__tests__/lifecycleStub.test.ts` passes.
- **Committed in:** `c1544acb` (part of Task 1's commit)

**2. [Rule 3 - Blocking issue] `app.userAgentFallback` missing on the real stub, masking D-06 behind an unrelated crash**
- **Found during:** Task 2, while designing Group 2's "drive the REAL, unmocked net stub" integration test
- **Issue:** `humble/userAgent.ts`'s `standardBrowserUserAgent()` reads `app.userAgentFallback`, which `electronStub.ts`'s `app` object never defines. That call happens INSIDE `humblePostRequest`, before `request.on('error', ...)` is ever attached — on the real stub it throws a `TypeError` synchronously (`.exec(undefined)` → no match → `undefined.replace(...)`), which the surrounding `new Promise((resolve, reject) => {...})` converts into a rejection with the WRONG cause, completely masking D-06's fix from the integration test.
- **Fix:** Supplemented (not modified) `app.userAgentFallback` inside `netStub.test.ts`'s own `jest.mock('electron', ...)` factory, spreading the real, unmocked hardened `net` implementation unchanged. `electronStub.ts` itself is untouched by this fix.
- **Files modified:** `src/backend/sidecar/__tests__/netStub.test.ts` (test-scope only; no production code changed)
- **Verification:** Group 2's integration test passes against the fixed stub and fails for the documented reason against the pre-fix stub (see hand RED proof below).
- **Committed in:** `f93d6c59` (part of Task 2's commit)

## Hand RED Proof (Task 2, mandatory)

Restored the pre-D-06 `electronStub.ts` via `git show HEAD~1:src/backend/sidecar/electronStub.ts` (HEAD at the time = Task 1's commit `c1544acb`), ran `netStub.test.ts`, and confirmed both discriminating tests fail for the expected reason:

- **Group 1** ("invokes a registered 'error' handler... after a flush"): `expect(errorSpy).toHaveBeenCalledTimes(1)` → **received 0 calls** — the pre-fix `on()` never records anything, so the handler genuinely never fires.
- **Group 2** (the `revealKey`/`humblePostRequest` integration test): the test **never settles** and fails with Jest's own `Exceeded timeout of 5000 ms for a test` — because the pre-fix `on()` records nothing, `request.on('error', ...)` is never invoked, and the test deliberately never advances the fake `REQUEST_TIMEOUT_MS` timer (that is the whole point of the discriminating assertion), so nothing else can ever resolve the promise.

**Correction to the plan's own prediction, recorded here rather than silently absorbed:** the plan's `<objective>`/Task 2 action assumed that forcing the pre-fix timeout to elapse would surface the misleading `"Humble reveal request timed out"` rejection message, and asked for that verbatim text to be recorded. A separate, ad hoc check (a throwaway scratch test, deleted before this commit, that used `jest.advanceTimersByTimeAsync(15_000)` to force the pre-fix timer to fire) showed this is not what actually happens: `humblePostRequest`'s timeout branch calls `request.abort()`, which the stub's four-method surface has **never** implemented (neither before nor after D-06) — so the real pre-fix failure mode on a genuinely-elapsed timeout is:

```
TypeError: request.abort is not a function
    at src/backend/humble/adapter.ts:283:15
```

— not a clean rejection with the misleading text at all. This is an even stronger illustration of why D-06 (and, eventually, a real Phase 34.4.1 transport) is needed than the plan anticipated, but it means the "verbatim before message" requested in the plan does not exist as a clean string — it is this masking `TypeError` instead. Recorded as fact rather than fabricating the text the plan expected.

**"After" (fixed) message, verbatim**, observed directly from the shipped `Error` construction in `electronStub.ts`:
```
[electronStub] net.request(): not implemented in the sidecar -- this seam is Phase 34.4.1's (Humble reveal POST). See D-06.
```
