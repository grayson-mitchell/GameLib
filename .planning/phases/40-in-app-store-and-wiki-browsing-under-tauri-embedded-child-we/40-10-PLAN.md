<planning_findings>
1. **The panel now serves TWO distinct cases where it used to serve one.** Before this phase it said
   "in-app store and wiki browsing is not available on this build" for every store route on every
   platform. After plan `40-08` it is reached in two situations with different truths: on Windows and
   Linux for ANY store route (D-02 — a platform reason), and on macOS for the Epic route only (D-08 —
   a provisional, non-accusatory reason). One message cannot honestly serve both. The component needs
   a reason discriminator, not a second component.

2. **D-08's wording constraint is factual, not a tone preference.** The confirmed Epic 403 is on a
   LOGIN endpoint. Whether Talon guards store browsing the same way is untested — that is exactly what
   the spike D-05 creates exists to answer. So the copy must not assert that Epic blocks in-app
   browsing. Wording along the lines of "Epic Store browsing isn't available in-app yet" is accurate;
   anything naming Epic as the cause is a claim this project has not earned and would have to retract.

3. **The Epic tile stays** in the stores panel (D-08). Do not remove it. A tile leading to a working
   escape hatch beats no tile, and removing it would hide the gap from the user — the opposite of what
   D-02's principle requires.

4. **The panel's existing conventions to preserve**: a hookless static panel using only the translation
   hook; the translation call shape that passes a key and a default; an open-in-browser button through
   the existing external-open API; and the WebView screen logging the gap before returning it, per the
   "logged, never silent" discipline. Keep all four.

5. **The i18n rules that bite here, from project memory.** New strings go in `gamelib.json`, never
   `translation.json`, and NO gate catches a violation — the lint gate is blind to an absent key.
   Renaming a string through the translation function's DEFAULT argument is a no-op when the key
   already exists. And nothing detects English-side drift, so a changed English string under an
   existing key silently disagrees with every translated locale. Mint NEW keys; do not edit defaults
   in place.

6. **Phase 38 is the destination D-04 names** — the deferred hardware and environment gate collection.
   Four unknowns belong there: whether the embed mechanism works at all on the Windows backend; the
   same for Linux; retina behaviour at scale factor 2.0; and drag-resize latency. Two of those four
   also appear in plan `40-11` as macOS human-verification items, so each ledger entry must say it is
   the NON-macOS version and that `40-11` passing does not close it. Without that sentence a reader
   who sees `40-11` pass will believe the ledger item is satisfied — the one-direction audit failure
   this project has already recorded.

7. **The spike harness already exists** for D-07's Epic probe at
   `.claude/skills/spike-findings-gamelib/sources/016-embedded-child-webview-basic/app/` — a full
   runnable multiwebview app with an interactive panel and a scripted autorun mode. Name that path in
   the filing; a spike filed without its harness path costs the next person the search.

8. **This phase's minted strings come from three plans**: the placeholder (plan `40-06`), any
   genuinely new chrome label (plan `40-07`, which otherwise reuses the existing localised control
   keys), and the two panel messages minted here. The census must count what was ACTUALLY minted by
   reading the catalog diff across the whole phase, not what those plans predicted they would mint.
</planning_findings>
