<objective>
G28 (UAT 38): after the confirmed engine-restore-failed dialog at 19:31:45, three later engine
notices (19:31:48, 19:32:09, 19:32:10) logged `display=unconfirmed timeout=15000` and the operator
saw nothing on those Play clicks.

Diagnosis-first. Evidence already gathered at planning time (verify it, do not take it on trust):
`~/Library/Logs/GameLib/gamelib.log` lines 150-184 show each of the three unconfirmed notices
followed by `[dialog] showDialog frame received ... replacesOpenDialog=true visibility=visible
hasFocus=true`, so every frame reached the renderer and was queued behind an open dialog
(`src/frontend/state/dialogQueue.ts` queues while `current.showDialog` is true). The ack is only
sent when a queued dialog becomes current. The leading hypothesis for why none ever became
visible: `Dialog.tsx` holds `const [open, setOpen] = useState(true)` and its `close()` does
`setOpen(false)` then `onClose()`; `onClose` dispatches `{ showDialog: false }`, the reducer
promotes the next queued dialog, `dialogModalOptions.showDialog` stays true, so React does not
unmount `MessageBoxModal`/`Dialog`; the same instance keeps `open === false`, the MUI dialog stays
closed, and the state believes a dialog is open, so every later request queues behind an invisible
one. That matches "operator saw nothing" with `replacesOpenDialog=true` at 19:32:09-10 (the operator
had closed the first dialog by then; Play was clickable, so no modal was on screen).

Output: diagnosis in SUMMARY, a failing-then-passing test, a keyed remount fix and renderer log lines
(or a todo if the cause is not in this code).
</objective>
