<objective>
Close G30 (minor, re-UAT 5 item 42) and WR-02 from the round-5 review.

G30 root cause (.planning/debug/g30-slow-dxvk-removal-on-crossover-restore.md): the strict restore
in `DXVK.installRemove` runs `reg delete` d3d10core, `reg delete` d3d11 and `wineboot -u` through
CrossOver as three `runWineCommand({ wait: true })` calls. Each settles on pipe `close`, which waits
out the wineserver's 3-4 s linger (scratch measurements: reg about 1.0 s exit / 4.1 s close;
wineboot -u 6.0 s / 10.1 s), and `wait: true` also runs `wineserver --wait`. Same mechanism as
a2f661281 (shared redists) and 110920bcd (DRM stage), which both use `wait: false` with
`resolveOnExit: true`. Expected effect: the switch-to-launch time drops from about 20 s to about
8-14 s (the first call still carries the automatic prefix update that every engine flip forces).

Because the restore now returns while its CrossOver wineserver is still alive, prepareBottleForEngine
stops it once afterwards, as it already does for the built-in-engine restore (G10). Without that,
a launch on the phase-60 overlay clone could join a stock-CrossOver server (60-RESEARCH Pitfall 2).

Not done here, by instruction and on evidence: removing `wineboot -u` (the auto-update replacing
it was shown only on Wine-Staging, unverified on CrossOver) and batching the two deletes into one
`reg import` (saves about 1 s after this change, and adds an import format unverified on
CrossOver whose failure mode is a silent no-op). Both go to the todo 59-52 files.

WR-02: the review assumed two titles in the legacy shared bottle can switch it concurrently. That
path is already refused before any kill (`shared-bottle`, 59-REVIEW WR-06, engineSwitch.ts:439-447).
What remains is that the install path (`resolveInstallEngineSettings`, games.ts:2580-2614) calls
prepareBottleForEngine with no in-flight guard, so an install-time switch and a launch-time switch
of the same per-game bottle can interleave. A per-bottle serialisation inside prepareBottleForEngine
covers launch and install alike.
</objective>
