# Phase 88.1 Plan 02: prepare_launch and Epic status goldens Summary

**The whole prepare step a store manager runs before building its command (offline resolution, the Epic status check, anti-cheat, the Linux tool probes, umu, the CrossOver bottle folder) and the Epic status check itself are pinned by 652 TS-recorded golden cases in gamelib-launch before any Rust prepare code exists.**

## Accomplishments

- Task 1 (tracer): `isEpicServiceOffline` ran end to end over one replayed exchange, the tracer's `<verify>` (jest, manifest, prettier) was re-run, then the slice grew to 70 cases: each service type against `operational`, `degraded_performance`, `partial_outage`, `major_outage`, `major` and `under_maintenance`, an absent component, the monitor offline (zero requests, zero notifications), 13 transport error codes (the 11 the TS lists plus `EPROTO` and `ERR_CANCELED`), six HTTP error statuses, eight malformed bodies and one named case per `epicServiceStatus.test.ts` title. The notification copy is the real English catalogue text.
- Task 2: `golden/prepare_launch` holds 582 cases: 15 (OS, runner) cells, each with an identity suite and, on Linux, a tools suite, plus named cases for mangohud missing on Flatpak, gamescope missing on Flatpak, Steam Deck game mode, a third-party app on Mac CrossOver (bottle reported, line unterminated, none, probe fails), anti-cheat status only, empty list and both, umu downloaded and skipped offline, and one case per `epicOfflineMode.test.ts` title. Each case records `input`, `result`, `log`, `spawns` (with class), `requests` and `events`.

## Deviations from Plan

### Auto-fixed / judgement calls

**1. [Rule 1 - Bug] `recordingLogWriter` left promises nested in an array part unsettled**
- **Found during:** Task 2
- **Issue:** `prepareLaunch` logs `logInfo(['System Info:', promise, ...])`; the 88.1-01 recorder only settled top-level promise parts, so the entry would have recorded a pending promise as `{}`. The real writer's `stringifyLogValue` awaits nested promises.
- **Fix:** the recorder settles one array level, with a unit test.
- **Files modified:** src/backend/testUtils/launchOracle/fakeLauncherDeps.ts, src/backend/testUtils/launchOracle/__tests__/fakeLauncherDeps.test.ts
- **Commit:** 4ac8c07cf

**2. [Rule 3 - Blocking] a shared `replayAxiosClient` helper**
- **Found during:** Task 2
- **Issue:** `backend/utils` builds `axiosClient` at import, so `installRecorder` alone does not reach it, and the recorder's `networkError` exchange raises an error with no `request`, which `isNetworkLevelFailure` reads as a config error rather than "unreachable".
- **Fix:** `testUtils/launchOracle/epicReplay.ts` installs the recorder in replay mode only, puts its dispatcher on the client's own adapter and gives a transport failure the code and request the real http adapter attaches. Both oracles use it. A `networkError` exchange carries an extra `errorCode` field the Rust replay needs.
- **Files modified:** src/backend/testUtils/launchOracle/epicReplay.ts (new), epicStatus.oracle.test.ts
- **Commit:** 4ac8c07cf

**3. [Rule 3 - Blocking] pairwise rows are generated by suite, not over one product**
- **Found during:** Task 2
- **Issue:** the plan asks for pairwise rows over about twenty axes per cell. `allPairs` enumerates the full feasible product (over a million rows on Linux legendary), which does not fit in memory.
- **Fix:** two suites per cell sharing the axes they interact on, a feasible predicate that collapses axes the step never reaches, and a composite gamescope axis (see key-decisions). `uncoveredPairs` is `[]` for every cell and suite, and every axis value appears. Tool axes against anti-cheat, Epic status and the expired flag are not paired. This is a narrower claim than the plan's "pairwise within each cell"; whether it is enough is the verifier's call (D4).
- **Files modified:** src/backend/__tests__/oracle/launchPrepare.oracle.test.ts
- **Commit:** 4ac8c07cf

**4. [Rule 1 - Plan contradiction] censuses carry reasoned exclusions and different title counts**
- **Found during:** Tasks 1 and 2
- **Issue:** the plan asks for "13 titles" for `epicServiceStatus.test.ts`; the file has 16 (14 behaviour titles and two `utils.ts wiring gate` source-text gates). `epicOfflineMode.test.ts` has 8 (five behaviour titles, three `R8 source gate` titles).
- **Fix:** the source-text gates are listed as not ported with the reason "source-text gate, dropped per D-15" (88-CONTEXT D-15, as 88.1-01 did for gamescope); the other 19 titles are named cases, and each census also asserts no case exists without a title.
- **Files modified:** epicStatus.oracle.test.ts, launchPrepare.oracle.test.ts
- **Commit:** 6a59abcc2, 4ac8c07cf

**5. [Rule 3 - Blocking] cases.json, deltas.json and the authored exchanges are generated, not hand-typed**
- **Issue:** the plan calls them hand-authored; pairwise rows are generator output and the exchanges follow the case table.
- **Fix:** write mode writes them from the tables and compare mode asserts the committed files equal the builders (88.1-01's approach). `deltas.json` holds `discord-rpc-dropped` once in `prepare_launch` and `js-engine-error-text` in `epic_status`.
- **Commit:** 6a59abcc2, 4ac8c07cf

**Total deviations:** 5 (2 plan contradictions, 2 blocking, 1 bug). **Impact:** none on the goldens' purpose, except deviation 3, which narrows the pairwise claim.
