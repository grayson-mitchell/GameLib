# Phase 88.1 Plan 05: System information goldens Summary

**System information (gpu, memory, os-release, Steam Deck, version probes, pci.ids DNS lookups and caches, the single-flight cache and the byte-size format) is pinned by 94 TS-recorded golden cases in gamelib-info before any Rust port exists, with every probe, lookup and manager call scripted so nothing real runs.**

## Accomplishments

- Task 1 (tracer): `systemInfo.oracle.test.ts` drives the real `createSystemInfoCache().getSystemInfo` and `formatSystemInfo` over an injected platform, `process.arch`, `os.*` probes, the three os-release locations (`fs/promises` `stat`/`readFile` answer for those paths only), `FLATPAK_ID`/`APPIMAGE`, `isSteamDeckGameMode`, a spawn tracer, fake library managers and a scripted `dns.resolveTxt`. One Linux AMD case was recorded and compared: its `dns.json` has the `e445.1da2.73bf.1002.pci.id.ucw.cz` and `1002.pci.id.ucw.cz` lookups and `cache.json` the write-back. The tracer's `<verify>` was re-run before expanding.
- Task 2: the slice grew to 94 cases (floor 94): 21 named incident-title cases, 6 single-flight and sequence rows, free/os-release/env rows, 15 pci.ids rows, 11 Steam Deck rows, macOS and Windows rows, 13 version-probe rows, the app-version names, a no-CPU row and the `filesize` vector table. Three censuses (one per systeminfo test file) pass with an empty not-ported map.
- Each case writes eight files (`input`, `result`, `text`, `spawns`, `versions`, `dns`, `cache`, `events`) sharing one `seq` counter, so a probe, a version call, a lookup and a log line keep their order.

## Deviations from Plan

### Auto-fixed / judgement calls

**1. [Rule 1 - Plan contradiction] the three test files hold 21 titles, not 20**
- **Found during:** Task 2
- **Issue:** the plan and its acceptance criterion say "20 titles"; `gpuLinux.test.ts` has 11, `probes.test.ts` 6 and `index.test.ts` 4.
- **Fix:** all 21 are named cases, and a test pins the split `[11, 6, 4]` so a renamed or added test title is noticed.
- **Files modified:** src/backend/__tests__/oracle/systemInfo.oracle.test.ts
- **Commit:** ade29b55f

**2. [Rule 3 - Blocking] the code under test is loaded in a fresh registry, and the logger is spied on two instances**
- **Found during:** Task 1
- **Issue:** `backend/utils` imports `systeminfo`, so `pci_ids.ts` is loaded (and its `promisify(resolveTxt)` captured) by almost any import; and the backend project's `resetMocks` wipes a spy's answer before every test, which made the first lookup hang.
- **Fix:** the dns spy is installed first, the modules are required in `jest.isolateModules`, and the spy's answer is re-installed per case. Because modules `import()`ed later (`gpu/linux`, `memory/*`, `osInfo/*`) resolve in the file's own registry, both logger instances are spied so no warning line is lost.
- **Files modified:** src/backend/__tests__/oracle/systemInfo.oracle.test.ts
- **Commit:** df0a29cd9, ade29b55f
