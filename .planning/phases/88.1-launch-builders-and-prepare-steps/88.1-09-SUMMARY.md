# Phase 88.1 Plan 09: System-information probes and the pci.ids caches Summary

**The system-information probes, the pci.ids name lookups and their two caches are Rust in `gamelib-info/src/sysinfo/`, with the DNS TXT query written in-repo over UDP (operator decision A) and golden/sysinfo replayed in full: 87 probe cases compared, 7 handed to 88.1-10.**

## Performance

- **Tasks:** 3 (tracer, operator decision, pci.ids and the rest)
- **Commits:** 2 (`3027711fe` Task 1, `f6201c6f5` Task 3), measured from the ledger base `9ab6a25bb`
- **Completed:** 2026-11-25

## Accomplishments

- **Task 1 (tracer, `3027711fe`):** `InfoCtx.proc`, `HostFacts`/`RealHostFacts` per OS, `parse_lspci_gpus`, `gpu_info_linux`, the memory probes and `os_info`; the Linux and macOS cases replayed.
- **Task 3 (`f6201c6f5`):**
  - `dns.rs`: `TxtResolver` seam and the production `SystemTxtResolver`: nameservers from `/etc/resolv.conf` (unix) or `GetNetworkParams` (Windows), a recursive TXT query over a connected tokio UDP socket, at most three servers, 2 s each inside a 5 s total bound, a shutdown registrant held for exactly the time the lookup is in flight and a token race that ends it on cancel. NXDOMAIN and a TC-flagged answer are definitive; SERVFAIL and a silent server hand on to the next.
  - The reply parser (T-88.1-18): checks the id, QR and opcode bits, that the question is echoed (case-insensitively), reads every length against the packet, caps the answers walked at 32 and the name at 255 bytes, and never follows a compression pointer (a pointer must point backward past the header; a self-pointing, forward or in-header pointer is malformed). The answer is used as a display name only and is never logged.
  - `pci_ids.rs`: `lookup_device_string`, `lookup_vendor_string` and `populate_device_and_vendor_name` over `pci_ids_device` and `pci_ids_vendor` (7 days, `InvalidateCheck::Always`, constants in `cache_view.rs`), with the TS sequence: sub-id key, plain key, write-back under the sub-id key; device and vendor are both looked up before either is checked, and a GPU missing either name is dropped.
  - `gpu.rs`: the Windows PowerShell parse (a single object or an array, a bad member spoils the array, NVIDIA `31.0.15.3713` shown as `537.13` with JS `slice` clamping, `VEN_/DEV_/SUBSYS_` matched with `.{4}` semantics), `get_gpu_info` for all three platforms with one fixed warning on failure. `deck.rs`: `steam_deck_info`. `mod.rs`: `probe_system` and `SystemProbe`.
  - `golden_sysinfo.rs`: calls `probe_system` (the Task 1 emulation is gone), a scripted `TxtResolver` answering `dns.json`, seeded caches aged per case, and compares result (CPU, memory, GPUs, OS, Steam Deck, the two container flags), spawns, events, lookup order and cache contents before and after. `compared + deferred >= 94` is the floor check.

## Decisions Made

**Operator decision at Task 2 (blocking-human): option A, an in-repo TXT query over std UDP.** Chosen by the operator. Reason: it is the only option adding no crate (the Cargo.lock name count stays 716) and needing no re-plan; the recorded answers are short single `i=<name>` strings, so no TCP fallback is needed; T-88.1-18 already prices it with malformed-packet vectors; A is reversible and B is not; C (nslookup) would regress GPU names on Linux desktops that lack nslookup. Options B (`hickory-resolver`) and C (`nslookup -type=TXT`) were not taken.

Implementation note on that decision: the socket is tokio's `UdpSocket` (feature `net`, already in the lockfile through the shell's tokio), not a blocking `std::net::UdpSocket`, so cancellation is immediate and no blocking-pool thread is left behind. See also `key-decisions` in the frontmatter.

## Flagged assumptions

- **SVC-03 edge coverage is `unclassified` and unresolved** (spec-less edge probe): the D-14 matrix stands in for it and is not claimed as a verified edge.
- macOS `RealHostFacts::free_mem` returns 0; nothing on macOS reads it (the macOS memory probe uses `sysctl` and `vm_stat`).
- `read_os_release` treats an unreadable file as not found and moves on to the next location; the TS would have thrown on a read error other than a missing file.
- The TXT string is decoded as UTF-8 with replacement; I did not verify whether Node's resolver decodes TXT bytes as UTF-8 or Latin-1. `pci.ids` names are overwhelmingly ASCII; the goldens hold only ASCII.
- A TC-flagged (truncated) UDP answer is treated as no answer, with no TCP retry, as the operator's option A scopes it. c-ares retries over TCP, so a name whose answer exceeds the UDP size would resolve in Node and not here; the recorded answers are short strings.
- Windows resolvers come from `GetNetworkParams`, which lists IPv4 servers only.
- `PciCaches::open` is only attempted when at least one GPU was listed, so a macOS or GPU-less machine creates no cache file; the TS opened the stores at boot. The golden `cache.json` is `{}` for those cases either way.

## Known Stubs

None. `probe_system` stops short of the software versions, the formatted sizes and the single-flight cache by design; those are 88.1-10's and the `sequence` (6) and `filesize` (1) golden cases are counted as deferred against the floor.

## Threat Flags

None. T-88.1-18 (bounds-checked parser, no recursion, size cap, malicious-packet vectors all answering `None`), T-88.1-19 (every probe a Helper ProcSpec with the TS 30 s bound; the lookup bounded to 5 s and cancelled on shutdown) and T-88.1-20 (failures log fixed text; the queried name and the answer are never logged) are implemented as planned. The lookup opens a UDP socket to the system's resolvers, which is the one network surface this plan adds, and it is the one T-88.1-18 names.
