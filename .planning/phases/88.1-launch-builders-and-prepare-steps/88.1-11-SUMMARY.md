### Design points the plan left open (judgement calls, not golden diffs)

- **Trait shape.** `PrepareDeps` has `search_on_path` as a synchronous call and `umu_path_is_default()` in place of `umu_path()`; `umu_supported` is a pure function of the settings (it never asks whether umu is installed here), so it is not a dependency.
- **A fourth host fact.** `PrepareHost` carries `steamDeck` beside `steamDeckGameMode`: the TS `isSteamDeck` is true in desktop mode too, and the Linux non-native log filter reads it. The golden pins both to game mode.
- **System information that cannot be read.** The TS rejected the whole prepare on a failed read; Rust writes the fixed line `System information could not be read.` and continues (no golden covers it, and failing a launch for a log line seemed wrong). Recorded here so 88.3 can revisit.
- **Settings key order.** `serde_json` is built without `preserve_order` workspace-wide, so the `Game Settings:` object lists its keys alphabetically where the TS kept merge order. Every key and value is compared (as JSON); only the printed order differs.
- **Spawn comparison.** The gamescope help probe is scripted with the answer the golden spawn recorded (the child's output is a replay input); the Rust request side (program, argv, 5 s limit, env diff, cwd, result, class) is compared. `replaceEnv`, `resolveOn`, `timeoutNone` and `windowsHide` are TS spawn-wrapper options with no Rust twin and are not compared.
- **Documented prepare_launch differences** (each must be used by a case or the replay fails): `observation-points` (the online-monitor ask count and the store-hook call), `epic-status-log-fixed-text`, `wine-spawn-failure-line` (the TS command runner logged `Wine command failed to run: Error: spawn ENOENT`; the Rust wine core answers that in its result and logs nothing), `discord-rpc-dropped`, `settings-key-order`.
- **`launch_prepare` is not in `UNBOUNDED_RUST_CHANNELS` yet.** It can download the umu runtime past the 60 s bound (T-88.1-27); the shim that calls it is 88.1-15 and lists it there. Until then nothing calls it.
- **Gamescope settings of an unexpected shape** (a non-string width, say) and an unterminated quote in `additionalOptions` answer `launch_prepare:<fixed message>` (shlex's own message for the quote, as `launch_setup_wrappers` does); the TS threw.
