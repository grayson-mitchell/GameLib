# Phase 88.1 Plan 07: Launch channels and the builder shims Summary

**Five `launch_*` rustInvoke channels behind a new shell `launch_dispatch`, with the managers' four builder calls (`setupWrapperEnvVars`, `setupEnvVars`, `setupWrappers`, `getKnownFixesEnvVariables`) on scheduled async shims and awaited through gog, legendary, nile and the sideload native launch.**

- **Completed:** 2026-11-25

## Accomplishments

- `launch_dispatch.rs`: one `Arc<LaunchCtx>` built by `install()` right after `knownfix_dispatch::install` in `run_setup`; five `rpc_launch_*` arms, each decoding with the generated type and an arity check before looking at the context, then running `gamelib_launch::dispatch_sync`. The two env arms append `wine_dispatch::wine_run_host()` after the context check, so the sidecar sends no environment or Darwin release (T-88.1-14).
- Five channels in `sidecarTransport.ts` (constant plus list entry, all inside the 60 s `RUST_INVOKE_TIMEOUT_MS`), zod args in `rustInvoke.ts`, arms in `rust_dispatch.rs`, regenerated `ipc_contract.rs`. Channel count 205 to 210.
- `launchrust/builders.ts`: four shims, each one returned typed call, each a schedule row with `deletedBy: 92`. The wine-env channel exists with its schema and arm but no shim (88.1-08 wires it with its callers).
- `createLauncher` binds the four members to the shims and narrows the answers; the Launcher interface members are now async. gog, legendary, nile and `storeManagerCommon/games.ts` await every call, keeping the env merge order exactly as it was.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The shims answer `Promise<unknown>`, not `Promise<Record<string, string>>`**
- **Found during:** Task 1
- **Issue:** `checkShimShape` accepts only parentheses and `await` around the returned call, so a typed return needs a cast the gate refuses; `requestRustInvoke` itself answers `unknown`.
- **Fix:** shims return `Promise<unknown>`; `launchBuilderReply.ts` (outside `launchrust/`, so not a discovered survivor, the `knownFixLaunchReply.ts` precedent) narrows in `createLauncher`, and the Launcher members carry the typed signature.
- **Files modified:** src/backend/launchBuilderReply.ts, src/backend/launcher.ts, src/backend/launchrust/builders.ts
- **Commit:** 69847af6e, 33405c885

**2. [Rule 3 - Blocking] `storeManagerCommon/games.ts` also calls three of the members**

- **Issue:** the sideload native launch spreads `setupWrapperEnvVars`, `setupEnvVars` and `getKnownFixesEnvVariables` and joins `setupWrappers`; not in the plan's file list.
- **Fix:** awaited each call inside its already-async function.
- **Files modified:** src/backend/storeManagers/storeManagerCommon/games.ts
