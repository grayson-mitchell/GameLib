# Phase 88.1 Plan 08: The prefix check and the wine env on Rust shims Summary

**`verifyWinePrefix` runs through a new `launch_verify_wine_prefix` op over gamelib-wine and `setupWineEnvVars` through the wired wine-env channel, each a scheduled async shim, and the command runner's wine binding now awaits Rust's env builders in the same merge order.**

- **Tasks:** 2 (tracer, then the wine env shim and the runner binding)
- **Commits:** 2 (`42b890412`, `b16ad4385`), measured `rev-list ${plan_head_before}..HEAD` = 2
- **Completed:** 2026-11-25

## Accomplishments

- `gamelib-launch`: op `launch_verify_wine_prefix` (`[settings, host]`) calls `verify_wine_prefix` on `ctx.wine` and answers `{ res: <WineCommandResult json> }`; `Err` is the fixed `launch_verify_wine_prefix:failed`. The `launch_*` op table is now six, and the host argument decode is one shared `host_arg` for the env ops and this one.
- Shell: `launch_dispatch::rpc_launch_verify_wine_prefix` decodes `[gameSettings]` with the generated type, an object check and an arity check first, checks readiness second, and appends `wine_run_host()`; `rust_dispatch.rs` arm; regenerated `ipc_contract.rs`. Channel count 210 to 211.
- `RUST_LAUNCH_VERIFY_WINE_PREFIX` is in `UNBOUNDED_RUST_CHANNELS` with the eighteenth doc entry and in `dialogOptionForwarding.test.ts`'s expected set (T-88.1-16).
- `launchrust/builders.ts`: `setupWineEnvVars` and `verifyWinePrefix` shims, two schedule rows (`deletedBy` 92). `createLauncher` binds both Launcher members and narrows the answers (`settleEnvMap`, new `settleVerifyPrefixReply`). `save_sync.ts` awaits `setupWineEnvVars`; the `verifyWinePrefix` callers in save_sync, gog and nile setup already awaited.
- `commandRunner.ts`: the `wine` binding's `setupEnvVars` and `setupWineEnvVars` return `Promise<Record<string, string>>` and `runWineCommand` awaits both with the merge order unchanged (`process.env`, `options.env`, setupEnvVars, setupWineEnvVars, `PROTON_VERB`). `bootstrap.ts` binds the three members to the shims with the host read lazily and drops its `../launcher` import.
