### CR-01 (Critical): confirmed, reachable, a gap

I refuted nothing; I reproduced it.

- `GameSettingsView.wine_version` is `WineInstallation` with no default (`gamelib-wine/src/wine_cmd/env.rs:103-104`). `WineInstallation` requires `bin`, `name`, `type` and is `deny_unknown_fields` (`wine_cmd/mod.rs:37-38`).
- `launch_setup_env_vars` decodes the whole settings through `settings_arg` (`gamelib-launch/src/lib.rs:295-311`). The shell passes the settings object through untouched (`launch_dispatch.rs:167-183`; the zod schema is `knownFixGameSettings`, no wine injected).
- Ran `src-tauri/target/debug/gamelib-launch-cli` (built after the last commit touching `env.rs`; the source has not changed since):

| Args | Result |
|------|--------|
| `[{"nvidiaPrime":false,"winePrefix":""},null,null]` | `launch_setup_env_vars:bad-args`, exit 2 |
| `[{"wineVersion":{}},null,null]` | `launch_setup_env_vars:bad-args`, exit 2 |
| settings with `wineVersion:{"bin":"/x","name":"w","type":"wine"}` | `{"LD_PRELOAD":""}`, exit 0 |
| `wineVersion` with an extra key `legacy` | `launch_setup_env_vars:bad-args`, exit 2 (this is WR-01) |

- Reachability: `game_config.ts:238` sets `defaultSettings.wineVersion` only under `if (!isWindows)`; `config.ts:249` makes the Windows factory default `{}`. `legendary/games.ts:995-1006` and `storeManagerCommon/games.ts:150-157` call `setupEnvVars` with no Windows guard (GOG and Nile guard theirs with `isWindows`). Before the port, `setupEnvVars` (checked at `33405c885~1:src/backend/launcher.ts:1304`) read only `nvidiaPrime`, `showFps`, `enviromentOptions` and `installPath`, never the wine.
- Other builder ops are not affected: `launch_setup_wrappers` with `{}` settings answers `[]` (ran it), and `launch_prepare` reads `wineVersion` as raw JSON and decodes `GameSettingsView` only for a Mac CrossOver bottle.
- No golden covers it (see the gap's artifact entry), which is why the 113-case replay and the 1405-test proof are green.

Classification: BLOCKER. The builders "run from Rust" but break a supported platform, which fails SVC-03's "same command line and environment as before". The review disposition ledger still lists CR-01 as `open`.

A black-holed resolver can hold a launch for several seconds per GPU. WARNING; not a correctness gap. |

## Decisions Requested

That reasoning is principled but it is an assumption the goldens cannot test, and the roadmap wording is "across the pairwise matrix". Options: (a) accept it with an `overrides:` entry on truth 2, naming it and who accepted it; (b) require a cross-suite pair run for the two or three suspect pairs (tool axes against anti-cheat/Epic status in `prepare_launch`; fix against runtime in `prepare_wine`). I recommend (a) once CR-01 is fixed, because CR-01 shows the real escapes are missing platform axes, not cross-suite pairs. Not a blocker on its own.
