# Phase 88.1 Plan 04: check_wine goldens Summary

**`checkWineBeforeLaunch` and `downloadDefaultWine` are pinned by 49 TS-recorded cases in gamelib-launch before any Rust port exists, with every settings write recorded as data the Rust reply has to return and every dialog (including a dismissal) mapped by the real dialog layer.**

## Accomplishments

- Task 1 (tracer): one case (game wine invalid, default valid, answer Yes) ran end to end into `golden/check_wine` with its single `gameConfigs` write of `wineVersion`, its two-button dialog ("YES" and "NO" from the real en translation), its two `wine_valid` exchanges and its two backend log lines. The tracer's `<verify>` (jest in compare mode, the MANIFEST file, prettier) passed before expansion.
- Task 2: the slice grew to 49 cases (floor 49): 11 for the default-valid branch (Yes, No, dismissed, verbose and disableLogs both ways, three store runners and the Steam bottle's `__gamelib_steam_bottle__` appName), 6 for a valid discovered wine, 11 for the download path (success, error, no release, empty after install, discovery rejecting, the Steam bottle, mac both ways, Windows) and 16 direct `downloadDefaultWine` rows. Assertions beyond the golden compare pin: a valid game wine asks only `wine_valid`; a dismissal is `scriptedAnswer: null, response: 1` and is indistinguishable from No; a Yes mutates `wineVersionAfter` to equal the one game write; a successful download writes the global setting (store marker `kvs`) before the game write; the release is picked by type, not position.
- Two D-20 quirks kept as recorded and filed as todos (below).

## Deviations from Plan

### Auto-fixed / judgement calls

**1. [Rule 1 - Plan contradiction] the mac "not Sonoma" direction uses Darwin 13, not 22.6.0**
- **Found during:** Task 2
- **Issue:** the plan says mac picks `Wine-Crossover` with release `22.6.0`. `isMacSonomaOrHigher` tests the Darwin major against 14 (not 23), so `22.6.0` answers true and picks `Game-Porting-Toolkit`; only Darwin 13 or lower picks `Wine-Crossover`. The 88.1-01 builders golden already records the same threshold.
- **Fix:** the Wine-Crossover direction uses `13.6.0`; Darwin 23, 22 and 14 are recorded as toolkit picks, so the recorded behaviour is explicit. Filed as a todo rather than changed (D-20).
- **Files modified:** src/backend/__tests__/oracle/checkWine.oracle.test.ts
- **Commit:** 57c5cbca9

**2. [Rule 3 - Blocking] the golden folder has seven files, written by the oracle's own function**
- **Found during:** Task 1
- **Issue:** `writeOrCompareGolden` always writes `spawns.json` and `tree.json` (empty here) and has no `writes`, `dialogs` or `log` files; the plan's artifact list is `input, result, writes, dialogs, requests, log, events`.
- **Fix:** a 15-line write and compare function in the oracle test with the seven files only; compare mode checks the file set and the bytes.
- **Commit:** 560be808e

**3. [Rule 3 - Blocking] the dialog goes through the real `createDialogs`, and the `config` and `gameConfigs` deps are supplied as overrides**
- **Found during:** Task 1
- **Issue:** the plan wants a dismissal "mapped exactly as the TS `dialogs.showMessageBox` path maps it", which a fake that returns `{ response }` cannot show; `createFakeLauncherDeps` leaves `config` and `gameConfigs` unscripted by design.
- **Fix:** `createDialogs` over a scripted `dialog_message` reply, and recording `config` (its `getAlternativeWine` is the real one-call shim into `RUST_WINE_DISCOVER_ALTERNATIVES`) and `gameConfigs` fakes merged into the deps for the call. `fakeLauncherDeps.ts` is not edited, as 88.1-01 stated.
- **Commit:** 560be808e

**4. [Rule 3 - Blocking] real i18next, not the key-echoing mock**
- **Found during:** Task 1
- **Issue:** the backend jest project shadows i18next; the dialog title, message and buttons would be keys.
- **Fix:** `jest.unmock('i18next')` and the sidecar's init, as 88.1-03 does. The buttons record as "YES" and "NO" (the shipped en strings), not the "Yes" and "No" fallbacks.
- **Commit:** 560be808e

**Total deviations:** 4 (1 contradiction, 3 blocking). **Impact:** none on the goldens' purpose; deviation 1 corrects the plan's mac release to the threshold the TS really has.
