# Phase 22 — UI Design Contract

> Visual and interaction contract for "Steam Game Families" (multi-bottle macOS Steam). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** all 9 requirements in `22-SPEC.md` and all 12 HOW decisions in `22-CONTEXT.md` are LOCKED — this document does not reopen them. It specifies the visual/interaction contract on top of D-01..D-12, anchored to the exact existing components named in D-10/D-11 (`SteamInstallLocationPicker.tsx`, `SteamBottleSetup.tsx`, the Settings `components/` folder, `showDialogModal`).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is **intentionally not introduced**. GameLib is a Heroic fork that must stay upstream-mergeable (CLAUDE.md); it ships its own hand-rolled SCSS token system + MUI icon primitives, not a component-library preset. |
| Preset | not applicable |
| Component library | none (project convention: plain `.tsx` + co-located `.scss`, using `frontend/components/UI/*` primitives — `Dialog`, `TextInputField`, `SelectField`, `ToggleSwitch`, `SvgButton`, `InfoBox`/`InfoIcon`) |
| Icon library | `@fortawesome/react-fontawesome` (brand/solid glyphs) for content icons; `@mui/icons-material` (`Edit`, `AddBox`, `RemoveCircle`) for **row-action** icon-buttons — this is the established split (see `TwoColTableInput`, `WineVersionSelector`) |
| Font | `var(--primary-font-family)` = Rubik (headings/labels), `var(--secondary-font-family)` = Cabin (body) — both already global, do not override |

This phase adds **zero** new dependencies, new colors, or new spacing units. Every value below is a **reuse** of an existing token or component; new CSS classes must resolve to these same `var(--...)` custom properties (project is themeable — 8 themes in `themes.scss` — so literal hex must never be hard-coded, only var() references).

## Color

This app is multi-themed (`themes.scss`, 8 themes). Values below are **CSS custom-property names** (the only thing safe to hard-code in `.scss`); hex shown in parentheses is the default theme (`midnightMirage`) for reference only — never hard-code the hex.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--body-background)` (`#161c1e`) | Dialog page background, Settings screen background |
| Secondary (30%) | `var(--background-darker)` (`#070a0b`) | Family-picker/guided-setup dialog panel background (mirrors `.steamBottleSetupToast`'s `background: var(--background-darker, var(--body-background))`); each family row's container in the Settings list |
| Accent (10%) | `var(--accent)` (`#8bffff`) | **Reserved for exactly:** (1) the rename/edit icon-button per family row (mirrors `TwoColTableInput`'s `EditIcon style={{color:'var(--accent)'}}`), (2) the pre-selected family row's selection indicator in the install-time picker, (3) focus outline on the active `<select>`/radio in the picker. Primary action **buttons** use `.button.is-primary` (`var(--brand-primary)`, `#1de8f5`) per the existing button system — accent and brand-primary are visually adjacent but are two different tokens; do not conflate them. |
| Destructive | `var(--status-danger)` / `var(--danger)` (`#f97881` / `#a62b2b` themed) | **Reserved for exactly:** the per-row delete icon-button (mirrors `RemoveCircleIcon style={{color:'var(--danger)'}}`), the `.button.is-danger` confirm button inside the delete-confirmation dialog, and the "last remaining family" blocked-message text. |

Accent reserved for: rename icon-button, pre-selected/focused row indicator in the family picker. Never used for body text, never used for more than one element type per surface.

## Per-Surface Contract

Three new UI surfaces (all macOS-only, behind the existing `isMac` gate — see SPEC Boundaries). Each is a **clone/parameterization of an existing component**, not a new pattern.

### Surface 1 — Install-time family picker (Req 3, D-10)

**Baseline to clone exactly:** `src/frontend/screens/Game/GamePage/components/SteamInstallLocationPicker.tsx` + `src/frontend/state/SteamInstallLocation.ts`.

- **New files:** `SteamFamilyPicker.tsx` (component) + `frontend/state/SteamFamilyPicker.ts` (zustand store), same shape as the baseline: `{ isOpen, appName, gameInfo, families, open(), close() }`.
- **Container:** `Dialog` / `DialogHeader` / `DialogContent` / `DialogFooter` — identical import block to the baseline. `className="steamFamilyPickerDialog"`.
- **Header copy:** `t('install.steam-family.title', 'Choose a Steam family')`.
- **Body copy:** `t('install.steam-family.description', 'This game runs through a dedicated CrossOver bottle. Choose which family to install it into — Default works for most games.')`
- **List control:** a `<select>` (NOT a free-text field — matches the baseline's registered-libraries-only `<select>`, since a family must always be a known, provisioned-or-provisionable entity). One `<option>` per family (`displayName`), pre-selected per D-03's soft default (`lastUsedFamily ?? migratedFamily`) — computed by the backend and delivered in the `families` list already ordered/flagged, never re-derived in the component.
- **"New family…" row:** always the **last** `<option>`, value `"__new__"`, label `t('install.steam-family.new', 'New family…')`. Visually identical `<option>` styling — no special color, no icon (keeps the `<select>` a plain native control, matching the baseline).
  - Selecting it and confirming: creates the family inline (auto-`displayName` "Family N", D-02), **then immediately opens Surface 2** (guided setup) for that new family, **then** continues the install once setup completes — one continuous flow, no intermediate "family created" toast (mirrors D-10's "no context switch" requirement).
- **Primary button:** `t('button.install')` (verbatim reuse, see Copywriting Contract).
- **Secondary button:** `t('box.cancel', 'Cancel')`, `className="button is-secondary outline"`.
- **Gate:** component renders `null` unless `isOpen && appName && gameInfo` — identical guard to the baseline. Opened **exclusively** from the Steam install chokepoint in `handleInstall()` (`GamePage/index.tsx` ~672) and `InstallGameModal.ts`, replacing today's direct bypass — never opened speculatively.
- **Never shown for:** native-macOS Steam games, Linux/Windows Steam games (Req 3 acceptance) — the chokepoint must check `isBottleEligible` before opening this store, exactly as it already checks `runner === 'steam' && !is_installed`.

### Surface 2 — Family management ("Steam Families" Settings section) (Req 4/5, D-11)

**Location:** new file `src/frontend/screens/Settings/components/SteamFamilies.tsx`, registered in the same barrel (`Settings/components/index.ts`) and rendered from **`GeneralSettings/index.tsx`**, directly adjacent to `<DefaultSteamPath />` and `<EnableSteamNativeInstall />` (these three are the global, not per-game, Steam settings — `CrossoverBottle.tsx` itself lives in the per-game `GamesSettings` tab and is a different surface; D-11's "alongside" reference is to the **file location/pattern**, not literal adjacency in the same tab). Gated by `isMac` (component returns `<></>` on non-mac, matching `EnableDXVKFpsLimit`'s `isMac &&` pattern) — **not** by `isDefault`, since families are account-level, not per-game, but still global-settings-only.

- **Section heading:** `<h4 className="settingSubheader">` (matches the existing `.settingSubheader` convention used for `h3` general-section headers, sized one step down since this is a subsection) — `t('settings.steamFamilies.heading', 'Steam Families')`.
- **Intro copy (once, above the list):** `t('settings.steamFamilies.description', 'Each family is its own CrossOver bottle with its own Windows Steam login. Most users only need Default.')`
- **List container:** reuse the **table row pattern from `TwoColTableInput`** (`frontend/components/UI/TwoColTableInput/index.tsx`) as the structural precedent — NOT its exact component (that component is a generic 2-column key/value editor; this needs 3 semantic columns: name / Wine version / actions), but the **same interaction and icon conventions**:
  - Per-row layout: `TextInputField` for the editable `displayName` (inline rename, no separate "edit mode" toggle — matches the baseline table's inline-edit-on-blur/enter feel, but simpler: this is a single text field per row, not edit-then-commit via a pencil icon) — **actually use a pencil (`EditIcon`) to enter rename mode** to avoid accidental renames on every keystroke sync, mirroring `TwoColTableInput`'s `EditIcon` → populate-then-explicit-save flow. Rename commits on blur or Enter; Escape cancels.
  - Per-row Wine/CrossOver selector: reuse `WineVersionSelector`'s **rendering conventions** (icon-prefixed `MenuItem`s via `SelectField`), but the options list must be **filtered to CrossOver only** (SPEC constraint: "Non-CrossOver engines must not be offered or accepted for a family") — this filtering is a new prop/variant on the shared selector or a bespoke `<SelectField>` here; either way, GPTK/`toolkit`/plain Wine entries must never appear in this dropdown (mirrors `hideSharedPrefixToggle` precedent in `SteamBottleSetup.tsx` where an existing shared control gained a narrowing prop for the Steam-only path).
  - Per-row delete icon-button: `SvgButton` wrapping MUI `RemoveCircleIcon`, `style={{color: 'var(--danger)'}}`, `fontSize="large"` — **identical** to `TwoColTableInput`'s `removeRow` icon. Opens Surface 3 (delete confirmation) — never deletes immediately on click.
  - Row background: `var(--background-darker)`, `padding: var(--space-md)`, `gap: var(--space-md)` between rows.
- **"Create family" action:** a row below the list, `SvgButton` + MUI `AddBoxIcon` (`style={{color:'var(--success)'}}`) + label `t('settings.steamFamilies.create', 'Create family')` — clicking creates the family inline (auto-name "Family N") then opens Surface 2b (guided setup, parameterized by the new `bottleName`) exactly as the picker's "New family…" path does (D-11: "reuses the existing `SteamBottleSetup` guided flow, parameterized by `bottleName`").
- **Delete-disabled state (last remaining family):** when exactly one family exists, its delete icon-button renders **visually disabled** (reduced opacity, `cursor: not-allowed`, no hover color change) and clicking it shows the inline blocked-message copy (Copywriting Contract → "Destructive — blocked") directly under that row rather than opening a dialog — the user should never reach a confirm dialog only to be told no.
- **Provisioning status per row:** a small `--text-xs`/`--semibold` status label to the right of the name (not a separate badge component — reuse the plain-text convention already used for `status.settingUpBottle`), reading `t('settings.steamFamilies.notProvisioned', 'Not set up yet')` when `provisioned === false`, and nothing (no label) when provisioned — absence-of-label is the "normal/ready" state, matching the project's general convention of only surfacing exceptional states.

### Surface 3 — Destructive delete confirmation (Req 5, D-09)

**Pattern:** the existing frontend `showDialogModal` (`ContextProvider` / `GlobalState.tsx`) — **not** a bespoke modal component, and **not** the backend-only `showDialogBoxModalAuto` (that one is for main-process-triggered native/IPC dialogs with no rich content; this is a frontend-triggered confirm with a dynamic game list, so it must go through `showDialogModal` like every other in-app destructive confirm — see `helpers/library.ts`'s `handleStopInstallation` for the exact call shape to mirror).

- **Call shape** (mirror `handleStopInstallation`):
  ```
  showDialogModal({
    title: t('settings.steamFamilies.deleteTitle', 'Delete "{{name}}"?', { name: family.displayName }),
    message: <composed below>,
    buttons: [
      { text: t('box.cancel') },
      { text: t('settings.steamFamilies.deleteConfirm', 'Delete family'), onClick: () => deleteFamily(bottleName) }
    ]
  })
  ```
  The confirm button is the **second/right-most** button (matches existing convention where the non-destructive option comes first) and must render with danger styling (`.button.is-danger` equivalent inside the dialog's button renderer — check `DialogHandler`'s button-role mapping; if it does not already support a danger variant, that is an executor-level implementation note, not a new pattern to invent).
- **Message composition (Req 5 "naming the games/login that will be lost"):**
  - If the family has 0 installed games: `t('settings.steamFamilies.deleteEmptyBody', 'This will remove the "{{name}}" CrossOver bottle and its Steam login. No games are currently installed in it.', {name})`
  - If the family has 1–5 installed games: list them by title, one per line, under a lead sentence: `t('settings.steamFamilies.deleteBody', 'This will remove the "{{name}}" CrossOver bottle, its Steam login, and uninstall:', {name})` followed by a `<ul>` of game titles.
  - If the family has 6+ installed games: same lead sentence + first 5 titles + `t('settings.steamFamilies.deleteMore', 'and {{count}} more', {count: n-5})` — avoids an unbounded dialog height.
  - Always append: `t('settings.steamFamilies.deleteIrreversible', 'This cannot be undone.')` as the final line, styled with `var(--danger)` (matches the irreversibility-warning convention already used in `HumbleClaimWizard`'s reveal warning).
- **Blocked path (last remaining family):** never reaches this dialog — see Surface 2's Delete-disabled state. `showDialogModal` is not called at all in that case.

### Surface 4 — Not-ready / deleted-family routing (Req 7) — no new component

- **Unprovisioned family, Install/Play clicked:** reuse Surface 2b / the existing `SteamBottleSetup.tsx` guided-setup flow verbatim, parameterized by the resolved `bottleName` from `resolveFamilyForApp()` (D-05). The existing status copy `t('status.settingUpBottle', 'Setting up Steam…')` (`MainButton.tsx`/`GameStatus.tsx`) is already family-agnostic wording — **no new status string needed**, since it never names a bottle today either.
- **Deleted family, Install clicked:** per D-09, a deleted family's games become unassigned + uninstalled — clicking Install therefore **naturally re-opens Surface 1** (the standard install-time family picker), which is exactly the SPEC's "prompts the user to re-pick a family." No new UI, no new copy — this is a direct, deliberate consequence of the state model, not a separate surface to design.
