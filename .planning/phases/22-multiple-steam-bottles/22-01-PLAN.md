<objective>
Establish the multi-family data contract and bring the last single-bottle
`bottle.ts` primitives to the explicit-`bottleName` shape the rest of the phase
builds on. This is the interface-first foundation: reshape `SteamBottleConfig`
(D-04) into `families` + `assignments`, define `SteamFamily` (D-01/D-02), and
thread an explicit `bottleName` through `getSteamBottleSettings` and
`dispatchToBottledSteam`/`tellBottledSteamTo*` (D-05), while exporting the
private CrossOver helpers `families.ts` (Plan 02) needs.

Purpose: every later plan reads `families[bottleName]` and passes a resolved
bottle name — none of that is possible until the type and these primitives
change. Removing the flat keys deliberately turns every stale single-bottle
reader into a compile error (Pitfall 5), which later waves resolve.

Output: reshaped `common/types/steam.ts`, `bottle.ts` primitives + exports,
extended `bottle.test.ts`.
</objective>

Target shape — getSteamBottleSettings (was zero-arg, bottle.ts:266; MUST keep the
`?? globalSettings.wineVersion` fallback — Pitfall 2):

```typescript
export function getSteamBottleSettings(bottleName: string): GameSettings {
  const globalSettings = GlobalConfig.get().getSettings()
  const family = steamBottleConfigStore.get_nodefault('families')?.[bottleName]
  return {
    ...globalSettings,
    wineCrossoverBottle: bottleName, // D-01/D-02: bottleName IS the CrossOver id
    wineVersion: family?.wineVersion ?? globalSettings.wineVersion
  }
}
```
