# Phase 86 Plan 06: Keyless network slice goldens Summary

**GOG discounts, the CrossOver index and wiki game info with umu were each recorded once from their live services, and 72 committed goldens pin what the TS returned, the requests it sent and the cache bytes it left, all before any Rust for them exists.**

## Accomplishments

- **Discounts (tracer, Task 1).** `getGogDiscounts` runs over a stub of the credential cache (no gogdl). 13 cases: two live (US/en-US/USD, and PL/pl-PL/PLN) and eleven synthetic clones of the live first page (hideOwned / wishlistOnly with and without a token, both flags, a page-2 500 skipped, a page-1 500 and a transport failure rethrown, an empty PL locale retried as US, an empty US result with no retry, ids duplicated across pages deduped). The US catalog has 132 pages, so the live cases fetch the MAX_PAGES cap of 30 and keep every page. The golden requests list shows the Authorization header only where a token applied and the `hideOwned=true` / `wishlist=eq:true` parameters in order.
- **CrossOver index (Task 2).** 19 cases over the real fetcher, lookups and rating map: live fetch, a second load inside 24 h with no request, a fresh cache with no request, a stale cache refetched, a 500 with the 5 minute back-off (no request inside it, retried after 6 minutes), recovery after the back-off, bundled fallback used and written to the store, no bundled snapshot, an invalid bundled snapshot, and six rejections (version 2, rating 6, 999 entries, bad `generatedAt`, a 5 MiB + 1 body, non-gzip) each leaving the previous cache bytes identical (checked byte for byte against the state file), a non-https descriptor refused with no request, the rating map on mac with eight games and empty on linux and windows. The live gz is 33 KB, 2469 entries.
- **Wiki and umu (Task 3).** 40 cases across Steam, Epic, GOG, sideload, a dotted title and an unknown title on mac, linux and windows: the 30 day cache (fresh, expired at 45000 minutes, forceRefresh, a repeat call inside the lifespan with no request), each stale rule (staleAppleData, staleCrossoverData null and old shape, a cached CrossOver miss that the index now covers versus one it does not, pcgamingwiki `error`, howlongtobeat `skipped`, no `fetchStatus`), PCGamingWiki 403 as `error`, the CrossOver index unavailable, three HowLongToBeat paths (403 re-init once, ambiguous search refused, init 403), and eleven direct `getUmuId` cases (hit with the lower-cased codename, miss caches null, cached null refetched, fresh cache, expired truthy value kept, a runner with no catalog, a 500, a transport failure, a nile miss). GOG titles go through the real `GOGGame.getExtraInfo` and `GOGLibraryManager`, so the `af.gog.com` rewrite and the store page request are what TS computes.
- **D-23.** In every GOG case the `v2/games` and `products?...expand=changelog` requests are `tsOnly: true` and Rust's `api.gog.com/v2/games/<id>?locale=en-US` GET is stored as a `rustOnly: true` exchange (4 GOG cases hold both). GamesDB is the same URL on both sides and stays shared. The golden also records `gogApiInfoWrites` (the TS-only `gog_api_info` cache writes).

Sizes (working tree): recorded discounts 10.3 MB (two live cases of 30 pages, about 5 MB each), crossover 5.4 MB (mostly the one 5 MiB zero-fill body), wiki 2.8 MB; goldens 0.4, 3.1 and 3.1 MB; state 2.3 and 2.7 MB.

## Deviations from Plan

**1. [Rule 3 - Blocking] Recorder and harness extended (backward compatible)**
- Synthetic `bodyBase64` (a gzip payload does not survive a utf8 string); `maxContentLength` is now enforced on a served body, as the real http adapter does (without it the over-5-MiB case would have been served and accepted); `tsOnly` accepts a `METHOD url-prefix*` pattern; `rustOnly` request headers default to those of the TS request for the same URL; `normaliseDates` moved into the harness for reuse. Existing oracles (anticheat, recent, overrides) still pass.

**2. [Plan wording] hideOwned with no credentials is synthetic, not live**
- It issues the same requests as `live-us-default`, so a live recording would store the 30 page catalog a third time (5 MB). It is a one-page clone with the same request pins (no Authorization, no hideOwned).

**3. [Plan wording] Large live discount results are digests**
- Full results are about 5 MB of JSON each; the golden holds count, ids and a canonical-JSON sha256 (see key-decisions).

**4. [Rule 1 - finding, not fixed] PCGamingWiki's GOG-id lookup is broken in production**
- The live cargoquery answers `permissiondenied` with HTTP 200; the TS then throws and reports outcome `error` for every GOG title (so each visit refetches). The live GOG goldens pin that. Two synthetic GOG cases pin the paths that work when the API answers normally (id hit, empty result falling back to title search). Logged as `.planning/todos/pending/2026-11-22-pcgw-cargoquery-permissiondenied-gog-lookup.md`; out of scope here. The Rust port must reproduce the current behaviour until the TS is fixed and the goldens re-recorded.

**5. [Plan wording] D-23 rustOnly applied to every GOG case**
- TS does issue `v2/games/<id>?locale=en-US` exactly, but only through `getExtraInfo`, which Rust does not call, so those requests are tsOnly and Rust's own GET is stored separately as rustOnly.
