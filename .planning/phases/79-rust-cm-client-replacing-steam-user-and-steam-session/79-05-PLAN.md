<objective>
Build the Web API sign-in transport, the QR flow and the flow registry with its background poll loop. Plan 79-10 adds credentials + Steam Guard on top.

Purpose: D-05 keeps sign-in off the CM. Owning the poll loop in Rust means the TS side holds no timers (the sidecar exit contract) and only reads status.
Output: webauth/mod.rs and the test mock.

Op shapes this module serves (registered in plan 79-14; JSON camelCase):
- `steamcm_signin_qr_start {}` → `{ flowId, challengeUrl }`.
- `steamcm_signin_status { flowId }` → one of:
  - `{ status:'waiting', challengeUrl }`
  - `{ status:'guardRequired', guardType }`
  - `{ status:'done', refreshToken, accountName, steamId }` (once only)
  - `{ status:'error', reason:'timeout'|'eresult'|'cancelled'|'unknownFlow'|'network', eresult? }`
- `steamcm_signin_cancel { flowId }` → `{}`.
</objective>

    - qr_start posts BeginAuthSessionViaQR with platform_type SteamClient and device_details matching steam-session; it returns a flowId and challenge_url and spawns a poll task
    - with tokio::time paused: the poll task polls at the response interval (clamped to 1..=10 s); a poll answer with new_client_id + new_challenge_url swaps the client id used by the next poll, and status() then returns the new challengeUrl
    - a poll answer with refresh_token yields status done {refreshToken, accountName, steamId from the JWT sub or new_steamid}; a second status() for that flowId returns error unknownFlow
    - no answer within 120 s yields status error timeout; cancel() yields error cancelled and stops polling (no further requests to the mock)
    - a second qr_start cancels the first flow
    - a poll x-eresult other than 1 that is not a pending code ends the flow with error eresult n
  </behavior>
  <action>Implement the registry and the QR flow.
    - Registry: `pub struct Flows` with `Mutex<HashMap<String, FlowState>>`. flowId is 16 random hex characters from `std` time + counter hashing; no new crate. `FlowState` holds client_id, request_id bytes, the current challenge_url, kind (Qr | Credentials), the status enum, a JoinHandle and the deadline. A done status keeps the token only until the first status() read.
    - `pub async fn qr_start(&self) -> Result<QrStarted, WebAuthError>` cancels any live QR flow first (userSignIn.ts parity) and spawns the poll task on the current runtime.
    - The poll loop sleeps `interval`, calls PollAuthSessionStatus with the current client_id and request_id, applies `new_client_id` / `new_challenge_url`, and stops on refresh_token, error or deadline.
    - steamId is parsed from the refresh token's JWT `sub`, by a base64url decode of the middle segment only, never logged. `new_steamid` from the poll response is used if present.
    - `pub fn status(&self, flow_id) -> FlowStatus` and `pub fn cancel(&self, flow_id)`.
    - `pub fn cancel_all(&self)` aborts every task, for crate shutdown.
    - D-08: no guard data or machine token is read or written; doc comment states it.
    - Diagnostics through `crate::error::diag` carry the flow kind and status transitions only. Never log the challenge URL, client id, request id or tokens.</action>
