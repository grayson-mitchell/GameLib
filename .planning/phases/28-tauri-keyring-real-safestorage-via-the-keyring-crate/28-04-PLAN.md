<objective>
Give the sidecar build a real, Keychain-backed `TokenStore` and make the `safeStorage` stub honest.
`SidecarKeyringTokenStore` implements the plan-28-03 interface entirely over plan-28-01's
`requestRustInvoke` against plan-28-02's four Rust keyring channels, and `bootstrap.ts` installs it
via `setTokenStore()` at the same point it installs `bindTransport()`.

Purpose: REQ-28-01 (keyring-native storage), REQ-28-06 (honest-unavailable → clean signed-out,
never persist plaintext), and the by-construction half of REQ-28-02/D-04 — this module physically
cannot write `TOKEN_STORE_KEY`, because it never imports it.

Output: the sidecar token path, the honest stub, the bootstrap wiring, and Wave 0 classification
coverage against a faked Rust responder (no real Keychain in Jest).
</objective>

- `requestRustInvoke(channel: RustInvokeChannel, args: unknown[]): Promise<unknown>` — resolves with
  the Rust `result`, rejects with an `Error` carrying the Rust `error` string, rejects after 60s,
  rejects immediately for a non-allowlisted channel.
- `RUST_KEYRING_GET = 'keyring_get'`, `RUST_KEYRING_SET = 'keyring_set'`,
  `RUST_KEYRING_DELETE = 'keyring_delete'`, `RUST_KEYRING_AVAILABLE = 'keyring_available'`.

From plan 28-02 (`src-tauri/src/main.rs` `dispatch_rust_channel`) — the response contract:
- `keyring_get` → `Ok(string)` when a token exists; `Ok(null)` when the entry does not exist yet
  (backend healthy, nothing stored); `Err("keyring:unavailable:…")` on any real backend failure.
- `keyring_set` → `Ok(true)`; `Err("keyring:bad-args")` for a missing/non-string arg;
  `Err("keyring:unavailable:…")` on backend failure.
- `keyring_delete` → `Ok(true)` (including when the entry did not exist); `Err("keyring:unavailable:…")`.
- `keyring_available` → `Ok(true)` / `Ok(false)` — a `false` is a SUCCESSFUL report of
  unavailability, not an error.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sidecar token path → OS Keychain (via Rust) | Session-equivalent credential material leaves the Node process for native storage |
| sidecar → shared `configStore` file | The write-direction trap SEAM.md §2 documents; the sidecar shares this file with the real Electron app |
| unported Electron API surface (`safeStorage`) → sidecar callers | Any caller still reaching for the stub instead of the seam |
