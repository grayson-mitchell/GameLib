# Phase 88.3 Plan 13: The Wine window raiser in Rust Summary

**`raise_wine_window` runs the `osascript` raise loop as a Helper through the engine's spawn seam (12 attempts 1500 ms apart, one 2500 ms settle re-raise, constant AppleScript, pids and names only as argv), is replayed against all 25 recorded TS cases, and sits behind `launch_window_raise` and a `createRustWindowRaiser` glue that the boot's `windowRaiser` now is.**

## What was built

- **Crate** (`gamelib-launch/src/raise.rs`): `RAISE_SCRIPT` (byte for byte the TS text, checked against the golden's recorded script), `RaiseArgs` (camelCase, `deny_unknown_fields`), `windows_exe_name_from_command` (a Rust twin kept as recorded, ASCII case-insensitive `.exe` search), `clean_pids` (non-empty, ASCII digits only) and `raise_wine_window`. Off macOS and for empty input it returns at once. A run holds a `shutdown.register("window-raise")` Registrant only while in flight and passes the shutdown token as the spec's cancel; the wait between attempts is `tokio::select!` on the token against `tokio::time::sleep`. Log lines go through `ctx.log_sink.general(Prefix::Steam, ...)` with the TS text. Op `launch_window_raise` added to `OPS` (28, sorted) and routed in `route`.
- **Replay** (`tests/golden_window_raise.rs`): scripted spawn seam (`CaseRunner` wrapped to record each spawn's argv and virtual delay), a log sink that records level, prefix and text into the same ordered list, and tokio's paused clock advanced 1 ms at a time. Per case it compares the ordered spawn, log and settle events; `exe-names` compares every row against `windows_exe_name_from_command`. `WINDOW_RAISE_FLOOR` is 25 and the line `golden window_raise: compared 25 floor 25` is written straight to stdout, so it shows without `--nocapture`. Also: the tracer test, an empty-list floor failure, a script-equality test, a differing-replay-fails test and a deltas test.
- **Channel**: `RUST_LAUNCH_WINDOW_RAISE` (in `RUST_INVOKE_CHANNELS`, bounded), strict `[{ context, pids?, processNames? }]`, `pnpm gen:ipc-contract` (ipc_contract.rs +21 lines, nothing else), shell arm `rpc_launch_window_raise` / `window_raise_over` (generated decode and arity check first, fixed `bad-args`, `not-ready` before the install).
- **Sidecar**: `launchrust/raise.ts` as planned. The 'abort-registry' step builds `state.services.windowRaiser` with `createRustWindowRaiser({ transport: () => requireHost(state) })`; `services/types.ts` takes `WineWindowRaiser` from it. `createWineWindowRaiser` has no production caller left (only `testUtils/testAbortRegistry.ts`, a test helper); `utils/wineWindowRaise.ts` stays for 88.3-20, as do the other type imports of it (`bottledSteam.ts`, `bottleProcessMonitor.ts`).
- **Schedule**: rows `raiseWineWindow` (shim) and `createRustWindowRaiser` (twin), both `deletedBy: 96`, callers `services/types.ts` and `sidecar/bootstrap.ts`.
- **D-20 todos** (from 88.3-02's candidates 7 and 8): `2026-11-28-wine-window-raise-stop-never-settles` and `2026-11-28-windows-exe-name-from-command-splits-on-backslash-only`, each with severity, platform, ready in that order (`pnpm planning-gates` 12/12).

### Judgement calls

- **Tracer case.** The plan names "a hit on attempt 3"; no such case was recorded. The tracer replays `window_raise--a-hit-on-attempt-12-then-the-settle-re-raise` (eleven misses, a hit on the twelfth, the settle re-raise), which exercises every timing in the loop.
- **"A scripted clock" is tokio's paused clock.** The engine `Clock` trait has only `now_ms`; the loop waits on `tokio::time`. This needed `tokio` with `test-util` as a dev-dependency of `gamelib-launch` (a feature of a crate already in the lock; `Cargo.lock` is unchanged, no package added).
- **Three documented deltas** (`golden/window_raise/deltas.json`): `stop-is-the-shutdown-token` (the TS `stop()` never settled; Rust has no stop, so a replayed stop cancels the context's shutdown token, each pending raise settles at that instant, and a raise after it runs on a fresh context), `spawn-failure-text` (the TS logged the rejection text beside the fixed line; Rust logs the fixed line only), `construct-has-no-rust-object` (the construct case replays as "a cancelled token with nothing in flight spawns nothing"). This is what lets n == f == 25 hold with every case compared rather than excluded.
- **No `osascript` time limit.** I first added a 5 s per-attempt limit for bounded in-flight work, then removed it: a first run waits on the macOS Automation consent prompt, and killing it each attempt would re-raise the prompt. The TS had none; the shutdown token ends a run, and the invoke's 60 s bound only rejects the sidecar's call (which the glue swallows). The "about 21 s" bound holds unless a prompt is held.
- **The golden line is written with `io::stdout().write`**, not `println!`, so the plan's `grep` finds it without `--nocapture`.
- **Requirement SVC-03 not marked complete here.** It is phase-level; the verifier closes it after 88.3-22.
- **The plan's `cargo fmt --check` over the whole shell crate** reports only the generated `ipc_contract.rs` (known, must stay as generated); the other shell files and `gamelib-launch` are clean.
- **Flagged assumption (spec-less edge probe):** SVC-03's edge-coverage row is `unclassified` and unresolved; the D-14 matrix stands in for edge coverage and is not claimed as a verified edge.
