# Phase 88.3 Plan 01: Record golden/funnel from the TS funnel Summary

**The TS launch funnel's order for 59 scenarios (tracer, 24 pairwise rows, every `launcher.engineStep` title, 20 named incidents) is pinned as a golden recorded from the real `createLauncher(...).launchEventCallback`, before any Rust funnel exists.**

## What was built

- `funnelTrace.ts`: `recordFunnel(scenario)` builds deps with `createFakeLauncherDeps` and replaces every member the funnel reaches with a recorder that writes into one ordered `events` list: `gameStatusUpdate` frontend pushes, backend-bus emits, gamelib.log lines (`jest.spyOn` on `logInfo|Warning|Error|Debug`), per-game log frames (`jest.spyOn` on `enqueueLogEntry` and `logLine`, clock dropped), Rust requests with their replies or rejections, hook calls, `tsStore` and runs-for-me writes, `config` and `gameConfigs` reads and writes, `appState` calls, dialogs, script runs. The platform and `isCLINoGui` are injected, the clock is a Date-only fake pinned to 2026-01-01T00:00:00.000Z and moved by `sessionMs` inside the scripted `launch`, each case runs in `withEngineOracleProfile` and `withPinnedBaseEnv`, and paths are normalised to placeholders. Also exports `baseFunnelScenario`, `funnelScenario` (a one-level merge helper), `FunnelScenario`, `FunnelEvent`, `FunnelTranscript`, `Answer`, `RustAnswer`.
- `funnelTrace.test.ts`: 8 tests pin the recorder itself (unscripted channel rejects by name, the clock moves only by `sessionMs`, the writer's rotation state is recorded, platform injection, sequences, no stack in a scripted rejection, nothing faked outlives a run, placeholders).
- `funnel.oracle.test.ts`: compare by default. Cases come from builders (tracer, `allPairs` over 12 axes with a feasibility function, one case per `launcher.engineStep` title, named incidents), `cases.json` and `deltas.json` are checked against the builders, each case is compared to `expected/<case>/{result,events}.json`, plus the tracer-order test, the pairwise coverage test (`uncoveredPairs` empty, every axis value present), the census (`assertCasesCoverTitles`), the named-incident list, a D-20 pin test, the manifest guard (`FUNNEL_FLOOR = 59`) and `expectEmptyCasesToFail`.
- `golden/funnel/`: `MANIFEST.json` count 59, floor 59; `deltas.json` holds `events-bus-emit` (re-grep of `on('gameStatusUpdate'` at HEAD found one match, a test; the only non-test bus listeners are `releasesInfoReady`, `settingChanged` and the per-app `progressUpdate-<app>`).

Case count: 1 tracer + 24 pairwise + 14 engine-step titles + 20 incidents (12 named by the plan, 8 added).

## D-20 candidates

Recorded as the TS behaves; 88.3-05 files the todos (with `severity:`, `platform:`, `ready:` in that order) when it copies them.

1. **Config read three to five times per launch** (every case, e.g. `funnel--native-legendary-plain`): `config.getSettings()` is read for `minimizeOnLaunch`/`noTrayIcon`, again for `disableLogs`, again for `disablePlaytimeSync`, and a fourth time inside the Wine check; `gameConfigs.get(app).getSettings()` is read for `verboseLogs` separately from `game.getSettings()`, so one game's `verboseLogs` comes from two stores. Suggested severity: minor.
2. **`totalPlayed` counts from before the pre-launch work** (`funnel--native-legendary-plain`, `funnel--saves-download-rejects-logs-and-goes-on`): `startPlayingDate` is taken before the save download, the engine step and the before script, so the session includes them, and `Math.floor` truncates 90 s to 1 min; runs-for-me uses a second clock (`launchedAt`, taken right at launch). Suggested severity: minor.
3. **A rejected GOG playtime post rejects the whole launch** (`funnel--gog-playtime-post-rejects`): the rejection skips the recent-game write, the save upload and the final `done`, so the renderer never hears the launch ended. Suggested severity: medium.
4. **A rejected before-launch script strands the display blocker** (`funnel--before-script-rejects-releases-engine`): only the engine is released; the display-sleep blocker stays held, no `done` is sent, the per-game log is never closed. Suggested severity: medium.
5. **A rejected after-launch script skips the whole tail** (`funnel--after-script-rejects`): the log is not closed, presence is not cleared, the blocker stays held, no playtime is recorded and no `done` is sent; only the engine is released. Suggested severity: medium.
6. **`done` is sent mid-flow with cloud saves** (`funnel--saves-download-rejects-logs-and-goes-on`, the on-online pairwise rows): `done`, then `syncing-saves`, then `done` again. Suggested severity: minor.

Observation, not a defect: the engine overlay (`launchSettings`) REPLACES the game settings for everything after the engine step, so the before and after script paths come from the overlay; an overlay without them silently drops the scripts (found while building the script incidents).

### Judgement calls inside the plan's intent

- **Tracer log-entry order:** the acceptance lists the per-game log entries before `engine_launch_select`; in the plain tracer the TS writes none until the end-of-log marker (nothing warns with verbose logs on), which is the one `rotate: true` frame and comes after the `launch` hook. - **`launch` hook writer state:** recorded as `{ target, rotationClaimed }` from earlier frames; `LogWriter.handOff()` was not used because it claims the rotation and would have changed every later frame.

- **`RustAnswer` sequences and `playAgain`:** added to the recorder so the title cases that make two Plays (`after a refused launch the next launch starts a fresh blocker`, the offline-flag "second Play") are one case each.
