# Phase 88.3 Plan 05: Every branch of the funnel, the playtime step and the stub-game join Summary

**`run_launch` now does everything the TS `runLaunchEventCallback` does, in the same order, and replays all 59 `golden/funnel` cases, all 58 `golden/runs_for_me` vectors and all 24 `golden/single_flight` cases; two Plays of one game through the funnel spawn one real stub game.**

## What was built

- `hooks.rs`: six more `ManagerHooks` ops with `unavailable` defaults (D-26): `sync_saves(runner, app, SyncSavesArgs { direction, saves_path, gog_saves })`, `set_presence`, `clear_presence`, `persist_bottle_wine_version`, `update_gog_playtime(app, start_iso, end_iso)` and `wine_settings_write(app, WineSettingsWrite { global, game })` (only the two `wineVersion` values Rust's own check chose, T-88.3-10). `RecordingHooks` gained a `HookCall` variant and a tape event for each, scripted rejections that write the lines the TS handler writes around them, and `with_on_facts`.
- `steps.rs`: `select_engine` and `end_engine` may fail with a fixed word (a rejected channel in the TS). `RecordingSteps` now keeps each scripted channel as a sequence (nth call, last repeated) of the recorder's JSON and writes `rust` events (`engine_launch_select`, `engine_launch_end`, `launch_check_wine_before_launch`, `launch_ask_force_uninstall`, `info_recent_add`) and `script` events to the tape.
- `run.rs`: the folder-missing question and `abort`; saves down and up (`syncing-saves`, the `done`/`syncing-saves`/`done` run); every engine answer (refused, thrown, `use` with the overlay replacing the settings for everything after, release after the after-script, a failed release logged and never replacing the result); the Wine check with its two writes in the hook (global first) and the in-place `wineVersion` change, and `persist_bottle_wine_version` after a pass; the before and after scripts with their `Running script ...` lines; the launch and presence calls (`launch` first, `set_presence` second, joined); the `finally` order (after script, log close, engine release); the macOS runs-for-me record; `clear_presence`; the GOG playtime post or its skip warning; the recent-game write; the CLI no-GUI exit.
- `playtime.rs`: `PlayTimes::{open, first_played_if_new, record_session_end}`, `iso_string` (moved from run.rs), the runs-for-me state machine, `RunsForMeIo` (read, write, push, each failing with a fixed word) with the store-host implementation `CtxRunsForMe`, and `record_play_session[_with]`.
- `log.rs`: `stringify_log_value` (the TS writer's argument conversion), `LaunchLog::write_entry` for a prepare step's `{ level, parts }`, and the conversion of the hand-off to the runner's typed form.
- Tests: `tests/funnel.rs` replays 59 of 59 (`golden funnel: compared 59 floor 59`), asserts every applied delta is documented and every documented delta used; `tests/golden_runs_for_me.rs` (`golden runs_for_me: compared 58 floor 58`); `tests/single_flight.rs` floor 24 (`LAUNCHER_NOT_YET` deleted, `GateHooks` answers `sync_saves`); `tests/stub_game.rs`: `two_plays_through_the_funnel_spawn_one_game` and `a_play_after_the_first_settles_launches_again`, on every OS leg, polling to a deadline, every pid registered in `Strays`, the pids counted from the file the stub wrote.

## Deviations from Plan

### Judgement calls and auto-fixes

**1. [Judgement] Task 1 and the branches of Task 2 landed in one commit.** The cross-branch case needs the hooks, the steps and the log seams, and the replay of the remaining cases needed the same code, so splitting the commit would have meant a red intermediate. The tracer gate was still run (replay green, then two mutations red).

**2. [Judgement] `deltas.json` entries.** Added `rejection-text-is-a-fixed-word`, `recent-game-warning-text`, `warning-prefix-is-an-options-object`, `hook-error-lines-are-the-managers` and `release-warning-is-a-fixed-word` to the two 88.3-04 entries; the TS oracle's `DELTAS` table was edited to match (`funnel.oracle.test.ts`, 68 tests pass), a file not in `files_modified`. A `redundant-store-write` entry was tried and dropped: re-seeding the store between two Plays (muted from the tape) made it unnecessary.

**3. [Judgement] The runs-for-me warning difference lives in `golden_runs_for_me.rs`'s header** (`runs-for-me-warning-is-a-fixed-word`, with a test that at least one vector applies it), not in a `deltas.json`: `golden/runs_for_me` has no deltas file and its TS vectors test owns the folder.

**4. [Judgement] Plan signatures bent where the plan was loose.** `first_played_if_new` and `record_session_end` are methods of `PlayTimes` (the opened store), not free functions taking the runner; `record_play_session` takes the context's platform; `clear_presence` takes the runner only (the TS call has no app argument); `run_launch`'s `FunnelHost` is now used (the Wine host and the runner host).

**5. [Judgement] Presence failures.** The TS rejected the launch when `setPresence` threw, leaving the game running un-awaited. In Rust the launch and the presence call are joined, so a presence failure other than `unavailable` writes a fixed warning (`Setting presence failed (<word>)`) and the launch goes on. `clear_presence` failures escape as in the TS.

**6. [Judgement] Failure words.** A non-`failed` category from `sync_saves` writes `Saves sync did not run (<word>)` (no title, no error text, T-88.3-09); the TS handler writes the `failed` line itself.

**7. [Judgement] `settings_json` key order.** The scripts' `HEROIC_GAME_SETTINGS` is `serde_json`'s text of the settings (keys sorted unless the workspace enables `preserve_order`), where the TS passed `JSON.stringify` in insertion order. The same JSON, a different key order, in the script's environment (T-88.3-11, accepted: the script parses it).

**8. [Judgement] Test harness differences from the recorder, not from the funnel.** The TS recorder's stores answered constants on every Play; a replay's second Play re-seeds `totalPlayed` and forgets the runs-for-me record (both muted from the tape) so a real store starts from the same state. The platform scenario words are `mac`/`linux`, so the old `darwin`/`win32` mapping of the tracer replay was wrong for the 31 mac cases and was replaced.

### Auto-fixed Issues

**1. [Rule 1 - Bug] The tracer replay's platform mapping** read `darwin`, but `golden/funnel` writes `mac`. Fixed with the replay rewrite.

**2. [Rule 3 - Blocking] `two_keys_never_join` (88.3-04) expected the gog launch to end with `launch:unported:gog`.** With the branch ported it launches; `GateHooks` answers `update_gog_playtime` and the test now expects three launches in flight and three `done`.
