# Phase 88.3 Plan 08: The TS answers for the funnel's manager hooks Summary

**The sidecar's one `launchManagerCall` handler now answers all ten ops (88.2's two and the funnel's eight), and a `launch` op reaches a manager's `launch()` through a log facade whose rotation is exactly the one the Rust funnel still owed, so the per-game log rotates once between them.**

## What was built

- `sidecarInternal.ts`: `launchManagerCallUnion`, a union of strict per-op tuples (`game_title`, `force_uninstall` and the eight funnel ops, each with its own strict payload), `FunnelHookCall`, and `LAUNCH_MANAGER_OPS` listing all ten. The channel table only accepts a tuple, so `sidecarInternalInvokeArgs.launchManagerCall` is the pair `[op, unknown]` with a refine that delegates to the union: the same strictness at the boundary, and the handler parses the union again for the typed result.
- `targetWriter.ts`: `LogWriter(target, logsDisabled, { rotationOwed })` (default unchanged: owed for a non-general target) and a read-only `rotationClaimed` getter that is true once a rotation was claimed. `logger/index.ts`: `gameLogWriterFromHandOff(log)`.
- `funnelHooks.ts`: `answerFunnelHook(deps, call)`:
  - `launch_facts`: game info, `getSettings()`, `isNative()`, the per-game `verboseLogs` from `gameConfigs.get(appName).getSettings()` (read separately), the four global settings and `cliNoGui` (from `isCLINoGui`).
  - `launch`: builds the facade, awaits `game.launch(writer, launchArguments, args, skipVersionCheck)`; on a throw writes `An exception occurred when launching the game:` and the exception to the facade and `logError`s it, answers launched false; flushes the log forwarder; answers `{ launched, rotated: writer.rotationClaimed }`.
  - `sync_saves`: the manager call, `true`; on a throw writes the download or upload error line the TS wrote (chosen by direction) and answers `false`.
  - `set_presence`, `clear_presence`, `persist_bottle_wine_version`: the store hook's call and `true`, or `false` when the store defines none; the wine value is narrowed (`bin`, `name`, `type` strings) or the call is refused.
  - `update_gog_playtime`: `libraryManagers.gog.getGame(appName).updateGOGPlaytime(new Date(start), new Date(end))`; a rejection rejects the call.
  - `wine_settings_write`: both values narrowed first, then the global `wineVersion` through `config.setSetting` and the game's through `gameConfigs.get(appName).setSetting`, nothing else.
- `runner.ts`: `registerLaunchManagerHooks` keeps the 88.2 answers and hands every other op to `answerFunnelHook`; its deps are `FunnelHookDeps`. `handlers.ts` passes the widened deps (still one registration).

## Deviations from Plan

### Judgement calls and auto-fixes

**1. [Judgement] Task 2's ops and the handler wiring landed in Task 1's commit.** `registerLaunchManagerHooks`' deps widen to `FunnelHookDeps` in Task 1, so `handlers.ts` (a Task 2 file in the plan) had to change in the same commit for `pnpm codecheck` to pass, and `funnelHooks.ts` is one file. Task 2's commit holds the tests and the lint and gate fixes.

**2. [Judgement] The channel schema is a tuple `[op, unknown]` with a refine, not a bare union.** The plan says "a union of strict per-op tuples"; the channel table (`ArgsMap`) only accepts `ZodTuple`, so the union is exported as `launchManagerCallUnion` and the table entry delegates to it. The handler parses `launchManagerCallUnion` directly (a typed result per op).

**3. [Judgement] `hookRefusal` is exported from `funnelHooks.ts`** and `runner.ts`'s `managerCallRefusal` uses it for a known op, so there is one text.

**4. [Judgement] The `launch` payload is refused when its log target is another game or not a `launch` log** (a refine on the payload). The shell never sends that; it is the T-88.3-18 guard against a forged frame writing another game's log.

**5. [Judgement] The payloads of the wine ops are `z.unknown()` in the schema and narrowed in the handler**, because the plan says "narrowed to a wine installation or refused" and the shell sends the value opaque (`persist_bottle_wine_version.wine`, `wine_settings_write.global/game`). A `null` or any non-wine value for a present key is refused, not skipped.
