# Phase 88.3 Plan 15: Stale launcher stubs out of nine tests Summary

The nine Steam and GOG tests that stubbed `backend/launcher` no longer do, each proven not to load it, with the backend-di ceilings lowered by hand in the same commits.

## What was done

- **Task 1 (tracer), `6f3d27762`:** `gog/__tests__/setup.engine.test.ts` lost its `backend/launcher` stub and its relative `../../../launcher` twin (same module). `storeManagers.gog.json` 12 -> 10.
- **Task 2, `0443d1281`:** the eight Steam tests lost one `jest.mock('backend/launcher', ...)` each. The ceiling for each file went down by exactly one.

## Proof each stub was stale

Before removal, each stub's factory was swapped for `() => { throw new Error('LAUNCHER_LOADED') }` and all nine suites were run together: 9 of 9 passed (156 tests). Jest runs a factory only when the module is required, so a pass means nothing the test loads reaches the launcher (the GOG test's relative twin was probed the same way). After removal the nine suites pass again (146 + 10 tests), `pnpm backend-di-ceilings` passes (`jestMock=1572 (365 files)`), `git grep -l "jest.mock('backend/launcher'" -- src/backend/storeManagers` exits 1, and prettier is clean on every path written.

No stub turned out to be load-bearing, so nothing is left to retarget for 88.3-16 from these nine files.
