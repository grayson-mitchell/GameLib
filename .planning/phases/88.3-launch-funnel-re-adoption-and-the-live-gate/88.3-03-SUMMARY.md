# Phase 88.3 Plan 03: The adopted-game proof and its kill Summary

**`gamelib_proc::adopt::identify` proves a re-adopted game from its leader's stamp or, once the Wine loader has exited, from a recorded member's stamp and process group, and `kill_adopted_tree` ends that tree only after proving it again in the same call.**

## What was built

- `adopt.rs`: `Member { pid, stamp }`, `AdoptProof { leader_pid, leader_stamp, members }`, `Identity { Leader, Member(u32), Job, NotOurs, Gone }`.
  - `identify`: a live leader decides alone (recorded stamp is `Leader`, any other stamp is `NotOurs`, no member consulted). A gone leader on unix is matched through the first recorded member that is alive, has its recorded stamp, and is still in group `leader_pid` (`Member(pid)`); leader pids 0 and 1 and pids over `i32::MAX` are `Gone`. On Windows a gone leader is `Job` when the Game Job named for the leader's pid and stamp still holds a process. Otherwise `Gone`.
  - `snapshot_members(pgid, leader_pid)`: unix lists `probe::group_pids(pgid)` minus the leader with their stamps in pid order; Windows lists the Game Job's processes (opened with query rights), which needs the leader's own stamp and so answers empty once the leader is gone.
- `probe::group_pids` (Linux `/proc`, macOS `proc_listpids`, other unix empty, Windows empty) and `probe::pgid_of` (`getpgid`; `None` on Windows). Linux and macOS `group_alive` are now "`group_pids` is not empty".
- `kill_tree::kill_adopted_tree(&AdoptProof, grace) -> KillOutcome`: `identify` first; `Leader` goes to `kill_game_tree`; `Member(pid)` re-reads that member's liveness, stamp and `pgid_of` and only then ends group `leader_pid` through `terminate_known_group` (so `signal_group`'s pgid <= 1 refusal applies); `Job` reopens the Game Job, needs it to hold a process, terminates it through `GameJob::terminate` and waits for it to empty within `grace` capped at one second; `NotOurs` and `Gone` signal nothing. Exported from `lib.rs` with the `adopt` types.
- `GameJob::process_ids` (`JobObjectBasicProcessIdList`, one retry for `ERROR_MORE_DATA`).
- Stand-in: `game --leader-exit-ms <ms>` makes the game leader exit after it has recorded its child; `parent --game-leader-exit-ms <ms>` passes it on.
- Orphan arms (unix names; each has a Windows wrapper where the scenario exists there): `adopted_leader_matches_after_parent_sigkill`, `adopted_member_matches_after_the_leader_exits_and_the_parent_is_sigkilled`, `adopted_proof_with_a_wrong_stamp_is_not_ours`, `adopted_proof_with_an_older_stamp_is_not_ours`, `adopted_member_with_a_wrong_stamp_is_gone`, `kill_adopted_tree_on_an_empty_group_is_gone`, `adopted_member_outside_the_recorded_group_is_gone` (unix only). Windows: `windows_adopted_leader_matches_after_parent_terminate`, `windows_adopted_job_matches_after_the_leader_exits_while_the_parent_holds_it`, `windows_adopted_proof_with_a_wrong_stamp_is_not_ours`, `windows_adopted_job_with_a_wrong_stamp_is_gone`, `windows_kill_adopted_tree_on_an_empty_job_is_gone`. Unit tests in `adopt.rs` and `probe.rs` cover the order of `identify`, `snapshot_members` and the new probes.

**2. [Rule 3 - Blocking] `job.rs` modified.** The plan lists no `job.rs` change, but the Windows `snapshot_members` needs the Game Job's process list, and `GameJob` had only `active_processes`. Added `GameJob::process_ids`.

**3. [Judgement] Stand-in flag lives on `game`, not `game-tree`.** `parent` spawns the `game` mode through `spawn_game_tracked`; `game-tree` is only used by the own-handle test. The flag is `--leader-exit-ms` on `game`, plus `parent --game-leader-exit-ms`. The member's pid is already in the pids file the leader writes, so no extra record line was needed.

**4. [Judgement] One more arm than the plan listed.** `adopted_member_outside_the_recorded_group_is_gone` pins the pgid half of the member re-check (a live process with its recorded stamp that is not in group `leader_pid` proves nothing). The `adopted` filter runs 7 tests on macOS (plan floor 5).

**5. [Judgement] `member_holds` and the member arm are unix-only** (`#[cfg(unix)]`), and `kill_adopted_tree` answers `Gone` for a `Member` on Windows and for a `Job` elsewhere; neither identity is produced on the other family.

The Windows Job arm keeps the parent alive (the name opens only while a handle is held, 88.2-25).

**7. [Flagged assumption (spec-less edge probe)]** SVC-03's edge-coverage row is `unclassified` and unresolved; the orphan arms above stand in for edge coverage and are not claimed as a verified edge. `requirements:` SVC-03 was NOT marked complete: it is phase-level and this is plan 3 of 22.

## Known limits (for 88.3-07, 88.3-09, 88.3-21)

- **Windows after a GameLib crash.** The Game Job's name goes with its last handle (88.2-25), so after a crash the `Job` identity is unreachable; a live leader is still matched (`Leader`, which walks descendants) but a Wine launcher that has already exited leaves nothing to prove on Windows. The `Job` arm helps only while a process still holds the Job.
- **Windows `identify` order.** A recycled leader pid that is alive with another creation time is `NotOurs` before the Job is looked at (the plan's order); the Job name carries the stamp, so this is fail-closed.
- The Windows code was cross-clippy'd on `x86_64-pc-windows-gnu` (`--all-targets`) and has not run; its first run is windows-latest in 88.3-21.
- The unix member proof rests on the flagged assumption that a pid is not reissued while a process group with that id has a member. Measured only on macOS here; the Linux leg runs in CI.
