## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sidecar -> shell (`launch_run`) | a sidecar-originated request starts a launch |
| shell -> sidecar (`launchManagerCall`) | the shell asks the TS managers and decodes their replies |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-88.3-12 | Tampering | a malformed `launch_run` request | medium | mitigate | the generated args type and an arity check first, then the crate's strict `deny_unknown_fields` decode; a fixed `launch_run:bad-args` that never echoes input |
| T-88.3-13 | Spoofing | a forged or malformed hook reply steering the funnel | medium | mitigate | every reply is decoded strictly into its Rust type; anything else is `bad-reply`; the funnel treats a failed `launch_facts` as a launch error |
| T-88.3-14 | Denial of Service | a hook call that never returns holding a shared thread | low | mitigate | each call runs on its own named thread; sidecar EOF fails every pending invoke through `drain_pending_invokes`, which the hook maps to `sidecar` |
| T-88.3-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package is added |
</threat_model>
