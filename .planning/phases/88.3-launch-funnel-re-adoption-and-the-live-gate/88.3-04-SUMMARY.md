# Phase 88.3 Plan 04: The Rust launch funnel skeleton and its single-flight table Summary

**`run_launch` runs one Play through the Rust funnel in the TS order over `ManagerHooks`, `FunnelShell` and `FunnelSteps`, replayed against `golden/funnel` for the tracer, and `LaunchFlights` makes a second Play of the same game join the first, with no leader or joiner able to hang, replayed against 23 of the 24 `golden/single_flight` cases.**

## What was built

- `funnel/mod.rs`: `LaunchParams` (strict, camelCase, `args` and `skipVersionCheck` stay `Option` so an absent one is told from an empty one), `LaunchStatus` (`{ "status": ... }`), `FunnelHost { runner, wine }`, and the test tape type.
- `funnel/flights.rs`: `LaunchFlights::enter(runner, app) -> Enter::{Lead(FlightGuard), Join(FlightJoin)}`, decided under one `Mutex` with no await inside; the key is `<runner>:<appName>`. `FlightGuard::settle(Value)` releases the key (serial-checked) and then publishes on a `watch` channel; a guard dropped unsettled releases and publishes `abandoned`; `FlightJoin::wait(&shutdown)` answers the leader's value, `abandoned` or `shutdown`. `enter` is public and keyed by a plain string, so the Steam dispatch of 88.3-11 can lead `steam:<appId>`.
- `funnel/run.rs`: `run_launch` enters the flight first. A joiner writes `Launch of <app> (<runner>) already in progress; joining it (WR-03)` through the context's general log sink and returns the leader's result. The leader is its own tokio task holding a `Shutdown` registrant, raced against the shutdown token (`launch:shutdown`); the guard it owns is settled with the result and released by the unwind if the task panics (`launch:panic`). The tracer path, in the TS order: `launch_facts`, the `firstPlayed` write when the app is absent from `store/timestamp`, `Launching <title> (<app>)`, `launching`, hide window, display-sleep start (once per context), log open and the two forced warnings when `verboseLogs` is off, engine select (a skip), the second `launching`, the `launch` hook with the log hand-off, the end-of-log marker, the display-sleep stop, `lastPlayed` and `totalPlayed` (floor of whole minutes added to the stored total, from the start taken before the pre-launch work), `recent add`, `done`, and `exit_app` when launched without a window.
- `funnel/log.rs`: `LaunchLog` with the TS writer's semantics (disabled sends nothing unless forced, the first accepted entry claims the rotation, `close` writes the end-of-log marker, a refused target sends nothing). `hand_off()` carries the rotation still owed without claiming it; `take_back(rotated)` records the hook's answer.
- `funnel/steps.rs`, `funnel/shell.rs`: the two seams. `CtxFunnelSteps` calls `select_engine_for_launch` with `CtxStepDeps`, `end_engine_launch`, `check_wine_before_launch` over `CtxPrepareDeps`, `ask_force_uninstall`, `run_script_for_game` and `gamelib_info::recent::add` in process. `RecordingSteps` and `RecordingShell` record each call and write it, in the TS recorder's event shape, to a shared tape.
- `hooks.rs`: `launch_facts` and `launch` with `LaunchFacts`, `GlobalFacts`, `LaunchHookArgs`, `LaunchHookReply`; `RecordingHooks` gained scripted answers, a launch effect (the clock moves by `sessionMs`), a never-answering launch and the tape. `ctx.rs`: `flights`, `shell`, `steps` and `power`, with `with_shell` and `with_steps`.
- `tests/funnel.rs`: replays `funnel--native-legendary-plain` and prints `golden funnel: compared 1 floor 1`; `NOT_YET` lists the other 58 cases and a test pins it to existing cases, without the tracer, covering `cases.json` exactly with the MANIFEST count.
- `tests/single_flight.rs`: a step-list driver over `LaunchFlights` (flights cases) and over `run_launch` with recorders (launcher cases); prints `golden single_flight: compared 23 floor 23`. Rust tests: `a_leader_whose_launch_hook_never_answers_releases_on_shutdown`, `a_panicking_leader_releases_and_its_joiner_answers_abandoned`, `a_cancelled_joiner_leaves_the_leader_running`, `a_caller_that_drops_its_future_neither_stops_the_launch_nor_strands_a_joiner`, `two_keys_never_join`, and one proving the cloud-saves case ends with `launch:unported:cloud-saves` before it has written anything.

## Deviations from Plan

### Judgement calls and auto-fixes

**1. [Judgement] `run_launch` is the tracer path, with named fail-closed branches.** The plan says "write run_launch for the tracer's path", and 88.3-05 owns the branches. A funnel that silently skipped a folder check, cloud saves, scripts, the Wine check, a non-skip engine step, GOG playtime or the macOS runs-for-me record would be worse than one that refuses, so each ends the launch with a fixed `launch:unported:<branch>` before any side effect (`folder-missing`, `gog`, `wine-check`, `cloud-saves`, `launch-scripts`, `runs-for-me`; a non-skip engine answer releases the blocker, sends `done`, closes the log and answers `unported:engine-step`). Nothing calls `run_launch` until 88.3-06 adds the op. `launch_scripts` and the rest are therefore still to replay: 58 funnel cases in `NOT_YET`.

**2. [Rule 3 - Blocking] The new trait methods have default bodies.** The shell's `SidecarManagerHooks` (`src-tauri/src/launch_dispatch.rs`) implements `ManagerHooks`; two required methods would break its build. Both answer `HookError("unavailable")` by default, as a context with no hooks already does, until 88.3-06 implements them. That file is not touched.

**3. [Rule 3 - Blocking] `gamelib-store` became a regular dependency of `gamelib-launch`.** It was optional behind `harness`. The funnel opens `store/timestamp` through `ctx.engine.host` and needs `Store`, `Json` and `row_for_key`. A workspace crate already in the lockfile (gamelib-engine and gamelib-info depend on it); no new crate enters the tree. `harness` no longer lists `dep:gamelib-store`.

**4. [Judgement] A fourth context field, `power`.** The plan lists `flights`, `shell` and `steps`; the TS launcher's per-instance `PowerState` ("once per context") needs a home, and a `PowerState` on the context is the Rust twin.

**5. [Judgement] `LaunchHookArgs.args` and `.skip_version_check` are `Option`, not `Vec<String>` and `bool`.** The TS passed an absent argument as absent and the golden records `[null, null, null]`; an empty list or `false` would be told apart from absent only with an `Option`.

**6. [Judgement] A hook transport error on `launch` spends the rotation.** The other side may or may not have rotated the log; treating it as spent means a log is never rotated twice, at the cost of appending to the previous session's log in the rare case the hook never ran. It writes the fixed line `The launch hook failed (<word>)` and the launch answers `error`.

**7. [Judgement] An unopenable `store/timestamp` or a refused write is a fixed warning (`Recording play time failed`), not a failed launch.** The TS rejected the launch when `tsStore.set` threw. This is the only behavioural difference from the TS that is not in a golden.

**8. [Judgement] New documented deltas, kept honest in both places.** `deltas.json` gained `reads-folded-into-launch-facts` (the TS recorder's play marker and every `getSettings`, `config.getSettings` and `gameConfigs.get(app).getSettings` read are one `launch_facts` call in Rust), and the TS oracle's `DELTAS` table was edited to match so its `deltas.json is exactly the documented delta table` test stays green (68 tests pass). That TS file is not in the plan's `files_modified`. The slice-specific differences of the single-flight replay (`open-game-log`, `onjoin-notifier-is-the-callers`, `same-promise-identity`, `redundant-store-write`, `recent-game-warning-text`) are documented in the header of `tests/single_flight.rs`; `golden/single_flight/deltas.json` was left empty (88.3-02's file).

**9. [Judgement] The floor of the single-flight replay is 23, not the manifest's 24.** The CR-41 launcher case that runs with `autoSyncSaves` needs the cloud-saves branch; it is in `LAUNCHER_NOT_YET`, a test proves it ends with `launch:unported:cloud-saves` before writing anything, and compared plus not-yet must equal the manifest count. 88.3-05 removes the entry and raises the floor to 24. The plan's bar (`n >= f >= 14`) holds.

**10. [Judgement] `FunnelHost` is carried but unused.** `run_launch(ctx, params, host)` has the plan's signature; the host is read by the script and Wine-check branches that 88.3-05 ports.

**11. [Judgement] Shared test rig.** The replay recorders live in `tests/common/funnel_rig.rs` (added to `tests/common/mod.rs`), used by both new test files; the plan lists only the two test files.
