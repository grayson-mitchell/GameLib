<objective>
Close GAP-A from the live run (30084918812): both macOS legs failed with `failed to bundle
project: failed codesign application: failed to run command security import: failed to import
keychain certificate` even though NO Apple cert secret is enrolled — a direct violation of
D-04's locked invariant ("no cert secrets -> skip signing, warn, ship unsigned, job stays
green").

Root cause (already diagnosed from the live logs — do NOT re-investigate): the job-level `env:`
block unconditionally maps `APPLE_CERTIFICATE: ${{ secrets.APPLE_CERTIFICATE }}`. When the
secret is absent this resolves to the EMPTY STRING and the variable is still DEFINED in the
runner process environment. The Tauri bundler's macOS signing path tests for the variable's
*presence* (`var_os`), not its truthiness, so it enters the keychain-import branch and runs
`security import` on empty data. The existing `Warn if macOS signing will be skipped` step is
decorative — it prints a line and prevents nothing.

Purpose: make the Apple signing/notarization env vars genuinely UNSET when their secrets are
absent, restoring "unsigned, warned, job green" as the real default on macOS.
Output: a gated Apple-signing env step in release-tauri.yml whose executed shell body is proven
by tests to export nothing when the secrets are empty.
</objective>
