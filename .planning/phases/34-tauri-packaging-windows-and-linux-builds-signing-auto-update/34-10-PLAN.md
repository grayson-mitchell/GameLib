<objective>
Close **WR-01** and **WR-03**, both in `src-tauri/src/main.rs`.

**WR-01:** `use_dev_sidecar()` is `std::env::var("GAMELIB_SIDECAR_ENTRY").is_ok() || cfg!(debug_assertions)`
— the env-var check is unconditional, so a release build whose environment happens to carry that
variable takes `spawn_sidecar_dev()` and runs `Command::new("node").arg(&entry)` against an
attacker- or accident-supplied path, instead of the verified packaged `externalBin`. This directly
contradicts the function's own doc comment ("A release build always resolves the bundled sidecar via
`tauri-plugin-shell` — never a system `node` (D-06)"), and nothing tests it.

**WR-03:** the sidecar `Child` is held only as `_child` "so the child is not reaped". There is no
`RunEvent` handler, no `WindowEvent::CloseRequested` handler, and no `Drop` impl that kills it.
`app_exit`/`app_relaunch` are reached by only two in-app call sites; a normal window close
(red X / Cmd+Q / Alt+F4) does not route through them. Whether the OS reaps a piped-stdio child is
platform- and session-dependent, so the sidecar can survive as an orphan holding an authenticated
Steam session and open sockets after the user believes they quit.

Purpose: a shippable release build must not have an env-var escape hatch into arbitrary `node`
execution, and quitting the app must actually stop the backend.
Output: a hardened `use_dev_sidecar()`, an explicit exit-time sidecar shutdown, and a new
source-shape test suite extending this phase's Wave-0 convention to `main.rs`.
</objective>
