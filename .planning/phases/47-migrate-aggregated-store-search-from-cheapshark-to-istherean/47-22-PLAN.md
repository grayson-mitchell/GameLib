<objective>
Close two Deals filter layout gaps (both pre-existing since the upstream Deals page commit 927f1565c, not 47-18
regressions):

- G-47-14b (major): the Genres control crops and re-centres its chips when space runs out, and extra genres spill
  outside the box. Root cause (binding, `.planning/debug/deals-genres-control-crops.md`): the multi-value MUI
  Autocomplete root is forced into a fixed 40px height with overflow hidden and nowrap (DiscountFilters/index.css:269-275)
  while its content is unbounded (limitTags only applies when blurred, the custom renderTags emits every chip, MUI's own
  wrap ties on specificity). Focused or narrow, the chips overflow and the browser scrolls the clipped root to the caret,
  cropping chips and scrolling the notched outline away. With four or more genres, a hover bubble listing every chip pops
  out below the control as well.
- G-47-14c (cosmetic): 'Operating system' and 'Suitable for age' wrap onto two lines and push their controls down before
  the filters switch to two columns. Root cause (binding, `.planning/debug/deals-filters-reflow-breakpoint.md`): the
  6 -> 2 column reflow is a viewport media query at 1100px (DiscountFilters/index.css:217-231), but the grid is the
  viewport minus 322px (256px tier-2 panel plus screen and panel padding and border), so labels wrap from about vw 1455
  down to 1100, a band that contains the default 1280 window. Measured in the real WKWebView, where Cabin's synthetic bold
  makes the labels wider than in Chrome.

Choices recorded (Claude's discretion):
- Keep `limitTags={2}`: blurred, the control stays compact (two chips and +N, which the label's count pill backs up);
  focused, it now grows to show every chip inside its outline. The hover bubble is removed because the control can
  now hold its chips.
- Use the existing `main-content` container (App.css:61, already used by GamePage) with
  `@container main-content (max-width: 1239.98px)`, the debug session's WKWebView-validated threshold: worst case (PEGI
  value showing) the labels need a ~1130px grid, which is a ~1196-1200px content area, so 1240 leaves a 40px margin; no
  label wrapped at any width from 900 to 1561 with it. Inputs and sliders rows switch together, as they did before.
- Delete the 700px one-column rule rather than convert it: `tauri.conf.json` sets minWidth 900, so the viewport rule can
  never fire, and as a container rule it would fire at the minimum window, where two columns fit fine.
- Not taken (the debug session marked it optional): fixed label-row height or subgrid for long-locale labels. The
  threshold is tuned to English; a long translation (Russian 'Suitable for age' is 35 characters) can still wrap in the
  six-column layout just above 1240. Record it in the SUMMARY as a known limitation.
