<objective>
Close gap G-47-8 (minor), part 1 of 2: the Store Search price region can only be changed on the Deals screen.

Root cause (binding, from `.planning/debug/store-search-region-only-in-deals.md`): a deliberate Phase 47 scope cut
(47-RESEARCH D3, 47-UI-SPEC section 1). The region is one renderer-only localStorage value whose helpers live in
`Discounts/helpers.ts`; its only writer is the inline MUI Select in `Discounts/index.tsx` (569-627), coupled to
the Deals filter resets and styled under `.discountsScreen`; Store Search reads it once through a `useMemo` keyed
on `i18n.language` and has no write path.

This plan asks the operator to decide the country list (Task 1), hoists the region helpers into a neutral module,
extracts a shared `RegionPicker`, puts it on Store Search, and amends 47-UI-SPEC section 1. Plan 47-18 moves the
Deals screen onto the same component; it is split out only to keep every task at five files or fewer. The
Store Search truth closes here.

Choices recorded (Claude's discretion):
- No new strings: the picker reuses `discounts.region.label` ('Store region') and `discounts.region.auto`
  ('Auto ({{code}})'); country names come from `formatCountryName` (Intl.DisplayNames), matching the caption.
- No currency pill on Store Search: 47-ITAD-COVERAGE.json measured ITAD's currency per country, and it differs
  from REGION_OPTIONS' GOG currency for CZ, DK, HU, JP, NO, RO, KR, SE, CH, TW and TR; 47-UI-SPEC Currency
  Contract rule 7 already makes the ISO code on the price the truthful currency label.
- The key name stays as is (Phase 68 inventory: migration none), so existing choices survive.
- Backend unchanged: `country` is a per-call argument and the cache is keyed per country.

Purpose: the user picks the price region where the prices are.
Output: storeRegion.ts, RegionPicker (+css, test), Store Search wiring and tests, UI-SPEC amendment.
</objective>
