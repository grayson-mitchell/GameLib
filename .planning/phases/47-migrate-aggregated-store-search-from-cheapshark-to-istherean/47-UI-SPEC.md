## Currency Contract (amended) — supersedes 20-UI-SPEC lines 246-265

Correctness requirement, intent preserved: **the currency unit is impossible to miss and travels with the number.**

1. Every rendered price (collapsed cheapest + every breakdown sub-row) is produced by `formatPrice(amount, currencyCode, language)` and rendered as **one string in one text node** in one element.
2. `formatPrice` = `new Intl.NumberFormat(toI18nextCode(language), { style: 'currency', currency: currencyCode }).format(Number(amount))`, then append ` ${currencyCode}` **only if the formatted text does not already contain the ISO code**. Examples: en/USD -> `$14.99 USD`; de/EUR -> `14,99 € EUR` (the code is appended whenever the output lacks the literal ISO code; the redundancy is accepted because it is the only rule that keeps `$`/CAD/AUD unambiguous and keeps the checker rule mechanical); en/CAD -> `CA$14.99 CAD`; ja/JPY -> `¥1,480 JPY` (zero-decimal, no fabricated decimals); en-GB/GBP -> `£12.99 GBP`.
3. The old rule "never fabricate `.00`" is retired. `Intl` default fraction digits for the currency are correct because ITAD supplies exact amounts.
4. Fallback: on any `Intl` RangeError render `${amount} ${currencyCode}` (still one node, unit still visible).
5. `toI18nextCode(i18n.language)` is mandatory (shipped directory codes like `pt_BR` are not BCP-47), as in `Humble/Keys/syncAge.ts`.
6. Unchanged enforcement: the code is never a separate span, never smaller, never lower opacity, never hover-only, never a dismissible banner; number and code share size, weight and colour. A muted code is a checker FAIL.
7. Never claim "your currency" in copy. The truthful label is the ISO code on the price itself (RESEARCH Pitfall 5).
8. The timestamp (below) is a separate sibling element and is NEVER concatenated into the price node.

The `formatUsdPrice` tests are replaced with a `formatPrice` describe covering: USD/en, EUR/de, GBP/en-GB, CAD/en, JPY/ja, bad currency code fallback. `buildOwnedBadgeLabel` tests stay.

## Component Contract Changes

### 1. Region caption (new, no control)

- Position: directly under `SearchBar`, above the results/state area. Single line, `--text-sm`, `--text-secondary`.
- Copy: `t('storeSearch.region', 'Showing prices for {{country}}.', { country })`, `country` from `new Intl.DisplayNames([toI18nextCode(language)], { type: 'region' }).of(countryCode)` (fallback to the raw 2-letter code if DisplayNames throws).
- Always visible whenever the screen is mounted (including the initial prompt state) so the user knows which region drives prices before searching.
- No picker this phase (RESEARCH D3). The override still lives on the Deals screen; do not link to it and do not add helper copy about it. This is a recorded limitation: language-derived country is coarse (`en` -> US).

### 2. Cached-at line (rate-limited -> cached price) — PRICE-03

Trigger: result or deal carries `cachedAt` (epoch ms), meaning the price was served from cache because ITAD returned 429 or was unreachable.

- This is a SUCCESS state. Rows render normally. No error banner, no screen-level banner, no row dimming.
- Collapsed row: under the price (inside the right-aligned price column), one extra line: `faClockRotateLeft` icon (12px via `--text-sm` em sizing, `aria-hidden`) + text. Right-aligned with the price.
- Breakdown sub-row: same line under that sub-row's price, only when that deal has its own `cachedAt`.
- Timestamp format (absolute, not relative, because relative text goes stale without a re-render): `new Intl.DateTimeFormat(toI18nextCode(language), { dateStyle: 'medium', timeStyle: 'short' }).format(cachedAt)`; on RangeError fall back to `new Date(cachedAt).toLocaleString()`. Helper `formatCachedAt(cachedAt, language)` lives in `StoreSearch/helpers.ts` and is pure.
- Copy: `t('storeSearch.cached', 'Price from {{time}}', { time })` and the accessible/tooltip expansion `t('storeSearch.cachedTitle', 'Live prices are temporarily unavailable, so this is the last price we saved.')` as `title` and `aria-label` on the line (no hover-only reveal of the timestamp itself; the visible text stays).
- Do not put the word "error", "failed" or "rate limited" in the visible line. The user cares that the price is old, not why.
- If the row's own price was fresh but the breakdown is cached (or vice versa), each shows its own line independently.
- Interaction: unchanged. Row expand and sub-row click-through still work on cached data.

### 3. Rate-limited with NO cache available

Trigger: 429/outage and no cached entry exists (`handlers.ts` rethrow contract: the throw becomes the provider-failed state).

- Reuses the **provider-failed banner** exactly (Phase 20 three-state contract) with a distinct body so the user gets a useful next step. The container distinguishes it from the generic failure by an error code carried in the rethrown message/IPC error (`rateLimited`), falling back to the generic copy if the code is missing.
- Copy (rate limited): `t('storeSearch.error.rateLimited', 'Price lookups are busy right now. Try again in a minute.')` + the existing `t('storeSearch.error.retry', 'Retry search')`.
- Copy (provider not configured, e.g. embedded key missing in a dev build and no user key): `t('storeSearch.error.notConfigured', 'Price lookups aren\'t set up in this build. Add an IsThereAnyDeal API key in Settings > Advanced.')`. No retry link for this variant (retrying cannot help); search box stays enabled.
- Generic copy `storeSearch.error.provider` is unchanged.
- Retry while `blockedUntil` is in the future must not spam the provider: the backend serves the blocked response immediately, so the banner re-appears at once. This is accepted; no client-side countdown UI.
- The search input stays enabled and focusable in every variant (fail-soft, inherited).

### 4. Region-fallback / unsupported-country note (coverage UNKNOWN until Wave 0)

Coverage is pending the operator measurement sweep (RESEARCH Measurement Task). The contract is written so the UI is correct under every measurement outcome:

- The adapter returns, alongside results, `pricedCountry: string` = the country code ITAD actually priced (equal to the requested country normally; `US` when the adapter retried with `US` after a 4xx, or when the Wave 0 `ITAD_PRICED_COUNTRIES` constant says the requested country is silently served in USD).
- Show the note **only when `pricedCountry !== requestedCountry`**. When the sweep shows full coverage, the note never renders and costs nothing.
- Placement: between the region caption and the results list, one per results set (not per row). Info-note treatment from the Color table (info bar, `faCircleInfo`), `role="note"`. Not dismissible. Not a banner in the error sense: no Retry.
- Copy: `t('storeSearch.regionFallback', "Prices aren't available for {{country}} yet, so these are shown for {{pricedCountry}}.", { country, pricedCountry })`, both names via `Intl.DisplayNames`.
- The region caption in this state reads the requested country (it states the user's setting); the note explains the difference. Prices keep their real ISO currency code per the Currency Contract, so the numbers stay truthful even if the note were absent.
- Wave 0 decision hook for the planner: if the sweep shows ITAD returns USD silently for some countries, `ITAD_PRICED_COUNTRIES` is the single constant the note keys off; no other UI change is needed.
- Not shown: no-prices rows. A game with no deals in the priced country is dropped (RESEARCH D1), and if all rows are dropped the existing **No results** state applies unchanged.

### 5. Store labels and filters (34 ITAD shops, no Amazon)

- Store names in the breakdown now come from `deal.shop.name` supplied by ITAD, rendered as plain text, verbatim (no re-casing, no truncation beyond a single-line ellipsis).
- `<StoreLogos runner>` prefix rules (Phase 20) remain, now keyed through `ITAD_SHOP_TO_RUNNER`: Steam `'61'`, GOG `'35'`, Epic (id locked from the Wave 0 `/service/shops/v1` dump, do not guess). All other shops render text-only (no new logo assets).
- **Amazon gets no price sub-row** (ITAD does not track it). The "Owned on Amazon" ownership badge is unaffected: it is derived from GameLib's own Amazon library, not from ITAD.
- There is no store filter UI on this screen, so there are no filter effects. Do not add one.
- Breakdown sub-row order: ascending by price (unchanged intent); ties by store name ascending for determinism.
- Row count is capped by the backend (20-30, RESEARCH Q6); no pagination or "show more" control is added.

### 6. Deal links (no UI change)

- Sub-row click -> `window.api.openExternalUrl(deal.buyUrl)` exactly as today. `buyUrl` is ITAD's `deal.url` passed through **verbatim** (contractual, ITAD terms; never rewritten, re-encoded, or given extra params).
- The renderer must not wrap, shorten or display the URL. Accessible name stays `t('storeSearch.aria.viewDeal', 'View deal for {{title}} on {{store}}')`.
- A deal whose URL is not `https:` is dropped by the adapter, so the sub-row simply does not render. No placeholder row.
- Open item for the operator (not specified here): ITAD links may carry affiliate tags. Whether the screen needs an "affiliate links" disclosure is a legal/product call outside this contract; no copy is added.

### 7. Optional user-supplied ITAD API key (Settings)

- Location: **Settings > Advanced**, directly after the SteamGridDB API key block in `AdvancedSettings/index.tsx`, as a sibling `<div className="advancedSetting">` followed by `<hr />`. New component `Settings/components/ItadApiKey.tsx`, modelled on `SteamGridDbApiKey.tsx` (same `TextInputField type="password"`, `htmlId="itad-api-key"`, persist-on-change, `callOrDeclare` unavailable handling).
- Label (`label` prop): `t('settings.itad.apikey.title', 'IsThereAnyDeal API Key')`.
- Help: icon-only `(i)` via `labelHelp={<InfoBox text={t('settings.advanced.details', 'Details')} iconOnly>...}` on the label line. **No "Help" text link and no helper paragraph under the input** (project memory). Reuse the existing `settings.advanced.details` string for the icon's accessible text.
- Help body copy: `t('settings.itad.help.description', 'Optional. Store Search uses a built-in IsThereAnyDeal key. If you have your own key from isthereanydeal.com/apps/my, enter it here and it is used instead. The key is stored encrypted when your system supports it.')`. Do NOT say it gives "your own quota" or "avoids rate limits" (RESEARCH Open Q1, unconfirmed).
- Placeholder states (match SteamGridDB pattern):
  - Unset: `t('settings.itad.apikey.placeholder', 'Enter your IsThereAnyDeal API key (optional)')`
  - Saved: `t('settings.itad.apikey.placeholder_saved', 'Key saved — type to replace, clear to remove')`
  - Unavailable: reuse the existing `tGamelib('settings.steamgriddb.apikey.unavailable', 'Unavailable on this build')` pattern with a new `gamelib` key `settings.itad.apikey.unavailable` if the keyring arm is not wired on a platform. Field renders disabled.
- Rejected key (401/403 from ITAD): the backend falls back to the embedded key once and the field shows one inline status line below the input in `--status-danger`: `t('settings.itad.apikey.rejected', "ITAD rejected this key, so Store Search is using the built-in key.")`. The status clears when the key is changed or cleared. It is plain text, `role="status"`, not a dialog or toast.
- Clearing: emptying the field removes the key (no confirmation; reversible, falls back to embedded).
- Never display the saved key value back (the field stays empty with the "saved" placeholder), never log it.
- Plan note: this setting is last-wave and optional; PRICE-01..03 do not depend on it.

## Interaction summary

| Situation | What the user sees |
|---|---|
| Normal fresh search | Rows with localised prices, region caption, no extra lines |
| Search while ITAD is rate-limiting, cache exists | Rows render; each stale price has "Price from {{time}}"; no error |
| Search while rate-limited, no cache | Danger banner "Price lookups are busy right now. Try again in a minute." + Retry search |
| Country not priced by ITAD | Info note above results explaining which country was priced; prices keep real ISO code |
| Build has no embedded key and no user key | Danger banner (no Retry) pointing to Settings > Advanced |
| User key rejected | Inline status under the Settings field; search keeps working on the built-in key |
| Expand row, deals cached | Sub-row price + "Price from {{time}}" on that sub-row |
