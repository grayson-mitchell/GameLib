# Phase 34.10 Plan 03: Downloads ring — ambient queue indicator Summary

**`DownloadsRing`, the navbar's always-mounted ambient Downloads affordance: a conic-gradient progress ring filled from the head download's own percent, badged with the queue count, dimmed (never unmounted) when idle, and labelled for screen readers via the existing `download-manager.link` key.**

## Accomplishments

- `DownloadsRing/index.tsx` ports `CurrentDownload`'s data hookup (`hasProgress`) and `Sidebar/index.tsx`'s queue subscribe/unsubscribe shape, but **inverts the idle guard per D-07**: the component always returns a `<Link to="/download-manager">` — the `if (!libraryStatus.length) return null` early return from the retired analog is gone entirely (`grep -c "return null"` returns 0).
- The badge count and ring fill both come from pre-existing sources — `elements.length` from the already-fetched DM queue array, `hasProgress(appName, runner).percent` from the head element — with **no invented aggregate**, matching the plan's explicit constraint that no aggregate-progress source exists in the codebase.
- The remount key (`key={head.params.appName}` on the inner `RingProgress` component) is preserved exactly as `CurrentDownload`'s analog required, so `hasProgress`'s once-per-mount `useState` initialisers reset between downloads instead of carrying a blended percent forward.
- `aria-label={t('download-manager.link', 'Downloads')}` reuses the existing, already-"Downloads"-valued translation key — zero new i18n surface, satisfying the plan's requirement and the phase's i18n-gate-scope trap (no new hardcoded string to escape the gate).
- `aria-current="page"` fires only on `/download-manager` routes, since `resolveActiveTab` (a later plan's concern) deliberately lights no tier-1 tab there.
- `index.scss` implements the pure-CSS conic-gradient ring from the sketch reference exactly, with the `::after` inset filled by `var(--navbar-background)` (never a literal) so it survives `dracula`'s navbar/body inversion, and the idle state reduces opacity only — never `display: none` / `visibility: hidden` — so the navbar slot is always held.
- Zero regressions: `pnpm codecheck` clean, `pnpm test:ci` 208→209 suites / 4116→4124 tests (exactly the 1 new suite / 8 new tests this plan added).
