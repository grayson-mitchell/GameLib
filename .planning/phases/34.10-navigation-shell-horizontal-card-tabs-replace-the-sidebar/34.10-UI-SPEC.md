# Phase 34.10 — UI Design Contract

> Visual and interaction contract for the navigation shell rebuild. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker. Sketches `001`–`004` are the settled design input
> (`.planning/sketches/MANIFEST.md`, `Skill("sketch-findings-gamelib")`); this document translates
> those decisions into the project's **real** tokens and existing components — it does not
> re-litigate tab style, tier structure, the 78px inset, the Downloads-is-ambient rule, or
> theme-survival requirements. Those are locked in `.planning/ROADMAP.md` (Phase 34.10 section)
> and `.claude/skills/sketch-findings-gamelib/references/navigation-shell.md`.

has no 34.10 entries yet (phase dir was empty besides `.gitkeep`); requirements will be minted at

## Spacing Scale

This codebase's spacing tokens are **em-relative**, not raw px
(`src/frontend/styles/_spacing.scss:1-11`). Declared values below map the nearest real token to
its px-equivalent at the 16px root; do not invent new spacing tokens — reuse these.

| Token (existing) | px @ 16px root | Usage in this phase |
|---|---|---|
| `--space-3xs` | 4px | Icon–label gap inside tier-2 rows (matches existing `.Sidebar__item { gap: 10px }` is actually 10px flat — see Exceptions) |
| `--space-2xs` | 6px | Tab top-corner radius (see Typography/Shape below); tight vertical padding |
| `--space-xs` | 8px | Tier-1 tab horizontal micro-padding; tier-2 row vertical padding (matches current `.Sidebar__item` padding: `var(--space-xs) var(--sidebar-horizontal-padding)`, `SidebarItem/index.css:17`) |
| `--space-sm` | 12px | Tier-2 panel horizontal padding |
| `--space-md` | 16px | Tab horizontal padding, default gaps, tier-2 row horizontal padding (`--sidebar-horizontal-padding` is currently `var(--space-md)`, `Sidebar/index.scss:2`) |
| `--space-lg` | 24px | Tier-2 panel vertical (block) padding, content area padding |

Exceptions (project has no matching token — these are new fixed literals, not scale violations,
because they are dictated by the OS/sketch, not aesthetic choice):

- **78px** traffic-light inset — macOS platform constant.
- **204px** tier-2 width — locked sketch value.
- **56px** navbar height — new, see Layout & Grid.
- Existing `.Sidebar__item` uses `gap: 10px` flat (`SidebarItem/index.css:15`) rather than a spacing
  token — carry this forward as-is for tier-2 rows rather than "fixing" it to `--space-2xs` (6px)
  or `--space-xs` (8px); it is a pre-existing, working value outside this phase's scope to correct.

## Typography

| Role | Size | Weight | Line Height | Source |
|------|------|--------|-------------|--------|
| Tier-1 tab label (inactive) | 16px (`--text-md`) | 400 (`--regular`) | 1 (single-line button) | New — matches body-text size used everywhere else |
| Tier-1 tab label (active) | 16px (`--text-md`) | 600 (`--semibold`) | 1 | `references/navigation-shell.md` CSS pattern: `.tab.active { font-weight: var(--semibold) }` — real token, not invented |
| Tier-2 row label | 16px (`--text-md`) | 400 inactive / 700 (`--bold`) active | 1.25 | Matches existing `.Sidebar__item` (`SidebarItem/index.css:21`) and `.active.SidebarLinks__subItem { font-weight: var(--bold) }` (`SidebarItem/index.css:45-47`) — reuse verbatim, do not introduce a third weight |
| Downloads count badge | 13px (`--text-sm`) | 400 | 1 | Matches `CurrentDownload`'s existing `Typography variant="body2"` percent label (`CurrentDownload/index.tsx:78-81`) |

Only **2 weights** are introduced by this phase's new elements (regular 400 / semibold-or-bold for
active state) — consistent with the template's "declare exactly 2" guidance, even though the
project's global type system defines 5 weights (`_typography.scss:24-28`). This phase does not
touch body/heading typography elsewhere in the app.

**Shape:** tab top-corner radius = `var(--space-2xs)` (6px at 16px root) — this is the closest real
token to the sketch's invented `--radius-md: 6px`; there is no dedicated `--radius-*` scale in this
codebase (only `_buttons.scss:3` reuses a spacing token, `var(--space-3xs)`, as a button radius —
same pattern, different token). Tier-2 panel stays **unrounded** (0px), matching the current
`.Sidebar`'s flat rectangle (`Sidebar/index.scss` has no `border-radius` anywhere).

**Motion:** no global transition-duration token exists in this codebase (existing values are ad
hoc: `transition: color 250ms` at `SidebarItem/index.css:23`, `transition: 0.1s` on hover at line
72). Adopt the sketch's tested values as this phase's new standard since nothing conflicting is
established project-wide: `.12s–.22s ease` for tab/hover states, `cubic-bezier(.4,0,.2,1)` over
`.22s` specifically for the tier-2 width/collapse transition (`references/navigation-shell.md` CSS
pattern).

## Open Questions

Recorded per instruction — these are genuinely unresolved by the upstream artifacts (ROADMAP,
skill, sketches) and need a decision before or during planning. Each has a recommended default;
none of these are locked contract, do not treat the defaults as settled the way the "Locked Inputs"
table is.

1. **Is the macOS titleBarStyle-overlay actually configured yet?** `src-tauri/tauri.conf.json` has
   no `titleBarStyle`/overlay setting today, and `src-tauri/src/main.rs` has no matching Rust-side
   config. The 78px inset is a documented *constraint for when* the titlebar is transparent/overlaid
   — but nothing currently makes it so on this branch. **Recommended default:** this phase's plan
   must either (a) configure the transparent/overlay titlebar for macOS as part of shipping the new
   navbar, or (b) confirm Phase 34.1 already did this via the "frameless runtime" work
   (`34.1-03-PLAN.md`, `pre-paint setDecorations`) and just verify empirically on a macOS build
   before assuming the 78px reservation is even necessary yet. Do not ship the 78px `padding-left`
   defensively without confirming which titlebar mode is active — an un-overlaid native titlebar
   would make the reservation wrong, not just unnecessary.
2. **Where does "System Information" (`/settings/systeminfo`) go?** Present in code
   (`SidebarLinks/index.tsx:228-236`), absent from the ROADMAP's settled Settings tier-2 list.
   **Recommended default:** fold it into the Settings tier-2 list anyway (append after Logs) rather
   than silently dropping a working destination — the ROADMAP table is very likely an
   incomplete-but-not-deliberately-exclusionary summary, not a decision to cut this screen.
3. **Where do Quit and the app-version display go?** Neither has a placement in the new tree.
   **Recommended default:** Quit moves to a small overflow affordance near the Settings tier-2
   panel's bottom (it was already visually last in the old sidebar); version display is dropped
   from the nav shell entirely and left to the existing About window
   (`34.1-07-PLAN.md` already built `showAboutWindow` as a real `WebviewWindow`) — check whether the
   About window already surfaces version info before re-adding it elsewhere.
4. **Onboarding tour selector migration.** `SidebarTour.tsx` targets `data-tour="sidebar-*"`
   selectors by string. **Recommended default:** carry the same `data-tour` values onto their
   structurally-new equivalent elements (e.g. `sidebar-stores` moves from the old flat sidebar item
   onto the new tier-1 Stores tab) rather than renaming them, so `SidebarTour.tsx` needs zero edits;
   only relocate the attribute, don't rename it, unless a tour redesign is explicitly wanted later.
5. **Navbar wordmark: icon only, or icon + text?** The current `Sidebar` renders only the
   `GameLibIcon` PNG (`Sidebar/index.tsx:140`), no adjacent text logo. The sketches add a text
   wordmark ("Game**Lib**", reusing the existing `.Sidebar__brandLib` accent-color pattern from
   `SidebarItem/index.css:113-116`). **Recommended default:** icon only, at ~28–32px, matching
   current shipped behavior — do not invent a new brand-typography element inside a navigation-shell
   phase; if a text wordmark is wanted, it's a one-line addition reusing the existing
   `.Sidebar__brandLib` class, not a new design decision.
6. **Search icon and avatar affordances shown in the sketches' `nav-right`.** Sketch 003's markup
   includes an `⌕` search icon-button and, per the skill's synthesized HTML, an avatar circle —
   neither maps to a real GameLib feature today (no global cross-app search exists; GameLib has no
   single unified "logged in user" concept — Epic/GOG/Amazon/Steam/Humble are independently
   authenticated). **Recommended default:** omit both from this phase's `nav-right`; ship only the
   Downloads ring. If global search or a unified identity affordance is wanted, that's new product
   scope, not a navigation-shell relocation.
