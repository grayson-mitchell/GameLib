## Trust Boundaries

Consolidated from the 27 plan-level boundary tables.

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| renderer DOM event → native window operation | A mousedown in renderer content invokes `startDragging` / `toggleMaximize` through the preload seam | Pointer events; no user data. Privilege-bearing — a too-broad drag region is EoP |
| Library route subtree → app-shell DOM (React portal) | Filter UI owned by a route renders into a node owned by the persistent shell | React element tree; context parentage is the security-relevant property |
| sidecar/backend → renderer | `handleDMQueueInformation`, `progressUpdate`, `handleGoToScreen`, `getLatestReleases` push into always-mounted chrome | Queue elements, app names, percentages, route strings, release markdown |
| backend route push → client-side navigation | `handleGoToScreen` payload passed verbatim to `navigate()` | Hash-route string |
| sessionStorage `last-store` → route target | Renderer's own storage value interpolated into a client-side route path | Store identifier |
| renderer → external browser | `window.api.openKofiPage` opens a URL outside the app | Fixed destination; no renderer-assembled URL |
| renderer → app lifecycle | The Quit row terminates the application | Control action, no data |
| shared UI component → all call sites | `Dropdown` is shared; geometry/surface changes reach every consumer | N/A — blast-radius boundary |
| stylesheet source text → gate assertion | A comment containing a forbidden literal can vacuously satisfy or break a source gate | Source text |
| theme token → rendered foreground | A colour chosen against one theme can vanish in another (`dracula` inverts the navbar) | CSS custom properties |
| desktop-browser reasoning → WKWebView behaviour | Grid + percentage-height interactions have produced a garbage row on this project before | Layout geometry |
| build tooling → committed artifact | A locally-run generator writes the snapshot CI then trusts as the gate's entire scope | `i18nGateScope.json` |
| human operator observation → recorded verdict | An inferred or remembered verdict is indistinguishable in the file from a measured one | Gate verdicts |
| contract author → contract runner | An author who also runs can rationalise an unreachable item into a PASS (decision D-E) | Verdict slots |
| gate verdicts → REQUIREMENTS.md | A requirement ticked from a green suite outlives the run that should have contradicted it | Requirement status |
| concurrent session → this repository | Another agent editing files this run must not stage | Working tree |
| npm/pip/cargo install → dependency tree | Supply-chain surface. This phase asserts **zero** new dependencies | Package manifests |

## Audit Notes

**1. `Dropdown` consumer census — evidence corrected.** The auditor read the census at **HEAD** and
reported a single consumer (`NavShell/components/FilterFacetGroup/index.tsx`). That is a HEAD-time
reading, not a 34.10-time one. At this phase's close (`03df8f751`) there were exactly **two**
production consumers — `UI/CategoryFilter/index.tsx` and `UI/LibraryFilters/index.tsx` — matching
the plan-time census that T-34.10-32 and T-34.10-81 required. `FilterFacetGroup` arrived later in
`25c0ee70a` (Phase 34.11) and consolidated them. **No third consumer ever appeared**, so the control
held; only its evidence needed restating against the correct commit.

**2. `accept` dispositions were re-verified, not re-argued.** Each of the 11 non-supply-chain
accepts was checked for whether its factual premise still holds in current source — e.g. that
`resolveDefaultStore` still routes the stored value only into `store/:store`; that `navTabs.ts` is
still IPC-free; that `ChangelogModal` still uses `rehypeRaw` unchanged. All premises hold. The
dispositions themselves were not reopened.

**3. `## Threat Flags` heading coverage.** Only 2 of 27 SUMMARYs (34.10-16, 34.10-18) carry an
explicit `## Threat Flags` heading; both state "none beyond the plan's own threat model." The other
25 omit the heading. This is a documentation-completeness observation, **not** a security gap — no
new attack surface (new IPC channel, new external URL, new file-write path) was found anywhere in
the 67-file `files_modified` union lacking a corresponding register entry.

**4. What this audit cannot establish.** Every control here is verified against source text, test
assertions, and artifact structure. Rendered-pixel claims (ring visibility, per-theme contrast, tab
label clipping) are outside its reach by construction — the suite is `testEnvironment: 'node'` with
no jsdom and no CSS engine. Those route to run 4 of `34.10-LIVE-GATE.md`, which this audit confirms
completed with 41/41 slots resolved, but whose verdicts it did not re-derive.
