# Phase 34.10: Navigation shell — horizontal card tabs replace the sidebar Verification Report

**Phase Goal:** Replace the left sidebar with a two-tier navigation shell. Tier 1 is a horizontal
row of card/folder tabs — Manage Accounts, Games, Stores, Settings — where the active tab merges
into the content surface below it. Tier 2 is a vertical contextual panel scoped to the selected
tab. Sidebar and SidebarLinks are retired and their ~14 destinations redistributed. The Games panel
carries today's filter controls across unchanged (the filter redesign is Phase 34.11). Downloads
is not a tab — it is ambient state as a top-right progress ring with an active count.

**Verified:** 2026-08-09
**Status:** gaps_found
**Re-verification:** Yes — after gap closure. The previous VERIFICATION.md on disk was derived from
live gate run 2 and is stale; this report replaces it, derived from live gate run 3
(`34.10-LIVE-GATE.md` §9) plus the post-run-3 debug session (`.planning/debug/navbar-seam-and-logo-offset.md`).

## Goal Achievement

**Methodology note.** This phase is gated by a live, human-driven visual/behavioral test, not by
automated checks — the project's `Frontend` jest project has no jsdom, no CSS engine, and cannot see
a pixel. This has been demonstrated repeatedly within this exact phase: F-34.10-03/-04 each survived
TWO prior "fixed" declarations (34.10-18's seam border, 34.10-19's tab min-height) before a live
gate measurement contradicted the fix, and the jest suite was fully green through every one of those
failures. Per the project's own standing rule ("a live gate has beaten a green test suite three
times"), this verification does not accept "a fix shipped" (a diff exists, source reasoning is
sound, a debug session's single-theme pixel probe confirmed it) as equivalent to "a fix was measured
to work" against this phase's own gate contract (the full multi-theme sweep REQ-34.10-06 and the
gate itself require). That distinction is the entire basis for this report's `gaps_found` status.

### Gaps Summary

This phase's remaining gap is narrow but load-bearing: two findings (F-34.10-03 the seam,
F-34.10-04 the wordmark/ring offset) were root-caused and fixed correctly in a `/gsd-debug` session
after live gate run 3 — the diagnosis (an unscoped `.MuiTabs-root { padding-bottom: var(--space-xs) }`

this build) showing an exact 8px band. The fix itself (`padding-bottom: 0` nested under
`&.MuiTabs-root` in `NavTabs/index.scss`) is confirmed present in the working tree. But it was
pixel-verified and operator-confirmed in exactly one theme — the app's ambient teal scheme, not
`midnightMirage`, `gruvbox_dark`, or `dracula`, the three themes REQ-34.10-06 and the gate contract
actually score. This phase's own history is the reason this matters: F-34.10-03/-04 have now
survived TWO prior "fixed" declarations before a live measurement found each one still failing.
Declaring the phase closed on a third fix's single-theme, single-window-state confirmation — without
re-running the gate's own multi-theme contract — would repeat exactly the failure mode this phase's
own debug file and `live-gate-contract-authoring.md` warn against; the debug file's own Resolution
section says as much verbatim ("STILL OWED: the phase gate (34.10 item 1) must be re-run in full").
The gate's own no-partial-pass rule (`verdict: pass` requires `items_passed == 5`) has not been
re-evaluated since the fix landed, and REQ-34.10-06/REQ-34.10-16 correctly remain Pending. Two
secondary items are also open and independent of the fix itself: the gamepad focus-scroll regression
has never been measured in any run (no controller hardware ever available), and the operator's
mid-run election to switch from a card/folder tab to a pill tab is an unresolved open design decision
that a run-4 contract author needs answered before scoping the re-run.
