<objective>
Move the library filter controls into the Games tier-2 column **without moving them out of
`LibraryContext`** — by portalling `<Header />` from `Library` into the shell's registered target —
restack `Header` vertically, and delete the frameless padding hack that only existed because
`Header` used to sit beneath the window controls.

Purpose: this phase relocates navigation, it does not redesign filters. But a naive relocation here
is the single most dangerous change in the phase: `LibraryContext`'s `initialContext` is a complete
set of silent no-op setters, so a `<Header>` rendered outside `Library`'s provider would look
perfect and do nothing, with no error and no failing test.
Output: portalled filters, a vertical Header, a retired sticky-offset measurement, one source gate.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.10-13 | Tampering | portal target node | mitigate | The target is supplied by React as a callback ref from the shell's own `GamesPanel`, never located by `document.getElementById` or a selector query, so no unrelated DOM node can be substituted and no stale node survives a tab switch. |
| T-34.10-14 | Denial of service | portal render when target is null | mitigate | The render is guarded on a non-null target and returns null otherwise; `setFilled(false)` on unmount lets the shell collapse rather than show an empty fixed-width column. |

The portal keeps the React-tree parentage, and the source gate asserts `<Header />` appears only inside a `createPortal(` call. |
