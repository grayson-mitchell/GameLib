# Phase 34.10 Plan 14: Downloads ring mask + comment-immune source gate Summary

**Replaced the Downloads ring's opaque `::after` "guess" (`var(--navbar-background)`) with a real CSS-mask hole that cannot mismatch any backdrop, repainted the idle track in the count badge's proven-visible token chain, and pinned all of it behind a comment-immune source gate that explicitly disclaims proving visibility.**

- **Duration:** ~15 min (exact start not captured; task commits landed 2026-08-08T13:21:38+12:00 and 13:23:31+12:00)
- **Completed:** 2026-08-08
- **Tasks:** 2

## Accomplishments
- `.DownloadsRing__ring`'s centre is now cut with `-webkit-mask`/`mask: radial-gradient(farthest-side, ...)` instead of painted with a guessed backdrop colour -- the hole is genuinely transparent in every state and every theme
- `@supports not (mask: ...)` fallback restores the old `::after` technique for a webview without mask support, and additionally adds the `:hover` case the original fallback path never had
- Idle track colour changed from `var(--divider)` to `var(--navbar-inactive, var(--navbar-accent))`, the exact token chain `.DownloadsRing__count` already uses -- the one foreground in this component confirmed visible on real hardware
- `.DownloadsRing--idle` opacity raised `0.5` -> `0.65` (dimmed, not hidden, per D-07)
- Ring grown `15px` -> `16px` so the 3px band lands on whole device pixels at 1x/2x
- `downloadsRingStyles.test.ts` gates the mask declarations, the absence of `--divider`, the shared token chain (>=2 occurrences), the raised opacity, the grown size, and positionally confines every `::after` inside the `@supports not` block -- with a docstring stating plainly that visibility itself is unprovable here

## Decisions Made
- Kept the mask value's `radial-gradient(farthest-side, ...)` on a single line (rather than the plan's multi-line illustration) so the verify script's regex, which does not tolerate a newline between `radial-gradient(` and `farthest-side`, matches cleanly -- purely a formatting choice, no semantic change from the plan's specified declaration.
- Followed the plan's explicit instruction not to write `var(--divider)` or `background: var(--navbar-background)` in any trailing `//` comment; the docstring's mentions of both live inside the `/* ... */` block comment, which `stripSourceComments` strips entirely before any gate assertion runs.
