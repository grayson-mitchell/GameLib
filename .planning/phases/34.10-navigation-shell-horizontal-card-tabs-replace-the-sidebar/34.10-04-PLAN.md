    scoped under `.NavTabs`. The underline-plus-sliding-indicator style is the explicitly rejected
    alternative from sketch 001; leaving MUI's default visible would ship the rejected design on top
    of the chosen one.

    Inactive tab: `border: 1px solid transparent` with `border-bottom: none`, transparent
    background, `color: var(--navbar-inactive)`, `padding: var(--space-xs) var(--space-md)`,
    `border-radius: var(--space-2xs) var(--space-2xs) 0 0`, `position: relative; top: 1px`,
    `font-size: var(--text-md)`, `font-weight: var(--regular)`, `text-transform: none` (MUI
    uppercases labels by default and that would break the translated strings' casing).

    Active tab — this is the whole point of the plan, so express it **relationally** (**D-04**):
    `background: var(--body-background)` (the seam-erasing colour), `color: var(--navbar-active)`,
    `border-color: var(--divider)`, and `border-bottom: 1px solid var(--body-background)` so the
    seam against the content surface disappears, plus `font-weight: var(--bold)`. Use **exactly two
    weights across the whole nav system** — 400 inactive, 700 active — matching the tier-2 rows;
    do not introduce `--semibold`, which the sketch CSS uses but UI-SPEC deliberately rejected.
    Never key the active state off `var(--navbar-active-background)`: that token is the active
    tier-2 **row** background, and in some themes it coincides with `--body-background` today, which
    is exactly what would make the mistake invisible in `midnightMirage` and broken elsewhere.
    Never use a hex literal for any tab state.

    Hover: `color: var(--text-hover)` plus a subtle neutral tint — **not** the accent, which stays
    reserved for "this is where you are". Focus-visible reuses the nav-wide ring
