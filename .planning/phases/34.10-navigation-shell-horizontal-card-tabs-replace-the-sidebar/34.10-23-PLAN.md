<objective>
Rescope the unscoped `.MuiTabs-root` rule that caused F-34.10-03 / F-34.10-04, and add a
regression guard so the same leak class cannot recur.

The debug session (`.planning/debug/navbar-seam-and-logo-offset.md`, status `resolved`) found the
root cause at `src/frontend/screens/Settings/sections/GamesSettings/index.scss:40`: a top-level
`.MuiTabs-root { padding-bottom: var(--space-xs) }` (8px) with no scoping ancestor, applying to
EVERY `<Tabs>` in the app. It fixed the symptom in `NavTabs/index.scss` and filed the rescoping as
an unfixed follow-up with no guard test. That follow-up is this plan.

Purpose: the current state is a workaround, not a fix. The same 8px trap is still armed for every
future `<Tabs>` added anywhere in the app, and nothing detects it.
Output: a rescoped rule, a retained-and-documented NavShell override, and a `Frontend` jest guard
that flags any unscoped `MuiTab*`/`MuiTabs*` selector in a frontend stylesheet.

**This plan does NOT re-fix F-34.10-03 or F-34.10-04.** They are already fixed (commit `220211230`)
and live-confirmed (operator, 2026-08-09, commit `1c7a3359d`: "the download and wordmark read level
now"). Do not propose a sixth attempt at the seam. The debug file lists all five failed attempts
so none is retried — read it before touching either stylesheet.
</objective>
