## New finding — F-34.10-08 (process-not-product, open)

Preflight row P11's own command is defective two independent ways, both **proven empirically at run
time**, neither of which would have failed loudly:

1. **Anchor defect.** `grep -c '^\.MuiTabs-root{padding' build/assets/*.css` expects `0`. Vite
   minifies each stylesheet to one physical line, so a mid-line rule can never match a `^`-anchored
   pattern. Measured: the anchored form returned `0` for **every** file *including the one that does
   contain the rule*. It reports its pass value unconditionally and would have passed identically
   against a bundle carrying the live leak.
2. **Directory-wide glob defect.** It greps `build/assets/*.css`, but `build/` accumulates chunks
   across builds and is never cleaned. At preflight it held 14 `App-*.css` chunks spanning two days,
   several with abandoned debug instrumentation (`outline:2px solid #00ff00!important`).

Recorded, not fixed — decision D-E forbids the runner reshaping the contract it is scoring. Neither
altered a verdict; the intended assertion was carried out correctly by hand and recorded verbatim.

**Generalisable rule:** a grep-based assertion must be proven to FAIL against a known-bad input
before it is trusted to pass against a good one. Passing against a good input is not evidence — a
check that can never match passes vacuously. Note that 34.10-26 *did* exercise its verdict-slot
checker against a filled specimen and that checker is sound; P11, authored by a different plan, was
never exercised at all.
