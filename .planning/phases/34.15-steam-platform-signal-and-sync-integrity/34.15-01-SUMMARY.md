# Phase 34.15 Plan 01: Bulk Steam platform capture module Summary

**New `platformCapture.ts` backend module: oslist parser + read-modify-write merge + D-04-scoped, fail-soft bulk PICS `getProductInfo` capture, landed and unit-tested in isolation — not yet wired into `refresh()`**

## Performance

- **Duration:** ~15 min execution (three task commits between 15:03 and 15:09 local time)
- **Tasks:** 3 completed
- **Files modified:** 2 (both new)

## Accomplishments
- `parseOslistPlatforms` parses PICS `appinfo.common.oslist` (comma-separated `windows`/`macos`/`linux` tokens, `osx` accepted as a legacy synonym for `macos`) into a `CapturedPlatforms` triple, returning `null` (write nothing) for any non-string, empty, whitespace-only, or unrecognised-tokens-only input — D-02's "absent/empty writes nothing" rule, proven non-vacuous with a `treatsAbsentAsAvailable` saboteur test.
- `mergePlatformCapture` performs a read-modify-write against `steamMetadataStore`, spreading the existing entry forward before writing the three platform flags plus `platformsCaptured: true` — every other field (`art_cover`, `art_square`, `extra`, `is_delisted`, `mac_arch`, `mac_arch_verified`, `mac_arch_source`, `forcedWindowsViaBottle`) survives, proven field-by-field, with a `wholesaleSet` saboteur proving the carry-forward guarantee is non-vacuous.
- `captureOwnedAppPlatforms` scopes to apps where `depotSignalCaptured()` (imported verbatim from the pinned `metadataCapture.ts`, never re-derived) is `false`, issues exactly ONE `getProductInfo` call with zero chunking (mirroring `depot.ts`'s `fetchDlcInfos` precedent, bounded by the existing `STEAM_PICS_BULK_TIMEOUT_MS`), and never throws — a rejection or a timeout both resolve to `{ failed: true }` after logging, so a future `refresh()` caller (Plan 05) can await this without a try/catch of its own.
- 39 new unit tests across the three exports (24 originally written, redistributed across 3 task commits — see Task Commits below for the actual per-commit counts), all passing; the pinned `metadataCapture.test.ts` (24 tests) and the full `src/backend/storeManagers/steam` suite (30 suites / 1109 tests) also verified green with zero regressions.

## Decisions Made
- **Type-assertion escape hatch in `mergePlatformCapture`.** `SteamMetadataCacheEntry` types `art_cover`/`art_square`/`extra` as required strings because every existing writer (`games.ts`) only ever writes them alongside a freshly-fetched `appdetails` response. This bulk PICS writer has no art source and, by D-04's own design, exists specifically to reach apps no other writer has touched yet — so `existing` can legitimately be `undefined` here in a way it never is for the per-game writer. Rather than widening the shared interface (which would let every other writer silently omit required art fields too), the merged object is asserted to `SteamMetadataCacheEntry` locally, documented inline. The on-disk store is untyped JSON, so a partial entry is a legitimate runtime shape, not a corruption — verified by `npx tsc --noEmit` reporting zero errors.
- **`unknownApps` short-circuits the `apps` map lookup.** An id present in the bulk response's `unknownApps` array is treated as an absent entry unconditionally, rather than falling through to check `response.apps?.[id]` first — this is defensive against a PICS response that populates both arrays inconsistently for the same id.
- **Reconstructed task-scoped commits.** The full file was designed and verified as one coherent module (all cross-cutting concerns — the `SteamMetadataCacheEntry` type-assertion issue in particular — only surfaced once Task 3's code was in place and `tsc` ran against the whole file). To honor per-task atomic commits without re-verifying from a blank slate three times, each task's commit was built by staging the already-verified final content incrementally (Task 1's slice, then Task 2's addition, then Task 3's addition), re-running jest/tsc/eslint/the acceptance-criteria greps at each stage before committing. This is a process note, not a functional deviation — every commit's code is real, working, and independently verified.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `mergePlatformCapture`'s object literal failed `tsc --noEmit` when no existing cache entry exists**
- **Found during:** Task 2/3 verification (`npx tsc --noEmit -p tsconfig.json`, run as part of Task 3's acceptance criteria)
- **Issue:** `SteamMetadataCacheEntry.art_cover`/`art_square`/`extra` are required (non-optional) fields. When `steamMetadataStore.get(appId)` returns `undefined` (the D-04 "never captured, no prior writer ever ran" case this whole module targets), `{ ...existing, ...newFields }` produces an object whose `art_cover` is `string | undefined`, which `steamMetadataStore.set()`'s parameter type rejects. `npx tsc --noEmit` failed with `TS2345`.
- **Fix:** Cast the merged literal to `SteamMetadataCacheEntry` with an inline comment explaining why: the required-field contract reflects every OTHER writer's invariant (art always fetched together), which this bulk-PICS-only writer cannot uphold and was never designed to; the underlying store is untyped JSON so a partial entry is a legitimate, non-corrupting runtime shape.
- **Files modified:** `src/backend/storeManagers/steam/platformCapture.ts`
- **Verification:** `npx tsc --noEmit -p tsconfig.json` reports zero errors; the "with NO existing entry" jest test (Task 2's second `mergePlatformCapture` test) passes, confirming the runtime write still succeeds and does not invent `mac_arch`.
- **Committed in:** `e24cc285c` (Task 2 commit; the assertion was added before Task 2 was committed, so Task 2's committed code already includes the fix)
