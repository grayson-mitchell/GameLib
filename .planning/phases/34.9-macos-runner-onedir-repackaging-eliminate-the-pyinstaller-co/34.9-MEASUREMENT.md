## 1. Harness — verbatim text

Throwaway script, never committed to `meta/`, lives only at
`.build-tools/runners-onedir/measure.sh` for the duration of this plan. Reproduced here in full so
the run is reproducible without that file existing.

```bash
#!/bin/bash
# Phase 34.9 Plan 03 -- per-runner onedir-vs-onefile cold/warm measurement
# harness. THROWAWAY: lives only here, is never committed to meta/, and its
# verbatim text is embedded in 34.9-MEASUREMENT.md so the run is reproducible
# without this file existing.
#
# Methodology (reproduced from .planning/debug/nile-spawn-app-side-latency.md
# and its ADDENDUM measurement): a 400s idle before each cold sample is the
# empirically-chosen separation that reliably produces a cold amfid
# Gatekeeper assessment on this machine -- NOT a modelled decay constant (the
# decay curve is explicitly NOT a clean function of elapsed time). Six pairs
# are measured, ordered so the two builds of any one runner are never
# adjacent, to catch ordering artifacts the way the original session's
# reversed second round did.
set -euo pipefail

REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
EVIDENCE_FILE="$REPO_ROOT/.planning/phases/34.9-macos-runner-onedir-repackaging-eliminate-the-pyinstaller-co/evidence/onedir-per-runner-measurement.txt"
IDLE_SECONDS=400

# label:absolute-path pairs, in measurement order.
PAIRS=(
  "nile-onefile:$REPO_ROOT/public/bin/arm64/darwin/nile"
  "legendary-onedir:$REPO_ROOT/.build-tools/runners-onedir/extracted/legendary/legendary"
  "gogdl-onefile:$REPO_ROOT/public/bin/arm64/darwin/gogdl"
  "nile-onedir:$REPO_ROOT/.build-tools/runners-onedir/extracted/nile/nile"
  "legendary-onefile:$REPO_ROOT/public/bin/arm64/darwin/legendary"
  "gogdl-onedir:$REPO_ROOT/.build-tools/runners-onedir/extracted/gogdl/gogdl"
)

# Times one "$path --version" invocation with /usr/bin/time -p and returns
# just the "real" seconds figure (/usr/bin/time -p prints real/user/sys to
# its own stderr, one per line).
time_one() {
  local path="$1"
  local out
  out="$( { /usr/bin/time -p "$path" --version >/dev/null; } 2>&1 )"
  echo "$out" | awk '/^real/ {print $2}'
}

for pair in "${PAIRS[@]}"; do
  label="${pair%%:*}"
  path="${pair#*:}"

  echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) [$label] idling ${IDLE_SECONDS}s before cold sample ($path)" >&2
  sleep "$IDLE_SECONDS"

  cold="$(time_one "$path")"
  warm1="$(time_one "$path")"
  warm2="$(time_one "$path")"

  echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) $label cold=${cold}s warm1=${warm1}s warm2=${warm2}s path=$path" >> "$EVIDENCE_FILE"
  echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) [$label] recorded: cold=${cold}s warm1=${warm1}s warm2=${warm2}s" >&2
done

echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) Measurement complete: 6/6 pairs recorded." >&2
```

- Confirmed no `GameLib`/`gamelib-shell`/`tauri dev` process was running before or during the
  measurement (`pgrep -fl GameLib` showed only an unrelated `tail -f gamelib.log`, which never
  spawns a runner binary) — nothing else could spawn any of the six binaries under test during
  their idle windows.
- Each of the three onedir binaries was adhoc-signed before measurement, putting them on equal
  signing footing with the vendored onefile controls (which are already adhoc-signed):
  ```
  codesign -s - --force --deep .build-tools/runners-onedir/extracted/legendary/legendary
  codesign -s - --force --deep .build-tools/runners-onedir/extracted/gogdl/gogdl
  codesign -s - --force --deep .build-tools/runners-onedir/extracted/nile/nile
  ```
  All three re-signed successfully (`replacing existing signature` → `Signature=adhoc`).

**This run's `nile-onefile` cold reading: 7.91s.**

Per the binding rule: *"If `nile-onefile` cold is under 10s, the harness did not produce a cold
condition and EVERY number in the run is VOID."* **7.91s < 10s → the anchor FAILS.**

**This is not a one-off misread.** Before committing to the full six-pair run, three independent
400s-idle standalone diagnostic checks of the exact same `public/bin/arm64/darwin/nile` binary
were run (to avoid burning a full 40-minute run on a control that might not reproduce):

|---|---|---|
| diagnostic 1 | 400s | 8.13s |
| diagnostic 2 | 400s | 4.56s |
| diagnostic 3 (standalone, immediately before the official run) | 400s | 8.06s |
| **official run, line 1** | 400s | **7.91s** |

Four independent 400s-idle cold reads of the identical binary, all in the 4-8s band — none within
range of the ~20-21s this exact protocol produced in the referenced debug session. This is a
consistent, repeated condition on this machine at this time, not sampling noise around a
borderline value.

**Verdict: RUN INVALID.** Per the rule, no conclusion about legendary or gogdl may be drawn from
this run's ratios, and none is reported below as a PASS or FAIL. `Assumption A3` / `Open Question
3` remain OPEN, not discharged and not falsified, pending a rerun under conditions that reproduce
the cold baseline.

### Why the anchor likely failed (recorded, not fully explained — matching the debug session's own
"do not over-fit the decay curve" caveat)

- System state during this run: `top -l 1` showed load average 5.2-6.2 and ~70MB of free physical
  pages (`vm_stat`) throughout — the machine was busy and had committed most of its RAM, immediately
  after Task 1's real clone/venv/pip/pyinstaller work for all three runners. The debug session's own
  documented mechanism theory ("likelier eviction under memory pressure than a timer") does not
  cleanly predict which direction that should push a reading, and this run's evidence does not
  cleanly fit it either: `nile-onedir` (3.46s) and `gogdl-onedir` (3.52s) both read far above their
  ~0.2s reference despite onedir having no extraction-path randomization to defeat caching, while
  `legendary-onedir` (0.41s) read close to the reference. A build-activity-driven, broad, transient
  slowdown affecting many spawns similarly (not a clean onefile-only effect) fits this run's pattern
  at least as well as a Gatekeeper-cache-specific explanation, but this is not proven, only recorded
  as the honest leading candidate.
- Recommended for a future rerun: attempt again after a period with no other build/clone/pip
  activity on the machine, and confirm system load/free-memory readings alongside the anchor check
  itself, so a future void run can distinguish "this machine's Gatekeeper cache behavior differs
  from the reference session" from "recent heavy build activity was still settling."
