  function archSpecificBinary(binaryName: string) {
    if (process.platform === 'win32') binaryName += '.exe'
    const archSpecificPath = join(publicDir, 'bin', process.arch, process.platform, binaryName)
    if (existsSync(archSpecificPath)) return archSpecificPath
    const x64Path = join(publicDir, 'bin', 'x64', process.platform, binaryName)
    if (existsSync(x64Path)) return x64Path
    throw new Error(/* names both attempted paths + resolved publicDir */)
  }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk `public/bin` tree → backend process spawn | `archSpecificBinary` decides which file the app will execute as a runner |
| user settings (`alt*Bin`) → backend process spawn | a user-supplied absolute path is spawned verbatim, bypassing all resolution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.9-06 | Denial of Service (fail-safe) | `archSpecificBinary` after the layout change | mitigate | A checkout holding the old flat-file macOS runner would otherwise resolve nothing and surface as `spawn ./nile ENOENT` inside `callRunner` six layers away — the exact shape that cost Phase 34.5's live gate items 1/2/3. The stale-layout branch throws at the point of resolution, naming both paths and the fix command. Loud failure here is the SAFE outcome; no silent flat-file fallback is added. |
| T-34.9-12 | Tampering | `alt*Bin` user overrides | accept | The overrides spawn an arbitrary user-supplied absolute path with no existence or provenance check. This is UNCHANGED pre-existing behaviour (they already bypass `archSpecificBinary` entirely) and is a deliberate power-user escape hatch recorded as a hard constraint in 34.9-CONTEXT.md. This plan's only obligation is not to weaken it; Task 2 pins that with an `existsSync`-never-called assertion. |
| T-34.9-13 | Spoofing | nested darwin path construction | mitigate | The nested segment is `[binaryName, binaryName]` drawn from a closed `MACOS_ONEDIR_RUNNERS` literal, never from configuration, an env var or a filesystem listing — so no on-disk directory name can steer resolution into an unexpected tree. |
</threat_model>
