Build all three runners as onedir bundles on the arm64 dev machine with the committed script, then
MEASURE the cold and warm spawn cost of each against its own currently-vendored onefile binary.

The harness takes an ordered list of `label:path` pairs and, for each in turn: sleeps 400 seconds,
then times one `"$path" --version` invocation with `/usr/bin/time -p` (the COLD sample), then
immediately times two more back-to-back invocations (the WARM samples), appending one
`label cold=<s> warm1=<s> warm2=<s>` line per pair to
`.planning/phases/34.9-macos-runner-onedir-repackaging-eliminate-the-pyinstaller-co/evidence/onedir-per-runner-measurement.txt`
along with the timestamp and the resolved path.

Measure exactly six pairs, ordered so the two builds of a given runner are never adjacent (to catch
ordering artifacts the way the original session's reversed second round did):

  nile-onefile      public/bin/arm64/darwin/nile
  legendary-onedir  .build-tools/runners-onedir/extracted/legendary/legendary
  gogdl-onefile     public/bin/arm64/darwin/gogdl
  nile-onedir       .build-tools/runners-onedir/extracted/nile/nile
  legendary-onefile public/bin/arm64/darwin/legendary
  gogdl-onedir      .build-tools/runners-onedir/extracted/gogdl/gogdl

Run the harness in the BACKGROUND (total wall clock is roughly 40 minutes, almost all of it idle)
and poll the evidence file until six lines are present. Do not run it in the foreground and do not
shorten the 400s idle — the idle IS the cold condition.

Before running, adhoc-sign each extracted onedir runner with `codesign -s - --force --deep <path>`
so the onefile control and the onedir build are on equal signing footing, exactly as the original
debug session did. Record that this was done.

Then write `34.9-MEASUREMENT.md` containing: the verbatim harness text; the six raw lines; a
per-runner table of cold-onefile, cold-onedir, warm-onefile, warm-onedir and the cold ratio; and
the verdict, applying these rules in order:

1. **Harness validity anchor.** If `nile-onefile` cold is under 10s, the harness did not produce a
   cold condition and EVERY number in the run is VOID. Record the run as INVALID, state that no
   conclusion about legendary or gogdl may be drawn from it, and stop — do not report ratios from a
   void run.
2. Per runner, PASS when `cold_onefile / cold_onedir >= 10`. Record the actual ratio either way.
3. Any runner that does not PASS is recorded as a FINDING (mint `F-34.9-01`, `F-34.9-02`, … in
   order) stating the measured ratio, and the consequence spelled out plainly: the phase still
   ships onedir for that runner if the ratio is favourable but sub-10x, and the honest number
   replaces the ~95x claim in the ROADMAP for that runner. Do NOT quietly reuse nile's figure for a
   runner that did not reproduce it.

Also record the measured bundle growth per runner (`du -sh` of the extracted tree vs the vendored
onefile file size), so the 2.2x cost figure is per-runner rather than nile-only too.
  </action>
