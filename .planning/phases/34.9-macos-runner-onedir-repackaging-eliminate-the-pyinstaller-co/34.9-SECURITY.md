## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Third-party GitHub repos → GameLib CI/dev machine | `git clone` of `imLinguin/nile`, `Heroic-Games-Launcher/legendary`, `Heroic-Games-Launcher/heroic-gogdl` at a pinned tag, then executing that repo's own build tooling | Executable source and build scripts |
| PyPI → build venv | `pip install` of each repo's declared requirements plus PyInstaller into a throwaway venv | Executable Python packages |
| GitHub Actions runner → GameLib GitHub Releases | The onedir workflow gains write access to publish executable artifacts every install will trust | Signed release archives, `SHA256SUMS-{arch}` |
| GameLib GitHub Releases → developer/CI filesystem | Runner archives cross into `public/bin`, are bundled into the shipped app, and are later spawned | Executable binaries |
| Network bytes → `public/bin` | Downloaded archives land on disk and will be bundled and spawned | Executables, archive-chosen paths |
| Archive contents → filesystem layout | `tar` extraction writes paths chosen by the archive, not by GameLib code | Attacker-influenceable path names |
| Vendored `public/bin/**` runner trees → `build/bin` → signed `.app` → user machine | PyInstaller onedir trees are git-ignored, externally sourced, and are code-signed and notarized as-is | ~100 Mach-O files per runner per arch |
| Staged `build/` tree → electron-builder → `codesign`/notarization → `.dmg`/`.zip` | Structural defects surviving this boundary become attested | Application bundle structure |
| `dist/` directory contents → recursive delete | `cleanDistMac` is destructive by function; entries are selected by name | Filesystem entries |
| User settings (`alt*Bin`) → backend process spawn | A user-supplied absolute path is spawned verbatim, bypassing all resolution | Executable path |
| Developer/CI argv → `meta/runTs.cjs` → `os.tmpdir()` → spawned `node` | The wrapper writes executable code into a shared-tenancy directory and forwards argv to a child | Compiled bundles, argv |
| Gate artifacts → repository | Captured evidence can carry secrets — `gamelib.log` held plaintext PKCE material at `nile/user.ts` | OAuth/PKCE material, account identifiers |
| Evidence documents, ledgers and review markdown → phase closure | A verdict, a ticked requirement, or a swept finding is what a later phase builds on; a false PASS closes a phase on a broken build | Verdicts, requirement state, findings |
| GameLib repo → third-party public repositories | Patches and PR bodies authored here are published under the developer's GitHub identity | Source patches, identity |

## Escalations

**E-01 — T-34.9C3-16 (plan 34.9-25): the declared mitigation was under-scoped and a live defect shipped.**
The plan asserted protection because two *different* script names got distinct cache filenames. It did not
consider two *concurrent invocations of the same script*. `34.9-REVIEW-CYCLE3.md` finding C3-01 reproduced
this live at **60/60 trials, 100% cross-contamination, exit 0, zero diagnostics** — one process silently
executing another concurrent invocation's freshly compiled output. Plan 34.9-25's own threat model,
acceptance criteria and RED/GREEN proof all tested only sequential invocations and so could not catch it.
**Fixed** by plans 34.9-29/30 (private `mkdtempSync` dir per invocation), verified live in `meta/runTs.cjs`.
No action against current code. Recorded so the row's closure is read as *"closed by a successor control"*,
not as *"the plan-25 control was concurrency-safe"*.

**E-02 — T-34.9C3-19 (plan 34.9-25): doc-accuracy drift, third recurrence, and wider than first scoped.**
Plan 34.9-25 corrected every comment the pipe→`&&` conversion falsified and left the `IN-01/IN-02`
doc-comment pins green (still green today). Plan 34.9-29 then changed the execution mechanism again without
re-running that correction discipline. **12** files under `meta/` still document the retired
`node_modules/.cache/*.cjs` execution path:

`buildCrossoverIndex.ts`, `buildRunnersOnedir.ts`, `buildSidecarSea.ts`, `buildSteamBridgeShims.ts`,
`cleanDistMac.ts`, `downloadHelperBinaries.ts`, `genI18nGateScope.ts`, `gen_vtables.ts`,
`i18nCatalogChurnGuard.ts`, `machineFillGamelib.ts`, `trayIconVariants.ts`, `verifyRunnerBundle.ts`.

Two things keep this invisible: the `IN-01/IN-02` jest pins assert *prose about why `__dirname` is avoided*,
not the path literal, so they stay green while the comment is factually wrong; and stale `.cjs` files still
sit in `node_modules/.cache/` as residue from before plan 34.9-29, so a reader who checks whether the path
exists concludes the comment is accurate. Not a security control failure — recorded as a defect in the
evidence surface. Carried to `deferred-items.md`.

**Audit-method note.** The first pass over this finding sampled two files and reported two. A census over all
of `meta/*.ts` found twelve. The defect's unit is the file; an audit whose unit was coarser could not find it.
