# Phase 34.9 Plan 02: macOS Onedir Path Resolution Summary

**`archSpecificBinary()` now resolves the nested `.../{runner}/{runner}` onedir path on darwin for exactly legendary/gogdl/nile, leaves comet/win32/linux provably unchanged, and fails loudly (naming the fix) on a stale pre-34.9 flat binary -- with zero edits to any consumer.**

## Accomplishments
- `MACOS_ONEDIR_RUNNERS = ['legendary', 'gogdl', 'nile'] as const` is the single closed literal deciding which runner names get onedir nesting on darwin; `comet` and Windows/Linux are structurally excluded (the check requires both `process.platform === 'darwin'` AND membership in this array).
- `archSpecificBinary()` computes the nesting decision from the pre-suffix runner name, keeping the existing win32 `.exe`-suffix behaviour byte-identical while making the darwin/non-darwin split textually obvious at the top of the function.
- The 34.5 G-1 x64-fallback existence-check block is untouched verbatim (including its comment citing `34.5-APP-ROOT-SWEEP.md`) and now also covers the nested case: the x64 fallback preserves its NESTED shape rather than degrading to flat.
- A new stale-layout throw fires when a pre-Phase-34.9 flat onefile binary is found on disk where an onedir tree is now expected -- naming both the stale flat path and the expected nested path, and instructing `pnpm download-helper-binaries`. This is strictly additive: it only intercepts the darwin-onedir-runner case when neither nested candidate exists, never touching the generic not-found throw for any other runner/platform.
- `archSpecificBinary` and `MACOS_ONEDIR_RUNNERS` are now exported (previously module-private), letting the new test suite exercise all seven resolution shapes directly with no memoisation to fight.
- 12 new tests (22 total, up from 10) cover: darwin-nested legendary/gogdl/nile, comet-stays-flat, linux-stays-flat, win32-stays-flat-with-.exe, x64-nested-fallback-shape-preserved, stale-flat-layout-throws, generic-not-found-throws, and all three `alt*Bin` overrides proven to never call `existsSync`.
- `git diff src/backend/launcher.ts src/backend/storeManagers/` is empty -- the containment claim (this is the one chokepoint, zero consumer edits) is proven by absence of a diff, not asserted.

## Decisions Made
- **Nesting decision computed from the pre-suffix name, segments built after.** `isMacOnedirRunner` is evaluated using the clean runner name (e.g. `'nile'`) before the `if (process.platform === 'win32') binaryName += '.exe'` line runs; the `segments` array used for path-joining is then built from whatever `binaryName` holds at that point (suffixed on win32, clean on darwin/linux). This satisfies both requirements simultaneously: the darwin/non-darwin split is decided before any suffix mutation could theoretically interfere, and the win32 `.exe` extension still appears correctly in the final path. Verified live by mutation test (c) below.
- **Stale-layout throw is additive only.** It's gated behind `isMacOnedirRunner` and only checked after BOTH existing candidates (arch-native nested, x64 nested) have failed `existsSync` -- it can never fire for comet, win32, linux, or a genuinely-missing onedir runner (that case still falls through to the original generic throw, confirmed by the "nothing exists" test case).
- **No code changes needed for alt*Bin.** Re-reading `getLegendaryBin`/`getGOGdlBin`/`getNileBin` confirmed the `altXBin` check runs and returns BEFORE `archSpecificBinary` or the memoised `defaultXPath` variable is ever touched -- Task 2's job was only to add regression coverage proving this invariant, not to change any code.
