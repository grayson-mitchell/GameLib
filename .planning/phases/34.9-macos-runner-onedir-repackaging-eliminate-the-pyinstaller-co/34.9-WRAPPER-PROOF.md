## 1. What this proves and why it exists

**The claim under test, in one sentence:** after plan 34.9-29's wrapper conversion, no two
concurrent invocations of the same script can execute each other's compiled output (C3-01, closed),
AND a script whose entry file fails to compile still exits non-zero while executing nothing (the
exit-code short-circuit property `34.9-PIPE-PROOF.md` already proved for the retired `&&` idiom must
not have regressed under the new wrapper).

`34.9-REVIEW-CYCLE3.md`'s C3-01 finding, reproduced independently twice already (reviewer 60/60,
`34.9-VERIFICATION.md`'s own re-verification 20/20, both 100%): every pre-conversion script wrote its
compiled output to ONE shared, script-name-keyed path
(`node_modules/.cache/<name>.cjs`) -- two concurrent invocations of the same script raced on that
file, one process's `node` silently executing the OTHER's freshly-compiled code, exit 0, no
diagnostic. `meta/runTs.cjs` (plan 34.9-29) replaces the shared path with a private,
`fs.mkdtempSync`-created directory per invocation -- there is structurally nothing left to share. But
"the mechanism looks right" is not evidence; this project's hardest-won standing rule is that a claim
like this must be proven against a known-bad input, not merely read from the source. Plan 34.9-29's
own change touched EVERY build and guard script in this repository -- at least as much surface as the
defect it fixes -- so it must clear the same evidence bar `34.9-PIPE-PROOF.md` (PASS 36/36) and
`34.9-GUARD-PROOF.md` already met.
