## 1. What this proves and why it exists

**The claim under test, in one sentence:** after plan 34.9-29's wrapper conversion, no two
concurrent invocations of the same script can execute each other's compiled output (C3-01, closed),
AND a script whose entry file fails to compile still exits non-zero while executing nothing (the
exit-code short-circuit property `34.9-PIPE-PROOF.md` already proved for the retired `&&` idiom must
not have regressed under the new wrapper).

`34.9-REVIEW-CYCLE3.md`'s C3-01 finding, reproduced independently twice already (reviewer 60/60,
`34.9-VERIFICATION.md`'s own re-verification 20/20, both 100%): every pre-conversion script wrote its
compiled output to ONE shared, script-name-keyed path
(`node_modules/.cache/<name>.cjs`) -- two concurrent invocations of the same script raced on that
file, one process's `node` silently executing the OTHER's freshly-compiled code, exit 0, no
diagnostic. `meta/runTs.cjs` (plan 34.9-29) replaces the shared path with a private,
`fs.mkdtempSync`-created directory per invocation -- there is structurally nothing left to share. But
"the mechanism looks right" is not evidence; this project's hardest-won standing rule is that a claim
like this must be proven against a known-bad input, not merely read from the source. Plan 34.9-29's
own change touched EVERY build and guard script in this repository -- at least as much surface as the
defect it fixes -- so it must clear the same evidence bar `34.9-PIPE-PROOF.md` (PASS 36/36) and
`34.9-GUARD-PROOF.md` already met.

(a) The wrapper (`node meta/runTs.cjs ...`) exits NON-ZERO. **Failing observation:** `0`.

(b) The script body's own output is ABSENT from stdout. Operationalised as: the transcript, after the
    injected break, contains ONLY esbuild's own compile-diagnostic lines (identified by the `✘
    [ERROR]` marker and a `file:line:col` citation naming the injected entry file) -- no line

    absence of ANY non-esbuild output line is sufficient and necessary, since a compile failure that
    correctly short-circuits produces esbuild diagnostics and nothing else. **Failing observation:**
    any line in the transcript that is not an esbuild diagnostic line.

(c) The transcript contains esbuild's own error marker (`✘ [ERROR]`) and the injected entry file's
    path -- for S2 additionally the literal `Could not resolve
    "__wrapper_proof_unresolvable__"`. **Failing observation:** no error marker present -- the
    injection did not take. **Exit-code-alone is NOT sufficient** (criterion (a) alone is never the
    bar): an out-of-space abort, a missing `esbuild` binary, or an unrelated crash all exit non-zero;
    this criterion discriminates WHICH step aborted.

(d) The transcript does NOT contain `Cannot find module`. **Why this is a real discriminator, not

    `outfile` esbuild never wrote, and `require()` would print exactly this string. Its presence is
    the signature of a broken conversion; its absence is positive evidence `node` was never spawned.
    **Failing observation:** the string IS present.

(e) The private `mkdtempSync` directory (`$TMPDIR/gamelib-runts-*`) created for this invocation is
    ABSENT afterward -- `cleanupAndExit` (`meta/runTs.cjs:127-130`) removes it on every exit path,

    survives under `$TMPDIR` after the process exits. This is `meta/runTs.cjs`'s OWN discipline under
