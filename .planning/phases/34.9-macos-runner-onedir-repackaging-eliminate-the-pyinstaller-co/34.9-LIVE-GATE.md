## Sink partition (confirmed against current source at this authoring)

Every required literal below is annotated with the sink it can actually reach. No sidecar-emitted
literal is ever required of the session transcript; no Rust-shell-emitted literal is ever required
of `gamelib.log`.

- **Rust `[shell]`-prefixed lines** (`src-tauri/src/main.rs`'s `eprintln!` calls) reach
  `tauri:dev`'s own stdout/stderr, and therefore the **session transcript** ONLY. They never reach
  `gamelib.log`.
- **Sidecar `logInfo`/`logWarning`/`logError` calls** (`src/backend/logger/index.ts`'s
  `heroicLogWriter`) reach **`~/Library/Logs/GameLib/gamelib.log` ONLY** -- the sidecar's stdout is
  consumed as the RPC frame pipe, never surfaced as human-readable text
  (`sidecar-console-and-logger-are-invisible`).
- **Per-runner log files** (`getRunnerLogWriter`, `src/backend/logger/index.ts:82-94`) write to
  **`~/Library/Logs/GameLib/runners/{legendary,gog,nile}.log`** -- a THIRD sink, distinct from both
  `gamelib.log` and the transcript. `callRunner()` (`src/backend/launcher.ts:1652`) pushes this
  writer into `options.logWriters`, which captures the runner subprocess's raw stdout/stderr --
  including the actual version STRING a `--version` probe prints (e.g. `legendary version
  "0.20.43", codename "Undue Alarm"`), which `gamelib.log` itself never carries verbatim.
- **`gamelib.log`'s "Running command:" line** (`callRunner()`, `launcher.ts:1703-1704`, via the
  general `logInfo`) DOES carry the fully resolved spawn path (`getRunnerCallWithoutCredentials()`,
  `launcher.ts:1877-1926`, prepends the quoted `runnerPath` before the arguments) -- this is the
  correct sink for proving NESTED PATH RESOLUTION (`darwin/{runner}/{runner}`), but it is NOT the
  sink for the actual version text a probe returns. Items requiring both facts name both sinks.
- **Sidecar STDERR** reaches the session transcript, prefixed `[sidecar:err]`.
- **Sidecar `console.*` calls** reach nothing at all.

**Identifier-redaction discipline (mirrors T-34.4.2-49).** No cookie value, gamekey, OAuth code,
account id, or PKCE material (`code_verifier`, `serial`, `client_id`) is ever transcribed into
this document or any captured artifact -- timestamps, window/launch ordinals, and file paths
only. This binds with particular force on one literal named below: `src/backend/storeManagers/
nile/user.ts:62`'s `logInfo(['Register data is:', output], LogPrefix.Nile)` writes the FULL
`NileLoginData` object (url, `code_verifier`, `serial`, `client_id`) to `gamelib.log` in
plaintext -- this is PRE-EXISTING behaviour, unrelated to onedir packaging, and this plan does
not fix it (out of scope; recorded in the Summary as an out-of-scope finding for a future
security pass). The gate MUST use only this line's TIMESTAMP as Item 2's completion marker,
never its contents.

## Evidence-capture instruction (dual-sink standard, reproduced literally)

### 1. One-time session setup, before the first launch

```
export GATE_SESSION_DIR="/tmp/gamelib-gate-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$GATE_SESSION_DIR"
ls -d /tmp/gamelib-gate-* 2>/dev/null
```
Confirm no prior session directory is reused; note any prior ones as unrelated (do not delete
them). Archive any pre-existing `.old` file before the first launch:
```
[ -f ~/Library/Logs/GameLib/gamelib.log.old ] && cp ~/Library/Logs/GameLib/gamelib.log.old \
  "$GATE_SESSION_DIR/gamelib-launch-0-preexisting-old.log"
```

### 2. Single-instance assertion -- before EVERY launch, at window-appearance, and at teardown

**Before each Tauri-dev launch**, assert zero pre-existing instances:
```
pgrep -f 'target/debug/gamelib-shell'
```
must return nothing. **Before the Electron-packaged launch (item 4)**, assert instead:
```
pgrep -f 'GameLib.app'
```
must return nothing. A non-empty result means STOP and resolve it before launching -- never
"proceed and hope." **After the window appears**, record the single PID into the transcript:
```
pgrep -f 'target/debug/gamelib-shell' | tee -a "$GATE_SESSION_DIR/terminal.log"
```
(or the `GameLib.app` pattern for item 4). **At teardown**, record it again with the identical
command. **If the count is ever not exactly 1 at any of these three points, the launch is ABORTED
and re-run, and its evidence is NOT SCORABLE** -- nothing from an aborted attempt is archived or
cited. A second concurrent instance splits the `[shell]`/Rust-side sink while `gamelib.log` stays
SHARED, producing a populated, plausible-looking `gamelib.log` next to a transcript missing every
scored `[shell]` literal -- the most dangerous evidence shape this standard exists to prevent.

### 3. Per-launch delimiter -- write BEFORE each launch, exact literal text

```
echo "=== GATE LAUNCH ${N} — $(date -u +%Y-%m-%dT%H:%M:%SZ) ===" | tee -a "$GATE_SESSION_DIR/terminal.log"
```
where `${N}` is the launch ordinal (1-3). A reader greps section boundaries with
`grep -n '^=== GATE LAUNCH' "$GATE_SESSION_DIR/terminal.log"`.

### 4. The launch command itself -- `tee -a`, never bare `tee`, never `>`

Tauri dev (launches 1-2):
```
pnpm tauri:dev 2>&1 | tee -a "$GATE_SESSION_DIR/terminal.log"
```
Electron packaged (launch 3, item 4) -- there is no single "launch command" piping a long-running
dev server; instead, the build step itself is captured, then the `.app` is opened separately:
```
pnpm dist:mac 2>&1 | tee -a "$GATE_SESSION_DIR/terminal.log"
open "$(find dist -maxdepth 3 -iname 'GameLib.app' | head -1)" 2>&1 | tee -a "$GATE_SESSION_DIR/terminal.log"
```

### 5. Per-launch `gamelib.log` archive -- AFTER that launch's app has quit, BEFORE the next launch starts

```
cp ~/Library/Logs/GameLib/gamelib.log "$GATE_SESSION_DIR/gamelib-launch-${N}.log"
```
**Mandatory ordering reason** (`src/backend/logger/log_writer.ts:72-74`): `existsSync(this.
logFilePath)` then `renameSync(this.logFilePath, this.oldLogFilePath)` on the very next process's
FIRST write renames the live file to `.old`. A later launch destroys an earlier launch's sidecar
evidence unless archived first. Additionally, per-runner log files must be archived the same way,
same timing, for items that name them:
```
cp ~/Library/Logs/GameLib/runners/legendary.log "$GATE_SESSION_DIR/runners-launch-${N}-legendary.log"
cp ~/Library/Logs/GameLib/runners/gog.log       "$GATE_SESSION_DIR/runners-launch-${N}-gog.log"
cp ~/Library/Logs/GameLib/runners/nile.log      "$GATE_SESSION_DIR/runners-launch-${N}-nile.log"
```
(Only copy files that exist -- not every launch touches every runner.)

`AltLegendaryBin`, `AltGOGdlBin`, `AltNileBin` -- confirmed at `src/frontend/screens/Settings/

call (`getLegendaryVersion`/`getGogdlVersion`/`getNileVersion`) on mount, with no login and no

**Why not "on startup," despite that being this item's original framing.** The sidecar's own
entrypoint (`src/backend/sidecar/bootstrap.ts:84`, `initHeadless as initLogger`) calls
`initHeadless()`, which explicitly SKIPS the one-time `getSystemInfo().then(formatSystemInfo)`
dump that Electron's real `init()` (`src/backend/main.ts:99`, `init as initLogger`, called from

at boot -- they are gated behind the Settings > Advanced Settings UI mount, confirmed by grepping
every caller of `getLegendaryVersion`/`getGogdlVersion`/`getNileVersion` in `src/frontend/`: only
`AltLegendaryBin.tsx`, `AltGOGdlBin.tsx`, `AltNileBin.tsx`. This is a genuine Test 1/Test 7 defect
found and fixed during this contract's own authoring (see Structural Reachability Review, finding
F-34.9-G1-01) -- the plan's literal "on startup" framing is FALSE for Tauri dev and is corrected
here, in the item itself, not left standing.

**Required evidence, two sinks:**
1. `gamelib.log` (sidecar sink): three "Running command:" lines (`launcher.ts:1703-1704`), one per
   runner, each containing a resolved path matching `darwin/legendary/legendary`,
   `darwin/gogdl/gogdl`, and `darwin/nile/nile` respectively (the nested onedir shape
   `archSpecificBinary()` produces, `src/backend/utils.ts:524-526`). Grep:
   `grep -c 'darwin/legendary/legendary' "$GATE_SESSION_DIR/gamelib-launch-1.log"` (repeat per
   runner) -- each must be >= 1.
2. Per-runner log files (`~/Library/Logs/GameLib/runners/{legendary,gog,nile}.log`, archived per
   step 5 above) AND the Settings page's own visible "<Runner> Version:" text next to each

### Findings resolved during this authoring (not left for the run to discover)

- **F-34.9-G1-01 (Test 1 + Test 7, Item 1).** The plan's original framing ("on startup the four
  version probes run") is FALSE under the Tauri sidecar: `initHeadless()`
  (`src/backend/sidecar/bootstrap.ts:84`) explicitly skips the system-info dump `init()` performs
  for Electron. Fixed by retargeting item 1's gesture to the actually-shipped Settings >
  Advanced Settings mount, and by naming the correct two-sink evidence shape (path resolution in
  `gamelib.log`, version text in the per-runner log or the UI) rather than assuming both facts
  live in one place.
- **F-34.9-G1-02 (Test 1, Item 3).** Measuring GOG's interval from "click" (as item 2 does for
  nile) would conflate uncontrolled human OAuth-typing time with runner-spawn time, since GOG's
  login URL is a constant requiring no preliminary gogdl spawn (unlike nile's). A "PASS when under
  2s" bar measured from click would be non-diagnostic -- it would fail on every real human login
  regardless of onedir's actual win. Fixed by starting the clock at
  `[oauthLoginCapture] runner=gog status=captured`, the backend-only event immediately preceding
  the gogdl spawn, isolating the same quantity item 2 measures for nile.
- **Pre-existing sensitive-logging pattern noted, not fixed (out of scope).** `nile/user.ts:62`'s
  `logInfo(['Register data is:', output], ...)` writes PKCE material to `gamelib.log` in
  plaintext. This is unrelated to onedir packaging and outside this plan's `files_modified` list;
  recorded here and in the Summary as a finding for a future security pass, with the gate's own
  redaction discipline (above) preventing it from leaking into any gate artifact.
