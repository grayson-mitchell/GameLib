<objective>
Enumerate the C2-01 defect class at the granularity of the defect -- one row per package.json
script -- and measure everything the conversion in plan 34.9-25 will change, BEFORE changing it.

Purpose: this phase's own standing rule is that an audit whose unit is coarser than the defect's
unit cannot find the defect. `34.9-REVIEW-CYCLE2.md` named FOUR affected scripts. The gap-planning
decision D-C3-01 widened that to TWELVE and explicitly instructed that the count be verified against
the live file rather than taken on faith. Both lists are inputs to this plan, and neither is its
output. The census is derived by a mechanical predicate; whatever it returns is the scope.

The conversion is not cosmetic. It changes each script from "reads its program from stdin" to
"executes a real file on disk", which moves `__dirname` from `process.cwd()` to the emitted file's
directory and causes Node to set `require.main`. At least seven `meta/*.ts` files contain comments
asserting the stdin behaviour and at least two deliberately avoid `__dirname` because of it. Those
are behavioural facts that must be measured per instance, not assumed benign.

Output: `34.9-PIPE-AUDIT.md`, carrying a census table, a caller map, a per-instance behavioural
delta measurement, and a compile-status baseline. This plan changes no code and no script.
</objective>

**The defect (C2-01), already proven twice against this repo's real toolchain -- do not re-prove it
here, plan 34.9-26 owns the proof.** npm/pnpm run scripts through `sh -c`, which has no `pipefail`.
A POSIX pipeline's exit status is its LAST command's. In `esbuild --bundle ... meta/X.ts | node -`,
when `esbuild` fails to compile, `node -` reads empty stdin, executes nothing, and exits 0 -- the
pipeline reports success and the `&&` chain proceeds.

**The target idiom (D-C3-02), which already exists in this repo.** `verify:updater-key`
(`package.json:73`) is the precedent:
`esbuild --bundle --platform=node --target=node22 --outfile=node_modules/.cache/verify-updater-key.cjs meta/verifyUpdaterSigningKey.ts && node node_modules/.cache/verify-updater-key.cjs`
Do not invent a mechanism. Do not use `set -o pipefail` (not portable across the `sh -c` npm uses).
Do not use `PIPESTATUS` -- it expands EMPTY under this project's zsh, a documented trap
