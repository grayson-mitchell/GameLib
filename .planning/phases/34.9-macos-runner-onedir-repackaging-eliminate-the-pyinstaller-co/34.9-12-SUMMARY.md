## Decisions Made

- **Recursion-guard restructure (Task 2, live-discovered):** the original `collectSymlinks` recorded a symlink then `continue`d before reaching the recursion-guard branch, which meant a mutation of the recursion guard alone could never actually change observed behavior for a symlink entry -- the mutation test would have passed vacuously. Restructured so `isSymbolicLink()` and `isDirectory()` are checked independently per entry (no `continue`); behavior is identical (the two are mutually exclusive under `lstat`) but the recursion guard is now a real, test-discriminable seam. This was proven: mutation (c) (swapping the guard for a `statSync`-following check) went RED (2 records instead of 1) only after this restructure.
- **`du -A` over raw `du -sk` for the F-34.9-03 payload check:** raw `du -sk` on the built tree showed `legendary`/`gogdl`/`nile` summing to ~103M against a ~83M source (~24% gap) even with all 12 symlinks correctly restored and `readlink` targets matching exactly. Investigated per-file: `ls -la` and `du -A` (apparent/logical size) showed byte-identical file sizes and a 0.0% aggregate difference; the gap was traced to macOS APFS clone/copy-on-write block-sharing making the pre-existing `public/` copies report a smaller allocated-block count than `copyFileSync`'s freshly-written `build/` copies of the SAME bytes. This is a filesystem accounting artifact, not a residual defect. Both measurements are recorded below for the record.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug/test-integrity] `collectSymlinks`'s `continue` made the recursion-guard mutation vacuous**
- **Found during:** Task 2, while performing the plan-mandated mutation (c) (swap `dirent.isDirectory()` for a `statSync`-following check)
- **Issue:** the `continue` statement immediately after recording a symlink meant execution never reached the recursion-guard branch for a symlink entry, so mutating that branch's condition produced no observable change -- the "does not walk through a symlinked directory" test passed unchanged even under the mutated (defective) guard, which is exactly the vacuous-assertion class this repo's standing lessons warn against.
- **Fix:** removed the `continue`; both checks now run independently per entry. Behavior for well-formed input is unchanged (the two dirent predicates are mutually exclusive under `lstat`), but the recursion guard is now a genuine seam.
- **Files modified:** `meta/preserveRunnerSymlinks.ts`
- **Verification:** re-ran mutation (c) after the restructure -- it now fails exactly the intended test (`records` length 2 instead of 1, showing the extra `dir-link/inner-link` record from walking through the symlink); reverted, reconfirmed all 6 fixture tests GREEN.
- **Committed in:** `39751cff6` (Task 2 commit)

**Total deviations:** 1 auto-fixed (Rule 1, test-integrity class)
**Impact on plan:** Necessary for the mutation-testing requirement's own validity; no scope creep, no behavior change for correct inputs.
