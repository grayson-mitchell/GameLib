## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions → GameLib rolling release → this repository | a CI run's output becomes a value committed to git and later trusted by every developer's and CI's vendoring run |
| network bytes → `public/bin` | executables cross onto disk and will be bundled and spawned |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.9-01 | Tampering | the act of pinning a digest | mitigate | Digests are transcribed ONLY from the SHA256SUMS assets captured in Task 1 and quoted verbatim in `34.9-CI-ROUNDTRIP.md`, alongside the run URL that produced them. Re-hashing a locally downloaded archive is explicitly forbidden, because that verifies the bytes against themselves and would turn an in-repo pin back into trust-on-first-use — the exact weakness `meta/downloadZig.ts` records about its own control. |
| T-34.9-28 | Repudiation | provenance of the committed digests | mitigate | The record names the specific workflow run URL, both leg conclusions and the full asset list, so a reviewer can re-fetch the release and compare. The record is written BEFORE the pin, so the pin cannot be back-justified. |
| T-34.9-21 | Denial of Service (fail-safe) | sentinel digests left in place | mitigate | Under outcomes B and C the sentinels deliberately remain, so a clean checkout keeps throwing loudly rather than silently skipping verification. The record names this as a phase-closing blocker. |
| T-34.9-29 | Spoofing | a hand-built substitute presented as a CI artifact | mitigate | The plan forbids hand-building x64 under any outcome, and requires the record to state, per arch, whether each tree came from a CI download or a local build. Outcome C's arm64 staging is explicitly labelled local. |
| T-34.9-30 | Tampering | the digest gate never actually firing against real bytes | mitigate | Task 2 requires a deliberate corrupt-one-digest negative test against a real download, with the thrown message quoted. Without it, a passing round trip would be equally consistent with the verification being dead code — the same class of defect as a cookie poll with no liveness proof. |
| T-34.9-SC | Tampering | package installs | mitigate | This plan installs no npm, pip or cargo package; it dispatches a workflow, transcribes digests and runs an existing script. No legitimacy checkpoint is owed. |
