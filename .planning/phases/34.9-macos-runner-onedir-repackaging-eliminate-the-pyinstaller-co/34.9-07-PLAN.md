<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build output → shipped application bundle | ~100 additional Mach-O files per runner per arch enter a bundle that macOS will code-sign, notarize and seal |
| packager config → what a user executes | a glob decides which binaries reach the user's machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.9-07 | Tampering | nested Mach-O files inside `app.asar.unpacked` and inside the Tauri bundle | mitigate (partial) | electron-builder #3940 documents that binaries inside `app.asar.unpacked` have not always been signed correctly, and a onedir tree is exactly the deeply-nested shape that has triggered silent skips. This plan's mitigation is to refuse to treat "no build error" as proof: plan 34.9-08's `verify:runner-bundle` inspects the BUILT artifact and reports every nested Mach-O's signature state, and plan 34.9-11's gate runs it. Residual risk is recorded in `34.9-PACKAGING-LIMITATIONS.md`. |
| T-34.9-22 | Tampering | Tauri notarization with `externalBin` present | transfer + record | tauri-apps/tauri#11992 is an open, untriaged upstream bug: notarization fails with "the signature of the binary is invalid" when a sidecar is present, and this repo already ships `externalBin`. Phase 34.9 substantially increases the signable-file count on top of it. This is not closable here — it is recorded in `34.9-PACKAGING-LIMITATIONS.md` as a known upstream risk to surface to the developer BEFORE real Apple signing secrets are enrolled, and Task 3 pins `externalBin` unchanged so this phase does not widen the blast radius. |
| T-34.9-23 | Tampering | real-certificate signing and notarization | accept (deferred, pre-existing) | Every real macOS CI run in this repo has shipped unsigned; D-03/D-04 defer paid Apple Developer enrolment. No task in this phase may claim "signing works" — the honest proxy is `codesign --verify` on an adhoc-signed bundle, and that limitation is written into `34.9-PACKAGING-LIMITATIONS.md` rather than left to inference. |
| T-34.9-24 | Elevation of Privilege | over-broad packaging glob | mitigate | The recursive glob is scoped to `build/bin/${arch}/darwin/**/*` — one architecture, one platform directory. Windows and Linux keep single-level globs, pinned by negative tests, so a future edit cannot silently start shipping directory trees on platforms that were never meant to receive them. |
| T-34.9-25 | Denial of Service (fail-safe) | packaged Tauri resolution | accept (owned elsewhere) | A packaged Tauri build cannot resolve the runner tree regardless of staging (R-34.5-G1-PKG). This is pre-existing for today's single-file runners, is owned by Phase 34.5's deferred item 12, and is recorded rather than papered over. This phase's gate scopes itself to Electron-packaged and Tauri-dev accordingly. |
| T-34.9-SC | Tampering | package installs | mitigate | This plan installs nothing; it edits two config files and adds one test. No legitimacy checkpoint is owed. |
</threat_model>
