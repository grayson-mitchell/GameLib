## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `main()`'s default `distDir` used `__dirname`, which resolves to `.` under the `| node -` stdin invocation, not `meta/`**

- **Found during:** Task 3 (the first live `pnpm clean:dist-mac` run against the real `dist/`)
- **Issue:** The plan's action text specified `path.join(__dirname, '..', 'dist')` as the default. When this script runs via `esbuild --bundle ... | node -` (piped through stdin, exactly as `build-runners-onedir`/`verify:runner-bundle` already do), Node sets `__dirname` to `.` (i.e. `process.cwd()`), not the source file's directory -- a trap `meta/genI18nGateScope.ts` already documents from an earlier plan. The first live run silently computed `../dist` (one directory above the repo root), found no such directory, and returned `{ removed: [], kept: [] }` -- printing `kept 0 non-macOS entries` and reporting success while removing nothing from the real `dist/`. This is precisely the false-pass shape F-34.9-02 exists to prevent, just relocated into the fix itself.
- **Fix:** Changed the default to a cwd-relative `path.join('dist')` literal, with a comment documenting the trap and pointing at the `genI18nGateScope.ts` precedent. `pnpm clean:dist-mac` always runs from the repo root (like every other `meta/` script), so this is correct without needing `__dirname` at all.
- **Files modified:** `meta/cleanDistMac.ts`
- **Verification:** Re-ran `npx jest --config meta/jest.config.js meta/__tests__/cleanDistMac.test.ts` (11/11 still green -- the test suite always passes an explicit `distDir`, so it could not have caught this), then re-ran `pnpm clean:dist-mac` live against the real `dist/` and confirmed via `ls -la dist/` before/after that the six stale entries were actually removed this time.
- **Committed in:** `b9a50dd36` (part of the Task 3 commit, since the bug was discovered and fixed while performing Task 3's live run)
