## Accomplishments
- `downloadOnedirAsset(binaryName, arch)`: fetches an archive named via `archiveName()` (the same function CI's publish step uses, so the two sides structurally cannot disagree about a filename), sha256-verifies it against `meta/runnersOnedirDigests.json` (missing/sentinel/mismatch all throw, none ever write anything), lists every tar entry with `tar -tzf` and rejects absolute paths, `..` traversal, or any entry not prefixed `{binaryName}/` before a single byte is extracted, extracts with argv-form `tar -xzf`, and chmods ONLY the single top-level `{runner}/{runner}` entry when its exec bit is missing.
- `downloadLegendary()`/`downloadGogdl()`/`downloadNile()`: the six `darwin:` entries are gone from their upstream asset maps; each now runs the existing win32/linux `downloadGithubAssets` call alongside two `downloadOnedirAsset` calls (x64 + arm64) via `Promise.all`. `downloadComet()`/`downloadEpicIntegration()` are untouched, including comet's own darwin entries.
- `meta/runnersOnedirDigests.json`: all 6 archive filenames (3 runners x 2 arches) pinned to the `PENDING-CI-PUBLISH` sentinel, plus a `layout` string; plan 34.9-09 fills in the real digests once CI has published them.
- `darwinLayoutMarker()`/`computeLayoutMarker()`: a sha256 over the digests file's `layout` + sorted `digests`, wired into `compareDownloadedTags()`/`storeDownloadedTags()` as a `__darwin_layout` marker independent of `RELEASE_TAGS` -- closes 34.9-RESEARCH.md Pitfall 6. Verified live against the real committed `public/bin/.release_tags` (no `__darwin_layout` key present, as every existing checkout has today): it correctly reports `['legendary', 'gogdl', 'nile']` need re-downloading even though every `RELEASE_TAGS` value already matches.
- `meta/__tests__/downloadHelperBinaries.test.ts`: 45 tests, this script's first-ever coverage. `child_process`'s `spawn`, `fs/promises`' write surface, and global `fetch` are mocked; the module's own trailing entrypoint guard (`JEST_WORKER_ID`) is what makes importing it under Jest safe at all for the first time.
- All 5 plan-mandated mutation proofs performed LIVE (not just claimed): removing the sha256 comparison, removing the tar-entry prefix check, widening the single chmod to a second (fake-recursive) call, deleting the `__darwin_layout` branch, and re-adding a `darwin:` entry to `downloadNile`'s upstream map -- each confirmed RED, then reverted and confirmed GREEN.
- Live-verified without any mocks: a real bundled invocation of `downloadOnedirAsset('nile', 'arm64')` against the real committed (still-sentinel) `meta/runnersOnedirDigests.json` threw exactly `Digest for "nile_macOS_arm64_onedir.tar.gz" is still the placeholder sentinel "PENDING-CI-PUBLISH" -- plan 34.9-09 must fill it in with the real sha256 published by build-runners-onedir-macos.yml before this archive can be verified and extracted.`, with zero network calls and zero writes under `public/bin` (confirmed via `git status --porcelain public/bin` before and after).

## Decisions Made
- **`downloadOnedirAsset` never fetches for a sentinel/missing digest.** The missing-entry and sentinel checks run before `fetchArchiveBuffer()` is called at all, so a not-yet-published archive (today's real state: all 6 are sentinels) causes zero network I/O, not a fetch-then-discard.
- **Buffer the whole archive in memory via `fetch().arrayBuffer()` rather than reusing the existing `downloadFile()`'s stream-to-disk-then-hash path.** This makes the digest check possible entirely against in-memory bytes before anything touches `os.tmpdir()`, so a mismatch leaves nothing on disk anywhere (stronger than "nothing under `public/bin`" -- nothing under the temp dir either).
- **`computeLayoutMarker(layout, digests)` is a separate, exported pure function**, with `darwinLayoutMarker()` (the plan's specified zero-arg signature) delegating to it. This lets the two required mutation-adjacent test cases (digest-value change -> different marker; key reordering -> same marker) run without mocking or mutating the shared `runnersOnedirDigests.json` import.
