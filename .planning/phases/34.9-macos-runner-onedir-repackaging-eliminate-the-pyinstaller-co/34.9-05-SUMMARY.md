## Accomplishments

### Task 1 — three applies-cleanly patches (2026-08-10)

| Repo | Pinned tag | Workflow file patched | Size |
|---|---|---|---|
| `imLinguin/nile` | `v1.1.2` | `.github/workflows/build.yaml` | 3094 B |
| `Heroic-Games-Launcher/legendary` | `0.20.43` | `.github/workflows/release.yml` | 3730 B |
| `Heroic-Games-Launcher/heroic-gogdl` | `v1.2.1` | `.github/workflows/build.yaml` | 3837 B |

Each patch changes the macOS leg's PyInstaller invocation from `--onefile` to `--onedir` — and
nothing else about the invocation — then adds an archive step tarring `dist/<name>` so the archive's
root entry is `<name>/` with executable bits preserved, uploaded as the macOS release asset in place
of the bare binary. Each repo keeps its own asset naming convention; GameLib's `_onedir.tar.gz`
suffix was not imposed on anyone else's repository.

### Task 2 — three PR bodies and the submission checklist (2026-08-10)

Each `PR-BODY-{repo}.md` states the change, then the mechanism as cause rather than symptom (macOS
`amfid` performs a Gatekeeper assessment per extracted file, and `--onefile`'s randomly-named
`$TMPDIR/_MEIxxxxxx` extraction directory means that assessment cache never hits), then **that
runner's own** measured figures from `34.9-MEASUREMENT.md`, then the cost honestly (~2.3x–3.6x
bundle growth, ~100 extra files, asset becomes an archive), then who benefits (Heroic itself vendors
these binaries and its macOS users pay this tax today).

`34.9-UPSTREAM-PRS.md` carries the per-repo fork/clone/branch/apply/push/`gh pr create` sequence and
prepared answers to four likely maintainer objections: bundle size, archive-vs-bare-binary asset
shape, why not Linux/Windows, and reproducibility of the numbers.
