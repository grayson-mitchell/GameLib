**Arg-forwarding mechanics — this is the load-bearing constraint.** pnpm appends extra CLI args to
the END of the whole script string. `build-base.yml:48` runs `pnpm dist:mac --x64 --arm64
--publish=never`, and `package.json`'s own `dist:flatpak` uses the same idiom (`pnpm dist:linux
appimage`). Therefore the verify step MUST be inserted BEFORE `electron-builder`, never after: with
`electron-builder` still last in the `&&` chain, appended args continue to land on it exactly as
today. Appending the verify step after `electron-builder` would silently redirect CI's `--x64
--arm64 --publish=never` onto `verifyRunnerBundle`, which would then parse `--x64` as nothing and
`--publish=never` as nothing and take `process.arch` — a silent behaviour change. Do not do that.

**Why `| node -` (trailing dash) makes the append work.** `verify:runner-bundle` ends in `| node -`,
so `pnpm verify:runner-bundle build --arch=arm64` expands to `esbuild ... | node - build
--arch=arm64` and `process.argv.slice(2)` is `['build', '--arch=arm64']`. Same idiom as
`clean:dist-mac` and `build-runners-onedir`. The pipeline's exit status is `node`'s (last command),
so a non-zero verdict propagates and the `&&` chain aborts before `electron-builder`.

**`verifyRunnerBundle.ts` CLI surface (read at planning time):**

| Aspect | Value |
|---|---|
| Usage | `verify-runner-bundle <root> [--arch=<x64\|arm64>] [--json]` |
| Root resolution | `findDarwinBinRoot` SEARCHES under `<root>` for a dir ending `build/bin/<arch>/darwin`; root `build` resolves to `<repo>/build` and finds `<repo>/build/bin/arm64/darwin` |
| Exit code | `main()` returns `summary.ok ? 0 : 1`; `process.exit(main())` unless `JEST_WORKER_ID` |
| Failure output sink | `console.log` — **stdout**, not stderr. The transcript must capture stdout. |
| Root-not-found error | thrown, printed via `console.error`, exit 1, and the message NAMES both root and arch: `could not find a "build/bin/arm64/darwin" directory under root "..." (arch="arm64")` |
| The literal the proof expects | `Versions/Current exists but is not a symlink (F-34.9-01)` — emitted contiguously from `summarise()`, prefixed by `<runner>: framework <path> is malformed -- ` |
| Also fires on the same injection | `top-level stub "Python" is a real file, not a symlink into Versions/Current (F-34.9-01)` |

**Why `--arch=arm64` is hardcoded.** `build/bin/x64/darwin` holds onefile binaries and would fail
