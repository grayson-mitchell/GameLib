<mandatory_standard>
`.claude/skills/spike-findings-gamelib/references/live-gate-contract-authoring.md` is not advisory.
Section 3's dual-sink evidence-capture standard states in terms that every future contract in this
project must implement it in full. Its load-bearing clauses:

- ONE session directory per run, `/tmp/gamelib-gate-<ISO8601-UTC>/`, created once before the first launch.
- The transcript is APPENDED via `tee -a`, never a bare `tee` and never `>`.
- A delimiter line before each launch: `=== GATE LAUNCH ${N} — <UTC timestamp> ===`, greppable as `^=== GATE LAUNCH`.
- `gamelib.log` archived per launch to `gamelib-launch-${N}.log`, copied BEFORE the next launch renames it to `.old`; the pre-existing `.old` archived on the first pass.
- Every item records which launch ordinal covered it.
- A closing inventory: `ls -la` plus `wc -l` of the session directory, performed during the run.
- **Exactly ONE app instance, asserted not assumed**: `pgrep -f 'target/debug/gamelib-shell'` empty before each launch, the single PID recorded after the window appears and again at teardown; count != 1 aborts the launch as unscorable. A concurrent second instance splits the `[shell]` sink while leaving `gamelib.log` SHARED, producing a populated, plausible-looking log next to a transcript missing every scored literal.

Section 4's two rules also bind: never use a tee'd transcript to prove a backend path did NOT run,
and a green test suite never closes a live gate.
</mandatory_standard>

<seven_tests>
Section 2's defect-class tests, each of which every item must pass, with the review written INTO the
contract as a table rather than performed silently:

  Test 1 — Origin/scheme reachability
  Test 2 — Concurrency reachability
  Test 3 — Log-line emitter reachability, INCLUDING the SINK clause (can the demanded line reach the
           sink the item reads? sidecar `[Backend]` output goes to `gamelib.log`; the Rust binary's
           `eprintln!` `[shell]` lines follow stderr into the transcript — a transcript structurally
           cannot carry sidecar output)
  Test 4 — Absence-observability
  Test 5 — Requirement-interaction reachability, **whose unit of review is the PAIR**: for every
           ordered pair of requirements, does satisfying A destroy B's evidence? Hunt specifically
           for anything that restarts, truncates, clears, resets, consumes a one-shot resource or
           changes an env var.
  Test 6 — Pre-existing external-state reachability
  Test 7 — UI-level reachability, distinct from backend-logic reachability: is the control the item's
           gesture needs actually offered by the shipped frontend?
</seven_tests>

<scope_fences>

**Tauri-packaged.** OUT of scope, blocked on R-34.5-G1-PKG (Phase 34.5's deferred item 12). It must

signature-state report, and must state that real notarization proof remains deferred.
