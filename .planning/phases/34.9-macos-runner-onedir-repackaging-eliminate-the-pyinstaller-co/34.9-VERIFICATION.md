**Phase Goal:** Ship `legendary`, `gogdl` and `nile` as PyInstaller `--onedir` builds on macOS so a

## What changed since the last verification

Gap cycle 3 existed for exactly one purpose: close truth 8's sole remaining failure, C2-01 — the
`esbuild ... | node[ -]` pipe idiom whose exit code is the LAST pipeline command's (`node`'s), so a
guard script's own compile failure is silently swallowed and reported as success. Plan 34.9-23
derived a programmatic census (parsing `package.json`'s `scripts` object, not grepping a line
window) and found **13** instances — one more than gap-planning decision D-C3-01 assumed
(`build:sidecar-sea`, `package.json:35`, sat outside the line-61-72 window both prior scoping passes
used). Plan 34.9-25 converted all 13 to `esbuild --outfile=node_modules/.cache/<name>.cjs ... &&
node node_modules/.cache/<name>.cjs`, where `&&` short-circuits on a non-zero `esbuild` exit so
`node` is never invoked on a broken compile. Plan 34.9-26 proved this both directions on real arm64
hardware (`34.9-PIPE-PROOF.md`, verdict PASS 36/36). Plan 34.9-24 closed two smaller cycle-2 findings
(C2-06, C2-08). Plan 34.9-27 closed C2-04 with a wiring-pin test proven red against four deliberate
mutations, and ledgered C2-05/C2-07 as dated deferrals per locked decision D-C3-05. Plan 34.9-28
swept all eight `34.9-REVIEW-CYCLE2.md` findings to a disposition table by set-difference (6 fixed,
2 deferred, unmapped 0 — reproduced live in this verification, see below).

**All of that is independently re-confirmed true in this re-verification.** `package.json` read
directly: all 13 scripts now use the `--outfile ... && node` shape, zero remaining `esbuild ... |
node` matches. `34.9-C2-SWEEP-CHECK.cjs` re-run live against the real `deferred-items.md` and
`34.9-REVIEW-CYCLE2.md` in this verification: exit 0, `C2-SWEEP-OK 8/8 mapped, unmapped 0`, matching
the phase's own claim exactly. The core exit-code fix was independently re-reproduced against the
real repo `esbuild` binary in this verification, outside any of the phase's own proof documents: a
deliberately syntax-broken entry file AND a deliberately unresolvable-import entry file each produced
pipeline exit `0` under the OLD `| node -` idiom (the bug, reproduced) and pipeline exit `1` under
the NEW `--outfile ... && node` idiom (the fix, reproduced), in both cases.

**Truth 8 is re-scored VERIFIED.** The specific, previously-falsifying claim — that a broken guard
script's own compile failure is silently reported as build success — no longer holds, and this is
now established by three independent parties against the real toolchain: the executor's own proof
(`34.9-PIPE-PROOF.md`), the gap-cycle-3 code reviewer's independent live reproduction outside the
repo, and this verification's own independent live reproduction.

**But a gap-cycle-3 code review (`34.9-REVIEW-CYCLE3.md`, committed `a1d55c53e`, run AFTER plan

### Truth 8 re-scoring — explicit judgment call

**The question:** does the fully-converted pipe-to-`&&` idiom satisfy "cannot silently ship again,"
given gap cycle 3's own review (`34.9-REVIEW-CYCLE3.md`) opened three new findings against the very
code that fix landed?

**Argument for "still FAILED" (considered, not adopted):** the previous verification held C2-01 to
FAIL truth 8 specifically because it fell through the phase's own reconciliation step — a review
landing after a gap cycle's own sweep, with the finding then sitting unrecorded. C3-01/02/03 are the
identical temporal shape: `34.9-REVIEW-CYCLE3.md` is dated after plan 34.9-28's own SUMMARY (same
day, later), so gap cycle 3's own reconciliation could not have swept it, and as of this verification
it still hasn't been. Applying the previous verification's own precedent literally would mean:
because ANY review can always, in principle, land after the reconciliation step it audits, truth 8
can never pass — there will always be a review one cycle behind.

**Argument for "VERIFIED" (adopted):** truth 8's specific, falsifiable claim was always narrower than
"no future code review will ever find anything" — it was "a broken guard script's compile failure is
silently reported as success," the exact mechanism C2-01 proved live. That mechanism is now closed
and independently confirmed by three separate parties (executor, reviewer, this verifier) against the
real toolchain, in both failure shapes (syntax error, unresolvable import). C3-01/02/03 do not
reopen that claim: C3-01 requires a different, deliberately-contrived trigger (two concurrent

**Verdict: VERIFIED**, with the review-closure work this cycle's own review generated tracked as a
