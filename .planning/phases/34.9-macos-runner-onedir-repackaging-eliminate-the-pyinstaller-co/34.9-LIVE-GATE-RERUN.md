## 3. Sink partition (reproduced unchanged from `34.9-LIVE-GATE.md`)

Every required literal below is annotated with the sink it can actually reach. No sidecar-emitted
literal is ever required of the session transcript; no Rust-shell-emitted literal is ever required
of `gamelib.log`.

- **Rust `[shell]`-prefixed lines** (`src-tauri/src/main.rs`'s `eprintln!` calls) reach
  `tauri:dev`'s own stdout/stderr, and therefore the **session transcript** ONLY. They never reach
  `gamelib.log`.
- **Sidecar `logInfo`/`logWarning`/`logError` calls** (`src/backend/logger/index.ts`'s
  `heroicLogWriter`) reach **`~/Library/Logs/GameLib/gamelib.log` ONLY** -- the sidecar's stdout is
  consumed as the RPC frame pipe, never surfaced as human-readable text
  (`sidecar-console-and-logger-are-invisible`).
- **Per-runner log files** (`getRunnerLogWriter`, `src/backend/logger/index.ts:82-94`) write to
  **`~/Library/Logs/GameLib/runners/{legendary,gog,nile}.log`** -- a THIRD sink, distinct from both
  `gamelib.log` and the transcript. `callRunner()` (`src/backend/launcher.ts:1652`) pushes this
  writer into `options.logWriters`, which captures the runner subprocess's raw stdout/stderr --
  including the actual version STRING a `--version` probe prints, which `gamelib.log` itself never
  carries verbatim.
- **`gamelib.log`'s "Running command:" line** (`callRunner()`, `launcher.ts:1703-1704`, via the
  general `logInfo`) DOES carry the fully resolved spawn path (`getRunnerCallWithoutCredentials()`,
  `launcher.ts:1877-1926`, prepends the quoted `runnerPath` before the arguments) -- this is the
  correct sink for proving NESTED PATH RESOLUTION (`darwin/{runner}/{runner}`), but it is NOT the
  sink for the actual version text a probe returns. Items requiring both facts name both sinks.
- **Sidecar STDERR** reaches the session transcript, prefixed `[sidecar:err]`.
- **Sidecar `console.*` calls** reach nothing at all.

## 5. Absolute-path rule

**Every path this document asks the sidecar to spawn, or asks the operator to type or paste into a
settings field, is written ABSOLUTE.** This is a dedicated rule, not folded into a precondition,
because Deviation 4 (Section 2 above) shows exactly what happens when it is skipped: the FAIL run's
own item-5 contract specified the repo-relative `public/bin/x64/darwin/nile`, but the sidecar spawns
with `cwd=<repo>/src-tauri`, so the path resolved to `src-tauri/public/bin/x64/darwin/nile` and
failed with ENOENT. The absolute path
(`/Users/graysonmitchell/Projects/GameLib/public/bin/x64/darwin/nile`) was substituted live and the
item PASSed on that basis -- a contract-authoring defect, not a product defect, since the real
Settings field is a file picker that only ever yields absolute paths.

**Repo-relative paths appear in this document ONLY inside shell commands that are explicitly stated
to run from the repo root**, and each such command says so at the point it is given (e.g. `pnpm
dist:mac`, `find build/bin/arm64/darwin -type l`, run from
`/Users/graysonmitchell/Projects/GameLib`). No such command's OUTPUT is ever fed into a settings
field or a sidecar-spawn argument without first being captured into an absolute-path variable --
Scored Item 2 below does this explicitly for the built `.app` path before using it in any
`codesign`/`find`/`verify:runner-bundle` invocation.

This rule applies going forward to every item in this document, including the three carried-forward
items' own future re-runs, not only to the two scored items below.

### 6.2 Single-instance assertion -- before EVERY launch, at window-appearance, and at teardown

**Before the Tauri-dev launch (Launch 1)**, assert zero pre-existing instances:
```
pgrep -f 'target/debug/gamelib-shell'
```
must return nothing. **Before the Electron-packaged launch (Launch 2)**, assert instead:
```
pgrep -f 'GameLib.app'
```
must return nothing. A non-empty result means STOP and resolve it before launching -- never
"proceed and hope." **After the window appears**, record the single PID into the transcript:
```
pgrep -f 'target/debug/gamelib-shell' | tee -a "$GATE_SESSION_DIR/terminal.log"
```
(or the `GameLib.app` pattern for Launch 2). **At teardown**, record it again with the identical
command. **If the count is ever not exactly 1 at any of these three points, the launch is ABORTED
and re-run, and its evidence is NOT SCORABLE** -- nothing from an aborted attempt is archived or
cited. A second concurrent instance splits the `[shell]`/Rust-side sink while `gamelib.log` stays
SHARED, producing a populated, plausible-looking `gamelib.log` next to a transcript missing every
scored `[shell]` literal -- the most dangerous evidence shape this standard exists to prevent.

### 6.3 Per-launch delimiter -- write BEFORE each launch, exact literal text

```
echo "=== GATE LAUNCH ${N} — $(date -u +%Y-%m-%dT%H:%M:%SZ) ===" | tee -a "$GATE_SESSION_DIR/terminal.log"
```
where `${N}` is the launch ordinal (1-2, or more if the Section-2 regression conditional triggers
and items 2/3/5 must be re-run). A reader greps section boundaries with
`grep -n '^=== GATE LAUNCH' "$GATE_SESSION_DIR/terminal.log"`.

### 6.4 The launch command itself -- `tee -a`, never bare `tee`, never `>`

Tauri dev (Launch 1):
```
pnpm tauri:dev 2>&1 | tee -a "$GATE_SESSION_DIR/terminal.log"
```
Electron packaged (Launch 2, Scored Item 2) -- there is no single "launch command" piping a
long-running dev server; instead, the build step itself is captured, then the `.app` is opened
separately:
```
pnpm dist:mac 2>&1 | tee -a "$GATE_SESSION_DIR/terminal.log"
BUILT_APP="$(find "/Users/graysonmitchell/Projects/GameLib/dist" -maxdepth 3 -iname 'GameLib.app' | head -1)"
open "$BUILT_APP" 2>&1 | tee -a "$GATE_SESSION_DIR/terminal.log"
```
`BUILT_APP` is captured into a shell variable as an ABSOLUTE path (the `find` root is itself
absolute) precisely so every subsequent `codesign`/`find`/`verify:runner-bundle` invocation against
it obeys Section 5's rule without re-deriving the path each time.

### 6.5 Per-launch `gamelib.log` archive -- AFTER that launch's app has quit, BEFORE the next launch starts

```
cp ~/Library/Logs/GameLib/gamelib.log "$GATE_SESSION_DIR/gamelib-launch-${N}.log"
```
**Mandatory ordering reason** (`src/backend/logger/log_writer.ts:72-74`): `existsSync(this.
logFilePath)` then `renameSync(this.logFilePath, this.oldLogFilePath)` on the very next process's
FIRST write renames the live file to `.old`. A later launch destroys an earlier launch's sidecar
evidence unless archived first. Also archive per-runner log files the same way, same timing, for
items that name them:
```
cp ~/Library/Logs/GameLib/runners/legendary.log "$GATE_SESSION_DIR/runners-launch-${N}-legendary.log"
cp ~/Library/Logs/GameLib/runners/gog.log       "$GATE_SESSION_DIR/runners-launch-${N}-gog.log"
cp ~/Library/Logs/GameLib/runners/nile.log      "$GATE_SESSION_DIR/runners-launch-${N}-nile.log"
```

(Only copy files that exist -- not every launch touches every runner.)
