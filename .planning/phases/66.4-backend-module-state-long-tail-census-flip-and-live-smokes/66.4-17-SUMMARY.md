# Phase 66.4 Plan 17: Launch, known-fixes and CrossOver-index long tail Summary

The nine remaining root-level process-wide objects (event bus, frontend-ready flag, launch single-flight, image fetch dedupe, CrossOver index failure backoff and memo, overlay install single-flight, plus the two frozen constants) are per-boot instances bundled in an AppRuntime built by the new 'app-runtime' step. Eight files (crossover_index/fetcher, images_cache, knownFixOverlayInstall, knownFixes, knownFixesFetcher, knownFixesRegistry, launcher.ts, protocol.ts) no longer import `backend/constants/paths`.

- `68b2bfd8f` lower the wiki_game_info.test jestMock ceiling (a ceiling the first commit missed).

## Behavior kept
- Launch single-flight: same join/release semantics, one table per boot (T-66.4-54, test).
- frontendReadySeen flips once per instance; a fresh boot is un-ready (T-66.4-55, test and protocol.test per-test runtime).
- CrossOver index failure backoff: same 5 minute window, now read from the injected clock; per descriptor, per boot (T-66.4-56, test on a FakeClock; a second runtime retries at once).
- Index maps memo keyed on generatedAt, per instance (test).
- Overlay install single-flight is per instance (new test: two boots do not share a fetch).
- Exit contract: construction allocates maps and an emitter only; no timer, no listener, no I/O. `smoke:sidecar` PASS.
