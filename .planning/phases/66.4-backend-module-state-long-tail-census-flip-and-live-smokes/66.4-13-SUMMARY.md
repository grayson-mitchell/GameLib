# Phase 66.4 Plan 13: Abort registry and Wine window raiser Summary

The process-wide abort-controller Map and the Wine window raiser's cancel flag and timer set are now closure state of two factories, built once per boot by an 'abort-registry' step and reached by every former importer through a Pick slice. stdin EOF still pauses the download queue first, then aborts every registered controller, now through `deps.aborts.abortAll()`.

## Commit
One code commit (`6148399c9`) for both tasks: the tree does not typecheck between them once the importers move to injected slices (as in 66.4-04 to 12).

## Boot step and exit contract
`'abort-registry'` builds `{ aborts: createAbortRegistry(), windowRaiser: createWineWindowRaiser({ clock: ctx.clock }) }`. Construction allocates an empty Map, a flag and an empty Set: no I/O, timer or handle (tested: zero fake-clock timers). `rpc-server` hands `services.aborts` to `releaseOnStdinEof`; the quit handler's `abortAll` and the command runner's `abort.create/remove` read the same instance, so EOF, quit and every cancel act on one registry (T-66.4-40). The pause-first order (live-gate 2026-10-26 lesson) is pinned by `stdinEofRelease.test.ts` (T-66.4-41). Raise timers run on the clock and `stop()` clears them with a fake-clock assertion (T-66.4-42).

`pnpm build:sidecar && pnpm smoke:exit-check -- --mode eof`: verdict PASS, exit latency 11 ms, no survivors. `pnpm smoke:sidecar` PASS (exits 0 on stdin EOF).
