<objective>
Close both code defects behind gap G-66.4-W2 (66.4-WINDOWS-UAT.md test 2, run under D-66.4-06): a Windows
Desktop/Start Menu shortcut opened Documents instead of launching the game, and showed a folder icon.

Root cause (binding, from `.planning/debug/windows-desktop-shortcut-opens-documents.md`): (1) `buildShortcutEnv`
hands explorer.exe the gamelib:// URL as an UNQUOTED argument; explorer does not dispatch an unquoted
`scheme://host?query` token and opens Documents. Every store is affected because every launch URL carries `?`.
(2) Steam install records have no `install.executable`, so the win32 arm of `addShortcuts` sets no icon and the
.lnk shows explorer.exe's own folder icon.

Purpose: the shortcut a user adds from GameLib must start the game and look like the game.
Output: quoted-argument writer, encoded win32 launch URL, a new icon resolver module, and unit tests that run on
every OS (CI is ubuntu-only). The live Windows proof is plan 66.4-25.
</objective>
