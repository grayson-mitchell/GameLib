# Phase 66.4 Plan 20: app-folder boot step; constants/paths, pathShim and bottleDirs deleted Summary

The heroic -> GameLib config-folder rename and the CI=e2e app folder are now an explicit, pinned first boot step; `constants/paths.ts`, `sidecar/pathShim.ts` and the temporary `steam/bottleDirs.ts` shim are gone, and nothing under `src/` or `meta/` imports them.

## Commits
- d872dea92: refactor(66.4-20): app-folder boot step; delete constants/paths, pathShim and steam bottleDirs

One commit for both tasks, on purpose: deleting the two modules breaks the typecheck of every importer, and the 'app-folder' step is what makes the deletion safe, so the tree does not typecheck between them.

## Step contract ('app-folder')
- `prepareAppFolder(paths: Pick<AppPaths,'appFolder'>, deps)` in `sidecar/appFolderStep.ts`. `deps` is `{ env, fs: { existsSync, renameSync, mkdirSync }, dirSync, log, logError }`.
- Rename: when `<appData>/heroic` exists and `<appData>/GameLib` does not, `renameSync` it; a failure logs `Failed to migrate legacy Heroic config folder to GameLib: <error>` to stderr and boot continues. Skipped under CI=e2e.
- CI=e2e (unreachable, D-35-14-01, comment kept): `resolveAppPaths` picks the config root with `tmpNameSync({ prefix: 'gamelib-e2e-' })` (a name only, no I/O); the step creates it with `dirSync({ name, tmpdir, unsafeCleanup: true })` and `mkdirSync(<root>/GameLib)`. tmp's cleanup is a process 'exit' listener (tmp 0.2.4, lib/tmp.js:732), which holds no event-loop reference.
- Exit contract: synchronous, bounded (two `existsSync` and one `renameSync`, or one `dirSync` and one `mkdirSync`), no handle, no in-flight work. A test pins the exact call list.
- `pathsBootOrder.test.ts` pins 'app-folder' at index 0 and ahead of logger, stores, migrations, config and secret-vault, with seeded misorder fixtures that assert the exact violation strings.
