# Phase 66.4 Plan 07: Steam token-store slot and path reads onto ctx.paths Summary

The Steam token store is a boot-owned slot rather than a module-level `let`, the four credential / depot error tables are frozen arrays, and five Steam files no longer import `backend/constants/paths`.

## Commit
One code commit for both tasks (the tree does not typecheck between them once the shared test helpers and ManagerDeps change, as in 66.4-04/05/06).

## Slot contract
`createTokenStoreSlot({ log })` returns `{ configure(next), current() }`. A fresh slot's `current()` is the fail-closed `UnconfiguredTokenStore` (setToken throws, reads report unreadable, clearToken only warns); `configure(next)` logs `Steam TokenStore implementation set to <constructor name>` and swaps. Two slots are independent (tested).

## Step position
`'steam-token-store'` sits directly after `'steam-session-state'` and before `'steam-anonymous-client'` / `'stores'` (construction only: no I/O, timer or handle, so the exit contract holds; nothing needs a release at stdin EOF). The `'secret-stores'` step calls `tokenStore.configure(...)` at exactly the point `installTokenStore` ran (dev-vault arm and keyring arm), and `'orphaned-token-cleanup'` still runs after it (T-28-10 ordering and legacy-key cleanup order preserved; the slot is unconfigured until then).
