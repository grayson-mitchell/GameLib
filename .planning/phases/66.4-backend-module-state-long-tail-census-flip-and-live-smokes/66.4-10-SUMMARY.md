# Phase 66.4 Plan 10: GOG long tail Summary

GOG library and installed-game maps, the presence keep-alive, resume baselines, the credential cache with its single in-flight spawn and the e2e gogdl stub slot are now closure fields of factories bundled in a boot-built GogRuntime, and gog/constants derives nothing at import.

## Commit
One code commit for both tasks: the tree does not typecheck between them once ManagerDeps, GOGUserDeps and the shared test helpers change (as in 66.4-04 to 09).

## Runtime contract
`createGogRuntime({ clock })` allocates empty maps and counters only: no I/O, no timer, no handle (tested: zero pending fake-clock timers). The presence interval is armed later by `setPresence` on the boot clock (unref'd) and cleared by `deletePresence`; one interval per runtime. Credential reads are single-flight per instance with the TTL measured on `clock.now`.

## Step position
`'gog-runtime'` sits directly after `'steam-install-runtime'` and before `'store-managers'`. BootServices.gogRuntime, ManagerDeps.gogRuntime, CreateStoreManagersDeps, managerDepsFromServices, requireServices and the store-managers step carry it. bootstrap.test pins 34 fields.

## deriveGogPaths importers
gog/{games,setup,redist,library,user}, downloadmanager/{utils,downloadqueue}. gog/library and gog/redist no longer import backend/constants/paths. `RedistDeps.paths` and `DownloadQueueDeps.paths` are widened with the GOG roots; `getRequiredRedistList`, `createRedistDMQueueElement` and `updateRedist` read them from deps.
