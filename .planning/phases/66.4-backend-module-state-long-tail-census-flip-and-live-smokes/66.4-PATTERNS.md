### S1: map or `let` cache -> per-boot instance (service, state)

**Analog:** `src/backend/engine/engineState.ts:242-262`, boot step `bootstrap.ts:1656-1672`, test `engine/__tests__/engineState.test.ts:1-30`.

Boot step (name registered in the `BOOT_STEP_NAMES` list, `bootstrap.ts:280-300`; `prebuilt` is the test injection point):

```typescript
{
```

Test shape: one owner per test, built in `beforeEach`/`freshOwner()`, no module reset, no `jest.mock` (`engineState.test.ts:11-30`).

Rules for every S1 file: add the field to `BootServices` (`services/types.ts`), expose to consumers as `Pick<>` slice, delete any `__reset*ForTests` export, delete the file's `meta/backendDiCeilings/<shard>.json` `moduleState` line and lower `jestMock` lines in the same commit. Rewriting `let m` to `const m = new Map()` at module scope does not lower the count (RESEARCH Pitfall 4). Where the file belongs to a family with an existing owner (engine -> `engine-state`; steam steam-core -> `steam-*` steps; gog `presence` -> existing `gog-presence` step), fold into it instead of adding a step. Single-flight state must be one instance per boot shared via slice (66.3 Pitfall 10).
