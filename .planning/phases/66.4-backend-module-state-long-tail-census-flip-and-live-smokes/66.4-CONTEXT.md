## Phase Boundary

This phase finishes D-15 step 3 of Phase 66, the half that 66.3 handed off (D-66.3-04). It has
four parts:

1. **The long tail.** Census on 2026-11-12: `moduleState` has **127 sites in 85 files** outside
   the 3 sanctioned sites (logger sink 2, boot entry 1). By area: `storeManagers/steam` 35,
   `storeManagers/gog` 9, `sidecar/appShellFlowRegistration.ts` 5, `utils.ts` 4,
   `storeManagers/legendary` 4, `utils/systeminfo` 4, then files with 1–3 sites each. This

   caches (`installingComponent`, `catalogCache`, `scriptMetadataCache`), `engineNoticeStore`
   and the two `pci_ids` stores. Each file is converted once, completely (D-15, read with
   D-66.3-11).

3. **The census flips into a zero-tolerance test,** and the `moduleState` ceiling section is
   deleted (D-13, D-16, D-66.4-02).
4. **Two non-autonomous closing plans:** the D-17 live macOS smoke with the scripted orphan/exit
   checker (D-66.3-05), and the Windows operator UAT (D-66.3-06, narrowed by D-66.4-06).

## Implementation Decisions

**Everything in `.planning/phases/66.3-backend-module-state-to-zero-and-live-macos-smoke/66.3-CONTEXT.md`
carries over unchanged.** That covers D-66.3-01..11, and through them Phase 66's D-01..D-17 and
the 66.1/66.2 carry-overs. Read it in full. The ones that bind this phase most:
- D-01: narrow slices, no locator, no `deps = defaultDeps`.
- D-05: no allowlist for process-wide state.
- D-15 read with D-66.3-11: a file's own state is converted once; import-line cascade edits don't
  count against that.
- D-66.3-05: the smoke's coverage, checker and defect policy.
- D-66.3-09: constant Sets are frozen, not exempted.

### The census flip
- **D-66.4-01: The once-only latches are converted, not sanctioned.** Five files keep one:
  `let registered = false` in `sidecar/devEpicCookieSweepRegistration.ts`,
  `runnerAuthFlowRegistration.ts`, `shortcutsFlowRegistration.ts` and
  `wineToolsFlowRegistration.ts`, and `let currentRegistry` in `sidecar/storeWriteHandlers.ts`.
  Idempotence moves to the owner. Either the injected IPC registry rejects or tolerates a
  duplicate channel registration, or the boot step that registers runs exactly once. The
  planner picks which and states the reason. The 66.3 README called these "latches that survive
  by design for now", and this decision ends that. The sanctioned list stays exactly the runner,
  `logger/index.ts` and `sidecar/bootstrap.ts`.
- **D-66.4-02: The census test is a hard zero with a fixed sanctioned list.** One jest test runs
  the D-06 census over `src/backend`. It asserts zero sites outside the sanctioned files, and the
  sanctioned list is a literal in the test, so changing it means editing the test where review
  will see it. The `moduleState` sections of `meta/backendDiCeilings/*.json` are deleted, along
  with the `moduleState` handling in `meta/backendDiCeilings.cjs`. The D-14 Rust-overlap
  exemption table is **not** kept as a hook. If Phase 75 is ever re-scoped, it adds one
  explicitly. `diPhaseGates.test.ts` pins the deletion.
- **D-66.4-03: `jestMock` ceilings stay as ceilings.** Only the `moduleState` section is
  deleted. `jestMock` keeps ratcheting down on its own track and is not part of this phase.

### Path constants and pathShim
- **D-66.4-04: Every derived path moves into `ctx.paths`, and the import-time side effects become
  a boot step.** `constants/paths.ts` (54 non-test backend importers) currently derives
  `configFolder`, `appFolder`, `userDataPath`, `publicDir` and the rest from `pathShim` and
  `GAMELIB_APP_ROOT`/`isPackagedSidecar()` at import time. It also runs two side effects at
  import time: the `CI=e2e` temp-dir `mkdirSync`, and the one-time **heroic → GameLib config
  folder `renameSync`**. Every derived path joins `AppPaths` on the boot context. The rename and
  the e2e temp dir become an explicit early boot step, ordered before the first store or config
  read. Today that ordering is implicit: the rename runs because the module is imported first.
  Preserve it, and pin it with a boot-order test. `steam/constants.ts` `steamSupportPath` becomes
  `AppPaths`-derived, as its own 66.4 hand-off comment says. The importers take a paths slice.
  A stateful importer does this in the plan that converts it. A stateless importer gets a
  D-66.3-11 cascade edit, which its SUMMARY lists.
  **Why:** the user chose the full move over moving only the side effects, because it ends
  import-bound paths. `ctx.paths` is the single swap point for the Tauri/Rust direction (the
  same reasoning as D-66.3-01).
- **D-66.4-05: `sidecar/pathShim` is deleted once no reader remains,** and `diPhaseGates.test.ts`
  pins its absence, the same way `platform/` was pinned in 66.3. If a boot-only caller
  (`createAppContext`) still needs its platform logic, that logic moves into the context module.
  It is not kept as a shim.

### Windows operator UAT (D-66.3-06, narrowed)
- **D-66.4-06: Delta only, no re-run of items that already passed.** The UAT covers:
  - The win32 paths 66.4 changes: `knownFolders` and the post-aq4 `pathShim` callers once
    they move onto `ctx.paths`.
  - The new path boot step: the config dir resolves, and existing settings and library data
    survive a restart.
  - One non-Steam game launch.
  - **Regression checks** on the Steam poller: a `steam://launch` game reaches Playing, then
    returns to Play, and Stop works (both from 7wo and 9p6, which passed live 2026-11-11).

  The 5fw spawn-path items are not re-run. When the UAT passes, close
  `.planning/todos/pending/2026-11-11-revive-steam-runningappid-poller-under-tauri.md`. It still
  says `ready: live-gate`, but the 9p6 gate already observed Playing on Windows. Items follow the
  UAT item shape. An item that cannot be reached is marked `blocked` with a reason.
  *(During discussion the user chose "Stop: observe only, known-blocked". The Stop todo turned out
  to be already completed and live-passed, so Stop becomes a regression item instead. This is
  recorded rather than silently changed.)*

### The 66.3 UAT gaps (both outside 66.4)
- **D-66.4-07: The offline banner is a todo and is left out of the smoke.** 66.3 UAT Test 4 found
  that the OfflineMessage banner never appears with the network off. The operator believes it
  never worked. It is filed as
  `.planning/todos/pending/2026-11-12-offline-banner-never-appears-with-network-off.md`
  (`severity: major`, `platform: any`, `ready: live-gate`). The D-66.3-05 live smoke has **no
  offline item**. If anyone shows the 66.3 `online_monitor` conversion caused it, it falls under
  D-66.3-05's regression arm and becomes a gap-closure plan in 66.4.
- **D-66.4-08: Steam uninstall without confirmation is a separate quick task, not part of 66.4.**
  It is diagnosed in `.planning/debug/uninstall-skips-confirmation.md`. GameSubMenu's Steam
  branch (D-05, 2026-06-28) skips the UninstallModal on the assumption that Steam shows its own
  dialog. But bridge, bottle and unadopted Mac-native installs are deleted directly by GameLib,
  with no confirmation. The fix is a frontend change that deletes user data, so it runs as its
  own `/gsd-quick`, independent of this phase.

### Claude's Discretion
- How the long tail is grouped into plans and waves (for example, `storeManagers/steam` 35 sites
  split from the rest, or grouped by owner). D-15 must hold, and the path-constant move must be
  sequenced so no file is touched twice for its own state.
- Whether each latch's idempotence lives in the registry or in boot-step single-run (D-66.4-01).
- Where short-lived caches (`pci_ids`, `crossover_index`, `cheapshark`, `images_cache`, the
  `tools/index.ts` caches) live: their own boot objects, or folded into their owning service. D-05
  rules out sanctioning them. (This carries over from 66.3.)
- The orphan/exit checker's name, tree-walk method and thresholds. They carry over from
  D-66.3-05, and each threshold is justified against the sidecar exit contract.
- Picking the "Known loose ends" from the 66.3 README up only where a long-tail plan already
  touches the file. Those are: no unit test for the quit-handler release of the anonymous
  client, the dead test-only `ElectronSteamGridDbSecretStore`, and `isMacSonomaOrHigher()`
  comparing the Darwin kernel major with the macOS major 14. None is required scope.

## Existing Code Insights

### Reusable Assets
- `createAppContext` / `ctx.paths` (`src/backend/process/context.ts`) absorb the derived paths.
- The 66.3 boot-step + context-field pattern for owners. Every long-tail stateful file becomes a
  `createX(deps)` factory built by a named boot step, or folds into an existing owner.
- `createTestContext`, `scriptedRunner`, `fakeClock`, `captureLog`, and `bootFresh()`/`reuseRegistry`
  for boot tests.
- `createIpcRegistry()` on `BootServices.host`, the natural place for latch idempotence (D-66.4-01).

### Established Patterns
- Ceilings drop in the same commit as the conversion, until the flip plan deletes the section.
- A census-definition change has to name every newly counted site.
- Cascade edits (D-66.3-11) are listed in each SUMMARY.
- Constant `Set`s are frozen (D-66.3-09).

### Integration Points
- Boot order in `bootstrap.ts`: the heroic rename step must precede `createGlobalConfig()` and
  every store read.
- `releaseOnStdinEof()` and the quit path: anything a converted long-tail owner holds that can't
  be `unref()`'d belongs there.
- Windows: `knownFolders` → `ctx.paths` is the one win32 behaviour surface 66.4 changes.
