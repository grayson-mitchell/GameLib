# Phase 66.4 Plan 05: Engine long tail onto a boot-owned EngineRuntime Summary

The 12 engine module-state sites are now closure fields of per-file `createX()` factories, bundled into one `EngineRuntime` built by a named `'engine-runtime'` boot step, and the engine files read paths from injected deps instead of `backend/constants/paths`.

## Commit
- fa24a6980: refactor(66.4-05): boot-owned EngineRuntime, engine path reads off constants/paths (one commit: the two plan tasks change one contract and the tree does not typecheck between them, as in 66.4-04)

## EngineRuntime contract
`createEngineRuntime({ clock, paths })` returns `{ ledger, crossover, registry, switcher, fallback, deadlines, launchState, launchSettings, perGameBottle }`.
- `ledger` (createBottleLedger): markGameRunning / markGameStopped / gamesRunningIn / otherGamesRunning / size.
- `crossover` (createCrossoverLocator({ paths })): resolveCrossoverBinDir / resolveCrossoverBinDirAsync; the bin-dir memo is per instance, probed on first use.
- `registry` (createEngineRegistry): set / get / clearEngineSelection.
- `switcher` (createEngineSwitcher): prepareBottleForEngine with the per-bottle in-flight map.
- `fallback` (createFallbackEngine({ paths })): pinnedEngineRoot / pinnedEnginePaths / isPinnedEngineInstalled / ensurePinnedEngine (single-flight download map and artifact-install counter) / pruneUnpinnedEngines / sweepStaleEngineTemps.
- `deadlines` (createLaunchDeadlines({ clock })): armLaunchDeadline / cancelLaunchDeadline / activeCount, timers on the injected clock (unref'd by default, no keepAlive).
- `launchState` (createLaunchEngineState): ledger-bottle and first-match-watcher bookkeeping of launchEngine.
- `launchSettings` (createLaunchSettingsRegistry({ registry, paths })): overlay contexts and getLaunchSettings.
- `perGameBottle` (createPerGameBottleFlights): ensureGameBottle with the per-bottle in-flight map.
Construction allocates empty maps only; `engineRuntime.test.ts` asserts `clock.pendingCount() === 0` after construction.

## Boot step
`'engine-runtime'` sits directly after `'engine-state'` and before `'winetricks-queue'` / `'store-managers'` in BOOT_STEP_NAMES. `BootServices.engineRuntime`, `ManagerDeps.engineRuntime`, the download-queue and store-manager wiring carry it. The 'engine-temp-sweep' step now calls `runtime.fallback.sweepStaleEngineTemps()`. `smoke:sidecar` passes (exit by event-loop drain at stdin EOF, no new handle).

## Deviations from Plan
- [Rule 3] Single commit instead of two (the tree does not typecheck between the tasks).
- [Rule 3] Steam bottle modules (bottle.ts, bridgeBottle.ts, bridgeBottleLifecycle.ts, provisionBottle.ts) expose module-level functions with 70-plus external callers and no deps bundle in scope. - [Rule 1] engineConfig: `readStoredGameConfig` no longer skips the settings migration when a root is supplied (production always passed the default root, which migrated); settingsVersioning.test passes the root explicitly.
- [Rule 1] games.test: two `reason: 'user'` pinned selections were typed through `jest.requireActual` (any); corrected to the valid `'override'`.
- [Rule 1] gameLaunch.ts was over the steam line ceiling by 4 lines after the edit; trimmed to 998.
