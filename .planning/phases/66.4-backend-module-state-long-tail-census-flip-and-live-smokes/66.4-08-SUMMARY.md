# Phase 66.4 Plan 08: Steam bridge long tail Summary

The Steam bridge's single-flight clone maps, entitlement plist counter and shared-redist install map plus ledger tmp sequence are now closure state of a boot-built BridgeRuntime, its constant tables are frozen, and `steamSupportPath` no longer comes from `pathShim`.

## Commit
One code commit (`c138e30b2`) for both tasks: the tree does not typecheck between them once ManagerDeps and the shared test helpers change (as in 66.4-04 to 07).

## Runtime contract
`createBridgeRuntime()` allocates one entitlement signer, then `createRunnerCloneFlights({ signer })`, `createOverlayRunnerCloneFlights({ signer })` and `createSharedRedistInstaller()`. Construction allocates empty maps and counters only: no I/O, timer or handle, so the sidecar exit contract holds. Consumers: `deps.bridgeRuntime.runnerClone.ensureRunnerClone` (drmLaunchSetup via `DrmSetupOverrides.bridgeRuntime`), `overlayRunnerClone.ensureOverlayRunnerClone` (prepareOverlayLaunch), `sharedRedist.installSteamBridgeSharedRedists` (gameInstallBridge, gameBridgeWineLaunch; the dynamic imports of the module are gone). Single-flight is per instance; plist and ledger tmp sequence numbers are per instance (unique within a boot, start fresh in a new one; tested).

## Step position
`'steam-bridge-runtime'` sits directly after `'steam-launch-runtime'` and before `'winetricks-queue'` / `'store-managers'`. BootServices.bridgeRuntime, ManagerDeps.bridgeRuntime, `CreateStoreManagersDeps.bridgeRuntime`, `managerDepsFromServices`, requireServices and the store-managers step carry it.
