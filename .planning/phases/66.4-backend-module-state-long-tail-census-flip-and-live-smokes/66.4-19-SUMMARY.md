# Phase 66.4 Plan 19: Convert the five once-only latches Summary

The `registered` latches in the dev cookie sweep, runner auth, shortcuts and wine tools registrations and the `currentLayer` latch in storeWriteHandlers are deleted. Single-run now belongs to the boot, and a new source-level pin keeps it there. Commit: `495b6b274`.

## Decision (D-66.4-01, verbatim)

The five once-only latches are converted by boot-step single-run over a per-boot IPC registry, NOT by a duplicate-tolerant registry. Reason: each registration is called exactly once per boot from handlers.ts inside the 'register-handlers' step; bootSidecar() throws on a second boot in one process (the sanctioned `booted`); the IPC registry is created fresh per boot by 'host-services'; so the module flag guarded nothing a boot can reach, and the latest-boot-wins re-pointing was the C-WR-1 bug class itself. Idempotence lives with the owner (the boot), not the module.

## What changed

- The four registration files lost `let registered` and its early return. The dev sweep keeps its isPackaged gate and gains no registration-time logging. Their docstrings now state that the boot step owns single-run.
- storeWriteHandlers: the plan text named `currentRegistry`; the live code held a `currentLayer` (registry, root, push) plus `requireCurrentLayer`, from the plans 04 and 15 seams. Both are gone. The three listeners close over a per-call `layer` built from `deps.registry`, `deps.root` and `deps.pushFrontendMessage`.
- `registrationOncePerBoot.test.ts` pins one call each in comment-stripped handlers.ts, with seeded duplicate and missing cases.
- `runnerSliceRegistration` idempotence describe rewritten to registry semantics. A second call must not throw, `handle` channels stay the same set (last wins), and `on` listeners append (count doubles).
- storeLayer C-WR-1 test now reads the second boot's own ipc.
- `diPhaseGates`: the moduleState total goes 9 -> 4, and the five files are asserted absent from the census. The OWNED_66_3 list is unchanged at 28.
- sidecar.json `moduleState` is now `{}`. The census holds constants/paths, logger and bootstrap only, and the sanctioned list is unchanged.

## Deviations (Rule 1/3, tests that the latch had been hiding)

- flowRegistrationCensus: with the latch gone the docstrings became adjacent to the function, so the census now reads them. runnerAuth, shortcuts and wineTools were removed from `NO_COUNT_CLAIM`, and their stated totals (11, 7, 15) match.
- runnerSliceRegistration isolation test: the latch had made `registerWineToolsFlows` a no-op after the canonical registration. Un-latched, it registers the winetricks queue trio (winetricksApply, winetricksQueueState, winetricksCancelRemaining), which is not in the declared set. I allow that trio for that module only.
- testContainment: `registrationOncePerBoot.test.ts` is classified as structurally contained.
