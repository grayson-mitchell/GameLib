# Phase 66.4 Plan 06: Steam launch long tail onto a boot-owned SteamLaunchRuntime Summary

The seven Steam launch-path module-state sites (bottle monitors, raise-loop cancel flag and timers, DRM runner map, DRM notice latch, platform-capture chain, overlay route set) are gone; the launch files read their path roots from `deps.paths`.

## Commit
- 0c5c35a32: refactor(66.4-06): one commit for both plan tasks (the tree does not typecheck between them, as in 66.4-04/05).

## Runtime contract
`createSteamLaunchRuntime({ clock })` returns:
- `monitors` (createBottleProcessMonitors): startBottleProcessMonitor / stopBottleProcessMonitor / getBottleProcessMonitorPhase / stopAllBottleProcessMonitors / getActiveMonitorKind. Poll sleeps run on the injected clock (unref'd), tracked per entry and cleared by clearEntry.
- `raiser` (createBottledSteamRaiser): raiseFrontmostBottledProcess + cancelRaiseLoops. Retry sleeps are clock timers; cancel flips the flag and clears every timer; a fresh loop resets the flag (today's semantics).
- `drmRunners` (createDrmBridgeRunners): set / setOverlay / get / getKind / clear / binDir; one runner per appId per instance.
- `drmNotice` (createDrmModeNoticeLatch): `claim(key)` true once per key per instance (at most one DRM-mode dialog per boot session).
- `platformCapture` (createPlatformCaptureQueue): `withPlatformCaptureLock`, strictly ordered, a rejection does not break the chain.
`OVERLAY_INPUT_FIX_ROUTES` is `Object.freeze(['tcp-clone', 'env'])` (membership unchanged, `.includes`).

## Step position
`'steam-launch-runtime'` sits directly after `'engine-runtime'` and before `'winetricks-queue'` / `'store-managers'`. BootServices, ManagerDeps (managerDepsFromServices), the store-manager, launcher, download-queue, tools and engine/wine-tools flow wiring carry it.

## EOF-release decision
No release in `releaseOnStdinEof` is needed: every monitor and raise-loop timer is a clock timer (unref'd by default, no keepAlive), nothing is armed at construction, and the runtime holds no socket, watcher or child handle. `smoke:sidecar` passes (exit by event-loop drain at stdin EOF).
