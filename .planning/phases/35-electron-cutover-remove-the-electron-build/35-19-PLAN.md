  - **Standing rule D-E: the author of a gate contract may never also run it.**
  - Seven defect-class tests, each with a worked example from a real failure:
      1 origin/scheme reachability — can the thing being observed be reached from where the
        operator is standing?
      2 concurrency reachability — does the item require two things to be true at once that cannot be?
      3 log-line emitter reachability WITH A SINK CLAUSE — necessary but not sufficient to name the
        line; the item must also name WHICH SINK the emitter writes to. The project's two sinks
        partition: `~/Library/Logs/GameLib/gamelib.log` and the terminal `[shell]` output.
      4 absence-observability — an item asserting something does NOT happen must say how absence is
        distinguishable from not-looking.
      5 requirement-interaction reachability — the unit of review is the PAIR, not the item.
        Sweep state-mutating requirements against each other: does item N leave state that makes
        item N+3 unsatisfiable?
      6 pre-existing external state — is the item's PREMISE true before the run starts (logged in?
        library populated? game installed?)
      7 UI-level gesture reachability — the unit is the GESTURE SEQUENCE. A sequence the UI forbids
        can never PASS no matter how the backend behaves.
  - Two rules paid for twice: **never use a tee'd transcript to prove a backend path did NOT run**,
    and **a green test suite never closes a live gate.**
