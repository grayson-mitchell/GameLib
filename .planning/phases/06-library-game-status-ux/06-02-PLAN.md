<objective>
Show a "Playing" status badge on a Steam game's library card while a Steam
session for that game is active (GAME-05), and hide the Stop action for Steam
because GameLib never owns the process (fire-and-forget `steam://rungameid`).

Approach (per D-05/D-06/D-07/D-08):
- Detect the active session from Steam's own local `RunningAppID` state via a
  per-platform reader (macOS registry.vdf, Windows `reg query`, Linux
  registry.vdf with a `reaper` process-cmdline fallback since the Linux VDF value
  is broken — ValveSoftware/steam-for-linux#9672).
- Run a ~5s poller mirroring the existing ACF install-poll lifecycle in
  library.ts; publish `gameStatusUpdate` deltas so the existing
  libraryStatus → hasStatus → getCardStatus → isPlaying chain lights the badge.
- Reuse the existing `isPlaying` badge UI (no new badge). Guard the Stop icon
  and Stop menu item with the existing `!isSteam` pattern.

Purpose: users get a live "Playing" signal for Steam sessions without GameLib
owning the process. Stop stays hidden because it cannot work for Steam.
Output: per-platform RunningAppID readers + poller in library.ts, poller
lifecycle wiring, and two runner-gated GameCard guards.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS/filesystem → GameLib backend | registry.vdf contents and `reg`/`ps` process output cross into the parser |
| Backend poller → frontend | RunningAppID (as appName) is published over IPC to drive the badge |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04 | Tampering | Windows `reg query` invocation | mitigate | argv-form spawnSync (array args, no shell), hardcoded registry path `HKCU\Software\Valve\Steam` — no user-influenced path, no shell-injection surface; windowsHide + 2s timeout |
| T-06-05 | Tampering | Linux `ps -eo args` reaper scan | mitigate | argv-form execFileSync (no shell), narrow regex `reaper SteamLaunch --AppId (\d+)`, parseInt base-10; a spoofing local process is an unprivileged same-machine actor — accepted low risk for a desktop launcher |
| T-06-06 | Tampering | registry.vdf RunningAppID parse | mitigate | Parse via @node-steam/vdf, read a single scalar with exact key path, parseInt base-10; on any parse failure return 0 (no throw). Stale value after crash self-corrects on Steam restart (Pitfall 8) — accepted per D-06 best-effort |
| T-06-07 | Spoofing | appID scoping into gameStatusUpdate | mitigate | Only a numeric id (String(parseInt result)) is published as appName; no raw external string is interpolated |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages this phase (RESEARCH Package Legitimacy Audit); no install tasks, no legitimacy checkpoint required |
</threat_model>
