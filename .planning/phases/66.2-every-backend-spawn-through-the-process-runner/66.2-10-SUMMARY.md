# Phase 66.2 Plan 10: DRM spawners on the process runner Summary

pgrep, codesign, unzip and the bounded `ps`/`lsof` listings now run through `runner.run` with their old caps, and the three single-flight Maps are closure state of one `createSteamDrm` built inside `createSteamProcesses`.

## What changed

- `boundedListing.ts`: `createRunBoundedListing({ runner })` maps `run` (timeoutMs 3000, maxBufferBytes, stdin '') to `{ error, stdout }`; never rejects. Its loop-drain test now bundles the real `createProcessRunner` and measures a plain node child exiting at once on `sleep 2`.
- `bottleProcesses.ts`: `defaultListBottleProcesses(deps, bottleDir)` and the listing helper take `{ runner }`.
- `drmLaunchSetup.ts`: `createIsMacSteamRunning` (pgrep, 5 000 ms, stdin '', fake HOME env with replaceEnv; 0 true, 1 false, else/timeout/rejection throws). `createSteamDrm` returns `{ drmLaunchSetup, prefetchDrmDownloads, ensureValveClient, ensureSteamclientLayerComponent, isMacSteamRunning }` and owns the setup single-flight Map.
- `steamclientLayerInstall.ts`: `createRunCodesign` (30 000 ms, 64 KiB cap, stdin '') and `createSteamclientLayerInstall({ runner })` with its own inFlight.
- `valveClient.ts`: `createRunUnzip` (120 000 ms, stdin '') and `createValveClient({ runner })` with its own inFlight.
- No `child_process` import and no module-level Map in any of the five files. Shard: four childProcess and three moduleState entries deleted, drmLaunchSetup jestMock 5 to 4. `CodesignRunner` knip line removed.

## Cascade edits

`stageDrmBottle.ts` (list-processes default now takes deps), `gameBridgeLaunch.ts` and `gameLaunch.ts` (use `steamGame.deps.steamProcesses.drm.*`; gameLaunch 995 lines), `steamProcesses.ts`, `testServices.ts` (throwing `drm` default in both factories), `games.test.ts` (drm stand-in delegating to the existing jest.fn-backed module mock).

## Deviations from Plan

1. **[Rule 3] createRestartDeps unchanged.** The plan asked to pass `drm.isMacSteamRunning` into createRestartDeps, but plan 09 already sources it from `macSteamOffline.isSteamRunning`. No edit needed in gameLaunch for that.
2. **Real runner in unzip/codesign integration tests.** valveClient's `itUnzip` tests and steamclientLayerInstall's real-codesign test genuinely extract/sign fixtures, so they use `createRealRunner()` (fake HOME) rather than a scripted runner. Everything else is scripted.
3. **Optional spawner overrides kept.** `runCodesign`/`runUnzip` deps remain optional test overrides (existing tests inject them); the `defaultRun*`/`default isMacSteamRunning` spawners themselves are gone. gameUninstall, gameInstallDepot, gameDrmLaunch, gameLaunchOverlay needed no edits.
4. **Kept mocks:** `games.test.ts` keeps its `drmLaunchSetup` module mock (it replaces the orchestrator, not child_process). No `jest.mock('child_process')` remains in the drm tests.
