# Phase 66.2: Every backend spawn through the process runner, then the `child_process` ban - Context

**Gathered:** 2026-11-10
**Status:** Ready for planning
**Source:** Inherited from Phase 66 by user decision (no separate discuss-phase), as 66.1 was. Phase 66 was split on 2026-11-10 into 66 (foundation) + 66.1–66.3; the roadmap states `66-CONTEXT.md` decisions D-01..D-17 apply to all four parts.

<domain>
## Phase Boundary

D-15 step 3 of Phase 66 (ROADMAP "### Phase 66.2"), for spawns. Every remaining `child_process`
file in `src/backend` (the census reads `childProcess=28` after 66.1) moves onto the runner. Each
file is converted completely in one plan, module state included, so no module is touched twice
(D-15).

- Engine per-child caps (`engine/runTool.ts`, `demoStatus.ts`, `bottlePrimitives.ts`) become `run`
  timeouts. `LAUNCH_DEADLINE_MS` stays a pipeline deadline owned by the clock (66 RESEARCH A1,
  confirmed 2026-11-09).
- The DRM spawners and `boundedListing`.
- The Steam spawn sites, including `macSteamOffline`, which absorbs the second `openDetached`.
- The bridge spawners.
- The 10 shell-string calls become argv (`compatibility_layers` keeps the three-word `mdfind`
  split; `tools/index` `which`), and the `execAsync` export is removed.
- Sync sites become async or go through a named `runSync` with a stated reason (D-09).
- `os/*` and `windowsShortcut`.
- The last plan merges `no-restricted-imports` for `child_process` into the existing ESLint `paths`
  array at `error` and deletes that ceiling (D-13, D-16).

Roadmap target: about 9–10 plans.

**Out of scope (66.3):** driving module state to zero (`GlobalConfig`, `helperRegistry`, the
static boot-bound holders, manager-module Maps, `engineNoticeStore`, the `pci_ids` stores) and the
live macOS smoke (D-17). Module state *inside a file this phase converts* is in scope (D-15).
</domain>

<decisions>
## Implementation Decisions

**All of Phase 66's D-01..D-17 apply unchanged.** Read them in full in
`.planning/phases/66-backend-dependency-injection-replacing-module-level-singleto/66-CONTEXT.md`.
Most relevant here: D-09 (async argv-only `run`; `runSync` only with a required timeout and a
stated reason), D-10 (every `run` has a timeout; `spawnLongLived` for app/game-lifetime children),
D-11 (the runner is the only code that uses `detached` or `unref()`s a child, and it owns log
capture/redaction; both `openDetached` helpers absorbed), D-12 (scripted fake by default, real
runner on `createFakeHomeProfile()`; tests stop mocking `child_process`), D-13 (`child_process`
imports at zero outside a short sanctioned list, each entry with a one-line reason, enforced by a
test/lint `error`), D-14 (Rust-port files stay exempt from DI but still spawn through the runner
once the ban lands), D-15 (each file converted once, completely), D-16 (ceilings only go down,
lowered in the same commit; at zero the rule becomes `error` and the ceiling is deleted).

### Carry-overs from Phase 66.1 (new for 66.2)
- **C-01: Build on what 66/66.1 shipped.** `src/backend/process/` (runner `run`/`spawnLongLived`/
  `runSync`/`openDetached`, clock, registries, `createAppContext`), the injected `spawnAsync`
  (thin runner caller, returns `aborted`/`timedOut` — 66.1 A-WR-4), `callRunner`/`runWineCommand`,
  `src/backend/testUtils/` (`scriptedRunner`, `realRunner`, `fakeClock`, `captureLog`,
  `createTestContext`), boot via `bootSidecar(ctx)`. Read `src/backend/process/README.md` first —
  its "Hand-off to 66.2" section is the authoritative leftover list.
- **C-02: 66.1 A-WR-3 lands here.** The module-private legacy `utils.spawnAsync` (ref'd,
  untracked, `AbortError` semantics) still backs `moveOnUnix`/`moveOnWindows`/`extractTarFile`,
  plus a bare `spawn` in `utils.ts`. Move those onto the injected `spawnAsync`/runner and delete
  the private one. Preserve each caller's cancel semantics explicitly (legacy rejected
  `AbortError`; the runner resolves `aborted: true`).
- **C-03: README hand-off items.** `config.ts`, `utils.ts`, `execAsync`, the VC redist probe,
  `wineserver -k`, the engine caps — each must appear in some plan.
- **C-04: Boot System Information probes.** 66.1 A-CR-1 moved the GPU/OS/comet-version dump off
  boot. Whatever spawners remain behind it (`genericSpawnWrapper` — lspci/powershell/df,
  `getCometVersion` `spawnSync`) go through `runner.run({ timeoutMs })`; no unbounded or ref'd
  work, per the sidecar exit contract.
- **C-05: Gate hardening deferred from 66.1 is owned here.** 66 REVIEW WR-04 (shard edits can
  raise the ratchet; no compare against `origin/main`), WR-05/WR-06 (`child_process` /
  `jest.mock` counting bypasses — dynamic `require`/`import`, `node:child_process`,
  `jest.doMock`/`setMock`) and IN-02 (loose census floors). At minimum the `child_process`
  bypasses must be closed before the ban is declared at zero, otherwise "zero" is not true. The
  `jest.doMock` re-count may rebaseline under the README's census-definition exception (name every
  newly counted site in the same commit).
- **C-06: Tests stop mocking `child_process`** in every file a plan converts (D-12); they move to
  `scriptedRunner`, or `realRunner` on `createFakeHomeProfile()` with the named real-profile arm
  where a defect only arms under a populated profile.

### Decisions on research open questions (user, 2026-11-10)
- **D-66.2-01 (OQ-1): `config.ts` factory defaults become spawn-free.** Flatpak detection via an
  fs check of the system/user flatpak install paths; the default wine binary via a PATH scan; the
  version probe moves to the already-async `getLinuxWineSet` path. Accepted cost: on a fresh Linux
  profile the persisted default wine name is the binary name until the wine list is read. Do not
  bind a runner into `GlobalConfig` (66.3 owns it).
- **D-66.2-02 (OQ-2): `readWindowsShellFolder` (knownFolders) becomes async**, called from its two
  async consumers. The `nativeImage` shim stays sync on a named `runSync` with a stated reason,
  supplied through the existing `bindTransport` seam (no new holder); `platformApi.shell.openExternal`
  reaches `openDetached` the same way.
- **D-66.2-03 (OQ-3): module state in converted files.** Closures that naturally become `createX`
  convert now. Three groups are explicitly deferred to 66.3 — `GlobalConfig`, the `utils.ts`
  default paths, the shared caches in `tools/index.ts` — and each touching plan's SUMMARY names
  the deferral (a recorded D-15 exception).
- **D-66.2-04 (OQ-4): WR-04 hardening is a hard-coded sanctioned-path table only.** No
  `--base origin/main` compare; CI checkout stays as is.

each with a reason).
