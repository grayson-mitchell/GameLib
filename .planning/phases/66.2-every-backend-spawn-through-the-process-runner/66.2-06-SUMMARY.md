# Phase 66.2 Plan 06: Steam probes and monitors through the runner Summary

Five Steam spawners (`steamClientProcess`, `runningFromFolder.isProcessRunningFromFolder`, `steamInstallApp`, `steamDownloadMonitor`, `library/runningPoll`) no longer import `child_process`. The two that held module state (the nettop monitors Map; the poll timer and last-seen appId) are now closure state of instances built once at boot by `createSteamProcesses` and handed out on `ManagerDeps.steamProcesses`.

## Commit

- 50285c0b5 feat(66.2-06): all three tasks in one commit. The `ManagerDeps` type change cascades through every Steam library test at once (typecheck would not pass between tasks), so the per-task split was not viable.

## What changed

- Probes: `listSteamClientPids(deps, platform)` and `readSteamProcessStartTokens(deps, pids, platform)` run on `runner.run` (5 000 / 15 000 ms, `windowsHide`, `stdin: ''`), keeping `undefined` on probe failure and `[]` on pgrep exit 1. Rejection and timeout map to the old `'ERR'` code.
- `isProcessRunningFromFolder(deps, folder, timeoutMs = 2000)`: `ps -A -ww -o args=` with `createFakeHomeProfile().childEnv()`, `replaceEnv: true`, `stdin: ''`; rejects on timeout or non-zero as before.
- `createSteamInstallAppRun({ runner })` replaces the execFile default; `SteamInstallAppDeps.run` is now required. Truncation (64 KiB), timeout and spawn error map to `code: null`.
- `readRunningAppId(deps, platform)` is async (win32 `reg query` 2 000 ms; linux `ps -eo args` 1 000 ms only when registry.vdf yields 0); `readMacRunningAppId()` is the pure darwin reader.
- `createRunningPoll({ clock, readRunningAppId, notify })`: clock interval (unref'd by default), idempotent `start`, `stop` resets the last id, an in-flight flag so ticks never overlap (Pitfall 7).
- `createSteamDownloadMonitor(deps)`: `spawnLongLived('/bin/sh', watchdogArgs, { id: 'steam-download-monitor:<appId>', stdio: 'pipe', onStdout })`, no timeout (D-10), no `unref`; `handle.exited` marks the monitor failed; `stop` sends SIGTERM (the watchdog traps it). `readContentLogTail` is the exported production `readTail`.
- Boot: `createSteamProcesses` is built in the `command-runner` boot step (prebuilt honoured), carried on `BootServices`, passed into `createStoreManagers`, and `releaseOnStdinEof` receives `stopAllSteamDownloadMonitors` through its deps. `pnpm build:sidecar && pnpm smoke:sidecar` pass (exits 0 on stdin EOF).

## Cascade edits

- `nativeDelete.decideSteamNativeDelete`: all three deps required, async `readRunningAppId`, no module-default fallbacks; `gameUninstall.uninstallNativeInGameLib` supplies them from `steamGame.deps.runner`.
- `gameInstall.ts`, `gameInstallDepot.ts`: pass `{ run: createSteamInstallAppRun({ runner: steamGame.deps.runner }) }`.
- `stopInstallPolling(deps, appId)` and `cancelDelegatedInstall(deps, appId)` gained a deps first param (they stop the monitor through `deps.steamProcesses`); callers: `installPolling.ts`, `installPollOnce.ts`, `gameInstallBridge.ts`, `games.ts`.
- `shouldHoldForSteamRestart(deps, ...)` and `rearmPersistedSteamRestartHolds` pass the runner to the probes.
- `macSteamAdoption.defaultRestartDeps`: one line, now `readMacRunningAppId` (plan 09 removes `defaultRestartDeps`).
- `library/index.ts` init calls `this.deps.steamProcesses.runningPoll.start()`.
- `services/types.ts`, `services/managerDeps.ts`, `storeManagers/index.ts`, `testUtils/testServices.ts` (throwing default `createTestSteamProcesses`, plus `createInertSteamProcesses` for suites that run library code but assert on neither).
