# Phase 66.2 Plan 11: utils.ts spawns through the runner Summary

`src/backend/utils.ts` no longer imports `child_process`: `execAsync`, the private legacy `spawnAsync` and `memoryLog` are deleted, and every spawn in the file runs on the injected `spawnAsync` or `runner.run`. The census `childProcess` map is now `{ 'src/backend/process/runner.ts': 1 }` (plan 10 had already landed).

## What changed

- `moveOnWindows` / `moveOnUnix` take `{ spawnAsync, runner }` first and call `spawnAsync(cmd, args, {}, onOutput)` with no `stdio` key (Pitfall 4). The `rsync --version` probe is `runner.run('rsync', ['--version'], { timeoutMs: 5000 })`; a rejection, a timeout or a non-zero exit logs and selects the `mv` fallback (the old catch path). `rm -rf` still runs only after rsync `code === 0`, asserted.
- `extractFiles` / `extractTarFile` take `{ runner }` and run `tar` with `timeout: { none: true, reason: 'tar extraction of multi-GB ...' }`; non-zero stays `status: 'error'` with stderr.
- `shutdownWine` awaits `deps.spawnAsync(wineserver, ['-k'], { env: { WINEPREFIX }, timeout: 15000 })`; a timeout logs a warning and does not throw.
- `detectVCRedist` is now async on `runner.run('powershell.exe', <unchanged argv>, { timeoutMs: 15000, windowsHide: true })`: timedOut -> the old "signal" branch (warning, no dialog), rejection -> the old 'error' branch, non-zero -> logError, under 4 lines -> the dialog.
- `checkRosettaInstall({ runner })` runs `arch -x86_64 /usr/sbin/sysctl sysctl.proc_translated` with `timeoutMs: 10000`; installed iff it resolves code 0 and did not time out. `checkRosettaWhenMac(i18nReady, { runner })` is still chained off the boot dialog step; `rosetta` boot step now receives `ctx` and passes `ctx.runner`.
- New `utilsRunner.test.ts` (scripted runner, recorded spawnAsync, no jest.mock site) covers robocopy/rsync options (no `stdio`), rm-after-rsync ordering, probe failure/timeout -> mv, wineserver options and timeout, tar opt-out and error, and one real-tar run through `createRealRunner`.

## Cascade edits

- `fallbackEngine.ts`, `engineSwitch.ts`, `launchEngine.ts`, `perGameBottle.ts`, `pinnedEngineProgress.ts`, `steam/gameInstall.ts`: the plan treated `fallbackEngine.ts:238` as a one-line edit, but the module held no runner. `ensurePinnedEngine(pin, { runner, ... })` now requires one; `ensurePinnedEngineReportingStatus` takes `processRunner`; `switchServicesFrom(services)` now also supplies `ensurePinEngine`; `ensurePinned`/`ensurePin` defaults became closures over `services.runner`.
- `tools/index.ts`: `installOrUpdateTool(deps, tool)`; `tools/dxmt.ts`: `getLatest(deps)` and `DxmtStoresDeps.runner`, bound in `bootstrap.ts`'s `secret-stores` step from `ctx.runner`.
- `wine/runtimes/util.ts`, `runtimes.ts` (`download(deps, name)`), `launcher.ts` (3 call sites), `runnerMiscFlowRegistration.ts`, `wine/manager/downloader/utilities.ts` + `main.ts` (`unzipFile` gets `runner`, already held by `installVersion`).
- `gog/nile/legendary games.ts`: `moveImpl(this.deps, ...)`; `sideload/games.ts`: `await shutdownWine`.
- `appShellFlowRegistration.ts`: `detectVCRedist(deps)` is wrapped `void Promise.resolve(...).catch(logSendFailure)` since it is async now.
- Test edits: `checkRosettaInstall`, `detectVCRedistDialog`, `moveOnUnix`, `rosettaBootWiring` (boot context script), `rosettaPlatformGate`, `bootstrap`, `rustInvokeChannel` (scripted arch answer: on a macOS host the boot probe now goes through the scripted runner), `fallbackEngine`, `pinnedEngineProgress`, `legacyBottleUntouched`, `unzip` (real runner), `dxmtBootFetch`, `dxmtExportGate`, `createStoreManagers` (sideload stop gets a faked spawnAsync), and dead `child_process` mocks removed from `getShellPath` and the three launcher suites.

## Deferrals and flags

- D-66.2-03: the four `utils.ts` `default*Path` lets (moduleState 4) stay; they belong to 66.3. The `_root.json` moduleState entry is unchanged.
- C-02 cancel note: no caller passed a `signal` to the legacy helper, so there was no AbortError semantics to preserve. The injected spawnAsync resolves `aborted`/`timedOut` instead of rejecting; the move/extract callers never abort.
- Robocopy quirk kept as-is: `moveOnWindows` logs "Finished Moving" on `code !== 0` (robocopy codes 0-7 are success). The inverted branch is pre-existing and out of scope.
- `memoryLog` had no other live user in `utils.ts` (`commandRunner.ts` and `spawnAsync.ts` carry their own copies), so it was deleted.

## Deviations from Plan

- **[Rule 3 - Blocking] Engine/DXMT/runtime cascades.** The plan said callers pass `{ runner: deps.runner }` "from the slice they hold"; `fallbackEngine`, `DXMT.getLatest`, `runtimes.download` and `unzipFile` held none. Threaded as listed under Cascade edits; no new module state.
- **[Rule 1 - Bug] `SideloadGame.stop` floated `shutdownWine`.** Now awaited (see decisions).
- **[Rule 3] Acceptance pattern.** `checkRosettaInstall({ runner: ctx.runner })` is not literal in `bootstrap.ts`: the call is inside `checkRosettaWhenMac`, which has no `ctx`, so it reads `checkRosettaInstall({ runner: deps.runner })` with `{ runner: ctx.runner }` passed at the boot step.
- **utilsRunner.test.ts carries no `jest.mock`** (the ratchet rejects a new entry); it stubs the logger writers with `jest.spyOn`.
