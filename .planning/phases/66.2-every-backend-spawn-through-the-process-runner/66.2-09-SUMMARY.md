# Phase 66.2 Plan 09: Mac Steam client integration on the runner Summary

The Mac Steam go-offline wrap, its owed-goonline debt and shutdown signal are now one boot-built `createMacSteamOffline` instance on the process runner and clock. `macSteamAdoption.ts` runs its pgrep probe on `runner.run`, and `platform/openDetached.ts` keeps only the pure `shouldOpenInBackground`.

## What changed

- `macSteamOffline.ts` (936 lines, no `child_process`, no module `let`): the nine lets (guided arm, expiry timer, debt generation, confirm in flight, gooffline pending, shutdown flag/signal, restore flights) live in the factory closure. `isSteamRunning` = `runner.run('/usr/bin/pgrep', ['-x','steam_osx'], { env: createFakeHomeProfile().childEnv(), replaceEnv: true, stdin: '', timeoutMs: 2000 })`; exit 0 true, 1 false, any other code / timeout / rejection rejects. `sleep`, `now` and the guided-expiry timer come from the clock; `openUrlDetached` is `runner.openDetached` with the existing warning on error. Pure readers and constants stay module exports. `createMacSteamOfflineEnvDeps()` supplies the non-spawn members (lazy config/paths requires, as before). `__resetMacSteamOfflineForTests`, `defaultMacSteamOfflineDeps`, `spawnOpenDetached` are gone.
- `platform/openDetached.ts`: `spawnOpenDetached` and the spawn import deleted.
- `macSteamAdoption.ts`: `probeMacSteamPid({ runner }, timeoutMs)` on `runner.run` (no timer needed: the runner bounds it); `createRestartDeps({ clock, macSteamOffline, launchRunGameId })` replaces `defaultRestartDeps`; `restartMacSteamForAdoption(appId, deps)` requires full deps.
- Boot: `createSteamProcesses` builds `macSteamOffline`; bootstrap binds it into `SteamUser` after building steamProcesses and calls `steamProcesses.macSteamOffline.restoreMacSteamOnlineIfOwed('boot')` at the same step position.
- Shards: `platform.json` (childProcess + jestMock entries removed), `storeManagers.steam.json` (macSteamOffline/macSteamAdoption childProcess and macSteamOffline moduleState removed; macSteamOnlineDebt jestMock 4 -> 3). `pnpm backend-di-ceilings` PASS.

## Cascade edits

gameLaunch.ts / gameUninstall.ts / gameInstallDepot.ts (pass `{ runner }` to the probe; gameLaunch builds RestartDeps; gameLaunch.ts 998 lines), steamAuthFlowRegistration.ts (guided flows call `deps.steamProcesses.macSteamOffline`), user.ts, bootstrap.ts, steamProcesses.ts, testServices.ts. Test edits: macSteamOnlineDebt / macSteamOfflineWrap (harness), macSteamAdoption (scripted runner + fake clock), games, user, authSessionLifecycle, steamStartupKeyringDeferral (bind a macSteamOffline double), appShellFlows / bootstrap (partial module mock now overrides the instance's restore).

## user.ts call-time deps note

`SteamUser` has ten `acquireAuthenticated*` callers and six suites binding it. Threading the instance through every call was out of proportion, so the instance rides the existing `bindStores` slot (`SteamUserBoundDeps = SteamStoresDeps & { macSteamOffline? }`); no new static field was added. `releaseForShutdown()` keeps its signature, so `stdinEofRelease.ts` and the quit handler are unchanged.

## Deviations from Plan

1. **[Rule 3 - scope] stdinEofRelease.ts and its test unchanged.** With the instance in the bound slot, `SteamUser.releaseForShutdown()` still needs no argument. Ordering and call sites are identical (T-66.2-37 holds).
2. **[Rule 3] createRestartDeps signature.** Probe comes from `macSteamOffline.isSteamRunning` (same pgrep, now on the runner) instead of the drmLaunchSetup `isMacSteamRunning`; emit helpers stay `sendGameStatusUpdate` inside the builder rather than parameters. The probe timer in `probeMacSteamPid` was deleted rather than moved to the clock, since `timeoutMs` on `run` already bounds it.
3. **Test shape.** Wrap/debt suites keep their hand-driven clock via `testUtils/macSteamOfflineHarness.ts`, which adapts the scenario's `now`/`sleep`/`isSteamRunning`/opener to a runner and clock; new tests use scriptedRunner + fakeClock for the pgrep mapping, openDetached and two-instance isolation.
4. **Behavioural test change (WR-04 window).** `macSteamOnlineDebt` "a shutdown during the LogOff watch" previously relied on the restore's probe resolving in fewer microtask ticks than the wrap's shutdown-cut race, so the restore saw `goofflinePending > 0` and returned `restore-unconfirmed`. With the probe now a real runner call (as in production, where pgrep is real I/O) the wrap has already settled, so the restore returns `restored` and the wrap fires its own goonline. Production behaviour is unchanged; the test now pins the realistic ordering. The `goofflinePending > 0` branch in `runRestore` is no longer exercised by a test.
5. **testServices.** The default `steamProcesses.macSteamOffline` is inert (not unscripted) because every boot pays the owed goonline through it.
