# Phase 66.2 Plan 08: tools and vulkan on the runner Summary

tools/index.ts (winetricks streaming install, `wine --version`, `which`) and the vulkan helper probes now run through `deps.runner`; `which` is argv with no shell; execAsync/child_process are gone from both files.

## What changed

- **vulkan**: `createVulkan({ runner })` returns async `getInstanceVersion`, `anyGpuSupportsVersion`, `getNvngxPath`; probes use `timeoutMs: 10_000`; the two memos are closure state (moduleState 2 -> 0, childProcess entry deleted; shard is now `{}`). Failed/timed-out/non-zero probes map to the old "unknown" values.
- **tools**: `createDxvk` builds one `createVulkan` instance; `getDxvkUrl`/`getVkd3dUrl` take it and are async. `readWineVersionOutput(runner, ...)` runs `wine --version` with `WINEDEBUG=-all`, `replaceEnv`, 5 s, 16 KiB. `checkDependencies` runs `which <dep>` as argv (T-66.2-32). The winetricks install runs with `timeout: { none: true, reason }`, `resolveOn: 'exit'`, streaming `onStdout`/`onStderr`; Done is decided from `result.code`; a rejection takes the old spawn-error path.
- `execOptions`/`getShell` deleted from constants/others.ts; `execAsync` is now used only inside utils.ts.

## Notes

- **resolveOn 'exit' grace**: Done now follows the runner's 250 ms drain grace instead of the old 2 s 'exit' fallback timer.
- **D-66.2-03 deferral**: `installingComponent`, `catalogCache` and `scriptMetadataCache` stay module-level (tools.json moduleState unchanged at 3); 66.3 owns them. The `extractFiles` call was not touched.
- Cancellation: the install passes no `signal` (the old code had none; the queue cancels between verbs).

## Deviations from Plan

**2. [Rule 3 - Blocking] New `testUtils/drivableRunner.ts` instead of scripted-runner-only tests.** The winetricks suites drive stdout/stderr and exit by hand across fake timers (output after exit, a hold across ticks), which `createScriptedRunner` steps cannot express. The scripted runner remains the default elsewhere; the helper is small and used by three suites.

**3. [Rule 3] wineVersionProbe.test.ts not created; winetricksInstallPathInvariant, wineToolsFlows and runnerMiscFlows tests unchanged.** A new test file needing `jest.mock('backend/logger')` would be a new jestMock census entry (the ratchet refuses it), and the probe is already covered in winetricksListAvailable.test.ts, where the argv/env/timeout/buffer cases were rewritten and non-zero/timeout/truncated cases added. The other three files had no child_process/execAsync mocks (only comments), so nothing to remove; sidecar-tests-wineTools.json is unchanged.

**4. Commits:** Tasks 1 and 2 are one commit (aaf234cfc) because vulkan's old exports are consumed by tools/index.ts, so neither compiles alone; task 3 is cd9e94def.
