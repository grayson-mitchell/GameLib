### WR-01: dependency-cruiser's npm spawn-package arm never matches

**Files modified:** `.dependency-cruiser.cjs`, `eslint.config.mjs`, `meta/__tests__/boundaryGates.test.ts`
**Commit:** 4e8377714
**Applied fix:**

- Added a `(^|/)node_modules/(execa|cross-spawn|shelljs|node-pty)/` arm to `no-child-process-outside-runner`.
  - The bare-name arm stays: `shelljs` and `node-pty` are not installed, and depcruise reports them as `couldNotResolve` with the bare specifier.
  - A live probe confirmed the gap. With the old rule, `execa` and `cross-spawn` resolved to `node_modules/<pkg>/index.js` and passed. Only the two uninstalled packages fired. With the new rule, all four fire.
- Added the four package names to the backend ESLint `no-restricted-imports` paths. `child_process`, `node:child_process`, `createRequire` and the electron `ipcMain`/`ipcRenderer` restriction are unchanged. A probe confirmed both the new names and the electron entry fire.
- Added two seeded boundaryGates tests: installed packages and uninstalled packages plus `child_process`. The installed-package test fails against the old rule.

### WR-03: Factory-default wine name no longer matches the wine list

**Files modified:** `src/frontend/screens/Settings/components/wineSelection.ts` (new), `src/frontend/screens/Settings/components/__tests__/wineSelection.test.ts` (new), `src/frontend/screens/Settings/components/WineVersionSelector.tsx`, `src/frontend/screens/Library/components/InstallModal/WineSelector/index.tsx`
**Commit:** 507ac05c1
**Status:** fixed: requires human verification (UI selection behaviour)
**Applied fix:**

- Both selectors now key their `MenuItem` values and `onChange` lookup by `bin`, through a shared helper (`wineOptionValue` / `findWineByOptionValue`).
- `WineVersionSelector` already re-synced the stored value by `bin` on mount, so the global selector was mostly self-healing.
- The InstallModal `WineSelector` seeds from `globalConfig.wineVersion` (name `wine`) with no name resync. It showed no selected option on a fresh Linux profile.
- The unit test covers the fresh-profile case (`{bin:/usr/bin/wine, name:'wine'}` vs list `wine-9.0`), round-trip and unknown values. It also has a source guard against a by-name `value=` in either selector.
- Not addressed: the persisted name stays `wine` until a selector re-syncs it. So `InstalledInfo` and launch log lines can still show "wine" instead of the version. Fixing that needs the boot-time rewrite the review describes.
