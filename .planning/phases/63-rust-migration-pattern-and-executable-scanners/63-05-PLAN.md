<interfaces>
Op result shapes:
- scan_steam_api_imports `{exePath, appId}` → one of
  - `{"status":"ok","arch":"x86"|"x64"|"none","dll":string|null,"symbols":[...],"delaySymbols"?:[...],"diagnostics":[{level,message}]}`
  - `{"status":"error","error":string,"diagnostics":[...]}`

  `delaySymbols` is ABSENT when there are no steam_api delay imports (`#[serde(skip_serializing_if = "Option::is_none")]`). The status tag uses `#[serde(tag = "status", rename_all = "lowercase")]`.
- Rust error strings:
  - `Invalid appId: "<appId>"` (same as TS);
  - `not a parseable PE: "<exePath>"` where TS said `objdump exited with code N for "<exePath>"`;
  - `could not read "<exePath>": <io>` where TS said `Failed to run objdump: ...`;
  - `conflicting steam_api.dll and steam_api64.dll import headings` (byte-identical to TS CONFLICTING_HEADINGS_ERROR).

  The normaliser (63-03) maps the two unreadable-PE wordings together; nothing else is normalised.
- Diagnostic message texts: reuse the TS strings from steamApiImportsTs, replacing the word
  "objdump" with "PE import scan" where the TS text names the objdump process (e.g. "objdump
  exited with code N for followed DLL" becomes "PE import scan could not parse followed DLL").
  Diagnostics are not diffed.
- scan_winemac_metal_exports `{wineBundlePath}` → `{"ok":true}` | `{"ok":false,"winemacPath","reason","missing":[...]}` with reasons `winemac.so not found`, `could not read winemac.so: <io>`, `winemac.so is not a parseable x86_64 Mach-O`, `winemac.so lacks the macdrv metal-view exports`. `missing` lists all four symbols except in the lacks-exports case, where it lists the absent ones in DXMT_REQUIRED_MACDRV_SYMBOLS order.
</interfaces>

    - steam_api_import_table(r) walks the import descriptors and returns { dll, arch, symbols, conflict } where a descriptor whose name matches `steam_api.dll` / `steam_api64.dll` case-insensitively sets dll to the canonical lowercase name and arch x86/x64; symbols are hint/name entries in thunk order, NOT deduplicated, ordinal-only thunks skipped; a repeated steam_api descriptor appends its symbols; seeing both names sets conflict
    - the INT/ILT walk uses OriginalFirstThunk, falling back to FirstThunk when it is 0; thunks are u32 (PE32) / u64 (PE32+); the ordinal flag is bit 31 / 63; the walk stops at a zero thunk or at 4096

    - an appId of "1 2" / "../x" / "" gives the Invalid appId error, and a test proves no file was opened (use a path that would panic a test reader, or assert on a non-existent path)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| game folder → closure walk | DLL names come from untrusted import tables and are used to build filesystem paths |
| appId → scan | appId originates from Steam data |
| winemac.so → Mach-O parser | GameLib-installed Wine file, treated as untrusted bytes anyway |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-63-19 | Tampering / Information disclosure | closure.rs path building from import names | mitigate | Names with `/`, `\` or `..` refused; same-dir lexical containment; system DLL skip; tests for each |
| T-63-20 | Denial of service | closure fan-out | mitigate | Depth <= 2 and <= 32 DLLs examined (ported constants); tests at the boundaries |
| T-63-21 | Tampering | appId | mitigate | Digits-only check before any open (T-24-06); tests for `"1 2"`, `"../x"`, `""` |
| T-63-22 | Spoofing (wrong arch shim) | conflict detection | mitigate | T-51-06: both headings, closure-arch and delay-arch mismatches → typed error, never a guess |
| T-63-23 | Denial of service | Mach-O parse | mitigate | Bounds-checked symtab/strtab; truncation loop includes Mach-O bytes |
</threat_model>
