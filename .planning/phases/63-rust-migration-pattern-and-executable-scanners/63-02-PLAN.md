<objective>
Define the TypeScript side of the scanner contract and wrap the existing TS scanners as
path-based oracles with no backend imports. Their results have the Rust ops' JSON shape exactly,
so the `ts` flag branch, the committed goldens (63-03) and the local sweep (63-10) all compare the
same TS code against Rust. Add the per-scanner flag module.

Purpose: D-11 needs a TS path to fall back to, and D-12 needs a TS oracle. Making both the same
function, with the Rust op's argument and result shape, means a zero-diff sweep proves exactly
what the app runs.
Output: `src/backend/scanners/` (contracts, oracles, flag), and importScan.ts refactored to delegate
with no change in behaviour.

**Recorded decisions (veto-able):**
- **Final op list (D-08).** The ops are `scan_contained_real`, `scan_steamstub_section`,
  `scan_steam_drm`, `scan_pe_imported_dlls`, `scan_pe_delay_imports`, `scan_steam_api_imports` and
  `scan_winemac_metal_exports`. `scan_pe_delay_imports` is **CLI-only**: its only caller after D-06
  is the census, because importScan's own delay read moves inside the Rust closure op. So it is a
  library and CLI op but not a rustInvoke channel; an allow-listed channel with no app caller
  would be dead surface.
- **`readPeMachineArch` is not ported** (open decision 3). It has no production caller. It dies
  with `peSteamDrm.ts` in 63-14.
- **The flag lives in an env var plus a defaults table, not AppSettings** (RESEARCH A4 allowed
  another dev-only store). An AppSettings key would need GlobalConfig plumbing inside pure scanner
  code and a settings migration to delete it again. The env is inherited by the sidecar from
  `pnpm tauri:dev`, because `sidecar.rs` sets extra vars and never clears the env.
- **Scanner names and ops.**
  - `peSections` covers `scan_steamstub_section`.
  - `peSteamDrm` covers `scan_steam_drm`, `scan_pe_imported_dlls` and `scan_pe_delay_imports`.
  - `importScan` covers `scan_steam_api_imports`.
  - `drmScanExe` covers `scan_contained_real`.
  - `machoExports` covers `scan_winemac_metal_exports`.
</objective>
