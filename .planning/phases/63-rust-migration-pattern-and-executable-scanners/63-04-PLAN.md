<objective>
Port the PE byte parsing (peSections.ts and the three readers in peSteamDrm.ts) to Rust as four
`gamelib-scan` ops: `scan_steamstub_section`, `scan_steam_drm`, `scan_pe_imported_dlls` and
`scan_pe_delay_imports`. The last one is CLI-only (see 63-02's recorded op list).

Purpose: the core of the native PE parsing for D-05. 63-05 builds the import-symbol walker and
the closure on top of these headers.
Output: the `pe/` module tree, with unit tests that run on in-memory bytes.

**Recorded decisions (veto-able):**
- Readers are hand-rolled over `RangeRead`; no `object`/`goblin`/`pelite` crate. The reasons are
  quirk parity (D-07), bounded ranged reads (D-10) and the lockfile pin (RESEARCH "Rust parsing
  approach").
- `readPeMachineArch` is NOT ported (open decision 3). It has no production caller.
</objective>

<interfaces>
Result JSON shapes (camelCase; mirror src/backend/scanners/scanTypes.ts from 63-02):
- scan_steamstub_section `{exePath}` → `{ drmWrapper: "steamstub" | "none" | null, readError: string | null }`; an open/read error gives drmWrapper null and the io error text in readError.
- scan_steam_drm `{exePath}` → `{ parsed: bool, cegMarkers: [string], hasBindSection: bool, readError: string | null }`; an open error gives parsed false, [] and false, with readError set; a short read gives parsed false and readError null.
- scan_pe_imported_dlls `{exePath}` → `{ names: [string] | null, readError }`.
- scan_pe_delay_imports `{exePath}` → `{ parsed, dll: "steam_api.dll" | "steam_api64.dll" | null, arch: "x86" | "x64" | "none", symbols: [string], conflict: bool, readError }`.
From 63-01: `RangeRead` (`byte_len`, `read_at` → Option), `FileReader::open`, `SliceReader::new`, `read_prefix(path, max)`.
</interfaces>
