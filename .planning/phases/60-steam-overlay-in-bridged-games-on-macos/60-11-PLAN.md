<objective>
Build the instrument that diagnoses G1 before anything is fixed. G1: in the two Unity titles on the
CrossOver overlay runner, Shift+Tab opens the overlay but in gameplay the mouse still turns the
camera and no cursor appears. The same title on the Wine-Staging fallback engine works (UAT item 9),
and so does Unreal on the same runner (item 3). The UAT lead is that nothing calls
`np_overlay_shim_set_active` (RESEARCH Pitfall 9 / A3). But that function only drops NSEvents in
`-[WineApplication sendEvent:]` (overlay_shim.m L992-1030). It does not release Wine's cursor clip
or unhide the cursor, so the lead alone does not explain "no cursor". Both winemac builds carry
`WineEventTapClipCursorHandler` and `WineConfinementClipCursorHandler`, plus the `Mac Driver`
config keys `UseConfinementCursorClipping` and `CursorClippingLocksWindows`. Mac Steam's
`gameoverlayrenderer.dylib` imports `CGAssociateMouseAndMouseCursorPosition`, `CGWarpMouseCursorPosition`,
`CGDisplayHideCursor`/`CGDisplayShowCursor`, `CGSForceShowCursor` and `NSCursor`. The probe records which
image calls which cursor API and when, so the 60-12 live run can tell the hypotheses apart.

Purpose: a fix for G1 is chosen from evidence, not guessed.
Output: a universal `overlay_input_probe.dylib`, a smoke test proving it logs, and launch wiring behind
a dev-only env flag.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sidecar process env -> launch env | A dev-only env flag decides whether an extra dylib is injected into the game |
| probe dylib -> game process | GameLib code runs inside a Wine game process |
| probe log file | written inside the user's app folder |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-11-01 | Tampering | probe log path (symlink swap) | mitigate | open with O_NOFOLLOW + O_CREAT 0600 inside a 0700 trace root; path passes safePath (absolute, no quote/colon/control) |
| T-60-11-02 | Elevation of Privilege | DYLD_INSERT of probe | mitigate | only when GAMELIB_OVERLAY_INPUT_PROBE is exactly '1' in the sidecar's own env (not reachable from renderer IPC); dylib checked with lstat isFile (no symlink follow), built from in-repo source, ad hoc signed |
| T-60-11-03 | Denial of Service | probe log growth / sampler | mitigate | 4 MiB cap, warp rate limit, sampler bounded to 120 s |
| T-60-11-04 | Information Disclosure | probe log contents | accept | records cursor API calls, coordinates and image basenames only; no credentials; launch-log line redacts home to ~ |
| T-60-11-05 | Denial of Service | sidecar exit contract | accept | no new timers or watchers in the sidecar (only an fs.lstat/mkdir per launch); all probe timers live in the game process |
</threat_model>
