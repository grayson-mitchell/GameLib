Build the overlay-only CrossOver clone for TCP-mode games (D-04). It is an unpatched clone with
both loaders re-signed, attempted on any CrossOver version with no allowlist (D-06), and it fails
open (D-08).

`CX_ENV`, which only works on a runner whose two loaders allow dyld env. The user's CrossOver is
never modified in place.

</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installed CrossOver -> overlay clone | Stock binaries are copied and re-signed with dyld env allowed |
| clone on disk -> launch | The clone is trusted after the per-launch verify |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-05-01 | Elevation of privilege | re-signed loaders (dyld env + library validation off) | accept | Same class DRM mode accepts (RESEARCH Security Domain): 0700 root, inner SharedSupport/CrossOver only, per-launch re-hash of clone and source loaders |
| T-60-05-02 | Tampering | planted file or symlink in overlay runners root | mitigate | lstat directory checks, 0700 root, 'wx' marker, safeRemove/removeInside containment, partial dir + atomic rename |
| T-60-05-03 | Tampering | stale clone after same-build reinstall | mitigate | The marker pins source loader hashes; a mismatch re-clones |
| T-60-05-04 | Denial of service | re-clone while the game runs | mitigate | isPathInUse guard returns a 'clone' error ("quit the game and retry"); the launch falls back to stock (D-08) |
| T-60-05-05 | Information disclosure | cp/codesign/xattr/plutil/ps spawns | mitigate | RunTool/defaultRunTool with createFakeHomeProfile().childEnv() |
| T-60-05-06 | Tampering | unexpected entitlement values | mitigate | parseEntitlementKeys returns null on non-`<true/>`, which becomes a 'resign' error and fails open |
</threat_model>
