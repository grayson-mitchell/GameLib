<objective>
Close **D-UAT-24-05 (MAJOR)** at its root primitive: the bridge install writes a correct `StateFlags=4` `appmanifest_<appId>.acf` INTO the bridge bottle (`GameLibSteamBridge/.../steamapps`), confirmed on disk, but the post-install readiness poll looks in the wrong location. `AcfSource` today is only `'native' | 'bottle'`; `'bottle'` hardcodes the Phase 17 `GameLibSteam` bottle (`getBottleSteamappsRoot()` → `getSteamBottleSettings()`). The bridge install has no source that points at the bridge bottle, so `pollInstallOnce` never sees the manifest it just wrote, times out after the grace window ("no manifest detected"), and the badge reverts to Install.

This plan adds the missing **`'bridge'` `AcfSource`** and a `getBridgeBottleSteamappsRoot()` helper resolving the dedicated bridge bottle's steamapps dir, and threads `'bridge'` through `readAcfState` / `pollInstallOnce` / `startInstallPolling` so a poll rooted at the bridge bottle detects the StateFlags=4 ACF. This is the self-contained, unit-testable primitive; 24-13 wires `installBridgeGame` to pass `pollerSource: 'bridge'`.

Purpose: give the bridge install a readiness poll that reads the manifest it actually wrote — so a completed bridge install stays "installed" instead of reverting.
Output: `AcfSource` 'bridge' + bridge-bottle steamapps root helper + threaded source, with unit tests.
</objective>
