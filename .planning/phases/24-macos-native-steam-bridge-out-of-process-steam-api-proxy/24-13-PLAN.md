<objective>
Close the remaining games.ts bridge-integration defects that keep Gates 2–4 (R5/R6) blocked. Depends on 24-11 (shim now actually placed) and 24-12 (`'bridge'` AcfSource exists).

**D-UAT-24-05 wiring:** `installBridgeGame` calls `installDepotDownload(..., { pollerSource: 'bottle' })`, which starts a poll rooted at the Phase 17 `GameLibSteam` bottle — it never sees the bridge-bottle ACF and times out. Switch to `pollerSource: 'bridge'` (24-12) so the poll reads the manifest the bridge install actually wrote.

**D-UAT-24-03 cascade (a) — sticky bridge-failed flag:** a single recoverable failure calls `markBridgeFailedThisSession(appId)`; `isBridgeEligible()` consults that set, so BOTH install and launch skip the bridge for the rest of the session (routing the retry down the native/bottled path). Add `clearBridgeFailedThisSession(appId)` and call it on a successful bridge (re)install so the session un-poisons.

**D-UAT-24-03 cascade (b) — wrong install record:** because the sticky flag forced the retry down the native fallback, `install.install_path` pointed at `GameLibSteam` while files landed in `GameLibSteamBridge`. Clearing the flag keeps routing on the bridge (whose `markBridgeGameInstalled` already records the bridge bottle root); add a test asserting the recorded path is under the bridge bottle.

**D-UAT-24-02 (a)+(b) — launch no-op for a non-bridge "installed" game:** a bridge-eligible game can be `is_installed:true` via a native 32-bit Mac build or an old bottle, so the bridge bottle + Windows depot + placed shim never exist. `launchBridgeGame` still resolves a bridge-bottle exe path and fire-and-forgets `runWineCommand({wait:false})` at a NON-existent exe in a NON-existent bottle → wine exits instantly, empty launch.log, button reverts. Add an on-disk existence gate: if the resolved exe (or the bridge bottle) is absent, surface `steamBridgeSetupRequired` (D-05, `fallbackAvailable:true`) and return false — never fire wine at a path that isn't there, never silently no-op.

Purpose: turn the now-placed shim + correctly-polled install into a real, non-reverting install and a launch that only ever runs a real exe.
Output: games.ts install-side + launch-side fixes + `clearBridgeFailedThisSession` + tests.
</objective>
