<objective>
Build the D-03 shared-helper lifecycle and the D-06 readiness/health signal. `ensureBridgeHelperReady()` lazily spawns ONE shared, long-lived helper (from the bundled `steamBridgeHelperPath`) on first bridge launch, holds the `ChildProcess` handle module-scoped, and reuses it for every bridge game until GameLib quits. Because bottle launches are fire-and-forget (`runWineCommand({ wait: false })`), the bridge needs an actual readiness signal — helper up + loopback channel reachable (PING/PONG) + init succeeded against a live session (WHOAMI) — so failures are observable, not assumed-success (D-06). Modeled on `ensureSteamClientReady()`'s status-union shape + `raiseFrontmostBottledProcess`'s bounded-poll mechanics.

Also add `steamBridgeHelperPath` to `paths.ts` (the bundled arm64 binary location, consumed here and produced by 24-07's packaging).

Purpose: the observable-failure seam R7's clean fallback depends on.
Output: `helperProcess.ts` (`ensureBridgeHelperReady`, spawn lifecycle) + `steamBridgeHelperPath` + tests.
</objective>
