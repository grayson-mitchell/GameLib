<objective>
Build R3: automatic per-bottle shim generation/placement. `importScan.ts` enumerates a game's imported `steam_api` symbols by shelling to `/usr/bin/objdump --private-headers <exe>` (argv-form; parse in JS, do not shell to grep). `shimGenerate.ts` orchestrates selecting/placing the correct `steam_api.dll` shim (built from 24-01's generated source) next to the game's own `.exe` in the bridge bottle — automatically, as part of install/setup, with no manual copy step. Placement is idempotent and guarded, following `provisionBottle`'s sanitize-then-place shape.

A drop-in shim must export EVERY symbol the game imports (Constraint) or the game will not load — the objdump-derived set is the contract.

Purpose: the per-game bottle-setup hook that makes an allowlisted game bridge-ready.
Output: `importScan.ts` + `shimGenerate.ts` + tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installed game .exe path → objdump | Untrusted install-directory path fed to a subprocess |
| generated shim export set → game load | Shim must export exactly the game's imports (attacker-influenceable if unbounded) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-06 | Tampering/Elevation | objdump/copy path handling | mitigate | argv-form `spawnAsync` only (never shell string); `sanitizeBottleName` + `NUMERIC_APP_ID` guards before any path/argv construction |
| T-24-04 | Tampering | shim export set | mitigate | Placement validates the built `.def` export set covers the objdump-derived import set — export exactly what the game imports, no broader attacker-influenced surface |
</threat_model>
