<objective>
Close the still-open CORE of **D-UAT-24-02**: for a bridge-eligible Steam title, a NON-bridge install location shadows the bridge and dead-ends the game.

**D-UAT-24-02 (24-UAT.md, confirmed on hardware 2026-07-21):** a bridge-eligible Windows-only title that is "installed" via a NON-bridge path — a native macOS 32-bit build and/or the Phase 17 `GameLibSteam` bottle — is currently counted as `is_installed:true` by the library install-state derivation (24-16's `native ?? bottle ?? bridge` precedence: native/Phase-17-bottle wins). The game therefore shows a **Play** button; Play routes to the bridge (`isBridgeEligible()` in games.ts is true); the bridge bottle (`GameLibSteamBridge`) does not contain the game; the launch/existence-gate refuses with "steam bridge not available." Hardware evidence: **Avernum 6 (206060)** lives only in the Phase 17 bottle, **Hoard (63000)** lives in native Mac + the Phase 17 bottle; neither is in the bridge bottle; both dead-end at the dialog. **Avernum 5 (206040)** worked only because it had no competing non-bridge install.

**Root cause:** the install-state model (24-16: native wins, then Phase 17 bottle, then bridge) and the bridge LAUNCH target disagree. For a bridge-eligible title the two must agree: install-state must be authoritative to the bridge bottle — a native/Phase-17-bottle copy must NOT satisfy `is_installed` for that appId.

**Fix:** in the install-state derivation that 24-16 touched (`refresh()` Step 3 and `refreshInstallState()` in `library.ts`), make the selection **bridge-authoritative for bridge-eligible titles**: if an appId is bridge-eligible, use ONLY `bridgeInstalledData` (and source `'bridge'`) for its is_installed/platform — ignore the native and Phase 17 bottle maps for that appId. Non-bridge-eligible titles keep today's `native ?? bottle ?? bridge` behavior unchanged. Bridge-eligibility is determined the SAME way it is composed in games.ts (`isBridgeEligible()` = `bridgeAllowlist.has(appId)` + the `isBottleEligible()` mac/arch gate), derived inside library.ts from `bridgeAllowlist` + `steamMetadataStore` so the existing games.ts↔library.ts import cycle is not deepened.

**Expected outcome:** Avernum 6 / Hoard (NOT in the bridge bottle) become `is_installed:false` → show Install → `installBridgeGame` runs → Play launches through the bridge. Avernum 5 (in the bridge bottle) stays installed. A native / Phase-17-bottle-only copy of a bridge-eligible game no longer shadows the bridge.

Purpose: make install-state authoritative to the bridge bottle for bridge-eligible titles so eligible games reach the bridge install→launch path instead of dead-ending on a non-bridge install.
Output: library.ts (isBridgeAuthoritativeForInstallState helper + bridge-authoritative selection in refresh() + refreshInstallState()) + tests.
</objective>
