<objective>
Close Gap 2 (Phase 30 UAT Test 8): under Tauri the Settings screen is unreachable (permanent spinner).

Root cause (already diagnosed — do NOT re-diagnose, see `.planning/debug/settings-unreachable-tauri.md`):
both render gates at `Settings/index.tsx:79` (`if (!currentConfig || !contextValues) return <UpdateComponent/>`)
depend on `window.api.requestAppSettings()` — an invoke channel Phase 30 deliberately left unported
(`30-PORTED-CHANNELS.md:54`, whose rationale only considered `DownloadDialog` and missed that the
Settings screen AND `useSettingsContext` both call it at mount). Under Tauri it rejects with
`UNPORTED_CHANNEL_MARKER`; neither call site (`Settings/index.tsx:65-71`, `useSettingsContext.ts:31-38`)
catches it, so `currentConfig` and `contextValues` stay null forever. Two independent paths hit the same
channel, so patching one alone still blanks the route. Test 8's real subject (openDialog file-vs-folder
mode, WR-02/WR-01) is blocked behind this and stays unverified until Settings renders.

Remedy = the COMBINATION (both, with rationale):
- (a) Port `requestAppSettings` + `requestGameSettings` onto the sidecar. These are Phase 31's
  settings-config cluster, but the UAT proves Settings is unreachable until they land. This is a
  bounded, minimal slice: two READ handlers calling real backend config already reachable in the
  sidecar's import graph, zero new Rust, mirroring the established `*FlowRegistration.ts` pattern. It
  is what makes Settings functional (real values), not just reachable. The WRITE side (`setSetting`,
  `writeConfig`) and the remaining four DownloadDialog config channels stay Phase 31.
- (b) Harden both frontend call sites with try/catch + a usable default-config fallback. This belongs
  regardless (defense-in-depth, SEAM Invariant B: an unported/failed channel must degrade non-fatally
  at the UI, not blank a route), and protects Settings against any future config channel failing.

Purpose: make Settings reachable and functional under Tauri, and make the route resilient to a failed
config load.
Output: new `settingsFlowRegistration.ts` + handlers wiring + sidecar test; hardened Settings call
sites + frontend test; updated 30-PORTED-CHANNELS.md.
</objective>
