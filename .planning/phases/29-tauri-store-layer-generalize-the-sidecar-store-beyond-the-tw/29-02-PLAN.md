<objective>
Make every `StoreStructure` store reachable from a generic, name-keyed lookup inside
the sidecar process: extract the three heavy declaration sites into thin modules
(D-15) and give `TypeCheckedStoreBackend` a self-registering instance registry.

Purpose: a generalized `storeSet(storeName, key, value)` handler cannot import stores
by name one by one, and it must never re-derive `{cwd, name}` from the
`ValidStoreName` string — `TypeCheckedStoreBackend`'s constructor drops its `name`
parameter entirely, so the logical store name is NOT the filename (29-RESEARCH
Pitfall 4). The registry is the only correct lookup.

Output: three new thin `electronStores.ts` modules, three mechanical host-module
edits, and `storeRegistry`/`getRegisteredStore()` in `src/backend/electron_store.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer-supplied store name → sidecar store lookup | the string that will key `getRegisteredStore()` in plan 29-05 comes from the renderer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-05 | Tampering | name-keyed store dispatch | mitigate | The registry is a closed map of ALREADY-CONSTRUCTED instances. An unknown/attacker-chosen name resolves to `undefined` — it can never cause a store to be constructed from attacker-supplied `cwd`/`name`, which is the T-27-03 path-tampering surface. The registry deliberately exposes no constructor. |
| T-29-06 | Information Disclosure | `getRegisteredStoreOptions()` | accept | Returns only `{cwd, name}` construction metadata already hardcoded in source; no secret material. Sidecar-internal, never serialized to the renderer (the snapshot handlers in 29-04 return values, not options). |
| T-29-07 | Tampering | D-15 host-module rewire | mitigate | Extractions must be mechanical re-exports; acceptance criteria require `npx jest src/backend` green and `npx tsc --noEmit` clean so an accidental behavior change in the shipped Electron path is caught (REQ-29-07). |
| T-29-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — zero new packages this phase (29-RESEARCH.md § Package Legitimacy Audit). |
