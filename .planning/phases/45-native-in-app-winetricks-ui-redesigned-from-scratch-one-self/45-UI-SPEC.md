## Spacing Scale

This project's existing spacing system (`styles/_spacing.scss`, em-based @ 16px root). Reused
verbatim — not a parallel scale. Every value below is a multiple of 4px **except** `--space-2xs`,
which is a declared, justified exception (see immediately below the table — not a baseline grid
step):

| Token | Value (px @ 16px root) | Usage in this phase |
|-------|-------------------------|----------------------|
| `--space-3xs` | 4px | Checkbox-to-label gap, badge internal padding |
| `--space-xs` | 8px | Gap between a row's trailing metadata and its checkbox/icon slot |
| `--space-sm` | 12px | Gap between the three tiers (Suggested / task groups / Everything else), row horizontal inset |
| `--space-md` | 16px | Banner-to-scroll-container gap, sticky bar internal padding |
| `--space-lg` | 24px | Vertical gap above the banner when present |

**Exceptions:**
- **`--space-2xs` (6px) — row internal vertical padding, group-header internal padding.** Not a
  4px-grid step; kept anyway, as a named exception, because it is the exact metric the shipped
  `FilterFacetGroup` / `FilterFocusRow` / `FilterCollectionList` components already use for this
  identical padding role (`src/frontend/components/UI/NavShell/components/FilterFacetGroup/index.scss`
  and siblings), and this tab's own Component carry-forward note (see Layout) commits to copying
  that pattern's *contract* — caret, badge, row padding — verbatim. Substituting `--space-xs` (8px)
  here would silently de-align this tab's row/group-header padding from the exact precedent it is
  modeled on, trading one grid nonconformance for a visual-parity regression against a component
  this spec explicitly says to match. `_spacing.scss` is a pre-existing, codebase-wide token several
  other shipped surfaces depend on at this exact value (`FilterChipRow`, `LibrarySignInNotice`,
  `SearchBar`, `HumbleExpiryToast`, among others) — it is not this phase's invention and not a value
  this phase can unilaterally change.
- Checkbox hit target: **44×44px** minimum (existing documented touch-target exception, carried
  forward from Phase 44's own `--space-2xs` note), even though the visual checkbox glyph itself is
  14×14px (matches `FilterFacetRow__box`'s shipped dimension) — the *clickable* row region is the
  full row height, not just the glyph.
- Row minimum height: **two-line rows** (Suggested, task groups — title + family sentence) get a
  fixed `min-height: 56px`; **one-line rows** (Everything else — title only, per D-08) get a fixed
  `min-height: 44px`. Not a spacing-scale value — a layout-stability decision, called out
  explicitly (see Layout, "no vertical shift on state swap").
- The per-task-group expanded body gets a bounded scroll window, `max-height: min(50vh, 320px)` —
  smaller than the 420px Phase 44 used for its whole browse region, because this tab's groups stack
  **inside** the single page scroll container (D-02), not inside a height-constrained modal; a
  group does not need to protect a sibling fixed-height log box the way Phase 44's category body
  did (P-7 does not recur here — there is exactly one scroll container, by design).

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (`--text-md`) | regular (400, `--regular`) | 1.5 | Row title (bold variant for two-line rows' title, see below), banner text, sticky-bar copy |
| Caption | 14px (`--text-sm`) | regular (400) | 1.4 | Family sentence beneath a row title, `publisher · year` trailing metadata, per-row phase word (`Downloading 42%`) |
| Label | 11px (`--text-xs`) | bold (700, `--bold`) | 1.2 | Section headers (`Suggested for this game`, task-group names, `Everything else (N)`) — uppercase, `0.1em` tracking, matching the shipped `FilterFacetGroup` header treatment verbatim |
| Heading | — | — | — | Not used — the tab's own label ("Winetricks") is a plain MUI `Tab`, inherited, unchanged; no new heading element is introduced inside the tab body |

Exactly **2 weights** (regular 400, bold 700) and **3 distinct new-content sizes** (11px/14px/16px)
— matches this project's established "3–4 sizes, 2 weights" ceiling (the same ceiling Phase 44's
spec held itself to).

Row title itself is **bold** on two-line rows (Suggested / task groups, where a family sentence
sits beneath it) so the title visually outranks its own caption; on one-line Everything else rows
the title is regular weight, since there is no caption beneath it competing for attention.

## Color

Scoped to this tab only, using existing per-theme custom properties. **No new tokens invented.**
Per CONTEXT.md's load-bearing token lesson (restated here because it is the single rule this
document cannot let drift): every one of Phase 44's nine contrast defects traced to a
`--navbar-*` or `--text-hover` token consumed on a surface with no guaranteed contrast —
**neither token is consumed anywhere on this surface,** full stop, even though the
`FilterFacetGroup` pattern this tab's disclosure groups visually imitate uses exactly that chain on
its own home surface (`.NavShell__tier2Portal`). This tab is not that surface.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--body-background` (inherited Settings-screen chrome, unchanged) | Tab body background |
| Secondary (30%) | `--input-background` | Section-header row background, sticky action bar, environment banner, expanded group body |
| Accent (10%) | `var(--accent, #0080ff)` — direct, no `--navbar-active`/`--navbar-accent` chain | See reserved-for list below |
| Destructive | not applicable this phase | D-09 hides every destructive/bottle-wiper verb; no uninstall affordance is exposed. If one is ever added, use `var(--danger, #cc3333)` / `var(--danger-hover, #a62b2b)`, never raw `--status-danger`. |

**Accent reserved for, and only for:**
1. The checkbox's checked-state fill/border (the surface's one selection signal — D-10's "a tick
   means exactly one thing").
2. The `Apply` button fill/label in the sticky bar (the primary CTA).
3. `:focus-visible` outline rings — `outline: 2px solid var(--accent, #0080ff)`, matching the rest
   of the app, including this exact fallback literal already shipped in `FilterFacetGroup`'s own
   focus-ring chain.
4. The per-row "Downloading NN%" progress fill, when rendered as a thin bar rather than text alone.
5. Task-group/Suggested-header hover and keyboard-focus text+caret color. **This is the one
   deliberate deviation from the `FilterFacetGroup` precedent this tab's groups otherwise copy**:
   that component's hover/focus color is `var(--navbar-active, var(--accent-overlay, var(--accent)))`,
   which is banned on this surface by the rule above. Use `var(--accent, #0080ff)` directly instead
   — it resolves in every theme block (unlike `--navbar-active`, declared in only 4 of 10+), so no
   fallback chain is needed, only the terminal hex literal.

**Non-accent semantic colors:**
- **Installed** row state: icon + text in `var(--success, #2ecc71)` — the theme-adaptive alias,
  never raw `--status-success`.
- **Install failed** row state: icon + text in `var(--danger, #cc3333)` — the theme-adaptive alias,
  never raw `--status-danger`. Per the project's own measured lesson, `--danger` itself can sit as
  low as 3.55:1 (under AA for text) in at least one shipped theme — pair it with the failure icon
  always, never ship the red text alone as the only signal (see Non-colour signal rule below).
- **Cached** badge (orthogonal modifier on an Available/Selected row — carried forward from the
  frozen `cachedTag` key, D-20): `var(--text-secondary, #a8aeaf)`, neutral, never accent.
- **Unchecked checkbox border**: `var(--neutral-05, #a8aeaf)`, not `--border-color` — per the
  project's own measured finding, `--border-color` resolves to an invisible ~1.08:1 grey in 10 of
  13 themes; `--neutral-05` is the global neutral-scale step Phase 44's own live sweep corrected to
  for this exact element (`FilterFacetRow__box`), unthemed so it holds in every theme, not just
  the one it was first measured in.
- **Environment banner** (D-16): deliberately **not** warning-colored. `--status-warning` is a raw,
  non-theme-adaptive token — the existing `HumbleExpiryToast` banner consumes it directly
  (`border-inline-start: var(--space-3xs) solid var(--status-warning)`), which is exactly the raw
  `--status-*` anti-pattern this project's own lesson warns against, and that banner is not a model
  to copy here. D-16 independently requires this banner to read as informational, "never styled as
  an error" — so rather than inventing a new theme-adaptive `--warning` alias (out of this phase's
  scope, and no such alias exists today), the banner uses the same neutral pair as its own
  background surface: `var(--input-background)` fill, `var(--text-secondary, #a8aeaf)` icon + text,
  `faCircleInfo` (not `faTriangleExclamation`, to avoid even a shape-level caution read). **(researcher
  discretion — flag for planner review if a dedicated adaptive warning alias is preferred instead;
  that would be new scope, not a token already in the system.)**

**Primary visual anchor.** At rest — before typing, expanding, or running anything — the first
accent-colored, actionable thing the eye should land on is the **checkbox column of the open
`Suggested for this game` group**, because that group is open by default and the curated-8
fallback guarantees it is never empty (D-06). The `Apply` button in the sticky bar is the second
anchor and stays visually quiet (not accent-filled) until at least one row is selected — see
Copywriting Contract and States below for the bar's rest-vs-armed treatment.

**Non-colour signal requirement.** Every state below pairs its color with an icon and a text
label — colour is never the only signal. This directly repeats Phase 44's own C-3 rule because the
measured reason for it (an accent/success/danger hue alone can sit under AA, or depend on a
same-hue background swap that reads differently per theme) is a property of this app's token
system, not of the surface Phase 44 happened to apply it to.

**Verification requirement (D-21, restated as a contract, not optional):** the live gate must
spot-check this tab in **at least one light theme (`nord-light`) and one dark theme** — Phase 44's
nine defects split 1 light-only / 1 dark-only among the measured ones, so a single-theme sweep
would have passed both and still shipped both. Every custom property this tab consumes carries a
terminal hex fallback (shown inline above); none is bare.

## Layout

**Placement (D-01).** A new `Winetricks` tab in the per-game Settings tab strip
(`GamesSettings/index.tsx`'s `<Tabs>`), added immediately **beside** `Wine`
(`showWineTab && !isCrossover`, mirroring the exact gate `<Tools />` uses today — D-03). Not a
modal, not a route. The tab's own label is a plain MUI `Tab`, no new heading inside the panel.

**Visibility (D-03).** Shown only when `!isDefault && !isWindows && runner && !isCrossover` — the
`Tools` card's own gate (`isDefault || isWindows || !runner`) plus the Wine tab's existing

(`<Winetricks onClose={...} runner={runner} />`) are deleted; `Winecfg` and `Run EXE` stay exactly
where they are on the `Tools` card.

**Tab body, top to bottom, inside **one** scroll container (D-02 — Phase 44's P-7 nested-scroll
trap must not recur, and here it structurally cannot: there is no modal, no separate fixed-height
log box competing with the list for the same vertical budget):**

- **Suggested for this game** is **not collapsible** — no disclosure caret, always rendered open,
  because D-06 guarantees it is never empty and it is this tab's one unconditional anchor. Inside
  it, game-specific signals (known-fixes, PCGamingWiki `direct3DVersions`) render first, in that
  order, then the curated 8 under the reused `Commonly needed` sub-heading; when no per-game signal
  exists (the common case), only the curated 8 render, under that same sub-heading, with no visible
  seam marking the fallback as a fallback.
- **The 5 task groups** (D-07's working names, locked in Copywriting Contract above) are
  **collapsed by default** **(researcher discretion** — CONTEXT.md does not pin their open/closed
  state explicitly; collapsed-by-default matches the contrast the roadmap draws between the open
  Suggested tier and the collapsed `Everything else` tier, and matches Phase 44's own category
  convention for the same "curated-open, everything-else-closed" novice-first shape). Each header
  is a real `<button aria-expanded>` (the `FilterFacetGroup` *contract*, not the component instance
  — see Component carry-forward note below), showing its member count exactly like
  `FilterFacetGroup`'s own badge idiom, caret rotating on expand/collapse.
- **Everything else** is collapsed by default and holds the long tail with search
  (`searchPlaceholder`, frozen key). **(researcher discretion** — placement and threshold were
  explicitly left open by CONTEXT.md): the search field sits at the top of this group's own
  expanded body, `position: sticky; top: 0;` within that body's scroll window (same sticky-search
  idiom Phase 44 used), and filters **only** this group's flat list, not the task groups or
  Suggested — task groups are curated shortcut views; search is the long-tail's own recovery
  mechanism, and mixing the two would mean a search hit silently reordering or duplicating into an
  already-visible curated row. Threshold is **≥2 characters**, carried forward unchanged from Phase
  44's own deliberate anti-noise choice for this same 500+-row catalog.
- **Verbs appear in both a task group and `Everything else`** (D-07 — groups are shortcut views,
  not a partition); a verb in the curated-8/game-specific set also still appears in its task group
  and in `Everything else`. No verb is ever shown twice **selected** independently — selection
  state is keyed by verb, shared across every place that verb's row renders.
- **Component carry-forward note.** The task-group and Suggested-group headers follow
  `FilterFacetGroup`'s shipped *contract* (caret rotation, uppercase bold-tracked label, tabular-nums
  count badge, `--neutral-05` unchecked-equivalent border fix) but are declared under this tab's
  **own** CSS scope — not literally imported from `NavShell/components/FilterFacetGroup`, whose
  styling is selector-scoped to `.NavShell__tier2Portal` and consumes the `--navbar-*` chain this
  surface is banned from using (see Color). Reusing the *pattern* is right; reusing the *instance*
  across an unrelated ancestor scope is the exact cross-context CSS reuse this codebase has already
  been burned by twice (`Dropdown` styling its panel's contents from a different consumer;
  `34.10`'s unscoped `.MuiTabs-root` leak) — restated here because it is the same risk class, not a
  new one.
- **No vertical shift on state swap.** Both row templates (two-line, one-line) get a **fixed row
  height** (56px / 44px respectively, see Spacing exceptions) and every one of a row's possible
  trailing-slot treatments (checkbox, checked checkbox, disabled/queued checkbox, spinner+phase
  word, success icon+"Installed", danger icon+"Install failed"+Retry) shares the **same**
  line-height and vertical padding within that fixed height — directly porting Phase 44's own
  lesson that an Installing→Installed swap which is not metrically identical shifts every row below
  it at the exact instant a user might be acting on one of them. This applies regardless of this
  phase's different trigger (checkbox slot swap, not a button swap) — the hazard class is
  unchanged.
- `min-width: 0` on every flex row and every group body, stated explicitly per this codebase's own
  standing "a flex child overflows its container without it" trap.

## Interaction Contract

**1. The task-group/Suggested headers are never a `<div onClick>`.** Each is a real `<button
aria-expanded>` (or the shared disclosure primitive this tab defines following the
`FilterFacetGroup` contract) — carried forward from Phase 44's own §4, unchanged, because the
underlying reason (this codebase has already paid for the `<li onClick>` mistake once, in
`LibrarySearchBar`) is a property of the codebase, not of the surface that rule was first written
for.

**2. Checkbox and `Apply`/`Retry`/`Cancel remaining` clicks use mousedown-capture with a
`suppressNextClick` guard**, exactly the technique the `winetricksInstallMouseRace.test.tsx` test
(D-04 — ported, not deleted) encodes. The row-remount mechanism that originally motivated this
technique in Phase 44 does not exist in the same shape here (checkboxes replace per-row buttons,
and D-18 keeps the tab mounted across navigation rather than remounting on install completion), but
the general mousedown→mouseup target-drift hazard this technique guards against is independent of
that mechanism and is free to keep — restated, not re-derived.

**3. Selection is never read from search-box state.** Exactly like Phase 44's §3 (the
"Install is always a specific row's action" rule), `Apply` always acts on the set of verbs the user
explicitly ticked, keyed by verb string, never on whatever is currently filtered into view — a
verb ticked while `Everything else` was expanded and searched stays selected after the search is
cleared or the group is collapsed again.

**4. Everything else's search never resurrects the `SearchBar` suggestions overlay.** If this
tab's `Everything else` search reuses `<SearchBar>` for its input chrome, it must pass no
`suggestionsListItems` (or leave it `undefined`) so `.autoComplete` — a `display: none` except
`&:focus-within` overlay — never renders; the results list is an always-mounted sibling below the
input, independent of focus state, exactly as Phase 44's §1 established and as the still-open Half
B of the 2026-08-26 `SearchBar`/`LibrarySearchBar` todo makes clear is not yet globally fixed.

**5. A run outlives navigation without any modal interruption (D-18).** Switching tabs or leaving
Settings neither warns nor cancels the in-flight queue. On return, the tab rebuilds every row's
state from the live install events plus a fresh `winetricksListInstalled` read — no state is
assumed to have survived in memory. There is no dialog, toast, or confirmation anywhere in this
flow; the only outside-the-tab signal is the existing game-page `label.winetricks` status, reused
unchanged.

**6. `Cancel remaining` finishes the in-flight verb** (CONTEXT.md's stated default for this
discretion item) rather than killing it mid-install — it only drops verbs that have not yet
started. The button is disabled (not hidden) for the brief window after the in-flight verb's own
completion event but before the next queued verb's start event, so there is never a moment where a
click could race an empty queue.
