## Planner assumptions (UI-SPEC unresolved rows and open choices this plan settles)

- **A-45-01 (UI-SPEC E4-empty, unresolved):** a task group with zero resolved members renders
  nothing (no header, no `0` badge). RESEARCH's recommended default; consistent with D-06's
  "never show an empty group" spirit. Reversible (one conditional).
- **A-45-06 (loading order):** the whole-tab loading state waits for the catalog, the installed list,
  the queue state AND both suggestion sources (`getKnownFixes`, `getWikiGameInfo`), so Suggested never
  grows after first paint (no vertical shift). A rejected or slow-failing source resolves to "no
  signal". PCGamingWiki is normally already cached by the game page (30-day cache).
- **UI-SPEC internal conflict resolved by a locked decision:** UI-SPEC's Spacing section gives
  task-group bodies `max-height: min(50vh, 320px)`, which would create a nested scroller; D-02 (one
  scroll container) and UI-SPEC's own E4-overflow row forbid it. D-02 wins: no group body sets
  `max-height` or `overflow`.
- **Row layout reading:** leading fixed-width slot = checkbox / spinner / success icon / danger icon;
  then title (bold on two-line rows) with inline muted `publisher · year`; family sentence as the
  14px caption on two-line rows; a fixed-width trailing status slot for `Installed`, the phase word,
  or `Install failed` + Retry. The full upstream title is the native `title` tooltip; the visible
  title is `displayTitle(title)` (45-05).
- **Search input:** a plain `<input type="search">` styled under the tab's scope — not `SearchBar`
  (Interaction §4 allows SearchBar without suggestions; a plain input removes the overlay hazard
  entirely). Threshold 2 characters; matches verb or title, case-insensitive (Phase 44 behaviour).
