<objective>
Forward `ISteamUser::GetAuthTicketForWebApi(pchIdentity)` (SteamUser023, vtable slot 14) to the
real Mac Steam through the helper. Today the shim stub `vt_SteamUser023_GetAuthTicketForWebApi`
returns handle 0 (k_HAuthTicketInvalid), so Abiotic Factor's EOS login never gets a web-API
ticket (root cause: `.planning/debug/abiotic-factor-loading-hang.md`).

This is a pure data change following the 53-14 `GetAuthSessionTicket` precedent: the manifest and
`wire-policy.json` declare the method `wire` with `helperFlat SteamAPI_ISteamUser_GetAuthTicketForWebApi`
and `pchIdentity` kind `in-string`; `pnpm gen-vtables` regenerates the shim and the helper
dispatch header. No generator code changes (`in-string` already exists for UserStats `pchName`).

Planner decision (Claude's discretion, recorded): hand-edit the manifest and policy, do NOT re-run
`pnpm extract-proton-inventory` (it fetches from the network at a pinned SHA; the edit is two keys).
Only `isteamuser.manifest.json` (SteamUser023) carries the method; `isteamuser021.manifest.json`
does not and is not touched.

The returned HAuthTicket handle is real after this plan, but the bytes arrive asynchronously in
callback 168, which nothing delivers yet. Delivery is plans 55-03 (helper) and 55-04/55-05 (shim).

Purpose: piece 1 of 3 of the roadmap fix (forward the call).
Output: forwarded method, regenerated shim + dispatch, P55-1 pins.
</objective>

|----------|-------------|
| game process (bottle) -> shim -> loopback socket -> helper | Game-controlled `pchIdentity` string crosses into the Mac helper |
| helper -> real libsteam_api.dylib | Helper requests a web-API ticket under the user's real Steam account |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-01 | Tampering / DoS | in-string `pchIdentity` decode in generated bridge_dispatch.h | mitigate | Existing generator in-string path: length capped at WIRE_IN_STRING_MAX_BYTES 4096 and bounds-checked against the frame before copy; NULL sentinel 0xFFFFFFFF passes NULL. No new marshal code is written by hand |
| T-55-02 | Information disclosure | helper CALL log line for GetAuthTicketForWebApi | mitigate | The generated once-per-method CALL latch logs only `CALL SteamUser023.GetAuthTicketForWebApi`, never arguments or the returned handle's ticket bytes (bytes are not returned by this call at all; they arrive in callback 168) |
| T-55-03 | Elevation of privilege | any local game in a GameLib bottle can now mint a web-API ticket for an arbitrary identity string | accept | Same trust level as the already-forwarded GetAuthSessionTicket (53-14): the bottle runs the user's own purchased game under the user's own account; the identity string only scopes the ticket's audience |
| T-55-04 | Spoofing | unauthenticated loopback helper port | accept (pre-existing, flagged) | Pre-existing posture (T-51-01: INADDR_LOOPBACK bind, OS-assigned port in a per-game cfg). Not redesigned in this phase; recorded so the reviewer sees the ticket-minting surface now sits behind it |
