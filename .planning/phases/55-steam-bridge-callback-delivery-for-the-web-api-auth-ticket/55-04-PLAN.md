<objective>
Build the shim side's callback registry and dispatcher as a portable C block generated by
meta/gen_vtables.ts, and prove its behaviour on the host before it is wired into the Win32 shim
(55-05).

Planner decision (Claude's discretion, recorded): the registry is emitted by a new exported
`generateCallbackRegistryC()` that is transport- and lock-agnostic. The embedder supplies
`GL_CB_LOCK()` / `GL_CB_UNLOCK()`, `THISCALL`, `gl_cb_now_ms()` and `gl_cb_transport_drain()`.
55-05 embeds it in the shim with an SRWLOCK, `GetTickCount` and `bridge_transact` on CONTROL slot 6.
The host harness embeds the SAME generated text with ERRORCHECK pthread mutexes (a re-lock returns
EDEADLK and the harness aborts instead of hanging), a scripted fake transport and a fake clock. This
gives a behavioural proof of "no lock held during Run" and re-entrancy, which a source pin cannot.

Constants (Claude's discretion, recorded): registry capacity 512, drain throttle 30 ms, at most 4
messages per RunCallbacks, backoff to 1000 ms after 8 consecutive failed drains, drain buffer
2584 bytes (= helper `GL_CBQ_DRAIN_RESP_MAX_BYTES`), relay table {168: 2572} mirroring the helper.
The measured MSVC constants come from meta/msvcCallbackLayout.ts (55-02).

Register semantics (RESEARCH Pattern 3): set `flags |= 0x01` (never `=`, preserving the gameserver
bit 0x02) and write m_iCallback, because the SDK's CCallbackImpl destructor unregisters only when
the registered bit is set; without it the registry would keep a dangling pointer.

Not generated into the shim yet: generateShimC is NOT changed here, so `pnpm gen-vtables` output is
unchanged by this plan (55-05 wires it).

Purpose: piece 3 of 3 (shim records registrations and dispatches), proven on the host.
Output: generator block + constants, harness, host test, source pins.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| helper reply -> shim decode | Bytes from the loopback peer are parsed in the game process |
| game-owned CCallbackBase objects -> shim | The shim stores and later calls through game pointers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-15 | Tampering | drain reply decode | mitigate | Every length checked before read: len >= 4, count in {0,1}, len >= 12, id in relay table, cub == table size, len == 12 + cub; buffer is GL_CB_DRAIN_RESP_MAX_BYTES and bridge_transact refuses larger replies (harness `malformed` case) |
| T-55-16 | Tampering / crash | dangling CCallbackBase pointer after the game frees an object | mitigate | Register sets the registered bit so the SDK destructor unregisters; membership re-validated under lock immediately before each call; clear_all on shutdown (wired in 55-05). Residual race (another thread frees between re-check and call) matches real Steam's own contract and is accepted |
| T-55-17 | DoS | registry flood | mitigate | Fixed 512-entry table; overflow counted and ignored, no write past the table and no flag write on the overflowing object (harness `capacity` case) |
| T-55-18 | DoS | deadlock via re-entrant handler | mitigate | No lock held across transport or Run; proven with ERRORCHECK mutexes (harness `no_lock_held`, `reentrant_handler`) |
| T-55-19 | Information disclosure | ticket bytes left in the game-process stack buffer | mitigate | Volatile zeroing after dispatch (harness `buffer_zeroed`) |
| T-55-20 | Information disclosure | harness compile under the real HOME | mitigate | createFakeHomeProfile().childEnv() |
