<objective>
Wire the generated callback registry (55-04) into the Win32 shim and close the build gates.

The shim embeds `generateCallbackRegistryC()` once, after `bridge_transact` and the D-53-15
helpers, behind its own `g_cb_registry_lock` SRWLOCK (separate from `g_bridge_lock`, per the
082ff80db lock discipline). `gl_cb_transport_drain` is `bridge_transact` on CONTROL slot 6,
`gl_cb_now_ms` is `GetTickCount` (wrap-safe unsigned subtraction in the core; available on every
Windows target zig builds, unlike GetTickCount64 on older headers). The game-facing flat exports
call the core.

Explicit scope boundaries (research recommendation adopted as the default, recorded as deferrals):
- `SteamAPI_RegisterCallResult` / `UnregisterCallResult` stay no-ops: 168 is a plain callback, not
  a call result. Deferred.
- `SteamAPI_ManualDispatch_*` stay no-ops (Unity/Steamworks.NET consumers). Deferred.
- `Steam_RunCallbacks` (old-SDK x64) and `SteamGameServer_RunCallbacks` stay as they are. Deferred.
- Callback IDs other than 168: recorded in the registry (needed for correct flag handling), never
  relayed. Deferred.
- P55-9 (Wine PE harness dispatching a seeded 168 on x64 and x86) is DEFERRED: it needs a helper
  test seam that writes into the credential queue over the unauthenticated loopback port, which
  this phase declines to add. Coverage instead: the measured layout (55-02), the host harness over
  the same generated C (55-04), both PE compile gates (this plan), and the x64 live gate (55-07).
  The x86 dispatch path has no live confirmation; 55-06 records it as a todo.

Purpose: the shim records registrations and dispatches 168 (roadmap piece 3), built and gated.
Output: regenerated shim, wiring pins, triple-pin test, PE build.
</objective>
