<objective>
Give the helper a way to receive callback 168 from Mac Steam and hand it to the shim on request.

The helper today only calls `SteamAPI_RunCallbacks` three times inside WHOAMI (`pump_callbacks`,
bridge_helper.c:283-288) and registers no handler, so every callback is dropped. This plan switches
it to the SDK's manual-dispatch flat API (`SteamAPI_ManualDispatch_Init/RunFrame/GetNextCallback/
FreeLastCallback` + `SteamAPI_GetHSteamPipe`, all exported by the installed dylib), keeps an
allowlisted bounded ring, and serves it over a new pull-only CONTROL slot 6.

Planner decisions (Claude's discretion, recorded):
- Ring: 8 entries x 2572 bytes, drop-oldest (`GL_CBQ_RING_SLOTS 8`). Allowlist is a closed table
  with exactly one row {168, 2572}. Pump at most 64 messages per pump (`GL_CBQ_PUMP_MAX_MSGS 64`).
- Drain wire: request has no args (argLen must be 0, else STATUS_ERR). Response blob is
  `[u32 count]` with count 0 or 1, then if 1 `[i32 iCallback][u32 cub][cub bytes]`. Max response
  blob `GL_CBQ_DRAIN_RESP_MAX_BYTES` = 4+4+4+2572 = 2584. The shim (55-04/55-05) sizes its buffer
  from the same number (cross-pinned in 55-04).
- RunFrame is called only on DRAIN and in WHOAMI's warm-up (RESEARCH Open Question 2). This is not a
  regression for titles that never drain: the helper already left callbacks unpumped except in WHOAMI.
- The ring logic lives in a NEW header-only `gamelib_cbqueue.h` beside bridge_helper.c, with no
  dylib or socket dependency, so a host-compiled harness can unit-test it. A quoted include resolves
  relative to the including file's directory first, so `buildHelperCompileArgv()` (whose `-I` is
  `native/steam-bridge/generated`) needs NO change -- this resolves the pattern-mapper's open point.
- Unity/Steamworks.NET manual-dispatch consumers, call results, `Steam_RunCallbacks` and
  `SteamGameServer_RunCallbacks`, and every callback ID other than 168 are OUT OF SCOPE (research
  scope boundaries; deferred explicitly). The ring's `{iCallback, bytes}` shape is what a later
  phase would need for the shim's `ManualDispatch_GetNextCallback`, but nothing here wires that.

`protocol.ts` changes (one constant). It lives in src/backend and the sidecar bundle imports it, so
before any live test the dev app must be restarted and `build/main/sidecar.js` mtime checked
(memory: tauri dev does not rebuild the sidecar). 55-07 carries that step.

Purpose: piece 2 of 3 of the roadmap fix (helper captures and queues 168).
Output: cbqueue header + host test, helper slot 6 + manual dispatch, protocol constant, DRAIN tests.
</objective>
