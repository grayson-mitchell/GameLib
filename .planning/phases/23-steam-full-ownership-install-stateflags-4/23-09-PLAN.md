<objective>
Close the **observability half only** of gap **G-23-01** (user-locked scope).

KCD2 (appId 1771300) aborted its entire install because Steam returned `EResult 40 (Blocked)` for
depot **1771304**'s decryption key. GameLib had selected 1771304 via the package-ownership gate
(`depot/select.ts:174`), but **owning a depot ≠ Steam granting its key**. `classifyDepotError` treats
EResult 40 as non-retryable (`depotErrors.ts` `NON_RETRYABLE_ERESULTS`) and fails the WHOLE install.
The user saw only *"This game's content isn't available to download right now."*

**USER DECISION (locked): diagnostic + observability ONLY this cycle.** The decisive diagnostic —
install KCD2 in the official Steam client on this account/region and observe whether depot 1771304
downloads — is a human task planned in **23-10 Task 3**. This plan ships only the cheap, low-risk
observability improvement so that whatever the diagnostic finds, the next occurrence is legible.

**EXPLICIT NON-GOALS — do NOT implement any of these this cycle:**
- No change to `src/backend/storeManagers/steam/depot/select.ts` (no skip-and-warn, no
  required-vs-optional depot classification, no ownership-gate change).
- No change to `NON_RETRYABLE_ERESULTS` or to any retry/abort behavior. A blocked key still fails the
  install, exactly as today — only the *message* and the *log* improve.
- No change to depot ordering, plan-build retry counts, or `withPlanBuildRetry`.

Requirement mapping: G-23-01 surfaced during REQ-23-07's Gate 2, and this plan is diagnostic support
for that gate. There is no dedicated requirement for depot error copy, so this is cited against
**REQ-23-07** (the D-07 hardware-validation gate the diagnostic serves) with REQ-23-06 carried for
continuity of the depot pipeline work; no new REQ ID is minted.

Purpose: without naming the blocked depot, neither the user nor a future debugging session can tell a
genuine region block apart from a GameLib over-selection defect.
Output: a dedicated Blocked classification, a failure-site log line, and a written, gated follow-up.
</objective>

```
// EResult codes where retrying the SAME request will never succeed:
//   8 InvalidParam · 9 FileNotFound · 15 AccessDenied · 17 Banned
//   40 Blocked (region/content blocked) · 42 NoMatch · 43 AccountDisabled
const NON_RETRYABLE_ERESULTS = new Set([8, 9, 15, 17, 40, 42, 43])
export function isNonRetryableDepotError(err: unknown): boolean   // reads err.eresult

export function classifyDepotError(err: unknown): ClassifiedDepotError {
  const text = errorText(err)                    // Error.message | string | String(err)
  if (isNonRetryableDepotError(err)) {           // checked FIRST, before the connection-drop pattern
    const base = i18next.t('steam.download.error.depotUnavailable',
      "This game's content isn't available to download right now.")
    return { key: 'steam.download.error.depotUnavailable', message: `${base} (${text})` }
  }
  ... ENOSPC / traversal / sha1 mismatch / connection-dropped branches ...
}
```
Note the branch already appends `(${text})`, and `text` for this case is the wrapped message
`couldn't get decryption key for depot 1771304 (app 1771300): Blocked`. The gap is that Blocked has no
distinct copy, no "the game may still be installable" guidance, and the depot id survives only inside
a parenthetical that reads as an internal detail.
