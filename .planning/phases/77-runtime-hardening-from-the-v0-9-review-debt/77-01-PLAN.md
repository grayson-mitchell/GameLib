<objective>
Bound the known-fix relay's request body on every request (DEBT-02, 57 WR-09). Today `handle()` in
`relay/src/handler.ts` calls `request.text()` after a `Content-Length` check that treats a missing
header as 0, so a chunked request is buffered in full before the size check runs. Replace that read
with a capped stream read that stops and cancels once the count passes `KNOWN_FIX_REPORT_MAX_BYTES`
(2048).

Purpose: the relay faces the network. An unbounded body is a memory and CPU DoS vector, and a
`Content-Length` header can lie.
Output: unit-tested code on `main`. DEBT-02 is NOT complete after this plan: plan 77-03 covers the
deploy and the live probe that D-07 requires.

Discretion choice (CONTEXT "Claude's Discretion", helper factoring): `readCappedBody` goes in its own
module, `relay/src/readCappedBody.ts`, with its own test. That follows the relay's
one-module-per-concern layout (`limits.ts`, `steamTitle.ts`). It also lets a test assert the exact decoded text of a
split multibyte character. Through the handler that is unobservable, because a wrong per-chunk
decode yields U+FFFD and still parses as JSON. Because handler.ts imports the export, knip sees it
as used.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet -> Worker (POST /v1/reports) | Anonymous clients send untrusted headers and bodies, chunked or length-declared |
| Worker -> logs (wrangler tail) | The operator sees log lines in real time; IPs and headers must not be logged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-77-01 | Denial of Service | handler.ts body read (chunked, no Content-Length) | mitigate | readCappedBody stops at total > 2048, calls reader.cancel() and answers 413; nothing past the cap is buffered |
| T-77-02 | Tampering | Content-Length header lies under the cap | mitigate | The capped read runs on every request, whatever the declared length (D-05); covered by the 'lying Content-Length' handler case |
| T-77-03 | Denial of Service | slow or never-closing stream | mitigate (partial) / accept residual | Cancel on overflow is test-proven. The Workers platform's per-request CPU/wall limits bound a slow under-cap stream; accepted residual |
| T-77-04 | Information Disclosure | new log line | mitigate | The fixed string 'relay: body over cap -> 413' carries no IP, header or body content, which matches the wrangler.jsonc no-retention comment |
| T-77-05 | Denial of Service | stream read error crashing the handler | mitigate | The error propagates to handleReport's catch, which returns 503; covered by the 'stream error' case (D-06) |
| T-77-06 | Elevation/abuse | rate-limit bypass with oversize bodies | mitigate | checkIpLimit stays above the body read, so every attempt counts (D-15); the acceptance criteria check line order with grep |
</threat_model>
