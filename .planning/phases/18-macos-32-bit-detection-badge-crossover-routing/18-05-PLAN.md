<objective>
Close the single confirmed BLOCKER from 18-VERIFICATION.md (CR-01): the Mach-O-resolved `mac_arch:'32'` verdict is persisted only to `steamMetadataStore` (backend disk cache) and never reaches the frontend-visible `GameInfo.mac_arch` that `MacArchBadge` renders from. This makes MAC32-04 (the "32" badge beside the game logo) unreachable in the realistic post-install flow.

Two independent, code-confirmed propagation breaks are fixed here — both in `library.ts`:
1. `verifyMacArchGroundTruth()` writes only to `steamMetadataStore`; it never updates the in-memory `library` Map or pushes the updated `GameInfo` to the frontend.
2. `refresh()` rebuilds every `GameInfo` from `cachedMeta` but omits `mac_arch` entirely, silently dropping a cached '32' verdict on every startup/resync.

Purpose: make the badge reachable end-to-end so the deferred 18-04 visual placement/styling UAT (Task 3) can re-run, and satisfy MAC32-04.
Output: propagation fixes in `library.ts` + a regression test that locks both paths so this cannot silently regress again.

Scope fence (do NOT touch): `MacArchBadge.tsx` (component is correct), `isBottleEligible`/`games.ts` (reads `steamMetadataStore` directly, unaffected), and the WARNING/INFO robustness items (WR-01/02/04/06) tracked separately in 18-REVIEW.md.
</objective>
