## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GameLib -> game processes | a game is spawned outside GameLib's group and Job, and the test arm signals its tree |
| game output -> disk | the capture file holds whatever the game prints |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-88.2-16 | Information disclosure / Tampering | capture file readable by others or written outside the launches folder | medium | mitigate | 0600 on unix, created by GameLib before spawn and truncated; the file name maps every character outside `[A-Za-z0-9._-]` to `_`, so a crafted app name cannot leave `<app_folder>/launches` (Task 1) |
| T-88.2-43 | Elevation / DoS | a game spawned into GameLib's process group, ChildSet or kill-on-close Job (it would die with GameLib), or a cleanup kill reaching a reused pid | high | mitigate | The game arm spawns only through `spawn_game_tracked` (own session, never in the ChildSet, a non-kill-on-close Game Job) and never takes a pipe; the parent-SIGKILL arm proves survival on three OSes and ends the survivors only through `kill_game_tree` with the probed start stamp (Tasks 1, 2) |
| T-88.2-SC | Tampering | npm/pip/cargo installs | high | mitigate | gamelib-store is a workspace crate behind the `harness` feature; no new lockfile crate |
