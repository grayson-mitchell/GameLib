## Facts at planning time (HEAD bac11b689)

- kill_tree.rs `mod win`: the front door (:63-69) proves identity with two throwaway opens (`probe::is_alive`,
  `probe::start_time`); the Job arm (:70-78) drops the terminate result and answers Killed; `terminate_stamped_tree`
  (:103-129) collects, terminates the leader through `terminate_stamped_leader` (:208-244, which verifies, terminates and
  drops its handle, mapping every TerminateProcess failure to NotOurs), then re-collects up to WALK_PASSES = 3 times from
  the bare pid; `collect_descendants` (:134-176) seeds `accepted` from `(root, root_stamp)` without proof; handles carry no
  SYNCHRONIZE, so the two WaitForSingleObject calls are likely no-ops today. The unix `mod unix` is out of scope.
- 88.2-26 added `probe::handle_exited(HANDLE) -> Option<bool>` (pub(crate), Windows): Some(true) signalled, Some(false)
  running, None when the wait cannot be made. `probe::creation_time(HANDLE)` is pub(crate) already.
- windows-sys 0.61.2 (locked): `windows_sys::Wdk::System::Threading::{NtQueryInformationProcess, ProcessBasicInformation}`
  need feature `Wdk_System_Threading`; `windows_sys::Win32::System::Threading::PROCESS_BASIC_INFORMATION`
  (field `InheritedFromUniqueProcessId`) needs `Win32_System_Kernel`. Features are not recorded in Cargo.lock, and no new
  crate enters it (diagnosis, scratch crate compiled for x86_64-pc-windows-msvc).
- `gamelib_proc::job::GameJob` is public on Windows (`open`, `terminate`, `active_processes`); its name is
  `Local\GameLib-Game-<pid>-<stamp>` (job.rs `game_job_name`, private). A Job name exists only while some process holds a
  handle to it (88.2-25 disproved A5), so with the stand-in parent alive the name is openable and after it is killed it is
  not. The `harness` feature is enabled for this crate's tests through the dev-dependency and never by the shell.
- Callers of `kill_game_tree` at HEAD are tests only (orphans.rs, stub_game.rs's `Strays`); the production consumer is
  88.3-03. `KillOutcome` is matched exhaustively in gamelib-launch registry.rs (`Killed` vs `Gone | NotOurs`).
- Locally `cargo check` and `cargo clippy --offline -p gamelib-proc --all-targets --target x86_64-pc-windows-msvc --
  -D warnings` exit 0 at HEAD. Windows behaviour is proven only on windows-latest (88.2-31). No test can force a pid
  recycle: the proof of CR-01 is structural (a `Leader` that owns the verified handle, `select_tree`'s rule) plus the
  synthetic-table unit tests.
- Rust and TOML files have no prettier parser (`--file-info` inferredParser null); rustfmt checks the .rs files. The
  disposition file is prettier-ignored.
