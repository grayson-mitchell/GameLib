<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GameLib -> game processes | the registry signals process trees |
| sidecar -> shell | the kill ops are reachable from the sidecar |
| game output -> disk | the capture file holds whatever the game prints |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-88.2-15 | Tampering / DoS | registry kill reaching an unrelated process | high | mitigate | Games are killed only through their own unreaped `GameHandle` or a stamp-checked `kill_game_tree`; helpers only through their own group or Job; the quit-kill arm probes from outside (Tasks 2, 3) |
| T-88.2-16 | Information disclosure / Tampering | capture file readable by others or written outside the launches folder | medium | mitigate | 0600 on unix, created by GameLib before spawn and truncated; the file name maps every character outside `[A-Za-z0-9._-]` to `_`, so a crafted app name cannot leave `<app_folder>/launches` (Task 1) |
| T-88.2-17 | DoS | a kill-all that hangs the quit | medium | mitigate | `kill_all` is bounded by `ExitBudget::DEFAULT.child_grace` and holds a registrant only for the kill (Task 2) |
| T-88.2-SC | Tampering | npm/pip/cargo installs | high | mitigate | gamelib-store is a workspace crate behind the `harness` feature; no new lockfile crate |
</threat_model>
