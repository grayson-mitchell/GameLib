## Facts at planning time (HEAD bac11b689)

- probe.rs `mod imp` (Windows) `is_alive` opens PROCESS_QUERY_LIMITED_INFORMATION only and answers `ok != 0 && code ==
  STILL_ACTIVE_CODE` (:184-197). `start_time` and `creation_time` sit beside it. windows-sys 0.61 with the features
  gamelib-proc already enables provides PROCESS_SYNCHRONIZE, WaitForSingleObject, WAIT_OBJECT_0 and WAIT_TIMEOUT
  (diagnosis: type-checked for x86_64-pc-windows-msvc).
- end.rs `wait_end` (:51-79): the leader loop polls `probe::is_alive(pid)` (no lock); the Close arm loops on
  `lock(game).group_alive()` (:62) and the reap takes `lock(game)` (:75), both blocking std Mutex locks inside the async fn.
  registry.rs `GameEntry::kill` (:86-99) holds the same lock across `kill_tree(grace)` on a blocking-pool thread.
- The stub (`gamelib-launch-stub-game`, feature harness) has `exit --code <n>` (exits at once with n) and
  `game --pids <file> --child --lines 0 --exit-after-ms 0` (records its pid and an idle child's pid in the file, then the
  leader exits at once while the child idles: a group or Job that outlives its leader).
- `gamelib_launch::game::{end, registry}` are public: `TrackedRegistry::new()`, `register_game(RunIds, started_at,
  CancellationToken, GameHandle) -> EntryId`, `entry(id) -> Option<GameEntry>`; `GameEntry.handle` is
  `Arc<Mutex<GameHandle>>`. `gamelib_proc::spawn_game_tracked(Command, Option<&Path>) -> io::Result<GameHandle>`.
- Locally from macOS: `cargo clippy --offline -p gamelib-proc --all-targets --target x86_64-pc-windows-msvc -- -D warnings`
  and `cargo clippy --offline -p gamelib-launch --all-targets --target x86_64-pc-windows-gnu -- -D warnings` both exit 0
  at HEAD (msvc fails for gamelib-launch on ring's C build, so its Windows check uses the gnu triple). Windows behaviour
  is proven only on windows-latest (88.2-31).
- Rust files have no prettier parser (`npx prettier --file-info` reports inferredParser null), so the formatter check
  for them is `cargo fmt --check`. 88.2-REVIEW-DISPOSITION.md is under .planning, which prettier ignores.
</context>
