# Phase 88.2 Plan 11: Running-game registry reads and kills Summary

**The Rust running-game registry can now be read and killed through five `launch_*` ops: a quit-kill ends a running stub game's whole tree through its own unreaped handle and the run settles as `{ abort: true }`, a tracked kill takes the TS filter, the abort id reaches games, and golden_runner replays all 93 recorded cases, the 24 game launches through a scripted game spawner**

## Performance

- **Duration:** about 75 min (cargo builds and the Windows-gnu clippy dominate)
- **Completed:** 2026-11-27 (machine clock)
- **Tasks:** 2 (a tracer, then the rest of the registry and the golden replay)
- **Files modified:** 11 in the two code commits (1 created, 10 modified)

## Accomplishments

- `game/registry.rs`: `TrackedRegistry` now holds game entries and helper entries under `RunIds { runner, key, abort_id, stream_id }`. `games_running()` and `games() -> Vec<GameSummary>` are the reads; `kill_tracked(shutdown, runner?, key?)` has the TS filter semantics, `kill_all`, `kill_stream` and `abort_game` share one kill core. Games are killed concurrently on blocking threads through `GameHandle::kill_tree(KILL_GRACE)` (= `ExitBudget::DEFAULT.child_grace`), the whole kill bounded by that grace plus 500 ms, holding one `"game-kill"` registrant only while it runs. Helpers are ended through their cancel token.
- A kill takes the handle's lock, sets `killed_by_us` and calls `kill_tree`; the run's reap (`end::wait_end`, now taking the `GameEntry`) sets `ended` under the same lock, so a kill after the reap signals nothing (the pgid of a reaped leader is not ours any more). The flag is put back when the tree was already gone.
- `call_runner`: the game arm builds `RunIds`, notes the abort and track events and the abort-remove (so the recording tables see a game as they see a helper), spawns through `ctx.game_spawner`, registers with the run's abort token, and answers `{ abort: true }` when `entry.was_killed()` or its token is cancelled. Helper runs register in the registry too (guard inside `TableGuard`). `abort_run` is `run_abort` for either class; the old table-based `kill_tracked` is gone (nothing used it).
- `lib.rs`: ops `launch_games_running`, `launch_tracked_kill_all`, `launch_tracked_kill`, `launch_runner_kill`, `launch_runner_abort` (OPS 13 -> 18), each with the fixed bad-args literal. The kill ops run outside `guarded`'s shutdown cut-off.
- `game/spawn.rs` and `LaunchCtx::with_game_spawner`: the seam a game is spawned through; production is `spawn_game_tracked`.
- Tests: three stub_game arms beside 88.2-10's two (all five pass, four consecutive runs) and registry unit tests over the filter. golden_runner: a scripted `CaseGameSpawner` writes the recorded chunks into the capture file and starts a stub process (`exit --code N`, `term`, or `idle` until the replay ends it through `kill_tracked` or `abort_run`, as the recording's `killedByUs` and `abortWhileHeld` say); the spawn class is observed from which seam the spawns came through, and 93 of 93 cases compare.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Helper entries are ended through the cancel token alone, with no pid**
- **Found during:** Task 2 (`register_helper`)
- **Issue:** The plan has helpers killed through `ChildSet::terminate_one(pid, child_grace)` and their cancel token, with `register_helper(runner, key, pid, cancel)`. `call_runner` runs a helper through `SpecRunner::run_streamed`, which never tells the caller the child's pid, and the `ChildSet` is inside `gamelib-proc`, so `terminate_one` has no pid to be given.
- **Fix:** `register_helper(ids, cancel)`; a kill cancels the token, which `run_streamed` answers by ending the child's whole group through the child it owns (the same path an abort id takes). A helper is never ended as a game.
- **Files modified:** src/game/registry.rs, src/runner/call_runner.rs
- **Commit:** aae0c917b

**2. [Rule 3 - Blocking] A GameSpawner seam on LaunchCtx (not in the plan's files)**
- **Found during:** Task 2 (golden_runner's game cases)
- **Issue:** The game arm called `spawn_game_tracked` directly, so the recorded programs (`gogdl`, `legendary`, ...) would have to exist to replay a launch case, and a scripted capture source had nothing to hook.
- **Fix:** `game/spawn.rs` (`GameSpawner`, `GameSpawn`, `ProcGameSpawner`) and `LaunchCtx.game_spawner` / `with_game_spawner`; `ctx.rs` and `game/mod.rs` are outside the plan's `files_modified`.
- **Commit:** aae0c917b

**3. [Rule 1 - Bug] `wait_end` could let a kill signal a reaped leader's group**
- **Found during:** Task 1 (design of the kill)
- **Issue:** The run reaps the leader (`reap_status`) before its guard unregisters the entry, and a kill landing in between would `kill_tree` a pgid nobody holds any more.
- **Fix:** `GameEntry.ended`, set by `wait_end` under the handle's lock at the reap and checked by the kill under the same lock; `wait_end` takes the `GameEntry` instead of the shared handle. src/game/end.rs is outside the plan's `files_modified`.
- **Commit:** aae0c917b

**4. [Rule 2 - Missing critical] The kill ops are not cut short by the shutdown token**
- **Found during:** Task 1 (the ops)
- **Issue:** `dispatch` wraps every op in `guarded`, which answers `<op>:shutdown` the moment the token cancels, and drops the work; a quit-kill runs exactly when the token may already be cancelled.
- **Fix:** `KILL_OPS` run through `unguarded` (panic-catching only); the kill takes its own registrant and is bounded by the child grace.
- **Commit:** aae0c917b

**5. [Rule 3 - Blocking] A named delta, `game-merged-streams`, in `golden/runner/deltas.json`**
- **Found during:** Task 2
- **Issue:** A game's two streams share one capture file (88.2-10's decision), so the recorded per-pipe stream, the per-chunk log entries, the result's stdout/stderr split and the error handler's trimmed-chunk text cannot match a helper recording byte for byte.
- **Fix:** the delta states exactly what is compared joined (observer chunks, raw writer entries, a successful result's stdout, the error handler's text without whitespace) and what stays compared as recorded; `deltas_json_names_each_delta_with_a_reason` lists it. The fixture file is outside the plan's `files_modified`.
- **Commit:** ef55fd74c

**6. [Rule 3 - Blocking] The stub game gained `exit` and `term` modes**
- **Found during:** Task 2
- **Issue:** The scripted spawner needs a real process that exits with a code or dies of SIGTERM; `src/bin/stub_game.rs` is outside the plan's `files_modified`.
- **Commit:** ef55fd74c

**Total deviations:** 6 auto-fixed (4 Rule 3 blocking, 1 Rule 1 bug, 1 Rule 2 missing critical). **Impact:** the plan's contract (registry reads and kills, five ops, quit-kill proof, every golden case replayed) is met; the deviations are additions around it.
