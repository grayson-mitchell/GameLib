# Phase 88.2 Plan 28: terminate_all waits for the group (WR-01) Summary

Unix `ChildSet::terminate_all` now treats a helper as finished only when its whole process group is empty, so a wine tree or download helper whose child ignores SIGTERM is SIGKILLed at the grace deadline instead of surviving a graceful quit.

## What changed

- **children.rs (unix only; the Windows arms are untouched):**
  - `exited()` reaps an owned leader with `try_wait` (logging an error with the existing fixed-text line) and answers `!probe::group_alive(pid)` for every entry.
  - `still_ours()`: owned stays true; a stored stamp that reads and matches is true; reads and differs is false; cannot be read (leader gone and reaped) answers `group_alive(pid)`, with a comment on why that is safe; no stored stamp keeps `is_alive`.
  - `terminate_entries`: ownership decided once at the SIGTERM phase, entries not ours left out of the poll, and the SIGKILL phase signals a pending group only when still ours and alive. `hard_killed` names those groups only. The reaper unregistration in `terminate_all` is unchanged; `terminate_all`'s doc updated.
- **standin.rs:** `stubborn` and `stubborn-tree` modes, `--stubborn-tree` flag (one `spawn_helper_with_pipes` helper, one `SpecProcRunner` helper), `run_spec_tree(mode, label)` generalised so `--spec-tree` behaves exactly as before.
- **orphans.rs:** `graceful_quit_sigkills_helper_grandchildren_that_ignore_sigterm` (unix).
- **Disposition:** WR-01 `fixed`, `open: 4`.

## Observed reds (TDD)

- **Unit tests at HEAD (before the fix), run locally on macOS:** `terminate_all_sigkills_an_owned_helpers_member_that_ignores_sigterm` and `terminate_all_sigkills_a_tokio_helpers_member_that_ignores_sigterm` both failed on `assert_eq!(hard, vec![label])` with `left: []` (hard_killed empty, so the group was not hard-killed and the member was left to the test's sweep guard).
