## Facts at planning time (HEAD bac11b689)

- job.rs `Job::create_for` sets JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE through SetInformationJobObject with a
  JOBOBJECT_EXTENDED_LIMIT_INFORMATION; job.rs's GameJob doc records the measured fact that a Job without kill-on-close
  leaves its members running after its last handle closes. A zeroed struct passed the same way (LimitFlags 0) type-checks
  with the features already enabled (diagnosis).
- children.rs: `HelperGuard { pid }` whose Drop calls `global().unregister(pid)`, which removes the entry (dropping its
  Job, so kill-on-close fires) and unregisters from the reaper. `terminate_all` drains entries first, so a later
  unregister or release of a drained pid is a no-op. After 88.2-28 the unix `exited`/`still_ours` are group-based.
- spec.rs `run_spec` (:297-406): `let (mut child, _guard) = spawn_helper_tokio(...)`; the select ends in
  `End::Exited(code, signal)`, `End::TimedOut` or `End::Cancelled` (cancel token or app shutdown); `stop()` runs for the
  last two; the guard drops when the function returns. The module doc (:7-10) and `stop()`'s doc (:408-412) say the Job is
  closed when the guard drops, which kills every member.
- Every gamelib-launch helper (script.rs, spawn_async.rs, call_runner.rs's helper class, wine_command.rs) runs through
  `ctx.engine.proc` = SpecProcRunner, so `run_spec` is the one place to opt in. `ProcRunner` (runner.rs) and
  gamelib-steamcm's macowned.rs call `spawn_helper_tokio` directly and are out of scope.
- tests/spec_runner.rs: every child's environment is built from a FakeHome (`fake_env`); `a_timeout_kills_the_grandchild_too`
  is `#[cfg(unix)]` (a shell one-liner). Integration tests can run the stand-in through
  `env!("CARGO_BIN_EXE_gamelib-proc-standin")` (orphans.rs does); its `spec-tree` mode waits for `go`, spawns an `idle`
  grandchild with null stdio and prints its own pid then the grandchild's. orphans.rs has `kill_pid` (SIGKILL on unix,
  OpenProcess + TerminateProcess on Windows) and `Strays`.
- Windows behaviour is proven only on windows-latest (88.2-31); `cargo check`/`clippy --target x86_64-pc-windows-msvc` for
  gamelib-proc work locally. Rust files have no prettier parser (`--file-info` inferredParser null); rustfmt checks them.
  The disposition file is prettier-ignored.
