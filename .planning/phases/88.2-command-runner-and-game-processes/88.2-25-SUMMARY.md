### Auto-fixed Issues

**1. [Rule 1 - Bug] RunnerAdapter members declared with method syntax**
- **Found during:** Task 1 (the first `pnpm lint`)
- **Issue:** 88.2-17/21 declared `RunnerAdapter` with method syntax, and three files destructure `runWineCommand` from it: three `@typescript-eslint/unbound-method` errors, `pnpm lint` exit 1

- **Files modified:** `src/backend/runnerAdapter.ts`

**2. [Rule 1 - Bug] Windows `kill_game_tree` left the game's grandchild alive (flagged assumption A5 disproved)**
- **Found during:** Task 3, windows-latest of run 45954057247
- **Issue:** the named Game Job (no kill-on-close) cannot be reopened by name once the process that created it died, so the stamped kill fell back to the leader alone and `terminate_parent_spares_game_then_stamped_kill_removes_its_tree` timed out. The mechanism (Windows drops the name of a kernel object when its last handle closes) is the explanation consistent with the log; the log shows the symptom, not the mechanism.
- **Fix:** a tree fallback inside gamelib-proc, as the plan prescribed (no hand-rolled kill): when `GameJob::open` fails, `kill_game_tree` snapshots the process table, keeps only descendants of the stamped leader that are newer than their named parent (the leader counting as created at the stamp), holds each handle from check to terminate, terminates the leader then the descendants, and repeats up to three times. `GameJob::open` is still tried first. windows-sys gains the `Win32_System_Diagnostics_ToolHelp` feature; no new crate, `Cargo.lock` unchanged. Comments stating A5 as fact were corrected.
- **Files modified:** `src-tauri/crates/gamelib-proc/Cargo.toml`, `src/job.rs`, `src/kill_tree.rs`, `tests/orphans.rs`
- **Commit:** `c7ec52d1e`

**3. [Rule 1 - Bug] Wine goldens compared POSIX recordings to Windows-joined paths**
- **Found during:** Task 3, windows-latest of run 45956464586 (the first time the 88.2 replays ran on Windows)
- **Issue:** `golden_wine_launch` and `golden_wine_path` failed on 17 cases that differ from their recordings only in separators after a profile placeholder (`<HOME>\.steam\steam`)
- **Fix:** both normalisers fold backslashes to `/` after a placeholder on Windows only; test code only
- **Files modified:** `src-tauri/crates/gamelib-launch/tests/common/mod.rs`, `tests/golden_wine_launch.rs`
- **Commit:** `25bc3b526`
