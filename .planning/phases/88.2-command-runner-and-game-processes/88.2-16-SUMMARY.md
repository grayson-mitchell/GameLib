# Phase 88.2 Plan 16: The commandRunner-shaped adapter Summary

**`createRunnerAdapter(...).callRunner` runs a runner command through `launch_runner_call` with commandRunner's signature and `ExecResult`, handing every log writer off once through `LogWriter.handOff()`, and `createAbortRegistry({ forwardAbort })` forwards ids Rust owns; nothing is wired at boot yet**

## Accomplishments

- `LogWriter.handOff()` (`LogHandOff = { target, disabled, rotate }`): claims the owed rotation through `#claimRotate()` synchronously, so the first hand-off of a writer carries `rotate: true` and every later one `false`, and a write after a hand-off carries none. Closed or refused writers answer null. A disabled writer is handed off disabled and keeps its rotation owed.
- `runnerAdapter.ts`: appends the runner writer to `options.logWriters` as the TS did, opens a stream when `onOutput` or `onSpawn` is set (sends its id as `streamId` with `observe: true`), awaits `flushLogs()`, then hands the writers off (the runner's own last) and sends `runnerCall` with env as `[key, value]` pairs (undefined values left out), wrappers, prefix, sanitizer name, abort id, track key, cwd and `skipErrorHandler`; closes the stream in `finally`; narrows the reply with `settleExecResult`. No `spawnClass` is sent (helper is the default, so no `runnerSpawned` frame arrives and `onSpawn` is for the game path).
- `createAbortRegistry({ forwardAbort })`: `call(id)` aborts the local controller if present, forwards the id, and logs `Could not find a matching abort controller` only when neither the map nor Rust's answer knew the id. A forward that rejects or throws counts as "no run answered". No deps: unchanged and synchronous.
- Schedule: the three runner shim rows now list `runnerAdapter.ts` as their importer (it was empty); `runnerAdapter.ts` also joins the `createCommandRunner` twin's importers (it keeps `RunnerProps` as a type import).

- The plan lists the hand-off before the flush. Claiming a rotation, then awaiting the flush, would let a TS line of the same writer be written (carrying no rotate) ahead of Rust's rotate, which then truncates it away. The adapter flushes, then claims and sends with no await between.
