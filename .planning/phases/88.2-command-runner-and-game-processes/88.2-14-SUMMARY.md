# Phase 88.2 Plan 14: spawnAsync and the Windows command-line cross-check Summary

**spawnAsync is the `launch_spawn_async` Helper op (cwd, replacing env, a timeout that kills the child group, a stream-id kill answering `aborted: true`, 50-chunk windows), all 33 replayable goldens match at `compared 33 floor 33`, and a Windows test starts a real exe through the Rust helper path, the Rust game path and Node's `spawnSync` to prove the child receives the same arguments on all three**

## Accomplishments

- `runner/spawn_async.rs`: `spawn_async(ctx, SpawnAsyncArgs, sink) -> Result<SpawnAsyncResult, String>`. The run is a Helper (label `spawn-async`) through `ctx.engine.proc.run_streamed`, with `replace_env` exactly when an env was passed, a timeout only when `timeoutMs` is finite and above zero (a fraction of a millisecond is kept; a value too large for a duration is no limit), `hide_window` from `windowsHide`, no capture of its own, and the stream id registered as a helper entry so `launch_runner_kill` cancels it. Each chunk goes to the observer and then untrimmed into one of two `ChunkWindow`s (50 chunks, joined with an empty string). A spawn error is `Err(text)`; a timeout answers `timedOut: true, code: null`; a cancel (the kill, the quit or the app shutdown) answers `aborted: true, code: null` as a resolved result. Nothing is written to any log.
- Op `launch_spawn_async` (OPS 21 -> 22, sorted), argument `[args]`, fixed `launch_spawn_async:bad-args`; an observed call gets a `UiOutputSink` so the TS caller's `onOutput` runs.
- `golden_spawn_async`: `compared 33 floor 33` (the 37 recorded cases less the 4 `tsOnly` option-check cases). Per case: the spawn (program, argv, cwd, env or none, replaceEnv, windowsHide, class), the time limit (a golden `timeoutMs` has that limit, fraction kept; an opt-out has none), the chunks the caller watching the stream sees, the answer, and no log line. Guard tests prove a changed argument, a dropped chunk and a run that did not time out each fail the replay. The tracer replays the plain case first.
- `spawn_async_real.rs` (unix, FakeHome, `/bin/sh`, through the op): the two real-child titles (exit code 3 with stdout `ok`; timeout and abort), the env replacing the inherited one with the cwd honoured, a timeout whose grandchild is gone afterwards, a `launch_runner_kill` mid-run that answers a resolved `aborted: true` and leaves the registry empty (a second kill ends 0), a missing program answering an error, and a chatty child's tail.
- `gamelib-launch-cmdline-echo` and `windows_quoting.rs`: 16 rows (plain, spaces, embedded quotes, trailing backslash, backslashes before a quote, an empty argument, a tab, non-ASCII, `%PATH%`, `^&|<>`, single quote and backtick, flags, a 3000-character argument, and three PowerShell `-ArgumentList` strings built by the real `powershell_command`). Each is started through `SpecProcRunner`, `spawn_game_tracked` (capture file) and Node's `spawnSync` from one Node process; the same table runs against `echo.bat` and `echo.cmd`. No vacuous skip: `GITHUB_ACTIONS` with no Node fails.
- Batch files (A4): the direct Windows path in `call_runner` refuses a `.bat` or `.cmd` with Node's own text before anything spawns, for helper and game runs. `batch_refusal.rs` proves it on every host over the scripted seam (a Windows-platform context, no spawn reaches the seam, the PowerShell form and non-Windows unaffected). A D-20 todo records the runtime difference.
- Cargo: `windows-sys` 0.61 with `Win32_System_Environment` as an optional `cfg(windows)` dependency behind `harness`, the one lock line changed; no new crate.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The batch refusal text is `spawn EINVAL`, not `spawn <file> EINVAL`**
- **Found during:** Task 2 (reading how the TS runner calls `spawn`)
- **Issue:** The plan says refuse with "Node's error text". Node's `spawn` throws an errno exception for a refused batch file (`Error: spawn EINVAL`, no file name) from inside the TS runner's promise executor, so a TS call fails with exactly `spawn EINVAL`. `spawnSync` is the one that names the file. A first draft that put the program in the message would not have matched.
- **Fix:** `BATCH_REFUSAL = "spawn EINVAL"`; the Windows test captures Node's message from a `try { spawn } catch` plus the `error` event and asserts equality with the Rust answer.
- **Files modified:** src-tauri/crates/gamelib-launch/src/runner/call_runner.rs, tests/batch_refusal.rs, tests/windows_quoting.rs
- **Commit:** d9800e863

**2. [Rule 1 - Bug] "The three command lines are equal for every .exe row" cannot hold byte for byte**
- **Found during:** Task 2 (reading Rust std's `append_arg` and libuv's `quote_cmd_arg`)
- **Issue:** Rust always wraps the program name in quotes where libuv does so only when needed, and for an argument holding a `"` libuv wraps the whole argument in quotes and escapes inside (`"a\"b"`) where Rust escapes in place (`a\"b`). Asserting raw equality for every row would be red on the Windows leg for reasons that are not a bug: both parse to the same argument. Argument injection (T-88.2-20) is about what the program receives, not the bytes.
- **Fix:** The test asserts, for every row and on all three paths, that the child's own parsed argv equals the argv sent; that the two Rust paths build one command line; and that Rust and Node build the same text after the program token for every row with no `"`. Rows with a `"` print both command lines. Recorded in the module doc and in the D-20 todo.
- **Files modified:** src-tauri/crates/gamelib-launch/tests/windows_quoting.rs, src-tauri/crates/gamelib-launch/src/bin/cmdline_echo.rs (the stub prints its parsed argv on a second line)
- **Commit:** d9800e863

**3. [Rule 3 - Blocking] Files beyond the plan's list**
- `tests/common/mod.rs` gains `Step.hold` and `Step.timed_out` (a held run ends when the spec's cancel fires; a timed-out run) so the replay can model the recorded abort and timeout; both default off, so `golden_script` and `golden_wine_path` are unchanged. `tests/batch_refusal.rs` proves the refusal on every host (`windows_quoting.rs` is `cfg(windows)` and could not). `src-tauri/Cargo.lock` carries the one-line dependency edge. `call_runner::powershell_command` became `pub` so the cross-check builds its PowerShell rows with the real function.
- **Commits:** eebc6142a, d9800e863

**4. [Rule 3 - Blocking] The op takes `[args]`, not `[args, host]`**
- The plan's signature `spawn_async(ctx, args, host, sink)` has no use for `host`: a spawnAsync child with no env inherits the process environment, and every golden records `replaceEnv: false` with `env: null` in that case. An unused parameter would only mislead the TS shim author (88.2-21).
