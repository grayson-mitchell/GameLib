# Phase 88.2 Plan 04: Wine launch, winepath and launch script goldens Summary

**41 runWineCommand, 16 getWinePath and 18 runScriptForGame cases recorded from the real TS runner into golden/wine_launch, wine_path and script, with the commandRunner.test.ts census closed, before any Rust for them exists**

## Performance

- **Duration:** about 50 min (the start time was not captured)
- **Completed:** 2026-11-27
- **Tasks:** 2
- **Files:** one test file, three fixture slices (75 case folders), one todo

## Accomplishments

- `golden/wine_launch` pins the sideload wine launch: the `Wine Command: <bin> <parts>` header and every chunk at the forwarder boundary (target, rotate, entry), the `onOutput` sequence, the track `{ runner: 'wine', key }` and its precedence, `resolveOn` close versus exit, the caller's `commandParts` and `wrappers` after the call, and the `wineserver --wait` spawn with its 30-minute timeout. A claimed writer's header carries `rotate: false`, an unclaimed one `rotate: true`.
- The cases run on the real env builders over a seeded fake HOME for wine, proton with and without umu, crossover and toolkit prefixes, with `PROTON_LOG` set so `ignoreLogging` shows.
- `golden/wine_path` records the `cmd /c winepath -u|-w` run (runinprefix verb), the trimmed answer and the empty-answer error line, including spawn failure and invalid wine.
- `golden/script` records the spawn (empty argv, cwd the install path, the HEROIC_GAME_* block with the settings and game-info JSON of nested and non-ASCII input, the inherited env merged last, `resolveOn: 'exit'`, no timeout), the verbose-on chunk writes, verbose-off silence, and the throw with and without verbose logs.
- The census moved here: `assertCasesCoverTitles` over commandRunner.test.ts against the union of the four slices, with a not-ported map of only the `Layer-2: real children` titles, each naming `gamelib-launch/tests/runner_real.rs`. runner.oracle.test.ts is untouched and still passes.

## Task Commits

Tasks 1 and 2 share one oracle file and one census, so neither could pass on its own commit: `35e93e2cf` (test) holds both.

**Plan metadata:** the docs commit that carries this file.

## Decisions Made

- The wineserver spawn gets `runner.wine_command.wineserver_wait` per spawn, matching on the program and `--wait`, rather than one call site for the whole case.
- `deltas.json` is written to all three slices with the same table: `shell-injected-env`, `caller-arrays-mutated` (commandParts and wrappers changed in place, which the Rust function will not do) and `error-stack-trace` (a logged Error keeps its first line only).
- The `validWine` stand-in checks file existence only and skips the macOS Sonoma rule: the golden cases do not exercise it and the Rust wine core owns it.
