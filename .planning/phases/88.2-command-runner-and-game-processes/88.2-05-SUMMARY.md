## Accomplishments

- `golden/spawn_async` records, per case, the one `run` spawnAsync makes (program, argv, cwd, whole env or `null`, `replaceEnv` true exactly when an env is passed, `timeoutMs` or the unbounded reason, `windowsHide` defaulting to false, signal passed), the `onOutput` chunk sequence and the result `{ code, stdout, stderr, timedOut, aborted }` with the last 50 chunks per stream. An abort resolves with `aborted: true` and never rejects; a spawn error is `{ rejected: <message> }`; the option-check TypeError is `tsOnly`.
- `golden/error_handler` records every branch per runner: empty error, both ignore-list messages alone and inside text, the deleted-folder message answered Yes, No and dismissed, with no app name and with a title-less game, the legendary `.py` rule and its MemoryError exception, expired credentials, order-of-check overlaps and unmatched text. The dialog's cancelId is 0; `forceUninstall` is called only for Yes; MemoryError records no dialog and no frontend message.
- Both oracles compare by default with a census (spawnAsync.test.ts titles), a manifest floor equal to the count and guard tests for the properties above.

## Decisions Made

- The golden messages use the real English catalog through the real i18next (`jest.unmock('i18next')`, the sidecar init as `secretsAlerts.oracle.test.ts` does it) because the backend jest project's key-echoing mock would have recorded `box.error.legendary.generic` as a user-facing message. The buttons are therefore `NO` and `YES`, the catalog values.
- Two deltas are documented in `error_handler/deltas.json` (`english-catalog`, `interpolation-escaping`); `spawn_async/deltas.json` holds `shell-injected-env`.
- Case counts exceed the plan floors (>= 18 and >= 30); the floors equal the counts (37 and 108).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Real i18next instead of the project-wide mock**
- **Found during:** Task 2
- **Issue:** The plan reads the i18n keys from `public/locales/en/gamelib.json`, but the keys live in `translation.json`, and under jest `i18next` is auto-mocked to echo the key, so a recorded modal would have held a key instead of text.
- **Fix:** The oracle unmocks i18next and initialises the real instance with the English catalog, then records what the code produces.
- **Files modified:** src/backend/__tests__/oracle/errorHandler.oracle.test.ts
- **Verification:** oracle passes in compare mode; a guard asserts the credentials message is not the key
- **Committed in:** 877cf7507

**2. [Rule 3 - Blocking] Own recording dialog and library fakes layered on createFakeLauncherDeps**
- **Found during:** Task 2
- **Issue:** The shared fake answers a dialog with a scripted number only, cannot answer with the dialog's own cancelId, and its game has no `forceUninstall`.
- **Fix:** The oracle passes `dialogs` and `libraryManagers` through the fake's `overrides`, recording the options, answers, lookups and uninstall calls itself; the shared file is untouched.
- **Files modified:** src/backend/__tests__/oracle/errorHandler.oracle.test.ts
- **Committed in:** 877cf7507

**3. [Rule 3 - Blocking] Golden file names follow the shared harness**
- **Found during:** Task 1

- **Fix:** Kept the harness names and added `stream.json` through its `extra` slot.
