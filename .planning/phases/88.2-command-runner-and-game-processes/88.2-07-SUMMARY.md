# Phase 88.2 Plan 07: callRunner helper path in Rust Summary

**callRunner's helper path ported to Rust (exact credential redaction, log hand-off, dedup and abort tables, 50-chunk result, `launch_runner_call` op) and replayed against 92 of the 93 TS goldens plus real `/bin/sh` children**

## Performance

- **Duration:** about 95 min (start time not captured; estimated)
- **Completed:** 2026-11-27
- **Tasks:** 2 (a tracer, then the expansion; the helper path was written whole in the first, see Deviations)
- **Files modified:** 18 in the two code commits (3 Rust crates besides gamelib-launch touched additively)

## Accomplishments

- `get_runner_call_without_credentials` is an exact port: exact-element match for the eight flags (a trailing flag grows the line as the JS array assignment does), the PowerShell `-ArgumentList` pattern with JS lazy-match and no-line-terminator semantics, the env diff against the host env, `quote_if_necessary`. It is the only command form any log sees.
- `call_runner` runs a runner as a `SpawnClass::Helper` through `ctx.engine.proc`: no timeout, merged env replacing the inherited one, cwd `cwd || runner dir`, `./` prefix off Windows, PowerShell `Start-Process -Wait -NoNewWindow` when `powershell` is on the host PATH (probed once per context), 64 KiB reads, result stdout the last 50 trimmed chunks joined with nothing and stderr joined with a newline.
- Two identical joinable calls share one spawn and one result; an observing call neither joins nor registers; entries leave the tables when the run settles (also on panic); abort by id (`run_abort`) and tracked kill (`kill_tracked`) end a run as `{ abort: true }`; the app shutdown does the same.
- Log hand-off: `LogHandOff { target, disabled, rotate }` decoded through `gamelib_log::frame::target_of`; a disabled or refused writer is dropped, rotate rides the first entry written to a target only; the general line is written through the sink with the runner's prefix.
- `launch_runner_call` op (`[args, host]`, fixed `launch_runner_call:bad-args`, game class refused with a fixed text, `runnerOutput` frames over `ctx.engine.ui.send_to_sidecar` when `observe`).
- Verified: `golden_runner` prints `compared 92 floor 92`; `runner_real` (8 tests) passes on macOS; crate tests, clippy, fmt, `cargo tree` (no keyring, no tauri, no new third-party crate), `cargoFeatures.test.ts`, the TS runner oracle (deltas) and `pnpm planning-gates` all green.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The spawn seam reported no signal**
- **Found during:** Task 1
- **Issue:** `SpecOutput` had no signal, so a child ended by SIGTERM (code `None`) looked like a spawn failure; 12 recorded steps end by `SIGTERM` and expect `Process terminated with signal SIGTERM`.
- **Fix:** additive `signal: Option<i32>` on `SpecOutput`, filled from `ExitStatusExt::signal` in `gamelib-proc`'s `drive`; every other construction site compiled unchanged (`..Default`).
- **Files modified:** crates/gamelib-core/src/process.rs, crates/gamelib-proc/src/spec.rs
- **Verification:** golden_runner and runner_real (a real `kill -TERM $$`); `cargo test -p gamelib-proc` and a workspace check
- **Committed in:** 840fd5a03

**2. [Rule 3 - Blocking] 64 KiB reads need a size on the spec (the plan's own "additive read-size field")**
- **Fix:** `ProcSpec.read_chunk` (default `DEFAULT_READ_CHUNK` 8 KiB, so every other caller is unchanged); the runner sets 64 KiB.
- **Committed in:** 840fd5a03

**3. [Rule 3 - Blocking] The typed-target conversion was private to gamelib-log**
- **Fix:** `frame::target_of` and `format::is_js_space` made public, `FrameTarget` derives `Clone` (the plan said to move the conversion if it lived in the shell; it already lived in gamelib-log).
- **Committed in:** 840fd5a03

**4. [Plan gap] The acceptance count `> 80` cannot be reached by helper-class cases alone**
- **Found during:** Task 2
- **Issue:** `golden/runner` records 69 cases under `runner.call` (helper) and 24 under `runner.call.launch` (game class). The plan says the launch cases join in 88.2-11 yet also asks for `compared n == floor > 80`.
- **Fix:** all cases but the sanitizer one are replayed (92) through the helper spawn; the preamble, logs and classification are the same code the game path will share. The spawn class itself is not observable through a scripted seam, so nothing here claims the game class.
- **Verification:** `compared 92 floor 92`

**5. [Rule 2 - Hardening] Table entries are given back only by the run that registered them**
- The TS `abort.remove(id)` deletes by id. A run now removes the abort and tracked entries only when the serial matches, so an old run cannot strand a newer one on the same id. No golden covers two live runs on one id.

**6. [Rule 2 - Hardening] The general `Running command` line escapes CR and LF** (`gamelib_log::log`). Byte-equal to the TS line for every recorded case.

**7. [Scope] Task 1 held the whole helper path, not a tracer slice.** The path is one function; splitting it would have meant committing a non-compiling half. Task 2 added `runner_real.rs` and the todos.

## Deltas added to golden/runner/deltas.json (and the TS DELTAS table)

- `chunk-boundaries` (the plan's): read boundaries are an OS artefact; the window counts chunks.
- `spawn-error-text` (the plan's): the OS error text replaces Node's `spawn <bin> ENOENT`; compared by prefix.
- `windows-path-separator` (new): the win32 cases were recorded on a POSIX host; only the separator of the joined runner path is excused.

## Notes for the plans that follow

- **88.2-08** adds the `log_sanitizer` field and its enum to `RunnerCallArgs` and empties `NEEDS_SANITIZER` (one case). The chunk closure in `Run::chunk_sink` is where the sanitizer goes (writers get the sanitized text, the observer and the window the raw one).
- **88.2-09** implements `RunnerErrors::handle`.
- **88.2-10** adds the game path in `call_runner` (it currently refuses `spawnClass: "game"` with a fixed text) and calls `OutputSink::spawned`.
- **88.2-15/16** send `env` as `[[key, value], ...]` (an object works but loses its order), the runner's own log writer last in `logTargets`, and `stream_id` when `observe`. `RunnerHost { env, path }` is appended by the shell; `path` is the PATH the PowerShell probe searches.
- Observed difference to record: the TS `callRunner` waits for the pipes to close; the Rust runner gives them the `POST_EXIT_DRAIN` (2 s) after the child exits (`runner_real` shows an 8 s lingering grandchild does not hold the result).

## Issues Encountered

- Concurrent cases settle in a different order in Rust than in the TS (a JS microtask artefact); the replay compares those cases' creates in order and errors and removes as sets.
- The first replay yielded to the runtime between the calls of a concurrent case, which let the first call finish before the second began; removing the yields reproduced the TS start order.
