# Phase 88.2 Plan 20: The ManagerHooks handler and the askForceUninstall shim Summary

**The sidecar now answers the shell's `launchManagerCall` (`game_title` through `resolveTitleForGame`, `force_uninstall` through the manager) behind a strict schema that refuses a forged call without echoing it, and the deleted-folder prompt is one typed unbounded shim, `askForceUninstall`, over a new `launch_ask_force_uninstall` channel and shell arm**

## Performance

- **Duration:** ~12 min
- **Started:** 2026-11-27T00:27:24Z
- **Completed:** 2026-11-27T00:39:23Z
- **Tasks:** 2 (a tracer, then the refusals task)
- **Files modified:** 16 (1 created, 15 modified; `ipc_contract.rs` regenerated)

## Accomplishments

- `launch_ask_force_uninstall` end to end: a constant, a strict zod schema (`[{ runner, appName }]`, the five runner names), the regenerated `ipc_contract.rs`, and a shell arm that decodes and checks arity first so a bad call is the same fixed `launch_ask_force_uninstall:bad-args` literal before and after the install and never echoes the sidecar's value. The crate op already existed (88.2-09), so the arm is the whole Rust change.
- The channel is in `UNBOUNDED_RUST_CHANNELS` (twenty-sixth paragraph of its comment) and in `dialogOptionForwarding.test.ts` in the same commit, because the user may take longer than 60 s to answer.
- `askForceUninstall(deps, { runner, appName })` in `launchrust/runner.ts`: one returned typed call, answers the clicked index (0 No, 1 Yes) or `null`.
- `registerLaunchManagerHooks(ipc, { libraryManagers })` registers `launchManagerCall` once (called once from `handlers.ts`). It validates `[op, { runner, appName }]` against the new `sidecarInternal` invoke schema, answers `game_title` with `resolveTitleForGame(getGame(appName), appName)` and `force_uninstall` by awaiting `getGame(appName).forceUninstall()` (answers `true`). A manager that throws rejects the call.
- Refusals: an unknown op names only the op (cut to 32 characters, `[A-Za-z0-9_-]` kept, the rest `?`), every other malformed shape says `bad arguments for <op>`; the runner and app name are never in a message, and no manager is reached.
- Schedule row `askForceUninstall` (shim, deletedBy 92, `wiring: ['registerLaunchManagerHooks']`); `handlers.ts` is added to `RUNNER_SHIM_IMPORTERS`.
