<objective>
Close UAT GAP 3 (major, test 2): the game-page Install button and status message desync from the in-progress bottle setup that the right-side toast correctly shows.

**Root cause (already traced — do not re-diagnose from scratch, but read both sides to confirm):**
The Install button (`MainButton`) and the "This game is not installed" message (`GameStatus`) both read `is` from `GameContext`, which is derived entirely from `status = hasStatus(gameInfo)` — i.e. the `libraryStatus` DownloadManager queue. The right-side setup toast (`SteamBottleSetup.tsx`) reads a SEPARATE zustand store, `useSteamBottleSetup`, opened by the backend `steamBottleSetupRequired` signal. **These two state sources are never connected.** When `SteamGame.install()` (backend) is bottle-eligible but `!isBottleReady()`, it emits `steamBottleSetupRequired` (opens the toast) and returns `{ status: 'done', deferredToSetup: true }`; the DownloadManager `finally` block (`downloadmanager/utils.ts:123`) then pushes `status: 'done'` because `deferredToSetup` is true, which clears the transient badge — so the button reverts to "Install" and the message to "This game is not installed" while the toast shows setup-in-progress. That is the "flash of queued then reverts" and the button/status desync. Clicking Install again just repeats this (dead-end) because `isBottleReady()` stays false during provisioning.

**Fix (single source of truth — reuse existing wiring, do NOT invent a parallel channel):**
Make the game-page button + status + install-click derive from the SAME store the toast already reads (`useSteamBottleSetup`). Add a derived `is.settingUpBottle` flag (true when a setup surface is active for THIS game) and have `MainButton`/`GameStatus` reflect it, and gate the install-click so it never re-dispatches a no-op install while setup is active.

Purpose: unblocks UAT tests 4-7 (login/install/launch/badge), which cannot be observed until setup-in-progress is reflected on the game page.
Output: `is.settingUpBottle` plumbed from the store through GameContext into the button + status, a shared pure selector, i18n key, and a CI-runnable selector test.
</objective>
