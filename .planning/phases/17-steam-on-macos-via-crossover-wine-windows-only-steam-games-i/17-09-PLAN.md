<objective>
Close UAT GAP 2 (MAJOR, MACSTEAM-04): on macOS, Install/Play on a Windows-only
Steam game jumps straight to "steam installing" with NO consent dialog and NO
WineSelector — the guided setup never fires.

Root cause (see .planning/debug/steam-bottle-guided-setup-never-fires.md):
`isBottleEligible()` requires `meta.platformsCaptured === true`, which is only
set by a throttled fire-and-forget appdetails fetch. When that fetch hasn't
completed or failed (cold-cache ETIMEDOUT history), the gate is false and
install()/launch() fall through to the native `steam://install` branch — no
`steamBottleSetupRequired` signal, so the (correctly wired) frontend guided
setup never renders.

Purpose: make platform capture reliable at the moment of Install/Play by forcing
a synchronous appdetails platform check before routing, decoupling bottle
routing from the async metadata race; and reconcile the D-08 "Runs via Windows
Steam bottle" indicator gate with the backend routing gate so the UI promise and
actual routing agree.

Output: `ensurePlatformsCaptured()` awaited at install/launch/uninstall entry, a
`steamPlatformsCaptured` passthrough on GameInfo, and a tightened frontend
indicator gate — plus regression tests.

Depends on 17-08 (shares games.ts / games.test.ts; 17-08 must land its
isBottleReady gate first).
</objective>
