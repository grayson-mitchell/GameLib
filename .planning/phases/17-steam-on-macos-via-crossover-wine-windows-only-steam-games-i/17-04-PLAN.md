<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main (bottle IPC) | Frontend passes a bottle name + wineVersion into provisioning |
| main → cxbottle / runWineCommand (spawn) | Bottle name + appId flow into spawned process argv |
| main → Steam CDN (HTTPS) | SteamSetup.exe fetched from an external CDN |
| bottled Steam client → its own credential store | Bottled login persists in the prefix; opaque to GameLib (D-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Tampering | bottle name → cxbottle/runWineCommand argv | mitigate | `sanitizeBottleName` at provision entry; argv-form spawn only (arguments as discrete words), never shell-string interpolation |
| T-17-04 | Tampering | appId → tellBottledSteamTo* command | mitigate | `/^\d+$/` numeric guard (buildSteamProtocolUrl precedent) before the appId reaches commandParts; reject otherwise |
| T-17-02 | Tampering | SteamSetup.exe download | mitigate | HTTPS-only official `cdn.cloudflare.steamstatic.com/client/installer/SteamSetup.exe` via downloadFile; consistent with existing GOG/EA installer-fetch posture (no unilateral pinning) |
| T-17-03 | Denial of Service | provisioned pre-flight before every bottled verb | mitigate | `isBottleProvisioned()` cxbottle.conf gate before spawn; steamwebhelper-hang (A3) surfaces a descriptive error, never a silent hang |
| T-17-06 | Information Disclosure | bottled Steam credentials | accept | D-04 — GameLib never reads loginusers.vdf/sentry; bottled auth is entirely internal to the Windows Steam client, outside GameLib's control (ASVS V2/V3 not applicable) |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | Zero new dependencies this phase (RESEARCH.md audit: not applicable) |
</threat_model>
