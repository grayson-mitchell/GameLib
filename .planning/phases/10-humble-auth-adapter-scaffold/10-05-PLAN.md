<objective>
Re-point the Humble login from the retired popup BrowserWindow to the embedded Stores WebView
via a new `/loginweb/humble` route, matching the Epic/GOG/Amazon in-app login UX. Cookie capture
and validation stay in the main process (reading the shared `persist:humble` partition); the
authoritative login-success signal becomes `GET /api/v1/user/order` (gamekeys) 200 + zod parse
(D-16), and identity becomes a best-effort post-acceptance fetch (D-02). The candidate-cookie
state machine (throttle, navigation-forced re-validation, single-flight, standard-Chrome UA) is
preserved and re-surfaced, not rewritten (D-17).

Purpose: The parked 10-05 login window never auto-closed because the assumed `/api/v1/user/info`
identity check kept rejecting validated-looking cookies, and the user pushed back on the popup
when Epic/GOG log in inside the embedded WebView. This plan fixes both: the correct login gate
(gamekeys) and the correct surface (embedded WebView).

Output: a re-pointed `HumbleUser` login watch, three new IPC channels, the `/loginweb/humble`
WebView surface, the tile wired to it, and the retired BrowserWindow/HumbleConnect code removed.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer `<webview>` → humblebundle.com | Untrusted third-party login page (credentials/reCAPTCHA/Humble Guard handled entirely by Humble's own form) |
| renderer webview cookie store ↔ main process | The `persist:humble` cookie store is shared by name; main reads `_simpleauth_sess` from it |
| main process → Humble API | Authenticated adapter calls using the captured cookie |
| main → renderer IPC | `humbleAuthState` push and login-result payloads must never carry the cookie |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-10-19 | Information Disclosure | persist:humble on-disk cookie store | accept | D-18 accepted trade-off: a second on-disk copy in Chromium's cookie store, identical to every other runner's login partition; the encrypted electron-store cookie remains canonical; the whole partition is cleared on explicit Disconnect (D-07) |
| T-10-20 | Information Disclosure | cookie value in logs / IPC payloads | mitigate | Login validation logs status only ("Humble login validation rejected candidate session: <status>"), never the cookie; `humbleAuthState` and login-result payloads stay cookie-free (HumbleAuthState type); test asserts no logger/store call carries the raw cookie |
