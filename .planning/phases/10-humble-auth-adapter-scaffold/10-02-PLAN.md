<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BrowserWindow (humble-login partition) → main process | Cookie extracted from an isolated session partition |
| main process → disk (electron-store) | Encrypted cookie persisted at rest |
| main process → renderer (IPC push) | humbleAuthState pushed — must exclude the cookie |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-04 | Information Disclosure | cookie at rest | mitigate | safeStorage.encryptString + HUMBLE_TOKEN_PREFIX sentinel; on unavailable encryption set user-visible `encryptionDegraded` flag + logWarning (success criterion 5), never silent plaintext |
| T-10-05 | Information Disclosure | logs / IPC payloads | mitigate | Cookie never passed to logger or into humbleAuthState; unit test asserts no logger/configStore.set receives the raw cookie |
| T-10-06 | Tampering / Elevation | cross-domain cookie bleed | mitigate | Isolated `humble-login` partition keeps Humble cookies out of the app's default session (D-07) |
| T-10-07 | Information Disclosure | leftover session on disconnect | mitigate | disconnect() clears all five partition caches + configStore (HACCT-03); reconnect deliberately keeps partition (D-11) |
| T-10-08 | Spoofing | 401 vs 403 on health check | mitigate | Only 401 marks expired; 403 routes to C5 backoff, never a spurious re-login prompt |
</threat_model>
