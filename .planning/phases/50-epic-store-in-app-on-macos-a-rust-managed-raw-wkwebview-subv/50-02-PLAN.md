  <behavior>

    - A main-frame navigation that starts and then neither finishes nor fails within the bound raises the surface's timed-out flag exactly once and enqueues exactly one nav event carrying it.
    - The next main-frame finish OR failure clears the flag and enqueues one nav event carrying it cleared.
    - A navigation that starts while a previous one is still in flight supersedes it: the earlier navigation's deadline no longer applies, and only the newest navigation's deadline can raise the flag.
    - Exactly one monitor thread exists per open surface regardless of how many navigations occur, so a page navigating in a loop cannot spawn threads without bound.
    - The monitor thread exits when the surface is closed; it does not exit on `deselect` or `hide`, because the timer deliberately keeps running while the tab is hidden.
    - No automatic reload, retry or backoff is issued on timeout — the flag is the only effect besides the log line.

  <action>
Add D-05's timeout, D-08's no-silent-retry rule and D-06's transparency to the surface.

**Delegate hooks.** Implement the remaining four `WKNavigationDelegate` lifecycle methods on
`EpicEmbedNavDelegate`: `webView:didStartProvisionalNavigation:`,
`webView:didFailNavigation:withError:`, `webView:didFailProvisionalNavigation:withError:`, and
extend the existing `webView:didFinishNavigation:`. RESEARCH.md confirmed against the vendored
crate's own Apple doc comments that all four are main-frame-only by the delegate contract, so add
no extra frame filtering and do not invent a frame-info parameter they do not carry.

- `didStartProvisionalNavigation`: increment the surface's `nav_generation`, record
  `nav_started_at: Some(Instant::now())`, clear the timed-out flag, clear the challenged flag
  (D-11: every load starts fresh), and enqueue one nav event.
- `didFinishNavigation`: clear `nav_started_at`, clear the timed-out flag, record the new
  `top_level_host`, and enqueue one nav event (Task 1 already enqueues here — extend it).
- Both failure hooks: clear `nav_started_at`, clear the timed-out flag, log the error, and enqueue
  one nav event. A genuine navigation failure is NOT a timeout and must not raise the timeout flag
  — the user gets WebKit's own failure, not the slow-load notice.

**The bound and the monitor.** Declare `EPIC_EMBED_LOAD_TIMEOUT: Duration` as one named constant
set to 45 seconds, with a doc comment recording that 45 s matches this project's existing bound
idiom (Phase 49 D-01), clears nearly every observed healthy cold Epic load (spike: 11 of 16
rendered by 40 s) and surfaces the stopped-document-stream stall well before the 120 s the spike
sampled at.

Spawn exactly ONE monitor thread when a cold `open()` creates the subview, not one per
navigation. Its loop sleeps 1 second, then takes the surface lock and checks: if the surface is
gone, return (the thread exits with the subview); if `nav_started_at` is `Some(t)` and the pure
helper says `t.elapsed()` has reached the bound and the timed-out flag is not already set, set
the flag, log one line, enqueue one nav event, and clear `nav_started_at` so the flag is raised
once per navigation and not once per second. A newer `didStartProvisionalNavigation` has already
overwritten `nav_started_at` and bumped the generation, so an older navigation's deadline simply
cannot fire — which is the supersede rule without a second mechanism.

Choose the polling monitor over a per-navigation timer deliberately and record why: a thread per
navigation is unbounded against a page that navigates in a loop (T-50-07), and a main-thread
`NSTimer`/dispatch timer would add a main-thread lifetime to manage for no benefit. RESEARCH.md
Assumptions Log A3 leaves this primitive to the planner; this is the recorded choice.

**Timer while hidden — the recorded answer to RESEARCH.md Open Question 1:** the timer KEEPS
RUNNING. The monitor does not consult visibility, and `hide()`/`deselect()` do not touch
`nav_started_at`. The consequence is intended: a banner that is already correct the instant the tab
becomes visible again beats a reset that silently extends a real stall. Record this in the module
doc comment and in the SUMMARY so it is a decision, not an accident. Only `close()` ends the
monitor.

**Factor the boundary check as a pure helper** — elapsed duration in, bound in, bool out — with no
`&AppHandle` and no webview, exactly as `store_embed_navigation_policy` is factored, and cover
just-under / exactly-at / just-over in `#[cfg(test)] mod` cases. The real `Instant` and the real
delegate plumbing are not unit-testable in this crate; the decision is.

**Transparency (D-06).** After constructing the webview in `open()`, set it non-opaque so the
styled placeholder shows through the slot until Epic paints. The mechanism is key-value coding on
the webview with the drawing-background key set to a boxed false, reached through `objc2`'s
`msg_send!` because `objc2-web-kit` exposes no typed method for it. Mark the call site
`[ASSUMED]` in a comment that cites RESEARCH.md Assumptions Log A1 verbatim: this is standard
long-documented Apple KVC usage but has no in-repo precedent and no typed binding, and if the key
name or value type is wrong the call SILENTLY NO-OPS rather than erroring, leaving the subview
opaque. State in the same comment that the live gate's cold-jar arm is the measurement (plan 06),
and that if it no-ops the correct response is a todo recording the measurement — not a
first-paint-signal mechanism, which D-06 explicitly rules out as unnecessary.

**Wire type.** Add `loadTimedOut?: boolean` to `StoreEmbedNavEvent` in `storeEmbedSeam.ts`,
documented as present only on `surface: 'epic'` events. In `coerceNavState`, apply the strict
rule: when `surface` is `'epic'` the field MUST be present and boolean; when `surface` is absent or
`'tauri'` the field MUST be absent. Throw with the channel name and the raw response on either
violation. Do not coerce a default — an absent flag on an Epic event would make a dead timer
indistinguishable from a healthy fast load, which is exactly the defect class this file's header
names.
