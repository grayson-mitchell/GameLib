<objective>
Prove this phase's architecture end-to-end on one path before building anything out: on macOS,
`/store/epic` stops landing on `WebviewUnavailablePanel` and instead paints the real Epic Games
Store inside the Stores-tab slot, through a Rust-owned raw `WKWebView` added as a subview of the
main window's content view at the rect `useStoreEmbedHost` already measures for every other store.

Purpose: spike 024 measured that this construction is served (0 of 22 Epic arms challenged, runs
17-27) while the Tauri-managed child webview was challenged alongside it every time. The one thing
the spike did NOT prove is that the construction survives being wired into the shipped embed
contract — the renderer's single geometry oracle, the hide-on-leave lifecycle, the validated
last-URL restore, and the shared default cookie jar. This plan proves exactly that, on the happy
path, before the delegate, the timeout, the challenge fallback and the chrome are built on top.

Output: a new `#[cfg(target_os = "macos")]` Rust module owning the subview's construction and
lifecycle; `storeKey` crossing the existing `store_embed_open` wire so one IPC command family
serves both surfaces; a platform-aware `embeddable` decision; and a darwin-only `/store/epic`
guard. No timeout, no challenge detection, no banner, no toast, and no back/forward reporting —
those are functionality gaps this plan deliberately leaves for plans 02-05, each fillable without
an architectural change.
</objective>

<assumption_delta_decision>
The `assumption-delta scan` detector fired `pluralization` on this phase (signals: "challenged
alongside every time", "a second, Rust-owned WKWebView construction"). A core assumption did lose
its monopoly, and the decision is **split**, recorded here so no later task re-opens it:

**Primary noun: `(store, platform) -> embeddable`.** Decision: **promote**. `storeEmbedOrigins.ts`
today carries `embeddable: boolean` per store — a singular assumption that a store's embeddability
is platform-independent, written when Epic was gated everywhere. Phase 50 makes it false. The
static field is **replaced**, not supplemented: every caller asks the generalized question, and
there is no surviving per-store boolean to read. Task 2 pins this with an invariant test over the
full (store x platform) matrix, so a future phase cannot reintroduce the singular form silently.

**Rust-side surface state: add-alongside, accepted debt.** `StoreEmbedState` (one
`OnceLock<Mutex<..>>`, one `STORE_EMBED_LABEL`) is written assuming exactly one Tauri-managed
webview exists. Rather than generalize it into a surface-keyed map — a refactor across 10 shipped
channels and 58 Rust tests to serve one macOS-only, Epic-only surface — this phase adds a parallel,
explicitly-named `EpicEmbedSurface` and routes on which surface is *selected*. RESEARCH.md Open
Question 2 recommends exactly this to avoid cross-surface state bleed. **What would force a later
promote:** a second raw-subview surface (a non-Epic store needing the raw construction), or Epic on
Linux via a WebKitGTK raw view. At three parallel structs the keyed map wins; at two it does not.

**The IPC command *names* stay shared** (`store_embed_*` with the existing `storeKey` argument as
the discriminator), which is why the renderer keeps ONE geometry owner, ONE nav-poll drain and ONE
validated-restore effect instead of a near-duplicate sibling hook that the reload-loop regression
test would not cover.
</assumption_delta_decision>

Module-level items this task creates:

- `pub(crate) const EPIC_EMBED_STORE_KEY: &str = "epic";`
- `pub(crate) const EPIC_EMBED_NAV_EVENTS_CAP: usize = 50;` — mirror `STORE_EMBED_NAV_EVENTS_CAP`'s

  with an accessor `fn surface() -> &'static Mutex<EpicEmbedSurface>` mirroring
  `store_embed_state()`. Fields this task needs: `webview: Option<SendPtr>` (the retained
  `WKWebView`), `delegate: Option<SendPtr>` (the retained delegate, deliberately leaked for the
  process lifetime exactly as `EpicPristineNavDelegate` is), `selected: bool`,
  `top_level_host: Option<String>`, `pending_nav_events: Vec<Value>`. Reuse `main.rs`'s existing
  `SendPtr` newtype if it is reachable from a sibling module; if it is private, declare an
  identical `SendPtr` in this module with the same SAFETY comment (a raw pointer that only ever
  crosses a channel or a mutex and is only ever dereferenced back on the main thread).
- `pub(crate) fn is_selected() -> bool` — true when a subview exists AND `selected` is set. Fails
  CLOSED on a poisoned lock (returns false), so a poisoned mutex routes to the Tauri embed rather
  than to a surface whose state cannot be read.
- `pub(crate) fn open(app: &AppHandle, url: &tauri::Url, x: f64, y: f64, w: f64, h: f64) -> Result<Value, String>`

- `pub(crate) fn close(app: &AppHandle) -> Result<Value, String>`
- `pub(crate) fn deselect(app: &AppHandle) -> Result<Value, String>` — hides the subview and clears

- `pub(crate) fn take_nav_events() -> Result<Value, String>` — drains `pending_nav_events`.
- A minimal `EpicEmbedNavDelegate` via `define_class!`, with ivars holding only what this task
  needs, implementing `NSObjectProtocol`, `WKNavigationDelegate`'s
  `webView:decidePolicyForNavigationAction:decisionHandler:`, and
  `webView:didFinishNavigation:`. The action hook parses the request URL into a `tauri::Url` and
  calls `main.rs`'s existing `store_embed_navigation_policy(&url, top_level_host.as_deref())`,
  mapping `Allow` to `WKNavigationActionPolicy::Allow` and both `Block` and `Handoff` to `Cancel`
  (the Epic surface's top-level host is never a Valve host, so `Handoff` is unreachable here —
  log and cancel rather than silently allowing). `didFinishNavigation` records the webview's
  current `URL()` host into `top_level_host` and enqueues one nav event built from the native
  `canGoBack()`/`canGoForward()`/`URL()` values, with the same four JSON field names
  `store_embed_nav_state_json` emits plus the new `surface` field (see step 4). Plans 02 adds the
  remaining delegate methods; this task adds no others.

`open()` is idempotent create-or-navigate, marshalled exactly like
`open_pristine_epic_login_window`: the calling (worker) thread builds an `mpsc` channel, calls
`app.run_on_main_thread(..)` with a closure that does every unsafe objc2/AppKit/WebKit call, and
blocks on `rx.recv_timeout(Duration::from_secs(10))`. Inside the main-thread closure, on a cold
open:

- `objc2::MainThreadMarker::new()`, erroring `epic_embed_open:not-on-main-thread` if absent.
- `app.get_window(MAIN_WINDOW_LABEL)`, erroring `epic_embed_open:no-window:{label}`.
- `window.ns_view()`, then resolve and `Retained::retain` immediately on this thread before parking
  anything — the pointer is autoreleased and is not a stable handle.
- Convert the renderer's rect to AppKit coordinates with the spike's own conditional: use `y`
  directly when the content view reports a flipped coordinate system, otherwise
  `bounds.size.height - y - h`. Port that conditional; never hardcode one orientation (RESEARCH
  Pitfall 5).
- `WKWebViewConfiguration::new(mtm)`, then `setWebsiteDataStore` with
  `WKWebsiteDataStore::defaultDataStore(mtm)` — the shared process-wide jar every shipped embed and
  login window already runs on (L-3). Do not reach for the spike's ephemeral variant, and do not
  partition this surface with a per-store data-store identifier.
- `WKWebView::initWithFrame_configuration(mtm.alloc(), frame, &config)`. Make no custom
  user-agent call at all and never reference the Tauri embed's Chrome UA constant (L-4). Add no
  user-content controller, no init script, no message handler and no scheme handler (spike 024
  established #7 — this absence is the whole point of the construction).
- Attach the delegate with `setNavigationDelegate`, retaining it in the surface struct so it
  outlives the closure.
- `ns_view.addSubview(&webview)`. Set no autoresizing mask: the renderer's `set_bounds` IPC is the
  sole geometry authority (D-18, RESEARCH Pitfall 4).
- `NSURL::URLWithString` + `NSURLRequest::requestWithURL` + `webview.loadRequest(&request)`.
- Park the retained webview and delegate pointers in the surface, set `selected = true`, and
  enqueue one nav event.

On a warm open (a subview already exists): `setHidden(false)`, apply the rect via the same path
`set_bounds` uses, navigate to `url` if it differs from the current `URL()`, set `selected = true`,
enqueue one fresh nav event, and return. Enqueueing on select is what makes the chrome correct the
instant the user returns.

`hide()`/`show()` are `setHidden(true)`/`setHidden(false)` on the main thread. A hidden subview
must be neither visible nor hit-testable — `setHidden` gives both. `close()` calls
`removeFromSuperview()` (the spike's own teardown at its line 474), drops the parked pointers and
clears `pending_nav_events`, mirroring `StoreEmbedState::clear`'s D-21 discipline. `deselect()`
hides and clears `selected` and clears `pending_nav_events` without removing the subview.

Every one of these functions returns a named, logged error on the failure paths rather than
panicking or returning silently.
