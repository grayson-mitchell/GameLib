<objective>
Build the glossary-aware machine-fill script that translates `en/gamelib.json` into any locale —
built and unit-proven here, deliberately NOT bulk-run.

Purpose: D-08 is explicit that 34.8 ships the script as a repeatable `pnpm` task and proves it on
one or two locales; bulk-filling all 48 becomes a separate, revertible commit runnable at any
time. The reason is blast radius — any script bug in a bulk run ships to 48 files at once, and
the phase's actual compliance bar is "no hardcoded strings + `en` coverage", with machine-fill as
polish layered on top.

The interesting engineering is not the API call; it is the D-09 contract (fill only missing keys,
never overwrite a non-empty value, preserve interpolations and plural suffixes) and the D-10
provenance manifest that makes a future Weblate import correct. Both are pure logic and both get
hermetic tests with an injected fake translator.

Output: `meta/machineFillGamelib.ts`, its test suite, and a `pnpm` script entry.
</objective>

Catalog file layout: `public/locales/<locale>/gamelib.json`, sidecar
`public/locales/<locale>/gamelib.mt.json`. 49 locale directories exist (48 non-English).

Empty values in `en/gamelib.json` are EXPECTED, not a defect: the parser writes
`defaultValue: ''` and the app falls back through `t(key, 'English default')` because
`fallbackLng: 'en'` and `returnEmptyString: false`. So the English SOURCE for a key may need to
come from the inline `t()` default rather than the catalog value — handle both.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo catalog text → third-party translation API | Developer-authored UI copy leaves the machine over the network |
| API response → committed catalog → rendered UI | Model output becomes UI text in 48 languages |
| `ANTHROPIC_API_KEY` → process environment | A live credential in the developer's shell |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.8-33 | Information Disclosure | catalog text sent to an external API | mitigate | Only `en/gamelib.json` values and upstream-catalog translation-memory pairs are sent — all developer-authored UI copy; no user data, credentials, paths or telemetry ever flow through `gamelib.json`. The SUMMARY must state which files were read as request input. |
| T-34.8-34 | Information Disclosure | API key leaking via shell history, process listing or logs | mitigate | Key read from `process.env` only, never a CLI flag (the `verifyUpdaterSigningKey.ts` convention, with its rationale comment copied); never logged; request bodies not logged |
| T-34.8-35 | Tampering | prompt/content injection — model output introducing markup, placeholders or scripts that render in the UI | mitigate | `validateTranslation` rejects any target that adds a placeholder the source lacks, drops one it has, or loses a glossary term; a failing key is left UNFILLED and reported rather than written. Plan 09's `lintTranslations` gamelib scope adds the content-less-tag mismatch check over the committed result. |
| T-34.8-36 | Tampering | a bug shipping to 48 locale files in one run | mitigate | `BulkRunRefusedError` by default; `GAMELIB_MT_LOCALES` must name locales explicitly; `GAMELIB_MT_CONFIRM_BULK=1` is a deliberate typed opt-in; D-08 keeps the bulk run as a separate revertible commit |
| T-34.8-37 | Tampering | overwriting a human translation with machine output | mitigate | `mergeFill` builds from the target and adds only `missing` keys; the `gamelib.mt.json` manifest distinguishes MT-origin keys from human ones on re-run; a dedicated `never overwrites` test fixture proves it |
| T-34.8-38 | Tampering | writing into upstream-owned catalogs | mitigate | Upstream catalogs opened read-only; acceptance criteria assert no write call names them; plan 09's `assertNoUpstreamChurn` is the CI backstop |
| T-34.8-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages — the API call uses the already-present `axios` or Node's built-in `fetch` (Node ≥22). If the executor concludes a new SDK package is required, STOP and raise a blocking-human legitimacy checkpoint before installing. |
</threat_model>
