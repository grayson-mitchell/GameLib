## pnpm i18n blast radius

**Framing:** `i18next-parser.config.js:39` sets `keepRemoved: false`, so `pnpm i18n` deletes any key
the static lexer cannot see — pruning upstream keys referenced dynamically or through aliased `t`,
i.e. churning the exact files the phase promises not to touch.

| Option | Description | Selected |
|--------|-------------|----------|
| Flip `keepRemoved` to true | One-line config change; parser only ever ADDS. Fork strings are `gamelib:`-prefixed so upstream namespaces receive nothing. Cost: dead upstream keys stop being auto-pruned. | ✓ |
| Second fork-only parser config | `i18next-parser.gamelib.config.js` with input scoped to fork files. Stronger isolation, but mixed files contain upstream `t()` calls too, needing namespace filtering. | |
| Run as-is, audit and revert | No config change; manually revert upstream hunks each run. Works against making the sync repeatable. | |

**User's choice:** Flip `keepRemoved` to true
**Notes:** → D-03.

| Option | Description | Selected |
|--------|-------------|----------|
| Superseded — gamelib namespace replaces it | ROADMAP item (3) becomes "generate en/gamelib.json repeatably"; the three upstream en catalogs go fully out of scope. | ✓ |
| Both — also backfill upstream en catalogs | Honors the ROADMAP text literally, but writes to the three files the phase promises not to churn. | |

**User's choice:** Superseded
**Notes:** The fork-namespace decision (2026-08-06) postdates ROADMAP.md:2204-2205. → D-04.

| Option | Description | Selected |
|--------|-------------|----------|
| Yes — assert byte-identical in the gate | CI fails on any change under `public/locales/` outside `*/gamelib.json`. Catches a mis-namespaced `t()` writing into `translation.json`. | ✓ |
| No — convention plus review is enough | Relies on `gamelib:` prefix discipline and PR review. | |

**User's choice:** Assert byte-identical
**Notes:** → D-05. Became the backstop that lets the gate stay namespace-agnostic (D-13).

## Migrate already-translated fork keys?

**Framing (measured mid-discussion):** `en/translation.json` has 80 Steam-mentioning lines and
`en/gamepage.json` has 54 — a population of fork keys already lives in the upstream namespaces,
colliding with the byte-identical gate just approved.

| Option | Description | Selected |
|--------|-------------|----------|
| Leave them — only new retrofits go to gamelib | Zero upstream churn; gate switches on immediately with no exception window. Cost: permanent split-brain, must be documented. | ✓ |
| Migrate all fork keys to gamelib | Ideologically clean, trivially safe upstream merges. But a large deletion diff, and the gate must allow one migration commit then clamp shut. | |
| Measure first, decide in planning | 80/54 is an upper bound including Heroic's own Steam-shortcut strings. Get an exact count before choosing. | |

**User's choice:** Leave them
**Notes:** → D-06. Migration moved to Deferred Ideas, revisit only if the split-brain becomes a real
maintenance cost.

| Option | Description | Selected |
|--------|-------------|----------|
| Diff against the upstream Heroic remote | Mechanical, exact, re-runnable on every upstream sync; reusable as the gate's allowlist source. | ✓ |
| Git blame / commit authorship | Blurred by the fork's substantial history rewriting across the Tauri phases. | |
| Manual list from the 2026-08-05 audit | Fastest, but a point-in-time sample naming examples with "etc." — can't safely drive scope. | |

**User's choice:** Diff against the upstream Heroic remote
**Notes:** → D-07.

| Option | Description | Selected |
|--------|-------------|----------|
| Gate checks literals only, not namespace | Any `t()` call passes. Avoids false positives against the split-brain and against legitimate upstream-key reuse. | ✓ |
| Gate also enforces `gamelib:` on fork files | Stronger guarantee the split-brain never grows, but needs a reliable fork-file list and flags legitimate reuse. | |

**User's choice:** Gate checks literals only
**Notes:** → D-13. Namespace discipline backed mechanically by D-05 instead.

## Gate strictness + CI wiring

**Framing (measured mid-discussion):** `lint-translations` appears in no CI workflow. Three
candidate hosts exist: `lint.yml`, `test.yml`, `codecheck.yml`.

| Option | Description | Selected |
|--------|-------------|----------|
| Blocking from day one | No grace period. Viable because the split defers the two hard files behind an explicit allowlist. | ✓ |
| Advisory first, flip later | Lower risk of stalling unrelated PRs, but "flip it later" is an unowned promise. | |

**User's choice:** Blocking from day one
**Notes:** → D-12. Rationale: an advisory gate nobody fails is the exact failure mode this phase
exists to prevent — hardcoded constants already shipped once.

| Option | Description | Selected |
|--------|-------------|----------|
| Scope catalog checks to gamelib.json only | Signal stays 100% actionable; the fork can't fix Weblate-sourced upstream defects anyway. | ✓ |
| Run over all namespaces, allowlist current failures | Catches upstream regressions, but the baseline needs regenerating on every upstream sync. | |
| Leave lintTranslations out of CI entirely | Smallest change, but nothing checks that en/gamelib.json stays well-formed. | |

**User's choice:** Scope to gamelib.json only
**Notes:** → D-15.

| Option | Description | Selected |
|--------|-------------|----------|
| Allowlist entries that fail once the file is compliant | Expected violation counts; gate fails with "stale exemption" when a count hits zero. Exemption cannot outlive its reason. | ✓ |
| Plain allowlist plus a TODO comment | Readable, but a comment enforces nothing — entries survive indefinitely. | |
| Deferred-items ledger entry instead | Consistent with existing debt tracking, but a document can't fail a build. | |

**User's choice:** Stale-failing allowlist entries
**Notes:** → D-18.
