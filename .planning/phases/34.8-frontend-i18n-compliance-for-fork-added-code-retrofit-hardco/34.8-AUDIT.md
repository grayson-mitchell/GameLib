### First Raw Run (superseded by the fix below — kept here for the audit trail)

The very first `scanScope()` run at `2710e8f9d23fafdac83e5963862c3022793c4887` (before any
plan-06 changes) reported `scannedFiles=134`, `totalCandidates=2050`, `violations.length=335`.
Reading a representative sample of those 335 raw hits (documented file-by-file during this task)
showed the gate was flagging things far beyond what D-16/D-15 intend as "hardcoded, user-facing
string literals" — including several cases where the source code was **already correctly
internationalized** and the gate simply could not see it:

- `TauriLoginPanel.tsx` alone contributed **20** of the 335 raw hits — every single one already
  routed through `t(key, runnerLabel ? \`Signing in to ${runnerLabel}\` : 'Signing in')`-shaped
  calls (a ternary or `+`-concatenated default-text argument), which `isTCallArgument` could not
  see because the string is one AST hop away from being a *direct* call argument.
- `SteamBottleSetup.tsx`/`SteamBridgeSetup.tsx`/`SteamClientSetup.tsx` used
  `t(key, { defaultValue: '...', ...vars })` — react-i18next's own interpolation idiom — which is
  a different AST shape again (the string is a property of an object literal, not a direct
  argument).
- `EmptyLibrary/index.tsx`, `GamePage/index.tsx`'s wikiLink, `DownloadDialog/index.tsx`'s
  anticheat warning, and `WineSelector/index.tsx` (x2) all use react-i18next's `<Trans
  i18nKey="...">English text<Link>...</Link></Trans>` component — a *different, equally valid*
  i18n mechanism from `t()` that the gate had no concept of at all.
- A large volume of CSS custom-property values (`var(--accent)`, `--primary-font-family`,
  `2px`, `blur(10px)`) used programmatically (MUI `createTheme()`, `getComputedStyle()`,
  `element.style.setProperty()`, a `getStatusColor()`-style helper) rather than through a literal
  `style={{}}` JSX attribute, so plan 05's `isStyleAttributeValue` fix never saw them.
- Several further narrower categories: `KeyboardEvent.key` comparisons (`e.key === 'Escape'`),
  `classNames()`-call/ternary/template-interpolated `className` values, `<InfoBox text="...">`'s
  own i18n-key-forwarding prop, electron-store key arguments
  (`configStore.get('games.hidden', [])`), and a bracketed CSS attribute-selector shape
  (`[data-tour="..."]`).

Per this plan's threat register (T-34.8-15) and D-15's "100% actionable" requirement for gate
trust, publishing a 335-item backlog that included dozens of already-compliant call sites and
internal technical constants — asking plans 07/08 to literally wrap `'Escape'` or `'MESSAGE'` in
`t()` — would have been a materially wrong deliverable, not merely a noisy one. Per Rule 1 (bugs
in scanner logic are auto-fixed, no permission needed) and the direct precedent plan 05 already
set in this exact file (finding and fixing 2 scanner false-positive categories *while performing
its own required measurement task*), these 9 categories were fixed in
`fix(34.8-06): fix 9 hardcodedStringGate false-positive categories found by the whole-scope
audit` (`0399c505a`), with 40 new regression tests (`meta/__tests__/hardcodedStringGate.test.ts`,
77 → 117 tests, all green) and a glossary extension (`glossary(...)` — see `meta/i18nGlossary.json`
diff) for 9 further brand/platform short-forms the audit surfaced (`Mac`, `Win32`, `Android`,
`Browser`, `EA app`, `Epic Games`, `ZOOM Platform`, `GE`, `CachyOS`). Full `meta` jest project
green (117/117) both before and after; full `pnpm test:ci` green (199 suites / 3965 tests,
baseline 199/3921 — no regressions) after. **This fix work is itself the deliverable of Task 1's

## Triage

**A note on dispositions before the table:** this plan's `<interfaces>` block declares exactly
four disposition values (`retrofit`, `glossary`, `file-exemption`, `deferred`). Auditing the
whole scope surfaced a fifth, real category the plan's design did not anticipate: a violation
that is **not genuinely user-facing prose at all** — an internal enum discriminator (`'MESSAGE'`,
`'ERROR'`, `'REDEEMED'`), a storage/URL/User-Agent constant, an icon-size or srcSet descriptor, a
diagnostic-only value, or (for `StoreSearch/helpers.ts` and `TauriLoginPanel.tsx`'s two remaining
items) code that IS already correctly routed through `t()` but through a dataflow chain one layer
deeper than this plan's scanner fixes trace (documented per-row below). None of the four declared
values fits: `retrofit` is explicitly "genuine user-facing prose" (these are not), `glossary` is
explicitly "a brand, store, platform or unit name" (these mostly are not), `file-exemption` is
scoped to `bootErrorSurface.ts`, and `deferred` is scoped to the two named D-17 files. Forcing
these into `retrofit` would corrupt plans 07/08's backlog with genuinely wrong work (wrapping
`'Escape'`/`'MESSAGE'` in `t()`); forcing them into `glossary` would pollute the do-not-translate
list with non-brand internal constants. This document therefore uses a fifth, explicitly-labelled
value, **`not-user-facing`**, for exactly this category — recorded here as a documented deviation
(Rule 2: a triage document without a way to record "this was never a real violation" is missing
something critical for the correctness of the resulting backlog), not silently substituted for
one of the four. **No `not-user-facing` row appears in `## Retrofit Backlog`.**
