## How this closes 08b's `blocked` item

08b recorded this item `blocked` because fixing it the way every other retrofit in this phase
was fixed — wrapping the string literal itself in `t()` — would have required converting
`defaultWineVersion` from a plain constant into a `t()`-requiring function/hook call, which would
touch all 14 out-of-scope consumer files (`AdvertiseAvxForRosetta.tsx`, `AutoDXVK.tsx`,
`AutoDXVKNVAPI.tsx`, `AutoVKD3D.tsx`, `CrossoverBottle.tsx`, `DisableUMU.tsx`,
`EnableDXVKFpsLimit.tsx`, `EnableMsync.tsx`, `PreferSystemLibs.tsx`, `SteamRuntime.tsx`,
`WinePrefix.tsx`, `WineVersionSelector.tsx`, `sections/GamesSettings/index.tsx`,
`sections/SyncSaves/index.tsx`) and, per the orchestrator's independent re-verification, is
unnecessary — of those 14, only three (`AutoDXVK.tsx:27`, `EnableDXVKFpsLimit.tsx:27`,
`EnableMsync.tsx:18`) even read `.name`, and every one of those three calls is
`wineVersion.name.endsWith('-DXMT')`, an internal comparison, never rendered.
`WineVersionSelector.tsx` is the ONLY consumer that renders `.name` — confirmed again by this
plan before touching anything.

This plan closes the item at that ONE real render site instead: **`WineVersionListItem`** (in
`WineVersionSelector.tsx`) is the single component MUI's `Select` uses to render both the
collapsed `SelectField`'s selected-value display and every open dropdown `MenuItem` (no
`renderValue` prop is set on `SelectField`, confirmed in
`frontend/components/UI/SelectField/index.tsx` — MUI falls back to rendering the matching
`MenuItem`'s children). Fixing `WineVersionListItem` fixes both display sites from one edit.

`defaultWineVersion`'s declaration itself is untouched at the VALUE level — its `bin`/`name`/
`type` strings remain byte-identical, preserving persisted-config compatibility for the 14
consumers — but is no longer flagged by the gate because it now carries `34.8-08c`'s new
declaration-scoped `i18n-gate-exempt:` marker (`meta/hardcodedStringGate.ts`'s
`checkDeclarationExemptMarker`), which exempts only that ONE top-level statement, not the whole
file. This is a genuinely different claim from 08b's original `blocked` reasoning — 08b treated
the definition literal as needing translation-or-defer; this plan established that the definition
literal never needs to be user-facing text at all once the render site translates its own
display, so exempting the definition (with its reason on record) is correct, not a workaround.

## The render-site fix

`WineVersionListItem` gained its own `useTranslation('gamelib')` hook (`WineVersionSelector`'s
default export already has one; `WineVersionListItem` is a separate component and needed its
own). `substitutedName`'s computation now branches: when `name === defaultWineVersion.name`, it
returns `tGamelib('gamelib:settings.wineDefaultLabel', 'Wine Default')` — falling through to the
byte-identical `'Wine Default'` string under any i18n setup with no `gamelib:` catalog entry for
this key, so the rendered text is unchanged for every user until a real translation is added.
For any OTHER `version.name` (a real installed Wine/Proton build), the existing
`name.replace(/(Proton-GE-Proton|Proton-GE)/, 'GE-Proton')` substitution is unchanged, byte-for-
byte, from before this plan.

The two MUI `value` props (`SelectField`'s `value={wineVersion.name}` and each `MenuItem`'s
`value={version.name}`) were deliberately left untouched — these are internal identifiers used
for selection matching and the `onChange` filter (`altWine.filter(({ name }) => name ===
event.target.value)`), not display text, and translating them would break selection.

## The declaration-scoped exemption

`Settings/index.tsx`'s `defaultWineVersion` declaration now carries a `/** ... */` block comment
directly above it (no blank line, so ts-morph associates it as the statement's own leading
trivia) whose first content line is `i18n-gate-exempt: 'Wine Default' is a persisted-config
fallback sentinel, not rendered directly` — the marker plus a non-empty same-line reason,
matching `checkDeclarationExemptMarker`'s requirement exactly. Because `defaultWineVersion` is
NOT the file's first statement (five `import` statements precede it), this marker reaches the
NEW declaration-scoped check (`meta/hardcodedStringGate.ts`'s task-1 addition), not the existing
whole-file `checkFileExemptMarker` — confirmed directly below in "Post-retrofit measurement":
`report.fileExempt` still contains exactly one file, `bootErrorSurface.ts`, proving
`Settings/index.tsx` was never blanket-exempted.
