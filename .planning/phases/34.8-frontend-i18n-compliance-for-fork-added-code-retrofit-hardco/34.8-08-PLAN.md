<interfaces>
<!-- The two call shapes, both already established in this repo. -->

Inside a React component (has `useTranslation` in scope) — the `CrossoverBadge.tsx` form:
  `const { t } = useTranslation('gamelib')` then `t('gamelib:library.someKey', 'English default')`
  A second hook call may be aliased, as `GameCard/index.tsx:105` already does with `t2`.

Inside a non-component module (no hook available) — the `repairFailure.ts` form adopted by plan
07 for `copy.ts`: add `t: TFunction` as a parameter and thread it from the calling component.
Prefer this over `import { t } from 'i18next'` at module scope, because a lazily-loaded
`gamelib` namespace is not guaranteed resolved for a bare module-scope `t()` call, whereas a
component's `t` is Suspense-gated.

Key convention: `gamelib:<feature>.<slug>`, `keySeparator: '.'`, `namespaceSeparator: ':'`.
Every call is TWO-argument `t(key, 'English default')`, never bare `t(key)`.

Namespace choice is NOT enforced by the gate (D-13) — but new fork strings go in `gamelib`, and
plan 09's D-05 no-churn assertion is the mechanical backstop that catches a mis-namespaced call
writing into an upstream catalog.
