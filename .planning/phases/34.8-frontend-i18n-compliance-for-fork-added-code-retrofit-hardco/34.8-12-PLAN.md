<objective>
Prove the two things this phase cannot prove with unit tests alone: that the machine-fill script
produces correct output on real locale data, and that the `gamelib` namespace actually loads at
runtime on BOTH shells.

Purpose (D-08): correctness on real catalog data — interpolations, plural siblings, glossary
terms, and translation memory drawn from Heroic's existing locale files — is only observable by
running the script and reading the result. Two locales, not 48.

Purpose (D-01 / runtime): namespaces load lazily through `i18next-http-backend` with no `ns`
array, and both Electron and Tauri serve the identical Vite-built `build/` tree
(`frontendDist: "../build"`, no `publicDir` override). That reasoning was verified against
config — but the `publicDir` / `getAppPath` divergence under the Tauri sidecar has bitten this
project FOUR times, most recently killing Phase 34.5's gate. A `gamelib.json` that 404s under
Tauri would be a SILENT phase failure: every string would fall back to its English default and
look perfectly fine in English. Only a real launch on both runtimes proves the fetch path.

Output: two filled locales with provenance sidecars, an automated parity test, and
`34.8-RUNTIME-CHECK.md`.
</objective>
