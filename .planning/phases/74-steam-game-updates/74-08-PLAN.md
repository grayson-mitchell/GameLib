<decisions>
- Hand-off URI (Claude's discretion, D-12): `steam://nav/games/details/<appId>` opens the game's page in the Steam library, which is where Steam shows its Update button for a pending update. `steam://install/<appId>` was rejected: on an installed app its behaviour is unverified and it is the install verb. RESEARCH A1 marks both unverified, so plan 13 live-checks the details URI on macOS and records Windows/Linux as an optional item.
- Completion test for an update poll: `readAcfUpdateState` shows `isAcfUpdatePending(f) === false` AND (stateFlags & 4) set. Bit 4 alone is never completion (StateFlags 6 = installed + update required).
- Progress for an update poll: reuse the delegated-native path's live download monitor (`isLiveMonitorEligible` / `deps.steamProcesses.downloadMonitor`, spike 050: nettop beats the ACF) by also passing `delegatedToSteamClient: true`; the ACF BytesDownloaded/BytesToDownload is the fallback percent. Status sent is 'updating' (not 'installing') with managedBySteam true.
- No-activity: an awaitingUpdate poll replaces the delegated "revert with sign-in notice" rule with a quiet stop after STEAM_REQUEST_NO_ACTIVITY_TICKS without any update activity (flags 0x2 with growing bytes, or bits 0x100/0x400 set), sending one 'done' status; is_installed is never flipped.
- Running refusal: `readRunningAppId(...) === appId` -> `{status: 'error', error: i18next.t('gamelib:steam.update.refusedRunning', ...)}` (key added by plan 09).
</decisions>
