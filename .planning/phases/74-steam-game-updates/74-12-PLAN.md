<decisions>
- No UI-SPEC (operator choice). Visual rules from sketch-findings: reuse the GamePage `iconWithText` info-row markup and existing classes; any new style uses tokens only (`--brand-primary` for the "Show update size" link/accent, `--neutral-05` for muted estimate text), 6px control radius, transitions .12s–.22s ease; never hardcode the cyan (multi-theme survival).
- Size copy: when oldManifestAvailable, the disk number is exact and the download is an upper bound -> `game.update.sizesEstimate`; when the old manifest is gone -> `game.update.fallback` plus the sizes line. `isEstimate` is always true for the download, so the "(estimate)" form is the one shown.
- Confirmation flow (bridge only): open the dialog immediately with `game.update.checkingSize`, call getSteamUpdateInfo(appId, {computeSize: true}), then replace it (showDialogModal queues; close the checking dialog by showing the result dialog per the uiState reduceDialogRequest semantics — read it) with: sizes line + [Update (onConfirm), Cancel]. If `estimate.freeBytes` is defined and below `peakBytes`, show `game.update.notEnoughDisk` with only [OK] and never call onConfirm (D-13); the backend repeats the check at start. On sizeError: show the error text with [Update anyway (onConfirm), Cancel] (the backend recomputes).
- Registered games: GamePage/GameCard call updateGame directly; SteamUpdateInfo shows `game.update.registered`.
</decisions>
