update to unattended (WR-03), fix the unattended failure log (IN-05), and fold in the trivially
co-located half of todo `2026-11-13-auto-update-requeue-churn-and-double-detection.md`.

path raises no error dialog", is already true after 74-19 (an unattended failure shows the queue's
OS notification only, no dialog); confirm with the existing updateBridge test named "unattended
refused lease: error result, one log line, no dialog". With all three covered, the todo moves to
completed.

`done`) is not taken: the backend marker breaks the loop whatever the frontend does, and the
frontend status carries no unattended flag.

Purpose: D-01 auto-update must not cost two OS notifications plus a detection pass per cycle forever
when a bridge update cannot run unattended.
Output: autoUpdateAttempts module, marker wiring, one-detection listing, queue-aware autoUpdate.

The loop (74-REVIEW CR-02): autoUpdate queues `{ unattended: true }` -> updateQueueElement sends
'updating' -> the bridge update fails fast (Keychain gate locked) -> finally sends 'done' -> the
frontend's done-after-updating calls refreshLibrary({ checkForUpdates: true }) -> checkGameUpdates
-> listAutoUpdateableGames still lists it -> autoUpdate re-queues it -> repeat.

src/backend/utils/checkGameUpdates.ts: per runner, `badge = await listUpdateableGames()`, then
when autoUpdateGames is on `autoSource = await listAutoUpdateableGames()` and
`autoUpdate(runner, autoSource.filter((a) => badge.includes(a)))`. It is the only caller of
listAutoUpdateableGames.

src/backend/storeManagers/steam/library/index.ts (lines ~297-320): `listUpdateableGames()` ->
`staleAppIds()`, `listAutoUpdateableGames()` -> `staleAppIds('bridge')`; staleAppIds calls
`detectSteamUpdates(this.deps)` each time (two detection passes per refresh).

src/backend/storeManagers/steam/games.ts `async update(overwrites?: { unattended?: boolean })`
(line ~451): attended calls `noteSteamAuthTrigger('user-install')`; bridge installs go to
`updateBridgeGame(this, { unattended: true })` or `updateBridgeGame(this)`; registered unattended
returns abort (D-02).

src/backend/storeManagers/steam/updateBridge.ts `runBridgeUpdate(steamGame, title, unattended)`:
`logUnattendedFailure(reason)` logs "unattended=true update not started: <reason>"; called for the
estimate error (line ~148) and for `downloadSteamDepotsRust` returning error (line ~201, after the
job ran). Not called for: the context error (`resolveBridgeUpdateContext`), the
branch-unresolved refusal, the disk-space refusal. `updateBridgeGame` also returns an error early
when the game is running (isRunning).

src/backend/storeManagers/index.ts `autoUpdate(runner, gamesToUpdate)` builds
`buildUpdateQueueElement(gameInfo, appName, { unattended: true })` and calls
`deps.getDownloadQueue().addToQueue(el)`. downloadqueue.ts `addToQueue` replaces an existing
element for the same app/runner in place. `getQueueInformation()` returns `{ elements, finished,
state }`; the running element stays at index 0 of `elements` until it finishes.

getLastKnownSteamUpdateState(deps, appId) (updateDetection.ts) returns the cached
SteamUpdateState (`kind`, `state`, `targetBuild?`). SteamInstallRuntime (steamInstallRuntime.ts)
is a plain object of per-boot closure state built by createSteamInstallRuntime; tests build it via
src/backend/testUtils/testSteamInstallRuntime.ts (which calls the real factory, so no edit there).
