<decisions>
- Ack storage (Claude's discretion, D-06): a dedicated per-boot-injected CacheStore in the steam store family (analog: steamRestartHoldStore + restartHoldStoreFrom), value = acknowledged target build id string per appId. Not GamesConfig/<appId>.json: bridge games' settings are split between title file and bottle (titleSettings.ts) and an ack is state, not a setting.
- Prompt widget: the backend native `deps.dialogs.showMessageBox` with THREE buttons [0 "Update now", 1 "Play anyway", 2 "Don't ask again for this build"], defaultId 0, cancelId 1. A checkbox is not usable: the native shim hard-codes `checkboxChecked: false` on every return (appShellFlowRegistration.ts ~:578, quick 260919-sch). Button 2 records the ack and launches. Closing the dialog = Play anyway (the user pressed Play).
- Placement: in gameLaunch.ts immediately before `return launchBridgeGame(steamGame)` (:136), outside `bridgeLaunchesInFlight`, so a dialog wait never holds the G26 dedupe entry. The dispatcher's single-flight (launchDispatch.ts) still covers the dialog: a second Play while the dialog is open joins and shows the existing "already starting" notice — accepted.
- Timeout (Claude's discretion, D-05): 3 s via detectSteamUpdates({appIds:[appId], force:true, timeoutMs: STEAM_UPDATE_PRELAUNCH_TIMEOUT_MS}); detection already falls back to last-known/unknown, and gateBridgeLaunchOnUpdate wraps it in its own try/catch -> 'launch'.
- Interrupted-commit guard: readAcfUpdateState(deps, appId, 'bridge') with (stateFlags & 4) === 0 -> notify `steam.update.prompt.finishFirst` and return 'abort'.
- If an 'update' element for this app is already queued or running, skip the prompt and launch the current build (the user already chose to update).
- 'abort' makes SteamGame.launch return false; check the frontend's handling of a false launch for Steam (it must not show a generic launch-failed error for this case; if it does, send the same status reset the dispatcher sends for a launch that never started).
</decisions>
