<decisions>
RESUME DISCRIMINATOR (RESEARCH Open Question 1 / A3), decided here:
- Read before deciding: `src/backend/storeManagers/steam/library/resume.ts` runs a verify_only
  job only for NATIVE downloading ACFs found by `scanDownloadingAppIds` over `getSteamLibraries`
  roots. Bridge ACFs live in the bridge bottle's steamapps and are never scanned, and the delta
  never writes a partial ACF before commit, so Phase 73's startup resume cannot "repair" a
  half-updated bridge tree back to the old manifest. No marker in the ACF is needed.
- The discriminator is a Rust-owned journal file `<finalize.steamapps_dir>/gamelib-delta/<appId>.json`
  (appId numeric-guarded; directory created 0700 on unix). Content: `{"appId", "newGids":{depot:gid},
  "oldGids":{depot:gid}, "retired":[depotId...], "startedAt": unix secs}`. Written via temp + fsync +
  rename BEFORE the first commit rename; deleted after finalize succeeds.
- Job start, delta shape, journal present:
  - journal.newGids equals the job's {depot: manifest_id} map and oldGids equals the job's
    fromManifest map -> COMMIT-RESUME: re-plan from the old manifests (cached), but for each
    work-set file first `sha1_file(target)`; equal to new sha_content -> already committed, skip;
    otherwise build it as in plan 01 (local candidates whose file was already replaced simply fail
    their SHA-1 check and go to the CDN, so correctness needs no extra state). Removed/retired
    deletes are idempotent. DeltaReport.mode = commit_resume.
  - journal present but GIDs differ (a newer build shipped between attempts) -> FILE_FALLBACK
    against the new manifest (the tree is mixed old/mid, only a full sha1 reconcile is safe), and
    delete the journal after that job completes.
- No journal: fresh delta as in plan 01; stale `*.gamelib-delta-tmp` files for work-set paths are
  deleted before building (an abort before commit, or a pause, leaves only temps).
- Hashing every work-set target on a FRESH run would cost ~13 GB of reads on Manor Lords, which is
  why the journal gates the "already new?" check.

ACF POLICY:
- Failure/cancel before the first rename: ACF untouched (plan 01 behaviour, unchanged).
- Failure/cancel after the first rename: call finalize with a RunResult carrying the failures (or
  outcome Cancelled) so can_write_full_ownership is false and it writes "1026", and pass the OLD
  GIDs as `attempted` depots so InstalledDepots still names the old manifests. TS (plan 10) reads
  fromManifest from the ACF on resume, so the retry sends the same old GIDs and the journal matches
  -> commit-resume, not an expensive file-level fallback. Keep the journal; DeltaReport.committed =
  false. Plan 09 refuses Play on a bridge ACF without bit 4 with a "finish the update" notice.

D-14 FALLBACK:
- Old manifest load fails for any reason other than cancel (manifest_unavailable incl. a missing
  request code, manifest_decode) -> run_delta returns `DeltaRoute::Fallback`; run_install_inner
  clones the job with every `from_manifest = None` and `retired_depots` cleared and runs the
  ordinary install path (Phase 73 reconcile: sha1-matching files kept, the rest downloaded),
  then sets `Outcome.delta = Some(DeltaReport{ mode: FileFallback, changed_files: [], removed_files: [],
  committed: status == completed, ... })`. Removed files cannot be known without the old manifest
  and are left (documented limitation; Verify is the deferred repair path). Note: this path
  rewrites the shimmed steam_api*.dll and any game-modified owned file; TS (plan 07) treats
  file_fallback as "shim possibly replaced".

RETIRED DEPOTS:
- Load each retired DepotRef's manifest (its manifest_id is the old GID). Unavailable -> Warning
  event "retired depot manifest unavailable; its files are kept" and continue (never fail an update
  over cleanup). Its owned regular files and symlinks whose case-folded path no new manifest owns
  are deleted in the commit, after the renames, through resolve_contained_path; their chunks are
  also valid reuse candidates for the index (SHA-checked like any other).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Disk journal -> crate | The journal file is read back from disk and may be corrupted or planted |
| CDN -> crate | Old/retired manifests may be missing or hostile |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-74-07 | Tampering | journal parse | mitigate | Parsed with serde into a fixed struct; every GID/appId numeric-checked; a malformed journal is treated as "stale" (file_fallback), never as permission to skip verification |
| T-74-08 | Tampering | retired-depot deletion | mitigate | Same resolve_contained_path + case-folded ownership rule as removed files; unavailable retired manifest deletes nothing |
| T-74-09 | DoS/data integrity | commit-phase failure | mitigate | 1026 ACF + kept journal; never reports the old build as fully installed over a mixed tree |
| T-74-10 | Info disclosure | journal content | accept | Holds only numeric app/depot/GID ids, no keys or codes |
