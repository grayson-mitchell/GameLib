<objective>
Close UAT 16 step 3: Esc on the 74-14 three-button launch prompt beeps and the box stays open on
macOS.

Root cause (verified at planning time in rfd-0.16.0's source): with no parent window, rfd's macOS
`AsyncMessageDialog::show()` does not use NSAlert at all. It calls
`CFUserNotificationDisplayAlert` on a spawned thread (`src/backend/macos/utils/user_alert.rs`),
which is drawn by a separate system process. That alert has no Escape equivalent for custom
labels, and no in-process key monitor can see its key events. So the fix is to stop using rfd for
the macOS three-button case and present an in-process `NSAlert` (the shell already does this for
the pristine Epic login's JS dialogs, `login_window/pristine_epic.rs:275-320`), with a scoped
local key monitor that turns a bare Esc into a dismissal. NSAlert itself only gives Esc to a
button titled "Cancel", and the first button already owns Return, so the monitor is required.

Purpose: D-04/D-06 prompt must be dismissable, and a dismissal must mean Play anyway.
Output: macOS three-button NSAlert path in dialogs.rs, pure mapping helpers with unit tests, todo
closed.
</objective>
