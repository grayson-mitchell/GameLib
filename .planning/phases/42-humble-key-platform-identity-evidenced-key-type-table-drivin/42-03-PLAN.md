## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Steam library cache -> Humble state machine | An ownership signal derived from Steam data now MUTATES persisted Humble key state, which previously only the user could do. |
| on-disk stores -> backend | `humble_local_redeemed.json` and the new `humble_settle_declined.json` are user-writable mode-0600 files. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-08 | Tampering | a wrong ownership match silently marks an unredeemed key as redeemed | mitigate | Only `matchConfidence === 'exact'` settles — a ground-truth Steam AppID match carried on the tpk itself, never a title heuristic. Fuzzy and `'none'` are table-driven negative-pinned in Task 1. Every settle is reversible via `undoRedeemed`, and Task 3 makes the reversal durable so a wrong settle cannot be re-applied on the next sync. |
| T-42-09 | Denial of service | a Steam hiccup zeroes ownership and mass-settles or mass-reverts | mitigate | The settle runs ONLY inside `recomputeOwnership`, which returns early when `getSteamGate()` is closed (Steam disconnected or empty cached library). A closed gate produces zero writes — pinned by the gate-CLOSED total-no-op test. The mid-sync per-order path, whose Branch B carries stale flags forward, is explicitly excluded as a settle site. |
| T-42-10 | Repudiation | the user cannot tell why a key became REDEEMED | mitigate | Every settle appends an `ownership_settled` audit record (title/platform/timestamp, never the key value) and stamps `source: 'ownership-exact'`, surfaced to the renderer via 42-02's `ClaimAnnotation.redeemedSource`. |
| T-42-11 | Information disclosure | key value leaking into the new store or the audit trail | mitigate | The decline record is `{ declinedAt: number }` only. `appendAudit`'s signature accepts only `title`/`platform`/`outcome`, so the settle physically cannot write a key value. Neither new code path calls the logger. |
| T-42-12 | Elevation of privilege | order-freeze flags desynchronised, permanently stranding an order | mitigate | `allTerminal` and `freezeEligible` are RECOMPUTED from the patched key set with the same `isTerminal`/`isFreezeEligible` helpers `patchCachedState` and `classifyOrder` use, so a settle and its undo can never leave `partitionGamekeys`' next-sync decision disagreeing (WR-01). Pinned both directions by Task 1's flag test. |
| T-42-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install in this plan. No new dependency. No `[ASSUMED]`/`[SUS]` package to gate. |
</threat_model>
