## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input → renderer state | Username/password/SteamGuard code entered in the form before crossing IPC |
| renderer → main (IPC) | Form submits delegate to window.api.steam* (handlers validated in plan 02) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SPOOF-TOTP-UI | Spoofing | SteamGuard retry in the credential tab | mitigate | On a wrong-code error the UI shows the error and does not auto-resubmit; the user must re-enter — prevents the error-84 IP-ban loop (Pitfall 4) |
| T-01-DISC-PWD-UI | Information Disclosure | password in renderer memory | mitigate | Password kept only in component state, sent once via IPC, cleared on back/error; never written to a store and never re-populated |
| T-01-ROUTE | Tampering | /loginweb/steam captured by WebView catch-all | mitigate | Specific route placed before loginweb/:runner; codecheck + ordering assertion in verify |
| T-01-XSS | Tampering | rendering Steam-returned strings (username) | mitigate | React escapes text by default; username rendered as text content only, no dangerouslySetInnerHTML |
</threat_model>
