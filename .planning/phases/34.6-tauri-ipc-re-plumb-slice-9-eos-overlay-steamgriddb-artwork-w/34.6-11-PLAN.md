    - `assertContainedPath(root, candidate)` returns the resolved absolute path when the candidate resolves inside `root`.
    - It throws `PathContainmentError` for `../escape`, for an absolute path outside `root`, for a backslash-encoded `..\\escape` (normalised BEFORE the check), and for a candidate containing a NUL or other control character.
    - It does NOT throw for a legitimate path containing an apostrophe, a space, an ampersand, or a unicode character — `Sid Meier's Civilization V` and `Grand Theft Auto: San Andreas` must pass.
    - It does NOT throw for `root` itself.
    - `assertCommandParts(parts)` returns the array unchanged when every element is a non-empty string with no control character and no NUL.
    - It throws `CommandShapeError` when `parts` is not an array, is empty, contains a non-string, contains an empty string, or contains a control character.
    - Neither error message contains the rejected value's full contents — they name the channel and the reason.
  </behavior>
  <action>
Create `src/backend/sidecar/rendererPathGuard.ts` exporting `assertContainedPath`,
`PathContainmentError`, `assertCommandParts` and `CommandShapeError`.

`assertContainedPath(root, candidate)` MUST mirror `resolveContainedPath`'s order of operations:
normalise separators FIRST (including backslashes, per `depot.test.ts:3637`'s WR-02 case), then
`path.resolve` both root and candidate, then assert the resolved candidate starts with the resolved
root PLUS a path separator (a bare `startsWith` on the root string alone would accept
`/games-evil` for root `/games`). Add the narrow denylist REQ-37-06 names — path separators inside
a single component, `..`, leading and trailing dots, control characters — as defense in depth
ALONGSIDE the containment check, not instead of it.

**Do not implement this as a safe-character allowlist.** REQ-37-06 records exactly why: widening a
character class without a RED traversal test trades this defect for a worse one, and the apostrophe
in `Sid Meier's Civilization V` is legitimate punctuation that an allowlist rejects, landing the
game where Steam will never adopt it.

`assertCommandParts(parts)` validates SHAPE, not content: an array of non-empty strings, no control
characters, no NUL. It does not attempt to sanitise shell metacharacters — task 2 removes the shell
instead, which is the actual fix.

**Write the failing tests FIRST**, in `src/backend/sidecar/__tests__/rendererPathGuard.test.ts`,
covering every case in the `<behavior>` block. Prove each assertion in BOTH directions: a
known-bad input that must throw, and a filled legitimate specimen that must not. A gate proven only
against a bad input can still be measuring the wrong property — name, in the test titles, the
property each case measures.
