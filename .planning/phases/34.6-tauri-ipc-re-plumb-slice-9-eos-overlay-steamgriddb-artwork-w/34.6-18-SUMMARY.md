## What Changed

`34.6-VERIFICATION.md` CR-01 found that plan 34.6-11's hardening gated `moveInstall`/`importGame`'s renderer-supplied `path` against `GlobalConfig.get().getSettings().defaultInstallPath` via `assertContainedPath`. That containment root was circular against its own named adversary (T-34.5-C6-49-03: a renderer that can call `moveInstall` could first call `setSetting` to widen its own root and move anywhere) and, worse, silently rejected the primary real-world use case of both features -- a cross-drive move or an out-of-tree import, both of which by definition target a location outside `defaultInstallPath`.

**Task 1** added `rendererPathGuard.assertPlausibleAbsolutePath` (+ `PathShapeError`) to `rendererPathGuard.ts`: rejects non-strings, NUL-bearing values, empty/whitespace-only values, non-absolute values, and absolute values containing a `..` path segment (segment-wise comparison, never substring, so a legitimate directory name like `..hidden` is correctly accepted -- T-34.6-47). No containment root. Rewrote the module header to name the new primitive, state `assertContainedPath` now has ZERO production call sites, and cite its future consumer (the open winePrefix/wineVersion containment todo). `assertContainedPath`/`PathContainmentError`/`assertCommandParts`/`CommandShapeError` bodies are byte-unchanged. `rendererPathGuard.test.ts` gained 17 new tests (21 → 38) and its own stale header was corrected to stop naming the two install handlers as containment callers.

**Task 2** RED-proved the fix first: added 3 new tests against unmodified source (2 ACCEPT tests for the cross-drive/out-of-tree cases that the old containment would reject, 1 REJECT test for an absolute `..`-segment path), captured the failing run to `evidence/34.6-18-RED-crossroot.txt`, confirmed exactly the 2 expected ACCEPT-direction failures, then swapped `installFlowRegistration.ts`'s `moveInstall`/`importGame` handlers from `assertContainedPath(defaultInstallPath, path, ctx)` to `assertPlausibleAbsolutePath(path, ctx)`, removed the now-dead `GlobalConfig`/`assertContainedPath` imports, and re-ran to confirm GREEN (18 tests, was 15). Every surviving prose site describing the removed containment property as a live control -- the module header, import-site comment, both handler header comments, the `beforeEach` note, two RETARGETED notes, two RED-recipe notes, two no-wedge notes, and two REJECT test titles -- was corrected in this same commit.

## Declared Residuals

- **T-34.5-C6-49-03-R (accepted, ASVS L1):** `moveInstall`/`importGame`'s trust boundary is now the OS-native directory picker plus a shape check, not a containment root. A renderer that could somehow bypass the picker and call the channel directly with an arbitrary absolute, non-traversing path would have that path forwarded to a real filesystem move/import. Accepted because the sidecar's IPC surface is not renderer-arbitrary-code-reachable in this architecture, and the picker is the actual grant in normal operation.
- **T-34.6-49 (declared, untested):** `isAbsolute()`'s platform-native behavior is exercised only under macOS in this suite/CI; Windows/UNC-path edge cases (`\\server\share`, drive-relative paths) are unverified.
