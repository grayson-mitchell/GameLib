## Decisions Made

- **A-01 held as binding**, overriding this module's own earlier D-04 framing: `Winetricks` (`tools/index.ts:528`) has no `!isLinux` guard anywhere; genuine macOS support exists via the `macEnvs` branch (`:628`), selected by `isMac ? macEnvs : linuxEnvs` (`:642`). No platform-decline branch was ported. An empty component list is documented in-code as an acceptable, data-dependent result.
- **D-02 scope boundary respected**: `runWineCommandForGame` ported byte-equivalently — no path containment/sanitisation logic added. `T-34.5-C6-49-03` is named in a code comment, explicitly deferred to plan 34.6-11.
- **D-11 observable pattern followed**: `logSendHandlerReached('winetricksInstall')` is the first statement inside the async try block, mirroring `shortcutsFlowRegistration.ts`'s existing send-kind idiom (`void (async () => {...})()` wrapper, `logSendFailure` on catch).
- **`wineToolsFlowRegistration.ts` added to `flowRegistrationCensus.test.ts`'s `NO_COUNT_CLAIM` set** (Rule 1): the newly-added idempotence guard sits between the docstring and `export function registerWineToolsFlows`, breaking `registerFnDocstring()`'s adjacency assumption — the identical structural reason `runnerAuthFlowRegistration.ts`/`shortcutsFlowRegistration.ts` were already excluded.
- **Multi-line grep vs. plan's single-line acceptance criterion**: the plan's literal single-line grep pattern for counting `ipcMain.handle(...)` registrations doesn't match this file's prettier-formatted multi-line call style (existing convention, e.g. `installWineVersion`). Verified the underlying property with a multi-line-aware equivalent (`tr '\n' ' ' | grep -oE`) instead of reformatting working, convention-consistent code. Documented as a plan-authoring grep limitation, not a defect.
- **Ephemeral scratch test for the `commandParts` pass-through RED-proof**: no existing test covered `runWineCommandForGame`'s pass-through property, and Task 1's `<files>` scope excludes test files. A temporary, never-committed scratch test file (created, used to RED-proof by temporarily inserting a shell-metacharacter rejection, reverted, then deleted) satisfied the RED-proof requirement without violating Task 1's file scope or leaving a stray artifact.
