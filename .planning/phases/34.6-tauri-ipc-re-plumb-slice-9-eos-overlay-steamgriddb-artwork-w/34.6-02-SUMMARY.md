# Phase 34.6 Plan 02: SteamGridDB Sidecar Keyring Store Summary

Keyring-backed `SidecarSteamGridDbSecretStore` installed on both arms of the sidecar's exclusive secret-store branch, with a ciphertext-aware one-time plaintext-to-keyring migration for the `steamGridDbApiKey` `GlobalConfig` setting — closing REQ-34.6-06 (A-03) started by plan 34.6-01.

## Accomplishments
- `SidecarSteamGridDbSecretStore` (`src/backend/sidecar/steamgridSecretStore.ts`) implements the `SteamGridDbSecretStore` seam from plan 34.6-01, delegating every method to a single `SidecarKeyringSlotStore` bound to the `steamgrid-api-key` slot — total, never throws/rejects to its caller.
- `installSidecarSteamGridDbSecretStore()` wired into `bootstrap.ts` immediately after `installSidecarHumbleSecretStore()` (same keyring arm, same post-`startRpcServer()` placement reasoning) and into `devSecretVault.ts`'s dev-vault arm via the new `DevVaultSteamGridDbSecretStore` — both arms of the exclusive branch now route the SteamGridDB key away from the Electron plaintext default.
- One-time plaintext-to-keyring migration (`migrateSteamGridDbApiKey`) reads `GlobalConfig`'s `steamGridDbApiKey` setting, decrypts a pre-existing `sgdb:v1:` ciphertext before ever handing a value to the keyring, writes to the keyring, invalidates the slot store's cache, reads back, and only on an exact match clears the `GlobalConfig` setting — every failure path (rejecting write, rejecting readback, mismatched readback, undecryptable ciphertext) leaves the existing value untouched and logs exactly one warning naming the failure mode, never the value.
- Live-verified: `pnpm build:sidecar && node build/main/sidecar.js` boots cleanly, prints the ready sentinel, and writes `[bootstrap] steamgrid secret store: keyring` to the real `gamelib.log` immediately before the pre-existing `[bootstrap] secret stores: keyring` line.
- 17-test suite (`steamgridSecretStore.test.ts`) covers the happy path, all four migration failure modes, and three A-03-specific hazard assertions (never-writes-config, read-back-mismatch, ciphertext-decrypted-before-write) plus a fourth (undecryptable-ciphertext-left-in-place) beyond the plan's minimum ask.
- Both required RED-proofs performed live against the running suite (not merely reasoned about) and reverted cleanly — see Deviations/Issues below for the exact commands and outcomes.

**2. [Rule 1 - Bug] Own test's synchronous-callLog assumption was factually wrong**
- **Found during:** Task 3
- **Issue:** The first draft of the "dispatches the migration fire-and-forget" test asserted `callLog` was empty immediately after the synchronous return of `installSidecarSteamGridDbSecretStore()`, on the premise that no `await`ed step inside `migrateSteamGridDbApiKey()` could have run yet. This premise was wrong: the mocked `requestRustInvoke`'s implementation pushes to `callLog` synchronously as part of its own function-call execution (the synchronous portion of an async function body runs up to and including the call expression being awaited, not only up to the `await` keyword), so `callLog` already contained one `keyring_set` entry by the time control returned to the test.
- **Fix:** Rewrote the test to assert what the plan's own hazard actually requires — that `installSidecarSteamGridDbSecretStore()`'s own return value is `undefined` (a synchronous `void` return, never a `Promise` the caller in `bootstrap.ts` might be tempted to `await`) — rather than asserting anything about the migration's internal call-log state, which the dedicated `migrateSteamGridDbApiKey()` describe block already covers exhaustively.
- **Files modified:** `src/backend/sidecar/__tests__/steamgridSecretStore.test.ts`
- **Verification:** Full suite re-run, 17/17 passing.
- **Committed in:** `e9826dc43` (part of Task 3's commit)

**3. [Rule 3 - Blocking issue] `resetMocks: true` silently wiped the `GlobalConfig` mock's implementation between tests**
- **Found during:** Task 3
