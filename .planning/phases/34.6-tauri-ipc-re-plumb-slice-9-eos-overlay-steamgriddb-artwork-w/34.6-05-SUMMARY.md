## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `jest.requireActual` inside a `jest.spyOn` mock caused infinite recursion**
- **Found during:** Task 2, writing the "never throws" test for `frontendReady`.
- **Issue:** The never-throws test's mock implementation called `jest.requireActual('../../logger').logInfo(...)` to delegate non-matching calls to the real logger. Because `jest.spyOn` replaces `loggerModule.logInfo` in place on the same module object, `requireActual` resolved to the *same already-spied* property, causing `RangeError: Maximum call stack size exceeded`.
- **Fix:** Captured `const originalLogInfo = loggerModule.logInfo` *before* calling `jest.spyOn`, and delegated to that captured reference instead of re-requiring the module inside the mock implementation.
- **Files modified:** `src/backend/sidecar/__tests__/appShellFlows.test.ts`
- **Verification:** Suite reran green (38/38, then 42/42 once combined with the other two suites).
- **Committed in:** `c7e4b8eba` (part of Task 2's commit)

**2. [Rule 1 - Bug] warnSpy assertion checked the wrong argument for the failure text**
- **Found during:** Task 2, same never-throws test, after fixing deviation #1.
- **Issue:** `logSendFailure(channel, error)` calls `console.warn('[appShellFlowRegistration] ${channel} failed:', error)` — the channel name and the error/failure text are two *separate* `console.warn` arguments. The test's first draft checked `String(msg).includes('synchronous logger failure')` against only the first argument, which never contains the error text.
- **Fix:** Destructured both `[msg, err]` from each `warnSpy` call and checked the channel name against `msg` and the failure text against `err`.
- **Files modified:** `src/backend/sidecar/__tests__/appShellFlows.test.ts`
- **Verification:** Test passed after the fix; RED-proof not separately re-run for this specific assertion shape since the underlying bug (recursion) already had its own RED/GREEN cycle via deviation #1.
- **Committed in:** `c7e4b8eba` (part of Task 2's commit)

All subsequent commits (Task 2, Task 3) used `git commit --only` from the start and were verified via `git status --porcelain` immediately before each commit to confirm no unrelated files were staged.
