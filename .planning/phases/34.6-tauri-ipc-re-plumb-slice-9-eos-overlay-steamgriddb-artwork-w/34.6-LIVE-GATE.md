# Phase 34.6 — Blocking Live Gate (run 1)

> Written with EMPTY result slots BEFORE any live work.

This contract is authored by plan `34.6-03`. Per this project's standing rule (decision D-E in
`Skill("spike-findings-gamelib")` § `references/live-gate-contract-authoring.md`), **the plan that
authors a gate contract may never also run it.** Steps 1-8 and the Humble rider are run by plan
`34.6-12`; step 0 is run earlier, by plan `34.6-04`, on a build that deliberately predates the
winetricks port — see Step 0 below for why that ordering is load-bearing and irreversible.

## Why this gate exists

This is the **last** IPC re-plumb slice. The gate closes two kinds of work in one document:

1. **24 newly-ported sidecar channels** — 8 EOS overlay, 5 SteamGridDB artwork, 3 winetricks, and 8
   late-discovered channels (`frontendReady`, `getAchievements`, `getDefaultSavePath`,
   `getGogDiscounts`, `getPlaytimeFromRunner`, `importGame`, `moveInstall`,
   `runWineCommandForGame`) — the full count corrected by D-01 from the ROADMAP's stale "16".
2. **Four inherited verification legs re-homed from the parked Phase 34.7** — the Epic login half of
   34.5 UAT test 11, test 12's `egsSync`, test 13's legendary save sync, and Epic logout's
   `clearEpicCookies`. These exercise already-ported code; they add no channel-porting work of their
   own.

**D-12: one document, one verdict, no partial-pass mode.** Two prior gates in this project
(`34.4.1-35-PLAN.md`, `34.4.2-VERIFICATION.md`) both went through a rerun caused by a defect in the
*contract*, not in the code the contract was measuring:

- `34.4.1-35-PLAN.md` precondition 6 (**still UNSTRUCK**) records a gate item whose PASS condition
  was satisfiable by an empty starting state — `survivingNonHumble=0` was accepted when
  `before total=34` equalled `matched=34`, so the census had no non-Humble cookie left to spare. The
  number was arithmetically forced, not passing. Nothing in that run could have failed the item, so
  the item proved nothing.
- `34.4.2-VERIFICATION.md` records **nine** separate gate attempts, each amended in place rather than
  regenerated, because a contract written after the fact cannot be checked for the defect class above
  and a regenerated document destroys hand-corrections layered onto prior amendments.

A contract with empty result slots, authored before any live work and before this phase's own port
lands, cannot exhibit either defect — there is no result to reason backward from while writing it.
That is the entire purpose of this document existing as a separate, earlier-committed artifact from
the plan that runs it.
