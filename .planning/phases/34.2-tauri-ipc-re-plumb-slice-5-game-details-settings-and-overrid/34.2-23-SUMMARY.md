## Decisions Made

- **jest.replaceProperty tried first, empirically rejected for `process.platform`.** The plan named it as the preferred mechanism "if available" (this project pins `jest@^29.7.0`, confirmed available since 29.4). It was implemented first and immediately broke the whole test FILE (`TypeError: Cannot assign to read only property 'platform' of object '#<process>'` at `.restore()` time), because `process.platform`'s own descriptor on this Node version is `{ value: 'darwin', writable: false, configurable: true }` — `jest.replaceProperty`'s `.restore()` performs a plain assignment that a `writable:false` descriptor rejects, even though the initial replacement (which uses `Object.defineProperty` internally) succeeds. Fell back to `Object.defineProperty` (value + `writable` redefined together) for both the mutation and its restoration, matching the pre-existing pattern this file already used — only the SCOPE moved, from a suite-wide `beforeAll`/`afterAll` to a per-test `finally` inside a new `withAdversarialPlatformAndEnv()` helper.
- **`testContainment.test.ts` classifies itself in `STRUCTURALLY_CONTAINED_SUITES`.** The gap-cycle-2 reviewer's original suggested snippet excluded the gate file from its own coverage; this plan deliberately includes it instead, since excluding it would leave Block C's tripwire with a permanent one-file blind spot and the file is, functionally, just another backend suite benefiting from structural containment.
- **`diffSuiteClassification()` factored as a standalone function** shared by Block C's real gate and both of its self-tests, so a self-test cannot silently reimplement different comparison logic than the gate it claims to prove non-vacuous.
