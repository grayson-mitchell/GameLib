<objective>
Close **code-review finding CR-03** (listed as a platform-conditional Blocker in
`34.2-VERIFICATION.md`'s Anti-Patterns table): two new test suites destructively delete and overwrite
paths whose only redirection mechanism is a `jest.mock('os')` `homedir()` override that
`src/backend/sidecar/pathShim.ts` **bypasses on Windows and Linux**.

`enrichmentFlows.test.ts` does `rmSync(fixesPath, { recursive: true, force: true })` in `beforeEach`
(runs before EVERY test) and again in `afterAll`, plus `configStore.set('games.recent', [])`.
`gameDetailsFlows.test.ts` does `gameOverridesStore.set('overrides', {})` in two `beforeEach` blocks.
Both suites also do `jest.mock('electron', () => jest.requireActual('../electronStub'))`, which routes
`constants/paths.ts`'s module-scope `app.getPath('appData')` at the REAL `pathShim`, whose
`resolveAppDataDir()` returns `env.APPDATA` on `win32` and `env.XDG_CONFIG_HOME` on the default
branch — **preferring the environment variable over `homedir()`**. On Windows `APPDATA` is always set,
so the mock is completely bypassed: `fixesPath` becomes `%APPDATA%\GameLib\fixes` (recursively deleted
before every test), `configStore` becomes the real `config.json` (recent-games list wiped), and
`gameOverridesStore` becomes the user's real title/art customizations (wiped). Only `darwin` is safe,
because it is the one branch that goes through `homedir()`.

This is this repo's own recorded `tests-clobbering-real-steam-store` incident (commit `92c29a5e`,
2026-07-22) re-armed, and that incident's recorded lesson is explicit: **an `afterAll` restore is not
a safety net, because jest workers can force-exit.** The redirect must be established before the
destructive call can ever resolve a real path.

Also closes **WR-08** in the same file: `enrichmentFlows.test.ts`'s `online_monitor` factory mock is
never re-armed under the shared jest config's `resetMocks: true`, so `isOnline()` returns `undefined`
and `runOnceWhenOnline(cb)` never invokes `cb` in any test in that file. Latent today, but the first
test added that asserts on an online-gated path would silently pass against a never-executed branch.

Purpose: eliminate a real data-loss risk on Windows/Linux dev machines and CI, and de-arm a booby trap.
Output: a platform-independent redirect, a loud containment tripwire, and a correctly re-armed mock.
</objective>
