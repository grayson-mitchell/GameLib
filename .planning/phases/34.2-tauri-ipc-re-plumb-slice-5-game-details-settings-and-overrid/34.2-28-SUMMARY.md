## Task 2: Fixture/title discrepancy resolution (the known_state item)

The uncommitted Task 2 diff on arrival had self-test (c)'s synthetic fixture as:

```
const RUNGAME_PREFIX: &str = "steam://rungameid/";
```

with no trailing comment, while the test's title claimed "plus a trailing comment" and the plan's acceptance criteria described a falsifiability check ("temporarily removing the trailing comment ... observing that self-test fail") that presupposes one exists.

**Investigation (hand-verified, both variants):**

1. With the fixture AS FOUND (no trailing comment) -- title was false. Fixed by adding `; // trailing note` per the plan's literal action text, making the title true.
2. Tested whether the plan's stated falsifiability check ("remove the trailing comment, observe FAIL") actually works once the comment is present. It does not: removing ONLY the appended `// trailing note` (fixture reverts to `"steam://rungameid/";`) leaves the self-test **PASSING**:

```
✓ self-test: a synthetic code line with a quoted steam:// literal plus a trailing comment produces an ODD "-count on that line (proves the guard can fail) (1 ms)

Test Suites: 1 passed, 1 total
Tests:       17 skipped, 1 passed, 18 total
```

   This is because the naive stripper's regex (`/\/\/.*$/`) finds the FIRST `//` on the line -- which is the one embedded inside `steam://` itself -- and truncates from there regardless of whether a second, separately-appended comment exists afterward. The appended comment is redundant to the truncation mechanism; it was never what made the guard fail.

3. Verified the GENUINE falsifiability lever instead: removed the embedded `//` from the literal (`"steam:rungameid"`, keeping the trailing comment), and the self-test flipped to **FAILING**:

```
● stripper integrity (WR-08) › self-test: a synthetic code line with a quoted steam:// literal plus a trailing comment produces an ODD "-count on that line (proves the guard can fail)

    expect(received).toBe(expected) // Object.is equality

    Expected: 1
    Received: 0

Test Suites: 1 failed, 1 total
Tests:       1 failed, 17 skipped, 18 total
```

**Resolution chosen:** Option A from the known_state (add the trailing comment the plan asked for, making the title literally true) -- the fixture now reads `'const RUNGAME_PREFIX: &str = "steam://rungameid/"; // trailing note'`. Additionally corrected the block comment above the test to state plainly, in-line, that the trailing comment is NOT what drives truncation -- the literal's own embedded `//` is -- and that the plan's specific "remove the trailing comment" falsifiability check is vacuous for this fixture; the real lever (removing the embedded `//`) is what was hand-verified above and is what a future reader should reproduce if they doubt the guard's falsifiability. Restored the fixture to its final form after both experiments; `diff` against the pre-experiment backup confirmed byte-identical restoration each time.
