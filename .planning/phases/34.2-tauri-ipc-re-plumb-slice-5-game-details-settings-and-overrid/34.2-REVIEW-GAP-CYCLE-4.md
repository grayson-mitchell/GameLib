## Critical Issues

### CR-01: Every "comment-stripped source" gate can still be satisfied by a comment — `stripComments` does not strip block-comment bodies

**File:** `src/backend/sidecar/__tests__/testContainment.test.ts:198-203`
(also `src/backend/sidecar/__tests__/loggerCallSiteGuard.test.ts:148-153`)

**Issue:** `stripComments` is a *line-prefix* filter:

```ts
source.split('\n').filter((line) => !/^\s*(\/\/|\*|\/\*)/.test(line)).join('\n')
```

It drops a line only when that line *begins* with `//`, `*`, or `/*`. The interior of a
block comment whose lines are **not** `*`-prefixed survives stripping verbatim. Every
gate cycle 4 built on this helper therefore accepts a pure comment as satisfaction:

- `hasContainmentOsMock` (`:762-771`) — the WR-02 gate, described at `:751-760` as
  gating "THE load-bearing fix".
- `assignsContainmentEnvVar` (`:747-749`) — the WR-01 gate, whose own docblock at
  `:732-745` states: *"Before this plan, this gate matched RAW source, so a docblock
  line merely mentioning `process.env.HOME =` … satisfied it identically to the real
  assignment actually being present."* Moving it onto `stripComments` did not fix that;
  it fixed only the `*`-prefixed spelling.
- Block B's three presence gates (`:506`, `:516`, `:526`).
- Block E's `importsContainmentModule` (`:906-916`).
- `hasExpressionBodyErrorWrapper` in `loggerCallSiteGuard.test.ts:163-165` — the Test D
  gate for the CR-01 fix itself.

Proven by executing the helper verbatim:

```
block-comment-only source satisfies hasContainmentOsMock:            true
block-comment-only source satisfies assignsContainmentEnvVar(HOME):  true
block-comment-only satisfies hasExpressionBodyErrorWrapper:          true
```

with input of the shape:

```
/*
jest.mock('os', f)
jest.mock('node:os', f)
homedir: () => x
userInfo: (a) => y
*/
const real = 1
```

The self-tests do not catch this because each one uses only the `*`-prefixed docblock
spelling (`:803-811`, `:818-848`, `loggerCallSiteGuard.test.ts:313-322`). They prove the
gate rejects one comment style and are presented as proving it rejects comments.

This matters because the entire deliverable of this cycle's WR-01/WR-02 work is *"a
comment cannot self-satisfy its own gate"* (`:196-197`, `:739-745`). That contract is
false as shipped. Note that `structuralContainment.test.ts:265-267` already contains a
correct stripper (`stripCommentsForNodeOsGate`, which does `replace(/\/\*[\s\S]*?\*\//g, '')`
first) — the right implementation exists in the same gap cycle, in a sibling file, and
was not applied here.

**Fix:** strip block comments before the line filter, in the shared helper, and add a
self-test using the non-`*` spelling.

```ts
function stripComments(source: string): string {
  return source
    .replace(/\/\*[\s\S]*?\*\//g, '')          // block comments, incl. non-`*` bodies
    .split('\n')
    .filter((line) => !/^\s*(\/\/|\*)/.test(line))
    .map((line) => line.replace(/\/\/.*$/, '')) // trailing line comments
    .join('\n')
}

it('gate self-test: a NON-docblock block comment cannot satisfy hasContainmentOsMock', () => {
  const synthetic = [
    '/*',
    "jest.mock('os', mockOsFactory)",
    "jest.mock('node:os', mockOsFactory)",
    'homedir: () => x',
    'userInfo: (a) => y',
    '*/',
    'const unrelated = 1'
  ].join('\n')
  expect(hasContainmentOsMock(synthetic)).toBe(false)
})
```

Apply the same replacement to `loggerCallSiteGuard.test.ts:148-153` (or export one
helper from a shared test util so the four copies cannot drift again).

### WR-01: Containment roots are now created once per *test file* and never removed — measured 113 new directories per backend run, 1968 currently on disk

**File:** `src/backend/jest.setupContainment.ts:229-239`

**Issue:** `ensureContainmentRoot()` memoizes on `globalThis`, but Jest gives each test
*file* a fresh sandbox global — so `mkdtempSync` runs once per test file, not once per
worker process. Combined with the deliberate no-teardown policy (`:109-117`, `:148-151`),
nothing ever deletes them. Measured on this host:

```
before full backend run: 1968 dirs under $TMPDIR/gamelib-jest-home-*
after  full backend run: 2081   (+113 = exactly the suite count)
naming split: 211 numeric-suffix (old per-pid scheme) vs 1757 mkdtemp-suffix (new scheme)
total size 5.1M; many contain real gamelib.log content and electron-store JSON
```

The old per-pid scheme accumulated 211 directories over the phase's whole history; the
new scheme accumulated 1757 in a few days. Cycle-3's WR-07 named four properties
—predictable, **never-cleaned**, default-permission, TOCTOU. Cycle 4 closed three and
made the fourth ~113× worse per run. The docstring at `:116` still calls it "the per-pid
directory", which no longer describes the behaviour.

The no-teardown reasoning (`92c29a5e`: a force-exited worker skips hooks) argues against
relying on teardown as a *safety net*; it does not argue against best-effort cleanup on
the normal path, nor against reaping stale roots at setup.

**Fix:** keep the root per worker process rather than per test file, and best-effort
reap stale siblings at setup:

```ts
function ensureContainmentRoot(): string {
  if (globalThis.__GAMELIB_JEST_CONTAINMENT_ROOT__ !== undefined) {
    return globalThis.__GAMELIB_JEST_CONTAINMENT_ROOT__
  }
  // One root per worker PID, not per test file: mkdtemp is still atomic/0700, but
  // the suffix is derived once and reused by every file this worker runs.
  const marker = join(realTmpRoot, `gamelib-jest-home-pid${process.pid}`)
  const root = existsSync(marker)
    ? readFileSync(marker, 'utf8')
    : (() => {
        const r = mkdtempSync(join(realTmpRoot, 'gamelib-jest-home-'))
        chmodSync(r, 0o700)
        writeFileSync(marker, r, { mode: 0o600 })
        return r
      })()
  globalThis.__GAMELIB_JEST_CONTAINMENT_ROOT__ = root
  return root
}
```

plus a `globalTeardown` (or a `pnpm test` pre-step) that `rm -rf`s
`$TMPDIR/gamelib-jest-home-*` older than N hours. Mode 0700 stays the security control;
this is the hygiene control.

### WR-02: The predictable-`/tmp`-path pattern WR-07 removed from `jest.setupContainment.ts` still exists, unchanged, in two files edited by this same cycle

**File:** `src/backend/sidecar/__tests__/loggerFlows.test.ts:84`, `:100-106`, `:134-140`

block) and `testContainment.test.ts` gained Blocks D/E, so both were open for edit.

**Fix:** replace the pid-derived roots with `mkdtempSync`, the same remedy applied to the
structural module:

```ts
const mockTmpRoot = jest
```

and have all three mock factories (`os`, `../pathShim`, `backend/logger/paths`) read

### WR-04: The exclusion-allowlist guard proves at most one of three entries is load-bearing while claiming to prove none are decorative

**File:** `src/backend/sidecar/__tests__/structuralContainment.test.ts:354-377`

**Issue:** The test is named *"the exclusion allowlist is exactly the 3 declared entries
… and is load-bearing (not decorative)"*, and its inline comment at `:373-375` claims it
*"Proves the exclusions are load-bearing, not a set of decorative names that quietly
disable the gate"*. The implementation is:

```ts

for (const exemptName of NODE_OS_GATE_EXEMPT_FILES) { … if (…) atLeastOneLoadBearing = true }
```

safe today.

```ts
const decorative = NODE_OS_GATE_EXEMPT_FILES.filter((exemptName) => {
```

### WR-06: Test 8's `uv_os_get_passwd` guard — the stated WR-11 remedy — is unreachable dead code

**File:** `src/backend/sidecar/__tests__/structuralContainment.test.ts:312-327`

**Issue:** Test 8 wraps `userInfo()` in a `try`/`catch` that re-throws with an

### WR-08: `hasBehavioralRustTestModule`'s three conditions are independent — an empty loop plus an unrelated assertion satisfies the gate

**File:** `src/backend/__tests__/longRunningChannels.test.ts:150-168`

**Issue:** The predicate ANDs three region-wide facts:

### WR-11: `currency-gate.py`'s token lists are hand-transcribed from the review with nothing cross-checking them, and the gate is not wired into any script or workflow

```python
def finding_ids_from_review(path: Path) -> set[str]:
```
