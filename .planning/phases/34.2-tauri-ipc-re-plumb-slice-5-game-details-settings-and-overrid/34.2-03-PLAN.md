<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer IPC args → `readKnownFixes` path construction | `getKnownFixes(appName, runner)` sends both values from the renderer; they become path segments in `join(fixesPath, \`${appName}-${storeMap[runner]}.json\`)`. |
| bundled/downloaded fix JSON → `JSON.parse` | The fix files are content GameLib obtains out of band; a malformed or hostile file reaches `JSON.parse` and then the launch pipeline. |
| test suite → developer's real config directory | `fixesPath` derives from `appFolder`, which derives from `os.homedir()`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.2-10 | Tampering | `appName` as a path segment in `readKnownFixes` | accept | Pre-existing Electron behavior, relocated byte-identically — this plan changes the file the function lives in, nothing else. `join` is NOT containment in this codebase's own precedent (use `resolve` + `relative`), and a traversal here reads an attacker-chosen JSON rather than writing anything; the read is already wrapped in `existsSync` + `try/catch` and returns `null` on any failure. Adding containment would change Electron behavior and is out of scope — recorded here so a later reviewer sees it was considered, not missed. Flagged for `/gsd-secure-phase` as a candidate hardening in a follow-up. |
| T-34.2-11 | Denial of Service | Malformed fix JSON reaching `JSON.parse` | mitigate | The original `try/catch` → `logWarning` → `return null` is preserved verbatim and asserted by Task 3 test 3, so a bad file degrades one game's fixes rather than throwing into the launch pipeline. |
| T-34.2-12 | Elevation of Privilege (of scope) | `crossover_index/ipc_handler.ts` re-exporting `buildCrossoverRatingMap`, leaving the side-effect-import trap open | mitigate | Task 2's verify explicitly fails on a re-export, and its new anti-remerge test fails if `addHandler` reappears in `crossoverRatingMap.ts`. `ratingMap.test.ts` losing its `jest.mock('backend/ipc')` block is the positive evidence the trap is closed. |
| T-34.2-13 | Information Disclosure | Test fixtures written into the developer's real `~/Library/Application Support/GameLib` | mitigate | `jest.mock('os')` homedir redirect installed before any module resolves `appFolder`, plus an explicit assertion that `fixesPath` is under `os.tmpdir()`. Established precedent: an `afterAll` restore was already proven insufficient here (worker force-exit). |
| T-34.2-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — zero packages installed, no manifest change. |
