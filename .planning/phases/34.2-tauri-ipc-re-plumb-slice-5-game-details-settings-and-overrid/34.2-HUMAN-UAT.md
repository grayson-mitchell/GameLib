## Tests

1. **UAT-34.2-01 — a translated notification string actually renders (D-02 / REQ-34.2-02).**

   Why manual: jest can assert `i18next.t()` returns a real string after `init()`, and
   `gameDetailsFlows.test.ts` proves `repair`'s notify body reflects that real string over the real
   sidecar RPC loop. It cannot see the app actually show a notification, and it cannot exercise a
   **packaged** build's locale-path resolution — jest runs from the repo root, where `process.cwd()`
   happens to resolve `publicDir` correctly (the `publicdir-getapppath-chunking` gotcha family).

   Steps:
   1. `pnpm tauri:dev`.
   2. Trigger a repair on a game whose repair path errors (any Steam title — recall §3 rider 1 of
      `34.2-PORTED-CHANNELS.md`: Steam's `repair` is itself an upstream no-op, so the reliable way to
      exercise the notify path is a non-Steam runner, or force an error condition).
   3. Confirm the notification BODY is a real, translated sentence — not blank, not literally
      `undefined`.
   4. Repeat against a **packaged** build (`pnpm tauri build` or the project's packaging command),
      which is the half jest structurally cannot reach.

   Expected: the notification body renders a real sentence in both the dev and packaged builds.

   Note: sidecar logs go to `~/Library/Logs/GameLib/gamelib.log`, **NOT** the `tauri:dev` terminal —
   a reader looking in the terminal will wrongly conclude nothing happened.

   result: partial — dev build PASSED 2026-08-22; packaged build NOT RUN
   evidence: |
     Driven on real hardware against a live `pnpm tauri:dev` (binary
     `target/debug/gamelib-shell`, window titled "GameLib"). Target was **Endless Sky**
     (GOG `1829678475`, macOS native) — a non-Steam runner, per this item's own note that
     Steam's `repair` is an upstream no-op.

     **The prescribed step was CORRECTED before running, because as written it could not
     fail.** Step 2 says to trigger a repair that ERRORS. That path is
     `i18next.t('notify.error.reparing', 'Error Repairing')` (`dispatch.ts:183`) — the
     hardcoded second argument is byte-identical to the locale value, so it renders a
     perfect sentence even if D-02's entire bootstrap init were deleted. Zero
     discriminating power. The SUCCESS path is the real gate:
     `i18next.t('notify.finished.reparing')` (`dispatch.ts:187`) carries **no default**, so
     a dead i18next renders the raw key.

     Ran the success path instead. Operator observed a real macOS notification **toast**
     (explicitly confirmed as the toast, not the terminal — the two are one capital letter
     apart, since `dispatch.ts:188` logs the untranslated string `Finished repairing`)
     reading a real translated sentence, NOT `notify.finished.reparing`. Backend
     corroboration: `Finished repairing` at 20:01:00 and 20:02:02, each following a real
     `gogdl repair` invocation; `repair.log` ends `[V2] INFO: All files look good`
     (Deleted 0 / Changed 0), so the repair genuinely completed.

     Incidental, not a failure: macOS raised its App Management privacy prompt
     ("GOG Galaxy was prevented from modifying apps"). gogdl needed to change 0 files, so
     nothing was blocked — but a repair that DID need to rewrite `Endless Sky.app` could be
     blocked unless GameLib is allowed under Privacy & Security → App Management.
   still_open: step 4 — the packaged build. Unrun. See Gaps.

## Gaps

**G-34.2-UAT-01 — UAT-34.2-01 step 2 was a test that could not fail (test-design defect,
found 2026-08-22, corrected before running).** The step directs the operator to trigger a
repair that ERRORS. `dispatch.ts:183` is
`i18next.t('notify.error.reparing', 'Error Repairing')`, and `notify.error.reparing` in
`public/locales/en/translation.json` is *also* `"Error Repairing"` — so the rendered text is
identical whether i18next is fully initialised or completely dead. The step would have
passed against the exact defect D-02 exists to prevent. Corrected by driving the SUCCESS
path (`t('notify.finished.reparing')`, no default) instead. **The written step should be
amended in place** so a future re-run does not repeat it. Same class as this phase's
recurring "gate measures the wrong property" finding.

**G-34.2-UAT-02 — the packaged-build half of UAT-34.2-01 is STILL UNRUN**, and it is the
half that structurally matters. Jest and `tauri:dev` both resolve `publicDir` off
`process.cwd()` from the repo root, where it happens to be correct; a packaged build
resolves it off `getAppPath()`. That exact divergence is a repeat offender in this project
(the `publicdir-getapppath-chunking` family, four recurrences, one of which killed Phase
34.5's gate). **A dev-build pass carries no information about it.** Until `pnpm tauri build`
is run and the notification re-observed there, REQ-34.2-02 is proven only for dev.

**Nothing here blocks phase closure** — per D-11 neither item ever gated it.
