## Tests

1. **UAT-34.2-01 — a translated notification string actually renders (D-02 / REQ-34.2-02).**

   Why manual: jest can assert `i18next.t()` returns a real string after `init()`, and
   `gameDetailsFlows.test.ts` proves `repair`'s notify body reflects that real string over the real
   sidecar RPC loop. It cannot see the app actually show a notification, and it cannot exercise a
   **packaged** build's locale-path resolution — jest runs from the repo root, where `process.cwd()`
   happens to resolve `publicDir` correctly (the `publicdir-getapppath-chunking` gotcha family).

   Steps:
   1. `pnpm tauri:dev`.
   2. Trigger a repair on a game whose repair path errors (any Steam title — recall §3 rider 1 of
      `34.2-PORTED-CHANNELS.md`: Steam's `repair` is itself an upstream no-op, so the reliable way to
      exercise the notify path is a non-Steam runner, or force an error condition).
   3. Confirm the notification BODY is a real, translated sentence — not blank, not literally
      `undefined`.
   4. Repeat against a **packaged** build (`pnpm tauri build` or the project's packaging command),
      which is the half jest structurally cannot reach.

   Expected: the notification body renders a real sentence in both the dev and packaged builds.

   Note: sidecar logs go to `~/Library/Logs/GameLib/gamelib.log`, **NOT** the `tauri:dev` terminal —
   a reader looking in the terminal will wrongly conclude nothing happened.

   result: pending
   reason: not attempted this session (deferred per D-11)

2. **UAT-34.2-02 — the anticheat data file actually appears on disk (D-07 / REQ-34.2-07).**

   Why manual: jest asserts the event fires and the file is written, under a tmp home with a
   **mocked** axios (`bootstrapWirings.test.ts`). It cannot prove a real GitHub fetch completes in a
   live process across a real network after a real connectivity transition.

   Steps:
   1. Delete `<appFolder>/areweanticheatyet.json`.
   2. `pnpm tauri:dev`.
   3. Wait for `initOnlineMonitor()`'s online transition.
   4. Confirm the file reappears at `<appFolder>/areweanticheatyet.json`.
   5. Check `~/Library/Logs/GameLib/gamelib.log` for the `AreWeAntiCheatYet data downloaded` line.

   Expected: the file reappears and the log line is present. **The file appearing IS the pass
   condition** — it is not a visible badge.

   **Rider (recorded inline so a correct result is not misread as a failure):** even with the file
   present, `getAnticheatInfo` returns `null` for Steam titles on every platform and `null` for
   everything on Windows (§3 rider 2 of `34.2-PORTED-CHANNELS.md`). Do not treat a `null`
   `getAnticheatInfo` result, or the absence of a visible anticheat badge on a Steam game, as a
   failure of this test — that is the FOUR-of-five expected outcome even after this fix.

   result: pending
   reason: not attempted this session (deferred per D-11)
