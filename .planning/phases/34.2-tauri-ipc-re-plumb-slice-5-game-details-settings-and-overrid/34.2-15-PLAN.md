<objective>
Close **verification gap #2 (GAP-CYCLE-1 CR-02, REQ-34.2-07)**: `processGuards.ts:48-49` builds
`const message = \`[sidecar] unhandled promise rejection: ${String(reason)}\`` OUTSIDE its own
`try` (the try at lines 50-62 wraps only the `logWarning` call). `String(reason)` throws
`TypeError: Cannot convert object to primitive value` for any value with a null prototype or a
throwing/absent `toString`/`Symbol.toPrimitive`. A throw from a `process` `'unhandledRejection'`
listener is escalated by Node into an `uncaughtException`, and the sidecar installs no
`uncaughtException` handler anywhere — so the process dies. The verifier reproduced this
empirically with a minimal Node script.

This is the exact `sidecar-dialog-reject-crashes` failure class the module's own docstring says it
exists to prevent, reintroduced by the guard itself. The whole point of gap cycle 2 is that gap
cycle 1's safety-net code contained the defect it was written to prevent — so this plan hardens the
guard AND proves the hardening with hostile inputs, not with "the happy path still works".

Purpose: a process-level guard that cannot be crashed by a bug- or attacker-controlled rejection
value (availability), and that still emits a signal when the value is unprintable (observability).
Output: a hardened `processGuards.ts` and three new Group 2 test cases.
</objective>
