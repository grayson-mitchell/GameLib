## Sampling Rate

- **After every task commit:** the task's own targeted `npx jest <file>` (plus
  `npx tsc --noEmit` for the extraction/registration tasks, which is how a broken import
  surfaces fastest).
- **After every plan wave:** the cross-file sweep
  `npx jest gameDetailsFlows|enrichmentFlows|bootstrapWirings|gameDetailsImportGate|gameDetailsModules|knownFixes|longRunningChannels`
  (naming mirrors 34.1's own sweep convention), plus
  `npx jest appShellFlows|settingsFlows|downloadQueueFlows|bootstrap|electronUntouched`
  as the regression sweep — every plan in this phase touches shared bootstrap/registration
  surfaces that those suites already exercise.
- **Before `/gsd-verify-work`:** `pnpm test:ci` full suite green **plus**
  `cd src-tauri && cargo check --quiet` green **plus** `npx tsc --noEmit` clean.
- **Max feedback latency:** ~15 seconds for targeted runs.

## Manual-Only Verifications

Exactly **two** items, and that is the point. Per D-11 this slice's unit claim is
genuinely strong — 26 channels of data-in/data-out with assertable return shapes,
exercised over the real sidecar RPC loop — unlike 34.1, whose headline deliverable was
visual and which therefore deferred ten items. Padding this table would dilute the two
that actually matter. Both are **deferred**; neither gates phase closure (D-11).

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| A translated notification string actually renders under a live Tauri boot | REQ-34.2-02 (D-02) | Jest can assert `i18next.t()` returns a real string after `init()`; it cannot see a notification, and it cannot exercise a **packaged** build's locale-path resolution — jest runs from the repo root, where `process.cwd()` happens to make `publicDir` resolve (the `publicdir-getapppath-chunking` gotcha family) | `pnpm tauri:dev`, trigger a repair on a game whose repair path errors, confirm the notification BODY is a real sentence and not blank. Repeat against a packaged build. Sidecar logs are at `~/Library/Logs/GameLib/gamelib.log`, **not** the `tauri:dev` terminal |
| The anticheat data file actually appears on disk after a live boot | REQ-34.2-07 (D-07) | Jest asserts the event fires and the file is written under a tmp home with a **mocked** axios; it cannot prove a real GitHub fetch completes in a live process across a real network after a real connectivity transition | Delete `<appFolder>/areweanticheatyet.json`, `pnpm tauri:dev`, wait for `initOnlineMonitor()`'s online transition, confirm the file reappears and `gamelib.log` shows `AreWeAntiCheatYet data downloaded`. **Rider:** even with the file present, `getAnticheatInfo` returns `null` for Steam titles on every platform and `null` for everything on Windows — the file appearing IS the pass condition, not a visible badge |

**The honest boundary, stated once here and verbatim in `34.2-PORTED-CHANNELS.md` §6 and
`34.2-HUMAN-UAT.md`:** for the 26 channels, the automated tests exercise the real
extracted bodies over the real transport and assert real return values — so "wired and
unit-proven" is genuinely close to "works" for this slice, which is a stronger claim than
34.1 could make. For the two bootstrap wirings it is not: those tests prove the wiring
under mocked network and a tmp home, and nobody has booted the Tauri build and watched
either effect. Do not read "wired and unit-proven" as "seen working" — that conflation is
exactly how G-30-02 was declared fixed twice while the live build hung.
