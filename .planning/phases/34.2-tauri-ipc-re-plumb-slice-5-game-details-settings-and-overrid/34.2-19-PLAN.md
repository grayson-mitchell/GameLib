src/backend/logger/paths.ts — `getBaseLogPath()` (private, reached via the exported
`getLogFilePath(args)`), branches on `isWindows` / `isMac` imported from
`../constants/environment` (it never reads `process.platform`):
  - isWindows → `process.env.LOCALAPPDATA ?? join(homedir(), 'AppData', 'Local')` + 'GameLib/logs'
  - isMac     → `join(homedir(), 'Library', 'Logs', 'GameLib')`
  - otherwise → `process.env.XDG_STATE_HOME ?? join(homedir(), '.local', 'state')` + 'GameLib/logs'

src/backend/sidecar/pathShim.ts — `resolveAppDataDir()` (private, reached via the exported
`getPath(name)`), switches on `platform` imported from `process`:
  - 'darwin' → `join(homedir(), 'Library', 'Application Support')`
  - 'win32'  → `env.APPDATA || join(homedir(), 'AppData', 'Roaming')`
  - default  → `env.XDG_CONFIG_HOME || join(homedir(), '.config')`
  `getPath('userData')` appends the `'GameLib'` segment to that.

Node semantics that make the env-only approach work (probed on this host, 2026-07-26):
`os.homedir()` returns `process.env.HOME` verbatim when it is set on POSIX, and
`process.env.USERPROFILE` on win32. Confirmed:
`node -e "process.env.HOME='/tmp/fake-home-probe'; console.log(require('os').homedir())"`
prints `/tmp/fake-home-probe`. Therefore setting HOME/USERPROFILE plus the four
APPDATA/LOCALAPPDATA/XDG_CONFIG_HOME/XDG_STATE_HOME variables covers **every branch of both
resolvers on every platform**, with no `jest.mock` and no module-registry surgery.

src/backend/jest.config.js — the backend project config. Note `rootDir: '../..'` (the repo
root), `roots: ['<rootDir>/src/backend']`, `resetMocks: true`, and the ts-jest transform
