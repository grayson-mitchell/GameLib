<objective>
Close review WR-01 (developer decision 2026-11-07: FIX). On an inconclusive CrossOver pre-flight,
the shared `decideLaunchEngine` today always picks CrossOver, never reads the bottle's engine
marker, and logs `reason=cx-healthy`. After this plan it keeps the bottle on the engine its
marker records, labels the decision `cx-inconclusive`, and every consumer of the selection reason
(launch log, fallback toasts, in-app launch notice, game-page badge, tests) handles the new label
without treating it as a fallback.

Purpose: an inconclusive probe proves nothing (59 D-09). Forcing a bottle that really runs the
built-in engine back onto a possibly expired CrossOver brings back the 59-UAT G10 Expired-dialog
hang, and makes the D-16 busy check refuse a launch that used to work beside another game.
Output: the fixed decision, consumer guards, Steam and non-Steam regression tests, and
61-HUMAN-UAT.md item 1 recorded.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bottle on disk -> engine decision | the bottle's engine marker file (written by GameLib) is read to choose the launch engine |
| CrossOver probe -> engine decision | an inconclusive `--demo-status` result (timeout, invalid-bottle) drives the branch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-61-26-01 | Tampering | readBottleEngineMarkerSummary | mitigate | Same chokepoint as readBottleEngineMarkerKind: sanitizeBottleName guard, read-only, try/catch to null; the pin id is only compared against the two known ENGINE_PINS ids, never used as a path, so a hand-edited marker can at most select pins.current |
| T-61-26-02 | Denial of Service | decideLaunchEngine inconclusive branch | mitigate | A non-crossover-marker bottle is no longer switched to CrossOver, so no wineserver kill, no DXVK rewrite and no D-16 busy refusal under a running neighbour game; and no launch onto a possibly expired CrossOver that hangs behind its dialog (59-UAT G10) |
| T-61-26-03 | Repudiation | launch log label | mitigate | The D-13 log line records reason=cx-inconclusive with the probe detail, so a log reader can tell an unproven decision from a healthy one |
| T-61-26-04 | Spoofing | inconclusive with crossover/absent marker | accept | Still launches on a located CrossOver without a trial read (61-22 T-61-22-03 unchanged); now labelled honestly. Lower harm than rewriting a healthy bottle |
