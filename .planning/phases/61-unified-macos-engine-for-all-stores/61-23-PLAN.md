<objective>
Close CR-05 (D-08/D-09) and UAT G-1 (D-04).

CR-05: `game_config.ts` `readSettings()` sets `defaultSettings.engineOverride = globalEngineOverride`
for any game with no config file. The Engine control's `stored` (via `useSetting`) then shows the
global pick, while the launch's `readEngineForGame` reads the file, finds no entry, and derives
from the global `wineVersion` — the UI and the launch disagree. And because `setSetting` flushes
`this.config` (defaults included) in explicit mode, any unrelated toggle writes the engine to
disk, which can move a plain-prefix game to a fresh bottle with no D-04 warning.

Design decision (planner): the single source of truth is `readEngineForGame`, unchanged in
behaviour. Remove the injection from `game_config.ts`. Rejected alternative: making
`readEngineForGame` inherit the global engineOverride for a missing entry — that would move an
existing config-less game on the shared plain prefix to a fresh per-game bottle as soon as the
user set the global Engine to Automatic (gamePrefix rule 4), stranding its saves with no warning,
which is the very harm CR-05 describes; and D-09 scopes the global pick to *new installs*, which
already get an explicit `engineOverride` from the install dialogs (`EngineSelector` defaults from
`getDefaultEngine`, not from this injected default, so D-09/D-20 are unaffected). With the
injection gone, `useSetting('engineOverride')` is empty for a config-less game and
`effectiveSelectValue` falls back to `state.effectiveEngineId`, which `getGameEngineState` computes
with `readEngineForGame` — the same call the launch makes.

G-1: `needsFreshBottleConfirm` checks `prefixKind === 'plain'` only. A Legacy game always runs on
a winePrefix (`game_config.ts` defaults `winePrefix || sharedWinePrefix` on macOS, and D-05 makes
CrossOver-wine games Automatic, not Legacy), and the backend routes it to a fresh per-game bottle
when switched (`resolveGamePrefix` rule 4), so 'legacy' must confirm too.

Output: patched game-config defaults, a pinned engine-read contract, confirm logic, regression tests.
</objective>
