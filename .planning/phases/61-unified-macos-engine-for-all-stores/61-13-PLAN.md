<objective>
Wire the engine step into the shared launcher (`src/backend/launcher.ts`), which every non-Steam
store reaches (Steam does not: it uses dispatchSteamLaunch). The engine step runs in
`runLaunchEventCallback` after the game log writer exists and before the Wine validity check;
`prepareWineLaunch` reads settings through the overlay; the step is released when the launch
ends. Arming the launch deadline is NOT done here (61-15).

Pitfall 5 audit (RESEARCH): every `wineVersion.type === 'crossover'` branch in launcher.ts
(prepareLaunch L588, prepareWineLaunch L840/L904, setupWineEnvVars L1196, verifyWinePrefix L1461,
runWineCommand L1526) must see the overlay settings, so a fallback launch takes the `wine`
branches with the bottle as `winePrefix` and a CrossOver launch keeps `CX_BOTTLE`.
Output: launcher wiring, a launcher-level test, the census test, the D-02/D-04 snapshot test.
</objective>
