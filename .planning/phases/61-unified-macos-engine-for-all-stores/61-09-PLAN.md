<objective>
Generalise the engine state (the data behind the badge, notices and toast) from a Steam
appId-keyed module to one keyed by game, and finish cutting `src/backend/engine/` loose from
Steam.

- New shared payload type `EngineState` in `src/common/types/engine.ts` (identity `runner` +
  `appName` instead of `appId`), plus `EngineOption` (adds a `legacy` kind for D-15). The Steam
  types are removed and every importer (backend and frontend) is repointed; the frontend change
  in this plan is mechanical only (type names, `state.appId` -> `state.appName`). Re-keying and
  widening the frontend store is plan 61-16.
- `engineState.ts` exposes `getEngineState(identity, deps)`, `recordLaunchDecision(identity, ...)`,
  `dismissEngineNotice`, `publishOverlayNotice`/`publishOverlayExitNotice` with every Steam
  dependency injected; the Steam wrapper `getSteamEngineState(appId)` lives in the adapter.
- `steamEngineNoticeStore` moves to `engine/engineNoticeStore.ts` as `engineNoticeStore`, with the
  CacheStore name `steam_engine_notices` unchanged (RESEARCH runtime-state inventory).
- Neutral log prefix in every engine file; dependency-cruiser rule `engine-is-store-agnostic`.

Output: the generalised state module, shared types, adapter wrapper, rule, repointed importers.
</objective>
