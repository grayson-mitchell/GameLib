<objective>
Close the deadline-safety cluster from 61-VERIFICATION.md: CR-02 (the deadline kills a running
game when no `ps` line matches), WR-01 (a watcher that gives up leaves the deadline armed) and
CR-03 (the deadline kill skips the D-16 ledger).

Design decision (planner, per the verification's "or make the unmatched case a no-kill notice"
option): arming "only when a match is provable" is not achievable before launch, because the
unmatchable shapes (spike 068 S4 bare-basename, launcher stubs that exec from `%LOCALAPPDATA%`)
are decided by the game, not by GameLib. So the non-Steam deadline becomes a **notice that never
kills**: when it fires, GameLib stops its watcher, logs, and tells the user it could not confirm
the game started and did not stop it. The game, its runner, the engine registry, overlay context
and ledger entry are all left in place; `endEngineLaunch` still runs when the launcher exits.
This structurally closes CR-03 too: with no kill on the deadline path there is no wineserver to
stop in a busy bottle, and a regression test proves a neighbour in a shared bottle survives.
Separately the matcher gains the `C:\` form for installs under the bottle's `drive_c`, so those
games get a real first-match and never see the notice.

Steam's own deadline (`src/backend/storeManagers/steam/gameLaunch.ts`, `didntStart`) is out of
scope and unchanged.

Purpose: a running game is never killed on the absence of a `ps` hit (D-18, 59 D-11), and a
neighbour in a shared bottle is never taken down (D-16).
Output: patched watcher and deadline handler, regression tests, one new pair of en strings.
</objective>
