<objective>
Close CR-01 (D-05): `demoStatus.ts` rejects any bottle name outside `/^[A-Za-z0-9._-]{1,64}$/`
with `invalid-bottle`, `preflightCrossover` maps that to a definite `broken`, and under Automatic
`decideLaunchEngine` then falls back with `cx-broken`, which kills the bottle's wineserver,
installs DXVK into the user's bottle and toasts "CrossOver isn't working" on every launch of a
healthy game.

Fix in two layers: (1) validate with the same chokepoint the rest of the engine layer uses
(`sanitizeBottleName`) plus a 255-character cap; `CX_BOTTLE` travels in the child's env, not
argv, so spaces are safe; (2) a name that still fails becomes an inconclusive pre-flight, and an
inconclusive pre-flight with a located CrossOver never triggers a fallback (Automatic launches on
CrossOver; a CrossOver override stays usable). This also applies to the existing
timeout-while-a-game-is-running inconclusive result, which is the coherent rule (59 D-09/G29:
only a real pre-flight failure means broken) and matters most in a busy shared bottle (D-16).

Purpose: D-05 "gains the fallback silently while CrossOver is healthy".
Output: patched probe and decision, updated test table, new regression tests.
</objective>
