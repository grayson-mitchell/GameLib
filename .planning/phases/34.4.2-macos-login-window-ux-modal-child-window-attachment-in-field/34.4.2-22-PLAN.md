<objective>
Build layer (b) of binding operator decision **D-G1**: a frontend test that pins the behaviour which
actually prevents item 5's gate scenario, so withdrawing that item from the live gate does not leave
T-34.4.2-39/-41 with a silent regression path.

**D-G1's reasoning, restated so this plan carries it.** RERUN-4's item 5 asked the operator to click
Amazon sign-in and then click Humble sign-in during nile's ~7-8s spawn delay, exercising the Rust
`PENDING_VISIBLE_LOGIN_WINDOW` single-flight guard. The operator reported: *"app clears buttons so
cant press humble"* — the second click cannot be performed from the shipped UI at all. Item 5 is
therefore being WITHDRAWN from the next contract as structurally unreachable (plan 34.4.2-23 records
the withdrawal with its full reasoning; it is never silently deleted). Coverage is preserved by two
layers: **(a)** Plan 14's existing mutation-proven guard-ordering unit test in
`src/backend/__tests__/tauriShellSource.test.ts`, which this plan does not touch; **(b)** this plan —
a test pinning the frontend behaviour that prevents the second click, so if that behaviour ever
changes, something fails loudly rather than T-34.4.2-39 quietly re-opening with nothing watching.

**The mechanism must be derived, not assumed.** `deferred-items.md` and `ROADMAP.md` both
characterise the cause as *"the frontend disables/clears the other login buttons while one login is
in flight"*. Preliminary source reading suggests that characterisation is approximate: the `Runner`
tiles' `disabled` prop appears to be fed only by a macOS-version check, and the actual reason a
second tile is unreachable appears to be that clicking a tile NAVIGATES away from the login screen,
unmounting every tile at once. **Confirm which it is against current source before writing a single
assertion.** Pinning a disable that does not exist would be worse than no pin at all — it would read
as coverage while guarding nothing. If the derived mechanism differs from the recorded
characterisation, say so plainly in the test's own docstring and in the SUMMARY; that correction is
part of this plan's output.

**What this plan does NOT do.** It does not change any frontend behaviour, does not add or remove a
disabled state, does not touch `src/backend/__tests__/tauriShellSource.test.ts` or any Rust source,
and does not make any claim that T-34.4.2-39/-41 are live-discharged. They are not, and after D-G1
they never will be by this gate — their honest basis becomes unit-proven plus UI-pinned.

Output: one new frontend test file whose every assertion is falsifiable and whose docstring states
exactly what it does and does not prove.
