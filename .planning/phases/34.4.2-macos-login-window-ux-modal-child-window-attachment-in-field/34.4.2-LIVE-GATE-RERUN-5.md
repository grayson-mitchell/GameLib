## Evidence-capture instruction

Implements the dual-sink standard
(`.claude/skills/spike-findings-gamelib/references/live-gate-contract-authoring.md` §3) literally,
**including its single-instance capture-integrity rule for the first time in this phase's
history.** Sink partition, restated so no item can be written against the wrong sink again:

- Rust `[shell]`-prefixed lines reach `tauri:dev`'s own stdout/stderr, and therefore the **session
  transcript** ONLY. They never reach `gamelib.log`.
- Sidecar `logInfo`/`logWarning` calls (`src/backend/logger/index.ts`) reach **`gamelib.log` ONLY**
  — the sidecar's stdout is consumed as the RPC frame pipe, not surfaced as human-readable text
  (`sidecar-console-and-logger-are-invisible`).
- Sidecar STDERR reaches the session transcript, prefixed `[sidecar:err]`.
- Sidecar `console.*` calls reach **nothing at all**.

**Every required literal below is annotated `(session transcript)` or `(gamelib.log)`. No
sidecar-emitted literal is required of the transcript anywhere in this document.**

**Identifier-redaction discipline (T-34.4.2-49):** no cookie value, individual gamekey, order
identifier, email or account id is ever transcribed into this document or any captured artifact —
aggregate counts, domains and window labels (`loginwin-N-...`, random session ids) only. The
session directory lives under `/tmp` and is never committed.

### 0. Single-instance assertion — before EVERY launch, at window-appearance, and at teardown (NEW, F-34.4.2-15/F-A, F-34.4.2-18/F-D)

**Before each launch**, assert zero pre-existing instances:
```
pgrep -f 'target/debug/gamelib-shell'
```
must return nothing. **A non-empty result means STOP and resolve it before launching** — never
"proceed and hope." (This is exactly the gap F-34.4.2-18/F-D found: RERUN-4's own preflight
checked `lsof` for the DummyStore harness but nothing for a stray `gamelib-shell` process, and a
56-minute-old stale instance forced launch 1 to be aborted and re-run.)

**After the window appears**, record the single PID into the transcript with a command whose
output lands in the captured file, not only on screen:
```
pgrep -f 'target/debug/gamelib-shell' | tee -a "$GATE_SESSION_DIR/terminal.log"
```

**At teardown**, record it again with the identical command.

**The abort rule, stated as a rule, not a suggestion:** if the instance count is ever not exactly 1
at any of those three points, **the launch is ABORTED and re-run, and its evidence is NOT
SCORABLE** — nothing from an aborted attempt is archived or cited. RERUN-4 already aborted and
cleanly re-ran two launches for exactly these reasons (a stale pre-existing instance before launch
1; a concurrent operator-driven second instance during launch 2); this promotes that practice from
improvisation to contract.

**Why this exists, stated plainly:** a second concurrent instance does not announce itself — it
**splits the `[shell]` sink while `gamelib.log` stays SHARED**, producing the most dangerous
evidence shape this standard can make: a populated, plausible-looking `gamelib.log` sitting next to
a transcript missing every scored `[shell]` literal. RERUN-4 measured exactly this against items 1
and 2, whose own mechanisms operator-reported as working — the evidence loss, not the mechanism,
is what failed them.

### 2. Per-launch delimiter — write BEFORE each launch, exact literal text

```
echo "=== GATE LAUNCH ${N} — $(date -u +%Y-%m-%dT%H:%M:%SZ) ===" | tee -a "$GATE_SESSION_DIR/terminal.log"
```
where `${N}` is the launch ordinal (1–5). A reader greps section boundaries with
`grep -n '^=== GATE LAUNCH' "$GATE_SESSION_DIR/terminal.log"`.

### 3. The launch command itself — `tee -a`, never bare `tee`, never `>`

```

```
Optionally prefixed `GAMELIB_DEV_SECRET_VAULT=1` (bypasses only this project's own `TokenStore`
path, not the macOS system Passwords/AutoFill store item 3(d) observes — does not affect any
item's evidence).

### 4. Per-launch `gamelib.log` archive — AFTER that launch's app has quit, BEFORE the next launch starts

```
cp ~/Library/Logs/GameLib/gamelib.log "$GATE_SESSION_DIR/gamelib-launch-${N}.log"
```
**Mandatory ordering reason, re-confirmed against current source at this authoring:**
`src/backend/logger/log_writer.ts:1` imports `existsSync, renameSync`; its rotation method
(`log_writer.ts:72-74`: `const haveToArchive = existsSync(this.logFilePath); ...
renameSync(this.logFilePath, this.oldLogFilePath)`) renames the live file to `.old` on the very
next process's first write. A later launch would otherwise destroy an earlier launch's sidecar
evidence outright unless archived first.
