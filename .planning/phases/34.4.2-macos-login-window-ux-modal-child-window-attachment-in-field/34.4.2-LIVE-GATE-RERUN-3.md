### Item 1 — Sheet presentation and survival of the minimize/restore cycle (REQ-34.4.2-01/-02)

**What to do.** With a Humble/GOG/Amazon login sheet presented, perform in order:

(a) Click the main window while the login sheet is open (do not dismiss it).
(b) Drag the main window to a new screen position.
(c) Minimize the main window (into the Dock).
(d) Restore the main window from the Dock.
(e) **Immediately after the restore, type into the password field, then activate the cancel
strip.**

**Gate run 2's sub-check (f) is DELETED** — it required an autofill-glyph click as its own
precondition (via item 3), and there is no glyph any more. There is no mid-session-detachment
mechanism left to re-check, because the mechanism that could cause it (`post_autofill_right_click`)
is deleted (T-34.4.2-36 RETIRED BY DELETION, `34.4.2-PLATFORM-SCOPE.md` §5 sixth update).

**PASS condition for each sub-check:**
- (a) The sheet **stays in front** of the main window and the main window **does not** come over
  it. A sheet BLOCKS its parent by AppKit design — the main window declining clicks while the sheet
  is up is correct sheet semantics and is **NOT** a failure. Only a sheet going BEHIND the main
  window, or the main window accepting input while the sheet is presented, would be a failure.
- (b) The sheet **moves with** the main window's drag.
- (c) The sheet **follows the parent into the Dock**.
- (d) The sheet is **visible and in front** immediately upon restore.
- (e) **Typed characters appear in the password field AND the cancel strip responds** (dismisses
  the sheet when activated). This sub-check is the whole reason this item exists — F-34.4.2-01 (the
  child window's post-restore unresponsive state) turned directly into a PASS condition for the
  sheet mechanism.

**PASS = all five sub-checks (a)-(e) observed as above.**

**Machine evidence — do not accept `sheet_presented=` alone.** Require BOTH of these lines from the
captured transcript:
```
[shell] login-window sheet: read-back attached=true for '{label}'
```
(`src-tauri/src/main.rs:2436`, confirmed present in current source) and
```
[shell] humble_login_open: presentation requested visible=true width=900 height=700 center=true focus_once=true persistent_pin=false light_theme_requested=true sheet_presented=true
```
(`src-tauri/src/main.rs:3698`, confirmed present in current source). `sheet_presented=` alone was
CR-02's original unfalsifiable signal (true on nothing more than "the dispatch did not time out");
`attached=true` comes from the read-back (`child.isSheet()` + pointer-compared
`parent.attachedSheet()`) and is the falsifiable one. If `attached=` is absent but
`sheet_presented=true` is present, that is itself a finding.

**The RETIRED line MUST NOT appear** — its absence is a PASS signal, not a missing observation:
```
[shell] login-window: parent deminiaturized, re-raising {N} attached child window(s)
```
(Plan 07 Task 2 deleted the observer outright; confirmed 0 occurrences in current source by
`grep -c "parent deminiaturized" src-tauri/src/main.rs src/backend`.)
