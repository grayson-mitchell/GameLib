<objective>
Close the last mechanically-identical instance of the F-34.4.2-12 reentrancy self-deadlock, and make
the regression pin that guards it robust to shape rather than to two literal strings.

**What is already done and MUST NOT be re-planned or re-litigated.** F-34.4.2-12 is DIAGNOSED,
FIXED and LIVE-VERIFIED as of commit `6bad86227`. The root cause is a reentrancy self-deadlock on
tao's `EventLoopHandler` handler mutex: wry's blocking `WebviewWindow::cookies()` resolves to
`wait_for_blocking_operation`, which reentrantly pumps `NSRunLoop::mainRunLoop()` from inside
`handle_user_message` — itself already inside tao's `EventLoopHandler::with_callback`, which holds
tao's handler `Mutex` for the whole user-event dispatch. The reentrant pump lets AppKit service a
pending CoreAnimation transaction flush, tao's own redraw path relocks the mutex it already holds,
and the main thread deadlocks on a lock it owns. A live hung-process `sample` put 4185 of 4185
samples in that identical frame chain. **Do not build a discriminator. Do not add a timeout** — the
block sits below the level any Tauri-side receive timeout lives, so a timeout converts a guaranteed
deadlock into a guaranteed timeout. The two candidate layers the gate document recorded (plan 13's
shared-closure arm removal; plan 14's single-flight latch) are **FALSIFIED outright** by that
backtrace and must not reappear in any task here.

**What this plan actually does.** The debug session's own `## Residual Risks` records one call site
it deliberately left out of scope: `humble_login_cookies` (`src-tauri/src/main.rs:3795-3827`), the
LOGIN-POLL direction used by `watchForLogin()`. It still calls `window.cookies()` unconditionally on
every platform — mechanically the identical hazard, differing only in trigger shape (one call per
poll tick against a settled visible window, versus the four-call burst against a freshly-created
hidden window that reproduced the deadlock). Operator decision **D-F2** puts it in scope for this
cycle. Port it onto the same already-proven async `WKHTTPCookieStore` pattern.

The debug session also recorded a second limitation, and it is the more consequential one: the
regression pin `f_34_4_2_12_wry_blocking_cookies_calls_are_macos_gated` is a **source-text scan that
matches two exact call-site prefixes** (`Ok(w.cookies()` and `let all = window.cookies()`). It would
not catch a blocking `.cookies()` written with a different binding name, split across lines, or
added at a third site. There is already a live example of the shape it misses in this very file:
`main.rs:4237-4238` splits `window` and `.cookies()` across two lines. D-F2 requires the pin be made
**shape-robust**, not merely given a third literal.

Output: `humble_login_cookies` hardened and macOS-gated; the pin broadened to all three cookie-reading
arms and to any textual shape; non-macOS untouched; `cargo test`/`build --tests`/`clippy --tests`
clean; the TypeScript source guards still green.

| WKWebView cookie jar → Rust process | Live Humble session credentials (`_simpleauth_sess`) cross here. Values must reach the requesting rustInvoke caller and nowhere else — never a log, never a diagnostic string, never an error message. |
