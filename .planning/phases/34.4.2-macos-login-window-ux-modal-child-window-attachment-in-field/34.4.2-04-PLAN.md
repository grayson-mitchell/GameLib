<objective>
Close the affordance: turn the autofill request plan 34.4.2-03 delivers into the **synthesized
right-click** that pops the real system context menu with `AutoFill ›` in it. Spike 022 measured this
as the only reachable route (L2) — the AutoFill panel cannot be opened directly (L3 impossible), and
the menu item is injected by macOS at display time and is absent from the `NSMenu` object graph.

Purpose: everything before this plan is scaffolding. This is where a user clicking the key glyph gets
the same menu a browser user gets from a right-click, and can pick AutoFill → Passwords to fill the
field.

**SCOPE (locked user decision, 2026-08-04): the Tauri-managed `WebviewWindow` surface ONLY.** The
pristine Epic login window is out of scope and byte-unchanged (REQ-34.4.2-10); it receives no glyph
in plan 03, so it emits no sentinel, so there is nothing here to wire for it. Epic ships last, after
all other runners are proven.

Output: two pure, cargo-tested coordinate helpers; one `post_autofill_right_click` that resolves the
login window's OWN `WKWebView`, converts CSS px → view coords → window coords, clamps, debounces, and
posts an `NSEventType::RightMouseDown`/`RightMouseUp` pair via `NSApplication::postEvent_atStart`;
and the wiring that replaces plan 03's single log-only sentinel branch.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote login page → synthesized OS input | A page-originated request now causes the app to inject a real `NSEvent` into its own event queue. This is the highest-privilege surface in the phase. |
| Rust shell → AppKit main thread | Raw `WKWebView`/`NSWindow` pointers reconstructed inside a main-thread closure. |
| Rust shell → log file | Converted coordinates and `elementFromPoint` metadata reach an uploadable log. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.4.2-17 | Elevation of privilege | page-controlled event injection | mitigate | Six independent constraints, each source-asserted: (1) only `RightMouseDown`/`RightMouseUp` are ever constructed (Test 4) — no left click, no key event, so no button can be "pressed" and no text typed; (2) coordinates are never accepted as window coordinates — the page supplies a CSS rect and the shell converts it through the WEBVIEW's own `bounds()`; (3) `clamp_point_to_view_bounds` REFUSES anything outside those bounds rather than edge-clamping, and runs before any post (Test 2); (4) the event's `windowNumber` is the login window's own, so it cannot be aimed at another app or another window; (5) only labels in `ATTACHED_LOGIN_CHILDREN` are eligible (Test 5), so hidden windows are unreachable; (6) `clickCount: 1`, `pressure: 1.0`, empty modifier flags — no chord can be forged. |
| T-34.4.2-18 | Denial of service | synthesized-event flooding | mitigate | Server-side `LAST_AUTOFILL_POST` debounce at 750 ms per label, checked BEFORE any AppKit call (Test 3). The page-side limit from plan 03 is treated as advisory only. The debounce map is bounded, matching `LOGIN_WINDOW_EVENTS_CAP`'s discipline. |
