# Phase 34.4.2 Platform Scope, Epic-Deferred Record, and Electron-Unchanged Evidence

This document states, in one place, exactly what this phase does on macOS, what it deliberately
does NOT do on Windows/Linux or on the pristine Epic login surface, and what evidence backs both
claims. It is written **before** the blocking live gate runs (`34.4.2-LIVE-GATE.md`, plan
34.4.2-06) — nothing below may be treated as a substitute for that gate's own recorded result.

**Honest residual (Plan 14, T-34.4.2-39).** The single-flight guard above arms at
`humble_login_open`, the earliest point the SHELL can know a login is being opened. It does NOT
cover the interval between the user's click and that call — on the Amazon path that interval is
the ~7-8s nile PyInstaller-onefile spawn (F-34.4.2-06), during which the shell has been told
nothing at all. Concretely: if the user clicks Amazon then Humble during that window, Humble
presents and Amazon is REFUSED — the user's first click loses, not the second. This is a
deliberate trade recorded here plainly, not full coverage: an explicit, logged refusal is
strictly safer than an unrequested sheet arriving over a dismissed one (the concrete failure
mode T-34.4.2-39 was minted to close), but it is not the same as covering the whole click-to-open
interval. See §5's seventh update, below, for the threat-register disposition.

different problem. The same caution applies here: a passing macOS live gate (plan 06) proves
nothing about Windows or Linux, and this document does not claim otherwise.
