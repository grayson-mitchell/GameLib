self-deadlock (`humble_login_cookies`, the login-poll direction), and rebuilt the regression pin so
it guards a *shape* rather than two literal string prefixes. Both mutation proofs the plan demanded

Along the way a **pre-existing red CI gate** was diagnosed and fixed, and the plan's own stated

### Task 2 — shape-robust regression pin (`34515a290`, `9eebcb0c2`)

## Deviations

### DEVIATION 1 — mutation-proof form

### DEVIATION 2 — scope expansion: WR-08 guard fixed (`29e12621f`) — **operator-authorised**

`src/backend/__tests__/longRunningChannels.test.ts` is **outside** plan 17's declared
`files_modified`. The operator authorised the deviation during execution after being shown the
diagnosis.

The WR-08 "stripper integrity" guard counts bare `"` per line to detect a string literal cut in half
by the comment stripper. It normalised away char literals and raw strings but had **no awareness of
escaped quotes** inside ordinary string literals — so `trimmed.ends_with("\" => {")` counted 3
quotes and was reported as truncated despite being perfectly balanced Rust. The gate had been RED on
this false positive since `6bad86227`, reporting a defect in correct source.

`stripRustEscapes` removes whole two-character escapes (`\\.`), not just `\"`: in `"\\"` the escaped
backslash must be consumed first, or a `\"`-only pass would eat the closing delimiter and
manufacture the imbalance it set out to remove. `.` does not match a newline, so a `\`-continued
multi-line literal keeps its trailing backslash and still reads as odd — that shape is a REAL
finding and must not be laundered away.

**Mutation-proven against real source:** restoring the pre-plan-17 `main.rs` (which used
`\`-continued pin messages) puts the guard RED on exactly those 4 continuation lines and on neither
escaped-quote line. False positives removed, falsifiability intact. A self-test covering all four
properties was added.

Related: `9eebcb0c2` rebuilt the pin's own assert messages with `concat!` instead of
`\`-continuation, taking WR-08's unbalanced-line count from 8 to 2 before the guard fix cleared the
residual 2. Message text is unchanged; `{arm}` became a positional `{}`. Proof 1's output above
confirms the message renders correctly at runtime.
