## Evidence-capture instruction

Sink partition, restated so no item is written against the wrong sink (this has gone wrong before):

- Rust `[shell]`-prefixed lines reach `tauri:dev`'s stdout/stderr, therefore the **session
  transcript ONLY**. They never reach `gamelib.log`.
- Sidecar `logInfo`/`logWarning` reach **`gamelib.log` ONLY** — the sidecar's stdout is the RPC
  frame pipe, not human-readable text.
- Sidecar STDERR reaches the transcript, prefixed `[sidecar:err]`.
- Sidecar `console.*` reaches **nothing at all**.

**Every required literal below is annotated `(session transcript)` or `(gamelib.log)`.**

**Identifier-redaction discipline (T-34.4.2-49):** no cookie value, gamekey, order identifier,
email or account id is transcribed into this document or any captured artifact — aggregate counts,
domains and window labels only. The session directory lives under `/tmp` and is never committed.

**A note this contract states plainly, because it changes how logs may be read.** `LogWriter`'s
serialization gate is racy under unawaited near-simultaneous callers
(`src/backend/logger/log_writer.ts`, logged 2026-08-08 alongside F-34.4.2-22): two logger calls in
the same synchronous stretch can land on disk in the opposite of their true call order.
**On-disk log ORDER is therefore not call-order evidence anywhere in this run.** Every PASS bar
below is written as presence/absence of a literal, never as an ordering between two sidecar lines.
The one ordering requirement in this contract (item 1's `attached=` before `sheet_presented=`) is
between two **transcript** lines from the same Rust process, which this defect does not affect.

### 0. Single-instance assertion — before launch, at window-appearance, at teardown

**Before launch**, assert zero pre-existing instances:

```
pgrep -f 'target/debug/gamelib-shell'
```

must return nothing. **A non-empty result means STOP and resolve it before launching** — never
"proceed and hope."

**After the window appears**, record the single PID into the captured file, not only to screen:

```
pgrep -f 'target/debug/gamelib-shell' | tee -a "$GATE_SESSION_DIR/terminal.log"
```

**At teardown**, record it again with the identical command.

**The abort rule:** if the instance count is ever not exactly 1 at any of those three points, the
launch is **ABORTED and re-run, and its evidence is NOT SCORABLE** — nothing from an aborted
attempt is archived or cited.

**Why this exists:** a second concurrent instance does not announce itself — it **splits the
`[shell]` sink while `gamelib.log` stays SHARED**, producing a populated, plausible-looking
`gamelib.log` next to a transcript missing every scored `[shell]` literal. RERUN-4 lost items 1, 2
and 3 to exactly this (F-34.4.2-15), against mechanisms the operator reported as working.

### 1. One-time session setup

```
export GATE_SESSION_DIR="/tmp/gamelib-gate-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$GATE_SESSION_DIR"
```

UTC-timestamped so a prior run's evidence can never be mixed in. Confirm no prior directory is
reused with `ls -d /tmp/gamelib-gate-* 2>/dev/null` first; note any as unrelated, do not delete.

**Archive any pre-existing `.old` before launch:**

```
[ -f ~/Library/Logs/GameLib/gamelib.log.old ] && cp ~/Library/Logs/GameLib/gamelib.log.old \
  "$GATE_SESSION_DIR/gamelib-preexisting-old.log"
```

**Re-resolve the log directory's actual contents at run time** — `ls -la ~/Library/Logs/GameLib/`
— and record it verbatim. Prior contracts embedded an authoring-time `ls` snapshot; that is a
snapshot, never a run-time guarantee. Only `gamelib.log` and `gamelib.log.old` are in scope for
archiving; suffixed historical files and the `games`/`runners` directories are untouched.

### 2. Launch delimiter — write BEFORE the launch

```
echo "=== GATE LAUNCH 1 — $(date -u +%Y-%m-%dT%H:%M:%SZ) ===" | tee -a "$GATE_SESSION_DIR/terminal.log"
```

### 3. The launch command — `tee -a`, never bare `tee`, never `>`

```
npm run tauri:dev 2>&1 | tee -a "$GATE_SESSION_DIR/terminal.log"
```

Optionally prefixed `GAMELIB_DEV_SECRET_VAULT=1` — bypasses only this project's own `TokenStore`
path, not the macOS system Passwords store item 3(d) observes, and affects no item's evidence.

**Use `pnpm tauri:dev` / `npm run tauri:dev`, never bare `tauri dev`** — the latter serves a stale
static bundle.

### 4. `gamelib.log` archive — AFTER the app quits

```
cp ~/Library/Logs/GameLib/gamelib.log "$GATE_SESSION_DIR/gamelib-launch-1.log"
```

`LogWriter`'s rotation (`log_writer.ts`) renames the live file to `.old` on the next process's
first write, so a later launch would destroy this one's sidecar evidence unless archived first.

**A single-launch contract makes this materially safer than any predecessor:** all five items'
sidecar evidence lives in ONE `gamelib.log` with no rotation between items, and the relaunch that
destroyed RERUN-3's evidence (F-34.4.2-11) does not occur at all.

### 5. Closing inventory

```
ls -la "$GATE_SESSION_DIR/"
wc -l "$GATE_SESSION_DIR"/*
```

A zero-length or missing capture is then visible immediately, not discovered during write-up after
the app has quit.
