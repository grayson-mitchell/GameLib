# Phase 34.4.2 Plan 08: Mandated Close Affordance (Cancel Strip + Esc Backstop) Summary

**Two independent, page-optional dismissal routes for a presented login sheet -- an injected, self-re-appending "Cancel sign-in" strip with no kill switch, and a page-independent bare-Esc NSEvent monitor -- both funnelled through a single `request_login_sheet_cancel` entry point that ends the sheet before closing the window.**

## Accomplishments

- `LOGIN_CANCEL_EXFIL_PATH` (`/login-cancel`) joins `AUTOFILL_EXFIL_PATH`/`/reveal`/`/clear-storage` as a fourth path-discriminated sentinel on the shared `REVEAL_EXFIL_HOST`; `is_login_cancel_request` validates host+path only -- no payload, since the channel's entire semantic is "the user pressed cancel" (T-34.4.2-34, accepted and bounded)
- `login_cancel_strip_script` builds a self-re-appending "Cancel sign-in" control (idempotent marker, `MutationObserver` re-add, hidden-iframe delivery, single top-level try/catch, no keyboard listener, no `.value`/`password` read), injected into `humble_login_open`'s visible builder **outside and independent** of the `GAMELIB_AUTOFILL_GLYPH` kill switch -- machine-pinned by Task 3's Test 1 as "the single most important assertion in this plan"
- `request_login_sheet_cancel` is the single dismissal entry point: calls `dismiss_login_window_sheet` (Plan 07) FIRST, then `window.close()`, so the existing `WindowEvent::Destroyed` hook fires and `oauthLoginCapture.ts` settles `{ status: 'cancelled' }` with reason `window-closed`
- `.on_navigation(` now checks `is_login_cancel_request` BEFORE `parse_autofill_request` (cheaper, and the two sentinels are disjoint by path)
- A single process-wide `NSEvent` local key-down monitor installed in `main()`'s `.setup()`, at the exact site Plan 07 retired the deminiaturize observer from: empty-registry short-circuit, then bare-Esc-only (keyCode 53, no Command/Option/Control), then window-address match against every presented sheet via `login_window_ns_window`, then `request_login_sheet_cancel(..., "esc")` and event consumption. Reads only `keyCode()`/`modifierFlags()` -- never `characters()`/`charactersIgnoringModifiers()` (T-34.4.2-35)
- 14 new cargo unit tests (131 passed, 0 failed, 1 ignored -- up from Plan 07's 117) and 8 new jest tests in a "Phase 34.4.2 Plan 08" describe block (84 passed -- up from Plan 07's 76), plus one pre-existing Plan 02 test updated for a legitimate second `dismiss_login_window_sheet` call site
- `open_pristine_epic_login_window` and `EpicPristineNavDelegate` remain byte-identical across all three task commits (confirmed via `git diff --unified=0` hunk inspection each time) -- REQ-34.4.2-10

## Decisions Made

- The cancel strip is macOS-gated (`#[cfg(target_os = "macos")]`) while the autofill glyph is not -- a deliberate divergence from `34.4.2-PLATFORM-SCOPE.md` § 1's recorded cross-platform wart, since only macOS presents a login window as a sheet in the first place (Plan 07's scope).
- The strip gets NO kill switch, by design, unlike the autofill glyph's `GAMELIB_AUTOFILL_GLYPH`: an env var that removes the only visible exit from a parent-blocking sheet is a lock-out switch, not a safety switch.
- The Esc monitor is a fresh, separate implementation rather than a refactor of the pristine Epic arm's own local monitor -- that region is byte-frozen by REQ-34.4.2-10, and its monitor legitimately reads `charactersIgnoringModifiers()` for Cmd+V/C/X/A/Z routing, which this privacy-constrained monitor must never do.
- `app_for_cancel` is a separate `AppHandle` clone from `app_for_autofill` in the `.on_navigation(` closure (not a reuse), matching this arm's existing per-use-site clone convention for independent readability.
