## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest (existing project-wide config, multi-project) |
| **Config file** | root `jest.config.js` — **FIVE** projects: `Backend`, `Common`, `Frontend`, `Preload`, `Meta` |
| **Quick run command** | `npx jest --selectProjects <Project>` — pick by *which tests read the file*, not by where the file lives (see the two corrections below) |
| **Full suite command** | `pnpm test` |
| **Estimated runtime** | quick ~30–90s per project; full suite several minutes |

> ⚠ **`--selectProjects` is CASE-SENSITIVE.** `--selectProjects backend` matches nothing
> and **exits 0** — a green-looking run that measured nothing.

> ⚠ **CORRECTED 2026-08-27 during `/gsd-execute-phase 34.18` — this section was wrong TWICE,
> and both errors fail OPEN (green, exit 0, measuring nothing).**
>
> **Error 1 — there are FIVE projects, not two.** This file originally said the projects are
> "named `Backend` and `Frontend`" and prescribed `--selectProjects Backend` for work it also
> described as "`meta/`-tier". But `meta/**` runs under **`Meta`**. Plans 01, 02 and 03 create
> their gates under `meta/__tests__/`, so the prescribed command would have run ~4,270 Backend
> tests, gone green, and measured **zero** of the gates those plans exist to produce. Verified
> from `jest.config.js` `projects[]` plus each project's own `displayName`:
> `src/backend`=`Backend`, `src/common`=`Common`, `src/frontend`=`Frontend`,
> `src/preload`=`Preload`, `meta`=`Meta`.
>
> **Error 2 — select by WHICH TESTS READ THE FILE, not by where the file lives.** Correcting
> Error 1 by mapping each plan's `files_modified` to a project *by path* produced a second
> fail-open miss. `.github/workflows/*.yml` lives in no jest project, so plan 34.18-02 was told
> its tests were "all under `meta/`" and ran only `Meta`. But
> `src/backend/__tests__/runnersOnedirWorkflow.test.ts` lives in **`Backend`** and reads that
> workflow from disk. Plan 02 retired the x64 leg while that suite still pinned the two-leg
> world; **six failures went undetected until the wave-boundary full-project run**, and were
> fixed in commit `ba9964d44`.
>
> **Standing rule for the rest of this phase and for verification:** before running a gate,
> `grep -rln "<artifact-name>" --include="*.test.ts" src/ meta/` and run EVERY project that
> matches. Non-source artifacts (`*.yml`, `package.json`, `*.json` manifests) are the dangerous
> case — they belong to no project yet are asserted against from several.
> Known cross-project readers in this phase:
> `build-runners-onedir-macos.yml` → `Backend` + `Meta`;
> `electron-builder.yml` → `Backend` + `Meta`;
> `package.json` → `Backend` + `Frontend` + `Meta`.
>
> Always confirm a **non-zero test count** and that your new suite appears by name
> (`--listTests` or `--testPathPattern <file>`).

> ⚠ **Gate on per-project runs, not the full suite.** A full `pnpm test` on this repo
> manufactures a different (load-induced) failure set than the per-project runs. Use
> `pnpm test` for wave merges only, and diff any new failure against a per-project re-run
> before treating it as real.

> ⚠ **`pnpm codecheck` (tsc) says NOTHING about CI lint.** Any edit that touches
> formatting or string tables must additionally be checked with `pnpm lint` /
> `prettier --check` **in place** (a check run against a temp copy resolves a different
> config and is meaningless).
