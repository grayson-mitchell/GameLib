## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest (existing project-wide config, multi-project) |
| **Config file** | root `jest.config.*` — projects are named `Backend` and `Frontend` |
| **Quick run command** | `pnpm test --selectProjects Backend` (most of this phase) / `pnpm test --selectProjects Frontend` (frontend-only edits) |
| **Full suite command** | `pnpm test` |
| **Estimated runtime** | quick ~30–90s per project; full suite several minutes |

> ⚠ **`--selectProjects` is CASE-SENSITIVE.** `--selectProjects backend` matches nothing
> and **exits 0** — a green-looking run that measured nothing. The display names are
> exactly `Backend` and `Frontend`.

> ⚠ **Gate on per-project runs, not the full suite.** A full `pnpm test` on this repo
> manufactures a different (load-induced) failure set than the per-project runs. Use
> `pnpm test` for wave merges only, and diff any new failure against a per-project re-run
> before treating it as real.

> ⚠ **`pnpm codecheck` (tsc) says NOTHING about CI lint.** Any edit that touches
> formatting or string tables must additionally be checked with `pnpm lint` /
> `prettier --check` **in place** (a check run against a temp copy resolves a different
> config and is meaningless).

## Sampling Rate

- **After every task commit:** `pnpm test --selectProjects Backend` (or `Frontend` for
  frontend-only edits). Most of this phase is Backend-tier or `meta/`-tier.
- **After every plan wave:** `pnpm test` (full suite) **plus** `pnpm codecheck`.
- **Before `/gsd:verify-work`:** Full suite green.
- **Phase close:** full suite green **AND** D-05's blocking `checkpoint:human-verify`
  discharged. **The phase does not close on sentinels** — it closes with real arm64
  digests and a working `pnpm download-helper-binaries` on darwin.
- **Max feedback latency:** ~90 seconds (per-project run).

## Wave 0 Requirements

New test files this phase needs before its gates can be non-vacuous. Every one of these
must be **RED-proven**: demonstrated to FAIL against the known-bad input it guards, not
merely to pass against HEAD.

- [ ] **D-02 — README disclosure gate.** Asserts the verbatim literal
      `GameLib will not support Intel Macs on macOS` in `README.md`.
      **RED-proof:** must fail against the pre-fix `README.md` (line 82 is
      `- macOS 14 or newer`). A gate that names a landmark rather than the literal
      does not satisfy D-02.
- [ ] **D-08 — non-goal survivor test** (the *over*-reach direction). Pins that the three
      out-of-scope `x64` categories still exist after the sweep: **7**
      `electron-builder.yml` refs to `build/bin/x64/win32/*.exe` (including inside the
      `mac:` files block), **6** linux/windows download keys in
      `meta/downloadHelperBinaries.ts`, and the runtime fallback at
      `src/backend/utils.ts:553`. Follow the existing idiom —
      `meta/__tests__/verifyRunnerBundle.test.ts:373` ("vacuity control") and
      `meta/__tests__/buildRunnersOnedir.test.ts:765` ("vacuity guard").
- [ ] **D-10 — `isIntelMac` removal completeness gate.** Static zero-match proof over
      `src/`. This is **load-bearing**: research traced the partial-removal failure mode
      to `GlobalState.tsx`'s uncaught await → sidecar `dispatchInvoke()` returning
      `UNPORTED_CHANNEL_MARKER` → swallowed by `bootErrorSurface.ts` as a `console.warn`.
      Absence of a runtime error therefore proves nothing; the static gate is the proof.
- [ ] **Digest 6→3 reduction non-vacuity.** Update
      `meta/__tests__/pinRunnerDigests.test.ts` (exists; fixture shape not yet read in
      full — read it before editing). The reduced-key assertion must fail against a
      six-key manifest, not merely pass against a three-key one.
- [ ] **Audit before assuming coverage** for the **4 additional D-11 branch sites**
      research found beyond the 2 D-11 names (`tools/dxmt.ts` ×3, `tools/index.ts:637`,
      `main.ts:233`, `WineManager/index.tsx:61`). These may need new assertions in
      existing files rather than new files.
