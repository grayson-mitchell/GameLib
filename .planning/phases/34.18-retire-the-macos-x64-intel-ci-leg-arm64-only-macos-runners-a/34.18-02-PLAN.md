<objective>
Retire the macOS x64 half of the runner-onedir pipeline end to end: one workflow leg, three digest
slots, an arm64-only downloader, and an archive namer that cannot produce a name with no pin.

Purpose: the ROADMAP's own words are that "a partial retirement is worse than none, because a
half-retired arch leaves the guard and the digest manifest disagreeing about how many assets exist."
This plan is the consumer set (1, 2, 3) that has to move together for that disagreement to be
impossible.

Output: `build-runners-onedir-macos.yml` builds and publishes one arch; `runnersOnedirDigests.json`
has three keys; `downloadHelperBinaries.ts` fetches arm64 only and says something true when it
throws; `buildRunnersOnedir.ts` refuses `x64`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub rolling release -> developer/CI machine | `downloadOnedirAsset()` fetches an archive over the network and extracts it into `public/bin`. The digest committed in this repository is the only thing standing between a tampered release asset and code that runs on every build machine. |
| GitHub Actions runner -> rolling release | The workflow's `gh release upload --clobber` writes the assets everyone downstream trusts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.18-04 | Tampering | `meta/downloadHelperBinaries.ts` `downloadOnedirAsset()` supply-chain gate | mitigate | The 6→3 reduction must not weaken fail-closed behaviour.
