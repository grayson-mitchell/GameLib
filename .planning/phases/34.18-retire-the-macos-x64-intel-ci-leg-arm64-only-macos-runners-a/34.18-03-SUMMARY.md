# Phase 34.18 Plan 03: Reduce pinRunnerDigests.ts and its test suite to arm64-only Summary

Reduced `meta/pinRunnerDigests.ts` — scope consumer 7, discovered at discuss time and absent
from the ROADMAP's list of six — from a two-arch tool (fetching a `SHA256SUMS-x64` file that has
never existed, because the x64 leg never dequeued) to a single-arch (arm64) tool that fetches
`SHA256SUMS-arm64` and `BUILD-MANIFEST-arm64.json`, validates three tracked digest keys instead
of six, and replaces the now-vacuous two-manifest `runId` equality check with a named
single-manifest non-null assertion carrying the same actionable message. The test suite was
reduced in lockstep, with every one of the five required fail-closed cases confirmed still
present and passing.

## What Was Built

**Task 1 — `meta/pinRunnerDigests.ts` reduced to arm64-only.**
`type Arch = 'x64' | 'arm64'` narrowed to `type Arch = 'arm64'`. `main()` now fetches only
`SHA256SUMS-arm64` and `BUILD-MANIFEST-arm64.json` (the two x64 fetches, and their corresponding
`parseSha256Sums`/`assertKnownFilenames`/`warnOnTagDrift` calls, were deleted). `arch` parameters
on `parseSha256Sums`, `assertKnownFilenames`, and `warnOnTagDrift` were kept unchanged — they name
their arch in error/warning messages, which is the property that survives the reduction, not the
arity. `assertAgreedRunId(manifestX64, manifestArm64)` — whose cross-manifest equality check goes
vacuous with a single manifest — was replaced with `assertNonNullRunId(manifest)`, which throws
when `runId` is null, carrying forward the existing message's actionable half in substance
(mentions `build-runners-onedir-macos.yml` and `pin:runner-digests` verbatim) plus a docstring
explicitly recording that Phase 34.18 retired the two-manifest equality check because there is now
one manifest, so a later reader sees it was replaced deliberately rather than lost. The
disagreement branch was deleted entirely (structurally unreachable with one manifest).
`assertCoversAllKeys`'s error text changed from "six tracked digest keys" to "three tracked digest
keys" — the function's logic already derives its expectation from `existingKeys`, so only the
prose changed, no new hardcoded numeric literal. The header docstring, the
`gh release upload --clobber` rationale comment, and the `assertCoversAllKeys` docstring were all
updated to describe two-file, single-arch, three-digest operation. `GAMELIB_RUNNERS_REPO`,
`RUNNERS_ONEDIR_TAG`, `BASE_URL`, `DIGESTS_PATH`, and the fetch-then-validate-then-write-once
ordering were all left untouched.

**Task 2 — `meta/__tests__/pinRunnerDigests.test.ts` reduced to arm64-only, every fail-closed case
preserved.** `CURRENT_DIGESTS_FILE`'s `digests` fixture reduced from six keys to the three arm64
keys. The six `DIGEST_*_X64`/`DIGEST_*_ARM64` constants were reduced to three
(`DIGEST_LEGENDARY_ARM64`, `DIGEST_GOGDL_ARM64`, `DIGEST_NILE_ARM64`) — no x64 constant name was
reused for a "need two distinct digests" case, since none of the surviving cases needed that.
`SHA256SUMS_ARM64_TEXT` replaced the two-text fixture pair. `queueFetchSequence()`'s override shape
dropped from four keys to two (`sumsArm64`, `manifestArm64`). The `runId agreement gate` describe
block was renamed `runId gate` and reduced to the single null-`runId` case; a comment in its place
records that the disagreement case was retired by Phase 34.18 because there is only one manifest
now — no `xit`/`.skip` was used. A vacuity control was added to the `main() success path` test:
after asserting the written digests equal `EXPECTED_DIGESTS`, it additionally asserts
`Object.keys(parsed.digests)` has length exactly 3 and that `mockedWarn` was not called, so a
negative case elsewhere in the suite cannot be "passing" for an unrelated reason (e.g. a silently
swallowed error would still leave `thrown` `undefined` and fail the `expectMainToThrow` helper's
own `expect(thrown).toBeDefined()`, but this control additionally pins the happy-path output shape
itself).
