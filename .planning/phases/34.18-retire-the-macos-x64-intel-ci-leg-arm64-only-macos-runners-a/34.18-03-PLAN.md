<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub rolling release -> `meta/runnersOnedirDigests.json` | `pin:runner-digests` is the only automated writer of the digests that every later `download-helper-binaries` run verifies against. Whatever it accepts becomes the repository's committed statement of what the correct bytes are. |
| developer machine -> repository | The pin is a developer-initiated write, deliberately not a bot PR (34.16 D-10). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.18-08 | Tampering | `assertAgreedRunId` removal | mitigate | The cross-manifest `runId` equality check is a real integrity assertion (digests spanning two runs cannot honestly be attributed to one pin). With one manifest it is vacuous, but deleting it with nothing in its place would let a `runId: null` manifest — a LOCAL build, not a CI run — be pinned as provenance. Task 1 replaces it with `assertNonNullRunId`, carrying the same actionable message; Task 2 keeps a test for the reachable failure. |
| T-34.18-09 | Spoofing | `BASE_URL` / `GAMELIB_RUNNERS_REPO` / `RUNNERS_ONEDIR_TAG` | mitigate | These are hardcoded precisely so the fetch source cannot be redirected by an env var or argv flag. The reduction must not "helpfully" parameterise them while touching the fetch block; the acceptance criteria pin `process.env`/`argv` occurrence counts as unchanged. |
| T-34.18-10 | Tampering | fail-closed parse/coverage assertions | mitigate | Digest-format strictness (exact 64 lowercase hex, exact two-space separator, known filenames, full key coverage) is what stops a malformed or partial SHA256SUMS from being pinned as authoritative. Task 2 walks a written inventory rather than trusting a green run, because a reduction is exactly the shape of edit that silently drops a case. |
| T-34.18-11 | Denial of Service | write-once-at-the-end invariant (T-34.16-19) | mitigate | A partially written digests file would leave the repo unable to download helpers at all. The single-`writeFile` shape and the fetch-then-validate-then-write ordering are pinned by an occurrence-count criterion and by the "no write on any negative path" check. |
| T-34.18-SC | Tampering | npm/pip/cargo installs | accept | **This plan installs no packages.** No dependency block or lockfile is touched. |
</threat_model>
