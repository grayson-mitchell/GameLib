<objective>
Settle D-43-05 by measurement: does a populated Humble order carry any purchase/order date field
that could back a `Most recent` sort? Do NOT decide the answer — run the probe and record what it
returns.

Purpose: `HumbleKey` (`src/common/types/humble.ts:93-126`) carries no date. Every adapter schema
is `.passthrough()`, so a date WOULD survive if Humble sends one. The existing structural
diagnostic (`describeZeroKeyOrder` → `order_fields=`) only fires on the `tpkd_dict`
absent/null/mistyped branch, which has never fired live. Reaching it on a populated order needs a
deliberate, temporary probe.

Output: a verdict document, and a tree with the probe removed.

**This plan does not block anything.** Its outcome only decides whether the sort picker ships two
options or three. If the verdict is NEGATIVE, the other 23 requirements ship unchanged.
</objective>

Facts measured against the repo during planning — use these, do not re-derive them:

- `src/backend/humble/classify.ts:582` declares `function fieldNames(value: object): string`.
  It is **module-private — there is no `export` keyword on it.** `43-RESEARCH.md`'s probe design
  assumes it can be called; it cannot be, from outside the module, without a change.
- `src/backend/humble/classify.ts:565` declares `const MAX_DIAGNOSED_FIELDS = 15`, and
  `fieldNames` truncates to that many names, appending `,+N more`.
  **This is the probe's single most dangerous detail.** A real order with more than 15 top-level
  fields would hide a date field behind `+N more`, and the probe would read that absence as
  evidence the field does not exist. Test 4 (absence-observability) of
  `live-gate-contract-authoring.md` names exactly this class of defect. The probe MUST log the
  complete, uncapped name list.
- `src/backend/humble/library.ts:334-344` is the only call site of `describeZeroKeyOrder`, and it
  sits inside `if (entry.keys.length === 0)`. A populated order never reaches it.
- `src/backend/humble/constants.ts:57` declares `export const HUMBLE_CLASSIFIER_VERSION = 7`.
- Log sink (from `live-gate-contract-authoring.md` § Section 3, confirmed against
  `src/backend/logger/index.ts`): sidecar `logInfo`/`logWarning` calls reach
  `~/Library/Logs/GameLib/gamelib.log` and **never** the tee'd terminal transcript. Sidecar
  `console.*` reaches nothing at all. The probe must use `logInfo`, and the operator must read
  `gamelib.log`, not the terminal.
- `src/backend/logger/log_writer.ts:72-74` rotates `gamelib.log` to `.old` on each launch, so the
  file must be archived per launch before relaunching.
</interfaces>
