<objective>
Half A, part 1. Make Enter commit a typed path in `PathSelectionBox`, and make that new commit
route incapable of double-firing the one non-idempotent consumer among its 13 call sites.

Purpose: `PathSelectionBox` commits only via `onBlur`. A user who types a path and presses Enter
loses the input silently — no error, no affordance, no indication the value was discarded
(`.planning/phases/34.9-.../deferred-items.md` item 8, re-verified live 2026-08-23). The seam to
fix it already exists end-to-end: `TextInputWithIconField` declares `onKeyDown` at
`TextInputWithIconField/index.tsx:17` and spreads it into `TextInputField`, whose props type
inherits `onKeyDown` from `React.InputHTMLAttributes` and forwards it to the real DOM `<input>` at
`TextInputField/index.tsx:65`. `PathSelectionBox` is the only link in the chain that never passes
one.

Output: an Enter handler on `PathSelectionBox`'s `<TextInputWithIconField>` call, a two-part
commit guard inside `PathSelectionBox` that generalises the no-op discipline all 13 callers
currently have to implement (or fail to implement) for themselves, and a no-DOM jest suite that
invokes both handlers and asserts on mock call arguments and call counts.

**This plan is Half A only. It must not touch anything about the paste half.** The two halves are
not one defect; the paste half is owned by `34.17-03-PLAN.md` as a reproduction obligation, not a
fix obligation.
</objective>

Introduce three functions in the component body, above the return statement:

- `commitPath(next: string)` — the single funnel every commit route now goes through. **Guard G1:**
  if `next === path` (the already-committed prop), clear `enterCommittedRef.current` to `null` and
  return WITHOUT calling `onPathChange`. Otherwise clear `enterCommittedRef.current` to `null` and

  `enterCommittedRef.current = next`. The assignment must come AFTER the `commitPath` call, because
  `commitPath` unconditionally clears the ref.
- `commitFromBlur(next: string)` — **Guard G2:** if `enterCommittedRef.current === next`, set the
  ref to `null` and return WITHOUT calling `onPathChange`. Otherwise call `commitPath(next)`.

Why both guards, and why G1 alone is not enough — record this as a comment in the file, because
`34.17-RESEARCH.md` recommends option (b), the `path`-prop comparison, on its own and that
recommendation is insufficient: at `EgsSettings.tsx` the `path` prop (`egsPath`) is only updated
after `window.api.egsSync` resolves, so during an Enter-then-Tab in the same tick `path` is still
the OLD value, G1 does not fire, and `egsSync` runs twice. G2 is what actually closes
REQ-34.17-02 there. G1 is what suppresses a redundant commit at the other 12 sites and what keeps
a held-Enter/blur cycle from re-committing an already-settled value. Conversely G2 alone would
leave the unchanged-value blur firing `egsSync` on every focus change. Neither guard subsumes the
other.

swallow a genuine edit made between the Enter and the blur; test case 5 pins that.
