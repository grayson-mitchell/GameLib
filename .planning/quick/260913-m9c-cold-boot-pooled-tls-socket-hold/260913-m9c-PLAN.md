**1. Candidate 3 is ANSWERED, and it reframes the todo.** The todo asks whether Node v26's global
agent `keepAlive` behaviour makes the pool ours to configure. Measured:

```
http.globalAgent.keepAlive= true  keepAliveMsecs= 1000  scheduling= lifo  options.timeout= 5000
https.globalAgent.keepAlive= true
```

`Agent.prototype.keepSocketAlive` (read from `node:http` at runtime) does two things to a socket
going idle: `socket.unref()`, and `socket.setTimeout(this.options.timeout || 0)`.

So Node's own global agent parks a free socket for at most **5s**. But the sidecar does not use
the global agent for this traffic.

**2. The pool is OURS, it is a single site, and it has no idle timeout.**
`src/backend/utils.ts:1731`:

```
const axiosClient = axios.create({
  timeout: 10 * 1000,
  httpsAgent: new https.Agent({ keepAlive: true }),
  headers: { 'User-Agent': GAMELIB_USER_AGENT }
})
```

No `timeout` on the agent → `this.options.timeout || 0` → `socket.setTimeout(0)` → **the idle
socket is never destroyed on a timer**. It lives until the remote end closes it, which is exactly
the "waiting for the remote ends to close them" shape the todo measured. `grep -rn
"httpsAgent\|keepAlive" src/ meta/` returns this ONE line and nothing else, so the whole blast
radius of the pooling policy is one object literal. `https` is already imported at
`src/backend/utils.ts:13` as `import https from 'node:https'`.

**3. There is a genuine open question the fix depends on, so Task 1 measures before Task 2 edits.**
`keepSocketAlive` calls `socket.unref()`, yet the todo measured 25 sockets that were still
`hasRef()` at t=20s and a diagnostic report with referenced `tcp` handles. Those two facts are in
tension, and only two readings survive:

  - **(a) the sockets are still IN-FLIGHT** (in `agent.sockets`, not `agent.freeSockets`), so
    `keepSocketAlive` never ran on them; or
  - **(b) the sockets ARE free, but `unref()` on a `TLSSocket` does not reach the underlying TCP
    handle** — the JS stream's `_handle` is the `TLSWrap`, while the referenced libuv handle
    belongs to the parent TCP socket. Under (b) the agent's `unref()` is cosmetic and the missing
    `timeout` is the whole defect.

Prediction on the current evidence, stated so the measurement can falsify it: **(b)**. Reason:
`axiosClient` sets a 10s per-request `timeout`, so no single request can still be in flight at
t=20s, and the todo's count held flat at 25 from t=5s to t=20s.

This matters because the remedies differ. Under (b), adding an agent `timeout` fixes it and the
`unref()` question is moot. Under (a), an agent `timeout` would change nothing and the real defect
is an unbounded boot-time request — a different file and a different fix.

**4. Do NOT hand-roll an `unref()` of free sockets as the remedy.** Node re-refs on reuse inside
`Agent.prototype.reuseSocket` via `socket.ref()`. If `TLSSocket.unref()` cannot reach the TCP
handle (reading (b)), then `ref()` cannot either, and a hand-rolled `unref()` on the agent's
`'free'` event is the *same call Node already makes* — it adds nothing, while any asymmetric
variant risks the process exiting out from under an in-flight request. The supported lever is the
agent's `timeout` option.

**5. `pnpm smoke:sidecar` CANNOT reproduce this locally.** That gate is the named real-profile
exemption, so the operator's run inherits a warm, populated profile and finishes fast. CI runs
cold. Only a fresh fake-profile run exercises the failing condition.
