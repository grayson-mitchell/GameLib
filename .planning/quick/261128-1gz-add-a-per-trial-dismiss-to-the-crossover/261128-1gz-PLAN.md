## Findings the plan rests on (traced at planning time, HEAD b7ca72fff)

**Where `dismissEngineNotice` lands: Rust, not the sidecar.** Since 87-49 (D-14) it is a native `engine`
channel. The renderer's `window.api.dismissEngineNotice` goes to `src-tauri/src/native_router.rs:558`, which
calls `engine_dispatch::dismiss_engine_notice`. That handler runs `parse_dismissal_args` (`engine_dispatch.rs:673-687`,
a strict union whose one rejection is `("0", "invalid_union")`) and then `run_engine_op("engine_notice_dismiss")`.
The op is `gamelib-engine` `lib.rs:462-469`, which calls `state::notices::dismiss` (`notices.rs:127-147`), and that
writes through the StoreHost into `<userData>/store_cache/steam_engine_notices.json`. No sidecar TS is involved; the
`flowRegistrationCensus.test.ts:90-93` comment confirms it. The 56c-3 owed check ("dismissal handled by Rust alone")
is therefore true in code. It is still a live check, and this plan does not run it.

**Who reads the dismissal.** `engine_state.rs` `compute()` (`:288-390`) is the only place a state is built. It is
called from the page read `get_engine_state` (`:449`) and from the launch publish `record_launch_decision`
(`:642`), and both call sites have `ctx` in scope. `show_trial_notice` is
`trial_days_remaining.is_some_and(|days| days <= TRIAL_NOTICE_DAYS)` (`:363`), with `TRIAL_NOTICE_DAYS = 7` at `:43`.
The only renderer surface for the trial notice is `EngineNotices.tsx:29-55`. The launch-fallback toast
(`steam.engine.toast.*`) is the expired case, not the trial countdown. `src/backend/enginewine/decision.ts` only
carries the type.

**What identifies a trial.** The engine state holds only `trialDaysRemaining` (from `wine --demo-status`,
`crossover/demo_status.rs`) and the build. The spike says the trial clock is per bottle (`InstallTime` in the bottle's
`system.reg`, XOR-obfuscated, a 15-day trial; spike-findings `macos-runtime-signals.md`: "Do not check expiry once per
CrossOver install — it is per bottle"). GameLib reads no profile content (T-87-45), so `InstallTime` is off limits.
The build does not change on a trial reset, and neither does the bottle name. The one trial identity available is the
estimated end day, `floor(now_ms / 86_400_000) + daysRemaining`, the way `untested-crossover` keys on `build`.
A new trial ends at least 8 days after a dismissed one: the notice only shows at 7 days or fewer, and a trial is 15
days. So a 3-day slack absorbs CrossOver's day rounding, and the drift of a Healthy page pre-flight that is cached
without a TTL (`cached_preflight`, `:270-281`), without ever hiding a genuinely new trial. Keeping the max end day
means a dismissal on an earlier-ending bottle never un-hides a later one.

**Why Rust logs only the new kind.** `tests/golden_state.rs:618-623` asserts `got.logs == 0` for every golden case,
including every existing `dismiss` case, and no golden uses `crossover-trial`. That file is `#![cfg(unix)]`, so it
runs in CI and not on this Windows machine.

**The renderer log channel.** It is `window.api.logInfo` (`src/preload/api/misc.ts:103`, native `logInfo` in
`src/common/types/ipc/native.ts:254`), used for example in `DialogHandler/index.tsx:113`. The Dismiss label reuses
the existing `steam.engine.notice.dismiss` key ("Dismiss"), so no locale file changes.

**The IPC contract files.** `src/common/types/ipc/nativeChannels.json` is hand-edited and holds the type string and
the valid/invalid vectors that `native_router.rs:871` replays. `pnpm gen:ipc-contract` regenerates
`src/common/types/ipc/ipcSchemaSnapshot.json` (and `src-tauri/src/ipc_contract.rs` if it changes), and
`pnpm check:ipc-contract` fails on drift.
