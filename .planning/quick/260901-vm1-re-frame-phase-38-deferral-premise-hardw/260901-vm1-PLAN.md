# Quick Task 260901-vm1: Re-frame Phase 38's deferral premise

## Problem

Phase 38's records assert that its items are blocked on hardware or an OS **this project does not
have**. That premise is FALSE. The operator owns a Windows machine, a Linux machine, an Xbox
controller and a second controller. Nothing in Phase 38 is hardware-blocked.

The real cost of every item is a **machine switch**, a **controller pairing**, or (on four items)
a **two-library Steam setup step** — all schedulable, none an acquisition.

This matters because the two framings behave differently:

- "needs an OS this project does not have" → indefinitely blocked, unfalsifiable, nobody can act
- "costs a machine switch, so batch it" → a task with a known cost that competes for time

Phase 38's own **relocation rule (2)** forbids exactly this: it names
`blocked_by: "a sub-1200px-wide display"` as the cautionary example of an unfalsifiable prose
blocker that "rots without anyone noticing". The live ledger commits that error 29 times.

Measured 2026-09-01 — every `blocked_by` value in the ledger, summing to exactly the 29 items
`gsd-sdk query audit-uat` reports for this phase:

| Value | Count |
|---|---|
| `a game controller` | 8 |
| `a Windows machine` | 7 |
| `a Linux machine` | 5 |
| `a Windows or Linux machine` | 3 |
| `BOTH a Windows and a Linux machine (scored on matrix rows 5 and 7)` | 2 |
| `a Windows machine with TWO registered Steam libraries` | 2 |
| `a Linux machine with TWO registered Steam libraries` | 2 |
| **Total** | **29** |

- **Every `platform_gate` expression.** These are CORRECT and are the falsifiable half of each
  item. Several read "unobservable on this project's hardware" / "this project's macOS-only
  hardware" — those remain TRUE, because they describe the macOS dev machine the app runs on, not
  what the operator owns. Editing them would destroy the only sound part of the ledger.
- Every `why_human`, `origin_phase`, `origin_item`, `prior_state`, `expected`, `test` field.
- `status: human_needed` and the `human_verification` array shape.
- Relocation rule (2)'s illustrative quote of the `sub-1200px-wide display` blocker — it is a
  historical example, not a live blocker.
