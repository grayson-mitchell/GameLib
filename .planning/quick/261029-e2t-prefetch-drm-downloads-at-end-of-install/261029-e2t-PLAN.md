# Quick 261029-e2t: prefetch DRM-mode downloads at the end of a bridge install

## Problem

A SteamStub (`.bind`) game's first Play ran drmLaunchSetup's download steps — CrossOver
allowlist, steamclient-layer component, runner clone, Valve client — before staging the
bottle, so the user waited on downloads after clicking Play. The install already knows the
exe is SteamStub (`placeShimForGame` logs `drmWrapper=steamstub`).

## Change

- Extract steps 2-5 of `runSetup` into `ensureDrmDownloads`; the launch path calls it
  unchanged (each step's error object returned as-is, same `fail()` handling).
- New `prefetchDrmDownloads`: gates on `resolveBridgeMode`, runs `ensureDrmDownloads` with
  `'drm-setup'` progress, never rejects. Skips the Mac Steam check (a download needs no
  Steam); registers no runner, clears no runner, touches no bottle.
- `installBridgeGameLeased`: after the shared redists and before the final `'done'`,
  `prefetchBridgeDrmDownloads` resolves the mode exactly as `launchBridgeGame` does
  (UE-aware `detectLaunchDrmWrapper`, CEG markers from the `.bind` exe) and prefetches.
  A failure logs and the install still completes; Play retries every step.
