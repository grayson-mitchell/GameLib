<objective>
Fix the silent no-op when a user uninstalls, on Mac, a native Steam install that GameLib downloaded and the running Mac Steam never adopted.

Today `SteamGame.uninstall()`'s `root === 'native'` branch always fires `steam://uninstall/<appId>`. A running Mac Steam that never adopted the install still holds the app as Uninstalled, so it ignores the URL and shows no dialog. Live evidence (2026-10-29, WazHack 264160): three URL dispatches, content_log's last line for 264160 still "Uninstalled", files untouched, same steam_osx PID. The "Uninstalling" pill (set by `uninstallGameCallback` in `src/backend/utils/uninstaller.ts`, which suppresses `done` for steam) is cleared only by `startUninstallPolling`'s grace branch after GRACE_TICKS (20 x 3 s, about 60 s), with an "Uninstall not confirmed by Steam" toast, and the badge stays Installed. That poller can never see 'absent' because Steam never removes the ACF.

Quick 261029-ji2 makes this state normal: it records a pending adoption {steamPid, manifestPath, baseline ACF} after a native Mac depot install with Steam running.

Fix: in that exact state, which is ji2's own `decidePlayAdoption(...) === 'restart'` (record present, same PID, `isSteamAdoptedAcf` false), GameLib removes the install itself through the existing guarded `removeSteamInstallCopy(appId, 'native')`, then completes through the existing `pollUninstallOnce(appId, 'native')`. Every other case keeps today's delegation unchanged.

Output: one new private method plus its call site in games.ts, and a new test describe in games.test.ts.
</objective>
