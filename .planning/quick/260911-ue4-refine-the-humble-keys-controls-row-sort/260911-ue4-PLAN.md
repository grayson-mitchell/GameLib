# Refine the Humble Keys controls row

Follow-up to `260911-t0p` after its live UAT
(`.planning/quick/260911-t0p-fix-four-ui-defects-on-the-humble-keys-s/260911-t0p-UAT.md`).
t0p's defect-2 fix moved the `Sort` label off its stacked position and onto the row — that part
holds and is re-verified live. The operator then reported three refinements against the shipped
result. All three are **measured**, not impressions.

## Evidence (measured from the t0p UAT capture, 2× retina ÷ 2 = CSS px)

| Observation | Measured |
|---|---|
| `Sort` label is to the **right** of the picker | label ink starts 427.0 CSS; select's right edge 414.0 CSS |
| Picker is bulky | select box **197.0 CSS px** wide × **40px** declared height, `--text-md`, heavy drop shadow |
| Little room under the controls row | **40.0 CSS px** gap above the row, **5.5 CSS px** below it, before the `Type/Game/Key` header |

The asymmetry in row 3 is the operator's "very little white space" made numeric: 40 above, 5.5 below.

## Task 1 — flip the label to the left of the picker

`index.css:721` `.humbleKeysSortPicker`:

- `grid-template-areas: 'select label'` → `'label select'`
- swap the tracks to match: `grid-template-columns: 12rem max-content` → `max-content <select-width>`

`column-gap: var(--space-sm)` stays. `.selectFieldWrapper label` already carries
`grid-area: label` + `align-self: center` (`SelectField/index.css:60-64`), so no label rule is needed.

**This breaks a pin that t0p added.** `humbleKeysStylesheet.test.ts` has
`SORT_PICKER_LABEL_BESIDE = /grid-template-areas:\s*'select label'/` (≈`:306`), asserted at
≈`:336`. Update the regex **and** the test's wording, which says "sits beside, not above" — the
claim is now specifically **label-then-select**. Its SANITY sibling must still fail against a
known-bad input; re-check that the bad fixture is still bad under the new regex (a fixture
declaring `'select label'` is now exactly the right negative control, so prefer that over the
generic `color: red` one).

## Task 2 — make the picker compact

The bulk is inherited from the **global** rule `.selectStyle, .selectFieldWrapper
.MuiOutlinedInput-root` (`SelectField/index.css:6-39`): `height: 40px`,
`font-size: var(--text-md)`, `box-shadow: 0px 4px 4px rgba(0, 0, 0, 0.25)`, `min-width: 100px`.

**Specificity trap — this is the load-bearing part of the task.**
`.humbleKeysSortPicker .MuiOutlinedInput-root` is **(0,2,0)** — *identical* to the global
`.selectFieldWrapper .MuiOutlinedInput-root`. Ties are broken by source order in the bundle,
which is not something this file controls. Use the compound form:

```
.humbleKeysSortPicker.selectFieldWrapper .MuiOutlinedInput-root   /* (0,3,0) — wins outright */
```

(Both classes are on the same element — `SelectField/index.tsx:34` renders
`selectFieldWrapper Field ${extraClass}` — so the compound selector matches.)

Note the two **existing** scoped rules at `index.css:727+` (`.MuiSelect-select` colour,
`.MuiOutlinedInput-notchedOutline` border-colour) are *not* affected by this trap: neither
property is declared by the global rule, so there is nothing to tie with. Leave them as they are.

Target a compact control:
- `height`: ~32px (down from 40)
- `font-size`: `var(--text-sm)` (down from `--text-md`)
- `box-shadow: none` — the 4px drop shadow is most of the "clunky"

Shrink the select's grid track to match. **Sizing risk to check live, not to assume:** the
global rule paints the dropdown arrow as a `background-image` and reserves roughly the right
**40px** as chrome (`background-position: calc(100% - 20px) / calc(100% - 15px) / calc(100% - 40px)`),
and `SelectField`'s `sx` hides MUI's own icon. So usable text width ≈ track − 40px − left padding.
`Expiring soonest` at `--text-sm` needs ≈105px. **Do not go below ~11rem** without checking the
text does not clip; if in doubt keep it wider. Clipping here is silent and ugly.

## Task 3 — give the column header room to breathe

`index.css:690` `.humbleKeysControlsRow` declares `margin-top: var(--space-lg)` and **no**
`margin-bottom` — hence 40 above / 5.5 below.

Set both to `var(--space-md)`: tightens the top (the operator asked for "smaller margins")
and opens the bottom (they asked for more white space before the heading row). Symmetric and
smaller overall, which is the combined ask.

Do **not** add the space by padding `.humbleKeysColumnHeader` instead — its standalone block is
pinned for `text-align: start` and carries the `--divider` border-bottom that is one of the
**exactly three** counted `var(--divider, color-mix(...))` occurrences. Leave that block alone.

## Do not disturb

- The three-occurrence `var(--divider, color-mix(…))` count. The sort-picker's occurrence is
  prettier-wrapped across `index.css:~731-735`; a naive `grep 'var(--divider'` finds only two.
- The `grid-template-columns` **file-wide count of 2** pinned in
  `HumbleKeyRow/__tests__/index.test.tsx`, plus its sibling test asserting the second occurrence
  is the `.humbleKeysSortPicker` rule. Task 1 keeps the property on that rule, so the count holds —
  confirm rather than assume.
- Comments must **paraphrase** `grid-template-columns` rather than spell it out: that census
  greps **raw, un-stripped** source, so naming the property in prose is a false extra occurrence.
  This already bit `260911-t0p`.
