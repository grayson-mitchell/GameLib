# Quick Task 260927-t57: Correct the Prettier --file-info Literals Summary

Corrected the seven `npx prettier --file-info` JSON literals in CLAUDE.md's "A formatter check
belongs in every task's `<verify>`" section from a hand-normalised unspaced form to the spaced
form prettier 3.7.4 actually emits, reworded the one bare-fragment occurrence instead of spacing
it, and added a permanent warning that the spacing is load-bearing for anyone writing a grep.

## What Changed

Three keyed edits to CLAUDE.md, all inside the existing formatter-check section, no other content
touched:

1. **The "Sees" fragment** — `"Sees" means the probe below reports `"ignored":false`.` became
   `"Sees" means the probe below reports that path as **not ignored**.` This occurrence is a prose
   definition rather than a quotation of command output, and spacing it would have left a second,
   subtly different literal in the section that matches no complete tool output — exactly the
   grep-bait shape that caused the original defect.
2. **The six quoted outputs** — the `**Decide which case a path is in...**` paragraph now quotes
   `{ "ignored": false, ... }` and `{ "ignored": true, "inferredParser": null }`, and all six
   per-path readings (`src/preload/index.ts`, `src/backend/utils/uninstaller.ts`, `package.json`,
   `CLAUDE.md`, `.planning/STATE.md`, `public/locales/en/gamelib.json`) now carry spaces after
   every colon and inside every brace, with the measurement note extended to "Measured on this
   machine 2026-09-26 and re-measured 2026-09-27, both under prettier 3.7.4." Every ignored/not-
   ignored verdict and every parser name is unchanged — only the JSON literal spelling moved.
3. **New warning paragraph** — inserted immediately after the quoted-outputs paragraph and before
   the pre-existing "vacuous" paragraph: states the spacing is load-bearing, names 2026-09-27 as
   the correction date, states the prior form was wrong under the very 3.7.4 version it cited, and
   gives `grep -Eq '"ignored":[[:space:]]*false'` as the space-tolerant pattern to use instead.
   That pattern's post-colon character is `[`, so the warning introduces no unspaced literal of
   its own.
