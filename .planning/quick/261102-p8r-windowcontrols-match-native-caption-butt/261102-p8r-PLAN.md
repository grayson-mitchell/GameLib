<objective>
Make GameLib's in-app WindowControls (Windows/Linux, frameless mode) look like the native Windows 11
caption buttons, then close the frameless-refresh todo whose Windows live gate passed today.

Operator feedback, Windows, 2026-11-02, after quick 261102-dma's frameless-toggle fix passed live:
1. The controls paint `var(--titlebar-color)` (which is `--body-background`, black) over the dark-grey
   tab bar, so they show as a black block. They should be transparent.
2. They are larger than the native controls (39x39 today), and the minimize glyph is a
   bottom-justified underscore (the Material `Minimize` icon). It should be a vertically centred
   dash like the native one.

Purpose: when the operator toggles "Use frameless window" on and off, the in-app buttons and the
native ones should look the same.

Output: a new glyph module, restyled WindowControls, a one-token reserve change scoped off macOS, a
new jest gate file, and the todo moved to `completed/`.

**Dimension and reserve decision (planner's choice; the executor implements it as written):**

- Buttons are 46px wide x 32px tall CSS px (the native Windows 11 caption-button size at 100%
  scale), with a 10x10 glyph and 1px strokes. The cluster is therefore 3 x 46 = 138px.
- 138px does not fit the existing 120px reserve. Squeezing the buttons to 40px wide (3 x 40 = 120)
  would avoid the reserve change, but the operator compares these buttons directly with the native
  ones by flipping the frameless toggle, so a 6px-per-button width mismatch would be visible. The
  reserve is widened instead.
- The widening is scoped OFF macOS. WindowControls never render on darwin (`App.tsx`:
  `showOverlayControls = isFrameless && !hasNativeOverlayControls && !isMac`). Two of the three
  `--overlay-controls-width` consumers (`StoreEmbedControls/index.css:13-17`,
  `GamePage/index.css:818-820`) are not scoped out of macOS. Changing body's 120px fallback would
  move them by 18px on the Mac for buttons that are not there. So body's declaration stays
  byte-identical, and a new `.App:not(.macOverlayTitlebar).frameless` block redeclares
  `--overlay-controls-width` from `3 * var(--window-controls-button-width)`. On macOS `.frameless`
  implies `.macOverlayTitlebar` (both come from the same `settings.framelessWindow`, the reasoning
  already recorded at `NavShell/index.scss:191-205`), so that block never matches there.
- The override sits on `.App` rather than as a body-level `var()` indirection on purpose. A custom
  property's `var()` references are substituted on the element that declares it, and descendants
  inherit the computed result. Overriding a helper token on `.App` would therefore NOT change a
  `--overlay-controls-width` that was computed on body. The property itself has to be redeclared on
  `.App`.
- `--overlay-controls-height`'s fallback drops from 39px to 32px. Its only consumer is
  `.windowControls button`, which never renders on macOS, so this is macOS-neutral. The 42px navbar
  still clears it. The prose at `NavShell/index.scss:45-47` that cites "39px" is updated so it does
  not go stale.
- On Windows/Linux the NavShell trailing padding becomes 138 + 10 = 148px. StoreEmbedControls and
  GamePage `.topRowWrapper` reserve 138px instead of 120px. Neither of those two shares the navbar
  row (WindowControls moved into the `navbar` grid row in 34.1-09), so the 18px extra is harmless
  dead space and they stay consistent with the token.
