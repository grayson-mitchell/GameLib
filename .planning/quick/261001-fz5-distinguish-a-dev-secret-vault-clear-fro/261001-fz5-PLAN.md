<objective>
Make a dev-secret-vault credential wipe unmistakable from a credential store in `gamelib.log`, without changing one byte of what the clear path writes to disk.

Purpose: `clearSlot()` delegates to `writeSlot()`, so `clearToken()` and `setToken()` emit a byte-identical `[dev-secret-vault] write key=<slot>` line. On 2026-10-01 that collision had an ordinary Steam logout read as a successful QR login immediately clobbered by a stale-token race, and it was very nearly reported to the operator as a real defect. The line was the first and only trace of either event in the log.

Output: a direction token on the existing write line, a test pinning each direction by string equality plus a disk-behaviour-unchanged assertion, and the todo closed into `completed/`.
</objective>

<decision>
## Direction chosen: Option B — a direction token on the existing line

The todo left this open. Chosen shape:

- store: `[dev-secret-vault] write key=<slot> op=store`
- wipe:  `[dev-secret-vault] write key=<slot> op=wipe`

**Why Option B over Option A** (a separate `[dev-secret-vault] clear key=<slot>` line):

1. **Option A silently narrows an existing grep.** Verified live at HEAD: the only occurrences of `write key=` anywhere in `src/`, `meta/`, `docs/`, `.github/`, `scripts/` are this module's own line 165 and its line 162 doc comment — so the established reading habit is `grep 'dev-secret-vault] write'`. Under Option A that grep keeps returning results and keeps looking complete, while every wipe quietly drops out of it. That is a new blind spot of exactly the same class as the one being closed: a pattern that appears to cover all vault mutations and does not. Option B keeps the prefix intact, so the existing habit returns the same set of lines it does today, with the direction visible at the end of each.
2. **Both directions are still one grep away, in both directions.** `grep 'op=wipe'` is every wipe; `grep 'op=store'` is every real store; `grep 'write key='` is still every mutation. Option A can only give you two of those three without a union pattern.
3. **A wipe is unmistakable on sight** — the token sits on the same line as the slot name, so no adjacent-message inference is needed, which is the specific failure mode the todo records.
4. **Nothing has to be un-pinned.** Verified live at HEAD: `devSecretVault.test.ts` pins the *read* line by equality at :349, and asserts `includes('REFUSED')` / `includes('INSTALLED')` elsewhere — there is no equality assertion, and no `toHaveBeenCalledTimes` assertion, against the write line anywhere in the file. The todo's claim on this point is re-verified, not taken on trust. Both options are equal on this count; it argues against neither.

Cost of Option B, stated rather than hidden: the line grows, and a reader who has memorised the old full-line text now sees it as a prefix rather than a whole line. That is the price of keeping the prefix stable, and it is the cheaper of the two prices.

**The direction is CHOSEN by the call site, never DERIVED from the value.** `writeSlot` takes a required parameter typed as a two-member string-literal union; it does not infer `wipe` from `value === ''`. A derived direction would mean a legitimate `setToken('')` logs as a wipe, and — more importantly for guardrail (b) — it would make the log token a function of the secret value, which is precisely the property that must never hold. This is also why the parameter is required rather than defaulted: a default would let a future call site emit a direction it never thought about.

**Not raised with the user, with reasons:**
- **api-coverage gate:** does not fire. Scope is one local log string and its test in a dev-only, env-gated module. No external API, SDK or service is integrated, so no coverage matrix is written and none is fabricated. (If the orchestrator's detector fires anyway, write `No external API integration: scope is one local log line in a dev-only env-gated module.` to `COVERAGE.md` rather than a matrix.)
- **assumption-delta gate:** does not fire. `writeSlot` goes from three required parameters to four required parameters — not a singular→plural, required→optional, or derived→chosen transition of an existing assumption. The direction did not exist before, so nothing transitioned; it is chosen from the outset, as argued above.
- **schema-gate:** does not fire. No Prisma, Drizzle, Payload, Supabase-migration or TypeORM path is in scope.
</decision>
