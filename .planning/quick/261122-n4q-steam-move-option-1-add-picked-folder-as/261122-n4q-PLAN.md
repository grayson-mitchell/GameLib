<objective>
Ship Steam Move option 1 from spike 094. GameLib keeps the free folder picker. When the picked folder isn't a registered Steam library, the bridge helper registers it with IClientAppManager::AddLibraryFolder and moves the game to the index Add returned. The plan also fixes the folder-gap bug in the already-shipped `gl_ia_list_folders()`, adds a one-shot StartValidatingApp nudge after a move, and rewrites the todo's live gate.

Purpose: today a Move to any folder that isn't already a Steam library is refused with "add it in Steam first". The user's locked decision is that the picked folder becomes the library root. Separately, a library removal leaves an empty entry in Steam's in-memory folder list, and that breaks every `--library` install and move until Steam restarts. That bug is in shipped code.
Output: helper changes in `gamelib_installapp.h`, the TS seam and moveNative route, a host-compiled C harness that gives the helper's pure logic its first unit seam, jest tests, and the todo rewrite.

User decisions (locked; cited as U-1 and U-2 below):
- U-1: Option 1. The free folder picker stays. A picked folder that is not a Steam library is registered with AddLibraryFolder, then MoveApp targets the index AddLibraryFolder RETURNS. Never use a list position: Steam reuses gaps from the top.
- U-2: The picked folder becomes the library root. The game lands in `<picked>/steamapps/common/<installdir>`.

Planner decisions (Claude's discretion; record each in the SUMMARY):
- **One helper run with an `--add-library` flag, not a separate subcommand.** `--steam-moveapp <appId> --library <abs> --add-library [--wait] [--dry-run]` does the add and the move in one attach. AddLibraryFolder's return value flows straight into MoveApp, with no index crossing the TS boundary. 9sl rejected passing indices from TS, and a second spawn would repeat the multi-second getter scan. Without the flag, an unmatched library still gives `unavailable library-not-registered`, so every existing caller is unchanged.
- **Call AddLibraryFolder only when the picked folder matches none of Steam's live folders**, not always. Steam's idempotency was tested only for the exact path and a trailing slash. Calling Add on `<lib>/steamapps` or `<lib>/steamapps/common`, which the matched route accepts, would hit Steam's "subfolder of existing folder" refusal and leave stub files behind (spike 094 step 3). Only-when-unmatched keeps the existing-library route free of writes.
- **The order inside the helper is: refusals, then the read-only CanMoveApp, then Add, then MoveApp.** A not-installed game or a CanMoveApp error therefore never leaves a freshly registered library behind. A MoveApp error after Add does leave the library registered, because GameLib never calls Remove. The error line carries `addedLibrary:true` and the message says so.
- **Where the checks live.** TS (`moveNative.ts`) runs every refusal and owns the user-facing messages. The helper re-checks existence, path length and nesting against Steam's LIVE folder list as defence in depth: `libraryfolders.vdf`, which TS reads, can lag Steam's memory, and Steam itself accepts a parent of a library. Steam's own `-1` is the last backstop.
- **Non-empty folders are allowed.** Spike 094 step 3 showed that Steam adds its stub next to existing files and leaves them alone, and users commonly pick folders like `~/Games`. The single overlap that matters is refused instead: the picked folder already holding `steamapps/common/<installdir>` or `steamapps/appmanifest_<appId>.acf`, which would mean two installs of one app or an untested MoveApp onto an occupied destination. A folder that is an old, unregistered library is allowed, since Steam's own Storage → Add Drive accepts it. The same collision refusal also guards the existing-library route. It costs nothing there and is strictly safer.
- **GameLib does not create the folder.** The macOS picker creates folders itself. The path comes from the renderer, so GameLib refuses one that doesn't exist rather than calling mkdir on it.
- **Paths of 255 bytes or more are refused** in TS and in the helper (`GL_IA_ADD_PATH_MAX 254`, with a drift test). AddLibraryFolder's C-string writer caps at 255 (spike 094 Research table), so a longer path would register a truncated, different folder.
- **Gap rule.** An empty path (GetLibraryFolderPath returns 0 and "") is a gap: it is skipped, and every other folder keeps its Steam index (`gl_ia_folders` stays indexed by Steam index and the count still includes gaps). A non-empty entry that is not absolute, or an absolute path that is not a directory, still fails the whole lookup (-1). Non-absolute output is the only run-time signal that GetLibraryFolderPath's shape drifted; the strict check exists because serializer sizes are not decoded. An absolute path that does not stat is a library on an unmounted volume, which spike 094 lists as untested, so keeping today's refusal avoids acting on an untested Steam state. This is recorded as still open in the todo. At least one real (non-gap) folder is required.
- **Nudge timing.** A gap of 5 s (`GL_IA_MOVE_NUDGE_AFTER_S`) with the game at the target, Files Missing set and no busy bits triggers one StartValidatingApp. After that, Files Missing still set with no busy bits for `GL_IA_MOVE_VERIFY_PENDING_S` (60 s) ends with `not-settled` / `verify-pending`. The 60 s `GL_IA_MOVE_SETTLE_FALLBACK_S` now applies only when Files Missing is clear, so it still rides out persistent UpdateRequired/UpdateQueued bits from before the move, but it can no longer report success at state 46. If the validate slot can't be verified, there is no nudge and the result is not-settled after 60 s.
- **A real seam for the C logic.** The listing, folder match, nesting check and wait decision become small pure functions in the header. A host-compiled arm64 harness drives them with a fake vtable and synthetic clock values, following the established `cbqueue_harness.c` + `cbqueue.test.ts` pattern. No test reaches steamclient or a running Steam.
