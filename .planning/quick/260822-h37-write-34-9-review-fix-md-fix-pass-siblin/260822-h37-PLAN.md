<status_decision_rule>
Apply this mechanically after Task 1's derivation. Do not decide it by feel.

Let `D(id)` be the disposition column (column 3) of the `| <id> | ... |` row in `deferred-items.md`,
for each ID derived from `34.9-REVIEW.md`.

- **If `D(id) == "FIXED"` for every ID** → `status: all_fixed`, `outstanding: []`.
- **Otherwise** → `status: partial`, `outstanding:` lists every ID where `D(id) != "FIXED"`, and the
  body names each one with its ledger disposition, item number and OWNER.

`all_fixed` was the expected outcome when this work was scoped. It is **not** a required one. A
formally deferred finding is still an unfixed finding: writing a green badge over it would reproduce
the exact failure mode this phase already hit four times — a review finding sitting unledgered while
the phase reads closed. Under the ledger as measured, the rule selects `partial`.

Note what `partial` buys, so nobody "fixes" it later by upgrading the word: `partial` maps to
`inprogress`, so the review badge goes **red → yellow**. The lie (an unaddressed Critical) is gone;
the remaining yellow is true, because one Info finding really is outstanding and owned elsewhere.
Upgrading the word without upgrading the ledger is the one change this plan forbids.
</status_decision_rule>
