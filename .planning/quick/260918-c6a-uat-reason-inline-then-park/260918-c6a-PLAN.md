`sdk/dist/query/uat.js:150` — `parseUatItems` item pattern (the gate's `VISIBLE_PATTERN` is a
verbatim port of it):
```
/###\s*(\d+)\.\s*([^\n]+)\nexpected:\s*([^\n]+)\nresult:\s*(\w+)(?:\n(?:reported|reason|blocked_by):\s*[^\n]*)?/g
```
Requires `### N. Name`, then `expected:` with inline text, then `result:` on the very next line.
Adding prose BELOW the `reason:` line cannot disturb this triple.

`sdk/dist/query/uat.js:158-159` — how the value is taken from the item's block text:
```
const reasonMatch    = blockText.match(/reason:\s*(.+)/);
const blockedByMatch = blockText.match(/blocked_by:\s*(.+)/);
```
Unanchored, no `m` flag, first match wins, `.` does not cross a newline. `blockText` runs from the
item heading to the next `\n###`. **It only ever consumes the first line** — which is why a summary
on the key plus prose below it works.

`sdk/dist/query/uat.js:116-146` — `categorizeItem(result, reason, blockedBy)`. The `reason`
argument is read **only** on the `result === 'skipped'` branch. Both target items are
`result: pending`, which returns `'pending'` without ever inspecting `reason`. Changing the reason
text therefore cannot move `category`. The one thing that CAN move it is `blockedBy` becoming
truthy — so no added line may contain the substring `blocked_by:`.

`sdk/dist/query/uat.js:81-82` — the only block-scalar dedent in the whole dist, and it matches
`^expected:\s*\|` only. Nothing dedents `reason:`.
