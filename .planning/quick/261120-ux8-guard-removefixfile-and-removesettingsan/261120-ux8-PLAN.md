<objective>
Close the renderer-appName path traversal in the two uninstall file deletes. `removeFixFile` and
`removeSettingsAndLogs` (src/backend/utils/uninstaller.ts) join a renderer-supplied `appName` into a
delete path with no containment check, so `appName = '../config'` with "remove settings" deletes
GameLib's own `config.json` (`appFolder/config.json`, the sibling of `GamesConfig/`), and `../x`
under fixesPath deletes `appFolder/x-<store>.json`. Route both through the shared Rust guard with
`kind: 'app-data'` targets and per-site trust roots so an escaping path is refused
(`outside-trust-root`) instead of deleted, and add defence in depth at the `uninstall` IPC schema.

Purpose: no delete path in the uninstall flow is built from unvalidated renderer text.
Output: guarded file deletes plus tests per site, one crate row pinning the file-outside-root
semantics, a plain-name check on the `uninstall` IPC, and the todo closed.

**Guard fit, verified from source (not assumed):**
- `src-tauri/crates/gamelib-safety/src/remove.rs` `delete_location` uses `remove_dir_all` only for a
  real directory and `remove_file` for anything else, so a single-file target is supported.
- `check_kind` applies content rules only to `Prefix` and `SideloadFolder`; `AppData` gets none.
- `check_trust_root`: with a trustRoot, the canonical target must be strictly inside the
  canonicalised root (`is-trust-root` when equal, `outside-trust-root` otherwise). Without one,
  `AppData` is `unknown/no-trust-root`. A missing trust root dir fails canonicalisation, which is an
  `unknown` refusal.
- An absent target reads `yes` with `absent: true` and is skipped by the delete loop.
- Node's `join` normalises `..` away before the path reaches Rust, so an escape arrives lexically
  clean and is caught by containment (`outside-trust-root`); a raw `..` string would hit
  `dot-segment` in `lexical_check`. The crate already has `app_data_file_inside_its_trust_root_is_removed_alone`
  but no outside-root FILE row, which Task 1 adds.
- `resetHeroic` (src/backend/utils.ts:392) is the in-repo precedent for `app-data` targets:
  `trustRoot`, `knownInstalls: collectKnownInstalls(deps)`, `protectedRoots: protectedRootsFor(deps)`.

**Decisions taken at Claude's discretion (documented, not locked):**
- Refusal reporting is a closed-set log line only, no `removalRefusedNotice`. These deletes are
  outside D-10/D-11/D-13. The game itself is already uninstalled when they run; a leftover settings
  or fix JSON is harmless, and a refusal here is either a hostile/bogus appName or a transient Rust
  failure. A user-facing toast would need a new `RemovalRefusalKind`, renderer copy, locale strings
  in `public/locales/en/gamelib.json` (currently dirty in the working tree with unrelated edits) and
  IPC-schema parity updates, which is out of scope for a quick task.
- An `existsSync` pre-filter runs before the guard: only existing candidates are sent, and no
  rustInvoke is made when none exist. This is not a safety check (everything sent is still
  guarded; the crate re-checks on delete); it keeps a missing `GamesConfig/` or `fixes/` root from
  logging a canonicalize-failed refusal on every uninstall, avoids Rust round trips for the common
  no-file case, and keeps the 82-07 tests' exact rustInvoke call lists valid.
- No `selfKey` on these requests (the `resetHeroic` shape, stricter than the prefix request): a
  file target only meets the known-install check if it sits inside an install folder, and the game
  has just been uninstalled.
- The IPC plain-name check is applied to the `uninstall` channel only. Evidence that it does not
  break legitimate appNames: `Runner` is `legendary | gog | sideload | nile | steam`
  (src/common/types.ts:23). Steam appIds and GOG product ids are numeric; the reserved Steam
  bottle appName is `__gamelib_steam_bottle__` (src/backend/storeManagers/steam/constants.ts:23);
  Amazon ids are `amzn1.adg.product.<uuid>` (dots, never equal to `.`/`..`); sideload uses
  `short-uuid` (SideloadDialog, base58, no separators); Epic app names are alphanumeric. None
  contains `/`, `\` or NUL.
