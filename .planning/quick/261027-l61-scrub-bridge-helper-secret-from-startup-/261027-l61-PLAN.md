    In the `main()` secret block, change the declaration to `char *envSecret = getenv(BRIDGE_SECRET_ENV);`. `getenv` returns `char *`, so this avoids casting away const. Put it after the copy/log branch and immediately before `unsetenv(BRIDGE_SECRET_ENV)`: take `size_t n = strlen(envSecret)`, then zero `n` bytes through a `volatile char *` pointer in a plain for-loop.

    Use strlen, not `BRIDGE_SECRET_HEX_LEN`. A malformed value can be shorter or longer than 64 chars, and a fixed 64-byte write would either run past a short string's NUL or leave a long string's tail.     Use the volatile loop, not `memset_s`. `memset_s` needs `__STDC_WANT_LIB_EXT1__` defined before `<string.h>`, and that define would ripple through the include list at L161-186. The volatile loop is portable and survives `-O2` dead-store elimination. Do not scrub `g_secret`; it is needed for the life of the process.

    Rewrite the comment above the block. It must say: the secret comes via env, not argv, because argv is world-visible in `ps`. `getenv()` returns a pointer into the process's startup env block. On macOS `ps eww` reads that block through `KERN_PROCARGS2`, and `unsetenv()` alone only removes the `environ` entry. So the string is overwritten in place (volatile, full strlen, valid or not) and only then unset, which also keeps it out of anything the Steam dylib spawns.
