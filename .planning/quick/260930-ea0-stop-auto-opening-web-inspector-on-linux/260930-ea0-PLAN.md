window and for the shared login window (`humble_login_open`, ~main.rs:7264). Leave macOS and Windows
behaviour unchanged. Then prove live on this X11/NVIDIA host that the dev app mounts with
`WEBKIT_DISABLE_DMABUF_RENDERER` UNSET, and close out the debug session that found the cause.

Why. `.planning/debug/linux-dev-app-blank-without-dmabuf-workaround.md` (status: diagnosed) showed
the following. The `#[cfg(debug_assertions)]` `window.open_devtools()` in `main()`'s `.setup()`
calls wry's `webkit_web_inspector_show`. That attaches the inspector while `src/frontend/index.tsx`'s
entry module is still running, and the page's WebKitWebProcess aborts (SIGABRT, a JavaScriptCore
internal assertion reached from JIT code). With the DMABUF renderer enabled, the natural attach
instant lands in that window 6/6. `=1` only moves it out most of the time: 2 crashes in 8 once the
attach was delayed 100-150 ms. The 4-arm census was unset+inspector 0/6, =1+inspector 6/6,
unset+suppressed 6/6, =1+suppressed 6/6. The existing code comment justifies the auto-open for macOS
only ("the dev webview exposes no right-click inspect on macOS").
