<objective>
Apply the saved Accessibility zoom to the webview once at startup, from `GlobalState`'s boot path, so
the Zoom slider's persisted value is actually in effect after a relaunch instead of only being
displayed back to the user.

Purpose: `zoomPercent` is persisted by the slider and read back into state at boot
(`GlobalState.tsx:549`), but `setZoomPercent` (`:609-618`) has exactly one caller — the slider's
`onChange` — so nothing on the boot path ever calls `window.api.setZoomFactor`. The Accessibility
screen reads 150% while the app renders at 100%, every launch, until the slider is touched again.
A saved accessibility setting that silently is not in effect is the defect.

Output: one pure, tested helper; one new call site in `componentDidMount`; a wiring gate with a
self-test arm; one corrected doc comment; the source todo closed; and the un-deskable half filed as
a live-gate todo.

Chosen layer, not reopened: the fix goes in `GlobalState`'s boot path. That is where the saved value
is already read and where `setZoomPercent` already owns the `window.api.setZoomFactor` call, so no
new plumbing is needed. The source todo's second option (apply from the Tauri shell or preload
before first paint) is NOT taken — it needs the setting available outside frontend state. Its third
option (apply on the Accessibility screen's own mount) is NOT taken — it only runs if that screen is
opened.

Accepted cost of that choice: the first paint still happens at factor 1 and the apply lands just
after mount, so a non-100% user sees a brief jump. This is the trade the chosen layer makes; it is a
known limitation to be written down (Task 3), not a defect to be discovered later.
</objective>
