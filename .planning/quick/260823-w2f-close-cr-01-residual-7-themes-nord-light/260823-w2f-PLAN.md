# Quick task 260823-w2f — CR-01's residual

## The prescription this task started with was WRONG

Todo `2026-08-23-navbar-active-undefined-in-7-of-11-themes` (written by `260823-v3k`, i.e. by me)
prescribed: *declare `--navbar-active` in the 7 theme blocks that lack it.*

`themeTokens.test.ts` already contains a census from a **34.11 code review** (WR-13/CR-03) that
asserts the exact opposite:

```ts
expect(declaringCount).toBeLessThan(themeSelectors.length)
```

The codebase settled this architecture deliberately: **do not declare the token in every theme —
require the fallback chain at every consumer.** The prescribed fix would have broken that assertion
and fought a decision that was already made and tested.

Recorded because it is the recurring shape here: *a review's prescribed fix can carry the defect it
reports.* The todo was written from the ROADMAP prose without reading the guard file it named.

## Why the residual survived a green suite anyway

`NAVBAR_ACTIVE_CONSUMERS` is a **hardcoded list of 4 files**, and lines 67–82 say why, naming the
escapees exactly:

> Three PRE-EXISTING consumers use the bare `var(--navbar-active)` form and are **knowingly left
> unguarded** here, because fixing them was not in this review's scope and *a gate that fails on
> untouched code is a gate someone deletes* [...] **If those are ever fixed, add them to this list.**

Honest, documented, and it left `NavTabs/index.scss` — **CR-01's own original site** — outside the
guard built in CR-01's aftermath. It also names a fourth site nothing had tracked:
`GamePage/index.css`, three occurrences.

## The second defect, found by measuring rather than by reading

Building the contrast baseline first surfaced a bug in no finding, no todo and no review.

**`body.nord-light` painted the selected tab label at 1.18:1** — `--navbar-active: #d0ddff` on
`--body-background: #eceff4`, near-white on near-white — and it is live in the picker
(`themeLabels.ts:43`).

It is not in CR-01's 8 because it **does** declare the token, so both the fallback chain and WR-13's
census pass on it.

**Root cause is structural:** `nord-light` is the **only light theme**. Everywhere else the navbar
and body surfaces are both dark, so one navbar-surface token coincidentally serves the body-surface
element too. `#d0ddff` is correct where it was chosen — `NavItem` paints it on
`--navbar-active-background` (#2e3440) at **9.20:1**. The token must not change globally.

**This is why Task 4 asserts contrast, not declaration.** A census of *"every theme declares
`--navbar-active`"* passes `nord-light` — it has one — and would have shipped green over an
illegible label. Landmark, not property.

established and WR-13 requires. Resolves to `--accent-overlay` in the 7 themes: measured
**7.42:1 – 13.92:1**, all clearing AA. No `themes.scss` edit at all.

## Task 3 — `nord-light` scoped override

## Task 4 — contrast-floor census

Per theme: resolve the colour `NavTabs` actually paints — **read from the stylesheet, never
hardcoded**, preferring a theme-scoped override — through the same `var()` chain the browser would,

loudly rather than skipping.

Needs `styles/_colors.scss` seeded as globals: theme chains terminate in its `:root`, and without it
every `midnightMirage` token resolves to nothing — which reads as "no data" rather than as an error,
a silent route to a vacuous census. Guarded by an explicit non-vacuity assertion.
