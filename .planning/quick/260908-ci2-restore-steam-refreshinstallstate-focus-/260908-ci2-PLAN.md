<design_decision>
**LOCKED by the orchestrator — do not revisit.**

`WindowEvent::Focused(true)` in Rust → a `send` frame on the sidecar's stdin → a sidecar
listener that calls `libraryManagerMap['steam']?.refreshInstallState?.()`.

The rejected alternative was a renderer-side producer (`getCurrentWindow().onFocusChanged` in
`src/preload/api/tauriWindowChrome.ts`). That module's CR-03 comment documents the project's
renderer-side rule for window events, but that rule is scoped to events whose CONSUMER is the
renderer. Here the consumer is the sidecar, so the renderer route would add a preload export, an
`IPC-PORT-INVENTORY.md` bucket line, a `preload-surface-gate.py` update and a frontend
subscription — all for a hop that exists only to relay, and one that stops working the moment the
renderer is unmounted.

**Channel name: `shellWindowFocused`** (camelCase, matching sidecar IPC channels like
`logoutSteam`/`trayResolveRunner`, NOT the snake_case `rustInvoke` command names). It names the
EVENT, not the consumer: the Rust shell must not know Steam exists, and the sidecar — which owns
`libraryManagerMap` — owns the policy of what a focus means. `listenerRegistry` supports multiple
listeners per channel, so a future second consumer needs no new channel.
</design_decision>

<hazards>
Each of these is a ledgered project hazard that bears directly on this task. Every one has a
named mitigation in the tasks below; none may be silently dropped.

1. **`send` channels fail SILENTLY.** Unlike `invoke` (which surfaces `UNPORTED_CHANNEL_MARKER`
   and a 60 s timeout), an unregistered `send` channel produces *nothing*: `dispatchSend` finds
   zero listeners and returns, and Rust's write path has no pending/timeout machinery. A name
   typo between the Rust `channel` string and the sidecar `ipcMain.on` name is **undetectable at
   runtime**. → Mitigated by Task 3's cross-side pin (T-A), which builds the expected Rust literal
   from the TS constant so a rename on either side alone reds.

2. **Startup ordering.** The main window is built `.focused(true)`, so a `Focused(true)` event can
   fire before or around sidecar readiness, and `write_frame` returns `Err`. → Fail soft: log one
   `eprintln!("[shell] WARN: ...")`, never panic, never abort startup, never block the event loop.
   Mirrors the `exitToTray` handler's idiom.

3. **Fire on `Focused(true)` ONLY, never on blur.** The Electron original was a `focus` handler.
   → T-B asserts the stripped source contains `Focused(true)` and does NOT contain `Focused(false)`.

4. **`refreshInstallState()` does real disk I/O** — `buildInstalledMap()` plus up to two
   bottle/bridge ACF scans on macOS. The Electron original was **unthrottled per focus**, so
   unthrottled is exact parity. This was considered and deliberately not changed; adding a
   throttle here would be a behaviour change smuggled in under a restoration. Recorded as
   `T-CI2-02: accept` in the threat model.

5. **Coverage of each end is not coverage of the boundary.** A Rust handler and a sidecar listener
   can both be individually green while the wire between them is dead — exactly the 2026-09-05
   store-embed failure that `storeEmbedWireContract.test.ts` exists to prevent. → The consumer
   test drives the REAL transport (`startRpcServer` over a PassThrough pair), not a direct call.
   A direct-call test is precisely how `shutdownBridgeHelper()` stayed green with zero production
   callers for a milestone. The remaining un-automatable half (a real Steam install/uninstall on
   the operator's machine) is scoped OUT explicitly in Task 3, not silently claimed.

6. **Comment-stripping is mandatory for the source pins.** `main.rs`'s own doc comment will quote
   the channel name and `Focused(true)`, so an unfiltered grep would be satisfied by the prose
   alone. → Use the two-stage recipe from `tauriShellSource.test.ts`: `stripSourceComments` FIRST
   (block comments), THEN `stripTrailingLineComment`. Note the known hazard that
   `stripSourceComments` eats Rust lines starting with `*` (deref) — the asserted lines must not
   begin with `*`.

7. **`flowRegistrationCensus.test.ts` is a deliberate tripwire and WILL red.** `countRegistrations`
   counts `ipcMain.on(\s*'`, so adding one send moves `'steamFlowRegistration.ts'` from
   `{ invoke: 2, send: 0 }` to `{ invoke: 2, send: 1 }`. That table edit is mandatory, in the same
   commit, with a dated comment in the established style. **Second trap:**
   `steamFlowRegistration.ts` is in `NO_COUNT_CLAIM`, which asserts
   `doc === null || claimedTotal(doc) === null`. `claimedTotal` reads the first token after
   `Registers\s+(?:the\s+|...)` — today that is `read-flow`, a non-number, which is why the module
   passes. **If the executor rewrites the `registerSteamFlows()` docstring to say "Registers the
   two invoke handlers and one send listener", the token becomes `two` and Gate 2 REDS.** Update
   that docstring in the naming style it already uses, without a leading count.

8. **Do not run `pnpm test:ci` as a gate.** It exits 1 at HEAD from a leaked 60 s
   `rustInvoke('store_embed_open')` timer at `sidecarRpc.ts:339` that crashes Node *after* a green
   summary — pre-existing, unrelated, Phase-41-era. Use scoped runs.

9. **Never run jest in the same shell command as a write** (`&& npx jest` reads a stale tree).
   Write, then run the gate as a SEPARATE command.

10. **`prettier` is red repo-wide** and `.husky/pre-push` refuses pushes; `pnpm lint` sits at
    ~4188 warnings against a 4157 ceiling. Check prettier on the touched files ONLY, in place

11. **CI runs no cargo step.** The Rust half is gated ONLY by the TS source pin — this is the
