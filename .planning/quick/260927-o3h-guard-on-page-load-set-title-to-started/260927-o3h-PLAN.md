Guard the login window's `on_page_load` `set_title` call to `PageLoadEvent::Started` only, so the
composed `origin — document title` set by `on_document_title_changed` survives `Finished` instead
of being overwritten with the bare origin. Correct the two comments that misdescribe the
mechanism, and pin the guard with a falsifiable source-grep regression test.

`human_verification_discharged`, 2026-09-26) is SUPERSEDED — the fix is authorized. Do not
re-litigate it.

D-01 .. D-05 below are the five numbered points of the operator's locked decision for this quick
task; every task action cites the ones it implements.

- D-01 — guard ONLY `let _ = window.set_title(&login_window_title(&new_origin, None));` on `Started`.
- D-02 — A GUARD ON ONE LINE, NOT ON THE BLOCK. The `page_load_origin` write and the macOS
  origin banner must keep running on BOTH events.
- D-03 — reuse/extend the closure's existing `match payload.event()` rather than adding a second
  unrelated one; keep it rustc-warning-free; say in the plan which shape was chosen.
- D-04 — correct the stale comment that claims the document title "replaces" the origin.
- D-05 — add an in-situ comment at the guarded line recording WHY `Started`-only and WHY
  line-scoped rather than block-scoped.

Purpose: Windows/Linux login windows currently show the bare origin forever. The document title —
the half that tells the operator WHICH page of that origin they are on — is set once by
`on_document_title_changed` and then destroyed by the `Finished` pass through this closure.

Output: a one-line `Started` guard, two corrected/added comments, one new regression test, and the
todo closed out.

**Chosen guard shape (D-03), decided at planning time:** extend the EXISTING match into a tuple
destructure — `let (kind, is_started) = match payload.event() { ... Started => ("started", true),
Finished => ("finished", false) };` — then `if is_started { <the set_title line> }` inside the
existing `if visible {` block. Rationale: it honors D-03's "extend the existing match" literally
(the closure keeps exactly ONE match on `payload.event()`, so there is one source of
event-kind truth), it is a `bool` rather than a string comparison, and both bindings are used so
neither trips `unused_variables`. The `matches!` alternative D-03 also permits was rejected only
because it would introduce a second, separate read of `payload.event()` a few lines below the
first — legal and warning-free, but two places to keep in step.
