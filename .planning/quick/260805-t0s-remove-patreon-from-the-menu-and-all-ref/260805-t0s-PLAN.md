<decisions>
**D-1 — Delete the channel, do not stub it.** `openPatreonPage` is removed from the
`IpcListeners` type, so any surviving caller becomes a compile error rather than a
silent runtime no-op. `pnpm codecheck` is therefore the primary completeness proof.
This matters most for the sidecar: sidecar `send` channels fail *silently* when
unregistered, so a half-removal there would be invisible at runtime.

**D-2 — The three non-`src` funding files ARE in scope.** `.github/FUNDING.yml`,
`Support.md` and `snap/snapcraft.yaml` each carry exactly one Patreon line pointing
the fork's GitHub sponsor button / support doc / snap donation list at *upstream's*
Patreon. They are one-line deletions, they are the only remaining matches, and leaving
them would make "all references removed" untrue and unverifiable by a single grep gate.
**Only the Patreon lines are touched** — the sibling Ko-fi, GitHub Sponsors, ETH and
BTC entries in those same files are deliberately left exactly as they are (the
developer asked about Patreon only).

**D-3 — Upstream translation payloads are untouched.** Verified: `public/locales/*`
contains no `patreon` string, so there is nothing to strip. Had there been one, the
call would have been to leave upstream-owned translation JSON alone (it is regenerated
from Weblate; editing it guarantees merge conflicts) and let the dead key rot. No such
edit is needed here.

**D-4 — Stale channel counts are corrected, not left approximate.** The sidecar
docstrings state exact channel counts and the test asserts one via `toHaveLength`.
Both the prose and the assertion are decremented so the module keeps telling the truth
about itself. The slice denominator moves 29 → 28 as well: the channel is deleted from
the product, not merely unregistered. `.planning/IPC-PORT-INVENTORY.md` and the
`*-PORTED-CHANNELS.md` ledgers are **not** touched — they are historical records of
what was ported at the time, and this plan does not rewrite history.
</decisions>
