<measured_facts>
Measured before planning. These are inputs, not questions. Do not re-derive them.

1. **The renderer build is mandatory, not hygiene.** `src-tauri/src/main.rs:9813` calls
   `tauri::generate_context!()`, which embeds `frontendDist` at COMPILE time.
   `src-tauri/tauri.conf.json:7` sets `frontendDist: "../build/renderer"` and `:8` sets
   `beforeBuildCommand: ""`. The crate therefore does not compile -- tests included -- unless
   `build/renderer` exists. `pnpm exec vite build` alone produces it: `vite.config.ts` has
   `outDir: 'build'`, and its `assembleRendererDistPlugin` (`meta/assembleRendererDist.ts`)
   assembles `build/renderer` in `closeBundle`. A stub `build/renderer/index.html` was considered
   and REJECTED in CONTEXT: a fake input means a real asset/codegen break passes the gate and only
   surfaces at release time.

2. **The job lands green.** `cd src-tauri && cargo test --bin gamelib-shell` was run on the
   operator's Windows machine on 2026-09-23: `234 passed; 0 failed; 2 ignored`. The
   `store_embed_wire_contract_*` break the todo describes is already fixed.

3. **`gamelib-shell` is the crate's only target** (binary, no lib), so `cargo test --bin
   gamelib-shell` and a bare `cargo test` select the same set today. The explicit `--bin` is kept
   deliberately: it is the exact command the todo names, and it fails loudly if a lib target is
   ever added without thought.

4. **Ubuntu is deliberately excluded.** `src-tauri` needs `libwebkit2gtk-4.1-dev`,
   `libappindicator3-dev`, `librsvg2-dev` to build (`release-tauri.yml:93-97`), and the only
   Linux-specific Rust code is the `cfg(unix)` `libc::kill` arm, which the macOS leg already
   compiles.

5. **The steps to copy verbatim** live in `release-tauri.yml`:
   `- uses: ./.github/actions/install-deps` (`:99`), `pnpm exec vite build` (`:166-168`),
   `dtolnay/rust-toolchain@stable` (`:170-171`), and `swatinem/rust-cache@v2` with
   `workspaces: './src-tauri -> target'` (`:175-177`). `actions/checkout@v6` is the version every
   workflow in this repo uses.

6. **`build-steam-bridge` is NOT needed here.** `release-tauri.yml:153-158` runs it before its
   vite build so `public/bin` lands in the macOS bundle. `cargo test` consumes no bridge assets,
   and `assembleRendererDist.ts:33` explicitly excludes `bin/` from `build/renderer`, so omitting
   it changes nothing the compiler or the tests can observe.

7. **`js-yaml@4.1.1` resolves from the repo root**, so the structural verifies below run without
   installing anything.
</measured_facts>
