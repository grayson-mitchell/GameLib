# [QUICK-260927-p4a] Align the three reused-key `t()` defaults with their catalog values

## Context

`quick-260926-p2w` triaged seven i18next-parser collisions into three classes, fixed the two
mechanical ones, and filed the third — three keys each used at two sites that want different copy —
because choosing the copy is a person's call.

**That call is made: Option A on all three keys.** Align each divergent `t()` default byte-for-byte
with its English catalog value. Do not mint keys. Do not touch `public/locales/`.

The edits are **inert at runtime**: a `t()` default is consulted only when the key is missing, and
all three keys resolve from the catalog at every site today. What changes is that the source stops
claiming copy that is never shown, and a catalog regenerated from source can no longer pick up the
wrong variant.

### Do not re-litigate

removed (`box.shortcuts.message*` vs `box.shortcuts.message-remove*`), so a shared `Shortcuts` title
loses nothing; the Wine modal is reached from a button whose own `title` is `Settings`
(`WineManager/index.tsx:189`), so a `Settings` heading is in-context; the EOS case has a real if
minor copy cost, accepted, and carried forward as Task 2's filed todo.

## Decision — in-situ comments: YES, one line at each of the four sites

The brief asked this to be decided and stated. **Add a comment at all four sites**, and the
divergence from `quick-260926-p2w` (which added none) is principled rather than inconsistent:

- p2w's divergences were a typo (`'Geting'`), a case difference (`'Ok'`) and an ellipsis. Nobody
  re-introduces those on purpose. There is nothing to warn a future author about.
- These four are **deliberate copy someone wrote and will want back**. `'Shortcuts'` sitting inside
  a handler whose every neighbouring key ends in `-remove` reads as a copy-paste bug; `Settings` as
  a dialog `<h3>` reads thin; `'Updating...'` next to three full-sentence siblings reads wrong — and
  Task 2 files a todo saying it arguably *is*. All four carry a live re-introduction hazard.

Each comment is one line and says **why** (the key is shared; the catalog value wins), not what.
Proposed text — the executor may adjust wording for fit but must keep one line per site and stay
consistent in form:

- sites 1 and 2: `// Shared key: catalog 'Shortcuts' wins; the body names the removal.`
- site 3: `// Shared key: catalog 'Updating...' wins; a fuller wording is filed as a todo.`
- site 4 (JSX, directly above the `<h3>`):
  `{/* Shared key: catalog 'Settings' wins, as on the tab that opens this. */}`

Prettier does not reflow comments, so a line slightly over the 80-column `printWidth` will still
pass `--check`; prefer ≤ 80 anyway.

**Named risk: three of the four files are covered by source-grep guard tests that read the real file
and assert inside character windows** — `EosActionConfirmationGuard.test.ts` and
`EosDeclineCallSiteGuard.test.ts` over `AdvancedSettings/index.tsx`, and
`flowRegistrationCensus.test.ts` / `electronReachLedger.test.ts` / `shortcutsFlows.test.ts` over
`sidecar/shortcutsFlowRegistration.ts`. Their windows are anchored by content regex, not absolute
offset, so an inserted comment line should be invisible to them — but this is a prediction, not a
measurement. **Fallback, to keep the consistency requirement intact under either branch:** if a
guard test fails, confirm the comment is the cause by deleting that one comment and re-running; if
confirmed, drop the comments at **all four** sites (not just the failing one) and record the
measurement in the SUMMARY.
