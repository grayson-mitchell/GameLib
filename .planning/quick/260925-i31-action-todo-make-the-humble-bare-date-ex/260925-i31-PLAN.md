<objective>
Make the Humble bare-date expiry defect **unarmable** at its only real fix site:
`extractExpiration` in `src/backend/humble/classify.ts`.

Purpose: `new Date('2026-08-01')` is UTC midnight by spec; `toLocaleDateString()` renders local.
Everywhere west of UTC that renders as the **previous day**. Today `extractExpiration` calls
`.toISOString()` on the parsed value, which **erases date-only-ness** — so by the time the value
reaches either render site it is indistinguishable from a genuine UTC-midnight instant, and no
display-side fix can tell them apart. Fixing it here dissolves the question the todo parked on a
live Humble sync: the corrective is a strict no-op for every value that already carries a time or
zone, so it is correct whichever format upstream actually sends.

Output: a scoped date-only branch in `extractExpiration`, zone-independent correctness tests, and
the todo closed with its stale `ready: live-gate` rationale rewritten.
</objective>
