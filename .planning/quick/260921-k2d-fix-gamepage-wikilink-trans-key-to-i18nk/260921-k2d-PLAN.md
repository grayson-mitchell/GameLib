# Quick Task 260921-k2d — flip `key=` to `i18nKey=` + `ns` + `shouldUnescape`, and prove the entity decodes

## Objective

`src/frontend/screens/Game/GamePage/index.tsx:452` writes:

```
<Trans key="wikiLink" i18n={i18n}>
```

`key` is React's reserved reconciliation prop. React consumes it; it never reaches `Trans`
as a prop, so `Trans` has no `i18nKey` to resolve, falls through to its inline English
children, and renders English in **every** locale. 31 non-English human translations of
`wikiLink` in `gamepage.json` are currently dead.

**Output:** a three-attribute source fix, an explanatory comment that names a deliberate
trade, a rendering test with a fourth assertion the sibling task did not need, and a new
todo carrying a finding this task is scoped out of repairing.

## The todo's central premise is FALSE — read this before you start

`.planning/todos/pending/2026-09-19-gamepage-wikilink-trans-uses-key-not-i18nkey.md` says
this is "probably a genuine one-line fix" that lights up 31 translations "with **no catalog
change at all**". **The first half is wrong.** It was written from a diff review, and this
defect's whole character is that a diff review cannot see it.

Measured by the orchestrator in this session, by actually rendering through a real i18next
instance against the real catalogs — **do NOT re-derive these; re-running the probe costs
context for no gain**:

- With `i18nKey` + `ns="gamepage"` and nothing else, `lng: 'de'` renders
  `Wichtige Informationen zu diesem Spiel, bitte lies dies:&amp;nbsp;<a ...>Öffne Seite</a>`.
  The user **visibly sees the seven characters `&nbsp;`**. The catalog stores the literal
  entity; React escapes the `&` on output. The naive one-line fix trades a
  dead-translation defect for a visible-mojibake defect across ~31 locales. **That is a
  regression, not a fix.**
- Adding `shouldUnescape` renders
  `Wichtige Informationen zu diesem Spiel, bitte lies dies: <a ...>Öffne Seite</a>` — clean.
  `shouldUnescape?: boolean` is a real typed prop of the installed react-i18next v12
  (`node_modules/react-i18next/TransWithoutContext.d.ts:24`).

**The trade you are making, deliberately.** `shouldUnescape` decodes `&nbsp;` to an
**ordinary space, `U+0020`** (measured codepoint `0x20`) — **not** a true non-breaking
space `U+00A0`. The original JSX `&nbsp;` compiled to a real `U+00A0`. So this fix restores
31 translations at the cost of downgrading one non-breaking space to a breaking one, in
English too. That is an accepted, stated trade. It goes in the code comment and in the
summary. It is not an oversight and it is not to be quietly "fixed" by hand-editing the
catalogs — see Scope.
