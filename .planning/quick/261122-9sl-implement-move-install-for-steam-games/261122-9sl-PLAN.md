<objective>
Ship Move install for Steam-registered games on macOS. Mac Steam does the move itself through IClientAppManager::MoveApp, which spike 090 validated. GameLib picks the target library, refuses unsafe or pointless moves, waits for Steam to finish, then updates its cached install_path so the game does not show "not available".

Purpose: Move is one of the Steam actions GameLib can't start today. `moveInstall()` in `gameMaintenance.ts` is a stub, and the Install tab hides Move for Steam.
Output: a `--steam-moveapp` helper subcommand, the `requestSteamMoveApp` TS seam, `moveNative.ts`, real `moveInstall()` routing, a path-aware `refreshInstallState`, the Move gate shown for Steam on macOS, unit tests, and a progress note on the todo.

How the chosen folder reaches Steam (checked during planning, so the executor need not re-derive it):
- Move… on the Location row (`LocationRow.tsx`, through `useInstallLocationActions.onMoveInstallYesClick`) calls `window.api.moveInstall({ appName, path, runner })`.
- That reaches the `'moveInstall'` handler in `src/backend/sidecar/installFlowRegistration.ts` (~line 490). The handler runs `assertPlausibleAbsolutePath`, sends 'moving', calls `getGame(appName).moveInstall(path)`, shows its own error dialog for `status: 'error'`, then sends 'done'. It does NOT catch a rejection, so `moveInstall` must never throw.
- `changeInstallPath` (`gamedetails/dispatch.ts`, `gameDetailsFlowRegistration.ts`) is the separate "Wrong folder?" / Set-folder action. For Steam it is a library no-op, and its gate stays hidden. It is out of scope and is not touched.
- The only reason Move is unreachable for Steam today is `installActionGates.ts`: `move: conflicting(managedStore)`, where `managedStore` excludes Steam.

Planner decisions (Claude's discretion, recorded for the SUMMARY):
- The helper takes `--library <absPath>`, not a raw folder index, and resolves the index itself from Steam's own `GetNumLibraryFolders`/`GetLibraryFolderPath` list with the existing `gl_ia_folder_matches`. This is the same matching `--steam-installapp --library` does. TS cannot compute Steam's index safely: `getSteamLibraries()` prepends `/usr/share/steam` and drops paths that don't exist, so its positions are not Steam's indices.
- The helper does not decode serializer argument sizes, so the slot guard is the whole spike-090 run 67–70 in order. GetAppLibraryFolder (0x166e) and GetAppInstallState (0xeaf2) have the simple `(appId)` shape and are accepted on a unique ID alone, the same trust level validate gives GetAppInstallState.
- Move is not gated on the experimental InstallApp setting. This matches validate and uninstall: the user explicitly asked for the move, and it runs through Steam's own flow.
- No progress percentage reaches the frontend. GameStatus "Moving…" is the readout, and the helper logs progress to stderr only.
- No UI change beyond the gate. The Move picker stays a free folder picker. The backend refusal names Steam's registered libraries, which the orchestrator accepted as sufficient.
- Tests are jest (`npx jest`). The repo has no vitest, and every existing steam test is jest.

Add `static int gl_ia_run_move(uint32_t app_id, const char *library, bool wait, bool dry_run)` inside the existing `__aarch64__` block, in this order:

1. Same preamble as `gl_ia_run_validate`: redirect fd 1 to fd 2, find the getter slot, attach, check the RTTI.
2. **Run guard.** `move_slot = gl_ia_find_method_slot(vt, GL_IA_FN_MOVEAPP)`. Require all three neighbours, each by unique ID (`gl_ia_find_method_slot`) AND by `gl_ia_slot_hi` at the exact position:

    - Elapsed >= `GL_IA_MOVE_WAIT_CAP_S`: stop with reason `wait-cap`.
