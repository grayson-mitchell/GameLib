<objective>
Close two review findings on the Phase 34.4.1 login/OAuth seam:

- **WR-01** (cycle 1): three business-logic files central to this seam create five timers that are
  cleared on their own success/failure paths but never withdraw their claim on the event loop. Under
  CLAUDE.md's sidecar exit contract each one can hold the process alive past stdin EOF for up to its
  own deadline — worst case a repeating 1500ms interval on a 10-minute leash — and CLAUDE.md records
  that anything the shell's `shutdown_child()` SIGKILL ever misses "leaves an orphan holding an
  authenticated session". Add the guard at all five sites.
- **D-WR-01** (cycle 2, lane D): the log-hygiene regression test in `useTauriOAuthLogin.test.tsx`
  iterates `mockApi.logInfo.mock.calls` with no assertion that the list is non-empty. It is
  non-vacuous today only incidentally. Add the missing non-vacuity guard, and prove by mutation that
  it is load-bearing.

Purpose: WR-01 is the one invariant in this codebase that has broken three times in three weeks, and
the transport layer already implements it correctly three files over — the gap is only in the
business-logic files this phase added. D-WR-01 is the security-property-that-stops-being-checked
shape: the test whose whole purpose is "no secret ever reaches a log line" would go green while
asserting nothing.

Output: five guarded timer handles across three backend files; one added assertion in one frontend
test; a mutation transcript proving that assertion fires.

**Additive only.** No timeout duration changes, no promise-race restructuring, no refactor of the
timer logic, no new gate/lint rule/census test for this invariant repo-wide (CLAUDE.md is explicit
that such a gate "would have caught none of the three breaks cleanly" and is "a separate,
deliberate decision — do not add one reflexively"). The second half of the exit contract
(unbounded in-flight boot work, open item `260913-m9c`) is out of scope.
