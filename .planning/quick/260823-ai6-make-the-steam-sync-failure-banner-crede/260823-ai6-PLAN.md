# Quick Task 260823-ai6: a signed-out Steam sync banner that offers sign-in, not retry

## Problem

Observed during the `260822-vov` UAT (2026-08-23). With the Steam credential proven gone, a
library refresh fails and raises `SteamSyncNotice` in `'failed'` mode:

> **Couldn't sync your Steam library**
> Your other libraries are still available. Try again, or check that Steam is reachable.
> `[ Retry Steam sync ]`

Both halves are wrong in this state. Steam **is** reachable — the session is unauthenticated.
And `Retry Steam sync` re-enters `refreshLibrary`, hits the same empty keyring read, and fails
identically.

This is the exact reasoning Phase 37 already applied to the **install** path
(`steam/depotErrors.ts:170`):

> *"Deliberately offers no "Retry" wording: retrying without first signing in can only fail
> again in the identical way."*

…which is why the install dialog gets a **Sign in to Steam** button. The sync banner never got
the same treatment. `steamConfigStore.credentialsMissing` (quick task `260822-vov`) now makes
the distinction available to the renderer.

## Design decision: `steamCredentialsMissing` is REQUIRED, not optional

Making the new `SteamSyncIndicatorInput` field optional would leave the 16 existing typed
literals in `librarySyncIndicator.test.ts` untouched — but there is exactly **one** production
call site (`Library/index.tsx:1002`), and the Frontend jest project has no jsdom, so **no test
can observe whether that call site passes the field**. A compile error is the only mechanism
that can prove it. Optional would let a forgotten argument ship a banner that silently never
appears — the same class as a void writer that can decline.

So: required, and the 16 test literals each gain an explicit `steamCredentialsMissing: false`,
which also documents their pre-flag meaning rather than leaving it implicit.

## Constraints

- Branch order in `resolveSteamSyncIndicator` matters. The `!steamLoggedIn → hidden` guard
  (branch 1) **must stay first** — its comment says it is evaluated first so no later branch
  can leak a Steam surface to a user with no Steam account. The new branch goes after it and
  before the `'failed'` branch.
- **Scoped:** `'signedOut'` only when `steamSyncStatus === 'failed'` **and** the flag is set.
  Never an always-on banner — the accounts tile already covers the idle signed-out case, and a
  second permanent surface would compete with it.
- `SteamSyncNotice`'s structural contract is load-bearing: one component, one
  `<div className="SteamSyncNotice">` in normal document flow, no `position: absolute/fixed`,
  no early return that replaces siblings. Its docstring records this as the mechanical reason
  defect 2b (GOG games hidden behind a centred Steam spinner) cannot recur.
- New strings go in `gamelib.json`. `translation.json` is upstream-owned and
  `meta/i18nCatalogChurnGuard.ts` fails the build on fork edits to it.
- Frontend jest is `testEnvironment: 'node'`, no jsdom — logic stays in the pure resolver.
