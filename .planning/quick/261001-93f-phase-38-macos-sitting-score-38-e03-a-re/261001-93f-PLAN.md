<e03_hypotheses>
The sharp, falsifiable form of the `38-E03`(a) question, derived from the two prior measurements.
Task 3 carries it into `e03a-prediction.md`; nothing here is a result.

Spike 017 measured, at scale factor **1.0**: `req (290.5, 96.5, 760.25x560.75)` read back as
`(291, 97, 760x561)` and concluded "fractional CSS px round to the nearest whole logical pixel".
At scale factor 1.0 that conclusion is **unidentified** — two different quantizations are
observationally identical there:

- **Hypothesis A (whole-logical quantization):** the realised physical edge is
  `round(x_logical) * dpr`.
- **Hypothesis B (physical-px quantization):** the realised physical edge is
  `round(x_logical * dpr)`.

At dpr 1.0 A and B are the same number for every input. At dpr 2.0 they differ by 1 physical px
whenever the fractional part of `x_logical` is neither 0 nor 0.5 — e.g. `x_logical = 1209.6` gives
A = 2420 and B = 2419. So only a scale factor other than 1.0 **plus a slot rect whose logical
coordinates are fractional** can separate them, and plan 40-11 could not: its delta was 0 px on a
static, integer rect. This is precisely the gap `38-E03`(a) exists to close.

**A premise that must be MEASURED, not assumed.** On a Retina panel, macOS implements the "looks
like" scaled modes by rendering into a larger framebuffer and downscaling to the panel, so
`backingScaleFactor` / `devicePixelRatio` may report **2.0 at every HiDPI setting** and vary only if
a non-HiDPI mode is selected. If that holds here, the variable that actually varies across the
operator's settings is the **fractional logical slot geometry** produced by differing logical
viewport widths, not the scale factor — and that is still exactly what the item needs. The
prediction file must state the premise as a reading to be taken (H1), record whatever comes back,
and must not assert in advance which way it goes.
</e03_hypotheses>

`edgeprobe.swift` — a single Swift file, `import Foundation`, `import CoreGraphics`,
`import ImageIO`, `import AppKit`, dispatching on `CommandLine.arguments[1]`. Every subcommand
prints exactly one JSON object per invocation on stdout (JSONL for `sample`), and exits non-zero
with a JSON `{error}` on failure. Subcommands:

- `winrect --pid <pid>` — filter `CGWindowListCopyWindowInfo` (`optionOnScreenOnly`,
  `excludeDesktopElements`) to the given owner pid, pick the largest layer-0 window, and print
  `windowNumber`, `bounds` (x, y, w, h in logical points), `layer`, `isOnscreen` and
  `onscreenFlagPresent`. When `kCGWindowIsOnscreen` is absent, set `onscreenFlagPresent` false and
  add a `warning` naming the inactive-Space trap: the app's Space must be active or the reading is
  garbage. Never substitute a default for a missing flag.
- `shot --rect x,y,w,h --out <path.png>` — capture that screen region. Try the CoreGraphics
  in-process capture first; if it yields nil (macOS 26 may refuse it), fall back to spawning
  `/usr/sbin/screencapture` with `-x -o -R` and the same rect. Print `backend` (which one ran),
  `width`, `height` and `elapsed_ms`. Width/height against the requested logical rect is what
  yields the capture scale, so both must be printed even on the fallback path.
- `bgsample --png <path> --at x,y --size <n>` — mean RGB of an n-by-n patch. This is how the
  background colour gets MEASURED; nothing downstream may hardcode one.
- `edges --png <path> --band y0,y1 --bg r,g,b --tol <n> --from right|bottom` — scan inward from the
  named side over the band, and report the first column (or row) whose mean colour falls outside
  `tol` of `bg`: that is the embed's realised edge, in image pixels. Also print `bg_run_px` (how
  wide the background strip was), `grad_max` (the largest absolute adjacent-column luma step near
  the boundary, which is the crispness figure `38-E03` needs) and `samples`. Set `unresolved` true
  and locate no edge when the entire band is background or the entire band is not — an
  all-background band means the embed is nowhere in the band, and an all-non-background band means
  the edge is outside it. Both are samples the instrument could not take and must be reported as
  such rather than resolved to a plausible number.
- `sample --rect x,y,w,h --band y0,y1 --bg r,g,b --tol <n> --pid <pid> --duration-s <n> --out <jsonl>`
  — the latency sampler: a tight loop that, per iteration, captures the strip, locates the edge, and
  reads the window rect through the same `winrect` path, appending one JSONL record with a monotonic
  `t_ms` (mach absolute time, not wall clock), `cap_ms`, `win`, `edge_px`, `gap_px` and
  `unresolved`. On exit print a summary object carrying `samples`, `duration_ms`,
  `cadence_ms` (median, p90, max), `unresolved_count` and `backend`. The cadence fields are the
  instrument's own resolution limit and are required output, not polish — sitting 13's Windows
  sampler recorded "cannot see sub-28 ms frames" and that statement is what made its numbers
  honest.
- `synth --out <dir> --frames <n> --edge0 <px> --step <px> --lag <px> --bg r,g,b --fg r,g,b` — the
  positive-control generator. Write `frames` PNGs in which a foreground block's right edge advances
  by `step` per frame while a second, trailing edge lags it by `lag` px, plus a `truth.json` listing
  the exact edge column of every frame. Ground truth is generated with the frames, never typed in
  afterwards.
- `selftest` — run `synth` into a temporary directory under `TMPDIR`, run the `edges` locator over
  every frame, and assert each located edge equals `truth.json` EXACTLY. Exit non-zero on any
  mismatch, printing the frame index and both numbers.

Write the two-profile declaration from `<two_profile_declaration>` as a header comment in this file,
at the `screencapture` spawn site: this instrument deliberately inherits the operator's real
profile, passes no `env` literal, assigns none of the eight containment variables, and never spawns
GameLib itself.

`slotprobe.js` — a plain browser snippet for the Web Inspector console (no imports, no bundler).
Define a `__glSlotProbe` object exposing `start()`, `stop()`, `mark(label)` and `dump()`. `start()`
resolves the slot with `document.querySelector('.WebView__embedSlot')` and **throws loudly when the
match is null** rather than sampling nothing — a silent null is the one failure that would make the
renderer arm look green while measuring air. It then samples on `requestAnimationFrame`, pushing
`performance.now()`, the slot's `getBoundingClientRect()` kept as FLOATS to three decimals (rounding
here would destroy the very fractionality `38-E03` measures), `devicePixelRatio`, `innerWidth`,
`innerHeight`, `outerWidth`, `outerHeight`, `screen.width` and `screen.height`. `mark(label)` drops
a labelled record so the operator can bracket each gesture and each settings change. `dump()`
returns one JSON string for the operator to save, and also reports `frames`, the observed rAF
interval (median and max) and the count of frames in which the rect did not change.

`analyze.mjs` — the reducer, Node ESM, no dependencies. Read an `edgeprobe sample` JSONL and
optionally a `slotprobe` dump, and print two tables:
(1) the `38-E04` measures — tracking gap between consecutive embed-edge changes while the window
size is changing, settle time from the last window-size change to the last embed-edge change,
and the excess gap during motion over the at-rest baseline gap, each as median/p90/max, alongside
the sampler's own cadence and its unresolved count;
(2) the `38-E03` table — per captured still, the renderer's float slot edge, the realised physical
edge, and the two candidate predictions from `<e03_hypotheses>` (`round(x)*dpr` and
`round(x*dpr)`), so the reader can see which one the measurement matches.
It **prints tables and computes no verdict** — no pass, no fail, no threshold comparison. Thresholds
