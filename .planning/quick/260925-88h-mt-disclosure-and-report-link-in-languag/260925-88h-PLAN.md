<measured_facts>
Measured by the planner on 2026-09-25. These are facts to rely on, not work to repeat.

- i18next is 22.5.1 and no `compatibilityJSON` is set, so plurals use JSON v4 suffixes
  (`_zero _one _two _few _many _other`). The suffix comes from `pluralResolver.getSuffix(code, count)`,
  which calls `new Intl.PluralRules(code)` (node_modules/i18next/dist/cjs/i18next.js:1218, 817).
  Inline plural defaults are supported: `options["defaultValue" + suffix] || options.defaultValue`
  (line 663-664).
- Consequence: if `ru` holds only `_one/_other`, a count of 3 resolves `_few`. That key is missing
  in ru, so i18next falls back to **en** `_other`, and the user sees ENGLISH. Adding en plural keys
  without making the fill emit each locale's CLDR categories would make Slavic locales worse. That
  is why Task 1 exists.
- `machineFillGamelib.ts` detects stale keys by **key presence only**. `collectMissingKeys` (L124)
  treats a key as missing when it is absent or '' AND en is non-empty, and never touches a
  non-empty value (D-09). There is no source hash. So "invalidate" means: delete the key from the
  locale's gamelib.json. Plural handling today is pairwise `_one`/`_other` only (`pluralSiblingOf`,
  L374). `TranslateFn` batch items are `{keyPath, source, locale, memory}` (L36-43). The system
  prompt is built at L620-640, and the user payload is `{keyPath, source, memory}` at L644-648. The
  writer uses `JSON.stringify(merged, null, 4)+'\n'` for gamelib.json and `(manifest, null, 2)+'\n'`
  for gamelib.mt.json (L866-867). The CLI refuses a bulk run unless
  `GAMELIB_MT_LOCALES=all GAMELIB_MT_CONFIRM_BULK=1`, and reads `ANTHROPIC_API_KEY` from env only.
- `meta/__tests__/gamelibCatalogParity.test.ts` runs over every committed locale. It FAILS on any
  key not present in en/gamelib.json ("orphaned translation"), and its pairing check is `_one`/
  `_other` only. A future `ru` `_few` key would go red there. Old key names that are left behind
  after an en rename would also go red.
- `meta/lintTranslations.ts` does NOT fail on extra keys (`printExtraTransations = false`). Its
  inverted presence check requires every en key in every locale. Known gaps are recorded in the
  committed SET `meta/i18nCatalogPresenceBaseline.json` (currently `totalPairs: 0`), and drift in
  either direction fails. The repo handles a new en key by regenerating the baseline:
  `LINT_TRANSLATIONS_WRITE_BASELINE=1 pnpm lint-translations:gamelib` (precedent `68348932e`).
  The live-tree test in `meta/__tests__/lintTranslations.test.ts` enforces it in jest/CI.
- `i18n-churn-guard` allows any `*/gamelib.json` / `*/gamelib.mt.json` change and forbids upstream
  catalogs. Do not touch translation.json/gamepage.json/login.json.
- An external-URL opener already exists: `window.api.openExternalUrl(url)` (preload
  `src/preload/api/misc.ts:26`, typed `src/common/types/ipc.ts:90`, sidecar
  `shellFilesFlowRegistration.ts:148` -> `openUrlOrFile`, which does `shell.openExternal` for
  `http*`). It is used by HeroicVersion and DialogHandler. **No new IPC channel is needed, so the

- `showWeblateLink` is never true anywhere: GeneralSettings uses the default false, and Login
