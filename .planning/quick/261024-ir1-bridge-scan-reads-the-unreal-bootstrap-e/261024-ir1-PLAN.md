## Root cause (verified by the planner against the source)

- The UE stub imports no steam_api, so `placeShimForGameInner` takes the `importResult.arch === 'none'` branch (shimGenerate.ts ~line 576). It walks `resolveWalkRoot(...)`, which is the install root `steamapps/common/<installdir>` from games.ts `resolveBridgeGameInstallRoot`, through `findRuntimeLoadedSteamApiDlls`.
- That walk is bounded by `RUNTIME_WALK_MAX_DEPTH = 4`. `walk(root, 0)` recurses only while `depth < 4`, so files are seen at most 4 directories below the root. `Engine/Binaries/ThirdParty/Steamworks/Steamv157/Win64/steam_api64.dll` is 6 directories down, so `runtimeDlls` is empty and the branch falls through to `no-steam-api` (~line 769).
- If the dll were found, the existing i94 branch would already handle the rest. It replaces the dll at its real path, reports `shimPaths`, picks the launch arch with `readExeMachineArch` (the stub is x64), and evaluates coverage from same-arch importers found by `findSteamApiImporterPes`. The Shipping exe at `<P>/Binaries/Win64/` is depth 3, so it is reachable. That walk does stop at `IMPORTER_SCAN_MAX_FILES = 512` in readdir order, and UE trees ship many DLLs under `Engine/Binaries/ThirdParty`. The Shipping exe can therefore be cut off, which gives a spurious `steam_api64.dll@runtime-loaded` miss.
- **Do not just raise `RUNTIME_WALK_MAX_DEPTH`.** The existing test `no steam_api DLL within depth 4 -> unchanged no-steam-api` (test file ~line 740, a dll at `a/b/c/d/e/`) pins the generic bound, and i94 loosened no existing test. The fix is a targeted UE probe that leaves the generic walk as it is. Raising the importer depth or cap is also wrong: each extra PE costs one objdump spawn.
- **games.ts needs no change.** Its `no-steam-api` / `placed` / `placed-miss` handling and the cfg-beside-every-`shimPaths` write (quick 261023-ue0) already do the right thing once placement returns `placed`/`placed-miss`. `gameInstallRoot` is already passed at both call sites (games.ts ~1594 and ~2755). Modern-SDK `SteamInternal_*` exports (todo fix step 3) already shipped in i94. Do not redo them.
