<objective>
Fix macOS shortcut icon generation, which is broken on BOTH a mismatched import and a
correct install. Two independent proximate causes live in `src/backend/shortcuts/utils.ts`
(NOT `shortcuts/shortcuts.ts`, which the todo's `files:` frontmatter wrongly names):

1. `getIcon`'s gog branch dereferences `gameInfo.install.install_path!` through a false
   non-null assertion, so `join()` throws `ERR_INVALID_ARG_TYPE` whenever `install_path`
   is absent.
2. `downloadImage` is declared non-async and calls the `async` `downloadFile` without
   `await`, so the download is fire-and-forget: `getIcon` returns an icon path while the
   file is still in flight, `convertPngToICNS`'s `readFileSync` hits ENOENT, and
   `downloadImage`'s own `try/catch` can never see the rejection.

Purpose: every macOS install/import currently either throws or produces an iconless
outcome that then DELETES the whole `.app` - a missing icon destroys the shortcut.

Output: guarded + awaited `getIcon`, graceful iconless degradation, unit coverage for
both causes, todo closed.

Root causes are already pinned. Do NOT re-derive them.
</objective>

- D-01 - `getIcon` returns `Promise<string | undefined>`. `undefined` means "no icon could
  be obtained". This is the natural shape and it forces every call site to be explicit.
  All FOUR call sites in the census above are updated in this plan.

- D-02 - the gog branch guards, it does not throw. `install_path` absent means: skip the
  `.ico` / `support/icon.png` probes entirely and fall through to `getProductApi` +
  `art_square`. Delete both `!` non-null assertions; do not replace them with `?? ''`
  (that would probe a bogus relative path).

- D-03 - `getIcon` verifies the EXACT file, replacing `checkImageExistsAlready(icon)` with
  `existsSync(icon)` inside `getIcon`. Rationale: `checkImageExistsAlready` matches `.png`
  OR `.jpg` in the same directory, so it can report `true` for `X.png` when only `X.jpg`
  exists - a second, independent route to the same ENOENT. `checkImageExistsAlready` stays
  exported and is still used by `steamhelper.ts:114`; this is not a deletion.

- D-04 - a missing icon must NOT destroy the shortcut. `generateMacOsApp`'s current `else`
  branch `rm`s the entire `.app`. Restructure so the `.app`, `Info.plist` and `run.sh` are
  written UNCONDITIONALLY, and only the `CFBundleIconFile` key pair is conditional on the
  icon having been produced. Delete the `rm`.

- D-05 - log levels. `logWarning` for the EXPECTED "no icon available" path (in `getIcon`,
  in `convertPngToICNS`'s undefined-path early return, and in `generateMacOsApp`'s iconless
  branch). `convertPngToICNS`'s existing `logError(['Error converting icon to icns:',
  error], ...)` in its `catch` SURVIVES BYTE-UNCHANGED - genuine failures do not get
  quieter, and nothing becomes silent.

- D-06 - no new user-facing strings. Every line added is a backend log line, so no
  `en/gamelib.json` key is minted and the i18n gates are untouched.

- D-07 - `prepareImagesForSteam` now awaits each download serially. This is the unavoidable
  consequence of D-01 at `steamhelper.ts:116`, and it is a correctness gain: that
  `if (error) errors.push(error)` branch is presently DEAD, because a non-async
  `downloadImage` can never return a rejection. Note the serialization in the SUMMARY; do
  not "optimize" it back into a fire-and-forget or a `Promise.all` in this task.
