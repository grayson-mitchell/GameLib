<design_decisions>
1. **Facility reuse.** `grep -rn storesearch src` returns nothing: no title->appid lookup exists in
   the Steam stack (gameMetadata.ts only does appid->details via `STEAM_STORE_API`
   `/api/appdetails`). The only existing title->steamAppId facility is CheapShark
   (`src/backend/storeSearch/cheapshark.ts searchGames`, returns `steamAppId`), considered and NOT
   used: it is a third-party deal index (games without deals or with a null `steamAppID` never
   resolve), its search is substring with limit 60, and it is a non-Steam intermediary for a
   Steam-identity question. Decision: call Steam's public
   `https://store.steampowered.com/api/storesearch/` with the project's frozen HTTP client
   (**axios**, per CLAUDE.md "axios for public store metadata"), mirroring gameMetadata.ts's
   `axios.get` + timeout pattern. No new dependency, no new client — one new endpoint function.
2. **Precision rule** (`pickConfidentAppId`): consider only items with `type === 'app'`; accept iff
   EXACTLY ONE distinct `id` has `normalizeForAppIdMatch(item.name) === normalizeForAppIdMatch(title)`
   and the normalized title is non-empty. Zero or >=2 distinct ids -> null (ambiguity, e.g. two
   apps both named "DOOM", is a miss). `normalizeForAppIdMatch` is a NEW strict normalizer — do NOT
   reuse `common/matching/titleMatch.ts normalizeTitle`, which strips ALL parentheticals and the
   EDITION_SUFFIXES list (it would equate "X" with "X Deluxe Edition" — the exact near-miss this
   rule must reject). Steps: NFKD + strip combining marks; lowercase; remove `™ ® ©`; strip a
   trailing `(steam)`, `[steam]`, `steam key`, `- steam`, `(steam key)` suffix (repeatably, at end
   only); replace every non-letter/non-digit (`/[^\p{L}\p{N}]+/gu`) with a single space; trim.
   Nothing else is stripped (no edition words, no "the", no `&`->and).
3. **Cache** = new CacheStore in the existing Humble store family (`createHumbleStores`):
   `humbleSteamAppIdStore = new CacheStore<HumbleSteamAppIdCacheEntry, string>('humble_steam_appid',
   null, { root: deps.root, kind: 'cache' })`, entry `{ appId: string | null; checkedAt: number }`,
   keyed by `normalizeForAppIdMatch(title)`. Lifespan `null` (TTL is applied in code, because hits
   and misses need different TTLs): hit (`appId` string) never expires; miss (`appId: null`)
   expires after `HUMBLE_APPID_MISS_TTL_MS = 7 * 24 * 60 * 60 * 1000`. Request ERRORS are never
   cached. Kind 'cache': rebuildable public title->id pairs. Not wiped on Humble disconnect
   (accepted, see threat T-ca6-03) — avoids touching user.ts and its clear-order test.
4. **Library accessor (no logon).** Ownership and the "should we resolve at all" gate both read
   `getSteamGate()` in library.ts (~L127): `steamUser.isLoggedIn()` — which is
   `SteamUser.isLoggedIn()` (src/backend/storeManagers/steam/user.ts L143), a plain
   `configStore.get_nodefault('isLoggedIn')` read, no keyring, no CM — and
   `stores.steam.steamLibraryStore.get('games', [])`, the persisted on-disk Steam library cache.
   Neither opens a steam-user connection, calls `getUserOwnedApps()`, refreshes the library or can
   reach the macOS Go Offline wrap. The resolver itself never touches the Steam stack at all (only
   axios to the public store endpoint). The resolve pass is SKIPPED entirely when
   `getSteamGate().open` is false (Steam not signed in or empty cached library) — no titles leave
   the machine for users who could not use the result.
5. **When it runs.** Only from `runSync()` (Humble sync = boot sync and manual Refresh both go
   through `sync()`), never per render, never from `recomputeOwnership()` / the Steam-refresh
   trigger. It is kicked AFTER `recomputeOwnership()` and NOT awaited, under its own single-flight
   (`resolveInFlight`), so the Humble sync spinner is not held for ~15s. When the pass completes
   and patched any key, it calls `recomputeOwnership()` (which re-pushes `humbleKeysUpdated`).
6. **Fill from cache at commit.** In `fetchAndCommitOrder`, right after `classifyOrder` and before
   the `steamGate` overlay branch, fill `steamAppId` + `steamAppIdResolved: true` on every
   `platform === 'steam'` key lacking a usable id from `resolver.lookupCached(key.title)`
   (synchronous, cache-only, hit-only). This keeps the id stable across re-syncs and restarts
   without any request, and closes the commit-time churn window the 14-08 comments describe.
7. **dedup tier for resolved ids.** Add optional `steamAppIdResolved?: boolean` to `HumbleKey`
   (src/common/types/humble.ts, next to `steamAppId` ~L112, doc-commented "true when steamAppId was
   resolved by GameLib from the title, not supplied by Humble"). In `dedup.ts`: usable id + library
   hit -> 'exact' (unchanged, for both sources); usable id + miss -> 'none' ONLY when
   `steamAppIdResolved !== true` (Humble-supplied, D-44 unchanged); a RESOLVED id that misses falls
   through to the existing fuzzy tier. So the change can only turn 'fuzzy'/'none' into 'exact' on a
   real library hit; it can never downgrade today's 'Likely'. The D-42 override still only clears
   'fuzzy'. HumbleOriginInfo.tsx (REDEEMED key `steamAppId === gameInfo.app_name`) benefits for free.
8. **Sidecar exit contract** (`Skill("gamelib-conventions")` -> "The sidecar's exit contract"; the
   sync runs at boot, so the pass can be live at stdin EOF). Half 1 — every handle unref'd: the
   inter-request sleep is `new Promise<void>((resolve) => { const t = setTimeout(resolve, ms);
   t.unref?.() })` (the `.unref?.()` spelling, because jest fake timers need not implement unref).
   Half 2 — no unbounded in-flight work: each request is bounded by `timeout: 8000`; a pass makes at
   most `HUMBLE_APPID_RESOLVE_CAP = 40` requests (remaining titles are counted as `deferred` and
   picked up by the next sync); the pass stops on the first request error (no retry storm, errors
   not cached) and stops when the Humble sync fence goes stale. Worst case at stdin EOF: one
   in-flight request holds the loop <=8s, then the unref'd sleep lets the loop drain. No new
   library-owned handle exists, so nothing is added to `releaseOnStdinEof()`.
9. **Politeness.** Sequential `for` loop (no `runBounded`, no Promise.all); sleep
   `HUMBLE_APPID_REQUEST_GAP_MS = 350` before every request except the first; cached titles
   (hit, or miss younger than TTL) skipped before counting toward the cap; titles de-duplicated by
   normalized key. Params via axios `params` (`term`, `l: 'english'`, `cc: 'US'`), never string
   concatenation.
10. **Logging.** Exactly one `logInfo` per pass, `LogPrefix.Backend`, exact text:
    `Humble: resolved ${N}/${M} Steam app ids (${H} cached, ${X} misses, ${E} errors, ${D} deferred)`
    where M = distinct normalized eligible titles, N = titles with an id after the pass (cached hit
    + fresh hit), H = titles answered from cache (hit or fresh miss), X = misses (cached + fresh),
    E = request errors, D = titles left for the next pass by the cap or a stop. Grep token:
    `Humble: resolved`. No per-title log lines; an error is summarized by the E count only (do not
    log the axios error object — it can carry request config). The resolver only ever receives
    titles, never keys, so key codes (`redemptionData.keyFormatted` / `revealedKeyValue`), cookies
    and tokens cannot reach it; a library test asserts this end to end.
</design_decisions>
