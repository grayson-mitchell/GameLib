<objective>
`GOGUser.getUserDetails()` fetches `https://embed.gog.com/userData.json`, which embeds the
account's entire wishlist / friends / checksum payload. For accounts with large wishlists GOG
returns an error rather than a truncated document, so `getUserDetails()` returns `undefined`,
`configStore.userData` is never written, and the user appears logged out with no username even
though auth actually succeeded.

Repoint the call at `https://api.gog.com/users/{user_id}` -- a small fixed-size document that
cannot grow with wishlist size -- and narrow the `UserData` type to the three fields anything
actually reads.

Purpose: make GOG login succeed for every account size.
Output: a `getUserDetails()` that writes `{ userId, username, galaxyUserId }` from an endpoint
whose response size is independent of the account's wishlist.
</objective>

<decisions>
Three decisions the executor MUST NOT relitigate:

**D-1 -- `UserData` is NARROWED, not made optional.**
`UserData` becomes exactly `{ userId: string; username: string; galaxyUserId: string }`.
Justification (one line): marking the dropped fields optional would still let new code compile
`userData.friends?.length` against data that can now never arrive, whereas narrowing makes `tsc`
reject every dead read at build time -- and it deletes `email` from the type outright, so the
`delete data.email` privacy scrub becomes structurally unnecessary rather than a runtime step
that can be forgotten. Also delete the now-unreferenced `Currency` and `Friend` interfaces.

**D-2 -- `user_id` is sourced WITHOUT a new subprocess spawn.**
`getUserDetails()`'s parameter changes from `accessToken?: string` to
`credentials?: Pick<GOGCredentials, 'access_token' | 'user_id'>`. The login path passes
`{ access_token: data.access_token, user_id: data.user_id }` -- both values are already in the
parsed stdout of the `gogdl auth --code` call `login()` just made, so ZERO extra spawns. The boot
path passes nothing and makes the same single `getCredentials()` call it makes today (TTL-cached,
`GOGCredentials` already carries `user_id`). Net gogdl spawn count is identical to today on both
paths. An object param rather than two positional params is deliberate: it makes "token without a
user id" unrepresentable, which is the shape that would otherwise silently write a `userData` with
an `undefined` galaxyUserId and break every playtime URL.

**D-3 -- `galaxyUserId` and `userId` are both set from `credentials.user_id`.**
`GOGCredentials.user_id` is the Galaxy user id gogdl obtains from GOG's own token exchange; it is
the same value `userData.json` reported. Because that identity is an assumption rather than
something this change can prove offline, the code carries a self-diagnosing guard: if a previously
stored `userData.galaxyUserId` exists and differs from the newly derived one, log a warning naming
both values. That converts a silent playtime-URL regression into a visible log line on real
accounts.
</decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gogdl subprocess stdout -> backend | `user_id` originates in gogdl's parsed JSON and is interpolated into a URL path |
| api.gog.com -> backend | untrusted response body is projected into a persisted config record |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-Q34-01 | Tampering | URL construction in `getUserDetails()` | mitigate | Wrap the interpolated id in `encodeURIComponent(userId)` so a malformed `user_id` cannot append path segments or a query string to `api.gog.com/users/` (Task 1 step 3) |
| T-Q34-02 | Information disclosure | persisted `userData` record | mitigate | Store an explicit `{userId, username, galaxyUserId}` projection instead of `response.data`; `email`, friends list and wallet balance are no longer typed, fetched, or persisted -- strictly less PII at rest than the `delete data.email` scrub this replaces |
| T-Q34-03 | Spoofing | response body drives the displayed identity | accept | The response is fetched over TLS with the account's own bearer token and only feeds a display name; `galaxyUserId` is NOT taken from the response body but from the credential, so a manipulated body cannot redirect playtime posts to another user's session URL |
| T-Q34-SC | Tampering | package installs | n/a | This task installs no packages -- `axios` and all types are already present |
</threat_model>
