# Quick Task 260821-o34: Switch the GOG user API off embed.gog.com Summary

**Repointed `GOGUser.getUserDetails()` from `embed.gog.com/userData.json` (which embeds the account's entire wishlist and fails outright for large-wishlist accounts) to the small, fixed-size `api.gog.com/users/{user_id}` endpoint, and narrowed `UserData` to the three fields anything actually reads.**

## Performance

- **Duration:** ~10 min (first commit 17:28:21+12:00, last commit 17:37:36+12:00)
- **Tasks:** 2/2 completed
- **Files modified:** 3 (`src/backend/storeManagers/gog/user.ts`, `src/common/types/gog.ts`, `src/backend/storeManagers/gog/__tests__/user.test.ts`)

## Accomplishments

- `GOGUser.getUserDetails()` now fetches `https://api.gog.com/users/${encodeURIComponent(userId)}` -- a small, fixed-size document independent of wishlist size -- instead of `https://embed.gog.com/userData.json`, which errors outright for accounts with large wishlists instead of truncating, previously leaving those users apparently logged out.
- `UserData` narrowed from 20 fields (including `friends`, `whishlistedItems`, `checksum`, `walletBalancy`, `email`, etc.) to exactly `{ userId, username, galaxyUserId }` -- the only three fields any of the seven traced consumer sites read. `Currency` and `Friend`, referenced only by the old `UserData`, are deleted.
- `getUserDetails()`'s parameter changed from `accessToken?: string` to `credentials?: Pick<GOGCredentials, 'access_token' | 'user_id'>`, so `login()` threads through the `user_id` it already has from its own `gogdl auth --code` exchange -- net gogdl spawn count is unchanged (still exactly one `runRunnerCommand` call for `login()`).
- `galaxyUserId`/`userId` are sourced from the resolved credentials, never the untrusted response body (T-Q34-01/T-Q34-03) -- a manipulated response body can only change the displayed username, never redirect a playtime session URL.
- A D-3 drift guard: if a previously stored `userData.galaxyUserId` differs from the newly derived one, `logWarning` names both values before the new record is written (diagnostic only, never blocking).
- Test suite retargeted: both original token-reuse pins now assert the full `https://api.gog.com/users/{scripted user_id}` URL (proving the `user_id` was threaded through, not just the host), plus 4 new regression cases covering the headline fix, the missing-`user_id` guard, the missing-`username` guard, and the drift-guard warning.

## Decisions Made

All three locked decisions (D-1, D-2, D-3) from the plan were honored exactly as specified:
- **D-1:** `UserData` is a hard narrowing (not `Partial`/optional fields), so `tsc` rejects any dead read at build time rather than letting new code silently compile `userData.friends?.length` against data that can never arrive.
- **D-2:** Object param (`Pick<GOGCredentials, 'access_token' | 'user_id'>`) rather than two positional params, making "token without a user id" structurally unrepresentable.
- **D-3:** `galaxyUserId`/`userId` both derive from the credential's `user_id`, never the response body; a drift against a previously stored value is a warning, not a silent regression or a hard failure.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Blast-radius grep sweep false positive on a legitimate code comment**
- **Found during:** Final verification pass (running the plan's own mandated `<verification>` step 4)
- **Issue:** The `UserData` comment in `gog.ts` (committed in Task 1) named the old endpoint literally: `https://embed.gog.com/userData.json`. The plan's mandatory sweep `grep -rn 'embed\.gog\.com/userData\.json' src/ | grep -v '^ *//'` is supposed to exclude comment lines, but `grep -rn` prepends `path/to/file.ts:157:` before the line content, so the second grep's `^ *//` anchor (anchored to the start of the whole piped line, not the start of the source line) never matches a comment and the sweep reported a false-positive hit.
- **Fix:** Reworded the comment to describe the old endpoint ("GOG's old 'embed' userData endpoint") without repeating its literal URL string -- consistent with how the test file's own regression-coverage docstring (added in Task 2) already avoids the same string for the same reason.
- **Files modified:** `src/common/types/gog.ts`
- **Verification:** `grep -rn 'embed\.gog\.com/userData\.json' src/ | grep -v '^ *//'` now returns zero hits (exit 1, no match). `pnpm codecheck` re-run clean.
