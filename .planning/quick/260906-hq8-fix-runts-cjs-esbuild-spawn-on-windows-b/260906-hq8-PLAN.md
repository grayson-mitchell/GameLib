# Quick Task 260906-hq8 — runTs.cjs esbuild spawn on win32

<objective>
`meta/runTs.cjs` resolves `esbuild/bin/esbuild` and spawns it as the command
directly. On win32 that path is a `#!/usr/bin/env node` JS wrapper, which
`CreateProcess` cannot execute — libuv reports errno `-4058` (ENOENT). This
repo already has the correct shape in `meta/buildSidecarSea.ts`'s
`buildEsbuildArgv()`; the bootstrap that *compiles* that file never got it.

Purpose: unbreak every `node meta/runTs.cjs ...` script on Windows — **23** of
them (counted from `package.json` on 2026-09-06; the brief estimated 18),
including `build:decompress-worker-dev`, which `pnpm tauri:dev` runs.

Output: the win32 branch, a corrected comment, and the first platform coverage
`meta/__tests__/runTs.test.ts` has ever had.
</objective>

M1 + M2 together establish the mechanism without a Windows box: the installer
skips the hardlink on win32, so the shipped shebang JS shim survives there.
M3 establishes the converse, and is why the non-win32 branch must NOT route
through `process.execPath` (a Mach-O header is not parseable JS).

**NOT confirmed: that this mechanism is what the reporting machine actually
hit.** The planner cannot reach that Windows box. `errno 4058` is the generic
ENOENT-from-`CreateProcess`; it does not name the file. Live alternative
causes, none excluded:

- a different `spawn` inside `meta/downloadHelperBinaries.ts` itself
- `node` not resolvable in the shell pnpm used
- Defender/AV blocking the spawned image
- a partially materialised `node_modules/esbuild` on that machine

**Falsifiers.** All three require the Windows box and are therefore
OUTSTANDING HUMAN STEPS, not gates in this plan:

- **F1** — on the Windows box, print the first bytes of the resolved esbuild
  bin (the command in the todo Task 3 files). If it does **not** start with a
  `#!` shebang, the diagnosis is wrong for that machine.
- **F2** — after this fix ships, `pnpm download-helper-binaries` on that box

export function buildEsbuildArgv(
  platform: NodeJS.Platform = process.platform
): { command: string; args: string[] } {
  const esbuildCli = resolveEsbuildCli()
