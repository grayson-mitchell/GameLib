<objective>
Close todo `.planning/todos/pending/2026-11-11-66.3-win32-known-folder-sync-fallback.md` through its
outcome (a). Retire the win32 sync fallback in `src/backend/sidecar/pathShim.ts`, where on win32
`getPath('desktop'|'documents')` returns `join(homedir(), 'Desktop'|'Documents')`, so that no win32
caller depends on a guessed folder any more.

Why (a) and not (b): the orchestrator gathered live evidence on the operator's Windows 11 box on
2026-11-11.
- `Test-Path <profile>\Desktop` returned False and `Test-Path <profile>\Documents` returned True.
- `[Environment]::GetFolderPath('Desktop')` returned `<profile>\OneDrive\Desktop` and `'MyDocuments'`
  returned `<profile>\OneDrive\Documents`.

So on that host the Desktop fallback names a folder that does not exist, and a shortcut write fails.
The Documents fallback names a folder that exists but is the wrong one, so GOG native save sync would
silently read and write the wrong directory. Outcome (b), "the fallback is usable", is false here.

Principle: **no guessed folder on win32.** When the registry lookup fails, each caller goes without the
folder and says so loudly.
- shortcuts: the Desktop .lnk is recorded as not written.
- save sync: the locations that need `<?DOCUMENTS?>` are left out.

Neither caller substitutes a path.

The census was verified while planning. Only two runtime sites ever reach `getPath('desktop'|'documents')`:
- `shortcuts.ts` `shortcutFiles`: the linux arm, plus the win32 arm's fallback.
- `save_sync.ts` `getDefaultGogSavePaths`: the native arm.

No IPC channel forwards a dynamic `getPath(name)`.

Output: the code and tests described below, docs that match the code, and the todo moved to
`completed/` with a resolution.
</objective>
