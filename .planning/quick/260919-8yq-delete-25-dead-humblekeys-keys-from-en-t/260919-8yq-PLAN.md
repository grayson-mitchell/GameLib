1. **Round-tripping the catalogue.** `public/locales/` is in `.prettierignore` (line 5),
   so these files are not prettier-normalised and each locale owns its key order and
   spacing. A `json.load` → `json.dump` reformats the file and buries the real change.
   *Handled:* line-in-place deletion, then re-parse as the check.
   (A byte-fidelity probe does show this particular file round-trips exactly at
   `indent=4, ensure_ascii=False, trailing newline` — recorded as a fact, not relied on.)
2. **The 47-vs-49 population trap and the `da`/`id`/`nl` trailing-comma trap.**
   Both are *disarmed here*: no locale carries any of these keys, so this touches exactly
   one file. Asserting "47 files changed" would be asserting a false count.
3. **D-05 churn guard is unstaged-only.** `meta/i18nCatalogChurnGuard.ts` runs
   `git diff --name-only -- public/locales` with **no `--cached`** (re-confirmed today).
   So this edit makes the guard's `live tree` test RED while unstaged and GREEN once
   staged. *Handled:* stage before running the Meta suite; a red before staging is the
   guard working, not a defect. The test's own comment claims it bites "staged or
   unstaged" — the comment is wrong about its own command; do not trust it.
4. **Do NOT regenerate the presence baseline.** It is scoped to `namespace: gamelib` and
   never tracked a `translation`-namespace key, so this deletion owes no regeneration and
   can produce no drift. Its own `reason` string calls it "a RECORD of a known gap, not a
   permission to grow it".
5. **A green gate proves nothing about this todo.** `lintTranslations` reads only the
   `gamelib` namespace (`FORK_OWNED_NAMESPACES = ['gamelib']`), so it is green and blind
   to everything here. It is run below as a *no-regression* check, never as evidence.
