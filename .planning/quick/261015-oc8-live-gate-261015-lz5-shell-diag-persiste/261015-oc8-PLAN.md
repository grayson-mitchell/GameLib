# Quick Task 261015-oc8: live-gate 261015-lz5's shell_diag persistence on a packaged launch

## Why this is orchestrator-run, inline

A live gate launches a real `.app` through LaunchServices, drives a real window with CGEvent
clicks and keystrokes, and reads an OS-level fact (`lsof` on the process's fd 2) that no
subagent round-trip adds anything to. Prior gates in this repo (`261015-n5k`, 50-UAT Items
3/16) ran the rig from the orchestrating session; this plan is written by the session that ran
it, before the record is closed, so the arms and pass bars are stated ahead of the verdict.

## Locked decisions (from the todo's own text and the repo's precedent)

- **The build is `pnpm tauri:dev:packaged`** (`tauri build --debug`), the same configuration the
  original todo's `found_by` field used. A `--debug` bundle runs the dev sidecar out of the
  source tree (`tauri-dev-packaged-ships-a-stale-sea-sidecar`); that is irrelevant here because
  the writer under test is the Rust shell, which IS the bundled binary.
- **The `.app` is recovered from the DMG and tied to `target/debug/gamelib-shell` by sha256**,
  never trusted by path or mtime (`tauri-build-deletes-the-app-after-bundling-the-dmg`).
- **Launch is `open -n <app>`**, so the process is a LaunchServices child with no terminal.
  Running `Contents/MacOS/gamelib-shell` from a shell would hand it a real stderr and measure
  nothing.
- **Pass bar is the todo's own:** the literal appears in `gamelib-shell.log` (NOT `gamelib.log`)
  prefixed `{epoch} pid={pid} `, under the pid `open` produced, for the cheaper of the two
  literals (`didFinishNavigation succeeded`). The launcher-scheme literal (D-14) is attempted
  but not required.
- **Exit path is exercised**: the todo explicitly doubts "that the file write survives whatever
  process-exit path a packaged app takes", so the line is re-read after a Cmd+Q quit.
