<objective>
Close the pending todo `.planning/todos/pending/2026-09-30-planning-frontmatter-gate-crashes-on-windows-cp1252.md`: on Windows, `pnpm planning-gates` crashes unless the UTF-8 mode env var is set.

Purpose: a planning gate that crashes instead of reporting is not a gate. On this machine the frontmatter gate has crashed on every plain run since at least quick 260930-iws. Every session since then has had to prefix the command with an env var, and doing that masks the defect. The fix also has to be correct, not merely quiet. Planning-time measurement found that the obvious one-line fix is not enough:

- **The node pipe corrupts text silently.** `subprocess.run(..., text=True)` with no `encoding=` uses the ANSI code page (cp1252) to encode stdin and to decode stdout. That is not only a crash risk:
  - Any non-ASCII character that cp1252 CAN encode (an em-dash becomes byte 0x97) reaches node as invalid UTF-8 and turns into U+FFFD.
  - Node's UTF-8 JSON reply is mojibaked on the way back.
  - The gate has been vouching for text it never saw exactly.
- **js-yaml's error snippets make the naive fix crash in a new place.** The snippets render a TAB as U+2192 (`→`). The gate prints those messages to stdout, and in the runner that stdout is a cp1252 pipe. Measured in a scratch simulation, fixing ONLY the subprocess encoding moves the crash into the gate's own self-test, at the `tab-indented mapping entry` case, on every run. Before the fix it only "worked" because the mojibake happened to be cp1252-encodable.
- **The node side splits multi-byte characters at stdin chunk boundaries.** `s += d` converts each stdin Buffer chunk to a string independently. A multi-byte character split across a chunk (about 64 KiB) becomes U+FFFD. A synthetic payload of 100000 x U+2192 came back with 5 U+FFFD, measured twice; with `setEncoding("utf8")` it came back with 0. This is armed but not currently firing. Two real ledger frontmatters span several chunks (`35-VERIFICATION.md` is 116352 bytes and `38-VERIFICATION.md` is 199709 bytes). Both came back with 0 U+FFFD today, measured twice, because the chunk boundaries happen to land on ASCII.

Output: a three-part fix in `.planning/planning-frontmatter-gate.py`, two self-test transport pins, a committed ablation harness, and the todo closed to `completed/`. The runner is deliberately left unchanged (see the audit in Task 3).
</objective>
