<objective>
A `keyring_get` timeout or a Keychain Deny is currently indistinguishable from "nothing stored":
`SidecarKeyringSlotStore.getToken()` collapses both to `''`. `SteamUser.ensureConnected()` then logs
`Steam: logged in but no stored refresh token — cannot reconnect`, the user reasonably concludes they
are signed out, signs out and back in, and `clearToken()` destroys a perfectly good refresh token.
Observed ratio in `~/Library/Logs/GameLib/gamelib.log*` for the real `steam-refresh-token` slot:
**9 read failures to 1 success** — the failure is the normal case.

Purpose: make `present` / `absent` / `unreadable` three distinct states so a transient read failure
can never masquerade as a signed-out state, and so the 120s failure memo rate-limits the Keychain
prompt without ever answering "absent" on behalf of a read that never completed.

Output: an additive `TokenReadOutcome` contract on the shared `TokenStore` seam, a `readToken()`
primitive on the keyring slot store, an `ensureConnected()` that branches on it, and regression tests
covering all four required guarantees.
</objective>

```typescript
/** Why a read could not be completed. Mirrors classifyKeyringFailure()'s
 *  existing two-way split in keyringTokenStore.ts — do not invent a third. */
export type TokenUnreadableReason = 'timeout' | 'unavailable'

export type TokenReadOutcome =
  | { status: 'present'; token: string }
  | { status: 'absent' }
  | { status: 'unreadable'; reason: TokenUnreadableReason }

export interface TokenStore {
  isAvailable(): Promise<boolean>
  getToken(): Promise<string>
  setToken(token: string): Promise<void>
  clearToken(): Promise<void>
  /** OPTIONAL, additive. Implemented only by stores whose read can FAIL as
   *  distinct from returning nothing. Absent on ElectronTokenStore and
   *  DevVaultTokenStore, which keep their existing '' semantics. */
  readToken?(): Promise<TokenReadOutcome>
}

/** The single entry point every caller that cares about the third state uses.
 *  Falls back to today's exact conflating semantics for stores without
 *  readToken() — which is what makes it a valid RED-proof harness in Task 2. */
export async function readTokenOutcome(store: TokenStore): Promise<TokenReadOutcome>
```
