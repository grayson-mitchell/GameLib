# Quick Task 260919-u23 — complete

## What shipped

One commit, `98a1586e6`, 98 files: 49 `gamelib.json` catalogs (`en` plus 48 locales), 48
`gamelib.mt.json` manifests, and `SideloadDialog/index.tsx`.

The `<Trans>` passed `key=` — React's reserved reconciliation prop, invisible to the component — so
the import hint never localised. It now passes `i18nKey` **and** an explicit `ns="gamelib"`. Both
are required: no `defaultNS` is configured, so i18next falls back to `translation`, and either
attribute alone still renders the English children.

Migration and fill shipped together deliberately. `en` gaining a key while 48 locales stay unfilled
is exactly the presence-baseline drift that fails CI hard — `comparePresenceBaseline` asserts the
live missing set equals `missing: {}`, and `missingPairs()` counts a key as missing when it is
`undefined` **or the empty string**.

## The design decision worth preserving: `{{doorLabel}}`

The English value interpolates the button name rather than hard-coding it, fed from
`tGamelib('installFlows.importDoorLabel')`. **The original defect existed *because* that label was
duplicated into 49 catalogs and then renamed.** Interpolating removes the recurrence rather than
the symptom: a future rename now updates every locale automatically instead of rotting.
`installFlows.importDoorLabel` already existed, correctly translated, in all 49 locales.

## The blocker, and why the tool was not patched

`meta/machineFillGamelib.ts:658` hard-codes `https://api.anthropic.com/v1/messages` with an
`x-api-key` header and **ignores `ANTHROPIC_BASE_URL`**. This environment sets `ANTHROPIC_BASE_URL`,
so its key is scoped to that gateway. Measured: HTTP 401 from the script for `de`, and HTTP 401
from an independent `curl` straight to `api.anthropic.com` with the same key. Not the transient
`fetch failed` that `260919-9gu` hit at 15/48 — an auth-scope mismatch.

Teaching the script to honour `ANTHROPIC_BASE_URL` was **refused**: that routes catalog content
through a different endpoint than the reviewed tool was built for, which is a policy decision about
where repo content is sent, not an implementation detail.

Re-running it via the session's `!` prefix was also tried and was **my error** — `!` executes in
this session's environment and inherits the same gateway-scoped credential, so it failed
identically. It is not an escape hatch to a different shell.

## How the 48 translations were produced instead

Authored in-session. **31 locales reused the existing human translation carried in the legacy
`gamepage.json` catalog** as read-only translation memory, which is what D-11 is for. Repairing
that memory was part of the work — the legacy copies were not clean:

| locale | damage in the legacy copy |
| ------ | ------------------------- |
| `ar`   | malformed closing tag — `<3>…<3>` instead of `</3>` |
| `de`   | no link markup at all; the `<3>` element was simply absent |
| `nl`   | garbled clause order, missing space after the link |
| `sk`   | half-untranslated, raw `"` instead of `&quot;` |
| `ta`   | truncated mid-sentence |
| `lt`   | doubled quoting — `„&quot;…&quot;“` |
| `pl`   | stray `.` immediately after `<br />` |

The other 17 were newly authored: 14 locales held an empty string, and `br`/`sl` had no copy at
all.

**Correcting the todo's own count while here:** it claimed 46 dead translated copies. 46 non-English
locales carried the key, but **14 held empty strings**, so the live translated population was 32 —
31 usable once `ta`'s truncation is excluded.

## Provenance — stated plainly because the manifest cannot express it

The operator chose in-session authorship over waiting for a credential, and chose stamping over
silence. Each locale's `gamelib.mt.json` now lists `sideload.import-hint.content` in `keys[]`, so a
future Weblate import cannot mislabel model output as a human translation.

**The known inaccuracy:** each manifest carries ONE global `model` field, still reading
`claude-sonnet-5`, and one `filledAt`, left unchanged. Both describe the earlier bulk run, not this
key, which was authored by Claude Opus 5. Stamping under a slightly wrong model name was judged the
lesser error against leaving model output unmarked; updating `filledAt` would have relabelled the
fill time of every other key in the file. Recorded in the commit message as well as here.
