# [QUICK-260926-k4t] Give `box.error.install.stalled` a singular default at the depot call site

## Context

`pnpm i18n` (i18next-parser) reported `Found same keys with different values:
gamelib:box.error.install.stalled`. The key has two `t()` call sites:

1. `src/backend/downloadmanager/utils.ts:284` — options form, declaring BOTH `defaultValue`
   (plural) and `defaultValue_one` (singular).
2. `src/backend/storeManagers/steam/depotErrors.ts:294` — three-arg form
   `t(key, 'plural default', { count })`, declaring `count` but only the PLURAL default.

Site 2 was added by `bed19006c`, the corrective from debug session
`depot-stall-bound-did-not-fire`, earlier the same day.

**Two framings were corrected before this task was written, and both corrections are load-bearing:**

- **There is NO locale drift.** The originating flag said "drifted values across locales". Measured
  across all 49 `public/locales/*/gamelib.json`: every one carries `stalled_one` AND
  `stalled_other`, zero absent. The 22 carrying additional `few`/`many`/`two`/`zero` forms are
  correct CLDR plural categories, not damage. The EN catalog matches site 1's defaults
  byte-for-byte.
- **The warning class is endemic, not new.** A full `pnpm i18n` run reports this warning for
  **eight** keys. Seven predate this work entirely (`gamepage:game.getting-install-size`,
  `translation:box.ok` ×2, `box.select.exe`, `box.shortcuts.title` ×3,
  `setting.eosOverlay.updating`, `settings.saves.not_supported`, `wine.manager.settings`). So the
  goal here is NOT "silence the parser" — that is unreachable by this change and was never the
  scope. The goal is to stop having added a ninth.

## Goal

Remove `gamelib:box.error.install.stalled` from the parser's collision set, without touching any
catalog and without disturbing the other seven.

## What is deliberately NOT claimed

- **No runtime behaviour changes.** The key is present in all 49 catalogs, so under an initialised
  i18next both defaults are inert — the catalog wins at both call sites today and after.
- **The degraded path is unchanged too.** An uninitialised i18next returns the SECOND argument
  regardless of what the options object holds, so the "1 minutes" wording in that path is not
  improved by this fix. Saying otherwise would overclaim.
- The only real consequence is catalog regeneration: without a singular default, a catalog
  regenerated from source would have the PLURAL sentence written into `stalled_one`.

## Tasks

### Task 1 — add `defaultValue_one` to the depot call site

Add `defaultValue_one` to the options object at `depotErrors.ts:294`, matching the EN catalog's
`stalled_one` byte-for-byte (em dash, and the word "the"). Comment it in situ with the mechanism
and with the two non-claims above, so the next reader does not mistake it for a runtime fix.

**Do NOT convert the call to the options-object form.** The bare-string second argument is a
deliberate, documented defense (`depotErrors.ts:286-292`): a stubbed/uninitialised i18next returns
its second argument, so a string degrades to a readable English sentence where an options object
would leak the object itself into `message`, which is typed `string`.
