<objective>
`meta/genI18nGateScope.ts` writes two artifacts unconditionally. One of them,
`meta/i18nGateScope.json`, is the input to the **blocking** hardcoded-string
i18n gate and is **hand-curated** (160 files; its `generatedBy` header records
"hand-edited (34.13 review CR-02(b), then A-02/A-03)"). The other,
`meta/i18nForkTouchedFiles.json`, was added by 34.13 review A-17 as the
CI-readable input to the staleness ratchet and is routine to regenerate.

A-17 therefore gave people a routine reason to run `pnpm gen-i18n-gate-scope`,
and doing so **silently widens the blocking gate from 160 to 178 files and
destroys the hand-edited provenance marker**. This has already cost real work:
34.13-08 had to remove two entries by hand rather than regenerate, and the
34.13 A-17 fix agent had to restore the file with `git show HEAD:... >`.

Purpose: make the routine path (`pnpm gen-i18n-gate-scope`) incapable of
touching the curated artifact, and make the deliberate path refuse loudly with
an actionable diff instead of clobbering.

Output: a flag-gated, provenance-guarded single write path plus a behavioural
gate that is RED-proven against today's generator on real bytes.
</objective>
