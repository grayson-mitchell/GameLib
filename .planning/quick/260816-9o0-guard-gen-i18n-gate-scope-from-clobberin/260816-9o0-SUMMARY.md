# Quick 260816-9o0: Guard gen-i18n-gate-scope from clobbering the curated scope Summary

`pnpm gen-i18n-gate-scope` no longer touches the hand-curated blocking-gate
input; the scope write is behind an explicit `--rewrite-scope` flag that
still refuses while the file's own `generatedBy` marker says a human curated
it, printing the exact 160 -> 178 / +18 diff it declined to apply.

## What changed

`meta/genI18nGateScope.ts` used to `writeFileSync` both artifacts
unconditionally. Now `writeArtifacts()` is the only place either artifact is
written, and it applies two independent gates to the scope snapshot: the CLI
flag, then the on-disk provenance marker.

- **`GENERATOR_PROVENANCE`** — one constant replacing both inline
  `'pnpm gen-i18n-gate-scope'` literals.
- **`parseCliFlags`** — recognises only `--rewrite-scope`; any other `--`
  token throws naming the offending token. A typo must not silently degrade
  into "don't write" and exit 0.
- **`readScopeProvenance`** — never throws; absent / unreadable / non-JSON /
  no-string-`generatedBy` all yield `null`.
- **`isHandCuratedProvenance`** — exact-match default-deny. `null` is *not*
  hand-curated (legitimate bootstrap); anything that is not exactly the
  generator marker *is*.
- **`writeArtifacts`** — always writes the fork-touched artifact; without the
  flag it does not open the scope file at all; with the flag it returns a
  populated `refusal` (provenance, counts, sorted added/removed) instead of
  writing.
- **`main()`** — now holds zero `writeFileSync` calls, prints an actionable
  `::error::` block on refusal and exits 1, and no longer claims to have
  written the scope file on a default run.
- **`package.json`** — added `gen-i18n-scope:rewrite` with the flag placed
  *after* the entry file, per `runTs.cjs`'s documented forwarding rule, so it
  never depends on pnpm's own arg forwarding.

## FINDING — the plan's RED (b) harness was defective and did NOT reproduce

Running the plan's protocol verbatim produced **not** a clobber but:

```
EmptyScopeError: i18n gate scope derivation yielded zero files ...
exit=1
```

**Root cause, measured:** the plan's premise was that `.redproof/` is a safe
sacrificial CWD "because the generator's output paths are CWD-relative
(`join('meta', ...)`)". That is true — but the generator's *input* is
CWD-relative too. `git diff --name-status <base> HEAD -- src/frontend` uses a
**CWD-relative pathspec**, so with CWD `.redproof/` it resolved to
`.redproof/src/frontend`, matched nothing, and returned 0 lines:

```
cd .redproof && git diff --name-status <base> HEAD -- src/frontend | wc -l
       0
```

The harness isolated the writes correctly but simultaneously neutered the
read, so the generator aborted at `buildScopeSnapshot` and never reached the
write it was supposed to be caught performing.

**Repair — harness only, known-bad input untouched.** The generator was left
byte-for-byte unmodified at HEAD. Only the CWD moved outside the repo, with
git pointed back at it by environment variable:

```
cd <scratch>/rp && GIT_DIR=<repo>/.git GIT_WORK_TREE=<repo> \
  node <repo>/meta/runTs.cjs --bundle --platform=node --target=node21 \
  <repo>/meta/genI18nGateScope.ts
```

This yields the full 335-line diff (identical to a repo-root run) while output
paths still land in the scratch dir. A note documenting this trap was added to
the module docblock so the next person reproducing a run does not lose the same
time.
