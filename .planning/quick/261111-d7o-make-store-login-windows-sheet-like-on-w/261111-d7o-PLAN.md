<objective>
On Windows and Linux, make the visible store login window behave like a sheet: owned by the main
window and modal to it. The user's scope is locked and this plan does not revisit it. The target
is the visible window that `rpc_humble_login_open` builds in `src-tauri/src/login_window/humble_open.rs`.
Off macOS that arm serves Epic, GOG, Amazon and Humble. The hidden reveal/clear windows the same
arm builds are out of scope, and so is everything compiled on macOS.

Purpose: today the login window floats free, centered on the screen. It gets lost behind main or
other apps, and main stays clickable underneath it. An owned, modal, parent-centered window gives
Windows and Linux the same behavior the macOS sheet already has, and the native title bar and close
button stay.

cfg-gated call sites in `humble_open.rs`, two `feat` commits, a baseline dir, and a SUMMARY that
lists the owed Windows live check and the Linux CI-only compile proof.
