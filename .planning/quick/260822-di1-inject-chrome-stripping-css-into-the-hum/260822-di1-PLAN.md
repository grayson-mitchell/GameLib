<decisions_recorded>
These are decisions this plan makes on the executor's behalf. Do not relitigate them; implement
them and carry the rationale into the code comments.

**D-1 — The CSS is exactly ONE rule.**
`footer.site-footer { display: none !important; }` and nothing else. The optional
`.base-main-wrapper` / `.inner-main-wrapper` spacing tighten from the task brief is DECLINED, on
record: (a) there is no measured baseline for those wrappers' current padding, so any override is
an unverifiable guess; (b) an `!important` padding override on a wrapper that hosts the
React-rendered form is exactly the class of change that shifts layout unpredictably; (c) removing
the footer alone already achieves the de-clutter goal, and adding a second rule later is a one-line
append to `HUMBLE_LOGIN_CHROME_CSS` with the drift pin already in place to keep both sides honest.

**D-2 — NO macOS cfg gate on the Tauri injection.** The two existing injections are
`#[cfg(target_os = "macos")]` because they substitute for macOS *sheet* chrome (a sheet renders no
title bar and no close button). This injection substitutes for nothing platform-specific — the
marketing footer is noise on Windows and Linux too — so it is injected unconditionally inside the
`if visible` block. Verified against the surrounding code: `humble_login_open`'s builder arm is not
itself cfg-gated, `builder` is already `mut`, and an ungated block introduces no
unused-function warning on any target (the existing zero-warnings bar holds).

**D-3 — Host gate runs BEFORE the idempotence flag.** Order inside the try is: top-frame guard ->
hostname suffix gate -> idempotence flag -> DOM work. This is a deliberate divergence from the
banner's flag-then-work order and it makes the inertness property strictly stronger: on
`accounts.google.com` (or any Epic/GOG host — `humble_login_open` is runner-agnostic and takes no
`runner` argument) the script touches nothing at all, not even a `window` property. That is the
same "a non-participating document leaves no state behind" discipline the top-frame guard already
encodes for subframes.

**D-4 — Keep the full `build()`/`ensure()`/readyState/MutationObserver shape.** The task brief
asks for an explicit judgement rather than a silent omission. It IS needed, for a reason that has
nothing to do with the page deleting our `<style>`: an `initialization_script` runs at
document-start, when `document.head` may not exist yet, so a bare `build()` would silently no-op
and the CSS would never apply for that document. The `document.readyState === 'loading'` ->
`document.onreadystatechange` arm is the cheap retry that closes that, and the debounced
`MutationObserver` — already the house pattern on this exact page for two other scripts — closes
the re-append case for free. Use `document.onreadystatechange` (a property assignment), NEVER
`addEventListener`, exactly as the banner does, so REQ-34.4.2-06 holds by construction.

**D-5 — Include the drift pin.** It stays cheap: the Rust side emits the CSS as a single
single-quoted JS literal on one `concat!` line, so extracting it is one regex and comparing it is
one `toBe`. `tauriShellSource.test.ts` already establishes reading `main.rs` as text from jest, and
jest is the only gate CI actually runs (CI runs no cargo step).
</decisions_recorded>
