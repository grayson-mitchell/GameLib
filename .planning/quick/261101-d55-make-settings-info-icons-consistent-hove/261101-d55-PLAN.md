  <files>src/frontend/components/UI/PopoverComponent/index.tsx, src/frontend/components/UI/PopoverComponent/__tests__/index.test.tsx</files>
  <behavior>
    - Dispatching a `keydown` Event with `key: 'Escape'` on the injected target calls `close('escape')` once
    - A `keydown` with any other key (e.g. 'Enter') does not call close
    - A `click` whose target the `isInside` predicate rejects calls `close('outside')`; a click it accepts does not call close
    - After the returned unbind function runs, neither Escape nor an outside click calls close
  </behavior>
  <action>
Write the test first (RED). Create `PopoverComponent/__tests__/index.test.tsx`. Mock `'../index.scss'` to `{}` the same way FieldLabel's test mocks css. Import `{ bindPopoverDismiss }` from `'../index'`. Use `new EventTarget()` as the fake document. Build key events as `Object.assign(new Event('keydown'), { key: 'Escape' })`, because Node has no KeyboardEvent global. Use `jest.fn()` for close, and use a predicate such as `(t) => t === insideMarker` for isInside. For click tests, call the predicate path by making `isInside` return true or false directly, since the event's target is the EventTarget itself. Cover the four behaviours above. Run it and confirm it fails (the helper does not exist yet).

Then implement (GREEN) in `PopoverComponent/index.tsx`:
- Export a named helper `bindPopoverDismiss(doc: EventTarget, isInside: (target: EventTarget | null) => boolean, close: (reason: 'escape' | 'outside') => void): () => void`. It adds a `click` listener (calls close('outside') when `!isInside(event.target)`) and a `keydown` listener (calls close('escape') when `(event as KeyboardEvent).key === 'Escape'`). It returns a function that removes both listeners. This keeps the existing outside-click behaviour and moves it into the helper.
- Replace the body of the `[open]` useEffect. When open, return `bindPopoverDismiss(document, (t) => !!wrapper.current?.contains(t as Node), onDismiss)`. When closed, return nothing; drop the `() => ''` no-op. `onDismiss` calls `setOpen(false)`. When the reason is `'escape'`, it also returns focus to the trigger: call `wrapper.current?.querySelector<HTMLElement>('button, [tabindex]')?.focus()`, so keyboard users are not dropped at `<body>`.
- Add `'aria-expanded': open` to the props passed through `React.cloneElement(item, ...)`, next to onClick and style, so assistive tech knows the state. The trigger is already keyboard-focusable because InfoBox iconOnly renders a native `<button type="button">`. Do not add tabIndex.
- Do not change the rendered markup or class names beyond this (`.popover-wrapper`, `.popover`, `id={item.props.id}`), because other popovers depend on them.
  </action>
