## Decisions Made
- **78px reserve stays exactly as-is (USER-LOCKED).** The plan's Task 3 checkpoint asks whether the frameless-ON 78px macOS traffic-light offset (tabs starting at x=78 instead of the panel gutter, only when frameless is ON) is acceptable. The user has already answered: **keep the 78px reserve.** This is not re-litigated here and Task 3's verification below still asks the user to *confirm the traffic lights don't overlap the tabs*, not to re-decide the offset itself.
- **`--navbar-height: 42px` is a literal value, not a `calc()` built from `--space-xs`/`--text-md`.** Duplicating the tab's own min-height formula in a second calc() would be the exact "hardcoded value that silently drifts from the token" defect `shellTokens.test.ts` exists to prevent — and the `em` units in that formula resolve against a *different* font-size context on `.NavShell__navbar` than on `.MuiTab-root`, so a shared token would actually compute the wrong number. `appShellLayout.test.ts`'s Test E is the drift guard instead (exactly-once + exact-value assertion).
