**F1 — The navbar is a bare flex row with NO gap and NO inline-start padding.**
`.NavShell__navbar` (`NavShell/index.scss:53-142`) declares `display: flex; align-items: flex-end`
and no `gap`, no `padding-inline-start`. Its three children in `NavShell/index.tsx:66-76` are, in
order: the wordmark `<img className="NavShell__wordmark">` (30x30, `index.scss:185-191`), `<NavTabs />`,
and `.NavShell__navRight`. **Deleting the `<img>` therefore moves `.NavTabs` to inline offset 0 with
no CSS change at all.** Do NOT add a `padding-inline-start` to the base `.NavShell__navbar` block —
see F4.

**F2 — At inline offset 0, the tab content already aligns with the tier-2 panel content.**
`.NavTabs .MuiTab-root` sets `padding: var(--space-xs) var(--space-md)` (`NavTabs/index.scss:157`).
`.NavShell__tier2 .NavItem` sets `padding: var(--space-xs) var(--tier2-row-padding-inline)`, and
`--tier2-row-padding-inline: var(--space-md)` (`NavItem/index.scss:15`, also re-declared at
`NavShell/index.scss:393`). Both are `var(--space-md)` = `1em` = 16px. So the tab's icon/label
starts at x=16 and the panel row's icon/label starts at x=16 — this is the "default left panel
starting point" the user asked for. It works today only by coincidence of two independent
declarations agreeing; Task 1 adds a gate so the coincidence becomes a contract.

**F3 — macOS conflict, and why it is NOT a blocker in the default configuration.**
`.App.macOverlayTitlebar .NavShell__navbar { padding-inline-start: var(--traffic-light-inset) }`
(`NavShell/index.scss:151-153`, 78px). That class is `App.tsx`'s `isMac && isFrameless` hook.
`src/backend/config.ts:367` ships `framelessWindow: false` by DEFAULT, so on a default macOS
install `.macOverlayTitlebar` is absent, there is a native title bar above the webview, and the
tabs land at x=0 exactly as requested. **When the user turns frameless ON, the tabs will start at
78px, not at the panel gutter** — that reserve is one of the two hard constraints in
`Skill("sketch-findings-gamelib")` ("No top-mounted bar starts at x=0") and is explicitly fenced
out of scope by this task's constraints. Keep it. The Task 3 checkpoint asks the user to look at
both states and decide whether the frameless-on offset is acceptable.

**F4 — `shellTokens.test.ts:137-143` forbids ANY `padding-inline-start` in the base
`.NavShell__navbar` block**, not just the traffic-light one. Since F1 means no base padding is
needed, that gate stays green and MUST NOT be edited. If you find yourself wanting to add a
`--navbar-inline-start` token, stop: it is unnecessary and it trips that gate.

**F5 — Vertical arithmetic for the 5px buffer.**
`* { box-sizing: border-box }` (`App.css:14-17`) and `.NavShell__navbar` carries
`border-bottom: 1px` inside its `height: var(--navbar-height)`. `.NavTabs .MuiTab-root` has
`min-height: calc((2 * var(--space-xs)) + 1.25em + 1px)` = 8 + 8 + 20 + 1 = **37px** at the 16px
root (`_typography.scss:30` sets `font-size: 16px`; `--text-md: calc(1rem)`), and `top: 1px`
(`NavTabs/index.scss:191`) pushes it down 1px. Tabs are bottom-aligned by the navbar's
`align-items: flex-end`.
  buffer = navbarHeight - 1 (border) - 37 (tab) + 1 (top offset)
  Today: 56 - 1 - 37 + 1 = **19px**. Target 5px => navbarHeight = **42px**.
`--navbar-height` is consumed in exactly ONE place (`NavShell/index.scss:55`) and is not pinned by
any test — `grep -rn "navbar-height" src/` returns only that declaration, that consumer, and two
prose mentions in `NavTabs/index.scss`.

**F6 — 42px does not clip anything else in the row.**
`WindowControls` shares `grid-area: navbar` with `align-self: start` and
`height: var(--overlay-controls-height)` = `env(titlebar-area-height, 39px)`
(`WindowControls/index.scss:12-25`, `index.scss:38`). 39 < 42, and the navbar sets no `overflow`,
so the Windows/Linux control cluster still fits. `.NavShell__navRight`'s DownloadsRing ring svg is
16x16 (`DownloadsRing/index.scss:56-57`).

**F7 — Test-side blast radius of removing the `<img>`.**
`grep -rn "wordmark\|GameLibIcon" src/` shows: `NavShell/index.tsx` (the import + the element —
both deleted here), one CSS rule (`NavShell/index.scss:185-191` — deleted here), several prose-only
comment mentions in `NavTabs/index.scss` / `appShellLayout.test.ts` / `GamesSettings/index.scss`
(leave them, they are historical incident records), and two `jest.mock('frontend/assets/gamelib-icon.png', ...)`
lines in `NavShell.test.tsx:29` and `destinationCoverage.test.tsx:86`. **Leave both mocks in place** —
a `jest.mock` for a module that is no longer imported is inert, and the PNG is still imported by
four other screens (`Login`, `ConsoleMode`, `SystemInfo/software.tsx`, `StoreLogos`), so the asset
itself stays. No test asserts the `<img>` exists; `NavShell.test.tsx:140-143` only asserts the
FRAGMENT has two children (navbar, tier2), which is unaffected.
