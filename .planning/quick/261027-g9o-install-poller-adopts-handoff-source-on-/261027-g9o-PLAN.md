<objective>
Fix the false "no manifest detected; user may have cancelled" warning logged after a successful native install into the GameLibSteam bottle (todo `.planning/todos/pending/2026-10-26-install-poller-false-cancel-warning-after-native-install.md`, 51-UAT item 22).

Root cause (confirmed): `resumeInterruptedSteamInstall` (library.ts ~535) starts a bare `startInstallPolling(appId)`, so the poll's source is `'native'`. Later, games.ts's finalize handoff (games.ts ~2308) calls `startInstallPolling(appId, { source: 'bottle', isNativeHandoff: true, skippedDepots })`. The existing-entry upgrade branch (library.ts ~2861, 260822-dkf D-02) adopts `isNativeHandoff` and `skippedDepots` but not `source`. `source` is a `const` captured by the setInterval closure (`pollInstallOnce(appId, source)`), so the poll keeps reading the native steamapps roots and never sees the StateFlags=4 manifest in the bottle root. Once `isNativeInstallInFlight(appId)` goes false, the GRACE_TICKS branch fires its warning and sends `gameStatusUpdate` `done`. The Luxor 3 control case started directly with source `bottle` and completed normally.

Purpose: the poll reads the root GameLib actually wrote the manifest into, so it completes through the 'installed' branch and the false cancel warning goes away.
Output: library.ts poller change plus regression tests in library.test.ts.
</objective>
