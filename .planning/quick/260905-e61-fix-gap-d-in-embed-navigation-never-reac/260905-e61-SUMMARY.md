# Quick Task 260905-e61 — Summary

## What was wrong

REQ-40-06's control inversion was half-built. Rust's `on_page_load` moved the history cursor
and **emitted nothing**; `RUST_STORE_EMBED_TAKE_NAV_EVENTS` was declared in the transport but
had **no dispatch arm**; the seam method threw a declared-unimplemented Error; and the renderer
had no poll. So an in-embed link click moved Rust's `can_go_back()` to `true` while the
renderer's stayed `false` forever — Back greyed out, host label frozen on the start URL's host.

Everything *between* those points — preload binding, `ipc.ts` type, `ipcMain.handle` arm — was
already correct and untouched.

## What changed

| `1a98652ca` | seam + transport | `takeNavEvents()` reaches the arm; `coerceNavEvents()` coerces per element; two defect-pinning tests inverted; stale prose corrected |
| `b4de6820a` | `useStoreEmbedHost.ts` | 250 ms drain poll, re-entrancy-guarded, cleaned up on unmount |
| `<records>` | inventory + census | stale "declared-unimplemented" prose corrected; counts unchanged |

**Option 1 (Drain)** over Option 2 (Push): the whole wire for Drain already existed and was
inert at exactly two points. Push would have needed a new event channel plus a subscription
shape with no sibling in this codebase, and would have left the shipped `takeNavEvents` rung of
the seam dead permanently.

Three design points worth keeping:

- **The queue lives inside `StoreEmbedState`**, behind the same one `Mutex`. An outboard queue
  would be a second source of truth for a cursor the struct already owns.
- **A suppressed push queues nothing.** That is the confirming `Finished` event of a
  back/forward/reload this process issued, whose caller already holds the identical state.
- **`coerceNavEvents` throws rather than resolving `[]`.** An empty array is this channel's
  normal healthy answer, so a coerced one would make a dead arm indistinguishable from an idle
  one forever. The fail-safe `[]` stays at the `ipcMain.handle` arm, after logging.

### The RED proof that matters most

Neutering the renderer drain turns properties 10 and 11 red **while 1–9 stay green**. That is
the todo's own diagnosis reproduced mechanically: the pre-existing suite drives every navigation
through a call the test itself makes and reads what that call returned, so it was structurally
incapable of seeing a navigation the *page* initiated. Coverage of each end is not coverage of
the boundary — the same lesson `storeEmbedWireContract.test.ts` was written for.

Two of the five Rust tests (suppressed-push, clear) stay green under their mutation because they
assert *emptiness*; they guard the no-duplicate and teardown properties rather than the enqueue.
Recorded rather than glossed.

### Tests that were green BECAUSE the defect was present

Two tests pinned the gap and were **inverted, not deleted**:

1. `storeEmbedFlows.test.ts` — the arm test asserted `resolves.toEqual([])` *on the
   declared-unimplemented throw*. Its property (the arm never rejects) is real and kept; only
   its driver changed, to a rejecting transport.
2. The `unimplemented-navigation-throws` describe block became a reachability assertion — the
   same migration plan 40-07 applied to the other four methods. Inverted twice now, deleted
   never.
