## Goal

Close GAP-D: after an in-embed link click, the renderer's `canGoBack`/`canGoForward`/`host`
must follow the Rust history stack. Today Rust's `on_page_load` mutates a Mutex and emits
nothing, so the chrome freezes at the START URL's host with Back permanently greyed.

## Chosen approach — Option 1 (Drain)

The todo offers two alternatives. **Drain** is chosen because the entire wire for it already
exists and is *inert only at two points*:

| Layer | Today | After |
|---|---|---|
| `sidecarTransport.ts` `RUST_STORE_EMBED_TAKE_NAV_EVENTS` | declared, unimported | imported |
| `main.rs` dispatch | **no arm** | `store_embed_take_nav_events` arm |
| `main.rs` `StoreEmbedState` | pushes history only | also enqueues a nav-state snapshot |
| `storeEmbedFlowRegistration.ts` `takeNavEvents()` | throws declared-unimplemented | drains + coerces |
| `useStoreEmbedHost.ts` | no poll | anchored poll |
| preload / `ipc.ts` / `ipcMain.handle` arm | **already correct** | untouched |

Option 2 (push an event to the renderer) would need a new event channel, a new subscription
shape with no sibling in this codebase, and would leave the already-shipped `takeNavEvents`
rung of the seam dead forever. Drain also keeps the poller anchored to a **survivor** (the
main webview's React hook) per the 013–015 rule — the embed handle dies with the embed, and
nothing in this design holds one.

The event snapshot is taken **inside `StoreEmbedState::push`**, after the cursor moves, so
`canGoBack`/`canGoForward` on the wire are the same cursor-derived values every other arm
reports. A queue outside the Mutex would be a second source of truth for the same cursor.

Suppressed pushes (the confirming `Finished` event of a back/forward/reload we ourselves
issued) enqueue **nothing** — the caller already received that state as the arm's return
value, and re-queueing it would make the renderer re-apply state it just applied.

## Tasks

### T1 — Rust: queue the nav state on push, and add the missing dispatch arm

- **files:** `src-tauri/src/main.rs`
- **action:**
  - Add `pending_nav_events: Vec<Value>` to `StoreEmbedState`, capped by a named
    `STORE_EMBED_NAV_EVENTS_CAP` (50, oldest-dropped — mirrors `LOGIN_WINDOW_EVENTS_CAP`
    and its T-34.4.1-09 rationale: a page navigating in a loop must not grow the queue
    between drains).
  - `push()` enqueues `store_embed_nav_state_json(self)` *after* mutating history/cursor,
    and only on a real (non-suppressed) push.
  - `clear()` empties the queue (D-21 teardown).
  - Add `take_nav_events()` — drains and returns the queued values.
  - Add a `store_embed_take_nav_events` arm to `dispatch_rust_channel`, macOS-gated with
    the same legible non-macOS error every sibling store-embed arm uses.
  - `store_embed_nav_state_json` must move above `StoreEmbedState`'s `impl` or be callable
    from it — resolve by having `push` call the free function (it already takes `&StoreEmbedState`;
    borrow-checker: build the snapshot after the mutation completes, from `&*self`).
- **verify:** `cargo test` — new unit tests below, plus the 7 existing cursor tests stay green.
- **done:** a `store_embed_take_nav_events` dispatch arm exists and drains a queue that
  `push` fills.

**New Rust tests (each must fail against today's code):**
1. `push` enqueues one event carrying url/host/canGoBack/canGoForward derived from the cursor.
2. A suppressed push (post-`go_back`) enqueues nothing.
3. `take_nav_events` drains — a second call returns empty.
4. The cap holds at 50 with oldest-dropped.
5. `clear()` empties the queue.

## must_haves

**truths**
- After an in-embed page load, the renderer's `canGoBack` and `host` follow the Rust cursor.
- A dead `store_embed_take_nav_events` channel is distinguishable from an idle one (throws,
  never resolves a plausible `[]` from the seam).
- The queue is bounded; a navigation loop cannot grow it without bound between drains.
- Nothing added holds a handle that dies with the embed.

**artifacts**
- `store_embed_take_nav_events` dispatch arm in `src-tauri/src/main.rs`
- `takeNavEvents()` implementation in `storeEmbedFlowRegistration.ts`
- poll effect in `useStoreEmbedHost.ts`
- ≥5 new Rust unit tests, ≥3 new/inverted TS seam tests, ≥1 renderer test proven RED first
