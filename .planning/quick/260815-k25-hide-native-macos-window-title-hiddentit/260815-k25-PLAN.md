**F1 — `setTitleBarStyle('overlay')` does NOT hide the title. This was the wrong assumption.**
In `tauri-runtime-wry-2.11.4`, `TitleBarStyle::Overlay` sets ONLY `titlebar_transparent(true)` +
`fullsize_content_view(true)` — at the creation path (`src/lib.rs:1211-1214`) AND at the runtime
`SetTitleBarStyle` message handler (`src/lib.rs:3653-3656`). Neither path touches title visibility.
So the frameless toggle makes the title bar TRANSPARENT and lets the webview extend under it, while
AppKit keeps painting "GameLib" on top. That is the whole symptom.

**F2 — Title visibility is an INDEPENDENT, CREATION-ONLY knob.**
`hidden_title(bool)` -> `with_title_hidden` (`tauri-runtime-wry-2.11.4/src/lib.rs:1233-1234`) ->
tao applies `ns_window.setTitleVisibility(NSWindowTitleVisibility::Hidden)` at
`tao-0.35.3/src/platform_impl/macos/window.rs:269-271`. `WindowMessage` in
`tauri-runtime-wry-2.11.4/src/lib.rs` has `SetTitle(String)` (line 1435) and
`SetTitleBarStyle` (line 1471) but **no title-visibility variant** — there is no runtime setter.
That is exactly WHY this is the right fix: applied once at window creation, it is structurally
immune to every later frameless toggle, `setDecorations` call and `setTitleBarStyle` call.

**F3 — The config key, and why `title` and `hiddenTitle` are orthogonal.**
`tauri-utils-2.9.3/src/config.rs:2066-2068` declares
`/// If true, sets the window title to be hidden on macOS.` `pub hidden_title: bool`, with
`#[serde(default, alias = "hidden-title")]`. The struct carries
`#[serde(rename_all = "camelCase", deny_unknown_fields)]` (`config.rs:1916-1917`), so the JSON key
is **`"hiddenTitle"`** and it defaults to `false` (`config.rs:2333`).
On macOS, `setTitleVisibility(Hidden)` suppresses only the DRAWN text; `NSWindow.title` keeps its
string. Mission Control, the Window menu, Cmd-Tab and VoiceOver all read the string, not the
drawing. This is precisely the property the user's chosen option depends on.

**F4 — `deny_unknown_fields` changes what each gate is actually worth. Read this before writing
the tests.**
Because of `deny_unknown_fields`, a MISSPELLED key (`"hiddentitle"`, `"hidden_title"`) is a HARD
build failure — `cargo check` is a genuine spelling gate here. This is the opposite of the
`titleBarStyle` situation this test file's existing docstring describes, where a bad *value*
silently falls back to `Visible`. What `cargo check` can NOT catch is the *value*: `"hiddenTitle":
false` compiles perfectly and does nothing. So the division of labour is:
  - `cargo check` owns key spelling;
  - the jest gate owns `hiddenTitle === true` and `title === "GameLib"`;
  - the human checkpoint owns "is the pixel actually gone".
Say this in the test docstring; do not let a future reader think jest covers spelling.

**F5 — No generated artifact needs regenerating. Verified.**
`src-tauri/gen/schemas/` holds ONLY the capability/ACL schemas (`acl-manifests.json`,
`capabilities.json`, `desktop-schema.json`, `macOS-schema.json`). It is gitignored
(`src-tauri/.gitignore:5:/gen/schemas`), `git ls-files src-tauri/gen` returns nothing, and it is
rewritten by `tauri-build` on every build. Window-config keys are not permissions and do not appear
in it. `tauri.conf.json`'s `"$schema"` is the REMOTE `https://schema.tauri.app/config/2` — an
editor/IDE aid, not a local artifact. **No regeneration step, and nothing to commit under `gen/`.**

**F6 — Windows and Linux are provably unaffected, but not for the reason you might assume.**
The struct field itself is NOT cfg-gated — it deserializes on every target, so adding the key
cannot break the Windows or Linux build. The APPLICATION is what is gated:
`WindowBuilderWrapper::with_config` calls `.hidden_title(config.hidden_title)` inside a
`#[cfg(target_os = "macos")] { ... }` block at `tauri-runtime-wry-2.11.4/src/lib.rs:865-878`.
On Windows/Linux the value is parsed and then never read — a compile-time no-op. Record the nuance
(field not gated, consumption gated); "the config key is cfg-gated" is the imprecise version and
would imply a parse failure that does not happen.

**F7 — The `main` window is config-created, so the key reaches it. Login windows are NOT, so it
cannot leak to them.**
`grep -n MAIN_WINDOW_LABEL src-tauri/src/main.rs | grep -i builder` returns NOTHING — nothing in
the Rust shell builds a window labelled `main`; it comes from `app.windows[0]` via
`WebviewWindowBuilder::from_config` (`tauri-2.11.x/src/webview/webview_window.rs:150`), which is
the ONLY path that reads a `WindowConfig`. Every login window is built with
`WebviewWindowBuilder::new` (`main.rs:3628`, `4633`, `4700`) or the pristine webview-less
`tauri::WindowBuilder::new` (`main.rs:2023`), both of which start from `WindowBuilderWrapper::new()`
and never touch the config. Login windows therefore keep `hidden_title: false` and keep rendering
the origin titles `main.rs` deliberately sets at lines 3668 / 3792 / 4010. Do not "helpfully"
propagate the key.

**F8 — Test-side blast radius: nothing asserts the window object's key SET.**
`grep -rn "toEqual|Object.keys|toMatchObject|toMatchSnapshot" src/backend/__tests__/tauriConf.test.ts
src/backend/__tests__/tauriWindowConfig.test.ts` finds only `capabilities.windows`, `bundle.targets`,
`bundle.externalBin`, `bundle.icon` and an icon-header check. No exhaustive shape assertion exists
on `app.windows[0]`, so adding a key breaks nothing. `tauriConf.test.ts` has NO `title` assertion at
all today — the `title: "GameLib"` pin added here is genuinely new coverage, not a duplicate.

**F9 — The existing SANITY idiom in this exact file. Reuse it verbatim; do not invent a new one.**
`tauriWindowConfig.test.ts:88-95` runs the identical `findWindowByLabel`-then-assert helper against
an in-file bad fixture and wraps it in `expect(() => expect(...)).toThrow()`. That is this repo's
standing "a gate must be proven to FAIL against a known-bad input" discipline expressed for
JSON-shape gates (the `shellTokens.test.ts` / `appShellLayout.test.ts` form is the source-text
variant of the same rule). Note also that these gates are `JSON.parse` assertions against a
DIFFERENT file, so — unlike this repo's source-text greps — a docstring mentioning `hiddenTitle`
or `"GameLib"` cannot make them pass vacuously. No comment-stripping is needed or wanted here.

**F10 — Backend jest project name is `Backend`** (`src/backend/jest.config.js`, `displayName`).
Frontend suites use `--selectProjects Frontend`; this file needs `--selectProjects Backend`.
