The pre-Phase-52 017 manifest (`git show 7ed535984:meta/sdk/isteamclient017.manifest.json`) is the reference shape: manifest `mode: "stub"`; CreateSteamPipe and ConnectToGlobalUser carry `mode: "wire", helperFallback: 1`; no other method has `mode`, `helperFlat` or param `kind`.
- In `emitVtableStub` (gen_vtables.ts ~5780-5900), the order is: shimLocal, then the SteamClient version lookup (stub mode gives `emitSteamClientVersionLookupStub`: resolve, then `x64_null_object_for_version`), then helperFallback (`return <literal>` with a FALLBACK note), then `emitStubBody` (`return 0` / `return;` with a STUB note). These are the same values as `STEAM_CLIENT_OFF_PATH_VALUES` / OFFPATH today. The only intended deltas are the diagnostic note kind (OFFPATH becomes FALLBACK or STUB, logged by the helper's STUBCALL line) and the stub signatures, which use `uint32_t dummyN` params; that is harmless on Win64 because the caller cleans up.
- `SHIM64_SERVED_INTERFACE_VERSIONS` in `src/backend/storeManagers/steam/bridge/shimCoverage.ts` (~238-327) is HAND-maintained and already labels 020/021 `'wire'` despite their stub manifests. Do NOT change those modes; only fix the stale Phase 52 comment.
- `GAMELIB_STUBCALL_KIND_OFFPATH 2` and the helper's `k_stubcall_kind[4] = {"stub","fallback","offpath","null"}` (bridge_helper.c ~1865) are protocol vocabulary. KIND_NULL must stay 3. Keep both the define and the helper table. The Resolution notes that nothing emits kind 2 any more.
