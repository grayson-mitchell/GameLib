# Quick 261012-97a — name the resource the parser is waiting on

## Task 1 — probe instrumentation (`.planning/spikes/024-…/app/src/main.rs`, `probe_script` only)

- `inflight`: resource entries with `responseEnd === 0` (the todo's prescription — expected
  EMPTY, because Resource Timing adds an entry only when a fetch finishes; kept so the README can
  say so from a measurement, not a reading of the spec).
- `pendingScripts` / `pendingStyles`: every `script[src]` and `link[rel=stylesheet]` in the
  document whose URL has NO resource-timing entry yet — the set-difference is the real in-flight
  list. Flags `[async]` / `[defer]` / `[type]` so a parser-blocking script is told from one that
  is not.
- `tail`: last 500 chars of `documentElement.outerHTML`; `lastEl`: the deepest last element —
  where the parser is actually sitting.
- `nav`: add `responseEnd`, `transferSize`, `encodedBodySize`, `decodedBodySize` — `responseEnd
  === 0` means the main document is still streaming (network stall); `> 0` with `docLen` short
  means the document is in and the parser is blocked (resource stall).
- `counts` (resource entries / scripts / styles — a `res` of 250 flags the timing buffer cap),
  `sw` (service-worker controller URL), `currentScript` (null while parser-blocked).
- verify: `cargo build`; prettier N/A (`.rs` under `.planning/spikes` is not governed).
