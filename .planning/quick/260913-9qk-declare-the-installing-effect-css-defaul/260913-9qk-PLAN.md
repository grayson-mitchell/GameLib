# Quick Task 260913-9qk — declare `--installing-effect`, drain the sweep allowlist

Closes `.planning/todos/pending/2026-09-12-installing-effect-grayscale-amount-is-unrecoverable-needs-a-design-decision.md`.

## The todo's premise is false

The todo says `--installing-effect` "is declared nowhere" and that the grayscale amount
"is unrecoverable from history", so it needs a **design decision** (`ready: human`).

Both claims are wrong. The token **is** declared — at runtime, in TSX:

```tsx
// GameCard/index.tsx:190
const installingGrayscale = isInstalling ? `${125 - getProgress(progress)}%` : '100%'

// GameCard/index.tsx:558-560, on the <Link> that wraps both images
style={{ '--installing-effect': installingGrayscale } as CSSProperties}
```

So non-installed library tiles render **fully greyscale today** (`100%`), and while a game
is installing the tile colours in progressively as the download advances. The todo's claim
that "every non-installed tile in the library grid renders in full colour" is the opposite
of what ships.

**Why two instruments both missed it — the same off-by-one-character:**

| instrument                                         | pattern                  | source text                | result |
| -------------------------------------------------- | ------------------------ | -------------------------- | ------ |
| todo's `git log -S "--installing-effect:"`          | `--installing-effect:`   | `'--installing-effect':`   | 0 hits |
| gate's `DECLARATION` regex (`(--[\w-]+)\s*:`)       | name then `:`            | name then `'` then `:`     | no match |

The quote sits between the name and the colon. `git log -S "--installing-effect':" --all`
finds `b6ce8bdf9` (upstream Heroic #869, spatial-navigation refactor) — the value is fully
recoverable. This repo had already written the truth down: `34.10-F02-DIAGNOSIS.md:161`
cites `--installing-effect` as a *working* inline-custom-property precedent while the todo
was calling it undefined.

## The fix: the in-repo pattern, 2-for-2

Three `.tsx` files set a custom property via an inline style object. Two declare a CSS-side
default for it; `GameCard` is the only one that does not:

| component      | runtime set (tsx)                       | CSS-side default              |
| -------------- | --------------------------------------- | ----------------------------- |
| `DownloadsRing`| `'--dl-progress': ${n}turn`             | `index.scss:25` `0turn` ✓     |
| `WineItem`     | `'--progress': ${n}%`                   | `index.css:15` `0%` ✓         |
| `GameCard`     | `'--installing-effect': 100% \| ${n}%`  | **missing** ← this task       |

## TRAP — verified, do NOT follow the todo's step 1

The todo prescribes declaring it in the base `body {}` block of `themes.scss`. **That would
turn the game-detail hero art fully greyscale.**

`GamePicture/index.tsx:39,48` renders `className={`gameImg ${className}`}` and
`className={`gameLogo`}` and **never** applies the `installed` class, so the consuming rule
`.gameImg:not(.installed)` matches there too. GamePicture is not inside a `.gameCard`, so it
inherits nothing from the `<Link>` — a `body`-level declaration would reach it and desaturate
the game page. Today that site resolves to an invalid `filter`, which degrades to `none`.

Scoping the declaration to the two card roots keeps GamePicture exactly as it is.

## Zero visual change — why

- `.gameCard` / `.gameListItem` are the two wrapper roots (`index.tsx:490`).
- The `<Link>` carrying the inline value is a **descendant** of that wrapper
  (`index.tsx:555-618`) and wraps both `imgClasses` (581) and `logoClasses` (589).
- A declaration on the wrapper is *inherited* into the Link's subtree; the Link's own inline
  declaration beats an inherited value. So every library image keeps taking the runtime value.
- The new default therefore only paints if the inline style is ever absent — and `100%` is
  exactly what the runtime emits in the non-installing case, so even then it agrees.
- GamePicture is out of scope of the selector entirely.

Do **not** declare it on `.gameImg:not(.installed)` itself: a declaration on the element
beats an *inherited* value, which would freeze the install-progress ramp.
