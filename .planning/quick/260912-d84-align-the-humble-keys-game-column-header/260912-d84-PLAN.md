## Established cause — DO NOT re-open the investigation

The todo's prescribed `tauri:dev` inspector run is obsolete. The cause was established
statically before this plan was written, from source plus the measurements already in the
todo.

`src/frontend/screens/Humble/Keys/index.css:220-226` declares the shared row/header
geometry on the combined `.humbleKeysColumnHeader, .humbleKeyRow` selector, including
`column-gap: var(--space-md)`.

- `--space-md` is `1em` (`src/frontend/styles/_spacing.scss:8`).
- An `em` length in a NON-`font-size` property resolves against the element's OWN computed
  font-size.
- `.humbleKeysColumnHeader` — the standalone typography block at `index.css:674` — sets
  `font-size: var(--text-xs)` = `1rem / 1.2^2` = **11.11px** at the 16px root
  (`src/frontend/styles/_typography.scss:29-33`).
- `.humbleKeyRow` sets no font-size and inherits **16px**.

So ONE declaration produces TWO gaps: 11.11px on the header, 16px on the rows. Track 1 is
6.5rem = 104px starting at x=220 for both, which is why the TYPE column measured a 0.0
offset — track 1 needs no gap. Track 2 therefore starts at 324 + 11.11 = 335.11 for the
header and 324 + 16 = 340 for the rows: a **4.89px** divergence, matching the measured
335.5 / 341.0 ink positions once each font's left side bearing is allowed for. The KEY
column is unaffected (0.5px measured) because the 20rem track is anchored off the
container's right edge, not off the gaps.

Every one of the todo's three "ruled out" findings is consistent with this cause and no
other.

Fix: `var(--space-md)` -> `var(--space-md-fixed)`. `--space-md-fixed` is
`calc(1 * var(--space-unit-fixed))` = `calc(1 * 16px)` (`_spacing.scss:12,17`) — exactly
what the rows already resolve to, so **the rows are pixel-unchanged** and only the header
moves right to meet them. This token is the established house instrument for exactly this
situation and is already used at `Humble/Keys/index.css:5`, plus `Library/index.css`,
`Discounts/index.css` and `StoreSearch/index.css`.
