## The fix is the file's idiom PLUS one call, and the extra call is MEASURED, not guessed

Four sites in `main.rs` already surface `main` with the same pair:

| Line | Site |
|---|---|
| `~6477-6478` | child-window attachment fallback |
| `~8783-8784` | `__GAMELIB_FOCUS__` single-instance socket handler |
| `~9126-9127` | tray menu `"show"` arm |
| `~9164-9165` | tray icon left-click handler |

All four are `let _ = window.show(); let _ = window.set_focus();`.
`open_about_window_from_tray` is the one window-surfacing site that omits both.

**`show()` + `set_focus()` alone is NOT sufficient for the minimized case.** Read from the vendored
runtime, not assumed — `tao-0.35.3/src/platform_impl/macos/window.rs`:

```
:677  pub fn set_focus(&self) {
:679    let is_minimized = self.ns_window.isMiniaturized();
:680    let is_visible   = self.ns_window.isVisible();
:681    if !is_minimized && is_visible { util::set_focus(&self.ns_window); }
```

`set_focus()` is a **hard no-op while the window is miniaturized**. Two more measured facts from the
same file:

- `:668-673` `set_visible(true)` is `make_key_and_order_front_sync` — **synchronous**. So `show()`
  before `set_focus()` is what makes `is_visible` true by the time `set_focus` tests it. The
  ordering is load-bearing, not cosmetic.
- `:1035-1050` `set_minimized(false)` early-returns when `isMiniaturized()` is already false, so
  calling `unminimize()` unconditionally is free on every non-minimized path.

**Therefore the fix is three calls, before the eval:**

```
let _ = window.unminimize();
let _ = window.show();
let _ = window.set_focus();
```

**Deliberate deviation, and it must be documented in the code comment:** this site uses three calls
where its four siblings use two. `grep -n "unminimize" src-tauri/src/main.rs` returns nothing today.
The four siblings have the same latent minimized-window gap — that is **observed, NOT fixed here**.
Do not widen scope to them; record the observation in the SUMMARY instead.

**Measured caveat that must NOT be smoothed over.** AppKit's `deminiaturize:` animates, so
`isMiniaturized()` may still read true when `set_focus()` runs one line later, and focus may still
not land in the minimized case even after this fix. `deminiaturize:` orders the window front itself,
so the user-visible symptom should still be gone — but "should" is why the minimized state is an
enumerated live criterion below rather than an assumed pass.
