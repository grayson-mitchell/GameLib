## Item 1 was a hard prerequisite, and this is the interesting part

Before `0fdbdac36`, widening the grep would have produced a gate that **could never hit**. A
successful `keyring_available` emitted no line at all, so an absence-assertion over
`issuing keyring_available` would have been vacuously true by construction — a false green, the
exact defect class this gate exists to avoid. Item 2 was not merely ordered after item 1; it was
unimplementable before it.

## Measured ground truth (2026-09-05, at 0fdbdac36)

**The todo's own remedy is too narrow.** It says a startup gate "must count `keyring_available` as
well as `keyring_get`". The prompt surface is **four** channels, not two — `setToken()`'s and
`clearToken()`'s own comments state it outright: *"a write is a real Keychain round trip and can
prompt"*, and *"a delete is a real Keychain round trip that can prompt. A 2026-08-14 session
observed TWO prompts during a single Steam sign-out."*

| Channel | Can prompt | Pre-invoke `(may prompt)` announcement | Post-invoke line |
|---|---|---|---|
| `keyring_get` | yes | yes | `ok` / `failed` |
| `keyring_available` | yes | yes, as of `0fdbdac36` | `ok` / `failed` |
| `keyring_set` | yes | **no** | `ok len=` / `failed` |
| `keyring_delete` | yes | **no** | `ok` / `failed` |

For an ABSENCE gate the post-invoke line is sufficient: a completed round trip always leaves one.
So the widened pattern keys on both the announcement and the outcome line, covering all four.

**Calibration, measured — not asserted.** Specimen generated FROM THE CODE (a throwaway jest run
capturing the real logger output, then deleted) rather than retyped from a display copy, and saved
as `260905-kd0-specimen-startup-probe.log`. The real 2026-08-17 pre-fix log
(`~/Library/Logs/GameLib/gamelib.run3.log`) is still present on this machine and was used as the
known-bad specimen.

| Pattern | code-generated specimen | real pre-fix log | humble-slot false hits |
|---|---|---|---|
| OLD (`getToken(): issuing keyring_get`) | **1** — misses the `keyring_available` line | 1 | 0 |
| WIDENED (full surface) | **4** | **2** | **0** |

The OLD pattern scoring 1 where the WIDENED scores 4 on the same file **demonstrates the hole
rather than arguing it**. The WIDENED pattern still hitting the real pre-fix log keeps the
calibration property intact: a later zero is meaningful, not a broken pattern. Zero humble-slot
hits confirms it stays slot-scoped, which Gate A requires (`humble-*` lines MAY be present).
