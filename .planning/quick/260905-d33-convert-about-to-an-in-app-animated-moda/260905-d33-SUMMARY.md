# Quick Task 260905-d33 — Summary

## What shipped

Settings → About opened a 420×380 capability-free Tauri `WebviewWindow` backed by the static
`public/about.html`, a page with its own hardcoded `#1a1a1a` / `#e6e6e6` / `#b3b3b3` palette that
could not participate in theming at all. It is now `components/UI/AboutDialog`, an in-app MUI
`Dialog` themed with `var(--*)` tokens.

The animation came for free. The 500ms directional Slide the todo asked for already lives inside
the shared `Dialog` primitive (`TransitionComponent={SlideUpTransition}` + `transitionDuration={500}`,
pinned by `dialogWindowChrome.test.ts`), so consuming the primitive delivered it with no new
animation code.

Deleted rather than orphaned: `public/about.html`, `tauriShowAboutWindow`, `showAboutWindowAsync`,
`resolveAboutVersion`, `ABOUT_VERSION_TIMEOUT_MS`, the orphaned `showAboutWindow` channel type in
`common/types/ipc.ts`, and `backend/utils.ts`'s already-dead Electron `app.showAboutPanel()` body.

## The thing that went wrong, stated plainly

**I authorised deleting `window.api.showAboutWindow` on a census that was wrong, and it shipped.**

The census grepped `src/` and concluded `SettingsPanel/index.tsx` was the only live caller. It is
not. The macOS tray's "About GameLib" item is implemented in Rust
(`open_about_window_from_tray`, `src-tauri/src/main.rs`) and reaches About by evaluating
`window.api?.showAboutWindow?.()` in the main window. Deleting the export made that menu item a
**live silent no-op** — the eval is optional-chained, so nothing threw and nothing logged, on
either side of the boundary.

Three things are worth recording about it:

- It is the **exact failure shape that function's own doc comment warns about**, two paragraphs
  above the eval. The warning was there; the census did not reach the file.
- It shipped in `bb560d51a` with **every gate green** — full frontend, preload, meta and backend
  suites, tsc, eslint, prettier and 8/8 planning gates. Nothing in the ordinary verification set
  can see a Rust-side `eval` of a JS name.
- It was caught by a follow-up reference sweep that widened the grep past `src/`, not by any test.

Fixed in `d92c888fb`: `showAboutWindow` is **kept as a name** and repointed. It now dispatches
`SHOW_ABOUT_DIALOG_EVENT` (`src/common/aboutDialogEvent.ts`), which `AboutDialogHost` — mounted
app-level in `App.tsx` beside the other app-wide dialogs — answers. App level, not inside
`SettingsPanel`, because a dialog owned by the tier-2 panel would not exist when the user is
anywhere else in the app, which is most of the time the tray is used. `SettingsPanel` went back to
its original one-line call and its original test; both were right all along.

`src/preload/__tests__/showAboutWindow.test.ts` now pins the seam explicitly, including the
"export exists at all" case, since its absence is the silent one.

## Decisions

- **D1 — the behind-content crossfade was NOT ported.** The todo asked for
  `screens/Login/index.scss:51-57`'s `transform`/`opacity` pair. That rule slides the *login
  page's own content* away behind its overlay. About opens from a tier-2 nav panel with no
  equivalent behind-content, so there was nothing to crossfade, and animating the app body on
  About-open would have been a new visual effect rather than a port of an existing one.
- **D2 — dialog state is app-level, via an event.** Revised mid-task from "local to SettingsPanel"
  once the tray caller surfaced. About has two entry points and only one of them is React.
- **D3 — the capability isolation boundary is deliberately dropped.** `about.html` was fail-closed
  by window label (`capabilities/default.json` scopes `"windows": ["main"]`) and took its version
  through a `?v=` query param *because* it had zero Tauri command access. In-app it inherits
  `main`'s capabilities. Impact is nil — the surface renders a version string and static text,
  makes no network call and holds no secret — but this is a real reduction in isolation and is
  recorded rather than skipped.
- **D4 — `ABOUT_VERSION_TIMEOUT_MS` deleted, after confirming its job.** The 1s race guarded
  *window construction* against a wedged sidecar. A dialog is on screen immediately, so the
  version fills in asynchronously — the same unbounded `getHeroicVersion()` call `HeroicVersion`
  and `ChangelogModal` already make.
- **D5 — todo item 2 was STALE.** No Electron divergence remained: Phase 35 plan 17 had collapsed
  the Electron branch, `src/backend/tray_icon.ts` no longer exists, and `utils.ts:247` was
  registered on no IPC channel. `IPC-PORT-INVENTORY.md` already recorded the channel as retired
  with Phase 35's window-chrome cluster, so the inventory needed no edit — confirmed by the gates,
  not assumed.

## Not anticipated by the todo

- `meta/assembleRendererDist.ts` listed `about.html` in a **fail-loud** static-copy set. Deleting
  the page would have thrown at build time. Removed there and in its test; `icon.png` stays,
  because `public/manifest.json` still references it.
- `src/backend/__tests__/aboutHtmlSource.test.ts` was a source gate over the deleted page — six
  cases erroring on read. Deleted with the page it guarded.
- Registering the new component in `meta/i18nGateScope.json` requires it to also be in
  `meta/i18nForkTouchedFiles.json` (scope must stay a subset), and cascaded into four pinned
  counts in `genI18nGateScope.test.ts`. Hand-edited surgically per the documented
  `260901-w9e` / `260902-qs4` precedent, never regenerated. Scope 169 → 171, fork-touched
  213 → 215, declared debt unchanged at 44. **Worth the cascade:** the blocking gate immediately
  caught a hardcoded `'GPL V3'` constant in the new component.
- One self-inflicted false RED: the first draft of the "no hardcoded colour" test grepped the
  component source for hex values and convicted itself, because the doc comment *names* the
  colours it exists to keep out. Retargeted at the stylesheet with comments stripped, plus a
  positive `var(--` assertion so it cannot pass vacuously.
