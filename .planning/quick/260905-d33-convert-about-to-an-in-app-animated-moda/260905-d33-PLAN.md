# Quick Task 260905-d33 — About becomes an in-app animated modal

## Goal

Replace the bare 420×380 OS `WebviewWindow` that Settings → About opens with an in-app MUI
`Dialog`, themed with `var(--*)` tokens, carrying the shared primitive's 500ms directional
Slide. Delete the OS-window path rather than orphaning it.

## Decisions

- **D1 — Behind-content crossfade is NOT ported.** The todo asked for `Login/index.scss:51-57`'s
  `transform`/`opacity` crossfade. That rule animates the *login page content* sliding away
  behind its overlay. About opens from a tier-2 nav panel; there is no behind-content to
  crossfade, and animating app content on About-open would be a new, unreviewed visual effect.
  The animation the todo actually wants — a 500ms Slide entrance — is already **inside** the
  shared `Dialog` primitive (`Dialog.tsx`, `TransitionComponent={SlideUpTransition}` +
  `transitionDuration={500}`, pinned by `dialogWindowChrome.test.ts:85`). Consuming the
  primitive delivers it with zero new animation code.
- **D2 — Dialog state is local to `SettingsPanel`.** `NavShell/index.tsx:70` mounts
  `<SettingsPanel />` for the active tier-2 tab; the About row is a plain `<button>` that does
  not navigate, so the panel stays mounted while the dialog is open. The heavier
  `ExternalLinkDialog` pattern (GlobalState + ContextProvider, `App.tsx:155`) exists because
  that dialog is triggered from several places — About is not, so it does not earn global state.
- **D3 — Capability isolation boundary is deliberately dropped.** `about.html` was fail-closed
  by window label (`src-tauri/capabilities/default.json` scopes `"windows": ["main"]`) and
  therefore had **zero** Tauri command access, which is why it received its version through a
  `?v=` query param instead of IPC. In-app it inherits `main`'s capabilities. Practical impact
  is nil — the surface renders a version string and static text — but the boundary is being
  removed, not preserved, and that is recorded here rather than discovered later.
- **D4 — `ABOUT_VERSION_TIMEOUT_MS` (1s) is deleted.** Its stated job
  (`tauriChildWindows.ts:145-165`) was to stop a wedged sidecar delaying *window construction*
  for up to `INVOKE_TIMEOUT` (60s) — the menu item appeared dead. A Dialog renders immediately
  and fills the version in asynchronously, so the race has no job. Precedent for the async fill:
  `HeroicVersion/index.tsx:47` and `ChangelogModal/index.tsx:22` both call
  `window.api.getHeroicVersion()` unbounded.
- **D5 — Strings are fork-owned `gamelib:` keys.** `about.navLabel` already exists in
  `public/locales/en/gamelib.json`. New sibling keys join it there, never `translation.json`.
  Note the glossary (`meta/i18nGlossary.json`) holds `GameLibSteam` but **not** bare `GameLib`,
  so the product name cannot be left as bare JSX text — `hardcodedStringGate` flags it.

## Risks

- **`meta/i18nGateScope.json` staleness guard** (`genI18nGateScope.test.ts`) — the snapshot is
  hand-curated with a provenance check. Adding the new file by hand must keep
  `generatedBy` honest as a hand edit; do **not** run `pnpm gen-i18n-gate-scope`, which
  regenerates and cascades into unrelated pins.
- **`isTauriRemoved.test.ts`** is a zero-match grep over all of `src/` for the bare identifier
  `isTauri`, and it does **not** exempt comments. Any comment written during this task must
  avoid that identifier — it has already caught two drafts of the SettingsPanel comment.
- Deleting a file that is in `i18nGateScope.json` breaks the blocking i18n gate; `about.html` is
  not in scope (not `src/frontend/**`), but confirm before deleting.
