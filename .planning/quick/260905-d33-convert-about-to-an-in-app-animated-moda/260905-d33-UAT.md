### Correction to a standing note

Memory `tauri-dev-serves-stale-static-bundle` states `frontendDist: "../build"` with **no dev
server**, and concludes a bare `tauri dev` serves the last `electron-vite build`. That is **no
longer the mechanism**: the config now carries `devUrl` + `beforeDevCommand`, and `pnpm tauri:dev`
is `build:sidecar && build:decompress-worker-dev && tauri dev` — it no longer runs
`electron-vite build` at all. The staleness trap it warns about is real for **packaged** builds
and for anything read out of `build/`, but it does not apply to renderer/preload changes in dev.

Evidence the old artifact is genuinely stale and simply unused here: `build/about.html` still
exists on disk (1909 bytes, 07:51) even though the file was deleted from the repo in
`bb560d51a`.

## Tests

Three checks, taken from the replacement observations written into
`34.1-HUMAN-UAT.md` item 8b.

### 1. (a') Settings → About opens an in-app modal

**Expected:** the modal animates in over the app with a ~500ms slide-up. **No separate OS
window** — nothing new in the Dock, no second entry in the window list, no native title bar
reading "About GameLib". It shows the app icon, "About GameLib", a version line reading
`Version: 0.7.0`, "License: GPL V3", and the project URL as plain text.

result: **PASS** — operator-confirmed 2026-09-05, live, macOS, dev build.

### 2. (b') The modal follows the active theme

**Expected:** with the modal open, switching theme (or opening it under a light theme) changes
the modal's background and text colours with it. The page this replaced hardcoded
`#1a1a1a` / `#e6e6e6` and stayed dark under every theme.

**Gesture used:** Settings → General → Select Theme → **Nord Light**, then Settings → About.

result: **PASS** — operator-confirmed 2026-09-05. The modal followed the light theme. This is the
property the retired surface could not have held at any effort: it loaded no bundle and carried
its own hardcoded palette.

### 3. (b'') The macOS tray's "About GameLib" opens the SAME modal

**Expected:** clicking the tray icon → "About GameLib" opens the identical in-app modal in the
main window (focusing it if backgrounded).

**Why this one is sharp:** the tray reaches About from Rust by evaluating
`window.api?.showAboutWindow?.()` in the main window. The call is optional-chained, so if the
seam is broken the item does **nothing and logs nothing on either side** — no throw, no console
line, no entry in the Rust log. This exact seam broke during the task and shipped with every
gate green. A "nothing happened" result here is a real FAIL, not an inconclusive one.

result: **PASS** — operator-confirmed 2026-09-05: "works, same as in app click". The Rust →
`eval` → preload → `CustomEvent` → `AboutDialogHost` path is proven end to end, on the one
surface where a break is silent by construction. This is the observation that mattered most in
the whole run.
