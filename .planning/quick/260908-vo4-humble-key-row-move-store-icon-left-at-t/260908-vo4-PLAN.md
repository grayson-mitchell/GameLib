<decisions_made_during_planning>
These five were researched and settled here so the executor does not re-litigate
them. Each names the evidence.

**1. DOM move, not `order:`.** `order:` only permutes siblings WITHIN one flex
container. The logo is currently `li > div.humbleKeyRowInfo > span.humbleKeyRowCaption
> span.humbleKeyRowStoreLogo` — two levels below the row's flex container, so no
value of `order:` can place it first among the row's flex children. The DOM move
is mandatory, not a preference.

**2. `humbleKeys.rowCaption` stays in the catalog, unused.** It lives at
`public/locales/en/translation.json:621` — an UPSTREAM-owned catalog.
`meta/i18nCatalogChurnGuard.ts` classifies every changed path under
`public/locales/` and throws `UpstreamChurnError` for anything that is not a
`gamelib.json`/`gamelib.mt.json` leaf; its `live tree` assertion runs as a Meta
jest suite. **Deleting the key from 49 `translation.json` files would turn that
gate red.** Leaving it is stable: `pnpm i18n` runs with `keepRemoved: true`
(D-03), so the parser will not drop it either. No locale file is touched by this
plan and no new key is minted.

**3. The icon's accessible name is `platformDisplay.name`, not a new i18n key.**
Those names (`Steam`, `GOG`, `Epic Games`, `Ubisoft Connect`, `Battle.net`,
`Origin`, `Nintendo`) are untranslated proper nouns held in
`keyTypePresentation.ts` and marked do-not-translate in `meta/i18nGlossary.json`.
Reusing the already-resolved variable gives the icon a name with ZERO locale
work. It must be passed as an EXPRESSION (`aria-label={platformDisplay.name}`):
`meta/hardcodedStringGate.ts:74-79` lists `aria-label` in `USER_FACING_ATTRIBUTES`,
so a string LITERAL there is a gate violation. `role` is in `EXCLUDED_ATTRIBUTES`
(`:97`), so `role="img"` as a literal is safe. `role="img"` is required, not
optional — `aria-label` on a bare `<span>` (an ARIA `generic` role) is not
reliably exposed by screen readers.

**4. The no-logo text label stays in `.humbleKeyRowCaption`, below the title —
it does NOT move to the left slot.** Moving it left would make the left column
content-sized and ragged (`Ubisoft Connect` vs a 19px glyph), staggering every
row — the exact failure the `.humbleKeyRowAction` comment at `index.css:184-190`
documents and solves with a fixed basis. Asymmetric rows (branded = icon + title;
named = title + one caption line) are acceptable; the row already varies in
height via the `ownedElsewhere` badge.

**5. Title line-box height is expressed as `calc(var(--text-md) * <ratio>)` with
the ratio declared once as a custom property — NOT as `1lh`.** Two reasons `1lh`
fails: GameLib ships on WebKitGTK (Linux) where the `lh` unit is version-risky,
and `1lh` on `.humbleKeyRowStoreLogo` would resolve against the LOGO element's
own line-height, not the title's — the font-size would have to be copied onto it
anyway, so `lh` buys nothing. The ratio must be DECLARED because the app sets no
body line-height (`src/frontend/index.scss:31` `body` has none; the only
`--line-height` token is button-scoped, `_buttons.scss:13`), so today the title's
line box is the font's UA `normal` and is not expressible in CSS at all.
</decisions_made_during_planning>
