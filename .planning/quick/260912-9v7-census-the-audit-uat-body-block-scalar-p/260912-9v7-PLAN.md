# Census the `audit-uat` body block-scalar population

Actions `.planning/todos/pending/2026-09-11-audit-uat-reads-block-scalars-in-document-bodies.md`.

That todo asks for three things **in order**, and forbids the third before the first two:

1. Measure the body population (files / fields / characters after the closing frontmatter fence).
2. Establish which body blocks any GSD tool actually reads, and by what rule.
3. **Only then** decide the remedy — which may legitimately be "none, record the finding".

This plan is investigation-first. **Task 1 commits nothing.** Task 3's sweep is gated on a numeric
condition stated below, and that condition is written so that "sweep nothing" is a legitimate,
recorded outcome rather than a failure.

## Why the order is load-bearing

This todo is the third generation of one population. Its grandparent
(`.planning/todos/completed/2026-09-11-54-historical-planning-md-frontmatters-fail-to-yaml-parse.md`)
was re-scoped **three times**, each round quoting a figure that was wrong by the time someone acted
on it:

| round | quoted | actual |
| --- | --- | --- |
| `260911-ayu` | "53 js-yaml failures" | wrong population entirely — the damage was in files the gate called **green** |
| `260911-j88` | 64 files / 92 fields / 56 bare | promoted to 66 / 103 / 59 **by that task's own fixes** |
| `260911-vox` | 66 / 103 / 59 | **68 / 160 / 160** — a 2x undercount, because every prior census walked top-level keys only and missed 96 fields nested in list items (`  - reason: >`) |

Repeat that here and it is the fourth. Both directions must be counted before any number is
believed.

## What is already known about the reader rules — desk-read, NOT a measurement

Read at the path `readlink -f "$(command -v gsd-sdk)"` resolves to, which on this machine is
`~/.npm/_npx/4db0de1f85c3165e/node_modules/get-shit-done-cc` (**v1.42.3**). A second, stale npx
cache exists at `9785a834b31d581d` (v1.27.0) with no `sdk/dist/query/` at all; do not read it by
accident. **Verify this resolution yourself at execution time** — GSD resolves through content-hash
npx caches that differ across sessions and machines, and the grandparent todo was explicitly burned
by treating one session's resolution as permanent.

Findings from that read, all of which Task 2 must **confirm empirically against the running
binary**, not inherit:

- **`parseFrontmatterYamlLines` appears in exactly one dist module: `sdk/dist/query/frontmatter.js`.**
  It never touches document bodies. So **the body defect is a different mechanism from the
  frontmatter one**, and the fabricated-keys behaviour that dominated `260911-vox` may not apply
  here at all. Do not assume it transfers.
- **`audit-uat`'s body reader is `parseUatItems` (`sdk/dist/query/uat.js:148-175`)** — a raw regex,
  not a YAML parser. It matches a `### N. Title` heading followed by an inline `expected:` and a
  `result:` word, slices to the next `\n###`, then runs `blockText.match(/reason:\s*(.+)/)`
  (uat.js:158) and the `blocked_by` equivalent (uat.js:159). Unanchored, no `m` flag, first match
  wins, `.` stops at the newline. `reason: |` therefore yields the one-character string `"|"`.
- **The same file contains a code path that DOES handle block scalars.** `uatRenderCheckpoint`
  (uat.js:81-82) explicitly matches an `expected: |` block and dedents it. So one reader in
  `uat.js` supports `|` and its sibling does not. That asymmetry is a finding in its own right and
  it bounds the remedy: a sweep that flattens `expected: |` changes what `uat render-checkpoint`
  returns, even where it improves `audit-uat`.
- **`audit-open`'s `scanDebugSessions` (`audit-open.js:10-59`)** does a **non-recursive**
  `readdirSync` of `.planning/debug` filtered to `entry.isFile()`, so `debug/resolved/` is **never
  opened** — and it skips any file whose frontmatter `status` is `resolved` or `complete` before
  reading the body at all. Its only body read is the `## Current Focus` section, first line, sliced
  to 100 chars. If that holds, the 513-field `debug/resolved/` bucket has **no reader whatsoever**.
- `parseVerificationItems` (uat.js:219+) has a body fallback that scrapes `## human_verification`
  for table / bullet / numbered lines — the known "empty `human_verification` makes audit scrape
  prose" hazard, live in this code.

**Everything in this section is a desk read of one resolved version. It is orientation, not
evidence.** Task 2's job is to turn it into measurement or refute it.

## The four ways `audit-uat` is already known to lie

"`audit-uat`'s output does not show field X" is **not** proof that field X is unaffected. The
executor must state, explicitly, which of these they ruled out and how:

1. A `gaps_found` status **hides a whole phase** from the output.
2. The `status` field hides items **six** ways.
3. It **drops `id:`** and emits items by position.
4. An empty `human_verification` block makes it **scrape prose**.

At baseline, `gsd-sdk query audit-uat` reports **8 phases** and **2 bare-indicator occurrences**
(matching `260911-vox`'s post-sweep state exactly). Eight phases is not eight UAT files — reconcile
against the UAT / HUMAN-UAT files actually on disk and name every one the tool omitted, with the
reason.
