# Quick Task 260909-su5 — `tauri:dev:vault`

## Problem

`GAMELIB_DEV_SECRET_VAULT=1` is **opt-in by exact string match** (`devSecretVault.ts:73`,
branched exclusively at `bootstrap.ts:1061`). Every dev session that omits it takes the keyring
arm and prompts for the macOS Keychain.

This has a measured cost, not a hypothetical one. On 2026-09-09 the StateFlags=4 live gate
(`260909-nzb`) was started without the flag, took the keyring arm, and the first install died on
`refresh token read failed (timeout)` with zero bytes transferred — a **BLOCKED** run that
measured nothing. A failed keyring read is then memoised ~120 s, so the immediate retry failed
from cache and read like a second, independent failure. The operator's instruction on seeing it:

> "note in these tests should run in 'dev mode' and not ask for keychain credentials."

There is no script for it today — `package.json:32` is a bare `tauri:dev`, so the flag lives only
in prose scattered across `.planning/` and has to be retyped from memory each session.

## Approach

Add one sibling script directly beneath `tauri:dev`.

Use **`cross-env`** rather than a bare `VAR=1 …` prefix: a bare env prefix is a POSIX shell-ism
that fails under `cmd.exe`, and this project targets Windows (CLAUDE.md constraint). `.npmrc`
sets `node-linker=hoisted` only — **no `shell-emulator`** — so pnpm does not paper over the
difference. `cross-env@7.0.3` is already a devDependency (`package.json:158`) and resolved in
`node_modules/.bin/`, so this adds no install.

Delegating to `pnpm tauri:dev` (rather than duplicating its three-stage body) keeps a single
definition of the build chain; the env var is inherited by every child down to the sidecar.

## Tasks

### Task 1 — add the script

- **files**: `package.json`
- **action**: Insert `"tauri:dev:vault": "cross-env GAMELIB_DEV_SECRET_VAULT=1 pnpm tauri:dev"`
  immediately after the `tauri:dev` entry, so the two sit adjacent in the scripts block.
- **verify**:
  - `node -e` reads the key back and asserts the exact string
  - `pnpm prettier --check package.json` clean (repo-wide prettier is red; check this file only)
  - `git diff --stat` shows `package.json` and nothing else
- **done**: `pnpm run` lists `tauri:dev:vault`, and its value names both `cross-env` and
  `GAMELIB_DEV_SECRET_VAULT=1`.

## Out of scope

- **No change to the vault's own guardrails.** The exact-`'1'` match, the packaged-build refusal
  and the `0600` requirement are the reason this is safe to make one word long; they stay.
- **No default flip.** `tauri:dev` keeps taking the keyring arm. Making the vault the default
  would silently retire the only arm that exercises the shipped Keychain path — the arm gates like
  `260817-d61-LIVE-GATE.md:41` explicitly require (`GAMELIB_DEV_SECRET_VAULT` MUST be unset).

## Verification the script cannot provide

Running `tauri:dev:vault` proves the env var is set; it does **not** prove the vault arm installed.
The receipt is `[bootstrap] secret stores: dev-vault` in `~/Library/Logs/GameLib/gamelib.log`
(vs `keyring`) — that log line stays the precondition check before arming any live fixture, and
this script does not replace it.
