<objective>
Make the game-page Uninstall for Steam confirm before GameLib deletes anything. Today GameSubMenu skips UninstallModal unless `getSteamDeleteRoute` returns `gamelibDelete: true`, which only happens for native + "delete directly" ON. That rule dates from D-05, when every Steam uninstall went to steam://uninstall and Steam showed its own dialog. Bridge, bottle and unadopted-Mac-native uninstalls were added later. GameLib deletes those itself, so nothing confirms them. In 66.3 UAT test 5 this silently removed the bridge bottle `GameLibSteamBridge-427410`. Root cause: `.planning/debug/uninstall-skips-confirmation.md`.

Approach: the backend route reports whether the uninstall is **delegated** to steam://uninstall. The renderer opens the modal for every route that is not delegated. Why not always open the modal (GameCard does)? A delegated uninstall would then be confirmed twice, once by GameLib and once by Steam, which goes against D-05 for the one case where D-05 still holds. The flag fails closed, so the modal opens whenever the route is uncertain.

Opening the modal for bridge and bottle games exposes a second hazard. For a bottle-eligible title, Steam `getSettings().winePrefix` is the **shared** CrossOver Steam bottle (`steamBottle.getSteamBottleSettings()`). The modal's "Remove prefix" toggle would therefore offer to delete the whole Steam bottle. GameCard's context menu already exposes this. This plan hides the toggle for Steam and also makes the backend ignore `shouldRemovePrefix` for Steam.

Output: route flag + backend prefix guard (Task 1), renderer decision + modal cleanup (Task 2), operator live check (Task 3).
</objective>
