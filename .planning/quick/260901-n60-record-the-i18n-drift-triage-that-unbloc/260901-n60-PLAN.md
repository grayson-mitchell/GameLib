## Findings that drive the edits

**F1 — the blocker premise is false (masking is impossible).** The stated risk was that a
1000+-line refresh would mask the drift. Measured: both upstream commits touch **73 files
across 45 locales, zero of them under `en/`**; the entire drift is under `en/`. Disjoint
file sets — a pull cannot mask the drift.

**F2 — the stated `en/` conflict does not exist.** The todo says `en/translation.json` has
diverged +290 lines and "needs hand-resolution". Upstream touches no `en/` file in either
commit, so those fork edits are never contested. Nothing to hand-resolve.

**F3 — the churn-guard complication is false.** `meta/i18nCatalogChurnGuard.ts:runCli()`
collects paths from `git diff --name-only -- public/locales` — **unstaged working-tree
changes only**. A committed (or even merely staged) upstream refresh is invisible to it.
The guard cannot fire on a replayed refresh. (Side note: this makes it fail-open against
staged churn — out of scope here.)

**F4 — the real complication the todo missed.** Fork base is `b5b5cad3f`. Between it and
`c39d40174` there are **9 further upstream commits that also touch `public/locales/`**
(`8eb7fe7f9`, `adefbca62`, `ccfc8e849`, `43dd58cd6`, `728bd197e`, `a6bf657bd`, `6d32bae8e`,
`a71a8b4b7`, `bdafb95ff`). Blob comparison: 57 of the 73 target files differ between
`HEAD` and the upstream commits' parents. A two-commit cherry-pick will therefore NOT apply
cleanly — not because of fork edits, but because of skipped intermediate upstream commits.

**F5 — `pnpm i18n --fail-on-update` writes nothing.** Verified twice: exits 1, leaves
`public/locales/` byte-clean. It is a pure check; only bare `pnpm i18n` writes.

**F6 — 4 of the 78 drift keys are test-only sentinels leaking into shipped catalogs**,
because `i18next-parser.config.js`'s `input: ['src/**/*.{ts,tsx}']` includes 343
`__tests__` files. Leaked keys: `translation:bottle.setup.done = "INLINE-DEFAULT-SENTINEL"`
(from `labelSuiteI18nCensus.test.ts:118`), `translation:no.such.key.anywhere = "fallback"`
(same file, :123), `gamelib:__wr16spec.plural` and `gamelib:__wr16spec.typo` (from
`chipLabels.realI18next.test.ts`).

**F7 — the drift and the churn guard are in direct contradiction, which is why the drift
cannot simply be committed.** `pnpm i18n --fail-on-update` (pre-push gate) demands zero
pending updates, i.e. that 71 keys be written into `en/translation.json`. D-05's churn
guard forbids `pnpm i18n` changing any upstream catalog. Both can only be satisfied by
fixing the call sites so the fork-authored keys route through the `gamelib:` namespace —
which is the new todo's job, not this one's.
