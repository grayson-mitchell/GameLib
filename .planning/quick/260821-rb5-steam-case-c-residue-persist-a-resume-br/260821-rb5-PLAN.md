<objective>
Close case C of the aborted-depot-residue todo: when GameLib is hard-killed
(`kill -9`, crash, power loss) mid native-depot-download, NO JavaScript runs at teardown, so
no `appmanifest_*.acf` is written, `nativeInstallsInFlight` dies with the process, and nothing
reaches `steamLibraryStore`. Partial bytes sit under `steamapps/common/<installdir>` with zero
record anywhere, and `scanDownloadingAppIds` (library.ts:2836) — which only ever opens
`appmanifest_*.acf` and tests `StateFlags & 4` — can never see them.

Fix: persist a crash-surviving resume breadcrumb at install START, union it into init()'s
existing surfacing path, and self-heal it away when the install later turns out to be complete.

Purpose: makes the residue RECONCILABLE (the second of the todo's two acceptance branches),
without touching `depot.ts`'s manifest-write ordering — which is the entire reason this design
was chosen over the rejected "write the 1026 manifest up-front" alternative.
Output: two new `InstalledInfo` fields, three new library.ts helpers, three call-site changes,
and a behaviour gate that proves the residue is SURFACED (not merely that a helper was called).
</objective>
