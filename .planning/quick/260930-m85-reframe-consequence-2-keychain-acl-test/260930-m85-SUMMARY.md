# Quick Task 260930-m85: Reframe consequence 2 as a local signed-A to signed-B Keychain ACL test Summary

**One-liner:** Appended a fifth, purely-additive STATUS section to the macOS signing/notarization
todo, reframing its last open arm — previously read as needing a second published, notarized
release — as a claim about the Keychain ACL's designated requirement that two locally-signed
bundles can settle on this Mac alone, and separately naming a previously-unrecorded trap: the
release workflow's `tagName: v__VERSION__` would destroy the existing `v0.7.0` draft artifact if a
second throwaway tag were ever pushed.

## What happened

The todo's own title and `needs:` framed the remaining arm (consequence 2 — Keychain prompt COUNT
across an update) as blocked on cutting a second signed release, which is itself gated behind an
unrelated open todo and an operator-only `v*` tag push. Re-reading what consequence 2 actually
asserts — a claim about the Keychain ACL's designated requirement (identity-based vs.
cdhash-pinned) — showed the claim is testable with two locally-signed bundles on this machine,
needing neither notarization, a published release, nor the updater path at all. The session also
surfaced a trap the todo had never named: the release workflow's `tagName: v__VERSION__` means a
second throwaway-tag run overwrites the existing `v0.7.0` draft release and its assets, which would
destroy the one artifact (artifact N) the eventual N -> N+1 test still needs preserved.

**Task 1** appended a new `## STATUS 2026-09-30 (quick-260930-m85)` section immediately before
`## Related`, changing nothing else in the 531-line file. The section:
- Names all four prior STATUS sections (`2026-09-14`, `2026-09-17`, `2026-09-23`, `2026-09-24`) as
  not revised, per the file's own additive convention.
- Reproduces `gh release list --limit 20`'s three-line tab-separated output verbatim, confirming
  one `v0.7.0` draft and no second release, and the two surviving `v*` remote tags.
- Records the `tagName: v__VERSION__` destructive-tag trap and names artifact N (filename, sha256,
  byte size, release id) so it can be preserved before any second tag run.
- Records the reframing: `security find-identity -v -p codesigning`'s verbatim output, the
  identity-vs-cdhash mechanism, and the runnable sign-A/create-item/sign-B/read-under-B/count-prompts
  shape.
- Records three prerequisites as traps, each with its source location: the three contaminated
  Keychain items (deliberately not deleted — operator's call), a launch alone not being a trigger
  (with the real read channel and the explicitly-not-a-trigger boot probe both cited), and the
  requirement that builds A and B be signed identically to the release.
- Records what the reframing does NOT claim (the updater's replace-in-place path, a real
  `v0.7.0 -> v0.7.1` sequence), and records `ready: live-gate` as a proposal in prose only, with
  `severity: minor` unchanged and the frontmatter left untouched.
