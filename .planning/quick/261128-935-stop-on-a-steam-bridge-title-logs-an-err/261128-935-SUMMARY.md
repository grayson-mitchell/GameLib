# Phase quick-261128-935 Plan 01: Stop on a Steam bridge title no longer logs an ERROR Summary

`call(id, { ifMissing })` on the abort registry lets `dispatch.kill` report "no abort controller" at INFO, so Stop on a Steam bridge title (206060) writes no ERROR while every caller that expects a registration keeps the ERROR.

## Root cause

`dispatch.kill` aborts unconditionally on every Stop, then runs the store's `stop()`. Nothing is keyed by a running Steam game's appId in the TS map (the bridge launch registers no controller by design) or in Rust's table (wine runs are `wine-<serial>`, no Steam spawn is game-class). So the forward answered `false` and `logNotFound` wrote the ERROR on every Stop. The todo's `files:` path was wrong; the module is `src/backend/utils/aborthandler/aborthandler.ts`.

## Decision

No controller for the bridge launch (a dummy or a second kill path, and a bare-appId key would collide with the six download and maintenance controllers). Gating `kill` on `aborts.has` was rejected because it skips the Rust forward and leaves the sideload ERROR. Chosen: keep the abort and the forward, choose the level at the call site. The default stays `'error'`, byte-identical; only `kill` passes `'info'`.
