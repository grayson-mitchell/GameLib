Quick 261029-riq, part 2 of 2: item 3, "have the filters look like the ones in console mode. (Installed) | (All) (Native) rather than current 4 main". The user decided these follow-ups (relayed by the coordinator):

- The chip row is exactly `(Installed) | (All) (Native)`.
- Installed is an independent on/off toggle, like console mode, and combines with everything else.
- All and Native are a single-select pair. All means no native restriction. Native means it runs natively on the host. On macOS that is a native macOS build that is not confirmed 32-bit; unknown bitness is included.
- Recently played and Favourites are removed from the filter panel. They remain as Focus row content.
- Migrations: a saved `libraryView: 'installed'` becomes All + Installed on. `recentlyPlayed` and `favourites` become All.
- Remove dead view plumbing where it is dead. Keep and declare it where other code depends on it.

What "the current 4 main" were: the four `FilterViewList` rows, All games / Installed / Recently played / Favourites (`NavShell/components/FilterViewList/index.tsx:40-63`), a single-select `libraryView`. Where they go:

| Old row | New home |
|---|---|
| Installed | the Installed toggle chip (`installedOnly`) |
| All games | the All chip (`nativeOnly === false`) |
| Recently played | removed from the panel; still a Focus row option (`FilterFocusRow` viewRows) |
| Favourites | removed from the panel; still a Focus row option |
| (new) | the Native chip (`nativeOnly === true`) |

Planner decisions (Claude's discretion, stated for the user):

- **D-riq-1, Native on Windows: hidden.** `deriveRunnabilityTier` already treats every runnability row as uncomputable on win32, because GameInfo carries no Windows-native signal. On Windows every game is "native", so the filter is meaningless there. The All | Native pair and the divider do not render on win32; only Installed shows. `engineState.nativeOnly` is forced false on win32, so a persisted flag from another OS's profile has no effect.
- **D-riq-2, duplicate "Runs natively".** It is removed from the Runnability group under Filters: `FilterRunnabilityFacet` filters out the 'native' tier. On Linux, 'native' was that group's only row, so the group disappears there. On macOS the group keeps Runs for me / Runs via bottle / Won't run / Not yet checked.
  - The 'native' tier itself stays in the engine, in `runnabilityRowsForHost` and in the context `runnabilityRows`. That keeps "Runs natively" selectable as Focus row content and keeps persisted Focus row selections valid.
  - A persisted `runnabilityFacet` that contains 'native' is migrated once: 'native' is stripped, and Native is turned on (non-win32).
- **D-riq-3, chip order.** The user's order is used. Native stays on the All side of the divider, because All/Native is the single-select pair and the divider separates the toggle from the pair. That is exactly the shape of the user's example.
- **D-riq-4, the Native rule versus the "Runs natively" tier.** Both share one new predicate, `hasNativeBuild(game, host)`: darwin `is_mac_native === true`, linux `is_linux_native === true`, win32 false. That is today's test in `deriveRunnabilityTier`, extracted. The Native chip adds the macOS 32-bit exclusion on top: `isHostNative = hasNativeBuild && !(host === 'darwin' && mac_arch === '32')`.
  - FLAG for the user: the existing tier returns 'native' for a mac-native game even when `mac_arch === '32'`, because the native check comes before the 32-bit bottle rule. So the Focus row's "Runs natively" can still include a confirmed-32-bit mac build that the Native chip excludes.
  - This plan does NOT change `deriveRunnabilityTier`'s precedence. That is install-routing-adjacent and was not asked for.

32-bit signal source per store (the only arch field is `GameInfo.mac_arch?: '32' | '64' | 'unknown'`, `src/common/types.ts:270-275`; absent means unknown):

- **Steam:** the one store with a 32-bit signal. `mac_arch` is seeded into GameInfo from `steamMetadataStore` (`steam/library.ts:1425`, default 'unknown'). '32' can only come from two writers:
  - (a) The post-install Mach-O ground-truth check: `machOArchsOf` uses `lipo -archs`, falling back to `file`, and `verifyMacArchGroundTruth` persists the result (`steam/library.ts:~1848-2014`). That writer sets `mac_arch_source: 'macho'` and `mac_arch_verified: true`.
  - (b) A curated known-fix `macArch: "32"` hint, seeded on Apple silicon only (`steam/macArchKnownFix.ts`). That writer sets `mac_arch_source: 'known-fix'` and leaves it unverified.
  - The pre-install min-OS heuristic `macArchFromMinOS` (`steam/games.ts:593`) only ever returns '64' or 'unknown'. So an uninstalled Steam 32-bit mac title with no known-fix entry reads as unknown and IS included by Native.
- **GOG:** no arch signal. `is_mac_native` comes from `supported_operating_systems` containing 'osx' (`gog/library.ts:1164`). `mac_arch` is absent, so the game is included when it is mac-native.
- **Epic (legendary):** no arch signal. `is_mac_native` comes from the game info (`legendary/library.ts:636`). Included when mac-native.
- **Amazon (nile):** no arch signal, and `is_mac_native`/`is_linux_native` are hard false (`nile/library.ts:112-113`), so it never matches Native.
- **Zoom:** no arch signal. Native flags come from `operating_systems` ('osx' / 'linux', `zoom/library.ts:171-172`).
- **Sideload:** no arch signal; its native flags are whatever the sideload record carries. No arch data is invented for any store.
- **Linux host:** the user's rule is macOS-specific, and no Linux bitness field exists. Linux Native is `is_linux_native === true`.

Dead plumbing removed versus kept (declared):

- REMOVED (main-grid only, no other consumer):
  - `libraryView` / `setLibraryView` on `LibraryContextType` and in `LibraryContext.tsx`'s default.
  - The `libraryView` state, `VALID_LIBRARY_VIEWS` and `setLibraryViewPersisted` in `Library/index.tsx`.
  - The 'view' descriptor kind: `ActiveFilterDescriptor.kind`, the view branch of `describeActiveFilters`, the `case 'view'` in `chipLabels.ts`, and the remover in `FilterChipRow/index.tsx`.
- KEPT, because the Focus row depends on it:
  - `LibraryView` (all four values, including 'installed'), `FilterEngineState.view` and `passesView`, all used by `focusRowSelectors.ts` `selectFocusRowGames`.
  - `FOCUS_ROW_VIEW_VALUES` (`src/common/focusRowMigration.ts`).
  - The four `gamelib:library.filterPanel.view*` keys, used by `FilterFocusRow`.
  - The main grid now always passes `view: 'all'`.
  - The legacy `show_installed_only` / `showInstalledOnly` context field (pre-existing Heroic residue, not read by the engine) is left alone. The new toggle uses a fresh key so the two cannot collide.

Purpose: one compact, console-styled quick-filter row with the user's semantics, without losing Recently played / Favourites (Focus row) or anyone's saved filter.
