## Deviations from plan

**None functionally.** One process deviation, disclosed:

- **A `/*` landmine in `stripSourceComments` was discovered and worked around during Task 1** (in
  the prior session, before this session's continuation began). My own prose (in `Login/index.tsx`
  and in the new test file) originally contained the literal two-character substring `/*` inside
  `//` line comments — e.g. the path pattern `` `/loginweb/*` ``. `stripSourceComments`'s
  block-comment stripper (`src/backend/testUtils/stripSourceComments.ts`) is a raw text scan with
  no `//`-context awareness: it matched from that `/*` to the NEXT `*/` anywhere later in the
  file (an unrelated, legitimate JSX comment ~250 lines on), silently deleting all code in between
  from every sibling gate's view. Three unrelated test files momentarily failed as a side effect.
  Fixed by rewording the prose to avoid the literal substring; not a plan deviation, but worth
  flagging since it is a repo-wide hazard for any future prose touching these files. No gate
  exists for this landmine today.
- **A vacuous assertion was caught and tightened during Task 1's falsifiability proof** (also in
  the prior session): the D-2 "both `useCallback`s have empty dependency arrays" assertion
  originally used `.toBeGreaterThanOrEqual(1)`, which stayed green even when only one of the two
  callbacks was mutated to a non-empty array. Rewritten to require the empty-dep count to equal
  the total `useCallback` count. This is exactly the discipline the plan's falsifiability
  requirement exists to enforce, not a deviation from it.

No architectural changes, no new dependencies, no new localisation strings (D-4 — the Dialog
title reuses `getStoreDisplayName`, body copy is entirely `TauriLoginPanel`'s existing
`webview.login.oauth.*` keys).

## D-3 provenance (recorded per the plan's explicit instruction)

The Dialog-rendering phase split (`DIALOG_PHASES = {preparing, finalizing, blocked, error,
timeout}`, i.e. a Dialog only for the two windowless waits plus the three failure phases) is the
**operator's 2026-10-03 decision**. Its discriminator is **"is a native sign-in window on
screen?"**, NOT "is the phase terminal?". This plan's first draft used the terminal/non-terminal
split and put `preparing` and `finalizing` in the silent set even though neither phase has a
window to defer to — the operator corrected this, which is why `OAuthLogin`'s `DIALOG_PHASES` is
coded as a positive membership test (listing all five Dialog phases) rather than a negation
chain: a future phase added to the hook's union fails CLOSED (renders nothing) instead of
silently falling into the Dialog branch.
