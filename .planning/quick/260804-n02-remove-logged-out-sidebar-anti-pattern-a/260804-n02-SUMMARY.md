# Quick Task 260804-n02: Remove logged-out sidebar anti-pattern Summary

Removed the sidebar's login-state-dependent identity swap: "Manage Accounts" now
renders unconditionally, in its normal (non-promoted) position, in both logged-out
and logged-in states, and the onboarding tour targets it unconditionally.

## What Was Built

`SidebarLinks` previously rendered a `Login` item promoted to the very top of the
menu when no store account was logged in, and suppressed the real `Manage Accounts`
item (positioned between Wine Manager and Accessibility) entirely — the reverse
happened when any account was logged in. This made the menu's item count, label,
and position a function of session state.

**Task 1** added a `describe('SidebarLinks account item', ...)` block to the
existing test file with 5 regression tests pinning: unconditional `Manage Accounts`
label (never `Login`), no promotion above the `GameLib` library link, fixed
position immediately before `Accessibility`, invariance of all three assertions
when logged in, and a stable `url="/login"` across both states. Confirmed RED:
4 of 5 new tests failed against the unmodified implementation (the logged-in
invariance test already passed, since the current code already handled that
state correctly — only the logged-out promotion was broken). The 2 pre-existing
Redeem-a-Steam-key tests continued to pass throughout.

**Task 2** made the fix in `SidebarLinks/index.tsx`: deleted the
`{!loggedIn && (<SidebarItem ... dataTour="sidebar-login" />)}` block so `GameLib`
is unconditionally the first child of `.SidebarLinks`; unwrapped the
`{loggedIn && (...)}` guard around the real Manage Accounts item, leaving it
byte-identical in its original position; deleted the now-dead `loggedIn`
derivation and dropped the now-unused `faUser` icon import (`faUserAlt` survives,
since it's used by the surviving item). The `useContext` destructure
(`epic`/`gog`/`amazon`/`zoom`/`steam`) was left untouched — those bindings remain
live through `handleRefresh()`, the `defaultStore` selection block, and the
Steam-key redemption item. Result: `npx jest SidebarLinks` went 7/7 green.

**Task 3** fixed `SidebarTour.tsx`'s matching conditional, which — after Task 2 —
would have had its `else` branch target `[data-tour="sidebar-login"]`, an element
no longer present in any state. Replaced the `if (isLoggedIn) {...} else {...}`
block with a single unconditional `baseSteps.push(...)` for the
`sidebar-manage-accounts` step (kept its `tour.sidebar.accounts` translation key,
default copy, and `position`); dropped the `sidebar-login` step and its
inline-only `tour.sidebar.login` default. Deleted the dead `isLoggedIn`
derivation and narrowed the `useContext` destructure from
`{ epic, gog, amazon, zoom, platform, isRTL }` to `{ platform, isRTL }` after
confirming via grep that `epic`/`gog`/`amazon`/`zoom` had no other consumer in
the file. The `isWin`-gated Wine Manager step and all other steps were left
untouched.

  file already worked around this by casting its return to

- **Fix:** Added a local `findManageAccountsItem` helper inside the test, mirroring
  `findRedeemItem`'s cast pattern, instead of accessing `.props.url` on the raw
  `collectElements()` result.
- **Files modified:** `src/frontend/components/UI/Sidebar/components/SidebarLinks/__tests__/index.test.tsx`
