<objective>
Make `pnpm bridge-census` measure what actually runs, so plan 51-30 can use its closing numbers.

1. **Dual-arch.** The census picks "the first exe with a steam_api import", so for AoD 230070 it scanned AoD.exe (x86) while install, shim placement (steam_api64.dll) and launch all used AoD64.exe (x64).
2. **"Verified".** The census's `verified` currently means "the allowlist seed entry carries `playVerified`", and those records cite Mac Steam In-Game status. That status comes from the helper's own `SteamAPI_Init`, not from the game. Verified must instead mean: the helper logged a HELLO for this appid AND the game's own log shows no Steam-init failure.

Findings from planning (what exists today):
- `CensusRow.verified: boolean` is driven only by `bridge-allowlist.json` `seed[].playVerified` (`loadPlayVerified`, `withVerified` in `classifyCensusTitleCore`), shown as the `Verified` column and as "K of M verified running through the bridge". The static `Class` column (`bridge`/`missing-symbols`/...) comes from the import table. No live evidence is read anywhere.
- The launcher's exe choice is `resolveBridgeLaunchExe` (`src/backend/storeManagers/steam/bridge/launchTarget.ts`). It reads PICS `config.launch` over a live Steam CM session (`SteamUser.getClient()` / `ensureConnected()`), and it imports `backend/logger`, `../user` and `../bottle`. The census is deliberately zero-backend-import, and its offline, bundled-standalone design (header docblock) rules that out. So, per the task brief's "or read the persisted verdict" option, the census reads what install wrote from that same exe: `steam_metadata.json` -> `<appId>.bridge.scan.arch` (`SteamBridgeScanVerdict`, schema in `bridgeVerdict.ts`: `status: 'clean'|'miss'`, `arch: 'x86'|'x64'`, ...). Measured on this Mac: 230070's entry has `bridge.steamApi: "both"` and `bridge.scan.arch: "x64"`. Entries are top-level keys by appId, unwrapped.
- File locations on this Mac: metadata at `~/Library/Application Support/gamelib/store_cache/steam_metadata.json` (`CacheStore('steam_metadata')` -> cwd `store_cache` under pathShim userData `.../Application Support/gamelib`). App log at `~/Library/Logs/GameLib/gamelib.log` (+ `gamelib.log.old`, `logger/paths.ts` darwin branch). The HELLO line, verbatim: `bridge helper [1691190]: [2026-10-23T21:19:34Z] HELLO  shim attached appid=1691190` (two spaces after HELLO; `bridge_helper.c:447` `logts("HELLO", ...)`). Unity log at `<bottle>/drive_c/users/crossover/AppData/LocalLow/<Company>/<Product>/Player.log`, e.g. `GameLibSteamBridge-1691190/.../LocalLow/Ice Code Games/RogueWaters/Player.log`, which carries `Unity intercepted Exception: EntryPointNotFoundException: SteamAPI_ISteamClient_GetISteamUser assembly:<unknown assembly> ...` followed by a `Steamworks.SteamAPI.Init ()` stack frame.

Output: an updated `meta/bridgeCensus.ts` and its test suite, and the dual-arch todo closed. This plan does not build a live launcher, does not change the persisted verdict schema, and does not edit `bridge-allowlist.json`.
