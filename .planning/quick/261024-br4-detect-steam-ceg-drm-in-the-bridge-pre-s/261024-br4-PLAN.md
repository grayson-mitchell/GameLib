## Departures from the orchestrator's design direction, and why

1. **SteamStub `.bind` is detected and reported, but never routed.** The todo says "do the same
   for a SteamStub `.bind` section". This plan does NOT do that. The newer sibling todo
   (`2026-10-23-forwarding-steamclient-dll-for-steamstub-titles.md`, "Contrast with CEG") puts
   SteamStub in scope for the bridge. The user's standing rule is that bottled Steam is a narrow
   fallback to shrink toward zero, and that DRM which needs a Windows Steam client (CEG) is the
   only justified new route into it. `.bind` therefore appears only as a log line (backend) and as
   detail text (census). The close-out note records this deviation.
2. **A detected CEG beats a bundled non-DRM known-bad reason.** The design direction says the
   effective reason is "bundled reason, else 'drm-wrapped' when drm is 'ceg'". With that order, a
   title bundled as `does-not-run` would hide a detected CEG and fall through to the bridge, which
   is exactly the defect this plan fixes. CEG is the stronger fact, so the effective reason is
   `verdict?.drm === 'ceg' ? 'drm-wrapped' : knownBadReason`. The census uses the same order.
3. **No separate fs-wrapper module.** The thin fs reader lives as a private function inside
   `shimGenerate.ts`, which already imports `node:fs`. That keeps the backend surface to one
   existing file. The pure parser is still its own zero-import module.
4. **No type-union edits needed.** `steamBridgeSetupRequired.reason` in `ipc.ts` and
   `SteamBridgeSetup.ts` state are plain `string`. 'drm-wrapped' / 'known-bad' already exist in
   `SteamBridgeKnownBadReason` / `SteamBridgeRouteReason`. `bridgeRouteDisplay.ts` already maps
   'drm-wrapped' to `steam.bridge.knownBad.drmWrapped`. So `common/types/steam.ts`, `ipc.ts` and
   `frontend/state/SteamBridgeSetup.ts` are NOT modified. Only the setup dialog gets a DRM line.

Parse little-endian, in this order:
1. 'MZ' at offset 0, then e_lfanew (u32) at 0x3C.
2. 'PE\0\0' at e_lfanew. The COFF header follows: NumberOfSections is the u16 at +6 from the
   signature start, and SizeOfOptionalHeader is the u16 at +20. The optional header starts at
   e_lfanew+24.
3. The optional-header magic u16 is 0x10b (PE32) or 0x20b (PE32+). Any other value is unparsed.
   NumberOfRvaAndSizes is the u32 at opt+92 (PE32) or opt+108 (PE32+). The data directories start
   at opt+96 or opt+112. The resource directory is index 2 (RVA u32, Size u32). An absent index 2
   (NumberOfRvaAndSizes < 3) or a size of 0 means no resources, which is still parsed.
4. The section table is at opt + SizeOfOptionalHeader, 40 bytes per entry. Cap NumberOfSections
   at 96. Read the name from 8 bytes trimmed of NULs, VirtualSize at +8, VirtualAddress at +12,
   SizeOfRawData at +16 and PointerToRawData at +20. hasBindSection is true when any name equals
   '.bind'.
5. Map RVA to file offset through the section with VA <= rva < VA + max(VirtualSize, SizeOfRawData):
   offset = PointerToRawData + (rva - VA). No containing section means unparsed.
6. The resource root is an IMAGE_RESOURCE_DIRECTORY (16 bytes): NumberOfNamedEntries is the u16
   at +12 and NumberOfIdEntries the u16 at +14. Entries follow at 8 bytes each: the Name/Id u32,
   then OffsetToData u32. If the high bit of OffsetToData is set, it points to a subdirectory at
   resourceRoot + (value & 0x7fffffff).
7. At the top level, find the ID entry 10 (RT_RCDATA) that has the subdirectory bit set. In its
   subdirectory, walk the named entries only (high bit of Name set). Each name string sits at
   resourceRoot + (Name & 0x7fffffff): a u16 length, then UTF-16LE code units. Cap the length at
   256. Collect a name when its uppercased form is in CEG_RESOURCE_NAMES, keeping the name as
   read, de-duplicated, in file order.
8. Cap each directory's total entries at 4096. Any subdirectory offset that points back at or
   before its parent is unparsed (cycle guard).

Wrap the whole body in try/catch so any unexpected error returns
`{ parsed: false, cegMarkers: [], hasBindSection: false }`. It must never throw.
