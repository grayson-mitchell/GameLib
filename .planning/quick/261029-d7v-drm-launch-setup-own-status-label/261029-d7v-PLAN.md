# Quick 261029-d7v: DRM-mode launch setup gets its own status label

## Problem

`drmLaunchSetup` (Phase 56, 56-11) reports progress with `status: 'redist'`, so the
Play button and status line read "Installing Redistributables (Compatibility runner)"
while it downloads the steamclient layer, clones the runner, fetches the Valve client
and stages the bottle. No redistributable is installed by that step. Live evidence:
`gamelib.log` 2026-10-29 08:48:32-08:48:50, appId 219990 — the real shared redists had
already run at the end of the install (08:45:01-08:45:54).

## Change

Add a `'drm-setup'` member to `Status` and send it from `drmLaunchSetup`'s `progress()`.
It behaves exactly like `'redist'` everywhere a status list gates behaviour (sleep
assertion kind `system`, library status tracking, Play disabled on GameCard / GamePage /
ConsoleCard), and differs only in its label:

- Play button: `label.drmSetup` "Preparing Steam DRM support"
- Status line / console overlay: `status.drmSetup` "Preparing Steam DRM support ({{step}})",
  with the same 14px spinner the redist line carries (quick 261026-e1c).

Contexts (`DRM_PROGRESS_CONTEXT`) are unchanged. The shared-redist installer, known-fix
`runInPrefix` and the GOG/Epic/Amazon setup keep `'redist'`.
