## Design (locked by the orchestrator; planner choices marked)

- **Do not enable the flag in `tsconfig.json` or `tsconfig.meta.json`.** A scoped tsconfig cannot
  work alone, because tsc reports errors in every file in the program, imported files included.
  So the scope lives in the ratchet's bucket rules instead.
- **Planner choice: use the TypeScript compiler API, not a spawned `tsc`.** This follows the
  precedent of `meta/lintScoped.cjs`, which calls the ESLint API for exactly this reason: no shell
  and no exit code to lose, no extra committed tsconfig, and no spawn for the fake-HOME rule to
  govern. Use `ts.getParsedCommandLineOfConfigFile(path, { noUncheckedIndexedAccess: true }, host)`
  and then `ts.createProgram` and `ts.getPreEmitDiagnostics`. Pass the first program as
  `oldProgram` to the second so shared source files are reused.
- **Planner choice: equality ceiling, as in clippyRatchet.** A bucket below its baseline FAILS with
  "lower <bucket> to <n> in this commit", which is stricter than a hint. A baseline left above the
  real count is slack that later growth can hide in, which defeats a shrink-only ratchet. This
  costs one edited number per incidental fix. Write the rationale into the script header.
