# Quick Task 260808-f80

## Problem

On the Manage Accounts screen the wrong Epic tile is coloured red as
deletion-pending. Under Tauri the red marker sits on the **primary** "Epic Games
Login" tile — which is the SIDLogin (real system browser + auth-code) path, the
path Phase 34.7 turns into the single Epic device-auth sign-in. The tile that
should be red is the **"epic Alternative Login Method"** tile — the embedded
WebKit web login that hits Epic's Talon anti-bot 403 and is scheduled for
deletion.

Quick task 260805-d62 deliberately wired `deprecatedTile` to follow the SIDLogin
tile ("this reads inverted relative to intuition on purpose"). That premise is
now wrong: SIDLogin is the keeper, the embedded web login is the casualty.

## Tile roles (why the ternary must stay a ternary)

| Shell | primary tile | alternative tile |
|---|---|---|
| Tauri | SIDLogin — **keep** | embedded web login — **deprecate** |
| Electron | embedded web login — **deprecate** | SIDLogin — **keep** |

So the marker must name the embedded web login in both shells:
`deprecatedTile={isTauri() ? 'alternative' : 'primary'}` — the exact inverse of
today's expression.

## Tasks

- **files:** `src/frontend/screens/Login/index.tsx`
- **action:** Change `deprecatedTile={isTauri() ? 'primary' : 'alternative'}` to

  in both shells and that SIDLogin/device auth is the surviving path per Phase
  34.7. Leave `primaryLoginAction` / `alternativeLoginAction` untouched — the
  F-34.5-G6-01 pivot still stands.
- **verify:** `grep -n "deprecatedTile" src/frontend/screens/Login/index.tsx`

- **done:** Under Tauri the red tile is "epic Alternative Login Method".
