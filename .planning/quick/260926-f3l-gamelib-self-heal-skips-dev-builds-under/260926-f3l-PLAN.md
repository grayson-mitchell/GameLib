<predicate_choice>
The planner considered three predicates and chose the operator-preferred one, for these reasons:

- `cfg!(debug_assertions)` is rejected. The debug NSIS build installed to `%LOCALAPPDATA%\GameLib` is
  a debug build, and it must self-heal.
- Allow-listing the install root (repair only under `%LOCALAPPDATA%\GameLib`) is rejected. The NSIS
  install directory is not fixed: it can be user-chosen, per-machine, or a copied or portable exe. An
  allow-list would silently stop repairing every legitimate install outside the one path it knows,
  and a failed repair is the invisible failure uok exists to prevent.
- **Chosen: deny-list exactly this build's own cargo target dir.** Use `env!("CARGO_MANIFEST_DIR")` +
  `\target`, plus `option_env!("CARGO_TARGET_DIR")` when set at compile time. The directory is baked
  at compile time, so it names only the tree that produced this binary. An installed copy of the same
  binary runs from the install dir, which is never under that tree. A release build made on CI bakes
  the runner's path, which never matches a user's install. The only exes skipped are ones executed
  in place where cargo wrote them. That covers `tauri dev`, and also a `target\debug`/`target\release`
  exe launched by hand, which is also a dev build of this tree and correctly skipped.
</predicate_choice>
