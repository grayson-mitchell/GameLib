## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in the plan's own verify script] Prettier reformatting broke a single-line grep check in Task 1**

- **Found during:** Task 1, verifying the `shortcutsFlows.test.ts` change
- **Issue:** The plan's Task 1 verify script checked for the gated describe via a literal single-line grep: `grep -qF "describeOnDarwin(\"addShortcut's darwin GAMELIB_SHELL_EXE pin" "$SF"`, which requires the opening paren and the title string on the same source line. Renaming that describe from `describe(...)` to `describeOnDarwin(...)` (5 characters longer) pushed the line past prettier's wrap threshold, and prettier's own `--check` (also required by the same verify block) reformats it to multi-line: opening paren, then the title string, then the arrow function, each on its own line. The two requirements in the same verify script -- "prettier-clean" and "this exact string appears on one line" -- became mutually exclusive once the identifier grew.
- **Fix:** Kept the code prettier-formatted (multi-line, `npx prettier --check` clean) rather than fighting the formatter, and substituted an equivalent wrap-aware `awk`-based check to confirm the same semantic claim -- that Describe 5 specifically (and only Describe 5) is the one wrapped in `describeOnDarwin` -- instead of the plan's brittle single-line literal grep.
- **Files modified:** `src/backend/sidecar/__tests__/shortcutsFlows.test.ts` (no additional change beyond what the plan specified; only the verification method differed from the plan's script)
- **Commit:** `b57eb48a9`
