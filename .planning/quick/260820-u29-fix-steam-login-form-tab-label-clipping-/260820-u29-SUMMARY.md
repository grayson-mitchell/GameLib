## Task 2: The fixes applied

**`index.tsx` (around what were lines 577-598):** `variant="scrollable" scrollButtons="auto"` replaced with a single `variant="fullWidth"`. The wrapping `<div className="tabsWrapper">` and its closing `</div>` were deleted; `<Tabs>` is now a direct child of the returned fragment, re-indented one level. No scoped `.tabsWrapper` rule was invented -- see key-decisions above.

**`index.scss`:** two rules appended after `.steamQrContainer`:

```scss
.steamQrContainer svg {
  display: block;
}

// [arithmetic comment -- see file for full text]
.steamLoginBody #tabpanel-qr > div {
  min-height: 310px;
}
```

The 310px arithmetic, as computed in the plan and reproduced in the source comment: 248px deterministic block (16px + 8px + 200px QRCode + 8px + 16px, the two `.steamQrContainer`/white-wrapper padding pairs plus the 200px `<QRCode size={200}/>`) + 308.4px total once the two `<p>` line boxes and their margins are added (19.2px first `<p>` line box + 16px its margin-bottom + 11.11px second `<p>`'s UA margin-top collapsing against the container's 0 bottom margin + 13.3px second `<p>` line box), rounded up to 310px with ~1.6px deliberate slack.

**Known limit, stated rather than papered over:** both `<p>`s are assumed to fit on one line, which holds at `.steamLoginBody`'s `width: min(480px, 95%)` (the longer string is ~335px at 16px Rubik). At a window narrow enough to wrap a paragraph, the natural height would exceed 310px and a small growth would return. Not fixed here -- out of this plan's scope per its constraints.
