<objective>
Fix the three defects that live gate D (setting ON, game running) of quick 261106-s3n exposed. In the evidence from 2026-11-07, WazHack 264160 was running natively on macOS arm64. Steam's own EAppUpdateError 16 refusal was the only thing that saved the game files. GameLib then deleted 264160.json, .log and -lastPlay.log, and sent the refusal message as an OS notification the operator never saw.

1. The running check is blind on macOS: RunningAppID is absent from registry.vdf. Add a check for any process running from the install folder.
2. A refused uninstall falls into uninstallGameCallback's success branch and deletes the GameLib settings. Add a typed `refused` flag that the callback honours.
3. Refusal messages are OS notifications. Move them to the in-app steamRequestNotice stack, and treat Steam error 16 as "is running".

Output: one new module and edits to the delete route, the uninstall callback and the request-notice renderer, each with unit tests. The live re-check of gate D is run by the operator. It is listed below and not claimed here.
