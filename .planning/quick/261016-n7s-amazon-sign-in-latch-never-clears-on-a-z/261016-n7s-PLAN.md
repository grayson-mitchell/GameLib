<objective>
Let the Amazon sign-in latch clear from a successful app-side `nile library sync`,
so a recovered token un-sticks the "Sign-in expired" tile on a profile with zero
installed games. The expiry probe itself is untouched.

Purpose: the probe's zero-installed run is `unknown` by design (260822-vov), and
`unknown` never writes. A refresh line can therefore latch the flag but nothing
can ever clear it except a Reconnect login (measured 2026-10-15, quick 261015-rud,
Arm B launches 1-3). Rationale for this fix over a replacement probe command:
every nile 1.2.0 refresh-reaching command with zero installed games either IS
`library sync` (forbidden as a probe, D-16) or is a launch/install path, so no
replacement probe command exists. Meanwhile `refreshNile()` already spawns
`nile library sync` on every library refresh and that spawn already proves the
credential. Observing a spawn that already happens is not the pass triggering a
sync, so D-16 holds.

Output: a clear-only classifier, an observer at the existing spawn site, tests,
two corrected doc comments, and the source todo closed.
</objective>
