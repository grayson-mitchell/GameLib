<findings>
Facts the planner checked. They constrain the design, so don't re-derive them.

1. **The `ConsoleSteamVerdict` ok arm is `{ ok: true }`. It exposes no target.**
   `evaluateQuickInstallTarget` (InstallGameModal.ts ~L198) also returns bare `{ ok: true }`.
   `SteamInstallLibraryTarget` is `{ path; steamappsDir; isPrimary }`. To show the real target,
   the probe has to add it to the ok verdict itself.
2. **The D3 source gate (`assertNoFilesystemPathOnScreen`) bans one identifier: `libraryPath`.**
   That is the degrade record's field, and the gate checks for it anywhere in the comment-stripped
   overlay. Its error text says "no filesystem path may render on a TV", which overstates it: the
   non-Steam overlay already renders `defaultInstallPath` on the TV. The in-file comment ties the
   no-path rule to the D-29 failure card. Decision for this task: the failure card still never
   shows a path, and `libraryPath` must still never appear in index.tsx. The ok-state "Install to"
   row may show the resolved library root, for parity with non-Steam. Name the new field
   `targetPath`, never `libraryPath`. Reword D3's description and error text to match what the gate
   actually proves; the detection logic stays as it is.
3. **B4 pins `resolveConsoleActionIntent` to destructure EXACTLY `{runner, focused}`.** Do not
   add a readiness parameter. Gate Steam readiness inside the overlay instead: the `installGame`
   guard plus the disabled button.
4. **The D7 gate allows `reason` exactly once in the stripped overlay.** It is the
   `steamBlockedMessage(steamBlocked.reason)` argument. New code must not use the word `reason`,
   in identifiers or in string literals.
5. **D5 asserts that `setTimeout(` comes after `probeSteamQuickInstallTarget(`.** The timer is being
   removed, so D5 has to be replaced (see Task 2).
6. **D6 requires exactly one `install({` and D8 requires the literal
   `installSteamGame(game.app_name, game)` with no `installPath: 'default'`.** Both must stay green.
   D2-RED and D8-RED derive their known-bad input by replacing that exact literal.
7. **`console.steam.installing` lives only in `public/locales/en/translation.json`.** That is an
   upstream-owned catalog. `pnpm i18n-churn-guard` forbids any change to upstream catalogs, and
   `i18next-parser.config.js` sets `keepRemoved`. Drop the `t()` usage and leave the key in the
   JSON. Do not edit `translation.json`.
8. **New fork strings go into `public/locales/en/gamelib.json` (en only)**, under `consoleMode`
   in alphabetical key order, the same way quick 261102-pgy added `steamClientSetupHandOff`.
   Use `tGamelib('gamelib:consoleMode.<key>', '<default>')`. index.tsx is in
   `meta/i18nGateScope.json`, so a bare string literal there trips the hardcoded-string gate.
9. **Jest (frontend project, `testEnvironment: node`) cannot render the overlay.** That's why the
   overlay's tests are source-text gates over `stripSourceComments` text.
10. **Prettier sees** `consoleSteamTarget.test.ts` (`"ignored": false`). Run `--file-info` on the
    other two `.ts`/`.tsx` paths before checking them. `public/locales/` is prettier-ignored, so
