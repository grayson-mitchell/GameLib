# Quick 261027-k51: Forward UserStatsReceived_t (1101) from the helper to the game

The helper now captures `UserStatsReceived_t` from its own Steam session (broadcast or the
completion of its own `RequestUserStats` call), repacks it from the 20-byte Mac layout into the
24-byte MSVC layout, and queues it for the shim. The shim relays it to every registered
`CCallback<UserStatsReceived_t>`, holds it if no listener exists yet, and reports each dispatch
back so the helper log shows `CBDISP`. This targets the ELEX (411300) loading-screen hang.
Not yet proven live (needs the operator run below).

**4. [Design detail] Log formats.** The existing DRAIN source pin forbids `%s` in any CBQ format, so the 1101 CBQ lines use literal-format branches (a small macro) rather than a `%s` for `src`/`app`/`action`. No SteamID, gameID, call handle or payload is ever logged; a new source pin enforces it.

## Behaviour notes

- A fetch is "one in flight" via `pending_call`; if Steam never completes the call and never broadcasts a 1101, later requests log `call=inflight` and do not refetch. A broadcast 1101 clears it. A failed `GetAPICallResult` clears `pending_call` and keeps `pending` set.
- Identity-only helpers (`g_bd_identity_only`) log `request mode=identity-only` and do nothing (SteamUserStats is app-scoped, T-51-25).
- Old helper with new shim and new helper with old shim: slots 9/10 answer STATUS_ERR on the old helper (ignored); an old shim never sends them.
