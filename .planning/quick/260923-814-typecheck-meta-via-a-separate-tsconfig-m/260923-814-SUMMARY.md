## The config

`tsconfig.meta.json` is `extends` + `include` and nothing else, matching `tsconfig.eslint.json`'s
shape. That is the anti-drift property, not a style choice: with no `compilerOptions` block there
is no way to relax `strict`/`strictNullChecks`, and no way to bump `target` to es2018 to silence a
TS1501 rather than fix the source.

`npx tsc -p tsconfig.meta.json --noEmit` at `cc5df29d2` exited **2 with exactly 12 errors** and
**zero** TS7016/TS2664 artefacts — file, line and code identical to the plan's list. The include
set was not re-litigated; the plan's measurement was confirmed by the count.

### Two inherited settings, confirmed by inspection

**`baseUrl: "./src/"` is inherited and must stay inherited.** `extends` resolves `baseUrl` relative
to the file that DECLARES it, so it keeps pointing at `<root>/src/`. Load-bearing:
`meta/__tests__/hardcodedStringGate.test.ts:1122` carries a baseUrl-relative specifier
`'common/types/humble'`, which a redeclared `baseUrl` would break. **Positive evidence: not one
TS2307 appears anywhere in the 12.**

**`exclude: ["vite.config.ts","**/__mocks__/**","sign"]` is inherited too.** Measured:
`find meta -path '*__mocks__*'` returns **nothing**, so that pattern silently excludes nothing from
the new project today. It would start doing so the moment someone adds a `meta/__mocks__/`
directory — worth knowing, because the exclusion would be invisible.

## The 8 sites — runtime argument for each

Per constraint 3, each site was opened and its runtime behaviour established BEFORE any type was
changed.

**1–2. `meta/hardcodedStringGate.ts:574`, `:587` — TS2339 `getTagNameNode`.**
Both sites read `getFirstAncestor((n): n is Node => Node.isJsxElement(n) || Node.isJsxSelfClosingElement(n))`.
The type predicate discarded exactly what the guard body proves, narrowing to bare `Node`.
Predicate corrected to `n is JsxElement | JsxSelfClosingElement`; those two types added to the
existing ts-morph import. **Runtime: the guard body is byte-identical, so the set of matched
ancestors is identical.** A type predicate has no runtime representation at all — it erases.
Confirmed by `meta/__tests__/hardcodedStringGate.test.ts`, this gate's only runner, **151/151**.

**3. `meta/hardcodedStringGate.ts:1456` — TS2339 `findReferencesAsNodes`.**
`findAssignedBindingNameNode` was declared `: Node | undefined`, but every one of its three return
paths is `Node.isIdentifier(x) ? x : undefined` or a bare `undefined` — it can only ever return an
`Identifier` or `undefined`. Return type narrowed to `Identifier | undefined`. **Runtime: zero
change; the annotation was simply weaker than the code.** `findReferencesAsNodes` is a
`ReferenceFindableNode` member and resolves once the type is honest. `const references: Node[]`
kept (`Identifier[]` is assignable); lint and prettier did not object.

**4. `meta/machineFillGamelib.ts:453`, `:521` — TS2345 `MtManifest | null` vs `| undefined`.**
`stampFilledAt` declared `priorManifest: MtManifest | undefined`, but the module's convention
everywhere else is `| null` (`mergeFill`, `FillLocaleParams`), and both call sites pass the `| null`
value. Widened the parameter to `MtManifest | null`. **Runtime: every path through the body is
null-safe and was already exercised with `null`.** The body has exactly ONE read of the parameter —
`priorManifest?.filledAt` — and optional chaining short-circuits on `null` and `undefined`
identically. `stampFilledAt` is module-private with exactly two callers (grepped: 3 total
occurrences, 1 declaration + 2 calls), so there is no third caller relying on the narrower type.
Fixed by widening rather than by `?? undefined` at the call sites, because coercion would hide the
convention mismatch that caused it. `Meta/machineFillGamelib` **48/48**.

**5. `meta/pruneStaleHelperBinaries.ts:235` — TS2365 `&` on `number | bigint`.**
`let binaryStat: ReturnType<typeof statSync> | undefined` resolves to statSync's LAST overload,
whose bigint variant widens `.mode` to `number | bigint`, so `binaryStat.mode & 0o111` is rejected.
The actual call is `statSync(binaryPath)` with **no options**, which returns `Stats` (`mode: number`).
Annotated `Stats | undefined`, `type Stats` added to the `node:fs` import, with an in-situ comment
naming the overload trap. **Runtime: unchanged — a `let` annotation erases entirely.** The exec-bit
check at `:235` is a real release gate (`has no exec bit set`); it was NOT cast, NOT unmasked and
NOT otherwise touched.

**6. `meta/rebrandUpstreamCatalogs.ts:275` — TS1501, the es2018 `s` flag.**
`entry.split(/:(.*)/s)` → `entry.split(/:([\s\S]*)/)`, with a comment naming why. **Runtime:
verified empirically, not asserted** — both regexes were run through `String.prototype.split` over
six inputs (`'gamepage:a.b.c'`, `'ns:'`, `'x'` with no colon, `'a:b:c'` double colon,
`'ns:line1\nline2'`, `'ns:a.b\n.c'`), producing byte-identical arrays in every case including the
embedded-newline cases the `s` flag exists for. `target` was NOT bumped anywhere.
`Meta/rebrandUpstreamCatalogs` **34/34**.

**7. `meta/sidecarSeaFsShim.ts:65` — 2 × TS2322 (threat T-814-01, the highest-risk site).**
This file is `--inject`ed into the SEA bundle and patches production `fs.readFileSync`, so runtime
neutrality here is the whole requirement. The patched function declared
`(path: unknown, ...rest: unknown[])`, so `apply(fsModule, [path, ...rest])` could not match
`readFileSync`'s parameters. Retyped the parameters **from the original**:
`...args: Parameters<typeof originalReadFileSync>`, with `isSteamSystemPemPath(args[0])` and
`originalReadFileSync.apply(fsModule, args)`. The passthrough remains `.apply(fsModule, <the
caller's own argument list>)`; the `system.pem` short-circuit and its early
`return STEAM_SYSTEM_PEM` are untouched.

**Runtime: measured against the esbuild-bundled shim** (`esbuild --bundle --platform=node
--target=node21`, then required into a live process). Every `readFileSync` result was captured
before and after the patch installs:

```
PASS buf           (Buffer read)                        PASS fd            (file-descriptor read)
PASS utf8          (encoding string)                    PASS throwsENOENT  (error propagation)
PASS opts          ({ encoding } options object)        PASS zeroArg       (ERR_INVALID_ARG_TYPE)
PASS nullOpt       (explicit null options)
PASS system.pem short-circuit returns the inlined key without touching disk
RUNTIME-NEUTRAL
```

The zero-argument row is a small strict improvement: the old `[path, ...rest]` reconstruction
padded a 0-arg call to `[undefined]`, length 1; a single rest parameter forwards the real
`arguments` list, so the error now comes from node rather than from the shim's reconstruction.
Both still raise `ERR_INVALID_ARG_TYPE`. `Meta/buildSidecarSea` **67/67**.

**Which way the two directives went, as the plan required a report on:**

- The pre-existing **`@ts-expect-error` at :52–55 STAYS.** `tsc` reports no TS2578, so it is still
  covering the `fsModule.readFileSync = ...` assignment and is still doing work. Not removed.
- The **`eslint-disable-next-line prefer-spread` at :63–64 was REMOVED**, with a negative control:
  `npx eslint --report-unused-disable-directives` is clean with it gone, and with it reinstated
  reports `74:3 error Unused eslint-disable directive (no problems were reported from
  'prefer-spread')`. The rule had been firing on the array LITERAL `[path, ...rest]`, not on
  `.apply`. A replacement comment states why `.apply` is deliberate, so the reasoning survives the
  directive.

**8. `meta/__tests__/machineFillGamelib.test.ts:90` — TS2352 + the `:93` TS2339 fallout.**
The cast had lost its wrapper: the two passing precedents 12 and 23 lines above read
`as { merged: typeof target }` / `as { merged: { ... } }`, while line 90 read
`as Record<string, string>` — casting the `{merged, manifest}` wrapper instead of `merged`, so
`merged` was typed `string` and `merged.alpha` at `:93` failed. Corrected to
`as { merged: Record<string, string> }`, matching the precedent exactly. **Runtime: none — a type
assertion erases.** This was a real defect in the test's own typing, and it is the todo's headline
evidence that ts-jest is not a substitute gate: the suite passed while carrying it.

**9. `meta/__tests__/lintTranslations.test.ts:291` — TS2345 on the `process.exit` spy.**
The double cast targeted `(code?: number) => never`; @types/node declares
`process.exit(code?: string | number | null)`. Widened both the mock implementation's parameter and
the cast target to `string | number | null`. **Runtime: the body's only use of `code` is
`String(code)`, which accepts all four admitted values identically** (`String(null) === 'null'`,
`String(undefined) === 'undefined'`). No `as any`; the existing `as unknown as` shape is kept and
only its target corrected; no NEW `as unknown as` introduced anywhere. The REQ-41-02 comment block
at lines 280–289 is preserved verbatim. `Meta/lintTranslations` **32/32**.
