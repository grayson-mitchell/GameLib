# Quick Task 260901-w9e — Plan

Close the OPEN todo `disable-plausible-telemetry-reporting-into-heroic-property` by **removing
the Plausible integration and both consent surfaces outright.**

## Why "removed", not "kept and hard-wired off"

The todo left this as an OPEN SUB-DECISION on 2026-08-18, deferred until Phase 35 landed. Phase 35
closed 2026-09-01 (quick `260901-vuy`). Measured at HEAD, the sub-decision is no longer balanced:

- `startPlausible()` has **zero importers**. Its only caller was `src/backend/main.ts:22`/`:496`,
  both deleted in `5643c7583` (plan 35-14, the Electron cutover point of no return). The
  module-level `backendEvents.on('settingChanged', …)` listener at `plausible.ts:133` therefore
  never registers either.
- `build/main/sidecar.js` contains **0** occurrences of `heroic-games-client.com`.

So the leak the todo was filed for is already closed by the cutover, and "kept, hard-wired off" is
the *current* state — which is precisely the [[uploaded-log-delete-button-lies]] failure mode the
todo warned about, in its worst form: `AnalyticsDialog` interrupts first launch to ask the user to
consent to collection that names Plausible, GDPR/CCPA/PECR and "the data we collect", none of
which can happen. `AnalyticsOptIn` offers a toggle whose only effect is to write a config field
nothing reads.

Removal also matches the operator's standing decision of 2026-08-15 — *disable telemetry entirely*
rather than repoint at a GameLib-owned property.

**Out of scope, explicitly:** the todo's "Future direction" section (GameLib-owned destination,
opt-out consent model, Steam in the provider props). The todo itself scopes that as separate
future work — a fresh design pass, not an un-disabling of this code path.

## Decisions

**D-01 — `public/locales/` is NOT touched.** All 12 analytics keys (`setting.analyticsOptIn`,
`help.analytics`, `analyticsModal.title|enable|disable|info.pt1..pt7`) live in **upstream-owned**
`translation.json`, not fork-owned `gamelib.json`. `meta/i18nCatalogChurnGuard.ts` classifies any
changed `public/locales/` path that is not a `gamelib.json`/`gamelib.mt.json` leaf as `upstream`
and throws `UpstreamChurnError`, and its `live tree` test asserts that against the real working
tree under `pnpm test:ci`. `meta/lintTranslations.ts` sets `printExtraTransations = false`.
The keys go inert across all 49 catalogs. This is the same call quick `260810-tr4` (D-01) and
`260805-rwy` already made — the todo's open i18n question is answered by precedent, not by a new
judgement.

**D-02 — the two blocking-gate artifacts are hand-edited surgically, NOT regenerated.**
`meta/i18nGateScope.json` lists both components. `scanScope()`'s `scanFile` **throws
`ScopeLoadError` on an unreadable scoped file**, and `genI18nGateScope.test.ts:332` asserts
`existsSync` for every scoped entry — so deleting the components without editing the scope turns
the blocking i18n gate red for a structural reason, not a real violation. `genI18nGateScope.ts:498`
names surgical hand-editing as the sanctioned path. `pnpm gen-i18n-gate-scope` is **not** run:
[[i18n-fork-pin-regen-cascades]] measured that regen taking the suite from 1 failure to 5.

**D-03 — no settings migration.** Existing `config.json` files carry `"analyticsOptIn": false`.
Once the field leaves `AppSettings`, it is an ignored extra key — nothing reads it, nothing
throws. Same call as `260810-tr4` D-03. The `analytics-modal-shown` localStorage key is likewise
left orphaned and unread.

**D-04 — `meta/hardcodedStringGate.ts:225`'s comment is left as written.** It names
`AnalyticsDialog.tsx` among five files where `34.8-AUDIT.md` confirmed an ALL-CAPS token is a
discriminator rather than prose. That is a record of what the audit triaged; rewriting it would
falsify an audit history to tidy a comment. Four of the five files still exist.

## Fork-hygiene sweep (the todo asks for it)

Swept every `http(s)://` literal in `src/` and `src-tauri/src/` outside `__tests__`, reduced to
hosts. **No second Heroic-owned analytics property exists.** Two outbound sinks that *receive*
user data remain and are deliberately NOT touched here:

- `https://dpaste.com/api/v2/` (`src/backend/logger/uploader.ts:13`) — log upload. Already
  tracked by [[log-upload-has-no-redaction]]; unredacted-content is that todo's problem, not this
  one's.
- `https://heroic.legendary.gl/v1/…` (`storeManagers/legendary/library.ts:725`, `:742`) — Heroic's
  Legendary metadata API. It is **read-only** (`version.json`, `sdl/{appName}.json`); it is a
  fetch, not a report. Named here so a later reader does not have to re-derive that.
