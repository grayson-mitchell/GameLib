<objective>
Give the About window a user-reachable entry point.

`tauriShowAboutWindow` (`src/preload/api/tauriChildWindows.ts:139`) is fully implemented — it
races `getHeroicVersion()` under a 1s bound, refocuses an existing `about` window, and loads the
first-party static `public/about.html`. It has never been invocable. The only caller of
`showAboutWindow` anywhere in the tree is `src/backend/tray_icon/tray_icon.ts:124`, the
**Electron** tray menu, which Tauri does not run.

Output: an **About** row in the Settings tier-2 nav panel, between Documentation and Ko-fi,
calling `window.api.showAboutWindow()`.

This is a pure entry-point addition. Not one line of the About window's own implementation
changes.
</objective>

<deviation_from_todo>
The todo proposes putting the entry point on the **Tauri tray menu**, matching where Electron put
it. This plan puts it in the **Settings nav panel** instead. Three measured reasons:

1. **The Rust tray cannot call the code the todo wants to make reachable.**
   `tauriShowAboutWindow` is preload/renderer code. A Rust tray item would have to either
   duplicate the `WebviewWindow` construction in `main.rs` (leaving `tauriShowAboutWindow` still
   dead, so the todo's stated defect would survive its own fix) or add new Rust→frontend event
   plumbing that does not exist today. Both are far past a `severity: low` todo.

2. **Phase 34.1 declared the tray About item out of scope, deliberately and in writing**
   (`main.rs:18`, `:5856`). The tray is a bounded two-item Show/Quit menu by design. Reopening
   that boundary is a phase decision, not a quick task.

3. **The nav row is strictly more reachable.** It works on all three platforms, in the primary
   window where users already are, on both shells — `helpers.ts:17` already routes
   `showAboutWindow()` to `tauriShowAboutWindow()` under Tauri and to the IPC listener under
   Electron. No Linux tray-support caveat, no macOS menu-bar-only caveat.

The todo's actual goal — "`tauriShowAboutWindow` … cannot be invoked by any user action" — is
fully met. The todo's follow-on note (UAT item 8b becomes runnable, and should move back out of
`human_verification_resolved` in `34.1-VERIFICATION.md`) is met too, and is Task 4.

**What this plan does NOT close:** the todo's second observation, that the About version string
cannot be falsified under `pnpm tauri:dev` because dev runs a plain bundled `sidecar.js` with
`npm_package_version` set. That is a property of the dev harness, not of the entry point, and it
stays true after this change. Only a packaged build discriminates `0.0.0` from `0.7.0`. That
caveat is carried forward into the UAT item text rather than silently dropped.
</deviation_from_todo>
