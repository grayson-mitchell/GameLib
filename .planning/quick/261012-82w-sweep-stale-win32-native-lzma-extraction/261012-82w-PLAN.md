<objective>
Close the 261011-wrx accumulation defect, using the sweep the operator chose. Today, on Windows, every
decode worker of every sidecar process that engages native LZMA leaves one
`gamelib-lzma-native-<pid>-XXXXXX` directory in `%TEMP%`, because a loaded addon and the
`liblzma.dll` it maps cannot be unlinked while the process runs. Measured: 16 dirs (~13 MB) per
packaged-app session that decodes a depot, never reclaimed. Sixteen such dirs (dead pid 37008) sit
in this box's `%TEMP%` right now.

Purpose: the binding sweeps, before it creates its own directory, the directories of processes that
have exited. Accumulation becomes bounded by one live session's own workers instead of growing
without limit. It does this without breaking the sidecar exit contract and without ever deleting a
directory whose owner may be alive.

Output: a win32-only synchronous bounded sweep in `lzmaNativeBinding.ts`, a sweep sentence in the
loader's existing log lines, unit tests, a real win32 SEA measurement (or a recorded reason it
could not run), and the closed todo.

Discretion choices made in this plan (the todo and the operator's intent leave these open):
- **win32 only.** On POSIX the existing `finally` unlink succeeds, so nothing accumulates. `/tmp`
  there can also be shared across users and pid namespaces, where ESRCH does not prove the owner is
  gone. `%TEMP%` on Windows is per-user, and pids are system-global.
- **Exact name match, suffix included.** `^gamelib-lzma-native-(\d{1,10})-[A-Za-z0-9]{6}$`, because
  mkdtemp's suffix is exactly six alphanumerics (measured: 200 of 200 on this box). This only
  narrows the intent's prefix pattern. It never matches a name the binding could not have minted.
- **Delete-time `lstatSync` check.** Mirrors `reapStaleRoots()` in `src/backend/jest.globalSetup.js`:
  skip symlinks/junctions and non-directories, and skip entries that vanished because a sibling
  worker removed them first, so removal counts are not double-counted.
- **Logging goes through the loader.** The binding has no logger and deliberately reaches the log
  only via a `globalThis` record (the 261011-wrx extraction-record design). The sentence is appended
  to the existing single engaged `logInfo` call, so the "logged exactly once" invariant that
  `decompressPool.test.ts` asserts still holds. It is also appended to the import-failure
  `logWarning`, so a sweep that deleted files is never silent.
- **The LEFT BEHIND sentence is reworded.** It currently ends "count them there to measure
  accumulation", which the sweep makes misleading. It now says a later process removes them.
- **A live SEA arm (Task 2).** The only true end-to-end proof. It is precondition-gated and skips
  rather than halting, exactly as 261011-wrx Task 3 did.
