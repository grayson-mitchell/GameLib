## Task 1 — honour the forwarded picker options in the `dialog_open` arm

**files:** `src-tauri/src/main.rs`

**action:** The `dialog_open` arm (`main.rs:4722`) reads **only** `properties`. Everything else
the caller sends crosses the wire and is dropped on the floor. Plumb it:

- `title` → `set_title`
- `defaultPath` → `set_directory` (and, when the path names an existing FILE rather than a
  directory, its parent via `set_directory` — rfd/AppKit does not accept a file path as a start
  directory). Skip entirely when the path does not exist: handing AppKit a nonexistent
  directory is worse than handing it nothing.
- `filters` → `add_filter`, **file-mode only**. `SideloadDialog` sends image and executable
  filters today (`localImageFilters`, `fileFilters`) and gets an unfiltered picker. Folder
  pickers ignore filters, so applying them there would be noise. Mirror `dialog_save`'s existing
  `filters` parse verbatim — same wire shape, same `name`/`extensions` keys.
- `buttonLabel` → **cannot be honoured.** tauri-plugin-dialog 2.7.2's `FileDialogBuilder` has no
  confirm-button setter (verified against the vendored crate: `add_filter`, `set_directory`,
  `set_file_name`, `set_title`, `set_can_create_directories` — that is the whole surface).
  Record this inline as a known gap rather than leaving the next reader to re-derive it.

**verify:** `cargo check` clean; the new jest source-shape pin (Task 4) passes.

**done:** the arm reads `title`, `defaultPath` and `filters` off `args[0]`, and carries an
inline comment naming `buttonLabel` as unsupported-by-the-plugin with the crate version.

## Task 2 — give the human-gated sibling channels the inner exemption

**files:** `src/backend/sidecar/sidecarRpc.ts`

**action:** `UNBOUNDED_RUST_CHANNELS` is still `[RUST_DIALOG_OPEN]` alone. The audit the todo
asked for has a definite answer, and both siblings fail the same way `dialog_open` did:

- **`dialog_message`** — `showMessageBox` (`platform/index.ts:450`) catches a transport failure
  and resolves `{ response: safeIndex }`, i.e. **the declined branch**. A user who deliberates
  for 60s on a native confirm has their dialog answered "no" on their behalf while the panel is
  still on screen; their real click then arrives for a deleted `rustPending` id and is dropped.
  `showErrorBox` swallows the same timeout.
- **`dialog_save`** — `showSaveDialog` (`platform/index.ts:532`) resolves `{ canceled: true }`,
  i.e. **claims the user cancelled** while the save panel is still open. Identical in shape to
  the `dialog_open` bug this exemption list was created for.

Both are gated on a human by construction, which is this list's own stated membership rule
("gated on a HUMAN, not on machine work") — no measurement is owed, unlike the outer
`LONG_RUNNING_CHANNELS`, whose rule is measurement-based.

**Deliberately NOT done:** adding outer `LONG_RUNNING_CHANNELS` entries for the renderer→shell
channels that wrap these. Record the reachability finding in the closure record instead —
`showMessageBox`'s live callers sit under `uninstall` (already exempt) and `quit`, and
`showSaveDialog` has no live backend caller at all. That list grants membership on a
MEASUREMENT, and there is none here.

**verify:** new jest test pins all three members.

**done:** `UNBOUNDED_RUST_CHANNELS` is `[RUST_DIALOG_OPEN, RUST_DIALOG_MESSAGE, RUST_DIALOG_SAVE]`
with per-entry rationale, and the doc comment above it no longer speaks only of `dialog_open`.
