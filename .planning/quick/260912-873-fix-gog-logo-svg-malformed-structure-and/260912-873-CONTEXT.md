# Context — `gog-logo.svg` geometry + structure

Investigation was completed by the orchestrator before planning. Everything below is
**measured or read from source**, not inferred. Treat it as locked.

## 1. The todo's headline is a sound measurement with a WRONG remedy

The todo asks to "correct the `<symbol>`'s viewBox to a square aspect … so the glyph renders
19.0 × 19.0 like the Steam icon". **Do not do that.**

Rendered the asset at 192×192 (`rsvg-convert -w 192 -h 192`) and measured the ink bbox by
decoding the PNG scanlines:

```
ink cols 0..191   -> width  192  (100.0% of the box)
ink rows 17..191  -> height 175  ( 91.1% of the box)
175 / 192 = 0.9115     31 / 34 = 0.9118     <- matches the symbol's 34:31 viewBox
```

The artwork is the **gog.com wordmark inside a rounded rectangle**, and that rectangle's own
path spans `0..34` × `0..31` user units — the outer rounded-rect subpath is
`M31,31 H3 a3,3…V3 A3,3…H31 a3,3…V28 A3,3…Z`, i.e. corners at (0,0) and (34,31). The mark is
**genuinely wider than it is tall**. That is the GOG brand aspect, not a defect.

Forcing a square render would require `preserveAspectRatio="… none"`, a **~9.7 % vertical
stretch** (34/31) that turns the rounded corners into ellipses and distorts the letterforms.
A square viewBox *with* `meet` changes nothing at all — the ink stays 34:31, just letterboxed,
and the live measurement would come back 19.0 × 17.5 again. So the todo's remedy is either a
no-op or a brand-mark distortion.

For reference, the neighbouring `steam-logo.svg` is **also** not square (`viewBox="0 0 496 512"`).
"Square" was never the house convention; `epic-logo.svg` (`0 0 24 24`) is, `amazon-logo.svg`
(`0 0 448 512`) is not.

## 2. The REAL defect the same measurement exposes: the glyph is bottom-flush

`top gap 17px, bottom gap 0px` in that 192-box. The symbol carries
`preserveAspectRatio="xMidYMax meet"` — **`YMax` = align to the bottom edge**. So the whole
letterbox slack is dumped above the glyph and none below.

Scaled to the live 19.2 px box the Humble Keys row gives it
(`.humbleKeyRowStoreLogo`, `index.css:418-428`, `width/height: calc(var(--text-md) * 1.2)`):

| | today (`xMidYMax`) | after (`xMidYMid`, the default) |
|---|---|---|
| ink size | 19.2 × 17.5 | 19.2 × 17.5 (unchanged) |
| space above | 1.70 px | 0.85 px |
| space below | 0.00 px | 0.85 px |

So the GOG mark currently sits **~0.85 CSS px lower** than a centred glyph, next to Steam
logos that are vertically centred in the same row. That is the fixable defect.

## 3. The two structural malformations (both real, both fixable in the same edit)

- `<symbol id="icon-logo-gog">` is nested **inside** the `<use href="#icon-logo-gog">` that
  references it. There is exactly one glyph in this file, so the `<use>`/`<symbol>`
  indirection buys nothing.
- `<path className="cls-1">` — `className` is a JSX prop name, not an SVG attribute. The
  sibling `zoom-logo.svg:3` correctly uses `class="cls-1"`, which confirms this is an anomaly
  and not a house pattern. No `<style>` block in the file defines `.cls-1`, so it is inert
  either way, but the correct spelling is `class`.

## 4. `class="gogIcon"` on the ROOT `<svg>` MUST be preserved

`src/frontend/screens/Humble/Keys/index.css:447` declares the scoped escape
`.humbleKeyRowStoreLogo .gogIcon { fill: currentColor; }` that out-specifies the global
`.gogIcon { fill: var(--text-default) }` in `styles/_colors.scss:101`. That fix (quick task
260911-p6s, commit `c690a117a`) is **closed and re-measured PASS** in REQ-43-19 run 3.
`src/frontend/screens/Game/GamePage/index.css:619` also keys off `&.gogIcon`.
Dropping the root class would silently re-open the closed colour defect.

There is a stylesheet test (`Humble/Keys/__tests__/humbleKeysStylesheet.test.ts`) pinning the
CSS side of that escape. It does **not** read the SVG. No test anywhere pins this asset's
internals (`icon-logo-gog`, `cls-1`, and the `0 0 32 32` viewBox appear in no test).

## 5. Consumers, and why the viewBox change is layout-safe

Three importers, all via `?react` (vite-plugin-svgr):

| consumer | sizing CSS | both dimensions fixed? |
|---|---|---|
| `Humble/Keys/components/HumbleKeyRow/index.tsx` | `.humbleKeyRowStoreLogo svg { width:100%; height:100% }` (Keys/index.css:430) | yes |
| `components/UI/StoreLogos/index.tsx` | `.gameCard .store-icon { width:35px; height:35px }` (GameCard/index.css:173); GamePage `& > svg { width:46px; height:46px }` (GamePage/index.css:612) | yes |
| `screens/Login/index.tsx` | `.runnerIcon svg { width:100% }` (Runner/index.css:64) **+** `.runnerWrapper svg { height:100% }` (:74) | yes |

`* { box-sizing: border-box }` is global (`App.css:14`). Because **every** consumer pins both
width and height, the SVG's intrinsic aspect ratio never drives layout — changing the root
viewBox reflows nothing. It only changes where the glyph sits inside its already-fixed box.

## 6. The one knock-on that MUST ship with the asset change

`src/frontend/screens/Game/GamePage/index.css:619-621`:

```css
&.gogIcon {
  padding: 0px var(--space-3xs) var(--space-3xs);
}
```

against the base `& > svg { width:46px; height:46px; padding: var(--space-2xs); … }`.

That asymmetric override (no top padding, bottom padding only) exists **solely to hand-correct
the bottom-flush rendering** — it lifts the bottom-aligned glyph back off the floor. Once the
asset centres itself, the override becomes a ~9 px-wide over-correction that pushes GOG up and
leaves it sized differently from the Epic/Steam/Amazon icons beside it, which all use the
symmetric `var(--space-2xs)`.

**Delete the `&.gogIcon` block** so GOG inherits the same symmetric padding as every other
store icon. Leaving it in place converts this fix into a new GamePage defect.

## 7. Target file content

`src/frontend/assets/gog-logo.svg` becomes a single flat element. The `d` attribute must be
copied **byte-for-byte** from the existing `<path>` — it is ~1.5 KB of coordinates and any
transcription slip is invisible at icon size:

```xml
<svg class="gogIcon" viewBox="0 0 34 31" xmlns="http://www.w3.org/2000/svg">
	<path class="cls-1" d="…UNCHANGED…"/>
</svg>
```

Root `viewBox="0 0 34 31"` = the path's true bounds, so the asset stops lying about its own
extent, and the default `preserveAspectRatio` (`xMidYMid meet`) centres it. Tab indentation,
matching the rest of `src/frontend/assets/`.
