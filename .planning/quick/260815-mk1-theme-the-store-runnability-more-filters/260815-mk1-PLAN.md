# Quick Task 260815-mk1: Theme the Store / Runnability / More-filters group headers

## Problem

The three collapsible group headers in the Games tier-2 filter panel — **Store**,
**Runnability**, **More filters** — render as default user-agent push-buttons:
grey `buttonface` fill, a beveled UA border, and near-black text. They look like
Windows 95 buttons sitting inside an otherwise fully-themed dark panel.

### Root cause (diagnosed, not guessed)

`FilterFacetGroup` renders its header through the shared `Dropdown` component,
whose `<button className="dropdownButton">` is styled **nowhere**:

- `components/UI/Dropdown/index.scss` styles `.dropdownContainer`, `.dropdown`
  and `.dropdown > button` (the *contents*) — it has **no `.dropdownButton`
  rule at all**.
- `FilterFacetGroup/index.scss:49` is the only `.dropdownButton` rule in the
  codebase, and it sets **layout and typography only**: `display`,
  `align-items`, `justify-content`, `width`, `font-size`, `font-weight`,
  `line-height`, `padding`. It never sets `background`, `border`, `appearance`
  or `color`.

So the cascade leaves the UA button chrome intact, and the global
`styles/_buttons.scss:7` rule (`button { @include buttonDefaultStyle }` →
`color: #161616`) paints near-black text on it.

This is a *missing declaration*, not a wrong token — no theme is involved, which
is why it looks identical in every theme.

## Scope

One file: `src/frontend/components/UI/NavShell/components/FilterFacetGroup/index.scss`.

Out of scope: `Dropdown/index.scss` (shared with `MainButton` on the Game page —
changing it there would be an unrelated blast radius), and the facet rows
themselves (already correct).

## Tasks

### Task 1 — Theme `.FilterFacetGroup .dropdownButton`

**files:** `src/frontend/components/UI/NavShell/components/FilterFacetGroup/index.scss`

**action:** Extend the existing `.FilterFacetGroup .dropdownButton` rule (do not
add a second rule — one declaration site) with:

- `appearance: none; background: none; border: 0;` — removes the UA button chrome
  that is the reported defect.
- `color: var(--navbar-accent);` — overrides `_buttons.scss`'s `#161616` at
  higher specificity and matches `.FilterFacetRow`'s resting colour, so header
  and rows read as one panel.
- `cursor: pointer; user-select: none; border-radius: var(--space-3xs);`
- Section-header treatment from the validated sketch (004 `.grp-label`):
  `text-transform: uppercase`, `font-size: var(--text-xs)`,
  `letter-spacing: 0.1em`. `font-weight: var(--bold)` and the existing padding
  stay as-is.
- Hover: `background: var(--navbar-active-background); color: var(--filter-active-color);`
  — the exact pair `.FilterFacetRow:hover` already uses, so the header responds
  the same way a row does.
- `:focus-visible { outline: 2px solid var(--accent); outline-offset: -2px; }`
  — identical to `.FilterFacetRow:focus-visible`; the header is keyboard-reachable
  and must show it.
- Add a `transition` on `background-color`/`color` at the same `0.12s ease` the
  rows use.

**Token-survival constraint (the `--divider` / CR-01 defect class):** an
undefined custom property with no fallback drops the *entire* declaration at
computed-value time, silently, in whichever theme lacks it. Every token used
here is verified present:

| Token | Declared | Note |
|---|---|---|
| `--navbar-accent` | all theme blocks | already consumed bare by `.FilterFacetRow` |
| `--navbar-active-background` | 11 declarations in `themes.scss` = 11 theme blocks | already consumed bare by `.FilterFacetRow:hover` |
| `--accent` | all theme blocks | already consumed bare by `.FilterFacetRow:focus-visible` |
| `--filter-active-color` | declared file-locally at `index.scss:43` | the `var(--navbar-active, var(--accent-overlay, var(--accent)))` chain — reused, **not** re-declared, and no bare `--navbar-active` is introduced |

`--text-xs` (`_typography.scss:33`) and `--space-3xs` (`_spacing.scss:3`) are
global, unthemed.

**verify:**
- `grep -c "appearance: none" …/FilterFacetGroup/index.scss` → ≥ 1
- `grep -n -- "--navbar-active[,)]" …/FilterFacetGroup/index.scss` returns only
  the pre-existing line 43 chain (no new bare consumer → the `themeTokens`
  census gate stays green)
- `pnpm exec tsc --noEmit` clean, `pnpm exec jest NavShell` green
- Rule stays inside the `.NavShell__tier2Portal { … }` block (no app-wide leak —
  the 34.10 `.MuiTabs-root` incident)

**done:** The three headers paint on the panel surface with no button chrome,
uppercase and dim at rest, hover-lit and focus-ringed like the rows beneath them.

## Must-haves

- `.FilterFacetGroup .dropdownButton` sets `background`, `border`/`appearance`
  and `color` — the three properties whose absence is the defect.
- Every new declaration stays scoped under `.NavShell__tier2Portal`.
- No new bare `--navbar-active` consumer.
- NavShell test suite and typecheck stay green.
