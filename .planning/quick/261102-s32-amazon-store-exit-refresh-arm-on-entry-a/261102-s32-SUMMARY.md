# Quick 261102-s32: Amazon store-exit refresh, arm on entry, and nile awaits sync

## What changed

1. `armForUrl` (storeExitRefresh.ts): pure helper with injected logger. Logs `[<store>StoreExitRefresh] armed host=<hostname> via=<entry|nav>` once per arming, hostname only. Commit 3c067504c.
2. `useStoreEmbedHost.ts`: `noteVisitedUrl` goes through `armForUrl(..., 'nav')`. The `[storeKey]` effect resets the armed ref, then entry-arms from `startUrlRef.current` with `via=entry`. Existing tests unmodified (diff is additions only: 114 lines). Commit 0ae9213d6.
3. `nile/library.ts`: `refresh()` now `await this.refreshNile()` before `refreshInstalled` / `loadGamesInAccount` / `libraryStore.set` (F3). `refreshNile`'s catch kept, comment updated. New `refreshAwaitsSync.test.ts` (ordering, sync error, sync throw, rejected promise, signed-out).

## Decisions

- Entry URL is `startUrl`, not `navState.url`: on a store switch `navState.url` still holds the previous store's last URL, and arming from it would break the pinned "fires once per session" steam test. This deviates from the orchestrator's "navState.url, falling back to startUrl" suggestion.
- Consequence: a Steam/GOG/Epic `startUrl` restored from `last-url-<store>` to a product page now arms on entry (the page already shown counts as visited). Home and start pages never arm.

## Investigation: nile games missing on macOS

No filter-side cause found; the likeliest cause is the F3 stale publish.

- `loadGamesInAccount` hard-codes `is_mac_native: false` (nile/library.ts:113) and `platform: 'Windows'`. That only affects the Native chip / `nativeOnly` and runnability tier (`hasNativeBuild`, filterEngine.ts:85-93, `deriveRunnabilityTier` :132-175).
- Those filters are off by default: `DEFAULT_FILTER_ENGINE_STATE` has `nativeOnly: false`, `runnability: []`, `stores: []` (filterEngine.ts:524-527). So with defaults a nile game is not hidden. If the operator has Native or a runnability chip on, nile games would be hidden or tiered (rating-based; `null` tier if never looked up, :165-170).
- `showNonAvailable: 'off'` excludes `nonAvailableAppNames` (filterEngine.ts:404); that list is for installs whose path vanished, so uninstalled nile titles should not be in it (not verified live).
- Frontend reads the same store the backend publishes: `loadAmazonLibrary` -> `nileLibraryStore.get('library', [])` (GlobalState.tsx:452, :1325). Before this change `refresh()` published without awaiting the sync (library.ts, old line 326), so a just-claimed title was missing until a second refresh. Fixed by task 3.
- Unverified: whether the renderer-side `nileLibraryStore` sees sidecar writes immediately (I did not trace the store-sync path).
- Recommendation: if titles are still missing after the live retest with Native/runnability filters off, open a todo for the store-sync path. No todo created.
