<objective>
Kill the sidecar's EPIPE self-feeding spin loop at its source, and stop the test-harness leak
that most often arms it.

The `uncaughtException` guard in `processGuards.ts` formats `error.stack` and writes it to a
stream. When that stream is a pipe whose read end is gone, the write raises EPIPE
**asynchronously, as an `error` event on the stream** — structurally outside both of the guard's
`try`/`catch` halves. Node escalates an unhandled stream `error` into a fresh
`uncaughtException`, which re-enters the same handler, which formats and writes again. The
guard's (correct, deliberate) "never exit, never re-throw" doctrine is exactly what turns that
into an unbounded 100%-CPU loop rather than a crash.

Purpose: remove the loop's fuel (a dead pipe must never become an `uncaughtException` at all),
add a synchronous re-entrancy bound as defence-in-depth, and give the SEA-spawning test a reaper.
Output: two shipping-code edits, two test edits, one todo closed, one todo filed, and a live gate
with a negative control on the real binary.

This is a FIX plan for a diagnosis that is already complete and live-reproduced. Do NOT
re-investigate the root cause.
</objective>
