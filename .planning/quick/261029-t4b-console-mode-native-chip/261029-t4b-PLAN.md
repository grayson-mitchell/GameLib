<objective>
Add a "Native" chip to console mode's top-bar chip row. It filters the grid to games that run natively on the host, using the same predicate as the desktop Native chip (quick 261029-riq). It is hidden on Windows.

Purpose: console mode gets the same "what runs natively here" filter as the desktop library without a second copy of the rule.
Output: a pure `applyConsoleChipFilters` helper in selectors.ts with unit tests, plus the chip wired into ConsoleMode/index.tsx.
</objective>

<decisions>
- D-t4b-1 (toggle, not a pair): Native is an independent on/off toggle, the same shape as console mode's existing Installed chip. It combines with Installed and with the selected store. Desktop uses an All/Native pair, but console mode already uses its store row's "All" chip for "no store restriction". Adding a second "All" would put two "All" chips in one row, and the console Installed chip is already a single toggle, so Native matches that.
- D-t4b-2 (separate state): console Native is a local `useState(false)` (`filteringByNative`), exactly like `filteringByInstalled` today: not persisted, reset on every console mount, and independent of the desktop `libraryNativeOnly` config. Console Installed does not share the desktop `installedOnly` either, so Native follows the same pattern.
- D-t4b-3 (placement): the chip goes directly after Installed and before the vertical divider, so the row reads (Installed) (Native) | (All) (Epic) ... Both toggles sit together ahead of the single-select store group. That is "in front of the stores", and the divider keeps separating toggles from the store selector. L1/R1 `cycleStore` is unchanged and cycles stores only.
- D-t4b-4 (Windows): the chip is not rendered when `platform === 'win32'`. The helper also ignores `nativeOnly` on win32, because `hasNativeBuild` is always false there and a stray true would empty the grid. This mirrors desktop D-riq-1 (`platform !== 'win32' && nativeOnly`).
- D-t4b-5 (i18n): reuse `gamelib:library.filterPanel.native` ("Native") through the existing `tGamelib` with `'Native'` as the default. No locale edits, no new files, and so no gate-scope promotion. `ConsoleMode/index.tsx` is already in `meta/i18nGateScope.json` and `meta/i18nForkTouchedFiles.json`. `public/locales/en/gamepage.json` is not touched.
- Out of scope: backend 32-bit detection for GOG/Epic (quick 261029-t39). This plan only consumes `isHostNative` and does not edit filterEngine.ts.
</decisions>
