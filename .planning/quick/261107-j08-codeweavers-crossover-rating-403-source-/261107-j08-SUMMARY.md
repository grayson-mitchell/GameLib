# Quick 261107-j08: CrossOver rating sourced from the index only

CrossOver ratings now come only from the daily crossover index on macOS. The CodeWeavers page scrape (Cloudflare 403) is deleted.

## Commits
- a59daa19e: index-only lookup with three outcomes, macOS-only staleness, tests
- Task 2 commit (HEAD after a59daa19e): scrape deleted, `slugify` kept, todo moved to completed

## Behavior
- Index hit: rating returned, as before.
- Index loaded but title missing: returns `{macRating:null, linuxRating:null, slug:''}`. It is cached and the UI shows "Unrated". No codeweavers.com request.
- Index unavailable or lookup threw: `null`. It is not cached as a miss, so the next visit retries.
- Linux and Windows: no CodeWeavers request. `staleCrossoverData` is now `isMac &&`, so a Linux `codeweavers=null` entry is served from cache.
- Deleted `getInfoFromCodeweavers` and its helpers, plus `codeweavers/constants.ts`. `codeweavers/utils.ts` exports only `slugify`.

## Deviations
- The miss marker uses `slug: ''` instead of `slugify(title)`. With an empty slug the UI opens the CodeWeavers search, since a constructed slug page for an unrated title is likely a soft-404. `CodeweaversInfo.slug` is `string`, so common/types.ts is untouched.
- In `wiki_game_info.test.ts` I added `wikiGameInfoStore.use_in_memory()` to the first describe's `beforeEach`. Without it the cache assertions (unavailable retry, Linux no-refetch) would pass vacuously.
