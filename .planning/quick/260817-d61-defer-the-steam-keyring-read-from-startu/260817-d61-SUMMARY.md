# Quick Task 260817-d61: Defer the Steam keyring read from startup to first Steam user action Summary

**Steam's refresh-token keyring read is deferred off both startup paths (`init()`'s background sync and the mount-time `refreshLibrary`) and now fires only on a deliberate Steam action (Install, Update, Play, game-page open, explicit Refresh, Steam login); every `keyring_get` log line now carries `trigger=`/`elapsed=` so the hypothesised 9:1 prompt-timeout ratio can be re-measured on real hardware.**

## Performance

- **Tasks:** 3/3 completed
- **Files modified:** 13 source/test files, 3 new files

## Accomplishments

- Added `authTrigger.ts`, a leaf module with zero imports from `library.ts`/`games.ts`/`user.ts`/`keyringTokenStore.ts`, exporting the sticky unlock gate (`isSteamAuthUnlocked`/`noteSteamAuthTrigger`), the allowlist origin mapper (`mapRefreshOriginToTrigger`), and the Steam-inclusive-dispatch-only trigger recorder (`noteRefreshTrigger`).
- Widened `readToken()`/`readTokenOutcome()` with an optional `context` parameter, forwarded through `keyringTokenStore.ts`'s `fetchToken()` so every `keyring_get` issue/outcome/memo-armed log line carries `trigger=<label>` and (on issue/outcome) `elapsed=<ms>`, appended strictly AFTER the pre-existing `present=`/`len=`/`class=`/`ms=` substrings — none renamed or reordered.
- Threaded the frontend's already-computed `origin` through `refreshLibrary`'s IPC signature (`Runner | 'all', origin?: string`) to both backend handlers (Electron's `addHandler` and the Tauri sidecar's `handleRefreshLibrary`), each calling `noteRefreshTrigger()` as their first action — Steam-inclusive dispatches only (`'steam'`/`undefined`/`null`/`'all'`); a named non-Steam runner never unlocks the Steam gate.
- Flipped the gate: `SteamLibraryManager.refresh()` checks `isSteamAuthUnlocked()` as its first statement (before the `syncing` emit) and returns `null` + `steamSyncStatus: 'idle'` when locked — proven structurally to issue ZERO `keyring_get` on both startup paths, with a non-vacuous companion test proving the unlocked path still reads exactly once.
- `SteamGame.install()`/`update()`/`launch()` each call `noteSteamAuthTrigger()` as their first statement; `getExtraInfo()` unlocks on game-page open and fires exactly one bounded, fire-and-forget `SteamUser.ensureConnected()` on the locked->unlocked transition only — a second call fires none.
