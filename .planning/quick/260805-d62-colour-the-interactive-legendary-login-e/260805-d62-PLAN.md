<critical_finding>
## The red tile is NOT always the "Alternative Login Method" tile

The task description says to colour "the alternative login entry point". Reading the code shows that
would be **wrong under Tauri**, because Epic's two tiles swap roles by shell
(`src/frontend/screens/Login/index.tsx:166-180`, the F-34.5-G6-01 pivot):

| Shell | PRIMARY tile action | ALTERNATIVE tile action |
|-------|---------------------|-------------------------|
| Electron (`isTauri()` false) | `navigate(epicLoginPath)` — embedded web login | `setShowSidLogin(true)` — **SIDLogin** |
| Tauri (`isTauri()` true) | `setShowSidLogin(true)` — **SIDLogin** | `navigate(epicLoginPath)` — embedded web login |

Colouring "the alternative tile" would, under Tauri, paint the embedded **web** login red and leave
the interactive legendary login unmarked — the exact inverse of the intent.

**Resolution (implement this):** the marker follows the *SIDLogin action*, never the tile position.
Both source statements agree on this reading — the task description says "NOT the primary Epic web
login" (the web *login flow*, which is never SIDLogin in either shell), and ROADMAP 34.7 says the
thing being deleted is "the interactive legendary-login UI". So:

- Electron -> the **alternative** tile is red
- Tauri -> the **primary** tile is red
- The embedded web-login tile is red in **neither** shell

This is why Task 2 wires `deprecatedTile={isTauri() ? 'primary' : 'alternative'}` rather than
hardcoding a tile.
</critical_finding>
