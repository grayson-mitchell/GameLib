Facts found at plan time that the tasks depend on (from the 0.4.0 dist; do not re-derive):
- Every `gsd-graph sync`, including the detached one the hook starts, calls `init()`, and
  `init()` runs `appendGitignoreIfNeeded`. That function appends `.gsd-graph/` to .gitignore
  unless some line trims to exactly `.gsd-graph/` or `.gsd-graph`. The locked pattern
  (`.gsd-graph/*` + `!.gsd-graph/config.json`) contains neither, so on its own it would make
  every sync append a trailing `.gsd-graph/`. That line dirties .gitignore after every
  post-commit sync, and it re-ignores config.json for git and for prettier, which reads
  .gitignore. Task 1 therefore puts a no-op `.gsd-graph/` + `!.gsd-graph/` pair above the
  locked lines. This was tested in a scratch repo: git check-ignore and prettier --file-info
  both report config.json as not ignored and graph.v1.json / hooks/ as ignored.
- prettier 3.7.4 reads .gitignore. `.gsd-graph/config.json` is prettier-visible (json parser),
  so `.husky/pre-commit` checks it. `.gsd-graph/graph.v1.json` stays out of the pre-push
  `prettier --check .` only because .gitignore covers it.
- `.planning/config.json` round-trips byte-identically through `JSON.stringify(x, null, 2)`, so
  the rewrite by `gsd-graph enable` should add the `gsd_graph` block and change nothing else.
- The corpus resolver silently skips paths that do not exist, so a typo just drops a file without
  any error. All 35 named corpus paths exist at HEAD, and there are 104 spike READMEs.
- `gsd-graph sync` and `ask` make no LLM calls unless `--llm` is passed (`resolveLlmMode`
  returns `none` by default). `graphify update` is AST-only. Its `--force` only lifts the
  refuse-to-shrink guard.
- Package legitimacy was verified at plan time. `npm view @opengsd/gsd-graph@0.4.0` lists the
  same three maintainers as the already-installed @opengsd/gsd-core (trek-e, solvely-colin,
  jeremymcs). The package has no install or postinstall script. The user named the package and
  approved the global install. API-coverage, assumption-delta and schema detectors all skipped
  (no external API, no singular-to-plural shift, no ORM).
</objective>
