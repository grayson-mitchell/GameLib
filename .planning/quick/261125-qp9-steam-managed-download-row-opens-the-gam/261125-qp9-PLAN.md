<objective>
Clicking a Steam-managed download row's title opens the game page with its `gameInfo` in router state, instead of
navigating with no state and landing on the route error page.

The fix is at the row level only, per the scope decided for this quick task (do not widen it):
- Scope 1: the container (`SteamManagedItem/index.tsx`) keeps the `GameInfo` it already finds in `steam.library`
  by `app_name === row.appName` and passes it to the view.
- Scope 2: when a gameInfo is present, the view's title `Link` goes to `/gamepage/steam/${appName}` with
  `state={{ gameInfo }}`, the same shape as `DownloadManagerItem` and `GameCard`.
- Scope 3: when there is no gameInfo, the title is plain text with the same `steamManagedItem__title` class, not a
  link; `index.css` is checked so it still looks right.
- Scope 4: the view's own tests are extended (link carries the state; no link without gameInfo), and its prop types
  stay narrow (`gameInfo?: GameInfo`).
- Scope 5: GamePage is NOT hardened against missing `location.state`. That is a larger change (its render reads
  `gameInfo.*` synchronously, so it would need a loading state). It is named as a follow-up in the todo's Resolution
  and the SUMMARY only.
- Scope 6: the todo moves to `.planning/todos/completed/` with a `## Resolution (2026-11-25)` section.
