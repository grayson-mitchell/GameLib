<findings>
Verified during planning — the executor does not need to re-investigate these:

- Dependencies of the two components: both use only `useSetting` (needs a SettingsContext
  provider), `useTranslation`, and UI primitives. `UseDarkTrayIcon` additionally reads
  `useUiState((s) => s.platform)` (global zustand store, available everywhere) and calls
  `window.api.changeTrayColor()`. Neither reads `isDefault` from SettingsContext, neither uses a
  Settings-screen-only CSS class. Platform guards live INSIDE the components
  (`window.isSteamDeckGameMode` in UseFramelessWindow; `trayIconVariantOptions(platform)` empty
  on macOS in UseDarkTrayIcon) so they travel with them — do not add outer guards.
- `AccessibilityWrapper` (bottom of Accessibility/index.tsx) wraps the page in
  `SettingsContext.Provider value={useSettingsContext({ appName: 'default' })}` — the same
  provider shape the Settings screen gives General, so `useSetting` resolves the global config.
  Precedent: `LoginBackground` is already imported from `'../Settings/components'` and rendered
  on this page (it even depends on `isDefault`, which works here).
- Page root is `<div className="Accessibility Settings">`, so the `.Settings` descendant styles
  that style these controls under General also apply here.
- `ToggleSwitch` renders its own `label.toggleSwitchWrapper.Field`; `UseFramelessWindow` returns a
  bare ToggleSwitch. Render it bare, exactly as General did — do NOT wrap it in the page's
  `span.setting > label.toggleWrapper` (that would nest a label inside a label).
- Existing tests are unaffected: `framelessWindowCopy.test.ts` and
  `trayIconVariantSetting.test.ts` read the component files by path (components do not move);
  `gameStartWindowSetting.test.ts` reads GeneralSettings/index.tsx but only asserts
  `<GameStartWindow />` presence and absence of two unrelated names.
- i18n: no new strings are introduced (no new heading), so no catalog edit is needed and the
  churn guard on `translation.json` is not touched. Both edited source files are already listed
  in `meta/i18nForkTouchedFiles.json`, so no `gen-i18n-gate-scope` regeneration is needed.
- No settings-search index, tour step or help text references these settings' location
  (grep of src/frontend for framelessWindow/trayIconVariant found only runtime consumers).
- Both edited files report `{ "ignored": false, "inferredParser": "typescript" }` under
  `npx prettier --file-info`, so the scoped prettier check is meaningful.
