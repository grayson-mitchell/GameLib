# Quick Task 260721-u77 — Summary

## What changed

- `src/frontend/components/UI/CachedImage/index.tsx` — the rendered `<img>` now
  carries a `usingFallback` class whenever `fallbackIndex >= 0`, i.e. while a
  fallback source (not the primary `src`) is on screen. The existing src-keyed
  `useEffect` resets `fallbackIndex` to -1, so the marker clears automatically
  when the primary source changes.
- `src/frontend/screens/Library/components/GameCard/index.css` — added
  `object-fit: contain` for `.gameCard .gameImg.usingFallback` and
  `.gameCard.justPlayed .justPlayedImg.usingFallback`. Aspect ratios are
  unchanged, so tile geometry is identical; only the placeholder's scaling mode
  differs.
- `src/frontend/components/UI/CachedImage/__tests__/index.test.tsx` — new test
  asserting the class appears only while a fallback is displayed and clears on a
  new primary `src` (plus a `className` field on the test's `ImgElement` type).

## Root cause

The `gamelib_card_missing.svg` placeholder rendered through the same
`.gameCard .gameImg` rule as real cover art (`object-fit: cover`,
`aspect-ratio: 3 / 4`), so it was cropped to fill the tile. Cropping is correct
for real cover art and wrong for a branded placeholder. Nothing in git history
carried a prior fit-vs-crop distinction — the earlier change the user recalled
testing never landed on this branch.
