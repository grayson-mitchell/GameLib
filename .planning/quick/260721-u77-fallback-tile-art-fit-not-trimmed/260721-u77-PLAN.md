# Quick Task 260721-u77: Fallback tile art should fit, not be trimmed

## Problem

When a game has no usable cover art (e.g. Hoard), `CachedImage` walks its fallback
chain down to `gamelib_card_missing.svg`. That placeholder renders through the same
`.gameCard .gameImg` rule as real cover art — `object-fit: cover` with
`aspect-ratio: 3 / 4` — so the placeholder gets cropped instead of being shown whole.
Real cover art *should* be cropped to fill the tile; a branded placeholder should not.

## Tasks

### Task 1 — Expose fallback state from CachedImage
- **files:** `src/frontend/components/UI/CachedImage/index.tsx`
- **action:** Add a `usingFallback` class to the rendered `<img>` whenever
  `fallbackIndex >= 0` (i.e. the primary `src` failed and a fallback is showing).
  Reuse the existing `classNames` call alongside `loaded` / `loading`.
- **verify:** `yarn jest src/frontend/components/UI/CachedImage`
- **done:** `<img>` carries `usingFallback` only while a fallback source is displayed,
  and drops it when `props.src` changes (the existing `useEffect` already resets
  `fallbackIndex` to -1).

### Task 2 — Size fallback art to fit in GameCard
- **files:** `src/frontend/screens/Library/components/GameCard/index.css`
- **action:** Add `object-fit: contain` overrides for `.gameImg.usingFallback` and
  `.justPlayedImg.usingFallback`. Keep the aspect-ratio so tile geometry is unchanged.
- **verify:** Placeholder renders whole (letterboxed inside the tile) rather than cropped.
- **done:** Only fallback art is `contain`; real cover art still `cover`.

## Non-goals

- No change to the fallback chain order or to the placeholder SVG assets.
- No change to StoreSearch/Discounts cards (they use `CachedImage` but their CSS does
  not target `usingFallback`, so behaviour there is unaffected).
