# Quick Task 261002-b63: Move the Console Mode entry into the Games library filter panel Summary

Moved Console Mode from a three-clicks-deep Settings nav row into an icon-only control at the top of the Games library's tier-2 panel (`Header`), reusing the shipped `sidebar.console` i18n key and this repo's canonical two-arm focus indicator — no new strings, no new packages.

## What Was Built

**Task 1 (tracer, TDD):** Added `.Header__utilities` as the first child of `Header`, containing one react-router `Link` to `/console` with `aria-label`/`title` sourced from `t('sidebar.console', 'Console Mode')`, rendering a `faTv` `FontAwesomeIcon`. It sits above the existing `Header__search` child. CSS gives it `color: inherit` (no new token), a `var(--navbar-active-background)` hover (theme-safe, declared in all 11 primary theme blocks), and the standard two-arm focus rule (`:focus-visible, :focus:is(body.controllerLayout *)`) consuming the shared `--focus-ring-*` custom properties. `justify-content: flex-end` on `.Header__utilities` is the new alignment decision (see Decisions above).

Tests: `headerTourAnchors.test.tsx` now asserts four direct children of `Header` (was three), adds a Console Mode `Link`-identity test (`to`, `aria-label`, `title`, exactly one `FontAwesomeIcon` child) and a test asserting no `data-tour` attribute on that `Link`. `focusIndicator.test.ts` adds `.Header__consoleButton` to `TARGETED_RULES`/`sourceForSurface` (read as raw CSS, following the `gamePageCss` precedent, not folded into `NAVSHELL_COMPILED_CSS`) with a dedicated assertion that it is not grouped behind any other selector's hover/focus rule.

**Task 2 (auto, TDD):** Removed the `/console` `NavItem` row and the now-unused `faTv` import from `SettingsPanel`. Updated its doc comment to describe two reparented rows instead of three, explaining Console Mode's new location without naming any retired helper/predicate identifier (the file is covered by a zero-match grep completeness gate). `SettingsPanel.test.tsx` and `destinationCoverage.test.tsx` both gained a positive `not.toContain('Console Mode')` assertion (removed from the destination-union `toEqual` array and asserted absent from the union separately), per the plan's `must_haves` requirement that the absence be asserted positively rather than inferred from a shorter list.
