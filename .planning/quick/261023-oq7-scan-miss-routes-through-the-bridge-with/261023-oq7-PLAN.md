<objective>
Implement the user's two decisions of 2026-10-23.

1. A persisted scan miss no longer routes to bottled Steam. It routes to the bridge, carrying its missing symbols, behind a one-time informational notice. A title that is also known-bad gets one combined dialog.
2. "Place shim anyway". When the shim does not cover a title, install keeps the download and places the shim, and launch runs it. A miss no longer deletes the bottle, arms the circuit breaker, or offers bottled Steam.

Expected consequences: static-import misses will fail at load with a Windows entry-point error, by design, and their missing symbols are recorded. Runtime-loaded misses may play. The census stays honest about which titles are routed, covered and verified.

Purpose: per the user, bottled Steam is a narrow fallback the project means to eliminate. The recorded missing symbols drive shim widening.

- reordered resolver
- placement-on-miss in shimGenerate.ts
- install, launch and notice-gate changes in games.ts

- Route and reason are already independent axes. Since 261023-og0, 'known-bad' appears on both routes.

  - persisted `noticeAcknowledgedFor` values
- A new union member would force entries in both `Record<SteamBridgeRouteReason, string>` REASON_KEYS maps (steamBridgeRouteLine.ts:47, bridgeRouteDisplay.ts:46), add a new catalog key, and require regenerating the presence baseline across 48 locales. It would carry no information the route field does not already have.
- The existing copy is route-agnostic. `steam.bridge.route.reason.scanMiss` and `routeNotice.scanMiss` never mention bottled Steam, so the route line renders correctly as "Native Steam bridge -- <scanMiss>" plus the symbols.
- The census classifies from the exe, not from the reason.

**Placement on a miss (shimGenerate.ts).** Today a coverage miss returns `{status:'miss'}` BEFORE `copyFileSync`, leaving the target untouched. The runtime-loaded CR-04 branch returns 'miss' without placing anything.

Replace the `'miss'` result variant with `{ status: 'placed-miss'; shimPaths: string[]; verdict: SteamBridgeScanVerdict }`, where verdict.status is 'miss'. Make it unconditional rather than an opt-in flag: both production callers want it, and an always-false option would be test scaffolding. The TS union change forces both games.ts call sites to be revisited.

What must NOT weaken:
- Every T-24-06 guard (numeric appId, sanitized bottle, exe containment) still runs first.
- The `shim-not-built` check still runs before anything is copied. A missing x64 source still returns `{status:'shim-not-built', arch:'x64'}`, so the win64-no-shim branch is untouched.
- The D-UAT-24-04 byte-identity guard still short-circuits to 'already-placed' with no verdict, which keeps the persisted miss.
- The D-51-07 interface-version capture still reads the ORIGINAL dll before it is overwritten, so a later stale-shim refresh has persistedInterfaceVersions.
- `isGameLibShimBytes` identity is still how an older GameLib shim is recognized.
- The miss is still logged, as logWarning rather than logError, with "placing anyway (quick 261023-oq7)". Drop the "target file is left unmodified" claim.

Static miss: run coverage exactly as today. If missingSymbols is non-empty, still `copyFileSync` and return 'placed-miss' with the same verdict fields today's 'miss' carries.

Runtime-loaded (CR-04) miss:
- Change `findRuntimeLoadedSteamApiDlls` to return entries `{name, path, isGameLibShim}` instead of skipping GameLib shims.
- For each non-shim entry, pick the source by name: steam_api.dll takes the x86 shim, steam_api64.dll the x64 shim. If any needed source is missing, return `shim-not-built` with that arch.
- Copy the shim over each non-shim entry and return 'placed-miss' with today's marker verdict (`<dll>@runtime-loaded`, interfaceVersions {}).

**The runtime-loaded downgrade hazard this creates must be closed in the same change.** Once the shim sits where the game's dll was, the old walk skipped GameLib shims and would return 'no-steam-api' with a CLEAN verdict on the next launch. That would do two things:
- overwrite the persisted miss and its marker (the census and the resolver lose it)
- send launchBridgeGame down its no-helper branch, leaving a placed shim with no helper to talk to

So, in the arch-'none' branch:
- When the walk finds GameLib-shim entries and no non-shim entries: if every shim entry is byte-identical to the current built source, return `{status:'already-placed', shimPath: <first>}` with NO verdict. Otherwise re-copy the stale ones and return 'placed-miss' with the marker verdict, built from the entry names.
- Return 'no-steam-api' only when the walk finds no steam_api*.dll entries at all.
- The CR-04 never-downgrade rule in `reconcileBridgePrescreen` (games.ts:1668-1697) is kept. Add 'placed-miss' to its upgrade condition (a persisted 'none' is upgraded to the verdict's arch, because a shim is now placed). It never writes 'none' over a real arch.

The isWin64NoShim branch stays byte-for-byte as it is today, including its `setBridgeUserRoute(undefined)` clear, bottle deletion, breaker and 'win64-no-shim' message.
- D-51-11's `setBridgeUserRoute(undefined)` is NOT applied on 'placed-miss'. It existed so a forced 'bridge' would not be re-forced into the same failing miss. A miss is no longer a failure, so the user's explicit 'bridge' choice is kept. Say so in the comment.

**Census honesty.** The live resolver now also routes 'missing-symbols' and 'unknown-version' titles (version problems reach the persisted scan as missing symbols) and non-DRM 'known-bad' titles to the bridge, and they are now actually placed and launched.

**Technical caveat to write in substance** in bridgeRoute.ts (row 7), shimGenerate.ts (placed-miss) and 51-CONTEXT.md:
- Routing and launching a miss is deliberate. Per the user, bottled Steam is a narrow fallback to eliminate.
- An exe whose STATIC imports the shim lacks will most likely fail at load with a Windows "entry point not found" error. That is expected by design, and the recorded missingSymbols drive shim widening.
- A `<dll>@runtime-loaded` marker (51-22, CR-04) is a miss without that load-time failure, and such titles may play.
