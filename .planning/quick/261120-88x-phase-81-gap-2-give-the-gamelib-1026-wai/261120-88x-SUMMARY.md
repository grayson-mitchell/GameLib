# Quick 261120-88x: Phase 81 Gap 2, "Restart Steam now" at the GameLib 1026 edge

The no-record "Restart Steam now" press now starts Steam (not running) or runs the existing graceful restart (running) at the GameLib 1026 waiting edge, with the D-05 refusals intact.

## Mechanism

- `runRestartNow`'s no-record branch calls `runWaitingEdgeRestart`. It asks Rust `steampoll_status` (via `invokeSteamPoll`) for a non-delegated install poll on the appId (`hasGameLibInstallPoll`). The `steam-waiting-for-restart` context is emitted only by that poll, and AdoptionNote shows the button without a record only there, so this is the backend's own evidence of the edge. The renderer supplies no flag, so no IPC, preload, Rust, frontend or locale file changed.
- No poll, another appId's poll, a delegated poll, a malformed answer or a rejected invoke all answer 'no-record' with nothing touched.
- Steam running: `restartSteamForAdoption` byte-for-byte (graceful `steam://exit`, 30 s wait, then `steam://open/main`). Steam not running: `startSteamForWaitingInstall` runs the same two D-05 guards (game running, wrap owed), then relaunches with `steam://open/main` alone. A failed process probe counts as running.
- `emitStatus`/`emitDone` are no-ops on this path (the Rust poll owns the game status). No record written or cleared, no adoption unwatch. Refusals reuse `pushAdoptRestartRefusal(..., false)`.
- The record path now builds its deps via the extracted `restartDepsFor` (field list moved verbatim); every pre-existing test passes unmodified and it never reads poll status.
