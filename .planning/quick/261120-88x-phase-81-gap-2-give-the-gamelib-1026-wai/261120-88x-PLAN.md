Phase 81 Gap 2 (81-VERIFICATION.md, truth "D-02: wherever the page shows 'Restart Steam now', pressing it restarts Steam"). At the GameLib 1026 waiting edge, AdoptionNote shows "Restart Steam now". The edge is an install whose ACF reads StateFlags exactly 1026 while GameLib's native-handoff install poll is on it, with status context `steam-waiting-for-restart`. Pressing the button reaches `runRestartNow`, which today answers 'no-record' and does nothing, because no pending-adoption record exists when Steam was not running at install end. Per the operator's D-02: wherever the button is shown, pressing it must restart Steam (start it if it is not running), with no record required. The D-05 refusal guards still hold, and the with-record path stays unchanged.

Mechanism (chosen from the code, smallest correct; record it in the SUMMARY):
- The backend decides the edge itself. It does not take a renderer flag.
- The status context `steam-waiting-for-restart` is emitted only by the Rust install poll (`install_once.rs`: StateFlags 1026 plus `is_native_handoff`). Rust's existing `steampoll_status` op lists active install polls (`PollStatus.installs[].appId` and `delegatedToSteamClient`).
- AdoptionNote renders the button for exactly two states. One is `installedPending`, which needs a record. The other is `waitingForRestart`, which needs an active poll.
- So "no record" plus "a GameLib-owned install poll for this appId" is the backend's own evidence that the press came from the 1026 edge. Anything else stays 'no-record'.
- This needs no new IPC channel or argument and no preload, frontend or Rust change, so the IPC inventory (`IPC-PORT-INVENTORY.md`, `ipc_contract.rs`, the zod tuple in `src/common/types/ipc/steam.ts`) is untouched. It also keeps the module's rule that the frontend never derives adoption.
- Steam not running is handled without `steam://exit`. A `steam://` URL sent to a stopped Steam launches the client to handle it, and the 30 s quit wait would then time out. Steam running reuses `restartSteamForAdoption` byte-for-byte.
