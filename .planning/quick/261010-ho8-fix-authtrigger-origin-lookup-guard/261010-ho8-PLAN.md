<objective>
Close 49-REVIEW WR-04: `mapRefreshOriginToTrigger` in `src/backend/storeManagers/steam/authTrigger.ts`
indexes the module-scoped `ORIGIN_TO_TRIGGER` allowlist (a plain object literal, so it inherits
from `Object.prototype`) with a renderer-supplied `origin` string and no own-property check. A
crafted `origin` of `'__proto__'` or `'constructor'` therefore resolves to `Object.prototype` or
the `Object` function instead of `undefined`, slips past the `?? 'startup'` fallback, and is stored
as `lastTrigger`. That breaks `currentTriggerLabel()`'s documented "never undefined, a log label"
string contract and can write `[object Object]`-style noise into the `keyring_get` log lines. The
gate itself still fails closed (`DELIBERATE_TRIGGERS.has()` rejects both values), which is why the
finding is a warning and not a security defect.

Purpose: make the lookup use the own-property-guarded pattern this repo already uses for the same
class of untrusted-string-as-key input, `Object.prototype.hasOwnProperty.call(map, key)` before
bracket access (`steamFlowRegistration.ts` lines 176 and 324, `appShellFlowRegistration.ts` line
599, `sanitizeSignInProbeOutcomeMap` in `src/common/signInState.ts` line 133).

Output: the guarded lookup, regression tests that are red before the fix and green after it, the
todo moved to `completed/`, and WR-04 recorded `fixed` in `49-REVIEW-DISPOSITION.md`.
</objective>

Decisions made during planning, with the evidence behind them:

- **A `hasOwnProperty` guard, not a null-prototype map.** The guard is the repo's dominant
  existing form for this exact input class: four call sites, all spelled
  `Object.prototype.hasOwnProperty.call(...)`, never `Object.hasOwn` and never `in`. It is also the
  smallest diff, and it leaves `ORIGIN_TO_TRIGGER`'s declared type
  (`Readonly<Record<string, SteamAuthTrigger>>`) and the function's `SteamAuthTrigger` return type
  unchanged. `steamFlowRegistration.ts` lines 314-319 already record why `in` and a bare index
  truth test are both wrong here: `in` matches inherited names, and a bare index returns
  `constructor`/`toString`/`valueOf`/`hasOwnProperty` as functions.
- **Also reject a non-string `origin`, inside the same function.** The only production caller is
  `steamFlowRegistration.ts` lines 164-165, which pass `args[1] as string | undefined | null`, an
  unchecked cast from the IPC payload. A bracket index or `hasOwnProperty` call coerces its key to a
  string, so an array `['login-success']` currently reaches the `'login'` entry. That gives the
  renderer no capability it lacks (it can send the string itself), but it is the same
  key-coercion class as WR-04, and the launch guard at `steamFlowRegistration.ts` lines 320-325
  already pairs `typeof x !== 'string'` with the own-property check. The change stays inside
  `mapRefreshOriginToTrigger`, as the task scope requires.
- **Test command form.** `npx jest --selectProjects Backend <bare path>` silently drops the path

  planning: 1 suite, 35 tests, all green.
