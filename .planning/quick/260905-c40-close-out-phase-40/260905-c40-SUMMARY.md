# 260905-c40 — Close out Phase 40

## The finding

**`pnpm test:ci` was RED at the moment Phase 40 was about to be closed**, and the phase's own
verification is the reason it was still red: `40-VERIFICATION.md` recorded, honestly, that the
full suite CI runs had never been reproduced locally. Running it found one failing suite,
`src/backend/__tests__/tauriShellSource.test.ts`:

```
● D-35-29-01 (quick q93) the census arm falls back to the label-independent
  default-store read for Epic domains
  › POSITIVE: the real census arm satisfies every fallback requirement
    + "the Epic fallback guard (existing_window.is_none() &&
       epic_cookie_domain_matches(domain)) is missing"
```

**The code was correct and the gate was wrong.** Plan 40-04 deliberately widened the
`humble_login_cookies_for_domain` fallback guard (D-15 / T-40-04-07/-08) so GOG and Amazon reach
the same no-window census path Epic already had:

```rust
if existing_window.is_none()
    && (epic_cookie_domain_matches(domain)
        || store_logout_cookie_domain_matches(domain))
```

Phase 35's pin asserted the whitespace-collapsed **bare substring**
`existing_window.is_none()&&epic_cookie_domain_matches(domain)`. The added parenthesis broke it.
This is the recorded "a gate can convict CORRECT code" shape, and its twin — a `toContain`-style
pin catches deletion but is defeated by extension.

## Ownership: proven, not assumed

Red-at-HEAD is not the same as caused-by-this-phase, so the tree was varied against a constant
commit rather than reasoned about:

```bash
git -c core.hooksPath=/dev/null worktree add --detach /tmp/p40base 8ac3a8c12
```

At `8ac3a8c12` — the last commit before Phase 40's first — the suite is **GREEN, 138/138**, and
the guard there is verbatim the un-parenthesised shape the pin wanted. **Phase 40 caused this.**

⚠ **The process finding is larger than the bug.** Three earlier quick tasks each ran into this
exact failure and each recorded it as **"pre-existing"**:

- `260905-fast` — "2 `tauriShellSource.test.ts` failures pre-existing"
- `260905-ew2` — "⚠ 2 `tauriShellSource.test.ts` failures PRE-EXISTING at HEAD, proven by stashing"
- `260905-glr` — "present in baseline, unchanged after… different defect, a formatting commit
  should not absorb it"

Every one of those statements was **locally true** — it *was* already red at each of their HEADs,
and each task was right to refuse to absorb an unrelated fix. Collectively they were wrong:
"pre-existing" was measured against the immediately-prior commit, never against the pre-phase
baseline, so nobody bisected it, no todo was filed, and `.github/workflows/test.yml` stayed red
across four consecutive tasks with no owner. **"Pre-existing" is a claim about a baseline, and it
is only as good as the baseline chosen.**

## The fix

Match the guard **expression** instead of one spelling of it:

```ts
const guardCondition = noWs.match(/existing_window\.is_none\(\)&&([^{]*)\{/)
if (!guardCondition?.[1].includes('epic_cookie_domain_matches(domain)')) { … }
```

This still requires the `existing_window.is_none() &&` conjunction and the Epic check inside the
conjoined condition, while tolerating further OR'd terms and operand reordering.

**Two narrowness tests**, because relaxing a pin is only safe if it still convicts what it exists
to catch — and neither mutation below is caught by any other check in the violation list (both
still bind `existing_window` and still reach `default_data_store_cookies_for_domain`), so a false
PASS would have been invisible everywhere else in the suite:

1. Keep the disjunction, **drop the Epic term** → still RED.
2. **Sever the `is_none()` conjunction** → still RED.

Both are anchored on the census arm's own `return default_data_store_cookies_for_domain(...)`
line. **This mattered:** the clear arm at `main.rs:6727` carries a byte-identical guard, so a
plain `.replace()` edits the *first* (clear-arm) occurrence, leaves the census arm untouched, and
the test then fails for a reason unrelated to what it asserts. Each test also asserts
`expect(mutated).not.toEqual(code)` first, so a no-op edit cannot pass for the wrong reason.

`tauriShellSource`: 138 → **141/141**.
