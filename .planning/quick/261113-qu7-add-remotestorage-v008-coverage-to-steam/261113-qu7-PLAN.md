<objective>
The bridge withholds its shim from Dungeons of Dredmor (98800), so the game launches with no Steam
and the launch counts as bridge-unverified. The cause is that Dredmor's original
`steam_api.dll` hands out `STEAMREMOTESTORAGE_INTERFACE_VERSION008` from its bare `SteamRemoteStorage`
accessor, and the x86 shim does not serve that version. This plan serves it the same way 51-14
served RemoteStorage 005/010: a manifest extracted from Proton's pinned lsteamclient tree, mode
`'stub'`, with cloud disabled. It also records Dredmor's real measurements as fixtures and proves
with an acceptance test that Dredmor's import set has no unservable versions left.

Purpose: resolve `.planning/todos/pending/2026-11-13-bridge-shim-remotestorage-v008-unservable.md`
(74-UAT item 18).
Output: one new manifest, two Dredmor fixtures, a widened `shimCoverage.ts`, a regenerated shim that
compiles, a Dredmor acceptance test, and the todo deleted.

Precedent: quick task 261021-pgx (Hoard, commits `e9519488d` and `8628ea5a7`) and 51-14
(`47d900401`, the 005/010 stub manifests). This plan follows the same shape. It differs in one way:
the new manifest is **stub** mode, so unlike Hoard's wire manifests it gets **no** hand-added
`helperInterface`. `isteamremotestorage005/010.manifest.json` carry none, and `generateDispatchHeader`
requires one only for wire-mode manifests.
