<objective>
Ship "Launch without Steam" for Steam games that do not use the Steam API and carry no Steam DRM
wrapper, per the todo `.planning/todos/pending/2026-11-07-launch-steam-games-without-steam.md`
(the spec — read it in full first).

Purpose: every Steam launch today needs the Steam client (`steam://rungameid` for Mac-native,
bridge forwarding to Mac Steam for Windows games). Games that never call Steam can run directly,
like Epic's offline launch.

Output: an eligibility verdict (PE + Mach-O, reusing the bridge's detection), cached per install
on buildid; a direct launch path (Mac-native natively, bridge games in their bottle without
forwarding); two sidecar IPC channels; a verdict-gated sub-menu entry with a what-you-lose
confirm; the todo closed with its live gate recorded as owed (not claimed).

Scope notes (decided here, Claude's discretion):
- Host: macOS only. The todo is `platform: macos` and names exactly two install kinds — Mac-native
  and bridge. Every other host/route returns an ineligible verdict (`host-unsupported` /
  `route-unsupported`); the bottled-Steam (GameLibSteam) route is not a direct-launch target.
- The todo's "optionally add a curated allowlist of Steam-API games confirmed live" is NOT built:
  it is explicitly optional and no live-confirmed entry exists yet to put in it. Steam-API games
  stay on the Steam launch.
- Hard boundary (todo + spike-findings DRM boundary): nothing here writes, copies, replaces or
  emulates `steam_api`. Detection only reads.
