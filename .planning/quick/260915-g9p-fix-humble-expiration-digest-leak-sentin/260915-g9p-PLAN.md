<design_decisions>
Decided during planning so the executor does not re-litigate them:

**D-1 — Close the timezone axis by making the assertion zone-agnostic, NOT by
pinning `TZ`.** Setting `process.env.TZ = 'UTC'` in the test file would work
(jest sandboxes `process.env` per test FILE, so it would not leak) but it is
fragile: it depends on Node re-reading `TZ` after module evaluation and on no
`Date` being constructed first. Pinning `TZ` in `jest.config.js` would change
every backend suite — far outside this scope. Instead, compute the expected date
in the test with the SAME `new Date(iso).toLocaleDateString()` call. Both sides
then shift identically under any host zone AND any host locale. Do NOT add a
`TZ` pin.

**D-2 — The structural assertion is exact equality of the whole body.** This is
the todo's direction item 2, and it subsumes substring absence: if ANY token
beyond the permitted `title`/`expiration` render appears in the body, equality
fails. Note explicitly in a code comment that this deliberately does NOT assert
date *correctness* (F-7) — the expected value is rendered by the same call as
the value under test, so it is a leak/composition assertion, not a date
assertion. Without that comment the next reader will mistake a self-consistent
render for a correctness claim.

**D-3 — Keep the named negative assertions as well, and order them FIRST.**
`toBe` alone would catch a leak, but it reports as a large diff. The
`not.toContain(<sentinel>)` assertions name the threat and fail with a message
that says what leaked. Put them BEFORE the `toBe` so a real leak reports as the
specific sentinel failure. They are also the assertions the Task 2 negative
control exercises.

**D-4 — GREP HYGIENE: do not write the old expression verbatim in a comment.**
A verify step greps for the removed `not.toContain('7')` expression. If the
explanatory comment quotes that expression literally, the grep gate is satisfied
by the prose that names it and stops meaning anything (a recorded repo failure
mode). Describe it as "the bare single-digit sentinel" in prose; never retype
the expression.
</design_decisions>
