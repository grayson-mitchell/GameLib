## What changed

- **WR-02** `location_keys` returns no keys for a non-absolute reference (skipped). An absolute one that `canonical_location` cannot resolve is placed by the new `safe_path::lexical_reference_location`, so it still refuses a target at or inside it (is-protected-root / nested-known-install) and no longer blocks an unrelated removal. A dotted unresolvable reference stays `unknown(canonicalize-failed)`. `may_skip` (no trust root) now needs at least one absolute protected root, so relative-only requests answer `no-trust-root`.
- **WR-06** `check_sideload` also refuses `folder-looks-shared` when a real top-level sibling directory (not the game's own entry, links not descended) holds an executable-looking file or `.app` at its own top level. One level only; `Data/` and `Engine/` with an exe two levels down still pass.
- **IN-01** `is_link_metadata` is `FileType::is_symlink()` alone. The reparse-bit helper pair is gone. Name-surrogate tags (symlink, mount point) are links; cloud, dedup and WOF directories go through `remove_dir_all`.
- **WR-05 (TS half)** `refuseUnsafeCopy` refuses an installed copy it cannot place (no installPath, or `copyInstallRoot` null) with `canonicalize-failed`; `remove_copy` is not called. Absent, downloading and unknown still reach `remove_copy`.
- **WR-09** `cancelDelete.ts` keeps the raw `rmSync` and the Phase 75 synchronous section and adds `changedSinceCheck` (a synchronous `lstatSync` against the verdict's `absent`/`isLink`) immediately before the delete; a mismatch refuses with "install root changed since the safety check" and keeps manifests and breadcrumb. `removePerGameBridgeBottle` re-runs `checkRemoval` after `cxbottle --delete` returns and reports `error` (not `removed`) when the guard now objects.
- **IN-02** the refused bottle removal passes kind `remove-bottle`. No i18n change was needed, so `public/locales/en/gamelib.json` (which carries unrelated uncommitted edits) was not touched.
- **IN-03** a second-stage sideload `refused` outcome returns `refused: true` with a `refused` notice; other outcomes keep `failed`.
- **IN-04** the known-install list also carries Steam in-progress installs: `join(steamResumeTargetSteamappsDir, 'common', steamResumeInstalldir)`, else a `steamResumePending` entry's `install_path`. legendary, gog and nile entries take install info from the store's installed list written at completion, so their in-progress installs are outside D-16 (written in the docstring). **Never-loaded versus empty:** `LibraryManager` has no loaded signal, and an empty list is the permanent state of a store the user never signed in to, so returning null on empty would make every removal unknown for most users; an empty list stays empty and the reason is in `knownInstalls.ts`.
- **IN-05** `cargo-test` has `timeout-minutes: 45` with a reason comment, pinned by a new test in `rustTestWorkflow.test.ts` (mutating 45 to 46 makes it fail). RUSTSEC-2026-0545 (AES authentication code skipped on short or empty data, patched zip >= 9.0.0) and -0548 (ZipStreamReader local-header names, patched zip >= 9.0.5) each carry their own reason. Both rustsec.org pages were re-fetched on 2026-11-21 and the facts held. cargo-deny is not installed locally, so the ignores themselves were not exercised (deny.toml parses with tomllib).
