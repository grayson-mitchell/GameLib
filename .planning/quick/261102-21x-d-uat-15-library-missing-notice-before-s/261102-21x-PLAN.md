<objective>
Fix D-UAT-15. On Phase 21 UAT 4a (Steam client absent) and 4b (installed, never launched), clicking
Install first shows the options dialog with `steam.install.libraryMissingOnlyNotice`. The correct
D-10/D-11 client-setup prompt only appears after the user clicks Install in that dialog. The
operator said "the first error window should be skipped, the second is the relivent error". They
also said the notice's reconnect-the-drive sentence wrongly assumes a removable drive.

Root cause (orchestrator-verified, line numbers re-checked by the planner): `startSteamQuickInstall`
runs D-24's local check against the primary library's `steamappsDir`. Backend `getSteamLibraries()`
always yields the configured default Steam path, plus a hardcoded fallback, even when
`libraryfolders.vdf` does not exist. With Steam absent, or never launched, that `steamappsDir` does
not exist, so `validPath: false` produces a spurious `library-missing` degrade. The real
precondition check, `ensureSteamClientReady`, runs only inside `runNativeDepotDownload`, which means
it runs only after the click.

The fix: on the library-missing branch only, ask the backend first via the existing
`steamClientSetupRecheck` channel. That channel runs the same `ensureSteamClientReady` the click
would run, and it sends the same push. If the backend reports a client-setup precondition, return
without opening the degrade dialog. Then reword the two drive-assuming strings, and record the fix
on the todo.

Purpose: SNI-06 (D-10/D-11) is unreachable as a first prompt on a fresh machine, and the user is
shown a false diagnosis before the true one.
Output: the gated `startSteamQuickInstall`, Group U specs, reworded desktop and console copy, the
D-UAT-15 todo re-triaged to `ready: live-gate`, and one follow-up todo for Console Mode.
</objective>
