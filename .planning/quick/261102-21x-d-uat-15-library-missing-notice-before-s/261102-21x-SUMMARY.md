# Phase quick-261102-21x Plan 01: D-UAT-15 library-missing notice before Steam client setup Summary

With the Steam client absent or never launched, Install now goes straight to the backend client-setup prompt instead of first showing a spurious "library couldn't be reached" dialog.

## What changed

`startSteamQuickInstall` now, on a library-missing verdict only, awaits a module-private `steamClientSetupPending(appName)` helper. The helper calls `window.api.steamClientSetupRecheck` (the same `ensureSteamClientReady` the click reaches through `runNativeDepotDownload`, sending the same `steamClientSetupRequired` push). It returns true only for `ready === false`, no `error`, and status `needs-install` or `needs-launch`. In that case the function returns without opening the options dialog. A rejection, an `error` verdict, or `ready` falls through to the D-24 degrade, unchanged. The frontend still never opens SteamClientSetup itself.

## Accepted consequences

- macOS bottle-route ordering: on a bottle-routed title with no native Steam, the client-setup prompt can now appear before the CrossOver / bridge / bottle checks `install()` makes first. Every prompt is still a real precondition. Recorded in the function's doc comment and the D-UAT-15 todo.
- Console Mode scoping: not gated, because `SteamClientSetup` is mounted only in `App.tsx`'s non-console branch (a push would open an unmounted store, a silent failure D-29 forbids).
