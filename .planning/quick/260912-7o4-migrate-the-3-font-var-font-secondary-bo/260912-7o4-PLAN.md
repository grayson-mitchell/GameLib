# Migrate the three `--font-secondary-bold` call sites

## What the todo reported, and what is actually true

The todo is correct on its facts: three shared stylesheets set `font: var(--font-secondary-bold);`
and no `--font-secondary-bold:` declaration exists anywhere in the tree. Its line number for
SearchBar has drifted (89 → 97, moved by `e368075c3`); the other two are unchanged.

Investigation established the thing the todo could not: **why** the token is missing, which
decides between its two suggested fixes.

`git log -S "--font-secondary-bold:"` finds the declaration and its deletion. It was defined in
the `html` block and removed by upstream Heroic commit `b6f3da757` ("[Tech/Refactor]
Frontend/design system (#1851)", Oct 2022), together with its whole family:

```css
--font-primary-regular: var(--actions-font-family) normal 400;
--font-primary-bold: var(--actions-font-family) normal 500;
--font-primary-bolder: var(--actions-font-family) normal 700;
--font-secondary-regular: var(--content-font-family) normal 400;
--font-secondary-bold: var(--content-font-family) normal 500;
--font-secondary-regular-italic: var(--content-font-family) italic 400;
--font-secondary-bold-italic: var(--content-font-family) italic 500;
```

That refactor replaced the vocabulary with the one in `src/frontend/styles/_typography.scss`
(`--primary-font-family` / `--secondary-font-family`, and the numeric weight scale
`--light`/`--regular`/`--medium`/`--semibold`/`--bold`/`--extrabold`). It migrated most call
sites and missed these. So option 1 in the todo — re-declaring the token — would resurrect a
vocabulary that was deliberately retired. **Option 2 (longhands on the live tokens) is the fix.**

Two facts that fix the *values*:

1. `--font-secondary-bold` meant `--content-font-family` at weight **500**. In the live scale
   500 is `var(--medium)`, not `var(--bold)` (which is 700). "Bold" in the old token names was
   a slot label, not a weight.
2. `--content-font-family` is itself dead. `GlobalState.tsx:528-542` sets
   `--primary-font-family` / `--secondary-font-family` at runtime from the Accessibility font
   pickers; the old `--content-`/`--actions-` names are never declared. The live equivalent of
   `--content-font-family` is `--secondary-font-family`.

## Why the declaration is inert today, not merely wrong

`font` is a shorthand. `var(--font-secondary-bold)` resolves to nothing, so the declaration is
invalid at computed-value time, which per CSS Variables §3 makes every longhand it covers
compute to `unset` — for the font longhands, all inherited, that means `inherit`. So these three
rules currently contribute nothing and the elements take their ancestor's font.

Worth recording: even when the token *was* declared, its value `var(--content-font-family) normal
500` was not a legal `font` shorthand (no `font-size`, and family must come last). These
declarations have therefore never applied, in this repo or upstream, since at least 2022.

## Rendering delta this fix introduces

Restoring a four-year-dead declaration is a visible change, so state it up front rather than
discover it later:

- **Weight 400 → 500** on `.searchBarInput`, `.FormControl__{button,select,input}`, and
  `.infoBox > strong`. This is the intent the original token encoded.
- **Family: no change in practice.** `body` already resolves to `var(--secondary-font-family)`,
  which `.infoBox > strong` inherits. The two form-control sites do *not* inherit family (UA
  stylesheets give `input`/`select`/`button` the system font), so naming it there is what makes
  the Accessibility "Content Font Family" picker actually reach them — today it does not.
- **No font-size, no line-height.** The dead shorthand never validly set either; adding one now
  would be a second, unrequested change, and `260911-umj` ratified these controls at 34px only
  yesterday.
