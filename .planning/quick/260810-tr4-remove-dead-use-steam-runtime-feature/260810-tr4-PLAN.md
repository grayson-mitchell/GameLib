# Quick Task 260810-tr4: Remove dead "Use Steam Runtime" feature

## Goal

Delete the "Use Steam Runtime" launch-wrapper feature (the Steam Linux Runtime
scout/soldier/sniper container that optionally wrapped Epic/GOG/Amazon/Zoom game
launches on Linux). This is a pure deletion, porting the deletion half of Heroic
upstream commit `0a18fef2b` (branch `rm/use-steam-runtime`, unmerged upstream).

## Scope decisions

**Ported:** the deletion only.

**NOT ported (explicitly out of scope):**
- The umu replacement from `0a18fef2b` (`UMU_NO_PROTON=1` / `RUNTIMEPATH=scout-on-soldier`
  for Linux-native games, and widening the `DisableUMU` toggle to linux-native).
- The `setupWrappers` refactor from `9a41a7d79` / `70d46cf37`. `setupWrappers` stays;
  only its now-dead `steamRuntime` parameter is removed.

**`public/locales/` is NOT touched — deviation from the task brief.**
The brief asked to remove the `setting.steamruntime` / `help.steamruntime` i18n keys.
Rejected after measurement, three independent reasons:
1. `meta/i18nCatalogChurnGuard.ts` classifies *any* changed path under `public/locales/`
   that is not a `gamelib.json`/`gamelib.mt.json` leaf as `upstream` and throws
   `UpstreamChurnError`. `meta/__tests__/i18nCatalogChurnGuard.test.ts`'s `live tree`
   block runs that assertion against the real working tree under `pnpm test:ci`.
   `translation.json` is upstream-owned; editing it is precisely what the guard exists
   to stop.
2. `meta/lintTranslations.ts` sets `printExtraTransations = false` with the comment
   "there are many extra keys in translation files without a matching key in the english
   file / this is not really a problem". Orphaned keys are explicitly tolerated.
3. Upstream's own `0a18fef2b` touched no catalog either — Weblate reaps orphans.

Net effect: `setting.steamruntime` and `help.steamruntime` become unused-but-inert keys
across all 49 locale catalogs, exactly as upstream leaves them.

**No settings migration is needed.** `useSteamRuntime` is not present in
`GlobalConfig.getFactoryDefaults()` (`src/backend/config.ts`) — it is only ever read
out of persisted user JSON. Once the field is gone from the `GameSettings` type, any
stored `"useSteamRuntime": true` is an ignored extra JSON key. Nothing reads it, nothing
throws. Upstream shipped no migration for this either.

typed against `GameSettings`. Removing the backend field first would break this file, so
the frontend goes first and each commit compiles on its own.

  - `src/frontend/screens/Settings/components/SteamRuntime.tsx` (delete file)
  - `src/frontend/screens/Settings/components/index.ts` (drop barrel export, line 53)
  - `src/frontend/screens/Settings/sections/GamesSettings/index.tsx` (drop import line 30,

- done: the toggle no longer renders in Settings → Games, and nothing imports it.
