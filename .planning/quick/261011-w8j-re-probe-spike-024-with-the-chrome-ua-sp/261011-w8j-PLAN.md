# Quick 261011-w8j — re-probe spike 024 with the UA spoof off

## Why

Spike 024's five runs all stamped a Chrome 131 UA onto WebKit (`builder.user_agent(CHROME_UA)`
when `spoof_ua`, which the autorun hardcodes `true` and the panel defaults to ticked). The
README never names it as a variable. The todo asks for the same harness, one flag flipped.

## Tasks

### Task 1 — give the harness a switch (code, spike-local)

`app/src/main.rs`: `SPIKE_SPOOF_UA=0` makes the autorun's PHASE 1 `create_embed` pass
`spoof_ua=false`; log the flag at the PHASE 1 header; carry `navigator.userAgent` on the probe's
`/report` exfil (the control server already reads `ua=`). `tauri.conf.json`: fresh container
`spike024e` for run 6, bumped per run.

- files: `app/src/main.rs`, `app/tauri.conf.json`
- verify: `cargo build` green; run log PHASE 1 header shows `"spoofUa":false`; the
  control-server `/probe` record's `userAgent` carries no `Chrome/` token.

### Task 2 — the runs (live, unattended autorun)

Steam positive control runs in every autorun (arm 3 of PHASE 3). Three autoruns, each on a fresh
container (`spike024e`, `f`, `g`), `SPIKE_SPOOF_UA=0 SPIKE_AUTORUN=1 SPIKE_AUTORUN_EXIT=1`.
Screenshot the window during each arm's `SCREENSHOT WINDOW NOW` pause via
`screencapture -l<windowNumber>`. Logs copied to `run-6.log`, `run-7.log`, `run-8.log`.

The interactive arm (a human clicking the Turnstile widget) is **operator work** and is not
fabricated here. It is only needed if the unattended arms are still challenged.
