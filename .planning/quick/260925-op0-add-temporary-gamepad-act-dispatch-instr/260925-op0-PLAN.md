Two edits inside `checkAction`. Nothing else in the file changes.

**Edit A -- capture the pre-switch original.** Immediately BEFORE the
`// check special cases for the different actions, more details on the wiki` comment that heads
the `switch (action)` block (currently `:182-183`), add one `const`. Type it EXPLICITLY:
`const requestedAction: ValidGamepadAction = action`. The explicit annotation matters -- the
`if (action === 'guide')` early return above has already narrowed `action`, and an inferred
narrow type invites a spurious TS "these types have no overlap" error on the `!==` comparison in
Edit B. The `ValidGamepadAction` import already exists; do not add one. Name it
`requestedAction`, not `originalAction`: it states the semantics (what the operator asked for)
against `action` (what actually fires).

**Edit B -- emit, after the switch closes and before dispatch.** Place the probe between the
closing brace of the `switch` block (currently `:282`) and the `if (action === 'mainAction')`
dispatch chain (currently `:284`).

This exact position is the point of the whole task. The switch REWRITES `action` before dispatch:
`mainAction` becomes `leftClick` / `keyboardClick` / `tab`; `back` becomes `tab` / `shiftTab` /
`rightClick`; `padDown` / `leftStickDown` become `tab`; `padUp` / `leftStickUp` become `shiftTab`.
A source census of `gamepad_layouts/` confirms **no layout binds `tab` or `shiftTab` to any button
on any pad** -- they exist ONLY as these derived rewrites -- so a probe placed before the switch
could not score `38-C03` (does controller input produce Tab/Shift+Tab traversal?) at all.

The emission: a single `window.api?.logInfo?.(...)` call in the optional-call spelling, the whole
thing inside `try { ... } catch { ... }`, the catch carrying a comment in the same voice as the
permanent connect line's ("diagnostic only -- must never break controller dispatch"). Build the
message string inside the `try`.

Line shape -- one line, space-separated `key=value`, prefixed `[GAMEPAD-ACT] `:
- `action=<resolved>` -- always
- `from=<requestedAction>` -- ONLY when `action !== requestedAction`, so a rewrite is visible as
  a rewrite and an un-rewritten action does not carry a redundant field
- `ctrl=<controllerIndex>` -- always; it is already in scope and costs nothing
- `tag=<el.tagName>`, or `tag=none` when `el` is undefined
- `cls=<class sliced to 60>` -- only when the focused element carries a non-empty class
- `testid=<data-testid>` -- only when the attribute is present

Read the two attributes with `el.getAttribute('class')` and `el.getAttribute('data-testid')`
guarded by a plain `if (el)`. Do NOT reach for `el?.getAttribute?.()` -- an unnecessary optional
call on a non-optional `HTMLElement` method is exactly the kind of thing that adds a lint warning
and breaks the zero-new-warnings constraint. Omitting empty fields rather than printing a
placeholder keeps the line scannable when a dozen land in a sitting.

Reuse the existing `el` from `:161`. Do NOT call `currentElement()` again: `el` is already the
element focused when the action fired, and a second DOM query is an unnecessary behaviour delta.

**Edit B's comment block -- the removal contract.** Above the `try`, write a comment specific
enough that a later reader greps and removes it without archaeology. It must state: that the
probe is TEMPORARY; that it serves the **Phase 38 controller sitting**; that it is to be
**removed in the Phase 38 close-out task**; that `GAMEPAD-ACT` is the single grep token that
finds every line of it; and that it deliberately sits post-switch so a rewritten action is
