<path_resolution_trap>
This is the most likely way the change breaks in CI, and the resolution strategy is a decision,
not an incidental.

`meta/runTs.cjs` esbuild-bundles `meta/signMachOResources.ts` into an `fs.mkdtempSync`-created
**private temp directory** and runs it from there (its own header says so, and it never sets a
`cwd` for the child — `grep -n cwd meta/runTs.cjs` returns nothing, so the child inherits the
caller's cwd). Consequently `__dirname` and `import.meta.url` inside the bundled script point at
that temp dir, NOT at `meta/`. A plist path derived from either resolves to a nonexistent file at
CI time.

**Decision:**

1. `HELPER_ENTITLEMENTS` values are **repo-relative POSIX paths**
   (`meta/steam-bridge-helper.entitlements.plist`) — never absolute, never `__dirname`-derived.
2. `resolveEntitlementsPath(relPath, startDir = process.cwd())` walks UP from `startDir`, testing
   `join(dir, relPath)` at each level, returns the first absolute hit, and throws naming EVERY
   directory it tried if there is none. The walk exists because CI invokes
   `pnpm sign:macos-resources` with the repo root as cwd (a bare cwd-join would be enough there)
   but a local invocation from a subdirectory would otherwise resolve to a nonexistent path.
3. `preflightEntitlements(map, startDir = process.cwd())` resolves EVERY value in the map ONCE, at
   the top of `signMachOResources`, **before any codesign call and in dry-run mode too**.

**How a wrong path is DETECTED rather than silently producing an unentitled binary:** the
preflight throws before the first `codesign` spawn, with the searched directories in the message,
so the run dies at file 0 rather than after 253 signatures. We do **not** rely on codesign's
behaviour when handed a missing `--entitlements` path — that behaviour is unmeasured, and this
todo's whole history is about the difference between permitted and observed.

**What proves the strategy works rather than merely reading well:** the existing end-to-end test
spawns the REAL `sign:macos-resources` package script, i.e. it runs through `meta/runTs.cjs` from
the esbuild temp dir. Once the fixture contains a `steam-bridge-helper` (Task 2), a
`__dirname`-based resolution makes that test RED. Say so in a comment at the test.
</path_resolution_trap>
