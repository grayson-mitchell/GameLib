<objective>
Keep the game page's Play and Settings buttons on screen at every window height. Today the
buttons get clipped at mid heights when Steam-engine notices make the left panel too tall, and
that hides the Settings button the 59-28 `cx-expired` override warning tells the user to press.

Purpose: the operator must always be able to reach Settings to set the override back to Automatic.
Output: a CSS-only fix in `src/frontend/screens/Game/GamePage/index.css`, a live resize check, then the todo moved to completed.
</objective>

<root_cause>
Traced from `src/frontend/screens/Game/GamePage/index.css` and `index.tsx` (L546-591):

1. `.mainInfoWrapper` (L96-112) is a flex column with `overflow-y: auto` and is the
   `main-info-wrapper` size container. `.mainInfo` (L121-133) has `flex-grow: 1` and
   `overflow: hidden`. That makes `.mainInfo` a scroll container, so its automatic flex
   `min-height` resolves to 0. `.mainInfo` therefore always shrinks to the wrapper's height,
   the wrapper's own `overflow-y: auto` never gets anything to scroll, and anything past
   `.mainInfo`'s bottom edge is **clipped with no scrollbar**. `.buttons` is the
   second-to-last child (only `{wikiLink}` comes after it), so it is the first thing clipped.
2. Inside `.mainInfo` (a flex column), `.summary` (L282-291) is the only child that can shrink.
   It has `overflow: auto`, so its min-height is also 0. The notice boxes, release date,
   TimeContainer, GameStatus and LaunchOptionSelector are `overflow: visible`, so they keep
   their content height. Once the description has shrunk to its padding, any remaining
   overflow from the notices pushes `.buttons` below the clip line.
3. The three `@container main-info-wrapper` queries (L864-889) hide developer/releaseDate/genre
   (<=560px), `.summary` (<=500px), then gameStatus/timeContainerLabel (<=450px). At the
   **smallest** heights they remove enough fixed-height content that the rest fits again, so
   the buttons show. At **mid** heights (roughly 500-650px with a long notice) none of those
   rules applies yet, the summary is already at 0, and the notices overflow, so the buttons are
   clipped. At **fits-everything** heights nothing overflows. That is exactly the
   show/hide/show pattern the operator reported. The narrow-width `@container main-content
   (max-width: 700px)` layout gives the `main` row a fixed 400px, so the same mechanism applies
   there.
</root_cause>

<chosen_fix>
Make `.mainInfo` the panel's real scroll container and pin `.buttons` to its bottom edge:

- In the `.mainInfoWrapper { .mainInfo { ... } }` block only (L159+, NOT the shared
  `.mainInfo, .extraInfo` rule at L121, which `.extraInfo` also uses), set `overflow-x: hidden;
  overflow-y: auto;`. This overrides the shared `overflow: hidden` because it is more specific
  (0,3,0 vs 0,2,0).
- On `.buttons` (L329), add `position: sticky; bottom: 0; z-index: 2;`, plus
  `background-color: var(--body-background)` and a small vertical `padding-block` so content
  scrolling underneath does not show through. The selector
  `.gameConfigContainer .mainInfoWrapper .mainInfo .buttons` (0,4,0) beats the
  `.mainInfo > * { position: relative }` rule (0,2,0), so sticky takes effect.

Why this one (the alternatives were weighed):
- Sticky positioning does nothing while `.mainInfo` is `overflow: hidden`, because a hidden
  container never scrolls. It needs the `overflow-y: auto` change.
- Moving `.buttons` out of `.mainInfo` in the TSX would break the outlined card, the
  `::after` gradient and the gamepad focus order. CSS alone is enough.
- Letting only the notices scroll would hide the warning text itself. With this fix the
  notice is shown in full and can be scrolled to; until now it was clipped and could not be
  reached at all.

Theme survival (sketch-findings rule: never assume which band is darker): the strip's
background is `var(--body-background)`, the token `.mainInfo` already paints itself with. The
`::after` gradient also ends at `var(--body-background)` by 70%, so the strip matches the panel
bottom in every theme without a theme-specific value. It does not regress the smallest-height or
fits-everything cases. When nothing overflows, a sticky element sits at its normal position, and
the container queries are untouched.
</chosen_fix>
