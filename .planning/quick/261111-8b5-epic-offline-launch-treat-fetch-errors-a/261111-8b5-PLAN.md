<objective>
Fix the silent Epic offline-launch failure from the source todo
(`.planning/todos/pending/2026-11-07-epic-offline-launch-silently-fails-when-network-drops.md`,
found in Phase 62 smoke 2, `62-UAT.md` item result line 75). Right after the network drops,
`isOnline()` still reports online. `isEpicServiceOffline()` then gets ENOTFOUND from
status.epicgames.com, and its catch-all returns `false` (online). So `legendary launch` runs
without `--offline`, fails login with `Login failed, cannot continue!`, and exits 1. The
user sees nothing.

Two independent fixes, both scoped to the Epic/legendary launch:
1. Treat a network-level status-fetch failure as offline. Requests that got any HTTP
   response keep their current behaviour.
2. When `legendary launch` fails on login anyway, show a "Launch aborted" ERROR dialog. It uses
   the same `showDialogBoxModalAuto` + `box.error.launchAborted` pattern `launch()` already
   uses for its prepare/wine-prepare failures.

Purpose: an Epic game that can run offline starts offline when the network has just dropped,
and a launch that cannot sign in says why instead of doing nothing.
Output: two small pure modules with DI-style tests, the wiring in `utils.ts` and
`legendary/games.ts`, three en catalogue values, and the todo moved to completed/.
</objective>
