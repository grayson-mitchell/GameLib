# Phase quick-261111-8b5 Plan 01: Epic offline launch Summary

Network-level Epic status-fetch failures now make `isEpicServiceOffline()` return true so the launch goes `--offline`, and a `legendary launch` that fails to sign in shows a "Launch aborted" ERROR dialog naming the game and cause.

## What changed

1. `src/backend/utils/epicServiceStatus.ts`: `isNetworkLevelFailure` (axios request made, no response, not ERR_CANCELED; or a plain errno-style `code` in the listed set) and `checkEpicServiceOffline(deps, type)` with fetch/notify/log injected. `isEpicServiceOffline` in `utils.ts` keeps its signature and early `isOnline()` return and delegates to it. `launcher.ts` and `downloadmanager/utils.ts` are untouched.
2. `src/backend/storeManagers/legendary/launchFailure.ts`: classifier (credentials > network > generic login precedence; null when not errored, aborted, or no marker) and dialog builder. `LegendaryGame.launch()` captures output through `createBoundedOutputCapture(16_000).onOutput`, and on a classified failure logs only the kind and shows the dialog. Three `box.error.launch.epic.*` values were added to `en/gamelib.json` only.
3. Todo moved to `.planning/todos/completed/` with a Resolution section.
