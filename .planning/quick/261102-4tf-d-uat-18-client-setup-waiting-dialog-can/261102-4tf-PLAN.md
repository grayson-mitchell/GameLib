<objective>
Fix D-UAT-18, found in Phase 21 UAT 4c and the 4a re-run on real Windows, 2026-11-02. After the
user consents, the Steam client-setup prompt drops to a non-modal bottom-right toast. That toast
has three problems:

1. Its only button reads "Done", but it calls close(). By the 34.13 C-17 design, close() stops the
   readiness poll and abandons the pending install. The operator clicked it as an
   acknowledgement, and the first 4c attempt never continued.
2. It is styled unlike the consent Dialog that comes right before it. Operator: "inconsistant ui,
   shouldn't it be a standard window like the previous one."
3. Its copy goes stale. It kept saying the Steam client was installing after Valve's installer had
   finished, while GameLib was actually polling needs-launch (D-11) every 3s. Nothing told the
   operator to open Steam.

Locked decisions (operator-approved 2026-11-02; do not revisit):
- LD-1: The waiting surface becomes a standard Dialog. This covers the post-consent D-10
  "installing" state and the D-11 "launch-once" state. It uses the same
  `Dialog`/`DialogHeader`/`DialogContent`/`DialogFooter` family and styling as the consent prompt
  in the same file. The approved mockup is a "Waiting for Steam" title with a close X, the body
  "Finish the Steam installer that opened. GameLib will continue the download automatically.",
  and one "Cancel install" button.
- LD-2: The dialog has a single button, "Cancel install", with today's close() semantics. It
  preserves C-17: a dismissed prompt never starts a download later. The header X and the Dialog
  onClose (Escape, backdrop) also cancel. There is no Hide option, and the "Done" label is
  removed.
- LD-3: The copy follows the live recheck status. needs-launch shows launch-once wording ("Steam is
  installed but hasn't been opened yet. Open Steam once — GameLib will continue the download
  automatically.") and needs-install shows the installer wording.
- Planner's call: the error phase ("Steam setup could not start: ..." with Try again) moves into
  the same Dialog. It keeps Try again (returns to consent) and adds Cancel install (closes).

Purpose: SNI-06 (continue-to-download) is only reliable if the user can tell "waiting" from
"cancel", and is told what GameLib is waiting for.
Output: the reworked component (one Dialog root, live copy), a behavioural test file, the en
catalog changes, the deleted toast stylesheet, and the D-UAT-18 todo re-triaged to
`ready: live-gate`.
</objective>
