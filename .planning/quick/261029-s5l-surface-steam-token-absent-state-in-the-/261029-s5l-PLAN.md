<objective>
Action the todo `.planning/todos/pending/2026-10-29-steam-ui-signed-in-while-dev-vault-has-no-refresh-token.md`:
stop a Steam install from being attempted when GameLib holds no usable Steam refresh token, and
prompt a GameLib re-sign-in on the install affordance instead of failing after the click with
"You are not signed in to Steam, so this download could not start".

Root cause (established during planning, from the 56-25 session capture
`/private/tmp/gamelib-gate-20261028T192950Z/gamelib-launch-*.log`):

- Boot: `[dev-secret-vault] read key=steam-refresh-token` → `[signInProbe] steam outcome=expired`
  → `[signInProbe] steam verdict=unchanged`. `SteamUser.probeCredentialPresence()`
  (`src/backend/storeManagers/steam/user.ts:247-258`) maps an absent token to `expired`, and
  `applySignInVerdict` (`src/backend/signInProbe/verdict.ts`) returns `unchanged` for `expired`
  only when `steamConfigStore.credentialsMissing` is ALREADY set. So the flag was latched.
- That flag feeds `resolveSignInState` branch 1 (`src/common/signInState.ts`) → `expired`, which
  the Library shows as the non-dismissible `Your Steam sign-in expired` row
  (`librarySignInRows.ts`) and the Manage Accounts tile shows as `Reconnect`
  (`Login/signInTileState.ts`). The account UI did show "expired", which matches the operator's
  "signed in or expired". The token-absent case is already folded into `expired`. No new state is
  needed and none is added.
- The gap is the install affordance. `openInstallGameModal` → `startSteamQuickInstall`
  (`src/frontend/state/InstallGameModal.ts:234`) never looks at sign-in state, so Install stays
  live and the backend refuses after the click (`ensureConnected` absent branch → `token-absent`
  → `depotErrors.ts:181` generic failure dialog).

Approach: one pure helper that derives Steam's sign-in state through the shared selector, used at
the single install chokepoint (`startSteamQuickInstall`, native path only) and by the Steam
install dialog. The dialog shows a sign-in notice with a `Sign in to Steam` action and disables
Install.

Secondary "Next" items in the todo:
- **GameLib sign-in preflight for live-gate contracts.** Already done. `56-33-LIVE-GATE.md` PC12
  (line 84) checks the dev vault for `steam-refresh-token` before launch 0 and cites 56-25 Gap 4.
  Record it as already resolved; do not edit any live-gate file.
- **Persistent dev vault location.** Deferred. `src/backend/sidecar/devSecretVault.ts:80`
  deliberately puts the plaintext vault in `os.tmpdir()`, NOT `userData`, because it is
  disposable. Moving a plaintext secret store into a persistent location is a security and design
  decision, not a small change. Record it as a new pending todo (Task 3) and do not change the
  code.

Purpose: the first sign of a lost Steam credential becomes "Sign in to Steam", shown before any
download starts.
