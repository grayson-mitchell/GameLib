Part 1 (coverage): the x64 bridge shim exports only `SteamInternal_CreateInterface` from the modern-SDK `SteamInternal_*` family. Every SDK 1.58+ title calls `SteamInternal_SteamAPI_Init`. Grim Dawn's Engine.dll, Colony Ship, Hell Clock (Unity), Mining Mechs (GameMaker), Overlooting (Godot) and Ranch Simulator (UE) all import some of the five missing exports. Add all five through the generator, regenerate, re-pin the coverage set and rebuild the DLL.

Part 2 (detection): `placeShimForGame` reads only the launch exe's imports. When the exe imports nothing but `x64/Engine.dll` does, the verdict says only `steam_api64.dll@runtime-loaded` and never names the symbols. Walk the install tree for PEs that import `steam_api*.dll` and merge their imports into the required set.

The todo's spike-038 correction applies. Grim Dawn's 2-second exit is SteamStub (`.bind`), not this import miss. This plan alone will NOT make Grim Dawn run, because it is blocked on the forwarding-steamclient todo. Do not claim otherwise in the SUMMARY.

Scope decisions (record these in the SUMMARY):
- **x64 only. x86 is NOT free.** 51-15 (D-51-13) deliberately made the modern lookup family Win64-only. The x86 build has no `SteamInternal_CreateInterface`, no `SteamAPI_GetHSteamUser`/`GetHSteamPipe` and no null-object fallback. A modern-SDK x86 context init also calls `SteamAPI_GetHSteamUser`, so exporting the five on x86 would mean widening the whole family to x86. Leave `steam_api.def` and `SHIM_EXPORTED_SYMBOLS` byte-for-byte unchanged.
- **The Godot 322 MB "could not parse the exe as a PE" side note is left out.** It is not a read-limit fix. `detectExeSteamDrm` already does fd-ranged `readSync` reads with no size cap and no whole-file read. The parse failure must come from the PE's own layout (for example, the resource-RVA container lookup failing on Godot's appended-pck section layout), and finding it needs the actual binary. Say so in the SUMMARY and suggest a follow-up todo. Do not create that todo here.
- **meta/bridgeCensus.ts is not changed.** It already classifies runtime-loaded titles as `missing-symbols`, so it already counts them as not covered. Teaching the census the importer walk is a follow-up; note it in the SUMMARY.
- **Do NOT move or close the todo.** The orchestrator does that after execution.

Output: generator + regenerated artifacts + coverage re-pin (Task 1). Importer walk merged into the exe-imports branch (Task 2). Per-dll importer evaluation plus the launch-arch filter in the runtime-loaded branch (Task 3).
