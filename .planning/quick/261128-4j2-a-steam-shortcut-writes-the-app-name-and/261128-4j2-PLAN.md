<objective>
Make Add to Steam percent-encode the app name and runner in the `LaunchOptions` it writes into `shortcuts.vdf`. The
`gamelib://launch` URL sits inside double quotes there, and today `launch_options()`
(`src-tauri/crates/gamelib-shortcuts/src/steam/entry.rs:50-64`) writes both values raw. An app name holding `"` ends the
quoted argument early, so Steam hands the rest to GameLib as extra arguments. This closes
`.planning/todos/pending/2026-11-24-steam-shortcut-launch-options-carry-the-app-name-and-runner-unencoded.md`. Its
Problem and Direction sections are the spec.

The spec, labelled for traceability:

- **S1.** Percent-encode both values with the helper the `.lnk` uses, `launch_url(app_name, runner, true)`
  (`src-tauri/crates/gamelib-shortcuts/src/launch_url.rs:53`).
- **S2.** Never hand-edit the golden `steam/add-launch-options-hostile-app-name.json`. Keep the old line in a delta beside
  it.
- **S3.** An existing shortcut keeps its old line; only new ones change.
- **S4.** The `appid` is a hash of `Exe` and `AppName` only and must not move.
- **S5.** Confirm that the goldens for plain app names do not change.
- **S6.** The house pattern: a `fix(...)` commit, a `test(...)` commit pinning the goldens, and a `docs(...)` commit that
  moves the todo to completed/ with a resolution note.

Purpose: a shortcut whose app name holds `"`, space, `&`, `#` or `;` launches that game. Steam no longer passes the tail
of the name to GameLib as extra arguments. All four shortcut writers then encode the same way: `run.sh`, `.lnk` and this
one, with Linux `.desktop` tracked in its own todo.
Output: the one-function fix plus doc updates, one unit test, one delta and its replay, and the closed todo.
</objective>
