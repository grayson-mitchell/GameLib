# Phase quick-261128-4j2 Plan 01: Add to Steam percent-encodes LaunchOptions Summary

Add to Steam now writes `LaunchOptions` with `launch_url(app_name, runner, true)` inside double quotes (the `.lnk` writer's own call), so a `"`, space, `&`, `#` or `;` in an app name or runner no longer ends the quoted argument.

## Commits

- `24903e2b9` fix: `entry.rs` `launch_options` double-quotes the encoded URL; docs in `entry.rs` and `mod.rs`; new unit test `the_launch_options_hold_one_quoted_url_that_decodes_to_the_inputs`.
- `cd47bab9d` test: `deltas.json` gains `add-launch-options-hostile-app-name`; `golden_steam.rs` gains `with_launch_options_delta` (applied at the top of `replay_arm`) and `the_launch_options_deltas_are_exactly_the_add_cases_whose_names_encode`.
- `936ef351c` docs: todo moved to `completed/` with a `## Resolution`.

The hostile Linux entry now reads `--no-gui --no-sandbox "gamelib://launch?appName=a%20b%22c%26d%3De%23f&runner=r%3Btouch%20pwned"`.

## RED record (Task 1)

Before the fix the new unit test failed (1 failed, 97 filtered out). Both hostile pairs failed on all three contexts (linux, windows, flatpak), each on all three counts:

- `a b"c&d=e#f` / `r;touch pwned`: three double quotes in the options, bytes not equal to the encoded form, and the quoted text decoded to `[("appName", "a b")]`.
- `a b&c"d%25e` / `legendary`: the same three, decoding to `[("appName", "a b"), ("c", "")]`.

The control pairs (`oracle-app`/`legendary`, `jorg`/`gog`) passed in every context. After the fix the lib suite had 98 passing.
