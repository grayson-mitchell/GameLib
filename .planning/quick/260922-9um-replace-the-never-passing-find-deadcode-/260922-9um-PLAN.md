## ts-prune internals — READ THIS BEFORE WRITING A LINE

These were read out of `node_modules/ts-prune/lib/*.js`. They are non-obvious and the natural
first guess is wrong in both cases. **Carry each of these into a comment in the .cjs.**

1. **`require('ts-prune')` IS A TRAP.** The package `main` (`lib/index.js`) calls `getConfig()`,
   `run(config)` and `process.exit()` **at module scope** — requiring it runs the whole tool and
   kills the process. Deep-import instead: `require('ts-prune/lib/runner')` → `{ run }`. VERIFIED
   to resolve (ts-prune's package.json has no `exports` field blocking the deep path) and VERIFIED
   not to exit.
2. **`run(config, output)`** has signature `(config, output = console.log) => number`. It invokes
   `output(line)` once per finding and returns the post-filter count. Passing a collector callback
   yields every formatted line without touching stdout.
3. **Formatted line shape** (`lib/presenter.js`):
   ```
   `${file}:${line} - ${name}${usedInModule ? ' (used in module)' : ''}`
   ```
   `file` is repo-relative (cwd stripped, then leading `/` stripped).
4. **`config.ignore` is matched against the WHOLE FORMATTED LINE, not just the path**, despite the
   CLI help calling it a "Path ignore RegExp pattern" — `lib/runner.js` does
   `presented.filter(file => !file.match(config.ignore))` where `presented` is the array of
   formatted strings. So `ignore` *could* hide ` (used in module)` wholesale. See the rejected
   options below: doing that is DELIBERATELY refused.
5. **Do NOT call `getConfig()` from `ts-prune/lib/configurator`.** It parses `process.argv` through
   the `commander` global singleton — i.e. OUR argv. Read `.ts-prunerc` directly with
   `JSON.parse(fs.readFileSync(...))` so the gate has zero coupling to argv. Keep `.ts-prunerc` as
   the single source of the `ignore` pattern; do not duplicate the pattern into the .cjs.
