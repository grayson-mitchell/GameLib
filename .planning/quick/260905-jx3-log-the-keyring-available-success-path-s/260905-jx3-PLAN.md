# Quick Task 260905-jx3

## Measured ground truth (re-verified at HEAD 6e70527c1 + eb1a9dfd3, 2026-09-05)

- `keyring_available`'s Rust handler calls `entry.get_password()` — `src-tauri/src/main.rs:5369-5386`,
  read at `:5372`. It therefore raises a real macOS Keychain approval prompt, exactly as
  `keyring_get` does. Unlike `keyring_get` it is NOT wrapped in `bounded_keyring_read` (main.rs
  comment at `:5309-5312` states this is deliberate and out of that plan's scope) — **not this
  task's problem, do not change it.**
- `fetchAvailable()` — `src/backend/sidecar/keyringTokenStore.ts:211-233` — logs **only** in its
  `catch` (`logWarning`, one line). The success path writes `this.cachedAvailable` and returns with
  no log call of any kind. A successful probe is invisible in `gamelib.log`.
- `isAvailable()` (`:200-209`) has a cache-hit early return and an in-flight-join early return,
  **neither of which logs**. `readToken()` (`:264-312`) logs both at DEBUG, precisely so "no prompt
  because the fix works" is distinguishable from "no prompt because the value was already cached".
- `fetchToken()` (`:315-390`) is the shape to mirror: `started = Date.now()`, an INFO
  `issuing <channel> (may prompt) trigger=<label>` line **before** the invoke, and an INFO outcome
  line with `trigger=`/`elapsed=` appended **after** the pre-existing tokens.
- Interfaces: `TokenStore.isAvailable(): Promise<boolean>`
  (`src/backend/storeManagers/steam/tokenStore.ts:62`) and the separate
  `HumbleSecretStore.isAvailable(): Promise<boolean>` (`src/backend/humble/secretStore.ts:73`).
  Both are zero-arg. Adding an OPTIONAL parameter is assignment-compatible in TypeScript: every
  existing zero-arg implementer (`ElectronTokenStore`, `DevVaultTokenStore`,
  `ElectronHumbleSecretStore`) keeps satisfying it unchanged.
- Non-test `.isAvailable()` callers, census re-run 2026-09-05:
  | Call site | Reaches the probe? |
  |---|---|
  | `src/backend/humble/user.ts:116` (`storeHumbleSecret`) | yes, via `HumbleSecretStore` |
  | `src/backend/sidecar/humbleSecretStore.ts:76` (`SLOT_STORES.sessionCookie`) | yes, direct |
  | `src/backend/sidecar/steamgridSecretStore.ts:71` | **no** — synchronous seam, returns `true` optimistically, never reaches `SidecarKeyringSlotStore` |
- Existing test at `__tests__/keyringTokenStore.test.ts:220` is named
  "...reports false, **without logging**" but asserts only `expect(mockLogWarning).not.toHaveBeenCalled()`.
  Adding a `logInfo` success line does NOT break it. Its NAME becomes misleading and must be
  corrected — a successful `false` is a probe that prompted and must be logged.
