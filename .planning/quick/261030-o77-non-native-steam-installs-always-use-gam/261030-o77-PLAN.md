<objective>
Make every non-native (bottle-route) Steam install on macOS use GameLib's own depot installer and
finish without bottled Steam. Drop the toggle-OFF `tellBottledSteamToInstall` dispatch, drop the
quick 261024-h5y "Start Steam to finish" handoff, convert a bottle-route 1026 fallback into an
incomplete/resumable install, and narrow the `enableSteamNativeInstall` toggle to mac-native titles.

toggle-OFF arm nor the 1026 handoff ever finishes. Bottled Steam is a narrow fallback to eliminate,
not a download path.

<discretion_resolved>
Where the bottle-route 1026 -> incomplete conversion lives: the library POLLER's bottle-source arm
(library.ts), not `installDepotDownload`. Reasons, measured against the code:
1. `installDepotDownload` (games.ts ~2735-3138) then stays byte-for-byte unchanged, including its
   `opts.pollerSource` / `else if (isMac)` deferredPoll / `else` poller-start block (~3112-3131),
   so the native Mac and Windows/Linux paths cannot drift.
2. `installDepotDownload` keeps returning `status: 'done'`, so `install()` still persists
   `markForcedWindowsViaBottle` for a forced title. `isBottleEligible()` reads that flag
   (games.ts ~3215, `isForcedWindowsViaBottle()` ~3197), which is what routes the user's Resume
   back onto the bottle route. Returning abort/error from `installDepotDownload` would skip the
   flag and a forced title's Resume would route native.
3. `downloadSteamDepots`' outcome does not report whether 4 or 1026 was written; the poller already
   reads StateFlags and already has the exact predicate (`isWaitingForSteamRestart && source ===
   'bottle'`, today's `isBottledHandoff`, library.ts ~2977).
4. It also covers any bottle-source handoff poll started outside `install()` (for example a
   `resumeInterruptedSteamInstall()` boot finalize that writes 1026 — check whether it starts a
   bottle-source `isNativeHandoff` poll and note the answer in the SUMMARY).
</discretion_resolved>
