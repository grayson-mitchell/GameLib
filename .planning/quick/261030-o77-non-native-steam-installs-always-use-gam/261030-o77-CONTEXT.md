## Implementation Decisions

### Step 3: how a bottle-native install becomes installed (operator decision, locked)

Desk finding (orchestrator, 2026-10-30). The todo says every bottle-native install parks at
1026. The code says otherwise:

- `finalizeToSteam` (`src/backend/storeManagers/steam/depot.ts` ~3920) writes StateFlags 4 on
  every route when `canWriteFullOwnership` passes: completed, no failures, a real buildid, every
  file sha1-verified, every mode applied. `library.ts` (~3244) then sees "installed" on the first
  poll. Spike 003 validated this.
- So the bottle-source 1026 wait and the "Start Steam to finish" button only arise when that gate
  **fails**, and the write falls back to the 1026 verify-handoff.

Decision, the operator's choice ("Mark resumable"):

- Remove the bottled-Steam handoff entirely (todo step 3's delete list).
- On the **bottle route** (`pollerSource: 'bottle'`), the 4 fast path stays as it is.
- When the gate fails and a 1026 manifest lands, the install is **not** reported as installed,
  and it does **not** wait on bottled Steam. Mark it incomplete and resumable, the same state a
  cancelled depot install gets (`markSteamInstallIncomplete`). The user's Resume then re-runs
  GameLib's own depot installer, which verifies and fills the gaps.
- Do not treat files-on-disk at 1026 as installed (the operator rejected Candidate B).
- The native Mac route keeps its own 1026 "Restart Steam" handoff (`steam-waiting-for-restart`,
  plus the deferred poll in `runNativeDepotDownload`). It is out of scope: only the bottle-source
  arm goes.

### Claude's Discretion

- Where the bottle-route 1026 -> incomplete conversion lives: in `installDepotDownload` after
  the download, or in the library poller's bottle-source arm. Pick whichever keeps the native
  Mac and Windows/Linux 1026 paths byte-for-byte unchanged. Make sure the resume path picks the
  title back up on the bottle route.
- Exact settings copy for `EnableSteamNativeInstall.tsx`.

</decisions>

<specifics>
## Specific Ideas

- Launch for a bottle (non-bridge) title still goes through `tellBottledSteamToLaunch`. Leave
  launch alone. Whether bottled Steam launches a GameLib-written StateFlags 4 manifest without
  its own verify is a live check for the operator, and goes in the SUMMARY as a live gate.
- Keep `tellBottledSteamToInstall()` only if a caller remains after steps 2 and 3. Guided setup,
  launch and uninstall keep their own bottled-Steam mechanisms (`dispatchToBottledSteam`,
  `tellBottledSteamToLaunch`, and the rest).

</specifics>
