# Quick Task 260823-u1m — route 34.9's two unowned ledger items to real phases

## Why

`.planning/phases/34.9-.../deferred-items.md` closes with 15 open items. Thirteen name a real
owner. **Two do not:**

- **Item 8** — `PathSelectionBox` discards typed input unless the field is blurred.
  `OWNER: UNASSIGNED — no UI-owning phase remains after 34.11; developer decision owed` (2026-08-11).
- **Item 20** — repo-wide `pnpm lint` failure, 3544 problems (53 errors, 3491 warnings).
  `OWNER: unassigned (pre-existing repo-wide lint debt, not scoped to any phase-34.9 finding)`.

This is the same shape that left items 1/2/3/12/13/18 pointing at "a follow-up phase" with no
ROADMAP counterpart for 9-11 days, which Phase 34.16 was created on 2026-08-22 to fix. An OWNER
line that names nobody rots exactly as fast as one that names a phase that does not exist — and
the 34.9 sweep cannot catch either, because it scores whether an item maps to a *row*, not whether
the row's owner resolves to anything real (Phase 38's own entry records this).

**Item 8 re-verified live before routing (2026-08-23):** `src/frontend/components/UI/PathSelectionBox/index.tsx:84`
still reads `onBlur={(e) => onPathChange(e.target.value)}` with no `onKeyDown`, while
`src/frontend/components/UI/TextInputWithIconField/index.tsx:17` already *declares* an `onKeyDown`
prop that `PathSelectionBox` never passes. The item is live, not moot.

## Routing decision

Two phases, not one. A single phase owning both would have an incoherent goal, which GSD's
goal-backward verification handles badly.

| Item | Destination | Why there |
|------|-------------|-----------|
| 8 | **new Phase 34.17** | Frontend defect; belongs with the 34.x frontend cluster. Not blocked by anything. |
| 20 | **new Phase 39, sequenced AFTER Phase 35** | Repo-wide hygiene, not a Tauri slice. Phase 35 deletes the Electron half of the tree, shrinking the lint target set — doing the sweep first wastes work on files about to be removed. |

**Phase 38 was considered and rejected as a destination for both.** It is explicitly scoped to
items that "cannot run on this machine because [they need] hardware or an OS this project does
not [have]", and its own rule 2 requires every relocated item to carry a *source-level gate*.
Neither item is hardware-gated: item 8 is a code fix, item 20 is a lint sweep. Both are runnable
here today.
