# Quick Task 260819-p2d: record the bottle-name prefill defect against 34.13's G-D05-BOTTLENAME

## Why

Phase 34.13's D-05 requires the Steam install dialog's CrossOver bottle-name field to be
**prefilled `GameLibSteam` and read-only**. Only the read-only half is implemented. The field
renders empty, because `crossoverBottle` is never seeded on the Steam path.

This was found by reading source during a user question about per-game bottles — **not** by
running the app. Phase 34.13's manual UAT gate is BLOCKING and human-only (ledger ground rule:
"this executor does not perform, simulate, or infer any of the observations"), so this finding
must NOT be converted into a `FAIL` disposition. It is recorded as a code-read note so the
developer scoring `G-D05-BOTTLENAME` knows the row has three separately-scorable halves and
cannot pass it on the strength of the two that work.

## Evidence

- `src/frontend/screens/Library/components/InstallModal/index.tsx:127` — `crossoverBottle`
  initialised to `''`.
- `index.tsx:634` — the Steam branch passes `crossoverBottle` / `setCrossoverBottle` into
  `WineSelector`, but nothing seeds the value.
- `WineSelector/index.tsx:116` — `setCrossoverBottle(globalConfig.wineCrossoverBottle)` is gated
  on `useSharedPrefix`.
- `WineSelector/index.tsx:301` — the only writer of `useSharedPrefix` is the shared-prefix toggle.
- `WineSelector/index.tsx:292` — that toggle sits inside `!hideSharedPrefixToggle`, a prop the
  Steam branch sets (deliberately, per Phase 17 CR-01).
- `WineSelector/index.tsx:228` — the field's own `onChange` is disabled by `bottleNameReadOnly`.
- `SteamBottleSetup.tsx:213` — the guided wizard DOES seed `DEFAULT_STEAM_BOTTLE_NAME`; the
  34.13 install-modal dialog never got the equivalent.

Net: on the Steam install-modal path `crossoverBottle` is permanently `''`, and the field is
disabled, so the user cannot even type a value in.
