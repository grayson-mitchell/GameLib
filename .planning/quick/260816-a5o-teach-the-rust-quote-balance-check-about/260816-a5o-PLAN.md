<validated_design>
The pipeline below was **prototyped against the real `src-tauri/src/main.rs` and five discriminator
fixtures before this plan was written.** Measured results are in Task 1's `<behavior>` block.
Implement this design; do not invent an alternative.

```
stripRustLineComments   (existing, caller-side via loadMainRsCode)
  -> stripRustRawStrings (existing, WHOLE source - must precede the split)
  -> stripRustEscapes    (existing, WHOLE source)
  -> joinContinuedLogicalLines   <- NEW
  -> stripRustCharLiterals per LOGICAL line
  -> count the quotes, filter odd
```

**The load-bearing ordering fact:** `stripRustEscapes` MUST run **before** the join.
It consumes two-character escapes left-to-right, so an escaped backslash written as a doubled
backslash at end-of-line is eaten as a pair and leaves **no** trailing backslash; a genuine
continuation backslash is followed by a newline, and `.` does not match a newline, so it
**survives**. That is precisely what makes "ends with a backslash" an unambiguous continuation
signal. Joining first would mistake a doubled backslash for a continuation. Task 1 pins this with
a dedicated test.

**Index reporting:** a logical line reports the index of its **first physical line**. The existing
doc comment at lines 190-192 makes index stability an explicit requirement (it is why
`stripRustRawStrings` blanks characters instead of deleting lines); preserve it.
</validated_design>

<rotted_rationale>
`stripRustEscapes`'s doc comment, lines 220-224, currently reads:

> "`.` deliberately does NOT match a newline, so a `\`-continued multi-line string literal keeps
> its trailing backslash and its opening/closing lines still read as odd. **That shape is a REAL
> finding the guard is meant to report (it is indistinguishable from a stripper-truncated
> literal), so this pass must not launder it away.**"

The bolded premise is **false** and is the written form of the bug. A continued literal *is*
distinguishable from a truncated one — by the trailing backslash itself.

The `.`-does-not-match-newline behaviour is nonetheless still **required**, for a new reason: the
surviving trailing backslash is the joiner's signal. So the code does not change; only the
justification does. The test at lines 478-483 that pins this behaviour stays GREEN and keeps its
assertion — but its name and comment state the dead rationale and must be retargeted.

(Per this repo's own ledgered lesson, a pin asserting a *rationale* cannot detect that the *fact*
drifted. Here the inverse happened: the fact held, the rationale rotted. Fix the prose, keep the pin.)
</rotted_rationale>
