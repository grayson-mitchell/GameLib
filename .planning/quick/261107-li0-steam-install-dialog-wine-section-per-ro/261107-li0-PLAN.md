<finding_B>
## Forced-Windows route finding (decides Part B)

Traced in `src/backend/storeManagers/steam/gameInstall.ts` `install()` (around L175-345):
- `forceWindowsViaBottle = overrideRequested && isMac && is_windows_native === true` makes `routeThroughBottle` true.
- The route then comes from `resolveEligibilityBridgeRoute(steamGame)`, which is `bridgeRoute()` → `resolveBridgeRoute(assembleBridgeRouteInput(...))` in `gameEligibility.ts`. `assembleBridgeRouteInput` sets `platformsBottleEligible` from `isBottleEligibleFromPlatforms()`, which is deliberately NOT the widened D-17 wrapper. That function returns true only for `mac_arch === '32'` or `platformsCaptured && is_mac_native === false`.
- A real dual-build game has `is_mac_native === true` and a runnable Mac build, so `platformsBottleEligible` is false and `resolveBridgeRoute` rule 1 returns `route: 'not-eligible'`. The game does not take `installBridgeGame`. It falls through to the CrossOver-missing gate and the bottled path, `installBottleNative`, which installs into the shared `GameLibSteam` bottle with the shared Wine engine. `gameEligibility.ts`'s own doc comment confirms this ("that install went to `GameLibSteam`").
- `mac_arch === '32'` titles are bottle-eligible from platforms already. They do not have a runnable Mac build, so they are not "both a Mac and a Windows build" in the sense of this task.

**Conclusion:** structurally, every forced-Windows install of a dual-build Steam game lands on the bottled Windows Steam client, where a shared Wine choice applies. Per the task rule, Console Mode must NOT offer Windows for such a game, and the desktop dialog stays the place for it. A Platform row with one selectable value is a dead focus stop on a gamepad surface, so Console renders no Platform row for Steam. Its behaviour does not change: `showPlatform`/`hasWine` keep `!isSteam`, and `installSteamGame(game.app_name, game)` keeps no 4th argument. Task 3 records this in source and adds a gate. If the backend later routes forced-Windows dual-build installs to the bridge, that gate is the place to revisit.
</finding_B>
