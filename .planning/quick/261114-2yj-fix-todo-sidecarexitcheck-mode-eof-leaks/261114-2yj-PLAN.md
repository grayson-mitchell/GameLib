<objective>
Fix the todo `2026-11-14-sidecar-exit-check-eof-leaks-profile-and-child.md` (from 66.4-REVIEW WR-03).

`runEof` in `meta/sidecarExitCheck.ts` is shaped `try { ... return invalid(...) / return finish(...) } finally { profile.dispose() }`. Both helpers call `process.exit()` synchronously, so the `finally` never runs. As a result the fake-HOME profile, which holds the sidecar's logs and config, is never shredded. On the never-READY INVALID path the sidecar child is also left running. That hang is the very thing this tool exists to detect, and the orphan keeps writing into the profile that was never deleted.

The fix has three parts:

- The drivers return a `Report`, and the process exits once, in the CLI guard, after `runEof`'s `finally` has run.
- That `finally` reaps the script's own child (SIGKILL, bounded wait) and then disposes the profile.
- A platform-independent unit test drives the never-READY path with a stub sidecar. It asserts that the child is dead and the profile directory is gone.

Purpose: per the fake-HOME convention, cleanup belongs to the harness, not to anyone's memory. Quick `260913-901` left 103 MB of unredacted captures on disk exactly this way. A hang detector that leaves its own hung child behind is self-defeating.

Output: modified `meta/sidecarExitCheck.ts` and `meta/__tests__/sidecarExitCheck.test.ts`, plus the todo moved to `completed/`.

Ordering: Task 1 is the tracer. It wires the never-READY path end-to-end: the test, Report-returning drivers, the reap and dispose, and a CLI guard that finishes once. Task 2 adds the exit-code seam and its test, corrects the docblocks, and closes the todo.
