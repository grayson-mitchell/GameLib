**Fix patterns (apply as patterns, not per-line notes):**
1. Loops over `arr[i]` with `i < arr.length`: convert to `for...of`, `.entries()`, or
   destructuring where behaviour is identical.
2. Codegen / parse / regex / argv sites (`match[1]`, `split(...)[n]`, `argv[i + 1]`,
   `lines[i]`): narrow with an explicit check that throws a clear `Error` naming the input and
   expectation (e.g. "malformed manifest line: ..."). Never invent a default (`?? ''`, `?? 0`)
   that could change generated bytes or hide malformed input. A `?? default` is only allowed
   where the code already treated undefined that way (e.g. an optional flag absent).
3. Record lookups (`map[key]`) whose value is used: narrow with `if (v === undefined) throw` or
   restructure with `in`/`Map.get` + check; keep existing semantics where `undefined` was already
   handled downstream (then just let the type say `| undefined`).
4. Tests: when an indexed element is dereferenced or passed to a matcher that would pass on
   `undefined`, narrow with a throwing helper `defined(value, label)` / `at(arr, i)` so a missing
   element still fails loudly. `?.` is acceptable only when the following assertion would fail on
   `undefined` anyway (e.g. `expect(x?.name).toBe('foo')`). Never weaken `toEqual`/`toBe`.
   Helper placement: a file-local non-exported function, or, if 3+ test files need it, one shared
   `meta/__tests__/fixtures/indexed.ts` exporting only what is used (jest only collects
   `*.test.ts`, so it is not a suite). Create the shared file in the first task that needs it.
5. Forbidden: non-null `!`, `as T` casts that widen or erase undefined (`as string`, `as any`,
   `as unknown as`), `// @ts-expect-error`, changes to spawn `env` objects.
