# Quick task: stop `activeTour` surviving a launch

## Problem

`TourContext` persists the **whole** `TourState` -- including `activeTour` -- to
`localStorage['heroic-tour-state']` on every change, and `readPersistedTourState` restores
`activeTour` verbatim on boot. Nothing anywhere clears it.

So a session that ends while a tour is on screen (crash, `pkill`, force-quit -- anything that is
not a clean `endTour`) leaves `activeTour: "nav-tour"` on disk, and the **next launch opens that
tour with no user click**. `NavShellTour` and `LibraryTour` both gate purely on
`isTourActive(TOUR_ID)`, so a restored id is indistinguishable from a real `startTour()`.

Found during the 34.12-07 live gate, where it also **contaminated the measurement**: a "no tour on
launch" observation torn down with `pkill` mid-tour comes back positive on the next run for
reasons that have nothing to do with the code under test.

## Why `activeTour` is the only field that must not persist

- `completedTours` -- a genuine preference. Must survive. Drives "you have already seen this".
- `tourProgress` -- retained (currently written but never read); harmless, out of scope.
- `activeTour` -- a pointer to a **live intro.js overlay bound to DOM nodes in this window**. It
  has no meaning outside the session that created it. Persisting it is the bug.

## Tasks

### Task 1 -- drop `activeTour` at both boundaries

`src/frontend/state/TourContext.tsx`:

1. In `readPersistedTourState`, stop deriving `activeTour` from the parsed candidate; always return
   `defaultState.activeTour`. Update the docstring to say why. Leave the `tourProgress` /
   `completedTours` normalisation exactly as-is -- it is load-bearing for T-34.12-05-01.
2. In the persist `useEffect`, write only `{ tourProgress, completedTours }`.

Both halves are deliberate, not redundant: the write-side change stops NEW poison, the read-side
change heals blobs ALREADY on disk on machines today (including the operator's). Either alone
leaves a real gap.

### Task 2 -- pin it

`src/frontend/state/__tests__/tourContextState.test.ts`:

1. The existing `'returns a well-formed round-trip value unchanged, field for field'` test asserts
   `activeTour: 'nav-tour'` survives. It now encodes the defect -- rewrite it to assert the other
   two fields round-trip while `activeTour` comes back `null`.
2. Add a test named for the defect, so a future reader sees the intent rather than an incidental
   assertion.
