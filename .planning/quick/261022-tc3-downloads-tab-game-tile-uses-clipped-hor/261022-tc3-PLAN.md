<objective>
Fix the Downloads screen hero's cover tile so it uses the portrait art the Library grid card uses, instead of the landscape header art cropped into a 3:4 box.

Root cause (confirmed by reading the code, so no further investigation is needed):
- `DownloadHero/index.tsx` line 98 picks the tile with `gameInfo?.art_cover || gameInfo?.art_square`. The tile is `.downloadHero__cover`, styled `aspect-ratio: 3 / 4; object-fit: cover` in `DownloadHero/index.css`.
- Across the stores, `art_cover` is the landscape image and `art_square` is the portrait one. For Steam, `src/backend/storeManagers/steam/games.ts:776-779` sets `art_cover = header.jpg` (landscape 460x215) and `art_square = library_600x900.jpg` (portrait). Because the code prefers `art_cover`, every Steam game shows its header cropped to 3:4. Epic and GOG behave the same way.
- The Library grid card (`Library/components/GameCard/index.tsx:148-151, 574-586`) does the opposite. It uses `overrides?.art_square || art_square` as the src and falls back to `overrides?.art_cover || art_cover`. The hero also ignores the user's per-game art overrides, which may be what the user meant by "the correct artwork in that profile". Those overrides are attached to the frontend library entries (`GlobalState.tsx` `applyGameOverrides`), not to `getGameInfo()` results.
- Out of scope: the queue rows in `DownloadManagerItem/index.tsx:269` also use `art_cover || art_square`, but their `<img>` is styled `aspect-ratio: 16/9`, so landscape-first is correct there. Leave them unchanged.

Output: a pure `heroCoverSources` helper with unit tests, wired into the hero's cover `CachedImage`.
</objective>
