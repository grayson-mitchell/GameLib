<objective>
Make the game page load its own game when it is opened without router state, instead of throwing into
RouteErrorSurface. A thin outer `GamePage` resolves the `GameInfo` (router state first, then the library store, then
`getGameInfo`) and renders a loading state, a "game not found" state, or the existing page body.

Purpose: every in-app entry passes `{ gameInfo }` today, so the crash is latent, but the next entry point added
without state (a deep link, a restored tab, a new screen) would crash the page again. `runner` and `appName` are already
in the URL, so the page can recover by itself.

Output: a new `GamePageGate.tsx` module and its jsdom test, `GamePage/index.tsx` split into the gate-wrapped default
export plus a `GamePageContent` body, one CSS rule, one catalogued string, a corrected tabLocationMemory comment, and the
todo closed.

Deviation from the orchestrator's preferred shape, with the reason: the outer resolver lives in its own module
(`GamePageGate.tsx`, a render-prop component) rather than inline in `index.tsx`. A component cannot be jest-mocked from
inside the module that uses it, so an inline outer could only be tested by rendering the whole 830-line body. As its own
module the gate renders under jsdom with a small probe child, with no mocking of the body at all. The route still
lazy-loads `index.tsx`'s default export, which is now the thin outer `GamePage`.
</objective>
