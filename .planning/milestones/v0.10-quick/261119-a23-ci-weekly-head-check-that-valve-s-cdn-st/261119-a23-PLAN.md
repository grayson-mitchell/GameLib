<design_decisions>
Claude's discretion (quick task, no CONTEXT.md). Recorded here so the executor does not re-decide them.

1. **Plain CommonJS `.cjs`, `node:` builtins only**, following `meta/clippyRatchet.cjs`. Node 22's global `fetch` and `AbortSignal.timeout` cover everything the script needs, so CI needs no `pnpm install`. jest `require`s the file directly (same as `meta/__tests__/clippyRatchet.test.ts`, with the `@typescript-eslint/no-require-imports` disable/enable pair), and because `runTs.cjs` does not bundle it, the `require.main === module` guard works. ESLint ignores `**/*.cjs` (`eslint.config.mjs`), so only the two `.ts` test files are linted.
2. **Redirects are NOT followed (`redirect: 'manual'`). This deliberately differs from the orchestrator's "redirect follow" note.** Production `pin_client()` in `steam_api_pin.rs` builds its reqwest client with `redirect::Policy::none()`, and `LiveIo::fetch` treats every status other than 200 as a failure. A CDN that started redirecting would therefore already break fresh installs. A check that followed the redirect would stay green while the app failed. A 3xx is the verdict `http-<status>`. The User-Agent is `GameLib`, the same as production. Node fetch with `method: 'HEAD'` and `redirect: 'manual'` was probed at planning time: both hosts answered 200 with `Content-Length` equal to `PIN.package_size`, and a nonexistent package answered 404.
3. **A missing `Content-Length` header is a failure.** The todo asks for equality. Production tolerates a missing header, but both hosts send one today.
4. **Every host is probed, sequentially, and probing never stops at the first pass.** A dead secondary therefore surfaces as a `::warning::` while the run stays green.
5. **No retries.** A failed run is classified instead. If every host failed at the transport level (`error-*` verdicts, no HTTP answer at all), the check reports "unreachable" and advises re-running via `workflow_dispatch` before re-pinning. If any host answered with HTTP, it reports "no longer served" with the re-pin/self-host remedy. Both cases exit 1.
6. **Exit codes:** 0 = at least one host passed. 1 = CDN check failed. 2 = usage error, unreadable pin file or unparseable pin. A test can tell exit 2 from a CDN failure, and exit 2 always happens before any request.
7. **The `paths:` filter is acceptable here, unlike in `rust-test.yml` and `audit.yml`.** Those files refuse a `paths:` filter because they are (or will be) REQUIRED checks, and GitHub never reports a status for a filtered-out workflow. This check is deliberately NOT required: it can go red with no change in the repo whenever Valve drops the build. The header comment says so.
8. **The workflow mirrors `audit.yml`'s setup:** checkout@v6, pnpm/action-setup@v4, setup-node@v6 with `node-version-file: 'package.json'`, and no `pnpm install`. It runs `pnpm check:steam-api-pin-cdn`, so CI exercises the package.json entry itself.
9. **The parser is strict and textual.** It does not evaluate Rust; it reads two literal shapes and rejects anything else (rules in Task 2). Every `pnpm test:ci` run parses the real file, so CI catches a reshaped `steam_api_pin.rs` on the PR that reshapes it. The pointer comment added to the .rs file tells a Rust editor why.
</design_decisions>
