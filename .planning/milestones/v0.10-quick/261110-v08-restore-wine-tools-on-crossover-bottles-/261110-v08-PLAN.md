<objective>
Restore Winecfg, Run EXE and the Winetricks tab on macOS for games whose engine is a CrossOver bottle.

Purpose: Phase 61 made CrossOver the default macOS engine, and the upstream `!isCrossover` gate (git a40f27fa4) around the Wine tab's `<Tools />` block, copied by Phase 45 into `shouldShowWinetricksTab`, now hides these tools for most Mac games. Found in 66.1-HUMAN-UAT.md item 5. The user wants them usable on a CrossOver bottle.

Investigation result (planner, already done — do not redo): this is a frontend gating fix only. The backend already routes every one of these tools to the game's real bottle and engine:
- `callTool` (src/backend/sidecar/runnerMiscFlowRegistration.ts:145) calls `runWineCommandOnGame` (src/backend/tools/index.ts:1566), which ignores the passed `gameSettings` and calls `resolveToolSettings(..., { ensureBottle: true })` (src/backend/engine/toolSettings.ts). For a CrossOver-engine game that returns `buildCrossoverGameSettings` (src/backend/engine/launchSettings.ts:48): `wineVersion.type: 'crossover'`, CrossOver's `wine` bin, `wineCrossoverBottle: <per-game bottle>` — the same resolution the launch overlay uses.
- Winetricks run (`runWithArgs`, tools/index.ts:~923, `ensureBottle: true`) and installed list (`listInstalled`, tools/index.ts:~1329, `ensureBottle: false`) use the same resolver.
- `commandRunner.runWineCommand` (src/backend/commandRunner.ts:249) already skips the prefix-file check for `type === 'crossover'`.
- Steam titles are refused by `runWineCommandOnGame` (`winePrefixToolsAvailable: false`), which is why this plan keeps Mac Steam titles' visibility unchanged.

No backend file changes. No new wine-resolution logic.

Output: a pure `wineToolsHidden()` helper in visibility.ts, the Wine tab rendering `<Tools />` outside the `!isCrossover` toggle block, updated tests, and an operator live check.
</objective>
