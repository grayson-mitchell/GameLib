1. New edit state:
   - `editingIndex: number | null`, initially null.
   - `editKey` and `editValue` strings.
   Remove the `originalInputs` state and `setOriginalInputs`. Their only writer was the old
   `editRow`. The footer dirty flag becomes "newVarName or newVarValue is non-empty", so the
   save hint still appears only while something is typed in the footer. Leave the footer's
   connector-split and validation `useEffect` and `addRow` behaviour exactly as they are.

2. `editRow(index: number)`:
   - Set `editingIndex = index`, `editKey = rowData[index].key`, `editValue = rowData[index].value`.
   - Do NOT touch `newVarName`/`newVarValue`. This is the defect being fixed.
   - Clicking Edit on another row while one is open switches to the new row and drops the
     unsaved edit.
   - Change the Edit button's onClick to pass the map index.

3. Edit-row validation is derived during render, not stored:
   - When `editingIndex !== null && validation`, `[editKeyError, editValueError] = validation(editKey, editValue)`.
   - Otherwise both are ''.
   - Connector parity with the footer: in the edit key input's onChange, if `connector` is set,
     the new key contains it, and `editValue` is empty, split on the connector into editKey and
     editValue, the same way the footer effect does. Otherwise set editKey.

4. `saveEdit()`:
   - Return without saving when any of these hold: `editingIndex === null`, `editKeyError` is
     set, `editValueError` is set, `(!editKey && fullFills.key)`, or `(!editValue && fullFills.value)`.
     These are the same guards as `addRow`, plus valueError.
   - Otherwise build a new array:
     - Put `{ key: editKey, value: editValue }` at `editingIndex`.
     - Drop any other entry whose key equals editKey. This mirrors addRow's upsert-by-key, so a
       rename onto an existing key never yields duplicate keys.
   - Then `setRowData(next)`, call `onChange(next)` exactly once, and clear the edit state
     (index null, key and value '').

5. `cancelEdit()` clears the edit state and does NOT call onChange.

6. `removeRow` also clears any in-progress edit, since indices shift.

7. Shared `onKeyDown` handler for both edit inputs:
   - Ignore events while `event.nativeEvent.isComposing` (IME, same as PathSelectionBox).
   - `Enter`: preventDefault, then `saveEdit()`.
   - `Escape`: preventDefault and stopPropagation, then `cancelEdit()`. This keeps Escape from
     also closing the enclosing settings dialog.
   - Other keys do nothing.

8. Rendering a row where `index === editingIndex`:
   - Replace each `<span>` cell with a `TextInputField`:
     - Key cell: htmlId `${htmlId}-edit-key`, value editKey, `extraClass={editKeyError ? 'error' : ''}`, `autoFocus`.
     - Value cell: htmlId `${htmlId}-edit-value`, value editValue.
     - Same `label` and `placeholder` as the matching footer inputs.
   - Keep the middle connector `<td>`.
   - The action cell shows two SvgButtons in place of Edit/Remove:
     - Save: `CheckIcon` from '@mui/icons-material/Check', color var(--success).
     - Cancel: `CloseIcon` from '@mui/icons-material/Close', color var(--danger).
   - Directly after the editing row, render `<tr className="error"><td colSpan={3}>{editKeyError || editValueError}</td></tr>`,
     but only when one of the two is non-empty.
   - Every SvgButton gets `title` and `aria-label` from the same `tGamelib` call:
     - Existing Edit row button: `'gamelib:twoColTable.edit'` / 'Edit'.
     - Existing Remove row button: `'gamelib:twoColTable.remove'` / 'Remove'.
     - Save: `'gamelib:twoColTable.save'` / 'Save'.
     - Cancel: `'gamelib:twoColTable.cancel'` / 'Cancel'.
     Use `const { t: tGamelib } = useTranslation('gamelib')` beside the existing `t`. Keep the
     existing `two_col_table.save_hint` call on `t` unchanged, because it is an upstream key.
   - The `warning` prop shows when the footer value or (while editing) editValue is non-empty.
   - The tests in Task 2 key on these htmlIds and aria-labels. Do not rename them.
