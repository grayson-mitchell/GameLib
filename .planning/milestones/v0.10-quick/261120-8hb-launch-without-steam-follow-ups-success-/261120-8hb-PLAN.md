<objective>
Three follow-ups to quick 261117-q1t (the per-game "Launch without Steam" setting, macOS only), found by
the operator during live testing:

1. **Success log line.** A launch without Steam that starts logs one info line naming the appId, the
   kind (mac-native or bridge) and the binary or exe. Today a successful start writes nothing. Dead
   Age 2 launched, but the log could not show which route ran.
2. **In-app failure notice.** A spawn or launch failure of a launch without Steam shows in the app,
   through the existing bottom-right notice stack (the `steamRequestNotice` request slot of
   `SteamEngineLaunchNotice`). Today it goes only to an OS notification, which the operator never saw.
   Legends of Aethereus hit EBADARCH and the Play button just looked dead.
3. **"This game needs Steam" notice.** A game launched without Steam whose process ends within one
   threshold constant gets an in-app notice saying it probably needs the Steam app, with a pointer to
   Run > Launch without Steam. Avernum 6 (bridge) quit with "SteamAPI_Init() failed". WazHack
   (Mac-native) relaunched itself through Steam. So detection is keyed on early exit of the process
   GameLib started.

Purpose: the operator can see from the log which route ran, and sees why a launch without Steam did
nothing or quit, without leaving GameLib.
Output: new module `directLaunchOutcome.ts`, two new request-notice kinds wired from both launch
routes to the request slot, one new catalogue string in all 49 gamelib catalogues, and the owed live
checks recorded in the todo.

**Decisions taken at Claude's discretion (record them in the SUMMARY):**
- **Threshold: `DIRECT_LAUNCH_EARLY_EXIT_MS = 15_000`.** The operator asked for "about 10 seconds".
  The constant rounds that up to 15 s so the window also covers:
  - a Unity game that calls Steam's restart-through-Steam check after its splash screen (WazHack);
  - a bridge game under Wine that shows its own "Steam must be running" box and quits after a quick
    dismissal (Avernum 6).

  15 s is still far below any real play session. It is one exported constant, so the live check can
  tune it.
- **What the window measures.**
  - Mac-native: spawn to exit of the binary GameLib spawned.
  - Bridge: the bottle process monitor's first sighting of the game to `onStopped`. If the monitor
    never saw the game, the window starts at the launch start. The first sighting is the anchor
    because Wine and CrossOver boot time would otherwise eat into the window.
- **The OS notification is replaced, not duplicated.** Precedents:
  - quick 261106-pvk moved "Steam never started your install" from a system notification to this
    same request slot;
  - plan 61-27 moved the launch-deadline notice into the app.

  A toast plus an OS notification for one failure is noise.

  already translated in all 49 catalogues. The needs-Steam toast adds one key,
