# Phase quick-261120-963 Plan 01: Restart note and "Restart Steam now" flash Summary

At the end of a GameLib depot install the adoption reading is now taken after the InstallApp verdict and before the record, so the record's first push already carries Steam's signed-in state, and the poll starts as a non-handoff once Steam has adopted the install.

## Commits

- `d0459b101` fix(quick-261120-963): stop the restart note flashing at the end of a depot install (Tasks 1 and 2 together; code only).
- Task 3 (todo annotation) is edited on disk but NOT committed, per the orchestrator's instruction not to commit docs artifacts. The orchestrator's docs commit should include `.planning/todos/pending/2026-11-18-adoption-note-restart-flash-at-install-end.md`.

## Root cause

- 7b (Machinarium 40700, signed out): the InstallApp verdict did precede the record (`InstallApp adoption of 40700 not used (library-lookup-unverified)` then `recorded pending Steam adoption`, both 21:48:54), so the ordering hypothesis was wrong. `recordAndWatchPendingAdoption` pushes at once, `getSteamAdoptionStatus` reads `steamSignedIn` from a cache the Rust watch fills only on its first tick (up to 5 s), so the first push carried `null`. `AdoptionNote.tsx` line 80 treats only `false` as signed out, so null rendered "Steam will restart once when you press Play." and "Restart Steam now". (Gate session `/tmp/gamelib-gate-20261118T063108Z`, `gamelib-launch-2.log` 780-790 and 887-900, `terminal.log` 117-131.)
- 7a (Wildermyth 763890, signed in, InstallApp ok): no pending record existed, so the only other render path is `is.installing && statusContext === 'steam-waiting-for-restart'`, produced only by `install_once.rs` `state_flags == 1026 && is_native_handoff`. After InstallApp returned ok the poll still started with `isNativeHandoff: true`, and Steam's own InstallApp validation writes 1026 into the ACF. Inferred by elimination; neither log sink records that tick, so the live check is owed.

## Fix

- `recordAndWatchPendingAdoption(deps, appId, record, reading?)` seeds `signedIn` from a non-null reading before the store write and push; null or omitted leaves behaviour unchanged (D-10).
- Install-end branch: `readSteamAdoption` after the InstallApp attempt, before the record; one log line `adoption reading for <id> at install end: signedIn <v|unavailable>`; a reading with `adopted === true` writes no record, clears any stale one, logs the evidence word; the `recorded pending Steam adoption` line is kept byte for byte.
- `adoptedByInstallApp` renamed `steamAdopted` (also set by an adopted reading); poll options now `isNativeHandoff: !steamAdopted`. Steam-not-running and non-adopted paths keep `true`.
- `migrateOneHold` passes the reading it already holds.
- Frontend, `adoptionStatus.ts` and the Rust crates unchanged.
