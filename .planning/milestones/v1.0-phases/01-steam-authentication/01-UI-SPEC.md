# Phase 1 — UI Design Contract: Steam Authentication

> Visual and interaction contract for Phase 1. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Consumed by gsd-planner (task generation), gsd-executor (implementation reference), gsd-ui-auditor (retroactive audit).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom SCSS + CSS custom properties) |
| Preset | not applicable |
| Component library | Material UI v5 (@mui/material ^5.17.1) — already in project |
| Icon library | Font Awesome free (brands + solid + regular) + @mui/icons-material — both already in project |
| Font | Rubik (headings, --primary-font-family) / Cabin (body + buttons, --secondary-font-family) — both loaded via @fontsource |

**No shadcn initialization.** Project uses its own SCSS design token system defined in
`src/frontend/styles/_colors.scss`, `_typography.scss`, `_spacing.scss`, and `themes.scss`.
All new styles for Phase 1 MUST use the existing CSS custom property tokens — do not introduce
inline hex values or hard-coded px values outside of layout geometry.

## Spacing Scale

The project uses an em-based spacing system anchored at 16px root font-size.
Map to pixel equivalents when reasoning about layout geometry.

| Token | Em Value | Pixel Equivalent | Usage in Phase 1 |
|-------|----------|-----------------|-----------------|
| `--space-3xs` | 0.25em | 4px | Icon gaps, border-radius on inputs and cards |
| `--space-2xs` | 0.5em | 8px | Dense inline padding |
| `--space-xs` | 0.5em | 8px | Icon padding inside Runner logo strip; small gaps |
| `--space-sm` | 1em | 16px | Input internal padding; button padding |
| `--space-md` | 1em | 16px | Default vertical rhythm between form elements |
| `--space-lg` | 1.5em | 24px | Panel internal padding; section separation |
| `--space-xl` | 3em | 48px | Tab-to-form-body gap |

Fixed equivalents (use when em is inappropriate, e.g., fixed-height elements):

| Token | Value | Usage in Phase 1 |
|-------|-------|-----------------|
| `--space-md-fixed` | 16px | Consistent button height baseline; compact row gap in multi-field forms |

**Exceptions:**
- Runner card height: 60px fixed (matches all existing runner cards — do not change)
- Runner logo strip width: 60px fixed (matches all existing runner cards — do not change)
- QR code container: 200×200px fixed (minimum readable scan size on desktop)
- Input field height: 40px fixed (matches existing `sid-input` pattern in SIDLogin)
- Tab bar minimum height: 40px (matches WineManager MUI tab pattern: `min-height: 40px`)

## Typography

All sizes use the project's 1.2 type-scale ratio with 16px root.
Reference: `src/frontend/styles/_typography.scss`.

| Role | CSS Token | Approx Size | Weight Token | Weight | Font Family | Line Height | Usage in Phase 1 |
|------|-----------|-------------|-------------|--------|-------------|-------------|-----------------|
| Screen heading | `--text-lg` | ~19px | `--bold` | 700 | Rubik | 1.2 | Login screen title "Sign in to Steam"; step headings |
| Body / instructional | `--text-md` | 16px | `--regular` | 400 | Cabin | 1.5 | SteamGuard instruction text; detection warning body; tab panel copy |
| Caption / error | `--text-sm` | ~13px | `--regular` | 400 | Cabin | 1.4 | Inline error messages; helper text beneath inputs; input labels |
| Micro-caption | `--text-xs` | ~11px | `--regular` | 400 | Cabin | 1.4 | QR auto-refresh note; secondary captions |

**Weight constraint:** Use exactly 2 weights within any single view — regular (400) for body
content and bold (700) for headings and call-to-action labels. Button text weight (500, medium)
is inherited from `_buttons.scss` and need not be declared or applied manually in Phase 1
components.

## Color

The project supports multiple user-selected themes via CSS custom properties.
**All Phase 1 components MUST reference the semantic tokens only — never theme-specific hex values.**
The midnightMirage theme (body.midnightMirage) is the design reference for visual QA.

| Role | Semantic Token | midnightMirage Value | Usage |
|------|---------------|---------------------|-------|
| Dominant surface (60%) | `--body-background` | `#070a0b` | Page background behind login panel |
| Secondary surface (30%) | `--input-background` | `#272f31` | Runner card background; tab panel container; form inputs |
| Accent (10%) | `--accent` | `#8bffff` | Reserved for: tab active indicator; link highlight; focus rings; hover color on runner login text |
| Destructive | `--danger` | `#a62b2b` | Reserved for: "Log Out" text in Runner card (logged state); logout loading text |
| Warning surface | `--status-warning` | `#f8ae79` | Steam client not-found warning border/icon |
| Success | `--status-success` | `#0ce396` | Post-authentication confirmation (brief) |
| Text primary | `--text-default` | `#caf3fd` | All primary readable text |
| Text secondary | `--text-secondary` | `#a5edfd` | Username in runner card; instructional text |
| Primary button fill | `--brand-primary` | `#1de8f5` | "Sign In to Steam" CTA; "Verify Code" CTA |
| Disabled button | `--disabled-button` | `var(--neutral-03)` | Buttons while loading or invalid input |

**Accent is reserved exclusively for:** tab active state indicator, hover color on `.runnerLogin`
text, link underline highlights, and keyboard focus rings. Never use `--accent` as a button fill,
background fill, or general text color.

**QR code foreground/background:** QR SVG renders with `fgColor="#000000"` (black)
on `bgColor="#ffffff"` (white). Wrap in a white-background container (8px padding) to ensure
contrast regardless of theme. The white container uses `border-radius: var(--space-3xs)`.

## Screen Layout: `/loginweb/steam`

The screen uses the same outer wrapper as the login page (centered panel over blurred background),
but owns its own inner layout. It does NOT use the `loginContentWrapper` / `runnerList` structure
— it renders as a standalone auth panel.

```
┌──────────────────────────────────────────┐  width: min(480px, 95%)
│  [← Back to Login]  (link button, top)  │  padding: --space-lg (24px)
│                                          │  background: --body-background
│  "Sign in to Steam"     [title, --text-lg, Rubik bold]
│                                          │
│  ┌──────────────────────────────────────┐│  tabsWrapper: --body-background bg
│  │  [ QR Code ] [ Username & Password ] ││  border-radius: 12px; padding: 4px
│  └──────────────────────────────────────┘│
│                                          │
│  [TAB PANEL CONTENT — see states below] ││  padding-top: --space-lg
│                                          │
└──────────────────────────────────────────┘
```

**"Back to Login" navigation:** Renders as `.button.is-link` top-left; navigates to `/login`.
Not to be confused with the "Back to Credentials" button on step 2 of the credential flow (which
returns within the screen to step 1, not to `/login`).

**Focal points:**
- QR Code tab: primary visual anchor is the 200×200px QR image, centered in the tab panel.
- Credentials tab: primary visual anchor is the "Sign In to Steam" CTA button (full-width, `.button.is-primary`), at the bottom of the form.

## Interaction States

### State 1: Steam Client Not Found (blocks all other states)

Fires before rendering tabs. When `window.api.checkSteamInstalled()` returns false:

```
[Warning icon: FontAwesomeIcon faTriangleExclamation, --status-warning color]
"Steam client not found"         [--text-lg, bold]
"GamerLib requires the Steam client to authenticate and launch games."  [--text-md, regular]

[ Download Steam ]    [ Return to Login ]
  .button.is-secondary   .button.is-tertiary
  opens store.steampowered.com/about/  navigates to /login
```

Container: `border: 2px solid var(--status-warning)` with `border-radius: var(--space-3xs)`,
`padding: var(--space-lg)`. Same visual language as `.disabledMessage` in `Login/index.scss`.

---

### State 2: QR Code Tab — Generating

Shown while `steam-session` is generating the challenge URL:

```
[faSyncAlt spinning, --text-default color, 40px]
"Generating QR code..."     [--text-sm, --text-secondary color]
```

---

### State 3: QR Code Tab — Active

QR displayed and awaiting mobile scan:

```
┌─────────────────────────────────────┐
│  Open Steam on your phone and go   │   [--text-md, regular]
│  to Steam Guard → Add Authenticator│
│  or Approvals → Approve Sign-In    │
│                                     │
│  ┌──────────────────────────────┐   │
│  │  [white 8px-pad container]   │   │   200×200px QR (react-qr-code SVG)
│  │  <QRCode value={url} size=   │   │
│  │  {200} fgColor="#000000"     │   │
│  │  bgColor="#ffffff" />        │   │
│  └──────────────────────────────┘   │
│                                     │
│  QR code refreshes automatically.  │   [--text-xs, --text-secondary]
└─────────────────────────────────────┘
```

QR container: `display: flex; justify-content: center; padding: var(--space-md) 0`.
White wrapper: `background: #ffffff; padding: 8px; border-radius: var(--space-3xs); display: inline-block`.

**Auto-refresh:** When the challenge URL expires (~30s), the `<QRCode value>` prop updates
silently — no transition animation, no user-visible "refreshing" state unless the new URL fetch
takes >500ms (then show brief spinner in place of QR).

---

### State 4: QR Code Tab — Scan Confirmed (awaiting backend session)

Mobile scanned the QR, steam-session is completing the handshake:

```
[faCheckCircle, --status-success color, 40px]
"QR scanned. Completing sign-in..."   [--text-md, regular, --text-default]
```

---

### State 5: Credential Tab — Step 1

```
Username
[________________________]   <input type="text" height:40px --input-background>

Password
[________________________]   <input type="password" height:40px --input-background>

[ Sign In to Steam ]         .button.is-primary, full width, uppercase, disabled when fields empty
```

Input labels: `--text-sm`, weight `--regular`, `--text-secondary` color.
Label sits directly above input with `margin-bottom: var(--space-3xs)`.
Vertical gap between label+input pairs: `var(--space-md)` (16px).
Button margin-top: `var(--space-lg)` (24px).

---

### State 6: Credential Tab — Step 1 Loading

```
Username / Password fields: remain visible, opacity 0.5 (visual lock)

[ [faSyncAlt spin]  Signing in... ]   .button.is-primary, disabled, full width
```

---

### State 7: Credential Tab — Step 1 Error

Inline error appears between password field and submit button:

```
[faCircleExclamation icon]  "Incorrect username or password. Check your credentials and try again."
```

Error container: `color: var(--danger)`, `font-size: var(--text-sm)`, `margin-top: var(--space-xs)`.
Error text auto-clears after 3 seconds (matching SIDLogin pattern) OR clears on next keystroke.

---

### State 8: Credential Tab — Step 2 (SteamGuard)

Triggered after credentials accepted, steam-session requests a SteamGuard code:

```
"Check your authenticator app or email for a Steam Guard code."   [--text-md, regular]

Steam Guard Code
[____________]   <input type="text" inputMode="numeric" maxLength={5} width:60%>

[ Verify Code ]        [ Back to Credentials ]
  .button.is-primary     .button.is-tertiary
  disabled when len<5    returns to step 1 (fields reset)
```

"Back to Credentials" button returns to State 5 (step 1). Fields in step 1 clear on back
navigation — user must re-enter credentials (security convention: never re-populate passwords
on error/back).

---

### State 9: Credential Tab — Step 2 Error

```
[faCircleExclamation icon]  "Incorrect code. Check your authenticator and try again."
```

Same styling as State 7 error. If error is specifically a network failure:
`"Could not reach Steam. Check your connection and try again."`

---

### State 10: Authentication Success (either flow)

Navigates to `/login` (the main login screen). The Steam Runner tile now renders in its
logged-in state (State 11 below).

---

### State 11: Runner Tile — Logged In (Manage Accounts view)

Renders via the existing `Runner` component with `isLoggedIn=true`.

```
┌─────────────────────────────────────────────────────┐  height: 60px
│ [Steam logo  ]  Logged in as grayson    [ Log Out ] │
│ [60×60, FA   ]  [--text-secondary, --text-lg]  [--danger, bold, uppercase]
│ [faSteam icon]                                       │
└─────────────────────────────────────────────────────┘
```

Logo strip: `background-color: var(--text-default)` (matches all other runner icons).
`faSteam` icon renders via `<FontAwesomeIcon icon={faSteam} />` inside the `.runnerIcon.steam` div.
FA SVG inherits `.runnerWrapper svg { fill: var(--body-background) }` — renders dark-on-light.

Username truncation: 20 characters max, append `...` if longer (matches existing Runner behavior).

"Log Out" in loading state: renders "Logging out..." in same `--danger` color, no spinner needed
(fast operation — matches existing pattern).

## Accessibility Notes

Follow existing Heroic patterns (no new accessibility requirements declared in CONTEXT.md).
For Phase 1-specific elements:

- QR code `<svg>` must have `aria-label="Steam QR code for mobile login"` and `role="img"`
- Tab switcher: MUI Tabs renders `role="tablist"` with `aria-controls` / `aria-labelledby` automatically
- Form inputs: each `<input>` must have an associated `<label>` (use `htmlFor` + `id`)
- Error messages: rendered in a `<p role="alert">` so screen readers announce them on appearance
- SteamGuard input: `aria-label="Steam Guard code"`, `aria-describedby` pointing to instructional text
- "Download Steam" button: `aria-label="Download Steam client from steampowered.com"` (clarifies external link behavior)
- Focus management: when transitioning from step 1 to step 2, move focus to the SteamGuard code input
