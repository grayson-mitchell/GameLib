<objective>
Fix CR-01 (VERIFICATION gap 3), per orchestrator decision 2. Phase 52 flipped SteamClient017/014
to `wire`, and `emitSteamClientForwardedLookup` now returns NULL on a transport failure, on a native
`present == 0`, and on an exact-version miss, for EVERY x64 title. Before the phase, an ordinary
x64 title (ELEX 411300) got its local proxy or `&g_x64_null_object_instance`.

Chosen design (the reviewer's first option, stated concretely): a shim-global
`g_bridge_steamstub_path_active`, set by `GameLibBridge_CreateInterface`. Only `steamclient64.dll`
calls that export, and only on the SteamStub check path. While the flag is clear, every SteamClient
GetISteam* lookup takes the pre-phase local path with no wire round-trip. Once it is set, the
lookup forwards exactly as 52-01 built it.

Purpose: SteamStub titles keep the "never fabricate" boundary. Non-SteamStub x64 titles go back to
the behaviour ELEX was measured on.
Output: generator change, regenerated sources, pin tests.
</objective>
