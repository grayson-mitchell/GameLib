Two cancel races from 59-REVIEW plus the backend half of G21. All three edit
`src/backend/storeManagers/steam/games.ts`, so they share one plan (games.ts is hot; no other
wave-1 plan touches it).

- WR-02: a reinstall right after a cancel. The prior depot run is still tearing down; the new
  install registers its provisioning controller with `createAbortController(appId)`; the prior
  run's `runNativeDepotDownload` finally then calls `deleteAbortController(appId)`
  unconditionally and removes the NEW controller, so a cancel during the new provisioning finds
  no controller and is dropped.
- WR-03: a cancel while the depot run waits on a prior run. `installDepotDownload` awaits
  `existing.promise` for a tearing-down entry; a cancel during that await aborts the
  provisioning controller, then `runNativeDepotDownload` creates a fresh un-aborted controller
  and the download starts anyway.
- G21 (UAT item 23 note): bottle setup (21:16:54-21:17:26) showed no stage label in Downloads.
  With the engine already present, `ensureBuiltInEngineForInstall` sends nothing, and nothing
  is sent around `provisionBridgeBottle`. Emit a `creating-bottle` stage. 59-37 renders it.

Output: the two race fixes, the stage status, tests.
