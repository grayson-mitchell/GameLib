<objective>
G25 cause (c): `restoreNeedsAbsentPin` (engineSwitch.ts) returns false whenever the marker's DXVK
copy survives. That is right when CrossOver is healthy (59-26: the restore uses that copy, no pin
needed), but in UAT 34 run 1 CrossOver was missing, so the decision could only fall back to
`ENGINE_PINS.current` (engineDecision.ts `decideLaunchEngine`: unhealthy -> `pin = d.pins.current`,
`needsDownload = !isPinInstalled(pin)`), which cannot be downloaded offline. The refusal was
skipped and the launch failed only after a download attempt.

Whether CrossOver is installed is cheap and needs no probe, so this plan adds that fact and a
single pure predicate that decides "certainly blocked offline" from already-computed inputs. Plan
59-42 wires both into `selectLaunchEngine`. `restoreNeedsAbsentPin` itself is unchanged: it is
still the right test for the CrossOver-present arm.

Output: `offlineRefusal.ts` + table tests, `isCrossoverMissing` + tests.
</objective>
