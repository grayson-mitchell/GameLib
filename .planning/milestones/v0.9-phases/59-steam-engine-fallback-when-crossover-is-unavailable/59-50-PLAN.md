<objective>
Close G29 (major, re-UAT 5 item 40): a single transient `--demo-status` failure
(`outcome=nonzero-exit code=1 stderr= elapsedMs=33`, about 3 s after the previous overlay-clone
session ended) reclassified a licensed CrossOver as `cx-broken`, switched Planet Crafter's bottle
to Wine-Staging and launched it there.

Root cause (.planning/debug/g29-transient-demo-status-cx-broken.md): `preflightCrossover`
corroborates only timeouts; every other failure demotes at once. `probeDemoStatus` throws stdout
away on a nonzero exit, and on macOS CrossOver's Perl `bin/wine` reports `fatal_error` through
the `cxmessage` stand-in on stdout, so the reason was lost.

**D-09 amendment (recorded, not silent).** D-09 lists `--demo-status` "errors" as pre-flight
failures that mean CrossOver is broken. This plan narrows that: a nonzero exit or spawn error is
broken only when it happens on two consecutive probes within one pre-flight. It mirrors
quick-261101-jbm's timeout corroboration, which the operator already accepted, and stays
stateless per launch (D-07). Task 2 writes it into 59-CONTEXT.md.

**Considered and not taken: stopping the previous runner's wineserver before every probe.** It
would add a `wineserver -k` (capped at 15 s) to every healthy launch, including launches of a
bottle with no lingering server. The retry path stops the server only when a probe has already
failed, which covers the G29 trigger at no cost to the normal path. Note: the stop uses stock
CrossOver's `wineserver -k` while the lingering server may be the phase-60 overlay clone's. The
server socket is keyed by the prefix, and the clone is the same CrossOver build, so the kill is
expected to reach it; this is unverified live and re-UAT 6 observes it.

Output: stdout in the probe's nonzero-exit detail, the retry in preflightCrossover, tests, the
D-09 amendment note.
