<objective>
Stop the two false failure lines the built-in engine produces during install and launch.

- H2: the shared-redist step's null-display-driver window ends the bottle's wineserver session
  through `endPerGameBridgeBottleSession`, which dispatches through `killForRegisteredEngine`.
  At install time no engine is registered (the registry is per launch), so it falls through to
  stock CrossOver, logs "no CrossOver install found, skipping wineserver -k", returns false, and
  the redist step then logs "could not switch the bottle to the null display driver" and "could
  not restore the Wine display driver … the game may start with no display". Fix: let the
  caller pass the engine's wineserver (it already holds the engine's GameSettings) and use the
  engine-aware `killBottleWineServerWith` added in 59-05.
- H3: every pinned-wine call logs Heroic's `Couldn't find all library folders … Missing
  undefined and/or undefined!`. The pinned engine's `WineInstallation` carries no `lib`/`lib32`
  (buildFallbackGameSettings, bottle.ts), and on macOS that block only sets `LD_LIBRARY_PATH`,
  which macOS dyld does not consult. Decision (Claude's discretion, recorded here): make the
  error not apply on macOS when neither path is configured, rather than give the engine lib
  paths. Giving it lib paths would also set `WINEDLLPATH` on every fallback launch (the block
  sets it when `<lib>/wine` exists), which is a launch-environment change this noise fix must
  not make. The env output stays byte-identical.

Output: engine hint on the session-end path, a quiet macOS no-lib case, tests.
</objective>
