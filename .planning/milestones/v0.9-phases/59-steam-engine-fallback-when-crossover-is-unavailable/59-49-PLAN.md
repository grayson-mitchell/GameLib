<objective>
Close CR-01 (critical) and WR-01 from the round-5 review (59-REVIEW.md), and fold in IN-01.

CR-01: `checkLaunchOptionsAndLaunch` (src/frontend/helpers/library.ts:381-410, 463-471) re-sends
the picker through `showDialogModal` once a second. `reduceDialogRequest` queues each copy behind
the open picker, and since 59-45's `dialogKey` remount every promoted copy is visible and every
option button in it calls `window.api.launch` again. Fix per the review: a request carrying the
same `dialogId` as an open (or queued) dialog updates it in place, keeping its `dialogKey`, and is
never queued.

WR-01: MessageBoxModal runs `props.onClose()` then `button.onClick()`. Buttons whose onClick also
closes pop the queue twice, dropping the promoted dialog unseen. Fix both halves: the default close
carries the `dialogKey` it closes and the reducer ignores a close for a dialog that is no longer
current (or removes it from the queue if it is queued), and the redundant closes in button
handlers are removed. Untargeted closes keep their current behaviour, so the other callers
(GameCard / GameSubMenu backdropClick, Humble Keys line 300) are unchanged.

Output: reducer semantics + tests, DialogHandler close/log changes, picker and caller fixes, a
new library-level picker test.
</objective>
