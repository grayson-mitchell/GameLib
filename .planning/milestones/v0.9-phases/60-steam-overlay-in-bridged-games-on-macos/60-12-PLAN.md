<objective>
Run the 60-11 probe live and decide what causes G1, before any fix is written. Item 2 (Planet
Crafter, CrossOver overlay runner) failed and item 9 (the same title on Wine-Staging) passed. A
probe trace of each, around a Shift+Tab in gameplay, plus a third trace of Schedule I (a DXVK title,
UAT item 1) on the CrossOver overlay runner, shows which image hides or clips the cursor,
which mechanism winemac uses on each engine, and what gameoverlayrenderer does when the overlay
opens.

Verdict codes (60-15 implements the branch the code names; the combined code selects both halves
of the overlay_input branch):
- **V-CLIP**: in gameplay, winemac clips the cursor by a different mechanism on the two engines. On one,
  CGEventTapCreate/CGEventTapEnable come from `winemac.so` (the event-tap handler); on the other,
  `-[NSWindow setMouseConfinementRect:]` comes from `winemac.so` (the confinement handler). The engine
  that works is the one 60-15 makes CrossOver match, through `HKCU\Software\Wine\Mac Driver`
  `UseConfinementCursorClipping`.
- **V-REASSERT**: both engines use the same mechanism. But on CrossOver, after Shift+Tab, the
  gameoverlayrenderer-attributed show/associate calls (CGDisplayShowCursor, `CGAssociateMouseAndMouseCursorPosition arg=1`,
  `NSCursor unhide`) are followed inside the open window by winemac-attributed re-hide, re-clip or warp
  calls (CGWarpMouseCursorPosition, `arg=0`, `NSCursor hide`, setMouseConfinementRect). On Staging they are not.
- **V-INPUT**: the cursor is freed and stays freed on CrossOver (no winemac re-assert while open), but the
  game still turns. Events still reach the game through `-[WineApplication sendEvent:]` (the owner image
  is still winemac, not hooked). np_overlay_shim_set_active, called on open/close, is the fix.
- **V-REASSERT+V-INPUT**: both hold at once. winemac re-asserts capture while the overlay is open AND,
  where it does not, events still reach the game through winemac's sendEvent:. 60-15 defers the
  re-assert calls and calls np_overlay_shim_set_active.
- **V-NONE**: none of the above fits the evidence, or Planet Crafter and Schedule I point to
  different codes that no single code or the combined code covers. 60-15 stops and asks.

The verdict must hold for both renderer paths: Planet Crafter (D3DMetal, Runs A/B) and Schedule I
(DXVK, Run C). A verdict derived from one title only is not acceptable.

Purpose: D-15 is blocked on G1, and a guessed fix risks a second failed live gate.
Output: 60-12-SUMMARY.md with the G1 verdict.
</objective>
