<objective>
An early, cheap, throwaway probe that settles Research Open Question 4 (Assumption A3,
Pitfall 4) before any runner or launch code is written. It APFS-clones the installed CrossOver
into the executor's scratchpad, then runs a stock-created bottle under the clone's Perl
`bin/wine` with `CX_BOTTLE` exactly the way `runWineCommand` does (launcher.ts:1198,
`spawn(wineVersion.bin, commandParts, { env: { ...process.env, CX_BOTTLE } })`). It records
whether a prefix update happens, whether the wineserver comes from the clone, and whether
`WINEDLLPATH`/`WINEDLLOVERRIDES` reach the Wine process. It ends with a launch-form verdict.

Purpose: 56-08 (runner clone), 56-11 (`getBridgeBottleSettings` DRM variant) and 56-12 (the
wine launch) all assume a launch form. Static reading of CrossOver 26.3.0.39832's `bin/wine`
(see interfaces below) already shows the wrapper overwrites `WINEDLLPATH` and deletes
`WINEDLLOVERRIDES`, so the plain-env form in the Research staging recipe is likely wrong for
`bin/wine`. This plan measures that live instead of letting a later plan discover it.

Output: `56-01-SUMMARY.md` with a fixed-key results block and the verdict. The probe script
lives in the executor's scratchpad and is NOT committed. No repo source file changes.
</objective>
