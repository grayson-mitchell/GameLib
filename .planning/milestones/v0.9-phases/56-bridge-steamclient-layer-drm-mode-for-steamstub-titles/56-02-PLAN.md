<objective>
Build GameLib's own `lsteamclient`: the PE `lsteamclient.dll` and the unix `lsteamclient.so`,
both x86_64 (D-01). The inputs are:

- Proton's `lsteamclient`, fetched at a pinned commit and checked against its tree digest;
- NotProton's three overlay files, committed under `native/steam-bridge/steamclient-layer/lsteamclient/`;
- GameLib's D-15/D-16 `[drm-trace]` additions, confined to marked blocks in `steamclient_main.c`.

The build first tries CrossOver 26.3.0's source drop under a time box. If that attempt fails, it
falls back to stock Wine 11.15 headers (D-19). The build is operator-run through its own script
and stays out of release CI.

Purpose: this is the Steamworks-licensed half of the `steamclient-layer-cx<build>` component (D-02,
D-18). The trampolined `steamclient64.dll` exports land here, and from here the game process
reaches Mac Steam's `steamclient.dylib`. The trace lines are the only D-15/D-16 evidence DRM mode
has, because there is no GameLib shim and no `HELLO`. 56-05 parses them, 56-12 anchors and re-logs
them, and 56-15 judges them live.

Output:
- the overlay plus trace sources and `PINS.md`;
- `meta/buildLsteamclient.ts` and its jest suite;
- the `build:lsteamclient` script;
- a local, gated build of `lsteamclient.{dll,so}` in the gitignored component staging dir.

Built artifacts are never committed.
</objective>

1. **Provenance comment**, inserted after upstream line 1. It is a comment only, and states:
   - the origin (NotProton sha and path; Proton lsteamclient @ `164e0ccd…`);
   - that the file and GameLib's additions inside it ship under the Steamworks SDK License as part
     of the separately licensed `steamclient-layer` component (D-02), and that no GameLib

2. **Trace helpers**, inserted after the line `static BOOL wsa_initialized;`. Use only Win32 and C
   runtime calls that are already reachable from the file's includes, and add no new `#include`
   outside a block.
   - **State, all static:**
     - an enabled flag;
     - the role string `game` or `helper`;
     - the appId (1-10 ASCII digits);
     - the DOS trace path as WCHAR;
     - a `CRITICAL_SECTION` using the `{ NULL, -1, 0, 0, 0, 0 }` idiom;
     - the open `HANDLE`, initially `INVALID_HANDLE_VALUE`;
     - a create-interface-logged flag;
     - a 512-slot open-addressing table of 64-bit FNV-1a name hashes;
     - a non-identity name counter capped at 64 (`GAMELIB_TRACE_MAX_NAMES`);
     - a total line counter capped at 256 (`GAMELIB_TRACE_MAX_LINES`).
   - **`static void gamelib_trace_init(void)`.**
     - Read `GAMELIB_DRM_TRACE_FILE` with `GetEnvironmentVariableW`. Require that it starts with
       `/`, is shorter than 1,024 WCHARs and holds no character below 0x20 or equal to 0x7f.
     - Map it to a DOS path: prefix `Z:` and replace each `/` with `\`.
     - Read `SteamGameId` and require 1-10 ASCII digits.
     - Take the role from the basename of `GetModuleFileNameW(NULL, ...)`, the text after the last
       `\` or `/`. `lstrcmpiW(basename, L"steam.exe") == 0` means `helper`, anything else `game`.
     - Enable tracing only when every check passes. Do no file I/O here, because it runs under the
       loader lock.
   - **`static void gamelib_trace_write(const char *line, int len)`.** It enters the critical
     section and stops once the total-line cap is reached. It opens the file lazily on first use
     with `CreateFileW(path, FILE_APPEND_DATA, FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE, NULL, OPEN_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL)`.
     If the open fails, it disables tracing permanently, with no retry loop. It issues one
     `WriteFile` per line, so the game and helper processes interleave whole lines, and it keeps
     the handle open.
   - **`static void gamelib_trace_create_interface(const char *iface)`.**
