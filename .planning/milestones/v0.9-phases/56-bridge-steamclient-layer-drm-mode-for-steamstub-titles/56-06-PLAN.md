<objective>
Build the table-driven applier that adds NotProton's x64 loader detour to a byte-for-byte known
clean CrossOver `ntdll.dll`, plus the table that doubles as the D-09 CrossOver allowlist:
- `ntdllPatchTable.ts`: one pinned row per supported CrossOver build, plus the allowlist lookup;

  and refuses anything it doesn't recognise exactly.

`/Applications/CrossOver.app`, a game exe, a DRM payload or Valve's DLLs.

`ntdllPatchTable.ts`:
- `export type NtdllPatchRow`. Fields: crossoverBuild string; cleanSize number; cleanSha256
  string; hookRva number; stolenBytes string (hex); sectionName string; sectionRva number;
  sectionVirtualSize number; sectionRawSize number; sectionCharacteristics number; payloadSha256
  string; patchedSha256 string.
- `export const NTDLL_PATCH_ROWS: Readonly<Record<string, NtdllPatchRow>>`, holding exactly the
  one row from `<context>`.
- `export function findNtdllPatchRow(build: string, cleanSha256: string): NtdllPatchRow | null`.
  It looks up by build, then requires an exact lowercase-hex sha equality.
- `export function supportedCrossoverBuilds(): string[]`, which returns the sorted keys.
- No BigInt and no numeric `n` suffixes. Use plain numbers; every value fits below 2^53.

`ntdllPatch.ts`:
- `export type NtdllPatchResult = { status: 'patched'; bytes: Buffer } | { status: 'refused'; reason: string }`.
- `export function applyNtdllPatch(cleanBytes: Buffer, payload: Buffer, row: NtdllPatchRow): NtdllPatchResult`.
  The whole body sits in try/catch. Any exception becomes `refused` with reason `'internal: '`
  plus the message.
- Order:
  1. Check the clean size, then the clean sha256 (node crypto), then the payload sha256 and the
     payload length (at most row.sectionRawSize).
  2. Copy the input with `Buffer.from(cleanBytes)`.
  3. Read e_lfanew at 0x3c, NumberOfSections at pe+6, the optional header at pe+24, and the
     section table at opt + SizeOfOptionalHeader (pe+20). Read FileAlignment at opt+36,
     SizeOfImage at opt+56 and SizeOfHeaders at opt+60. Bounds-check every read against the
     buffer length.
  4. slot = tbl + NumberOfSections*40. Require slot+40 <= SizeOfHeaders and all 40 bytes zero.
  5. raw = length rounded up to FileAlignment. Write the 40-byte header at slot: name, VirtualSize,
     VirtualAddress, SizeOfRawData, PointerToRawData=raw, Characteristics. Increment
     NumberOfSections and add sectionVirtualSize to SizeOfImage.
  6. Zero-extend the buffer to raw + sectionRawSize and copy the payload at raw.
  7. Map hookRva to its file offset through the original section table, skipping entries with
     zero raw size or pointer. Require the 9 bytes there to equal stolenBytes. Write E9, then the
     int32LE rel32 = sectionRva - (hookRva + 5), then four 0xCC.
  8. Require sha256(result) == row.patchedSha256, then return patched.
- Never write to disk, never spawn, and never import backend/launcher, backend/utils or
  constants/paths. The only imports are 'crypto' and './ntdllPatchTable'.
- Put an ASCII `// ts-prune-ignore-next` line comment above every export in both files.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CrossOver install -> applier | the clone's ntdll.dll comes from the user's CrossOver install, which may be another version or modified |
| build output -> applier | the detour payload comes from 56-03's build or 56-10's downloaded component |
| table -> 56-08 allowlist | the row decides whether DRM mode may patch and launch at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-56-06-01 | Tampering | applyNtdllPatch input | mitigate | Pins on clean size and sha, a stolen-byte check, and a patched-sha check before return. Any mismatch refuses |
| T-56-06-02 | Denial of Service | PE parsing | mitigate | Every read is bounds-checked and the body is wrapped in try/catch. A malformed or truncated PE refuses and never throws into the launch path |
| T-56-06-03 | Tampering | detour payload | mitigate | A payload sha pin and a size cap of sectionRawSize |
| T-56-06-04 | Elevation of Privilege | allowlist | mitigate | findNtdllPatchRow needs both build and clean sha. Unlisted means null, and 56-08 maps that to 'unsupported-crossover' and does not launch (D-09) |
| T-56-06-05 | Tampering | user's CrossOver install | mitigate | The applier is pure and never writes. 56-08 applies it only to the APFS clone under app-support (D-08) |
</threat_model>
