<objective>
Build `drm/stageDrmBottle.ts`, the last setup step of a DRM-mode launch (`bottle-stage`). It turns
the title's existing per-title TCP-bridge bottle into a DRM-mode bottle, and does so idempotently on
every DRM launch:
1. Put the game's original `steam_api(64).dll` back over every GameLib shim, using the
   `.gamelib-orig` backup (D-11, research F2).
2. Delete `gamelib_bridge.cfg` and the Phase 52 forwarder `steamclient64.dll`, which a TCP launch
   or the Phase 52 path left behind (D-11, research Runtime State Inventory).
3. Stage the genuine Valve DLLs, `lsteamclient.dll` and the helper `steam.exe` into the prefix's
   `C:\Program Files (x86)\Steam\` (D-07, research "Staging recipe").
4. Write the HKCU-only `ActiveProcess` registry values, pointing `SteamClientDll64` at the genuine
   DLL (D-07, D-21). This also migrates the stale forwarder value.

Purpose: 56-11 calls this step after the component (56-10), the runner (56-08) and the Valve client
(56-07) are ready. Then 56-12 launches `C:\Program Files (x86)\Steam\steam.exe <game exe>`
through the cloned runner. SteamStub reads `ActiveProcess\SteamClientDll64` and must find Valve's
genuine client there, while the game's own untouched `steam_api64.dll` must load. If the shim is
still in place, or the registry still names the forwarder, the launch check fails just as it did in
Phase 52.

Output: one new service module and one jest file. It does not edit `bridge/steamClientSetup.ts`,
which belongs to 56-13, and it does not import from it either. That lets 56-13 delete that file
outright.
</objective>
