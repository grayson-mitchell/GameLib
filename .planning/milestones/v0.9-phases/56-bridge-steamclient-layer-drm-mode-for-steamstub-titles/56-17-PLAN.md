the game ran on DXVK; NotProton modified `/Applications/Steam.app` (Info.plist

half (56-CONTEXT specifics). 044's logs are in `.planning/spikes/044-notproton-drm-live/logs/`.

Grim Dawn install dir holds `action_manifest.vdf` (Steam Input action manifest).

Trace semantics (`native/steam-bridge/steamclient-layer/lsteamclient/steamclient_main.c`, GameLib
blocks): `steamclient_call` traces only when `status == 0` (`if (!status) gamelib_trace_call(name)`),
and the helpers dedupe by name hash (`gamelib_trace_hashes`, `GAMELIB_TRACE_MAX_NAMES 64`), so the
trace is a first-occurrence list of successful calls, not a timeline. "Last traced call" is therefore
not evidence that the crash followed GetActionSetHandle in time. Confirm by reading
`gamelib_trace_call` and its helpers in that file.

Gap 9 desk facts measured by the planner:
- live `GameLibSteamBridge-219990/user.reg`: `[Software\\Valve\\Steam]` has
  `"SteamPath"="C:\\Program Files (x86)\\Steam\\"` (TRAILING backslash) plus `SteamExe`;
  `[...\\ActiveProcess]` has `pid`, `SteamClientDll`, `SteamClientDll64`, `SteamPath` (no trailing
  backslash), `Universe`. `drmRegistryStagedInUserReg` (stageDrmBottle.ts) requires
  `steam.SteamPath === regEscape('C:\\Program Files (x86)\\Steam')` exactly, so it returns false and
  the four reg adds re-run on every later launch. `GameLibSteamBridge-648800/user.reg` currently
  shows no trailing backslash (state after the hang and kills; record, do not over-read).
- `.update-timestamp` in both bottles = 1784047440, equal to the mtime of both
  `/Applications/CrossOver.app/Contents/SharedSupport/CrossOver/share/wine/wine.inf` and the clone's
  `~/Library/Application Support/GameLib/steam-bridge/drm/runners/crossover-26.3.0.39832/CrossOver/share/wine/wine.inf`.
  So a prefix-update-triggered `wineboot --init` is not explained by a timestamp mismatch.
- `drmLaunchSetup.ts` runSetup step 6 calls `endBottleSession` ONLY when the registered runner dir
  differs (first DRM launch). `bottle.ts` `endPerGameBridgeBottleSession` -> `killBottleWineServer(name, drmRunnerBinDir(appId), timeoutMs)`,
  which runs `<binDir>/wineserver -k` with env `WINEPREFIX` + `CX_ROOT` (not `CX_BOTTLE`).
  The 56-16 orchestrator observed `wineserver -k` with `CX_BOTTLE` alone did not stop the session.
- `drmBridgeRunners` (bottle.ts) is an in-memory map: it is empty after a dev restart.
