<objective>
Upgrade the generator from "two partial interfaces" to a multi-version, manifest-driven shim:
schema v2 manifests, the MSVC class-return ABI fix, stackBytes-exact stubs, bare legacy accessors
selected per game through gamelib_bridge.cfg, and wire marshaling for the parameter kinds
ISteamUtils/ISteamApps/ISteamUserStats need.

Planner finding that reshapes this plan (2026-10-17, VERIFIED): bare accessors return whatever
interface VERSION the game's original steam_api.dll was built against (XCOM: SteamUser016,
SteamFriends011, SteamUtils005, …) and those versions have different vtable layouts; and the
existing SteamUser023 GetSteamID stub returns uint64 in EDX:EAX with `ret 0`, which mis-handles the
MSVC hidden-pointer convention real games use for CSteamID (Proton's thunk takes `CSteamID *_ret`
after `this`, wrapper size 8). Production manifests also carry fabricated `_TESTONLY` slots at real
slot positions. This plan fixes the generator; 51-11/51-14/51-15 author the real manifests.

Purpose: ROADMAP sub-decision 1 (bare accessors), Claude's-Discretion generator shape.
Output: generator v2, ABI fixture manifest, regenerated shim/def, coverage literals updated.

Spec-less probe fallback skipped: phase has no requirement IDs to probe (visible skip).
</objective>
