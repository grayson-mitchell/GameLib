# Phase 51 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** Phase 51 is 14/19 plans executed; plans 51-01..51-14/51-15/51-17/51-18/51-19
are backend/native-bridge/build-tooling/UAT work with no frontend surface and are not re-litigated here.
The **only** unexecuted plan with a frontend surface is `51-16-PLAN.md` (Wave 6), which this contract
covers in full: the install dialog's wine-section route line + force-bottled toggle (D-51-09, D-51-10),
and the game-page route row + limited-features lines next to the AppleGamingWiki rating (D-51-09, D-51-02).
51-16 already names exact copy strings and i18n keys (pre-shipped in 51-04) and instructs reuse of the
existing row/checkbox classes and tokens. That prescription is the baseline; this document confirms it,
resolves the placement/spacing/state gaps the plan left open, and is the formal artifact the checker and
executor consume.

## Spacing Scale

This is not a greenfield surface: the project already runs an em-based spacing scale (`_spacing.scss`,
`@mixin spacingSystem`), predating the 4px-multiple convention. This phase adds **zero new tokens** —
every value below already exists in the codebase and is the one to reuse.

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| `--space-3xs` | 0.25em | Icon-to-text gap inside a reused `.iconWithText`/`.infoBox` row (existing pattern, e.g. `svg { margin-inline-end: 0.5rem }` in `InstallModal/index.scss` is the nearest sibling rule) |
| `--space-xs` | 0.5em | Gap between the route line and the force-bottle checkbox row; matches `.smallInputInfo`'s own `margin-block: var(--space-xs) var(--space-3xs)` |
| `--space-sm` | 0.75em | Vertical gap between the route row and a following limited-features line on the game page, when both render |
| `--space-md` | 1em | Default block spacing between this row and its siblings (`showBottle`, `showCrossover`, …) in `AppleWikiInfo`, and between the route line's `.infoBox` and the rest of `SteamDialog`'s content — matches the existing gap between sibling `.infoBox`/`SelectField` blocks in that file |

Exceptions: none. Do not introduce a px-based spacing value anywhere in this plan's files.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (route text, reason, limited-feature sentences) | `var(--text-md)` (1rem) | regular (`var(--regular)`, inherited default) | browser default (~1.5), unchanged — no new `line-height` declaration |
| Label (`<b>Steam route:</b>` prefix, checkbox label) | `var(--text-md)` (1rem) | bold (native `<b>` tag / `var(--bold)`) — matches every sibling row in `AppleWikiInfo` (`<b>{t('info.crossover-rating', …)}:</b>`) and `SteamDialog` (`<b>` pattern not used there today — see note below) | browser default |
| Helper/reason sub-line (`steam.bridge.forceBottle.help`) | `var(--text-sm)` (≈0.833rem) | regular | browser default — mirrors `.smallInputInfo`'s own `font-size: var(--text-sm)` exactly |
| Heading / Display | not applicable | — | — | This phase introduces no new heading level. `steam.bridge.limited.title` ("Some Steam features are limited") exists in `gamelib.json` but is **not** rendered as a heading — see UI Considerations, "limited-features stacking." |

Only two weights are used (regular, bold), both already project tokens — no new weight is introduced.

**Note on the install-dialog label:** `SteamDialog/index.tsx` currently has no `<b>`-prefixed label
anywhere in its own JSX (its `infoBox` blocks are plain sentences). The route line is the first `<b>`
label in this file; it should still use `<b>` for the "Steam route:" prefix to match the project-wide
convention (`AppleWikiInfo`, `InstalledInfo`, `DownloadSizeInfo` all do this), not because the file
already does.

## Color

Not a 60/30/10 surface-color decision — this phase adds two short text rows and one checkbox to
**existing** surfaces (the install dialog's `DialogContent` and the game page's "info" tab). No new
background, border, or surface color is introduced. The only color decisions are which existing
semantic token each new piece of text/iconography uses:

| Role | Token | Usage |
|------|-------|-------|
| Default text | `var(--text-default)` | Route label, route value ("Native Steam bridge" / "Bottled Steam client"), reason sentence |
| Secondary text | `var(--text-secondary)` | `steam.bridge.forceBottle.help` helper sentence — matches `.smallInputInfo`'s own `color: var(--text-secondary)` |
| Warning accent | `var(--status-warning)` | The `faWarning` icon already used for every other cautionary line in `SteamDialog`'s `infoBox` blocks (shared-bottle notice, library-missing notice) — reuse for the missing-symbols ("Not covered: …") sub-line and the limited-features lines, exactly as SteamDialog's existing warning icon already does at L432-434 (which hard-codes `style={{ color: 'var(--status-danger)' }}` inline — see caution below) |
| Destructive | not applicable | No destructive action exists in this plan's scope. The force-bottle toggle is a reversible preference (persisted; D-51-10 says "flipping it after install means a reinstall into the other bottle," not a delete) — it must **never** be styled or worded as a destructive/danger action. |

Accent reserved for: the warning glyph on the two caution-shaped sub-lines only (missing-symbols,
limited-features) — never on the baseline route line itself (seed/scan-clean/pending-scan render with
**no** icon and **no** warning color, since they are informational, not cautionary).

**Caution carried forward, do not copy:** the one existing inline-color usage in this file
(`style={{ color: 'var(--status-danger)' }}` at `SteamDialog/index.tsx` L433) is itself a minor
multi-theme smell (an inline style bypassing the SCSS layer, though it still references a token rather
than a literal hex, so it does not violate the hard rule). Do not introduce a **second** one for this
plan's warning icon — prefer a class-based color reference (reuse the existing `.infoBox svg` rule, or
add the color via the existing `infoBox` class's own icon rule) over a third inline `style=` color.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (`ui-consideration-probe.cjs`), run independently
> of the researcher's draft and cross-checked against it — not self-graded. Two elements classified:
> **Element A** = install-dialog route line + force-bottle toggle (detected kinds: `form`,
> `interactive-control`, `static-content`), **Element B** = game-page route row + limited-features
> lines (detected kinds: `list-collection`, `static-content`). Both detected-kind sets were confirmed
> complete by the operator (no missed kind) before resolution.

Applicable state considerations resolved: 15 covered (explicit), 0 backstop, 1 unresolved.

| Element | Category | Status | Resolution |
|---------|----------|--------|------------|
| A | empty | ✅ covered | When the verdict is `undefined`, route is `'not-eligible'`, or the wine section is not visible, the route row renders nothing — no placeholder, no "checking…" text. |
| A | loading | ✅ covered | The checkbox is controlled by `forceBottleChecked` from the *currently resolved* verdict (never optimistic). On change: disable the checkbox immediately (same submit-latch shape `SteamDialog` already uses for `eligibilityPending`/`submitting`), call `setSteamBridgeUserRoute`, then re-run the eligibility probe; re-enable the checkbox once the probe resolves and re-renders `forceBottleChecked`. No spinner — the disabled state alone is the loading signal. |
| A | error | ✅ covered | Re-enable the checkbox and `window.api.logError(...)` naming the plan/field only (never echo the verdict object — matches this file's existing `logError` convention at L342-345/353-357/394-397). Do **not** force the checkbox to a specific checked/unchecked value on failure: the subsequent probe re-run naturally reflects whatever the persisted value actually is. |
| A | partial | ✅ covered | The missing-symbols sub-line is independently optional within an otherwise-complete route-line object: rendered only when `missingSymbols.length > 0`, omitted otherwise — never a half-rendered route line (route label/value/reason always render together as one unit). |
| A | overflow / long-text | ✅ covered | `{{symbols}}` is comma-joined (`missingSymbols.join(', ')`) and wraps inside the existing `.infoBox` (`max-width: 630px`, no `white-space: nowrap`); no truncation or ellipsis is introduced. |
| B | empty | ✅ covered | Same empty-state contract as A: an `undefined` verdict or `'not-eligible'` route renders no row at all. |
| B | loading | ✅ covered | **This is the gap the objective named.** No skeleton, no spinner, no placeholder row: `resolveBridgeRouteDisplay(undefined)` resolves `visible: false`, so the row is simply absent until the `getSteamBridgeRoute` fetch resolves, then appears in place with no transition/fade — matching this exact dialog family's existing abrupt-appearance pattern (`gating.wineSection`/`gating.libraryDropdown`). |
| B | error | ✅ covered | Swallow the `getSteamBridgeRoute` rejection (`.catch(() => {})` or equivalent) and leave the row hidden — identical rendering to the loading/not-yet-resolved state. No toast, no inline error text. |
| B | populated | ✅ covered | Baseline happy path: route label + value + reason sentence on one line, `var(--text-default)`, no icon. |
| B | partial | ✅ covered | `limitedLineKeys` is the **sole** source of which lines render (0, 1, or 2 entries), mapped 1:1 to plain-text lines in array order, `steam.bridge.limited.body` first then `.identityFallback` second — never an added `steam.bridge.limited.title` heading (resolver is the sole source of visibility, mirrors `steamSectionGating` rule (e)). |
| B | overflow / long-text | ✅ covered | Same comma-joined, wrap-not-truncate treatment as A — the game-page tab panel is unconstrained-width prose with no nowrap. |
| B | zero-one-many | ✅ covered | Zero → line omitted (per the "empty" row above); one or many → a single comma-joined line, never a bulleted list. No singular/plural copy variant is needed since "Not covered: {{symbols}}" reads correctly for either count. |
| A, B | placement (domain-specific, not in the closed 8) | ⚠ unresolved | **Objective-named gap, partially resolved, one caveat left open.** Insert the new route row(s) as the **first** child in `AppleWikiInfo`'s returned fragment — *before* `showBottle`, `showCrossover`, `showProton`, `showWine` — since the route verdict is the freshest, most authoritative signal about where the game actually runs. **Left open:** `showBottle`'s existing copy ("Runs via Windows Steam bottle") is gated only on `is_mac_native === false` and is unmodified by `51-16-PLAN.md` — for a game now routed through the native bridge, that sentence is no longer accurate, and nothing in this plan's scope corrects it. Planner/executor must treat this as a known, accepted assumption, not silently expand 51-16's scope to fix it; flag to the operator as a likely fast-follow. |
| A, B | icon treatment (domain-specific) | ✅ covered | `.iconWithText`'s CSS rule could not be located anywhere in the SCSS source tree or compiled build output (searched `src/frontend` and `build/assets/*.css`). Resolved conservatively: **no icon** for the baseline route row (seed/scan-clean/pending-scan/etc. — informational, not cautionary); for the two caution-shaped sub-lines (missing-symbols, limited-features) only, reuse the existing `faWarning` icon already imported in `SteamDialog/index.tsx` (install dialog); the game page has no equivalent FontAwesome import today, so its limited-features lines render icon-free rather than pulling in a new import. |
