<objective>
Add a Steam install in-progress UX. Today, firing `steam://install` is fire-and-forget: a user who starts an install and stays in GamerLib sees no feedback until they tab away and back (focus reconciliation, D-01). This plan adds a backend ACF polling loop (D-07) so that:

1. The GamePage main button changes from "Install" to "Steam installing" with an indeterminate spinner — NO percentage, NO pause/cancel (GamerLib cannot control Steam's download).
2. When the download completes (ACF `StateFlags & 4` flips on), the install badge flips to installed and polling stops.

This reverses D-01's focus-only model for installs (D-07). Focus reconciliation stays as a backstop.

Purpose: Close the in-progress feedback gap surfaced during Phase 3 manual QA (GAME-02 UX).
Output: ACF single-app reader + poller in the backend; steam-aware installing rendering in the frontend.
</objective>

ACF install detection (src/backend/storeManagers/steam/library.ts, already exists):
- `export async function buildInstalledMap(): Promise<Map<number, { installPath: string; sizeOnDisk: string }>>`
  Walks every Steam library path's `steamapps/`, parses `appmanifest_*.acf` via `parse` from `@node-steam/vdf`, and includes only games whose `(StateFlags & 4) !== 0` (0x4 = FullyInstalled). Skips missing dirs / corrupt ACF without throwing (T-2-01).
  During an active download, the manifest EXISTS but bit 4 is NOT set; when finished, bit 4 flips on. That transition is the completion signal.
- `getSteamLibraries()` from `backend/utils` returns the library root paths.
- ACF fields used: `state.appid`, `state.StateFlags`, `state.installdir`, `state.SizeOnDisk`; install path is `join(steamappsDir, 'common', state.installdir)`.

Frontend game-status pipeline (how a game becomes "installing"):
- Backend pushes status with `sendFrontendMessage('gameStatusUpdate', payload)` where payload is `GameStatus`
  (`{ appName: string; status: Status; runner?: Runner; progress?; folder?; context? }` — src/common/types.ts:297).
  Analog already in use: `src/backend/launcher.ts:922`.
- Frontend `GlobalState.handleGameStatus` (src/frontend/state/GlobalState.tsx:836) consumes it into `libraryStatus[]`:
  - status `'installing'` → entry pushed/kept in `libraryStatus`.
  - status `'done'` or `'error'` → entry removed AND `refreshLibrary({ runInBackground: true, library: runner })` is called.
  - NOTE: a status that is neither in the add-list nor `done`/`error` (e.g. `'installed'`) does NOT call setState — it will NOT clear the installing entry. To clear the in-progress state you MUST send `'done'`.
- `hasStatus` (src/frontend/hooks/hasStatus.ts) reads `libraryStatus` → derives `status` → GamePage sets `isInstalling = status === 'installing'` (index.tsx:150) → `is.installing` in GameContext.
- `getStatusLabel` (src/frontend/hooks/constants.ts:13) maps status→label; `installing` currently = `Downloading {percent}%`.

| Boundary | Description |
|----------|-------------|
| disk (ACF files) → main process | Steam writes appmanifest_*.acf; GamerLib reads/parses them |
| main process → renderer | poller pushes status/library updates via sendFrontendMessage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | steam:// URL construction | mitigate (reused) | install() still routes through `buildSteamProtocolUrl` (`/^\d+$/`); poller takes appId from internal `library`/install state, never from renderer input |
| T-03-04 | Tampering | corrupt/malicious ACF manifest | accept | readAcfState wraps parse in try/catch and skips corrupt files (reuses Phase 2 buildInstalledMap mitigation); no ACF content is executed, only StateFlags/installdir read |
| T-03-06 | Denial of Service | unbounded polling loop | mitigate | startInstallPolling is idempotent (one interval per appId), has a grace window if no manifest appears, and an overall safety cap; stops on completion |
| T-03-03 | Information Disclosure / Tampering | focus reconciliation | accept (reused) | refreshInstallState takes no renderer input; unchanged by this plan |
</threat_model>
