<objective>
Give the two keyring-backed stores their boot probe: Steam through a new deliberate
`'boot-probe'` trigger with a keyring-only read (D-14, D-21), Humble through a labelled session
read plus `getGamekeys` with no csrf backfill and no hidden webview (D-15, D-18). Both return an
outcome only; 49-08's pass applies it with `applySignInVerdict`.

Purpose: these are the two probes that can raise a macOS Keychain prompt, so they carry the
P1/P2/P3 risk. This plan also records, in source and in prose, the reversal of quick task
260817-d61: Steam's keyring is now read at boot for a signed-in Steam account, deliberately,
because a boot-time notice cannot tell the truth without it (SPEC Background).

Output: `'boot-probe'` in `authTrigger.ts`, `SteamUser.probeCredentialPresence`,
`HumbleSecretStore.readSecret`, `SidecarHumbleSecretStore.readSecret`, `HumbleUser.probeSession`,
sign-in/out epoch hooks for both stores, and tests.
</objective>

<reversal_record>
**260817-d61 is reversed by this plan, on purpose.** That quick task made `'startup'` the one
non-deliberate trigger so an automatic Steam refresh never reached the keyring at boot. The SPEC's
round-2 decision chose boot-time probing of all five stores, and D-14 chose a sticky deliberate
trigger over a third gate state. Consequence, stated plainly: after the pass runs for a signed-in
Steam account, `isSteamAuthUnlocked()` is `true` for the rest of the process, so a later automatic
`SteamLibraryManager.refresh()` (`steam/library.ts:921`) may CM-connect where today it would skip.
The first boot refresh normally still sees the gate locked, because its `runOnceWhenOnline` is
registered before the pass's connectivity listener. The probe itself never connects (D-21). A
signed-out Steam user is never noted and never unlocks: `probeCredentialPresence` returns before
`noteSteamAuthTrigger` when `SteamUser.isLoggedIn()` is false.
</reversal_record>

| Boundary | Description |

| sidecar → OS keyring (via Rust `keyring_get`) | A boot read can raise a macOS Keychain prompt; its outcome may be present, absent, denied or timed out. |

| sidecar → Humble HTTP | `getGamekeys` carries the session cookie to humblebundle.com. |
