<objective>
Build the three pure, React-free seams the whole Winetricks browse UI rests on: the
hand-maintained curated verb list, the unattended-incapable (Needs-GUI) verb set, and the per-verb
row-state derivation — including the per-verb error attribution that `44-RESEARCH.md` Pitfall 2 and
`44-PATTERNS.md`'s "No Analog Found" table both confirm does not exist anywhere in this repo today.

Purpose: these are the only genuinely new *logic* in Phase 44. Everything downstream
(`WinetricksBrowse/Row`, `WinetricksBrowse/index.tsx`, `Winetricks/index.tsx`) is composition over
them. Isolating them in `src/common/winetricks/` makes them testable in the Common jest project
(plain `node`, no React harness) and importable by the Backend project's parser test, which is what
D-03's assertion needs.

Output: `src/common/winetricks/verbs.ts`, `src/common/winetricks/deriveRowState.ts`, their unit
tests, and an extended `winetricksListParse.test.ts` fixture.

**Planner note on placement (Claude's discretion, per CONTEXT.md).** `44-RESEARCH.md`'s proposed
layout put `curatedVerbs.ts` and `deriveRowState.ts` under
`src/frontend/components/UI/Winetricks/WinetricksBrowse/`. They are placed in `src/common/winetricks/`
instead for two measured reasons: (1) D-03's assertion lives in a **Backend**-project test
(`src/backend/tools/__tests__/winetricksListParse.test.ts`) which cannot import from
`src/frontend`; the existing `src/common/humble/viewFilters.ts` precedent is imported by
`src/backend/humble/__tests__/library.test.ts`, proving the direction works. (2) Every new
non-test `.ts`/`.tsx` under `src/frontend` enrols in `meta/i18nForkTouchedFiles.json`'s live git
derivation and must be hand-mirrored into the gate artifacts (see plan 44-07); keeping two pure
modules out of `src/frontend` reduces that churn from 4 files to 2. Neither file holds a
user-facing string, so nothing is hidden from the i18n gate by this move.

readonly record rather than a `Set` so React state identity comparisons are cheap and the value is
trivially serialisable.

**`export function deriveRowState(input: { verb: string; installed: readonly string[]; installing: boolean; installingComponent: string; erroredVerbs: VerbErrorMap }): WinetricksRowState`**

`installed`; (4) `erroredVerbs[verb]` → `errored`; (5) `installing` → `installingElsewhere`;

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-01 | Tampering | `resolveCuratedComponents()` in `verbs.ts` | mitigate | The curated list is resolved BY LOOKUP against `listAvailable()`'s parsed output and unmatched entries are skipped silently (D-03). A hand-edited curated string can therefore never widen the set of verbs reaching `winetricks -q` beyond the parsed 567 — the constant selects, it does not supply. |
| T-44-02 | Denial of Service | `NEEDS_GUI_WINETRICKS_VERBS` | mitigate | The 8 verbs winetricks cannot install unattended are enumerated and given unconditional first precedence in `deriveRowState`, so no UI path can hand them to `-q` where they hang or fail silently (ROADMAP fence 3 / C-4). |
| T-44-03 | Information Disclosure | `attributeProgressEvent()` | accept | It reads backend log lines already rendered verbatim by `ProgressDialog`. It stores only a verb name plus a boolean — strictly less data than the log box already shows. No new exposure. |
| T-44-SC | Tampering | npm/pip/cargo installs | mitigate | **No package installs in this plan or phase.** `44-RESEARCH.md` §"Package Legitimacy Audit" records the phase adds zero dependencies. If any task here reaches for `pnpm add`, that is a scope violation to escalate, not to satisfy. |
