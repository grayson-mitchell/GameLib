None of the three upstream artifacts mentions the i18n gate scope. The coupling was found by
grepping `meta/` during planning, and it is real:

- `meta/i18nForkTouchedFiles.json` **enrols `src/frontend/components/UI/Winetricks/WinetricksSearch/index.tsx`**
  (verified 2026-09-16) — the exact file plan 44-05 deletes.
- `meta/__tests__/genI18nGateScope.test.ts`'s `DECLARED_UNSCANNED_DEBT` array **also lists it**, and
  the `A-03 RATCHET` asserts `forkTouched \ scope` equals that array **exactly, by name**.
- `A-17 ANTI-ROT` asserts the committed `i18nForkTouchedFiles.json` equals a live git derivation, and
  `A0` pins three literal counts: `scopeSnapshot.files.length === 170`,
  `forkTouchedSnapshot.files.length === 212`, `freshSnapshot().files.length === 212`.

`deriveScopeFiles` filters to `.ts`/`.tsx`, skips `D` status, and excludes `.test.ts`/`.test.tsx`/
`.spec.*`. So the live derivation moves by exactly three files from this phase:

| Change | File | Effect on the derivation |
|---|---|---|
| deleted (44-05) | `.../Winetricks/WinetricksSearch/index.tsx` | drops out (`D` skipped once in HEAD) |
| added (44-04) | `.../Winetricks/WinetricksBrowse/index.tsx` | enters |
| added (44-03) | `.../Winetricks/WinetricksBrowse/Row/index.tsx` | enters |

Deliberately NOT in the derivation, and this is why plan 44-01 placed two modules where it did:
`src/common/winetricks/*.ts` is outside the `-- src/frontend` pathspec; `*.scss` is not `.ts`/`.tsx`;
and the four new `__tests__/*.test.tsx` files are excluded by the test-file filter.

**Expected arithmetic: fork-touched 212 → 213.** Derive it, do not trust it — the numbers above were
read at planning time and an unrelated commit may have moved them.

**Decision: add the two new `.tsx` to `i18nGateScope.json` as well, not to the debt set.** They are
new user-facing components carrying live `t()` calls; putting them in scope means the gate actually
scans them, which is what the gate is for. That makes scope 170 → 172 and shrinks
`DECLARED_UNSCANNED_DEBT` by one (the deleted file) rather than growing it by two. Declaring new
files as permanent unscannable debt would be widening a ratchet to admit new work — the opposite of
what it is for, and adjacent to the error the gate's own comments warn about (declaring *deleted*
files as debt that can never be paid).

`src/frontend/components/UI/Winetricks/index.tsx` is **already** in fork-touched-but-not-scope, i.e.
already in the debt set. This phase modifies it but does not move it. Leave it there — paying down
pre-existing debt is not this phase's scope and doing it silently inside a bookkeeping plan would
hide a real scope change.
