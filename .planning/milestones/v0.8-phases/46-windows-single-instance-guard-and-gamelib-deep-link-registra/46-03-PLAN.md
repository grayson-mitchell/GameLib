    1. Call `ConnectNamedPipe(current.as_raw_handle() as HANDLE, null_mut())`.
       - A nonzero return means connected.
       - A zero return with `GetLastError() == ERROR_PIPE_CONNECTED` ALSO means connected: the client connected between create and connect (RESEARCH Q4/A1). Before relying on this, check the `ConnectNamedPipe` Microsoft Learn page and record the confirmation in the SUMMARY.
       - Any other error: eprintln `[shell] WARN: single-instance ConnectNamedPipe failed: {io::Error::from_raw_os_error(code)}`, drop `current`, try to create a replacement instance, and continue. If the replacement cannot be created, break (see step 2).
    2. BEFORE reading, create the next instance with `create_single_instance_pipe_instance(&primary.pipe_name, &primary.sddl, false)`, so a listening instance always exists and a near-simultaneous secondary is not refused. On Err(e): eprintln `[shell] WARN: could not create the next single-instance pipe instance ({e}) -- warm deep-link delivery disabled for this session (fail-open, T-34.5-G6-24)`, handle the current connection, and then `return`.
    3. Convert `current` into `std::fs::File` via `File::from(owned_handle)`. Read with `BufReader::new(file.take(4096))` and a single `read_line` (T-34.5-G6-23). `Ok(0) | Err(_)` skips to the next iteration. std maps ERROR_BROKEN_PIPE to Ok(0) on reads, so a client that wrote and then closed is still read correctly.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| named pipe → primary accept loop | Bytes from another process. Treated as untrusted even with an owner-only DACL |
| accept loop → sidecar (`handleProtocolUrl`) | Only protocol_url_arg-accepted URLs cross |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.5-G6-20 | Tampering | run_windows_single_instance_accept_loop | mitigate | `protocol_url_arg(&[trimmed.to_string()])` before any invoke. Region + order gate in jest (validate-before-dispatch) |
| T-34.5-G6-23 | Denial of Service | pipe read | mitigate | `.take(4096)` + a single `read_line`, gated by jest region test. Pipe buffers are 4096 |
| T-34.5-G6-24 | Denial of Service | pipe re-creation failure | mitigate | The loop returns with a WARN. The app and main window keep running. The mutex is still held, so secondaries still exit (no second instance) |
| T-34.5-G6-25 | Information Disclosure | rejection log | mitigate | The exact Unix `bytes={}` line, gated by jest |
| T-46-09 | Tampering / Repudiation | cold-start double dispatch once Windows schemes become non-empty (46-04) | mitigate | The REQ-46-08 ordering gate: Builder::default() < .setup(move \|app\| < on_open_url(, with RED self-tests.
