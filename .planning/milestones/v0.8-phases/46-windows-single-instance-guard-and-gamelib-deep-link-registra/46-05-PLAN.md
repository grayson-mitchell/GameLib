Facts the gate relies on:
- Debug builds are NOT `windows_subsystem = "windows"` (`#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`, main.rs:25). So the installed debug exe has a console. Launching it from PowerShell shows the `[shell]` stderr lines, including `another GameLib instance is already running -- sending {kind} to it and exiting` and `delivered single-instance deep link to sidecar: ok`.
- `shell_diag` writes a file only when `HOME` is set, which it normally is not on Windows. Do not rely on `gamelib-shell.log` for evidence.
- Process names are `GameLib` (the shell) and `gamelib-sidecar` (bundled from `src-tauri/binaries/gamelib-sidecar-x86_64-pc-windows-msvc.exe`).
- The default NSIS installMode is currentUser, so the install lands under `%LOCALAPPDATA%` (confirm the real path from the Start-menu shortcut target) and registers HKCU.
- A force-killed shell does not reap its sidecar on Windows (no job object; `shutdown_child` runs only on `RunEvent::Exit`). This predates phase 46. Check 5 accounts for it rather than failing on it.
</context>
