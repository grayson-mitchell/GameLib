# Phase 34.16 Plan 01: Widen the runner-bundle guard to x64 in macOS packaging scripts Summary

**`dist:mac` and `release:mac` now run `pnpm verify:runner-bundle build --arch=x64` as a second, hardcoded `&&` step immediately after the existing `--arch=arm64` step and before `electron-builder`, closing item 18 / C2-05's auto-publish exposure on landing; `electron-builder.yml`'s comment block was rewritten in the same commit-pair to state that coverage instead of the retired ARM64-ONLY claim.**

## Accomplishments
- `dist:mac` and `release:mac` each invoke the `verify:runner-bundle` guard once per arch (arm64, then x64), both chained with `&&` before `electron-builder` runs — each failure names its own arch.
- `release:mac`'s `-p always` publish step is now preceded by both arch guards, closing the exposure where an unverified x64 build could reach the `electron-updater` feed with the guard green throughout (item 18 / C2-05's own named precondition). This closure is **correct-on-landing and unprotected against regression** (D-09) — no new pin was added, per the phase's explicit decision to decline one.
- `electron-builder.yml`'s macOS `files:` comment block no longer claims "Coverage is ARM64 ONLY"; it now states both arches are guarded, while retaining the unaffected electron-builder #3940 rationale, the STAGED-tree-vs-packaged-.app distinction, and the `34.9-LIVE-GATE-RERUN.md` citation.
