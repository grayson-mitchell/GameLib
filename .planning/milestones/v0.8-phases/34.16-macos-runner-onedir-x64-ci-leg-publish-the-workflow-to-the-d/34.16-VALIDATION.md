- [ ] `meta/__tests__/pinRunnerDigests.test.ts` — **new file, no coverage exists.** Must cover: fetch
      success → correct rewrite; fetch failure → no partial write; malformed `SHA256SUMS` line →
      clear error; run-id field addition does not perturb `layout` / `digests`.
- [ ] `meta/__tests__/downloadHelperBinaries.test.ts` — add a case proving a **sibling top-level JSON
      key** on `runnersOnedirDigests.json` (e.g. a future `runId`) has zero effect on
      `darwinLayoutMarker()`. Belongs in the existing
      `describe('computeLayoutMarker (darwinLayoutMarker sensitivity, mutation-proof)')` block.
      RESEARCH.md resolves the *code* answer (the marker is structurally blind to sibling fields);
      this test is what stops that answer from silently decaying.
- [ ] `meta/__tests__/buildRunnersOnedir.test.ts` — `writeSha256Sums` / `writeBuildManifest` are
      neither exported nor tested. If `pin:runner-digests` parses their output, either export and
      unit-test the writers, or add a format-contract fixture the parser is written against.
      Otherwise the parser is written against an unpinned format.
- [ ] **No fixture simulating a real x64 onedir tree exists**, and per constraint 3 one must NOT be
      invented — its shape is unobserved. Deliberate Wave 0 *non*-requirement. Once CI produces a
      real x64 tree, capture a fixture from it; today the guard's x64 path has zero regression
      coverage and the plan must say so rather than imply otherwise.
