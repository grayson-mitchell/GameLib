## Pattern Assignments

### `meta/pinRunnerDigests.ts` (new CLI script)

**Analog picked: `meta/downloadHelperBinaries.ts`. Why the others lose:**

- **`meta/buildRunnersOnedir.ts`** — closest in *subject matter* (it is the writer of the two files
  this script reads: `SHA256SUMS-{arch}` via `writeSha256Sums()` at line 723, `BUILD-MANIFEST-{arch}.json`
  via `writeBuildManifest()` at line 733) but it is a **local filesystem writer that runs on a build
  host**, not a **network fetcher that runs on a developer/CI machine against a published release**.
  Its `main()` (line 795) calls `buildRunner()`, which shells out to `pyinstaller` — none of that
  shape transfers. Use it only as the format contract for what the pin script must *parse*, not as
  the shape for how the pin script is *structured*.
- **`meta/buildCrossoverIndex.ts`** — the second-closest candidate: it does fetch a remote artifact
  over HTTPS (`loadDumpXml()`, line 279) and has a clean `main()` + guarded-invocation idiom. But its
  data flow is "transform one blob into a new derived artifact" (XML → gzipped JSON), not "fetch two
  small text files, verify their shape, and **overwrite a specific existing tracked JSON file's
  fields** while leaving its `layout` key structurally untouched." It also has no digest/mismatch
  vocabulary at all — `pinRunnerDigests.ts` needs that vocabulary and `downloadHelperBinaries.ts` is
  where it already lives.
- **`meta/verifyRunnerBundle.ts`** — a read-only inspector (`inspectRunnerTree`, `summarise`) with no
  network I/O and no file-writing at all. Wrong data flow entirely (verification, not
  fetch-and-rewrite). Useful only for its `parseCliArgs()` idiom and its `main(argv)` return-code
  convention, which `pinRunnerDigests.ts` does NOT need to imitate since it is not swapped in as a
  process-exit-code gate the same way.

**`downloadHelperBinaries.ts` wins** because it is the only file in `meta/` that already does the
*exact* three-step shape this script needs — fetch a remote asset from the same
`GAMELIB_RUNNERS_REPO` / `RUNNERS_ONEDIR_TAG` release, sha256-verify it, and refuse to write on
mismatch — and its `downloadOnedirAsset()` (lines 159-228) is the direct sibling function
`pinRunnerDigests.ts` must match in tone and safety posture, even though `pinRunnerDigests.ts` writes
`meta/runnersOnedirDigests.json` rather than `public/bin/**`.

**`SHA256SUMS-{arch}` parse target — the exact format the pin script must parse**
(`meta/buildRunnersOnedir.ts:723-731`, `writeSha256Sums()`):
```typescript
function writeSha256Sums(arch: string, results: RunnerBuildResult[]): void {
  const lines = results.map(
    (r) => `${r.archiveSha256}  ${archiveName(r.runner, arch)}`
  )
  writeFileSync(
    join(RUNNERS_OUT_DIR, `SHA256SUMS-${arch}`),
    lines.join('\n') + '\n'
  )
}
```
Produces standard `shasum -a 256`-compatible lines: `<sha256hex>  <filename>\n`, one line per runner
(three lines: legendary, gogdl, nile), no trailing metadata. Parse with a simple
`line.match(/^([0-9a-f]{64})\s+(\S+)$/)` per non-empty line — malformed lines (VALIDATION.md Wave 0
requirement) must throw a clear error naming the offending line, not silently skip it.

**Entry idiom — guarded `main()`, JEST_WORKER_ID discriminator** (mirrors all four `meta/` CLI

**Layout-marker safety proof (from RESEARCH.md, code-verified, `meta/downloadHelperBinaries.ts:398-408,
424-429`):**
```typescript
export function computeLayoutMarker(layout: string, digests: Record<string, string>): string {
  const sortedKeys = Object.keys(digests).sort()
  const canonical = JSON.stringify({ layout, digests: Object.fromEntries(sortedKeys.map((key) => [key, digests[key]])) })
  return createHash('sha256').update(canonical).digest('hex')
}
export function darwinLayoutMarker(): string {
  return computeLayoutMarker(runnersOnedirDigests.layout, runnersOnedirDigests.digests)
}
```
`darwinLayoutMarker()` is called with **positionally destructured** `layout`/`digests` only — a
sibling top-level key such as `runId` added by the pin script is structurally invisible to the marker
and will NOT trigger a spurious re-download for every developer's checkout. This is the fact Wave 0's
new `downloadHelperBinaries.test.ts` case must pin (see below).
