## Decisions Made
- **Test 2 anchoring fix (mid-execution correction):** The plan's acceptance criteria for the "fails loudly" test mirrored the existing single-error arch-guard idiom (`toMatch(/::error::[\s\S]*?exit 1/)`), but this workflow's guard has *two* `::error::`/`exit 1` pairs (empty-branch and wrong-branch). A non-anchored regex would satisfy the RED-proof step 2 mutation (deleting only the wrong-branch `exit 1`) because the empty-branch pair still matches. Rewrote the assertion to anchor on the `"$REF_NAME" = "$DEFAULT_BRANCH"` comparison text specifically, so it targets the intended failure path. This is a test-design correction discovered during the mandated RED-proof loop, not a deviation from the guard's shell logic itself.
- Guard placed as the literal first list item under `prepare-release.steps`, above `Create or update the rolling release`, per D-02 and the plan's explicit position requirement (a guard placed later would create the rolling release before refusing).
- No second copy of the workflow was created anywhere in this worktree; plan 06's `git hash-object -w` step (outside this plan's scope) will hash this single tracked copy for the `main`/branch byte-identity claim.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in test design, caught during mandated self-verification] "Fails loudly" test used a non-anchored regex that would not RED-proof correctly against mutation 2**
- **Found during:** Task 2's RED-proof loop, mutation 2 (delete the wrong-branch `exit 1`)
- **Issue:** The plan's acceptance criteria suggested mirroring the existing arch-guard test's `toMatch(/::error::[\s\S]*?exit 1/)` idiom verbatim. Because the new guard's `run:` body contains two `::error::`/`exit 1` pairs (not one, like the arch guard), that idiom is satisfiable by either pair -- deleting only the wrong-branch path's `exit 1` would leave the assertion green via the untouched empty-branch pair, defeating the RED-proof requirement.
- **Fix:** Anchored the regex to the wrong-branch comparison text (`"$REF_NAME" = "$DEFAULT_BRANCH"`) before matching `::error::[\s\S]*?exit 1`, so the assertion targets only the intended failure path. Verified this passes against the real guard and goes RED against mutation 2.
