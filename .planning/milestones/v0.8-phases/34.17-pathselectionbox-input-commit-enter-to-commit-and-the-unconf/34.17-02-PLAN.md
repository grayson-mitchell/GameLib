<objective>
Half A, part 2. Give `PathSelectionBox` a visible, non-blocking signal that distinguishes a typed
but uncommitted value from a committed one.

Purpose: `34.17-01` makes Enter commit. On its own that is still silent — the field looks
identical before and after, so the user has no reason to press Enter and no confirmation that
doing so worked. The ROADMAP's own framing of the defect is "there is no error, no affordance, and
no indication the value was discarded"; the affordance clause is the half of that sentence
`34.17-01` does not close.

Output: a reserved hint row beneath the input that reads as an unsaved-changes warning while the
edit buffer diverges from the committed path, and as a transient confirmation for about two
seconds after a real commit; a colocated stylesheet; two new strings in the fork-owned `gamelib`
i18n namespace; and human-captured screenshot evidence that the thing actually renders.

**This affordance is genuinely new — it is not the reuse of an existing pattern.**
`34.17-PATTERNS.md` surveyed every confirmation primitive the frontend uses and found no "field
committed" affordance anywhere: `TextInputField`'s `warning` slot is a permanent hint tied to
value truthiness, `HumbleExpiryToast` is a persistent multi-second global-state banner, and the
`aria-live` regions all live in ConsoleMode, a screen family `PathSelectionBox` never renders in.
Two independent in-repo comments (`HumbleExpiryToast/index.tsx:14-20` and
`SteamBottleSetup.tsx:17`) record that **no toast or snackbar library exists in this codebase**.
Do not plan against, import, or install one. The correct shape is the smallest local thing that
works, which is the precedent both of those components already set.
</objective>
