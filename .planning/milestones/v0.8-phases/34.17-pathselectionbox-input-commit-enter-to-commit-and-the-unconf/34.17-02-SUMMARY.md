## The 1px Finding, and Why It Nearly Shipped

The operator's eye caught a shift I had already asserted was absent. My claim came from comparing
screenshots by eye; theirs came from watching the real UI. **Theirs was right.**

Measured by decoding the PNGs and locating the "Legendary Version" text band, all frames captured
from one fixed `screencapture -R` rectangle so the comparison is exact. The Midnight Mirage
`"Saved"`-vs-empty pair is the clean control: the text below is byte-identical (`invalid`) in both,
so only the hint row differs.

| State | Pre-fix | Fix attempt 1 | Corrected fix |
| --- | --- | --- | --- |
| Hint empty | y=129 | y=129 | **y=132** |
| "Not saved yet — press Enter" | y=130 | y=132 | **y=132** |
| "Saved" | y=130 | y=132 | **y=132** |
| Pulse expired | y=129 | y=129 | **y=132** |
| Restored | — | — | **y=132** |

**Root cause.** `App.css:15` sets `box-sizing: border-box` app-wide, so `min-height` *includes* the
`padding-block-start`. An empty row has no line box, so its height is exactly `min-height`; a
filled row is line-box + padding, which overflows `min-height` unless `min-height` was sized to
hold both. Pre-fix the line box was the font's `normal` (~16px), overflowing by ~0.7px → 1px.

**Fix attempt 1 was wrong and made it worse.** Pinning `line-height` alone grew the line box to the
full reserved height, so the overflow became the entire 3.3px padding: 1px → 3px. The operator saw
this on screen at the same time the measurement did. Recorded here because the failed attempt is
the evidence for why all three declarations are load-bearing.

**Corrected fix**, in `PathSelectionBox/index.css`:

```css
min-height: calc(var(--text-sm) * 1.4 + var(--space-3xs));
line-height: calc(var(--text-sm) * 1.4);
padding-block-start: var(--space-3xs);
```

All five states now measure y=132. The row sits ~3px lower than the original design in *every*
state — uniform, so nothing shifts.
