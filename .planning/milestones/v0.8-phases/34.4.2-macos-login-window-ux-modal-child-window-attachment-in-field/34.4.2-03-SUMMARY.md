# Phase 34.4.2 Plan 03: In-Field Autofill Glyph and Its Cancelled-Navigation Channel Summary

**Injects a key glyph into every password field on the Tauri-managed login surface (Humble/GOG/Amazon) via `initialization_script()`, and adds a path-discriminated cancelled-navigation channel that carries the field's geometry back to Rust -- the pristine Epic surface receives none of it.**

## Accomplishments
- `AUTOFILL_EXFIL_PATH`, `AutofillRequest`, `parse_autofill_request`, and `autofill_glyph_script` added to `src-tauri/src/main.rs` as pure, `AppHandle`-free helpers (no Cargo.toml/Cargo.lock change at all). `parse_autofill_request` discriminates on host AND path so it can never be mistaken for the pre-existing `/reveal`/`/clear-storage` sentinels on the same reserved `.invalid` host, and rejects every malformed/degenerate input (missing/non-numeric/non-finite/zero-or-negative-size) without ever panicking. 18 new cargo tests (111 total, up from 93) cover every rejection case plus the script's never-reads-`.value`/never-binds-a-keyboard-listener guarantees.
- The glyph script is wired into `humble_login_open`'s `if visible` block via `.initialization_script()`, gated on a packaged-build-capable `GAMELIB_AUTOFILL_GLYPH=0` kill switch that DEFAULTS ON (unlike the file's own debug-only `GAMELIB_LOGIN_DIAG` precedent) -- re-earned specifically because an injected `initialization_script` has already been this codebase's prime suspect for a real anti-bot 403, and the failure mode of a repeat has no non-rebuild workaround. A sentinel-only `.on_navigation()` hook was added to the same builder chain: it parses and cancels exactly the autofill request, never calls `push_login_window_event`/`set_title`/touches `current_origin` -- the login-watch relay stays exclusively owned by `on_page_load`, per this arm's own F-34.5-G6-04 invariant.
- The pristine Epic surface (`open_pristine_epic_login_window`, `EpicPristineNavDelegate`) is byte-unchanged -- confirmed by a `git diff --unified=0` across all three of this plan's commits showing every hunk landing inside `dispatch_rust_channel`'s `humble_login_open` arm or the `#[cfg(test)] mod tests` block, never inside either pristine region.
- The pre-existing blanket `on_navigation` negative test (`tauriShellSource.test.ts:636`) was RETIGHTENED, not deleted: it now allows at most one sentinel-only, cancel-only arm whose closure body contains `parse_autofill_request` and none of `push_login_window_event`/`set_title`/`current_origin`/`login_event_value`.
- A new "Phase 34.4.2 Plan 03" describe block adds 8 tests: exact call-site counts scoped to production code, the if-visible guard (brace-matched), the sentinel closure's contents, a GENERALIZED scope guard that now checks `PHASE_34_4_2_NEW_SYMBOLS` against BOTH pristine regions (Plan 01's own Test 3 was generalized the same way, in place), and four permanent negatives fencing the platform-impossible approaches spike 022 measured (Digital Credentials selectors, `menuForEvent`, `willOpenMenu`/`NSMenu`, and the `objc2-web-kit` feature array). `tauriShellSource.test.ts` now has 68 tests (up from 60), and `test:ci` reports 190 suites / 3706 tests (up from 3698), zero regressions.
- All three plan-mandated mutation checks were performed live and confirmed, then reverted: adding `push_login_window_event` inside the new `.on_navigation(` closure failed the retightened negative; moving `autofill_glyph_script(`'s call site outside the `if visible` guard failed Test 2; referencing `parse_autofill_request` inside `EpicPristineNavDelegate::navigation_policy` failed BOTH this plan's Test 4 AND Plan 01's own generalized scope guard from the SAME mutation -- confirming the two-region guard is independently load-bearing in both places.

## Decisions Made
- **JS marker rename + log-line fix for a real substring collision** (see `key-decisions` in frontmatter): Task 3's own "GAMELIB_AUTOFILL_GLYPH appears exactly once" assertion caught that `window.__GAMELIB_AUTOFILL_GLYPH__` and the SKIPPED log line's literal env-var mention both contained the same substring, inflating the raw count to 4. Fixed by renaming the JS global to `__GAMELIB_LOGIN_GLYPH__` and rephrasing the log line to "kill switch set to 0" -- functionally identical, source-assertion-clean.
- **Production-code-only scoping for two "exactly once" jest assertions**: `autofill_glyph_script`/`parse_autofill_request` are pure, heavily cargo-tested helpers (18 tests) with intentionally many call sites inside `#[cfg(test)] mod tests`. A whole-file `.match()` count would conflate that with production call-site count, so Test 1 and Test 7 scope to the code before `mod tests {` -- consistent with the file's own established precedent for `reveal_post_script`/`clear_storage_script`, neither of which carries any whole-file uniqueness guard.
- **Brace-matched (not string-bounded) `if visible` extraction for Test 7's negative**: a string-search end boundary (e.g. up to the next `#[cfg(debug_assertions)]`) would make a "this block does NOT contain `#[cfg(debug_assertions)]`" assertion trivially true by construction of its own boundary. `extractBracedBlock` (a local copy of Plan 02's own helper) gives a real block boundary the negative assertion can meaningfully fail against.
