**The five defect-class tests, as finally worded:**

1. **Origin/scheme reachability** — does any sub-check require a URL the surface under test will
   reject before reaching the code it's trying to exercise?
2. **Concurrency reachability** — does any sub-check require two things driven at once through a
   UI where the platform's own modality rules make that impossible?
3. **Log-line emitter reachability, with a SINK clause** — grep the emitter, THEN identify which
   sink it writes to, THEN confirm the contract's mandated capture actually reads that sink. States
   the two-sink partition: Rust `[shell]` → tee'd transcript only; sidecar `logInfo`/`logWarning` →
   `gamelib.log` only; sidecar stderr → transcript as `[sidecar:err]`; sidecar `console.*` →
   nothing.
4. **Absence-observability** — for every required absence, would the presence case have produced
   an observable signal?
5. **Requirement-interaction reachability (NEW)** — unit of review is the requirement **PAIR**. For
   every pair (A, B), does satisfying A ever destroy, truncate, restart, clear, overwrite, or
   invalidate B's own evidence or preconditions? Hunting list: anything that RESTARTS a process;
   anything that TRUNCATES/OVERWRITES a file; anything that CLEARS state; anything that RESETS a
   store; anything that changes an env var a later item depends on; anything that consumes a
   one-shot resource.

**Test 5's pair-scoping reduction rule, quoted verbatim from the reference:**

> **Practical scoping rule:** the pass is over **state-mutating requirements against
> evidence-bearing ones**, not the full n² cross product of every requirement against every other.
> A contract with M state-mutating requirements (relaunches, clears, resets, env-var changes) and N
> evidence-bearing requirements (log-line assertions, artifact checks) needs at most M×N pairs
> considered, not (M+N)². The author must state which reduction they applied — e.g. "considered
> every {relaunch, clear, env-var change} against every {required log line, required artifact}" —
> so a reader can judge whether the reduction was sound, not merely trust that it was applied.

**The dual-sink evidence-capture standard's exact launch command shape and delimiter text** (for
plan 34.4.2-19 to implement literally):

- Session directory: `/tmp/gamelib-gate-<ISO8601-UTC>/`, created once before the first launch.
- Terminal transcript: `tee -a <session-dir>/terminal.log` (never bare `tee`, never `>`).
- Delimiter, written before each launch:
  `echo "=== GATE LAUNCH ${N} — $(date -u +%Y-%m-%dT%H:%M:%SZ) ===" | tee -a <session-dir>/terminal.log`
  — grep with `grep -n '^=== GATE LAUNCH'`.
- `gamelib.log` archive, run before the next launch's first write rotates it:
  `cp ~/Library/Logs/GameLib/gamelib.log <session-dir>/gamelib-launch-${N}.log` (archive any
  pre-existing `.old` on the first pass too).
- Closing inventory: `ls -la <session-dir>/` and `wc -l <session-dir>/*`.
