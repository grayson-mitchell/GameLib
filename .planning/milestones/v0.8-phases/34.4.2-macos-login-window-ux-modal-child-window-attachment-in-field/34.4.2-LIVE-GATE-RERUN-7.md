### D-G7 — NEW: the q11 main-thread-resolution assertion

**This is the one substantive addition over RERUN-6, and the reason this contract exists rather
than a bare re-run of RERUN-6.** Quick task 260930-q11 (commit `bb567faf3`) moved both login-sheet
`NSWindow` handle resolutions from the calling worker thread into the deferred main-thread closure
that dereferences them, replacing a pair of raw-pointer `SendPtr` shims with a retaining
main-thread-only resolver, `login_window_ns_window_retained`.

**Why this mattered, per the q11 SUMMARY's own findings, carried forward here rather than
re-derived:**

- **Finding A** — the handle `tauri::Window::ns_window()` returns is **autoreleased**
  (`objc2::rc::Retained::autorelease_ptr(ns_window).cast()`,
  `tauri-2.11.5/src/window/mod.rs:1642`). Its guaranteed validity is bounded by the autorelease pool
  of the thread that *resolved* it, not by the login window's lifetime — so carrying the raw address
  across the 250ms GCD deferral into a later run-loop turn was outside the API's contract
  **unconditionally**, independent of whether the user ever closed the window in between.
- **Finding B** — both the AppKit accessor (`view.window()`) and the autorelease registration ran
  on the **worker thread** at the old code, not merely the later dereference. Moving resolution into
  the main-thread closure fixes both, not only the narrower "dereferenced after a close" framing the
  originating todo used.

**The exact log literal the operator will see**, from current source at its re-resolved line
(Task 1, row 17):

```
[shell] login-window sheet: both NSWindow handles resolved on the main thread for '{deferred_label}' (deferred_elapsed={:?})
```

(**`src-tauri/src/main.rs:4330`**, session transcript.)

**Required pairing — the evidence bar this contract adds to item 1:** the existing
`attached=true` read-back (row 1, `main.rs:4358`) must be preceded, in the SAME session transcript
and for the SAME window label, by the line above. Both lines are emitted by the same Rust process
to the transcript, so RERUN-6's `LogWriter` ordering caveat — which governs cross-process /
sidecar-vs-transcript ordering — does not apply to their relative order, exactly as it does not
apply to item 1's existing `attached=`/`sheet_presented=` pair. **Say this of these two lines only;
it is not a general license to trust ordering elsewhere in this contract.**

What the pairing buys, stated plainly: it establishes that the `attached=true` read-back the
operator observes came from a handle resolved on the main thread by the q11 retaining resolver,
rather than from an address resolved earlier on a worker thread and carried across the deferral —
which is the exact hazard the q11 todo exists to close. Without the shared-label pairing, a bare
`attached=true` proves a sheet attached but says nothing about which resolution path produced it.

**Required absence, re-confirmed by Task 1 at 0 occurrences:** the q11-deleted predecessor literal,
`both NSWindow addresses resolved` (the pre-dispatch, worker-thread-resolved form this line
replaced), must not appear anywhere in the transcript. Its emitter no longer exists in source; a
non-zero count would mean either a stale build or a regression reintroducing the deleted shape.

**Record-only localizer, does not raise the PASS bar:** `beginSheet dispatch call returned` (Task 1
row 18, **`main.rs:4343`**) sits between the resolution line and the read-back and can help localize
a stall if one occurs. It is optional to cite in the operator's own notes and never required for
