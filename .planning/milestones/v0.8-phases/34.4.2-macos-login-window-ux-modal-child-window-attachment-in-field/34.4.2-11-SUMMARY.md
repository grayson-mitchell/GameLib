## Accomplishments

- **WR-07 closed:** `post_autofill_right_click` step 7 skips `makeKeyAndOrderFront(None)` when
  the target `isSheet()` is true, logging a distinct diagnostic line instead. This removes the
  only known route by which the app's own autofill poster could detach a live, presented sheet
  mid-session (a first glyph click reverting it to a free-floating window).
- **WR-01 closed:** extracted `register_presented_login_sheet` from `present_login_window_as_sheet`'s
  inline registration block (preserving dedup-on-insert + `PRESENTED_LOGIN_SHEETS_CAP` eviction
  verbatim, T-34.4.2-08). `dismiss_login_window_sheet` now re-registers the label on BOTH the
  main-thread-dispatch-`Err` arm and the `recv_timeout`-`Err` arm, so a failed `endSheet:` hop
  can no longer permanently strand the parent window behind an undismissable sheet with both
  cancel routes (strip, Esc) membership-gated shut. The healthy `child_addr == None` path
  ("already gone by the time `Destroyed` fires") deliberately does not re-register.
- **WR-03 closed:** the cancel strip's script now returns immediately if `window.top !== window`
  -- checked before the idempotence flag is even read -- so third-party iframes (spike 013
  measured 5 of 8 Humble navigations as such) leave no state and build no duplicate "Cancel
  sign-in" control.
- **WR-04 closed:** the `DOMContentLoaded` listener registration and the `MutationObserver`'s
  `observe()` call now run BEFORE the initial `ensure()` call, which is the LAST statement inside
  the strip's single top-level try. Both `appendChild` sites resolve their root
  (`document.body || document.documentElement`) into a local first and skip the append when
  neither exists, removing the throw source outright rather than adding a second `try` (which
  would have broken the pre-existing exactly-once `"try {"` guard the review's own suggested fix
  shape would have violated).
- **IN-02 closed:** dropped `tabindex="0"` (the strip cannot deliver Enter/Space activation --
  REQ-34.4.2-06 forbids key listeners) and added the static `aria-keyshortcuts="Escape"`
  attribute, truthfully advertising the bare-Esc monitor as the sanctioned keyboard route.
- **`34.4.2-LIVE-GATE-RERUN-2.md` authored:** frontmatter `verdict: null`, `run_date: null`,
  `items_passed: null`, `items_total: 6`. Item 1 is restated around what the out-of-plan debug
  arc (`white-window-not-sheet-cr01.md`, commits `751521663`/`56d4986f8`/`8b2fdb315`) actually
  proved live (`attached=true`) vs. what remains unmeasured (un-losability, moves-with-parent,
  follows-into-Dock, post-restore interactivity). Items 2-6 carry over intact from
  `34.4.2-LIVE-GATE-RERUN.md` (confirmed byte-unchanged) with three fix-specific additions: item
  2 gains an exactly-one-control sub-check (WR-03) and a record-only re-registration sub-check
  (WR-01); item 3 gains a WR-07-branch capture instruction; item 1 gains a post-glyph-click
  un-losability re-check (sub-check f, discharging the new T-34.4.2-36).

## Decisions Made

- **Scope boundary held at exactly five findings.** WR-02 (use-after-free race), WR-05
  (synchronous teardown inside a WKWebView delegate callback), WR-06 (arbitrary debounce
  eviction), WR-08 (harness-containment test gap), IN-01 (cap-eviction orphan), IN-03 (URL
  scheme not checked), and IN-04 (no AppKit-executing test infrastructure) are all real findings
  from `34.4.2-REVIEW.md` but sit adjacent to, not directly on, gate items 2/3/5's own routes --
  deferred per the operator's own scoping decision, not silently dropped.
- **WR-04's fix shape deliberately diverges from the review's own literal suggestion.** The
  review text proposed wrapping the initial `ensure()` call in its own inner `try`; this would
  add a second `"try {"` to the generated script and fail the pre-existing exactly-once cargo
  test protecting that invariant. The actual fix (reorder + null-root-safe appends) achieves the
  same resilience without touching that guard.
- **Author/runner separation preserved a fourth time.** This plan is the fourth in this phase's
  own gap-cycle history (after plans 05/06 and 09/10) to author a gate contract without running
  any of it -- `34.4.2-LIVE-GATE-RERUN-2.md`'s `verdict`/`run_date`/`items_passed` all stay
  `null`, and every `Observed:`/`Verdict:` field in the six items is blank.
