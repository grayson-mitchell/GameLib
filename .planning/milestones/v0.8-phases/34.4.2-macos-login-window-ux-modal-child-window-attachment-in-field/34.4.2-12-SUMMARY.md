## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 4-adjacent, but resolved as a contract amendment rather than an architectural change] DummyStore unreachable from a Tauri-managed login sheet**
- **Found during:** Task 1 preflight, before the operator started
- **Issue:** The plan's own preconditions assumed the DummyStore harness (port 17940, `http://`)
  would be reachable from a Tauri-managed login sheet, as it was in spikes 019-022's separate
  spike app. This app's own `login_window_url_arg` (`main.rs:926`) rejects any non-`https` scheme
  before any window opens; a dedicated test (`main.rs:5725`) confirms this. The harness could
  never be reached this way -- not a bug to fix, but a contract that assumed something false.
- **Fix:** Amended the gate contract (not the app) to run Humble-only for items 3/4's substantive
  sub-checks, recording the DummyStore-dependent sub-checks and precondition 4 as
  BLOCKED-BY-DESIGN/INAPPLICABLE-THIS-RUN, with the reasoning and a mitigating fact (spike 020's
  real-HTTPS control) stated explicitly so the narrowed scope is visible, not silent.
- **Files modified:** `34.4.2-LIVE-GATE-RERUN-2.md`
- **Verification:** Task 1's automated verify command re-run after the amendment, still echoed
  `PREFLIGHT_OK_RESULTS_STILL_NULL`.
- **Committed in:** `d63caa9db`

**2. [Rule 2 - missing critical, discoverability] Autofill glyph renders as tofu**
- **Found during:** Task 2, operator's live report
- **Issue:** `main.rs:1499`'s `String.fromCharCode(128273)` is 16-bit-only; codepoint 128273
  (U+1F511 KEY) is outside the BMP and truncates to PUA codepoint U+F511, which no font renders --
  the glyph is present, positioned, and clickable, but invisible as a key icon.
- **Fix identified but deliberately NOT applied** this session, to avoid contaminating the
  measured run with a mid-run rebuild. `String.fromCodePoint(128273)` is the one-line fix, owed
  to the next cycle.
- **Files affected (not modified this session):** `src-tauri/src/main.rs:1499`
- **Verification:** Confirmed empirically via `node -e` execution comparing `fromCharCode` vs
  `fromCodePoint` output.
- **Committed in:** n/a -- deferred; recorded as F-34.4.2-08 in `708057942`
