# Phase 34.4.2 Plan 02: AppKit Child-Window Attachment Summary

**Attaches a visible Tauri-managed login window (Humble/GOG/Amazon) as an AppKit child of `main` on open, detaches on close, and re-raises it after `main` restores from the Dock -- Epic's pristine login window stays byte-unchanged and unwired.**

## Accomplishments
- `attach_login_window_as_child` / `detach_login_window_from_parent` added to `src-tauri/src/main.rs` (both `#[cfg(target_os = "macos")]`), each resolving both `NSWindow`s via plan 01's `login_window_ns_window`, hopping to the main thread via the file's established `SendPtr` + `mpsc_channel` + `rx.recv_timeout` convention, and calling `addChildWindow_ordered`/`removeChildWindow`. Wired into `humble_login_open`'s `if visible` branch (attach, after `.build()`) and its existing `WindowEvent::Destroyed` hook (detach). Hidden reveal/clear windows and the pristine Epic surface are never attached -- verified by an exact-count test and a live mutation check.
- `MAIN_WINDOW_LABEL` const introduced, replacing all three `get_webview_window("main")` literals (tray show handler, tray click handler, debug devtools block) with a single definition.
- `ATTACHED_LOGIN_CHILDREN` (capped, deduplicated, insertion-ordered) tracks attached labels; a label is removed on detach unconditionally, even when the AppKit call itself cannot run, so a destroyed window can never linger on the re-raise list.
- A `NSWindowDidDeminiaturizeNotification` block observer installed in `main()`'s `.setup()` (macOS only) re-raises every attached child via `makeKeyAndOrderFront` when `main` restores from the Dock -- the exact defect spike 021 measured (attached child returns BEHIND `main` after Dock restore unless explicitly re-raised). Deliberately not paired with a focus-driven re-raise, which would steal key focus on every main-window click.
- 9 new source assertions added to `tauriShellSource.test.ts`'s new "Phase 34.4.2 Plan 02" describe block (60/60 total in that file, up from 51), covering both call-site exact-counts, the if-visible guard, the two AppKit method call sites, the notification/re-raise co-location, and three permanent negatives (no sheets, no Tauri `.parent(`, no focus-driven re-raise). `PHASE_34_4_2_NEW_SYMBOLS` extended with this plan's four new symbols; plan 01's own Test 3/4 scope guard covers them automatically.
- All three plan-mandated mutation checks performed live and confirmed: removing the if-visible guard fails Test 3; adding a Tauri `.parent(` call fails Test 7; referencing `attach_login_window_as_child` from inside `open_pristine_epic_login_window` fails BOTH this plan's Test 1 and Test 9 **and** plan 01's own Test 3 (three failures from one mutation, confirming both scope guards are independently load-bearing). Each mutation was reverted immediately after observing the failure.
- `open_pristine_epic_login_window` verified byte-identical across all three of this plan's commits (278 lines, zero diff via direct extraction and comparison against the pre-plan commit) -- REQ-34.4.2-10 holds.

## Decisions Made
- **`NSGraphics` feature reachable via wry's own request, not this project's explicit list** -- verified by reading the vendored `objc2-app-kit-0.3.2` crate source (`addChildWindow_ordered`/`removeChildWindow` are gated `#[cfg(feature = "NSGraphics")]`) and `wry-0.55.1`'s own `Cargo.toml` (which requests `"NSGraphics"` for its own macOS `objc2-app-kit` dependency). Cargo's feature unification supplies it project-wide without any `Cargo.toml` edit -- confirmed empirically by a clean `cargo build` and `git diff --exit-code src-tauri/Cargo.toml` returning 0, matching the plan's own stated expectation.
- **Presentation-record `eprintln!` relocated, not duplicated**: the pre-existing F-4 machine-record line (documenting `focus_once`/`persistent_pin`/`light_theme_requested`) had to move from the builder-setup block (before `.build()`) to immediately after `.build()`/attach, since `child_attached` can only be known once the window exists and the attach call has actually run. The doc comment explaining the line's purpose was preserved and extended in place.
- **Two-address `SendPtr` pattern**: attach/detach each need to cross the `run_on_main_thread` boundary with TWO resolved addresses (parent + child), not one. Rather than inventing a combined wrapper or a second pointer-passing convention, each function wraps the two addresses in two separate local `SendPtr` instances (following the file's exact existing single-address idiom twice), each explicitly rebound inside the closure per the file's documented Rust-2021 disjoint-capture discipline.
- **`&AnyObject` cast for the notification's `object` parameter**: `addObserverForName_object_queue_usingBlock`'s `object` argument is `Option<&AnyObject>`, not the typed `NSWindow`. Rather than relying on uncertain multi-hop `Deref` coercion through `Some(&NSWindow)` (Rust does not reliably coerce inside a generic constructor argument across multiple `Deref` hops), the raw address is cast directly to `&AnyObject`, mirroring the file's own pre-existing `let monitor: &AnyObject = unsafe { &*(monitor_ptr.0 as *const AnyObject) };` idiom on `open_pristine_epic_login_window`.
- **Test 7's negative required regex, not substring**: `src-tauri/src/main.rs` already contains two unrelated, pre-existing `std::path::Path::parent()` calls. A naive `expect(code).not.toContain('.parent(')` would false-positive on those. Scoped instead to `/\.parent\([^)]/` (a call WITH an argument), since `Path::parent()` always has empty parens and Tauri's window `.parent(&window)` always takes one -- verified by the mutation check (adding a real Tauri `.parent(` call correctly fails the test; the two pre-existing `Path::parent()` calls correctly do not).
