# Phase 34.4.2 Plan 04: Synthesized Right-Click Poster Summary

**Turns plan 03's parsed autofill request into a debounced, bounds-validated `RightMouseDown`/`RightMouseUp` pair posted at the password field's centre in the Tauri-managed login window, closing the affordance spike 022 measured as the only reachable route to the system AutoFill panel.**

## Accomplishments
- `css_rect_center_in_view` / `clamp_point_to_view_bounds` added to `src-tauri/src/main.rs` as pure, `AppKit`-free `f64` helpers (Task 1): the first flips a CSS top-left-origin rect centre to AppKit's bottom-left-origin view coordinates; the second REFUSES (never edge-clamps) any point outside the webview's own bounds, any non-finite input, or a zero-sized view. 6 new cargo tests (117 total, up from 111), one per behavior including every refusal case, each asserting an exact value.
- `synth_autofill_mouse_event` (Task 2) is the sole construction site for a synthesized `NSEvent`, calling `NSEvent::mouseEventWithType_location_modifierFlags_timestamp_windowNumber_context_eventNumber_clickCount_pressure` (empty modifier flags, `context: None`, `clickCount: 1`, `pressure: 1.0`) exactly once in the whole file.
- `post_autofill_right_click` (Task 2) implements the full ordered contract: server-side debounce first (`LAST_AUTOFILL_POST`, 750ms per label, checked before any AppKit call) → refuse a label absent from `ATTACHED_LOGIN_CHILDREN` → resolve the WEBVIEW via `login_window_wk_webview` (never the content view) → hop to the main thread, read the webview's own `bounds()`, flip and validate the coordinate → convert to window coordinates → resolve the `NSWindow` → `makeKeyAndOrderFront` then post exactly two events → log exactly one success line (label, four numbers, converted coordinates, `hit_*` diagnostics -- never URL/origin/title). Every refusal logs a distinct WARN line and returns without ever calling `postEvent_atStart`.
- Wired into the single sentinel branch plan 03 left log-only: `humble_login_open`'s `.on_navigation(` closure now calls `post_autofill_right_click` on macOS (and silently no-ops on other platforms, still cancelling the navigation). `open_pristine_epic_login_window` and `EpicPristineNavDelegate` are byte-unchanged -- confirmed by a `git diff --unified=0` across all three commits showing every hunk landing inside `dispatch_rust_channel`'s `humble_login_open` arm, the new pure-helper/poster section, or the `#[cfg(test)] mod tests` block.
- `objc2-app-kit` gained the `NSGraphicsContext` feature (Task 2) -- added only after a real `cargo build` produced `E0599` for the ungated constructor; `git diff --exit-code Cargo.lock` stayed 0 (confirmed both directly and via `cargoFeatures.test.ts`'s own lockfile-crate-name pin, still 100% matching). Two "unnecessary `unsafe` block" warnings (`convertPoint_toView`, `postEvent_atStart` -- both safe fns in this crate version, discovered only once the code actually compiled) were fixed under deviation Rule 1.
- A new "Phase 34.4.2 Plan 04" describe block (Task 3) adds 8 jest tests: exact call-site count, two ORDERING gates (bounds-check-before-post, debounce-before-webview-resolve) asserted by source position, an event-type RESTRICTION (exactly two `NSEventType::` constructions, both `RightMouseDown`/`RightMouseUp`), an `ATTACHED_LOGIN_CHILDREN` reference RESTRICTION, a re-asserted permanent Digital-Credentials-selector negative, the Epic scope guard (now covering this plan's six new symbols against both pristine regions), and a sole-construction-site check for the mouseEvent constructor. `cargoFeatures.test.ts` gained 2 tests pinning the `NSGraphicsContext` feature and the pre-existing features it sits alongside. `tauriShellSource.test.ts` now has 76 tests (up from 68); both plan-mandated mutation checks (reordering the bounds check past the post; wiring a reference into `EpicPristineNavDelegate`) were performed live, confirmed to fail the intended tests, and reverted.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Two `unnecessary unsafe` block warnings from over-wrapping already-safe AppKit calls**
- **Found during:** Task 2, first `cargo build` run after adding the `NSGraphicsContext` feature
- **Issue:** The plan's action text modeled `view.convertPoint_toView(...)` and `ns_app.postEvent_atStart(...)` as needing `unsafe` blocks (by analogy with other raw-pointer-reconstruction AppKit calls in this file), but both are safe `fn`s in `objc2-app-kit-0.3.2` (no `unsafe fn` in either generated signature) -- the compiler flagged both wrapping blocks as `unused_unsafe`.
- **Fix:** Removed both `unsafe { ... }` wrappers; the calls themselves are unchanged. The genuinely unsafe operations in this function (raw-pointer-to-reference reconstruction inside the `run_on_main_thread` closure) remain wrapped, each with its own `SAFETY:` comment, matching the file's existing discipline.
- **Files modified:** `src-tauri/src/main.rs`
- **Verification:** `cargo build --manifest-path src-tauri/Cargo.toml` produces zero warnings; `cargo test` still 117 passed / 1 ignored, no regression.
- **Committed in:** `8c097e3b4` (Task 2 commit)
