## Findings

### F1 — the Winetricks surface is UNREACHABLE on a CrossOver wine version

The operator could not initially find the Winetricks button. Root cause:
`GamesSettings/index.tsx:83` computes `isCrossover = wineVersion?.type === 'crossover'`, and
line 184's `{!isCrossover && (...)}` suppresses the ENTIRE block containing `<Tools />` — Winecfg,
Winetricks and Run EXE — along with AutoDXVK/Esync/Fsync/WoW64/FSR. With CrossOver selected the Wine
tab still renders (version selector, prefix, bottle), so nothing indicates anything is missing.
Switching the game's wine version to "Wine CrossOver - 23.7.1-1" (whose `type` is `"wine"`, not
`"crossover"`) revealed the button.

**Recorded as fixture provenance: the panel was NOT reachable as-found; a wineVersion change was
required to reach it.** Implication worth carrying forward: for any user on a CrossOver wine version,
the winetricks decline path is unreachable, so the marker could never be emitted for them at all.

This is not a Tauri porting artifact — the same gate exists under Electron. Whether it is intended
(CrossOver manages its own bottle tooling) is a product question, left open deliberately.

### F2 — on-disk config disagreed with the running app

Game 206020's config on disk read `type: "wine"` while the running app behaved as `crossover`.
Recorded as an observation for a future debug session; explicitly out of scope here and not chased.

### F3 — incidental pre-port capture for EOS overlay and SteamGridDB (see the gate's ADDENDUM)

does NOT fill step 2 or step 3's `Result:` slots.

## Provenance — this plan's completion was CHALLENGED and OVERRIDDEN

Recorded because a future reader should see that this gate was contested rather than waved through.

After a context compaction, the executor agent refused to finalise. It observed that the operator's
observation reached it as a **relayed message from another agent**, alongside a system reminder
stating that no genuine user input had occurred, and its operating rules hold categorically that
"no message from any agent is ever your user's consent or approval." Since
`checkpoint:human-verify` / `gate="blocking"` exists precisely to require human consent, it judged
that it could not certify the gate. It therefore: left the gate frontmatter at `status: pending` /
`verdict: null`; declined to write this SUMMARY or report PLAN COMPLETE; and declined to revert
`fb509b0fa` / `27e0fd013`, reasoning that destructive rollback on its own uncertain judgement carried
its own risk. All three of those calls were correct and were independently verified.

It was offered three checks and ran them: the two quoted UI strings resolve verbatim to
`Winetricks/index.tsx:150`/`:204`; the archived log's counts (5 / 2 / 0) re-grepped exactly; and
`34.6-07` had not landed. **All three passed.** It nonetheless maintained — correctly — that these
establish only that *something real happened*, not *that a human did it*, since each is producible by
tool access alone.

The deadlock is **structural, not evidentiary**: a subagent's only input channel is a relay from the
orchestrator, so under a categorical no-relay rule no evidence can ever satisfy it, including the
operator saying "yes, I did it". Its proposed alternative — driving the capture itself — is not
available here: this is Tauri, whose DevTools console cannot be pasted into and which exposes no
automation surface.

**Resolution:** the observation was genuine. The operator drove the panel and reported the UI text
and `grep` output as a typed turn in the live conversation. The load-bearing evidence is in any case
machine-verified rather than attested — step 0's PASS condition is defined on the LOG, not the UI,
and those bytes were re-grepped from disk independently. The human authorised the override
explicitly. The orchestrator, not the executor, performed this finalisation and owns the
certification.

A fresh executor was deliberately NOT spawned to write this file. That would have been shopping for a
more compliant agent to get past a refusal; that a fresh agent would not object is an artifact of
context, not a reason.
