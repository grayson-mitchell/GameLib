```typescript
export async function migrateOneSecret(key: HumbleSecretKey): Promise<void> {
  const { configKey, slot } = MIGRATION_TARGETS[key]
  const plaintext = configStore.get_nodefault(configKey)
  if (!plaintext || typeof plaintext !== 'string') { return }
  try {
    await requestRustInvoke(RUST_KEYRING_SET, [plaintext, slot])
  } catch (error) { logWarning(...); return }
  SLOT_STORES[key].invalidateCache()          // bypass the setter's own cache — prove a REAL round trip
  let readback: unknown
  try {
    readback = await requestRustInvoke(RUST_KEYRING_GET, [slot])
  } catch (error) { logWarning(...); return }
  if (readback !== plaintext) { logWarning(...); return }   // exact match required
  configStore.delete(configKey)
  configStore.set('encryptionDegraded', false)
}
```

### 6. Send-kind vs invoke-kind registration idiom (D-11)

**Two send-kind channels in scope:** `winetricksInstall` (in `wineToolsFlowRegistration.ts`) and
`frontendReady` (module TBD from the 8 late-discovered channels — likely
`runnerMiscFlowRegistration.ts` or a bootstrap-adjacent module; grep at plan time to confirm the
Phase 34.5 `SEND_CHANNELS` array's own home file).

**Send-kind is NOT a novel idiom requiring invention** — contrary to the framing that "if none
exists, say so plainly," it is well-established. Confirmed present in at least these existing
`*FlowRegistration.ts` files: `clipboardFlowRegistration.ts`, `appShellFlowRegistration.ts`,
`humbleFlowRegistration.ts`, `humbleLoginFlowRegistration.ts`, `steamAuthFlowRegistration.ts`,
`runnerAuthFlowRegistration.ts` (`logoutGOG`), `shortcutsFlowRegistration.ts` (`addShortcut`,
`processShortcut`, `removeShortcut`), `loggerFlowRegistration.ts`, `shellFilesFlowRegistration.ts`,
`settingsFlowRegistration.ts`, `storeWriteHandlersFlowRegistration.ts`, `downloadQueueFlowRegistration.ts`,
`gameDetailsFlowRegistration.ts`.

**Exact idiom to copy** (from `shortcutsFlowRegistration.ts`'s `addShortcut`/`processShortcut`/
`removeShortcut`, per `34.5-PORTED-CHANNELS.md`'s own row descriptions):
```typescript
ipcMain.on('winetricksInstall', (_e, appName, packages) => {
  try {
    Winetricks.installWinetricksPackages(appName, packages)
  } catch (error) {
    logError(...)   // NEVER a bare `.catch()`, per Phase 31 Pitfall 2 / sidecar-send-channels-fail-silently
  }

```
Guard the body in try/catch (sync) or `.catch()` on the returned promise (async) — never leave it
bare, since send-kind failures are structurally silent to the renderer by design and the only
observability is a caught, logged error.

**`frontendReady` is the harder case** — it likely has NO payload args at all (a pure "ready" ping).
VALIDATION.md's Wave 0 requirements call out "a new suite for D-11 observable with no `args`" —
this needs its own presence-assertion test since the payload-less shape differs from every other
send-kind example above (all of which take at least one argument).

    const value = await spec.call()
    return { ok: true, value }
  } catch (error) {
    const reason = errorMessage(error)
    if (!declaredOnce.has(spec.channel)) { declaredOnce.add(spec.channel); window.api.logError(message) }
    return { ok: false, channel: spec.channel, reason }
  }
}
