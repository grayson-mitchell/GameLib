## The proposed cause — DISPROVEN 2026-08-25, retained as the record of a refuted hypothesis

`SearchBar/index.scss` mounts the suggestions list only under focus — `.autoComplete { display: none }` plus `&:focus-within ul.autoComplete { display: block }` — and there was no mousedown guard anywhere in the component or its callers. So a mouse click on any item destroys the item mid-click:

1. mousedown inside the list blurs the `<input>` above it
2. nothing takes focus in its place — an `<li>` is not focusable in any engine, and macOS/WebKit does not focus a `<button>` on click either
3. `:focus-within` goes false, so the `<ul>` flips to `display: none`
4. mouseup lands elsewhere, and `click` only fires when mousedown and mouseup share a target

`install()` never runs, `window.api.winetricksInstall` is never called, `send()` is never entered. It also explains the operator's "the cursor is sometimes a text cursor rather than a pointer": `.autoComplete` is `position: absolute; top: 75%`, overlapping the input, so when the list collapses the pointer lands on the `<input>` underneath.

**Fix:** `onMouseDown={(e) => e.preventDefault()}` on the list — suppresses only the focus change. Cost: list text is no longer drag-selectable, which is correct for a suggestions list.

## Decisions Made

- **The trace went in Rust, not the preload.** The plan prescribed instrumenting `tauriTransport.ts`'s `send()` over "a non-send-kind sink". Measured: that sink does not exist there — the sidecar logs no invokes and registers no invoke-kind logging channel (`logError`, `logInfo`, `showLogFileInFolder` are all `ipcMain.on`), and adding one would break the census pins in `runnerSliceRegistration.test.ts`. `eprintln!` in `sidecar_send` needs no new channel, reaches a sink the gate already captures, and partitions the space three ways rather than two by surfacing `write_frame`'s otherwise-invisible error.
- **The trace's default was flipped ON, then back.** It shipped opt-in and the first drive produced no line at all, on a binary proven fresh with the sink proven working — leaving flag-propagation and truncated-observation both live. Rather than spend another rebuild separating them, the default was inverted; that run found the cause immediately. It is now back to opt-in, because the trace is no longer load-bearing for any gate.
- **The instrument stays.** The `write_frame` failure line is always-on and free; it is the only thing that can see a `write_frame` error, which currently returns as an invoke rejection the `.catch` → `logError` chain loses.
- **No `resolves_phase:` on the todo** — still correct, now for a better reason: 34.6 registered the channel correctly and the defect was never on its surface.
