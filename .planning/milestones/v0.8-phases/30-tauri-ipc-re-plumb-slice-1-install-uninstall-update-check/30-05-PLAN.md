<objective>
Close Gap 1 (Phase 30 UAT Test 4): under Tauri the Steam Install button spins forever.

Root cause (already diagnosed — do NOT re-diagnose, see `.planning/debug/steam-install-spinner-hangs-tauri.md`):
the sidecar install bypass (`installFlowRegistration.ts`) emits a terminal `gameStatusUpdate('done')`
ONLY for a THROWN error (catch) or `deferredToSetup`/`wasAborted` (finally). `SteamGame.install()` →
`runNativeDepotDownload` → `ensureSteamClientReady` RETURNS `{status:'error'}` (never throws) when it
cannot proceed headless (native macOS Steam client absent — this env runs Steam via a CrossOver
bottle). So the `installing` badge is never cleared → spinner forever. Electron clears the same
returned error through the download queue's `removeFromQueue(appName, forceStatusUpdate=true)`
(`downloadmanager/downloadqueue.ts:306-311`), which the D-05a bypass deliberately did not port.

UAT premise correction (record only — no code change): the Game-Page Steam Install button
(`GamePage/index.tsx:673-684`, D-04) is a direct `window.api.install({path:''})` bypass with NO folder
picker by design. "The native folder picker never opens" was a wrong test expectation, not a defect.

Purpose: make the sidecar install bypass always leave the `installing` state — matching Electron's
own outcome handling — so a headless-not-ready or failed Steam install returns the button to Install
and tells the user why.
Output: fixed `installFlowRegistration.ts` install handler + updated wiring test.
</objective>
