## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → sidecar RPC | Untrusted `InstallParams` / `UpdateParams` / `uninstall` args cross here |

| sidecar → shared `userData` | `isSteamNativeInstallEnabled()` reads the shared config the Electron build also writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-05 | Tampering | `install` handler's `path` / `appName` args | mitigate | Do not add new path handling — pass args straight into the unmodified `SteamGame.install()`, which already carries Phase 21/23's own containment checks (`resolve`+`relative`, never bare `path.join`). Any new containment logic here would fork from the audited Electron path. |
| T-30-06 | Elevation of Privilege | `uninstall` reaching an arbitrary runner/appName | mitigate | Register `uninstallGameCallback` UNCHANGED — it resolves the game through `libraryManagerMap[runner].getGame(appName)` and throws on an unknown runner exactly as Electron does. No widened surface. |
| T-30-07 | Denial of Service | `checkGameUpdates` iterating runners whose CLI binaries are absent | accept | This is the same call graph Electron already tolerates on machines without legendary/gogdl; failures degrade to a rejected promise the frontend already try/catches (`GlobalState.tsx:851-856`). |
| T-30-08 | Information Disclosure | `listSteamLibraryTargets` returning filesystem paths | accept | Returns only Steam library roots already known to the user and already returned by the Electron build; gated behind `isSteamNativeInstallEnabled()` identically. |
| T-30-09 | Denial of Service | newly registered handlers turning an Invariant-B warning into a crash | mitigate | Task 3 asserts an unported channel still rejects with the marker and the RPC loop keeps serving; return shapes are asserted against `common/types/ipc.ts` declarations. |
| T-30-SC | Tampering | npm/cargo installs | mitigate | This plan installs no packages. |
