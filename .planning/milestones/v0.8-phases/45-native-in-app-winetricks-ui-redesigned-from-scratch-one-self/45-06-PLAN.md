<objective>
Make the backend tell the truth about winetricks output and about each verb: classify every line
(D-15), report progress as a percentage (D-14), feed the environment banner (D-16), annotate the
catalog with script metadata and the derived needs-GUI flag (D-17/D-19), and enforce D-09 at the
source.

failure had nowhere to stand out. Classification belongs where the raw lines exist.

Output: a pure classifier module and its tests, a reworked `runWithArgs` stream path, environment
recording, a metadata-annotated and visibility-filtered `listAvailable`, and the run log the
remounted tab reads.
</objective>

- splitOutputChunk(remainder: string, chunk: string): { lines: string[]; remainder: string }
  (splits on \n AND \r — curl redraws its meter with \r; remainder capped at 65536 chars)
- parseUnsupportedWineVersion(line: string): string | null

Measured script facts this classifier relies on (pinned script, read at planning time):
- winetricks downloads with plain `curl -L -o … -C - --fail --retry …` (no `-s`, no `-#`), so stderr
  carries curl's default meter: a `  % Total    % Received % Xferd …` header, a `Dload  Upload …`
  header, and `\r`-redrawn rows whose first column is the percentage.
- `w_warn` prints `<dashed line>`, `warning: <message>`, `<dashed line>` to stderr; `w_die` is
  `w_warn` then `exit 1`, so a fatal message also arrives as `warning:` — the exit code decides
  failure, and `w_try` failures say `Note: command … returned status N. Aborting.`
- the wine-version notice is `warning: Your version of wine <X> is no longer supported upstream. You should upgrade to 8.x`

</threat_model>
