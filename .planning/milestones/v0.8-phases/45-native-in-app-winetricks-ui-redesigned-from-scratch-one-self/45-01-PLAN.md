## Planner decisions recorded here (Claude's Discretion items)

- Queue IPC shape (CONTEXT discretion; RESEARCH Open Question 2): invoke-kind `winetricksApply`
  returning an acknowledgment, NOT N renderer-driven sends — closes the "send channels fail
  silently" gap. The handler returns immediately after validation; the run loop continues
  detached in the backend (a long-lived invoke would collide with the sidecar RPC timeout).
- `Cancel remaining` finishes the in-flight verb (CONTEXT default); not-yet-started verbs become
  `cancelled` at once.
- File layout: the new tab lives at `src/frontend/screens/Settings/sections/WinetricksSettings/`
  (a Settings section like `SyncSaves`), so the retired `src/frontend/components/UI/Winetricks/`
  tree can be deleted whole by plan 45-02 without a half-replaced state.
- Visibility for another game's run: `busy` is global (the single-flight slot is global); a tab whose
  game is not the run's game sees `run: null, busy: true` and locks Apply.

| sidecar process lifetime | the queue runs detached inside the Node sidecar, whose exit is by event-loop drain |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-45-01 | Tampering / Elevation of Privilege | `winetricksApply` -> `Winetricks.install` argv | high | mitigate | `assertWinetricksApplyPayload` (Task 2) rejects any element that is not a `VERB_SHAPE_RE` string present in the game's parsed catalog — `--self-update`, paths and unknown verbs never reach `spawn()`; argv stays an array (no shell) |
| T-45-02 | Denial of Service | `winetricksApply` payload shape | medium | mitigate | non-array, empty, non-string and >100-entry payloads are refused `invalid` before any spawn; duplicates are collapsed (Task 2 tests) |
| T-45-03 | Denial of Service / Tampering | concurrent installs on one prefix | medium | mitigate | `busy` refusal covers a running run, a foreign `Winetricks.install`, and same-tick applies (`applyInFlight`), so two winetricks processes never race on a prefix |
| T-45-04 | Repudiation | silent install-request loss | medium | mitigate | invoke-kind ack (`WinetricksApplyResult`) replaces a fire-and-forget send; refusals are returned, never swallowed |
| T-45-05 | Denial of Service | sidecar exit contract | medium | mitigate | queue and environment modules create no timers/handles (acceptance grep); the detached loop carries `.catch` logging so no unhandled rejection escapes |
| T-45-06 | Information Disclosure | queue state / log pushed to renderer | low | accept | the state contains verb names and classified winetricks output for the user's own prefix, shown only in the user's own app window |
</threat_model>
