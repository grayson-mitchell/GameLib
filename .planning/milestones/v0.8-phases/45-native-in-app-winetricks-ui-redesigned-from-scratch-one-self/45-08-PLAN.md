## Planner assumptions (UI-SPEC unresolved rows and open choices this plan settles)

- **A-45-02 (UI-SPEC E9-empty, unresolved):** the expanded, empty log shows one `logEmpty` line
  ("No output yet."), RESEARCH's default; key added in 45-03.
- **A-45-03 (UI-SPEC E9-partial, unresolved):** the current or most recent run's log survives
  navigation because 45-01 put `log` on the backend run and 45-06 fills it (cap 200). This departs from
  RESEARCH's "does not survive" default because the backend state already exists — no new persistence
  mechanism is introduced. Earlier runs' lines are not kept.
- **A-45-04 (UI-SPEC E10-partial, unresolved):** catalog loaded + installed read failed renders rows
  as Available (fail-open), RESEARCH's default; the backend's `listInstalled` already returns `[]` on a
  read error.
- **A-45-05 (D-16 copy scope):** the GPTK banner row renders only when `platform === 'darwin'` and
  `environment.unsupportedWineVersion` is set — its copy names "GameLib's macOS compatibility layer",
  which is false elsewhere. On Linux an unsupported wine version stays visible as a neutral
  `environment` line in the details log only. The missing-dependencies row renders on every platform.
- **Conflict resolved by a locked decision:** UI-SPEC E9-error says wine `fixme:` noise "is not
  surfaced"; D-15 (locked) routes noise "→ details log only, not red". D-15 wins: noise appears in the
  details log, muted.
- **Done-state lifetime:** the done summary stays until the selection changes (UI-SPEC bar table:
  "a fresh Apply reappears once the user changes the selection again"); `phaseDone` shows for 1500 ms
  per verb via a renderer timer cleared on unmount (renderer timers are outside the sidecar exit
  contract).
