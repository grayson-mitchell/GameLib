<interfaces>
Facts measured against the repo during planning. The most important one changes this probe's whole
shape — read it before doing anything.

**No code change is required to run this probe.** `43-RESEARCH.md`'s probe design proposes adding
temporary instrumentation. That is unnecessary: the shipped code already discriminates every
outcome, and adding a probe would create a removal obligation for no gain.

- `src/backend/humble/adapter.ts:580-640` — `revealKey()` already branches four ways and logs three
  of them with `LogPrefix.Backend`:
  - schema parse failure → `describeSchemaFailure(HUMBLE_REDEEM_PATH, ...)` → returns
    `{ status: 'schema_error', raw }`
  - `success === false` → logs `reveal rejected by server success=false keyPresent=<bool>
    errorMsgLength=<n>` → returns `{ status: 'rejected_by_server' }`
  - `success !== true || !parsed.data.key` → logs `reveal did not succeed success=<v>
    keyPresent=<bool> errorMsgLength=<n>` → returns `{ status: 'schema_error', raw: undefined }`
  - success with a key → the D-29-03 success line
  **A keyless success (`success: true`, `key` absent or null) lands in the THIRD branch and logs
  `success=true keyPresent=false`.** That exact string is the probe's discriminating evidence.
- `src/backend/humble/adapter.ts:76-82` — `RevealResponseSchema` already declares `key` as
  `.nullish()` and uses `.passthrough()`, so a keyless body parses structurally. The open question
  is what the CALLER does with it, not whether the schema rejects it.
- `src/backend/humble/library.ts:1190-1215` — `revealKey` wraps `doRevealKey` in a composite-keyed
  in-flight set, so a double-click cannot double-fire the irreversible POST.
- `src/backend/humble/library.ts:1213-1250` — `doRevealKey` refuses any key whose state is not
  `UNREVEALED` (logs `reveal: ineligible ... state=<x>`) and refuses any `ownedElsewhere: true` key
  (C2 block). Both are preconditions the operator must confirm the sample satisfies.
- `src/common/humble/keyTypePresentation.ts:89` — `gog_keyless` presents as
  `{ kind: 'branded', name: 'GOG', logo: 'gog' }`, and `:121-125` records that it is deliberately
  absent from `REDEEM_URL_BUILDERS`.
- Log sink: sidecar `logInfo`/`logWarning` reach `~/Library/Logs/GameLib/gamelib.log` only — never
  the tee'd terminal transcript (`live-gate-contract-authoring.md` § Section 3). Read the file.

**Probe route:** today's Keys-waiting tab already renders a Claim/Activate button for an
UNREVEALED, not-owned `gog_keyless` key, and that button opens `HumbleClaimWizard`, whose
`window.api.humbleRevealKey` call (`HumbleClaimWizard/index.tsx:224`) reaches `revealKey`. Run the
probe BEFORE plan 43-07 rewrites the screen — the tabs still exist in wave 1.
