<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Rust (`dispatch_rust_channel`) | The renderer supplies `url`, `x`, `y`, `w`, `h` to `store_embed_*`. Renderer content is first-party but the `url` originates from route state that plan `40-09` will make third-party-influenceable via `store-page?store-url=`. |
| Rust → remote store origin | This is the first time GameLib points a webview at arbitrary third-party pages by design. The full model is plan `40-04`'s deliverable; this plan must not open a hole it cannot close. |
| process-wide cookie jar | The child inherits `WKWebsiteDataStore::defaultDataStore()`, shared by every window and child (spike 018). Every store session in the app is inside the blast radius. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-02-01 | Elevation of Privilege | `store_embed_open`'s `url` argument | mitigate | The URL is parsed with `tauri::Url` and any parse failure returns a prefixed `Err`, never a fallback URL. Scheme policy is deliberately DEFERRED to plan `40-04`'s `on_navigation` arm — this plan leaves an explicit `|_| true` placeholder with a comment naming `40-04`, so the gap is declared, not silent. |
| T-40-02-02 | Spoofing | `STORE_EMBED_LABEL` | mitigate | The label is a fixed `const`, never derived from a caller-supplied URL (T-34.1-27's rule). It is not `main` and not `about`. Whether it inherits `main`'s capability grants is measured and closed in plan `40-04` — see T-40-04-01. |
| T-40-02-03 | Tampering | embed geometry | mitigate | Exactly one Rust call site may write bounds, asserted by acceptance criteria. Spike 017 proved a second writer wins silently with NO error, so the control is structural (one arm) rather than a runtime check that could not detect the conflict anyway. |
