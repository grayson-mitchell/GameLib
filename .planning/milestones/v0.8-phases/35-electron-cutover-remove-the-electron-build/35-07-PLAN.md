<objective>
Register `gamelib://` with the OS from the Tauri shell and route external opens into the existing,
already-tested parser — and decide the single-instance question on evidence rather than inheriting a
recommendation that contradicts a recorded decision.

Purpose: `main.ts:501-507` is the only thing registering the protocol today and it dies at the point
of no return. Most of D-07 already exists: `protocol_url_arg()` at `main.rs:5388` is a tested
validation choke point serving both argv and the single-instance socket, and `protocol.ts` +
`protocol.test.ts` parse the URL. The genuinely net-new work is narrow — OS registration.

The conflict this plan must resolve: `35-RESEARCH.md` says `tauri-plugin-single-instance` is a hard
requirement alongside `tauri-plugin-deep-link` on Windows/Linux. `main.rs:5504-5512` records
decision D-44-A rejecting that exact plugin, with a mechanism that is still true — it cannot run
early enough to stop a secondary process spawning its own sidecar. The repo already has a
hand-rolled, Unix-only guard that does run early enough. Windows has no guard at all
(`U-34.5-18`, accepted).

Output: `gamelib://` working where it can be delivered, not registered where it cannot, and a
`openDialog` picker that no longer times out at 60 seconds.
</objective>

no deep link.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any process on the machine -> `gamelib://` URL -> the shell | fully untrusted input; any local process, browser page or document can emit a `gamelib://` open |
| single-instance socket -> primary process | a secondary process's payload crosses here; already treated as untrusted |
| OS registry / Info.plist / xdg-mime -> the app's advertised capability | registering a handler is a public claim the app can service it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
