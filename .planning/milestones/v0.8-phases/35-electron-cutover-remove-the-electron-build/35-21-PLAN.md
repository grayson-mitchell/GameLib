<objective>
Close review criticals `CR-01` and `CR-02` from `35-REVIEW.md`. Both are cutover-era defects on the
shell/sidecar boundary, both are reachable at runtime today, and neither is re-reported anywhere
else.

`CR-01`: `open_external` is an app-defined Tauri command, so the `opener` plugin's `allow-default-urls`
scope — which restricts `plugin:opener|open_url` to `mailto:`/`tel:`/`http`/`https` — is not consulted.
Rust-side plugin API calls bypass capabilities entirely, so a capability-file edit cannot fix this;
the allow-list has to live inside the command.

`CR-02`: the Electron original registered `frontendReady` with `ipcMain.once`. The sidecar port used
`ipcMain.on`. Plan 35-11 then moved the boot-time download-queue auto-resume inside that handler.
Under Tauri the sidecar outlives the renderer, so any renderer reload re-fires the channel into the
same process and schedules a second `initQueue(true)` — and `initQueue` has no re-entrancy guard, so
two concurrent installs can write the same install directory.

Purpose: `35-VERIFICATION.md`'s `human_verification` block requires "a decision per item: fix, or
accept with a recorded reason" for CR-01..CR-04. The operator chose fix.

Output: an explicit scheme allow-list in `open_external` with per-scheme `cargo test` coverage, and
restored once-semantics for `frontendReady`'s boot work.
</objective>
