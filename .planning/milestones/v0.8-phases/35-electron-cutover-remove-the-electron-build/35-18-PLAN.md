<objective>
Remove `electron` from the build entirely, mechanize D-03's success test, and write down every gap
this phase ships.

Purpose: D-03's whole point is that the phase's success test becomes a single grep rather than a
judgement call — `electron` appears nowhere in `src/` or `package.json`. That is only true once the
esbuild alias goes too. `35-RESEARCH.md` established that the alias literal exists in exactly one
place, not three, and that it must survive until the last `require('electron')` it rescues is gone —
which happened in plans 35-15 and 35-16. It can go now.

The care point is the guarding test. `meta/__tests__/buildSidecarSea.test.ts` currently asserts the
alias flag IS present. Deleting that assertion leaves nothing behind; inverting it to assert the
flag is ABSENT keeps a gate where a gate was. A removed check with no successor is how a fail-closed
tool goes fail-open — the same care point Phase 34.18 recorded when it retired `assertAgreedRunId`.

Output: no `electron` anywhere, a mutation-proven absence gate, and release notes stating the four
accepted gaps plainly.
</objective>
