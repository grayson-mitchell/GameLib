<objective>
Migrate the renderer off `electron-vite` onto plain Vite, and give the dev loop real HMR without
destroying the only cheap evidence path for packaged asset resolution.

Purpose: `tauri:dev` currently runs a full production renderer build (`electron-vite build`) before
every `tauri dev`. That is the direct cause of two recorded gotchas — `tauri dev` serving a stale
static bundle, and `tauri:dev` exiting 0 without replacing a running instance. It is also the last
Electron coupling in `release-tauri.yml`, an otherwise complete `tauri-action` pipeline.

The care point: `devUrl` and `frontendDist` are structurally different code paths in the Rust shell.
A `devUrl` run fetches the renderer over HTTP and performs no static-asset resolution at all, so it
provides ZERO evidence about the `frontendDist`/`resource_dir()` path — and `R-34.5-G1-PKG` is
precisely a dev-passes/packaged-fails bug living in that path. Today's `tauri:dev` accidentally
exercises `frontendDist`; introducing `devUrl` removes that accident. A deliberate build-then-serve
script replaces it.

Output: `vite.config.ts`, an HMR dev script, a build-mode script, a config-equivalence test, and a
`release-tauri.yml` that no longer mentions `electron-vite`.
</objective>

- **Additive only. Do not delete `electron.vite.config.ts`, and do not touch `start`, `test:e2e`,
  `release:*`, `dist:*` or `sign:win`.** Those are Electron's, and Electron must keep building
  until plan 35-14. Plan 35-02's A/B re-test depends on `pnpm start` working.
- **`preserveRunnerSymlinksPlugin` is not optional and is not a formality.** F-34.9-01: without it
  codesign rejects the bundle. If it is absent from `vite.config.ts` this plan has failed, whatever
  else is green.
- **Do not set `emptyOutDir: true`.** `build/` also holds `bin/`, `locales/`, the SEA prep blob and
  the sidecar output. Emptying it destroys artifacts other build steps put there.
- **Do not change `frontendDist`.** `devUrl` is additive: Tauri uses `devUrl` for `tauri dev` and
  `frontendDist` for `tauri build`. Removing or conditionalising `frontendDist` would break
  packaging.
- **Do not use `pnpm tauri:dev` to prove anything about packaged asset resolution.** After this
  plan it loads over HTTP and resolves no static assets. Say so in the script's own comment.
- Never `git stash`, never `git reset`, never `git checkout -- <path>` (post-checkout hook).
</constraints>
