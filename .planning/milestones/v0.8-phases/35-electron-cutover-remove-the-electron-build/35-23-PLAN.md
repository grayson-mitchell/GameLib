<objective>
Close verification gap 5 (`REQ-35-07`, `D-35-19-15`) and the backend half of review critical `CR-04`.

`D-35-19-15`: live gate criterion 21 PASSED and discharged the standing `34.6` Step 8 FAIL, but it
did NOT exercise the multi-domain clear the `EPIC_COOKIE_HOSTS` widening exists for. Four of the five
domains returned 0, and a bare 0 does not distinguish "no cookies were present" from "the clear did
not work". Only the primary domain — the case the old code already handled — exercised a real
removal. The widening is unit-proven and code-verified, never live-proven.

`D-35-19-15` also names the fix that already exists in this repo: Humble's disconnect logs a
before/after jar CENSUS (`total=`, `matched=`, `verdict=`) alongside its clear count, which makes a
zero self-interpreting. Porting that to the Epic path makes a future criterion-21 run self-validating
without depending on a tester remembering to seed cookies first.

`CR-04` part 2: `total === 0` across all five hosts is currently fatal to logout. A user who
authenticated Epic through a path that seeds no cookies in the default data store — a legendary CLI
`auth`, or a profile migrated from another launcher — legitimately has nothing to clear, and their
logout will always report failure. The seam already returns the liveness signal needed to tell those
two cases apart.

Purpose: without this, `REQ-35-07`'s closure evidence stays "code-verified, never live-proven", and
plan `35-29`'s criterion-21 re-run can reproduce the same vacuous zero.

Output: a per-domain Epic cookie census whose log line is self-interpreting, and a fatality rule
that fires on a broken clear and not on an empty jar.
</objective>
