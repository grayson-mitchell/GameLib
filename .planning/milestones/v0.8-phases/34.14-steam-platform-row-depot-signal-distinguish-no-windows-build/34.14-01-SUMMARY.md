# Phase 34.14 Plan 01: Widen the Steam Bottle Eligibility Verdict Summary

One-liner: `SteamBottleEligibilityVerdict` now carries two required booleans (`hasWindowsDepot`, `platformsCaptured`) populated from `steamMetadataStore` inside the single shared `getSteamBottleEligibilityVerdict` handler body — no new IPC channel, no second probe, no extra fetch — with a permanent, non-vacuous test proving that handler body is never forked between the Electron and Tauri runtimes.

## What Was Built

**Task 1 — widened the wire type.** `SteamBottleEligibilityVerdict` in `src/common/types/steam.ts` gained `hasWindowsDepot: boolean` and `platformsCaptured: boolean`, both required (not optional), each documented with its D-03 decision ID and the single-seam obligation ("never read `hasWindowsDepot` without `platformsCaptured === true` also holding"). Every typed construction site the widening broke was repaired: three literals in `steamInstallFormContracts.test.ts` (including retiring the now-false "accepts `{ eligible: true }` alone" claim), two `mockResolvedValue` literals in `steamAuthFlows.test.ts` (the sibling `toMatchObject` subset assertions were left untouched, as instructed), and four typed verdict literals in `steamEligibilityProbe.test.ts`. A new `@ts-expect-error` compile pin was added immediately after the existing A-07 pin, proving both new fields stay required.

**Task 2 — populated the pair in the one shared handler body.** `installFormIpc.ts`'s `getSteamBottleEligibilityVerdict` now imports `steamMetadataStore` alongside `steamBottleConfigStore`, reads it immediately after `checkBottleEligibility()` has already forced-and-awaited `ensurePlatformsCaptured()` (no new fetch, no new await), and derives both booleans with strict `=== true` comparisons so `undefined` never coerces to `false`-as-a-fact. The rejected-appName early return was widened to `{ eligible: false, hasWindowsDepot: false, platformsCaptured: false }` with an explicit comment distinguishing a REJECTED REQUEST from a genuine D-04 fail-open trigger. Three new specs in `installFormIpc.test.ts` prove the pair tracks the store rather than a constant (captured+available, captured-and-absent — the 34.13 fence — and uncaptured/timeout). `games.ts` was verified untouched (settled finding 3), and `checkBottleEligibility()`'s `Promise<boolean>` signature is unchanged.

**Task 3 — made the no-fork invariant checkable.** Neither `main.ts` nor `steamAuthFlowRegistration.ts` was edited — the widening reaches both runtimes by construction, since both import the identifier from the one shared body. A new `describe('D-02: the shared handler body is never forked')` block in `installFormIpc.test.ts` walks all production `.ts`/`.tsx` files under `src/` (excluding `__tests__`/`__mocks__`, following the established `externalDynamicImportGate.test.ts` `collectSourceFiles` convention) and asserts exactly one file — `installFormIpc.ts` — declares `export async function getSteamBottleEligibilityVerdict`. A second spec confirms `main.ts` and `steamAuthFlowRegistration.ts` each reference the identifier without redefining it. A non-vacuity spec proves the matcher counts 2 against a hand-built two-definition specimen; the specimen lives inside this `__tests__` file so it cannot contaminate the real production-source scan (which excludes `__tests__` directories).
