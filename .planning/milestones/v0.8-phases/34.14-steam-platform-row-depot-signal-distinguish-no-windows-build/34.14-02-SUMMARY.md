# Phase 34.14 Plan 02: Steam Platform Row Depot-Signal Distinguish Summary

**Adds a fifth `'pending'` row mode to the pure Steam install-options gating resolver, enforced by a read-order seam that makes it structurally impossible to consult the Windows-depot flag before the depot signal is resolved, plus one new pure function (`resolveDepotAvailability`) that folds fail-open-on-unknown and seed/probe selection into a single documented place -- proven by a 144-combination / 10-row matrix that was RED against unmodified source first.**

- Expanded the Section-Gating Matrix from 96 combinations / 8 rows to 144 / 10, proven RED against the unmodified resolver first (Row 9, Row 10, and the full `assertMatrix` sweep all failed as predicted)

**1. [Rule 1 - Bug in this plan's own Task-1 test authoring] `windowsHostGetsWineSection`'s expected-row set was initially incomplete**
- **Found during:** Task 2, when running the full suite against the newly-landed `'pending'` mode
- **Issue:** Task 1's static re-evaluation of this saboteur concluded it was unaffected by rows 9/10 (reasoning: rows 9/10 are darwin, and the saboteur's defect is dropping the `isMac &&` guard, which is a no-op when `isMac` is already true). - **Fix:** Added `'9'`, `'10'` to the saboteur's `expectedRows` and rewrote the explanatory comment to describe the actual interaction (a saboteur's OWN incomplete reimplementation, not just the resolver's read-order change, can be the source of a newly-broken row).
