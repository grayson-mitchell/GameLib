# Phase 34.10 Plan 07: Navigation shell root Summary

**`NavShell`, the app-level shell root: a fragment of `.NavShell__navbar` (wordmark, `NavTabs`, `DownloadsRing`) and `.NavShell__tier2` (route-switched `GamesPanel`/`StoresPanel`/`SettingsPanel`, plus an unconditionally-mounted `HeroicVersion` visible only on Settings) -- with `handleGoToScreen` carried over (leak fixed) and the onboarding tour fully disabled.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 2 completed (Task 1 single commit; Task 2 TDD RED -> GREEN)
- **Files modified:** 4 (all created)

## Accomplishments

- `HeroicVersion` relocated from `Sidebar/components/HeroicVersion` to `NavShell/components/HeroicVersion`. Both `useEffect` bodies (version-check/cache-clear, latest-releases) are byte-identical to the original -- confirmed by diffing the effect line ranges directly, not just by eye. The `TourButton` element and its `SIDEBAR_TOUR_ID` import are removed, along with the `data-tour="sidebar-version"` attribute -- this was the *second* of the phase's two tour entry points (`ActionIcons`' library-tour `TourButton` is the other, out of this plan's file scope). The stylesheet is re-parented from `.Sidebar` onto `.NavShell__versionSlot`, with the sidebar's `&.collapsed` drag-resize block and the now-dead `.sidebar-tour-button` rule both deleted.
- `NavShell/index.tsx` assembles the shell root as a **fragment** (not a wrapper element) whose two children -- `<header className="NavShell__navbar">` and `<aside className="NavShell__tier2">` -- are direct grid items, matching plan 34.10-02's `.App`-grid contract.
- The navbar row: icon-only wordmark (`GameLibIcon`, `alt="GameLib"`, ported verbatim from `Sidebar/index.tsx:140`), `<NavTabs />`, then `<div className="NavShell__navRight"><DownloadsRing /></div>`.
- The tier-2 column switches on `resolveActiveTab(useLocation().pathname)`: `games` -> `<GamesPanel />` (the portal target), `stores` -> `<StoresPanel />`, `settings` -> `<SettingsPanel />`, `accounts`/`null` -> no panel. `TabPanel` was deliberately not reused (its `value === index` contract doesn't fit four structurally different cases).
- The collapse modifier (`NavShell__tier2--collapsed`) applies when there's no active tab, the active tab is `accounts`, or the active tab is `games` with the portal context's `filled` false (covers `/gamepage/*`, where `Library` -- and its portalled `Header` -- isn't mounted).
- `HeroicVersion` mounts as the tier-2 column's last child, **outside every panel conditional**, wrapped in `<div className="NavShell__versionSlot" hidden={activeTab !== 'settings'}>` -- REQ-34.10-12's whole point: the version-check/cache-clear effect and the startup `ChangelogModal` are mount-triggered, so this is what keeps them firing on every launch regardless of which tab the user last had open, rather than only the first time they open Settings. A comment above the slot in `index.tsx` records this reasoning in-source.
- `window.api.handleGoToScreen` is carried over from `Sidebar/index.tsx:58-63` verbatim in behavior, with one fix: the effect now **returns the unsubscribe** (`frontendListenerSlot`'s return value), where the sidebar's original left it unbound and leaked the listener on every remount.
- No `SidebarTour`, no `data-tour`, no `sidebar-width`/`requestAnimationFrame` drag-resize -- all three verified absent by literal grep per the plan's acceptance criteria.
- `NavShell.test.tsx`: 17 structural tests, direct-invoke, no jsdom -- covers the fragment/className contract, a parameterised HeroicVersion-presence check across all five tab states (`accounts`, `games`, `stores`, `settings`, `null`), the version slot's `hidden` toggle in both directions, panel switching, all three collapse cases plus their negations, `SidebarTour`'s absence, navbar composition, and the `handleGoToScreen` subscription/unsubscribe/navigate-call chain.
- Zero regressions: `pnpm codecheck` clean, full suite (`pnpm jest --runInBand --silent --forceExit`) 213/4170 -> 214/4187 (exactly the 1 new suite / 17 new tests this plan added). All 9 NavShell suites pass together: 102 tests.

## Decisions Made

- Kept the doc-comment wording that describes the absence of `render(`/`screen.`/`userEvent` without spelling those exact literal tokens -- recurrence of the phase's own-doc-comment-trips-its-own-grep lesson (see Deviations).
- Used a lightweight synchronous `useEffect` mock (invoke immediately, capture the returned cleanup) rather than `DownloadsRing.test.tsx`'s full cursor-indexed hook harness, since `NavShell` has exactly one effect and no `useState` -- the simpler mock is sufficient and keeps the test file shorter without losing any assertion power the behavior list requires.
- Effect dependency array is `[navigate]`, not the retired sidebar's `[]` -- `navigate` is referenced inside the effect body and this project's `react-router-dom` version returns a stable `navigate` identity across renders, so this is a lint-clean equivalent to "mount once," not a behavior change.
