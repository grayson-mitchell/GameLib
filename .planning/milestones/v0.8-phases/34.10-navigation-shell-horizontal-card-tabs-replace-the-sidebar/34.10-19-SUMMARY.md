# Phase 34.10 Plan 19: Constrain MUI Icon+Label Tab Height to the Navbar Line Summary

**Overrode MUI's unconditional `minHeight: 72` for icon+label `<Tab>`s with a content-derived `calc()` min-height (37px at the 16px root) scoped under `.NavTabs`, and fixed a handed-off no-fallback `var(--divider)` border-color bug in the same file, closing F-34.10-04 per `34.10-F04-DIAGNOSIS.md`'s single surviving cause.**

## Accomplishments

- `.NavTabs .MuiTab-root` now declares `min-height: calc((2 * var(--space-xs)) + 1.25em + 1px)` (37px at the default 16px root), directly implementing `34.10-F04-DIAGNOSIS.md`'s H1 finding: MUI's `Tab.js` applies `minHeight: 72` unconditionally when a `<Tab>` receives both `icon` and `label`, and nothing in this file previously overrode it, so the 72px tab overflowed 16px above the 56px navbar (the navbar's `align-items: flex-end` anchored that excess upward, reading as a second row).
- The override is content-derived, not a shrink-to-fit guess: `2 * var(--space-xs)` mirrors the rule's own already-declared vertical padding, `1.25em` mirrors MUI's own `lineHeight: 1.25` multiplier on this rule's `font-size: var(--text-md)`, and `1px` accounts for the rule's own `border-top` (`border-bottom` is `none`).
- Fixed the `border-color: var(--divider)` no-fallback theme-survival bug that `34.10-18-SUMMARY.md` explicitly recorded as a finding owned by this plan's file: `--divider` is declared in only 2 of 11 real theme blocks in `themes.scss`, so `.Mui-selected`'s top/side "card" framing border was fully transparent in the other 9 themes (including 3 of the 4 the live gate sweeps). Replaced with `var(--body-background)`, the same token this rule already uses for `background` and `border-bottom`, already structurally verified elsewhere in this file's own test suite to resolve in all 11 theme blocks.
- Extended `appShellLayout.test.ts` (not a new file, consistent with the project's recorded macOS case-collision trap) with a five-gate `F-34.10-04` `describe` block: the exact implemented `min-height` declaration, MUI-selector scoping proof (no rule leaks to `WineManager/index.tsx:222`'s separate `<Tabs>` instance), seam-recipe survival (`position: relative`, `top: 1px`, `.Mui-selected`'s `background`), a `flex-wrap` prohibition (H2 was REJECTED in the diagnosis as a literal cause), and a no-hex-literal check covering the carried-in border-color fix.

## Decisions Made

- Implemented the diagnosis's single surviving cause exactly, at the exact selector it named (`.NavTabs .MuiTab-root`), and did not touch `--navbar-height` in `NavShell/index.scss` — the diagnosis explicitly rejected growing the navbar band to accommodate one child's default sizing, and `shellTokens.test.ts`'s single-declaration-ness gate for that token was left undisturbed (still passes).
