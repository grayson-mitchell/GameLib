# Phase 34.10 Plan 08: Mount the nav shell, restructure the grid, migrate the drag region Summary

**`NavShell` replaces `<Sidebar />` in `App.tsx` behind a shared `Tier2PortalProvider`, `App.css`'s grid gains a fourth area (navbar row + tier2 column splitting the old sidebar column), and the frameless-window drag-region fallback in `tauriWindowChrome.ts` moves from `.Sidebar` to `.NavShell__navbar` with all three pinning fixtures renamed in the same commit.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 3 completed (single commit each; task 3's commit spans both its source and test files)
- **Files modified:** 4

## Accomplishments

- `App.tsx`: `Sidebar` import/render replaced with `NavShell`, mounted as the sibling immediately before `<main className="content">` inside the `TourProvider` branch. `Tier2PortalProvider` now wraps `NavShell`, `<main>` (and therefore the `Outlet` subtree where `Library` portals `<Header />` from), the controller div, `WindowControls`, and `Help` -- so both tier-2 portal consumers (`NavShell` reading `filled`, `Library` writing into the target) share one provider instance. The `isConsoleMode` branch (bare `<main className="content consoleContent">`) is byte-identical to before -- verified by diff, no shell there.
- `App.css`: `grid-template-areas` changed from `'offline offline' 'sidebar content' 'sidebar controller'` to `'offline offline' 'navbar navbar' 'tier2 content' 'tier2 controller'`, `grid-template-rows` gained a fourth track (`min-content min-content 1fr min-content`), and the `.App .Sidebar` rule was deleted outright -- no replacement `.App .NavShell__navbar` rule added, since plan 02's `NavShell/index.scss` already owns those two elements' placement. `.App` and `.App .content` selectors, and the entire F-10 regression comment block explaining why `min-height: 100%` must never return, are unchanged verbatim. `WindowControls` needed no change (`grid-area: content` still resolves).
- `tauriWindowChrome.ts`: `resolveDragRegion`'s final fallback (`start.closest('.Sidebar') !== null`) now reads `start.closest('.NavShell__navbar') !== null`, with the doc comment above it updated to name the new class. The interactive-element exclusion selector (`a, button, [role="button"], input, select, textarea, .windowControls`) is byte-identical, preserving the WR-01 lower-case `.windowControls` fix. No settings-read was added inside the hot path (D-02's "gated on `isFrameless`" is satisfied structurally, per the plan's own reasoning: a decorated window's native titlebar supplies its own drag surface regardless).
- `framelessRuntime.test.ts`: all three `FakeElement('div', { className: 'Sidebar' })` fixtures (and their chained children) renamed to `'NavShell__navbar'`, with test titles updated to match, landed in the SAME commit as the source change -- `git show --stat` on that commit lists both files.
- Zero regressions: `pnpm codecheck` (tsc) clean; full suite (`pnpm jest --runInBand --silent --forceExit`) still 214 suites / 4187 tests, all passing (no new suites this plan -- no new test files were created, only existing fixtures edited). `pnpm lint-translations` exits 0 with only pre-existing empty-translation warnings in unrelated locale files. `npx eslint` on all four touched files reports no new findings (one pre-existing `no-this-alias` error at `framelessRuntime.test.ts:90` confirmed present before this plan's changes, outside this plan's edited region, out of scope).

## Decisions Made

- Placed `Tier2PortalProvider` at the outermost position inside `TourProvider` (wrapping everything that branch renders) rather than more narrowly around just `NavShell` + `<main>`, since the sibling elements (controller, `WindowControls`, `Help`) don't consume the portal context and a wider provider boundary is simpler to reason about than threading it around an irregular subset -- no functional difference, since only `NavShell` and `Library` (inside the `Outlet`) actually read from it.
- Did not add a `.App .NavShell__navbar` rule to `App.css` even though it would have been a natural place to declare it -- kept layout ownership solely in `NavShell/index.scss` per the plan's explicit instruction, avoiding a duplicated `--tier2-width`-style contract split across two files.
- Left `resolveDragRegion` free of any new `isFrameless`/settings read, matching the plan's explicit reasoning that a decorated window's native titlebar makes the app-provided drag region harmless when frameless mode is off, and that the function runs on every mousedown so adding a settings read there would be wasteful and premature (no settings state exists at `tauriAttach.ts`'s handler-install time anyway).
