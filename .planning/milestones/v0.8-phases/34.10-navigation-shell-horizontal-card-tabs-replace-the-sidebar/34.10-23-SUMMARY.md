# Phase 34.10 Plan 23: Rescope unscoped MuiTabs selector + add regression guard Summary

**Moved GamesSettings' unscoped `.MuiTabs-root` rule under its existing `.settingsDialogContent, .settingsWrapper` ancestor pair and added a 5-test jest source-text gate (`muiTabsSelectorScoping.test.ts`) that fails on any future unscoped `MuiTab*`/`MuiTabs*` selector in a frontend stylesheet.**

## Accomplishments
- `GamesSettings/index.scss`'s top-level `.MuiTabs-root { ... }` block (the confirmed root cause of F-34.10-03/F-34.10-04) is now nested inside the file's existing `.settingsDialogContent, .settingsWrapper` ancestor pair, closing the leak at its source instead of only at the symptom (`NavTabs/index.scss`'s override).
- `NavTabs/index.scss`'s nested `&.MuiTabs-root { padding-bottom: 0; min-height: 0; }` override is retained and its comment corrected to describe the new, rescoped reality — kept deliberately as a second line of defense, not removed.
- A new repo-wide jest guard (`src/frontend/__tests__/muiTabsSelectorScoping.test.ts`, 5 tests) scans every `.scss`/`.css` file under `src/frontend` and fails if any declares an unscoped, top-level `MuiTab*`/`MuiTabs*` selector — proven to actually fail (not just pass) via a one-off falsification against the real pre-fix file.

## Decisions Made
- Both `.settingsDialogContent` and `.settingsWrapper` are required as the scoping ancestor (neither alone covers both `GamesSettings` render sites — `Settings/index.tsx` and `SettingsModal/index.tsx`); followed the file's own existing `.defaults-hint` precedent for this exact pair.
- The guard's detection unit is "first compound of each comma-separated selector at brace depth 0" rather than a whole-line regex, specifically so `.downloadManager > .MuiTabs-root > ...` (legal, ancestor-scoped) is not confused with a bare `.MuiTabs-root { ... }` (illegal, unscoped) — both start with `.MuiTabs` somewhere in their text, but only the first compound is diagnostic.
- Built a dedicated `stripPreservingLineNumbers` helper for the guard instead of reusing `stripSourceComments` directly for line-numbered offender reporting, because `stripSourceComments` drops matched comment lines outright (collapsing line count for multi-line block comments), which would misreport offender line numbers. `stripSourceComments` is still imported and used (a sanity assertion that `PRE_FIX_SPECIMEN` strips to non-empty content), satisfying the plan's `key_links` requirement that the guard import and apply it.
