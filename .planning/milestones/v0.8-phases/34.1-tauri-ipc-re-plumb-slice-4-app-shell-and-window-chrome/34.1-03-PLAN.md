<objective>
D-01/D-02: implement the ten window-chrome channels renderer-side against Tauri's JS
window and webview APIs — no sidecar hop, no new Rust arms — and D-05/D-06: honor
`settings.framelessWindow` at runtime via `setDecorations()`, defaulting to decorated,
with GameLib's own titlebar buttons on all three platforms through one code path.

Purpose: this is the architectural headline of the slice. Window control is where Tauri
intends this API tier to live, it is the lowest-latency path for a titlebar click, and it
needs zero Rust work. It is also the first phase since Phase 27 to put real logic
directly into the `window.api` attach path, so SEAM Invariant A is binding here.

Output: a new `tauriWindowChrome.ts` implementation module, ten `isTauri()`-branched
exports in `misc.ts`, pre-paint decoration application from `tauriAttach.ts`, and a
frameless drag region that works without any frontend change.
</objective>
