## Sampling Rate

- **After every task commit:** Run the targeted `pnpm jest <new-test-file>` for that task's file
- **After every plan wave:** Run the cross-file sweep `pnpm jest appShellFlows|misc|capabilitiesDefault|electronUntouched` (naming mirrors Phase 34's `tauriConf|cargoFeatures|releaseWorkflow` sweep convention)
- **Before `/gsd:verify-work`:** `pnpm test:ci` full suite green **plus** `cargo check` in `src-tauri/`
- **Max feedback latency:** ~10 seconds for targeted runs

### Gap-Closure Additions (validation audit 2026-07-25)

*Three MISSING automated verifications found by this audit — none of them attached to a mapped task,
which is exactly why the original map read as complete. All three are now closed.*

| Gap | Requirement | Automated Command | Status |
|-----|-------------|-------------------|--------|
| GAP-1 | D-11 — the two tray icon assets must actually differ | `npx jest src/backend/__tests__/trayIconAssets.test.ts` | ✅ green (3 × `it.failing` — see note) |
| GAP-2 | D-12 / T-34.1-29 — `public/about.html` carries no `fetch` / `XMLHttpRequest` / `__TAURI__` / anchor tag, and does carry `default-src 'self'` | `npx jest src/backend/__tests__/aboutHtmlSource.test.ts` | ✅ green (6/6) |
| GAP-3 | AR-34.1-07 / SECURITY FOLLOW-UP-1 — `Cargo.lock` crate-name set is pinned; drift fails with an actionable diff | `npx jest src/backend/__tests__/cargoFeatures.test.ts` | ✅ green (10/10) |

**GAP-1's `it.failing` is deliberate and is not a weakened assertion.** The assertion is the honest
`expect(dark.equals(light)).toBe(false)`. `public/icon-dark.png` and `public/icon-light.png` are
byte-identical today (both md5 `e754404b2dfd8cb4181a20555175bb47`, 2129 bytes), as are the `@2x`/`@3x`
pairs — a tracked **artwork** defect (`.planning/todos/pending/tray-dark-light-icons-are-identical.md`,
`needs: artwork`), not a code defect, and out of scope for a validation pass that may not touch
implementation or assets. Jest 29.7's `test.failing` semantics mean the suite is green precisely
*because* the assertion fails. This is self-alerting in the right direction: the day the artwork is
replaced, the body starts passing and `it.failing` turns **red**, forcing the flip to `it`. If a
future "fix" doesn't actually change the bytes, the gate stays red and says so.

**Why GAP-1 matters beyond the one defect:** every pre-existing tray test asserted on the *selector*
(the boolean flag, the `include_bytes!` path string, the path returned by `getIcon()`) and none on the
*payload*. Each proved the two branches were distinguished; none proved the two images differed. That
is a sampling-rate gap in the Nyquist sense — the tests could not have caught this class of defect at
any frequency, which is why it took live UAT to surface it.
