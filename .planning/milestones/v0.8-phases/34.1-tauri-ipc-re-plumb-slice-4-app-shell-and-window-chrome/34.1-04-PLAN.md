<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → sidecar `openWebviewPage(url)` | A renderer-supplied URL is passed to `openUrlOrFile` → `shell.openExternal` → the OS handler. |
| renderer → sidecar `getThemeCSS(theme)` | A renderer-supplied filename is joined onto `customThemesPath` and read from disk. |
| sidecar module graph → the real `electron` package | Every import added here becomes part of what the SEA-compiled sidecar loads. |
| renderer → `quit` | Any script in the `main` window can terminate the app process. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.1-12 | Elevation of Privilege | `openWebviewPage(url)` / `openReleases` reaching `shell.openExternal` with an attacker-chosen scheme (`file://`, `smb://`, a registered custom protocol) | accept | Pre-existing Electron behavior ported at parity (`main.ts:719` already does exactly this), and the transport is the already-shipped `open_external` command reviewed in Phase 30/33. Scheme filtering would be a behavior change smuggled inside a port. Recorded as a named target for a later hardening pass covering all `open*` channels at once (slice 6 owns 20 more of them). |
