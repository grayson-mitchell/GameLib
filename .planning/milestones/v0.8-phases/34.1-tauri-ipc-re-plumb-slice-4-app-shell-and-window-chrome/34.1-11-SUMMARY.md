## Which macOS gate is unconditional, which is state-conditional

| Gate | Condition | Why |
|------|-----------|-----|
| Hide `WindowControls` | `isMac` = `platform === 'darwin'` -- **UNCONDITIONAL** | Native traffic lights exist in BOTH macOS titlebar states (in the bar when `'visible'`, over content when `'overlay'`, per plan 34.1-10). GameLib's own buttons are redundant either way; gating on the narrower state would let the D-06 duplicate-buttons symptom reappear whenever a macOS user turns frameless off. |
| Apply the 78px reserve | `isMacOverlayTitlebar` = `isMac && isFrameless` -- **CONDITIONAL** | The reserve exists only to clear lights drawn OVER the webview, which happens only in `'overlay'`. In `'visible'` the native bar is its own strip above the webview and the reserve would be dead leading padding. |

## Declared Electron-macOS Behavioural Change

Under Electron on macOS, `main_window.ts:44-48` sets `titleBarStyle: 'hidden'` (keeps the traffic lights) and `main_window.ts:16` counts that as frameless, so `WindowControls` previously rendered there too -- the "both sets of buttons" symptom the D-06 UAT note originally described. This plan's gate is keyed on `platform`, not on a shell/runtime check, so it also removes the duplicate `WindowControls` set from the Electron macOS build. This is a deliberate, declared behavioural change to the Electron build (REQ-34.1-12), **not silently introduced** -- it must be added to the UAT ledger and confirmed during the owed UAT test 10 (Electron parity) re-run. No platform-branch-by-shell workaround was added: one code path, one behaviour.
