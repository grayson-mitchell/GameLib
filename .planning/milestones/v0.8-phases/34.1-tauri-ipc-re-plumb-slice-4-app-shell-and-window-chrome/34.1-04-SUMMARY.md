# Phase 34.1 Plan 04: Sidecar app-shell flow registration Summary

Registered the 18 sidecar-routed app-shell channels on `electronStub`'s handler surface
against the real handler bodies extracted by plan 34.1-02, added zero new Rust arms, and
gated the sidecar's curated import graph by construction.

## What Was Built

**Task 1 — `src/backend/sidecar/appShellFlowRegistration.ts`** (new, 256 lines):
registers the 18 channels — 8 `invoke` (`getCustomThemes`, `getThemeCSS`, `getCustomCSS`,
`getHeroicVersion`, `getLatestReleases`, `getWebviewPreloadPath`, …) and 10 `send`
(`changeLanguage`, `openReleases`, `openCustomThemesWiki`, `openWebviewPage`, `notify`,
`abort`, `quit`, plus the three no-ops) — importing the real `backend/appshell/*` bodies
from plan 34.1-02. Side-effecting sends re-wire onto the **existing**
`app_exit`/`open_external`/`notification_show` rustInvoke arms.

`handlers.ts` gained exactly one import and one `registerAppShellFlows()` call, placed
alongside the existing five `register*Flows()` and before `ensureStoresRegistered()`.

**Two `electronStub.ts` fixes (both Rule 1 bug fixes, see Deviations):**
- `app.getVersion()` now reads `package.json`'s version instead of
  `process.env.npm_package_version`, which is **unset in the packaged SEA sidecar** —
  `getHeroicVersion` would have reported `0.0.0` in every shipped build (T-34.1-17).
- `fakeWindow` gained a no-op `hide()`. `handleExit()` — newly sidecar-reachable via
  `quit` — unconditionally calls `mainWindow?.hide()` after `getMainWindow()` resolves
  the truthy `fakeWindow`, which had no `hide` method and would have thrown before
  `app.exit()` could run.

**Task 2 — `appShellFlows.test.ts`** (new, 591 lines, 21 tests): drives the real
`init(input, output)` RPC loop via the `downloadQueueFlows.test.ts` real-shim harness
(including the `jest.mock('os')` per-pid tmp-home redirect, so the suite never touches the
developer's real `~/Library/Application Support/GameLib`). Proves all 8 invoke channels
resolve real values rather than `UNPORTED_CHANNEL_MARKER`, all 10 send channels reach
their backing function with no unhandled rejection, `getHeroicVersion` is not `'0.0.0'`,
`set-connectivity-online` is live-without-reregistration and singly registered, and a
zero-new-Rust-arms guard rejects any `requestRustInvoke` outside the existing
`RUST_INVOKE_CHANNELS` set. Both guards were spot-checked red (manual duplicate
registration; fabricated `tray_set_icon` call) then reverted byte-identically.

**Task 3 — `appShellImportGate.test.ts`** (new, 206 lines, 7 tests): comment-stripped
by-construction gates asserting no file under `src/backend/sidecar/` imports the real
`electron` module, `utils/ipc_handler.ts` is not side-effect-imported into
`appShellFlowRegistration.ts`, and `main.ts`'s six app-shell handlers remain
*delegations* rather than inline bodies (D-08's shape). Comment stripping means the
file's own explanatory header mentioning `from 'electron'` cannot self-invalidate its
gate. Deliberately a new file — `electronUntouched.test.ts` is byte-untouched.

## Deviations from Plan

**Rule 1 (bug fix) — `electronStub.app.getVersion()`.** Switched from
`process.env.npm_package_version` to a static `package.json` import. The env var is unset
in the packaged SEA sidecar, so the plan's own acceptance criterion (`getHeroicVersion`
returns a non-empty string that is NOT `'0.0.0'`) could not be met otherwise. This is
T-34.1-17's declared mitigation.

**Rule 1 (bug fix) — `fakeWindow.hide()`.** Adding a no-op `hide()` was required to make
the `quit` channel work at all; without it `handleExit()` throws before reaching
`app.exit()`. Not anticipated by the plan because `quit` was only now made
sidecar-reachable.

**Process deviation — Task 3 close-out completed by the orchestrator.** The executor agent
was terminated twice by the same infrastructure fault (`API Error: Connection closed
mid-response`), the second time after writing `appShellImportGate.test.ts` but before
committing it. Rather than resume a third time, the orchestrator independently re-ran the
full verification (suite, `tsc`, the `electronUntouched` and `main.rs` empty-diff checks,
test count and REQ-tag checks against the plan's acceptance criteria) and then committed
Task 3 and this summary. No plan content was skipped or reinterpreted; the only difference
is who ran the final commands. Worth noting for the phase record because this agent's
context had grown past 300k tokens — the same risk applies to any later long-running plan
in this phase.
