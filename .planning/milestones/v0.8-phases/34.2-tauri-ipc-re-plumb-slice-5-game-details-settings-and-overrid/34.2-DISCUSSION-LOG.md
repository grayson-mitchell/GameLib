## Runner breadth

**Q1 — How wide should the port be for the dispatch channels?**

| Option | Description | Selected |
|--------|-------------|----------|
| Runner-generic, all six (Recommended) | Port the dispatch verbatim. Phase 32 D-02 established narrowing buys zero import-graph savings — `storeManagers/index.ts` force-constructs all six managers in the sidecar today. Narrowing would *add* a guard Electron doesn't have. | ✓ |
| Steam-narrow, guard the rest | Follow Phase 31 D-01 literally: only `runner === 'steam'` gets real behavior, others reject per Invariant B. Tighter tested surface, but adds divergence and a guard to delete at cutover. | |
| Generic, but declare the Steam stubs | Same as generic, plus per-channel declaration that Steam's `repair`/`changeVersionPinnedStatus`/`getLaunchOptions` are upstream stubs. | |

**User's choice:** Runner-generic, all six
**Notes:** Option 3's declaration rider was folded into the decision as a mandatory bookkeeping requirement rather than treated as a competing choice — it is compatible with option 1 and consistent with the established declared-list discipline. Evidence gathered during discussion: `SteamGame.repair()` logs "not implemented until Phase 2" (`steam/games.ts:1610`); `SteamLibrary.changeVersionPinnedStatus` (L797) and `getLaunchOptions` (L907) are underscore-arg stubs — i.e. these channels are already inert for Steam titles *in Electron*.

**Q2 — How should 34.2 handle uninitialized i18next in the sidecar?**

| Option | Description | Selected |
|--------|-------------|----------|
| Initialize i18next in sidecar bootstrap (Recommended) | Mirror `main.ts`'s `i18next.use(Backend).init({...})` in the sidecar bootstrap. Fixes all 103 call sites incl. the already-shipped Phase 30/32 paths, and stops later slices inheriting the landmine. | ✓ |
| Scope to this slice only | Use inline English literals for `repair`'s two calls. Minimal blast radius, but leaves 100+ sites broken and forces every future slice to re-solve it per-channel. | |
| Declare it, defer the fix | Port at parity, record the gap in PORTED-CHANNELS.md + SEAM.md Accepted Constraints, let Phase 35 own it. Honest but ships known-broken notification text. | |

**User's choice:** Initialize i18next in sidecar bootstrap
**Notes:** Discovered during discussion, not previously known. Verified empirically against the installed i18next 22.5.1 that `t('key', 'Default')` on the uninitialized singleton returns `undefined` — it does **not** throw and does **not** fall back to the inline English default. That silent-failure mode is why it survived Phases 30 and 32 unnoticed while Phase 34.1's CR-01 caught the `changeLanguage()` half immediately (that one throws). Scope check: 103 `t()` call sites across 16 backend files; five of those files are already in the sidecar's import graph.

**Check-in:** "Next area" — Runner breadth settled.
