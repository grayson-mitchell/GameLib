## Decisions Made
- **getWikiGameInfo measurement (D-10):** Cold-cache latency measured live against real network providers for three representative titles (method: this repo's own jest `electron-store` automock forces every call to be a genuine cache miss, so no manual cache-clearing was needed). Results: Hades 1190ms, Stardew Valley 957ms, Portal 2 702ms — all comfortably under the 60s bound. Decision: `getWikiGameInfo` stays on the default 60s timeout; it is NOT added to `LONG_RUNNING_CHANNELS`. Date: 2026-07-25. Network: this development machine's normal internet connection (no artificial throttling).
- **getCrossoverIndex exemption:** Added to `LONG_RUNNING_CHANNELS` because `buildCrossoverRatingMap()` fans out over every game in every library manager AND calls `loadIndex`/`buildMaps` once per game (a known, deliberately-not-fixed inefficiency recorded in `34.2-03-SUMMARY.md`) — the same library-wide shape as the already-exempt `checkGameUpdates`/`refreshLibrary`. Exactly one string added; zero new `dispatch_rust_channel` arms (confirmed via `git diff src-tauri/src/main.rs | grep -c dispatch_rust_channel` = 0).
- **gameAnticheatInfo's real "no match" value:** `Array.prototype.find()`'s no-match result is `undefined`, not `null`, despite the function's declared `Promise<AntiCheatInfo | null>` signature. This is pre-existing behavior, out of this plan's scope to "fix" — the test suite asserts the real (falsy/undefined) behavior rather than the type declaration's implied `null`.
