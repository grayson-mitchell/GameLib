addressed: no Rust-side test proves `timeout_for()` (`src-tauri/src/main.rs:146-152`) actually
consults `LONG_RUNNING_CHANNELS`. The existing coverage

test would still pass.** That matters concretely: `repair` and `readConfig` were added to the
exemption list by gap cycle 1 precisely so a long repair does not surface as a spurious

`cargo test` nor `cargo check`). Feasibility was probed during planning:
`cd src-tauri && cargo test --no-run` completes in 43s and produces
`Executable unittests src/main.rs (target/debug/deps/gamelib_shell-…)`, so a `#[cfg(test)]`
module inside the binary crate builds and runs. The absence of a CI cargo step is exactly why
Task 2's jest source gate exists: without it, the Rust test could be deleted and nothing
automated would notice.

Purpose: replace a source-shaped claim with a behavioral one, for the one Rust function this
phase's requirements depend on.

const INVOKE_TIMEOUT: Duration = Duration::from_secs(60);            // main.rs:102

const LONG_RUNNING_CHANNELS: &[&str] = &[                            // main.rs ~:132-143
    "install", "updateGame", "uninstall", "checkGameUpdates", "refreshLibrary",
    "getCrossoverIndex", "repair", "readConfig",
];

fn timeout_for(channel: &str) -> Option<Duration> {                   // main.rs ~:146-152
    if LONG_RUNNING_CHANNELS.contains(&channel) { None } else { Some(INVOKE_TIMEOUT) }
}
// `None` means "wait indefinitely".
