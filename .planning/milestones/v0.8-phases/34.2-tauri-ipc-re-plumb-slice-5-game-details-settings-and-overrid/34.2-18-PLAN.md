an existing `gamelib.log` to `gamelib.log.old` on first write, so an uncontained run destructively

src/backend/sidecar/pathShim.ts:30-39
  function resolveAppDataDir(): string {
    switch (platform) {
      case 'darwin': return join(homedir(), 'Library', 'Application Support')
      case 'win32':  return env.APPDATA || join(homedir(), 'AppData', 'Roaming')
      default:       return env.XDG_CONFIG_HOME || join(homedir(), '.config')
    }
  }
`platform` and `env` come from 'process' — NOT from the mocked `backend/constants/environment`, and
NOT from the mocked `os`. This is why an os.homedir() mock alone does not contain anything.

src/backend/logger/paths.ts:12-24 — getBaseLogPath()
  isWindows → join(process.env.LOCALAPPDATA ?? join(homedir(),'AppData','Local'), 'GameLib','logs')
  isMac     → join(homedir(),'Library','Logs','GameLib')
  else      → join(process.env.XDG_STATE_HOME ?? join(homedir(),'.local','state'),'GameLib','logs')
  getLogFilePath(args) = join(getBaseLogPath(), relativeFilePath + '.log')
The three suites mock `backend/constants/environment` to isLinux:true, so the XDG_STATE_HOME branch
is ALWAYS taken regardless of host OS.

src/backend/logger/log_writer.ts:65-75 — #archiveOldLogFile() does a synchronous
renameSync(logFilePath, logFilePath + '.old') on first write. This is the destructive operation.

The remedy shape to copy (src/backend/sidecar/__tests__/gameDetailsFlows.test.ts:136-161): a
jest.mock('../pathShim', ...) factory returning getPath for 'appData'|'userData'|'temp'|'home',
rooted at one per-suite tmp directory, with NO platform branch and NO env var reference, and
throwing for any unshimmed name.

The tripwire shape to extend (gameDetailsFlows.test.ts:318-331 / enrichmentFlows.test.ts:274-287): a
top-level beforeAll looping [appFolder, userDataPath, fixesPath] through
relative(resolve(tmpdir()), resolve(candidate)) and throwing "REFUSING TO RUN" when the result
startsWith('..') or isAbsolute(...). Never join, never a bare startsWith on the raw string.

WARNING (sidecarRejectionGuard.test.ts:158-166): backend/logger must be wrapped with jest.spyOn,
never jest.mock — logger/index.ts and log_writer.ts require each other circularly and a
requireActual-based factory throws "getLogFilePath is not a function" inside LogWriter's
constructor. Mocking backend/logger/paths (a leaf module that imports only os/path/environment) does
NOT re-enter that cycle, provided the factory never requires backend/logger.
