# Phase 34.2 Plan 29: Close Four Gate-Quality Defects in testContainment.test.ts Summary

**Fixed two vacuous Block D gates (WR-01 docblock-only env assignment, WR-02 ungated `node:os` mechanism), decoupled Block C's misleading self-tests from the live directory (WR-05), added a new Block E enforcing the backend-only containment scope claim against frontend/common/preload/meta, corrected `bootstrap.test.ts`'s detector-vs-preventer comment (WR-10), and registered `loggerCallSiteGuard.test.ts`.**

## Performance

## Accomplishments

- Block D's `HOME`/`USERPROFILE`/etc. env-var gate now matches `stripComments(source)` via a shared `assignsContainmentEnvVar` predicate, instead of raw source — closing the exact docblock-vacuity defect gap cycle 2's original WR-01 was raised to fix, which had been silently reintroduced.
- New `hasContainmentOsMock` predicate gates the `jest.mock('os'/'node:os', ...)` module-registry substitution plus `homedir`/`userInfo` overrides — the mechanism `jest.setupContainment.ts`'s own docstring calls "THE load-bearing fix" — closing the gap where deleting the `node:os` registration (the exact CR-02 regression class) left Block D fully green.
- Block C's two self-tests now build their `actual`/`declared` inputs from small literal arrays instead of `listActualTestSuites()`, so a genuine unclassified-suite failure is no longer accompanied by two additional, misleadingly-worded self-test failures.
- `loggerCallSiteGuard.test.ts` registered in `STRUCTURALLY_CONTAINED_SUITES`, closing the Block C classification failure plan 34.2-26 deliberately left open.
- New Block E recursively walks `src/frontend`, `src/common`, `src/preload`, and `meta`, asserting no `*.test.ts(x)` file there imports `backend/logger`, `backend/logger/paths`, `backend/constants/paths`, or `backend/sidecar/pathShim` — converting `jest.config.js`'s hand-maintained "reachable only from `src/backend`" scope claim into an enforced invariant.
- `bootstrap.test.ts`'s tripwire comment corrected: it is a *detector*, not a *preventer* — `jest.setupContainment.ts`'s `setupFiles`-time precondition (plan 34.2-25) is the actual preventer, because `setupFiles` runs before this file's own module-scope imports, while the tripwire's "first `it`" position only precedes calls inside its own test body.
