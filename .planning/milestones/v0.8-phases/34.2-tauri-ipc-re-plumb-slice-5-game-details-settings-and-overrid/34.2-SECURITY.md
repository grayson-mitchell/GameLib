# Phase 34.2 — Security

> Per-phase security contract: threat register, accepted risks, audit trail.

Retroactive `/gsd-secure-phase` run, 2026-08-22. Phase 34.2 shipped **30 plans across four gap
cycles**; every plan carried a parseable `<threat_model>` block, so this is a *verification of
declared mitigations*, not a retroactive STRIDE construction.

**Register scope.** 164 threat entries. They are keyed by **`(plan, threat_id)`**, not by
threat_id — 117 distinct IDs are spread across the 164 rows, so several IDs recur in different
plans against different components. Keying on the ID alone would silently collapse 47 entries.
The three `## Threat Flags` sections present in the SUMMARY files (34.2-14, -15, -27) each read
"None", so nothing is added beyond the plan registers.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| renderer → sidecar IPC | 26 ported game-details/settings/overrides channels, invoke- and send-kind | game IDs, app names, runner names, settings objects, install paths |
| remote GitHub raw content → sidecar disk | `fetchLastestReleases()` and `downloadAntiCheatData` GET unauthenticated JSON from `raw.githubusercontent.com`; the second is written to `appFolder` | untrusted third-party JSON |
| bundled locale files → i18next resource loader | `i18next-fs-backend` reads JSON from a `publicDir`-derived path at runtime | first-party locale resources |
| sidecar stdout | stdout **is** the Tauri RPC pipe — any stray write corrupts transport | diagnostics that must go to stderr instead |
| sidecar process lifecycle | anything added to `init()` can prevent the process reaching `READY_SENTINEL` | boot-time promises and listeners |
| test process → developer filesystem | backend suites resolve `appFolder`/log paths from `homedir()`; unredirected, they write to the operator's real config and log directories | real user data (proven destroyed 3× before containment landed) |
