<objective>
Close **verification gap #3 (REQ-34.2-03) / code-review finding WR-02**: the requirement's literal
claim and two module docstrings assert that files under `src/backend/gamedetails/` and
`src/backend/sidecar/` do not reach `electron` **transitively**, "proven by a comment-stripped source
gate, not by inspection." Both halves are false. The claim is false, and the gate
(`gameDetailsImportGate.test.ts`) is a depth-1 regex over each file's own text that structurally
cannot see transitive edges.

`dispatch.ts:48` imports `notify` from `'../dialog/dialog'`, and `dialog.ts:2` does
`import { dialog, Notification } from 'electron'`.

At runtime this is harmless: `electronStub`'s `Module._load` interception rewrites every
`require('electron')` inside the sidecar process, which is why `cargo check`, `tsc` and the full test
suite all stay green. The defect is that the gate and the prose **overclaim a static property the
code does not have** — and Phase 35's cutover work depends on knowing precisely what is genuinely
electron-free versus what is hook-rescued.

**The decision this plan makes, and its evidence.** The gap could be closed either by making the gate
genuinely transitive or by correcting the prose. The choice was settled by measurement, not
preference. Resolving the real transitive import graph with the TypeScript compiler API from the four
gated entry points (`gamedetails/dispatch.ts`, `gamedetails/overrides.ts`,
`sidecar/gameDetailsFlowRegistration.ts`, `sidecar/enrichmentFlowRegistration.ts`) reaches
**194 first-party files, of which 29 import `electron` directly** — including
`constants/paths.ts`, `common/types.ts`, `common/types/ipc.ts`, `utils.ts`, `launcher.ts` and
`backend/ipc.ts`. It is not one `dialog/dialog` edge; it is effectively the entire backend, and it
includes modules that every file in the codebase imports.

A "real" transitive gate would therefore need a 29-module allowlist spanning the whole backend. Such a
gate constrains nothing and is itself a lie by omission. It is also not achievable inside this cycle
without untangling the backend's electron coupling wholesale — which IS Phase 35's job, not a gap
cycle's.

**So: correct the prose to the true invariant, and make the correction substantive rather than a
retreat** by committing the measurement itself as a ledger. The ledger is not a pass/fail purity gate;
it is a monotonic tripwire (the reachable electron-importing set may shrink, never grow without an
explicit, reviewed baseline edit) and it hands Phase 35 the exact, machine-generated cutover
work-list. That converts an overclaim into a measured fact.

Purpose: nobody — least of all the Phase 35 cutover — can be misled about which files are genuinely
electron-free versus hook-rescued.
Output: three corrected prose sites and a committed, enforced reach ledger.
</objective>
