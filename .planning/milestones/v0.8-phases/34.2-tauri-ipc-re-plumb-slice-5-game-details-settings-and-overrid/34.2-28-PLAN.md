<objective>
Close two gate-quality defects in the JS-side pin over `src-tauri/src/main.rs`:

**WR-04** — `hasBehavioralRustTestModule` (lines 105-116) deliberately runs against RAW source and
then asserts `timeout_for` appears "at least twice" inside the `#[cfg(test)]` region as proof the
module "genuinely exercises the function, not merely exists". Comments inside the region count, so a
test module consisting of nothing but two `// timeout_for` comment lines and a
`for _c in LONG_RUNNING_CHANNELS {}` loop with **zero assertions** satisfies all three conditions.
The gate's own description is therefore not enforced.

**WR-08** — `loadMainRsCode()` (lines 54-61) does `.replace(/\/\/.*$/, '')` with no string-literal
awareness. `main.rs` is safe today only because every `steam://` / `https://` occurrence sits on a
line that starts with `//` and is dropped wholesale; the moment a code line gains a literal such as
`"steam://rungameid/"`, the stripper truncates it and the `INVOKE_TIMEOUT` / `LONG_RUNNING_CHANNELS`
assertions fail or, worse, silently match a truncated body. This helper is also the pattern other
Wave-0 config gates copy.

Purpose: this project's CI runs no cargo step at all, so this JS file is the only automated thing
standing between the Rust behavioural tests and silent deletion. A gate that a zero-assertion module
satisfies provides no protection at all.

Output: a gate that requires a real assertion, and an explicit guard against the stripper class of
defect.
</objective>
