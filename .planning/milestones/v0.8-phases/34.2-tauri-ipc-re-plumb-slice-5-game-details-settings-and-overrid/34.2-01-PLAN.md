## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote GitHub raw content → sidecar disk | `fetchLastestReleases()` GETs `release-data.json` and `downloadAntiCheatData` GETs `games.json` from `raw.githubusercontent.com`, then writes the second to `appFolder`. Both are unauthenticated, attacker-influenceable-if-upstream-compromised inputs. |
| bundled locale files → i18next resource loader | `i18next-fs-backend` reads JSON from a `publicDir`-derived path at runtime. |
| sidecar process lifecycle | Anything added to `init()` can prevent the process reaching `READY_SENTINEL`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.2-01 | Tampering | `downloadAntiCheatData`'s write of remote JSON to `join(appFolder,'areweanticheatyet.json')` | accept | Unchanged Electron behaviour — this plan changes only *when* the existing code runs, not what it does. The path is a fixed constant, never derived from the response; the file is read back through `JSON.parse` + a `.find()` and its worst outcome is a wrong/absent anticheat badge. Re-evaluate only if the file ever gains executable meaning. |
