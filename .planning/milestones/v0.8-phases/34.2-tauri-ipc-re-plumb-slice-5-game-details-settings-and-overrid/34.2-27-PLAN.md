<objective>
Close **WR-06**: `repairFailure.ts:92-96` wraps `window.api.logError(...)` in `try { ... } catch { /* empty */ }`.
Under Tauri the single most likely failure of that call is that the preload factory did not attach it
(`window.api` or `.logError` undefined) — a `TypeError`, not a log-write failure — and it is discarded
with **zero** trace. That is the exact silent-void class this phase was convened to close, reproduced
inside the very function written to close it. Separately, the module's own docstring claims T-34.2-53
holds for "three plain, non-async calls", but signal 3's `showDialogModal(...)` and its two `t(...)`
calls (lines 98-103) are unguarded, so a throwing caller-supplied `t`/`showDialogModal` still escapes
`reportRepairFailure` into the un-awaited dialog-button handler at `index.tsx:158`.

Also closes **WR-03**'s `repairFailure.ts:78` prettier regression (CI runs `pnpm prettier` =
`prettier --check .`, and the review verified this file was clean at `4bd04595` and dirty at HEAD on
the exact line gap cycle 3 added).

Purpose: REQ-34.2-12 exists to guarantee a repair failure is visible. A signal that fails silently
does not satisfy that, and today no test in `repairFailure.test.ts` exercises a throwing or absent
`logError`.

Output: three signals that are each individually diagnosed on failure, with a dialog that still
renders when translation throws.
