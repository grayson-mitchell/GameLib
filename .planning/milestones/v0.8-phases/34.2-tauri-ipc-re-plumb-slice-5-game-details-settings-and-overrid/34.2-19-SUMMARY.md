## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 4 - Architectural, coordinator-approved] Env-var-only `os.homedir()` redirection does not work under Jest; switched to `jest.mock('os', ...)`**

- **Found during:** Task 2, while writing and running `structuralContainment.test.ts` against the Task 1 implementation.
- **Issue:** The plan's specified mechanism (`process.env.HOME`/etc. redirection only, explicitly forbidding `jest.mock`) does not redirect `os.homedir()` inside a Jest test. Jest's `jest-environment-node` + `jest-util`'s `installCommonGlobals` (`node_modules/jest-util/build/createProcessObject.js`) replace `global.process` PER TEST FILE with a deep-cloned synthetic process object whose `.env` is a pure-JS `Proxy` — a one-time snapshot of the real environment, decoupled from it. Writes to `process.env.HOME` inside a Jest test mutate only this JS-only clone; they never call the real `setenv()`. `os.homedir()` is a NATIVE binding (libuv `uv_os_homedir()`) that reads the real OS environ directly, bypassing Jest's fake `process.env` entirely — so `backend/logger/paths.ts`'s `getBaseLogPath()` isMac branch (which has no env-var fallback at all) kept resolving to the developer's real home the entire time Task 1's original commit was in place.
- **Live proof:** ran a full `sidecar/__tests__` jest run with the env-var-only fix installed and `stat`'d the real `~/Library/Logs/GameLib/gamelib.log`/`.log.old` before and after — both mtimes CHANGED (`11:36:51`/`11:36:22` → `11:42:53`/`11:42:53`), proving the defect was not closed.
- **Alternatives ruled out:** `Object.defineProperty(os, 'homedir', ...)`/`jest.spyOn` — throw `TypeError: Cannot redefine property: homedir` (Node's core-module exports are non-configurable getters under CJS `require()` on this Node version); a `Module._load` hook (the technique `installElectronHook.ts` uses successfully for `require('electron')`) — does not intercept `require('os')` under Jest, since Jest's Runtime resolves builtins via its own captured `require()`, bypassing `Module._load` entirely (verified empirically with a test-local hook).
- **Fix:** `jest.mock('os', () => ({ ...jest.requireActual('os'), homedir: () => containmentRoot }))`, called once from `jest.setupContainment.ts` — a module-registry substitution, not a property mutation, registered once via `setupFiles` before any test file's own imports run (still structural, one registration point, no per-suite opt-in). Env-var redirection kept as defense-in-depth for the Windows/Linux branches, which were never the problem.
- **Files modified:** `src/backend/jest.setupContainment.ts`, `src/backend/sidecar/__tests__/structuralContainment.test.ts` (docstring wording only), `src/backend/sidecar/__tests__/bootstrap.test.ts` (docstring), `.planning/.../34.2-19-PLAN.md` (full amendment + deviation log).
- **Verification:** live `stat` before/after now byte-identical (see "Live Destruction Check" below); `structuralContainment.test.ts` 6/6 green; hand-confirmed `jest.mock` called from a `setupFiles` module actually takes effect for that test file's transitive `require('os')` calls and is NOT defeated by `resetMocks: true` (the factory returns a plain arrow function, not a `jest.fn()`).
- **Escalation path:** since this contradicted an explicit, repeated plan constraint (not a simple bug), I stopped mid-Task-2 and returned a structured `checkpoint:decision` (Rule 4) to the coordinator with the full empirical evidence before making the change. Coordinator approved.
- **Committed in:** `752f6096` (correction), `a3963ed3` (plan amendment)
