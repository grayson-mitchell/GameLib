<objective>
Give `title` the same defensive fallback `error` already has on the install-failure dialog.

Purpose: On a real failed install the modal read, verbatim, gap intact:
"The installation of  failed: Steam servers dropped the connection. Retry to continue."
The backend had the identifier at that exact moment — the adjacent log line was
`Installation of 259130 failed with: ...` — so the appid was available even though the title was
not. A dialog naming "259130" is worse copy but strictly more useful than one naming nothing.

Output: `title` falls back to `appName`, plus a filed todo for the async-population root cause
(D-09 explicitly does NOT gate this plan on fixing it).

Note this is NOT the reserved-`{{count}}` i18next trap — `title` is an ordinary interpolation name.
The value itself was empty.
</objective>

Root cause, already resolved by research (do NOT re-derive it):
  `SteamGame.getGameInfo()` (`src/backend/storeManagers/steam/games.ts`, ~:554) returns
  `{} as GameInfo` — so `title` is `undefined` — when BOTH `library.get(this.appId)` and the
  `steamLibraryStore` cache miss. This gap is unique to Steam:
  `legendary/library.ts:203`'s `getGameInfo(appName, forceReload)` calls `this.loadFile(appName)`
  SYNCHRONOUSLY when `!library.has(appName)`, so GOG/Legendary never hit the race. Both
  `gog/games.ts:171` and `legendary/games.ts:91` additionally carry an explicit `title: ''` fallback
  with a `logError`. Steam has neither the sync-load nor the explicit-fallback pattern its siblings
  have.

Test harness, `src/backend/downloadmanager/__tests__/utils.test.ts` (already exists — it does NOT
need creating; `37-VALIDATION.md` flagged the path as "confirm during planning" and it is confirmed):
  `const getGameInfoMock = jest.fn().mockReturnValue({ title: 'Test Game' })`
  `jest.mock('backend/storeManagers', () => ({ libraryManagerMap: { steam: { getGame: ... }, gog: {...} } }))`
  `jest.mock('../../dialog/dialog', () => ({ notify: jest.fn(), showDialogBoxModalAuto: jest.fn() }))`
  `mockT` interpolates `{{token}}` from the options object against the string-literal fallback, so
  an assertion can read the RENDERED message.
  Existing precedent spec to copy the shape of: "D-03: a Steam install error ALSO raises a failure
  dialog via showDialogBoxModalAuto (one coherent error story)" (~:227).
  NOTE: `resetMocks: true` wipes `getGameInfoMock`'s return value before EVERY test — a test that
  needs `{}` must set it explicitly, and so must any test relying on the default.
