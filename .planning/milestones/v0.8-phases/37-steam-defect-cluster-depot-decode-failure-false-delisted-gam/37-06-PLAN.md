<objective>
Bound `platformsCapturedAt` from ABOVE as well as below, on BOTH sides of the comparison.

Purpose: `resolvePlatformWrite` carefully degrades a `NaN` / non-finite / wrong-type
`existingCapturedAt` to "indefinitely old" so a corrupt stamp can never block a write — and then
accepts any absurdly-large finite number, because `Number.isFinite` says yes to it. A clock-skew
event, an NTP correction or a hand-edited cache file writes one such stamp once, and that entry
outranks every subsequent write for that appId **permanently**. There is no repair path:
`MigrationSystem` is dead code under Tauri, so nothing will ever normalise it back (WR-02).
Separately, the incoming `capturedAt` parameter is not validated at all, which is safe only because
both current call sites happen to pass `Date.now()` — an asymmetry waiting for a third writer (IN-01).

Output: one plausibility predicate, applied symmetrically, degrading to writable on violation.

**This is NOT a ranking change.** D-17 is explicit: do not "fix" this by making one source beat the
other. Freshest-write-wins was chosen deliberately over "appdetails always wins" and "PICS always
wins" because it makes ordering explicit and auditable. This plan changes only which timestamps are
BELIEVED, never which source wins a believable comparison.
</objective>

| exported function -> future caller | `resolvePlatformWrite` is exported and general-purpose. The unvalidated `capturedAt` parameter is a trap for a third writer even though both current call sites pass `Date.now()`. |
