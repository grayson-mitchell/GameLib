<objective>
Establish the multi-family data contract and bring EVERY single-bottle read AND
write in `bottle.ts` to the family-shaped store the rest of the phase builds on.
This is the interface-first foundation: reshape `SteamBottleConfig` (D-04) into
`families` + `assignments`, define `SteamFamily` (D-01/D-02), thread an explicit
`bottleName` through `getSteamBottleSettings` and `dispatchToBottledSteam`/
`tellBottledSteamTo*` (D-05), convert `provisionBottle`'s (and `isBottleReady`'s
self-heal) persistence from the removed flat keys to `families[bottleName]`
read-modify-write, drop the now-dead flat-key fallback reads, and export the
private CrossOver helpers `families.ts` (Plan 02) needs.

Purpose: removing the flat keys turns every stale single-bottle reader into a
compile error (Pitfall 5). `provisionBottle` has SIX flat-key `.set(...)` writes
and `isBottleReady` a seventh — ALL must convert to `families[bottleName]` RMW in
THIS wave, or `tsc`/`codecheck`/`bottle.test.ts` (ts-jest type-checks on transform,
no `isolatedModules`) can never pass. This plan owns the entire flat→family cutover
in `bottle.ts` so no later plan re-touches it.

Output: reshaped `common/types/steam.ts`, family-shaped `bottle.ts` (reads +
writes + exports), extended `bottle.test.ts`.
</objective>

function upsertFamily(bottleName: string, patch: Partial<SteamFamily>): void {
