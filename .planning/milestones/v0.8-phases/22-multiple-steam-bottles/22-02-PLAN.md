<objective>
Create `steam/families.ts`: the single backend service that owns family CRUD,
the game→family resolver (D-05), and the one-time startup migration
(D-07/D-08). Every operation composes existing `bottle.ts` primitives — this
file reimplements nothing (`cxbottle`, sanitization, the CR-01 guard all come
from Plan 01's exports). It backs the D-12 IPC group wired in Plan 05.

Purpose: `resolveFamilyForApp` is the chokepoint between "user acted on appId"
and "which bottle" that games.ts (Plan 04) and the poller (Plan 03) consume.
The migration guarantees zero-loss upgrade of the Phase 17 bottle to the
"Default" family. Critically, `listFamilies`/`familyStatusForApp` report each
family's readiness LIVE via `isBottleReady` (Blocker 3) so the Settings "Not set
up yet" label (Req 4/6) clears the instant provisioning completes, rather than
sticking on a stale stored flag.

Output: `families.ts` (migration + slug + CRUD + resolver), new
`families.test.ts` (Wave 0).
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-03 | Tampering | family CRUD read-modify-write of the `families` Record | mitigate | Every mutator spreads the existing map and writes a single `[bottleName]` entry; delete uses object-rest — a naive whole-map `.set` (data-loss of siblings) is explicitly forbidden and grep-gated |
| T-22-04 | Elevation of Privilege | `createFamily` deriving a bottle dir id from user displayName | mitigate | displayName passes `sanitizeBottleName` (rejects `/`,`\\`,`..`,NUL,empty) before `slug()`; bottleName is frozen; provisionBottle's CR-01 guard is the sole `cxbottle --create` site (Pitfall 3) |
| T-22-05 | Spoofing/Info Disclosure | per-family Steam credential isolation | accept | Each family is a distinct CrossOver prefix with its own opaque bottled auth (D-04); no auth sharing path exists — isolation is structural, no code in this plan touches credentials |
| T-22-06 | Denial of Service | deleteFamily removing the last usable family | mitigate | Last-family guard blocks deletion; delete is confirm-gated at the UI (Plan 08) |
| T-22-06b | Info Disclosure | UI reporting a family as unprovisioned forever (stale flag, Blocker 3) | mitigate | provisioned reported LIVE via isBottleReady in listFamilies/familyStatusForApp; grep gate requires >= 2 isBottleReady call sites and a stale-flag test proves live derivation |
</threat_model>
