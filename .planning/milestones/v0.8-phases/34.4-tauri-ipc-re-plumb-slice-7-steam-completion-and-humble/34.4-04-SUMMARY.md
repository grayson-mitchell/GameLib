## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `humbleFlowRegistration.ts`'s own docstring broke `stripSourceComments`, making the curated-import guard vacuous against itself**

- **Found during:** Task 2, while performing the plan-mandated hand RED proof.
- **Issue:** The load-bearing circular-dep-fix comment block described the reach as `` `storeManagers/steam/*` `` (a wildcard-path mention, describing "any module under `steam/`"). That literal `/*` substring, sitting inside a `//` line comment, is indistinguishable from a real block-comment opener to `stripSourceComments`' `/\/\*[\s\S]*?\*\//g` first pass. The regex matched from that `/*` all the way to the next real `*/` later in the file — silently deleting the module's own `import { HumbleUser }` / `import { HumbleLibrary }` lines (and everything between) from the text the curated-import guard test inspects. First hand RED-proof attempt (adding `import '../humble/ipc_handler'`) showed the curated-import guard test still passing when it should have failed — that false-negative surfaced the defect.
- **Fix:** Reworded the three affected comment lines (`storeManagers/steam/*` → "storeManagers-under-steam" / "module under `storeManagers/steam`"; `humble/*` → "either humble module"; `steam/*` → "steam-touching") to remove every literal `/*` substring while preserving the original meaning.
- **Files modified:** `src/backend/sidecar/humbleFlowRegistration.ts`
- **Verification:** Re-ran the hand RED proof after the fix (see below) — the curated-import guard correctly failed once the forbidden import was genuinely present, and correctly passed once removed.
- **Commit:** `62637712` (bundled into the Task 2 commit — the fix was discovered and applied while writing Task 2's test)

**2. [Rule 1 - Bug] Curated-import guard regex missed the realistic bare-side-effect-import violation shape**

- **Found during:** Task 2, first hand RED-proof attempt.
- **Issue:** The first version of `importsIpcHandler()` only matched `from '...'` and `require(...)` forms. Adding a bare `import '../humble/ipc_handler'` (no `from` clause — this codebase's own curated-import idiom, e.g. `import '../storeManagers'`) was NOT detected, making the gate vacuous against the shape most likely to actually occur.
- **Fix:** Added an `import\s+['"]...['"]` branch to the regex, plus a new self-test proving the bare-side-effect form is now detected.
- **Files modified:** `src/backend/sidecar/__tests__/humbleFlows.test.ts`
- **Verification:** New self-test `gate self-test: a synthetic source with a bare side-effect import of humble/ipc_handler is detected` passes; full suite green (17/17).
- **Commit:** `62637712`

## Hand RED Proof (verbatim, per plan requirement)

`humble/ipc_handler.ts` has NO top-level registration side effect — `registerHumbleIpcHandlers()` is only a function *definition*; nothing in that file calls it at module scope. So a bare `import '../humble/ipc_handler'` alone registers nothing at runtime (confirmed: this shape alone left all 17 tests green, which is what first surfaced the docstring/regex defects above, since the deliberately-forbidden addition was NOT actually reproducing the danger). The real hazard this guard exists to catch is a curated module that imports **and calls** the forbidden registrar. The final, correct RED proof added:

```ts
import { registerHumbleIpcHandlers } from '../humble/ipc_handler'
```

to the imports, and

```ts
export function registerHumbleFlows(): void {
  registerHumbleIpcHandlers()
  // ...
```

as the first line of `registerHumbleFlows()`. Result — 3 of 17 tests failed, exactly as expected:

```
✕ REQ-34.4-07 registerHumbleFlows() does not register any of the 6 channels Phase 34.4.1 owns, as either a handler or a listener
  Object {
-   "handler": false,
+   "handler": true,
    "listeners": 0,
  }

✕ REQ-34.4-07 SEAM.md Invariant B: humbleRevealKey (deferred to Phase 34.4.1) still rejects non-fatally over the wire, and the RPC loop keeps serving
  Expected substring: "[GAMELIB_UNPORTED_CHANNEL]"
  Received string:    "Cannot read properties of undefined (reading 'gamekey')"

✕ REQ-34.4-07 humbleFlowRegistration.ts contains no import statement referencing humble/ipc_handler
  Expected: false
  Received: true
```

The second failure's message is itself confirming evidence: `humbleRevealKey` is now a REAL handler (registered by the forbidden `registerHumbleIpcHandlers()` call) that crashed on the test's empty-args invoke, rather than the expected non-fatal `UNPORTED_CHANNEL_MARKER` rejection — proof the 6 deferred channels genuinely became reachable, not merely that an assertion string changed.

Both changes were then reverted via `git checkout -- src/backend/sidecar/humbleFlowRegistration.ts`, which restored the file to the Task 1 commit — this *also* reverted the not-yet-committed docstring wording fix (Deviation 1), so that fix was reapplied by hand afterward. Final state: `git diff` on the module shows only the intended docstring wording change (Deviation 1) against the Task 1 commit; the RED-proof additions are fully gone. All 17 tests pass again.
