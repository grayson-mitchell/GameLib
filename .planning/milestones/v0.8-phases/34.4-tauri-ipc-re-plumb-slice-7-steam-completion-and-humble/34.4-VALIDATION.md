## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest 29.7.0 (backend project) + the frontend jest project for REQ-34.4-12's panel test. **No Rust this slice** — zero new `dispatch_rust_channel` arms expected, so no `cargo test` obligation (unlike 34.3). |

| **Quick run command** | `cd src/backend && npx jest sidecar/__tests__/<file>.test.ts` |
| **Full suite command** | `cd src/backend && npx jest` (plus `npx tsc --noEmit` and `cd src-tauri && cargo check`) |
| **Estimated runtime** | ~90s backend jest; targeted run <10s |

**Test-store safety — read before writing any test in this slice.** `tests-clobbering-real-steam-store`:
jest suites that `requireActual` electron-store once reached the REAL
`~/Library/Application Support/GameLib` and wiped the dev's Steam token. `afterAll` restore is
**not** a safety net (worker force-exit). Research found the risk is **structurally mitigated**
since Phase 34.2 gap cycle 4: `src/backend/jest.setupContainment.ts` redirects HOME/APPDATA/XDG
for every backend test file automatically, so new 34.4 suites inherit containment without
hand-rolling the per-suite `jest.mock('os', …)` pattern older suites use. Plans MUST NOT
disable, bypass, or opt out of that setup file. This is the slice that touches Steam **and**
Humble stores — the highest-exposure slice to date.

- **After every task commit:** targeted `npx jest <changed-file>.test.ts`

- **Before `/gsd-verify-work`:** full suite green **AND** the REQ-34.4-13 five-item live gate
  passed (**blocking** per D-08/D-13-carried)
- **Max feedback latency:** ~90 seconds (targeted run: <10s)

## Manual-Only Verifications

Per D-08/D-09/D-10 (carrying 34.3 D-11/D-13) these are **blocking phase-close conditions**, not
deferred UAT. Gate failure triggers a gap cycle **inside** Phase 34.4.

**`logoutSteam` is the reason this gate exists.** It is the G-30-01 channel; its failure mode
(`sidecar-send-channels-fail-silently`) produces no reject, no timeout and no console line —
structurally invisible to assertions, and already a known past defect. The "these channels have
assertable return shapes" argument is true for 14 of the 15 Steam channels and **false for the
one with a known past defect**.

Sidecar output is read from `~/Library/Logs/GameLib/gamelib.log` — **not** the `tauri:dev` terminal.

**All five items run under `pnpm tauri:dev`; there is deliberately NO packaged-build item (D-10).**
Recorded as a decision, not an oversight: unlike 34.3 D-12, nothing here depends on the
dev-vs-packaged sidecar spawn path — these are login, sign-out, data reads and a status check, all
build-independent. The keyring path that *does* differ when signed is already exercised by the
previously-ported QR login.

|---|---|---|---|---|
| 1 | Credential + SteamGuard login reaches a signed-in, populated library | REQ-34.4-13 / REQ-34.4-01 | End-to-end `steam-session` handshake against real Steam; jest can only prove the delegation | `steamStartCredentials` → `steamSubmitGuard` → `steamPollCredential` under `tauri:dev`; library populates |
