Both are **`addHandler` / `ipcMain.handle`**. Neither is a `send`.

`src/backend/main.ts:1510-1515`:
- `addHandler('getPrivateBranchPassword', (e, appName) => libraryManagerMap['gog'].getGame(appName).getBranchPassword())`
- `addHandler('setPrivateBranchPassword', (e, appName, password) => libraryManagerMap['gog'].getGame(appName).setBranchPassword(password))`

Note `setPrivateBranchPassword` takes **two** transport args (`appName`, `password`) — this is the
only two-arg channel in the whole 31-channel slice.

Backing implementation: `GOGGame.getBranchPassword` / `setBranchPassword` at
`src/backend/storeManagers/gog/games.ts:1398,1402`, reading/writing GOG's `privateBranchesStore`
(`storeManagers/gog/electronStores.ts:36`), **already registered** at `storeRegistration.ts:62` —
zero new store plumbing.

**No new import is required.** `libraryManagerMap` is already imported at
`settingsFlowRegistration.ts:68`, behind that file's own load-bearing `import '../storeManagers'`
first-import fix at L65. The existing precedent in the same file is `requestGameSettings` at L112-121,
which already calls `libraryManagerMap['steam'].getGame(appName).getSettings()` (L117), plus a
generic `libraryManagerMap[runner as keyof typeof libraryManagerMap].getGame(appName)...` shape at
L232-239. Mirror that shape.

**Why this is not the curated-import anti-pattern:** the rule (30 D-08 → 34.1 D-09 → 34.2 D-04 →
34.3 D-14) forbids side-effect-importing a feature module's `ipc_handler.ts`, which registers IPC
channels as an import side effect. `storeManagers/index.ts` registers nothing — it only constructs
library-manager instances. Reaching GOG through the already-imported `libraryManagerMap` is the
established, sanctioned pattern for a per-game-manager method.
