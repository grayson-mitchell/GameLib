<design_notes>

## What is actually true about `require.main === module` here — and what is not

Measured twice, independently (reviewer + verifier), under this repo's real `ts-jest` transform:
a module required from inside a test file sees `require.main.filename` = **the test file's own
path**, and `require.main === module` is **`false`**. So the standard idiom is safe under jest, and
the existing comment's central claim is false.

**But there is a second fact the review did not state, and it changes the design.** `runTs.cjs`
invokes esbuild with `--bundle`. A bundle collapses every source module into the **entry file's
single module scope**. Inside that bundle, `module` refers to the outfile's module and
`require.main` is the outfile's module — so `require.main === module` is `true` regardless of which
source file the top-level code originally came from. That is exactly what makes the CLI keep
working, and it also means this guard alone would **not** refuse a bundled import of this module by
some other entry.

Therefore: **do not replace `!process.env.JEST_WORKER_ID`. Add `require.main === module` to it.**

```ts
if (require.main === module && !process.env.JEST_WORKER_ID) {
  main()
}
```

Both conditions must hold. This is strictly narrower than either alone: `require.main === module`
adds refusal for non-bundled, non-entry-point imports (`ts-node`, a direct `require()` of a
transpiled copy, an ad-hoc probe) that `JEST_WORKER_ID` never covered, while `JEST_WORKER_ID`
preserves R15's "two independent gates" claim and covers the bundled case the other misses.

## The comment must state only measured claims

The whole finding is that the previous comment justified a design with an unmeasured, false claim.
A replacement comment that swaps one confident assertion for another has not fixed anything. The
new comment must name **both** measurements — the ts-jest `require.main` result, and the fact that
the CLI still prints its summary line after the change — and must state the `--bundle` module-scope
collapse as the reason the second condition is retained.

## Neither `tsx` nor `ts-node` is installed in this repo

Do not `npx` them and do not add them. The empirical evidence for this task comes from two places
only: the jest-internal RED proof of the new R5, and the live `pnpm lint-translations:gamelib` run.
