# Phase 34.11 Plan 02: NavItem Button-Branch Active State Summary

**Extended `NavItem`'s `elementType="button"` branch to merge caller `className` and render an `active` class via `classNames`, unblocking selectable Views/Collections rows in the tier-2 filter panel (REQ-34.11-11).**

- **Duration:** ~15 min

## Accomplishments
- `NavItemProps` gained an optional `active?: boolean` prop, deliberately named apart from react-router's `isActive` callback argument used in the NavLink branch
- The button branch now renders `<button className={classNames('NavItem', className, { active })} onClick={onClick}>` instead of the old hardcoded `className="NavItem"` — a selected View or Collection can now read distinctly from an unselected one
- The `NavLink` (default) branch is byte-identical to HEAD, confirmed via `git diff` showing no changes inside that case
- Four new direct-invocation test cases added to the existing 7-case suite (11 total), covering: active=true renders the class, active=false omits it, active-omitted omits it (guards the shipped default against regressing into a permanently-lit row), and a caller's `className: 'FilterRow'` merges alongside `'NavItem'`
