<objective>
Extend `NavItem`'s `elementType="button"` branch so it accepts `className` and renders an active
state, mirroring what the `NavLink` branch already does.

Purpose: this is a **required** task, not cleanup. `34.11-UI-SPEC.md` § "Views/Collections row
control" and `34.11-RESEARCH.md` Pitfall 1 both flag it: the button branch today is
`case 'button': return <button className="NavItem" onClick={onClick}>` — it drops `className`
entirely and has no `active` logic. Views and Collections are local `LibraryContext` state, not
routes, so they must use the button branch. Without this extension a selected View or Collection
is visually indistinguishable from an unselected one, and that is unimplementable rather than
merely ugly. The CSS is already correct and theme-safe (`NavItem/index.scss` declares
`--navitem-active-color` and `--navitem-active-background` and is already scoped under
`.NavShell__tier2 .NavItem`), so extending the existing component is strictly cheaper than the
rejected alternative of forking a parallel `FilterNavItem`.

Output: an extended `NavItem` plus new unit cases. Nothing else in the tree changes behaviour —
no existing caller passes the new prop, so every shipped `NavItem` renders identically.
</objective>
