## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest 29 (`ts-jest` preset), multi-project — roots: backend / common / frontend / preload / meta |
| **Config file** | `jest.config.js` (root) + `src/frontend/jest.config.js` |
| **Quick run command** | `pnpm jest src/frontend/screens/Library --silent` |
| **Full suite command** | `pnpm test:ci` (`jest --runInBand --silent`, all 5 projects) |
| **Estimated runtime** | quick ~15s · full suite ~3–5 min |

**Hard constraint — no jsdom.** `src/frontend/jest.config.js` sets `testEnvironment: 'node'`, and
neither `react-test-renderer` nor `@testing-library/react` is installed. Every new component test
MUST use one of the two established in-tree patterns:
1. **Direct function-invocation** — mock `react-i18next`/`react`, call the component as a plain
   function, inspect the returned element's `.props` (see `CrossoverBadge.test.tsx`).
2. **Source-text gate** — `fs.readFileSync` the raw `.tsx`/`.scss`, assert structurally (see
   `tier2Portal.test.ts`'s `cssBlock()` helper).

A plan that assumes `render()` is available will not run.
