# Phase 34.11: Library filtering — search, views, collections and cross-store facets - Discussion Log

> **Audit trail only.** Do not use as input to planning, research, or execution agents.
> Decisions are captured in CONTEXT.md — this log preserves the alternatives considered.

**Date:** 2026-08-09
**Phase:** 34.11-library-filtering-search-views-collections-and-cross-store-facets
**Areas discussed:** Filter semantics inversion, The 11 existing filters, Platform facet predicate, Genre facet fate, Collections model, Persistence & reset semantics, Chips/counts/empty state, Search scope

**Scouting note.** Three of the roadmap's "open" items turned out to be partly answered by shipped
code, which reshaped the questions before they were asked: nine filters already persist to
`localStorage`; manual collections already ship as `customCategories`; and genre coverage is not
merely "unverified" but measurably absent for Epic and lazy-only for Steam. A fourth discovery —
that `Library/index.tsx:819` already portals `<Header />` into the tier-2 slot — corrected one
answer after the fact (see Search scope).

## Filter semantics inversion

| Option | Description | Selected |
|--------|-------------|----------|
| Opt-in | Empty set = no constraint; ticking GOG shows only GOG. Matches the sketch engine; makes chips and exclude-own-facet counts meaningful. Requires migration. | ✓ |
| Keep opt-out | All boxes start ticked; unticking hides. No migration, no behaviour change — but chips would read "not Epic, not Amazon…" and an all-ticked default shows an empty chip row despite live state. | |
| Opt-in for Store/Genre, opt-out for Platform | Mixed model; each facet gets suiting semantics, at the cost of more code paths. | |

| Option | Description | Selected |
|--------|-------------|----------|
| Reset to empty, one-time | Detect legacy shape, discard, start with no filters. Mirrors the existing `migrateFilterMode()` helper. | ✓ |
| Translate all-true → empty, partial → complement | Preserves intent, but the complement can surprise. | |
| New storage keys, ignore old | Zero migration logic; orphaned keys accumulate and a rollback resurrects stale state. | |

| Option | Description | Selected |
|--------|-------------|----------|
| Confirm AND-across / OR-within | The conventional faceted-search model; users have strong priors. | ✓ |
| AND everywhere | For a store facet, ticking two stores would always be empty. Listed for completeness. | |

| Option | Description | Selected |
|--------|-------------|----------|
| Hide the unconnected store row entirely | No account → no games → the row is noise. Counts stay honest. | ✓ |
| Show dimmed with count 0 | Reuses the sketch's `.item.zero` pattern; advertises support but leaves dead rows. | |
| Show it, clicking prompts to connect | Turns a filter into onboarding — scope beyond a filter panel. | |

**Notes:** The inversion is the single largest behavioural change in the phase. Everything
downstream — chip wording, count meaning, the migration — follows from it.

## Deferred Ideas

- Genre facet — gated on real per-store genre coverage via a metadata backfill.
- Rule-based / smart collections.
- An "Install state" facet (Installed / Not installed / Update available / Downloading).
- Combining views, e.g. "installed favourites" — if it proves needed, promote Favourites to a
  facet rather than making views multi-select.
- Gamepad focus-scroll in the tier-2 panel — never measured across any of Phase 34.10's four gate
  runs, and the panel gets considerably taller here.
