`pnpm build-runners-onedir` script entry.

Create `meta/buildRunnersOnedir.ts` exporting:

`ONEDIR_RUNNERS` — a `Record<'legendary'|'gogdl'|'nile', { repo: string; tag: string }>` where
repo is `Heroic-Games-Launcher/legendary`, `Heroic-Games-Launcher/heroic-gogdl` and
`imLinguin/nile`, and each `tag` is read from `RELEASE_TAGS` (never a second literal). `comet` and
`epic-integration` MUST NOT appear as keys.

`archiveName(runner, arch)` — returns `${runner}_macOS_${arch === 'x64' ? 'x86_64' : 'arm64'}_onedir.tar.gz`,
matching the existing upstream `_macOS_x86_64` / `_macOS_arm64` naming already used in
`downloadHelperBinaries.ts`. Throws for any arch other than `x64` or `arm64`.

`extractUpstreamPyinstallerCommand(repoDir)` — globs `${repoDir}/.github/workflows/*.yml` and
`*.yaml`, finds the single line whose content contains `pyinstaller`, and returns it trimmed of
its YAML list/indent prefix. Throws naming the repoDir when zero such lines exist, and throws
naming every match when more than one does. Never guesses.

`toOnedirCommand(upstreamLine)` — returns `{ command, droppedExpressions }`. Throws if the line
does not contain the token `--onefile`, or contains it more than once. Replaces that one token
with `--onedir`. Removes every `${{ ... }}` GitHub-expression token, returning each removed token
in `droppedExpressions` so the deviation is auditable rather than silent. Throws if the resulting
command does not still start with `pyinstaller`.

A `buildRunner(runner, arch)` routine that: refuses to run unless `process.platform === 'darwin'`
and `process.arch === arch` (throws naming both, since PyInstaller cannot cross-compile — CONTEXT
constraint 1); shallow-clones `https://github.com/${repo}` at `--branch ${tag} --depth 1` into
`.build-tools/runners-onedir/src/${runner}`; creates a venv at `${repoDir}/.venv`; installs the
repo's own dependencies (`requirements.txt` if present, else `pip install .`); installs pyinstaller
using the repo's own pin if it declares one, else literally `pyinstaller==6.20.0`; runs the
`toOnedirCommand` output from within the repo dir; then archives `dist/${runner}` with argv-form
`spawn('tar', ['-czf', outPath, '-C', distDir, runner])` so the archive root entry is `${runner}/`.

Write `.build-tools/runners-onedir/out/${archiveName(runner, arch)}` plus, for the whole run,
`SHA256SUMS-${arch}` (one `sha256  filename` line per archive, computed with `node:crypto`) and
`BUILD-MANIFEST-${arch}.json` recording per runner: repo, tag, the verbatim upstream pyinstaller
line, the derived onedir command, `droppedExpressions`, the resolved `python3 --version`, the
resolved `pyinstaller --version`, the archive sha256, the file count and the Mach-O count under
`dist/${runner}`.

Every external invocation (`git`, `python3`, `pip`, `pyinstaller`, `tar`) uses argv-form
`spawn`/`spawnSync` with an array of arguments — never a shell string, never string interpolation
into a command (T-34.9-03, mirroring `meta/downloadZig.ts`'s T-24-06). `.build-tools/` is
build-tooling only and MUST NOT be written into `public/bin/**`.

Guard the entrypoint so importing the module for tests does not run a build: parse
`--arch=<x64|arm64>` and an optional `--runner=<name>` from `process.argv`, and only invoke the
build when the module is executed directly, following the entrypoint idiom already used in
`meta/buildSteamBridgeShims.ts`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GameLib CI/dev machine → third-party GitHub repos | `git clone` of imLinguin/nile, Heroic-Games-Launcher/legendary, Heroic-Games-Launcher/heroic-gogdl at a pinned tag, followed by executing that repo's own build tooling |
| Build script → PyPI | `pip install` of each repo's own declared requirements plus PyInstaller, into a throwaway venv |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.9-03 | Tampering | `buildRunner`'s `git`/`python3`/`pip`/`pyinstaller`/`tar` invocations | mitigate | argv-form `spawn`/`spawnSync` only, never a shell string and never interpolation into a command — mirrors `meta/downloadZig.ts`'s T-24-06 control. Asserted by the `shell: true` grep gate in Task 1. |
| T-34.9-10 | Tampering | Cloning and executing third-party repo build tooling | accept | The trust boundary is UNCHANGED from today: GameLib already vendors and ships the release binaries these same repos produce from these same tags. The clone is pinned to `--branch ${RELEASE_TAGS[runner]} --depth 1`, never a branch head, never `latest`. Recorded rather than mitigated because refusing this trust would mean not shipping the runners at all. |
| T-34.9-SC | Tampering | pip installs (PyPI) inside the build venv | mitigate | No package is chosen by this plan: dependencies come from each cloned repo's own pinned `requirements.txt`/`pyproject.toml` at the pinned tag, and PyInstaller is pinned to the repo's own pin or literally `pyinstaller==6.20.0` — never `latest`. The resolved `python3`/`pyinstaller` versions are recorded in `BUILD-MANIFEST-${arch}.json` for audit. 34.9-RESEARCH.md's Package Legitimacy Audit declares no new package for this phase, and this plan adds none: the `tar` npm dependency the research believed present is absent from `package.json` and is deliberately NOT added — system `tar` is used instead. |
| T-34.9-11 | Elevation of Privilege | `.build-tools/runners-onedir/**` | mitigate | Build output is written under `.build-tools/` only. `public/bin/**` is reserved for bundled runtime binaries (the convention `meta/downloadZig.ts` documents); this script never writes there — plan 34.9-06's downloader is the only writer of `public/bin/{arch}/darwin/{runner}/`. |
</threat_model>
