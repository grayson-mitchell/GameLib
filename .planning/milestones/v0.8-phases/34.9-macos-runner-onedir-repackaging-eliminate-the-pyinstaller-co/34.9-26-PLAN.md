<objective>
Prove, in both directions and against a known-bad input, that plan 34.9-25's conversion actually
converts silent success into loud failure -- per script, and at the `dist:mac` chain level.

Purpose: **this is the step that decides whether the conversion counts.** Plan 34.9-25 rewrote 13
`package.json` scripts from `esbuild --bundle ... meta/X.ts | node -` to
`esbuild --outfile=<cache>.cjs ... && node <cache>.cjs`. That change is an ASSERTION about behaviour
under a failure that has never been exercised against the converted form. This project's hardest-won
standing rule is that **a guard must be proven to FAIL against a known-bad input** -- an assertion
never shown to go red is vacuous. Observing that a healthy script exits 0 proves nothing; that is
precisely the mistake C2-01 describes, one layer up.

The proof is therefore **both directions, per script**:
- **Direction A (load-bearing).** The entry file `meta/X.ts` is made deliberately uncompilable, in
  BOTH failure shapes C2-01 was reproduced against -- a parse error and an unresolvable import.
  `pnpm <script>` must be OBSERVED exiting non-zero, with the emitted `.cjs` still absent from disk.
- **Direction B.** With the entry file restored, `pnpm <script>` exits 0, emits its `.cjs`, and
  actually does its work -- proven by the script's own success output, not by the exit code alone.

And at **chain** level, which no prior artifact covers: with `meta/verifyRunnerBundle.ts` deliberately
uncompilable, `pnpm dist:mac` must ABORT rather than reach `electron-builder`. `34.9-GUARD-PROOF.md`
proved the guard gates `electron-builder` when the guard COMPILES (PASS at log line 457,
electron-builder's banner at 458). Its section 7 states plainly that it does not cover the case where
the guard cannot compile at all. That case is exactly C2-01, and it is what this plan closes.

**Autonomy.** Every step is machine-driven; no human decision is required, so this plan is
`autonomous: true`. Task 3 opens with machine-checkable preconditions (no running dev instance, free
disk space, clean tree) and STOPS rather than proceeding on a failed one -- the single point at which
it returns to the operator. The one genuinely expensive step, a full healthy `pnpm dist:mac` used as
the same-session chain control, is gated on measured free disk space and is recorded as NOT RUN with
its reason if the gate does not clear.

**Transient mutation.** This plan deliberately writes broken files into `meta/*.ts` and restores
them. Those files are NOT in `files_modified` because no committed change to them is intended -- and
that is exactly why the restore is audited by `shasum -a 256` against a pre-injection baseline,
independently, rather than assumed.

Output: `34.9-PIPE-PROOF.md`, a both-direction run record mirroring `34.9-GUARD-PROOF.md`'s
structure, its frontmatter result fields, its disk-evidence-over-self-report discipline, and its
explicit "what this does NOT prove" section.
</objective>

the passing direction if and only if its entry file (a) performs no network I/O, (b) writes no file
