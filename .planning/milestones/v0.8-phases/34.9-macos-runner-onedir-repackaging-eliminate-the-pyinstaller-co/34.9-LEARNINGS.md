## Decisions

### macOS-only onedir, with Linux and Windows explicitly forbidden from following

The spawn tax is not a PyInstaller property, it is a Gatekeeper property: `amfid` runs a per-file
assessment on each extracted file, and onefile's randomly-named `$TMPDIR/_MEIxxxxxx` extraction
path means the assessment cache never hits. Linux and Windows have no equivalent assessment step,
so switching them would buy nothing and cost the bundle growth.

**Rationale:** The mechanism is platform-specific, so the fix must be. Recorded as LOCKED with the
explicit instruction "Do not switch Linux or Windows to onedir." Measured cost accepted up front:
2.2x-3.6x per runner (legendary 30M vs 13M, gogdl 25M vs 11M, nile 29M vs 8.1M), ~100 extra Mach-O
files each for notarization to sign and staple.

**Source:** `34.9-CONTEXT.md`; `34.9-03-SUMMARY.md`

### Verify the archive before it touches disk: in-repo digest, structural entry check, single chmod

`downloadOnedirAsset` checks the digest-missing/sentinel gate **before any `fetch()`** (a
not-yet-published archive costs zero network I/O), buffers the archive wholly in memory via
`arrayBuffer()` rather than reusing `downloadFile()`'s stream-to-disk-then-hash path, runs
`tar -tzf` to validate entry prefixes before `tar -xzf` writes a single file, and applies one
top-level chmod, never a recursive one.

**Rationale:** A digest mismatch then leaves nothing on disk anywhere, not even under
`os.tmpdir()`. The sha256 values are pinned in-repo (`meta/runnersOnedirDigests.json`,
code-reviewed) rather than fetched in the same round trip as the bytes — strictly stronger than
`meta/downloadZig.ts`'s trust-on-first-use control. Recursive chmod would mark ~100 data files
executable.

**Source:** `34.9-06-SUMMARY.md`

### `verify:runner-bundle` reports signature state as DATA and enforces only what is true without certificates

The tool enforces presence, exec bit, file type and a file-count floor; it *reports*
`unsigned` / `adhoc` / `signed:<identity>` / `unknown:<excerpt>` without ever turning that into a
pass/fail judgement. A dedicated test proves an all-unsigned fixture still passes, and one
mandatory mutation is "making unsigned a failure turns the pass case red."

**Rationale:** No Apple Developer credentials are enrolled (D-03/D-04), so a signature-identity
assertion would be unsatisfiable by design. Separating structural integrity (verifiable anywhere,
credential-free) from signing identity keeps the guard honest and portable. The tool also
searches for the first directory ending in `build/bin/${arch}/darwin` rather than assuming a
layout, so it works unmodified against a plain `build/` tree and a packaged `.app`'s
`app.asar.unpacked/` nesting.

**Source:** `34.9-08-SUMMARY.md`; `34.9-PACKAGING-LIMITATIONS.md`

### Fix the shared-outfile race with a cross-platform Node wrapper, not a shell PID suffix, and never with `set -o pipefail`

C3-01's obvious fix — key the outfile by `$$` — was rejected: `package.json` scripts run under
`cmd.exe` on Windows, where `$$` is not a PID. `set -o pipefail` was separately named and forbidden
as not portable across the `sh -c` npm/pnpm uses. The chosen fix, `meta/runTs.cjs`, compiles into a
private `fs.mkdtempSync(path.join(os.tmpdir(), 'gamelib-runts-'))` directory per invocation and
symlinks `<tmpDir>/node_modules` at the real project `node_modules` as a junction.

**Rationale:** Locked decision D-C4-01 required the fix be uniform across all exposed scripts and
portable, not partial and POSIX-only. The junction is a read-only reference to the same immutable
tree every invocation already shares, so it does not reintroduce C3-01 — whose hazard was a shared
**write** target, not concurrent reads.

**Source:** `34.9-29-PLAN.md` (D-C4-01); `34.9-25-PLAN.md` (D-C3-02); `34.9-29-SUMMARY.md`

## Lessons

### `code_review_gate` runs AFTER the reconciliation sweep, and writes to a fixed path that silently overwrites

`/gsd-execute-phase` orders its gates: run all waves, THEN `code_review_gate`, THEN
`regression_gate`, THEN `verify_phase_goal`. A phase's reconciliation sweep IS its last wave, so it
always runs before the review whose findings it is supposed to sweep — the sweep is structurally
incapable of seeing a file that has not been written yet. This phase hit the shape four times:
CR-01 (missed by 34.9-17), C2-01..08 (missed by cycle 2), C3-01..03 (missed by 34.9-28, a plan
written specifically to stop this — 28-SUMMARY.md mtime 19:32, REVIEW-CYCLE3.md mtime 19:45), and
C4-01..05. Separately, the gate writes `{phase_dir}/{padded_phase}-REVIEW.md` every time with no
versioning, append, or warning.

**Impact:** The remedy is ordering, not diligence — "no amount of care in a wave-scheduled task can
inspect a file `code_review_gate` has not written yet." Gap cycle 4 broke it with an
`autonomous: false` plan ending in a blocking checkpoint that carries the sweep past the review
gate. And the five-file review convention only ever held because each new file was moved by hand
immediately; a cycle that forgets loses the prior review permanently (`git show HEAD:<path> >
<path>` is the only recovery, and only before the next commit).

**Source:** `deferred-items.md` ("Closure protocol"); `34.9-33-SUMMARY.md`; `34.9-33-PLAN.md`
(D-C4-04)

### `esbuild ... | node -` reports success when the compile fails

npm/pnpm run scripts via `sh -c`, which does not set `pipefail`; a POSIX pipeline's exit status is
its LAST command's. When `esbuild` fails (bad import, syntax error, moved file), `node -` receives
empty stdin, executes nothing, and exits 0 — the pipeline reports success. Proven against the
repo's real esbuild in both failure shapes, with a control (guard failing on its own merits)
correctly exiting 1.

**Impact:** `dist:mac` proceeded straight to `electron-builder` with the framework-integrity guard
silently skipped. The most severe instance was not the guard: `build-steam-bridge` used the same
idiom and would ship a `.app` with missing Steam bridge shims — swallowed application code, not
merely a stale `dist/` artifact. Related trap in the same family: a bare `| node` (no dash) crashes
on any appended CLI argument before ever reading stdin, and `| node --` makes node treat the next
positional token as a script filename to `require()` (`MODULE_NOT_FOUND`) — that one recurred twice
in this phase from plan text.

**Source:** `34.9-REVIEW-CYCLE2.md` (C2-01, C2-02); `34.9-01-SUMMARY.md`; `34.9-08-SUMMARY.md`;
`34.9-23-SUMMARY.md`

### Replacing the pipe with a script-name-keyed shared outfile reintroduced the same defect class one layer down

The replacement wrote every invocation's output to `node_modules/.cache/<script-name>.cjs` — keyed
only by script name, never by process, invocation, or argument. Two concurrent invocations of the
same script cross-contaminate: one process's `node` reads the other's freshly compiled code. 60/60
paired trials cross-contaminated, 0 crashes, exit 0 throughout (esbuild's write is atomic enough
that a torn read never occurred, so the failure mode is silent wrong-content execution).

**Impact:** Literally the "reports success while doing something other than what was asked" class
the gap cycle existed to close. Not reachable through CI (the x64/arm64 matrix runs each leg on its
own host) but reachable by exactly the local workaround this phase's own missing x64 CI leg forces
developers into: `pnpm build-runners-onedir --arch=x64` and `--arch=arm64` in two terminals.

**Source:** `34.9-REVIEW-CYCLE3.md` (C3-01); `34.9-VERIFICATION.md`

### A pin asserting rationale prose cannot detect a fact drifting, and on-disk residue launders the drift

The `IN-01/IN-02` doc-comment jest pins assert *prose about why `__dirname` is avoided*, not the
path literal. When plan 34.9-29 changed the execution mechanism a second time, the suite stayed
green while 12 `meta/*.ts` comments became factually wrong. Compounding it: stale `.cjs` files from

### A plan-prescribed implementation carried three defects that only execution could find

Plan 34.9-29 specified `meta/runTs.cjs`'s shape. Three prescriptions were wrong, each proven
empirically rather than by reading: (1) `try { ... process.exit(...) } finally { fs.rmSync(...) }`
never cleans up — Node terminates on `process.exit()` before the stack unwinds far enough to run a
pending `finally` (`node -e "try { process.exit(3) } finally { console.log('finally ran') }"`
prints nothing). (2) `spawnSync(process.execPath, [require.resolve('esbuild/bin/esbuild'), ...])`
yields `SyntaxError: Invalid or unexpected token`, because esbuild's own `install.js` postinstall
overwrites `bin/esbuild` with the native platform binary. (3) Compiling into `os.tmpdir()` breaks
runtime `require.resolve('<pkg>/<subpath>')`, because Node's CJS resolution walks up parent
directories from the calling file's own location looking for `node_modules` — the retired
`node_modules/.cache/<name>.cjs` path satisfied that walk by construction.

**Impact:** Defect (2) would have broken all 15 wrapped scripts, not two. Defect (3) hit exactly the
two scripts that call `require.resolve` to locate a CLI tool's on-disk path for spawning
(`meta/updaterSigningKey.ts:95`, `meta/buildSidecarSea.ts:145,156`), found by census
(`grep -rln "require\.resolve(" meta/*.ts`), and was fixed by symlinking a `node_modules` junction
into the tmpdir.

**Source:** `34.9-29-SUMMARY.md`

### `__dirname` is `.` under `node -`, and the fix for the false-pass defect reproduced the false-pass defect

`meta/cleanDistMac.ts`'s default `distDir` was `path.join(__dirname, '..', 'dist')`. Under
`esbuild --bundle ... | node -` (stdin), node sets `__dirname` to `.` — i.e. `process.cwd()` — so
the default resolved to `../dist`, one directory above the repo root, found nothing, and returned
`{removed: [], kept: []}` while printing success.

**Impact:** F-34.9-02 is precisely "a step that did nothing reads as success." Its own fix
reproduced that shape. The test suite could not have caught it, because every test passes an
explicit `distDir`. The rule adopted: `meta/` CLI scripts default paths off `process.cwd()` or a
repo-root-relative literal, never `__dirname`.

**Source:** `34.9-14-SUMMARY.md`

### A file-to-directory transition poisons every non-cleaned output cache independently

Switching the darwin runners from flat single files to directory trees broke three separate output
caches, and fixing one only moved the failure down a layer: `build/bin` (vite, `emptyOutDir:
false`) → `EEXIST … mkdir`; `src-tauri/target/debug/_up_` → `Not a directory (os error 20)`;

**Impact:** Each error names its own toolchain's internals and never the stale file, so none of them

not verifying the one the toolchain will touch.

### PyInstaller's static discovery of a package's own compiled C extension requires an editable install

gogdl built with exit 0 and an executable binary, then crashed at `--version` with
`ModuleNotFoundError: No module named 'gogdl.xdelta3'`. PyInstaller's own
`build/gogdl/warn-gogdl.txt` recorded `missing module named 'gogdl.xdelta3'` during analysis even
though the compiled `.so` was in site-packages. Only `pip install -e .` — what upstream CI actually
uses — resolves it. Reproduced on Python 3.14 and 3.11, so it is not a version artifact.

**Impact:** A successful build with a runnable binary is not evidence the binary works. Two adjacent
traps from the same builds: `git clone --depth 1` leaves heroic-gogdl's pinned `xdelta3` submodule
empty (`xdelta3/xdelta3.h file not found`), and `--shallow-submodules` is unsafe because a pinned
submodule commit is not guaranteed to be the submodule's branch tip; and ignoring a workflow's
`working-directory:` makes legendary's build fail with `Script file 'cli.py' does not exist`.

**Source:** `34.9-03-SUMMARY.md`

## Patterns

### A mandatory positive control with its own PASS bar, its own `Observed:` field, and a decision rule fixed in advance

`34.9-WRAPPER-PROOF.md` Direction C is declared **INVALID — not PASS — without its control**: zero
cross-contamination is exactly what a broken harness would also report. The control ran the
identical 60-trial procedure against the RETIRED idiom in the same session on the same hardware,
BEFORE the new-idiom trials. Control: 60/60 trials cross-contaminated (29 A-ran-B, 31 B-ran-A, 0
both, 0 neither, `bothSawOwn=0`), matching the reviewer's 60/60 and the verifier's independent
20/20. New idiom: 0/120 cross-contamination, `bothSawOwn=60`.

**When to use:** Any time a result is a zero or an absence. The decision rule is written in advance:
a control that does not reproduce at the previously measured rate makes the direction INVALID
regardless of what the clean run showed, and the clean result is recorded as UNPROVEN, not PASS —
explicitly never "the fix worked even better than expected."

**Source:** `34.9-WRAPPER-PROOF.md` §6; `34.9-31-SUMMARY.md`; `34.9-32-SUMMARY.md`

### Prove the checker red before trusting it green

Three variants used in this phase. (1) Mutation tables: apply each mutation to the real file, run
the real suite, confirm RED naming the specific test, revert, reconfirm GREEN, verify byte-identical
`git diff --stat` — the sweep tool's four mutations each targeted a distinct predicate arm (`NO-ROW`,
`ITEM-NOT-STRUCTURED`, `FIXED-NOT-CONFIRMED-OUTSIDE-PLANNING`, `ITEM-DOES-NOT-NAME-FINDING`).
(2) Known-bad fixtures: the FIXED-row polarity check was proven to score
`FIXED-CONFIRMATION-DENIES-FIX` (exit 1) against an otherwise-identical row and to pass (exit 0)
when only the polarity was flipped. (3) A constructed failing specimen: to prove a
cleanup-on-exit check discriminates, launch a busy-wait specimen and `SIGKILL` it mid-run — no
process can catch SIGKILL, so it reliably leaks the artifact the check must flag, without mutating
the code under test.

**When to use:** Every gate predicate. Verifying a check exists in source is not verifying it fires.
Two traps this phase hit while doing it: a whole-tree `cp -RL` dereferenced two symlinks at once so
one mutation went vacuously GREEN (fix: apply the corruption surgically to one entry), and a
grep-pinned message literal split across two `+`-joined source lines undercounts because `grep`
matches per line.

**Source:** `34.9-28-SUMMARY.md`; `34.9-30-SUMMARY.md`; `34.9-31-SUMMARY.md`; `34.9-13-SUMMARY.md`;
`34.9-19-SUMMARY.md`

### Census by predicate, then publish explicit set-differences against every prior list

Plan 34.9-23's census parses `package.json`'s `scripts` object programmatically rather than grepping
a line window, then publishes four labelled differences — `P minus R`, `P minus D`, `R minus P`,
`D minus P` — each as an explicit list with a count, with any member of `P minus D` getting its own
named subsection explaining why the earlier scoping passes missed it.

**When to use:** Any remediation whose scope was estimated before it was measured. The plan's own
rule was "if the census disagrees with this paragraph, the census wins." Corollary from the next
cycle: scope by the defect's own predicate, never by a fixed list, and re-derive at execution time.

**Source:** `34.9-23-SUMMARY.md`; `34.9-29-SUMMARY.md`; `34.9-23-PLAN.md`

### A cycle-agnostic sweep tool that discovers its own inputs and derives its checklist live

### Author/runner separation for every live gate and proof contract

The plan that authors a gate contract is FORBIDDEN from running any item in it, starting any
harness, or writing any value into `verdict` / `run_date` / `items_passed` / `items_failed`; a
separate plan is the sole writer of results. Applied four times (34.9-10 / 34.9-11; 34.9-15 /
34.9-16; 34.9-20 / 34.9-21; 34.9-31 / 34.9-32). The authoring plan may run at most ONE bounded

**When to use:** Standing project discipline, referenced to
`.claude/skills/spike-findings-gamelib/references/live-gate-contract-authoring.md` decision D-E.
Paired rules from the same contracts: "a green test suite never closes this gate" (`test:ci` is a

reviewed 4 pairs and found 1. The 34.9-31 hazard: the positive control's shared throwaway path must
be deleted immediately after its final trial, or a later direction could read a stale old-idiom
artifact at a path no other direction checks.

**When to use:** Any multi-direction proof contract. Two individually-correct criteria can be
jointly defective, and item-by-item review cannot see it. The same phase produced a live instance in
its own plans: 34.9-26's Task 1 was required to quote a sentinel literal as documentation while
Task 3 required `grep -c '(UNFILLED' == 0` with no carve-out.

**Source:** `34.9-20-SUMMARY.md`; `34.9-31-SUMMARY.md`; `34.9-26-SUMMARY.md`

### Ledger discipline: four required fields, machine-enforced, and amend in place rather than re-tick

Every `deferred-items.md` entry carries a date, a **"Blocker (the mechanism, not a summary)"**
section, a named precondition, and an `OWNER:` — and the sweep tool fails any DEFERRED row whose
`### N.` target section lacks one of the three. FIXED rows must cite a source symbol, a
`package.json` script string, or a live run — never a SUMMARY's own claim, enforced by the
`FIXED-NOT-CONFIRMED-OUTSIDE-PLANNING` arm. When a later fix disagrees with an item's recorded
numbers, the original stands: item 24's census count of twelve was left in place even though a
re-census at fix time found thirteen.

**When to use:** Every descope and every closure. The header states the intent — "Descoped is not
done, and it is not forgotten" — and machine-enforcing the fields is what keeps it from being a
slogan. The count an item opened with is evidence about what was known then; correcting it silently
destroys that.

**Source:** `deferred-items.md` (header, item 24 closure note); `34.9-28-SUMMARY.md`;
`34.9-VERIFICATION.md`

### A harness that voids its own run rather than reporting a number

`34.9-MEASUREMENT.md` opens with **"RUN INVALID (harness validity anchor failed)"**. The harness
checks whether its own onefile control reproduced the cold condition; at 7.91s against a 10s
threshold the anchor failed, so no ratio was reported as PASS or FAIL even though six real raw
samples exist. The numbers are printed "for completeness only" with an explicit ban on citing them
downstream in PR bodies or ROADMAP claims.

**When to use:** Any measurement whose validity depends on reproducing a baseline condition. Build
the anchor into the harness and let it void the run — the alternative here would have been a
17.6x/3.0x/2.3x table, exactly the fabricated-confidence outcome threat T-34.9-15 exists to catch.
Static facts unaffected by the confound (bundle sizes via `du`) were still reported.

**Source:** `34.9-MEASUREMENT.md` §3-§5; `34.9-03-SUMMARY.md`

### A green 235-suite / 4598-test run never saw the phase's blocking defect

F-34.9-01 — vite's `copyDir` has no symlink branch (`statSync` follows links), so `Versions/Current`

framework and no symlinks, so the path was unreachable.

### `du -sk` reported a 24% size gap that did not exist

Verifying the symlink-preservation fix, raw `du -sk` showed source 85,244 KB vs built 105,584 KB
even though all 12 symlinks were correctly restored and every `readlink` target matched.

**Context:** macOS APFS clone / copy-on-write block sharing — the pre-existing `public/` copies
report fewer *allocated* blocks than `copyFileSync`'s freshly written `build/` copies of the same
bytes. Apparent size (`du -Ak`) is 254,544 KB on both sides, a 0.0% difference. Any size comparison
across an APFS copy boundary must use apparent size.

**Source:** `34.9-12-SUMMARY.md`

### Front-loading the review caught a defect in the gate CONTRACT, not just the code

Cycle 4's review ran before `34.9-WRAPPER-PROOF.md` was executed and found C4-01: `meta/runTs.cjs`
installed no signal handlers, so `SIGTERM` to the wrapper killed the parent at default disposition
while the `spawnSync`-launched child kept running unsupervised and the tmpdir survived. Direction B
row 11 of the unrun proof prescribes exactly `SIGTERM` (never `SIGKILL`) to abort a destructive step.

**Context:** Under the old ordering the review would have landed after the proof, and an operator
would have executed a contract whose abort methodology silently does not abort — then scored
"vendored runner tree byte-unchanged" as PASS. Recorded as value unrecoverable afterwards: a review
that runs before an unrun gate can invalidate the contract, not just the code.

**Source:** `34.9-REVIEW-CYCLE4.md` (C4-01); `34.9-VERIFICATION.md`

### The signal-handler fix reintroduced a narrower version of the same leak

C5-01: between `fs.mkdtempSync` (tmpdir created, line 119) and the loop installing the
`SIGTERM`/`SIGINT`/`SIGHUP` handlers (line 193), no listener exists — and a signal in that window
terminates the process via OS default disposition without emitting `'exit'`, so the
`process.on('exit', cleanup)` registered at line 142 (itself inside the window) never runs.

**Context:** Reproduced by splicing an 800ms busy-wait after the real `mkdtempSync` in a
byte-identical probe copy: `SIGTERM` at 200ms leaked the tmpdir while exiting a plausible-looking
`143`; the same probe signalled at 1200ms cleaned up correctly — a non-vacuity control proving the
leak is specific to the window. Five attempts against the unmodified file all cleaned up, so the
shipped window is real but sub-practical to hit.

**Source:** `34.9-REVIEW-CYCLE5.md` (C5-01); `34.9-33-SUMMARY.md`

### A documented security boundary was dead code on its only call path

`meta/cleanDistMac.ts`'s containment throw is documented as T-34.9G-09 enforcement, but every
`entry.name` reaching it comes from `readdirSync(distDir, { withFileTypes: true })` — real directory
entries can never contain a path separator or be `..`/`.`, so `path.resolve(distDir, entry.name)`
can never escape. The branch is unreachable as wired, and untested.

**Context:** Dispositioned by downgrading the comment to defense-in-depth against
currently-unreachable input rather than by exposing an internal seam to test it — with the explicit
note that if the module ever accepts externally-supplied names (a `--only` filter), the missing
coverage means a regression there would not be caught. Adjacent finding of the same character:
`git ls-files public/bin/arm64/darwin` returns 0 while `find … -type l` returns 12 — the vendored
darwin trees are git-ignored, so Guard A's failing direction is unreachable from any fresh checkout.

**Source:** `34.9-REVIEW.md` (IN-02); `34.9-PLAN-OUTLINE.md`; `34.9-18-SUMMARY.md`
