# Phase 34.9 Plan 08: Built-Artifact Runner Bundle Verifier Summary

**`meta/verifyRunnerBundle.ts` inspects a BUILT bundle's bytes -- not a packaging step's exit code -- to enforce that legendary/gogdl/nile are each present, executable, real Mach-O, and hold more than 20 files, while reporting (never enforcing) every nested Mach-O's codesign state, exposed via `pnpm verify:runner-bundle <root>` and pinned by 8 fixture-driven tests with all 4 plan-mandated mutation proofs performed live.**

## Accomplishments
- `inspectRunnerTree(root, arch)`: locates `build/bin/${arch}/darwin` by walking `root` (never a fixed-prefix assumption -- works unmodified against both a plain `build/` tree and a packaged Electron `.app`'s `Contents/Resources/app.asar.unpacked/` nesting), then for each of `legendary`/`gogdl`/`nile` returns the resolved `{runner}/{runner}` path, existence, exec-bit state, Mach-O-ness, total file count and Mach-O count under that runner's own subtree, and a `{path, signature}` array for every Mach-O found in it. Throws, naming both `root` and `arch`, when no matching directory exists anywhere under `root`.
- `summarise(results)`: enforces ONLY presence, exec bit, Mach-O-ness, and a `>20`-file floor per runner (catches a onefile binary smuggled under a directory name). Never fails on signature state.
- `getSignatureState`: argv-form `spawnSync('codesign', ['-dv', path])`, parsing stderr into `unsigned` / `adhoc` / `signed:<first authority>` / `unknown:<stderr excerpt>` -- always data, never a verdict.
- `isMachO`: magic-byte sniff (first 4 bytes, both endiannesses against the Mach-O magic set, mirroring `meta/buildRunnersOnedir.ts`'s existing `isMachO`), falling back to argv-form `spawnSync('file', ['-b', path])` only when the read itself is inconclusive.
- CLI: `pnpm verify:runner-bundle <root> [--arch=<x64|arm64>] [--json]`, exits 0/1 on `summary.ok`, prints a human table plus per-file signature lines, or the raw JSON structure with `--json`.
- `meta/__tests__/verifyRunnerBundle.test.ts`: 8 tests, one per plan `<behavior>` row -- pass case, missing runner, non-executable, not-Mach-O, smuggled onefile (file-count floor), tree-not-found, signature-reporting-is-not-enforcement, and comet/win32 out of scope. Every fixture is a real `fs.mkdtempSync(os.tmpdir())` tree torn down in `afterEach`; `codesign`/`file` are invoked for real, no mocking (this module's own interfaces note both tools are verified present on this machine and on macOS CI runners).
- All 4 plan-mandated mutation proofs performed LIVE against the real files, each confirmed RED then reverted and confirmed GREEN: (a) removing the exec-bit check -> non-executable case RED; (b) removing the file-count floor -> smuggled-onefile case RED; (c) making `unsigned` a failure -> 5 tests RED including the pass case and the scope case, proving reporting is not enforcement; (d) adding `comet` to the inspected runner list -> 2 tests RED (pass case returned 4 results instead of 3; the scope test's own manually-created `comet` file collided with the fixture builder's now-created `comet` directory).
- `pnpm run verify:runner-bundle -- <path> --arch=arm64` live-verified end to end against both a nonexistent root (exit 1, message names the root and the arch) and a real synthetic pass-case fixture (exit 0, correct table output, and `--json` output with `signature: "unsigned"` on every Mach-O entry).

- `npx tsc --noEmit -p tsconfig.json`: exit 0, no errors.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plan's literal `| node --` script form does not pipe stdin to the script**
- **Found during:** Task 2, live-verifying `pnpm run verify:runner-bundle -- /tmp/does-not-exist --arch=arm64` before committing
- **Issue:** The plan's `<action>` text specifies `"verify:runner-bundle": "esbuild --bundle --platform=node --target=node21 meta/verifyRunnerBundle.ts | node --"`, with the stated rationale "so the root path and flags reach the script rather than node." In practice `node --` only terminates Node's own option parsing -- it does not tell Node to read the script from stdin. With no `-` (the actual stdin sentinel) and no script filename, Node instead resolves the first positional argument after `--` as the script to run and tries to `require()` it as a file, producing `Cannot find module '<root-path>'` before the tool ever executes.
- **Fix:** Used `| node -` instead -- the single-dash stdin sentinel, which is the exact form this repo's own `build-runners-onedir` script already uses for the same esbuild-pipe-to-node pattern with positional CLI arguments.
- **Files modified:** `package.json`
- **Verification:** Live-ran both forms directly (`node --` reproduced the `MODULE_NOT_FOUND` failure; `node -` correctly reached the script and printed `verifyRunnerBundle: could not find a "build/bin/arm64/darwin" directory under root "..."`), then confirmed the full `pnpm run verify:runner-bundle -- <path> --arch=arm64` invocation against both a nonexistent root (exit 1) and a real fixture (exit 0, correct table + `--json` output).
- **Committed in:** `83d9ee9dd` (Task 2 commit)
