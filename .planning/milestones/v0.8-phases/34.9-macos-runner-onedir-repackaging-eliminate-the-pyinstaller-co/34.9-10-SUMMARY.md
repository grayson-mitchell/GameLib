### Auto-fixed Issues

**1. [Rule 1 - Bug in the plan's own item text] Item 1's "on startup" premise is false under the
Tauri sidecar**
- **Found during:** Task 1, while tracing item 1's gesture to a real caller before writing the
  gate's exact grep literals (per the mandatory "a gate check must be run against a filled
  specimen at authoring time" discipline).
- **Issue:** The plan's `<action>` text specified item 1 as "On startup the four version probes
  run." `src/backend/sidecar/bootstrap.ts:84` (`initHeadless as initLogger`) confirms the sidecar
  calls `initHeadless()`, which `src/backend/logger/index.ts`'s own doc comment states explicitly
  skips "the one-time system-info dump" `init()` performs. No automatic call path exists under
  Tauri dev; the four version-probe IPC channels are called only from three Settings components
  (`AltLegendaryBin.tsx`, `AltGOGdlBin.tsx`, `AltNileBin.tsx`), confirmed by grepping every
  frontend caller.
- **Fix:** Retargeted item 1's gesture to a Settings > Advanced Settings page visit (the real
  mount point for all three components), and named the correct two-sink evidence shape (path
  resolution in `gamelib.log`, version text in the per-runner log or the UI, since `gamelib.log`'s
  own "Running command:" line never carries the actual `--version` stdout text).
- **Files modified:** `34.9-LIVE-GATE.md` (written correctly from the start; no separate commit
  needed since Task 1 and Task 2 were committed together, see Task Commits above).
- **Verification:** Traced `AltLegendaryBin.tsx`/`AltGOGdlBin.tsx`/`AltNileBin.tsx`'s render
  location to `AdvancedSettings/index.tsx`; confirmed `bootstrap.ts`'s `initHeadless` import and
  `main.ts`'s real `init` import as the two divergent entrypoints; grep-confirmed no other
  frontend caller of the three version-probe channels exists.
- **Committed in:** `4b5ffebf8`

**2. [Rule 1 - Bug in the plan's own item text] Item 3's click-based timing would measure human
typing time, not runner-spawn latency**
- **Found during:** Task 1, while tracing item 3's "same shape as item 2" instruction against
  GOG's real login-code-capture mechanism.
- **Issue:** `useTauriOAuthLogin.ts:45-50`'s own comment confirms GOG's login URL is a constant --
  unlike nile, no runner spawn is needed to construct it. The first `gogdl auth --code` call
  (`gog/user.ts:82-88`) fires only after the operator has manually completed GOG's real login
  form and the OAuth redirect delivers a code. A click-to-completion interval (item 2's shape for
  nile) would therefore be dominated by uncontrolled human typing time, making a "PASS when under
  2s" bar fail on every real login attempt regardless of the onedir win it exists to demonstrate.
- **Fix:** Retargeted the measured interval to start at
  `[oauthLoginCapture] runner=gog status=captured` (`oauthLoginCapture.ts:235-238`), the last
  purely-backend event immediately preceding the gogdl spawn, isolating the same quantity item 2
  measures for nile.
- **Files modified:** `34.9-LIVE-GATE.md`.
- **Verification:** Read `oauthLoginCapture.ts`'s `settle()` function to confirm the exact log
  line and its timing relative to `GOGUser.login()`'s own call; confirmed the literal's sink
  (`LogPrefix.Backend`, `gamelib.log`) and grep-tested it against both a matching and a
  wrong-runner specimen.
- **Committed in:** `4b5ffebf8`
