## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest (ts-jest) via the root multi-project config. **Two projects are in scope this phase**: `Meta` (`meta/__tests__/**`) and `Backend` (`src/backend/__tests__/**`). **Rust is NOT in scope** — no plan edits `src-tauri/src/**`; plan 34.9-07 edits only `src-tauri/tauri.conf.json`, which is JSON config, so `cargo check` is not required. |
| **Config files** | `jest.config.js` (root, `projects: [src/backend, src/common, src/frontend, src/preload, meta]`) · `meta/jest.config.js` (displayName `Meta`, `roots: ['<rootDir>/meta']`) · `src/backend/jest.config.js` (displayName `Backend`, `setupFiles: ['<rootDir>/src/backend/jest.setupContainment.ts']`) |
| **Quick run command** | `npx jest meta/__tests__/<file>.test.ts` or `npx jest src/backend/__tests__/<file>.test.ts` |
| **Full suite command** | `npm run test:ci` (`jest --runInBand --silent`) |
| **Estimated runtime** | full suite several minutes; targeted run <15s |

**⚠ Containment gap — the `Meta` project has NO containment setup file.**
`src/backend/jest.setupContainment.ts` redirects HOME/APPDATA/XDG for every **Backend** test file
automatically (structural since the Phase 34.2 gap cycle 4). `meta/jest.config.js` declares **no
`setupFiles` at all**. This phase adds two new `Meta` suites — `downloadHelperBinaries.test.ts`
(plan 34.9-06) and `verifyRunnerBundle.test.ts` (plan 34.9-08) — whose subjects **write to
`public/bin/**`, spawn `tar`, and perform network `fetch`** by design.

This repo has already paid for this defect class twice: `tests-clobbering-real-steam-store`
(a `requireActual` electron-store reaching the real app-support dir) and the `bootstrap.test.ts`
run that renamed the developer's real `~/Library/Logs/GameLib/gamelib.log` three times. Neither was
in the `Meta` project, and neither would have been caught by a Backend-only containment file.

**Binding obligation for plans 34.9-06 and 34.9-08:** every new `Meta` test MUST mock `fetch`,
`node:child_process`'s `spawn` and the `node:fs/promises` write surface, and MUST build any fixture
under `fs.mkdtempSync(os.tmpdir())` with removal in `afterEach`. `git status --porcelain public/bin`
being empty after a test run is an explicit acceptance criterion in both plans — that check is the
substitute for the containment file the `Meta` project does not have. Do not weaken it, and do not
let a suite reach the real `public/bin` on the argument that it "only reads".

**No CI coverage for the new workflow's own execution.** `build-runners-onedir-macos.yml` (plan
34.9-04) is verified structurally by `runnersOnedirWorkflow.test.ts` and behaviourally only by a
real dispatch in plan 34.9-09. A green structural test does not mean the workflow runs.

## Sampling Rate

- **After every task commit:** targeted `npx jest <changed-file>.test.ts`
- **After every plan wave:** `npm run test:ci` + `npx tsc --noEmit`
- **Before `/gsd-verify-work`:** full suite green **AND** the REQ-34.9-11 live gate passed
  (**blocking** per D-08 — no advisory mode, no partial pass, no pre-authorized override)
- **Max feedback latency:** <15s targeted; full suite several minutes

**Mutation proof is mandatory, not optional.** Every plan in this phase carries explicit mutation
steps in its acceptance criteria (revert the control, watch the test go RED, restore). This is the
phase's answer to the standing project lesson that a green suite beat a live gate three times: a
test that stays GREEN when its control is removed was never testing the control.

### Explicitly NOT proven by this phase

Recorded here so their absence reads as a decision rather than an oversight:

- **Tauri-PACKAGED runner resolution** — blocked on `R-34.5-G1-PKG` (Phase 34.5's deferred item 12).
  `electronStub.app.isPackaged` is hardcoded `false` under the sidecar, so `publicDir` always
  appends `'public'` to a resource root with no such child. The residual **pre-dates this phase** and
  already breaks packaged-Tauri resolution for today's single-file runners identically.
- **Real-certificate signing and notarization** — D-03/D-04; no Apple Developer credentials are
  enrolled and every real macOS CI run to date shipped unsigned. The only proxy obtainable is
  `codesign --verify` on an adhoc-signed bundle plus a per-file signature-state report. No task may
  report "notarization passed" without a real `notarytool submit` transcript.
- **The macOS x64 leg**, if plan 34.9-09 records outcome B or C — CI-only by construction.
- **Windows and Linux behaviour** — unchanged by this phase by design, and deliberately not
  exercised. The packaging tests pin their globs FLAT as a negative guard.
