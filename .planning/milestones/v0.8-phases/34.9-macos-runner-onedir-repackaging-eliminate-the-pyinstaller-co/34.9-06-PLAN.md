<objective>
Teach the vendoring script to fetch, verify and extract the macOS onedir archives from the GameLib
rolling release, while leaving every other platform, runner and code path byte-for-byte as it is.

Purpose: this is where three separate hazards land at once — the single-repo-per-runner assumption
breaks (34.9-RESEARCH.md Pitfall 5), the `.release_tags` freshness marker cannot see a layout change
(Pitfall 6), and the script becomes the point where GameLib's own CI-built executables enter a
developer's tree with, today, no integrity check whatsoever.

Output: an extended `downloadHelperBinaries.ts`, an in-repo digest pin, and the first test file this
script has ever had.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GameLib GitHub Releases → developer/CI filesystem | executable runner archives cross into `public/bin`, are bundled into the shipped app, and are later spawned as child processes |
| archive contents → filesystem layout | `tar` extraction writes paths chosen by the archive, not by this code |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.9-01 | Tampering | darwin onedir archives fetched from the rolling release | mitigate | sha256 verified in `downloadOnedirAsset` against a digest committed IN THIS REPOSITORY (`meta/runnersOnedirDigests.json`) before any extraction. This is strictly stronger than `meta/downloadZig.ts`'s T-24-SC control, which fetches its shasum in the same network round-trip as the bytes: here a compromised GitHub Release cannot supply a matching digest, because the digest is under code review in git. Closes the gap that `downloadZig.ts` calls out as "the existing UNCHECKSUMMED meta/downloadHelperBinaries.ts precedent, which verifies nothing about the bytes it downloads" — for the darwin runner path. |
| T-34.9-02 | Tampering / Elevation of Privilege | `tar` extraction path traversal | mitigate | Every entry is listed with `tar -tzf` and required to begin with `${binaryName}/` before extraction; absolute paths and any path containing `..` throw. Extraction is scoped to `public/bin/${arch}/darwin` and runs only after the digest check has already passed. |
| T-34.9-03 | Tampering | `tar` invocations | mitigate | argv-form `spawn` with an explicit argument array and no `shell` option, mirroring `meta/downloadZig.ts` (T-24-06). Asserted behaviourally against the mocked spawn's recorded arguments, not by grepping source. |
| T-34.9-04 | Elevation of Privilege | permission widening on extraction | mitigate | Modes are restored from the archive, which CI creates with correct modes. Only the single top-level `{runner}/{runner}` entry is chmodded, and only when its exec bit is missing. No recursive chmod exists — marking ~100 data files executable would both widen the attack surface and enlarge what notarization must assess. |
| T-34.9-05 | Spoofing | source repository for darwin assets | mitigate | `GAMELIB_RUNNERS_REPO` is a hardcoded literal, deliberately not derived from `package.json`'s `repository` field, which still points at Heroic upstream — the same trap `electron-builder.yml`'s `publish:` block documents. Pinned by a test. |
| T-34.9-21 | Denial of Service (fail-safe) | placeholder digests | mitigate | The `PENDING-CI-PUBLISH` sentinel throws with a message naming the file and plan 34.9-09 rather than silently skipping verification. A loud, actionable failure is the safe outcome; there is no "verify if a digest happens to be present" path. |
| T-34.9-SC | Tampering | package installs | mitigate | No package is installed. 34.9-RESEARCH.md's recommendation of the `tar` npm package rests on a falsified premise (it is absent from `package.json`); system `tar` is used instead, so this phase's npm dependency set is unchanged and no legitimacy checkpoint is owed. |
</threat_model>
