## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `meta/buildRunnersOnedir.ts`'s entrypoint guard auto-ran on import, blocking `download-helper-binaries`'s first-ever real invocation**
- **Found during:** Task 2, first live run of `pnpm download-helper-binaries` (deliberately deferred by plan 34.9-06 to this plan)
- **Issue:** `downloadHelperBinaries.ts` does `import { archiveName } from './buildRunnersOnedir'`. esbuild bundles both into one script executed via `node`. `buildRunnersOnedir.ts`'s own `if (!process.env.JEST_WORKER_ID) { main() }` guard cannot distinguish "I am the invoked script" from "I am a bundled dependency of the invoked script" once bundled -- it fired regardless, calling `main()`, which requires `--arch=` (never supplied by `download-helper-binaries`, which takes no CLI args at all), throwing `Missing required --arch=<x64|arm64> argument` and `process.exit(1)`-ing before `downloadHelperBinaries.ts`'s own logic ran at all.
- **Fix:** Guard now also requires `--arch=` to be present in `process.argv` before auto-invoking `main()`. Verified this is a no-op for the real, legitimate CI invocation (`pnpm build-runners-onedir --arch=${{ matrix.arch }}`, `.github/workflows/build-runners-onedir-macos.yml:107`, always supplies it).
- **Files modified:** `meta/buildRunnersOnedir.ts`
- **Verification:** `npx tsc --noEmit` clean; `npx jest meta/__tests__/buildRunnersOnedir.test.ts meta/__tests__/downloadHelperBinaries.test.ts` 69/69 passing; `npm run test:ci` 235/235 suites, 4598/4598 tests, exit 0; live-reran `pnpm download-helper-binaries` twice afterward, both times reaching (and correctly throwing on) the darwin sentinel digest instead of crashing on the unrelated `--arch` error.
- **Committed in:** `5c84a2ba5` (Task 2 commit)

**2. [Self-correction, not a plan deviation] Reverted a `__darwin_layout` marker write that made an unverified checkout falsely report fresh**
- **Found during:** Task 2, immediately after the fact -- re-running `pnpm download-helper-binaries` printed `Nothing to download, binaries are up-to-date` instead of the expected sentinel throw
- **Issue:** This executor had written `public/bin/.release_tags`'s `__darwin_layout` key (via the project's own exported `darwinLayoutMarker()`) to satisfy a literal reading of one acceptance criterion. Since the underlying digests are still sentinels and the arm64 tree on disk was staged manually (not through the verified download path), this made the freshness marker lie about verification having happened -- exactly the silent-skip failure mode T-34.9-21 exists to prevent.
- **Fix:** Restored `public/bin/.release_tags` to its pre-34.9 five-key form (no `__darwin_layout` key). Reconfirmed the real sentinel throw afterward.
- **Files modified:** `public/bin/.release_tags` (untracked, gitignored -- no git diff either way)
- **Verification:** `pnpm download-helper-binaries` re-run after the revert reproduced the identical sentinel-throw transcript; `git status --porcelain public/bin` confirmed empty throughout.
- **Not committed:** this file is gitignored and was never staged.
