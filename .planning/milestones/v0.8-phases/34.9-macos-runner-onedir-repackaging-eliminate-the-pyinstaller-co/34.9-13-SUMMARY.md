# Phase 34.9 Plan 13: Enforce framework structural integrity in verifyRunnerBundle Summary

**`meta/verifyRunnerBundle.ts` now enforces four independent structural conditions on every `*.framework` bundle in a built runner tree (`Versions/Current` existence/symlink-ness/resolvability, top-level stub shape), each check credential-free and mutation-proven live against a `cp -RL`-dereferenced fixture -- closing the exact automated-coverage gap that let F-34.9-01 reach a live macOS gate before a 4598-test green suite ever caught it.**

## Accomplishments

- `FrameworkInspection` interface, `findFrameworks()` (recursive `.framework` discovery guarded on `dirent.isDirectory()` from `readdirSync(..., {withFileTypes: true})`, so a symlinked directory is never walked into) and `inspectFramework()` (every symlink determination via `lstatSync`, never `statSync`) added to `meta/verifyRunnerBundle.ts`.
- `getSignatureState()` (unchanged, plan 08) is now also called against the framework BUNDLE directory itself -- the artifact `codesign` actually classifies -- rather than only against inner Mach-O files, correcting the exact miss the 2026-08-11 live gate recorded (`codesign --verify --deep` on `.../gogdl/gogdl` exited 0 while the framework was already malformed).
- `summarise()` enforces four independent conditions, each message naming the runner, the framework path, and `F-34.9-01`: missing `Versions/Current`, `Versions/Current` not a symlink, an unresolvable `Versions/Current` symlink target, and a non-symlink top-level stub. Signature IDENTITY state (`MachOSignature.signature`) is untouched and stays data-only, per 34.9-08's own established invariant.
- `printTable()` extended with one line per framework (name, symlink-ness, target, codesign display).
- Fixture suite extended from 8 to 15 tests: a well-formed baseline, four dedicated malformation tests (one per enforced condition), a symlink-walk-avoidance test with a planted nested framework, and a no-framework-in-tree pass case.
- All three plan-mandated mutations applied live against `meta/verifyRunnerBundle.ts`, confirmed RED with the specific test named, reverted, and reconfirmed GREEN before being trusted -- see Mutation Table below.
- Empirical `codesign` determination performed and recorded (see Decisions Made / Issues Encountered) -- required by the plan before trusting any assumption about `codesign`'s exact error wording.

## Decisions Made

- **No fifth condition for the literal "bundle format is ambiguous" string** (plan-mandated empirical determination): built a well-formed vs. `cp -RL`-dereferenced `Python.framework` fixture outside the test suite (scratchpad) and ran `codesign -dv` and `codesign --sign --force --timestamp --options runtime` against both, targeting `Python.framework/Python` (the same artifact the live gate's failing invocation targeted). On this machine, BOTH commands against the dereferenced framework emit `bundle format unrecognized, invalid, or unsuitable` -- not the CI runner's exact `bundle format is ambiguous (could be app or framework)`. This is a wording difference between codesign/macOS versions for the same underlying condition, not a sign the dereferenced shape passes uncaught. Per the plan's explicit contingency ("do not add the condition speculatively"), no fifth condition keyed to that literal string was added; enforcement relies on the four structural conditions (a)-(d) alone, which fire on both machines regardless of codesign's wording.
- **Dereferenced fixture isolates Versions/Current only, not the whole framework** (discovered live during mutation (a)): the plan's `<action>` describes producing the dereferenced shape "via `spawnSync('cp', ['-RL', src, dest])`" applied to the framework as a whole. Doing that literally dereferences BOTH `Versions/Current` (condition b) AND the top-level `Python.framework/Python` stub (condition d) simultaneously -- so deleting condition (b)'s enforcement alone left condition (d) still catching the malformation, and mutation (a) produced 14/14 GREEN instead of the required RED. Fixed by applying `cp -RL` surgically to ONLY the `Versions/Current` entry (remove the symlink, `cp -RL` the version directory it pointed at into its place), leaving the top-level stub symlink untouched. Re-ran mutation (a) after the fix: it now fails exactly the intended test. This is the same vacuous-mutation class 34.9-12 found once already this phase (its `collectSymlinks`'s `continue` statement) -- confirms it recurs whenever a single external command is used to construct two logically-independent test fixtures at once.
- **All-unsigned assertion targets "not signed:-prefixed", not the literal string "unsigned"**: `codesign -dv` against the synthetic framework DIRECTORY (no `Info.plist`, its Python stand-in binary is only magic-byte-sniffable, not a linked Mach-O) reports `unknown:...bundle format unrecognized...`, which `getSignatureState()`'s existing parser correctly classifies as `unknown:<excerpt>` per its own documented behavior (34.9-08) -- not `unsigned`. The test was written to assert the property the invariant actually cares about (never a real signing identity) rather than a specific string that this fixture's shape cannot produce, and is documented as a fixture limitation, not a defect in `getSignatureState()` itself, which is unchanged.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Test-integrity bug] Whole-framework `cp -RL` fixture construction made mutation (a) vacuous**
- **Found during:** Task 2, performing the plan-mandated mutation (a) (delete the `versionsCurrentIsSymlink` enforcement)
- **Issue:** constructing the `dereferenced` fixture shape via `cp -RL` on the entire `Python.framework` directory (as the plan's `<action>` literally describes) dereferences both `Versions/Current` and the top-level `Python.framework/Python` stub in one step. With condition (b) (`versionsCurrentIsSymlink`) deleted, condition (d) (`topLevelStubExists && !topLevelStubIsSymlink`) still caught the same fixture, so the test the mutation was supposed to break stayed green -- the exact vacuous-assertion shape this repo's standing lessons warn against.
- **Fix:** narrowed the `dereferenced` fixture construction to apply `cp -RL` to only the `Versions/Current` entry (remove the symlink, then `cp -RL` the `3.14` version directory into its place), leaving `Python.framework/Python` and `Python.framework/Resources` as untouched symlinks. This isolates the Versions/Current defect from the top-level-stub defect (a distinct, separately-tested malformation via the `stub-file` shape).
- **Files modified:** `meta/__tests__/verifyRunnerBundle.test.ts`
- **Verification:** re-ran mutation (a) after the fix -- it now fails exactly `"dereferenced Versions/Current (the exact F-34.9-01 shape)..."` (1/15 RED); reverted, reconfirmed all 15 tests GREEN.
- **Committed in:** `2babd31d2` (Task 2 commit)

**2. [Rule 1 - Test-integrity bug] No reachable duplicate framework meant the symlink-walk-avoidance claim was untestable**
- **Found during:** Task 2, designing the "findFrameworks does not walk through a symlinked directory" test
- **Issue:** the plan's `<interfaces>` framework shape has no `.framework`-named directory reachable through `Versions/Current`'s target (`3.14`) -- so even a defective recursion guard that DID follow symlinked directories would find nothing new by walking into `Versions/Current`, and a test built on that alone could never go RED against mutation (b), regardless of whether the guard was correct.
- **Fix:** planted a second, nested `Nested.framework` directory inside `Versions/3.14/Resources/`, reachable via its real path exactly once but ALSO reachable via two symlink aliases (`Python.framework/Resources` and `Python.framework/Versions/Current`) if the guard were defective. Asserted `frameworks.length === 2` (not more) for the well-formed case.
- **Files modified:** `meta/__tests__/verifyRunnerBundle.test.ts`
- **Verification:** mutation (b) (guard changed to follow symlinked directories) drove this test RED alongside collateral failures in fixtures with broken symlinks (6/15 RED); reverted, reconfirmed 15/15 GREEN.
- **Committed in:** `2babd31d2` (Task 2 commit)

**Total deviations:** 2 auto-fixed (Rule 1, both test-integrity class, both found while performing the plan's own mandated mutation-testing step)
**Impact on plan:** Both were necessary for the mutation-testing requirement's own validity; no scope creep, no production-code behavior change beyond what Task 1 already specified.
