# Phase 34.9: macOS runner onedir repackaging - Context

**Gathered:** 2026-08-07
**Status:** Ready for planning
**Source:** Direct user decisions during debug session `nile-spawn-app-side-latency`

<domain>
## Phase Boundary

Ship `legendary`, `gogdl` and `nile` as PyInstaller **`--onedir`** builds **on macOS only**, so a
runner spawn costs ~0.2s instead of ~20s cold. This removes the dominant latency term from every
store login (Amazon, Epic, GOG) and from any other user-facing path that shells out to a runner.

**IN scope:** macOS arm64 + x64, three Python runners, the build/vendoring pipeline that produces
them, the downloader that consumes them, path resolution, and the code-signing/notarization work
that a multi-file runner tree forces.

**OUT of scope:** Linux and Windows (they keep the current onefile binaries — see Decisions).
`comet` (Rust static binary, ~0.01s, pays no tax). Any change to what the runners *do*. The Epic
login UX itself (Phase 34.7 owns that; standing decision: Epic is implemented last and this phase
must not touch Epic login code).

</domain>

<decisions>
## Implementation Decisions

### Sourcing strategy — LOCKED: build in GameLib CI now AND upstream PRs in parallel

There is no upstream onedir release to download today. The user chose **both** paths: build onedir
runners in GameLib's own CI so the win ships immediately, while opening PRs to the three upstream
repos in parallel. Drop the local build if/when upstream lands it.

Rejected: *GameLib CI only* (permanently diverges from how Heroic vendors runners, cutting against
the standing mergeability constraint in CLAUDE.md, and owns build maintenance forever) and
*upstream PRs only* (timeline entirely outside our control, may never land).

Upstream owners for the parallel PRs:
- `imLinguin/nile` — `.github/workflows/build.yaml`, currently
  `pyinstaller --onefile --name nile ${{ steps.strip.outputs.option }} nile/cli.py`
- `Heroic-Games-Launcher/legendary`
- `Heroic-Games-Launcher/heroic-gogdl`

Heroic has the identical problem, so upstreaming benefits both projects.

### Platform scope — LOCKED: macOS only

The tax is macOS-specific: `amfid` runs a per-file Gatekeeper assessment on each extracted file,
and onefile's randomly-named `$TMPDIR/_MEIxxxxxx` extraction path means the assessment cache never
hits. Linux and Windows do not pay this and would only absorb the 2.2x bundle growth for no gain.
**Do not switch Linux or Windows to onedir.**

### Runner scope — LOCKED: all three Python runners

`nile`, `legendary` and `gogdl` all pay the same tax and all sit behind a login. Fixing only nile
(the originally reported Amazon complaint) would leave Epic and GOG paying ~20s and would force
the packaging/signing work to be repeated later.

### Claude's Discretion

Archive format for the release assets; CI workflow structure and whether builds happen at release
time or are published as pinned assets; exact signing invocation; whether `archSpecificBinary()` is
extended or a sibling resolver is added; test strategy.

</decisions>

<specifics>
## Specific Ideas — measured facts the plan must build on

**The win is measured, not assumed** (debug session `nile-spawn-app-side-latency`, commit
`a9192ae80`; raw output at `.planning/debug/evidence/onedir-vs-onefile-measurement-2026-08-06.txt`).
nile v1.1.2 was cloned from `imLinguin/nile` at the pinned tag and built twice with upstream CI's
own pyinstaller command, differing only in the flag. Both adhoc-signed. Two cold rounds separated
by 400s idles, the second in reversed order to catch ordering artifacts:

| build | cold (avg) | warm |
|---|---|---|
| onefile (control — faithfully reproduces the tax) | 20.84s | 6.61s |
| **onedir** | **0.22s** | **0.14s** |

~95x cold, ~47x warm. For onedir the cold/warm distinction collapses to ~80ms of noise. The
onefile control reproducing the vendored binary's independently measured 21.27s/6.50s is what makes
the onedir figure trustworthy rather than an artifact of building differently from upstream.

**Measured cost:** onedir is 29MB across 108 files (103 Mach-O) vs 13MB as one file — 2.2x bundle
growth per runner, ~100 extra Mach-O files each for notarization to sign and staple.

**Do not re-litigate these, they are closed:** prewarming on login-screen mount is NOT a fix (it is
literally what the reverted code did, and it produced a 36s click when the user clicked into the
in-flight extraction); caching the `--version` probes is NOT a fix (it removes a load-bearing
warm-up, and would supply it once after install then silently stop forever). Both were reverted —
see `.planning/debug/evidence/reverted-getOsPlatformInfo-fix.patch`.

</specifics>

<constraints>
## Known constraints — do NOT rediscover these

1. **PyInstaller cannot cross-compile.** macOS x64 and arm64 must each build on their own runner
   (upstream uses a macos-13/macos-14 matrix). Only arm64 is verifiable on the dev machine, so the
   x64 leg is CI-only and cannot be locally proven before merge.
2. **`meta/downloadHelperBinaries.ts` assumes a single file.** `downloadAsset()` (~line 58)
   downloads one file to `public/bin/{arch}/{platform}/{name}` and `chmod 755`s it. Onedir assets
   are directory trees and need archive + extract + recursive permissions.
3. **`archSpecificBinary()` (`src/backend/utils.ts:~510`) resolves a FILE path**, with an x64
   fallback path and a throw when neither exists. Onedir needs `.../nile/nile`.
4. **The consumer shape probably survives.** `getNileBin()` / `getLegendaryBin()` / `getGOGdlBin()`
   already return `{dir, bin}` via `splitPathAndName`, so callers may need no change — **verify
   this, do not assume it.**
5. **Signing must cover every Mach-O in the tree or notarization fails.** Both
   `electron-builder.yml` and the Tauri bundler need it, because the Electron build still exists
   until Phase 35 removes it. This phase therefore pays the packaging cost twice; accepted
   deliberately for the size of the win.
6. **The `altLegendaryBin` / `altGogdlBin` / `altNileBin` user overrides must keep working.** They
   bypass `archSpecificBinary` entirely and may point at a user's own onefile binary.
7. **Pinned versions must not drift:** `RELEASE_TAGS` in `meta/downloadHelperBinaries.ts` is
   legendary `0.20.43`, gogdl `v1.2.1`, nile `v1.1.2`, comet `v0.2.0`. A repackaging phase must
   ship the SAME runner versions — this is a packaging change, not a runner upgrade.

</constraints>
