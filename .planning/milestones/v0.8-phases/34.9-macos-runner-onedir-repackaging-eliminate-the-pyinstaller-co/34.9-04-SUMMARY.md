# Phase 34.9 Plan 04: macOS Onedir Runner Build CI Workflow Summary

**A workflow_dispatch-only GitHub Actions workflow that builds legendary/gogdl/nile as PyInstaller --onedir bundles on macos-13 (x64) and macos-14 (arm64) and publishes all six archives plus per-arch SHA256SUMS/BUILD-MANIFEST to a rolling `runners-onedir-macos` prerelease, with a race-free two-job split and 37 mutation-proven tests pinning its shape.**

## Accomplishments
- `.github/workflows/build-runners-onedir-macos.yml`: a `workflow_dispatch`-only, two-job workflow. `prepare-release` (ubuntu-latest) owns rolling-release creation exclusively via the view-or-create + self-healing `gh release edit --prerelease --latest=false` shape carried over verbatim from `build-crossover-index.yml`. `build` (`needs: prepare-release`, `fail-fast: false`) matrixes `{os: macos-13, arch: x64}` and `{os: macos-14, arch: arm64}`, does inline `pnpm install` (deliberately skipping `./.github/actions/install-deps` to avoid its `download-helper-binaries` chicken-and-egg on assets this workflow hasn't published yet), runs an `uname -m` arch guard that fails loudly on mismatch, invokes `pnpm build-runners-onedir --arch=${{ matrix.arch }}`, and uploads the three `*_onedir.tar.gz` archives plus arch-suffixed `SHA256SUMS-${{ matrix.arch }}`/`BUILD-MANIFEST-${{ matrix.arch }}.json` with `--clobber`.
- `src/backend/__tests__/runnersOnedirWorkflow.test.ts`: 37 tests covering trigger shape, permissions, jobs/matrix shape (parsed via `js-yaml`, not regex), the five scope guards (`download-helper-binaries`/`install-deps`/`comet`/`win32`/`windows-` absent everywhere in the comment-stripped source, `ubuntu` absent from the `build:` job specifically), the publish and upload steps' executed-instruction content, the arch guard step, and a cross-module test asserting for every `{x64,arm64} × {legendary,gogdl,nile}` combination that `archiveName()` names a file the upload step's `*_onedir.tar.gz` glob and arch-suffixed digest filenames actually agree with.
- Four independent mutation proofs, each confirmed RED then reverted GREEN: `macos-13`→`macos-latest` (matrix test), removing `needs: prepare-release` (race-guard test), `SHA256SUMS-${{ matrix.arch }}`→bare `SHA256SUMS` (clobber-safety test, 7 tests RED), and `archiveName`'s `_onedir.tar.gz`→`_onedir.tgz` (cross-module test, 6 tests RED).
- `npm run test:ci`: 232/232 suites, 4535/4535 tests, exit 0 (no regression). `npx tsc --noEmit`: clean.

## Decisions Made
- **Scoped the `ubuntu` negative assertion to the `build:` job block, not the whole file.** The plan's Task 2 `<behavior>` list literally says "zero occurrences of ... ubuntu" against the whole comment-stripped source, but Task 1's own action text mandates `prepare-release` runs on `ubuntu-latest`, and Task 1's own (more precise) acceptance criteria already scoped this check to "inside the build job." A whole-file interpretation would have made the plan internally unsatisfiable — implemented the precise, intended scoping instead and documented the reasoning in the test file's header comment.
- **`js-yaml.d.ts` instead of `@types/js-yaml`.** `js-yaml` is already present in `node_modules` transitively (via eslint's dependency tree) and is the parser `npx js-yaml` (the plan's own verify command) already resolves to, but has no bundled types and `@types/js-yaml` isn't installed. Declared only the single `load()` export actually used, following the repo's existing `declare module` pattern (`src/common/typedefs/lzma.d.ts`, `steam-shortcut-editor.d.ts`) rather than running any package-manager install.
