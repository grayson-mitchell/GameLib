<objective>
Close **F-34.9-01**, the release-blocking regression this phase introduced: vite's `copyDir`
(`publicDir` → `outDir`) has no symlink branch — it `statSync`s through links and `copyFileSync`s —
so each onedir runner's `Python.framework` loses all four of its symlinks on the way into `build/`,
leaving `Versions/Current` a real directory. Apple's framework layout requires it to be a symlink;
without it `codesign` cannot classify the bundle and `pnpm dist:mac` aborts with
`bundle format is ambiguous (could be app or framework)`.

Purpose: no packaged macOS build can be produced at all today. This is the gap cycle's first
target and everything else in the cycle is downstream of it.

Output: a `closeBundle` vite plugin that re-creates every source symlink in the build output, wired
once into `electron.vite.config.ts` so all nine `electron-vite build` call sites inherit it;
fixture tests proven RED against a dereferenced framework; and a live build proof against the real
tree.
</objective>

**The exact defect mechanism, from `node_modules/vite/dist/node/chunks/dep-DBxKXgDP.js`
(vite 6.3.5).** `copyDir(srcDir, destDir)` at ~L6859 reads each entry, calls `fs.statSync(srcFile)`
(which FOLLOWS symlinks), and either recurses on `isDirectory()` or `copyFileSync`s. There is no
`lstat` and no symlink branch. It is called at ~L46262 from `prepareOutDir`, guarded by
`build.copyPublicDir && publicDir && existsSync(publicDir)` — and `prepareOutDir` runs BEFORE
`bundle.write()`, so a plugin `closeBundle` hook runs strictly after it.

**Which of electron-vite's three builds performs the copy.** Only the `renderer` config
(`root: '.'`, `outDir: 'build'`, `emptyOutDir: false`) — its `publicDir` defaults to `<repo>/public`.
`build/main` and `build/preload` contain only their own bundles (verified on disk). electron-vite
runs main → preload → renderer in order, so a renderer `closeBundle` hook is the last thing to run
in an `electron-vite build`.

**The twelve symlinks, verified on disk right now** (`find public/bin/arm64/darwin -type l` → 12;
`find build/bin/arm64/darwin -type l` → 0). Four per runner, identical shape for
`legendary`/`gogdl`/`nile`, relative targets:

| relPath under `<runner>/_internal/` | target |
|---|---|
| `Python` | `Python.framework/Versions/3.14/Python` |
| `Python.framework/Python` | `Versions/Current/Python` |
| `Python.framework/Resources` | `Versions/Current/Resources` |
| `Python.framework/Versions/Current` | `3.14` |

**Payload, measured now** (`du -sh`): source `public/bin/arm64/darwin` = gogdl 25M, legendary 30M,
nile 29M (84M). Dereferenced `build/bin/arm64/darwin` = gogdl 45M, legendary 55M, nile 52M (152M).
This 84M↔152M delta is **F-34.9-03**, and it is the corroborating signal that the fix took effect —
not a separate fix.

**Why a plugin and not a script step.** `electron-vite build` is invoked by nine `package.json`
scripts (`start`, `tauri:dev`, `test:e2e`, `release:linux/mac/win`, `sign:win`,
`dist:linux/mac/win`). A post-build script step would have to be added to eight of them and would
be silently missed by the ninth and by every future one. The plugin is one seam.

**`tsconfig.json` `include` is `["src"]`** — neither `meta/` nor `electron.vite.config.ts` is
covered by `pnpm codecheck`. `meta/` IS type-checked by ts-jest when a `meta/__tests__` suite
imports it (`meta/jest.config.js`, `displayName: 'Meta'`, `roots: ['<rootDir>/meta']`,
`testMatch: ['**/__tests__/**/*.test.ts']`). That import is therefore this module's only type
coverage and must exist.

**`fs.rmSync(p, { recursive: true, force: true })` on a symlink-to-directory** unlinks the LINK,
not the target — Node stats with `lstat`. This is what makes an idempotent
"remove-then-relink" safe against all three possible destination states (real file, real directory,
existing symlink).

**`readdirSync(dir, { withFileTypes: true })`** returns `Dirent`s stat'd with `lstat`, so
`dirent.isSymbolicLink()` is true and `dirent.isDirectory()` is FALSE for a symlink pointing at a
directory. Recursing only on `isDirectory()` therefore cannot walk through a symlink.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `public/bin/**` (vendored runner tree) → `build/bin/**` (build output) | The tree originates from a PyInstaller build or, in future, a downloaded release archive. Its symlink targets are attacker-influenceable in the download case. |
| build output → packaged `.app` → user machine | Anything this module writes ends up inside a signed, distributed application bundle. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.9G-01 | Tampering | `restoreSymlinks` destination path | mitigate | `resolveDestPath` throws unless `path.resolve(destDir, relPath)` is strictly inside `path.resolve(destDir) + path.sep`. A crafted `relPath` (e.g. via a `..`-bearing source entry) cannot cause a write outside the build output. Test-covered in Task 2. |
| T-34.9G-02 | Tampering | `rmSync(destPath, { recursive: true })` | mitigate | The removal target is always the containment-checked `destPath`, never a `readlink` target. Node's `rmSync` unlinks a symlink rather than following it, so a hostile link target cannot redirect the deletion. Stated in the Task 1 action and covered by the idempotence test. |
| T-34.9G-03 | Elevation of Privilege | symlink target contents | accept | Targets are copied verbatim from the source tree and are all relative. Rewriting or absolutising them would break the framework layout. The risk is bounded by the source tree's own provenance, which is REQ-34.9-04's digest verification — descoped this cycle and recorded as such, not silently assumed. |
| T-34.9G-04 | Denial of Service | `closeBundle` on a non-macOS checkout | mitigate | `collectSymlinks` returns `[]` for an absent or symlink-free tree and never throws, so Linux/Windows builds are a logged no-op rather than a build failure. Covered by the zero-symlink test. |
| T-34.9G-SC | Tampering | npm/pip/cargo installs | N/A | **This plan installs no packages.** No `package.json` dependency change, no `pnpm add`. The Package Legitimacy Gate does not apply; no `[ASSUMED]`/`[SUS]` checkpoint is owed. |
</threat_model>
