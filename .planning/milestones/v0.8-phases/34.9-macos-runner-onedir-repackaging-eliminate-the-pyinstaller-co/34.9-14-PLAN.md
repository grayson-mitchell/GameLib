**The naming contract that makes macOS artifacts identifiable.** `electron-builder.yml` sets
`mac.artifactName: ${productName}-${version}-macOS-${arch}.${ext}`, so every macOS artifact carries
the literal `-macOS-`. The other platforms do not: `win.artifactName` is
`${productName}-${version}-Setup-${arch}.${ext}`, `linux.artifactName` is
`${productName}-${version}-linux-${arch}.${ext}`, `portable.artifactName` is
`${productName}-${version}-Portable-${arch}.${ext}`. This token is the discriminator — and because
it is config-derived, a test must pin it, or a future `artifactName` edit silently turns this
cleaner into a no-op.

**Current scripts (`package.json`), verbatim:**
```
"dist:mac": "export CSC_IDENTITY_AUTO_DISCOVERY=false && pnpm build-steam-bridge && electron-vite build && electron-builder --mac"
"release:mac": "pnpm build-steam-bridge && electron-vite build && electron-builder -p always --mac --x64 --arm64"
```

**The `meta/` script invocation convention, and the trap in it** (34.9-08's own recorded
deviation): use `| node -` (single-dash stdin sentinel), NEVER `| node --`. With `--`, Node resolves
the first positional argument as a script filename and fails with `MODULE_NOT_FOUND` before the tool
runs. Both `build-runners-onedir` and `verify:runner-bundle` already use `| node -`.

**Jest project:** `meta/jest.config.js`, `displayName: 'Meta'`, `roots: ['<rootDir>/meta']`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `dist/` directory contents → a recursive delete | This plan's whole function is destructive. The entries it deletes are attacker-influenceable only by someone who already has write access to the repo checkout, but a path-traversal or symlink-following bug here destroys data outside `dist/`. |
| a stale artifact → a release decision | The defect being fixed is precisely a false-positive success signal. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.9G-09 | Tampering | `cleanDistMac`'s `rmSync` target | mitigate | Every removal path goes through a `path.resolve(distDir, name)` containment check that throws unless the result is strictly inside `path.resolve(distDir) + path.sep`. Test-covered. |
| T-34.9G-10 | Denial of Service | deleting a non-macOS artifact | mitigate | Selection is a positive allow-list (`-macOS-` token, `latest-mac.yml`, `/^mac(-.+)?$/` directories), never a deny-list. The survival test names all five foreign entries individually, and mutation (b) proves the guard is load-bearing. |
| T-34.9G-11 | Tampering | a symlinked entry inside `dist/` | mitigate | `rmSync` unlinks a symlink rather than following it; a dedicated test creates a macOS-named symlink pointing outside `distDir` and asserts the target survives. |
| T-34.9G-12 | Spoofing | a future `artifactName` edit silently disabling the cleaner | mitigate | The `mac.artifactName` pin parses `electron-builder.yml` with `js-yaml` and fails if the `macOS` token disappears — the cleaner cannot become a silent no-op. |
| T-34.9G-SC | Tampering | npm/pip/cargo installs | N/A | **This plan installs no packages.** `js-yaml` and `esbuild` are already dependencies. The Package Legitimacy Gate does not apply. |
