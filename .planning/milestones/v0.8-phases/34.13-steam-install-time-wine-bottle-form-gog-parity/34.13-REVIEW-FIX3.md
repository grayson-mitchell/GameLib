## Notes on method

**Every gate in this pass was proven RED against a concrete known-bad before
going green**, and each known-bad is named in its own section above. Where a
gate could be satisfied by over-refusing (A-12, A-13, A-14, A-15, A-16, A-21,
C-18, C-21) I added an explicit **DISCRIMINATOR** asserting the positive case
still works, so no gate in this pass can pass by deleting the behaviour it
guards.

**Three gates were made repo-wide censuses rather than file-scoped pins**
(`permanentlyMountedPolls.test.ts`, `labelSuiteI18nCensus.test.ts`,
`mainButtonCatalogDefaults.test.ts`), because the dominant defect shape in
iteration 2 was "fixed the reported file, missed the sibling". Each derives its
subject from the filesystem or from `App.tsx` at test time, so a future sibling
is enrolled automatically rather than needing someone to remember.

**Two findings were closed by DELETION rather than repair** (A-19's
`nativeBottleInstall`, B-WR-01's `onlyLibrary`). Both were write-only state whose
only remaining effect was cost plus an invitation to trust them. The repo's own
precedent is `SteamBottleConfig`'s retired `loggedIn`.

the second: rejecting on the write side would contradict review B-WR-08's
recorded decision that the backend seam must stay permissive for `launcher.ts`'s

instead.

rewrites `meta/i18nGateScope.json`, which carries `generatedBy: hand-edited`. I
restored it to HEAD with `git show HEAD:… >` so the blocking gate's scope stays
