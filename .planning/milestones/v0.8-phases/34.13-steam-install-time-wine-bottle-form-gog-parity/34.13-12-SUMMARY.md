# Phase 34.13 Plan 12: Mount the Steam install dialog Summary

InstallModal/index.tsx now branches to 34.13-10's `SteamDialog` first in its five-way router, driving the platform row and wine-section mount entirely off 34.13-05's `resolveSteamSectionGating()` verdict rather than the legacy `availablePlatforms.length > 1` guard -- the phase's built-but-unreachable Waves 1-5 work is now wired into the live component tree.

## What Was Built

1. **`steamPlatformRow.ts`** (new, zero runtime imports) -- `hasSteamWindowsDepot` (strict `is_windows_native === true`, fail-closed on absent/undefined), `selectSteamPlatformOptions` (omits the Windows option entirely when no depot exists, never disables it), `readonlyPlatformValue`. RED-proven before it existed; 21 unit tests cover the full 8-combination mode x depot space plus three saboteurs.
2. **`index.tsx`** rewritten to add a fifth, first-priority ternary arm rendering `<SteamDialog>`; `platformSelection()` now reads a single `platformRowMode` value (`steamGating.platformRow` on the Steam path, the untouched `legacyPlatformRowMode` everywhere else); the Steam `<WineSelector>` mount carries `runner="steam"` and `bottleNameReadOnly`; `showWineSelector` (`steamGating.wineSection` on the Steam path) replaces `hasWine` as every mount's gate; a single `listSteamLibraryTargets()` fetch feeds both the verdict and `SteamDialog`'s `steamLibraries` prop.
3. **`installModalSource.test.ts`** (new) -- comment-stripped source gates for every negative decision this file encodes: D-01 (SteamDialog first, unreachable from DownloadDialog), D-03 (legacy guard survives exactly once), D-17 (no `MenuItem disabled`), the 34.13-05 review obligation (no re-derived section conditions), D-16/D-05 (WineSelector props). 2. `platformRowOptions` = `availablePlatforms` -- unchanged from the original `.map()` source.
3. `value` = `readonlyPlatformValue(platformRowMode) ?? platformToInstall` = `undefined ?? platformToInstall` = `platformToInstall` for every non-Steam row (`readonlyPlatformValue` returns `undefined` for both `'absent'` and `'selectable'`, the only two modes `legacyPlatformRowMode` can produce).
4. `disabled` = `platformRowMode !== 'selectable' || disabledPlatformSelection`. For a non-Steam `'selectable'` row this reduces to `false || disabledPlatformSelection` = `disabledPlatformSelection`, unchanged.

6. `afterSelect` -- the `InfoIcon` guard is `isSteamManagedApp && platformRowMode === 'selectable'`; with `isSteamManagedApp` false the whole expression is `undefined`, so no `InfoIcon` renders for any non-Steam dialog.

```tsx
<SteamDialog
  appName={appName}
  runner={runner}
  winePrefix={winePrefix}
  wineVersion={wineVersion}
  availablePlatforms={availablePlatforms}
  backdropClick={closeModal}
```

The branch condition is `isSteamManagedApp && gameInfo` (not `isSteamManagedApp` alone) -- the extra `gameInfo` conjunct is what lets TypeScript's control-flow narrowing pass the non-nullable `gameInfo: GameInfo` prop `SteamDialog` requires; `isSteamManagedApp` already implies `Boolean(gameInfo)` at runtime, so this changes no observable behaviour. `eligibilityPending` is deliberately **not** passed -- that is 34.13-11's (wave 7) prop to add.

## `BOTTLE_REQUIRED_UNTIL_34_13_11`

Declared once at `index.tsx:77` (module scope, `const BOTTLE_REQUIRED_UNTIL_34_13_11 = false`), consumed once at `index.tsx:215` as the `bottleRequired` field of the sole `resolveSteamSectionGating` call. **34.13-11 (wave 7) is the only legitimate replacement** -- it must call `useSteamBottleEligibility` in this file and substitute the hook's resolved value for this constant. Until then, every Steam install-options dialog session computes its verdict as if no bottle is required, which is the correct fail-closed default (a wrongly-`true` value would mount a wine section for a game that doesn't need one).

## Pre-Fetch Fail-Closed Behaviour

`steamLibraries` defaults to `[]` on first render. The Steam branch is taken purely on `isSteamManagedApp && gameInfo`, which needs no async input, so the fetch can never gate WHICH dialog renders. `steamGating` is a `useMemo` recomputed whenever `steamLibraries` changes (dependency array includes it), so the verdict silently upgrades from the `[]`-derived content-light form (`nativeInstallOn: false`, `libraryCount: 0`) to the real one the instant `listSteamLibraryTargets()` resolves. The alternative -- making the `<SteamDialog>` branch conditional on the fetch and falling through the ternary to `<DownloadDialog>` -- was explicitly avoided: D-07 records that `SteamLibraryManager.getInstallInfo()`'s stub would leave `DownloadDialog` looping forever on "Geting download size...". `getInstallInfo` appears nowhere in `index.tsx` (verified by both a raw grep and Task 3's comment-stripped gate).

## `nativeInstallOn` Derivation

`nativeInstallOn: steamLibraries.length > 0`. Both IPC handler wrappers (`main.ts:913-914`, `installFlowRegistration.ts:189-190`) are already gated server-side on `isSteamNativeInstallEnabled()` and return `[]` when native install is OFF, so an empty array from `listSteamLibraryTargets()` IS the OFF signal by construction -- there is no observable difference between "native install OFF" and "native install ON with zero libraries returned." `34.13-RESEARCH.md` Pitfall 4 forbids adding a second settings read to distinguish them, and 34.13-05's own Section-Gating Matrix renders `OFF` and `ON-with-<=1-library` identically (rows 2/5 do not distinguish the two), so this derivation loses no information the matrix itself cares about.
