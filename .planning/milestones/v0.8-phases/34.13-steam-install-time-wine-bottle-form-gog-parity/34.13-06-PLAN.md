<objective>
Teach `SteamGame.install()` to honor an explicit Windows-via-bottle override (D-17), so a
mac-native Steam game can be installed as its Windows build through the CrossOver bottle instead of
always taking the native `steam://` path.

Purpose: D-17 is the user's stated *primary* motivation for this phase — "native Steam ports are
frequently absent, outdated, or worse than the Windows build, and overriding a native install is
the real reason to open the form for a game that does not strictly need it." Today install routing
is 100% `isBottleEligible()`; there is no input a user choice can travel through.

Output: one triple-gated routing const inside `install()`, and the phase's load-bearing regression
guard.

**Scope fence — the four branches STAY.** This plan adds no branch, deletes no branch, and reorders
no branch. `isBottleEligible()`, `isBridgeEligible()`, `ensurePlatformsCaptured()`,
`installBridgeGame()`, `installBottleNative()`, `installNative()` and `installDepotDownload()` are
all read-only here. The single behavioral edit is the condition at the head of the existing
`if (this.isBottleEligible())` block.

**The regression trap this plan exists to avoid** (outline note 2, binding): `installSteamGame()`
hardcodes `platformToInstall: 'Windows'` for **every** Steam install, and the Steam backend reads
that field **nowhere**. `platformToInstall === 'Windows'` therefore cannot distinguish "the user
chose Windows for a mac-native game" from "the legacy hardcoded default." An override keyed on it
would flip **every** mac-native install into the bottle. Read only the separate explicit field.
</objective>
