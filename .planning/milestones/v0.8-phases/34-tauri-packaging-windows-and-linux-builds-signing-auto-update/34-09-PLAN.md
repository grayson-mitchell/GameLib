<objective>
Close **CR-02** (BLOCKER): `nsis` is an active bundle target but `src-tauri/icons/` contains no
`icon.ico`, and `bundle.icon` does not reference one. The `windows-latest` CI leg will either fail
to bundle or ship an installer/executable with a default fallback icon — release-blocking either
way. `34-05-PLAN.md` anticipated this ("if any required icon is missing, regenerate from
`public/icon.png`") but the Windows output was never generated or committed, consistent with
`tauri icon` having been run on a macOS dev machine.

Purpose: the Windows release leg must produce a correctly-iconed artifact, and this defect class
must be caught by the existing Wave-0 config-shape suite rather than by a live Windows CI run (the
review explicitly asks for this).
Output: a committed `src-tauri/icons/icon.ico`, wired into `bundle.icon`, guarded by new
`tauriConf.test.ts` assertions.
</objective>
