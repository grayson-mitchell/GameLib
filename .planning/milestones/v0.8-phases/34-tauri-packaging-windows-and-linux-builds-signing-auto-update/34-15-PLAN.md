<objective>
Close **GAP-4** (34-VERIFICATION.md truth #7 "PARTIAL", 34-REVIEW.md WR-03): the Windows signing
override gate tests only `-n "$WINDOWS_CERTIFICATE"` and never `WINDOWS_CERT_THUMBPRINT`.
Enrolling the certificate secret without the thumbprint secret — an easy three-secret mistake —
renders `"certificateThumbprint":""` into the `--config` override, tauri invokes signtool with an
empty thumbprint, and the Windows leg hard-fails. That directly contradicts the workflow's own
stated invariant and D-04's graceful-skip decision ("CI must **never** fail on missing certs").

Secondary defect in the same step (34-REVIEW.md WR-03, "Secondary"): the `args` value is written
to `$GITHUB_OUTPUT` with the single-line `key=value` form even though it is secret-derived. A
thumbprint secret containing a newline would let arbitrary step outputs be injected. GitHub's own
guidance is a random heredoc delimiter for any non-literal output value.

Purpose: D-04 is a locked user decision. Today a partially-enrolled secret set turns the "ship
unsigned, stay green" default into a hard CI failure on the one platform that has no native
absent-secret skip.

Output: a both-secrets-required signing branch, a warn-and-skip middle branch, a narrower
cert-import condition so no unusable `.pfx` is ever written to disk, delimiter-safe output
emission, and regression tests that fail against today's workflow.

This plan is a **prerequisite** to resuming 34-07's deferred live gate (which is what will prove
REQ-34-04's live half). It does not re-own that gate.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions secrets -> step shell | `WINDOWS_CERT_THUMBPRINT` is interpolated into a string that becomes a step output and then a `tauri-action` CLI argument |
| Step output -> subsequent step inputs | `$GITHUB_OUTPUT` is a file whose format is line-oriented and therefore injectable |
| Secret -> runner filesystem | `WINDOWS_CERTIFICATE` is base64-decoded to `cert.pfx` on disk for `Import-PfxCertificate` |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

A newline inside `WINDOWS_CERT_THUMBPRINT` can then no longer terminate the output record and inject additional step outputs consumed by the `tauri-action` step. | T-34-SC | Tampering | npm/pip/cargo installs | n/a — accept | This plan adds NO package-manager install task and makes NO `package.json`/lockfile change. The Package Legitimacy Gate is not triggered. |
