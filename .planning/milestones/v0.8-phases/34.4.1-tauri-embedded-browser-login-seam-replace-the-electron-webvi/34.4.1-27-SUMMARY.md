# Phase 34.4.1 Plan 27: Guard WKWebView-degraded frontend capabilities Summary

**`queryLocalFonts` now degrades to default fonts instead of throwing into a swallowed rejection, and `CachedImage` stops requesting `imagecache://` on shells (Tauri) that never register the scheme — both gated behind one named, documented predicate each, closing two findings the 34.4.1 gate rerun left unassigned.**

## Accomplishments

- `queryLocalFontsSafe()` (new, dependency-free module) guards both failure shapes of the
  Chromium-only `queryLocalFonts` API — absent from `window`, and present-but-throwing (the actual
  WKWebView behaviour) — degrading to the two CSS-declared default fonts and logging once via
  `window.api.logError`, never letting a rejection escape unhandled.
- `imageCacheSchemeAvailable()` (new export in `preload/tauriTransport.ts`) is the single named
  predicate for whether the running shell serves `imagecache://`. `CachedImage` now consumes it at
  both the primary `useCache` initialisation and the fallback-advance path, so no `imagecache://`
  URL is ever emitted on a shell that doesn't register the scheme — eliminating the ~150
  guaranteed-failing `unsupported URL` requests per library render under Tauri.
- The bounded fallback chain (`nextIndex < fallbacks.length`) is now proven under both conditions —
  previously it had only ever run on a path where the first attempt (the imagecache wrap) always
  failed; this change removes that always-failing first attempt when the scheme is unavailable.
- A source-reading structural test pins `CachedImage/index.tsx` free of any direct `isTauri(`
  reference, mirroring the house pattern established by
  `GlobalStateSteamLogout.test.ts`. The test's load-bearing-ness was proven live: temporarily
  reintroduced `isTauri(` into the file, ran the test, observed the failure, reverted, re-ran green.
- `REQ-34.4.1-GAP-13` minted, adopting both previously-unassigned findings-register rows, with an
  explicit split between what unit tests close (queryLocalFonts) and what plan 29's live gate still
  owes (zero `unsupported URL` errors observed in a real Tauri build). ROADMAP.md's Phase 34.4.1
  Requirements line was extended with the new ID in this same plan — not left as a hand-off.

## Decisions Made

- **Extracted `queryLocalFontsSafe.ts` as a new file, deviating from the plan's declared
  `files_modified` list for Task 1.** The plan's own acceptance criteria require functional tests
  (including real unhandled-rejection tracking) against `src/frontend/screens/Accessibility/`, but
  `index.tsx` imports MUI plus several `.css`-importing components (`ThemeSelector`, `ToggleSwitch`
  directly; the `frontend/components/UI` barrel transitively pulls in `PathSelectionBox`, which
  imports `electron`). This project's frontend jest project has `testEnvironment: 'node'` with no
  jsdom/css-mock infrastructure (confirmed empirically — no moduleNameMapper for `.css` anywhere in
  the repo, and no existing test imports a `.css`-having `index.tsx` directly; every sibling
  screen/component test in this codebase tests a narrow, dependency-light export instead, exactly
  matching `jest.config.js`'s own docstring rationale). Extracting the guard into a zero-dependency
  sibling module was the only way to satisfy the plan's own testing acceptance criteria without
  either adding new jest infrastructure (a broader, riskier change) or duplicating the guard logic
  in two places. `index.tsx` remains the guard's sole caller and still contains the literal
  substring `queryLocalFonts` four times (import, comment, call site, function name), satisfying
  the plan's `must_haves.artifacts` check.
- Chose `window.api.logError` (not a new `logWarning`) as the degraded-path logging channel — it is
  the only listener-caller export in `preload/api/misc.ts` with a "log something to the frontend's
  existing register" shape, and is already the established pattern across `frontend/state/*` and
  several screens for exactly this kind of non-fatal-but-notable failure.
