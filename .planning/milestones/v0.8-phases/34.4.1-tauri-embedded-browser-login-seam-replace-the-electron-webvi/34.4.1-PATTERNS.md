## Shared Patterns

### 1. Fire-and-forget resolves a safe default, never rejects (`sidecar-dialog-reject-crashes`)

**Source:** `clipboardFlowRegistration.ts` L90-101 (already shown above) — `clipboardReadText`
resolves `''` on any failure, never propagates the rejection.

**Apply to:** every one of this phase's `handle`-kind channels
(`humbleStartLogin`/`humbleReconnect`/`humbleGetLoginUserAgent`/`humbleRevealKey`) at their
final catch — an unguarded `await`ed rejection from a fire-and-forget-shaped consumer is exactly
how the sidecar crashes (see the project memory: making a dialog stub REJECT instead of
resolving a safe default hard-crashed the app via `promptI386Recovery`/`askForceUninstall`'s
unguarded awaits). `humbleRevealKey`'s D-07 degraded-on-403 outcome specifically must resolve a
typed "failed, here's why" value, never reject.

### 2. Send-kind registration try/catch guards only the synchronous call

**Source:** `clipboardFlowRegistration.ts` L71-83 (`clipboardWriteText`) and L109-119
(`copySystemInfoToClipboard`'s async-IIFE wrapping).

**Apply to:** `humbleStopLogin`/`humbleLoginNavigated` — both are void-returning per the Kind
Verification table; wrap any `await`-needing body in the same `void (async () => { try {...}
catch (error) { logSendFailure(...) } })()` shape so a listener's own async rejection never
becomes an unhandled rejection.

### 3. Curated import — never side-effect-import a feature's `ipc_handler.ts`

**Source:** `clipboardFlowRegistration.ts`'s docstring, L34-43 (quoted above in full).

**Apply to:** `humbleLoginFlowRegistration.ts` must import `humble/user.ts`, `humble/adapter.ts`,
`humble/userAgent.ts` directly — `humble/ipc_handler.ts` registers 15 already-ported channels
(this phase's 6 are NOT among them; they are the ones `ipc_handler.ts` currently owns per L21-25/
102/126-127 but per this phase's plan will be re-homed) and a side-effect import would
double-register.

### 4. Fail-closed, generated, never-URL-derived window labels (T-34.1-27)

**Source:** `tauriChildWindows.ts`'s `nextExternalWindowLabel()`, L36-59 (full excerpt above) —
timestamp + counter + entropy, survives renderer reload (WR-04), never derived from a caller
URL, never `main`/`about`.

**Apply to:** every Rust-side window this phase's arms create (`humble_login_open`, the reveal
POST's hidden window). Port the same three properties to Rust: generated, survives-nothing-
relevant-on-the-Rust-side-since-it's-per-call, never a substring/hash of the URL, never a
reserved label. The label-safety test cases to mirror are `childWindows.test.ts` L83-103 and
L151-165 (two-successive-calls-differ, same-url-yields-different-labels, `external-` prefix
never `main`/`about`).

### 5. No hard-coded title on remote-content windows (WR-07, anti-phishing)

**Source:** `tauriCreateNewWindow`, L66-91, the `WR-07` comment (L74-81) — omitting `title` lets
the loaded document's own `<title>` show, preventing an attacker page from presenting itself
under `'GameLib'`. Applies to the login window (loads real humblebundle.com / Epic / GOG /
Amazon content) but NOT to any first-party static page this phase might add (contrast with
`showAboutWindowAsync`'s deliberate `title: 'About GameLib'` at L146, which is correct because
`about.html` is first-party static content, not remote).

### 6. `on_page_load`, never `on_navigation`, for any navigation-driven relay

**Source:** RESEARCH.md Pattern 4 / Pitfall 2 — `on_navigation` fires for every iframe
(measured: 5 of 8 events on the real Humble page were third-party iframes), which would let an
ad iframe re-arm `notifyLoginNavigated()`'s `forceRevalidate()` deadline indefinitely, defeating
the existing `LOGIN_WATCH_TIMEOUT_MS` budget (`user.ts` L62). Use `.on_page_load` (Started/
Finished, main-frame-only) for the OAuth-code-capture relay and any Humble navigation signal.

### 7. Domain-suffix cookie filter, never `cookies_for_url()`

**Source:** RESEARCH.md Pattern 2, reproduced above under the `main.rs` entry — `cookies()` +
manual `==`/`.ends_with(".domain")` filter. `cookies_for_url()` is confirmed (spike 014a,
cross-verified against `wry-0.55.1/src/wkwebview/mod.rs:1184`) to silently drop
`_simpleauth_sess` via exact-string domain equality. Apply to EVERY cookie read this phase does:
login detection (`checkCookie`) and the D-08 disconnect clear.

### 8. Liveness-proof cookie-read discriminator (never bare `count === 0`)

**Source:** RESEARCH.md Pattern 3, reproduced above under the `user.ts` entry. Apply to
`checkCookie()`'s replacement — classify every read as proved-live-once (`everProvedLive`) vs.
`UNDECIDABLE` (first-ever read, empty), never silently treat empty-on-a-live-API the same as
empty-because-unsupported (the `navigator-clipboard-noops-under-tauri` failure shape).
