# Plan 34.4.1-34 — D-29-08 and D-29-06: give the two unassigned findings owners

**Wave 2. No code. The deliverable is ownership, which is the thing both items actually lack.**

## Why a plan exists for this at all

`grep -rl "34\.4\.1" .planning/todos/` is **empty in both `pending/` and `completed/`**. All ten
`D-29-*` findings live only in `deferred-items.md`, which carries **no frontmatter** — so it is
invisible to `gsd-sdk query audit-uat` *and* to the explorer's folder rollup. Two of the findings
have no owner at all.

`deferred-items.md` states the rule against itself: *"A carry-forward without an owning plan that
declares the file is a note, not a task."* Notes rot. This plan converts two of them into tracked
items.

## Task 1 — D-29-08: record Epic logout as ORPHANED, then re-home it

The finding names **Phase 34.5** as owner. That is no longer true, and the evidence is dated:

| claim | evidence |
|---|---|
| 34.5 does not own it | `34.5-26-SUMMARY.md:316` — *"The Epic logout path … was NOT specifically re-exercised by this plan … not independently live-verified here."* |
| 34.6 inherited only the login/save-sync legs | 34.6's ROADMAP scope names *34.5 UAT test 11 (Epic login from scratch)* and *test 12 (`egsSync`)*. Logout is absent. |
| 34.7 cannot own it | ON HOLD; its premise died and it owes Phase 35 nothing. |
| nothing else references it | `clearEpicCookies` appears in **no phase folder except 34.4.1's own**. |

Write a todo at `.planning/todos/pending/2026-08-23-epic-logout-cookie-clear-unobserved-and-unowned.md`.

**The blocker must be greppable, not a category word.** Name `clearEpicCookies`, the shared Rust arm
it calls, and the precise condition that would discharge it: *an authenticated Epic session exists
and a logout is driven live, producing a `clearEpicCookies` count line*.

Preserve the epistemics exactly. The structural argument is sound — Epic's logout calls the **same**
arm Humble's disconnect proved fixed — but it is **an inference from shared code, not a
measurement**, and that is precisely the distinction that let run 2's failure hide behind a fully
green suite. **No document may describe Epic's logout as verified on this basis.**

Then propose an owner in ROADMAP. If the right owner is 34.6 (which already holds the live Epic
surface), say so and add it to 34.6's inherited list explicitly — do not assume the inheritance
already covered it, because it demonstrably did not.

This is the `blocker-records-rot-silently` shape, third recurrence. **Diff the dates** when writing
the record: the finding is 2026-07-31, the descope 34.5→34.7 and the re-home to 34.6 are later.

## Task 2 — D-29-06 / F-9: assign it, and preserve the methodological correction

`[shell] response for unknown/timed-out id=1575 (dropped)` — a request timed out, was abandoned, and
its response arrived to find no waiter. `keyring:timeout` specifically did **not** fire.

Write a todo at `.planning/todos/pending/2026-08-23-f9-generic-rpc-timeout-cooccurrence-undetermined.md`.

Record, without softening:

- **The contract's specific question — did it co-occur with a cookie operation — is UNDETERMINED,
  and is recorded as such rather than rounded to "no".** `id=1575` carries no channel name;
  answering it requires locating the request that opened that id in the same scrollback.
- **The transferable correction:** this was first recorded as *"F-9 watch CLEAN"* on the strength of
  a `gamelib.log` grep. **That grep could not have seen it — shell `eprintln!` never reaches the log
  file. A clean grep of the wrong source is not evidence of absence.**

Name what would settle it: capture the full shell scrollback (not `gamelib.log`) across a run that
exercises a cookie operation, and correlate `id=` values.

`REQ-34.4.1-GAP-11` is the related observability requirement and is being un-checked by plan 30 —
cross-link the two so the requirement and the todo cannot drift apart.
