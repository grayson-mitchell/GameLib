<objective>
Make item 3(b)'s domain-scope claim **observable**, and stop the reveal log misreporting its own
transport.

Purpose (F-5): item 3(b) — "prove the clear was domain-scoped, not a blanket wipe" — was recorded
BLOCKED-UNOBSERVABLE before the gate ran, for three traced reasons: `humble_login_cookies`
requires a live window label (`main.rs:1003-1005`) and `disconnect()` closes its window
unconditionally, so no label survives the operation; the only `readCookies` call site hardcodes
`host: 'www.humblebundle.com'`, `names: ['_simpleauth_sess']`, so no other domain can be queried;
and `total` — computed in Rust at `main.rs:1007` and carried to `classifyCookieRead` — **never
reaches `gamelib.log`**, because the `SUPPORTED_BUT_EMPTY` branch returns silently and neither
warning string interpolates it.

**A fix for F-6 that cannot be verified re-creates this exact problem.** Plan 16 just made the
disconnect do much more; without this plan, the gate can no more prove the new behavior than it
could prove the old.

Purpose (F-8): `humble/library.ts:1190-1198` stamps the literal `"electron-net transport"`
unconditionally. Under Tauri the request goes through the seam, so the line misreports it — and
its own adjacent comment states its purpose was to make the next log capture *unambiguous about
which transport ran*. It now achieves the opposite, and it cost real time during the gate to rule
out.

Output: a paired before/after cookie-jar census taken from INSIDE the clear step, and a transport
label derived from the seam at the moment of logging.

**The instrument this plan builds is the one plan 20's gate item 3(b) reads.** Building it in a
run-and-record plan was explicitly declined at gate time because the new code would itself be
unproven; here it lands ahead of the gate, with unit proof, which is the correct ordering.
</objective>

<interfaces>
The read that makes a census possible — already returns exactly what is needed
(`src/backend/humble/loginWindowSeam.ts:39-42`):
```
interface LoginWindowCookieRead {
  total: number                    // the UNFILTERED jar size — the liveness proof
  matched: LoginWindowCookie[]     // the subset passing the caller's domain-suffix + name filter
}
```
`total` is already computed in Rust (`main.rs:1006-1007`, `window.cookies()` then `all.len()`).
Nothing new is needed from Rust — the number exists and is simply never surfaced.

**The census arithmetic, which is the whole proof.** Taken inside the clear step while the window
is still open, with a domain filter of `humblebundle.com` and an EMPTY name filter (so `matched`
counts every Humble cookie, not just `_simpleauth_sess`):
```
before: { total: T0, matched: M0 }
   ...clear runs, reports D deleted...
after:  { total: T1, matched: M1 }

domain-scoped  <=>  M1 == 0  AND  (T0 - T1) == M0  AND  D == M0
```
The middle equality is the load-bearing one: it says the jar shrank by EXACTLY the number of
Humble cookies, so nothing else was removed. A blanket `clear_all_browsing_data()` would give
`T1 == 0` and fail it immediately. The surviving non-Humble count `T1 - M1` is the positive
evidence item 3(b) wanted, obtained without ever naming or reading another origin's cookie —
which is why precondition 6's planted control cookie is no longer needed.

T-34.4.1-39 / T-34.4.1-34 discipline, unchanged and binding: **counts only.** Never a cookie name,
never a domain, never a value. The existing line
`Humble disconnect: cleared ${deleted} humblebundle.com cookie(s)` (`user.ts:819-820`) is the
register to match.

F-8's site (`src/backend/humble/library.ts:1185-1198`), with its own comment explaining the intent
the hardcoded literal now defeats:
```
// Round 6: "electron-net transport" is stamped into this line so the NEXT gamelib.log
// capture is unambiguous about which round's fix actually ran ...
logInfo(['Humble reveal: calling adapter (electron-net transport), csrfTokenPresent=' + ...])
```
The branch that decides the real transport is `humblePostRequest` (`humble/adapter.ts:267-275`):
seam present -> `humblePostRequestViaSeam`; seam absent -> `humblePostRequestViaElectronNet`.
