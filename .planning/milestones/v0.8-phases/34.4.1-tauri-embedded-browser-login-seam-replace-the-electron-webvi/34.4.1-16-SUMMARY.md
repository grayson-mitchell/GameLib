# Phase 34.4.1 Plan 16: Close F-6 (disconnect does not disconnect) on both paths Summary

**Both Humble's disconnect() and Legendary's logout() (Phase 34.5's file, a deliberate cross-phase edit) now run an independent `clearStorage()` wipeStep alongside the existing cookie clear under Tauri, closing the 5-vs-1 wipe-step asymmetry at the code level; `seamBranchParity.test.ts` was upgraded from a declared-gap registry to an enforced-parity guard whose two remaining permanently-open categories (`authCache`/`hostResolver`) now require a real in-source threat-ID comment to stay excused, and the guard was proven load-bearing by a temporary revert that turned it RED.**

## Accomplishments

- `humble/user.ts`'s `disconnect()` Tauri branch gained a second, independent `'clearHumbleStorage'` `wipeSteps` entry calling Plan 15's `seam.clearStorage(HUMBLE_BASE_URL, standardBrowserUserAgent())`. It is a SEPARATE array tuple (not folded into the cookie step) so the existing guarded loop keeps treating the two independently — a rejecting storage step never blocks the cookie step and vice versa. Only per-category counts are logged, never a key or value. 4 new tests prove: both steps run, a rejecting storage step still resolves `disconnect()` with the cookie step having run, a rejecting cookie step doesn't block the storage step, and only counts appear in any logger call.
- `storeManagers/legendary/user.ts`'s `logout()` — Phase 34.5's file, edited here deliberately per this plan's own scope note — got the identical fix: a second `'clearEpicStorage'` step calling `seam.clearStorage(EPIC_LOGIN_ORIGIN, ...)`. The unconditional credential-side cleanup (`configStore.delete('userInfo')` + `clearCache('legendary')`) is unchanged and still runs even when BOTH cookie and storage steps reject (new test asserts this explicitly). Electron's untouched five-step branch is unaffected (regression test still passes).
- Both call sites' new step calls `seam.clearStorage()` directly with **no** `seam.open()`/`seam.close()` — a genuine structural difference from the cookie step's shape: Plan 15's Rust arm (`humble_login_clear_storage`) opens and closes its own hidden window internally, so the call site never holds a window handle to leak. This is documented in-source at both sites.
- Both sites carry a new in-source paragraph (referencing T-34.4.1-73) declaring that `clearAuthCache`/`clearHostResolverCache` have no in-page JavaScript equivalent and are therefore DECLARED, not silently dropped — the accepted residual risk is a surviving HTTP-auth-cache or DNS-cache entry, neither of which carries a session.
- `seamBranchParity.test.ts` (Task 3) was upgraded from "declared gap" to "enforced parity": the 4 `storage`/`cache` `KNOWN_GAP` entries (2 categories x 2 sites) were deleted (the capability landed for real); `clearAuthCache`/`clearHostResolverCache` were reclassified into a new `DECLARED` registry whose entries are only honoured if `isDeclaredInSource()` finds BOTH the threat id and a category-naming term in the REAL source file on disk (never trusted from the test file alone) — the same discipline that caught `seam-parity-sweep.py`'s own vacuous id-only check during Plan 10's development. 4 new anti-vacuity cases prove `isDeclaredInSource()` rejects an unrelated comment, an id-only comment, and a term-only comment, and accepts only when both are present. `KNOWN_GAP` itself is left as an empty array (the mechanism stays live for any future dual-branch site) rather than deleted.
- **The guard was proven load-bearing, not merely written**: `clearHumbleStorage` was temporarily removed from `humble/user.ts`, `seamBranchParity.test.ts` was re-run and observed to fail RED (`drops: ['storage', 'cache']` where `[]` was expected, on the "every Electron-only category is either present in Tauri..." assertion), then the file was restored from a backup and `git diff` confirmed byte-identical to the prior commit. Re-running the suite afterward confirmed GREEN again (28/28).
- Full suite: `npm run test:ci` 176 suites / 3365 tests, all passing (was 173/3279 at the start of the gap cycle; net +3/+86 across this plan's 3 commits and the two prior plans in this wave). `npx tsc --noEmit` clean. `cd src-tauri && cargo test` 60/60 (no Rust change in this plan). `ported-channels-gate.py` and `--self-test` both exit 0. `git diff --stat -- .planning/IPC-PORT-INVENTORY.md` empty.
