## Decisions Made

- **`electronStub.app.userAgentFallback` derives its platform token from `process.platform`**, not a hardcoded macOS string, mirroring `constants/environment.ts`'s `isMac`/`isWindows`/`isLinux` convention — the sidecar runs on all three platforms even though this smoke was only exercised on macOS hardware. - **No `electronReachLedger.test.ts` change was needed.** `humble/userAgent.ts` was already present in the committed `BASELINE_ELECTRON_REACHING_MODULES` array and the `requiredModules` anti-degradation list (Phase 34.4 Plan 08) — this fix only populates a property on a module already tracked as electron-reaching; it introduces no new import edge. This is worth noting explicitly for plan 06's ledger sweep (per that plan's own scope) so it does not attempt a duplicate/redundant entry for this change.
- **Chrome/142.0.7444.52** was chosen to match the Electron 41.1.1 pairing already hardcoded in `humble/__tests__/user.test.ts`'s own fixture (this repo's pinned Electron version per `node_modules/electron/package.json`), rather than inventing a fresh version number.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `electronStub.app.userAgentFallback` was undefined, causing `standardBrowserUserAgent()` to throw under the sidecar**
- **Found during:** Task 4 (A4 smoke re-run, first live evidence after DEFECT 1/2 were fixed by the prior agent)
- **Issue:** `standardBrowserUserAgent()` (`humble/userAgent.ts:26-36`) reads `app.userAgentFallback` unconditionally and calls `.replace()` on it in its defensive fallback branch. `electronStub.ts`'s `app` object never defined this property, so it was `undefined`, and the very first sidecar call to this function threw `Cannot read properties of undefined (reading 'replace')`. This aborted the A4 smoke hook before `seam.open()` — and therefore before `WebviewWindowBuilder::build()` — was ever reached, which is why the smoke's first two live runs (diagnosed by the prior agent/orchestrator) produced a booted app with zero evidence in either direction.
- **Fix:** Added `stubUserAgentFallback()` to `electronStub.ts`, deriving a Chrome-shaped `Mozilla/5.0 (<platform-token>) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/142.0.7444.52 Safari/537.36` string with no `Electron/x.y.z` token (matching `standardBrowserUserAgent()`'s happy-path extraction regex directly), and assigned it to `app.userAgentFallback`. Platform token derived from `process.platform` (darwin → `Macintosh; Intel Mac OS X 10_15_7`, win32 → `Windows NT 10.0; Win64; x64`, else → `X11; Linux x86_64`).
- **Files modified:** `src/backend/sidecar/electronStub.ts`, `src/backend/humble/__tests__/userAgent.test.ts` (new)
- **Verification:** New `userAgent.test.ts` (3 assertions) passes; headless smoke (`GAMELIB_LOGIN_SEAM_SMOKE=1 node build/main/sidecar.js`) now emits a real `humble_login_open` rustInvoke frame with the correct UA string in its `args`, and `gamelib.log` shows `starting` with no `failed:`; live `pnpm tauri:dev` smoke (below) confirms end-to-end.
- **Committed in:** `2ddeb716c`
