<objective>
Close the two **code-side** items of this cycle's housekeeping set: `queryLocalFonts` throwing
unguarded under WKWebView, and the ~150 Steam artwork loads failing with `unsupported URL`.

Both are instances of the SAME class this cycle exists to sweep — a browser capability the code
assumes is present, which under WKWebView is not — and both have sat "unassigned" in the findings
register since the second gate.

**The artwork failure's cause is located and mechanical, not speculative.** `CachedImage`
(`src/frontend/components/UI/CachedImage/index.tsx:60-66`) rewrites any `http`-prefixed source to
`imagecache://${encodeURIComponent(src)}`. That scheme is registered by
`src/backend/images_cache.ts:17`'s `protocol.handle('imagecache', …)` — **Electron's protocol API,
called from an Electron `whenReady()` init**. Project memory `phase-33-complete` records that
Electron `whenReady()` inits are **NOT auto-run in the sidecar**, so under Tauri the scheme is never
registered and WKWebView rejects every such URL as `unsupported URL`. The percent-encoding in the
observed failures is `encodeURIComponent`'s output at line 64 — it is a symptom of the wrapping, not
the cause. Every game tile with http art produces one failure, which is why the count is ~150.

The component then recovers: `onError` flips `useCache` to `false` and retries the real URL
(`:41-44`). So the user mostly sees art eventually — at the cost of a doubled request per tile, a
visible load flash, and ~150 console errors that made the gate's logs materially harder to read.
**It also means a green suite and a working-looking app have coexisted with a completely dead cache
path for the whole Tauri port**, which is the same silent-degradation shape as
`navigator.clipboard`.

**`queryLocalFonts`** (`src/frontend/screens/Accessibility/index.tsx:63`) is Chromium-only and
**throws** under WKWebView (project skill `references/tauri-chromium-only-web-apis.md`). The call
sits in `getFonts()`, which is invoked from a `useEffect` with no `.catch`, so the throw becomes an
unhandled rejection and the font list is never populated. `src/common/typedefs/dom-additions.ts:3-8`
declares the API ambiently — which is precisely why the unguarded call type-checks and `tsc` has
never objected.

**The stale-guard landmine this plan must not step on.** Phase 34.4's gate item 2 failed on a stale
`isTauri()` guard that a fully-green suite could not see; the codebase carries a dedicated
regression test for that exact shape (`src/frontend/state/__tests__/GlobalStateSteamLogout.test.ts`,
which greps the real source for `isTauri(`). So this plan does **not** sprinkle another renderer-side
platform sniff into `CachedImage`. It introduces ONE named predicate,
`imageCacheSchemeAvailable()`, next to `isTauri()` in `src/preload/tauriTransport.ts`, whose doc
comment names `images_cache.ts`'s registration as the single source of truth — so if a Tauri-side
handler ever lands, exactly one line changes.

**Adjacent already-present code this plan verifies (binding constraint 1).** Three things here are
present and have never been checked: (a) `CachedImage`'s bounded fallback chain
(`nextIndex < fallbacks.length`, commented "never loops") has only ever been exercised on a path
where the FIRST attempt always failed — this plan removes that always-failing first attempt under
Tauri, so the chain's behaviour changes and must be re-asserted; (b) `dom-additions.ts`'s ambient
declaration, which hides the hazard from `tsc` and needs to say so; (c) `getFonts()`'s effect, which
must still install the two default fonts when the API is unavailable rather than leaving an empty
picker.

Output: a font picker that degrades instead of throwing, an image path that stops requesting an
unregistered scheme, and one named place where the `imagecache://` decision lives.
</objective>

```
const currentSource = fallbackIndex < 0 ? props.src : fallbacks[fallbackIndex]
const src = useCache && currentSource
  ? `imagecache://${encodeURIComponent(currentSource)}`
  : currentSource
```
`useCache` is initialised from `props.src?.startsWith('http')` (`:27`) and reset on every `props.src`

never loops.

**The scheme's only registration (`src/backend/images_cache.ts:17,25`):**

protocol.handle('imagecache', (request) => { … })

Electron's `protocol` API, from an Electron-only init path.
