## This plan mis-specified its own item 2

Items 2(a)/(b)/(c) ask what the **title bar** shows. On macOS the login window is an AppKit sheet,
and `main.rs:1551` states it outright: *"AppKit sheets structurally render NO title bar UI at all,
so that string is never user-visible on macOS (F-34.5-G6-16)."*

**This is the same defect class as run 3's item 3(b)** — a contract requiring an observation its own
setup makes impossible — **written the day after unstriking precondition 6 for exactly that
reason.** Scoring 2(a) as "PASS, `Tauri app` never appeared" would have been a pass covering a
surface that cannot render at all.

The operator saw the **designed replacement**: the login-sheet origin banner (Phase 34.5 Plan 52),
which exists *because* sheets have no title bar. It showed the origin from the very start —
`origin banner updated len=28`, and `len("https://www.humblebundle.com") == 28`.

**Consequence: D-29-05 can never be closed on macOS**, and plan 33's fix is unobservable here — it
sets an `NSWindow` title macOS never renders. Still correct for Windows/Linux, which is now the only
place its live half can close. **Re-scoped, not passed.**

## New finding — filed as a todo, not a D-29 item

A newly-synced Humble key cannot be claimed until you navigate away and back. `refreshAnnotations()`
has three call sites — mount (`[]` deps), claim-wizard close, undo — and **none fires on a sync**, so
`humble.keys` gains the key while `annotations` stays at its mount-time snapshot and
`keyindexResolved ?? false` disables Claim. Backend was correct throughout (`gamekeys=32
keysCached=32`). **An incomplete fix of a defect already known on this exact map**, and the same
family as D-29-01 on a different surface.
