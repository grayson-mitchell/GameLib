<objective>
Fix the root cause behind G-30-02's rehydrated-install failure mode: replace
`SteamUser.ensureConnected()`'s blind fast-path (trusts any truthy `client.steamID` without
revalidating a possibly half-open socket) with a bounded canary probe that, on failure, calls
steam-user v5.3.0's purpose-built `client.relog()` and awaits a bounded reconnect — so a
store-rehydrated library whose connection went stale by Install time reconnects and the install
proceeds. Also run the D-01a gap-audit confirming every PICS await on the install path stays
`withTimeout`-bounded.

Purpose: 30-07 bounded the awaits so a stale CM can no longer hang forever, but the fixed
constraint (D-02) is that the rehydrated install must *succeed*, not merely fail fast. `relog()`
tears down the half-open socket (its own bounded 4s fallback) and reconnects with the stored
refresh token, no user interaction (33-RESEARCH verified against installed steam-user source).

Output: Self-healing, always-bounded `ensureConnected()` + unit tests. Runs in parallel with
Plan 33-01 (no file overlap); together they constitute the G-30-02 fix proven live in Plan 33-05.
</objective>
