## Deviations from the plan's stated file placement (both auto-fixed, Rule 3)

1. **Split into new sibling files, not the same file the plan named.** Both `index.tsx` files
   this plan touches transitively or directly import `.scss` (`ThemeSelector/index.tsx`
   imports the UI barrel `frontend/components/UI/index.tsx`, which pulls in several `.scss`
   files; `SideloadDialog/index.tsx`'s own first line is `import './index.scss'`). This
   project's jsdom-less jest config (`src/frontend/jest.config.js`, no `.scss`
   transform/moduleNameMapper) cannot parse a `.scss` import, so a test file importing
   anything from either `index.tsx` fails immediately with "Jest encountered an unexpected
   token" before any assertion runs. Extracted the pure, `t`-parameterized retrofit logic into
   two new SCSS-free sibling modules — `ThemeSelector/themeLabels.ts` and
   `SideloadDialog/filters.ts` — which the new test files import directly, and which each
   `index.tsx` imports and re-exports/calls unchanged.
2. **ThemeSelector's tuple table does not gate-trace with `gamelib:`-prefixed keys.**
   `meta/hardcodedStringGate.ts`'s Pattern 2 `[key, defaultText]` tuple exemption (the
   CrossoverBadge.tsx idiom this plan's `<read_first>` named) requires its first tuple element
   to match `DOTTED_KEY_RE`, which rejects the `gamelib:` namespace-prefix colon this plan's
   own key convention requires. Caught by running `scanSource()` directly against
   `themeLabels.ts` (not just `npx jest` green) — 28 violations on the first attempt.
   Reworked `resolveThemeLabel` into a 14-case `switch` with direct, literal
   `t('gamelib:themeSelector.<slug>', '<English>')` call sites (Pattern 1, no key-shape
   requirement), and `defaultThemes` into a `Record<string, true>` (key set unchanged, no
   string values at all). Re-verified: 0 violations, 28 exempted.
