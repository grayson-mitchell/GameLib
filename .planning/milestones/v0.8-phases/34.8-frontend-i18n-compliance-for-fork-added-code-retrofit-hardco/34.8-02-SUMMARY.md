## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `__dirname` resolved to `process.cwd()`, not `meta/`, under the esbuild-bundle-pipe-to-node execution mode**

- **Found during:** Task 2 (first `pnpm gen-i18n-gate-scope` run)
- **Issue:** The CLI wrote its output via `join(__dirname, 'i18nGateScope.json')`. Because this script runs as `esbuild --bundle ... | node` (piped through stdin, per the `meta/` convention), Node's `__dirname` in the bundled output resolved to the process's current working directory (the repo root) rather than the source file's `meta/` directory. The first run produced `./i18nGateScope.json` at the repo root instead of `meta/i18nGateScope.json`.
- **Fix:** Changed the output path to the repo-root-relative `join('meta', 'i18nGateScope.json')`, since `pnpm gen-i18n-gate-scope` always runs from the repo root. Added a comment recording the measured behavior so a future editor doesn't reintroduce `__dirname` here. Deleted the stray root-level file and re-ran the generator to confirm it now lands in `meta/`.
- **Files modified:** `meta/genI18nGateScope.ts`
- **Verification:** Re-ran `pnpm gen-i18n-gate-scope`; confirmed `meta/i18nGateScope.json` exists and `./i18nGateScope.json` does not; re-ran the full `genI18nGateScope` test suite (9/9 green) and `git status --porcelain .github/ public/locales/ src/` (empty).
- **Committed in:** `5b478e620` (Task 2 commit)
