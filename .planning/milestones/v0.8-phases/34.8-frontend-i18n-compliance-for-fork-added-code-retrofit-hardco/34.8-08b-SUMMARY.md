## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `GameStatus.tsx`'s deeply-nested multi-line template literal did not gate-trace**
- **Found during:** Task 1, re-verifying gate compliance by running `scanScope()` directly against the real committed scope (not trusting `npx jest`/`tsc` green alone — the exact lesson plans 07 and 08a's own deviations already recorded, now confirmed a third time)
- **Issue:** The plan's `<action>` text showed the ETA fragment retrofitted as a `t()` call nested three template-literal levels deep (an outer `` `${...}` ``, containing a ternary, containing an inner `` `${percent}% [${bytes}] ${...}` ``, containing the `t()` call's own multi-line object argument). This compiled clean (`tsc --noEmit`) and ran correctly (`jest` green), but `scanScope()` flagged two garbled multi-line "argument" literals at the outer template's boundaries (e.g. `"% [] }', {` spanning several source lines) — a scanner AST-tracing gap triggered specifically by this deeply-nested, multi-line shape, not a real violation.
- **Fix:** Extracted the ternary + `t()` call into a standalone local `etaText` binding, computed before the template literal, so the template itself collapsed back to a single flat interpolation (`` `${percent}% [${bytes}] ${etaText}` ``) and the `t()` call became a direct, single-line, non-nested argument.
- **Files modified:** `src/frontend/screens/Game/GamePage/components/GameStatus.tsx`
- **Verification:** Direct `scanScope()` run: 0 violations for this file (down from 2 spurious + would-have-been 1 real). `npx jest --selectProjects Frontend`: unaffected, still green.
- **Committed in:** `3877167cb`

**2. [Rule 1 - Bug] `LibraryFilters/index.tsx`'s dead `RunnerToStore.sideload` entry kept the original violation flagged**
- **Found during:** Task 2, re-running `scanScope()` after implementing the plan's literal `<action>` instruction (special-case sideload in the ternary, "leave `RunnerToStore` itself... untouched")
- **Issue:** Following the plan's `<action>` text verbatim left `sideload: 'Other'` in `RunnerToStore` even though the new ternary makes that branch unreachable at runtime (sideload is intercepted before the lookup). The scanner flags every string-literal object property of an object it can see flowing into any `t()` call elsewhere in the file, regardless of runtime reachability — so the exact original `"Other"` violation stayed flagged, unchanged.
- **Fix:** Removed the now-dead `sideload` key from `RunnerToStore` (verified via `npx tsc --noEmit` that the ternary's `else`-branch narrows `store`'s type away from `'sideload'`, so `RunnerToStore[store]` still type-checks). The five real store-name mappings (Epic Games/GOG/Amazon Games/ZOOM Platform/Steam) are byte-unchanged — this is dead-code removal, not a restructuring of the map's purpose, and stays within this plan's own file scope.
- **Files modified:** `src/frontend/components/UI/LibraryFilters/index.tsx`
- **Verification:** Direct `scanScope()` run: 0 violations for this file. `npx tsc --noEmit`: clean.
- **Committed in:** `4393f62d9`

**3. [Rule 1 - Bug] `App.tsx`'s multi-line `t()` call broke an existing source-gate test regex**
- **Found during:** Task 2, running `npx jest --selectProjects Frontend` after the initial retrofit
- **Issue:** The first retrofit attempt wrote `<ErrorComponent message={t('gamelib:app.routeError', '...', { detail })} />` split across multiple lines (`<ErrorComponent` and `message=` on separate lines). `src/frontend/screens/Login/__tests__/index.test.tsx` has an unrelated pre-existing source-gate test (`RouteErrorSurface renders ErrorComponent...`) that asserts `expect(source).toMatch(/<ErrorComponent message=/)` against `App.tsx`'s raw source text — a literal substring match that requires both tokens on the same line.
- **Fix:** Extracted the translated message to a local `message` binding computed before the return, then wrote `return <ErrorComponent message={message} />` as a single line — satisfying both the gate (a direct, single-line `t()` argument) and the pre-existing source-gate test.
- **Files modified:** `src/frontend/App.tsx`
- **Verification:** `npx jest --selectProjects Frontend --testPathPattern="Login/__tests__/index.test.tsx"`: 17/17 green (was 1 failing). Full `npx jest --selectProjects Frontend`: 45/45 suites, 540/540 tests green.
- **Committed in:** `4393f62d9`
