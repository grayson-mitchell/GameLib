## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `window.api.logInfo`/`logError` diagnostic-log arguments were flagged as user-facing violations**

- **Found during:** Task 2, while measuring `useTauriOAuthLogin.ts` — the plan's own read_first stated an expected count of exactly 2, but the pre-fix scanner produced 19, 17 of which were `window.api.logInfo(...)` diagnostic log-line arguments.
- **Issue:** `isConsoleArgument()` only recognized the global `console` identifier. This codebase's Tauri sidecar swallows `console.*` output (memory: `sidecar-console-and-logger-are-invisible`), so 26 of the 134 in-scope frontend files use `window.api.logInfo`/`logError` instead — an equivalent, developer-facing diagnostic channel, never rendered to a user.
- **Fix:** Added `isWindowApiLogArgument()` — matches a call whose callee is `window.api.<logMethod>` (any method name starting with `log`) — and wired it into `isStructuralNonCandidate()` alongside `isConsoleArgument()`.
- **Files modified:** `meta/hardcodedStringGate.ts`, `meta/__tests__/hardcodedStringGate.test.ts`
- **Verification:** Re-measured `useTauriOAuthLogin.ts` after the fix: 2 violations (matches the plan's exact prediction). 2 new regression tests added (`logInfo` and `logError`). Full `meta` jest project green (234/234) both before and after.
- **Committed in:** `299688446` (Task 1 commit)

**2. [Rule 1 - Bug] CSS values nested inside a `style={{}}` JSX attribute were flagged as `object-property` violations**

- **Found during:** Task 2, while measuring `SteamLogin/index.tsx` — the pre-fix scanner produced 91 violations against a research estimate of ≈26-28, with ~64 of them CSS custom-property/unit values (`var(--text-lg)`, `'2em'`, `'8px'`) inside inline `style={{ ... }}` objects.
- **Issue:** `getEnclosingJsxAttributeName()` only recognizes a literal used DIRECTLY as an attribute value (`title="text"` / `title={'text'}`). React's `style` attribute is always an object literal, so every CSS value nested inside it fell through to the generic `object-property` classification meant for real config/prose objects (`{ message: 'Repair failed.' }`), never reaching the JSX-attribute exclusion path at all.
- **Fix:** Added `isStyleAttributeValue()` — walks up to the nearest `JsxAttribute` ancestor and discards if its name is `style` — wired into `isStructuralNonCandidate()`. Also added `'style'` to `EXCLUDED_ATTRIBUTES` for defense-in-depth on any future direct-string case.
- **Files modified:** `meta/hardcodedStringGate.ts`, `meta/__tests__/hardcodedStringGate.test.ts`
- **Verification:** Re-measured `SteamLogin/index.tsx` after the fix: 27 violations (within the research session's ≈26-28 estimate). 2 new regression tests added, including a negative case proving a sibling `title` attribute on the same JSX element still flags (the exemption is scoped to `style` only, not a blanket "if this element has a style prop" hole). 17/134 scope files use inline `style={{}}`. Full `meta` jest project green (234/234) both before and after.
- **Committed in:** `299688446` (Task 1 commit)
