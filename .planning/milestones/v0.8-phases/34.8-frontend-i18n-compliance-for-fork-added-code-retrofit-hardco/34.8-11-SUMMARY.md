# Phase 34.8 Plan 11: Machine-fill script -- backend + provenance + bulk-run refusal Summary

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A literal NUL byte landed in `buildTranslationMemory`'s dedupe-key template literal**
- **Found during:** post-Task-2 verification, running `git add`/`git commit` for Task 2 -- the commit diff showed `meta/machineFillGamelib.ts | Bin 15359 -> 27109 bytes` instead of a normal line diff, and `file meta/machineFillGamelib.ts` reported `data` (binary) instead of `ASCII text`/`UTF-8 text`.
- **Issue:** A `\x00` byte (not the intended plain space) was present in the source at `` `${enValue}\x00${targetValue}` ``, most likely a tool-transcription artifact from the earlier `Write` call rather than anything I typed literally. This made git treat the entire file as binary (no line-level diffs, `Bin ... bytes` summaries), which would have made every future diff on this file opaque and unreviewable, and could confuse any downstream tool that assumes source files are text.
- **Fix:** Located the byte offset with a Python byte-scan (`data.index(b'\x00')`), confirmed it was the single occurrence in the file, and replaced it with a plain space via a direct byte-level rewrite. Behavior is unaffected -- the string is only used internally as a `Set`-based dedupe key for `buildTranslationMemory`'s result list, never rendered or written to a catalog.
- **Files modified:** `meta/machineFillGamelib.ts`
- **Verification:** `file meta/machineFillGamelib.ts` now reports `ASCII text`; `git diff --stat -a HEAD -- meta/machineFillGamelib.ts` (before the fix commit) showed a normal `+`/`-` line diff instead of `Bin`; re-ran the full 24-test hermetic suite (24/24 green) and `npx tsc --noEmit` (clean) after the fix; `git diff --stat 3c61bc188 HEAD -- meta/machineFillGamelib.ts` against the pre-plan baseline now shows a normal `748 insertions(+)` text diff.
- **Committed in:** `6795179e5`

## Known Limitations (documented, not defects)

- **The six `redeemKey.*` keys with an empty English catalog default are not yet fillable by this script.** `collectMissingKeys` deliberately excludes any key whose `en/gamelib.json` value is itself the empty string (their real default lives in an inline `t(key, 'Default')` call in source, per plan 09's own documented, expected shape) -- there is no English text to translate FROM. Backfilling these would require a separate mechanism to extract inline `t()` defaults into the catalog first; out of this plan's scope, and does not block D-08's "build the script" bar since it correctly handles the empty-source case (skip, don't crash, don't mistranslate) rather than silently producing garbage.
- **A live, real Anthropic API translation run was never executed in this plan, by design (D-08).** The script is proven at the pure-logic layer (24 hermetic tests) and at the CLI-refusal layer (three live runs, transcripts above), but the actual `createAnthropicTranslator` HTTP call path has not been exercised against the real API in this environment -- the ambient `ANTHROPIC_API_KEY` in this sandbox returned `invalid x-api-key` against `api.anthropic.com/v1/models` when probed for model-ID research, so it is not a working credential here. Bulk-filling (or even a single real locale fill) remains the deliberately separate, revertible follow-up commit D-08 describes, runnable by a developer with a working key.
