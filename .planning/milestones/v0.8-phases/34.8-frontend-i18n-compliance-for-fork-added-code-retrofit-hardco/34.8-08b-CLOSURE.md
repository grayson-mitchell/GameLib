## The two developer-judgement items, decided

### `WineVersionSelector.tsx:208` — whole `<li>` vs. annotation-only

The audit left this open as BORDERLINE: a filesystem path with a real English parenthetical
annotation, unlike its sibling bare-path `<li>` items. Two options were offered:

- (a) retrofit the whole `<li>` text as one key
- (b) extract only the `(Steam Flatpak)` annotation, leaving the path as a literal

**Decision: (a), the whole line as one key** (`gamelib:settings.wineFlatpakPath`). Option (b) was
attempted first and rejected: splitting the JSX text into `~/.var/app/com.valvesoftware.Steam (` +
`{t(...)}` + `)` produced a **new residual `jsx-text` violation** for the leading path+paren
fragment (`~/.var/app/com.valvesoftware.Steam (` — a distinct AST node from the original combined
string, and not itself glossary-exempt or dataflow-exempt). Retrofitting the whole `<li>` as a
single `t()` call avoids fragmenting the JSX text entirely, matches the audit's original
single-node measurement, and reaches zero violations cleanly. Verified via a direct `scanScope()`
run after the switch: 0 residual for this file (excluding the unrelated pre-existing
`not-user-facing` `-latest` item at line 50).

### `Settings/index.tsx:29` — `defaultWineVersion`'s `'Wine Default'`

Per the plan's `<read_first>` fan-out instruction, ran
`git grep -n "defaultWineVersion" -- src/frontend` before touching anything. Result: **14 files**
outside this plan's `files_modified` consume `defaultWineVersion` as a typed fallback default for
`useSetting('wineVersion', defaultWineVersion)` (`AdvertiseAvxForRosetta.tsx`, `AutoDXVK.tsx`,
`AutoDXVKNVAPI.tsx`, `AutoVKD3D.tsx`, `CrossoverBottle.tsx`, `DisableUMU.tsx`,
`EnableDXVKFpsLimit.tsx`, `EnableMsync.tsx`, `PreferSystemLibs.tsx`, `SteamRuntime.tsx`,
`WinePrefix.tsx`, `WineVersionSelector.tsx`, `sections/GamesSettings/index.tsx`,
`sections/SyncSaves/index.tsx`).

Read `WineVersionSelector.tsx` (this plan's own file) to check whether `.name` genuinely reaches
the DOM as visible text, not just an internal comparison: confirmed YES —
`value={wineVersion.name}` is the `SelectField`'s displayed selected value, and every
`<MenuItem>` renders `WineVersionListItem`, whose `substitutedName` is derived directly from
`version.name`. When no real Wine version is configured yet (the exact case `defaultWineVersion`
exists to cover), `'Wine Default'` is rendered literally in the UI — this is not a hypothetical,
it is the confirmed rendering path.

**Decision: `blocked`.** Converting `defaultWineVersion` from a plain constant into a
`t()`-requiring function/hook call would require editing all 14 consumer files, none of which are
in this plan's assigned `files_modified` — doing so would also break the disjoint-`files_modified`
guarantee `34.8-08a`/`34.8-08b`'s parallel-execution split relies on. No partial or out-of-scope
fix was attempted. `Settings/index.tsx` was not edited at all by this plan.
