## Accomplishments

- `meta/hardcodedStringGate.ts` gained a declaration-scoped sibling of the existing whole-file
  `FILE_EXEMPT_MARKER` mechanism: `getEnclosingTopLevelStatement()` walks a candidate node's
  ancestors to its enclosing top-level statement, and `checkDeclarationExemptMarker()` checks that
  statement's own leading comment for the marker plus a same-line reason — wired into `record()`
  immediately after the existing `fileExemptResult` check, never setting `result.fileExempt` (that
  field still means "the whole file is exempt," unchanged for `34.8-10-PLAN.md`'s own assertion)
- Extracted `commentRangesCarryExemptMarker()` as a shared helper so the file-scoped and
  declaration-scoped checks do not duplicate the marker/reason string-slicing logic
- 3 new fixtures in `meta/__tests__/hardcodedStringGate.test.ts`'s new `34.8-08c: declaration-
  scoped exemption marker` block: the positive case (marked declaration exempt, an unrelated real
  violation elsewhere in the same fixture source still flagged, `result.fileExempt` stays `false`),
  the bare-marker negative case (no reason on a non-first statement → not exempt), and the
  non-regression case (marker on the file's actual first statement still sets `fileExempt` `true`,
  proving the existing `bootErrorSurface.ts` behaviour is unchanged)
- `WineVersionListItem` (`WineVersionSelector.tsx`) gained its own `useTranslation('gamelib')`
  hook; when `name === defaultWineVersion.name` it now renders

  edit site, since MUI renders the matching `MenuItem`'s children as the selected-value display
  (no `renderValue` prop set). Every other `version.name` keeps the existing
  `Proton-GE-Proton`/`Proton-GE` → `GE-Proton` substitution, byte-identical to before this plan
- `Settings/index.tsx`'s `defaultWineVersion` declaration now carries the new declaration-scoped
  `i18n-gate-exempt:` marker with its reason on record; its `bin`/`name`/`type` values are

- Direct `scanScope()` run (not just `npx jest`) confirms zero violations for

## Decisions Made

- **Render-site fix over constant conversion.** The plan's `<objective>` had already selected
  this approach (the developer's decision, independently re-verified by the orchestrator before
  writing the plan). This plan's own execution re-confirmed the fan-out: `git grep -n
  "defaultWineVersion" -- src/frontend` still returns the same 14 out-of-scope consumers, and
  only `WineVersionSelector.tsx` (this plan's own file) renders `.name` as visible text — the
  other three consumers that read `.name` (`AutoDXVK.tsx`, `EnableDXVKFpsLimit.tsx`,
  `EnableMsync.tsx`) all do so only via `.endsWith('-DXMT')`, an internal comparison, never
  rendered.
- **Declaration-scoped exemption mechanism, reusing the existing marker string at a second
  granularity.** Both simpler alternatives (full-file exemption on `Settings/index.tsx`; an
  allowlist entry) were explicitly rejected by the plan's `<objective>` and `<constraints>`,
  and this plan implemented exactly the narrow mechanism specified: `getEnclosingTopLevelStatement`
  finds the top-level statement enclosing a candidate node, and the marker's placement (first
  statement vs. any other) determines whether the existing whole-file check or the new
  declaration-scoped check fires. No new marker string was minted — the same
  `i18n-gate-exempt:` text is now read at two granularities, documented explicitly so a future
  author is not surprised.
