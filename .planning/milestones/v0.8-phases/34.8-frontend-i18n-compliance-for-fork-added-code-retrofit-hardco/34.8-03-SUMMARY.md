# Phase 34.8 Plan 03: ts-morph Hardcoded-String Scanner Core Summary

**`meta/hardcodedStringGate.ts` — a pure ts-morph AST scanner (`scanSource()`) that collects JSX text/string/template literals, classifies their AST position, discards non-user-facing shapes (console args, thrown Errors, excluded attributes, technical tokens), and exempts exact glossary terms — proven correct in both directions by 50 jest tests, including the D-21/D-22 mechanical zero-violation proofs.**

## Accomplishments

- Built `scanSource(filePath, sourceText, config)` as a genuinely pure function: an in-memory ts-morph `Project` (`useInMemoryFileSystem: true`) parses the source, so the scanner never touches disk or network except `loadGlossary()`'s own fixed, overridable path — verified by grep (only 2 `readFileSync` occurrences total: the import and `loadGlossary`'s call site)
- Implemented the D-16-resolving INCLUDE/EXCLUDE scope as exported, documented constants (`USER_FACING_ATTRIBUTES`, `EXCLUDED_ATTRIBUTES`) rather than buried scanner logic
- Proved the gate can actually FAIL: a bare `<p>Steam client not found</p>` yields exactly one `jsx-text` violation — "the phase's central negative proof: a gate that cannot fail is worthless"
- Proved the gate never false-positives against `console.*` arguments, thrown `Error(...)` messages, comment/JSDoc prose, or 14 excluded/technical-token shapes (paths, URLs, hex colours, camelCase identifiers, `data-*`/`aria-*` attributes)
- Mechanically proved D-21 and D-22 with fixtures reproducing the real shapes from `ConsoleMode/index.tsx`, `LogSettings/index.tsx`, and `PlatformSupport.tsx` — all yield zero violations against the real, disk-loaded `meta/i18nGlossary.json`, with no code change needed in any of those three files
- Proved glossary matching is whole-string, not substring, via a dedicated near-miss test: `'Steam client not found'` and `'Amazon Games library'` each still violate; the isolated term `'Steam'` does not

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Glossary exemption was losing to the technical-token shape check for slash-containing glossary terms**

- **Found during:** Task 2, while writing the glossary-exemption `it.each` block over the real glossary's 17 terms
- **Issue:** Task 1's initial `shouldDiscard()` ran the technical-token check (which flags anything containing `/` with no whitespace as a "path") in the same pass as, and before, the glossary exact-match check. Glossary terms `MB/s`, `Epic/Legendary`, and `Amazon/Nile` were being silently discarded as path-shaped tokens before ever reaching the glossary comparison, so `ScanResult.exempted` was never incremented for them and the required `it.each` assertion (`exempted === 1`) failed for those three terms.
- **Fix:** Split the single `shouldDiscard()` into `isStructuralNonCandidate()` (position-based discards that must win regardless of text — console args, thrown-Error args, excluded attributes, import/export specifiers, literal type positions, object keys, enum member names, element-access keys) and a separate technical-token check, and reordered `scanSource`'s `record()` pipeline to: structural discard → contains-a-letter check → glossary exact match → technical-token shape → violation. This also required broadening the single-token discard rule from "camelCase with an internal case transition" to "any lowercase-leading, no-whitespace token," which is what makes D-21's ConsoleMode/LogSettings store-label-map fixtures (`{ key: 'legendary', label: 'Epic' }`) come out to zero violations: the internal `key` values (`legendary`, `gog`, `nile`, `steam`, `sideload`, `zoom`) are exempt by shape, and the display `label` values are exempt by glossary — while capitalized/multi-word real prose (`Unrated`, `Repair failed. See the log.`) is unaffected by the broadening and still flags correctly.
- **Files modified:** `meta/hardcodedStringGate.ts`
- **Verification:** Deliberately re-deleted the glossary-exemption branch after the fix and re-ran the suite — 20/50 tests failed as expected (proving the branch is load-bearing), then restored the file and re-ran — 50/50 passed again. Full `meta` jest project: 10 suites / 211 tests, all green. `pnpm codecheck` clean. Full `pnpm test:ci`: 199 suites / 3898 tests, all green (baseline was 198/3848 — this plan added exactly 1 suite / 50 tests, no regression).
- **Committed in:** `7090b8ba5` (Task 2 commit — the fix and the tests that necessitated it landed together, since the tests are what proved the bug)
