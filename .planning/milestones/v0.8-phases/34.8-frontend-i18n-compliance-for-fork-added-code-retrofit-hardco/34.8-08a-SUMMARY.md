## Decisions Made

- **Extracted-sibling-module pattern, not "same file" as the plan's `<action>` literally said:** Both `index.tsx` files (directly or transitively) import `.scss`, which this project's jsdom-less jest config (`src/frontend/jest.config.js`, no `.scss` transform) cannot parse — a test file importing anything from either `index.tsx` failed immediately with "Jest encountered an unexpected token" before any assertion ran. Extracted the pure, `t`-parameterized logic into new SCSS-free sibling modules instead, mirroring the extraction posture the plan's own `<interfaces>` section already required for the components themselves.
- **Switch-of-direct-`t()`-calls for ThemeSelector, not the CrossoverBadge tuple-table idiom named in `<read_first>`:** `meta/hardcodedStringGate.ts`'s Pattern 2 `[key, defaultText]` tuple exemption requires its first element to match `DOTTED_KEY_RE`, which rejects the `gamelib:` namespace-prefix colon. All three real committed fixtures of this pattern (`CrossoverBadge.tsx`, `LibraryFilters`, `stateLabels.ts`) use un-namespaced keys; none combines it with a `gamelib:`-prefixed key. Reworked to a switch of direct, literal `t()` calls (Pattern 1), which has no key-shape requirement and is already proven for every other `gamelib:`-namespaced call site in this codebase (`copy.ts`, `filters.ts`).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - blocking issue] `.scss`-importing `index.tsx` files are untestable under this project's jest config**
- **Found during:** Task 1, writing `ThemeSelector/__tests__/index.test.tsx` to import from `../index`
- **Issue:** `ThemeSelector/index.tsx` imports `{ SelectField, InfoBox, PathSelectionBox } from '..'` (the UI barrel), which transitively imports several `.scss` files; `SideloadDialog/index.tsx`'s own first line is `import './index.scss'`. Neither is parseable by this project's jsdom-less jest config (no `.scss` transform/moduleNameMapper — see `src/frontend/jest.config.js`'s own docstring on why jsdom is deliberately absent). A test importing anything from either `index.tsx`, even a non-rendering named export, fails on the `.scss` import before any test body runs.
- **Fix:** Extracted the pure, `t`-parameterized retrofit logic into new SCSS-free sibling modules (`themeLabels.ts`, `filters.ts`) in the same directory; each `index.tsx` imports from (and, for `ThemeSelector`, re-exports) the sibling module; each new test file imports the sibling module directly, never `index.tsx`.
- **Files modified:** `src/frontend/components/UI/ThemeSelector/index.tsx`, `src/frontend/components/UI/ThemeSelector/themeLabels.ts` (new), `src/frontend/screens/Library/components/InstallModal/SideloadDialog/index.tsx`, `src/frontend/screens/Library/components/InstallModal/SideloadDialog/filters.ts` (new)
- **Verification:** `npx jest --selectProjects Frontend ThemeSelector SideloadDialog`: 44/44 suites, 532/532 tests green
- **Committed in:** `c9a64d073`, `89f387246`

**2. [Rule 1 - Bug] ThemeSelector's `[key, defaultText]` tuple table did not trace as gate-exempt**
- **Found during:** Task 1, re-verifying gate compliance by running `scanSource()` directly against `themeLabels.ts` (not trusting `npx jest` green alone — the exact lesson plan 07's own deviation recorded)
- **Issue:** The first implementation built `defaultThemes` as a `Record<string, [key, defaultText]>` tuple table, mirroring `CrossoverBadge.tsx`'s `labelKeyByTier` idiom per the plan's `<read_first>`. `meta/hardcodedStringGate.ts`'s Pattern 2 tuple exemption requires the tuple's first element to match `DOTTED_KEY_RE` (`^[a-zA-Z][a-zA-Z0-9]*(\.[a-zA-Z][a-zA-Z0-9_]*)+$`), which does not accept a colon — so every `gamelib:themeSelector.<slug>`-keyed tuple entry (28 literals: 14 keys + 14 defaults) was flagged as a violation, not exempted.
- **Fix:** Reworked `resolveThemeLabel` into a 14-case `switch` with direct, literal `t('gamelib:themeSelector.<slug>', '<English>')` calls (Pattern 1 — direct call argument, no key-shape requirement), and `defaultThemes` into a `Record<string, true>` (key set unchanged for `src/frontend/index.tsx`'s external consumers; no string values at all, so no gate candidates remain in the lookup table itself).
- **Files modified:** `src/frontend/components/UI/ThemeSelector/themeLabels.ts`
- **Verification:** Direct `scanSource()` run: 0 violations (down from 28), 28 exempted. `npx jest --selectProjects Frontend ThemeSelector`: still green (14/14 copy-preserving + 14/14 sentinel-routing assertions unaffected by the internal implementation change).
- **Committed in:** `fee5c7a8b`
