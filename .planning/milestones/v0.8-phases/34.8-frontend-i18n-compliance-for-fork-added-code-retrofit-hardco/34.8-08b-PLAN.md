<!-- The call shapes and test idiom already established in this repo. -->

Inside a React component that already calls `useTranslation()` (every file in this plan except
`appleRating.ts` and `App.tsx`'s `RouteErrorSurface` does): add a SECOND, aliased hook call bound
to `gamelib` — `const { t: tGamelib } = useTranslation('gamelib')` — rather than repurposing the
existing `t`. This is deliberate, not stylistic: a component's `t` must have actually called
`useTranslation('gamelib')` somewhere in that component for the namespace to be subscribed and
fetched by `i18next-http-backend`; prefixing a `gamelib:` key onto a hook bound to a DIFFERENT
namespace risks the translation never loading even though the inline English default still renders
(the failure is invisible in English, only visible once a non-English locale exists). The
established precedent for a THIRD aliased hook in one component (when two already exist) is
`GamePage/index.tsx`'s own `t` (`'gamepage'`) + `t2` (default) pair — add a third alias there,
following the same pattern.

Inside a non-component module (no hook available) — the `repairFailure.ts` form, already adopted
by plan 07 for `copy.ts`: add `t: TFunction` as an explicit parameter and thread it from the
calling component. This is `appleRating.ts`'s shape.

Key convention: `gamelib:<feature>.<slug>`, `keySeparator: '.'`, `namespaceSeparator: ':'`. Every
call is TWO-argument `t(key, 'English default')`, never bare `t(key)`.

**Test infrastructure constraint:** this project has NO jsdom / react-test-renderer installed
(`src/frontend/jest.config.js`'s own docstring). Component tests invoke the function component
directly as a plain function and inspect the returned React element's prop object graph — no DOM,
no `render()`. `react-i18next` (and, where a component reads `useContext`, `react`'s `useContext`)
is mocked at the module level. `HumbleOriginInfo.test.tsx` is the reference pattern including the
`{{param}}`-interpolating mock `t`; `protonRating.test.ts` (a sibling of `appleRating.ts` in the
same directory) is the reference pattern for a plain, hook-free pure-function module. Most files in
this plan are stateful components (`useState`/`useContext`/`useEffect`) that CANNOT safely be
invoked this way — where a retrofitted violation lives inside such a component, prefer testing it
via a small extracted pure helper (the `appleRating.ts`/`repairFailure.ts` idiom) where one already
exists or is cheap to introduce; where it does not, note in the SUMMARY that the specific literal
is covered only by the gate's zero-violation proof (task 3), consistent with how every other
stateful component in this codebase is currently untested.

Namespace choice is NOT enforced by the gate (D-13) — but new fork strings go in `gamelib`, and
plan 09's D-05 no-churn assertion is the mechanical backstop that catches a mis-namespaced call
writing into an upstream catalog.
