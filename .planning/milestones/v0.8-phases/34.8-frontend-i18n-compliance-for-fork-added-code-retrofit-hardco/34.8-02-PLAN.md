<objective>
Produce the committed, versioned list of fork-owned frontend files that the enforcement gate
will scan, derived mechanically from the upstream Heroic merge-base (D-07), plus the offline CLI
that regenerates it.

Purpose: D-07 says fork-added code is identified by diffing against the Heroic merge-base. That
diff works locally (`origin` points at Heroic, merge-base `b5b5cad3fa2e822602d320b70788d87240fc056e`
is fetched and matches `package.json`'s `upstream.baseCommit`) but CANNOT run inside GitHub
Actions — `actions/checkout@v6` gives a shallow, single-remote clone with no Heroic remote and no
merge-base commit. So the diff runs offline and commits its output; the gate reads only the
artifact.

Output: `meta/genI18nGateScope.ts`, the generated `meta/i18nGateScope.json`, a `pnpm` script, and
tests over both the derivation filters and the committed artifact's freshness.
</objective>

    fork-added literals also live mixed into otherwise-upstream files, so an A-only scope

    `buildScopeSnapshot(opts)` assembles the `ScopeSnapshot` object exactly as declared in
    `<interfaces>`. It populates `excluded.deferred` with the two D-17 file paths
    (`src/frontend/screens/Login/components/SteamLogin/index.tsx` and

    The CLI half (guarded so the module stays importable by jest without side effects — mirror
    how `buildCrossoverIndex.ts` separates its pure exports from its entry point):

      - Invokes git with `execFileSync('git', ['diff', '--name-status', baseCommit, 'HEAD',

        array — never `execSync` with an interpolated shell string.
      - If git fails (the classic CI symptom is `fatal: invalid object name`), print a
        `::error::`-prefixed message that says the merge-base commit is not present in this
        clone, that this script is offline-only and must not be wired into CI, and exit 1.
      - Writes `meta/i18nGateScope.json` with two-space indentation and a trailing newline.
