### `src/frontend/components/UI/RedeemSteamKeyDialog/copy.ts` (retrofit target)

**Current file (verbatim, in full — this is what gets retrofitted):**
```typescript
// Source: src/frontend/components/UI/RedeemSteamKeyDialog/copy.ts:1-48
import { RedeemKeyOutcome } from 'common/types/steam'

export interface RedeemOutcomeCopy {
  message: string
  tone: 'success' | 'error'
}

export function redeemOutcomeCopy(
  outcome: RedeemKeyOutcome,
  packageName?: string
): RedeemOutcomeCopy {
  switch (outcome) {
    case 'success':
      return {
        tone: 'success',
        message: packageName
          ? `Key redeemed! ${packageName} has been added to your Steam library.`
          : 'Key redeemed! Your Steam library has been updated.'
      }
    case 'already-owned':
      return {
        tone: 'error',
        message: 'This key has already been redeemed — you already own this on Steam.'
      }
    // ... invalid, rate-limited, error cases follow the same shape
  }
}
```
This is a **plain module, not a React component and not a hook** — `redeemOutcomeCopy()` is a
pure function called from `RedeemSteamKeyDialog/index.tsx` (confirmed via graph:
`RedeemSteamKeyDialog() --calls--> redeemOutcomeCopy`). It has no access to `useTranslation()`.

**There is NO single established non-hook `i18next.t` idiom in this codebase — this is a real
planning gap, exactly as the task brief anticipated.** Two competing, both-real idioms exist:

**Idiom A — module-scope direct import (`GlobalStateV2.ts`), used for a one-off fire-and-forget
string, NOT parameterized by caller:**
```typescript
// Source: src/frontend/state/GlobalStateV2.ts:9, 100-113
import { t } from 'i18next'
// ...
window.api
  .refreshWineVersionInfo(fetch)
  .catch(() => {
    window.api.logError('Sync with upstream releases failed')
    notify({
      title: 'Wine-Manager',
      body: t(
        'notify.refresh.error',
        "Couldn't fetch releases from upstream, maybe because of Github API restrictions! Try again later."
      )
    })
  })
```
Risk for `copy.ts`: `redeemOutcomeCopy()` runs during React render/event-handling, potentially
before `i18next.init()`'s Suspense-gated namespace load resolves for a lazily-loaded `gamelib`
namespace — a bare `import { t } from 'i18next'` call is NOT guaranteed to have `gamelib.json`
loaded yet the way a `useTranslation('gamelib')`-driven component render is (Suspense blocks the
tree until the hook's namespace is ready; a direct `t()` import call has no such gate). This is
a genuine behavioral difference the planner must account for, not just a style choice.

**Idiom B — caller-supplied `TFunction` parameter (`repairFailure.ts`), used for logic that must
work identically regardless of caller/render context, with an EXPLICIT hardcoded-fallback
try/catch:**
```typescript
// Source: src/frontend/screens/Game/GameSubMenu/repairFailure.ts:1, 8-13, 76-81, 113-121
import { TFunction } from 'i18next'

interface ReportRepairFailureOptions {
  appName: string
  error: unknown
  showDialogModal: (options: DialogModalOptions) => void
  t: TFunction<'gamepage'>
}

export function reportRepairFailure({
  appName,
  error,
  showDialogModal,
  t
}: ReportRepairFailureOptions): void {
  // ...
  let title = 'Error'
  let message = 'Repair failed. See the log for details.'
  try {
    title = t('box.error.title', title)
    message = t('box.repair.error', message)
  } catch {
    // keep the hardcoded English fallback -- a throwing `t` must still
    // yield a rendered dialog
  }
  // ...
}
```
This idiom is a closer structural match for `copy.ts`: the caller (a React component that
already has `useTranslation('gamelib')`'s `t`) passes `t` in, `redeemOutcomeCopy()` becomes
`redeemOutcomeCopy(outcome, t, packageName?)`, and the existing hardcoded English strings become
the `t(key, defaultText)` calls' second argument — a mechanical, low-risk transform that requires
zero changes to `RedeemSteamKeyDialog/index.tsx`'s render-timing guarantees (it already has a
resolved `t` by the time it calls `redeemOutcomeCopy`).

**Recommendation for the planner:** Idiom B (caller-supplied `TFunction` param) is the safer
retrofit shape for `copy.ts` — it inherits the calling component's Suspense-resolved `t` rather
than racing `i18next.init()`. Idiom A remains valid precedent for genuinely module-scope,
render-independent strings (there are none of those in `copy.ts`). **This is a discretionary
call, not fully settled by existing precedent — flag it in planning.**

## Shared Patterns

### `meta/` script file shape (applies to `hardcodedStringGate.ts` and `machineFillGamelib.ts`)
**Source:** all 7 existing `meta/*.ts` scripts (`buildCrossoverIndex.ts`, `downloadHelperBinaries.ts`,
`verifyUpdaterSigningKey.ts`, `gen_vtables.ts`, `buildSteamBridgeShims.ts`, `buildRunnersOnedir.ts`,
`buildSidecarSea.ts`)
**Apply to:** both new `meta/*.ts` files
- Header doc-comment: what it does, how to run it (`pnpm <script-name>`), and any load-bearing
  design constraint (mirrors every existing file's opening `/** ... */` block).
- Plain Node built-ins (`node:fs`, `node:path`) + at most one purpose-built npm package —
  never a project-wide utility import from `src/`.
- Exported pure functions + exported types, so `meta/__tests__/*.test.ts` can import and test
  them directly without executing the script's own side effects.
- Wired into `package.json` via the exact form:
  `"<name>": "esbuild --bundle --platform=node --target=node21 meta/<File>.ts | node"`

### Test file shape (applies to `hardcodedStringGate.test.ts`)
**Source:** `meta/__tests__/buildCrossoverIndex.test.ts`, `meta/jest.config.js`
**Apply to:** `meta/__tests__/hardcodedStringGate.test.ts`
- File MUST be `meta/__tests__/<name>.test.ts` (`.ts`, not `.tsx` — `testMatch` is
  `**/__tests__/**/*.test.ts` under the `meta` jest project).
- Import the pure functions with a relative `../<file>` import, not a path alias.
- Structure: one `describe` per behavior/idiom, positive-fixture `it`s asserting "no violation
  flagged", at least one dedicated `describe('<guard-name>')` block for the hard-fail/edge case.

### Read-JSON-safely idiom (applies to the 3 new JSON config files + the gate's scope/allowlist/glossary loading)
**Source:** `meta/lintTranslations.ts:29-39` (`readFile()`)
**Apply to:** `hardcodedStringGate.ts`'s loading of `i18nGateScope.json` / `i18nGateAllowlist.json`
/ `i18nGlossary.json`
```typescript
function readFile(fileName: string, language: string) {
  try {
    return JSON.parse(
      readFileSync(join(localesPath, language, fileName + '.json')).toString()
    )
  } catch (error) {
    console.log(error)
    return null
  }
}
```
