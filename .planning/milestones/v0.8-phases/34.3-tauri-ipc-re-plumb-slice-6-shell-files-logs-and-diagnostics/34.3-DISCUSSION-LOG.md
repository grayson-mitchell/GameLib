## resetHeroic blast radius

**Mid-area clarification:** the user asked what `resetHeroic` actually does. Established from source before continuing: it is the "Reset GameLib" button (Settings → Advanced, behind a Yes/No confirm at `GlobalState.tsx:552`), and its 11-line body (`utils.ts:466`) deletes only `config.json` + `GamesConfig/`, then relaunches after a 1s setTimeout. The ~20 electron-store files (Steam token + library, all 10 Humble stores, download manager, Wine, caches) are siblings in the same folder and are **not** deleted — so the dialog's "removes all Settings and Caching" copy overclaims. `config.json` is owned by the in-memory `GlobalConfig` singleton, which is what makes a post-delete rewrite possible.

### Q1 — Stance given the orphaned-sidecar risk on the relaunch path?

| Option | Description | Selected |
|--------|-------------|----------|
| Verify, then fix the teardown | Confirm empirically whether `restart()` fires `RunEvent::Exit`; if not, add `shutdown_child()` to the app_relaunch arm, then port at parity | ✓ |
| Port at parity, declare the risk | Cheapest, but may resurrect deleted settings and leaves an orphan holding an authenticated Steam session | |
| Delete-then-quit, no relaunch | Deterministic and safe (Exit fires, sidecar dies), but a declared UX divergence | |
| Don't port resetHeroic this slice | Leaves a channel blocking the Phase 35 gate | |

**User's choice:** Verify, then fix the teardown
**Notes:** The orphan hazard was presented explicitly as an **inference from Tauri's API semantics, not a measurement** — `AppHandle::restart()` never returns (`-> !`) and exits the process directly rather than through the event loop, and the only thing that kills the sidecar is the `RunEvent::Exit` handler added by Phase 34 WR-03. Research must verify before the fix is written; the fix is conditional on the finding.

### Q2 — Where should the relaunch+quit race be resolved?

| Option | Description | Selected |
|--------|-------------|----------|
| Guard inside electronStub | A relaunch-in-flight flag makes `app.quit()`/`exit()` a logged no-op; resetHeroic's shared body stays byte-identical for both builds | ✓ |
| Branch in resetHeroic itself | Explicit at the call site, but puts an `isTauri()` conditional in shared backend code | |
| Serialize dispatch in Rust | Fixes it for all callers, but touches the hot path for every rustInvoke | |
| Accept and declare the race | Cheapest; ships known nondeterminism on a destructive action | |

**User's choice:** Guard inside electronStub
**Notes:** The race arises because the stub forwards `relaunch()` and `quit()` as two separate fire-and-forget frames dispatched on spawned worker threads, so `app_exit` can win and the app quits instead of restarting.

### Q3 — CI never compiles or tests Rust. How should this slice's two Rust changes be proven?

| Option | Description | Selected |
|--------|-------------|----------|
| Cargo tests + jest existence gate | Real `#[cfg(test)]` tests run manually with hand-verified RED proof in the SUMMARY, existence pinned by a jest gate — the 34.2 plan 22 `timeout_for()` precedent | ✓ |
| Add a cargo step to CI | Fixes the root cause; but CI/infrastructure work inside a port slice | |
| Live gate instead of Rust unit tests | Closest to user-visible truth, but leaves no regression net | |
| Cargo tests + CI step, both | Most thorough; largest scope expansion | |

**User's choice:** Cargo tests + jest existence gate
**Notes:** Surfaced from `main.rs`'s own docstring — `.github/workflows/*.yml` contains neither `cargo test` nor `cargo check`. The CI-step option was kept as a deferred idea rather than dropped.

discretion by analysis rather than by deferral, and are recorded in CONTEXT.md:

- **The extraction shape for the 23 `main.ts` registrations** — bounded by the constraint that
  registrations stay in `main.ts`, curated-import discipline holds, and nothing is
  re-implemented twice. Scouting found this slice needs far less extraction than 34.1/34.2

  stub and generic relay, with zero new Rust arms.

  a mandatory research item because `tauri-plugin-notification` crashed startup that way.
