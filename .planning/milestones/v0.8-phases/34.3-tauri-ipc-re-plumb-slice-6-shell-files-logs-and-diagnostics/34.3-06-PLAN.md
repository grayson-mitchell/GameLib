**Do NOT import `src/backend/utils/ipc_handler.ts`.** Besides `copySystemInfoToClipboard` it also
registers four already-ported channels (`abort`, `getSystemInfo`, `hasExecutable`, `isIntelMac`) AND
four channels belonging to the unported Phase 34.5 slice (`getLegendaryVersion`, `getGogdlVersion`,

D-04's read-path rule: `clipboardReadText` is registered with `addHandler` (async), so this module's
handler `await`s `requestRustInvoke(RUST_CLIPBOARD_READ_TEXT, [])` **itself** and never calls
`electronStub.clipboard.readText`, which is a synchronous, documented-dead no-op. On rejection the
handler resolves `''` — the same degraded-but-safe value the Electron path can also produce for an
empty clipboard — rather than rejecting, because `SIDLogin/index.tsx:137` consumes the value
directly.

D-03's write-path rule: `clipboardWriteText`'s registration calls `clipboard.writeText(...)`, which
is now a real fire-and-forget Rust forward with log-only failure. The registration must NOT try to
await or surface that failure — real Electron's `clipboard.writeText` is `void`.
