Two facts that decide the dialog wiring:
1. Sidecar send listeners receive `undefined` as their event (`sidecarRpc.ts:142`). There is no
   `event.sender`. So `showDialogBoxModalAuto` MUST be called **without** an `event` property,
   which takes its `sendFrontendMessage('showDialog', ...)` branch (`dialog.ts:23-31`) — the same
   push chain `downloadQueueFlowRegistration.ts:44-46` documents as already working under the
   sidecar. Passing a fabricated event object would take the `event.sender.send` branch and throw.
2. `sendFrontendMessage` (`src/backend/ipc.ts:68-83`) returns `false` when there is no live window;
   it never throws. And `electronStub.dialog.showMessageBox` (the `catch`-branch fallback) is a
   documented safe-resolve that **never rejects** — a rejecting dialog stub hard-crashes the
   sidecar through unguarded fire-and-forget awaiters (`sidecar-dialog-reject-crashes` project
   memory, guarded by `sidecarRejectionGuard.test.ts`). Do not change that.
