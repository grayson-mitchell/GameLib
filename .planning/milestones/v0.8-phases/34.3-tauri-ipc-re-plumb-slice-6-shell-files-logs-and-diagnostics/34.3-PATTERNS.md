```typescript
ipcMain.on('logInfo', (_event: unknown, ...args: unknown[]) => {
  let settled: Promise<unknown>
  try {
    settled = Promise.resolve(logInfoSettled(args[0], LogPrefix.Frontend))
  } catch (error: unknown) {
    // eslint-disable-next-line @typescript-eslint/prefer-promise-reject-errors
    settled = Promise.reject(error)
  }
  void settled.catch((error: unknown) => {
    let diagnostic = '[loggerFlowRegistration] logInfo call-site rejection: <unstringifiable reason>'
    try {
      diagnostic = `[loggerFlowRegistration] logInfo call-site rejection: ${
        error instanceof Error ? (error.stack ?? error.message) : String(error)

    } catch {
      // keep the hardcoded fallback

    } catch {
      // swallow — never re-throw, never exit, never write to stdout
    }
  })
```

### 1. send-vs-handle registration kind MUST match `main.ts` exactly, for every one of the 29 channels

**Source of truth for every channel's kind, already tabulated in RESEARCH.md Pitfall 2:**
- `addHandler` (invoke): `checkDiskSpace`, `getShellPath`, `clipboardReadText`, `pathExists`, `uploadLogFile`, `deleteUploadedLogFile`, `getUploadedLogFiles`.

**The two registration helpers side by side, so they cannot be confused:**
```typescript
// invoke-kind: request-response, caller awaits a return value
ipcMain.handle('checkDiskSpace', async (_event, ...args) => { /* returns a value */ })

// send-kind: fire-and-forget, caller does not await anything meaningful back
ipcMain.on('resetHeroic', () => { /* void, never returns anything to the caller */ })
```
