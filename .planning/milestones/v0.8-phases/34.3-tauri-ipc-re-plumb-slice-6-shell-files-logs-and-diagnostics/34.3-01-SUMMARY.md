## Decisions Made

- **checkDiskSpace's zod validation preserved exactly as-is.** `Path.parse(args[0] as string)` is called with no surrounding try/catch — an invalid path throws synchronously, the async handler's promise rejects, and `sidecarRpc.ts`'s `dispatchInvoke` converts that into a `{ok: false, error}` response frame. This is the channel's ASVS V5 input-validation control (T-34.3-01) and must not be softened.
- **removeFolder's array-destructuring shape matches main.ts byte-for-byte.** `const [folderPath, folderName] = args[0] as [string, string]` — a caller that sends two positional args instead of a single two-element array gets silent single-character destructuring from the first string argument (JS strings are iterable), which resolves to a nonexistent path and therefore deletes nothing. This is pinned by a negative test rather than left as an undocumented quirk.
- **getLegendaryVersion as the new "genuinely unported" example channel.** `checkDiskSpace` was used by 4 pre-existing test suites (`settingsFlows`, `installFlows`, `gameDetailsFlows`, `enrichmentFlows`) as their canonical stand-in for "an unported channel still rejects safely" (Invariant B). Since this plan ports `checkDiskSpace` for real, those 4 tests broke. Confirmed `getLegendaryVersion` is not registered anywhere in the sidecar (grep across `sidecar/*.ts`) and belongs to Phase 34.5 (far future, low risk of re-breaking soon) — substituted it in all 4 files, following the exact precedent `installFlows.test.ts` already documents from its own prior Phase 32 substitution of this same example channel.
