# Phase 34.3 Plan 05: Clipboard Forwarding + Relaunch/Quit Race Guard Summary

**`electronStub.clipboard.writeText` now forwards to the real OS clipboard through Rust with log-only failure; `app.quit()`/`app.exit()` are suppressed once a relaunch is in flight, closing the nondeterministic quit-instead-of-restart race on `resetHeroic` with zero changes to `utils.ts`.**

## Accomplishments

- Replaced `electronStub.clipboard.writeText`'s logged no-op (Phase 31 D-04, "deferred to Phase 33" — never collected) with a real fire-and-forget forward to `RUST_CLIPBOARD_WRITE_TEXT`, byte-shape-identical to `shell.showItemInFolder`'s existing template: never throws, a transport failure is logged not silent.
- Documented `clipboard.readText()` as **DELIBERATELY DEAD** rather than an incidental leftover — signature and `''` return are byte-unchanged; the comment names the exact reason (real Electron's `readText()` is sync, a sync stub cannot await Rust) and the one sidecar-reachable caller (plan 34.3-06's async `clipboardReadText` handler, which bypasses this member entirely).
- Added a module-scope `relaunchInFlight` flag to `electronStub.ts`: `app.relaunch()` sets it (never reset — a relaunch is terminal for the process); `app.quit()`/`app.exit()` each check it first and become logged no-ops if true. `resetHeroic` (`utils.ts:466-476`) is untouched — confirmed via `git diff --stat` showing zero changes across all 4 commits.
- Migrated `dialogStub.test.ts`'s obsolete "clipboard D-04 logged no-op" describe block to record the graduation, following the exact `shell.showItemInFolder` D-04→D-05 precedent already in this codebase: kept a real, executing assertion that `readText()` still returns `''` (the part of D-04 that did NOT graduate), and left a pointer comment to the new coverage rather than deleting the block.
- Extended `lifecycleStub.test.ts`: the `RUST_INVOKE_CHANNELS` allowlist test now names both new clipboard constants; added round-trip + never-throws coverage for `clipboard.writeText`; added an isolated 3-case race-guard describe block proving both directions of the guard (relaunch-then-quit is suppressed; quit-alone-with-no-relaunch still forwards, an explicit over-suppression regression guard; exit-after-relaunch is also suppressed).

## Decisions Made

- **`relaunchInFlight` lives entirely in `electronStub.ts`, contained, never reset.** `resetHeroic`'s shared body (`utils.ts:466-476`) required zero changes — confirmed empty `git diff --stat src/backend/utils.ts` across all 4 commits in this plan. No `isTauri()` branch was added anywhere (confirmed by grep against the pre-plan baseline).
- **Reordering over resetting module state for the pre-existing lifecycle tests.** Rather than introducing file-wide `jest.resetModules()` (which would have required restructuring every describe block's static imports into per-test dynamic requires), the two pre-existing tests that interact with the flag were reordered so the one requiring `relaunchInFlight === false` runs before the one that permanently sets it. This is minimal and correct because `relaunch()` itself is never guarded (only `quit()`/`exit()` check the flag), so no other existing test's assumptions were disturbed.
- **The new race-guard tests use per-test `jest.isolateModules()` isolation, not file-wide resetModules.** This mirrors `bootstrapWirings.test.ts`'s existing precedent for isolating module-scope singleton state and keeps the change scoped to the 3 new tests rather than touching this file's existing, working convention for every other describe block.
