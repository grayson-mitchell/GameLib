## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → sidecar (stdio JSON-RPC) | Channel args arrive as untrusted `unknown[]` from the webview, which also renders untrusted remote content (store-search) |
| sidecar → Rust (`rustInvoke`) | URLs/paths forwarded to `open_external` / `shell_open_path` / `reveal_item_in_dir` |
| sidecar → filesystem | `removeFolder` deletes a directory; `checkDiskSpace`/`pathExists` read paths |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.3-01 | Tampering | `checkDiskSpace` (`shellFilesFlowRegistration.ts`) | mitigate | Preserve `Path.parse(args[0])` zod validation (ASVS V5) — Task 2 forbids swapping it for node's `path.parse` and Task 3 pins it with an invalid-input rejection test |
| T-34.3-02 | Elevation of Privilege | `removeFolder` (recursive delete reachable from IPC) | accept | Electron parity: same channel, same unvalidated arg, same reachability today. The port neither introduces nor widens it. Argument-shape is pinned by test so a mis-shaped call no-ops instead of deleting an unintended path |
| T-34.3-03 | Information Disclosure | the 12 URL openers | accept | 10 of 12 open hardcoded constants from `constants/urls.ts` (no attacker-controlled input). `openExternalUrl`/`openFolder` take renderer input and are forwarded to `tauri-plugin-opener`'s own scoping — the exact provenance disposition already accepted as T-33-11 for `shell_open_path` |
