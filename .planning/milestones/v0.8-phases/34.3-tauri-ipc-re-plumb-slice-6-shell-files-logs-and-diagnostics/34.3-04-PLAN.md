<objective>
Extend the existing `loggerFlowRegistration.ts` (built by 34.2 gap plan 34.2-16 for `logError`)
with this slice's 5 logger channels: `logInfo`, `showLogFileInFolder`, `uploadLogFile`,
`deleteUploadedLogFile`, `getUploadedLogFiles`.

Purpose: `logInfo` is the frontend's primary logging channel and, being a **send** channel, it
currently does **nothing at all** under Tauri — no reject, no timeout, no console line (the
`sidecar-send-channels-fail-silently` project memory). The three upload channels back the
Settings → Logs surface. `uploadedLogFileStore` is already registered
(`storeRegistration.ts:115`, Phase 29 D-15), so there is zero new store plumbing.

Output: a new `logInfoSettled` export, 5 new registrations in the existing module, and extended
coverage in the two existing logger test files.

Two declarations this plan must produce for `34.3-PORTED-CHANNELS.md` (plan 34.3-08 consumes them):
1. **`deleteUploadedLogFile` is ported but does not work — in EITHER build.** `logger/uploader.ts:74-77`
   hardcodes `const token = '1'` with the comment "dpaste.com does not support deleting files…
   I'll hide the delete option." The option was never hidden — `UploadedLogFilesList/index.tsx:60`
   still wires a live button — so the channel POSTs a bogus token and either fails or falsely
   reports success while the paste stays public. **Key distinction from 34.2 D-07:** that channel was
   dead only *under Tauri* (port-introduced, so fixing it was in scope). This one is equally dead in
   both builds — an inherited upstream Heroic defect the port neither introduces nor worsens. Port it
   faithfully; file the UI bug as a separate todo; do **not** fix the button here.
2. **Log redaction is OUT OF SCOPE (D-09).** `uploadLogFile` sends up to 10 MiB of unredacted log
   content to a public dpaste with a 2-day expiry, and `src/backend/logger/` has no redaction
   anywhere. The threat is identical in both builds and predates this slice. **The user explicitly
   declined even a bounded audit of whether a token or key value can reach a log line — file the
   security todo, perform no audit, and do not re-open the question.**
</objective>
