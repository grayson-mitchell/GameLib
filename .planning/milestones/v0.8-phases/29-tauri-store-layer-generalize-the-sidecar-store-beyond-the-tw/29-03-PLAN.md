## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sidecar store values → renderer snapshot payload | untrusted-renderer-readable data crosses here; the allow-list is the access-control mechanism (ASVS V4) |
| renderer-supplied `(storeName, key)` → policy predicate | both strings are attacker-controllable under XSS via themes/custom CSS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-08 | Information Disclosure | `isAllowedStoreField` on an unanticipated field | mitigate | Fail closed by construction: unknown store ⇒ false, unknown field ⇒ false. A newly added secret field is excluded by DEFAULT rather than leaking until someone remembers to deny-list it — this is the whole point of D-08 and the exact failure that let `humbleConfigStore.csrfToken` slip past. Test asserts the unknown-name/unknown-field cases. |
| T-29-09 | Information Disclosure | dot-notation subpath read of a secret (`refreshToken.x`) | mitigate | Policy matches on `key.split('.')[0]`, preserving the old deny-list's `startsWith(secret + '.')` block. Asserted in Task 3. |
| T-29-10 | Information Disclosure | `humble_library` raw entries bypassing `getKeys()`'s projection of `revealedKeyValue`/`keyindex` | mitigate | `DENIED_CACHE_STORES` excludes `humble_library` wholesale from any snapshot (29-RESEARCH Open Question 4). |
| T-29-11 | Information Disclosure | policy enforced in the eager snapshot but forgotten in the lazy fetch or write path | mitigate | One exported `filterStoreSnapshot()`/`isAllowedStoreField()` that every path in plans 29-04/05/06 must call; 29-04 and 29-06 acceptance criteria grep for the call in each handler. |
| T-29-12 | Tampering | wire channel literal drift (`'storeSet'` renamed) | mitigate | Acceptance criterion pins the literal `= 'storeSet' as const`; a rename would silently orphan the renderer's existing sends. |
| T-29-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — zero new packages this phase (29-RESEARCH.md § Package Legitimacy Audit). |
