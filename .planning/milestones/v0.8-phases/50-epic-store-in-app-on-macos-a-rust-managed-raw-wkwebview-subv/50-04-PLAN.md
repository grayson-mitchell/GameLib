<objective>
Fill the six English keys plan 03 minted into all 48 non-English locale catalogues, stamp their
provenance, and take `pnpm lint-translations:gamelib` from the 288 recorded hard failures back to
zero — without regenerating the presence baseline and without reformatting a single catalogue.

Purpose: `pnpm lint-translations:gamelib` is structurally blind to an ABSENT key, so the gate that
actually catches an English-only key is the presence baseline's `missing` drift, and it fails HARD
at one failure per unrecorded (locale, key) pair. 6 keys x 48 locale directories is 288 failures
today. The tempting fix — regenerating the baseline — would convert a 49/49 parity win into 288
gaps behind a green check, which that artifact's own reason string explicitly forbids.

Output: 288 authored translations across 48 `gamelib.json` files, 288 provenance entries across 48
`gamelib.mt.json` manifests, a green translation gate, and a per-locale confidence disclosure in
the SUMMARY so nobody mistakes a non-empty string for a reviewed one.
</objective>

  <action>
Do not translate the English from scratch. Each of the six keys joins an existing sibling family,
and deriving from that family inherits the locale's own terminology, register and punctuation —
which is both better and cheaper than inventing. For each (locale, key), walk the parallel corpus
in this order and record which source each value came from:

1. **Subject noun-phrase** — from the SAME namespace (`gamelib`), because locales render the same
   product noun differently across namespaces. For the challenged-panel pair, the locale's own
   `webview.unavailable.epic.heading` / `.body` is the direct parallel: same panel, same voice, same
   subject.
2. **Predicate / verb** — from the locale's own `translation.json` sibling where one exists
   (`webview.controls.reload` for the Reload label, any existing loading/waiting phrasing for the
   timeout message). `br` and `sl` have no `translation.json`; fall back to step 4 for those.
3. **Sentence pattern, punctuation and ellipsis glyph** — from the locale's own adjacent strings.
4. **In-namespace verb and fallback corpus** — the locale's whole `gamelib.json`. This step is easy
   to skip and it is the one that changed four values in the last fill (ZWNJ handling, native verb
   versus loanword, script-specific word choice).

**The trap to re-audit:** taking a noun-phrase from one namespace and an inflection from a sibling
built on a DIFFERENT, gendered native noun silently breaks agreement. The last fill shipped a
feminine participle agreeing with `translation.json`'s noun against `gamelib`'s masculine
indeclinable term. Re-audit every gendered locale wherever the noun-phrase source differs from the
inflection source.

**Three shapes that look like defects and are not** — verify against the locale's own catalogue
before "fixing" them: `sl` puts a space before an ellipsis; `hr`, `ml` and `sk` use the single
ellipsis character even though their `translation.json` siblings are English pass-through with

untranslated English sibling is not typographic evidence); `de` uses a plain space where
`translation.json` uses a non-breaking space, because `de/gamelib.json` has zero non-breaking
spaces.

every locale — it is the one term the validator will actually enforce. "Epic" alone, in the timeout
message, is the store's brand and should follow whatever the locale's own existing `webview`
