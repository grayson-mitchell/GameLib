Write the pure resolver that turns `{ steamLoggedIn, steamSyncStatus, steamLibraryCount }` into a
render mode, and cover every state — including the two the shipped code never could (D-09).

`steam?.username && steam?.library?.length === 0 && refreshingInTheBackground`. That flag defaults

existing coverage only proves the spinner appears and clears on SUCCESS. The uncovered case is
refresh running and then FAILING — exactly the gap that let the sibling bug (`GlobalState.tsx:1508-1515`)
recur in a new form.

that is Plan 08.

Decision table — implement EXACTLY this, in this order, and write the rationale for each branch as
an inline comment:
  1. `!steamLoggedIn` -> `'hidden'`. A user with no Steam account must never see a Steam sync
     surface. This preserves the `steam?.username` half of the old guard, moved somewhere testable.
  2. `steamSyncStatus === 'failed'` -> `'failed'`, REGARDLESS of `steamLibraryCount`. A failure must
     be surfaced even when a cached library rendered — exit path 2 in `library.ts` serves the cached
     games and then reports the failure, and telling the user nothing because "there are games on
     screen" would hide a stale library behind a successful-looking render.
  3. `steamSyncStatus === 'syncing' && steamLibraryCount === 0` -> `'syncing'`. This preserves the
     SHIPPED intent of the old guard's `library.length === 0` term: show the sync indicator only
     when there is nothing else to look at. A refresh of an already-populated library is covered by
     the `steamMetadataSyncing` indicator in `LibraryHeader` and does not need a second surface.
  4. everything else -> `'hidden'`. This branch is where the DEFECT died: `'idle'` with an empty
     library now renders nothing, where the old guard spun forever. Comment it as such by name.

Import `SteamSyncStatus` with `import type` so no runtime import of `common/types/ipc` is created —
the zero-runtime-import property is what makes this module testable.

Do NOT add a `reason` field to the output in this plan. The notice copy is reason-agnostic in its
