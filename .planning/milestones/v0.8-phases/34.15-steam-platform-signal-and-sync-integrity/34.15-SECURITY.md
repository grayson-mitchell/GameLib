> Per-phase security contract: threat register, accepted risks, and audit trail.

**Register origin:** `register_authored_at_plan_time: true` — all 9 PLAN files carried a parseable
`<threat_model>` block. This audit **verified that the planned mitigations exist in the shipped

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Steam CM socket → sidecar | Valve-controlled PICS response data crosses into the sidecar on the already-authenticated CM socket inside `refresh()`. Authenticated, not user input — but response *shape* is not guaranteed. | `common.oslist` strings, app metadata |
| sidecar → `steamMetadataStore` (electron-store on disk) | Parsed platform values are persisted and later drive **install routing**. | Platform capture verdicts, `forcedWindowsViaBottle`, `mac_arch_verified` |
| sidecar/main → renderer (`steamSyncStatus` push IPC) | New one-way backend→frontend channel. | Closed string union only (`status`, `reason`) |
| sidecar/main → renderer (`isSteamBottleEligible` response) | Existing request/response channel widened by one boolean. | `hasMacDepot: boolean` |
| renderer → main/sidecar (`refreshLibrary` IPC) | The retry button re-invokes an existing, already-scoped call. No new channel. | Runner scope string |
| operator shell → system config (UAT only) | The D-16 forcing procedure asks for a `sudo` edit to `/etc/hosts` plus a DNS flush on the developer's own machine. | Hostname override lines |
| operator filesystem → app cache (UAT only) | Branch A deletes `steam_metadata.json` to force a cold capture. | Cached platform metadata |

## Audit Notes

**Note 1 — T-34.15-08-04, plan text vs shipped gate.** The plan-time register recorded the
`refreshingInTheBackground` occurrence count as "exactly 2". The shipped gate pins it at **3**, and
the live source contains 3 (`Library/index.tsx:97` destructure, `:1024` D-11-fenced overlay, `:1036`
pre-existing `<GamesList>` render gate). The gate carries an in-file comment reconciling the plan's
assumption against the real HEAD count. This is a **corrected plan figure, not a weakened gate** —
the invariant that matters is that no *fourth* occurrence appears, i.e. that the old guard was not
resurrected somewhere new, and the gate enforces exactly that. Confirmed by direct source inspection
during this audit, independent of the auditor agent's report.

**Note 2 — T-34.15-04-02, the "zero changed lines" criterion.** Plan 04 required `git diff -U0` to
show zero changed lines inside the D-17 describe block, and that held at Plan 04's landing. The later
WR-01 gap-closure fix (`REVIEW.md:175`) did modify the block, adding a fourth parameter mechanically.
The audit accepted this because the block's real assertions are unchanged and still non-vacuous
(`treatsAbsentAsAvailable({}) === true` vs `hasSteamWindowsDepot({}) === false`; `toHaveLength(2)` vs
`toHaveLength(1)`) — verified against current source rather than inferred from the summary. Flagged
here so a future audit sees the deviation rather than re-deriving it.
