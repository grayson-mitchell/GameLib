# Phase 34.15 Plan 03: Widen the Steam Eligibility Verdict with a Mac Depot Field Summary

**`SteamBottleEligibilityVerdict.hasMacDepot` now rides the same round trip as `hasWindowsDepot`, computed `is_mac_native === true` at the same `steamMetadataStore` read, and threaded through the eligibility probe's state machine end to end -- closing the gap neither RESEARCH.md nor PATTERNS.md surfaced for D-12's mac triple.**

## Accomplishments
- `SteamBottleEligibilityVerdict` widened with `hasMacDepot: boolean`, doc-commented with the same "meaningless without `platformsCaptured`" contract as `hasWindowsDepot`
- `installFormIpc.ts`'s single shared handler body (never forked, serving both Electron and the Tauri sidecar) now reads `is_mac_native === true` at the identical cache read and round trip as `hasWindowsDepot`, on both verdict return sites (the `eligible: false` early return and the real verdict)
- `steamEligibilityProbe.ts`'s `EligibilityState`, `initialEligibilityState`, `applyEligibilityResponse`, `applyEligibilityFailure`, and `useSteamBottleEligibility` all carry `hasMacDepot` with the same seed/resolve and fail-"never found out" (not fail-closed) semantics the Windows field already has
- A named `macTreatsAbsentAsAvailable` saboteur proves the mac-side `!== false` trap disagrees with the real `=== true` read, mirroring the three shipped Windows-side saboteurs in `steamPlatformRow.test.ts`

## Issues Encountered

The plan's own top-level `<verification>` block contains `grep -rn "is_mac_native !== false" src/` returns nothing`, while Task 1's `<action>` explicitly instructs writing a saboteur test containing exactly that literal string (`macTreatsAbsentAsAvailable(cached)` returning `cached?.is_mac_native !== false`). These two instructions are in direct tension for any implementation that follows Task 1 as written.

Resolution: implemented the saboteur exactly as specified (it is the whole point of the test -- proving the wrong comparator disagrees with the real one), and treated the single resulting grep match as expected, not a defect. This exactly mirrors the repo's existing precedent: the three shipped Windows-side `treatsAbsentAsAvailable` saboteurs in `steamPlatformRow.test.ts` already contain the literal `is_windows_native !== false` in test source, and that has never been treated as a violation. The intent of a source-wide grep check like this is almost certainly to catch the pattern in *production* code, not in a test file whose entire purpose is to demonstrate the wrong behavior by name. Confirmed the strict acceptance-criteria grep that IS scoped to production code (`grep -v '^\s*[/*]' installFormIpc.ts | grep -c 'is_mac_native !== false'` → `0`) passes cleanly.

No other issues.
