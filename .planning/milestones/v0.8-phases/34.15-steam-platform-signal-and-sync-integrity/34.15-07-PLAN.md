<objective>
Apply 34.14's *absent-is-not-negative* principle to the mac side of the install form: consume the
mac triple (D-12), suppress the whole glyph row while the signal is unresolved (D-13), and stop the
platform default freezing at open (D-14) — without reopening 34.14's pending-row pin (D-15).

Purpose: `SteamDialog/index.tsx:380-391` renders its header row from `availablePlatforms`, and the
Windows entry is `available: true` **unconditionally** (`InstallModal/index.tsx:223-227`). On a Mac
host with an unresolved signal, Linux is `false`, macOS is `isMac && isMacNative` = `false`, Browser
is `false` — so the row is exactly one Windows glyph. That reproduced live during 34.14's UAT:
Terraria (105600), which genuinely ships both, rendered a confident Windows-only row and defaulted
the selector away from a real native Mac build. The row is an **assertion about the game**; with the
signal unresolved the app cannot make it. No icons is honest; a Windows-only icon is not.

Output: the install form consumes and respects the mac triple, gated by one resolution moment.
</objective>
