# Phase 34.15 Plan 06: Pure Steam sync indicator resolver Summary

**A pure, zero-runtime-import resolver (`resolveSteamSyncIndicator`) replaces the `refreshingInTheBackground`-driven spinner guard with a four-branch decision over the real `steamSyncStatus` tri-state, covering the refresh-ran-and-then-FAILED case the shipped code could never distinguish from success.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 2
- **Files modified:** 2 created, 0 modified

## Accomplishments
- `librarySyncIndicator.ts` implements the exact four-branch decision table specified in CONTEXT.md D-06/D-08/D-09/D-10, each branch's rationale written inline as a comment, with `SteamSyncStatus` imported via `import type` so the module has zero runtime imports and stays importable by the Frontend jest project (no jsdom, no CSS transform reachable from `Library/index.tsx`).
- The 12-row cross product (`steamLoggedIn` x `steamSyncStatus` x `steamLibraryCount`) is exhaustive and passes, each row named for the user-visible situation it describes.
- Three named saboteurs each disagree with the real function on a specific input: `reproducesShippedGuard` encodes the actual shipped defect (`refreshingInTheBackground` reduces to "logged in AND library empty", proven to say `'syncing'` where the real function says `'hidden'` on the idle/empty row); `hidesFailureWhenGamesPresent` pins that a failure surfaces even behind a cached library; `leaksIndicatorWhenLoggedOut` pins the logged-out guard.
- An explicit test named for D-09's stated uncovered case ("refresh ran and then FAILED — the case existing coverage never reached") asserts the `failed` mode for the logged-in/count-0 row.
- `npx jest src/frontend/screens/Library` — 19 suites, 525 tests, all green (no regression in sibling suites). `npx tsc --noEmit -p tsconfig.json` shows only the pre-existing, out-of-scope `InstallModal/index.tsx:201` error (Plan 07's declared scope), confirmed identical before and after this plan.
