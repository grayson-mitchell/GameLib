## Pre-discussion corrections raised

Two ROADMAP claims were found stale during the codebase scout and surfaced before questioning,
so the decisions were not made against a wrong picture:

1. **"a guard hardcoded to `--arch=arm64`"** — `package.json:46,51` now run the guard for
   **both** arches (`--arch=arm64 && --arch=x64`), added by 34.16.
2. **"three of six sentinels stay permanent"** — all **six** slots are `PENDING-CI-PUBLISH`
   today, arm64 included, and `runId` is `null`. Darwin helper downloads are broken for both
   arches right now, which is why the post-checkout hook throws.

## The three arm64 digest sentinels

**Finding that reframed the area:** `meta/pinRunnerDigests.ts` is hard-wired to two arches
(fetches both `SHA256SUMS-{arch}`, requires both manifests' `runId` non-null **and equal**,
validates all six digest keys). The x64 leg never ran, so `SHA256SUMS-x64` does not exist and
`pnpm pin:runner-digests` is un-runnable today. It is a **seventh scope consumer** the ROADMAP
does not name.

| Option | Description | Selected |
|--------|-------------|----------|
| Yes — add as scope consumer 7 | Retire the pin tool to 3 keys / one arch alongside the rest | ✓ |
| No — separate follow-up phase | Cleaner scope, but ships a phase leaving darwin broken with no owner | |

**User's choice:** Scope consumer 7.

| Option | Description | Selected |
|--------|-------------|----------|

| Code-ready only — sentinels stay | Fully autonomous; darwin downloads stay broken | |
| Code-ready + I'll dispatch now | Digests available during the phase rather than at a closing checkpoint | |

**User's choice:** Code-ready + developer runs the pin at a blocking checkpoint.

| Option | Description | Selected |
