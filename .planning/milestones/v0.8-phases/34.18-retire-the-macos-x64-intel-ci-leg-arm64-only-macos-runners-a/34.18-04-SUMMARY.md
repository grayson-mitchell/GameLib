## Guard RED-proof (verbatim observations)

All three built in scratch space under `/private/tmp/claude-501/.../scratchpad/redproof/`, never inside the repo.

**Observation 1 — empty scratch root, `--arch=arm64`:** exit code `1`, stderr:
```
verifyRunnerBundle: could not find a "build/bin/arm64/darwin" directory under root "<scratch>/empty-root" (arch="arm64") -- wrong root or wrong --arch?
```

**Observation 2 — root with `build/bin/arm64/darwin` present but the `nile` runner directory absent** (only `legendary/legendary` and `gogdl/gogdl` present as minimal executable stub files, no `nile/` directory at all): exit code `1`, printed table showed `nile: exists=false, executable=false, isMachO=false, fileCount=0`, and the `FAIL:` block included:
```
- nile: runner binary missing at <scratch>/missing-runner-root/build/bin/arm64/darwin/nile/nile
```
(plus expected Mach-O/file-count-floor failures for the two present-but-undersized stub runners, which is expected collateral of using minimal stub files rather than real binaries — the load-bearing assertion is that `main()` returns non-zero over the fixed three-runner list even with two runners present).

**Observation 3 — byte-unchanged confirmation:**
```
$ git diff --name-only -- meta/verifyRunnerBundle.ts meta/__tests__/verifyRunnerBundle.test.ts
(empty)
$ npx jest --selectProjects Meta -t "verifyRunnerBundle"
PASS Meta meta/__tests__/verifyRunnerBundle.test.ts
Tests: 8 passed, 8 total
```

**Conclusion:** `meta/verifyRunnerBundle.ts` needed no functional change. Its arch-parameterised strictness under a single arch was proven against two independent known-bad trees (missing tree entirely; tree present but missing one of the three runners), not merely read from source and assumed.
