## D-15 Verified Dialog Chain (file:line citations for every hop)

`toggleDXVK` / `toggleDXVKNVAPI` / `toggleVKD3D`
&nbsp;&nbsp;→ `DXVK.installRemove` (`src/backend/tools/index.ts:205-260`)
&nbsp;&nbsp;&nbsp;&nbsp;→ on cache miss, `DXVK.getLatest()` (`tools/index.ts:163-203`, called at `:255`)
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;→ `Promise.all(tools.map(installOrUpdateTool))` (`tools/index.ts:202`)
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;→ `installOrUpdateTool` (`tools/index.ts:72-160`), on a `downloadFile` failure (`:110-115`, caught at `:116`)
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;→ `showDialogBoxModalAuto({ title, message, type: 'ERROR' })` (`tools/index.ts:137-141`)
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;→ `src/backend/dialog/dialog.ts:8-54`. Called with no `event` (the sidecar path never passes one — verified: none of the three toggle handlers thread an `event` through), so the primary path is `sendFrontendMessage('showDialog', props.title, props.message, props.type, props.buttons)` (`dialog.ts:25-31`), inside a `try`.
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;→ IF that throws (caught at `dialog.ts:32`): fallback branch calls `dialog.showErrorBox(props.title, props.message)` for `type === 'ERROR'` (`dialog.ts:38-40`, the only type this call site ever passes) — `dialog` here is `import { dialog } from 'electron'`, which under the Tauri sidecar resolves to `electronStub.ts`'s `dialog` object (`electronStub.ts:320-387`), NOT a real Electron dialog.

**Can `electronStub.dialog.showErrorBox` reject? NO — verified by direct read (`electronStub.ts:321-334`):**
```ts
showErrorBox: async (title?: string, content?: string): Promise<void> => {
  try {
    await requestRustInvoke(RUST_DIALOG_MESSAGE, [{ message: content, title, kind: 'error' }])
  } catch (error) {
    // Never throw to the caller (total-method convention)...
    console.warn(...)
  }
}
```
The entire body of `requestRustInvoke` is wrapped in its own `try`; any failure (timeout, transport error) is caught and only logged via `console.warn`. There is no code path in this function that returns a rejected promise or rethrows. This is the exact property proven, generically, by the pre-existing dedicated suite `dialogStub.test.ts` ("never throws and warns when requestRustInvoke rejects").

**Can `electronStub.dialog.showMessageBox` reject? NO — same construction (`electronStub.ts:335-381`):** its `try`/`catch` around `requestRustInvoke` resolves `{ response: safeIndex, checkboxChecked: false }` on any failure rather than rethrowing. (Not reached from this cluster's call site, which only ever passes `type: 'ERROR'`, but verified for completeness since `showDialogBoxModalAuto`'s `default` branch can reach it for other callers.)

Because `showDialogBoxModalAuto` itself is a synchronous (non-`async`) function that never `await`s or attaches a `.catch()` to the `dialog.showErrorBox(...)` call it fires, the ONLY way this fire-and-forget call could ever produce an unhandled promise rejection is if the callee (`electronStub.dialog.showErrorBox`) itself rejected — and it structurally cannot, per the code above. This plan's new test (Describe 4 in `wineToolsFlows.test.ts`) exercises exactly this call chain with the primary push forced to fail, and confirms no unhandled rejection occurs.
