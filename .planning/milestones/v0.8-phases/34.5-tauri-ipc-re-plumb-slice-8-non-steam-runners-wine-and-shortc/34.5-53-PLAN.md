**Site 1 — `src/backend/storeManagers/nile/user.ts:91`** (the site the gate observed):
`logDebug(['Got register data:', data], LogPrefix.Nile)` inside `NileUser.login(data: NileRegisterData)`.
`NileRegisterData` (`src/common/types/nile.ts:119-124`) = `{ code, code_verifier, serial, client_id }`.

**Site 2 — `src/backend/storeManagers/nile/user.ts:62`** (NOT observed by the gate — this is the
new half, recorded as `F-34.5-G6-20` by plan 34.5-54):
`logInfo(['Register data is:', output], LogPrefix.Nile)` inside `NileUser.getLoginData()`.

because this plan read the file rather than trusting the finding's own scope.

This file's own header comment at line 34 already says "`NileLoginData` carries single-use PKCE

  <action>
Add one non-exported-from-the-module-boundary helper pair in `src/backend/storeManagers/nile/user.ts`,
placed immediately above the class, named `redactNileLoginData` and `redactNileRegisterData`. Each
takes its respective type and returns a plain object safe to log. Required shapes:

`redactNileLoginData(d: NileLoginData)` returns an object with exactly these keys:
`url_host` (the host component of `d.url` only — parse with `new URL(d.url).host`, and on a parse
failure use the literal string `<unparseable>`; never the full URL, which carries `client_id` and
the code challenge), `code_verifier_len` (`d.code_verifier.length`), `serial_present`
(`Boolean(d.serial)`), `client_id_present` (`Boolean(d.client_id)`).

`redactNileRegisterData(d: NileRegisterData)` returns an object with exactly these keys:
`code_len` (`d.code.length`), `code_verifier_len` (`d.code_verifier.length`), `serial_present`
(`Boolean(d.serial)`), `client_id_present` (`Boolean(d.client_id)`).

Neither helper may return any field whose value is, or contains, `code`, `code_verifier`, `serial`,
`client_id`, or the full `url`. Lengths and booleans only, plus the host.

Then change the two call sites:
- The `logInfo(['Register data is:', output], LogPrefix.Nile)` site becomes
  `logInfo(['Register data received (redacted):', redactNileLoginData(output)], LogPrefix.Nile)`.
- The `logDebug(['Got register data:', data], LogPrefix.Nile)` site becomes
  `logDebug(['Got register data (redacted):', redactNileRegisterData(data)], LogPrefix.Nile)`.

Keep both lines — do not delete the logging. A silently-removed log line trades one debugging
regression for a security fix; the redacted form keeps the diagnostic value (was the field present,
was it plausibly the right length) with none of the secret.

Add a short comment above each helper naming `F-34.5-G6-17` (site 2 of the pair) and
`F-34.5-G6-20` (site 1 of the pair) and stating the rule for future editors: **nile login/register
payload objects are never logged whole.** Do not touch anything else in this file; in particular do
not change `runRunnerCommand`'s existing argument redaction — reuse its convention, do not rewrite it.
