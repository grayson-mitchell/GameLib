## Decisions Made

- **`EXPECTED_EOS_CALL_SITES = 11`, not recounted upward.** See the dedicated section above.
- **`isEosOverlayEnabled` wrapped but excluded from detection logic.** It is `isWindows`-gated and genuinely never fires on macOS (confirmed by direct read at planning time); using it for `eosOverlayUnavailable` detection would leave macOS undetected on the very probe that never runs there. Only the two unconditional probes drive the flag.
- **`checkForEosOverlayUpdates()`'s two calls (`updateEosOverlayInfo`, `getLatestEosOverlayVersion`) wrapped per the "wrap identically, leave remaining state untouched" bucket**, even though the plan's task text did not name this specific second `getLatestEosOverlayVersion` call site by line number in its channel-grouping breakdown. All 11 raw occurrences needed wrapping per the task's own `<behavior>` block ("Zero bare EOS calls remain"), so this one followed the closest-matching bucket rule.
- **34.5-PORTED-CHANNELS.md's "Two corrections" section header renamed to "Three corrections"** rather than adding an unnumbered fourth paragraph, keeping the document's own counting convention intact.
