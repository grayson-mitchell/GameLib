# Phase 34.5 Plan 01: pathShim extension + GAMELIB_SHELL_EXE handoff Summary

**Extended the sidecar's `getPath()` shim to five names and gave `exe` a real Tauri meaning via a `GAMELIB_SHELL_EXE` spawn-time env var set on both Rust spawn paths, unblocking the shortcuts and saves-sync clusters.**

## Performance

- **Duration:** ~30 min
- **Tasks:** 3/3 completed
- **Files modified:** 3 (1 test file created, 2 files extended)

## Accomplishments

- `pathShim.getPath()` now resolves `desktop`, `exe` and `documents` in addition to the existing four names, with the `exe` case throwing a named, loud error (never an empty string) when `GAMELIB_SHELL_EXE` is unset or empty — closing the gap that would otherwise write a broken launch command into a Steam shortcut VDF or a macOS `.app` `run.sh`.
- Corrected the plan-time attribution of `shortcuts.ts:227`'s `exe` call site from `addToSteam` (CONTEXT.md D-09 / research Correction 3) to `addShortcut` (via `addShortcuts` → `generateMacOsApp`), documented directly in the shim's source comment so a future reader does not re-inherit the wrong attribution.
- Both Rust spawn paths (`spawn_sidecar_dev`, `spawn_sidecar_packaged`) now hand the shell's own binary path down to the sidecar via `.env("GAMELIB_SHELL_EXE", ...)`, computed once in the `spawn_sidecar` dispatcher via `std::env::current_exe()` and formatted by a new pure, `#[cfg(test)]`-proven helper (`shell_exe_env_value`).
- `pathShim.test.ts` is the shim's first dedicated test file, pinning the four pre-existing names as a regression guard, both of `exe`'s distinct throw paths (unset vs. empty), and `desktop`/`documents` resolution under `jest.setupContainment`'s redirected home across darwin/win32/linux.

## Decisions Made

- **`exe` throws rather than returning empty** (D-10, T-34.5-01/T-34.5-02): both known consumers (`nonesteamgame.ts:258`, Steam VDF `Exe`; `shortcuts.ts:227`, macOS `.app` `run.sh`) interpolate the value directly into a launch command with no existence check, so a silent empty string would produce a shortcut that launches nothing.
- **`documents` belongs to saves-sync, not shortcuts** — resolves the open Discretion question CONTEXT.md D-09 left unsettled; its only consumer is `save_sync.ts:146` (`getDefaultGogSavePaths`, reached via `syncGOGSaves` on a native game).
- **Corrected the `shortcuts.ts:227` channel attribution at execution time**, per the plan's own must-haves: `generateMacOsApp`'s only caller is `addShortcuts` (`shortcuts.ts:111`), whose only IPC entry is `addShortcut` — `addNonSteamGame` never reaches this site. The shim's source comment now names both consumers with their correct owning channel.
- **Spawn-time env var over `rustInvoke`** (research Pattern 1): `getPath()` is a synchronous function called from many non-async call sites; an env var preserves that contract, while a `rustInvoke` round-trip would force an async signature change.
