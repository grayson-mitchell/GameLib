Key facts this task depends on:
- The OS title currently tracks the loaded DOCUMENT's title — a value the remote page fully controls. A page can title itself anything, so the current title is NOT an origin indicator and must never be treated as one.
- **`on_navigation` IS FORBIDDEN AS AN ORIGIN SOURCE IN THIS ARM.** `main.rs:1229-1233` states it verbatim: *"The relay is wired to `on_page_load` (main-frame Started/Finished only), NEVER `on_navigation` -- spike 013 measured 5 of 8 `on_navigation` events as third-party iframes, and relaying those would let an ad frame re-arm the sidecar's login-watch deadline forever (Pitfall 2)."* The two existing `.on_navigation(move |url| …)` usages (`humble_reveal_post` line ~1687, `humble_login_clear_storage` line ~1754) are NOT a precedent for this: they are navigation INTERCEPTORS that match one specific non-resolvable host (`REVEAL_EXFIL_HOST` = `gamelib.invalid`) and return `bool` to CANCEL it. Iframe noise is harmless there because a non-matching event is simply allowed through. It is not harmless here — an iframe origin written into the title bar is the inverse of the anti-phishing guarantee. The callback receives only a `Url` and carries no frame-type or main-frame flag, so it cannot be filtered into safety.
- **`on_page_load` IS the main-frame-only signal, and it is ALREADY WIRED on this builder** (line 1321, outside the `if visible` block):
  `.on_page_load(move |_webview, payload| { let kind = match payload.event() { PageLoadEvent::Started => "started", PageLoadEvent::Finished => "finished" }; let event = login_event_value(kind, payload.url().as_str()); push_login_window_event(&event_label, event); })`
  It provides `payload.url()` and is the signal this arm already trusts for exactly this reason.
- `.on_document_title_changed(|window, title| …)` — already wired inside the `if visible` block; `window.set_title(&title)` is the existing title write.
- WR-07's anti-phishing rule, from the same comment block: there is deliberately NO `.title()` call, because *"the loaded document's own title must show, never a hard-coded 'GameLib'"*. This plan does not reinstate a hard-coded title; it PREFIXES the shell-resolved origin.
- `login_window_url_arg(args)` already validates the URL is parseable and https-only; it returns a `tauri::Url`, so an `origin`/`host_str` is available without re-parsing.
- Every `eprintln!("[shell] …")` in this file goes to the SHELL process's stderr — the `pnpm tauri:dev` terminal — NOT to `~/Library/Logs/GameLib/gamelib.log`. The standing `sidecar-console-and-logger-are-invisible` finding means gate evidence must not depend on these lines.
- `.on_document_title_changed`'s existing comment explicitly forbids logging the title STRING (remote page content must never reach an uploadable log); it logs the length only. The same rule binds anything this plan logs.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote login page → OS window title | The document title is fully controlled by the loaded page and is currently the ONLY thing shown to the user |
| remote login page ← injected script | Anything the shell injects runs inside a live credential-entry context |
| shell-resolved URL → user's trust decision | The user decides which stored credential to enter based on what the window tells them |
