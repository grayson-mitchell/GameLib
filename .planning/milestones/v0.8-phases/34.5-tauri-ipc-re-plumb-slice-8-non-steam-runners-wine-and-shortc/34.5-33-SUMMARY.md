- Closed Routing item 1: the sidecar's `refreshLibrary` invoke handler was a Phase 27 walking-skeleton stub (`ipcMain.handle('refreshLibrary', async () => { await steamLibraryManager.refresh() })`) that ignored its runner argument entirely — any GOG/legendary/nile/zoom refresh request under Tauri silently refreshed Steam instead. ## Decisions Made

- **libraryManagerMap over a local SteamLibraryManager instance:** the old handler constructed its own `new SteamLibraryManager()`, a second instance separate from the one every other store-manager consumer reads. The rewrite imports `libraryManagerMap` by name from `../storeManagers` (still the first import, preserving the load-bearing circular-dependency fix from Phase 27 Plan 05) and drops the local construction and its direct `steam/library` import entirely — this also removes the one remaining direct-import hazard the module's own docstring warned about.
- **Own-property check, not `in`:** `Object.prototype.hasOwnProperty.call(libraryManagerMap, rawRunner)` rather than `rawRunner in libraryManagerMap`, so a renderer-supplied string like `'constructor'` or `'toString'` cannot spoof a valid runner via the prototype chain (T-34.5-C4-10).
- **HumbleLibrary ported, WR-05 CrossOver re-resolve not:** `HumbleLibrary.recomputeOwnership()` is already in the sidecar's import graph (via `humbleFlowRegistration.ts`) and has no dependency on `storeManagers`/`steam/library`, so porting it adds no new module and no circular risk. `refreshCrossoverRatingMap()` is a module-private function in `main.ts` (never exported) built on a filesystem/network-scanning helper with its own unrelated import graph — porting it would mean exporting new cross-cutting surface out of an Electron-only entry file, out of scope for a defect whose blocking behavior is "GOG library never lands," not "CrossOver badges go stale by one session." Recorded explicitly in the module docstring per the task's own instruction never to leave an omission unexplained.
- **origin kept local, not added to common/types.ts:** this plan's `files_modified` frontmatter scopes to `GlobalState.tsx` only. Threading `origin` into the shared `RefreshOptions` type and the `window.api.refreshLibrary` preload signature would touch `src/common/types.ts` and `src/frontend/types.ts`, outside that scope — deferred as a follow-up, `origin` defaults to `'unknown'` for the 8 external caller files this plan does not touch (`ClearCache.tsx`, `ConsoleMode/index.tsx`, `Login/index.tsx`, `SidebarLinks/index.tsx`, `ErrorComponent/index.tsx`, `ActionIcons/index.tsx`, `SideloadDialog/index.tsx`, `EgsSettings.tsx`).
- **New frontend test file added despite not being in files_modified:** the plan's own acceptance criteria for Task 2 required tests asserting on the log-line behavior, and `GlobalState.tsx` cannot be imported under this project's DOM-less frontend jest project (documented in the pre-existing `GlobalStateSteamLogout.test.ts`). A new structural-gate test file, following that exact established pattern, was the only way to satisfy the task's own test requirement without violating the DOM-less constraint. The `files_modified` acceptance criterion's explicit enumeration ("specifically NOT ClearCache.tsx, ... EgsSettings.tsx") targets the 8 unrelated caller files, not new test coverage for the very method being changed — none of those 8 files were touched.
