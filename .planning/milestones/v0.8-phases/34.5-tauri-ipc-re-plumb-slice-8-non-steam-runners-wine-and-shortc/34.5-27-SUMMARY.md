# Phase 34.5 Plan 27: Login Window Origin Title + Light Interface Style Summary

**Closed F-34.5-G6-04 (phishing-resistance: no origin indicator in the chromeless login window) and F-34.5-G6-05 (black-on-black Amazon verification-code text) with an origin-first OS title bar sourced only from the arm's existing main-frame-only `on_page_load` hook, and a `.theme(Some(tauri::Theme::Light))` request on the visible builder — both source-gated, neither closed on the strength of a green test suite alone.**

## Accomplishments

- Added `login_window_title(origin: &str, document_title: Option<&str>) -> String`, a pure, `AppHandle`-free helper (mirrors the file's existing `clipboard_text_arg`/`login_window_url_arg` convention) that places the shell-resolved origin FIRST, unconditionally — a document title crafted to look like a URL (e.g. `https://accounts.google.com/signin`) can never precede the real origin, only follow it.
- Wired a shared last-known main-frame origin (`Arc<Mutex<String>>`) into `humble_login_open`: seeded from the validated open URL before `.build()`, refreshed ONLY from the arm's already-wired `on_page_load` hook (main-frame `Started`/`Finished` only), and read by `on_document_title_changed` so a page-title change is always composed against the current host, never a stale one.
- **Explicitly did NOT use `on_navigation`** as an origin source, per the arm's own pre-existing rule (spike 013 measured 5 of 8 `on_navigation` events as third-party iframes, and the callback carries no frame-type flag to filter them). This is now stated for the title's origin source specifically, not just the login relay, in the arm's own doc comment — "one convention, not two."
- Requested a light interface style on the visible builder only (`.theme(Some(tauri::Theme::Light))`), addressing the likely `prefers-color-scheme` mismatch behind the developer's black-on-black report on Amazon's verification-code field, without injecting any CSS or script into the third-party page.
- Extended `tauriShellSource.test.ts` with a scoped positive/negative source-gate pair proving the title refresh lives inside `.on_page_load(`'s own block and that the arm contains no `.on_navigation(` call — deliberately scoped to the arm's own comment-stripped body, since this plan's justifying prose names `on_navigation` repeatedly and would satisfy an unscoped count vacuously.
