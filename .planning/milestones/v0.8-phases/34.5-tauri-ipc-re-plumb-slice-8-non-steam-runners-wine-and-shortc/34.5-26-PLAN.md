<objective>
Close layer 2 of F-34.5-G6-02, and with it F-34.5-G6-03 ("GOG games are not showing in Library and
Gog is not available as a filter option", and "account manager did not reflect that i had logged
in").

Purpose — **this is the finding that would have caused a THIRD failed gate.** Plan 34.5-23 makes the
captured outcome reach the renderer. But `useTauriOAuthLogin` deliberately calls the RAW
`window.api.login` / `authGOG` / `authAmazon` channels rather than `GlobalState.tsx`'s
`epicLogin`/`gogLogin`/`amazonLogin` wrappers — its own module doc states this is intentional, so it
could own the `UNPORTED_CHANNEL_MARKER` catch without touching `GlobalState.tsx`. That was correct
while the channels were unported. Now that Phase 34.5 has ported them, the consequence is that the
one thing those wrappers do AFTER a successful auth — `setState({ [runner]: { username } })` followed
by `handleSuccessfulLogin(runner)`, which calls `refreshLibrary({ library: runner })` — never runs.

So even with layer 1 fixed, the auth would succeed and the library would still be empty, the
username still null, and the runner still absent from the filter list: precisely what the developer
reported. Fixing only layer 1 and going straight to the gate would have reproduced the same FAIL for
a different reason.

Output: the captured code routed through the completion path, with the refresh asserted by test.
</objective>
