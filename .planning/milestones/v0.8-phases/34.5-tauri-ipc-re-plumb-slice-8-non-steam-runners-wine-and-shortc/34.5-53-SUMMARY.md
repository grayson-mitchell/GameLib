# Phase 34.5 Plan 53: nile OAuth code / PKCE code_verifier log redaction (F-34.5-G6-17, F-34.5-G6-20) Summary

**Both nile credential-logging call sites (`NileUser.login`'s `logDebug` and `NileUser.getLoginData`'s `logInfo`) now route the raw `NileRegisterData`/`NileLoginData` payload through a dedicated redaction helper before it reaches the logger -- neither the single-use OAuth `code`, the PKCE `code_verifier`, nor the full authorize URL is written to `gamelib.log` in cleartext any more.**

## Accomplishments

- Added `redactNileLoginData`/`redactNileRegisterData` immediately above the `NileUser` class in `src/backend/storeManagers/nile/user.ts`, each returning only lengths, presence booleans, and (for the login-data helper) the authorize URL's host via `new URL(d.url).host` (falls back to the literal `<unparseable>` string on a parse failure, never the full URL).
- Rewired both call sites to pass the helper's output instead of the raw payload object; neither log line was deleted, per the plan's explicit instruction (a silently-removed log line trades a debugging regression for a security fix).
