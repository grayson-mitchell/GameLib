**The defect found — the redaction sweep self-matches its own documentation.** The original sweep
pattern (`access_token=[^<]|refresh_token=[^<]|...`) was designed to catch "anything after
`fieldname=` that isn't the redacted placeholder." Run against the FILLED specimen as a whole-file
grep, it matched its own documentation line — the character immediately after `access_token=` in
the pattern's own quoted-in-prose text is `[`, which satisfies `[^<]`:

```
$ grep -oE "access_token=[^<]" <<< 'access_token=[^<]|refresh_token=[^<]|...'
access_token=[
```

**Proven with `git`, not merely asserted** — a throwaway repo was built to test the ACTUAL
prescribed invocation (`git diff --cached -- <file> | grep ...`) under two scenarios:

1. **Incremental diff (the normal case — this document already committed unfilled, then filled):**
   `git diff --cached -- 34.5-LIVE-GATE-RERUN-3.md | grep -nE "..."` → **exit 1, no match** — the
   static prose (including the sweep's own definition) is unchanged and does not appear in the
   diff, so no self-match occurs in the normal workflow.
2. **Whole-file-fresh diff (a real risk — this document's OWN first commit, or any future
   squash/re-diff):** staging the entire file fresh and running the same command →
   ```
   131:+git diff --cached -- 34.5-LIVE-GATE-RERUN-3.md | grep -nE "access_token=[^<]|refresh_token=[^<]|..."
   exit: 0
   ```
   **A false positive, confirmed live, with zero credential content.**

**The fix.** Replaced every `[^<]` single-character exclusion class with a 4+-character
token-alphabet requirement (`[A-Za-z0-9._+/=-]{4,}`), which no regex-punctuation string (`[`, `^`,
`<`, `]`, `(`, `)`, `|`) satisfies in a run of 4. Verified against 11 cases (5 safe forms, 6
real-leak-shaped forms) before committing:

```

OK  expect=False got=False  [safe: field name only]              access_token=
OK  expect=True  got=True   [BAD: real-looking leaked token]     access_token=eyJhbGciOiJIUzI1NiJ9...
OK  expect=False got=False  [safe: doc prose describing regex]   access_token=[^<]
OK  expect=False got=False  [safe: doc prose w/ brackets]        the character after access_token= is [
OK  expect=True  got=True   [BAD: real refresh token]            refresh_token=abcDEF123456
OK  expect=True  got=True   [BAD: real cookie]                   Cookie: SESSIONID=abcd1234efgh
```
