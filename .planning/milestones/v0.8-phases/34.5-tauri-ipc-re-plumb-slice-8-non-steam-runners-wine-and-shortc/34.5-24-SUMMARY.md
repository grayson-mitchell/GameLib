# Phase 34.5 Plan 24: F-34.5-G6-01 Discriminator Instrument Summary

**Built the observation Epic's OAuth capture never had — hostname-only navigation logging plus a source-free UA override — and pre-registered a two-arm, four-outcome discriminating experiment (`verdict: null`) that separates "Epic's login form is UA-gated" from "a WKWebView-only API throw is aborting it" before any live run happens.**

## Performance

- **Duration:** ~50 min
- **Completed:** 2026-08-01
- **Tasks:** 3 (all completed)
- **Files modified:** 2, created 1

## Accomplishments

- **Task 1 — nav host logging.** Added a `nav host=${hostname}` log line to `captureOAuthLogin`'s
  poll loop, computed from `new URL(event.url).hostname` inside its own try/catch (`<unparseable>`
  on a parse failure, never a throw), de-duplicated against the last LOGGED hostname (not merely
  observed) so a 500ms poll over the 300-second deadline cannot flood the log with repeats.
  Hostname ONLY — never origin, pathname, search, or href — because Epic's own redirect shape
  carries its authorization code in the query string (`matchOAuthRedirect`'s `legendary` branch),
  matching the module's existing T-34.4.1-45 logging discipline and the `nile` origin-mismatch
  line's precedent. This is the exact observation both prior 34.5 gate runs lacked: with it, "the
  form never submitted" (window sits on one hostname the whole attempt) becomes separable from
  "the submission was challenged elsewhere" (window reaches a second hostname).
- **Task 2 — diagnostic UA override seam.** Added `resolveUserAgent(runner)`, replacing the
  direct `USER_AGENTS[runner]` lookup at the `activeSeam.open()` call site. Reads
  `GAMELIB_OAUTH_UA_<RUNNER-UPPERCASED>`; unset, empty, or whitespace-only falls back to the
  existing default byte-for-byte (an empty UA is the forbidden failure mode the standing spike
  finding names). When an override is in effect, logs the runner and the override's LENGTH only,
  never the value. This makes plan 34.5-28's two-arm experiment ONE build, ONE environment
  variable, rather than a hand-edit-and-rebuild between arms that would make the two arms
  non-comparable.
- **Task 3 — pre-registered discriminator.** Wrote
  `34.5-G6-EPIC-DISCRIMINATOR.md` with `verdict: null`, `executed_by: 34.5-28-PLAN.md`,
  `blocking: false`. Names **R1** (user-agent gated — GOG/Amazon's Chrome-shaped agent reaches an
  interactive form, Epic's Chromium-`<webview>`-derived `EpicGamesLauncher` agent does not) and
  **R2** (WKWebView API gated — a Chromium-only API throws during Epic's form-enablement script,
  mirroring the confirmed `queryLocalFonts` precedent). The decision-rule table covers all four
  outcome combinations of a two-arm experiment, including the two that FALSIFY rather than
  confirm a reading (both-non-interactive falsifies R1 without confirming R2; both-interactive
  means NOT REPRODUCED, routing to a re-run of the originally-failing arm rather than a close) and
  the "neither fits → stop and escalate" branch. The `nav host=` sequence must be recorded for
  BOTH arms unconditionally, since it is independent evidence neither reading predicts identically.
  Explicitly reconciled against `34.5-G6-FINDINGS.md`: no divergence, F-34.5-G6-01 stays a
  separate, upstream defect from the already-closed F-34.5-G6-02.

## Decisions Made

- **Hostname only, never origin/path/query/fragment** — enforced both in the log line itself and
  by a dedicated test asserting a `?code=SECRETVALUE` event leaves no trace of the value in any
  logged string, even when that same event settles the capture as `status=captured`.
- **Dedup against the last LOGGED host, not the last OBSERVED one** — a same-host poll sequence
  (the common case: a page that hasn't navigated yet) writes exactly one line regardless of how
  many poll cycles observe it, verified with a real 500ms-interval fake-timer test.
- **UA override is diagnostic-only, explicitly documented as such** — the doc comment states
  removing it later requires a live re-proof of whichever UA the discriminator selects; it is not
  presented as a permanent configuration knob.
- **The discriminator document takes no side** — R1 and R2 are both given equal treatment (named
  mechanism, prior supporting evidence, and a distinct row in the per-reading prediction table);
  the decision-rule table was written to name all four outcome combinations, including two that
  FALSIFY a reading rather than confirm the other one by elimination, per this project's own
  standing "count/build a discriminator, don't ship the nicer reading" lesson from F-10.
