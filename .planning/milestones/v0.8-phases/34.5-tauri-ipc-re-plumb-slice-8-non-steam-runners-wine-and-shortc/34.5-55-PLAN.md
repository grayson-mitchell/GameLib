## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> sidecar IPC | A deferred channel rejects here; whether that rejection reaches a human is the whole subject of this plan |
| UI state -> user's belief about backend state | A confident empty list is a false claim, not a neutral one |
| `callOrDeclare` log message -> uploadable `gamelib.log` | The message must never carry a call argument |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.5-C7-13 | Spoofing | Winetricks panel, sites 8-9 | mitigate | A `catch { setX([]) }` makes the UI assert, falsely and confidently, that the prefix has no winetricks components. Replaced by a `declined` state that renders an explicit unavailable message and never substitutes an empty array. |
| T-34.5-C7-14 | Spoofing | SteamGridDB API-key field, sites 1-2 | mitigate | An editable key field with an inert Save is a false success surface. On decline the field is disabled and labelled unavailable. |
| T-34.5-C7-15 | Information disclosure | `callOrDeclare` log line | mitigate | `CallOrDeclareSpec` carries no `args` field by construction (T-34.5-48-04); the emitted message contains only marker, feature, channel, deferral id and the error message. `steamgriddb.searchGame` takes a user query and `winetricksInstall` takes an app name — neither may reach the log.
