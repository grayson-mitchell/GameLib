### Rule 1 fix discovered building Task 2

**Found during:** Task 2, while wiring Describe 6's `beforeAll` (`handlerRegistry.clear();
listenerRegistry.clear(); register all four`).

**Issue:** `registerRunnerAuthFlows`/`registerShortcutsFlows` each carry a permanent, module-scope
`let registered = false` idempotence guard. Once flipped true by their first real call in this
file's process (Describe 3's own `it.each`, which runs before Describe 5/6/7), every later call
is a silent no-op — including a call made *after* the registries have been cleared. The
pre-existing Describe 5 (`containment pin`) test clears both registries per module iteration and
its own `afterAll` re-invoked all four `registerXFlows()` functions to "restore" state for later
describes/files — but for the two guarded modules that restore was a no-op. Measured directly:
after Describe 5's original `afterAll` ran, `handlerRegistry.size` was 20 (only `wineTools`'s 9 +
`runnerMisc`'s 11 — the two guard-free modules — survived), not 34. Any describe or test FILE
that ran afterward in the same jest worker would have silently seen an incomplete registry.

**Fix:** Added a canonical registration snapshot at module scope (before any `describe`/`it`
runs, guaranteeing it is the true first invocation of every `registerXFlows()` in the process):
clear both registries, call all four functions once, then snapshot both registries into plain
arrays. Added `restoreCanonicalRegistrations()`, which clears and repopulates both registries
from that snapshot. Replaced every "re-invoke all four `registerXFlows()`" restore point
(Describe 5's `afterAll`, Describe 6's `beforeAll`/`afterAll`, Describe 7's `beforeAll`/`afterAll`)
with a call to this helper.
