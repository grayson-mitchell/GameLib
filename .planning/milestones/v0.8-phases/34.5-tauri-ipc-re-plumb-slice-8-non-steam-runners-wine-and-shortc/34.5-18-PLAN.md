<objective>
Close G-3, a GATE-CONTRACT defect rather than a code defect, and give G-1's fix a runtime witness.

`GAMELIB_SHELL_EXE` is emitted at exactly one place in the tree — `eprintln!` at
`src-tauri/src/main.rs:1231`, on the SHELL's stderr, i.e. the `pnpm tauri:dev` terminal. Nothing
writes it to `gamelib.log`. So `34.5-LIVE-GATE.md`'s precondition 5 ("read it back from
`gamelib.log`") and precondition 2 ("sidecar output is read from that log file and NOT from the
terminal") cannot both be satisfied. The gate document names two closures and marks the first
preferred: have the SIDECAR log the value it actually received. That is strictly stronger evidence —
`main.rs:1231` cannot distinguish "set on the child env" from "actually visible to `pathShim`".

The same boot moment is the right place to make plan 34.5-16's app-root handoff observable: an
existence-checked line per runner binary, logged before any login can be attempted, turns the
2026-08-01 failure mode (a silent hang, diagnosed only by reading four source files) into one
greppable error line.

Purpose: make the gate's preconditions satisfiable from the log file alone, and make this failure
family visible at boot.
Output: boot-time receipt logging and an asset-root self-check in the sidecar's `init()`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Sidecar process env → `gamelib.log` | Values received from the parent are written to a file users routinely upload with bug reports |
| Boot diagnostics → process lifetime | Anything that throws here runs before `READY_SENTINEL` and would hang the app at a blank window |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.5-G3-01 | Information disclosure | Logging `GAMELIB_SHELL_EXE`, the app root and binary paths | accept | Absolute filesystem paths only — no tokens, cookies, credentials or user identifiers. `gamelib.log` already carries comparable paths (the existing `locales` warning, `callRunner`'s command lines). Explicitly NOT logged: `process.env` in bulk, any `GAMELIB_*` value other than the two named here |
| T-34.5-G3-02 | Denial of service | A throwing diagnostic blocking `READY_SENTINEL` | mitigate | Both blocks are wrapped in try/catch with a log-and-continue catch, both are placed after `initLogger()` so the logger exists, and a test asserts `READY_SENTINEL` is still written on the failure arm |
| T-34.5-G3-03 | Repudiation | Reading the parent's `eprintln!` claim as proof of the child's state | mitigate | This plan exists precisely to replace that inference: the log line reports `process.env` as observed INSIDE the sidecar, and the gate re-run's precondition 5 is rewritten (plan 34.5-19) to cite this line rather than the terminal |
| T-34.5-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages; `files_modified` contains no manifest or lockfile |
