## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] PowerShell `-ArgumentList` redaction regex never matched anything, for any flag (F-34.5-G6-25)**
- **Found during:** Task 1, while verifying "BOTH branches redact each added flag" per the plan's own acceptance criteria
- **Issue:** `new RegExp(`"${sensitiveArg}","(.*?)"`)` assumed each `-ArgumentList` member was wrapped as a bare `"value"`; `callRunner`'s own `argsAsString` construction actually wraps every argument as `` `"value`"" `` (backtick-quoted). The regex's literal `"flag"` substring can never appear in that wrapped text, so the redaction `.replace()` was always a silent no-op on the PowerShell branch -- for `--code`/`--token` too, not only the new flags. Proven pre-existing by driving the UNCHANGED pre-fix regex against `--code` alone via a mocked-Windows probe.
- **Fix:** Corrected the regex and its replacement to match the real backtick-quoted shape (see `launcher.ts` inline comment for the exact before/after).
- **Files modified:** `src/backend/launcher.ts` (same commit as the census-list expansion, `b83595581`)
- **Verification:** RED (raw sentinel present) before, GREEN (all sentinels `<redacted>`) after -- captures below.
- **Committed in:** `b83595581` (Task 1 commit)
