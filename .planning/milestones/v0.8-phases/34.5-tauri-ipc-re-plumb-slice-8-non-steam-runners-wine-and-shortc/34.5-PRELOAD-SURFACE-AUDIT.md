## Method — the extractor (multi-line-aware, comment-stripping)

Two failure modes were measured at planning time and re-confirmed here: a naive single-line
regex undercounts by 11 (5.1%) because Prettier wraps 11 call sites across newlines, and an
any-backtick parse of `IPC-PORT-INVENTORY.md` overcounts because the ⚠ `F-34.5-G6-10` warning
paragraph names `getInstallInfo` in backticks while explaining that it is missing — prose *about*
an omission reads identically to coverage of it under a naive parse. Both traps are addressed
below and their evidence is pasted, not claimed.

### Extractor source (verbatim; re-run with `python3 extract_preload_surface.py [repo-root]`)

```python
#!/usr/bin/env python3
"""Preload surface extractor — multi-line-aware, comment-stripping.
Walks src/preload/**/*.ts (excluding __tests__), strips /* */ and // comments
(without breaking :// inside string literals), and extracts every distinct
channel name passed as a bare string literal to makeHandlerInvoker (invoke),
makeListenerCaller (send), or frontendListenerSlot (push). Multi-line-aware:
the factory name, its opening paren, and the string literal may be split
across lines (re.S lets '.' match newlines), which is the entire difference
between this extractor's 217 and a single-line regex's 206.
"""
import re
import sys
from pathlib import Path

BLOCK_COMMENT = re.compile(r"/\*.*?\*/", re.S)


def strip_comments(text: str) -> str:
    text = BLOCK_COMMENT.sub("", text)
    out = []
    for line in text.split("\n"):
        i, cut = 0, None
        while True:
            j = line.find("//", i)
            if j == -1:
                break
            if j > 0 and line[j - 1] == ":":  # don't treat :// as a comment start
                i = j + 2
                continue
            cut = j
            break
        out.append(line[:cut] if cut is not None else line)
    return "\n".join(out)


CALL_PATTERN = re.compile(
    r"\b(makeHandlerInvoker|makeListenerCaller|frontendListenerSlot)\s*\(\s*['\"]([^'\"]+)['\"]",
    re.S,
)


def extract(preload_root: Path):
    invoke, send, push = set(), set(), set()
    occurrences = []
    files = sorted(p for p in preload_root.rglob("*.ts") if "__tests__" not in p.parts)
    for f in files:
        stripped = strip_comments(f.read_text(encoding="utf-8"))
        for m in CALL_PATTERN.finditer(stripped):
            factory, name = m.group(1), m.group(2)
            line_no = stripped.count("\n", 0, m.start()) + 1
            {
                "makeHandlerInvoker": invoke,
                "makeListenerCaller": send,
                "frontendListenerSlot": push,
            }[factory].add(name)
            occurrences.append((name, factory, f, line_no))
    return invoke, send, push, occurrences


def single_line_baseline(preload_root: Path):
    """The naive alternative: identical pattern, but matched per physical line (no re.S) —
    measures what an extractor that is NOT multi-line-aware would have found."""
    pat = re.compile(r"\b(makeHandlerInvoker|makeListenerCaller)\s*\(\s*['\"]([^'\"]+)['\"]")
    found = set()
    for f in sorted(p for p in preload_root.rglob("*.ts") if "__tests__" not in p.parts):
        stripped = strip_comments(f.read_text(encoding="utf-8"))
        for line in stripped.split("\n"):
            found |= {m.group(2) for m in pat.finditer(line)}
    return found


if __name__ == "__main__":
    root = Path(sys.argv[1]) if len(sys.argv) > 1 else Path(".")
    invoke, send, push, occ = extract(root / "src" / "preload")
    print(f"distinct invoke: {len(invoke)}")
    print(f"distinct send: {len(send)}")
    print(f"union: {len(invoke | send)}")
    print(f"distinct push (out of tally): {len(push)}")
    single = single_line_baseline(root / "src" / "preload")
    print(f"single-line-only regex finds: {len(single)} (delta {len(invoke | send) - len(single)})")
```

### Bucket-membership parse (verbatim)

```python
import re
from pathlib import Path

doc_lines = Path(".planning/IPC-PORT-INVENTORY.md").read_text(encoding="utf-8").splitlines()
bucket_names = set()
for ln in doc_lines:
    names = re.findall(r"`([A-Za-z0-9_.-]+)`", ln)
    if len(names) >= 5:          # bucket-line scoping rule — see justification below
        bucket_names |= set(names)
```

**Bucket-line scoping rule and justification.** Bucket membership is parsed **only from lines
carrying 5 or more backticked names** — the exact shape every real bucket list in
`IPC-PORT-INVENTORY.md` uses (a long comma-separated list of `` `channelName` ``). Parsing
**every** backtick in the document instead yields **256** names (measured this run) and makes
`getInstallInfo` look listed on the pre-34.5-43 tree, because the ⚠ `F-34.5-G6-10` paragraph
names it in backticks while explaining that it is **absent** from every bucket — the prose that
records the omission would mask it under an any-backtick parse. This is a live vacuity trap in
this exact document, not a hypothetical one. Cross-check: bucket-line parsing on the tree handed
to this plan (post-34.5-43) finds **211** distinct names, which agrees exactly with
`## Totals` → "Unique channels | 211" as it stood before this plan's own edits.

## What this audit does NOT prove

This audit enumerates the surface **as exposed in preload**. It does not prove:
- That any enumerated channel **works** — "bucketed" is not "verified working."
- That any bucket's own prior port claims (the 39/3/16 split, the EOS/SteamGridDB/winetricks
  clusters) are themselves correct — this audit takes those as given and diffs against them.
- Anything about the reverse-direction names (§ (f) above) beyond their bare existence in a
  bucket line with no preload exposure found.
- Anything about `oauthCaptureLogin`/`connectivity-changed`/`get-connectivity-status`'s runtime
  correctness beyond "a handler is registered and reached at boot" — no live session exercised
  their full behavior as part of this plan.

It retires **no ledger row other than `U-34.5-14`**, and it makes no claim that any of the newly
bucketed channels declines honestly, is reachable from the UI, or behaves correctly under a real
`pnpm tauri:dev` session. `U-34.5-28` (opened by this plan, see `34.5-UNTESTED-ITEMS.md`) exists
specifically to record that gap for the newly-bucketed unported channels.
