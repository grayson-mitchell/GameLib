<objective>
Close `F-34.5-G6-16` — the anti-phishing origin indicator built by Plan 34.5-27 is set on the
login window's `NSWindow` title and is **never visible on macOS**, because that window is
unconditionally presented as a titleless AppKit sheet.

Purpose: gate item 1's clause (i) cannot pass on any re-run of any contract without this fix, and
`U-34.5-05`'s transcription bar is permanently unsatisfiable until it exists.

Output: an always-present, self-re-appending **in-page origin banner** injected by the exact same
mechanism as the already-shipped, already-live-PASSED cancel strip, plus a shell-driven update on
every main-frame origin change.
</objective>

<binding_decisions>
**D-CYCLE7-A (operator, 2026-08-13) — LOCKED.** The routing document offers two fixes for this
item ("stop presenting this window as a sheet, or find an AppKit-supported way to surface origin
text on a sheet"). **The first option is factually closed and the routing document is wrong to
still offer it.** Per `.claude/skills/spike-findings-gamelib/references/login-window-ux-macos.md`
§ "Current status (2026-08-05)" and Requirement 1: child-window attachment is off the table
**permanently** (measured live-broken, F-34.4.2-01/-02: unresponsive after minimize/restore, could
not be closed), and a free-floating login window was the original bug that started that whole line
of work. AppKit sheet presentation + the mandated cancel strip + the bare-Esc backstop is SHIPPED
and live-PASSED (`34.4.2-LIVE-GATE-RERUN-2.md` items 1-2).

Therefore the fix is: surface the live origin in an always-present, self-re-appending **in-page**
element, **reusing the exact injection mechanism the mandated cancel strip already uses**. Do not
invent a second injection path. Do not remove, weaken, reposition or re-layer the cancel strip.

`U-34.5-05`'s transcription bar is **RE-TARGETED** to that in-page element instead of the
`NSWindow` title. The row does not simply retire — its own named observation changes, and that
change is written into the ledger explicitly by Task 3. `F-34.5-G6-16` closes when the banner is
**live-transcribed**, not when this code lands.
</binding_decisions>

**Helper 1 — `fn login_origin_banner_script(origin: &str) -> String`.** Builds the JS injected as
an `initialization_script()`. Interpolate the origin ONLY through `serde_json::to_string(origin)`
into an `@@ORIGIN@@` placeholder, with the same `unwrap_or_else` fallback shape the cancel strip
uses for its host — never naive string interpolation. Required properties of the emitted script,
each of which Task 1's tests assert:
  - `concat!` of single-line pieces; every JS string literal single-quoted.
  - Top-frame guard `if (window.top !== window) { return; }` placed BEFORE the idempotence flag.
  - Idempotence flag `window.__GAMELIB_LOGIN_ORIGIN_BANNER__`.
  - Stores the current origin on `window.__GAMELIB_LOGIN_ORIGIN_VALUE__` so Helper 2 can update it.
  - Element id constant `'__gamelib_login_origin_banner__'`.
  - Sets text via `textContent` ONLY. The literal `innerHTML` must not appear anywhere in the body.
  - `position: 'fixed'`, `top: '8px'`, `left: '8px'` — the LEFT corner, so it can never overlap the
    cancel strip's `top: 8px / right: 8px`.
  - `zIndex = '2147482999'` — strictly BELOW the cancel strip's `'2147483000'`, so the banner can
    never paint over the sheet's only exit affordance.
  - `pointerEvents = 'none'` and `userSelect = 'none'`; registers NO event listener of any kind —
    no `click`, and specifically no `keydown`/`keyup`/`keypress` (REQ-34.4.2-06: Cmd+V into the
    password field must keep working, and it is the sole credential-entry route this project ships).
  - Never reads any input's `value`; never transmits anything anywhere; creates no iframe.
  - Self-re-append: a `MutationObserver` on `document.documentElement` with `{ childList: true,
    subtree: true }` and the same 200ms debounce/`scheduleEnsure()`/`ensure()`/`build()` shape as
    the cancel strip, plus the `DOMContentLoaded` arm for `document.readyState === 'loading'`.
  - The whole body in exactly ONE top-level `try {` / `} catch (e) { }` — a throwing banner must
    never break a live login page.
  - Pure: the same origin input always yields byte-identical output.

**Helper 2 — `fn login_origin_banner_update_script(origin: &str) -> String`.** A small script for
`window.eval()` on origin change: JSON-escape the origin the same way, assign it to
`window.__GAMELIB_LOGIN_ORIGIN_VALUE__`, and if `document.getElementById('__gamelib_login_origin_banner__')`
exists set its `textContent` to that value; wrapped in its own single top-level try/catch; no
listeners, no `innerHTML`.

Add a `#[cfg(test)]` block mirroring the cancel strip's own test set, in the same `mod tests`:
  - embeds the origin exactly once as a JSON-escaped literal;
  - escapes a tricky origin (use `https://ex\"a'mple.com` shaped input) and never naively
    interpolates it;
  - binds no keyboard listener (assert `keydown`, `keyup`, `keypress` and `addEventListener` are
    each absent);
  - never reads a field value (assert `.value` and `password` are absent);
  - uses `textContent` and never `innerHTML`;
  - top-frame guard index is strictly less than the idempotence-flag index;
  - the banner's z-index literal `'2147482999'` is present AND parses to a value strictly less than
    the cancel strip's `'2147483000'` — assert this by extracting both numbers, not by substring
    presence alone;
  - `pointerEvents` is set to `'none'`;
  - wrapped in a single top-level try/catch (assert `"try {"` occurs exactly once, matching
    `login_cancel_strip_script_is_wrapped_in_a_single_top_level_try_catch`);
  - pure — two calls with the same origin are byte-equal;
  - the update script contains the new origin and differs from the output for a different origin.

**RED proof is mandatory and must be captured in the SUMMARY.** Before accepting the tests, prove
at least these three fail against a known-bad body, then restore: (a) swap `textContent` for
`innerHTML`; (b) raise the banner z-index literal to `'2147483001'`; (c) add a `keydown`
`addEventListener` to the banner. An assertion that has never been shown to fail is not accepted —
this project has shipped 7 vacuous negative assertions in a single phase.

| Boundary | Description |
|----------|-------------|
| remote login page -> injected banner script | The store's own page is fully attacker-controlled relative to this project; the banner runs inside that document |
| shell (Rust) -> injected JS | The origin string crosses from validated Rust state into a JS source string |
| injected banner -> the mandated cancel strip | Both are in-page elements competing for the same viewport and stacking context |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.5-C7-01 | Spoofing | in-page origin banner | accept | An in-page indicator sits inside the attacker's document and a hostile page can render a look-alike. Accepted because the alternative (OS chrome) is structurally invisible in a sheet and child-window attachment is permanently closed (D-CYCLE7-A). Reduced by: fixed id re-ensured by a MutationObserver, top-LEFT placement away from the strip, `pointerEvents: none`. Residual recorded as `U-34.5-31`, not silently absorbed. |
