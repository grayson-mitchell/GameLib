# Phase 34.5 Plan 16: App Root Sweep + GAMELIB_APP_ROOT Handoff Summary

**Closed the root cause of live-gate items 1/2/3/5 (Epic/GOG/Amazon login + Wine) by sweeping every `publicDir`/`getAppPath()` consumer and installing one Rust-to-sidecar `GAMELIB_APP_ROOT` env var seam, rather than patching the `bin/` path alone — the exact mistake that produced the 4th recurrence.**

## Accomplishments

- Enumerated 25 non-test `publicDir`/`getAppPath()` call sites across the backend by reading real
  import chains (never assumed), classifying 15 as `FIXED BY ROOT`, 9 as `SAFE` (structurally
  unreachable from the sidecar module graph), and 1 (`archSpecificBinary`'s x64 fallback) as
  fixed-for-the-app-root-question-but-still-owed-an-existence-check by plan 34.5-17.
- Surfaced a previously-unnoticed silent failure while doing the sweep: `crossover_index/
  fetcher.ts:52`'s bundled-snapshot read has been silently falling back to `null` under the
  sidecar since the day it became reachable, because its own try/catch treats ENOENT as a normal
  cold start.
- Added `GAMELIB_APP_ROOT` to the Rust shell's spawn-time environment handoff on both
  `spawn_sidecar_dev` (compile-time `CARGO_MANIFEST_DIR` parent, honoring an override) and
  `spawn_sidecar_packaged` (`app.path().resource_dir()`), mirroring the existing
  `GAMELIB_SHELL_EXE` shape exactly — same non-panicking, empty-string-on-failure contract.
  Cargo test count rose from 80 to 84.
- `electronStub.app.getAppPath()` now consumes `GAMELIB_APP_ROOT`, falling back to
  `process.cwd()` (today's behaviour) when unset/empty — proven by a new suite covering both
  arms plus a source-text assertion against the real `main.rs`.
- Full suite: `npx tsc --noEmit` clean; `npm run test:ci` — **Test Suites: 179 passed, 179
  total; Tests: 3454 passed, 3454 total** (up from the 3447 baseline recorded in
  `34.5-LIVE-GATE.md`).

## Decisions Made

- One env-var seam (`GAMELIB_APP_ROOT`) rather than N per-call-site patches — see
  `34.5-APP-ROOT-SWEEP.md` § 2 for the full rejected-alternatives list (cwd change,
  per-call-site `join()`, `__dirname` math) and why each was rejected.
- `getAppPath()`'s fallback stays non-throwing by design (module-scope call site, pre-logger
  failure would be invisible) — loudness is plan 34.5-18's job, not this plan's.
- The packaged asset root is explicitly named as unresolved (`R-34.5-G1-PKG`), not silently
  assumed fixed by extension of the dev-path fix.

## Deviations from Plan

**1. [Process note, not a Rule 1-4 deviation] Task 2's TDD RED/GREEN landed as a single Rust commit.**

The plan's `tdd="true"` flag on Task 2 calls for the standard RED-then-GREEN-then-REFACTOR commit
cadence. This repo's existing Rust convention (visible in every prior `#[cfg(test)] mod tests`
addition across `main.rs`, e.g. `shell_exe_env_value`'s own commit history) lands a new pure
helper and its unit tests together in one `feat` commit rather than a separate failing-test
commit first — Cargo's test harness has no equivalent of a standalone "run just the new test
file" RED-phase gate the way `npx jest <file>` does for the JS side, and this project's own
prior plans (34.5-01 through 34.5-15) consistently followed the same one-commit-per-Rust-task
shape. Followed the established convention rather than introducing a new one for this plan alone.
`cargo test` was run and confirmed 84/84 passing (up from 80) before the commit, so GREEN was
verified even though it isn't a separately-committed step.
