<objective>
Close `F-34.5-G6-22` — the blocker plan 34.5-57's code review raised, which sets `halt_gate: true`
on `34.5-CYCLE7-REVIEW.md` and therefore blocks the fifth blocking live gate (plan 34.5-59) at its
Precondition 0.

`getRunnerCallWithoutCredentials` (`src/backend/launcher.ts`) redacts exactly two argv flags,
`['--code', '--token']`, by exact array-element match. Every other credential-bearing flag passed
to any runner is written to `gamelib.log` in cleartext by `callRunner`'s
`logInfo([prefix, safeCommand], runner.logPrefix)`.

Output: a census-derived redaction list, a guard that fails when a new credential flag is added
unredacted, and `halt_gate` amended to `false` so the wave-5 gate can launch.
</objective>

<diagnosis_established_at_planning_time>
Measured directly from current source at planning time. **The executor MUST re-confirm every line
number before editing — line numbers are the one part of this brief that rots.** Re-derive the
census with the command below rather than trusting the table.

**The logging path (one path, all runners):**
`<any runner>.runRunnerCommand(argv, …)` → `callRunner()` → `getRunnerCallWithoutCredentials(commandParts, env, fullRunnerPath)`
→ `logInfo([prefix, safeCommand], runner.logPrefix)` at `launcher.ts:1704`, plus the same
`safeCommand` written to every `options.logWriters` sink just below it.

**The redaction mechanism**, `launcher.ts:1888`:
```
for (const sensitiveArg of ['--code', '--token']) {
```
Non-PowerShell branch (`launcher.ts:1902`): `modifiedCommand.indexOf(sensitiveArg)`, then
`modifiedCommand[sensitiveArgIndex + 1] = '<redacted>'`. **Exact array-element match** — `--code`
does NOT match `--code-verifier`, because they are separate elements.
PowerShell branch (`launcher.ts:1892`): regex `"${sensitiveArg}","(.*?)"` against the
`-ArgumentList` member. `"--code","…"` likewise does not match `"--code-verifier","…"`.

**Census of credential-bearing argv flags reaching that path** — re-derive with:
```
grep -rnE "'--(code|token|code-verifier|client-id|serial|password|secret|refresh-token|api-key)'" --include='*.ts' src/backend | grep -v __tests__
```

| Flag | Where the value comes from | Redacted today? |
|---|---|---|

| `--token` | legendary `auth.ts:7` | YES |

**`F-34.5-G6-24` is this plan's own new finding and is arguably worse than the blocker it was
found alongside.** The review traced the nile login path only, so it saw `--code-verifier`. A
census of the whole redaction surface finds `--password` at four GOG call sites carrying a
**user-chosen secret** — a class of credential a user may well have reused elsewhere, unlike a
single-use PKCE verifier. It leaks on every private-branch install, update and library call, not
only at login. Record it under its own id; do not fold it silently into `F-34.5-G6-22`.

**`authLogSanitizer` (`nile/user.ts:13-24`) is NOT a mitigation for any of this.** It parses a
line as JSON and redacts `url`/`code_verifier`/`serial`/`client_id` — it sanitizes the runner's
**stdout**, never its **argv**, and it is passed only to `getLoginData()`'s spawn. The argv line
is emitted by `callRunner` itself before any sanitizer is consulted. Confirm this and record it;
do not "fix" `authLogSanitizer` in this plan.
