## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking issue] Python f-string syntax error: a literal `{...}` set-notation string
inside an f-string**
- **Found during:** Task 2, first run of `ported-channels-gate.py` against the real document.
- **Issue:** Two `fail(...)` messages embedded a literal set-notation string
  (`"{logoutGOG, addShortcut, ...}"` and `"{addToSteam, addShortcut}"`) directly inside an
  f-string — Python 3.12+ rejects a bare `}` inside an f-string expression segment (`SyntaxError:
  f-string: single '}' is not allowed`), since the parser tries to interpret the brace as closing
  an interpolation.
- **Fix:** Rewrote both messages to build the interpolated detail string as a plain variable first
  (`joined_details = "; ".join(details)`), then concatenate it into the literal string with `+`
  instead of embedding it inside the f-string that also contains the literal braces.
- **Files modified:** `ported-channels-gate.py`
- **Verification:** `python3 -c "import ast; ast.parse(open('ported-channels-gate.py').read())"` —
  clean parse; `python3 ported-channels-gate.py` and `--self-test` both then ran successfully.
- **Committed in:** `c49021608` (folded into Task 2's single commit — the bug was caught and fixed
  before that commit was made, not introduced by it).

**2. [Rule 1 — Bug] `_extract_section`'s heading regexes matched an earlier INLINE backtick
mention of the heading text before the real heading**
- **Found during:** Task 2, running the gate against the real `34.5-PORTED-CHANNELS.md`.
- **Issue:** `RESIDUALS_HEADING`/`OBLIGATIONS_HEADING` were compiled without a line-start anchor
  (`re.compile(r"## Accepted residuals")`). `re.search()` matches the FIRST occurrence anywhere in
  the text — and the real document's own `## Obligations closed and opened` section contains a
  forward-reference in prose, inside backticks: `` `## Accepted residuals` below``. That inline
  mention (not a real heading) sits BEFORE the actual `## Accepted residuals` heading, so
  `_extract_section` returned an empty/wrong slice and the four required residual markers appeared
  "missing" even though they were present in the real section.
- **Fix:** Anchored both regexes (and, defensively, `PHASE_34_5_HEADING`/`PHASE_34_6_HEADING`) to
  line-start with `re.compile(r"^## ...", re.MULTILINE)`.
- **Files modified:** `ported-channels-gate.py`
- **Verification:** Re-ran against the real document — the residuals check then correctly found
  all four markers.
- **Committed in:** `c49021608`.

**3. [Rule 1 — Bug] The Phase 34.6 channel-list extraction pattern was too strict, then (after the
first fix) too loose**
- **Found during:** Task 2, running the arithmetic cross-check (check 5) against the real
  `IPC-PORT-INVENTORY.md`.
- **Issue (round 1):** The initial `CHANNEL_LIST_LINE_PATTERN` required a channel-list line to
  consist of NOTHING but backtick names and an optional trailing period — but
  `IPC-PORT-INVENTORY.md`'s Phase 34.6 section spreads its 16 channels across three lines, each
  ending in a descriptive parenthetical (e.g. `` (EOS overlay, 8)``), which the strict pattern
  rejected, undercounting to 0. **Issue (round 2):** Loosening to "line merely OPENS with a
  backtick name" over-corrected — it then matched prose lines that happen to open with a
  channel name in backticks followed by more prose (`` `winetricksInstall` is `addListener`/send-kind
  (`tools/ipc_handler.ts`) — inherits ...``), which falsely added `addListener` and
  `tools/ipc_handler.ts` to the deferred set (18 names instead of 16).
- **Fix:** Anchored the pattern to match the WHOLE line: a comma-separated backtick list, optionally
  followed by exactly one trailing `(...)` parenthetical clause and/or a period, and nothing else.
  This accepts the real inventory's parenthetical-suffixed list lines while still rejecting a prose
  sentence that merely opens with a backtick name.
- **Files modified:** `ported-channels-gate.py`
- **Verification:** Re-ran check 5 against the real document — recovered exactly 16 deferred names,
  then the full arithmetic check passed (38 declared + 3 dropped + 16 deferred = 57, matching
  `IPC-PORT-INVENTORY.md`'s Phase 34.5 set with no name in two buckets).
- **Committed in:** `c49021608`.
