## Decisions this plan resolves (Claude's Discretion, per CONTEXT.md)

**OQ-1 — wrap, do not pick a representative element.** RESEARCH.md offered two options.
This plan takes option 1 (wrap `FilterViewList`+`FilterCollectionList` in one div, and
`FilterStoreFacet`+`FilterRunnabilityFacet`+`FilterMoreGroup` in a second). Reason: option 2
(anchor on one representative component) is unsafe because `FilterStoreFacet` renders `null`
when `connectedStores.length === 0` (`FilterStoreFacet/index.tsx:39-41`), which would make
the filters step's selector match nothing for exactly the users most likely to be running the
onboarding tour — a fresh install with no stores connected. That reintroduces the defect this
plan exists to fix. The cost of option 1 is the CSS gap risk, which is mechanically
preventable and gated by Task 1's automated check.

**Selector strings are renamed, not reused.** The new anchors are
`library-views-collections` and `library-facets`, not the old `library-categories` /
`library-filters`. Reason: the old strings are dead at HEAD, so reusing them leaves no way for
plan 06's census to distinguish "correctly re-anchored" from "the old dead string resurfaced
somewhere". Renaming also matches the surfaces' real 34.11 names — "Collections" replaced
"categories", and the three groups are facets, not the retired filters dropdown.

**Both steps mint new i18n keys (D-07's rule).** Compare against the CATALOG value, not the
component's inline fallback — the catalog wins at render time.
`tour.library.categories` currently reads "Organize your games into categories to keep things
tidy" and `tour.library.filters` reads "Filter your games by store, platform, favorites and
more using these options". Both name controls 34.11 deleted (there are no categories; platform
is not a facet; Favourites is a View, not a filter). Editing the inline fallback would be a
silent no-op for all 48 non-English catalogs, so both get new keys.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34.12-02-01 | Tampering | intro.js tooltip rendering of `tour.library.*` catalog strings | accept | The 48 non-English catalogs are upstream-Heroic-inherited, repo-committed build-time assets at the same trust level as source code, and no runtime input reaches them. A hostile string in a catalog is equivalent to a hostile string in a `.tsx` file and is caught by the same code review. Mitigating here (sanitising every `t()` result before it reaches intro.js) would be a repo-wide change to a shared component (`Tour.tsx`) that D-04 explicitly forbids this phase from touching. |
| T-34.12-02-02 | Information disclosure | The two new `data-tour` attribute values in the DOM | accept | `library-views-collections` and `library-facets` are static UI-region names. No user, library or account data is embedded. |
| T-34.12-02-SC | Tampering | npm/pip/cargo installs | N/A — no installs | This plan adds no dependency. If an executor reaches for `pnpm add`, STOP: that is out of plan scope and requires a blocking human package-legitimacy checkpoint. |
