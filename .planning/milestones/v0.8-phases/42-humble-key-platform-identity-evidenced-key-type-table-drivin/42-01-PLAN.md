<objective>
Create the ONE pure `key_type` -> presentation table this phase is named for
(CONTEXT.md scope item 1, D-42-03). It answers two questions and nothing else:

1. How does this key_type render? (display name + logo id, or explicit "unknown")
2. Where does this key_type redeem? (real prefilled deep link, or the static help URL)

call sites that spell it differently (`HumbleKeyRow/index.tsx:230`,
`HumbleClaimWizard`'s "Redeem on {{platform}}" label, and the wizard's
Steam-vs-help URL fork at `:648`/`:662`). Plans 42-04 and 42-05 replace all
three with calls into this module. Nothing else in the phase can start until
this contract exists.

Output: one new pure module under `src/common/humble/` plus its unit suite,
imported by two frontend components in later waves.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Humble API -> GameLib | `key_type` is an attacker-influenceable string from a remote server; it selects which URL template is used. |
| GameLib -> external browser | `getRedeemTarget` produces a URL that a later plan hands to `window.api.openExternalUrl`. The `code` argument is a live secret. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-01 | Information disclosure | `getRedeemTarget` fallback branch | mitigate | The `help` branch returns `HUMBLE_REDEEM_HELP_URL` verbatim and drops `code` entirely. Task 1 pins `result.url === HUMBLE_REDEEM_HELP_URL` and `!result.url.includes('SECRET-CODE')` for every non-deep-link key_type, including unrecognised ones. |
| T-42-02 | Tampering | `key_type` -> URL selection | mitigate | Deep links are selected from a closed set of two hard-coded templates keyed on the literals `'steam'` and `'gog'`. A hostile `key_type` (including a full URL string) can only reach the `help` branch — pinned by a test passing `'https://evil.example/'` as the key_type. No `key_type` value is ever interpolated into a URL. |
| T-42-03 | Information disclosure | key value in the URL path/query | mitigate | `encodeURIComponent(code)` on both deep links, matching the live Steam branch exactly. Test pins the exact encoded output for a code containing ` /?&#`. |
| T-42-04 | Information disclosure | logging | mitigate | Module imports no logger and touches no `console`; the never-log-a-key discipline (D-76/C4) is stated in the module docblock. |
| T-42-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install in this plan. No new dependency is added; `encodeURIComponent` is a platform builtin. No `[ASSUMED]`/`[SUS]` package to gate. |
</threat_model>
