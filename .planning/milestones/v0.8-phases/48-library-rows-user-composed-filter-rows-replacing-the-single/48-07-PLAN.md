## Design choice (Claude's discretion, rated reversible)

The verifier offered two fixes: (a) hydrate in the renderer from `requestAppSettings()`, or (b) have the backend write the derived value into the mirror when `getSettings()` first derives it. **This plan takes (a), and the renderer persists what it hydrated through the existing single setter path.** Option (b) alone would rest on an unproven boot ordering, for two reasons:

- `hydrateStoreSnapshot()` is awaited before React mounts (`src/preload/tauriTransport.ts:243`), and nothing orders the sidecar's first `GlobalConfig.get()` before that snapshot is served.
- `GlobalState` reads `globalSettings` once at module scope, so a later `STORE_CHANGED_CHANNEL` patch to the snapshot would never reach `this.state.focusRow`.

Option (a) is deterministic. One accepted transient follows: on the single first upgraded launch the strip pops in after one IPC round trip, rather than on first paint. Every later launch seeds synchronously from the mirror. The 48-08 live gate checks this.

The one-way decision (persist the seed at all) was already made and approved at 48-05's `checkpoint:decision`.</reversibility>
