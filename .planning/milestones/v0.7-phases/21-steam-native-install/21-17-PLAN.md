<objective>
Close **D-UAT-09** (MAJOR, real-macOS, build @adced885): a cancelled / incomplete native
Steam install is registered by GameLib as **Installed** (primary action = "Play"); clicking
Play hands off to Steam, which runs its own install/repair instead of launching.

This plan locks two invariants that close the gap regardless of the exact micro-cause
(the root cause must be confirmed by reproduction first — see Task 1):

1. **Install-state correctness (backend):** `is_installed` for a Steam game is derived
   STRICTLY from the ACF `StateFlags` bit 4 (`FullyInstalled`) through a single shared
   predicate, and a user-cancelled / interrupted download can NEVER finalize a
   `StateFlags=4` manifest (it always writes the honest `1026` verify-repair handoff).
   A same-session cancel additionally marks the library entry `is_installed=false` +
   `steamResumePending=true` so the incomplete state is visible.

2. **Honest affordance (frontend):** an incomplete on-disk native install (bit 4 unset,
   manifest present) surfaces a distinct **"Finish in Steam"** / resume affordance —
   never a "Play" button, and distinct from a bare "Install" — reusing the exact
   `statusContext` / `steamResumePending` plumbing that 21-16 introduced for
   `steam-waiting-for-restart`.

Purpose: the primary action must never lie about install state — a user shown "Play" must
get a launch, not a silent Steam download.
Output: hardened backend completeness gate + a distinct incomplete/resume affordance across
the tile, detail status, and detail action button, with regression tests.
</objective>
