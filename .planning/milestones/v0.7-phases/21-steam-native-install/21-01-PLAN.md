<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Steam CDN → GameLib | Depot chunk bytes and encrypted filenames are untrusted network input decrypted/decompressed here |
| PICS response → GameLib | Depot GIDs / IDs are untrusted 64-bit values that must remain strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-02 | Denial of Service | decompress.ts LZMA output | mitigate | Streaming/bounded write is enforced in Plan 05; this layer decompresses a single ~1MB chunk at a time (chunk-scoped, not whole-file) so per-call output is inherently bounded to Steam's chunk cap |
| T-21-03 | Tampering | decompress.ts fetchChunk | mitigate | Mandatory `sha1(data) === chunk.sha` gate before any chunk is returned; mismatched chunk retries across a different content server, never persists |
| T-21-04 | Tampering | select.ts / crypto.ts | mitigate | Depot GIDs emitted as `String(gid)`; no JS Number coercion; no @node-steam/vdf involvement in this layer |
| T-21-01 | Tampering | crypto.ts decryptFilename | accept (here) | decryptFilename only DECODES; path-traversal containment is the caller's control, enforced in Plan 05's write loop (resolve+relative). This layer must not silently sanitize (would hide traversal from the audited chokepoint) |
| T-21-SC | Tampering | `lzma` npm install | accept | `lzma` 2.3.2 Approved in RESEARCH Package Legitimacy Audit (slopcheck OK, empty postinstall, 42k downloads/wk, github.com/nmrugg/LZMA-JS) — no blocking checkpoint required for an Approved package |
</threat_model>
