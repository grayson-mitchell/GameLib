## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `console.warn` source-scan regression guard was overly broad and would have false-failed on this task's own new, intentional warning**
- **Found during:** Task 2, after implementing `resolveNativeLzmaAsset()`'s degraded-triple `console.warn` and running the full test suite
- **Issue:** `meta/__tests__/buildSidecarSea.test.ts`'s "WR-10-style source-scan guard: the inline-fallback warning cannot come back" describe block asserted `not.toMatch(/console\.warn\(/)` against the whole file — banning EVERY `console.warn(...)` call in `buildSidecarSea.ts` forever, not just the specific retired "inline single-thread" Pitfall-1 warning text the block is named for and dated to. This task's `resolveNativeLzmaAsset()` adds its own unrelated, intentional "NATIVE LZMA UNAVAILABLE" warning as the required loud-not-silent degrade signal — the test would have wrongly failed on legitimate new code with no relationship to the retired warning.
- **Fix:** Narrowed both assertions in that describe block to the actual phrase the guard exists to catch (`/inline single-thread/`) instead of banning `console.warn(` unconditionally. The "matcher rejects the known-bad old text" companion test was updated to assert against the same narrowed pattern, so the guard still provably fails on the retired warning text.
- **Files modified:** `meta/__tests__/buildSidecarSea.test.ts`
- **Verification:** All 64 tests pass, including both narrowed assertions; the companion test still demonstrates the matcher fails against the old warning text.
- **Committed in:** `380cb5d26` (Task 2 GREEN commit)

**2. [Rule 1 - Bug] `node_modules` source-scan regression guard was overly broad and would have false-failed on this task's own new, legitimate data-file path**
- **Found during:** Task 2, after adding `LZMA_NATIVE_PREBUILDS_ROOT = join('node_modules', 'lzma-native', 'prebuilds')` and running the full test suite
- **Issue:** The "the tested argv is the executed argv (WR-10 guard)" describe block's `not.toMatch(/node_modules/)` assertion banned the bare string `"node_modules"` anywhere in the file — intended to catch the CR-02 `node_modules/.bin/<tool>` CLI-spawn-path bug (documented in the file header), but broad enough to also reject `LZMA_NATIVE_PREBUILDS_ROOT`'s unrelated DATA-file path (locating `lzma-native`'s own prebuilt addon on disk, never spawned as a CLI).
- **Fix:** Narrowed the second assertion to the actual dangerous shape — `node_modules` immediately followed by a `.bin` path segment (`/node_modules['"]\s*,\s*['"]\.bin/`) — while keeping the pre-existing, still-sufficient `not.toMatch(/['"]\.bin['"]/)` assertion that independently guards the real CR-02 invariant (no bare `.bin` literal anywhere in the file).
- **Files modified:** `meta/__tests__/buildSidecarSea.test.ts`
- **Verification:** All 64 tests pass; the narrowed regex still matches the exact `join('node_modules', '.bin', 'postject')` shape the CR-02 fix note describes, so the guard's real invariant is unweakened.
- **Committed in:** `380cb5d26` (Task 2 GREEN commit)
