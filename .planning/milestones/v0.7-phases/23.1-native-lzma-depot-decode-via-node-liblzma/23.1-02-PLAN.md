<objective>
Make `lzma-native@8.0.6` a real repo dependency and teach the SEA build script to
embed its prebuilt native addon into the SEA blob as a SECOND named asset, resolved
by the build TARGET triple rather than the build host.

Purpose: the runtime halves (plans 23.1-03 and 23.1-04) cannot load a native addon
that the build never put in the blob. This plan owns the build-time half and the
dependency manifest, and it is the only plan that touches `package.json` /
`pnpm-lock.yaml` / `meta/buildSidecarSea.ts`.

This plan ASSUMES 23.1-01's spike returned verdict `VALIDATED` and the go/no-go
checkpoint selected `proceed`. If `23.1-01-SUMMARY.md` records `REFUTED` or
`UNDECIDABLE`, or the decision was `replan-mainthread` / `abandon` /
`proceed-anyway`, STOP and report back to the orchestrator — the whole 02/03/04
plan set is built on the `getRawAsset()` + `process.dlopen()` + eval'd-worker
mechanism and must be replanned, not adapted in flight.

Output: an installed, exactly-pinned dependency plus a build script that produces a
`build/sea-config.json` carrying two assets on every triple whose prebuild exists.

Note on host-vs-target: `meta/buildSidecarSea.ts` already carries a documented
CR-01 scar tissue about deriving things from `process.platform`/`process.arch`
instead of the resolved target triple. Every new function this plan adds takes the
triple as an explicit parameter for exactly that reason. Do not reintroduce a
`process.platform` read anywhere in the new code.
</objective>
