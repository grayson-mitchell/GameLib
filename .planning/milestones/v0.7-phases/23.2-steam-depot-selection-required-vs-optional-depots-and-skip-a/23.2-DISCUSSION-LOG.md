## Areas offered

## Area 1 — Skip trigger

**Q: Which key-request failures should trigger skip-and-warn instead of aborting?**
Options: EResult 40 only *(recommended)* / any non-retryable key failure / ship 40-only and widen later on evidence.
**Chosen: EResult 40 (Blocked) only.**

**Q: What stops GameLib skipping a depot the game actually needs?**
Options: no guard *(recommended)* / refuse to skip the largest depot / require a positive optional signal / cap at one skipped depot.
**Chosen: skip any blocked depot, no guard.**

Notes: the "require a positive optional signal" option was presented with the finding that **no such
signal exists in appinfo**, so choosing it would have blocked the fix indefinitely. The
"largest depot" heuristic was presented as arbitrary — 735 MB vs 82 GB was a coincidentally clear
case.

## Area 2 — StateFlags outcome

**Q: A blocked depot was skipped, everything else landed and verified. What StateFlags?**
Options: `4` with the depot omitted *(recommended)* / fall back to `1026` / `4` normally but `1026` on any other doubt.
**Chosen: `StateFlags=4`, skipped depot omitted from `InstalledDepots`.**

Notes: presented with the framing that this **reframes** Phase 23's D-01 fail-closed rule rather than
overriding it — completeness is measured against the post-skip plan. The `1026` option was costed:
Steam would verify 90 GB and find nothing wrong, because Steam does not consider the blocked depot
part of the app for this account.

**Q: If the depot later becomes available, how does GameLib handle it?**
Options: nothing, Steam's job *(recommended)* / re-check on next explicit install action / surface it for a user-triggered retry.
**Chosen: nothing — Steam's job.** Preserves Phase 23's D-05.

## Area 3 — User signalling

Raised before asking: this change makes 23-09's `steam.download.error.depotBlocked` copy —
shipped six days earlier specifically to name the blocked depot on failure — **unreachable for the
case it was written for**.

**Q: How should the user learn a depot was skipped?**
Options: completion notice naming the depot *(recommended)* / log only / notice plus a persisted per-game note.
**Chosen: completion notice naming the depot.**

**Q: What happens to 23-09's now-unreachable error copy?**
Options: repurpose as the skip warning *(recommended)* / keep both / delete it.
**Chosen: repurpose**, with the constraint that it needs a **NEW i18n key** (renaming via the `t()`
default is a silent no-op when the key exists).

## Area 4 — Fold in the manifest clobber

**Q: Fix the stub-manifest clobber inside 23.2, or keep it separate?**
Options: fold in full *(recommended)* / fold only the contradiction check / keep separate.
**Chosen: fold it in fully.**

Notes: the deciding argument offered was that fixing selection **removes the one reproduction we know
how to trigger** (EResult 40 stops aborting), so keeping it separate would leave a live
data-destructive defect that had just become harder to find.
