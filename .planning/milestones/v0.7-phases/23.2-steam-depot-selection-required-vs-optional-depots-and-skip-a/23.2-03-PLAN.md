<objective>
Implement the skip-and-warn policy that closes **G-23-01**: when Steam refuses a decryption key
for one owned depot with `EResult 40` (`Blocked`), drop that depot from the plan and finish the
install, instead of aborting the whole install.

Purpose: GameLib's selected depot set for KCD2 (appId 1771300) is
`{1771302, 1771303, 1771304, 1771306}`. The official Windows Steam client's own manifest for the
same account records `InstalledDepots = {1771302, 1771303, 1771306}`, `StateFlags "4"`,
`SizeOnDisk 96422090071`, `buildid 23914554`. GameLib's selected set **minus the blocked depot
1771304** equals the official client's installed set **exactly**. That is the acceptance
benchmark: after this phase a GameLib install of 1771300 should produce that same depot set and
the same `SizeOnDisk`.

Output: the reduction, the plan-level skipped-depot record, and the threading of that record out
through `DepotDownloadOutcome` so plan 23.2-04 can surface it to the user.

**Honesty limit that must survive into every log line, comment and message:** the evidence proves
depot 1771304 is not *needed*. It does **not** prove Steam would have granted its key — the
official client never asked for it. Do not write any wording that claims otherwise.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remote Steam CM → skip decision | The `eresult` value that decides whether an install continues or aborts arrives from a remote server. It flows into a policy branch, a log line, a plan reduction, and (via plan 23.2-04) a user-facing message. |
| Remote PICS → VDF-serialized manifest field | Depot ids that survive the reduction are interpolated into `InstalledDepots` block keys in a file the Steam client parses. |
| Fail-closed → fail-open inversion | REQ-23-01 established a fail-closed completeness principle. Skip-and-warn is deliberately fail-open for exactly one condition. What stops it widening is the entire security question of this plan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23.2-11 | Elevation of privilege | The fail-open skip branch in `buildDepotPlan`'s depot loop | mitigate | **This is the primary threat of the phase.** The skip is gated on an exact equality against the literal `40`, evaluated on GameLib's own wrapped error object, and the branch is closed for every other value including the rest of `NON_RETRYABLE_ERESULTS`. What stops it widening is enforced, not documented: Task 2's parameterised case over `8, 9, 15, 17, 42, 43` fails if the narrowing is replaced by `isNonRetryableDepotError`, and the executor must observe that failure before the plan is accepted. Widening beyond 40 is a future operator decision requiring an observed real-world failure, per D-01. |
| T-23.2-12 | Spoofing | A remote CM returning EResult 40 for a depot the user genuinely owns | accept | A malicious or compromised CM could return 40 for every depot and cause a deliberately incomplete install. Accepted: the user is already fully trusting this CM for the content bytes themselves, so an attacker in that position has strictly stronger options than withholding a depot. Residual risk is bounded by the all-skipped guard (an install where every depot was refused fails as an error, never as a success) and by D-06's completion notice, which names each skipped depot to the user rather than hiding the reduction. |
