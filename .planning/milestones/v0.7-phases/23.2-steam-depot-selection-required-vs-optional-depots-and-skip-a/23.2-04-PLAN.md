<objective>
Close D-06 and D-07: tell the user, at the moment they are paying attention, that the install
succeeded **and** which depot was skipped.

Purpose: a silently incomplete install is precisely the failure class this project has repeatedly
been bitten by. Log-only was explicitly rejected. The completion notice is the agreed surface.

Output: a new i18n key carrying the repurposed copy, a deliberate disposition for the key it
replaces, and the plumbing that carries the skipped-depot list from
`downloadSteamDepots`'s outcome to the toast.

**Honesty limit that must survive into the copy:** the evidence proves the blocked depot is not
*needed*; it does **not** prove Steam would have granted its key to another client. Write what
happened — Steam refused the key and the install continued without that content — not a claim
about what Steam would have done.
</objective>

<known_landmines>
Three traps in this specific surface, each of which has bitten this repo before:

1. **`{{count}}` is RESERVED by i18next.** Naming the interpolation variable `count` makes i18next
   silently resolve `_one`/`_other` plural keys that do not exist. It extracts fine and fails at
   RENDER. Name the variable `depots`.

2. **Renaming a label via the `t()` default argument is a silent no-op when the key already
   exists.** This is why D-07 mandates a NEW key rather than editing `depotBlocked`'s value.

3. **`pnpm i18n` writing to `translation.json` makes `pnpm test:ci` go RED until the change is
   staged.** `meta/i18nCatalogChurnGuard.ts`'s live-tree jest assertion runs
   `git diff --name-only -- public/locales` (working tree vs index, unstaged only) and fails if
   any non-`gamelib.json` catalog appears. Its error message tells you to
   `git checkout -- public/locales/` and fix the call site — **that advice does not apply here.**
   It assumes a `t()` call missing its `gamelib:` prefix. This key is a backend-composed Steam
   string joining the same un-prefixed `translation.json` block as its siblings `depotBlocked`,
   `notify.install.finished` and `steam.waitingForSteam.notify`, exactly as commit `3e6fbe9c4`
   (23-09) landed `depotBlocked` six days ago. Stage the catalog change before running the suite.
</known_landmines>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remote-sourced depot id → i18n interpolation → OS notification | Depot ids originate in remote PICS data, survive the skip decision, and are interpolated into a string rendered by the host OS notification system. |
| Backend poll state → user's understanding of install completeness | The notice is the only surface distinguishing a complete install from a deliberately reduced one. If it fails to fire, the user believes something false. |
| `pnpm i18n` parser → upstream-owned catalog | The parser writes into `public/locales/en/translation.json`, a catalog the churn guard classifies as upstream-owned. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
