# Phase 23.2 Plan 03: Steam depot selection — skip-and-warn on EResult 40 Blocked Summary

**Depot-level skip-and-warn for EResult 40 (Blocked) closes G-23-01: GameLib's selected KCD2 set minus the one depot Steam refuses now matches the official client's own installed set exactly, with the completeness gate proven to still fail closed on every other input.**

## Accomplishments

- `DepotPlan.skippedDepots: string[]` (required field) threads the set of depot ids Steam refused with `EResult 40` end-to-end, from the plan-build loop through `DepotDownloadOutcome`.
- The plan-build depot loop skips a depot on a literal `eresult === 40` from either `getDepotDecryptionKey` or `getRawManifest`, `continue`s, and lets `totalBytes` exclude it for free — while every other member of `NON_RETRYABLE_ERESULTS` (8, 9, 15, 17, 42, 43) still aborts the whole build, verified by a demonstrated RED-proof (see below).
- The all-skipped case (every selected depot Blocked) throws instead of silently reporting a downloaded-nothing install as done — closing the DoS threat T-23.2-16.
- End-to-end: a real `downloadSteamDepots` run with the KCD2-shaped four-depot plan (1771302, 1771303, 1771304 blocked, 1771306) writes `StateFlags "4"` with the three kept depots present in `InstalledDepots` as block keys and 1771304 absent as a block key; a sibling run with the same skip plus one additional sha1-mismatch failure still falls back to `StateFlags "1026"`, proving the skip is not an escape hatch from `canWriteFullOwnership`.
- `select.ts`, `depotErrors.ts`, and `canWriteFullOwnership`'s body are confirmed byte-identical across all three task commits (`git diff` shows zero hunks inside any of them).

## Decisions Made

- The skip trigger is a literal equality against `40`, never `isNonRetryableDepotError(err)` — the broader set also contains 15 (AccessDenied) and 17 (Banned), which plausibly signal a genuine account/ownership problem that must never be silently downgraded to "skipped a depot". This is the primary threat of the phase (T-23.2-11) and is enforced by a demonstrated test failure, not just documented.
- `NON_RETRYABLE_ERESULTS` was left untouched with 40 still a member — this is load-bearing: it is what makes `withPlanBuildRetry` fail fast on the first attempt for a Blocked depot instead of burning `PLAN_BUILD_MAX_ATTEMPTS` reconnects before the skip fires.
- The all-skipped guard throws a plain `Error` naming the appId and every skipped depot id, with `.eresult = 40` so `classifyDepotError` still maps it to the existing `depotBlocked` copy — no new error-classification branch was added.
- No recovery path was added for a skipped depot (D-05) — no retry, no re-check on a later run, no persisted marker. The skipped set is read for reporting only, pinned by a source census.

## D-01 RED-Proof Evidence (plan-mandated, recorded per the plan's own verification requirement)

Task 2's acceptance criteria required temporarily widening `depot.ts`'s skip check from the literal `eresult === 40` to `isNonRetryableDepotError(err)`, observing the parameterized `[8, 9, 15, 17, 42, 43]` case fail, and reverting before committing.

**Observed result:** all 6 of 6 parameterized cases failed as expected. Each resolved `buildDepotPlan` successfully instead of rejecting, with the "blocked" depot (`'222'`) present in the resolved plan's `skippedDepots` array instead of the whole build throwing. Example captured output for EResult 17:

```
● 23.2-03 (D-01) RED-PROOF: EResult 17 still aborts the whole plan build — never silently skipped

  expect(received).rejects.toThrow()

  Received promise resolved instead of rejected
  Resolved to value: {"appId": "12345", ..., "skippedDepots": ["222"], "totalBytes": 300}

Tests: 6 failed, 148 skipped, 154 total
```

This confirms the parameterized test genuinely detects a regression of D-01's boundary — a test suite asserting only "40 skips" would have passed equally well against an implementation that skips every terminal EResult, which is precisely what D-01 forbids. The widening was reverted (`git diff` on `depot.ts` returned empty before Task 2 was committed), and the full 154-test suite plus `pnpm codecheck` were re-confirmed green afterward.
