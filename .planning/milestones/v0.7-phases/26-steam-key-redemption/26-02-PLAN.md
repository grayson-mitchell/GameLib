valid non-standard keys (explicitly NOT a 5-5-5 regex, per D-09).

in isolation keeps the "no IPC call on malformed input" acceptance criterion cleanly provable.

<interfaces>
<!-- Design from RESEARCH Pattern 4 — no existing validator analog in the codebase. -->
normalizeKey(raw: string): string        -> raw.trim().toUpperCase()
isObviouslyMalformed(raw: string): boolean:
  - normalized length === 0 -> true (reject empty/whitespace)
  - normalized length < 10 OR length > 40 -> true
  - not matching /^[A-Z0-9-]+$/ -> true
  - otherwise false
ANTI-PATTERN (forbidden): /^[A-Z0-9]{5}-[A-Z0-9]{5}-[A-Z0-9]{5}$/ — over-rejects valid non-standard keys
(D-09 / SPEC REQ3). The validator catches typos, it is NOT a store router.
</interfaces>
</context>
