<objective>
Close the Phase 23 Gate 1 (multi-depot) UAT defect: during a real multi-depot install (Hogwarts Legacy, appId 990080) the single `progress.percent` flip-flops between two climbing figures (2%↔16%, later 6%↔27%). Root cause is CONFIRMED: `SteamGame.installDepotDownload` (games.ts:735) adds the appId to `nativeInstallsInFlight` but never checks it on entry, so `install()` can be entered twice for one appId and spawn two concurrent `downloadDepotFiles` runs — each emits `progressUpdate` for `{ appName: appId, runner: 'steam' }` against its OWN `doneBytes`, so the single percent slot alternates. This plan adds a single-flight guard + fail-safe cleanup, makes pause/resume abort-before-restart (no stacking), and reconciles startup-resume eligibility against the in-flight set so a stale `1026` manifest can't spawn a phantom concurrent install.

Purpose: A monotonic single-download-per-appId is the failed observable truth blocking Gate 1 (REQ-23-07). This unblocks the D-07 real-hardware gate re-run.
Output: Guarded `installDepotDownload`, targeted regression tests keeping the steam suite green, and a re-run + recorded result for 23-UAT.md Gate 1.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local IPC (renderer install action) → SteamGame.install/installDepotDownload | A user (or a retry/re-dispatch) can trigger install() for the same appId more than once, concurrently, from the trusted-local UI |
| GameLib depot writer → local filesystem (bottle/native steamapps) | Two concurrent downloadDepotFiles runs writing the same install root can interleave/corrupt partial files and race the appmanifest write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-12 | Tampering | Two concurrent downloadDepotFiles runs for one appId interleave writes into the same install root, risking corrupted partial files / an inconsistent SizeOnDisk vs on-disk reality feeding the StateFlags=4 completeness gate | mitigate | Single-flight guard at installDepotDownload entry (Task 1) — at most one download per appId; second entry joins/no-ops, never starts a second writer |
| T-23-13 | Denial of Service | A crashed/aborted run that fails to clear `nativeInstallsInFlight` would permanently block all future re-installs of that appId (self-inflicted DoS on the install action) | mitigate | Fail-safe `finally` cleanup deletes the appId entry on success/error/cancel (Task 1); regression test asserts registry release on the error/cancel path |
| T-23-14 | Tampering | A stale attacker-or-crash-authored StateFlags=1026 manifest on disk makes scanDownloadingAppIds mark an appId resumable, racing a live user-initiated install | mitigate | Startup-resume reconciles against the in-flight set — an appId already owned by a live install is skipped, so the on-disk manifest cannot drive a second concurrent path (Task 2) |
| T-23-15 | Repudiation | AbortController for a paused run left dangling could let a resumed run stack on a not-yet-torn-down run, producing untraceable duplicate progress emissions | mitigate | Resume awaits the prior aborted entry's settlement before starting fresh (Task 2); deleteAbortController on every finally (Task 1) |
| T-23-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — code + tests + a documentation update only; no dependency surface added |
</threat_model>
