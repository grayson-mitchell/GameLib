<objective>
Build GameLib-owned resume/interrupted-download recovery (D-04, REQ-23-04) and hold the update-ownership boundary (D-05, REQ-23-05). Today there is NO resume of the byte download: every retry re-downloads 100% (`downloadSingleFile` always `open(dest,'w')`+truncate), and the startup resume path finalizes an EMPTY `depots: []`. This plan adds `reconcile.ts` — walk the install root, sha1-verify each already-present file against its manifest `sha_content`, and download only what's missing/mismatched — then wires it into both the download job builder and the startup resume so a reconciled-complete install can earn a trustworthy `StateFlags=4` (via Plan 02's `allFilesVerified` signal).

Purpose: This is the one genuinely-new subsystem. Its single most important rule (Pitfall 1): existence guarantees nothing, sha1 guarantees content — never trust a present file without re-hashing it. GameLib, not Steam, is now asserting completeness.
Output: `reconcile.ts`, its wiring into `downloadDepotFiles` and `library.ts init()`, a regression test that the bottle steamapps root is never scanned at startup, and tests for skip/mismatch/complete-noop behavior.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pre-existing on-disk files → reconciliation | files on disk from a prior/interrupted run (or dropped by another process) are untrusted until sha1-verified |
| Manifest `filename`/`linktarget` → filesystem path | untrusted names drive path resolution during the disk walk |
| Startup resume → external Steam client | resume must not trigger Steam/CrossOver side effects the user didn't initiate |
