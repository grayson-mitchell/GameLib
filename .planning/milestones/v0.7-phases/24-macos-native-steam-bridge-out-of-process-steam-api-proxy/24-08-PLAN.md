<objective>
Wire the bridge into GameLib's real macOS launch path (R4) and guarantee clean coexistence + observable failure (R7). Add a private `isBridgeEligible()` composing `this.isBottleEligible() && bridgeAllowlist.has(this.appId)` (D-01/D-02) and insert the bridge sub-branch as the FIRST check inside each of `install()`/`launch()`/`uninstall()`'s existing `if (this.isBottleEligible())` block — mirroring exactly how `isSteamNativeInstallEnabled()` already composes there (the third instance of a proven in-file pattern, not a new one).

Three routing-shape deltas this plan gets right (RESEARCH Pattern 4):
- **install**: `installBridgeGame()` PROVISIONS the bridge bottle inline via `provisionBridgeBottle()` (24-04) when `!isBridgeBottleReady()` (BLOCKER 1 — the only caller of `provisionBridgeBottle`; a fast cxbottle create, no SteamSetup/login, so no consent dialog is needed), then reuses the Phase 21/23 `installDepotDownload` engine to fetch the Windows depot into the BRIDGE bottle (24-04), then runs 24-05's `shimGenerate` placement as a post-install hook.
- **launch**: resolves the game's OWN Windows launch `.exe` via `resolveBridgeLaunchExe(appId)` (new — from PICS appinfo `config.launch[]` filtered `oslist=windows`, review finding #2; there is no bottled `steam.exe` to `-applaunch`, so GameLib must resolve the exe itself) and runs it directly via `runWineCommand` with `getBridgeBottleSettings()` (24-04) — NOT `dispatchToBottledSteam`. Gate on `ensureBridgeHelperReady()` (24-06) first.
- **failure + fallback-bypass**: on readiness failure, mark the appId bridge-failed-this-session and fire `steamBridgeSetupRequired` (D-05/D-06) — no silent hang, no game with no Steam identity. Because `isBridgeEligible()` consults that session set (review finding #3), the user's fallback re-invocation routes to the existing non-bridge branch WITHOUT looping back into the bridge. The fallback (D-11) re-routes to the existing non-bridge branch (24-09 owns the dialog UI + on-demand provision).

Two mechanics the review flagged as missing owners, now assigned here: the launch-exe resolver (finding #2) and the fallback-bypass session set (finding #3). The `steamBridgeSetupRequired` IPC type is now registered UPSTREAM in 24-06 (finding #1) and only CONSUMED here.

Purpose: the integration that turns proven primitives into a real launch path.
Output: `games.ts` routing + `installBridgeGame()` + IPC event type + tests (R4 routing, R7 regression, forced-failure).
</objective>
