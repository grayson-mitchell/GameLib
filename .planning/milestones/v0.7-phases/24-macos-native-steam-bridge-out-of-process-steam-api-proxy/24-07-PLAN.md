<objective>
Build R5's packaging: the native helper ships inside the packaged app and is invoked from the bundle — not a developer-only side artifact. Two build-time `meta/` scripts, hooked before `electron-vite build && electron-builder`:
1. `meta/downloadZig.ts` — fetch a PINNED zig release tarball from `ziglang.org/download/index.json` (not "latest", not assuming `zig` on PATH), following `downloadHelperBinaries.ts`'s `RELEASE_TAGS` pinning precedent. Zig is a build-time-only toolchain — it does NOT ship in the packaged app.
2. `meta/buildSteamBridgeShims.ts` — compile the arm64 host helper (`native/steam-bridge/helper/bridge_helper.c`) with system `clang` to `public/bin/${process.arch}/darwin/steam-bridge-helper` (chmod 755, `downloadAsset` convention), STAGE `steam_appid.txt`=480 next to it (finding #4 — the helper's runtime cwd, set by 24-06, resolves the identity AppID from this file), and cross-compile the PE32 shim from 24-01's committed generated source via `zig cc -target x86-windows-gnu` (D-07 — build binary at packaging, mingw/clang windows-gnu uses the Itanium ABI so the generated stubs are explicitly `__thiscall`). The shim cross-compile doubles as a real COMPILE GATE: it MUST exit 0 and emit a PE `.dll`, catching ABI/emit bugs in the hand-authored generator output cheaply — long before the 24-10 human gate (finding #5a). No `electron-builder.yml` change needed (Pattern 5).

Purpose: make the bridge run from a real packaged build.
Output: `downloadZig.ts` + `buildSteamBridgeShims.ts` + npm-script wiring + tests.
</objective>
