<objective>
Build the D-03 shared-helper lifecycle and the D-06 readiness/health signal. `ensureBridgeHelperReady()` lazily spawns ONE shared, long-lived helper (from the bundled `steamBridgeHelperPath`) on first bridge launch, holds the `ChildProcess` handle module-scoped, and reuses it for every bridge game until GameLib quits. Because bottle launches are fire-and-forget (`runWineCommand({ wait: false })`), the bridge needs an actual readiness signal over the protocol.ts CONTROL frame (24-02): a HEALTH probe (process up, answerable pre-init) plus a WHOAMI probe (InitFlat succeeded against a live session) — two DISTINCT states — so failures are observable, not assumed-success (D-06, review finding #7). Modeled on `ensureSteamClientReady()`'s status-union shape + `raiseFrontmostBottledProcess`'s bounded-poll mechanics.

This plan also OWNS three seams the review flagged as under-assigned: (a) it registers the `steamBridgeSetupRequired` member of the `FrontendMessages` interface (`src/common/types/ipc.ts`) here — the first producer wave — so `sendFrontendMessage` (generically typed on `keyof FrontendMessages`) typechecks at first use (finding #1, previously mis-scoped to Wave-3 24-08); (b) it spawns the helper with `cwd = dirname(steamBridgeHelperPath)` so the helper's `InitFlat` finds the `steam_appid.txt`=480 that 24-07 stages into the bundle (finding #4 / SPEC AppID-before-init); (c) it wires `shutdownBridgeHelper()` into the main-process app-quit lifecycle (finding #8).

Also add `steamBridgeHelperPath` to `paths.ts` (the bundled arm64 binary location, consumed here and produced by 24-07's packaging).

Purpose: the observable-failure seam R7's clean fallback depends on.
Output: `helperProcess.ts` (`ensureBridgeHelperReady`, spawn lifecycle) + `steamBridgeHelperPath` + tests.
</objective>

| loopback readiness probe | Backend connects to the same unauthenticated 127.0.0.1 listener |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-06 | Tampering/Elevation | helper spawn path | mitigate | Spawn only the bundled `steamBridgeHelperPath` (fixed, packaged, arch-aware); no attacker-supplied binary path; argv-form spawn |
| T-24-07 | Tampering | appId into readiness seam | mitigate | `NUMERIC_APP_ID` guard before spawn/probe |
| T-24-02 | Information Disclosure | backend probe to loopback listener | accept | Same accepted-residual loopback-only risk as 24-02 (recorded at secure-phase); the probe is on 127.0.0.1 only |
| T-24-10 | DoS | helper crash/respawn loop | mitigate | Bounded poll budget + null-on-exit handle; ready returns not-ready (observable) rather than hanging (D-06) |
| T-24-15 | DoS/Resource-leak | orphaned helper on app quit | mitigate | `shutdownBridgeHelper()` wired into main.ts `before-quit`/`handleExit` (finding #8); idempotent no-op when never spawned |
