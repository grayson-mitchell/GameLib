<objective>
Build the R1 vtable + flat-export `steam_api.dll` shim SOURCE generator — the highest-risk, highest-uncertainty component of this phase, sequenced first per CONTEXT `<specifics>` and SPEC.

The generator reads a GameLib-authored interface manifest (D-09 — never vendored Valve SDK headers) for the pinned interfaces `SteamUser023` and `SteamFriends018`, and emits `.c`/`.def` source implementing: the flat `SteamAPI_*` exports (spike 005c proof) AND the C++ `__thiscall` vtables (spike 006 proof — the path unmodified games actually use). It is written in TypeScript (D-10, repo convention) with unit tests asserting the ABI (D-10 mandate). Generated source is committed to the repo (D-07); the PE binary is built later at packaging time (Plan 24-07), never committed.

Purpose: turn the proven one-off hand-written spike stubs into a mechanically-checkable generator producing ABI-correct stubs for the full pinned interface set.
Output: `meta/gen_vtables.ts` + manifests + committed generated `.c`/`.def` + unit tests + `pnpm gen-vtables` script.
</objective>
