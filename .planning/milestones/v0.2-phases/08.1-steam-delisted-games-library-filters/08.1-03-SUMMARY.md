# Phase 08.1 Plan 03: FilterMode Tri-State Migration Summary

**One-liner:** Atomic tri-state migration of showHidden/showNonAvailable from boolean to `'off'|'show'|'only'` FilterMode with direct `is_delisted` Steam check and safe legacy localStorage migration.

## What Was Built

### FilterMode Type (types.ts)
Added `export type FilterMode = 'off' | 'show' | 'only'` and retyped all four showHidden/showNonAvailable fields in `LibraryContextType`. This is the shared contract; changing it here cascades type errors to all consumers, which Task 2 and 3 resolve atomically.

### LibraryContext defaults (LibraryContext.tsx)
Changed `showHidden: false` and `showNonAvailable: false` to `'off'` so the context's default object satisfies the new FilterMode type.

### RecentlyPlayed prop retype (RecentlyPlayed/index.tsx)
Imported `FilterMode`, changed `showHidden: boolean` prop to `FilterMode`, and updated the filter guard from `if (!showHidden)` to `if (showHidden === 'off')`.

### Library state migration (Library/index.tsx)
- Added `migrateFilterMode(key, defaultValue): FilterMode` helper that validates the stored value is `'off'|'show'|'only'` and falls back to `defaultValue` for any other value (handles legacy `'true'`/`'false'`/`null` — T-08.1-06 mitigation).
- Both filters initialize with default `'off'` (D-03: delisted hidden by default).
- `handleShowHidden`/`handleShowNonAvailable` now store the raw string without `JSON.stringify`.
- Fixed boolean cast site: `if (showHidden)` → `if (showHidden !== 'off')` in `favouriteGamesList` useMemo.
- Removed BOTH duplicate `if (!showNonAvailable)` blocks (Pitfall 1 collapse).
- Replaced the removed blocks and the old `if (!showHidden)` block with one tri-state filter section using local `isNonAvailable`/`isHidden` helpers.
- `isNonAvailable` checks `nonAvailableGamesArray.includes(game.app_name) || (game.runner === 'steam' && !!game.is_delisted)` — covers not-installed delisted Steam games that never enter the localStorage array (LIB-07).
- Tri-state logic: both-'only' → union (D-09); single-'only' → isolate; else subtractive with 'off'.

### LibraryFilters tri-state controls (LibraryFilters/index.tsx)
- Extended `toggleWithOnly` signature to `(toggle, onOnlyClicked, isOnly?: boolean)` with `aria-pressed={isOnly ?? false}` on the `.only` button.
- Replaced boolean `toggleShowHidden`/`toggleShowNonAvailable` with tri-state cycle handlers: toggle-switch click cycles Off→Show (or Only→Show); only-button cycles →Only (re-click →Off).
- Added `setHiddenOnly` and `setNonAvailableOnly` handlers.
- Fixed `resetFilters` to call `setShowHidden('off')` / `setShowNonAvailable('off')` (Pitfall 6: reset must return to default off, not 'show').
- Replaced bare `<ToggleSwitch>` elements for both filters with `toggleWithOnly(...)` composites using `value={showHidden !== 'off'}` and `isOnly={showHidden === 'only'}`.
