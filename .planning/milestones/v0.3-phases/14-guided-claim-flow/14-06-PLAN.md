    Use a REAL connected Humble account and exactly ONE disposable UNREVEALED key you are willing to permanently consume (C1 is irreversible — do not use a key you might want to gift).
    1. Launch GameLib (dev build), open Humble Keys → Keys waiting.
    2. On a Steam UNREVEALED key you do NOT own, click "Claim" → confirm "Reveal key" on the danger warning.
       - EXPECTED: the modal shows the real key string (Step 2 "Your key"); the key is on your clipboard; the row later shows "Revealed {date}".
       - IF the very first attempt returns a 403 / "Temporarily unavailable" cooldown: this is likely the CSRF trap (Pitfall A), NOT a real rate-limit. Check the backend log for the reveal outcome and the presence of a captured csrf_cookie. Report which case occurred.

    4. Back in GameLib click "Mark as redeemed" → row shows "Redeemed {date}" + an "Undo"; click "Undo" → row returns to "Finish activation"; re-run "Finish activation" and confirm it re-opens at the key WITHOUT a second reveal call (check the log — revealKey must not fire again).
    5. On an OWNED (or fuzzy "Likely owned") key, click "Claim" → EXPECTED: the C2 block panel "You already own this on Steam" routes you to Giftable spares; no reveal happens.
    6. On a non-Steam key (if available), click "Claim" → after reveal, EXPECTED: "Redeem on {platform}" link-out + Copy key, and NO "Open Steam" one-click activation.
    Record in 14-VALIDATION.md: the confirmed URL/fields/response, whether csrf-prevention-token was required (and if the flow worked WITHOUT it, note that the csrf capture can be dropped as dead code in a follow-up), and any deviation from the researched contract.
