<objective>
Close both UAT gaps (test 2 CR-01, test 3 WR-02) at their single shared root
cause: `classifyTpk` treats Humble's server-populated `redeemed_key_val` as
`REDEEMED` (Steam-activated), when in Humble's own model that field only means
the key has been REVEALED (Humble's reveal endpoint is literally
`/humbler/redeemkey`). Humble has no knowledge of Steam activation, so every
sync after a reveal reclassified live claim state to REDEEMED — clobbering the
"Finish activation" resume and laundering the local Mark-as-redeemed mark into a
server-looking REDEEMED that dropped its Undo.

Core realignment (user-diagnosed and user-approved during the UAT session):
1. SERVER truth maps to UNREVEALED / REVEALED / UNREDEEMABLE only.
   `redeemedKeyValuePresent` → REVEALED.
2. REDEEMED becomes a LOCAL-ONLY overlay produced solely by the user's
   "Mark as redeemed" (`isLocallyRedeemed`), permanently undoable — Undo is
   local bookkeeping that survives any number of syncs.
3. Delete the compensation machinery this makes unnecessary: the CR-01
   `locallyRedeemedPending` special-casing and the WR-02 `selectKeysWaiting`
   keep-visible annotation workaround. With the realignment, REVEALED keys stay
   in Keys waiting naturally and every local REDEEMED mark is undoable, so no
   origin distinction is needed — the field is fully redundant and is removed.
4. Amend the D-30 rationale in the decision record: "server truth wins" stays
   true for what the server actually knows (revealed-ness, expiry) — the
   amendment is only what `redeemed_key_val` MEANS.
5. Preserve D-66 (a REVEALED key with a stored value opens finish mode without a
   second reveal POST) and D-30 expiry precedence (UNREDEEMABLE beats
   everything) — both untouched.

Purpose: make GameLib's claim state faithful to Humble's actual model so claim
progress survives sync, as the two failed UAT tests require.
Output: realigned classifier, simplified view/library layers, a
classifier-version bump that reclassifies cached rows on next sync, updated test
coverage for the new semantics, and an amended D-30 decision record.

## Out of scope / follow-up (do NOT build here)

A consequence of the realignment: keys revealed on Humble's website BEFORE
GameLib synced now surface in Keys waiting as REVEALED / "Finish activation"
instead of silently REDEEMED. This is honest per Humble's model. The interim
signal is the existing `ownedElsewhere` machinery + the D-72 owned-note in the
wizard's finish step (both already present — no change needed here).

The stronger corroboration — reading steam-user licenses
(`payment_method === EPaymentMethod.ActivationCode` + `time_created`) to
confidently auto-mark-redeemed (still undoable) — is a FUTURE-PHASE enhancement.
Capture it as a deferred item (Task 3); do NOT build it in this gap closure.
</objective>
