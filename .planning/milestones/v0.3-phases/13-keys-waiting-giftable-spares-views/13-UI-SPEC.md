# Phase 13 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — GameLib is a 12-phase-deep Heroic fork with an established, hand-rolled SCSS custom-property design system (`src/frontend/styles/_colors.scss`, `_spacing.scss`, `_typography.scss`, multi-theme `themes.scss`). No `components.json`, no Tailwind, no shadcn anywhere in the repo. CLAUDE.md explicitly instructs reusing existing SCSS tokens, not reinventing — introducing shadcn mid-fork would fork the design system itself and contradict that instruction. **shadcn gate: intentionally not offered, resolved by existing project convention.** |
| Component library | none — hand-rolled React components per screen (e.g. `HumbleKeyRow`, `HumbleKeyGroup`, `WarningMessage`, global `showDialogModal`/`DialogModalOptions`) |
| Icon library | FontAwesome (`@fortawesome/react-fontawesome` + `@fortawesome/free-solid-svg-icons`) — already the icon library for this exact screen (`faSyncAlt`, `faChevronRight` in `HumbleKeys/index.tsx` and `HumbleKeyGroup`). Use FontAwesome for any new icon in this phase (e.g. a chevron or external-link glyph on the "Gift on Humble" action); do not introduce `@mui/icons-material` here even though it exists elsewhere in the codebase (Settings screen) — stay consistent with the sibling components this phase extends. |
| Font | Primary (headings): `Rubik`. Secondary (body/UI): `Cabin`. Both already declared in `_typography.scss` `--primary-font-family` / `--secondary-font-family`; no new font-loading needed. |

## Spacing Scale

**Deviation from default 4px-multiple scale, by design:** this project's spacing tokens are em-based with a 1.2 ratio (matching the typography scale ratio), already in production across 12 shipped phases, including the exact screen this phase extends. Do not introduce a parallel px-based 4/8/16/24/32 scale — reuse the existing tokens as-is.

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| `--space-3xs` | 0.25em (~4px) | Badge/pill internal padding (state badge, urgency badge, count badge) |
| `--space-2xs` | 0.375em (~6px) | Badge padding (horizontal), tight inline gaps |
| `--space-xs` | 0.5em (~8px) | Row-internal gaps (title/caption stack, badge-to-text gaps) |
| `--space-sm` | 0.75em (~12px) | Tab-bar internal padding |
| `--space-md` | 1em (~16px) | Row gaps, header blurb bottom margin, group list gaps |
| `--space-lg` | 1.5em (~24px) | Group-list vertical rhythm (existing `.humbleKeysGroupList` gap) |
| `--space-xl` | 3em (~48px) | Empty-state vertical padding (existing `.humbleKeysEmptyState`) |
| `--space-md-fixed` | 16px | Screen-level outer padding (existing `.humbleKeysScreen`) |

Exceptions: none new. The tab bar (new in this phase) uses `--space-sm` vertical padding + `--space-md` horizontal padding per tab, matching the existing `.humbleKeysRefreshButton` touch-target feel (no new 44px touch-target exception needed — this is a desktop Electron app, not touch-first).

## Typography

Reuse the existing 4-size / 2-weight scale already exercised by `HumbleKeyRow`/`HumbleKeyGroup` — do not add a 5th size or a 3rd weight for this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / row title | `--text-md` (16px) | `--regular` (400) | 1.5 (default — no existing override; rows are single-line so this rarely visually matters, but declare it for any future multi-line body copy, e.g. header blurbs) |
| Label / caption / badge text | `--text-xs` (11.11px) | `--regular` (400) — plain captions; `--semibold` (600) — state/urgency badge fill text | 1.2 |
| Tab label / group heading | `--text-lg` (19.2px) | `--semibold` (600) | 1.2 |
| Empty-state heading | `--text-lg` (19.2px) | `--semibold` (600) | 1.2 |

Exactly 2 weights used across the whole phase: `--regular` (400, default body/caption text) and `--semibold` (600, badges/headings/tab labels/empty-state heading) — matches the existing screen's convention exactly.

## Color

Multi-theme app (`themes.scss` defines 8+ themes) — **all colors below are semantic custom properties, never hex.** This is a hard cross-cutting constraint inherited from every prior Steam/Humble phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--body-background)` | Screen background (`.humbleKeysScreen`, tab panel backgrounds) |
| Secondary (30%) | `var(--background)` | Tab-bar strip background, row dividers area |
| Accent (10%) | `var(--accent)` | Active-tab indicator (underline/text color) and hover states only — refresh button hover, "Not the same game" override hover already use `var(--accent)`; the new active-tab NavLink state reuses it |
| Destructive / irreversible-action | `var(--status-danger)` | NOT used for a delete action in this phase (there is none) — reused instead for the ≤7-day urgency badge fill (D-61), and for the confirm-dialog's primary button styling on the "Open Humble" gift-confirmation action (irreversibility, not deletion, but the same visual weight applies) |

**Accent reserved for:** active-tab NavLink indicator + hover states on interactive text (refresh icon, ownership override link, tab links). **Never** used as a background fill or for badges — badges use the semantic status tokens below, not accent.

**Status tokens for urgency + state badges (D-61, D-63, reusing Phase 7's tier→color convention):**

| Tier | Token | Hex (current theme) | Applies to |
|------|-------|----------------------|------------|
| Danger | `--status-danger` | `#f97881` | Urgency badge, ≤7 days left |
| Warning | `--status-warning` | `#f8ae79` | Urgency badge, 8–30 days left |
| Info | `--status-info` | `#2ceac7` | Existing UNREVEALED state badge (unchanged) |
| Success | `--status-success` | `#0ce396` | Existing REDEEMED state badge + "Owned on Steam" badge (unchanged) |
| Default | `--status-default` | `#d2d2d2` | Existing UNPICKED state badge (unchanged) |

No new semantic color is introduced this phase — the urgency badge reuses the exact `--status-danger`/`--status-warning` pair already governing state badges elsewhere, per the locked Phase 7 tier→color precedent D-61 explicitly cites.

## Copywriting Contract

> **Note on D-57 resolution:** RESEARCH.md conclusively determined the Humble cached payload never carries a gift-link field. The "copy gift link to clipboard" mechanic described in CONTEXT.md's D-58/D-59 is **superseded** by the deep-link fallback branch. All copy below reflects the resolved (deep-link) behavior, not the literal original wording.

| Element | Copy |
|---------|------|
| Primary CTA (Giftable Spares row action, HVIEW-02) | **"Gift on Humble"** — opens `https://www.humblebundle.com/home/keys` externally after confirmation |
| Confirmation dialog title | **"Gift this key?"** |
| Confirmation dialog body | **"Anyone with this link can claim the key — once redeemed, it's gone for good. You'll finish gifting it on Humble's own site."** |
| Confirmation dialog buttons | Cancel: **"Cancel"** · Confirm: **"Open Humble"** (no "don't ask again" checkbox — D-58 is explicit on this) |
| Post-action row annotation (D-59, reinterpreted) | **"Opened Humble gift page {{date}}"** — renders once a gift action has been confirmed for that key, guards against double-gifting the same spare |
| Keys Waiting — header blurb (D-64, locked) | **"Keys you don't own yet — claim them before they expire."** |
| Giftable Spares — header blurb (D-64, locked) | **"You already own these games — keep the keys unrevealed and gift them instead."** |
| Keys Waiting — empty state heading | **"You're all caught up"** |
| Keys Waiting — empty state body | **"No keys are waiting to be claimed. Check the All keys tab to see your full inventory."** |
| Giftable Spares — empty state heading | **"No giftable spares"** |
| Giftable Spares — empty state body | **"Keys show up here once they're confirmed owned elsewhere and haven't been revealed yet."** |
| Tab labels + live counts (D-52) | **"Keys waiting ({{count}})"** · **"Giftable spares ({{count}})"** · **"All keys"** (uncounted) |
| Urgency badge, ≥2 days left | **"{{N}} days left"** (`N = Math.ceil(daysLeft)`) |
| Urgency badge, exactly 1 day left (24h–48h) | **"1 day left"** |
| Urgency badge, under 24h left | **"{{H}}h left"** (`H = Math.max(1, Math.ceil(hoursLeft))`) |
| Error / fail-soft state (existing, reused unchanged across all 3 tabs) | **"Couldn't refresh — showing data from {{time}}"** (`humbleKeys.syncError`, already shipped in Phase 11 — not re-specified, shared header) |
| Destructive-style confirmation (only irreversible action this phase adds) | **Gift action**: see confirmation dialog row above — irreversibility framed as "gone for good," not phrased as deletion since no data is deleted, an external key-claim link is exposed |

**Rejected discretion resolution (documented for the checker):** D-62's "weeks phrasing beyond 7 days" option was considered and **rejected** in favor of a single consistent `"{{N}} days left"` format across the full 2–30 day range — a 15-day badge showing "2 weeks left" hides precision a user checking expiration urgency needs. Hours-phrasing under 24h is kept since it is genuinely more useful at that granularity, not merely stylistic.

## Phase-Specific UI Contract

*(Additional detail beyond the standard template, required because this phase's contract is unusually load-bearing for Phase 14 — the route path chosen here is a hard downstream dependency.)*

### Routes (D-51, locked path segments — Phase 14's C2 guard depends on these exact values)

```
/humble-keys                  → index redirect to /humble-keys/waiting (D-50 default)
/humble-keys/waiting           → Keys Waiting (HVIEW-01)
/humble-keys/spares            → Giftable Spares (HVIEW-02) — Phase 14 C2 redirect target
/humble-keys/all                → All keys (D-21 layout, unchanged, moved verbatim)
```

Sidebar entry / route guard (`humbleLoginPath` bounce when logged out) is unchanged and inherited by all three child routes automatically via the parent route.

### Tab bar (new component, no existing precedent to reuse verbatim)

- Built from semantic-token-styled `<NavLink>` elements (react-router), NOT the existing `TabPanel` component (`TabPanel` is non-routed in-memory state; D-51 requires real sub-routes).
- Tab strip background: `var(--background)`; active tab text/underline: `var(--accent)`; inactive tab text: `var(--text-secondary)`.
- Count badge (Keys waiting / Giftable spares only, D-52) reuses the exact chrome of the existing `.humbleKeyGroupCount` pill: `--text-sm` / `--regular`, `var(--text-secondary)`, `padding: var(--space-3xs) var(--space-2xs)`, `border-radius: var(--space-3xs)`, background `var(--input-background, var(--background))`.
- Sync-status header (refresh button, spinner, last-synced text, fail-soft banner) renders **once**, in the parent route, above the tab bar — not duplicated per child route (avoids triplicated `handleHumbleSyncProgress` listener wiring).

### Row extension (do not fork `HumbleKeyRow`)

- Extend the existing `HumbleKeyRow` component with two new optional props: an urgency-badge render (D-61/62/63, all 3 tabs) and a gift-action render (Giftable Spares only, D-60).
- The urgency badge renders as a second badge alongside the existing state badge — same `.humbleKeyStateBadge`-family chrome (`--space-3xs`/`--space-2xs` padding, `--space-3xs` border-radius, `--text-sm`/`--semibold`, `var(--neutral-01)` text on a status-color fill) so it reads as a sibling, not a competing visual language.
- **Mandatory safety valve (do not drop when extending the row for Spares):** the D-41 "Likely owned on Steam" badge and the D-42 "Not the same game" override must render on every fuzzy-matched row in the Giftable Spares tab exactly as they do today. This is the load-bearing mitigation for WR-02 (12-REVIEW.md) — a Spares-specific row rewrite that drops this is a regression, not a simplification.
- All-keys tab (`/humble-keys/all`) remains **strictly read-only** (D-22) with the sole D-42 override exception — the gift action must never render there (D-60).

### Urgency badge eligibility (D-63, locked)

Badge renders only for states `UNPICKED`, `UNREVEALED`, `REVEALED` and only when `daysLeft <= 30` and `daysLeft >= 0`. `REDEEMED` and `UNREDEEMABLE` never badge (the "Expired" state badge already communicates this for `UNREDEEMABLE`).

### Icons

- Reuse `faChevronRight` styling precedent for any new disclosure affordance.
- If the "Gift on Humble" action needs a visual external-link cue, use FontAwesome `faExternalLinkAlt` (or `faUpRightFromSquare` depending on installed FA version) — do not introduce a new icon package.
