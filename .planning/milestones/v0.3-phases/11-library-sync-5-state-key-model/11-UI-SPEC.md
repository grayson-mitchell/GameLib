# Phase 11 — UI Design Contract: Library Sync + 5-State Key Model

> Visual and interaction contract for Phase 11 (HSYNC-01..04). Generated by gsd-ui-researcher.
>
> This phase ships exactly one new surface: a minimal, strictly read-only "Humble Keys" page
> (D-19) that proves the 5-state classification model is correct. Per CONTEXT.md's own framing:
> **"Resist decorating it."** Every visual choice below defaults to the plainest existing
> pattern in the codebase rather than inventing new chrome. Phase 13 restyles this page into
> the real Keys-Waiting / Giftable-Spares views — this contract is deliberately conservative so
> that evolution, not a rebuild.

## Spacing Scale

Existing em/px-hybrid tokens from `_spacing.scss`. This phase adds zero new spacing constants;
row vertical padding has been moved onto an on-grid token (see Exceptions below) so that only
one legacy off-grid value remains in the contract, and that one is explicitly justified.

| Token | Computed Value | Usage in this phase |
|-------|-----------------|----------------------|
| `--space-3xs` | ~4px (0.25em) | Badge border-radius; row internal icon gaps |
| `--space-2xs` | ~6px (0.375em) | State badge padding (vertical/horizontal, matches `.gameCardUpdateBadge` pattern) — **documented exception, see below** |
| `--space-xs` | ~8px (0.5em) | Gap between row title and secondary caption line; freshness-indicator/refresh-button gap |
| `--space-md` | 16px (1em) | Group-section padding; page content horizontal padding; banner padding (via `WarningMessage`); **row vertical padding** |
| `--space-lg` | 24px (1.5em) | Gap between state groups |
| `--space-xl` | 48px (3em) | Empty-state vertical centering padding |

**Exceptions:** `--space-2xs` (~6px) is the sole off-grid value in this contract — it is not a
new invention. It is the exact padding value already shipping in production on
`.gameCardUpdateBadge` (`padding: var(--space-3xs) var(--space-2xs);` in
`GameCard/index.css`), which this phase's state badge deliberately reuses byte-for-byte per the
Component Inventory's "Reuses `.gameCardUpdateBadge` visual chrome (padding/border-radius/font)"
directive. Approved as a documented exception because: (1) it is pre-existing project debt this
phase does not own — substituting a different padding value here would break the "identical
visual chrome" contract this spec sets for badge reuse, producing two near-identical badge
components (Library `GameCard` vs. Humble Keys) with visibly inconsistent proportions on
adjacent screens; (2) it is a single legacy token, not a new off-grid pattern — every other
value in this contract is on the standard 4/8/16/24/32/48/64 grid. `--space-sm` (~12px), which
had no existing-codebase precedent justifying its use (no `.css` file in the project references
it), has been removed from this contract entirely and replaced with `--space-md` (16px,
on-grid) for row vertical padding — that substitution had no reuse fidelity to preserve, so it
is fixed outright rather than exempted.

**Source:** `src/frontend/styles/_spacing.scss` (detected); `.gameCardUpdateBadge` / `.steamStaleIndicator` / `.WarningMessage` existing padding patterns (detected).

## Typography

Exactly 3 roles, 2 weights — matches the existing type scale (base 16px, 1.2 ratio).

| Role | Token | Approx px | Weight Token | Weight | Line Height | Usage |
|------|-------|-----------|---------------|--------|-------------|-------|
| Group heading | `--text-lg` | ~19px | `--semibold` | 600 | 1.2 | State-group section label ("Unrevealed", "Redeemed", etc.) + count pill |
| Row title | `--text-md` | 16px | `--regular` | 400 | 1.5 | Key/game title per row |
| Caption | `--text-xs` | ~11px | `--regular` | 400 | 1.2 | Secondary row line (platform · bundle origin); "Last synced X ago" indicator; expiration date text |

State badges reuse `--text-sm` (~13px) at `--semibold` (600) — this is the existing `.gameCardUpdateBadge` badge-text convention, not a new role; declared in Color section below alongside the badge component spec.

**Do not introduce a 3rd font weight.** `--semibold` (600) is used for group headings and state badges only; `--regular` (400) for all row/body/caption text.

**Source:** `src/frontend/styles/_typography.scss` (detected); `LibraryHeader/index.css` `.steamStaleIndicator` (text-xs/regular) and `GameCard/index.css` `.gameCardUpdateBadge` (text-sm/semibold) precedents.

| Secondary surface (30%) | `var(--background)` / `var(--neutral-02)` | `#161c1e` | Group-section container background (subtle distinction from canvas), banner surface via `WarningMessage` |
| Accent (10%) | `var(--accent)` | `#8bffff` | Manual refresh button hover/focus color ONLY (mirrors `.steamRefreshButton:hover` pattern) |
| Text primary | `var(--text-default)` | `#eae8e5` | Row title, group heading |

Not applied anywhere else on this page — no accent on state badges, group headings, or row text.

**Destructive color:** `var(--status-danger)` is used only as the UNREDEEMABLE state-badge background (below) — there are no destructive user *actions* in this phase (D-22: strictly read-only), so no confirmation-dialog color is needed.

### 5-State Badge Color Mapping

Each row and each group heading uses one of these five colors, consistently. This is the phase's core visual contract — it must never vary per row within a state.

| State | Token | Resolved | Rationale |
|-------|-------|----------|-----------|
| `UNPICKED` | `var(--status-default)` | `#d2d2d2` (light grey) | Neutral/informational — action happens on Humble's site, not in-app. Matches the existing `.gameCardDelistedBadge` precedent of using neutral grey for "nothing actionable in-app." |
| `UNREVEALED` | `var(--status-info)` | `#2ceac7` (teal) | Ready/available — the "you have this to claim" signal (Phase 13 builds the actual claim CTA) |
| `REVEALED` | `var(--status-warning)` | `#f8ae79` (orange) | Mid-flow — key is out, activation not yet confirmed. Orange signals "needs follow-through," reused later by Phase 14's "mark as redeemed" reminder |
| `REDEEMED` | `var(--status-success)` | `#0ce396` (green) | Terminal success |
| `UNREDEEMABLE` | `var(--status-danger)` | `#f97881` (coral/red) | Terminal loss — key expired before redemption |

**Badge text color:** `var(--neutral-01)` (`#070a0b`, dark) on all five badge backgrounds — every background above is light/bright enough for dark text, matching the existing `.gameCardUpdateBadge`/`.gameCardDelistedBadge` convention of `color: var(--neutral-01)` regardless of background hue. Do not use white text on any state badge.

**Why the fail-soft banner overrides `WarningMessage`'s default red:** `WarningMessage`'s existing default background is `var(--status-danger)` (used today for the Humble session-expired-adjacent messages). D-31 explicitly states background sync failures "aren't interruption-worthy" and are a different severity than an expired session. Reusing `WarningMessage` as-is (red) would visually overstate the failure. This phase must pass a modifier class (see Component Inventory) that overrides `background: var(--status-warning)` and `color: var(--neutral-01)` — orange, not red, for this one banner instance only. `WarningMessage`'s built-in triangle icon keeps its existing hardcoded `color="yellow"` (pre-existing debt, out of scope to fix here).

**Source:** `_colors.scss`, `themes.scss` (detected); `.gameCardUpdateBadge`, `.gameCardDelistedBadge`, `.steamRefreshButton`, `.steamStaleIndicator`, `WarningMessage` (all detected in codebase).

## Sidebar Entry (D-20)

**Icon:** `faKey` (FontAwesome free-solid-svg-icons — already available in the project's FA import set).

**Label:** `t('sidebar.humbleKeys', 'Humble Keys')`

**Position:** Immediately after the "Stores" `SidebarItemWithSubmenu` block, before the "Deals" (`/discounts`) item — literally "alongside Stores" per D-20's wording, and before the general-purpose `divider`.

```tsx
{humble?.isLoggedIn && (
  <SidebarItem
    url="/humble-keys"
    icon={faKey}
    label={t('sidebar.humbleKeys', 'Humble Keys')}
    dataTour="sidebar-humble-keys"
  />
)}
```

**Gating:** `humble?.isLoggedIn` only — do NOT also require `!humble?.expired`. An expired session still has cached keys worth viewing (HSYNC-04's whole point); the nav slot must stay visible so the user can reach the fail-soft/expired view rather than losing access to their cached inventory. This mirrors the existing `HumbleExpiryToast` design note: expiry degrades data freshness, it does not hide the feature.

**Route guard:** If a user reaches `/humble-keys` directly (deep link, back-button) while `humble.isLoggedIn` is false, redirect to `/login` (reusing the existing `humbleLoginPath` constant), matching the project's existing unauthenticated-route-guard convention. No custom "disconnected" empty state is needed on this route — the guard prevents ever rendering it disconnected.

**Source:** `src/frontend/components/UI/Sidebar/components/SidebarLinks/index.tsx` (detected: `loggedIn` gating pattern for epic/gog/amazon/zoom, `/login` route reuse), `src/frontend/screens/Login/index.tsx` (detected: `humble.isLoggedIn`/`humble.expired`/`humbleLoginPath` shape).

## Interaction Contracts

### Sync Triggers (D-23)

Three triggers only, no background interval:
1. App startup, after the Phase 10 D-08 health check confirms a non-expired session
2. Immediately after a successful Humble login/reconnect
3. Manual refresh button on this page

**Manual refresh button:** icon-only (`faSyncAlt`), positioned top-right of the page header — exact visual/behavioral clone of `LibraryHeader`'s `.steamRefreshButton`: transparent background, `color: var(--action-icon)` default, `color: var(--accent)` on hover, spins (`fa-spin` / `.spinning` class) while a sync is in flight, `disabled` (not clickable, `opacity: 0.6`, `cursor: not-allowed`) during the 403 cooldown window (D-33).

`aria-label`: `t('humbleKeys.refresh', 'Refresh Humble Keys')`.

### Progressive Fill (D-26)

While a sync with more than one order in flight is running, replace the "Last synced X ago" text with a progress line:

`t('humbleKeys.syncing', 'Syncing… {{done}}/{{total}} orders', { done, total })`

Rendered with the same `.steamSyncSpinner`-style spinning `faSyncAlt` icon (color `var(--text-secondary)`, not accent) immediately preceding the text — matches `LibraryHeader`'s existing `isSteamSyncing` treatment exactly. Keys already resolved during this sync appear in the list immediately (progressive fill is a data-arrival behavior, not merely a text change) — do not gate list rendering on sync completion.

### Fail-Soft Banner (D-31, D-34)

Renders only when `syncError` is set (non-auth failure: network, timeout, 403/429 denial). Uses `WarningMessage` with the `humbleSyncBanner` modifier (orange, per Color section), positioned directly below the page header, above the grouped list:

`t('humbleKeys.syncError', "Couldn't refresh — showing data from {{time}}", { time: lastSyncedRelative })`

If the abort happened mid-sync (D-34, some orders refreshed before the 403), copy changes to:

`t('humbleKeys.syncErrorPartial', "Couldn't finish refresh — showing the latest data available", {})`

**No toast, no dismiss button.** The banner clears automatically on the next successful sync (D-31) — it is not user-dismissible, because it reflects current data state, not a one-time event (contrast with `HumbleExpiryToast`, which IS dismissible because it's a one-time prompt).

### Cooldown (D-33)

When the sync aborts on a 403, the manual refresh button becomes disabled and its `title`/tooltip attribute (not a separate banner) shows:

`t('humbleKeys.cooldown', 'Temporarily unavailable — retry in {{minutes}}m', { minutes })`

The disabled button uses the exact same visual state as `.steamRefreshButton:disabled` (opacity 0.6, `cursor: not-allowed`) — no new disabled-state CSS.

### UNPICKED Pseudo-Entry (D-27)

Renders as a normal row inside the UNPICKED group, using the grey badge:

Title: `t('humbleKeys.unpickedTitle', 'Humble Choice — {{month}} {{year}} · games not picked', { month, year })`

Secondary caption: omitted (no platform/origin — this is not a real key yet).

Expiration column: shows the pick deadline if the API supplies one; if not available, renders `t('humbleKeys.noDeadline', 'No pick deadline available')` in `--text-secondary` — never blocks the row from rendering, never throws (per Claude's Discretion / Pitfall 2).

### Row Read-Only Contract (D-22)

No `onClick`, no hover background/elevation change, no cursor:pointer, no keyboard focus ring beyond the browser default (rows are not interactive elements — render as `<div>`/`<li>`, not `<button>`/`<a>`). No copy icon, no reveal button, no expand affordance, no context menu. This is intentional and must not be "improved" during implementation — the read-only contract is a safety property (Phase 14 owns claim actions), not a placeholder oversight.

**Destructive actions in this phase:** **None.** All rows are read-only; no delete/reveal/redeem action exists. The disconnect action (removing the whole Humble account) is Phase 10 scope, unchanged here, and is not reachable from this screen.
