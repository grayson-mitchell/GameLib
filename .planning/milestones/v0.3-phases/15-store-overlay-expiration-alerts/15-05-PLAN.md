<objective>
Close CR-01 (HSTORE-01 blocker): the 'Key available' Discounts badge is
structurally unreachable in production because `Discounts/index.tsx` derives
BOTH `titleToSteamAppId` and `ownedSteamAppIds` from the same source
(`steam.library`) — so any AppID that resolves is always already in
`ownedAppIds`, and `resolveDiscountBadge` returns `'owned'` before it can ever
reach the `'key-available'` branch.

Fix: extract the map construction into a pure, shared helper
`buildDiscountBadgeMaps` in `common/discounts/badges.ts`. The helper builds
`titleToAppId` from steam.library AND merges each waiting Humble key's own
`title`/`steamAppId` (so an unowned-but-keyed title resolves to an AppID that is
NOT in `ownedAppIds`), while `ownedAppIds` stays derived from steam.library
only. The container consumes this exact helper, and the badge test suite
exercises the SAME helper — killing the "hand-decoupled fixtures" masking that
let CR-01 ship green.

Purpose: deliver the second of HSTORE-01's three required badge states.
Output: reachable 'key-available' pill + a regression test built from the real map path.
</objective>
