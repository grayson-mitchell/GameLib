<objective>
Build direction B's pre-install macOS arch hint: derive `mac_arch` from the Steam store-API `mac_requirements` minimum-OS heuristic — read off the SAME `appdetails` response the codebase already fetches for `is_mac_native` — and wire the confirmed-32-bit branch into `isBottleEligible()` so post-install Mach-O verdicts (Plan 18-03) route the moment they land (MAC32-01, MAC32-02).

Purpose: Plan 18-01's real appinfo dump proved Steam PICS appinfo carries NO 32-vs-64 mac-arch signal (`osarch` absent on every macOS entry, even for a confirmed 32-bit game). The entire osarch/PICS/`getProductInfo`/`parseOsArchHint`/`ensureMacArchHint` approach is dead and MUST NOT be carried forward. The replacement is the store-API `mac_requirements.minimum` min-OS floor: min-OS >= 10.15 (Catalina) proves the binary MUST be 64-bit (Apple physically cannot run i386 on Catalina+), so it is a CONFIDENT '64'; a lower/absent/unparseable floor proves nothing about bitness, so it is a SOFT 'unknown'. The heuristic NEVER asserts '32' pre-install — A Hat in Time (real min-OS 10.11.6, genuinely 64-bit) lives in the 'unknown' bucket, and asserting '32' there would recreate the exact false-flag over-routing the design forbids.

Output: `parseSteamMacMinOSVersion` + `macArchFromMinOS` pure functions in games.ts (colocated with the sibling `parseSteamStorageRequirement`); the inline `mac_arch` derivation folded into the existing `fetchMetadataIfNeeded` (no new async wiring — `ensurePlatformsCaptured()` already awaits it before every `isBottleEligible()` consultation); the `mac_arch === '32'` OR-branch in `isBottleEligible()`; the `mac_arch_source` enum reconciled from `'osarch'` to `'minos'`; fixture-based unit tests.
</objective>
