<objective>
Build the CI-only index builder that turns CodeWeavers' daily `.tie` XML dump into the small
offline artifact the macOS library badges/filter read: `meta/buildCrossoverIndex.ts` plus its
`package.json` script entry.

The builder fetches + gunzips the `.tie` dump, parses it with fast-xml-parser v5 entity limits
RAISED via a `ProcessEntitiesOptions` object (NOT `processEntities: false`), extracts against the
dump's REAL shape (`c4p > applications > app[]`, with `steamid`/`category`/`medal` nested inside
`<appprofile>`), filters to Games carrying a Mac medal (~2,866), applies the highest-`cxversion`
medal rule, dedups by the TOTAL deterministic three-key order (cxversion ▼, num ▼, appid ▲),
emits `crossover-index.json.gz` (~58 KB) plus a `collisions.json` drift report that never fails
the build, and fails ONLY on a zero-record extraction.

Purpose: this is the data-pipeline root of Phase 19 (CXIDX-01). Everything downstream (delivery,
fetch/validate, lookup, badges, filter) consumes what this emits. It is CI-only — the app never
parses XML.

Output: `meta/buildCrossoverIndex.ts`, a permanent jest regression test + trimmed fixture,
a `meta` jest project so the test is collected, and the `build-crossover-index` script.
</objective>

The dump's real shape (T-02 — the documented-note shape yields ZERO records):
  root path is `c4p > applications > app[]` (there is an <applications> wrapper).
  <app> has: @appid, @timestamp, name[], cxversion[], appprofile, contributor?, cdprofile?, installprofile?
  steamid / category / medal / description ALL live INSIDE <appprofile>, not on <app>.
  <name> is an array: first element is the bare canonical name (plain string), followed by
    { '#text', '@_lang' } localized variants INCLUDING a lang="en" duplicate.
    Take the entry with NO @_lang, falling back to lang="en".
  <app>'s own <cxversion> is the profile-applicability list — NOT the medal version.
    The medal carries its own @_version; the medal rule sorts on medal[@_version].
  medal attributes: #text (label e.g. gold/ungold), @_rating (1..5), @_platform, @_version, @_num, @_last.

fast-xml-parser config (T-01 — v5 throws "Entity expansion limit exceeded: 1001 > 1000" out of the box):
  new XMLParser({
    ignoreAttributes: false,
    attributeNamePrefix: '@_',
    processEntities: { enabled: true, maxTotalExpansions: 500_000, maxExpandedLength: 50_000_000, maxEntityCount: 1_000 },
    isArray: (name) => ['app', 'name', 'medal', 'category'].includes(name)
  })
  Parse then read: parser.parse(xml).c4p.applications.app

The three-key deterministic dedup (D-04 + Pitfall 5 — the third key is MANDATORY; many
collisions tie exactly on both cxversion AND num, e.g. Quake / EverQuest / Ghost Recon):
  winner(a, b) =
    compareVersion(b.cxversion, a.cxversion)   // 1. highest cxversion  (D-04)
    || (b.num - a.num)                          // 2. most ratings       (D-04)
    || a.appid.localeCompare(b.appid)           // 3. lowest appid       (breaks exact ties)

meta/ script run-shape (package.json, existing sibling entries to mirror):
  "lint-translations": "esbuild --bundle --platform=node --target=node21 meta/lintTranslations.ts | node"

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CodeWeavers FTP → CI builder | The `.tie` dump is an untrusted external document fetched over the network into an ephemeral CI runner. |
| CI builder → emitted index | The emitted `crossover-index.json.gz` is itself untrusted until the app schema-validates it (D-09, enforced in Plan 19-03). This builder produces it; it does not vouch for it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Tampering | emitted rating values (feed a user-facing "won't run" claim) | mitigate | Builder emits `rating` only from the medal `@_rating` coerced to `Number`; the app-side zod schema bounds it `int().min(1).max(5)` and rejects junk before any badge renders (D-09, Plan 19-03). The builder is never the last line of defense. |
| T-19-02 | Denial of Service | fast-xml-parser on a malformed/oversized/entity-bomb dump | mitigate | Raise-but-bound the v5 limits via a `ProcessEntitiesOptions` object (`maxTotalExpansions: 500_000`, `maxExpandedLength: 50_000_000`) — NOT `processEntities: false`. Parsing runs only in an ephemeral CI runner; the app never parses XML. Raised-but-finite limits on a trusted 23.7 MB source is an accepted, bounded CI risk. |
| T-19-03 | Repudiation / Integrity | zero-record extraction silently publishing an empty index | mitigate | Fail-fast: the zero-record guard exits the build non-zero (T-02). A structurally broken parse can never ship an empty "nothing is rated" index. D-05's never-fail applies to collisions only, not to this integrity guard. |
| T-19-04 | Tampering | emitted index consumed downstream without validation | transfer | The index is untrusted until the app schema-validates + bounds it (D-09) and keeps last-good on rejection — owned by Plan 19-03. Documented here as the cross-plan seam so 19-03 must not skip validation. |
| T-19-SC | Tampering | npm/pnpm installs | accept | No package installs in this plan — `fast-xml-parser`, `axios`, `zod`, `electron-store` are all already resolved in `package.json` (per 19-RESEARCH Package Legitimacy Audit). No `[ASSUMED]`/`[SUS]` packages; no legitimacy checkpoint required. |
