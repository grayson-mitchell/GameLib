D-17 (filter ONLY, no sort) and D-18 (warn but never block).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| index data -> renderer filter/warning | The rating numbers powering both the filter and the warning originate from the CI-built CrossOver index, fetched and schema-validated in the backend (D-09, 19-03/19-06) before reaching the `crossoverRatings` slice. This plan is a pure consumer of already-validated display data. |
| user intent -> Install action | The user authorizes an install. The D-18 warning sits alongside this action but must never override the user's authority over it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-08-01 | Tampering | WineSelector warning gate (`crossoverRating <= 2`) | accept | Data is community-sourced and may be a false negative (335 titles carry rating 1). D-18 makes the warning advisory-only; a wrong rating produces at most a spurious warning, never a blocked install or a code path. Accepted risk with full user agency preserved. |
| T-19-08-02 | Denial of Service (agency/availability) | Install button vs. warning | mitigate | The warning is a sibling `.infoBox` render, structurally decoupled from Install enablement. Acceptance criteria + the `disabled=…crossoverRating` grep gate (Task 2) enforce that the Install button's `disabled` prop never references the rating — a user-authorized install can never be hard-blocked by this UI. |
| T-19-08-03 | Tampering | Library display filter over `crossoverRatings` | mitigate | The filter reads `number | null` values already bounded to 1..5 by the D-09 zod schema upstream (19-03/19-06); it never executes or interpolates a rating value, only compares it to derive a tier. Absent keys are treated as "no signal" and never silently hide a game, so a partial/poisoned map degrades to fewer badges, not a hidden library. |
| T-19-08-SC | Tampering | package installs | n/a | This plan installs no npm packages and adds no new dependency (reuses already-imported `faWarning`, existing `ToggleSwitch`, existing zustand slice). Supply-chain surface unchanged. |
</threat_model>
