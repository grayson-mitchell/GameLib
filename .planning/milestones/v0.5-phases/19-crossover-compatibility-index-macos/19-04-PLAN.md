<objective>
Deliver the index **publishing** half of Phase 19: a self-contained GitHub Action that runs the
19-01 builder daily and publishes the result as a Release asset on a rolling, non-`v*` tag, plus
the bundled-snapshot delivery that fetches that asset into `public/` at packaging time so a fresh
install badges immediately and works offline (D-07).

Purpose: Keep the daily-rebuilt artifact **out of the source tree** to preserve Heroic
upstream-mergeability (D-06), while making a silently-dead builder detectable (T-03) and never
colliding with the real signed-release trigger (T-04).

Output:
- `.github/workflows/build-crossover-index.yml` — daily `schedule` + `workflow_dispatch` dual-trigger
  Action that runs `pnpm build-crossover-index` and publishes to the `crossover-index` rolling tag
  with `gh release ... --latest=false --clobber`.
- `.gitignore` — a rule for `public/crossover-index.json.gz` so the snapshot never gets committed.
- Snapshot-fetch steps in `build-base.yml` and `draft-release-mac.yml` that download the asset into
  `public/` before `pnpm dist`, tolerating absence.
- A one-time **human "enable workflow on fork"** checkpoint (forks disable scheduled workflows by
  default — the Action is dead until a maintainer clicks Enable).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → GitHub Releases | The publish step writes a Release asset using a repo token — a write action gated by `GITHUB_TOKEN` scope. |
| Fork scheduling → daily rebuild | Forks disable schedules; the builder's liveness depends on a human enable + `workflow_dispatch`, and its output is a user-facing correctness claim. |
| Release asset → packaging workflows | `gh release download` pulls an external-to-the-build artifact into `public/` before it is bundled into the shipped app. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Denial of Service | `build-crossover-index.yml` schedule on a fork | mitigate | Fork schedules auto-disable (T-03) → a silently-dead builder ships stale badges invisibly. Mitigated three ways: (a) a `workflow_dispatch` trigger keeps it manually runnable, (b) a blocking human "enable workflow" checkpoint (Task 3), (c) the `generatedAt` staleness signal in the published payload (from 19-01) surfaces staleness to the app instead of failing silent. |
| T-19-02 | Tampering / DoS | Rolling release tag vs `draft-release-mac.yml` | mitigate | The rolling tag is the literal `crossover-index`, which does not match `draft-release-mac.yml`'s `on.push.tags: ['v*']` (T-04) — so the daily publish cannot trigger a signed/notarized build. `--latest=false` prevents the index release from shadowing real app releases on the Releases page. No `on.push.tags` trigger is added to the new workflow. |
| T-19-03 | Elevation of Privilege | `GITHUB_TOKEN` used by the publish step | mitigate | Publish uses `permissions: contents: write` scoped to the single job (nothing broader) and `${{ github.token }}` — never `WORKFLOW_TOKEN` or the signing/notarization secrets that `draft-release-mac.yml` holds. The packaging fetch steps keep `contents: read` (a public release download needs no more), so no workflow is granted write beyond the one that must publish. |
| T-19-04 | Tampering | Snapshot fetched into `public/` before packaging | accept | The asset is downloaded over HTTPS from the same repo's own Releases (GitHub CDN); its integrity at app-runtime is separately enforced by 19-03's zod `safeParse` + rating-bound schema (D-09), which rejects a malformed/poisoned payload and keeps last-good. A build-time hash pin is disproportionate for a self-published artifact re-validated on the client. |
| T-19-SC | Tampering | pnpm/dependency installs in CI | accept | This plan adds no new package-manager installs — it reuses the existing `./.github/actions/install-deps` composite against the committed lockfile. Package legitimacy for phase deps is audited in 19-01/19-03 (`fast-xml-parser`, `zod` already project deps). No `[ASSUMED]`/`[SUS]` install introduced here. |
</threat_model>
