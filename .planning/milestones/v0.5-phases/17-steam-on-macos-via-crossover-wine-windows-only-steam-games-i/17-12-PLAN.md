<objective>
Close UAT BLOCKER **GAP-17-PFX86-PATH** (test 3, MACSTEAM-04/05): the bottle-readiness checks probe the wrong `Program Files` directory, so a win32 CrossOver bottle is never recognized as ready and the guided flow re-opens SteamSetup.exe on every Install click.

**Root cause (verified on real CrossOver 26.2 / macOS 2026-07-11 — do NOT re-diagnose):**
The CrossOver `win10` template created a **32-bit** prefix (`cxbottle.conf` → `WineArch = win32`). A win32 prefix has **no `Program Files (x86)`** directory — 32-bit apps install to `C:\Program Files`. Steam installed on disk to `…/Bottles/GameLibSteam/drive_c/Program Files/Steam/steam.exe` ✅, but `getBottleSteamExePath()` and `getBottleSteamappsDir()` in `bottle.ts` HARDCODE `Program Files (x86)`, which is empty in this bottle. So `existsSync(getBottleSteamExePath())` → false → `isBottleReady()` → false forever → `provisioned` stuck false → `dispatchToBottledSteam` short-circuits "Steam bottle is not ready yet" → the guided flow re-provisions on every Install click; badge never flips; install/launch/indicator (tests 3-5) never reached.

**Fix direction (locked by the gap):**
Introduce ONE shared resolver in `bottle.ts` that probes BOTH candidate Steam roots and returns whichever the bottle actually created:
- `drive_c/Program Files (x86)/Steam` — win64 prefix (Steam is 32-bit)
- `drive_c/Program Files/Steam` — win32 prefix
Route `getBottleSteamExePath()`, `getBottleSteamappsDir()`, `isBottleReady()`, and `provisionBottle()` step-8 through it. Prefer the root that actually contains `steam.exe` (self-heals a bottle that already installed Steam under `Program Files`). `library.ts:53`'s `getBottleSteamappsRoot()` calls `getBottleSteamappsDir(...)`, so the ACF scan inherits the fix with NO `library.ts` source change — but add a win32-layout regression assertion in `library.test.ts`.

Purpose: unblocks UAT tests 3-5 (install / launch / D-08 indicator), which cannot be observed until the bottle is recognized as ready.
Output: a shared both-root resolver, exe/steamapps/readiness routed through it, and both-prefix-layout unit fixtures in bottle.test.ts + a win32-layout ACF assertion in library.test.ts.
</objective>
