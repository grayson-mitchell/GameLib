<objective>
The pivot. Reverse Phase 3's blanket `SteamGame.isNative() === true` — but ONLY for confirmed-not-native macOS games (D-11) — and route those games' install/launch/uninstall through the bottled Steam client instead of native `steam://`. Everything else (Mac-native, not-yet-captured, Windows, Linux Proton) keeps the existing native path exactly.

CRITICAL ARCHITECTURAL FACT (verify as acceptance criterion) — CORRECTED for `launch()`:
- `install()` (invoked via the DM-queue path) and `uninstall()` (invoked via `uninstallGameCallback`) ARE self-contained — they fire `steam://` via `shell.openExternal` and do NOT flow through `launcher.ts`. Their bottle routing MUST be implemented inside the SteamGame methods (calling 17-04's `tellBottledSteamTo*`).
- `launch()` is DIFFERENT: it IS invoked from `launcher.ts` `launchEventCallback` at `launcher.ts:234`. Because `isNative()` now returns `false` for a bottle-eligible game, `launchEventCallback` runs `checkWineBeforeLaunch(gameInfo, gameSettings, logWriter)` at `launcher.ts:201-224` BEFORE it calls `game.launch()`. So the bottle-launch path has a pre-step outside `SteamGame.launch()`, and two consequences must be handled (see Task 2): (a) `checkWineBeforeLaunch`'s Pitfall-6 Wine-version auto-recovery would persist to `GameConfig.get(gameInfo.app_name)` using the REAL numeric Steam appId — a phantom per-appId config that never propagates to `steamBottleConfigStore`; (b) a `checkWineBeforeLaunch` early-return (`launcher.ts:222`) on an invalid engine would short-circuit before `game.launch()` ever runs (and thus before any `steamBottleSetupRequired` emit) — low impact since Play only shows for installed → provisioned games, but noted.
The bottle routing for the three verbs is still implemented inside the SteamGame methods (calling `tellBottledSteamTo*`); the launch pre-step is accounted for by resolving bottle settings in `getSettings()` (Task 2). The isNative() flip's other consumers are the frontend `is.native` (via the `isNative` IPC — drives the D-08 indicator + compat rows) and the safety gates audited in Task 3.

D-11 nuance: `library.ts:207` defaults `is_mac_native` to `false` for un-synced entries, so a raw `is_mac_native === false` is ambiguous. Confirmed-not-native REQUIRES `steamMetadataStore.get(appId)?.platformsCaptured === true` — otherwise treat as native (do not bottle a game whose platform data isn't confirmed).

Purpose: Deliver the actual macOS bottle install/launch/uninstall behavior.
Output: reversed + routed `games.ts`, extended tests, and the Pitfall-5 safety guard.
</objective>
