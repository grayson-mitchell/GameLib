<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user text (bottle name via CrossoverBottle.tsx) → filesystem path / spawn argv | An attacker-controlled or malformed bottle name could traverse paths or inject argv |
| GameLib → CrossOver bottle filesystem | Reading bottle state (cxbottle.conf, steamapps) crosses into a Wine-managed subtree |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Tampering | `sanitizeBottleName` / all bottle-name → path joins | mitigate | Single `sanitizeBottleName()` chokepoint rejects `/ \ .. \0`/empty before a name reaches `getBottleDir`/argv; mirrors buildSteamProtocolUrl's numeric-guard precedent (T-03-01) |
| T-17-03 | Denial of Service | `isBottleProvisioned` pre-flight signal | mitigate | Provisioned state derived from the live `cxbottle.conf` existence check (not a cached boolean alone), so a deleted/corrupt bottle is detectable before every bottled op |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | Zero new dependencies this phase (RESEARCH.md Package Legitimacy Audit: not applicable) |
</threat_model>
