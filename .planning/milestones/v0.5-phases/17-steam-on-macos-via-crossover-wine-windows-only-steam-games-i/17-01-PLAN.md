<objective>
Resolve Assumption A1 (RESEARCH.md Pitfall 1 / Open Question 1) BEFORE any provisioning code is written: confirm the exact mechanism to programmatically create a dedicated CrossOver bottle for the Windows Steam client. GameLib's existing Wine plumbing only *verifies* a CrossOver bottle exists (`cxbottle.conf` check) — `verifyWinePrefix()` is an explicit no-op for `wineVersion.type === 'crossover'`. Bottle *creation* is genuinely new territory and the community-documented `cxbottle --create` syntax is MEDIUM/LOW confidence.

Purpose: Prevent 17-04 from being built on an unverified CLI invocation. Mirrors the Phase 16 `spike/` precedent (throwaway, lives in `spike/`, deleted once acted on).
Output: A probe script + a FINDINGS.md that LOCKS the create mechanism (working `cxbottle --create ...` command, or the "user creates via CrossOver GUI, GameLib verifies+configures" fallback per D-02).
</objective>
