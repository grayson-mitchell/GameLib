<objective>
Close UAT GAP 1 (BLOCKER, MACSTEAM-02): first-install of a Windows-only Steam
game on macOS fails with "could not download steam", then enters a stuck
"steam installing" loop with no SteamSetup window.

Root cause (see .planning/debug/steam-bottle-provision-stuck-loop.md):
`provisionBottle()` writes `cxbottle.conf` BEFORE downloading/installing Steam,
and `isBottleProvisioned()` gates only on `existsSync(cxbottle.conf)`. The
redist download dir is never created, so the SteamSetup.exe download fails with
ENOENT, leaving a half-provisioned bottle. Every retry then sees
`isBottleProvisioned()==true`, skips guided setup, and dispatches
`steam://install` to a bottled `steam.exe` that was never installed.

Purpose: make bottle readiness reflect REALITY (conf AND steam.exe), create the
download directory before downloading, and make provisioning self-healing so a
half-provisioned bottle resumes instead of short-circuiting into a broken state.

Output: `isBottleReady()` gate, mkdir-before-download, re-entrant
`provisionBottle()`, and routing gates in `games.ts`/`bottle.ts` swapped onto
the real-readiness signal — plus regression tests.
</objective>
