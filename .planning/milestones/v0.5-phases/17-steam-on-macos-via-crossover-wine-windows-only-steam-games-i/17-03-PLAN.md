<objective>
Make Steam install-state reads bottle-aware. Today every ACF read (`buildInstalledMap`, `readAcfState`, `startInstallPolling`, `startUninstallPolling`, `refreshInstallState`) resolves the NATIVE `defaultSteamPath` via `getSteamLibraries()`. The bottled Windows Steam client keeps its own `steamapps/` inside the CrossOver bottle's `drive_c` — a separate filesystem root that must never be conflated (RESEARCH.md Pitfall 2). Additionally `hostInstallPlatform()` hardcodes `'Mac'` on macOS, which would mislabel a bottle install (a Windows game running under Wine) and break the D-08 indicator gate downstream (Pitfall 3).

This plan parameterizes the existing scan/poll functions on the steamapps root (native vs bottle) WITHOUT reinventing their GRACE_TICKS/MAX_TICKS/notify/idempotent-Map logic, adds a bottle-scoped install map, and fixes the platform label — all behind an explicit `source: 'native' | 'bottle'` selector so the native path is unchanged by default.

Purpose: Give 17-05 (games routing) a bottle-scoped poller + install map to call, so a bottled game's badge flips to installed from the bottle's ACF and reads as a Windows install.
Output: extended `library.ts` + tests with bottle-path fixtures (Wave 0 gap from VALIDATION).
</objective>
