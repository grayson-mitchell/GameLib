<objective>
Close GAP-17-CEF-RENDER: the bottled Steam install dialog renders as a grey bar
with unresponsive buttons because the CrossOver bottle is created 32-bit. The
17-01 spike locked `--template win10`, which is CrossOver's **32-bit** template
(`WineArch = win32`); modern 64-bit Steam's CEF UI (steamwebhelper) composites
the install dialog at `0 x 0` inside a win32 prefix (`webhelper.txt`: "Invalid
browser dimensions: 0 x 0").

Fix has two parts:
- **Part A** — create 64-bit bottles going forward: change the create template
  to `win10_64`.
- **Part B** — re-provision the existing win32 bottle: a win32 prefix cannot be
  converted in place, so `provisionBottle()` must detect a `WineArch = win32`
  bottle and delete + recreate it as win10_64 BEFORE its existing idempotent
  guards (which would otherwise reuse the stale bottle forever). GameLib's Steam
  ACCOUNT auth (refreshToken/isLoggedIn/userData) must be preserved; only bottle
  state (`provisioned`) is reset. Bottled-client login lives inside the prefix,
  so re-login in the fresh bottle is inherent and expected.

Purpose: unblock a NEW bottled Steam install (UAT step 3) so the CEF install
dialog renders and the Install button is clickable.
Output: `bottle.ts` create template + win32 detect/recreate; `bottle.test.ts`
coverage; `FINDINGS.md` LOCKED-CLI note updated.
</objective>
