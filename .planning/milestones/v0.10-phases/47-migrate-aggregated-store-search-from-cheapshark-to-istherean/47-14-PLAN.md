<objective>
Close gap G-47-9 (blocker): clicking Stores while offline crashes GameLib.

Root cause (binding, from `.planning/debug/offline-stores-tab-crash.md`): the renderer's 250 ms drain calls
`store_embed_take_nav_events`, which reads `Webview::url()` on the Tauri store embed on every tick
(`src-tauri/src/store_embed/controls.rs:98-100`, added in f8782dbbf / quick 261102-sk8). When the embed's
first navigation fails (offline, DNS, TLS), `WKWebView.URL` is nil and stays nil, and wry 0.55.1
`url_from_webview` (`wkwebview/mod.rs:1349`) unwraps it inside the main-thread `WebviewMessage::Url`
handler, so the shell panics before our `.ok()` ever sees a result. wry stays pinned at 0.55.1 and this fix
must not depend on an upstream wry release (wry#1729 is unreleased), so our code must never ask a
never-committed embed for its URL.

Not a Phase 47 regression; the operator wants it closed here. `requirements` lists PRICE-03 only because the
crash surfaced while running the PRICE-03 offline UAT item.

Scope note, recorded so it is not mistaken for an omission: the offline surface is driven by the app's
connectivity status (`uiState.connectivity`, owned by the sidecar). A first load that fails while the app is
online (one host's DNS or TLS failing) stays a blank embed, now without a crash, and keeps the existing
Reload / Open in browser chrome. wry 0.55.1's navigation delegate implements no load-failure callback
(`WryNavigationDelegate` maps Started to didCommitNavigation and Finished to didFinishNavigation only), so a
generic failed-load signal would need a new field in the store-embed nav-event wire shape, which
`coerceNavState` in `src/backend/sidecar/storeEmbedFlowRegistration.ts` rejects for non-Epic surfaces today.
Task 2 files that as a pending todo instead of widening this plan.

Purpose: a blocker crash on a first-class tab; the app must survive any first-load failure.
Output: guarded drain + regression tests in Rust; an offline variant of the existing notice row.
</objective>
