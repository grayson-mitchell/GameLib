<objective>
Close gap G-47-7 (cosmetic): Store Search game art is cropped significantly.

Root cause (binding, from `.planning/debug/store-search-art-cropped.md`): two conditions together. `thumbOf()`
(`src/backend/storeSearch/itad.ts:303-306`) picks `banner145` (145x55, 2.64:1 landscape) first, and
`.storeSearchRow__thumb` (`src/frontend/screens/StoreSearch/index.css:131-138`) renders it in a fixed 60x80
portrait box with `object-fit: cover`, so only about 28% of the image width shows. A latent Phase 20 spec defect
(20-UI-SPEC:168), not a Phase 47 regression: CheapShark's 231x87 capsule cropped the same way.

Choices recorded (Claude's discretion):
- Box 120px wide at `aspect-ratio: 300 / 140` (banner300's measured size), so the preferred asset fills it
  exactly; banner300 at 120 CSS px is also crisp on a 2x display, where banner145 would be upscaled.
- `object-fit: contain` on the box itself rather than `cover` plus a `.usingFallback` exception (the debug
  session's `missing` item): contain covers the fallback card AND the two asset shapes `cover` would still crop
  (banner145 when banner300 is absent, boxart-only games). A separate usingFallback rule would be redundant.
- Search results are cached for an hour (ITAD_FRESH_MS) with the thumb URL already chosen, so cached rows keep
  banner145 until they refresh; under contain they are letterboxed, not cropped.

Depends on 47-16 only because both plans edit `StoreSearch/index.css`.

Purpose: the user can recognise the game in each row.
Output: thumbOf order + test, landscape contain box, coupling regression test.
</objective>
