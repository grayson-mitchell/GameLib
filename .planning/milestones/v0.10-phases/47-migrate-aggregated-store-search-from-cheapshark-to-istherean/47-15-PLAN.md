<objective>
Close gap G-47-6 (minor): opening the GOG store from a game link leaves the left navigation with no
highlighted row ("goes blank rather than changing to gog").

Root cause (binding, from `.planning/debug/gog-store-open-blank-left-nav.md`): the in-app routes reached from a
game link (Deals `DiscountCard`, the game page's Store link, the Humble Keys claim) use
`/store-page?store-url=<store url>`. The Stores panel renders, but its rows are pathname-only NavLinks
(`/store/<key>`) with no `isActiveFallback`, so on `/store-page` none is active; the deep link's store key
(`resolveStoreForUrl(...).key`, computed in `WebView/index.tsx:278`) never reaches NavShell. Pre-existing
(the retired Sidebar had the same gap), not a Phase 47 regression; the operator wants it closed here.
`requirements` lists PRICE-01 only because the gap surfaced in that requirement's UAT item.

Choice recorded (Claude's discretion): NavShell imports `resolveStoreForUrl` from
`frontend/screens/WebView/storeEmbedOrigins` directly instead of moving it. That module is pure (no imports),
NavShell components already import from `frontend/screens/*`, and no lint or dependency-cruiser rule forbids
it, so a move would only add churn. `rememberLastStore` for deep links is not added: it would change which
store the Stores tab reopens, which no gap asks for.

Purpose: the tier-2 panel should always show where the user is.
Output: `resolveActiveStore` + tests; NavShell passes `activeStore`; StoresPanel highlights the matching row.
</objective>
