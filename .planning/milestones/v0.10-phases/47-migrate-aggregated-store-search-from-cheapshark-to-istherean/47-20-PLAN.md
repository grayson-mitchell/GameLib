<objective>
Close two gaps in shared input controls:

- G-47-12b (major): macOS replaces a typed search word when the user clicks outside the box ('xcom' becomes 'com',
  and the whole Library grid re-filters while the pointer is on a game). Root cause (binding,
  `.planning/debug/search-input-autocorrect-on-blur.md`): the shared SearchBar input sets no spellcheck/autocorrect
  opt-out, so WKWebView's automatic spelling correction (on by default, following the system "Correct spelling
  automatically" setting, with no squiggle shown) commits its correction on blur as a native `input` event, which
  SearchBar forwards to onInputChanged. One fix point covers Library, Store Search, Deals, Wine Manager and Humble Keys.
  The debug session's throwaway WKWebView harness could not reproduce the bug at all, so only the live check can confirm
  the fix; the tests here pin the attributes.
- G-47-14a (major): the region select shows a blank value whenever the region is Auto. Root cause (binding,
  `.planning/debug/region-picker-auto-shows-blank.md`): RegionPicker represents Auto as value '' and handles it in
  renderValue, but MUI 5.17.1 only calls renderValue when the value is filled or `displayEmpty` is set
  (SelectInput.js:333-341), so Auto renders a zero-width space. The existing test called renderValue directly and never
  went through MUI's gate, a false green. `displayEmpty` alone fixes it (verified by SSR in the debug session).

Decision recorded (Claude's discretion, the debug session's open item "decide whether TextInputField should default
spellCheck off"): yes. TextInputField's callers hold paths, launch arguments, environment values, API keys, URLs, numbers
and titles; an invisible correction committed on blur would silently corrupt a saved setting (a launcher argument, a
CrossOver bottle name, an API key). Squiggles are already off by default in GameLib's WKWebView, so nothing visible is
lost. The defaults sit before the caller's props so a caller can opt back in; none does today.

Purpose: what the user typed and what the user chose stay exactly as they left them.
Output: attribute opt-outs on SearchBar, the Winetricks searchbox and TextInputField; displayEmpty on RegionPicker;
render-level tests for both.
</objective>
