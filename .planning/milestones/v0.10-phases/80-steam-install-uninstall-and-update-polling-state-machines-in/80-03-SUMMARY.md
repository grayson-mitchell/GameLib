# Phase 80 Plan 03: gamelib-i18n Summary

The gamelib-i18n crate renders `{key, default, params}` identically to the sidecar's i18next. All 528 golden rows (48 language settings x 11 cases) pass in `cargo test -p gamelib-i18n`; the Jest freshness test fails with the regeneration command if a locale edit changes any rendering.

## Commits

- d7ebeb32e: golden generator, golden file, Jest freshness test
- (follow-up) fix: dropped an unnecessary type assertion flagged by eslint
- 768920884: Catalog implementation and `tests/render.rs`

## Golden numbers

43 shipped locales x 11 cases (6 poll keys + 5 edge cases) plus 5 extra language settings (`xx`, `nb-NO`, `pt-BR`, `zh-Hans`, empty) = 48 settings, 528 rows. Edge cases: `&<>"'/` in a param, a key absent from every locale (default, with and without namespace), a default naming an unsupplied param and a `{{ spaced }}` token, a numeric param. Most locales lack `steam.waitingForSteam.notify` (46 of the translation files), so the en fallback path is exercised on most rows.

## Does the backend escape interpolated values?

Yes. `bootstrap.ts` sets no `interpolation` option, so i18next 22's default `escapeValue: true` applies. Measured: a game title `Tom & Jerry's <b>"Cheese"</b>` renders as `Tom &amp; Jerry&#39;s &lt;b&gt;&quot;Cheese&quot;&lt;&#x2F;b&gt;`. Rust matches. Note for plans 17/19: titles shown in OS notifications are therefore escaped today; porting keeps that behaviour (parity), it is not corrected here.

## Deviations from Plan

**1. [Rule 3 - Blocking] Generator imports `i18next-fs-backend/cjs`.** `meta/runTs.cjs` bundles to CJS and the package's default (esm) entry uses top-level await, which esbuild rejects. The sidecar build solves this with an alias flag; the plan's verify command passes none, so the cjs subpath is imported directly.

**2. [Rule 3 - Blocking] Generator roots at `process.cwd()`.** The bundle runs from a private temp dir, so `__dirname` is useless; run it from the repo root (as the documented command does).

**3. [Rule 1 - Lint]** eslint flagged an unnecessary `as string`; removed in a separate fix commit.
