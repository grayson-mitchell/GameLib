<objective>
Close UAT 25 (major): the 74-30 InstallApp retry never fires live because Mac Steam, on start,
rewrites the ACF of an AutoUpdateBehavior-1 game to StateFlags 6 / TargetBuildID=PICS target /
BytesDownloaded 0 (update required, not started). `pollUpdateOnce` then sets `awaiting.sawPending`
from `isAcfUpdatePending`, and `retryInstallApp` returns early on `sawPending`, so the retry is
disarmed on the first tick after Steam starts.

Diagnosis verified against the code at planning time (2026-11-14):
- `updatePollOnce.ts` `retryInstallApp` guard (around line 45) returns when `awaiting.sawPending ||
  awaiting.sawActivity`.
- `pollUpdateOnce` (around line 133) sets `awaiting.sawPending = true` whenever
  `isAcfUpdatePending(fields)` (acfUpdateState.ts: StateFlags 0x2, or TargetBuildID != buildid).
- The existing test `never retries once pending or activity was seen` asserts exactly the buggy
  behaviour (StateFlags 6, TargetBuildID 200, no retry). 74-30's other retry tests keep the ACF at
  StateFlags 4 / TargetBuildID = buildid, so the live shape was never covered.

Second, latent defect on the same path: once `sawPending` is set, the non-quiet completion branch
completes on `!pending && bit 4 && sawPending` with no build check, so an ACF that reverts to
StateFlags 4 at the starting build would log `finished` at the stale build. This plan pins
"finished only at the PICS target" with a test and a narrow guard.

Purpose: STEAM-01 registered-update path (UAT 19 minor, UAT 25 major).
Output: retry gated on real activity only; completion guarded against the stale build; tests.
</objective>
