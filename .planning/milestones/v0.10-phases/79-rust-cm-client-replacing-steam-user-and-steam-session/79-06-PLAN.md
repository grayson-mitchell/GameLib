  <action>Implement the interfaces block.
    - The actor is spawned onto the current runtime by `SessionHandle::spawn(backend: Arc<B>, wrap: Arc<W>)`. It holds a `B: CmBackend` and `W: LogonWrap` and processes `Cmd` messages in a `tokio::select!` loop with three arms: commands, the idle-timer `Sleep`, and connect completion.
    - Every CM call (connect_authed, op closures, the canary) runs in `tokio::spawn`ed tasks whose results come back as messages. The control loop itself never awaits CM I/O.
    - Ported state: `lease_count`, `leases: HashSet<LeaseId>`, `generation: u64` (bumped by logout), `connecting: Option<(generation, Vec<oneshot::Sender<..>>)>` so concurrent acquires share one logon, `conn: Option<Arc<B::Conn>>`, `steam_id`, `licenses`, `shutting_down`, `logon_failure`.
    - The logon is wrapped: `wrap.before_logon()` is called first. Err(WrapRefused) maps to `Refusal::GoOfflineRequired` and no connect is issued ("never a silent logon"). Then connect_authed runs under `LOGON_BOUND`, then `wrap.after_logon(ticket)` runs whether the logon succeeded or not.
    - When the connect resolves, check generation and shutting_down first. A stale result is closed via `conn.close()`, with a diag line "logon landed after sign-out/shutdown, closed".
    - ensure_connected: with a session, run the canary (pics_product_info for app 753 with tokens, 5 s). Failure ends the session and starts one fresh logon with the most recent token kept in the actor. Plan 79-11 replaces this with probe + backoff. Without a session, return false; it does not log on (TS decides).
    - logout: generation += 1, leases cleared, the pending connect abandoned (its result fenced), conn closed, logon_failure cleared.
    - shutdown(bound): set shutting_down, abandon the pending connect, close conn, then `wrap.pay_owed(RestoreTrigger::Shutdown)` under `bound`. Later acquires return ShuttingDown.
    - Diag lines carry the reason, cause and counts only, e.g. `CM session closed mode=authenticated cause=idle` and `CM logon mode=authenticated reason=<reason>`, matching today's user.ts wording so live-gate greps carry over. Never the token.
    - Keep the token in the actor only as `RefreshTokenSecret`, replaced on each acquire, so reconnects in plan 79-11 can reuse it (D-07: unchanged token, no renewal).
    - Tests: `#[cfg(test)] mod tests` using FakeBackend, NoWrap, `#[tokio::test(start_paused = true)]`.</action>
